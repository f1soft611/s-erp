- 일자: 2026-10-29. 데이터 보정이며 DDL/API/UI 변경 없음.
- 영향: 명시한 테넌트의 `S_ERP_GROUPWARE_DEMO_20261029` 문서 내 합성 승인 의견과 합성 시스템 이력만 수정.
- 대상: `tb_electronic_approval_main`의 데모 메타데이터, `tb_electronic_approval_line_info.action_comment`, `tb_common_comment.content`.
- APPROVED의 합성 의견을 NULL로 하여 승인 도장만 표시한다. 시스템 이력은 HTML/마커가 없는 일반 텍스트로 바꾼다. 반려/보완 사유와 일반 댓글/답글은 유지한다.
- 기존 문서/댓글 ID, 상태, 생성/수정/처리 시각, 조회수는 보존한다. 삭제/재시드는 하지 않는다.

- DB 내부 문서 메타데이터에 변경 전후 값을 백업한다. 문서 편집 과정에서 메타데이터가 제거되면 자동 복원이 불가능할 수 있으므로 실행 전 별도 DB 백업이 필요하다.
- 잠금: 세 테이블 전체의 쓰기를 짧게 대기시킨다. 유지보수 시간에 실행하며 lock_timeout=5s, statement_timeout=60s를 적용한다.

## 이미 적용한 데모 데이터 보정

psql에 접속한 상태에서 아래를 한 줄씩 실행한다. 기존 실패 트랜잭션이 있으면 반드시 먼저 `ROLLBACK;`한다. `1`은 대상 테넌트에 맞게 지정한다. 파일은 psql이 실행되는 컴퓨터에 있어야 한다.

```sql
\set target_tenant_id 1
\i 'D:\\f1soft\\dev\\react\\S-ERP\\backend\\DATABASE\\20261029\\20261029_004_repair_groupware_demo_presentation.sql'
```

화면을 새로고침하면 승인 도장은 그대로이며 합성 승인 의견은 사라진다. 시스템 이력은 정상 문장만 표시된다. **기존 003 시드를 다시 실행하지 않는다.**

되돌리기:

```sql
\i 'D:\\f1soft\\dev\\react\\S-ERP\\backend\\DATABASE\\20261029\\20261029_004_rollback_groupware_demo_presentation.sql'
```

원문이 다르거나 수정된 행은 자동 정규화하지 않는다. 재실행은 이미 보정한 문서를 건너뛴다. 계정 정보/실제 데이터 행을 조회하거나 출력하지 않는다.

## 신규 시드와 검증

신규 003 시드는 승인 의견 NULL과 일반 텍스트 시스템 이력을 생성하도록 수정했다. 삭제 롤백은 새 시스템 이력 지문과 기존 마커 버전 모두를 검증한다. 기존 사용자의 공지분류 수정은 유지한다.

현재 세션의 기본 DB MCP 검색 결과 도구가 없어 재확인하지 못했다. 이전 메타데이터와 Mapper/Service/날짜별 DDL로 확인했다. 실DB에는 보정 SQL을 적용하지 않았으며 격리 PGlite 합성 데이터로만 검증한다.
