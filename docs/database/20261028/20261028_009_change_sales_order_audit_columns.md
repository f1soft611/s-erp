# 수주 감사 사용자 컬럼 길이 변경 이력

- 날짜/작업 번호: 2026-10-28 / 009
- 대상: `public.tb_sales_order_hd.created_by`, `updated_by`
- 변경: nullable `varchar(10)` → nullable `varchar(100)`
- 목적: 원본 `tb_login_account.login_code`의 100자 계약과 일치시켜 11자 이상 인증 사용자로 수주 등록/수정/삭제할 때의 길이 오류를 방지한다.
- 영향: 두 audit 컬럼의 길이만 확장한다. 기존 값, NULL, 기본값, 수주 금액·번호·상태·테넌트 경계 및 상세 테이블은 변경하지 않는다.
- 근거: 기본 읽기 전용 MCP의 `list_tables`, `describe_table`, `information_schema.columns` 메타데이터 조회. 업무/계정/테넌트 행은 조회하지 않았다.
- 적용 상태: 실제 DB 미적용. 관찰된 현재 길이는 10자이며 아래 변경 SQL 적용 후 100자가 된다.

## 적용

1. DB 담당자가 오류 발생 애플리케이션의 대상 DB와 점검 시간을 확인한다.
2. `20261028_009_expand_sales_order_audit_columns.sql`을 실행한다. psql 사용 시 `-v ON_ERROR_STOP=1`로 오류 즉시 중단한다. 신규 환경은 기존 `20261026_008` 생성 DDL 후 실행한다.
3. 메타데이터로 두 컬럼의 길이가 모두 100인지 확인한다.
4. 승인된 테스트 환경에서 11자 이상 인증 사용자로 수주 등록·수정·삭제 후 작성자 조회가 유지되는지 확인한다.

DDL은 트랜잭션으로 두 컬럼을 함께 변경하며 잠금 대기를 5초로 제한한다. 트랜잭션 실패 시 같은 연결에서 `ROLLBACK` 후 점검 시간에 재시도한다. 이미 100자로 변경된 대상에 재실행해도 값은 유지된다.

## 롤백

- `20261028_009_rollback_sales_order_audit_columns.sql`을 사용한다.
- 테이블 잠금을 획득하고 두 컬럼 중 어느 하나라도 10자 초과 값이 존재하면 예외로 중단한다.
- 중단된 트랜잭션은 `ROLLBACK`한다. 이때 기존 데이터와 100자 컬럼은 보존된다.
- 긴 사용자 키가 없는 경우에만 두 컬럼을 10자로 복구한다. 키 절삭/삭제를 자동 수행하지 않는다.
- 복구 후 11자 이상 사용자로 수주 저장하는 기존 오류가 재발할 수 있으므로 롤백은 업무 영향을 검토한 뒤 수행한다.

## 검증 범위

- 격리 PostgreSQL WASM 환경에서 합성 값으로 변경 전 SQLSTATE 22001 재현, 변경 후 10/11/100자·다국어·NULL 보존, 101자 거부, 재실행 및 안전 롤백을 확인한다.
- 실제 서비스 DB DDL 실행 및 실제 수주 저장 검증과 구분한다.
- 두 스키마 디렉터리에 동일한 변경 SQL·롤백·이력을 보관한다.
