# 거래처명 중복 방지 변경 이력

- 날짜/번호: 2026-10-23 / `20261023_001`
- 대상: `public.tb_customer_info`
- 내용: `(tenant_id, btrim(customer_name))` 고유 인덱스 `uq_tb_customer_info_tenant_name` 추가. 사용/미사용 구분 없이 앞뒤 공백을 제거한 이름을 같은 테넌트 내에서 중복 금지한다. 대소문자는 구분하며 기존 NULL 허용 여부는 변경하지 않는다.
- 영향: 등록/수정 및 동시 저장. 기존 거래처코드 고유 인덱스와 ID/채번/기존 컬럼은 유지한다.
- 사전 확인: 기본 DB MCP에서 테이블/컬럼/인덱스 metadata만 확인했다. 기본 DB의 이름 nullable 및 code index 이름은 이전 tenant 전용 문서와 다르다. 업무 행을 조회하지 않아 현재 중복 데이터 유무는 미확인이다.
- 적용: 읽기 전용 MCP로 실행하지 않았다. 실제 적용 완료가 아니다. 먼저 업무 담당자가 기존 중복을 확인하고 필요한 이름 변경을 승인해야 한다.
- 안전 절차: 쓰기 경합을 막는 테이블 잠금 아래 중복이 있으면 값을 출력하지 않는 오류로 전체 트랜잭션을 중단한다. 데이터 자동 삭제/수정 없음. 잠금 획득은 5초 제한이며 유지보수 시간에 적용한다. 대형 테이블의 인덱스 생성 시간은 별도 점검한다.
- 배포 순서: 중복 데이터 정리 승인 → migration 적용 → 애플리케이션 배포. 인덱스 없이 서비스 사전 조회만 배포하면 동시 중복을 완전히 방어하지 못한다.
- 롤백: `20261023_001_rollback.sql`로 신규 인덱스만 삭제하고 애플리케이션을 이전 버전으로 복구한다. 데이터는 삭제하지 않지만 이후 DB 차원의 이름 중복 방지는 해제된다.
- 사본: `docs/database/20261023`와 `backend/DATABASE/20261023`의 같은 번호 파일은 동일하게 유지한다.
