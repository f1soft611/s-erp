# 구매자재 메뉴 그룹 재구성 변경 이력

- 변경일: 2026-11-13
- 대상 테이블: `tb_menu` (데이터)
- 변경 항목:
  - `MATERIALS_PURCHASE` 이름을 `구매관리` → `구매요청관리`로 변경(구매요청등록·확정·현황 유지, 코드·URL 불변)
  - `MATERIALS_ORDER`(발주관리, `/materials/order`, 정렬 20) 그룹 신설
  - `MATERIALS_ORDER_CREATE`(발주등록)를 발주관리 아래로 이동(정렬 10)
- 목표 구성: 구매요청관리(요청 3개) / 발주관리(발주등록·발주현황) / 입고관리(가입고등록·입고등록·매입마감처리) / 출고관리(출고등록·출고현황). 입고관리·출고관리는 화면을 만들 때 그룹과 함께 등록한다.
- 대상 테넌트: 1
- 선행: `20261112_002~004`, `20261113_003`. 후행: `20261113_005`(발주현황).
- 영향: 메뉴 코드·URL·권한은 바꾸지 않아 화면 경로, 즐겨찾기, 역할 권한은 그대로다. 그룹 메뉴 표시 이름과 계층만 바뀐다. 신규 설치에서는 `20261113_003`이 발주등록을 `MATERIALS_PURCHASE` 아래에 만든 뒤 이 스크립트가 이동한다(003은 이동 후 재실행해도 오류가 나지 않도록 부모 일치 검사를 뺐다).
- MCP 확인: `s-erp-postgresql-readonly`로 테넌트 1의 `MATERIALS_*` 메뉴 계층(그룹 `MATERIALS_PURCHASE` 아래에 구매요청 3개와 발주등록), 그룹 메뉴에는 메뉴·역할 권한이 없음, 영업관리 그룹 구조(수주관리·출하관리)를 확인했다.
- 적용 상태: SQL 스크립트만 작성했으며 실제 DB에는 적용하지 않았다.
- 롤백 여부: 제공함. 발주등록을 구매관리 아래로 되돌리고 발주관리 그룹을 하위 메뉴가 없을 때만 삭제한 뒤 이름을 되돌린다. 발주현황(005)이 있으면 005 롤백을 먼저 실행한다.

적용 SQL: `20261113_004_restructure_materials_menu_groups.sql`

롤백 SQL: `20261113_004_rollback_materials_menu_groups.sql`
