# 20261007_001 문서작성 사용자 선택 테스트 데이터 변경 이력

## 최초 시드

- 변경일: 2026-10-07
- 변경 유형: 선택기 테스트용 시드 데이터 추가 (테이블 구조 변경 없음)
- 대상 테이블: `tb_user`
- 변경 내용: 예약된 `.invalid` 이메일과 표시용 테스트 이름을 가진 활성 사용자 프로필 10개를 추가하는 멱등 SQL 제공
- 최초 계정 연결: 기존 활성 `tb_login_account` 행의 `tenant_id`/`login_id`를 재사용하며 로그인 계정이나 비밀번호는 생성하지 않음
- DB 반영 여부: 최초 산출물 설명이며 실제 DB에는 적용하지 않음

## 후속 보정: 전용 로그인 계정

- 변경일: 2026-10-07
- 변경 유형: 기존 seed 데이터 로직 보정 (테이블 구조 변경 없음)
- 대상 테이블: `tb_login_account`, `tb_login_account_role`, `tb_user`
- 변경 내용: 기존 테스트 사용자 10개를 고유 로그인 코드 `doc-write-test-user-01`~`10` 및 각자 전용 계정에 연결하고, 해당 테넌트의 기존 활성 `DEFAULT_USER` 역할을 매핑
- 인증정보: 실행 세션의 `app.document_test_user_hash_01`~`10` 설정으로 계정별 SHA-256/Base64 해시 입력을 요구한다. 실제 비밀번호와 해시는 저장소/문서에 포함하지 않으며 값이 없거나 형식이 맞지 않으면 쓰기 전에 실패한다.
- 조직 참조: 기존 활성 계정 연결 기준 사용자의 테넌트, `department_id`, `level_id`를 사용
- 영향 범위: 사용자 선택기 후보가 고유 활성 계정과 대응하고, `tenant_id + login_id` 사용자 조인의 테스트 프로필 중복을 방지
- 충돌/재실행: 같은 테넌트의 로그인 코드가 다른 사용자에게 연결되거나 테스트 전용 계정에 `DEFAULT_USER` 이외 역할이 있으면 중단한다. 다른 테넌트의 동일 로그인 코드는 변경 대상이 아니다.
- 롤백 여부: `20261007_001_rollback.sql`은 지정된 이름/이메일의 프로필을 제거하고, 남은 사용자 프로필이 참조하지 않는 동일 테넌트 전용 테스트 계정과 역할 연결만 제거
- DB 반영 여부: 후속 보정 SQL도 실제 DB에는 적용하지 않음
- DB MCP 확인: 테이블 및 컬럼 메타데이터와 `DEFAULT_USER` 역할 코드를 확인했다. 제한된 조회 결과로 민감한 계정/사용자 행 데이터는 가져오거나 문서화하지 않았다. MCP는 읽기 전용이므로 쓰기와 로그인 검증은 수행하지 않음
