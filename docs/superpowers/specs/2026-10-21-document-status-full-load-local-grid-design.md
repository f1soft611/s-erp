# 문서현황 전체 조회 및 로컬 정렬·필터 설계

## 목적

문서현황에서 현재 조회조건과 결재신청 기간에 맞는 전체 결과를 조회하고, 정렬 및 필터 변경은 추가 API 조회 없이 그리드에서 처리한다. 기존의 페이지 조회 기능은 다른 호출부나 향후 용도를 위해 보존한다.

## 현재 동작과 원인

- 문서현황 프런트엔드는 F1Grid `dataSource`를 사용하고 `pageSize`를 200으로 설정한다.
- F1Grid는 최초 200행을 요청하고, 스크롤이 끝에 가까워지면 `offset`을 증가시켜 다음 행을 추가 요청한다. 페이지 버튼은 없지만 내부적으로는 서버 페이징/지연 로딩이다.
- F1Grid의 데이터소스 로드는 정렬 상태 변경에도 다시 실행되며, 문서현황 서비스는 정렬 필드를 API에 전달한다.
- 백엔드 문서현황 검색 서비스는 기본 `limit=200`을 적용하고 최대 200으로 검증한다. 목록 SQL도 `LIMIT/OFFSET`으로 제한한다.
- 문서현황 그리드는 `disableFiltering`을 전달해 헤더 필터 메뉴를 숨긴다.

## 승인된 설계

### API 및 조회

- 문서현황 화면의 검색은 상세검색 및 날짜 범위를 그대로 API에 전달한다.
- offset/limit이 없는 요청은 해당 검색조건에 맞는 전체 결과를 반환하도록 문서현황 검색 API에 전체 조회 경로를 추가한다.
- offset 또는 limit이 포함된 기존 요청은 현재의 최대 200행 페이지 조회 및 응답 계약을 유지한다.
- 전체 조회에서도 기존 인증 사용자/tenant 범위, 검색조건 검증, 기본 정렬, 응답 행 검증을 유지한다.
- DB 스키마는 변경하지 않는다.

### 그리드

- 문서현황 페이지는 전체 API 응답의 행 배열을 F1Grid `rows`로 전달하고 데이터소스 모드는 사용하지 않는다.
- F1Grid의 로컬 정렬을 사용해 헤더 정렬 변경 시 API를 재호출하지 않는다.
- `disableFiltering`을 제거해 헤더 필터 메뉴를 노출하고, 전체 조회된 행에 로컬 필터를 적용한다.
- 새로운 검색조건을 적용하면 서버에서 해당 조건의 전체 결과를 다시 조회한다. 그리드 헤더 정렬/필터 조작은 재조회하지 않는다.
- 기존 문서현황 상세검색, 기본 날짜 범위, 선택/상세 패널, 오류 표시 및 엑셀 내보내기는 유지한다.

### 로딩과 오류

- 전체 결과 조회가 완료될 때까지 문서현황 목록의 로딩 상태를 표시한다.
- 요청 취소/경합은 기존 페이지 패턴을 따른다. API 오류는 기존 오류 표시 영역에 전달하고 성공형 빈 결과로 대체하지 않는다.
- 전체 조회는 결과가 많을수록 초기 검색 대기시간과 브라우저 메모리 사용량이 증가할 수 있다. 요청된 날짜 범위와 나머지 검색조건은 그대로 적용해 범위를 제한한다.

## 검증 기준

- offset/limit 없는 문서현황 검색은 검색조건에 맞는 전체 결과를 반환한다.
- offset/limit이 있는 기존 요청은 최대 200행 페이지 동작과 전체 건수 응답을 유지한다.
- 문서현황 화면 최초 검색 후 서버 결과 전체가 그리드에 표시된다.
- 정렬 변경 및 헤더 필터 적용/해제는 문서 검색 API를 다시 호출하지 않는다.
- 필터 메뉴가 표시되고 로드된 전체 결과에 적용된다.
- 검색조건, 날짜 기본값, 선택 행/상세 패널, 로딩, 오류, 엑셀 내보내기 동작에 회귀가 없다.
- 프런트엔드 관련 테스트 및 빌드, 백엔드 타깃 테스트가 통과한다.
- F1-Grid 사용자 문서와 날짜별 결과 문서를 갱신한다.

## 범위 제외

- DB 스키마 변경
- 다른 화면의 페이징 또는 F1Grid 데이터소스 동작 변경
- 문서현황 검색조건/날짜 기본값 변경
- 화면에 페이지 이동 UI 추가
