# 문서작성 알림 카드 문서 정보 보강 설계

## 요구사항 및 승인된 화면 구성

사용자 요청에 따라 `놓치지 마세요` 알림에 기안자, 상신일, 결재상태, 업무구분을 표시한다. 라벨형 정보 배치를 선택했다.

1. 상단: 기존 알림 유형과 결재상태 배지.
2. 본문: 문서 제목을 굵은 본문 크기로 표시하고 긴 제목은 줄바꿈한다.
3. 하단: 업무구분, 기안자, 상신일을 각각 라벨/값으로 표시한다.

기존 중립 배경과 테두리, 좌측 정렬, 전체 카드 선택, 최대 3건, 빈 상태를 유지한다. 좁은 폭에서는 상단 배지가 줄바꿈되고 하단 값도 영역 안에서 줄바꿈된다. 배지는 기존 결재상태의 색상/표현을 재사용하며 업무구분은 축약 없이 전체 명칭을 표시한다.

## 데이터 연결

- 기안자: 기존 `drafterName` → `DocumentWriteItem.author`.
- 업무구분: 기존 `DocumentWriteItem.kind`.
- 결재상태: 기존 `status`, `statusColor`, `statusVariant`.
- 상신일: 기존 응답의 `submittedAt`을 별도 표시 필드로 전달한다. 공통 `date`는 수정일/작성일 fallback이 있으므로 상신일로 재사용하지 않는다.
- 상신일 미제공 시 `—`를 표시한다. 임의의 작성일/수정일로 대체하지 않는다.
- 기존 날짜 포맷 함수를 재사용하며 다른 목록 날짜 동작은 유지한다.
- 백엔드 API와 DB 스키마는 변경하지 않는다. 기존 응답 계약의 메타데이터만 확인한다.

## 검증 및 범위

- 알림 카드의 네 가지 정보, 상신일 fallback 금지, 상태 배지, 전체 업무구분을 테스트한다.
- 최대 3건, 보완 요청 문구, 클릭/키보드 선택, 빈 상태를 회귀 검증한다.
- 실제 컴포넌트와 앱 테마를 사용해 375px, 768px, 1280px에서 긴 제목/기안자 줄바꿈과 가로 넘침을 확인한다.
- 계획서/사양서/결과 문서와 스크린샷을 날짜별 폴더에 기록한다.
- 공통 목록·다른 우측 카드·결재 처리 동작은 변경하지 않는다.
