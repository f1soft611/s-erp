# 문서현황 그리드 정보 재정의 설계

## 목적

문서현황 목록에서 문서 식별, 결재 위치, 로그인 사용자의 처리 역할을 바로 파악하고 F1-Grid 상세검색으로 해당 정보를 검색할 수 있게 한다.

## 사용자 승인 방향

- `eabus_no`는 문서 유형별 구분 코드이므로 문서번호로 표시하지 않는다.
- 문서번호는 `electronicApprovalId` (`electronic_approval_id`)로 표시한다.
- `documentType`을 문서종류로 유지하고 중복되는 `eabusNo` 컬럼은 목록에서 제외한다.
- 결재 참여자 전체 이름 요약은 기본 그리드에서 제거한다. F1-Grid 숨김 컬럼을 검색 메타데이터에 연결해 참여자 이름 상세검색은 유지한다.
- 개인 문서 업무 판단에 필요한 현재 결재단계·담당자와 로그인 사용자의 역할·처리상태를 표시한다.
- 상세검색 필드는 그리드 컬럼 메타데이터에서 생성하며 문서번호, 결재상태, 문서종류, 결재신청일, 제목, 기안정보, 결재 참여자, 내 역할·처리상태, 현재 결재담당자 및 최종 변경일을 포함한다.
- 기존 상세 패널의 전체 결재선은 유지한다.

## 화면 및 데이터 흐름

F1-Grid 목록 행은 문서 ID, 제목, 종류, 문서 상태, 결재신청일, 기안자/부서, 현재 결재단계·담당자, 현재 사용자의 참여 역할·처리상태, 승인 진행 요약 및 최종 변경일을 표시한다. ID는 정수 표시와 동일 문서의 안정적인 식별자 역할을 한다.

문서현황 API는 현재 tenant·사용자 읽기 범위를 유지한다. 기존 결재선 테이블의 참여유형, 참여자 ID, 단계, 처리상태를 이용해 로그인 사용자 정보와 현재 대기 단계를 목록에 투영한다. 새 DB 컬럼/테이블은 만들지 않는다. 검색 및 정렬은 서버에서 수행하고, 검색 UI 값은 기존 F1-Grid 검색 metadata에서 생성한다.

## 상세검색 계약

- 문서번호: `electronicApprovalId`, 양의 정수 일치 검색.
- 문서종류 및 결재상태: 기존 선택값.
- 결재신청일/최종 변경일: 기존 `{ from, to }` 및 서버 날짜 범위 계약.
- 제목, 기안자, 기안부서, 현재 결재담당자: 부분 문자열 검색.
- 내 역할: 승인, 합의, 참조 유형 필터.
- 내 처리상태: 대기, 처리 중, 승인, 반려, 보완요청 필터.
- 빠른검색은 문서번호, 제목, 기안자를 검색한다. 기존 eabus 구분 코드는 문서번호 검색에 사용하지 않는다.

## 오류 및 보안

검색값은 서버에서 허용 목록/숫자 유효성 검증 후 사용한다. SQL 식별자는 기존 허용 정렬 필드 whitelist를 통해서만 정렬하며, tenant와 로그인 사용자의 문서 접근 조건을 모든 목록·건수 쿼리에서 유지한다. DB 행 데이터는 문서나 테스트 산출물에 복사하지 않는다.

## 검증

- 프런트엔드: 컬럼 순서/헤더, 상세검색 metadata 생성, 문서 ID 빠른/상세 검색, 역할·상태 검색 query serialization 및 응답 유효성 테스트.
- 백엔드: 목록 query 입력 검증, 허용 정렬, 역할/상태/담당자 SQL 필터와 결과 투영, tenant/사용자 접근 조건 테스트.
- 프런트엔드 빌드와 관련 테스트, 백엔드 타깃 테스트를 수행한다.
- 문서현황의 기존 상세 오버레이 및 날짜 범위 동작을 회귀 확인한다.
