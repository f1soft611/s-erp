# 공통 리치 텍스트 편집기 및 공지 페이지 분리 설계

## 상태

- 설계 승인: 공지와 기안양식이 공통 편집기의 전체 기능을 공유한다.
- 구현 승인: 사용자가 설계와 상세 사양을 승인했다. 구현은 완료됐으며 Chromium 반응형 검증과 결과 기록을 진행 중이다.
- 범위: 프론트엔드 공지사항과 기안양식 본문 편집기. 백엔드와 데이터베이스 계약은 변경하지 않는다.

## 배경

공지 작성과 기안양식 본문 편집기는 각각 Tiptap 확장, 툴바, 붙여넣기 처리, 이미지 삽입을 소유하고 있어 같은 기능을 두 번 구현한다. 공지 편집기는 글꼴·색상과 선택 이미지 크기 조절을 제공하지만 기안양식 편집기는 일부 기능이 빠져 있다. 표준화된 Excel 붙여넣기 정규화도 현재 공지 폴더의 `noticeClipboard.ts`에 위치했으며, 본 변경에서 도메인 중립 shared module로 승격한다.

공지 페이지는 조회, 목록 상태, 선택, 댓글, 반응, 작성/수정, 삭제, 고정 및 화면 조립을 `CommunityNoticePage.tsx`에 함께 두고 있다. API 서비스와 일부 화면 컴포넌트는 이미 분리되어 있지만 페이지 동작 훅이 없고, 여러 API 모델/폼 타입이 서비스 또는 다이얼로그 파일에 선언되어 있다.

## 목표

- 공지 페이지에서 화면 조립, 상태/동작, API 호출, 데이터 변환, 타입 책임을 분명히 분리한다.
- 공지와 기안양식이 같은 공통 리치 텍스트 편집기와 동일한 하단 icon toolbar를 사용한다.
- toolbar에서는 사용자가 제공한 목록(문단, B/I/U/S, 색상, 표, 링크, 번호/글머리)을 제공한다. 별도 글꼴/글자 크기 선택기는 두지 않고, Tiptap inline typography schema와 clipboard parsing은 기존/붙여넣은 서식 호환을 위해 유지한다.
- 공지/기안양식 footer toolbar는 screenshot reference와 같은 얇은 공통 icon style을 사용하며 consumer별 trigger/panel style override를 두지 않는다.
- 도메인별 이미지 업로드, 이미지 조회, 저장, 권한 및 임시 파일 정리 계약은 각 기능에 유지한다.
- 화면의 기존 동작과 저장 payload를 보존하며, 기안양식은 공지와 같은 글꼴·색상, 표 편집/붙여넣기, 이미지 크기 조절을 제공한다.
- 공유 파일명에는 `notice` 접두사를 쓰지 않고 `RichTextEditor`, `clipboard` 등 재사용 목적이 드러나는 공통 이름을 사용한다.

## 설계

### 공통 편집기

공통 모듈은 `frontend/src/shared/components/rich-text-editor/` 아래에 둔다. 공통 편집기가 소유할 책임은 Tiptap 스키마/확장, 툴바 동작, 표 및 서식 처리, 클립보드 HTML·일반 텍스트 정규화, 이미지 붙여넣기 placeholder/상태, 선택 이미지 크기 조절, 에디터 공통 스타일이다. 모듈과 테스트 파일명은 도메인 중립적으로 정한다.

공지 작성과 기안양식 다이얼로그는 기존 도메인 폼과 모달 셸을 계속 소유한다. 각 도메인은 이미지 업로드 함수를 공통 편집기에 주입하고, 업로드 응답을 공통 이미지 메타데이터로 매핑한다. 임시 이미지 삭제, 저장 payload 구성, 인증 이미지 재조회/복원, 저장 완료 처리는 해당 서비스와 다이얼로그에 남긴다. 공통 편집기는 공지 또는 기안양식 endpoint, object key, 소유권 정책을 알지 않는다.

공통 스키마는 기존 notice 속성(`data-file-id`, 업로드 token/state, object metadata, 크기/MIME)과 draft-form 임시 업로드 식별자를 지원한다. 커스텀 속성은 명시적 allowlist로 관리하고 도메인 전용 값은 optional로 취급한다. 표 붙여넣기의 안전한 정규화 결과와 우선순위는 기존 동작을 유지한다. Excel 표와 이미지가 함께 있는 경우 기존처럼 표 HTML을 우선한다.

공지의 기존 글꼴/색상 확장과 표 셀 스타일을 공통 스키마에 포함한다. 기안양식이 이를 사용해 기존 저장·조회 JSON/HTML과 호환되는지 테스트한다. 이미지 크기 조절은 양 도메인에서 같은 selection/resize 동작을 사용한다.

### 공지 페이지 구조

- `CommunityNoticePage.tsx`는 페이지 레이아웃과 하위 컴포넌트 연결에 집중한다.
- 복잡한 서버 데이터 로딩, 페이징/필터, 선택 항목 동기화와 사용자 동작은 책임 단위별 기능 훅으로 이동한다. 훅 사이에 공유 상태가 필요한 부분은 page-level hook에서 조정하고, 하나의 훅에 무관한 모든 동작을 몰아넣지 않는다.
- 기존 `noticeBoardService.ts`를 공지 게시글 API의 단일 경계로 유지한다. 댓글/공통 파일/공통 코드 endpoint는 기존 shared service를 사용하되 페이지 컴포넌트가 직접 호출하지 않도록 상태/동작 훅에서 조정한다.
- API 응답 타입과 편집 폼 타입은 기능 `types/`로 이동한다. 화면 모델과 순수 변환은 기존 `data/` 또는 `utils/` 경계에 둔다. 현재 테스트와 소비자가 사용하는 공개 export는 단계적으로 정리하며 불필요한 별칭이나 중복 모델을 만들지 않는다.
- 기존 UI 컴포넌트는 기능 전용 `components/`에 유지한다. 화면 동작이 바뀌지 않는 파일 이동 및 책임 분리만 수행한다.

### 대안

- 각 다이얼로그에서 공통 clipboard 유틸만 공유: 변경량은 작지만 툴바, 확장, 이미지 처리/크기 조절 중복이 남고 두 편집기의 기능이 계속 달라져 제외한다.
- 편집기뿐 아니라 도메인 저장/API까지 공통화: 코드 중복은 줄지만 서로 다른 업로드 소유권·정리 계약을 혼합하므로 제외한다.
- 공통 편집 동작과 UI를 공유하고 도메인 API는 어댑터로 유지: 기능 일관성과 소유권 경계를 모두 지키므로 선택한다.

## 데이터 흐름 및 오류 처리

각 다이얼로그가 본문을 초기화하고 공통 편집기에 전달한다. 사용자의 입력/붙여넣기/이미지 조절은 공통 편집기에서 처리한다. 이미지 파일은 다이얼로그가 제공한 도메인 upload callback으로 업로드하며, 성공 시 공통 이미지 노드에 메타데이터를 반영하고 실패 시 실패 이미지만 제거하면서 기존 본문을 보존한다. 업로드 중 저장은 현재처럼 차단한다. 도메인별 저장 실패 시 기존 다이얼로그의 본문/재시도 동작을 유지한다.

공지 페이지 훅은 기존 오류/로딩/낙관적 갱신 동작을 보존한다. 취소, 삭제, 좋아요/북마크/고정 및 댓글 처리의 결과 반영 범위도 기존 테스트와 동등해야 한다.

## 검증

- 공통 편집기 단위 테스트: 정규화/안전 필터, 표 셀 구조와 줄바꿈, 일반 텍스트 fallback, 이미지 붙여넣기 성공·실패, 이미지 리사이즈, toolbar 명령.
- notice/draft 통합 테스트: 같은 공통 편집기 기능 사용, 서로 다른 upload adapter 호출, 기존 본문 JSON/HTML 및 각 도메인 저장 payload 보존.
- 공지 페이지 테스트: 기존 목록·상세·페이징·필터·댓글·반응·권한·작성/수정/삭제 동작 회귀.
- 프론트엔드 focused 테스트 및 `npm --prefix frontend run build` 실행.
- Chromium에서 공지 작성과 기안양식 편집을 확인하고 375px, 768px, 1280px에서 툴바/표/이미지 편집 레이아웃을 확인한다. 결과 문서에 근거와 스크린샷을 기록한다.

## 범위 제외

- 백엔드 API, DB 스키마, 업로드 경로, object key, 파일 소유권/수명 정책 변경
- 공지 또는 기안양식의 저장·권한 정책 변경
- 공지 상세/피드 UI 재설계, 라우팅 변경, 관련 없는 페이지 리팩터링
- 임의 HTML/CSS 허용 범위 확대 또는 보안 정규화 약화
