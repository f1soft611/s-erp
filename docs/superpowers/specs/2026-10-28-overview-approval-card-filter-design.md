# 종합현황 개인 결재 카드 필터 설계

## 목표

종합현황의 결재 대기, 임시저장, 보완 필요 카드가 가리키는 건만 문서 화면에서 보이게 한다.

## 설계

카드 이동 경로에 `dashboardScope` 쿼리를 더한다. 기존 승인된 `approvalPath`를 유지하고 scope 값은 `MY_PENDING`, `DRAFT`, `REVISION_REQUESTED`로 고정한다. 작성 화면은 이미 사용하는 scope 조회와 필터 칩을 초기화에 재사용한다. 조회 전용 화면은 기존 검색 API가 지원하는 scope를 요청에 넘기고 칩으로 표시해 범위만 해제할 수 있게 한다.

유효하지 않은 쿼리 값은 무시한다. 권한, 메뉴 경로, 서버 API/DB 계약은 변경하지 않는다. 테스트는 카드 URL, 두 문서 화면의 요청 조건, 범위 해제를 검증한다.

## 영향 범위

- `OverviewPage` 개인 업무 카드 이동
- 문서 작성/조회 화면의 초기 scope 적용
- 관련 프론트엔드 테스트와 날짜별 작업 문서

## 검토

- 기존 scope API 계약을 재사용하므로 서버 변경이 불필요하다.
- 조회 전용 권한 경로도 같은 범위 의미를 사용하며, 화면에서 현재 필터를 알리고 해제할 수 있다.
- 일반 문서 화면의 기본 전체 조회 및 기존 세션 검색 조건은 유지한다.
