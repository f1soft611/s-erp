# 문서 참조자 추가 설계

## 목표

기안자가 문서를 상신한 뒤에도 해당 문서를 열람할 권한이 있는 사용자가 추가 참조자를 지정할 수 있게 한다. 추가된 참조자는 저장 즉시 문서에 접근할 수 있고, 기존 참조자 확인 흐름에 따라 미확인 참조 문서로 표시된다. 상세 화면의 더보기 메뉴는 관련 작업끼리 구분선으로 묶는다.

## 현재 구조와 근거

- 문서 상세의 `DocumentActionsMenu`에는 문서 공유, 문서 수정, 삭제가 있다. 수정과 삭제는 기안자 및 문서 상태에 따라 노출된다.
- 결재선의 참조자는 `REFERENCE` 참여자로 저장되며 기존 문서 권한 및 참여자 문서 목록 조회 흐름을 사용한다.
- 상신 후 참조자의 확인 상태는 기존 참여자 행과 `REFERENCE_CONFIRMED` 시스템 이력으로 처리된다. 미확인 참조 문서는 `MY_REFERENCE_PENDING` 범위에 포함된다.
- 참조자 선택은 문서작성의 기존 사용자 선택 UI와 참조자 입력 흐름을 재사용할 수 있다.
- 상세 근거: [문서 참조자 확인 설계](2026-10-29-document-reference-confirmation-design.md), [문서 링크 공유 상세 사양](../../spec/20261028/20261028_017_document-link-sharing_상세사양서.md), [문서 공유 후속 수정 상세 사양](../../spec/20261028/20261028_018_document-sharing-corrections_상세사양서.md)

## 승인된 동작

### 참조자 추가 권한 및 시점

- 문서가 임시저장(`DRAFT`)이 아닌 상신 후 상태이고 삭제되지 않았을 때 참조자를 추가할 수 있다.
- 추가 권한은 해당 문서를 현재 열람할 수 있는 사용자에게 제공한다. 서버는 요청 사용자와 문서의 접근 권한을 매 요청마다 검증한다. 클라이언트가 권한을 주장하거나 대상 문서의 내부 ID를 바꾸어 권한을 얻을 수 없어야 한다.
- 한 번의 추가 작업에서 기존 사용자 선택 UI로 한 명 이상을 지정할 수 있다.
- 이 기능은 참조자 추가만 제공한다. 기존 참조자 제거, 결재자/합의자 변경, 결재선 재배치 기능은 추가하지 않는다.

### 저장 및 즉시 접근

- 저장된 각 사용자는 해당 문서의 `REFERENCE` 참여자가 된다. 추가된 참조자는 저장 성공 직후 기존 문서 목록·상세 권한 검사를 통해 문서에 접근할 수 있어야 한다.
- 새 참조자는 미확인 상태로 등록된다. 기존 미확인 참조 문서 조회에 즉시 포함되고, 상세에서 기존 `확인` 액션을 사용할 수 있다.
- 기존 결재 단계, 승인/합의 진행, 결재 대기 건수와 문서 상태는 변경하지 않는다.
- 이미 해당 문서의 참여자인 사용자를 중복 지정하지 않는다. 기존 참조자는 보존하고, 중복 요청이 기존 참여 상태를 초기화하거나 중복 참여 행을 만들지 않도록 한다.
- 참조자를 추가해도 별도 알림이나 메시지는 발송하지 않는다.

### 더보기 메뉴 그룹

문서 상세의 더보기 메뉴를 다음 그룹으로 표시한다.

1. 문서 공유하기
2. 참조자 추가하기
3. 구분선
4. 문서 수정 또는 수정 후 재상신
5. 삭제

- `문서 공유하기`와 `참조자 추가하기`는 문서 공유/참여자 작업 그룹으로 묶는다.
- `문서 수정`과 `삭제`의 기존 권한 및 상태 조건은 보존하고 같은 문서 관리 그룹으로 둔다. 사용할 수 없는 항목은 기존 동작대로 숨긴다.
- 구분선은 양쪽 그룹에 표시되는 항목이 있을 때만 렌더링하고, 빈 그룹 사이에 단독으로 남기지 않는다.
- 메뉴 항목 선택 시 메뉴를 닫은 다음 해당 동작을 시작한다.

## 사용자 흐름

1. 문서 열람 권한이 있는 사용자가 상신된 문서 상세를 연다.
2. 더보기 메뉴에서 `참조자 추가하기`를 선택한다.
3. 기존 사용자 선택 UI에서 한 명 이상을 고르고 추가를 확정한다.
4. 서버가 문서 상태, 요청자의 문서 접근 권한, 선택 대상의 유효성을 검증하고 새 참조 참여자를 저장한다.
5. 성공 시 상세의 참조자 표시를 갱신한다. 새 참조자는 자신의 문서 목록 및 미확인 참조 목록에서 해당 문서를 볼 수 있다.
6. 실패 시 오류를 알리고 성공처럼 보이게 하지 않는다. 일부 사용자만 저장되는 부분 성공은 허용하지 않는다.

## 구성 및 데이터 흐름

- **더보기 메뉴 UI:** `DocumentActionsMenu`에 참조자 추가 동작을 추가하고 공유 작업과 문서 수정/삭제 작업을 구분선으로 분리한다. 기존 공유/수정/삭제 동작과 권한 판정은 유지한다.
- **참조자 선택 UI:** 현재 결재선 설정의 사용자 선택 패턴을 재사용하되, 상세 화면에서 선택과 확정을 완료한다. 이미 참여 중인 사용자는 추가 대상에서 제외하거나 선택 불가 상태로 보여 중복을 예방한다.
- **서비스/API:** 프론트엔드는 기존 전자결재 서비스 계층을 통해 선택 대상 사용자 목록을 서버로 전달한다. API 경로와 DTO는 기존 백엔드 계층/계약을 확인한 후 구현 계획과 상세 사양에서 확정한다.
- **서버 권한 및 저장:** 서버는 인증 정보에서 요청자를 식별하고 문서 읽기 권한과 상신 완료 상태를 검증한다. 선택 대상은 실제 사용자이며 같은 tenant에 속하고 활성 상태여야 한다. 검증 및 참여자 추가는 원자적으로 처리한다.
- **문서 접근 및 확인 대기:** 저장된 `REFERENCE` 참여자 행을 기존 권한 조회와 `MY_REFERENCE_PENDING` 조회가 사용하도록 한다. 별도의 문서 복제나 링크 권한 우회는 만들지 않는다.
- **데이터베이스:** 우선 기존 참여자 스키마를 재사용한다. 구현 전에 읽기 전용 DB MCP로 실제 테이블/컬럼/제약 및 문서 접근 쿼리를 확인한다. 스키마 변경이 필요한 것으로 확인될 때만 기존 날짜별 DB 변경·롤백 절차를 적용한다. 현 시점에서 신규 테이블/컬럼을 설계에 포함하지 않는다.

## 오류 처리 및 경계

- 문서가 없거나 삭제되었거나 임시저장 상태이거나 요청자가 열람 권한이 없으면 추가를 거부한다.
- 존재하지 않는 사용자, 다른 tenant 사용자, 비활성 사용자 및 현재 참여 중인 사용자는 서버 검증에서 거부하거나 중복 없이 제외한다. 한 요청의 처리 결과는 원자적이어야 하며 일부 대상자만 성공하는 결과를 반환하지 않는다.
- 동시 요청으로 동일 대상자가 중복 추가되지 않도록 서비스의 중복 검사와 현재 스키마 제약을 함께 확인한다.
- API 오류, 권한 오류, 저장 실패는 기존 문서 상세의 오류 표시 패턴으로 안내하고, 실패를 빈 성공 응답이나 성공 알림으로 변환하지 않는다.
- 추가 후 상세 화면의 참조자 목록 및 관련 사용자 문서 목록이 최신 상태가 되도록 재조회/갱신한다.

## 대안과 선택

1. **문서 열람 권한이 있는 사용자가 기존 참여자 모델에 참조자를 추가 — 선택.** 사용자 요구와 일치하며 기존 접근권한, 참조 확인, 대기 목록을 재사용한다. 문서별 별도 공유 권한이나 중복 모델을 만들지 않는다.
2. **기안자만 참조자를 추가.** 권한 관리가 단순하지만 “문서에 권한이 있는 모든 사용자”가 추가할 수 있다는 요구를 제한한다.
3. **별도의 문서 공유/ACL 모델을 추가.** 기존 참여자 외의 공유 정책까지 지원할 수 있지만 현재 요구에 비해 데이터 및 권한 모델을 불필요하게 확장한다.

## 제외 범위

- 임시저장 문서에서의 참조자 추가
- 기존 참조자 제거 및 결재선 수정
- 참조자에게 이메일/푸시/쪽지 알림 발송
- 별도 ACL, 공유 테이블, 문서 사본 또는 외부 링크 권한 부여
- 기존 참조 확인 동작 및 결재 상태 전이 변경

## 검증 기준

- 문서 접근 권한이 있는 사용자에게 상신 후 문서 상세의 참조자 추가 메뉴가 제공되고, 임시저장/삭제/접근 불가 문서에는 제공되지 않거나 서버에서 거부된다.
- 사용자 선택 UI에서 다중 선택할 수 있고, 잘못된 사용자와 다른 tenant 사용자 추가가 서버에서 거부된다.
- 참여자를 추가하면 상세의 참조자 표시가 갱신되며 추가 대상자의 기존 문서 조회와 미확인 참조 목록에서 즉시 문서가 보인다.
- 새 참조자의 확인은 기존 `REFERENCE` 확인 흐름을 따르고 결재 상태, 결재 단계, 결재 대기 수를 바꾸지 않는다.
- 기존 참여자를 다시 지정해도 중복 행이 생기지 않고 기존 상태가 보존된다. 동시 중복 요청도 무결성을 깨뜨리지 않는다.
- 여러 대상자 추가 중 저장 실패가 발생하면 부분적으로 추가되지 않는다.
- 더보기 메뉴가 `문서 공유하기`, `참조자 추가하기`와 구분선, 수정/삭제의 그룹 순서를 따르며 사용 불가 메뉴 조건은 기존처럼 유지된다. 빈 메뉴 그룹에 단독 구분선이 남지 않는다.
- 프론트엔드 서비스/컴포넌트와 백엔드 권한·저장·중복 처리에 대한 회귀 테스트를 추가한다. 필요한 브라우저 테스트는 375px, 768px, 1280px에서 확인하고 실제 화면 변경이 있다면 결과 문서와 스크린샷을 남긴다.
