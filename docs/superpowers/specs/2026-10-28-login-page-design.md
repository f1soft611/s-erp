# 로그인 페이지 디자인 개선 설계

## 상태

사용자가 기존 카드형을 깔끔하게 개선하는 방향으로 진행을 승인했다. 이 문서는 디자인 기준이며, 구현은 문서 검토 및 계획 수립 이후 시작한다.

## 목표와 범위

- 기존 로그인 동작과 입력 항목을 유지하면서 시각적 위계, 간격, 표면 대비를 정돈한다.
- 데스크톱과 모바일에서 안정적으로 보이는 단일 로그인 카드 레이아웃을 유지한다.
- 변경 범위는 프론트엔드 로그인 화면과 관련 스타일 및 문서화로 제한한다.
- 인증 API, 필드명, 로그인 후 라우팅, 검증 규칙은 변경하지 않는다.

## 제안 디자인

- 전체 화면은 현재 테마를 반영한 밝고 차분한 중립 배경으로 구성하고, 배경의 블루 포인트는 은은하게 제한한다.
- 중앙 로그인 카드는 기존 브랜드 색상과 조화를 이루는 흰색/다크 표면, 얇은 경계선, 절제된 그림자를 사용한다. 화면을 가득 채우는 강한 그라데이션과 과도한 장식은 피한다.
- `S-ERP` 브랜드 표식, 로그인 제목, 짧은 안내 문구를 명확한 위계로 배치한다. 제목은 한눈에 읽히게 하고 설명은 보조 색상으로 처리한다.
- 업체코드, 사용자 ID, 비밀번호 라벨은 각 입력 위에 고정 배치해 필드의 목적을 빠르게 알아볼 수 있게 한다. 입력 텍스트는 18px로 키우고 입력 높이는 약 56px로 맞춘다.
- 각 TextField의 기본 위아래 margin을 제거하고 필드 사이의 간격을 명시적으로 조정한다. 불필요한 여백을 줄이되 필드 그룹은 읽기 쉽게 분리한다.
- 포커스와 오류 상태는 기존 테마의 primary/error 색상으로 분명히 구분한다. 기존 helper text의 오류 메시지는 유지한다.
- 로그인 버튼은 카드 너비에 맞추고 primary 색상을 사용한다. 기존 제출 중 비활성/로딩 표시를 유지한다.
- 개발 환경 테스트 계정은 기존 DEV 조건을 유지하고, 계정/비밀번호 정보를 시각적으로 강조하지 않는 작은 보조 안내로 배치한다.
- 세션 만료 알림, 로그인 실패 메시지, 입력 검증, 비밀번호 표시 버튼, 저작권 표시는 현재의 조건과 동작을 유지하면서 카드와 시각적으로 조화를 이루게 한다.
- 라이트/다크 테마 모두에서 텍스트 대비와 입력 상태를 유지한다.

## 반응형 동작

- 1280px 이상에서는 카드가 화면 중앙에 놓이고 불필요하게 넓어지지 않는다.
- 768px 및 375px에서는 카드가 화면 여백 안에서 유동적으로 줄어들며, 입력·버튼·알림 텍스트가 잘리거나 가로 스크롤을 만들지 않는다.
- 작은 화면에서는 화면 높이가 짧거나 개발 안내가 표시되어도 페이지를 세로로 스크롤할 수 있어야 한다.

## 동작 및 데이터 흐름

기존 `LoginPage`와 `useLoginForm`의 제출 흐름을 그대로 사용한다. `LoginForm`은 기존 테넌트 코드, 사용자 ID, 비밀번호 값을 받아 제출하고, `authService` 호출 성공 시 기존 홈 경로로 이동한다. 디자인 변경을 위해 인증 상태, API 계약, 세션 저장 방식을 새로 만들지 않는다.

## 오류 처리 및 접근성

- 서버 로그인 실패와 세션 안내는 기존 메시지를 화면에서 식별 가능하게 유지한다.
- 고정 라벨은 실제 입력 요소와 `htmlFor`/`id`로 연결한다. 필드 오류는 해당 입력과 연관되어 표시되고, 포커스 표시 및 비밀번호 표시 버튼의 접근 가능한 이름을 유지한다.
- 색상만으로 오류를 전달하지 않고 기존 오류 문구를 함께 표시한다.
- 테마별 텍스트/배경 대비를 확인하고 키보드 조작 가능한 폼 순서를 유지한다.

## 영향 범위 및 검증

- 주요 대상: `frontend/src/shared/components/layout/AuthLayout.tsx`, `frontend/src/pages/auth/components/LoginForm.tsx`, `frontend/src/shared/components/LoginFormField.tsx`, 관련 로그인 테스트.
- 검증은 프론트엔드 로그인 관련 테스트와 빌드를 수행하고, 실제 브라우저에서 라이트/다크 테마 및 375px, 768px, 1280px 뷰포트를 확인한다.
- 결과 문서에는 변경 사항, 검증 결과, 스크린샷을 기록한다.
- 로그인 기능/API와 무관한 리팩터링은 범위에서 제외한다.
