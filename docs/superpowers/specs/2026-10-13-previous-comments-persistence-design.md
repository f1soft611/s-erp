# 이전 댓글 상태 유지 및 남은 댓글 수 설계

## 목표

공지사항과 전자결재 모두 이전 댓글을 한 번 펼친 뒤 댓글이나 답글을 등록해도 전체 로드 댓글 목록을 유지하고, 새 댓글을 현재 목록에 반영한다. 이전 댓글 버튼에는 아직 불러오지 않은 이전 댓글 수를 표시한다.

## 확인된 문제와 원인

전자결재 댓글 등록 핸들러는 서버 저장 후 기본 댓글 목록 로드(`loadComments()`)를 호출한다. 기본 로드는 첫 페이지를 다시 가져와 현재 목록과 이전 페이지 커서를 덮어쓴다. 이전 댓글을 펼쳐 둔 상태라도 새 댓글 등록 후에는 처음의 일부 댓글만 남고 이전 댓글 버튼이 다시 나타난다.

공지사항은 화면 로컬 상태와 서버 항목의 댓글 변경을 함께 반영하므로, 댓글/답글 등록 뒤 기존에 펼친 댓글 상태가 유지되는지 동일한 시나리오로 회귀 검증하고 공통 버튼 카운트를 적용한다.

## 승인된 동작

- 공지사항·전자결재의 이전 댓글 보기를 통해 기존 페이지를 불러온 상태에서 댓글 또는 답글을 등록하면, 이미 로드된 전체 댓글을 유지하고 새 댓글을 최신 댓글 위치에 추가한다.
- 등록 성공은 첫 댓글 페이지 재조회로 처리하지 않는다. 이미 사용자가 펼쳐 둔 상태와 이전 페이지 커서를 유지하며, 실패 시 목록/개수/커서 상태를 바꾸지 않는다.
- 아직 불러오지 않은 댓글 수를 공통 이전 댓글 버튼에 `이전 댓글 보기 (N)`으로 표시한다.
- 남은 수는 전체 댓글 수와 현재 로드된 댓글 수의 차이를 0 이상으로 계산한다. 이전 페이지를 읽으면 감소하며, 새 댓글/답글 등록 시 전체 댓글 수와 로드 수가 함께 증가하므로 남은 이전 댓글 수는 변하지 않는다.
- 카운트에 필요한 데이터가 없으면 숫자 없이 기존 버튼을 표시한다. 전자결재 시스템 이벤트는 사용자 댓글 카운트에 포함하지 않는다.
- 기존 댓글 정렬, 페이지네이션, 작성/답글 처리, 권한, 오류 알림 동작을 유지한다.

## 구현 경계

- 공통 이전 댓글 버튼의 레이블과 카운트 UI는 `FeedCommentsSection`에서 관리한다.
- 댓글 데이터, 로드 완료 상태, 전체 카운트, 페이지 커서는 각 기능 컴포넌트/훅에 유지한다.
- 댓글 등록 후 현재 화면 데이터를 일관되게 갱신하되, 이전 페이지 로드 상태를 초기화하지 않는다.
- API 및 DB 계약은 변경하지 않는다.

## 검증 기준

- 공지사항·전자결재에서 이전 댓글을 불러온 뒤 댓글과 답글을 등록해도 이미 보이던 이전 댓글이 그대로 남고 새 글이 기존 순서의 최신 위치에 표시된다.
- 기존 페이지 커서/남은 이전 댓글 카운트가 댓글 등록 때문에 초기화되지 않는다.
- 이전 페이지를 추가 로드하면 버튼 카운트가 로드된 수만큼 감소하고, 더 읽을 페이지가 없으면 버튼이 사라진다.
- 댓글 최초 진입, 등록/수정/삭제, 답글, 이전 댓글 로딩 오류 등 기존 동작이 유지된다.
- 관련 Vitest, 프론트엔드 빌드, 실제 브라우저의 좁은 화면과 데스크톱 화면을 검증한다.

## 제외 범위

- 백엔드, API, DB 계약 변경
- 댓글 페이지 크기, 정렬, 권한, 작성/수정/삭제 정책 변경
- 댓글 목록의 기존 순서나 답글 표시 방식 변경
