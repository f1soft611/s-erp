# 전자결재 공지사항형 피드 및 상세 패널 설계

## 목적

문서작업공간의 목록 선택 및 피드 보기 동작을 공지사항과 같은 피드/우측 상세 패널 흐름으로 제공한다. 문서 본문, 이미지, 첨부, 사용자 댓글은 공지사항 수준의 사용성을 제공하되 전자결재의 상태 전이와 권한 규칙은 그대로 유지한다.

## 결정 근거

- 기존 전자결재 작업지시서와 상세 사양은 문서 항목 선택 시 상세 모달을 열도록 정의했다.
- 사용자는 이를 수정하여, 목록 선택 결과를 공지사항처럼 페이지 우측의 상세 패널 피드로 표시하고 좌측 피드 보기 또한 공지사항 피드와 같은 형태로 표시하도록 요청했다.
- 사용자는 문서 본문/이미지/첨부 및 댓글·대댓글 작성, 본인 댓글 수정·삭제, 댓글 첨부/이미지를 포함하도록 승인했다.
- 사용자는 공지사항의 공감·북마크·고정 기능은 문서에 적용하지 않고 전자결재 권한 규칙을 유지하는 안을 선택했다.
- 사용자는 공지사항 화면의 기존 패턴을 재사용하면서 문서 전용 UI를 분리하는 접근을 승인했다.

## 화면 동작

### 목록 보기

- 기존 문서 목록, 필터, 요약 카드 및 문서 유형 필터는 유지한다.
- 목록 행을 선택하면 모달 대신 `PageAreaOverlay` 안에 `PostDetailPanel` 패턴의 문서 상세 패널을 연다. 패널은 공지사항과 같이 페이지 콘텐츠의 오른쪽에 배치한다.
- 상세 패널 닫기 버튼, 패널 바깥 영역 클릭 및 `Escape` 키는 선택 상태를 해제하고 이전 문서 목록으로 돌아간다.
- 패널이 닫히면 기존 요약 카드가 다시 표시된다. 상세 패널을 여는 동안 좌측 목록 상태와 선택된 필터/보기 모드를 보존한다.

### 피드 보기

- `PinnedViewToolbar`의 기존 피드/리스트 전환을 유지한다. 고정 문서 저장이나 고정/해제 기능은 만들지 않는다.
- 피드 모드는 공지사항 피드 카드와 같은 반복형 카드 레이아웃을 사용한다.
- 카드에는 기안자, 작성/상신 시각, 문서 유형, 결재 상태, 제목, 본문 미리보기와 표시 가능한 이미지/첨부/댓글 정보를 나타낸다.
- 카드를 선택하면 목록 보기와 동일한 우측 상세 패널을 연다.
- 관련 문서 목록 및 피드 전환 후 로딩/빈 결과/오류 상태는 실제 API 응답과 구별되게 유지한다.

## 상세 피드 내용과 동작

- 헤더에는 문서 제목, 기안자, 작성 또는 상신 시각, 문서 번호 및 상태를 표시한다.
- 저장된 본문 HTML은 기존 본문 안전 처리 규칙을 따른다. 전자결재 이미지 API를 통해 권한이 있는 참여자에게 이미지가 표시되며, 임시 업로드 URL이나 upload token은 노출하지 않는다.
- 일반 첨부파일은 기존 승인 문서 첨부 계약을 사용해 목록과 다운로드를 제공한다.
- 현재 결재선의 순서/합의 단계, 각 참여자의 진행 상태와 사유, SYSTEM 이벤트 타임라인을 별도로 표시한다.
- 사용자 댓글은 시스템 이벤트와 구분한다. 댓글·대댓글의 작성, 기존 UI 계약이 제공하는 댓글 수정/삭제, 댓글 첨부 업로드 및 이미지 표시/다운로드를 제공한다.
- 문서 참여자(기안자, 결재자, 합의자, 참조자)만 상세/댓글/파일을 조회할 수 있다. 참여자는 문서에 댓글을 작성할 수 있고, 수정/삭제는 공통 댓글 기능의 작성자 권한을 따른다. 참조자에게 결재 처리 권한을 부여하지 않는다.
- 승인/반려/보완요청은 현재 활성 처리자에게만 표시/허용한다. 반려·보완요청 사유 필수, 승인 사유 선택, 기안자의 초안/보완요청 문서 편집 및 재상신 규칙을 보존한다.
- 공감, 북마크, 문서 고정은 제외한다. 공지사항의 게시글 수정/삭제 동작도 문서에 복사하지 않는다.

## 컴포넌트 및 데이터 경계

- 공지사항의 `PageAreaOverlay`, `PostDetailPanel`, `ContentSplitLayout`, `FeedView`/`ListView` 패턴을 활용한다.
- 전자결재 문서 feed card와 approval detail feed는 문서 도메인 전용 컴포넌트로 둔다. 공지사항 전용 `NoticeFeedList`를 문서 데이터 어댑터로 직접 재사용하지 않는다.
- 공통 `AttachmentList` 및 `CommentThread`의 기존 표현/편집 흐름은 재사용한다.
- 피드 카드의 본문/이미지 미리보기 데이터는 목록 응답에서 효율적으로 제공한다. 각 목록 카드마다 상세 API를 반복 호출하는 N+1 조회는 만들지 않는다.
- 상세 선택 시 문서 상세, 결재선, 시스템 이벤트, 첨부 및 사용자 댓글을 로딩하며 진행/오류 상태를 표시한다. 상세 데이터를 가져오지 못한 경우 성공 또는 빈 타임라인처럼 표현하지 않는다.
- 기존 전자결재 문서와 시스템 이벤트 저장 계약은 유지한다. 사용자 댓글은 `tb_common_comment`의 USER 댓글 경로 및 owner type `APPROVAL`을 재사용할 수 있는지 검증한다.
- 기존 공통 댓글/파일 API가 전자결재 소유자에 대해 충분한 tenant·참여자 검증을 하는지 구현 전에 검사한다. 검증이 없으면 승인 도메인 서비스에 위임하는 방식으로 API를 보완한다. 클라이언트가 보내는 owner/user 식별자를 권한 근거로 신뢰하지 않는다.
- 댓글 첨부 및 본문 이미지의 저장/다운로드 권한도 문서 참여자 검증과 일치시킨다.
- 스키마 변경은 요구사항으로 선결정하지 않는다. PostgreSQL read-only MCP와 기존 mapper/schema를 확인한 후 필요성이 입증된 경우에만 승인된 날짜별 migration/롤백 절차를 따른다.

## 반응형 동작

- 데스크톱에서는 공지사항과 같은 우측 도킹 패널을 제공하고, 목록/피드의 좌측 상태를 유지한다.
- 모바일에서는 기존 `PageAreaOverlay` 패턴처럼 상세 패널이 사용 가능한 너비 전체를 차지한다.
- 375px, 768px, 1280px에서 페이지 전체 가로 overflow, 잘림, 겹침 없이 피드와 상세 내용이 동작하는지 브라우저로 검증한다.

## 검증 기준

- 목록 행 선택은 상세 dialog가 아니라 우측 `PageAreaOverlay`/상세 패널을 열고, close/backdrop/Escape 동작으로 선택을 해제한다.
- 좌측 피드 전환은 공지사항과 같은 카드 피드를 표시한다. 카드 선택도 동일한 상세 패널을 연다.
- 필터, 선택 문서, 보기 모드는 상세 열고 닫은 뒤 보존된다.
- 본문 이미지, 첨부파일, 댓글/대댓글과 댓글 첨부/이미지의 로딩·오류·표시·다운로드 동작을 검증한다.
- 시스템 이벤트는 USER 댓글과 구분하고, 공감/북마크/고정 또는 게시글 편집/삭제를 노출하지 않는다.
- 결재 액션은 기존 활성 처리자/상태 규칙을 만족하는 경우에만 제공되고 서버에서도 동일하게 검증된다.
- 비참여 사용자와 다른 tenant 사용자의 문서, 댓글, 댓글 파일, 문서 첨부 및 본문 이미지 접근은 차단된다.
- 리스트/상세 대량 조회가 항목별 반복 호출로 확장되지 않는지 확인한다.
- 관련 Vitest, 백엔드 controller/service/mapper 테스트, frontend build 및 실제 브라우저 375/768/1280px 검증을 수행한다. 결과와 스크린샷은 `docs/result/20261012/document-approval-workspace/`에 둔다.

## 범위 조정

이 설계는 이전 상세 사양의 “상세 모달” 표시 요구를 우선시했던 부분을 대체한다. 공감·북마크·고정은 계속 제외하며, 사용자 댓글 기능은 이번 변경에서 포함한다. 기존 결재 신청/처리 API와 순차 결재 상태 전이는 UI 변경을 이유로 완화하지 않는다.
