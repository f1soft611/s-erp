# 댓글 첨부 이미지 분리 미리보기 설계

## 목표

문서작성과 공지작성의 댓글 및 답글에서 이미지 첨부의 파일 항목과 이미지 미리보기를 분리한다. 첨부 영역은 파일 목록으로 유지하고, 이미지 미리보기는 그 아래에 표시해 본문 이미지처럼 클릭하여 크게 볼 수 있도록 한다.

## 범위

- 문서 피드의 댓글 및 답글
- 공지 피드의 댓글 및 답글
- 현재 표시 중인 기존 댓글·답글과 새 댓글·답글
- 첨부파일 목록의 이미지 썸네일 제거
- 별도 이미지 미리보기 영역과 기존 확대 뷰어 연결

이전 댓글을 미리보기 목적으로 추가 조회하지 않는다. 댓글 첨부 저장/업로드/API 데이터 계약, 권한, 본문 이미지 렌더링, DB 스키마는 변경하지 않는다.

## 현재 상태

- 공통 `TiptapCommentThread`는 댓글 첨부를 `AttachmentList`로 렌더링한다.
- `AttachmentList`는 이미지 MIME 정보와 Blob URL이 있는 파일의 작은 미리보기를 파일 항목 안에 표시한다.
- 문서 댓글 화면은 댓글 이미지 Blob을 인증 경로로 받아 object URL을 생성하고, 댓글 표시 모델에 MIME 정보와 미리보기 URL을 전달한다.
- 공지 댓글 어댑터는 댓글 첨부를 `id`, `name`, `size`로 정규화하면서 MIME 정보를 보존하지 않는다. 공지 화면에는 본문 이미지용 확대 뷰어가 이미 있다.
- 본문 이미지 미리보기는 가로 방향 썸네일 영역을 제공하고 클릭 시 공통 `ImageViewerDialog`를 연다.

## 선택한 접근

공통 댓글 컴포넌트에서 이미지 첨부를 별도 영역으로 표시하고, 페이지별 댓글 화면이 준비된 이미지 URL과 확대 뷰어 콜백을 제공한다.

검토한 대안:

1. **공통 댓글 컴포넌트에서 분리 표시 — 선택**: 두 화면의 댓글 UI와 동작을 일관되게 유지한다. 공지와 문서의 인증된 이미지 로딩 차이는 각 화면의 어댑터/서비스 경계에서 처리한다.
2. **문서·공지 화면별 구현**: 기존 화면별 코드에 맞추기 쉽지만 이미지 목록, 접근성, 확대 연결이 중복되어 동작이 달라질 수 있다.
3. **공통 첨부목록에서 이미지 갤러리까지 처리**: 변경 지점은 한 곳이지만, 파일 목록 컴포넌트가 댓글 전용 갤러리와 뷰어 책임까지 갖게 되어 다른 첨부 사용처에 불필요한 영향을 준다.

## 화면 동작

- 이미지 파일을 포함한 모든 첨부는 첨부 목록에 파일명, 파일 아이콘, 기존 다운로드/삭제 동작으로 표시한다.
- 댓글 보기 상태의 첨부 목록 내부에는 이미지 썸네일을 표시하지 않는다.
- 첨부 목록 아래에는 MIME 유형이 이미지인 파일만 별도 미리보기 영역에 표시한다.
- 미리보기 크기와 썸네일 표현은 `FeedBodyContent`의 본문 이미지 미리보기와 같은 기준을 따른다. 각 썸네일은 키보드로 접근 가능한 버튼으로 제공한다.
- 썸네일 클릭은 해당 이미지의 `src`와 대체 텍스트로 페이지의 기존 `ImageViewerDialog`를 연다.
- 편집 상태의 파일 목록, 업로드·삭제·다운로드 흐름은 유지한다.
- 댓글과 답글의 기존 페이지네이션·접기 동작은 유지하고, 이미 현재 화면에 로드되어 표시되는 댓글만 미리보기한다.

## 데이터 흐름과 책임

- 공통 댓글 UI는 파일 목록, 별도 이미지 미리보기, 클릭 콜백을 렌더링한다. 인증이나 API 라우트를 직접 결정하지 않는다.
- 문서 화면은 기존 댓글 이미지 Blob 조회와 object URL 생성 흐름을 재사용한다.
- 공지 어댑터는 서버 파일의 MIME 유형을 댓글 첨부 UI 모델까지 전달한다.
- 공지 화면의 이미지 조회는 기존 인증된 공통 파일 다운로드 경로를 Blob 조회 용도로 재사용한다. 필요한 서비스 함수가 없으면 공통 파일 서비스에 최소 범위로 추가한다.
- 두 화면은 Blob object URL을 폐기 시 해제한다. 비동기 조회는 화면/댓글이 교체되었을 때 오래된 결과가 상태를 갱신하지 않도록 한다.
- 이미지 조회 실패 시 이미지 파일 항목과 다운로드는 유지하고, 해당 미리보기 실패를 사용자에게 표시한다. 실패를 성공으로 처리하거나 조용히 숨기지 않는다.

## 오류 및 호환성

- 첨부파일 목록은 이미지 Blob 조회가 실패해도 기존 동작을 유지한다.
- 공지 댓글에 기존에 저장된 파일의 MIME 정보가 없으면 해당 파일을 이미지로 추정하지 않는다.
- 기존 본문 이미지 확대, 댓글 작성/수정/삭제, 답글, 댓글 더 보기, 파일 다운로드/삭제 동작은 그대로 유지한다.
- API 저장 응답과 DB 계약을 변경하지 않는다.

## 검증

- 공통 댓글 UI 테스트: 이미지 첨부가 일반 파일 항목으로 남고, 첨부 목록에 썸네일이 없으며, 별도 영역에는 이미지 파일만 표시되는지 확인한다.
- 상호작용 테스트: 썸네일 클릭이 정확한 이미지와 대체 텍스트를 확대 뷰어 콜백에 전달하는지 확인한다.
- 문서 댓글 테스트: 기존 Blob URL 연결과 URL 정리를 확인한다.
- 공지 댓글 테스트: MIME 정보 보존, 인증된 Blob 경로, 로드 실패 안내 및 URL 정리를 확인한다.
- 기존 첨부 편집/다운로드/삭제 및 본문 이미지 회귀 테스트를 수행한다.
- 관련 테스트와 프론트엔드 빌드를 실행하고 375px, 768px, 1280px 브라우저 화면을 검증한다.
