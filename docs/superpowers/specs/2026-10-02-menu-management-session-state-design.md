# 메뉴관리 조회조건 세션 보존 설계

## 배경

메뉴관리 화면의 모듈, 권한, 검색어는 컴포넌트 로컬 state라 페이지를 벗어나 다시 진입하면 초기화된다. 공통코드 관리의 페이지 세션 패턴을 재사용해 사용자가 마지막으로 보던 조회 조건을 로그인 세션 동안 복원한다.

## 목표

- 메뉴관리 재진입 시 모듈, 권한, 검색어를 복원한다.
- 저장된 모듈과 권한이 유효할 경우 해당 조합의 메뉴를 다시 조회한다.
- 기존 조회, 필터, 미저장 변경 확인, 저장 동작과 API 계약을 유지한다.

## 상태 계약

페이지 key는 `s-erp:page:menu-management`이며 `usePageSessionState`와 버전 envelope를 사용한다.

```ts
type MenuManagementPageSession = {
  selectedModuleId?: number;
  selectedRoleId: string;
  searchQuery: string;
};
```

초기 상태는 선택 모듈 미지정, 빈 권한 ID, 빈 검색어다. 상태 검증은 선택 모듈이 없거나 유효한 숫자이고, 권한 ID와 검색어는 문자열인지 확인한다. 세션 버전이 맞지 않거나 데이터가 잘못된 경우 공통 훅이 저장 값을 초기화한다.

## 복원 흐름

1. 화면 진입 시 모듈 목록과 권한 정의를 가져온다.
2. 권한 목록을 가져온 뒤 저장된 모듈 ID와 권한 ID가 각각 현재 목록에 존재하는지 검증한다.
3. 유효한 저장 모듈은 선택하고, 유효하지 않으면 기존 초기화 규칙대로 첫 번째 모듈을 선택한다.
4. 유효한 저장 권한만 복원한다. 권한이 없거나 유효하지 않으면 빈 값으로 두며, 모듈과 권한이 모두 유효할 때만 메뉴 목록을 조회한다.
5. 저장된 검색어는 옵션 목록 및 메뉴 데이터 로드와 별개로 입력 상태에 복원한다. 메뉴 필터는 기존 `filteredMenus` 로직을 사용한다.
6. 사용자가 모듈, 권한 또는 검색어를 변경하면 페이지 세션 상태를 갱신한다.

기존 `dirty` 보호 및 변경 확인 절차를 우회하지 않는다. 데이터 오류 시 기존 오류 처리를 사용한다. 복원 상태는 조회 조건일 뿐, 미저장 편집 내용의 복구를 약속하지 않는다.

## 제외 범위

- 선택된 메뉴 행 및 트리 펼침 상태
- 삽입/수정/삭제된 F1-Grid 행과 기타 미저장 편집 내용
- localStorage 또는 백엔드 영구 저장
- 검색 동작, 데이터 계약, F1Tree 공통 API 변경

## 검증 기준

- 상태 계약의 유효/무효 입력을 단위 테스트로 검증한다.
- 메뉴관리 화면에서 세션 상태 복원, 복원된 모듈·권한의 조회 호출, 존재하지 않는 ID의 기본값 처리를 통합 테스트로 검증한다.
- 기존 메뉴관리 조회/미저장 변경 확인 테스트와 프론트엔드 빌드를 실행한다.
