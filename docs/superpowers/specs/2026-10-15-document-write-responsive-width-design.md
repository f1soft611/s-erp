# 문서작성 상세 패널 반응형 너비 설계

## 목표

375px 모바일 화면에서 문서 상세 패널이 페이지 영역 밖으로 잘리거나 문서작성 페이지가 가용 너비보다 넓어지는 현상을 막는다. 상세 패널은 기존처럼 공통 헤더 아래 문서작성 페이지 내부에 표시한다.

## 근거 및 원인 가설

- 기존 페이지 영역 오버레이 상세 사양은 375px에서 가로 스크롤이 없어야 하고, 오버레이가 페이지 영역을 벗어나지 않아야 한다고 정의한다.
- `DocumentWritePage`는 `flex: 1`, `position: relative`, `overflow: hidden`을 가진 페이지 호스트이며 상세 오버레이의 containing block이다.
- 현재 페이지 호스트에는 `minWidth: 0`이 없다. 상위 Dashboard의 콘텐츠 flex item은 `minWidth: 0`을 사용하지만, 페이지 호스트 자체가 내부 콘텐츠의 최소 너비를 전달할 수 있다.
- 저장된 375px 화면에서 상세 패널 오른쪽이 잘린 것을 확인했다. 인증된 브라우저 화면이 현재 로그인 페이지로 리다이렉트되어 DOM 치수는 재측정하지 못했으므로, flex 최소 너비가 원인인지는 수정 후 브라우저 검증으로 확인한다.

## 확정 설계

- `DocumentWritePage` 루트에 `minWidth: 0`을 추가해 상위 대시보드 콘텐츠 너비 안에서 flex item이 축소될 수 있게 한다.
- 페이지 오버레이와 결재 상세 패널의 배치·너비 규칙은 변경하지 않는다. 오버레이는 계속 문서작성 페이지 루트를 기준으로 우측에 표시한다.
- 메뉴 레일, 앱 셸, 공지 페이지 및 공통 `PageAreaOverlay`는 변경하지 않는다.
- 상세 데이터, API, 권한, 결재 동작 및 패널의 닫기 동작은 변경하지 않는다.

## 검증 설계

- 문서작성 페이지 통합 테스트에서 루트가 `min-width: 0` 스타일을 제공하는지 검증한다.
- 변경 전후 집중 테스트와 프론트엔드 빌드를 실행한다.
- 가능하면 인증된 실제 브라우저에서 375px, 768px, 1280px을 확인한다. 특히 페이지 호스트와 패널의 bounding box가 뷰포트를 넘지 않고 문서 전체의 `scrollWidth`가 `innerWidth` 이하인지 확인한다.
- 인증된 브라우저를 사용할 수 없으면 해당 제한을 결과 문서에 명시하고, 확인하지 않은 브라우저 동작을 통과로 기록하지 않는다.

## 대안 및 절충

- `DashboardContent` flex 경계를 바꾸는 방법은 모든 페이지에 적용되어 범위가 넓으므로 선택하지 않는다.
- 공통 `PageAreaOverlay`를 뷰포트 고정형으로 바꾸는 방법은 페이지 콘텐츠 내부에만 표시한다는 기존 계약을 변경할 수 있으므로 선택하지 않는다.
- 문서작성 루트만 최소 너비를 재설정하는 방안은 기존 상위 앱 셸 및 페이지 오버레이 구조를 보존하면서 요청 화면을 제한적으로 수정한다.
