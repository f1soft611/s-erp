# 반려 사유 메시지 아이콘 표시 설계

## 목표

전자결재 상세 결재선의 반려 사유를 도장 아래에 항상 텍스트로 표시하는 대신, 반려 도장에 작은 메시지 아이콘을 표시하고 사용자가 클릭할 때 사유를 확인할 수 있게 한다. 기존 상세 API와 결재선 데이터 계약은 유지한다.

## 승인된 화면 동작

- 결재선의 `REJECTED` 참여자에게 `actionComment`가 비어 있지 않을 때만 메시지 아이콘을 표시한다.
- 메시지 아이콘은 반려 도장 영역의 오른쪽 위에 작게 겹쳐 배치한다. 도장과 카드의 기존 크기 및 결재선 순서는 유지한다.
- 아이콘은 접근성 이름이 있는 버튼으로 구현한다. 클릭 또는 키보드 활성화 시 해당 버튼을 기준으로 반려 사유 팝오버를 연다.
- 팝오버에는 해당 결재선의 `actionComment` 전문을 표시하고 긴 사유는 줄바꿈한다. 바깥 영역 클릭과 Escape 키로 닫는다.
- `REJECTED` 사유는 도장 아래에 직접 렌더링하지 않는다. 사유가 없으면 메시지 아이콘도 표시하지 않는다.
- 반려 이외 상태의 기존 의견 표시는 유지한다.
- API, 응답 타입, 데이터 저장, 결재 처리 상태 전이는 변경하지 않는다.

## 검토한 대안

1. **도장 오른쪽 위 겹침 (승인)**: 결재 카드 크기를 유지하면서 아이콘이 반려 도장에 속한 메시지임을 바로 알 수 있다. 아이콘이 도장을 가리지 않도록 작은 크기와 배치를 적용한다.
2. **도장 옆 배치**: 도장을 가리지 않지만 카드 안쪽 여유가 줄어든다.
3. **도장 아래 별도 행**: 위치가 분명하나 카드 높이를 늘리고 기존 결재선 흐름을 흔들 수 있다.

사용자는 브라우저 시안에서 첫 번째 배치를 선택했다. 반려 사유를 도장 옆 팝오버로 보여주는 방식도 선택했다.

## 데이터 흐름 및 오류 처리

1. 기존 상세 응답의 `approvalLines`에서 각 반려선의 `actionComment`를 읽는다.
2. 유효한 사유가 있는 반려선에만 메시지 버튼을 렌더링한다.
3. 버튼을 누르면 버튼에 연결된 결재선 사유를 앵커 팝오버에 표시한다.
4. 팝오버는 기존 MUI 레이어 동작을 이용해 바깥 클릭과 Escape 키로 닫는다. 별도 요청이나 지연 조회는 없다.
5. 사유가 없으면 조용히 생략하며, API/화면의 다른 오류 처리 방식은 변경하지 않는다.

## 범위 제외

- 백엔드 API, 결재선 타입, DB, 사유 저장/수정 동작 변경
- `RETURNED` 또는 `APPROVED` 상태의 의견 표현 변경
- 결재선 카드 레이아웃·크기·순서의 전반적 변경
- 기존 결재 승인/반려 권한과 상태 전이 변경

## 검증 기준

- 반려 사유가 있을 때 메시지 아이콘이 표시되고, 사유 텍스트는 도장 아래에 직접 노출되지 않는다.
- 아이콘 클릭과 키보드 활성화로 해당 반려 사유 팝오버가 열린다. 바깥 클릭 및 Escape로 닫힌다.
- 사유가 없으면 아이콘이 표시되지 않는다.
- 반려 이외 상태의 기존 의견 표시가 유지된다.
- 좁은 화면에서도 아이콘이 도장 또는 카드 경계를 부자연스럽게 덮지 않는다.
- 관련 Vitest, 프론트엔드 빌드 및 375px/768px/1280px 실제 브라우저 확인을 수행한다.
