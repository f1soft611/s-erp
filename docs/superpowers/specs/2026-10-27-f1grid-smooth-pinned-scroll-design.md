# F1-Grid 고정 컬럼 스크롤 자연스러움 개선 설계

## 배경

컬럼을 고정한 뒤 가로 스크롤할 때 헤더와 고정 컬럼 경계가 스크롤을 뒤따라 조정하는 것처럼 보여 움직임이 부자연스럽다. 현재 헤더와 본문은 별도 가로 스크롤 영역이며, 본문 `scrollLeft`를 헤더에 동기화한다. 동시에 본문 스크롤 위치와 viewport 정보를 requestAnimationFrame으로 React 상태에 반영해 열 가상화 계산에 사용한다. 고정 컬럼의 헤더/셀은 CSS `position: sticky`로 표시한다.

## 목표

- 고정 컬럼과 헤더가 본문 스크롤을 따라갈 때 눈에 띄는 지연, 떨림, 선 위치 변화가 없게 한다.
- 고정 컬럼의 기존 sticky 배치와 헤더/본문 끝단 정렬을 유지한다.
- 스크롤 위치가 실제 표시 열 집합을 바꾸지 않는 동안 불필요한 React 렌더를 줄인다.

## 비목표

- 고정 컬럼의 모양, 그림자, 선 스타일 또는 고정/해제 UX 변경
- 헤더와 본문 스크롤 영역의 레이아웃 전면 통합
- 스크롤 애니메이션이나 부드러운 스크롤 전환 추가
- 백엔드/API/DB 변경

## 검토한 접근

1. **본문을 단일 스크롤 기준으로 두고 렌더 상태 갱신을 필요한 경우로 제한 (추천)**  
   본문의 네이티브 스크롤을 유지하고 헤더는 현재처럼 즉시 동기화한다. 별도로 React가 추적하는 수평 위치는 열 가상화 창이 바뀌어야 할 때만 반영해, 픽셀 단위 스크롤마다 그리드 전체가 갱신되는 비용을 줄인다. 현 레이아웃과 sticky 구현을 보존하면서 체감 지연의 원인이 될 수 있는 렌더 부하를 낮춘다.
2. **헤더/본문을 하나의 스크롤 컨테이너로 통합**  
   동기화 자체를 없앨 수 있지만 헤더 sticky, 세로 스크롤, 스크롤바 gutter, 가상화 레이아웃을 함께 바꿔야 하므로 회귀 범위가 크다.
3. **고정 컬럼에 별도 transform 애니메이션 적용**  
   시각적 보정처럼 보일 수 있으나 실제 스크롤과 표시 위치 사이에 지연을 만들고 헤더/셀 경계를 어긋나게 할 수 있어 선택하지 않는다.

## 제안 설계

- 본문은 수평 스크롤의 기준으로 유지한다. 헤더 동기화는 브라우저의 네이티브 스크롤 이벤트 경로에서 즉시 반영하고, 서로의 `scrollLeft`가 이미 같을 때는 다시 쓰지 않아 이벤트 되먹임을 방지한다.
- 수평 스크롤 좌표를 React 상태로 반영하는 이유는 열 가상화 창 계산이다. 가상화가 비활성화된 그리드에서는 수평 스크롤만으로 viewport React 상태를 갱신하지 않는다. 가상화가 활성화된 경우에도 실제 표시 열 인덱스 집합이 바뀔 때만 렌더 상태를 갱신한다.
- 세로 스크롤에 필요한 행 가상화와 셀 범위 overlay 갱신은 기존 경로를 보존한다. viewport 크기와 세로 스크롤바 gutter 측정 및 헤더 오른쪽 여백 보정도 유지한다.
- 컬럼 고정 오프셋은 스크롤 프레임마다 재계산하거나 애니메이션하지 않는다. 현재 `position: sticky`와 고정 열 레이어 스타일을 유지한다.

## 검증 기준

- 고정 열이 있는 상태에서 가로 스크롤 중 헤더와 본문 열 경계가 계속 정렬되고, 고정 열 위치가 흔들리거나 뒤늦게 따라오지 않는다.
- 헤더/본문 끝까지 스크롤했을 때 기존 gutter 보정과 정렬이 유지된다.
- 가상화 비활성 그리드는 가로 스크롤만으로 React viewport 갱신을 반복하지 않는다. 가상화 활성 그리드는 표시 열 집합이 바뀔 때 창을 갱신하고, 동일 집합 내 스크롤에서는 불필요한 갱신을 하지 않는다.
- 세로 행 가상화, 고정 좌/우 열, 선택·편집, 열 크기 변경의 기존 동작을 유지한다.
- 관련 Vitest를 통과하고, 지정된 개발 서버에서 실제 브라우저의 데스크톱 및 반응형 뷰포트 렌더링을 확인한다. 브라우저 확인 자료는 결과 문서에 남긴다.
