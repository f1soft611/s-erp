# 업무작성 자주 쓰는 결재선 선택 및 저장 위치 변경 설계

## 목적

업무작성 결재선 설정 창에서 자주 쓰는 결재선을 바로 선택해 적용하고, 기존 관리 화면은 설정 버튼으로 계속 제공한다. 저장 버튼을 설정 창 하단 왼쪽으로 옮겨 반복 사용 흐름과 템플릿 관리 흐름을 분리한다.

## 기존 구조와 근거

- 결재선 설정 및 자주 쓰는 결재선은 `frontend/src/pages/groupware/documents/write/components/DocumentApprovalSettingsDialog.tsx`에서 관리한다.
- 현재 자주 쓰는 결재선 영역에는 저장 버튼과 불러오기 버튼이 함께 있다.
- 기존 불러오기 버튼은 F1-Grid 기반 템플릿 관리 모달을 연다. 이 모달의 행별 적용, 이름 인라인 편집/저장, 삭제 동작은 유지한다.
- 기존 템플릿 API의 목록/상세/생성 계약과 결재선 설정 창의 임시 적용 경계는 유지한다.
- 기준 기능 문서는 [결재선 템플릿 F1-Grid 상세 사양](../../spec/20261015/20261015_011_업무작성_자주쓰는결재선_F1Grid_상세사양서.md)이다.

## 검토한 접근

1. **설정 창 안에서 요약 목록 선택 (선택안)**: 제목 아래 select에 템플릿 이름을 제공하고, 선택 즉시 기존 상세 API로 불러온다. 설정 버튼은 기존 F1-Grid 관리 모달을 연다. 사용 빈도가 높은 선택을 한 단계로 제공하면서 기존 이름 변경/삭제 화면을 보존한다.
2. **관리 모달에서 선택 유지**: 기존 목록 모달을 불러오기 진입점으로 계속 사용한다. 별도 select가 없어 중복 UI는 없지만, 사용자가 매번 모달을 열어야 한다는 현재 불편이 남는다.
3. **설정 창 내 목록을 F1-Grid로 전환**: 선택과 관리를 한 화면에 모을 수 있지만, 핵심 결재선 편집 영역이 복잡해지고 관리 기능이 본 화면에 과하게 노출된다.

1안을 선택한다.

## 승인된 화면 설계

- `자주 쓰는 결재선` 제목 바로 아래 한 줄에 템플릿 select와 `설정` 버튼을 나란히 배치한다.
- select는 사용 가능한 가로 폭을 채우고, 설정 버튼은 select 오른쪽에 둔다. 좁은 화면에서도 select가 축소될 수 있도록 하고 불필요한 가로 넘침을 만들지 않는다.
- select의 초기 안내 문구는 `등록된 자주 쓰는 결재선`으로 한다.
- `설정` 버튼은 현재 제공 중인 F1-Grid 관리 모달을 연다.
- `자주 쓰는 결재선 저장` 시작 버튼은 현재 본문 섹션에서 제거하고, 결재선 설정 창의 footer 왼쪽으로 이동한다.
- 기존 `취소` 및 `적용` 버튼은 footer 오른쪽에 유지한다. 저장 시작 버튼은 기존과 같이 이름 입력 저장 창을 연다.

## 조회 및 적용 흐름

1. 결재선 설정 창이 열릴 때 현재 문서 코드에 해당하는 템플릿 요약 목록을 조회한다.
2. 조회 중에는 select를 비활성화하고 목록 로딩 상태를 표시한다. 결과가 비어 있으면 안내 항목만 제공하고, 저장/설정 버튼의 기존 문서 코드 및 사용자 옵션 활성화 조건을 유지한다.
3. 사용자가 템플릿을 선택하면 기존 상세 조회 API를 호출한다. 상세 조회가 성공하고 문서 코드와 참여자 유효성 검사를 통과한 경우에만 결재선 설정 창의 임시 결재선 및 참조자를 교체한다.
4. 템플릿 선택은 설정 창의 임시 상태에만 반영한다. 작성 화면에는 기존 `적용` 버튼을 눌렀을 때 반영하며, 결재선 설정 취소/닫기는 기존 임시 변경 폐기 동작을 유지한다.
5. 상세 조회에 성공한 항목을 select에 표시한다. 별도 저장 전에는 현재 임시 결재선의 수동 편집이 select 값을 자동 변경하지 않는다.
6. `설정` 버튼으로 관리 모달을 열고 닫은 뒤 목록을 새로 조회해 이름 변경, 추가, 삭제 결과를 반영한다. 기존 선택 항목이 이름 변경되면 ID 기준으로 선택을 유지하고, 삭제되면 선택을 안내 항목으로 초기화한다. 어느 경우에도 이미 적용한 임시 결재선은 변경하지 않는다.

## 저장 및 오류 처리

- footer 왼쪽 저장 버튼은 기존 이름 입력 창과 생성 API를 재사용한다.
- 새 템플릿 생성이 성공하면 요약 목록을 새로 조회하고 방금 저장한 템플릿을 select에서 선택 상태로 표시한다. 생성 API가 반환한 요약 항목을 사용해 목록 재조회가 실패해도 저장 성공과 목록 갱신 실패를 구분해 알리고, 해당 저장 항목을 목록에 반영한다. 저장 자체가 실패하면 기존 임시 결재선과 선택 상태를 유지하고 오류를 명시한다.
- 최초 템플릿 요약 목록 조회 또는 관리 모달 종료 후 목록 갱신이 실패하면 빈 목록처럼 성공 모양으로 처리하지 않는다. 오류 메시지와 목록 재시도 동작을 제공한다. 이미 적용한 임시 결재선은 보존한다.
- 템플릿 상세 조회 중에는 중복 선택을 방지하도록 select를 비활성화하고 진행 상태를 표시한다.
- 상세 조회 실패 또는 문서 코드/참여자 유효성 검증 실패 시 기존 임시 결재선과 참조자를 그대로 유지하고 오류를 표시한다. select는 사용자가 선택한 항목을 그대로 표시한다.
- 기존 관리 모달의 이름 변경, 삭제, 오류, 미저장 변경 확인 처리는 변경하지 않는다.

## 접근성 및 반응형

- select에는 `자주 쓰는 결재선` 또는 이에 준하는 명확한 접근성 이름을 제공한다. 조회/적용 중 상태와 오류/재시도는 보조기술에 전달한다.
- 저장 시작 버튼은 `CommonDialog.footerStart`에 배치하고 기존 `actions`의 취소/적용 버튼과 좌우로 구분한다.
- 설정/저장 버튼은 키보드로 조작 가능하고 현재 로딩 상태와 오류 상태가 보조기술에 전달되도록 한다.
- 최소 375px, 768px, 1280px 너비에서 select와 설정 버튼이 겹치거나 화면 전체 가로 넘침을 만들지 않는지 확인한다.
- 기존 결재선 단계/참조자 편집 레이아웃과 footer의 취소/적용 동작을 유지한다.

## 검증 기준

- 설정 창 진입 시 현재 문서 코드에 맞는 템플릿 목록을 조회하고 select에 표시한다.
- select 선택으로 상세 API를 호출하고 성공 시 임시 결재선 및 참조자를 교체하되 작성 화면은 즉시 변경하지 않는다.
- 상세 조회 실패 시 기존 임시 데이터를 보존하고 오류를 표시하며 선택 항목은 유지한다.
- 요약 목록 조회 실패에는 재시도 동작을 제공하고 임시 결재선은 보존한다.
- 설정 버튼은 기존 F1-Grid 관리 모달을 열고, 모달을 닫은 후 목록을 최신화한다. 이름 변경은 선택 ID를 유지하고 삭제는 선택을 초기화하되 임시 결재선은 보존한다.
- 저장 시작 버튼은 `CommonDialog.footerStart`에만 표시되고 기존 이름 입력/생성 흐름을 연다. 생성 후 새 템플릿이 선택 상태가 되며, 저장 성공과 목록 갱신 실패를 구별해 알린다.
- 이름 저장, 삭제, 미저장 변경 확인, 설정 창 취소/적용 등 기존 회귀 테스트를 유지한다.
- 관련 UI 및 서비스 Vitest, 프론트엔드 빌드, 지정 파일 문제 진단, `git diff --check`를 실행한다.
- 실제 브라우저에서 375px, 768px, 1280px를 확인하고 합성 템플릿 이름만 포함한 결과 캡처를 갱신한다.

## 비범위

- 관리 모달의 F1-Grid 기능 또는 템플릿 편집 동작 변경
- 결재선 구성 데이터의 자동 저장 또는 작성 화면 즉시 반영
- 자주 쓰는 결재선의 참여자 구성 자체를 관리 모달에서 편집하는 기능
