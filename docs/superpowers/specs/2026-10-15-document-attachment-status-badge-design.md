# 문서 첨부파일 상태 뱃지 디자인

## 목적

문서 수정 모달의 첨부파일 상태를 박스 아래 별도 문장으로 표시하지 않고, 파일 행 안에서 빠르게 구분할 수 있도록 한다. 사용자가 제공한 예시처럼 파일명과 삭제 버튼 사이에 상태 뱃지를 배치한다.

## UI 계약

- 기존 첨부파일 행의 상태 설명용 아래 문구를 제거한다.
- 파일 행은 파일 아이콘, 파일명, 상태 뱃지, 삭제 버튼 순으로 배치한다.
- 상태는 짧은 라벨로 표시한다.
  - `uploaded`: 초록 `완료`
  - `pending`: 중립 `대기`
  - `failed`: 빨강 `실패`
  - `unknown`: 황색 `확인 필요`
- 실패 첨부의 재시도 동작과 결과가 불명확한 첨부의 상태 확인 동작은 계속 제공한다. 상세 오류는 기존 저장 오류 영역을 이용하며 상태 문구를 파일 박스 아래에 추가하지 않는다.
- 기존 첨부 유지/삭제 및 신규 파일 업로드 상태 전이에는 변경이 없다.
- 좁은 화면에서는 파일명이 줄어들고 뱃지 및 삭제 동작은 축소되지 않도록 한다.

## 구현 범위

- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`
  - 파일 행 안에 상태 뱃지를 배치하고 상태 설명 `<Typography>`를 제거한다.
  - 실패/확인 상태의 보조 동작을 행 안에서 뱃지와 삭제 버튼에 인접하게 유지한다.

  - 상태별 뱃지 문구/상태 접근성, 행 내 배치, 아래 상태 문구 부재, 재시도/상태 확인 동작을 검증한다.
- `docs/directions/20261015`, `docs/plan/20261015`, `docs/spec/20261015`, `docs/result/20261015`
  - 작업 절차 및 검증 결과를 날짜별로 문서화한다.

## 접근성 및 반응형

- 뱃지는 접근 가능한 상태 텍스트를 포함한다.
- 파일명이 긴 경우에만 말줄임을 적용한다. 뱃지 및 파일 제거 아이콘은 flex shrink 대상에서 제외한다.
- 재시도/상태 확인 버튼은 기존 이름과 동작을 유지한다.

## 검증

- 각 첨부 상태의 뱃지가 삭제 버튼 앞 파일 행에 렌더링되는지 검증한다.
- 상태 안내 문구가 행 아래에 더 이상 렌더링되지 않는지 검증한다.
- 실패 재시도와 업로드 결과 상태 확인 기능의 기존 테스트를 회귀 확인한다.
- `frontend`에서 관련 `document-write-page` Vitest 테스트, 빌드, Problems와 `git diff --check`를 실행한다.
- 인증된 브라우저 세션이 가능하면 375px, 768px, 1280px에서 줄바꿈/말줄임/버튼 가시성을 확인하고, 불가능하면 사유를 결과 문서에 남긴다.
