# 거래처·품목 코드 자동채번 설계

## 상태

- 2026-10-23 사용자 승인
- 신규 저장 시 서버가 코드를 발급하고, 기존 코드는 수정할 수 없도록 한다.

## 배경

거래처관리와 품목관리에는 각각 코드 입력 필드가 노출되어 있다. 신규 저장에서 코드가 비어 있으면 두 서비스 모두 기존 eGov ID Generator로 6자리 코드를 발급하지만, 사용자가 입력한 코드는 그대로 사용할 수 있고 수정 요청으로 코드도 변경할 수 있다.

본 설계는 거래처코드와 품목코드를 사용자가 입력하거나 변경하지 못하도록 하고, 신규 등록은 기존 서버 채번으로 일원화한다.

## 검토한 방안

1. 화면에서만 입력을 막는다. 변경이 작지만 API 직접 호출로 임의 코드를 지정하거나 저장된 코드를 바꿀 수 있어 자동채번 정책을 보장하지 못한다.
2. 화면과 서버에서 모두 코드를 고정한다. 신규 저장은 기존 ID Generator로만 코드를 발급하고, 수정에서는 기존 코드를 유지한다. 사용자 요청의 자동채번 의도를 충족하고 기존 생성기·DB 구조를 유지하므로 선택한다.
3. DB 트리거나 새 채번 테이블/시퀀스를 도입한다. 추가 스키마와 이력이 필요하고, 이미 사용 중인 서버 생성기를 대체할 근거가 없어 제외한다.

## 승인 설계

### 화면 동작

- 거래처관리의 거래처코드와 품목관리의 품목코드는 F1-Grid 목록에서 표시하고 신규 등록·수정 폼에서는 숨긴다.
- 사용자가 F1-Grid 행 폼, 인라인 편집 또는 붙여넣기 등 다른 편집 경로로 코드를 바꿀 수 없어야 한다.
- 신규 등록 폼에는 코드 입력란이 없다. 등록을 저장하면 서버 응답/재조회 결과의 자동 생성 코드가 목록 행에 표시된다.
- 기존 행은 현재 저장된 코드를 목록에 그대로 표시하며 수정할 수 없다.
- 코드 이외의 폼 필드, 권한, 검색, 저장 피드백 동작은 변경하지 않는다.

### 서버 동작 및 데이터 흐름

- 신규 거래처와 품목 코드는 저장 시점에 기존의 각각의 eGov ID Generator를 사용해 발급한다. 저장 취소 시 번호를 예약하거나 발급하지 않는다.
- 신규 저장 요청에 코드 값이 포함되더라도 사용자 지정 코드로 사용하지 않는다.
- 수정 요청의 코드 값은 신뢰하지 않는다. 수정 SQL은 코드 컬럼을 갱신하지 않아 기존 코드를 보존한다.
- 기존 6자리 생성 규칙, 중복 확인, 테넌트 범위, 동시성 방어, 채번 한도 및 오류 처리 계약을 유지한다.
- API 응답 타입 및 저장된 코드 필드명은 유지한다. 신규 코드의 응답·재조회 값은 기존 화면 데이터 흐름으로 표시한다.
- 코드 필드가 목록용 F1-Grid 행 폼에서 빠지는 것은 기존 폼 메타데이터 동작을 따른다. 공통 F1-Grid 폼의 읽기 전용 필드 표시 기능은 추가하지 않는다.

### DB 및 범위

- 테이블, 컬럼, 제약, 인덱스, ID Generator 설정을 변경하지 않는다.
- 기존 코드 데이터는 수정·재채번하지 않는다.
- 코드 값의 형식, prefix, 테넌트별/전역별 채번 정책은 변경하지 않는다.
- 운영 DB에 SQL을 실행하지 않는다. DB/API 계약 변경 검토 시 구현 전에 읽기 전용 MCP의 현재 테이블 메타데이터를 확인한다.

### 검증 기준

- 신규 저장 시 요청에 빈 코드 또는 임의 코드가 있어도 서버가 생성한 코드만 저장되는지 거래처와 품목 각각 검증한다.
- 수정 요청에 다른 코드를 넣어도 기존 코드가 바뀌지 않는지 검증한다.
- UI에서 두 코드 필드가 목록에 표시되고 폼에서는 입력되지 않으며 다른 편집 경로로도 변경되지 않는지 검증한다.
- 기존 코드 표시, 생성기 경계/중복 오류, 이름·소비기한 등 인접 저장 검증과 저장 결과 표시의 회귀를 확인한다.
- 관련 프론트·백엔드 집중 테스트와 빌드를 수행한다. 화면 변경은 실제 브라우저에서 375px, 768px, 1280px로 확인하고 결과 문서에 스크린샷을 보관한다.

## 제외 사항

- 기존 코드 마이그레이션이나 중복 코드 정리
- 채번 형식 또는 기존 채번기 교체
- 새 DB 구조, API 엔드포인트, 코드 미리보기/예약 기능
- 거래처·품목 코드 외 다른 필드의 입력/수정 정책 변경
