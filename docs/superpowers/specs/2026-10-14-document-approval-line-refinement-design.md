# 전자결재 결재선 상세 표시 보완 설계

## 목표

전자결재 상세 결재선을 읽기 쉬운 기본 글자 크기로 정돈하고, 저장된 프로필·도장 이미지와 단계별 참여자 상태를 명확히 표시한다. 결재 처리 규칙, 문서 권한, 댓글, 첨부 동작은 변경하지 않는다.

## 승인된 화면 동작

### 결재선 헤더 및 승인 카드

- 결재선 패널 헤더에 `결재선`과 `기안자 {drafterName} · 기안일 YYYY.MM.DD`를 표시한다.
- 승인 카드 흐름 위의 독립 `결재` 제목은 제거한다. 결재선 패널 제목은 유지한다.
- 승인 카드의 상태 도장은 현재보다 크게 표시한다.
- 승인선 참여자의 action 상태가 처리 완료(`APPROVED`, `REJECTED`, `RETURNED`)인 경우 저장된 개인 도장 이미지가 있으면 이를 표시한다. 이미지가 없거나 표시되지 않으면 현재 action 상태를 나타내는 시스템 도장을 표시한다.
- 대기(`WAITING`) 및 진행(`PENDING`) 상태는 개인 도장 이미지와 관계없이 기존 상태 의미의 시스템 도장(`대기`, `진행`)을 표시한다.
- 기존 카드 순서, 꺾쇠 connector, 세 단계 슬롯, 읽기 전용 동작을 유지한다.

### 합의 참여자

- 합의 참여자는 `stageOrder` 단위로 그룹화한다. 단계 순번은 각 단계 그룹에 한 번만 표시한다.
- 그룹 내 참여자는 `participantOrder` 오름차순으로 배치하되 참여자 개인에게 순번을 반복 표시하지 않는다. 한 합의 단계의 동시 처리 규칙과 실제 상태를 보존한다.
- 각 참여자는 2행 구조를 사용한다. 1행은 프로필 사진과 이름, 2행은 부서명과 처리 상태다.
- 저장된 프로필 이미지가 없으면 이름 첫 글자를 Avatar 대체 표시로 사용한다.
- 같은 그룹의 참여자는 가용 폭에 맞춰 자동 줄바꿈한다. 합의 영역에 별도 가로 스크롤을 두지 않는다.

### 참조 참여자

- 참조자는 번호 없이 프로필 사진, 이름, 부서를 표시한다.
- 참조 목록도 가용 폭을 기준으로 자동 줄바꿈한다.
- 프로필 이미지가 없으면 이름 첫 글자를 Avatar 대체 표시로 사용한다.

### 글자 크기

- `caption` 등 기존의 축소된 글자 대신 기본 본문 크기를 기준으로 결재선 제목, 참여자 이름, 부서, 상태를 표시한다.
- 상태의 색상과 도장 모양은 구분을 보조하되 상태 의미를 텍스트와 접근성 이름으로 함께 제공한다.

## 데이터/API 설계

- 승인된 사용자의 기존 상세 API 응답에 포함된 `approvalLines`에 선택적 nullable `participantProfileImage`, `participantStampImage` 필드를 추가한다.
- 상세 권한 확인, 현재 응답 envelope, 이미지 저장 방식은 변경하지 않고 새로운 이미지 API나 테이블을 추가하지 않는다.
- MyBatis 결재선 조회에서 현재 tenant의 `tb_user`와 `tb_login_account`를 tenant 및 로그인 계정 ID로 LEFT JOIN한다. LEFT JOIN으로 사용자 계정이 비활성/누락된 경우에도 저장된 결재선 행을 유지한다.
- `participant_department_name`에 저장된 부서명을 그대로 우선 사용한다. 이미지 조회 목적으로 참여자 이름·부서 등 기존 결재선 값을 바꾸지 않는다.
- 프로필 이미지는 승인·합의·참조 참여자에게 반환한다. 도장 이미지는 승인 카드에 표시 가능한 처리 완료 상태에서만 반환하며, 미처리 상태에는 반환하지 않는다.
- 현재 계정의 프로필·도장 이미지는 기존 PNG/JPEG 데이터 URL 저장 계약을 따른다. 데이터가 없거나 이미지 로딩에 실패하면 앞서 정의한 UI 대체 표시로 복구한다.
- 이번 작업은 `tb_login_account.profile_image`와 `stamp_image`의 기존 값을 읽어 보여주는 API/화면 변경이다. 새 DB migration은 만들지 않는다.

## 컴포넌트 및 데이터 흐름

1. 기존 권한 검증을 통과한 상세 요청이 문서와 결재선 조회를 실행한다.
2. 결재선 조회는 기존 참여자 정보와 tenant가 일치하는 로그인 계정의 이미지 정보만 결합한다.
3. 상세 응답의 `approvalLines`를 기존 `stageOrder`, `participantOrder` 순서로 화면 그룹에 구성한다.
4. 승인 카드에서는 처리 상태와 도장 데이터로 사용자 도장/시스템 도장의 표시를 결정한다.
5. 합의는 단계 그룹별 참여자 목록으로, 참조는 번호 없는 사용자 카드 목록으로 렌더링한다.
6. 프로필 및 도장 이미지 누락/로드 실패는 지정된 아바타/상태 도장 fallback으로 처리한다. API·권한·조회 오류는 기존 상세 화면 오류 처리 방식을 유지한다.

## 범위 제외

- 결재·합의 처리 권한, 단계 활성화, 승인/반려 결과, 시스템 이력 변경
- 문서 상세 조회수 정책 변경
- 좋아요, 북마크, 댓글, 첨부 변경
- 사용자 프로필/도장 등록 및 편집 화면 변경
- 새로운 이미지 저장소, 파일 업로드, 별도 이미지 조회 API 또는 데이터베이스 migration
- 기존 문서 결재선 데이터의 순번/상태 수정

## 검증 계획

- 프론트 회귀 테스트에서 헤더의 기안자/기안일, `결재` 제목 제거, 확대 도장, 저장 도장 이미지/시스템 fallback, 2행 합의자, 동순번 그룹화, 자동 줄바꿈, 번호 없는 참조 프로필·부서와 기본 글자 크기를 확인한다.
- 백엔드 Mapper 테스트에서 tenant-scoped LEFT JOIN, 기존 참여자 행 보존, 프로필/처리완료 도장 이미지 매핑, 미처리 상태의 도장 미포함을 확인한다.
- 관련 프론트 및 백엔드 테스트, 프론트 build를 실행한다.
- 실제 브라우저 375px, 768px, 1280px에서 합의 참여자가 가로 스크롤 없이 자동 줄바꿈되고 페이지 전체 가로 넘침이 없는지 확인한다.
- 결과 문서와 개인정보를 포함하지 않는 화면 캡처를 날짜별 결과 폴더에 기록한다.

## 확인된 근거

- PostgreSQL 읽기 전용 MCP에서 `tb_login_account.profile_image`와 `stamp_image`가 nullable text 컬럼임을 확인했다.
- 같은 조회에서 결재선 `participant_user_id`, `participant_department_name`, `stage_order`, `participant_order`, `action_status` 컬럼을 확인했다.
- 기존 프로필 업데이트 서비스는 PNG/JPEG 데이터 URL을 최대 1MB, 최대 512픽셀로 정규화한다.
- 기존 전자결재 workflow 설계는 하나의 합의 단계에 다수 참여자를 배정하고 동시 처리하며 전원 승인 후 다음 단계로 진행한다고 명시한다.
- 합의 표시 시각 시안은 사용자가 C안과 동순번 그룹 표시를 선택하고, 세로 목록 대신 2행 참여자 항목의 자동 줄바꿈과 참조 부서 표시를 요청해 확정했다.
