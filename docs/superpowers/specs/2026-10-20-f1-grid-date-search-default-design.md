# F1-Grid 날짜 상세검색 기본값 설계

## 목적

F1-Grid 날짜 컬럼의 상세검색 기본값을 컬럼 메타데이터에서 선언하고, 첫 진입과 초기화에 같은 기본값을 적용한다. 오늘 날짜의 기준은 브라우저가 아니라 백엔드 시스템 날짜로 한다.

## 확인한 기존 구조

- `F1GridColumnSearchOptions`가 `search.label`, `order`, `group`, `span`을 제공하고 `toPageSearchFields`가 이를 상세검색 필드로 변환한다.
- 상세검색의 `date` 필드는 시작일·종료일 범위를 입력한다.
- `PageSearchArea`의 상세검색 초기화는 현재 필드값을 비우고 있다.
- 문서현황은 페이지에서 브라우저 `Date`를 사용해 최근 한 달 기본 기간을 계산한다.
- 백엔드 `EgovDateUtil.getToday()`가 현재 날짜 유틸로 이미 존재하지만, 이를 반환하는 공통 API는 없다.
- DB 변경은 필요하지 않다. 읽기 전용 MCP의 테이블 목록을 확인했으며 이 기능은 데이터베이스 계약을 사용하거나 변경하지 않는다.

## 승인된 요구사항

- 날짜 컬럼의 상세검색 메타데이터에 선언형 기본값을 설정할 수 있다.
- 기본값은 시스템 날짜 기준 상대 날짜 또는 고정 연·월·일 날짜다.
- 상대 날짜 연산은 달력 기준으로 처리한다. 월말을 넘어가는 월 계산은 해당 월의 말일로 보정하며, 윤년도 올바르게 처리한다.
- 시작일과 종료일은 독립적으로 기본값을 설정할 수 있고, 한쪽만 지정할 수 있다.
- 기본값이 지정된 검색 필드는 첫 진입 및 검색조건 초기화 시 기본값을 사용한다. 날짜 기본값이 지정되지 않은 필드는 기존처럼 빈 값으로 초기화한다.
- `sysDate`의 실제 날짜 문자열은 백엔드에서 제공한다. 프런트엔드 시스템 시계로 대체하지 않는다.
- 날짜 기본값이 없는 다른 검색조건 초기화 동작은 기존 동작을 유지한다.

## 선언 형식

검색 메타데이터 안에 상세검색용 날짜 범위 기본값을 둔다. 각 끝점은 고정 날짜 또는 서버 날짜 기준 오프셋 중 하나다.

```ts
type F1GridDateDefault =
  | { type: 'fixed'; year: number; month: number; day: number }
  | {
      type: 'systemDate';
      offset?: { years?: number; months?: number; days?: number };
    };

type F1GridDateRangeDefault = {
  from?: F1GridDateDefault;
  to?: F1GridDateDefault;
};
```

예를 들어 최근 1개월부터 오늘까지의 검색은 다음처럼 선언한다.

```ts
search: {
  defaultValue: {
    from: { type: 'systemDate', offset: { months: -1 } },
    to: { type: 'systemDate' },
  },
}
```

고정일 예시는 `{ type: 'fixed', year: 2026, month: 10, day: 20 }`이다. 기본값 metadata는 검색 필드 전용이며 F1-Grid 행 편집이나 셀 값의 기본값을 의미하지 않는다. 유효하지 않은 고정일은 설정 오류로 다루며, 유효하지 않은 metadata를 빈 날짜처럼 성공 처리하지 않는다.

## 데이터 흐름 및 구성요소

1. 백엔드 공통 시스템 날짜 조회 API가 `EgovDateUtil.getToday()`를 사용해 ISO `yyyy-MM-dd` 형식의 날짜를 성공 응답으로 반환한다.
2. 프런트엔드의 공통 검색 기본값 resolver는 날짜 필드 metadata 중 `systemDate` 표현이 있을 때만 시스템 날짜 API를 호출한다.
3. resolver는 서버에서 받은 기준일에 달력 단위 offset을 적용하고, 고정일을 검증해 각 필드의 `{ from, to }` 값을 만든다.
4. 공통 `PageSearchArea`는 해석한 기본값을 첫 진입과 상세검색 초기화에 사용한다. 기본 검색조건을 사용하는 페이지는 동일한 resolved snapshot을 API 필터 초기화에도 사용하여 첫 요청이 기본값 없는 상태로 먼저 나가지 않도록 한다.
5. 문서현황의 결재신청일은 컬럼 metadata에 최근 1개월 상대 날짜 범위를 선언한다. 페이지는 브라우저 `Date`로 날짜를 계산하지 않는다.
6. 저장된 사용자 검색 세션이 있는 경우에는 이를 기본값보다 우선해 복원한다. 사용자가 초기화하면 metadata 기본값이 재적용되고, 적용된 날짜 범위가 검색 세션에 저장된다.

## API 및 오류 처리

- 공통 API는 로그인 후 기존 API response envelope를 사용하며 날짜 결과는 `result.today`로 제공한다. 제안 경로는 `GET /api/v1/common/system-date`다.
- 조회 실패 시 브라우저 날짜로 fallback하지 않는다. 기본값 적용 및 기본값 의존 첫 조회를 오류로 표시하고 재시도할 수 있게 한다.
- 기존 `EgovDateUtil.getToday()`의 표기 계약을 API에서 ISO 날짜로 정규화한다.
- API/프런트엔드 기본값 검증에서 날짜 파싱 실패를 명시한다.
- DB 스키마, 테이블, 쿼리 변경은 없다.

## 대안 및 선택 이유

1. **공통 컬럼 metadata + 공통 시스템 날짜 API (선택):** 선언과 동작이 재사용되고 각 페이지에서 날짜 연산 및 API 호출을 중복하지 않는다.
2. **페이지마다 날짜 기본값 처리:** 단기 변경량은 작지만 페이지별로 날짜 계산, 초기화 및 서버 API 호출이 중복되고 규칙이 달라질 수 있다.
3. **백엔드에서 페이지별 상대 표현을 계산:** 프런트 metadata를 서버로 보내거나 각 페이지별 계산 계약이 생겨 검색 UI 설정과 백엔드가 과하게 결합된다.

## 검증 기준

- 고정 연·월·일과 서버 날짜 기준 today 및 상대 year/month/day 값이 올바른 ISO 날짜를 만든다.
- 월말 및 윤년 경계에서 달력 계산 결과가 유효하다.
- date search metadata 기본값이 첫 진입과 초기화에서 동일하게 적용된다.
- 기본값이 없는 date 필드는 초기화 후 빈 값이다.
- 문서현황의 날짜 기본값과 요청 필터는 서버 날짜를 기준으로 하며, 프런트엔드 현재 시각을 사용하지 않는다.
- 세션 검색조건 복원은 기본값보다 우선하고, 초기화 후에는 metadata 기본값이 다시 저장·복원된다.
- 백엔드 API가 날짜 형식의 `today`를 반환하고 조회 실패를 숨기지 않는다.
- 프런트엔드/백엔드 테스트 및 빌드가 통과하고 F1-Grid 문서와 결과 문서가 갱신된다.
