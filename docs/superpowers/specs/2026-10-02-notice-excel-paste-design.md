# 공지 작성기 Excel 표 붙여넣기 설계

## 배경

공지 작성 모달의 Tiptap 편집기는 Excel 표 붙여넣기를 허용하지만, 현재 HTML 정규화 과정에서 셀 내부의 줄바꿈을 하나의 공백으로 합치고 표의 행마다 하위 셀을 재귀적으로 수집한다. 복잡한 병합 표에서는 줄 내용 또는 셀 위치가 기대와 다르게 보일 수 있다. 편집기에는 표 내부 가로 스크롤이 이미 있으므로 가로 스크롤 자체는 수정 대상이 아니다.

## 목표

- Excel/Spreadsheet의 HTML 표 행·열 배치를 편집기에서 유지한다.
- `rowspan`, `colspan`, 셀/행 크기와 Excel의 글꼴 크기·가족·색상·강조 스타일을 안전하게 보존한다.
- Tiptap의 기본 셀 최소 너비를 16px로 낮춰 원본의 좁은 열이 과도하게 확장되지 않게 한다.
- 셀 내부의 `<br>` 및 문단 경계를 유지해 여러 줄이 한 줄로 합쳐지지 않게 한다.
- 악성 태그와 안전하지 않은 인라인 스타일은 계속 제거한다.
- 표 HTML이 없거나 유효한 표를 만들 수 없을 때는 기존 plain-text fallback을 유지한다.
- 넓은 표는 현재처럼 편집기 내부에서 가로 스크롤한다.

## 설계

`noticeClipboard.ts`의 HTML 정규화에서 표의 직계 행과 각 행의 직계 셀을 기준으로 표 구조를 재구성한다. 상위 행에서 중첩 표의 셀을 중복 수집하지 않도록 탐색 범위를 제한한다. 셀 값은 `textContent`로 평탄화하지 않고 허용된 텍스트·줄바꿈·문단 및 텍스트 서식을 안전하게 직렬화한다. 빈 셀, 셀 크기와 행·열 병합 정보는 유지한다.

Tiptap 공식 TextStyle 확장과 font family/size/color 확장을 이용해 inline 스타일을 parse/render한다. 스타일 처리는 allowlist 기반으로 유지하며 셀 너비/높이와 테두리·배경·정렬, font-family/font-size/font-weight/font-style/color/line-height를 제한적으로 전달한다. 원본 CSS 전체, script 등 실행 가능한 콘텐츠 및 지원하지 않는 외부 포맷은 저장하지 않는다. `NoticeComposerDialog`의 paste 우선순위와 표 HTML을 이미지로 취급하지 않는 동작은 바꾸지 않는다.

## 대안과 선택

- 표 폭/CSS만 변경: 보이는 잘림에는 대응하지만 행·열 구조의 이상을 해결하지 못하므로 제외한다.
- plain-text TSV에서 표를 재생성: 위치는 단순화할 수 있지만 병합과 서식을 잃으므로 제외한다.
- HTML 구조를 기준으로 안전하게 표를 재구성: 병합·줄바꿈·허용 스타일을 살리면서 현재 스크롤 동작을 유지할 수 있어 선택한다.

## 검증

- 단위 테스트에 여러 행/열, `rowspan`·`colspan`, 빈 셀, 셀 내부 여러 줄, 중첩 표 또는 하위 셀 탐색 경계를 포함한다.
- 공지 작성 모달의 실제 paste 경로에서 셀 텍스트와 구조가 유지되는 회귀 테스트를 추가한다.
- 기존 공지 Excel/일반 텍스트/이미지 붙여넣기 focused 테스트와 프론트엔드 빌드를 실행한다.
- Chromium 브라우저에서 병합 셀과 여러 줄 셀이 있는 긴 표를 실제 붙여넣고, 아래 행 내용이 옆 칸에 합쳐지지 않는지와 내부 가로 스크롤을 확인한다.

## 범위 제외

- 공지 API, 저장 계약, 데이터베이스, 첨부 파일 업로드 변경
- 전체 Excel 서식 복제 또는 임의 CSS 보존
- 편집기 폭/모달 레이아웃 재설계
- 일반 문서 텍스트 붙여넣기 방식 변경
