# 문서 상세 액션 후 댓글 즉시 갱신 설계

## 목적

문서 상세에서 결재, 반려, 보완요청, 결재신청 취소 또는 승인 취소를
성공적으로 처리했을 때 서버가 기록한 시스템 메시지를 댓글 영역에서 바로
확인할 수 있게 한다.

## 현재 동작과 원인

`DocumentApprovalDetailFeed`의 결재 액션은 성공 후 상위 목록 갱신을 요청하고
상세 화면을 닫는다. 취소 액션은 상위 목록과 상세 데이터만 갱신한다. 두
경로 모두 현재 컴포넌트가 관리하는 댓글 페이지는 다시 조회하지 않아,
액션이 생성한 시스템 메시지가 상세 댓글에 즉시 나타나지 않는다.

## 승인된 동작

- 결재, 반려, 보완요청, 결재신청 취소 및 승인 취소가 성공하면 상세를 열린
  상태로 유지한다.
- 액션 성공 후 최신 댓글 페이지를 다시 요청한다. 기존 통합 댓글 페이지
  계약에 따라 댓글과 시스템 메시지를 함께 조회하며 최신 항목 최대 3개를
  표시한다.
- 서버 조회 결과로 댓글 목록, 시스템 메시지, 총 건수, 이전 페이지 커서를
  갱신한다. 클라이언트에서 시스템 메시지를 임의 생성하지 않는다.
- 액션 성공 후 문서 상세 데이터를 다시 조회하고 기존 상위 목록 갱신도
  수행한다.
- 댓글 재조회가 실패하면 액션 성공 상태는 유지하고, 기존 댓글 오류 및
  재시도 UI를 사용한다. 액션 실패 시 현재 오류 처리를 유지하며 목록을
  성공 상태로 갱신하지 않는다.
- 이전 댓글 페이지를 열어 둔 상태라도 액션 완료 시 최신 페이지를 표시해
  방금 기록된 시스템 메시지를 확인할 수 있도록 한다.

## 구현 경계

- 프론트엔드 문서 상세/피드 컴포넌트와 해당 회귀 테스트만 변경한다.
- API 응답, 댓글 페이지 계약, 서버 결재 처리, DB 스키마, 공지사항 댓글
  동작은 변경하지 않는다.
- 액션별 권한, 확인 대화상자, 성공/오류 알림, 상위 목록 갱신은 유지한다.

## 검증 기준

- 각 액션의 성공 뒤 최신 댓글 조회가 호출되고 새 시스템 메시지가 표시된다.
- 결재 계열 액션 성공 후 상세가 닫히지 않고 상태 변경된 상세 정보가 반영된다.
- 취소 성공 후에도 상세 및 댓글이 갱신된다.
- 댓글 조회 실패 시 기존 댓글 오류/재시도 안내가 나타나며 액션 성공을 실패로
  잘못 표시하지 않는다.
- 액션 실패 시 댓글을 성공 상태처럼 갱신하지 않고 기존 액션 오류를 표시한다.
- 프론트엔드 관련 Vitest, production build 및 브라우저에서 액션 후 열린 상세와
  댓글 갱신을 확인한다.

## 고려한 대안

1. **서버에서 최신 댓글 페이지 재조회 (선택)**: 실제 저장된 시스템 메시지와
   댓글/커서/건수를 일관되게 표시한다.
2. **클라이언트에서 시스템 메시지 임시 생성**: 액션 응답에는 메시지 ID와
   표시 내용이 포함되지 않아 서버 데이터와 불일치할 수 있으므로 제외한다.
3. **상위 목록만 새로고침하고 상세를 닫음**: 사용자가 댓글을 확인하려면
   상세를 다시 열어야 하므로 요청된 즉시 갱신을 충족하지 못한다.
