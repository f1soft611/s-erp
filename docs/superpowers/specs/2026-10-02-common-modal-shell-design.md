# 공통 모달 셸 설계

## 목적

그룹웨어, 기안양식관리, F1-Grid 폼 등에서 사용하는 모달의 헤더·본문·푸터 배치와 시각 규칙을 일관되게 한다. 업무별 본문과 편집 기능은 유지하고, 공통 셸이 바깥 레이아웃과 영역 동작을 책임진다.

## 현재 구조와 확인 근거

- F1-Grid 행 폼 모달은 `DialogTitle`, `DialogContent`, `DialogActions`로 헤더·본문·푸터를 나누고, 닫기·설명·그룹 폼·하단 안내를 직접 구성한다.
- 그룹웨어 공지 작성 모달은 MUI `Dialog` 안에 자체 헤더와 본문, 푸터를 구성하고 하단 왼쪽에 편집·첨부 툴바를 둔다.
- 따라서 MUI 테마 기본값만 조정하면 공통 색상이나 모서리는 맞출 수 있지만, 푸터 슬롯·스크롤 책임·영역 간격은 화면별 구현에 남는다.

## 대안과 선택

### 대안 A: MUI 테마 기본값만 통일

변경량은 작지만 화면별 헤더·본문·푸터 구조와 스크롤 규칙이 달라 통일 효과가 제한된다.

### 대안 B: 공통 셸과 업무별 프리셋

공통 셸이 바깥 레이아웃을 관리하고 각 업무가 필요한 슬롯과 본문을 전달한다. 구조 일관성과 업무별 확장성을 함께 유지하지만 각 모달을 단계적으로 이전해야 한다.

### 대안 C: 모든 모달을 단일 고정 레이아웃으로 통합

시각적 일관성은 가장 강하지만 툴바나 편집기 등 업무별 콘텐츠 구조를 수용하기 어렵다.

### 선택

대안 B를 채택한다. 시각 방향은 간결하게 유지하고, 구조는 공통 셸로 통일한다. 업무별 본문과 선택형 슬롯으로 특수 기능을 제공한다.

## 승인 설계

### 공통 셸

- 공통 다이얼로그가 헤더, 스크롤 가능한 본문, 하단 액션 영역을 수직으로 배치한다.
- 헤더는 제목, 선택적 설명, 닫기 동작을 일관된 정렬·여백으로 제공한다.
- 본문은 공통 배경, 기본 안쪽 여백, 내부 스크롤 규칙을 사용한다. 편집기 등 별도 표면이 필요한 콘텐츠는 본문 안쪽에서 자체 영역으로 표현한다.
- 푸터는 상단 경계와 기본 여백을 통일한다. 본문이 길어도 헤더와 푸터는 유지하고 본문 영역만 스크롤한다.
- 모달 폭은 소수의 의미 있는 크기 프리셋으로 제한한다. 현재 대상 화면 폭을 기준으로 `md=820px`, `lg=960px`을 사용하고, F1-Grid는 기존처럼 작은 뷰포트에서 전체 화면으로 표시한다.
- 본문 높이는 폼처럼 콘텐츠에 맞추는 `content`와 에디터처럼 남은 공간을 채우는 `fill` 모드로 구분한다. 공지 작성은 기존 편집기 높이를 유지하기 위해 `fill`을 사용한다.

### 슬롯과 액션

- 푸터 왼쪽에 선택형 `footerStart` 슬롯을 제공한다. 공지 작성은 편집·첨부 툴바를 전달하고, 툴바가 필요 없는 모달은 슬롯을 생략한다.
- 푸터 오른쪽은 주요 액션과 보조 액션을 전달한다. 슬롯이 없어도 오른쪽 액션의 정렬은 동일하게 유지한다.
- 본문은 공통 셸의 자식 콘텐츠로 전달한다. 업무별 폼 필드, 탭, 표, 편집기 동작은 각 기능이 소유한다.

### 적용 범위

- 1차 적용 후보는 그룹웨어 공지 작성 모달, 기안양식관리 모달, F1-Grid 행 폼 모달이다.
- 적용은 공통 셸 구축 후 모달별로 이전하며, 기존 API 계약, 데이터 처리, 저장 흐름은 변경하지 않는다.
- 확인·경고 대화상자, 이미지 뷰어 등 특수 목적 모달은 공통 셸 적합성을 확인한 뒤 별도 적용 여부를 정한다.

## 검증 기준

- 공통 셸을 사용하는 모달은 헤더·본문·푸터 경계, 기본 간격, 배경 규칙이 일치한다.
- 본문 길이가 모달 높이를 초과하면 본문만 스크롤되고 헤더와 푸터는 유지된다.
- `footerStart`가 있는 공지 작성에서는 툴바와 우측 액션이 겹치지 않으며, 없는 모달은 우측 액션 정렬이 유지된다.
- 제목, 설명, 닫기 버튼, 액션이 접근 가능한 이름과 키보드 동작을 제공한다.
- 375px, 768px, 1280px 뷰포트에서 콘텐츠나 액션이 잘리거나 겹치지 않는지 브라우저로 확인한다.
- 각 이전 대상의 기존 생성·수정·저장·취소 동작과 관련 테스트를 회귀 확인한다.

## 범위 제외

- 모달 본문 내부의 업무별 레이아웃이나 편집 동작 재설계
- API·데이터 계약 및 저장 흐름 변경
- 모든 MUI 다이얼로그를 한 번에 이전하는 광범위한 리팩터링
- 구현 단계에서 확인되지 않은 고정 크기, 색상 토큰 또는 예외 동작의 사전 확정
