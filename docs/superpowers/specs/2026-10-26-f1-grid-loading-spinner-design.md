# F1-Grid 로딩 스피너 시각 정합성 설계

## 배경

F1-Grid는 로딩 중 그리드 전체 오버레이와 MUI `CircularProgress`를 표시한다. 현재 스피너 크기는 대시보드 첫 접속 로더와 같은 34px이지만, F1-Grid만 `thickness={4}`를 지정하고 그리드 위에 낮은 불투명도의 어두운 막을 사용해 초기 로더와 시각 차이가 있으며 스피너가 주변 데이터와 섞여 보인다.

대시보드 첫 접속 로더는 `CircularProgress size={34}`를 기본 두께와 테마 기본 색상으로 표시한다. 요청은 F1-Grid도 이 로더와 같은 인상을 주면서 로딩 표시를 쉽게 알아보게 하는 것이다.

## 설계

- F1-Grid 공통 오버레이와 입력 차단을 유지한다. 화면별 `loading` 전달 방식이나 로딩 상태 수명은 바꾸지 않는다.
- 스피너를 대시보드 첫 접속 로더와 동일한 `CircularProgress size={34}`로 렌더링한다. 두께와 색상은 MUI 기본값을 사용하며 별도 크기 확대, 아이콘, 안내 문구를 추가하지 않는다.
- 기존 어두운 저투명도 오버레이 대신 현재 테마의 `background.default`를 84% 불투명도로 사용한다. 첫 접속 화면의 배경과 가까운 표면 위에서 스피너를 분명하게 보이게 하면서, 로딩 중인 그리드 영역과 입력 차단은 유지한다.
- 그리드의 본문 렌더링, 높이, 스크롤, 접근성 상태, `F1Grid`/`F1Tree` 호출 계약은 그대로 둔다.
- 공통 구현만 변경하므로 해당 컴포넌트를 사용하는 F1-Grid 및 F1-Tree 화면에 동일하게 적용한다.

## 검증

- F1-Grid 로딩 테스트에서 오버레이 표시, 34px 진행 표시, 로딩 상태 접근성, 기존 본문 동작 보존을 확인한다.
- 관련 F1-Grid 단위 테스트와 프론트엔드 빌드를 실행한다.
- 브라우저에서 375px, 768px, 1280px 화면을 확인하고 결과 문서에 캡처 경로를 남긴다.

## 범위 제외

- 앱 첫 접속 로더 자체의 변경
- 로딩 상태의 생성·전달, API 호출, 저장 상태 정책 변경
- 스켈레톤/본문/헤더 구조 및 그리드 상호작용 변경
- 백엔드, DB, API 계약 변경
