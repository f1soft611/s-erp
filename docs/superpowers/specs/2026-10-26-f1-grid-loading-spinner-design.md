# F1-Grid 공통 로딩 스피너 설계

## 배경

F1-Grid는 로딩 중 그리드 전체 오버레이와 MUI `CircularProgress`를 표시한다. F1Grid/F1Tree 사용처는 공통 F1Grid 오버레이를 공유하지만, 대시보드 첫 접속 로더와는 별도로 스피너를 생성한다. 두 화면 모두 34px MUI 로더를 사용하지만 F1-Grid만 더 얇은 선을 적용해 같은 컴포넌트에서 일관되게 관리할 필요가 있다.

사용자는 F1-Grid 사용처에서 공통 로딩 스피너를 사용하고, 그리드에서만 선을 더 얇게 표시하도록 요청했다. 시각 비교 후 F1-Grid의 선 두께는 1.8px로 결정했다.

## 설계

- `frontend/src/shared/components/AppLoadingSpinner.tsx`에 재사용 가능한 34px MUI 스피너를 둔다. 색상은 테마 기본값을 사용한다.
- 공통 컴포넌트의 기본 두께는 기존 DashboardPage 첫 접속 로더와 같은 3.6px로 둔다. DashboardPage는 기본값을 사용하고 F1Grid 로딩 오버레이는 1.8px를 전달한다.
- 모든 F1Grid/F1Tree 사용처는 기존 F1Grid 공통 오버레이를 통해 같은 `AppLoadingSpinner` 구현을 사용한다. 화면별 `loading` 전달 방식이나 로딩 상태 수명은 바꾸지 않는다.
- 그리드 오버레이는 현재 테마의 `background.default`를 84% 불투명도로 사용하며 기존 입력 차단을 유지한다.
- 그리드의 본문 렌더링, 높이, 스크롤, 접근성 상태, `F1Grid`/`F1Tree` 호출 계약은 그대로 둔다.
- DashboardPage의 기본 두께는 현재 화면과 동일하게 유지하며 다른 MUI 진행 표시, 전역 테마 기본값, 저장/조회 정책은 변경하지 않는다.

## 검증

- 공유 컴포넌트가 기본 두께 3.6px와 전달된 1.8px를 표시하는지 검증한다.
- F1-Grid 로딩 테스트에서 34px 진행 표시, 1.8px 두께, 오버레이 표시, 로딩 상태 접근성, 기존 본문 동작 보존을 확인한다.
- 관련 F1-Grid 단위 테스트와 프론트엔드 빌드를 실행한다.
- 브라우저에서 375px, 768px, 1280px 화면을 확인하고 결과 문서에 캡처 경로를 남긴다.

## 범위 제외

- 앱 첫 접속 로더의 크기·색상·시각 동작 변경
- 로딩 상태의 생성·전달, API 호출, 저장 상태 정책 변경
- 스켈레톤/본문/헤더 구조 및 그리드 상호작용 변경
- 다른 MUI `CircularProgress` 인스턴스 및 전역 테마 기본값 변경
- 백엔드, DB, API 계약 변경
