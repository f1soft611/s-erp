# 견적서작성 레이아웃 및 품목 입력 개선 설계

## 배경

견적서작성의 기본정보 필드가 수주등록과 비슷한 CSS grid를 사용하지만, 수주등록의 필드 여백 정리와 picker 정렬 규칙을 모두 적용하지 않아 필드가 고르게 정렬되지 않는다. 견적 상세에서는 품목코드가 일반 텍스트로 편집되고, 마스터 품목 선택은 별도 버튼으로만 가능하다. 날짜 입력은 브라우저 기본 `type="date"`에 의존한다.

견적관리의 기존 데이터/API 계약은 유지하면서 수주등록과 같은 기본정보 레이아웃으로 정렬하고, 직접 입력과 품목 마스터 선택을 구분하며, 날짜 입력 편의성을 높인다.

## 기준 문서 및 화면

- 견적관리 작업지시서·계획서·상세사양서: `docs/directions/20261116/20261116_014_견적관리_작업지시서.md`, `docs/plan/20261116/20261116_014_견적관리_계획서.md`, `docs/spec/20261116/20261116_014_견적관리_상세사양서.md`
- 기본정보 레이아웃 기준: `docs/spec/20261026/20261026_010_수주등록_레이아웃_개선_상세사양서.md`
- 기준 구현: `frontend/src/pages/sales/order/create/SalesOrderCreatePage.tsx`

기존 견적관리 사양은 직접 입력 시 품목코드·품목명·규격·단위를 모두 입력할 수 있도록 정하지만, 이번 요청으로 직접 입력 필드는 품목명만 허용한다. 마스터 선택 시 코드·명·규격·단위 스냅샷을 채우는 기존 데이터 계약은 유지한다.

## 설계

### 기본정보 레이아웃

- 견적 기본정보 카드의 기존 필드 순서와 동작을 유지한다.
- 수주등록과 동일하게 600px 미만은 1열, 600px 이상 1200px 미만은 2열, 1200px 이상은 4열로 배치한다.
- 필드 간 가로 간격은 16px, 세로 간격은 8px로 유지하고 해당 폼 안에서만 MUI 입력 필드 기본 여백을 제거한다.
- 견적번호, 견적작성일, 거래처, 견적제출일을 첫 행에 배치한다. 참조, Incoterms, 결제조건, 견적유효기간을 다음 행에 배치한다. 화폐단위와 전체 너비 비고를 마지막 행에 배치한다.
- 거래처 picker는 인접 입력 필드와 높이 및 상단 정렬을 맞춘다. 좁은 화면에서도 요소가 겹치거나 페이지 가로 스크롤을 만들지 않는다.

### 날짜 필드

- 견적작성일과 견적제출일에 공통 `DateEditor`를 사용한다. 날짜 값과 API 형식은 기존 `YYYY-MM-DD` 계약을 유지한다.
- 달력 선택과 공통 날짜 입력의 축약 형식을 지원한다. 포커스 이동 시 정규화할 수 있는 입력은 ISO 날짜로 확정하며, 잘못된 값은 오류로 표시하고 저장을 막는다.
- 견적작성일은 기존 시스템 업무일 기본값과 필수 정책을 유지한다. 견적제출일은 선택 입력으로 유지한다.

### 견적 상세 품목

- 품목코드 컬럼은 일반 텍스트 입력 대신 수주 상세의 품목코드 셀과 같은 코드 선택 동작을 사용한다. 셀에서 품목 마스터 선택기를 열고 코드 직접 입력은 허용하지 않는다.
- 기존 `품목 선택` 툴바 버튼도 유지해 선택된 행에서 동일한 품목 선택기를 열 수 있게 한다.
- 품목 마스터 선택 시 `materialId`, 품목코드, 품목명, 규격, 단위를 기존처럼 행 스냅샷에 반영한다.
- 직접 입력 행은 품목명만 편집 가능하다. 품목코드·규격·단위는 직접 입력하지 않으며, 새 직접 입력 행에서는 비워 둔다.
- 저장 시 기존 필수 검증(품목명, 유효 수량 및 단가)과 금액 계산을 유지한다. 직접 입력 경로에서 품목 마스터 생성·수정 호출은 하지 않는다.
- 마스터 선택된 기존 행에서 품목명을 직접 바꾸면 수기 품목으로 전환하고, 마스터 참조 및 선택 품목의 코드·규격·단위가 직접 입력 값으로 오인되지 않도록 초기화한다.

## 범위와 호환성

- 프론트엔드 견적서작성 화면 및 상세 행 컬럼 정의, 관련 테스트와 날짜별 작업 문서·결과 문서만 변경한다.
- 견적 API, DB 스키마, 기존 저장 필드, 권한, 견적현황 기능, 수주등록 동작은 변경하지 않는다.
- 견적현황의 상세/수정 폼은 견적서작성 화면을 재사용하므로 동일한 입력 정책이 적용되는지 회귀 확인한다.

## 검증

- 견적 작성 테스트에서 수주 레이아웃과 같은 반응형 필드 배치, 날짜 정규화/오류, 코드 직접 입력 차단, 셀/툴바 품목 선택, 수기 품목명 입력, 마스터 선택 스냅샷과 저장 검증을 확인한다.
- 견적 등록 및 현황의 편집 화면에 회귀 영향이 없는지 확인하고 프론트엔드 빌드를 수행한다.
- 실제 브라우저에서 375px, 768px, 1280px 너비를 확인한다. 기본정보 필드 정렬, 날짜 달력 입력, 품목코드 선택, 수기 품목명 입력 및 페이지 가로 넘침을 점검하고 스크린샷을 `docs/result/20261117/quotation-entry-layout/screenshots/`에 보관한다.
