# 문서현황 검색조건 세션 복원 설계

## 목적

문서현황 페이지를 벗어났다가 같은 브라우저 탭 세션에서 다시 열어도 사용자가 마지막으로 검색 실행한 조건을 복원하고, 같은 조건으로 목록을 재조회한다.

## 사용자 승인 요구사항

- 저장 대상은 실제 검색 버튼으로 적용한 조건만 포함한다. 검색하지 않은 입력 중 조건은 저장하거나 복원하지 않는다.
- 빠른 검색어와 상세검색 입력값을 함께 복원한다.
- 페이지 복귀 즉시 저장된 검색조건으로 목록을 조회한다.
- `검색 조건 초기화`는 빠른 검색어와 상세검색 값을 비우고, 적용된 검색조건을 해제한다.
- 초기화한 상태 또한 세션에 저장하여, 이후 다시 페이지를 열어도 과거 검색조건이 되살아나지 않게 한다.
- 선택한 문서 행, 상세 패널 상태, 그리드 레이아웃은 저장 범위에서 제외한다.

## 기존 패턴

- `frontend/src/shared/hooks/usePageSessionState.ts`의 공통 훅은 페이지별 key를 이용해 `sessionStorage`에 상태를 저장하고 복원하며, 버전 및 validator를 지원한다.
- 메뉴관리와 공통코드 관리 페이지가 페이지 전용 key와 validator를 사용한다.
- 문서현황은 현재 빠른 검색 입력, 상세검색 입력, 적용된 API 필터를 별도로 보유하므로, 입력 상태와 마지막으로 적용된 상태를 분리해야 미적용 입력이 저장되지 않는다.

## 설계

### 세션 상태 모델

문서현황 전용 상태로 다음 두 항목만 저장한다.

- `keyword`: 마지막 검색 시 적용한 빠른 검색어
- `detailValues`: 마지막 검색 시 적용한 F1-Grid 상세검색 값

페이지 전용 key는 `s-erp:page:document-status`를 사용하고 버전 번호 및 타입 validator를 지정한다. API용 `DocumentStatusFilters`는 `keyword`와 `detailValues`에서 기존 변환 함수를 통해 계산한다. 별도로 중복 저장하지 않는다.

새 브라우저 탭 또는 저장된 상태가 없는 최초 접근은 기존 기본 동작을 보존한다. 즉, 결재신청일의 최근 1개월 기본 기간을 입력 및 조회 조건에 적용한다. 이미 저장된 상태가 있으면 저장된 검색값이 기준이며, 명시적으로 초기화해 비워 둔 상태는 기본 날짜 범위로 대체하지 않는다.

### 데이터 흐름

1. 첫 진입 때 공통 훅이 저장 상태를 읽는다. 유효하지 않거나 버전이 다른 값은 공통 훅 정책에 따라 제거하고 초기 기본 상태를 사용한다.
2. 유효한 저장 상태가 있으면 검색어와 상세검색 입력값에 복원하고, 같은 값으로 API 필터를 구성해 목록을 자동 조회한다.
3. 검색 실행 시점에만 현재 입력값을 세션 상태에 기록하고 해당 조건으로 API 필터를 갱신한다.
4. 검색 실행 전 입력 변경은 로컬 입력 상태만 변경하고 세션 상태와 그리드 조회를 바꾸지 않는다.
5. 초기화 시 검색어와 상세검색 입력을 빈 값으로 만들고 빈 검색 스냅샷을 세션에 저장하며, 날짜 범위를 포함한 적용 필터를 모두 제거한다.
6. 상세 패널을 열거나 닫는 행 선택 및 그리드 열 설정은 기존 동작을 유지하고 페이지 검색 세션에 포함하지 않는다.

### 오류·호환성

- sessionStorage 접근 또는 쓰기 실패는 기존 공통 훅의 동작을 따른다. 페이지의 메모리 상태와 조회는 계속 사용할 수 있다.
- 저장 key는 페이지 전용으로 분리한다.
- 상태 형식 변경은 버전 증가로 처리하여 오래된 상태를 폐기하고 기본값으로 시작한다.
- API 경로, 요청 파라미터, 권한, 응답 계약은 변경하지 않는다.

## 대안 및 선택 이유

1. **공통 page session hook (선택):** 다른 페이지의 기존 세션 상태 보존 관행과 일치하며 탭별 상태를 복원한다.
2. URL query parameters: 링크 공유와 새로고침 보존이 가능하지만 주소 노출 및 라우팅 연동이 필요하고 이번 요구 범위를 넘는다.
3. localStorage: 브라우저를 닫은 뒤에도 저장되어 세션 단위 복원 요구보다 상태가 오래 남는다.

## 구현 및 검증 범위

- 문서현황 페이지에서 검색조건 상태를 공통 훅과 연결한다.
- 유효한 저장 상태의 재진입 시 검색 입력과 결과 요청이 동일한 조건을 사용하는지 테스트한다.
- 검색 전 입력은 세션 저장에 영향을 주지 않는지 테스트한다.
- 초기화 상태가 저장되며 복귀 후 검색조건이 빈 상태인지 테스트한다.
- 저장 상태가 없을 때 기존 최근 한 달 날짜 기본값과 초기 조회 동작이 보존되는지 테스트한다.
- 프런트엔드 관련 테스트 및 빌드를 실행하고, 결과 문서에 변경·검증 결과를 남긴다.
- DB 및 백엔드 API 변경은 없다.
