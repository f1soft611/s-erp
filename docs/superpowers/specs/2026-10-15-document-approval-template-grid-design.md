# 결재선 템플릿 F1-Grid 관리 설계

## 목적

업무작성 모달의 `자주 쓰는 결재선 불러오기` 화면을 목록 버튼과 별도 이름 변경 폼에서 F1-Grid 기반 관리 화면으로 전환한다. 템플릿을 선택한 뒤 공통 불러오기 버튼을 누르던 흐름 대신 각 행의 액션에서 바로 불러오며, 결재선명은 그리드에서 편집하고 하단 저장으로 서버에 반영한다.

## 승인된 접근 방식

세 가지 대안을 비교했다.

1. **F1-Grid 인라인 편집 및 일괄 저장 (선택)**: 결재선명을 셀에서 편집하고, 수정된 행 전체를 하단 `저장`으로 반영한다. 행 우측 액션에서 불러오기와 삭제를 제공한다. 요청된 흐름을 따르며 별도의 선택 후 편집 단계를 없앤다.
2. 선택된 행 하나만 별도 이름 편집 폼으로 변경: 기존 편집 상태 모델을 유지하기 쉽지만 이름 변경을 그리드에서 직접 하는 요구와 맞지 않는다.
3. 이름 셀 수정 시 자동 저장: 저장 동작은 간단하지만 사용자가 요청한 하단 저장 버튼이 필요 없고, 실수 편집 시 즉시 서버에 반영된다.

사용자는 수정된 모든 행을 한 번에 저장하는 첫 번째 접근을 선택했다.

## 화면 및 동작

- 기존 템플릿 선택 버튼 목록을 F1-Grid로 교체한다.
- 최소 컬럼은 `결재선명`과 우측 `액션`이다. 이름 셀은 인라인 텍스트 편집을 지원한다.
- 각 행의 `액션` 컬럼에 `불러오기`와 `삭제`를 표시한다. 행 액션은 해당 행의 템플릿 ID에 직접 동작하며 그리드 행 선택에 의존하지 않는다.
- `불러오기`는 기존 상세 조회 및 참여자 검증을 실행한다. 성공 시 현재 결재선 설정 창의 임시 결재선·참조자만 교체하고, 템플릿 관리 창을 닫는다. 작성 모달에 반영하는 시점은 기존 `적용` 버튼으로 유지한다.
- `삭제`는 행의 템플릿을 대상으로 기존 확인 절차를 거친다.
- 관리 창 하단의 기존 `불러오기`는 `저장`으로 바꾸고, F1-Grid에서 수정한 모든 이름을 저장한다. 별도의 신규 템플릿 생성 버튼과 생성 입력 흐름은 유지한다.
- 이름은 trim 후 1~100자여야 한다. 동일 목록 안에서 이름 중복을 검사하고, 서버의 중복 오류도 사용자에게 표시한다.
- 저장 변경이 없으면 하단 저장을 비활성화한다. 목록 로딩/오류/빈 목록 상태를 구분하고 기존 오류 처리 원칙을 유지한다.
- 저장되지 않은 이름 수정이 있을 때 행 불러오기, 행 삭제 또는 관리 창 닫기를 요청하면 수정 내용을 폐기할지 확인한다. 취소하면 현재 편집을 보존하고, 확인하면 대기 중인 이름 수정을 폐기한 후 요청한 동작을 진행한다.

## 컴포넌트 및 데이터 흐름

- 영향 중심은 `DocumentApprovalSettingsDialog.tsx`와 `document-approval-settings-dialog.test.tsx`다.
- F1-Grid의 공개 `F1Grid`, `F1GridColumn`, `F1GridRef`, dirty changes API와 `renderCell` 행 액션 확장을 사용한다. Grid 공통 구현 자체는 변경하지 않는다.
- 이름 편집은 F1-Grid의 변경 집합으로 추적한다. 저장 시 변경된 각 행을 기존 `renameApprovalLineTemplate(templateId, name)` API로 보낸다. 목록/생성/상세/삭제 API 계약은 유지한다.
- 불러오기와 삭제 요청은 이름 변경 저장 중 비활성화하거나 중복 실행을 막는다. 기존 고정 기안자 및 임시 적용/취소 경계는 변경하지 않는다.

## 오류 및 부분 성공

- 이름 공백/길이/목록 내 중복 오류는 API 호출 전에 표시하고 저장 상태를 성공으로 표시하지 않는다.
- 이름 변경 API는 행별로 존재하므로 여러 행 저장은 서버 트랜잭션 하나로 원자화되지 않는다. 요청이 일부 성공하면 성공한 이름은 저장 완료로 목록에 반영하고, 실패 행의 수정 내용은 다시 시도할 수 있도록 보존하며 오류를 명시한다. 이미 저장된 이름을 반복 요청해 중복 오류가 나지 않도록 성공/실패 상태를 구분한다.
- 불러오기 실패는 기존 설정 창의 임시 결재선과 참조자를 그대로 보존하고 오류를 표시한다.
- 삭제 실패는 행을 목록에서 제거하지 않고 오류를 표시한다.
- 미저장 수정 폐기 확인을 취소하면 불러오기/삭제/닫기를 수행하지 않고 현재 그리드 편집 상태를 보존한다.

## 범위 제외

- 백엔드 API, DB schema, 템플릿 저장 모델 변경
- 템플릿의 참여자 구성 편집
- 다른 사용자/조직과 템플릿 공유
- 작성 모달의 기존 결재선 `적용` 및 취소 동작 변경
- F1-Grid 공통 코어나 신규 옵션 변경

## 접근성 및 반응형

- Grid 접근 가능한 이름을 `자주 쓰는 결재선 목록`으로 지정한다.
- 행 액션은 템플릿명을 포함한 고유 접근성 이름을 제공하고 Grid 셀/행 선택 동작과 분리한다.
- 편집 가능한 이름 컬럼, 저장 진행 상태 및 오류를 키보드와 스크린리더로 확인할 수 있게 한다.
- 375px, 768px, 1280px에서 모달 내부 Grid와 액션 접근성을 확인하고 페이지 전체 가로 넘침을 만들지 않는다.

## 검증 기준

- 목록을 F1-Grid로 표시하고 여러 행 이름 편집, 공백/100자 제한, 중복 이름 거부를 확인한다.
- 하단 `저장`이 모든 수정 행을 저장하며, 변경이 없을 때 비활성화되는지 확인한다.
- 여러 이름 수정 중 부분 실패가 발생하면 성공 행은 반영되고 실패 행은 수정된 이름과 오류를 유지하며 재시도되는지 확인한다.
- 각 행의 `불러오기`가 해당 행 ID로 상세를 조회하고 임시 상태만 교체하는지 확인한다.
- 각 행 삭제가 해당 ID 삭제와 기존 확인 흐름을 따르는지 확인한다.
- 미저장 이름 변경이 있는 상태에서 불러오기/삭제/닫기 확인을 취소하면 요청을 수행하지 않고 수정 내용을 보존하며, 확인하면 이름 변경을 폐기한 뒤 요청을 수행한다.
- 불러오기 및 삭제/API 오류에서 관련 행과 임시 상태를 보존한다.
- 관련 테스트 및 프론트엔드 빌드, 브라우저 375px/768px/1280px 검증을 수행한다.
- F1-Grid 사용 문서와 날짜별 작업 사양 및 결과 문서를 함께 갱신한다.
