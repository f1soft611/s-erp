# 문서 결재 액션 더보기 메뉴 설계

## 목표

문서작성 피드와 상세 화면에서 결재 액션 버튼을 상시 노출하지 않고 기존 `문서 더보기` 메뉴로 옮긴다. 결재 액션은 메뉴 첫 그룹에 배치하고, 공유·참조 및 수정·삭제 메뉴와 구분선으로 나눈다.

## 현재 구조

- 피드와 상세는 `DocumentApprovalDetailFeed`를 공유한다.
- 결재 액션은 `DocumentApprovalToolbar`의 `approvalActions`로 전달되어 상태 배지 옆에 표시된다.
- 공유, 참조자 추가, 수정, 삭제는 `DocumentActionsMenu`에 있다.
- 승인/반려/보완요청/최종확인/참조확인/상신취소/승인취소의 권한 판정과 각 기존 처리 함수는 공통 컴포넌트에 있다.

## 설계

- `DocumentApprovalDetailFeed`에서 권한이 있는 결재 액션을 메뉴 항목 데이터로 구성하고 `DocumentActionsMenu`에 전달한다.
- 메뉴 순서는 결재 액션 그룹, 문서 공유·참조 그룹, 문서 수정·삭제 그룹으로 한다.
- 각 비어 있지 않은 그룹 사이에만 구분선을 표시한다. 결재 액션 그룹은 다른 항목보다 먼저 나온다.
- 결재 액션 선택 시 메뉴를 닫은 뒤 기존 처리 함수를 실행한다. 기존 권한, 진행 중 비활성화, 확인 대화상자, 사유 입력, 성공/오류 처리는 바꾸지 않는다.
- 상태/문서종류 배지, 상단 고정, 처리 의견 입력은 기존 위치와 동작을 유지한다.
- 백엔드/API/DB 변경은 없다.

## 대안

1. 기존 더보기 메뉴에 결재 액션 그룹을 추가한다 — 선택. 피드와 상세의 액션 진입점을 하나로 통일하고 메뉴 컴포넌트를 재사용한다.
2. 결재 액션 전용 별도 더보기 메뉴를 둔다 — 기각. 기존 메뉴와 동작이 분산되어 사용자가 액션 위치를 찾기 어렵다.
3. 현재 결재 버튼을 유지하고 일부만 더보기로 옮긴다 — 기각. 요청한 화면 정리 목적을 완전히 달성하지 못한다.

## 검증

- 결재 액션이 툴바에 노출되지 않고 더보기 메뉴 첫 그룹으로 표시되는지 확인한다.
- 권한에 따른 항목 노출, 그룹 순서/구분선, 선택 후 메뉴 닫힘을 테스트한다.
- 승인, 반려/보완요청 사유 입력, 참조/최종 확인, 상신/승인 취소의 기존 흐름을 회귀 검증한다.
- 프론트엔드 빌드와 375px, 768px, 1280px 브라우저 화면을 확인한다.
