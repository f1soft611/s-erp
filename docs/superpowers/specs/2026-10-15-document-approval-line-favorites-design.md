# 업무작성 자주 쓰는 결재선 설계

## 배경과 목표

문서 작성의 `결재선 설정` 창에는 `자주 쓰는 결재선 저장`과 `자주 쓰는 결재선 불러오기` 버튼이 있으나 현재 비활성화되어 있다. 사용자가 결재·합의 단계와 참조자를 반복해서 구성하지 않도록, 로그인한 사용자가 이름을 붙여 여러 결재선 템플릿을 저장하고 다시 사용할 수 있게 한다.

기능은 문서별로 분리한다. 기존 전자결재 문서번호 코드(`eabus_no`)를 템플릿 분류 코드로 사용한다.

| 표시 이름 | 코드 |
|---|---|
| 기안 | `001` |
| 업무 | `008` |
| 지출 | `004` |
| 근태 | `031` |

## 설계 선택

1. **결재선에 맞춘 별도 마스터/상세 테이블 (선택)** — 즐겨찾기 이름과 소유자, 문서 코드를 마스터에 두고 단계 및 참여자 순서 정보를 상세에 저장한다. 기존 전자결재 문서와 결재선의 분리 구조에 맞으며, 사용자 소유권 및 순서 유효성을 명확히 검증할 수 있다.
2. **템플릿 전체를 JSONB 한 행에 저장** — 초기 테이블 수는 적지만 참여자/순서 검증이 DB에서 어렵고, 목록 및 부분 변경 시 JSON 처리 부담이 생긴다.

문서 결재선 행(`tb_electronic_approval_line_info`)은 실제 문서와 결재 처리 상태에 종속되어 있으므로 템플릿 저장에 재사용하지 않는다. 템플릿은 tenant와 인증 사용자 소유로 격리하며, 요청에서 전달한 사용자 ID를 소유권 근거로 신뢰하지 않는다. API는 기존 `/api/v1/groupware/approvals` 경로 아래 템플릿 목록, 생성, 이름 변경, 삭제 기능을 제공한다.

## 데이터와 검증 규칙

- 템플릿은 필수 이름, `eabus_no`, 소유 tenant/사용자 및 생성/수정 시각을 가진다.
- 각 상세 참여자는 단계 순서, 단계 내 순서, 참여 유형(`APPROVAL`, `AGREEMENT`, `REFERENCE`), 사용자 ID를 가진다.
- 결재/합의 단계와 참조자 목록을 함께 저장한다. 기안자 고정 단계는 템플릿에 저장하지 않고, 불러올 때 현재 작성자의 고정 단계로 유지한다.
- 저장 항목은 여러 개 허용한다. 같은 소유자와 문서 코드 안에서 이름은 중복될 수 없다. 이름 변경과 삭제는 템플릿 소유자만 할 수 있다.
- 문서 코드는 `001`, `008`, `004`, `031`만 허용한다. 목록은 현재 작성 중인 코드의 템플릿만 반환한다.
- 저장 시 참여자 ID가 같은 tenant의 활성 사용자에 해당하는지 서버가 검증한다. 순서값은 양수이며 결재 단계와 참조선의 중복 참여자를 거부한다.
- 사용자가 저장 후 비활성화된 경우, 불러오기는 해당 참여자를 포함한 템플릿을 그대로 적용하지 않고 명시적 오류를 반환한다. 실패 시 설정 창의 임시 결재선/참조선은 바뀌지 않는다.
- 모든 DB 변경은 날짜별 SQL, 변경 이력 및 롤백 문서를 `docs/database`와 `backend/DATABASE` 양쪽에 추가하고 `docs/database/db-schema.md`를 갱신한다.

## 사용자 흐름

1. 작성자가 `결재선 설정`을 연다. 기존 기안자 고정 및 결재/합의/참조 임시 편집 흐름은 그대로 유지된다.
2. 저장을 누르면 이름 입력 UI가 열리고, 현재 설정 창의 임시 결재/합의 단계와 참조자 목록을 현재 문서 코드로 저장한다. 저장 성공은 현재 작성 화면에 결재선을 적용하거나 설정 창을 닫지 않는다.
3. 불러오기를 누르면 현재 문서 코드에 해당하는 저장 목록이 표시된다. 선택한 항목은 설정 창의 임시 결재선과 참조자를 전체 교체한다. 적용 전 작성 화면에는 반영하지 않는다.
4. 작성자는 기존 `적용`을 눌러 불러온 구성을 작성 화면에 반영하거나, 취소/닫기로 임시 변경을 버린다.
5. 저장 목록에서는 이름 변경 및 삭제를 할 수 있다. 삭제 전 확인을 표시한다.

## 오류 처리와 접근성

- 서버 오류와 유효성 오류는 기존 API 오류 및 화면 알림 패턴에 따라 사용자에게 표시한다. 성공처럼 보이는 대체 상태를 사용하지 않는다.
- 저장/수정/삭제가 실패하면 목록 및 편집 상태를 유지한다. 불러오기가 실패하면 기존 임시 상태를 보존한다.
- 사용자 후보 옵션 로드 실패 시 템플릿 불러오기로 참여자 선택 상태를 훼손하지 않으며, 기존 사용자 로딩 오류를 표시한다.
- 이름 입력, 저장 목록, 선택/수정/삭제, 확인 다이얼로그는 키보드 접근이 가능해야 한다. 좁은 화면에서도 모달 내부 스크롤을 사용하고 페이지 너비를 넘기지 않는다.

## 검증 범위

- 프론트엔드 서비스는 목록/생성/이름 변경/삭제 요청 및 응답 계약을 검증한다.
- 설정 모달 테스트는 이름 입력, 코드별 필터링, 저장, 불러오기 후 임시 상태 교체, 이름 변경, 삭제 확인, 서버 오류 및 취소/적용 흐름을 확인한다.
- 백엔드 테스트는 문서 코드/이름/참여자 검증, 순서 유지, CRUD, tenant 및 소유자 격리, 다른 사용자의 템플릿 접근 거부를 확인한다.
- DB 변경 시 마이그레이션, 롤백 및 두 날짜별 스키마 관리 경로가 동기화되어 있는지 확인한다.
- 프론트엔드 관련 테스트와 빌드, 백엔드 관련 테스트를 실행한다. 브라우저에서 375px, 768px, 1280px 폭의 작성/설정 모달을 확인하고 결과 문서에 캡처를 남긴다.

## 범위 제외

- 문서 작성/상신 API 계약 변경 및 문서 결재 흐름 변경
- 다른 사용자가 만든 템플릿 공유, 조직 공용 결재선
- 기안자 단계 변경
- 결재선 템플릿의 참여자 구성을 목록 화면에서 직접 편집하는 기능 (템플릿을 불러온 뒤 설정 창에서 수정하고 새 이름으로 저장하는 방식은 가능)
