- 범위: 프론트엔드와 관련 문서·회귀 테스트. 백엔드, API 계약, DB 스키마 변경 없음. DB MCP 확인 대상 없음.
- 실제 서비스 데이터 대신 합성 응답으로 UI와 저장 요청을 확인했다. 백엔드 저장 자체를 검증한 것은 아니다.

| --- | --- | --- |

| 빈 날짜·일시·시간 폼 라벨 겹침 | native placeholder와 기본 라벨 위치가 겹침 | 세 입력 타입의 라벨을 위쪽에 고정 |

### 행 폼 계약과 유지한 동작

- 모바일 `addRow`는 초안 폼을 열고 **적용**할 때만 행·변경 집합·합계에 반영한다. 취소는 추가하지 않는다.
- 기존 행은 우측 `상세` 또는 `startEdit`로 폼을 열며, 기존 컬럼 편집 가능 여부·필수 검증·코드 도움창·계산을 재사용한다.
- 열린 폼은 데스크톱 크기로 변경되어도 적용·취소까지 유지한다.
- 편집 가능 컬럼이 없는 Grid에는 자동 액션을 만들지 않는다. `rowFormPlugin={{ enabled: false }}`는 모바일 자동 폼을 끈다.
- 데스크톱의 기본 즉시 추가·인라인 편집과 좌측 모듈 바는 유지한다.
- 출하계획 분할은 기존처럼 행 생성 후 편집을 시작한다. 폼 취소는 편집 초안만 버리므로 이미 생성된 분할 행은 기존 삭제 버튼으로 제거한다.
- 데이터가 있는 넓은 Grid의 내부 가로 스크롤을 검증했다. 빈 Grid에 별도 가로 스크롤 범위를 만드는 변경은 하지 않았다.
- [F1-Grid 문서](../../../../frontend/src/pages/f1-grid-docs/F1-GRID.md), 문서 포털 설명, API 참조와 타입 설명을 함께 갱신했다.

## 검증

### 관련 테스트 및 브라우저

| 대상 | 결과 |
| --- | --- |
| 행 폼 회귀 | 56개 통과. 모바일 기본 추가·수정·취소·검증·리사이즈·비활성화·데스크톱 및 native 라벨 포함 |
| 모듈 바 / PageHeader | 각각 5개 / 2개 통과 |
| 수주 / 출하 / 출하계획 / 수주 스크롤 | 각각 21개 / 18개 / 22개 / 1개 통과 |
| 거래명세서 / F1-Grid 문서 포털 | 각각 2개 / 30개 통과 |
| `npm run build` | TypeScript + Vite 프로덕션 빌드 통과 |
| 변경 파일 lint | 오류 없음. 기존 경고는 유지 |
| `node scripts\capture-mobile-sales-grid.mjs` | 합성 응답 기반 Playwright 회귀 통과, 브라우저 런타임 오류 없음 |

브라우저 회귀는 375/768/1280px에서 페이지 가로 넘침 없음, 데이터가 있는 Grid 내부 스크롤 이동, 수주·출하 합계의 패널 내부 배치와 접근, 출하계획·거래명세서 그리드의 좌우·아래 8px를 확인한다. 375px에서는 모바일 폼 필수 검증·취소·품목 도움창·수량/단가 입력·수정·저장 요청과 합계, 계획 수량 분할, 상단 모듈 전환·넘침 스크롤·메뉴 열기/닫기를 확인한다. 487px에서는 거래명세서현황의 설명을 접었을 때 경로와 조회 버튼이 같은 줄인지 확인한다.

예를 들어 375px 수주 Grid는 본문 폭 316px에 스크롤 폭 1488px였고 실제 `scrollLeft` 이동을 확인했다. 합계 하단은 상세 패널 하단 안에 있었다. 추가·수정 후 수주·출하 합계 330, 출하계획 저장 수량 `[8, 2]`도 확인했다.

### 기존 실패와 한계

전체 테스트·전체 lint가 통과했다고 판단하지 않는다. 변경 전 HEAD `3a1f1a58`을 별도 임시 폴더에 추출해 같은 의존성으로 비교했다.

- `f1-grid.test.tsx`: 현재와 변경 전 모두 177개 중 131개 통과, **46개 실패**. 실패 테스트 이름 집합이 동일했다. 기존 문자열/선택자 및 동작 기대 불일치가 포함되어 있으며 이 작업에서 수정하지 않았다.
- `dashboard-sidebar.test.tsx`: 단독 재실행 결과 현재와 변경 전 모두 20개 중 10개 통과, **10개 실패**, 실패 이름 집합 동일. 기존 로그인 지연·브랜딩/메뉴 기대 문제다. 최초 병렬 실행의 추가 시간 초과는 단독 재실행에서 발생하지 않았다.
- 전체 lint: 변경 전에도 `tests/common-code-management-page.test.tsx:53`의 조건부 `useImperativeHandle` 오류가 발생했다. 이 작업 범위 밖이므로 유지했다.
- 브라우저 확인은 Chromium과 합성 API 응답 기준이다. 실제 모바일 기기와 실제 서버 저장 검증을 대신하지 않는다.
