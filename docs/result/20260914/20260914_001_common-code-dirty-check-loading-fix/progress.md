- 범주: bounded

## 요구사항 반영

- 초기 진입 조회: 로딩 스피너 표시
- 조회 버튼 클릭: 로딩 스피너 표시
- 좌측 그룹 트리 클릭: 로딩 스피너 표시
- 저장 시: 조용한 로딩 스피너 비노출
- 상세 변경 시 좌측 트리 클릭: dirty 다이어그램 패턴 유지 및 확인 다이얼로그 적용
- 권한 관리 페이지와 동일한 dirty-check 패턴 유지

## 구현 내용

- 공통코드 페이지가 초기 진입, 조회 버튼, 그룹 선택에서 로딩 상태를 유지하도록 개선
- 저장 중에는 `loading` 상태를 비활성화하고 F1Grid의 로딩 오버레이를 보여주지 않도록 분리
- dirty 상태가 있을 때 좌측 그룹 전환 시 기존 `UnsavedChangesConfirmDialog` 패턴과 동일하게 확인 창 표시
- 계속 선택 시 대상 그룹의 상세 목록을 다시 조회하도록 처리하고, 취소 시 다이얼로그를 닫고 기존 선택 상태를 유지하도록 정리
- 선택 그룹 로딩이 끝나면 그룹 트리 로딩 스피너를 정상 종료하도록 정리
- 좌측 그룹 트리에서 빈 루트 행을 추가하면 우측 상세 상단은 `선택 그룹이 없습니다`로 표시하고, 본문은 빈 `공통코드 상세코드` 그리드를 유지하며 기존 상세 조회 로딩을 종료하도록 정리

## 검증 결과

- 단위 테스트: 19/19 통과 (`npm run test -- tests/common-code-management-page.test.tsx`)
- TypeScript + Vite 빌드: 성공 (`npm run build`)
- 브라우저 실시간 렌더링 검증:
  - 공통코드 페이지 진입 시 첫 번째 그룹('통화')의 상세 항목이 정상 로드됨
  - 좌측 트리에서 '루트 추가' 실행 시:
    - 신규 빈 행이 추가되고 우측 헤더가 '선택 그룹이 없습니다'로 즉시 전환
    - 우측 상세 영역은 빈 그리드("데이터가 없습니다") 상태로 유지
    - 무한 로딩/오버레이 없이 로딩 상태 즉시 종료
    - 불필요한 API 요청 및 무한 리렌더링(Infinite Update Loop) 제거 완료
  - 기존 그룹('국가') 재클릭 시 정상적으로 대상 그룹 상세 항목 로드 확인

## 리뷰 결과

- 구현 범위는 요구사항 문서 및 작업지시서와 일치한다.
- F1-Grid 로딩 오버레이는 조회/재조회 시 노출하고 저장 시에는 비노출하는 패턴을 유지했다.
- dirty 상태 확인 로직은 좌측 그룹 전환 시 권한 관리 페이지와 동일한 구조로 동작한다.
- 좌측 빈 행 추가 시 우측 빈 그리드 렌더링 및 '선택 그룹이 없습니다' 표시가 브라우저 환경에서 완전히 검증되었다.
