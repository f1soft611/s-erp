# F1-Grid Excel 텍스트 값 보존 결과

## 반영 내용

- 원인: exporter가 숫자형 문자열을 Excel String 셀로 기록해도 셀 표시 형식이 `General`이라 Excel에서 수정·확정할 때 숫자로 다시 해석될 수 있었다.
- 문자열 셀에 Excel 텍스트 서식(`@`)을 적용하고, 수주현황의 품목코드 컬럼도 `type: 'text'`로 명시했다.
- `000004` 값과 다른 문자열 표시값을 String으로 유지하며, 숫자/날짜/시간/Boolean typed 값은 기존 계약을 유지한다.
- F1-GRID 문서에 텍스트 서식과 코드 필드의 문자열 유지 조건을 반영했다.

## 검증

| 검증 | 결과 |
|---|---|
| 회귀 테스트 사전 실행 | 실패 확인: `000004` 셀의 `numFmt`가 없어서 실패 |
| Excel export·F1-GRID 문서·수주현황 테스트 | 42개 통과 |
| 프론트엔드 빌드 | 성공 |
| Windows Excel COM 열기·편집·저장·재열기 | 동일한 String/`@` 셀 형식의 검증용 workbook에서 `000004` 유지 |
| 변경 파일 `git diff --check` | 통과 |

화면 레이아웃 변경이 없어 브라우저 스크린샷은 생성하지 않았다. exporter가 만든 `.xlsx` 재로딩 테스트로 값/서식을 검증하고, 동일한 String/`@` 셀 형식은 실제 Excel 열기/저장 왕복으로 추가 확인했다.

## 범위

프론트엔드 공통 export, 수주현황 품목코드 컬럼, F1-GRID 문서에 한정했다. 백엔드/API/DB 및 기존 병행 작업 변경은 수정하지 않았다.
