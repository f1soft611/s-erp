## 재현과 원인

수주번호가 2개 이상의 상세 행으로 병합된 상태에서 컬럼을 고정하면 링크 중앙을 클릭해도 상세 보기 콜백이 실행되지 않았다. 수정 전 Chromium에서 실제 수주현황 컬럼과 합성 데이터를 렌더링하여 좌표 클릭 후 기대값 `[1]` 대신 `[]`가 반환되는 실패를 확인했다.

고정 셀은 `position: sticky`, `z-index: 2`, `isolation: isolate`로 각각 stacking context를 만든다. 링크의 기존 `z-index: 1`은 부모 영역을 벗어나지 못하므로 뒤쪽 투명 병합 셀이 클릭을 가렸다.

## 변경

`GridCell.tsx`에서 사용자 정의 콘텐츠를 표시하는 고정 병합 시작 셀만 z-index 3으로 올렸다. 병합 컨테이너는 포인터를 통과시키고 콘텐츠 래퍼와 시작 행 높이의 가상 요소만 포인터를 받는다. 따라서 링크는 직접 클릭 가능하며 첫 행 및 후속 행의 빈 공간 선택과 셀 범위 드래그는 유지한다. 고정 해제, 일반 셀과 편집 상태의 DOM/이벤트 구조는 변경하지 않았다.

수주현황 컬럼의 기본 고정 설정이나 링크 콜백은 변경하지 않았다. 백엔드/API/DB 변경이 없어 DB MCP 확인과 SQL 스크립트는 대상이 아니다. 기존 미커밋 엑셀 서식 작업과 동시 진행된 스크롤 작업은 수정하거나 되돌리지 않았다.

| 검증 | 결과 |

| `npm run build` | 통과 |
| 변경된 `GridCell.tsx`, 브라우저 테스트의 oxlint | 오류 없음. GridCell의 기존 Fast Refresh/ref 경고 유지 |
| `git diff --check` | 통과 |

브라우저 테스트는 375/768/1280px × 고정 해제/왼쪽 고정/오른쪽 고정을 확인한다. 각 조합에서 2행·3행 병합 링크 중앙 클릭이 해당 수주의 콜백을 정확히 한 번 실행하고, 빈 공간 클릭이 개별 상세 행을 선택하며, 셀 모드로 전환한 뒤 빈 공간 드래그로 범위가 생성됨을 확인했다. 고정 상태에서는 가로 스크롤 후 링크 클릭과 페이지 전체 가로 넘침 없음도 확인했다.

테스트는 합성 데이터만 사용했으며 실데이터나 계정 정보는 사용하지 않았다. 기존 4173 S-ERP Vite 서버를 확인해 재사용했고 해당 서버는 종료하지 않았다. 테스트의 Chromium과 페이지는 종료했다.

### 기존 검증 실패 구분

- 전체 `npm run lint`는 본 작업에서 변경하지 않은 `tests/common-code-management-page.test.tsx:53`의 조건부 `useImperativeHandle` 호출 오류로 실패한다. 해당 파일이 HEAD와 동일함을 확인했다.
- 추가 실행한 `tests/f1-grid.test.tsx`는 124개 통과, 47개 실패다. 깨진 한글 기대 문자열, 기존 병합 경계/편집 계약 기대값 등에서 실패한다. 공유 소스를 되돌리지 않고 임시 Vitest load 플러그인으로 **GridCell만 HEAD 원본으로 대체**하여 같은 테스트를 비교했다. 원본도 동일한 47개 테스트가 실패하며 실패 이름 집합의 차이는 0개다. 본 수정으로 추가된 실패는 없고 관련 없는 오류는 변경하지 않았다.
