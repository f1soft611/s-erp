# 공통 상세검색 날짜 입력 개선 결과

## 요구 및 적용 범위

- [작업지시서](../../../directions/20261022/20261022_003_grid_search_date_input_work_instruction.md)
- [계획서](../../../plan/20261022/20261022_003_grid_search_date_input_plan.md)
- [상세 사양서](../../../spec/20261022/20261022_003_grid_search_date_input_spec.md)
- 사용자 승인에 따라 특정 화면이 아닌 공통 `PageSearchArea`의 날짜 검색 전체에 적용했다.

## 재현 조건과 원인

- F1-Grid의 날짜 셀 편집기는 텍스트 기반 축약 입력과 MUI 달력을 제공했다.
- 반면 공통 상세검색의 시작일·종료일은 브라우저 native `type="date"`를 사용해 같은 숫자 축약 입력을 사용할 수 없었다.

## 해결

- 기존 `DateEditor`의 날짜 정규화·달력을 재사용하고 검색 폼용 label, outlined 스타일, 오류, blur callback 및 자동 포커스 해제 옵션을 추가했다.
- 기존 셀 편집기에서 옵션을 생략했을 때의 기본 스타일·포커스·키보드 계약은 유지했다.
- 시작일·종료일에 `YYYYMMDD`, `YYMMDD`, `MMDD`, `DD`, `M-D`, `YYYY-MM-DD` 및 달력 선택을 지원한다.
- blur 또는 조회 시 날짜를 ISO로 확정한다. 잘못된 날짜는 원문과 오류를 표시하고 실제 조회 callback 및 패널 닫기를 차단한다.
- 빈 endpoint와 한쪽 날짜만 지정한 검색, 기본값·초기화·외부 ISO 날짜 복원을 유지했다.
- controlled 폼에서 다른 날짜를 입력해도 이미 표시된 오류가 사라지지 않도록 오류 표시를 현재 입력값에서 계산한다.
- 입력 하나당 160px 확보가 어려운 영역에서는 시작일·종료일을 세로로 배치한다. 숫자 키보드와 ISO placeholder를 제공한다.
- F1-Grid 사용 문서와 포털의 필터·정렬 가이드를 함께 갱신했다.

## 날짜 기준 구분

- 축약 입력에서 생략한 연·월은 기존 셀 편집기와 동일하게 브라우저 로컬 날짜를 사용한다.
- 기존 서버 시스템 날짜 기반 검색 기본값은 변경하지 않는다.
- 백엔드, API 데이터 계약, DB 스키마 및 SQL 변경은 없다. DB MCP 확인 대상 작업이 아니다.

| 실제 Chromium 375·768·1280px | 축약 입력, 달력 선택, 오류 조회 차단, 초기화, 부분 범위 및 가로 넘침/아이콘 겹침 검사 통과 |
| 브라우저 page error | 최종 검증에서 없음 |
| 수정 파일 진단 및 scoped `git diff --check` | 오류 없음 |

### 기존 그리드 테스트 제한

- 전체 `f1-grid.test.tsx` 실행 결과 156개 중 110개 통과, 46개 실패가 있었다.
- HEAD의 원본 `DateEditor.tsx`를 임시 snapshot으로 생성하고 Vitest alias로 교체한 비교 실행에서도 동일한 46개 테스트가 실패했다.
- 변경 전/후 실패 테스트의 전체 이름 집합이 동일함을 JSON 결과로 비교했다. 새로 추가된 실패는 없었다.
- 해당 파일에는 깨진 문자열 기대값과 날짜 입력 외 기능의 기존 실패가 포함되어 있으며, 이번 작업에서 수정하지 않았다.
- 따라서 전체 그리드 테스트가 통과했다고 주장하지 않는다. 병합/PR은 수행하지 않았다.

### 브라우저 검증 범위

- 기존 `http://127.0.0.1:4173` S-ERP 개발 서버를 재사용했다. 서버를 새로 실행하거나 기존 서버를 종료하지 않았다.
- 실제 `PageSearchArea`와 `AppSettingsProvider`를 브라우저에서 직접 mount하고 합성 날짜만 제공했다. 업무 데이터나 계정 정보를 캡처하지 않았다.
- 공통 컴포넌트의 실제 렌더링·입력·달력·callback을 검증했으며, 각 업무 페이지의 백엔드 조회를 종단간 검증한 것은 아니다.
- 검증용 Chromium은 성공·실패와 관계없이 `finally`에서 종료했다.
