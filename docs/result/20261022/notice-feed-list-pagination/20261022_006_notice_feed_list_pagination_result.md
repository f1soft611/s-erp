# 20261022_006 공지사항 피드·리스트 페이징 결과

## 결과 요약

- 공지사항 피드형과 리스트형에 문서작성 페이지와 같은 20건 단위 공통 페이징을 적용했다.
- 고정 공지는 일반 공지와 분리 조회하고, 기존 API의 `resultCnt`에 맞춰 전체 결과를 수집한다.
- 백엔드 API 및 DB 변경은 없다.

## 검증 결과

| 검증 | 결과 |
| --- | --- |
| `use-notice-list.test.tsx`, `common-view-mode.test.tsx` | 25개 통과 |
| 페이징/고정 분리 통합 테스트 | 3개 통과: 피드, 리스트, 일반 공지가 없을 때 고정 공지 표시 |
| `npm run build` | 성공 (1MB 초과 chunk 경고 출력) |
| 전체 `notice-page-local-updates.test.tsx` | 38개 중 22개 통과, 기존 실패 16개 재현 |

전체 테스트 파일의 기존 실패는 중복 렌더링된 공지 제목에 대한 단일 요소 조회 실패와 댓글 관련 fixture/렌더링 불일치다. 작업 전 기준선에서도 해당 테스트 영역의 기존 실패가 확인되어 있었으며, 이번에 추가된 페이지네이션 및 고정 분리 테스트는 통과했다.

## 브라우저 확인

`/groupware/community/notice`에서 375px, 768px, 1280px 화면 폭으로 피드형과 리스트형을 각각 확인했다. 현재 환경의 조회 결과는 일반 공지 6건, 고정 공지 2건이며, 양쪽 보기에서 고정 영역과 일반 목록이 분리되어 표시됐다.

현재 일반 공지 수가 페이지 크기 20건보다 적어 실제 서버 데이터로 다음 페이지 자동 호출을 재현할 수는 없었다. 다음 페이지 누적, 중복 요청 방지, 실패 페이지 재시도 및 고정 전체 수집은 관련 자동화 테스트로 검증했다. 브라우저의 375px/768px 캡처에서는 기존 앱 셸의 고정 내비게이션과 좁은 콘텐츠 영역이 확인되었으며, 이번 페이징 변경 범위에는 포함하지 않았다.
