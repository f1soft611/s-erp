# 20261022_008 거래처 관리 페이지 구현 결과

## 구현 요약

- `/co/master/customers`를 Dashboard의 `co/customers` 화면으로 연결했다.
- `tb_customer_info` 조회·등록·수정 API와 테넌트별 조회/중복 확인을 추가했다.
- 별도 채번 테이블이나 PostgreSQL sequence를 만들지 않고 기존 eGov `IDS` 생성기를 사용한다. `tb_customer_info`용 generator는 6자리 zero-padding을 적용하며, 날짜별 SQL은 기존 거래처 코드를 기준으로 `ids.next_id`를 상향 초기화한다.
- 목록은 F1-Grid로 구성하고 기본 키워드 검색, 컬럼 metadata 기반 상세검색, 신규·수정 행 폼, 저장 후 재조회 및 오류 메시지를 연결했다.
- 물리 삭제는 제공하지 않고 `useAt`의 `Y`/`N`으로 사용 여부를 관리한다.
- 상세검색의 법인등록번호와 행 폼의 우편번호·팩스번호·메모 등 목록 비표시 필드를 F1-Grid metadata로 연결했다.

## 주요 변경

- 백엔드 고객 도메인 model/DAO/service/mapper/controller와 eGov ID Generator bean을 추가했다.
- 프론트엔드 고객 타입/service/hook/F1-Grid/page 및 Dashboard 연결을 추가했다.
- F1-Grid 문서에 숨김 검색 필드와 행 폼 필드의 사용 기준을 반영했다.
- `tb_customer_info` 스키마는 수정하지 않았다. DB MCP 확인은 스키마 및 제약 metadata 범위였으며, 업무 데이터 행이나 `ids` 카운터 행은 조회하지 않았다. 마이그레이션은 실행하지 않았다.
- 생성·수정은 서버에서 테넌트 관리자 역할을 확인하고, 인증 사용자 ID가 없거나 숫자가 아니면 거부한다. 입력 오류 메시지는 공통 응답의 `resultMessage`에도 반영해 화면에서 구체적으로 표시되도록 했다.

## 공통코드 패턴 정정 및 도메인 스키마 보완

### 사용자 지시 반영

- 검색 조건은 tenant가 없는 `CustomerInfoSearchCondition`으로 바꾸고 서비스가 tenant 및 정규화 검색값을 Map으로 조립하도록 공통코드와 통일했다. 조건 없는 목록 overload도 제공한다.
- 조회 성공 반환형은 `ResultVO`, 저장은 `ResponseEntity<ResultVO>`로 맞췄다. 존재하지 않는 행은 서비스의 `findByIdOrThrow`에서 HTTP 404로 처리한다.
- 별도 `CustomerInfoBatchService`와 변경 행/변경 세트/요청/결과 모델을 추가했다. 공통코드처럼 등록·수정 서비스를 재사용하고 `rollbackFor = Exception.class`로 전체 저장 트랜잭션을 묶었다.
- 화면은 행별 POST/PUT 반복 대신 `POST /api/v1/co/master/customers/save-batch`를 한 번 호출한다. eGov IDS 채번과 인증 사용자 감사 기록은 승인된 기존 요구대로 유지한다.
- 저장 요청·검색 조건·배치 모델의 누락된 `@Schema` 설명을 보완했다. 총 7개 도메인 모델의 클래스와 모든 비정적 업무 필드(상속 필드 포함)를 검증한다. 필수 거래처명, 코드 채번/수정 필수, Y/N 허용값, 로컬/서버 ID 차이, 삭제 금지 계약을 기술했다.
- 지정 tenant MCP의 `list_tables`와 `describe_table(tb_customer_info)`로 테이블 metadata를 재확인했다. 업무 데이터나 카운터 행은 조회하지 않았다. 이 정정은 DB 스키마 변경이 없어 신규 SQL이 필요하지 않으며, 기존 `20261022_005` counter 초기화 스크립트도 실행하지 않았다.

### 재현 조건·원인·해결 및 회귀 검증

| 재현 조건 | 원인 | 해결 및 검증 |
|---|---|---|
| 여러 신규·수정 행 저장 도중 뒤쪽 행에서 오류 | 행별 요청은 앞선 행만 먼저 커밋될 수 있음 | 단일 배치 요청과 서버 트랜잭션 적용. 정상 commit 및 후속 checked exception rollback 검증 |
| 저장 버튼을 연속 실행 | React state 갱신 전 중복 호출 가능 | ref로 즉시 잠금. API 한 번 호출과 실패 시 dirty 유지 검증 |
| 후속 행의 필수값 누락 또는 삭제 변경 | 일부 행을 먼저 전송하거나 삭제 변경을 무시할 위험 | 모든 행을 먼저 검증하고 삭제를 명시적 오류로 거부. 요청 미전송 검증 |
| 저장 성공 후 목록 재조회만 실패 | 저장된 신규 행이 dirty로 남으면 재저장 시 중복 등록 가능 | 서버 저장 성공 시 dirty 해제 후 재조회. 실패 시 저장 완료와 조회 재시도 안내 검증 |
| 잘못된 `useAt` 검색값 | GET 반환형 정정 과정에서 입력 예외의 HTTP 400 변환 누락 | 입력 예외 응답 처리와 구체적 `resultMessage` 회귀 테스트. 잘못된 인증 사용자 ID의 HTTP 401 유지도 확인 |
| OpenAPI에서 요청·배치 필드 설명 확인 | 클래스 일부에만 `@Schema`가 있고 필드 설명과 검색 모델 정보 누락 | 클래스/필드 metadata 8건 및 실제 Swagger model resolver 1건 검증. 배치 중첩 모델과 상속된 저장 필드·필수값 생성 확인 |

트랜잭션 테스트는 Spring 트랜잭션 interceptor와 `DataSourceTransactionManager` 및 mock JDBC connection으로 commit/rollback 호출을 확인했다. 실제 DB 행을 넣거나 수정하는 통합/E2E 테스트는 수행하지 않았다. OpenAPI 검증은 Swagger model resolver 기반이며 실행 중인 서버의 API 문서 화면 검증은 아니다.

이번 정정은 배치 저장 및 metadata 보완으로 화면 레이아웃은 바꾸지 않았다. 아래 3개 뷰포트 캡처는 최초 구현의 mock 화면 캡처를 유지하며, 저장 동작의 최종 증거는 위 자동 테스트와 빌드 결과다. `git diff --check`도 통과했다.

## 번호·연락처 자동 포맷

- 원인: 기존 요구사항은 허용 문자를 숫자/하이픈으로 제한하면서 하이픈 위치를 강제하지 않는다고 명시했고, `sanitizeInput`은 비허용 문자 제거만 수행했다. 따라서 직접 입력한 하이픈만 유지되고 자동 삽입은 구현되지 않았다.
- F1-Grid에 재사용 가능한 `inputFormat` 열 옵션과 공통 formatter를 추가했다. 인라인 입력, 행 폼, TSV 붙여넣기, 컬럼 metadata에서 생성한 상세검색에 동일한 formatter를 적용한다.
- 거래처 필드 설정: 사업자번호 `000-00-00000`(최대/검증 10자리), 법인등록번호 `000000-0000000`(최대/검증 13자리), 우편번호(최대/검증 5자리), 전화/팩스(`02`는 9·10자리 허용/최대 10자리, 그 외 10·11자리 허용/최대 11자리)로 확장했다.
- 입력 상한(`maxDigits`)은 인라인·행 폼·TSV 붙여넣기·상세검색에 공통 적용하고, 저장 검증(`validDigitCounts` 및 전화 prefix 규칙)은 `validateGridRow`에서 처리한다. 비어 있지 않은 값은 변경 여부와 무관하게 저장 시 검증되어, 기존 값도 규칙을 벗어나면 저장이 차단된다.
- 자동 포맷은 값 입력 또는 붙여넣기 시에만 수행한다. 앞자리 0은 문자열로 보존하고 입력 중 caret 위치를 유지하며, 기존 저장값과 API/DB 계약은 변경하지 않는다.
- 회귀 검증: formatter 20건, F1-Grid 입력/붙여넣기/caret 12건, 입력 포맷 저장 검증 4건, 거래처 페이지 10건, 검색 메타데이터 1건, 상세검색 21건으로 총 **68건 통과**.
- 실행 명령: `npm run test -- tests/customer-number-input.test.ts tests/f1-grid-input-format-validation.test.ts tests/f1-grid-input-sanitizer.test.tsx tests/customer-management-page.test.tsx tests/page-search-fields.test.ts tests/page-search-area-detail.test.tsx`.
- 넓은 기존 F1-Grid 테스트군은 이전 변경 기준선에서 실패가 기록되어 있어 이번 수정에서는 재실행하지 않았다. 해당 실패는 이번 수정으로 새로 발생한 것인지 확인하지 않았다.
- 브라우저 자동화 클라이언트가 연결되지 않아 실브라우저 입력 확인은 수행하지 못했다. 레이아웃은 변경하지 않았으며 기존 반응형 캡처를 유지한다. DB 스키마 변경이나 API 직접 입력 검증 변경은 없다.
