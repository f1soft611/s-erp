# 결과 문서

## 작업명

F1-Grid 전체 영역 로딩 스피너 적용

## 변경 내용

### 1) 공통 로딩 오버레이 추가

- [frontend/src/shared/components/f1-grid/core/F1Grid.tsx](../../../frontend/src/shared/components/f1-grid/core/F1Grid.tsx)에 전체 그리드 로딩 오버레이를 추가했습니다.
- `loading=true`일 때 최상위 `role="grid"` 컨테이너에 `aria-busy="true"`를 설정했습니다.
- 기존 `GridLoadingSkeleton` 경로와 `grid-loading-skeleton`, `grid-loading-row-skeleton` 테스트 식별자는 유지했습니다.
- 오버레이는 그리드 전체 영역을 덮는 방식으로 중앙에 `CircularProgress`를 배치했으며, 로딩 중에는 상호작용을 차단할 수 있도록 `pointerEvents`를 유지했습니다.

### 2) 스켈레톤 보존

- 전체 로딩 스피너를 추가했지만, 기존 스켈레톤 렌더링 구조를 삭제하지 않았습니다.
- 로딩 중에도 기존 스켈레톤과 5개 행의 placeholder가 그대로 보이는 구조를 유지했습니다.
- 로딩 종료 후 오버레이만 제거하고 기존 그리드 본문이 다시 보이도록 보존했습니다.

### 3) 회귀 테스트 작성

- [frontend/tests/f1-grid.test.tsx](../../../frontend/tests/f1-grid.test.tsx)에 로딩 오버레이 회귀 케이스를 추가했습니다.
- 테스트는 다음 조건을 검증합니다.
  - root `role="grid"`에 `aria-busy=true`
  - `grid-loading-skeleton` 유지
  - 5개 row skeleton 유지
  - `f1-grid-loading-overlay` 및 로딩 스피너 존재

## 참고

- 이 변경은 공통 `F1Grid`/`F1Tree` 의존 구조에서 동작하므로 각 화면의 `loading` prop 전달 방식은 그대로 유지했습니다.
- 전체 F1Grid 파일의 기존 다른 테스트가 현재 저장소 상태에서 별도로 실패하고 있어, 이번 작업은 로딩 오버레이 자체 회귀를 기준으로 검증했습니다.
- 브라우저 캡처는 이번 작업 범위 기준으로 자동화 회귀 검증까지만 수행했습니다.
