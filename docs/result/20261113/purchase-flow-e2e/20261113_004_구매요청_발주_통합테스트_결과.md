### 실패 1건: 테스트 기대값 오류
`상태/출처 필터(직접·정상)`은 "직접 발주 정상 행 6건 이상"을 기대했으나 그 시점 실제 행은 5건(PO4 3행 + PO5 2행)이라 실패했다. 서버 동작 문제가 아니라 테스트 스크립트의 기대값 오류이며, 수정은 이후에 이루어져 해당 시점 이후 DB 값은 모두 일치한다.

## DB 대조 (MCP)

- 모든 발주에서 헤더 공급가·세액·합계가 행 합계와 일치한다.
- 구매요청 합계 일치(MR-A 219,020 = MC1 204,020 + 15,000, MR-B 83,000).
- 직접 발주 PO-20261113-0005: 행 삭제·수량 수정 후 MR-20261113-0003 합계와 MC-20261113-0004 합계가 55,000으로 같고 연결 행 2건.
- 직접 발주 PO-20261113-0006(취소): MC-20261113-0005 `use_at=N`·연결 행 0, MR-20261113-0004 `use_at=N`(요청 상태·합계 0).
- 스냅샷: 신규 발주는 회사·구매처(상호)·발주자 정보가 채워졌고, 기존 PO-20261113-0001은 NULL(출력 시 현재 정보로 대체).
- 출력 기록: PO-20261113-0002 `print_at=Y`, 출력자 기록. 입고대기마감: PO-20261113-0003의 1행이 `Y`로 남아 있다.

## 확인하지 못한 항목

- 브라우저 화면 조작은 실제 백엔드로 하지 않았다(API 호출 기반). 화면은 합성 응답 브라우저 테스트로 별도 검증했다.
- 가입고 연동 없음(가입고 테이블 없음): 가입고가 있는 행의 삭제·취소 차단은 검증할 수 없다.
- 확정 수량을 넘겨 발주하면 잔량이 음수(-2)로 저장된다. 사양(경고만, 저장 허용)대로이며 후보에서는 빠진다.
