# 즐겨찾기 폴더·메뉴 구분 결과

## 변경 내용

- 폴더: 속이 채워지지 않은 `FolderOutlined` 윤곽선 아이콘, 기존 행 색상 상속, 일반 굵기의 이름, `폴더` 표시. 아이콘 별도 색상, 배경/테두리 강조와 굵은 이름 없음.
- 메뉴: 회색 문서 윤곽 아이콘과 일반 굵기의 이름. 루트/폴더 안 메뉴에 같은 스타일 적용.
- 폴더·메뉴 글자색은 기존 일반 메뉴와 동일하게 light `#475569`, dark `#dbeafe`로 통일했다. 폴더 아이콘도 해당 행의 색상을 상속한다.
- 색 이외의 형태/텍스트와 TreeItem 접근성 이름으로 같은 이름의 폴더와 메뉴를 구분.
- 긴 이름은 한 줄 말줄임과 전체 이름 title을 제공하고 아이콘/더보기/폴더 표시는 축소하지 않음.
- 좁은 flex 패널에서 긴 메뉴 이름의 최소 콘텐츠 너비가 전체 트리를 늘리는 현상을 발견해 최상위 컨테이너에 `minWidth: 0`을 적용.
- 폴더 펼침, 메뉴 선택, 더보기/우클릭, 빈 폴더 안내, 저장/API/권한 계약은 유지.

## 검증

| 명령/범위 | 결과 |
|---|---|
| `npm run test -- tests/menu-favorites.test.tsx` | 13개 통과. 새 구분 테스트가 구현 전 실패하고 구현 후 통과 |
| `npm run lint -- src\pages\dashboard\components\MenuFavoritesTree.tsx tests\menu-favorites.test.tsx tests\menu-favorites-distinction.browser.mjs` | 통과 |
| `npm run build` | TypeScript + Vite 통과 |
| `node tests\menu-favorites-distinction.browser.mjs` | 375/768/1280px × light/dark 6개 조합 통과 |
| `git diff --check` | 통과 |

브라우저는 기존 S-ERP `http://127.0.0.1:4173` 개발 서버를 확인하고 재사용했다. 서버를 새로 시작하거나 종료하지 않았다. 실제 즐겨찾기 컴포넌트와 앱 테마를 320px 폭 패널에 렌더링한 가상 데이터 테스트이며 실제 계정/테넌트 행은 사용하지 않았다.

같은 이름 폴더/메뉴, 긴 이름의 말줄임, 빈 폴더 펼침, 원래 module/menu 선택 callback, 더보기/우클릭, 폴더 전용 배경/테두리 부재 및 기존 행 색상을 상속하는 아이콘과 일반 이름 굵기(400), 페이지/트리 가로 넘침과 버튼 겹침 부재를 확인했다. Collapse 완료 후 스크린샷을 저장했다.

후속 요청 "폴더에 컬러 넣지마.." 반영 시 브라우저의 배경 제거 조건이 기존 컬러 구현에서 실패함을 먼저 확인했다. 컬러 제거 후 관련 테스트 13개, 변경 파일 lint, build 및 6개 브라우저 조합이 통과했고 스크린샷을 중립색 버전으로 갱신했다.

최종 후속 요청 "폴더 아이콘 색도 기존걸로 그냥 해줘", "굵은표시 제거"를 반영했다. 아이콘 상속 색상 검증이 수정 전 실패했고 수정 후 통과했다. 관련 테스트 13개, lint, build 및 6개 브라우저 조합을 다시 통과하고 최종 스크린샷을 갱신했다.

추가 요청인 폴더·메뉴 폰트 컬러는 `DashboardMenuTree`의 일반 메뉴 색상을 직접 확인해 맞췄다. 검정 계열 기존 값에서 브라우저 색상 검증이 실패한 뒤, 수정 후 두 이름과 폴더 아이콘의 색상 검증이 6개 조합에서 통과했다. 테스트 13개, lint, build를 다시 통과하고 스크린샷을 갱신했다.

### 헤더 크기/여백 일치 및 윤곽선 아이콘 최종 요청

- 즐겨찾기 헤더를 기존 메뉴의 58px CSS 변수 높이, 16px 좌우 여백, 중앙 정렬, subtitle2 제목 크기/굵기/글자 간격과 배경으로 맞췄다.
- 별 아이콘, `즐겨찾기` 제목, `새 폴더` 버튼과 생성 동작은 유지한다.
- 트리 바깥 12px 여백과 패널 배경을 유지/일치시키고 행 최소 높이 36px, 하단 간격 2px, 글자 크기 14px과 투명 좌측 3px 테두리를 기존 메뉴와 맞췄다. 이름 굵기는 400 유지.
- 사용자 정정에 따라 색상은 그대로 두고 채워진 폴더 아이콘만 `FolderOutlined`로 교체했다. 폴더 전용 색상/배경 강조는 추가하지 않았다.
- 실제 `DashboardMenuTree`를 같은 테마/58px CSS 변수로 별도 렌더링해 헤더 높이/좌우 여백/배경/글자 크기/굵기/글자 간격/제목 수직 위치, 본문 위 여백, 행 최소 높이/글자 크기를 직접 비교했다.
- 구현 전 헤더 53px 대 기존 58px, 배경/글자 간격/중앙 위치 차이가 검증에서 실패했고 구현 후 6개 viewport/theme 조합 모두 일치했다. 윤곽선 아이콘 테스트도 수정 전 실패 후 통과했다.
- 관련 테스트 13개, 변경 파일 lint, build 통과. 스크린샷 6개를 최신 상태로 갱신했다.

### 추가 사이드바 회귀 검증의 기존 실패

`tests/dashboard-sidebar.test.tsx`를 함께 실행했을 때 10개 통과/10개 실패했다. 로그인 필드/프로필 메뉴 대기와 기존 펼침 아이콘 이름에 대한 실패였다.

작업 파일을 되돌리지 않고 Vitest 메모리 변환으로 `HEAD`의 원래 `MenuFavoritesTree.tsx`를 사용해 같은 사이드바 테스트를 다시 실행했다. 동일한 10개 테스트가 실패해 이번 즐겨찾기 표현 변경 이전에도 재현됨을 확인했다. 해당 테스트/인접 작업 파일을 수정하지 않았다. 전체 사이드바 테스트가 통과했다고 보고하지 않는다.
