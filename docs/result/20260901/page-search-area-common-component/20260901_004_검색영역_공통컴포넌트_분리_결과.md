# 검색 영역 공통 컴포넌트 분리 결과

- 관련 사양서: [20260901*004*검색영역*공통컴포넌트*분리\_사양서.md](../../../spec/20260901/20260901_004_검색영역_공통컴포넌트_분리_사양서.md)

## 변경 내용

1. `frontend/src/shared/components/PageSearchArea.tsx` 신규 생성 — 검색 필드들을 감싸는 공통 컨테이너.
2. [MenuManagementPage.tsx](../../../../frontend/src/pages/settings/system/menus/MenuManagementPage.tsx)
   - 기존 `PageHeader`의 `children`으로 렌더링되던 모듈 선택(`FormControl`+`Select`)과 메뉴명/코드 검색(`TextField`)을 `PageSearchArea`로 이동.
   - 화면 순서를 `PageHeader → PageMessageArea → PageSearchArea → MenuManagementPanel`로 재구성(에러 메시지가 검색 영역보다 위에 위치).
3. 검색 UI가 없는 RoleManagementPage, DocumentsPage, OverviewPage, F1GridTestPage, DashboardContent fallback은 변경하지 않음(기존에도 `헤더 → 에러 메시지 → 패널` 순서였고 검색 영역이 필요 없음).

## 검증

- `npm run build` → 성공
- `npm run test -- tests/menu-management-f1-grid.test.tsx` → 31개 중 30개 통과, 1개 실패
  - 실패 테스트(`shows the full saved menu hierarchy in the page breadcrumb`)는 이전 작업(페이지 헤더 공통화)에서도 동일하게 실패가 확인된 **기존 미해결 이슈**이며 이번 변경과 무관함.

## 영향 범위

- 메뉴관리 화면의 모듈 선택/검색 필드 위치만 변경(헤더 내부 → 별도 검색 영역). 필드의 동작, 값, 이벤트 핸들러는 동일하게 유지됨.
- 다른 화면은 변경 없음.
