## 결과 요약

영업 화면의 고정 소수점 대체값을 없애고, 표시 전용 컬럼이 계약 규칙을 따르게 했으며, 계약 변경과 직접 설정을 자동 테스트로 막았다. 프론트·서버 가이드에 규칙과 JSON 예시를 문서화했다.

## 검증 결과

- 프론트: 수주·견적·출하·출하계획·명세서·소수점 관련 42개 테스트 파일 중 39개 통과. 병렬 실행에서 시간 초과로 실패한 3개 파일(5건)은 단독 재실행에서 57건 모두 통과했다.
- 서버: `DecimalColumnContractGuardTest` 3건 통과.
- TypeScript 검사(`tsc --noEmit`) 통과.
- 사전 실패: `tests/page-initial-errors.test.tsx` 한 건은 이번 변경과 무관하게 실패하며 원인을 조사하지 않았다.

## 확인하지 못한 것

- 실제 브라우저 375/768/1280px 확인과 스크린샷은 하지 않았다. 이번 변경은 표시값·계산 조건 변경이라 레이아웃 변경은 없지만, 실제 화면에서 `-` 표시와 정책 로드 후 값 표시는 사용자가 확인해야 한다.
- 정책이 로드되기 전 짧은 시간의 `-` 표시가 화면별로 자연스러운지는 브라우저로 보지 않았다.
- 매출마감(`revenue/closing`)은 계약 문서가 없어 범위에서 제외했다.
- 출하계획 저장 요청에서 새로 편집한 분할 행은 문자열, 기존 행은 숫자로 전송된다. 기존 동작이며 이번에 바꾸지 않았다.
- 수주 상세에서 쓰이는 공통 계산 함수 `calculateSalesOrderAmounts`의 기본 규칙(2자리)은 그대로 남아 있다.
