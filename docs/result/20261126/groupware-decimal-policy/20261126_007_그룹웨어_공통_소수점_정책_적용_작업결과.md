## 결과 요약

그룹웨어의 숫자 값인 첨부 수와 파일 크기를 계약 JSON과 `GROUPWARE` 정책으로 적용했다. 단가·금액 컬럼은 없고 컬럼 예외도 없다. 서버 변경은 없다.

## 변경 내용

| 항목 | 내용 |
| --- | --- |
| 정책 | 사용자가 `GRID_DECIMAL_GROUPWARE`의 number를 2자리에서 0자리로 변경(DB MCP로 확인). 첨부 수가 `3.00`이 아니라 `3`으로 표시되기 위한 조건 |
| 계약 JSON | `groupware.archivePost`(`attachmentCount` number), `groupware.file`(`fileSize` decimal) 추가, 골든 갱신 |
| 첨부 수 | 컬럼이 계약을 따르고 `getValue`로 값을 넘김 |
| 파일 크기 | `formatFileSize`로 공통화. 환산한 숫자에 정책 규칙 적용, `toFixed(1)` 제거. 자료실 파일 목록과 문서 첨부 목록에 적용 |
| 가드 | 프론트 가드 대상에 그룹웨어 폴더 등록, 서버 가드 화면 전용 문서 허용 목록 추가 |

## 동작 변화(확인 필요)

- 파일 크기 표시가 1자리(`1.5 KB`)에서 그룹웨어 decimal 정책의 2자리 FIXED(`1.50 KB`)로 바뀐다. 정책을 바꾸면 따라 바뀐다.
- 첨부 수는 정책 number 0자리를 따른다. 정책을 0자리가 아닌 값으로 되돌리면 `3.00`처럼 표시된다.

## 검증 결과

- 프론트 자료실·문서·그룹웨어·가드 관련 27개 테스트 파일 323건 통과. 신규: 첨부 수 3건(계약 추종, 예외 전달, 0자리 정수 표시), 파일 크기 4건(단위 환산·정책 자릿수·정책 없음·계약 예외).
- 서버 가드(`DecimalColumn*Test`) 9건 통과, 타입 검사(`tsc --noEmit -p tsconfig.app.json`) 통과.
- 서버와 DB는 변경하지 않았다.

## 확인하지 못한 것

- 실제 브라우저에서 첨부 수·파일 크기 표시와 레이아웃(375/768/1280px)은 확인하지 않았다.
- 쪽지·알림·공지·문서작성에는 정책 대상 숫자 컬럼이 없다고 판단했다(소스 검색 기준).

## 커밋 제목·내용 (복사용)

제목: `feat(groupware): 첨부 수와 파일 크기를 공통 소수점 정책으로 적용`
