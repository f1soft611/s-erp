## 결과 요약

기준정보의 숫자 컬럼(품목단가의 단가·최소주문수량, 품목의 안전재고·중량·소비기한 숫자, 정렬순서, 건수)을 수량·단가 기준의 계약 JSON과 `COMMON` 정책으로 적용했고 서버도 같은 정책으로 검증·저장하게 했다. 컬럼 예외는 없다. 작업표준(레시피)은 소수점이 있는 컬럼을 모두 `decimal`로 통일해 정책을 따르게 했다.

## 변경 내용

| 영역 | 내용 |
| --- | --- |
| 계약 JSON | `co.itemPartnerPrice`, `co.material`, `co.itemPartnerPriceSummary`, `co.classification`, `co.commonCode` 추가, 골든 갱신 |
| 서버 공통 | `SalesDecimalPolicy.forModule(모듈코드, …)`, `places(필드)` 추가(기존 `from`은 `SALES` 유지) |
| 서버 품목단가 | 단가·외화단가·MOQ를 `COMMON` 정책으로 검증(자릿수 초과·음수 거부), 정책 자릿수로 저장, 엑셀 검증 메시지에 정책 자릿수 표시. 기존 고정 "소수 둘째 자리" 검증 제거 |
| 서버 품목 | 안전재고·중량·소비기한 숫자를 `COMMON` 정책으로 검증 |
| 서버 가드 | 서버 사용 필드 대조가 `let/sales`와 `let/co`를 검사하고 단가·검증 보조 메서드 사용도 인식. 화면 전용 문서 허용 목록 추가 |
| 화면 | 품목단가·품목·분류·공통코드 숫자 컬럼이 계약을 따름. `decimalPlaces: 2` 및 고정 2자리 검증 정규식 제거, 안전재고 `decimal`→`number` |
| 작업표준(레시피) | 투입량·배합비·1판당을 `co.workStandard`(`decimal`)로 통일하고 직접 `decimalPlaces` 제거. 계산 함수의 고정 반올림(2·1·3자리)을 정책 규칙 인자로 대체, 합계 요약도 정책 포맷 |
| 가드 | 프론트 가드 대상에 기준정보 폴더 등록 |

## 동작 변화(확인 필요)

- 최소주문수량·안전재고·중량: `COMMON` number 정책이 0자리라 정수만 입력·저장된다(기존 데이터는 모두 정수).
- 원화·외화단가: 직접 2자리에서 정책 3자리로 바뀐다. 기존 데이터는 모두 3자리 이내다.
- 저장값은 정책 자릿수로 맞춰 전송된다(예: `7.25` → `7.250`).

## 검증 결과

- 서버 전체 테스트 1648건 통과(실패 0, 건너뜀 9). 신규 서버 테스트: 단가·수량 자릿수 초과/음수 거부, 테넌트 `COMMON` 정책 반영, 엑셀 검증 메시지, 안전재고 정책 거부·허용.
- 프론트 기준정보 관련 18개 테스트 파일 195건 통과, 신규 3건(컬럼이 계약 타입을 따름, 직접 옵션 없음, 예외 전달), 작업표준 계산·페이지 테스트 6건(정책 규칙 반올림, 정책 없을 때 반올림 없음 포함), 가드 테스트 통과.
- 이전 작업에서 "TypeScript 검사 통과"라고 적은 `tsc --noEmit -p .`는 루트 tsconfig가 참조만 하고 있어 실제로 타입 검사를 하지 않는다는 것을 이번에 확인했다. `tsc --noEmit -p tsconfig.app.json`으로 다시 검사했고, 이번 작업에서 누락한 import 1건 외에 오류가 없었다(수정 완료).
- DB MCP로 `tb_system_policy`(`GRID_DECIMAL_COMMON`), `tb_material_info`, `tb_item_partner_price`의 컬럼과 기존 데이터를 확인했다. 스키마 변경과 DB 스크립트는 없다.

## 확인하지 못한 것

- 작업표준(레시피)은 서버 구현이 없고 화면 개발이 진행 중이다. 기본정보의 숫자 입력창(기준 생산량 등)은 이번에 바꾸지 않았다. 정책 3자리로 통일되어 배합비는 2자리에서 3자리 표시로, 1판당(g)은 1자리에서 3자리 표시로 바뀐다.
- 서버 정책 스냅샷(409) 비교는 하지 않았다.
- 실제 PostgreSQL에 대한 저장 통합 테스트는 하지 않았다(모의 DAO와 서비스 단위 테스트까지 확인).
- 실제 브라우저(375/768/1280px)에서 단가·정수 입력 동작은 확인하지 않았다.
- 거래처·창고·기안양식에는 숫자 컬럼이 없어 적용 대상이 없었다.
