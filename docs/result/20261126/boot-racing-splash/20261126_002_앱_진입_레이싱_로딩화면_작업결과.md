## 결과 요약

새로고침 직후 빈 흰 화면 대신 F1Soft 레이싱카 스플래시가 가운데에 표시된다. `index.html`에 정적으로 포함되어 JS 번들 로딩 전에도 보이고, 라우트 화면이 실제로 그려지면 페이드아웃으로 사라진다. 300ms 안에 준비되면 보이지 않는다.

## 변경 내용

| 파일 | 내용 |
| --- | --- |
| `frontend/index.html` | `#boot-splash` 마크업·인라인 CSS, 저장 테마(`erp-theme`) 판별 스크립트 |
| `frontend/src/shared/bootSplash.ts` | `dismissBootSplash()`(미표시면 즉시 제거, 표시 중이면 페이드), `scheduleBootSplashFailsafe()` |
| `frontend/src/shared/components/BootSplashReady.tsx` | 커밋 시 스플래시 해제 |
| `frontend/src/routes/AppRouter.tsx` | `Suspense` 안 `Routes` 뒤에 `BootSplashReady` 배치. lazy 페이지가 해결되어 경계가 커밋될 때만 실행됨 |
| `frontend/src/main.tsx` | 15초 안전 해제 타이머 |
| `frontend/tests/boot-splash.test.tsx` | 해제·준비 신호·안전 해제·index.html 계약 테스트 |

## 요구사항 추적

| 완료 기준 | 검증 |
| --- | --- |
| 번들 전 표시 | 테스트(스플래시가 `#root`보다 앞), 브라우저에서 번들을 2.5초 지연시켜 표시 확인 |
| 준비 후 해제·페이드 | 테스트(`is-leaving` 후 제거), 브라우저에서 지연 로드 후 `#boot-splash` 제거 확인 |
| 300ms 안에 준비되면 미표시 | 테스트(미표시 상태 즉시 제거), 지연 없는 로드에서 제거 확인. CSS 표시 지연 `.3s`는 테스트로 고정 |
| 다크 테마 | `splash-dark-*.png`로 확인 |
| 모션 줄이기 | `prefers-reduced-motion` 규칙 존재를 테스트로 확인. 실제 정지 동작은 브라우저에서 보지 않음 |
| 안전 해제 | 가짜 타이머 테스트(15초) |
| 반응형 | 375/768/1280px 라이트·다크 6장 캡처, 가로 스크롤 없음 |

## 검증 결과

- `npx vitest run tests/boot-splash.test.tsx tests/app-router-not-found.test.tsx`: 15개 통과
- `npm run build`: 성공(기존 청크 크기 경고만 있음)
- 스크린샷: `screenshots/splash-{light,dark}-{375,768,1280}.png`, `screenshots/after-ready-login.png`
- 재현 스크립트: `capture.mjs` (`vite preview` 서버를 띄운 뒤 `node capture.mjs <주소> <출력폴더>`)

## 알려진 한계

- 진행바는 실제 진행률이 아닌 연출용 반복 애니메이션이다.
- 외부 폰트를 불러오지 않아 로고는 시스템 폰트(Arial Black 계열) 기울임체로 표시된다. 미리보기의 Exo 2와 글꼴이 조금 다르다.
- 전체 테스트(`npm run test`)는 실행하지 않았다. 변경과 관련된 라우터 테스트와 신규 테스트만 실행했다.
- DB 변경 없음.

## 커밋 제안

- 제목: `feat(frontend): 앱 진입 시 레이싱카 로딩 스플래시 추가`
- 내용: 새로고침 시 빈 흰 화면 대신 F1Soft 레이싱카 스플래시를 표시한다. 300ms 이내 로딩은 숨기고, 라우트 준비 후 페이드아웃하며 15초 안전 해제를 둔다.
