# 환경설정 공통 소수점 정책 적용 작업 결과

## 재현과 원인

- 환경설정 정책(`GRID_DECIMAL_SETTINGS`)의 number는 0자리다(DB MCP로 확인). 그런데 정렬 컬럼에 `1.5`를 입력하면 입력창에 `1.5`가 보이고 확정 시 `1`로 저장됐다.
- 원인: F1-Grid 일반 모드는 정책 자릿수를 값 정규화에만 쓰고 `.`·`,` 키 입력은 막지 않았다. 키 입력 차단은 `exactDecimal` 컬럼에만 있었다. 정규화는 정책의 반올림이 아니라 소수 부분을 버린다.

## 변경 내용

| 항목 | 내용 |
| --- | --- |
| F1-Grid 공통 | `NumberEditor`: 소수 자릿수가 0이면 `exactDecimal`과 무관하게 `.`·`,` 키 입력과 소수 구분자 입력을 막음. 자릿수가 있으면 그대로 허용 |
| 계약 JSON | `settings.module`(`sortOrder`, `menuCount`), `settings.menu`(`order`), `settings.role`(`menuCount`) 추가, `type: number`, 컬럼 예외 없음. 골든 파일 갱신 |
| 환경설정 화면 | 모듈·메뉴·역할 관리 숫자 컬럼이 `decimalColumnOptions`로 계약과 정책을 따름. 메뉴 관리의 직접 `decimalPlaces: 0` 제거 |
| 가드 | 프론트 가드 대상 폴더에 환경설정 3개 폴더 등록. 서버 가드는 환경설정 문서를 "화면 전용 문서" 허용 목록으로 두고, 허용 목록이 계약에 없는 문서를 가리키면 실패 |
| 문서 | `F1-GRID.md`의 정수 입력 설명 갱신, 작업지시서·계획서·사양서 |

## 검증 결과

- F1-Grid 공통 테스트 2건 추가(0자리에서 `.`·`,` 차단과 정수 확정, 자릿수 2에서는 차단하지 않음). 구현 전에 실패하는 것을 확인했다.
- 모듈 관리 화면 테스트 1건 추가(환경설정 정책 0자리에서 정렬 순서 입력의 `.`·`,` 차단).
- F1-Grid 관련 테스트 4개 파일 307건, 모듈 관리 16건 통과, 서버 소수점 가드 포함 9건 통과, TypeScript 검사 통과.
- 환경설정·정책·계정 관련 테스트를 한꺼번에 돌릴 때 시간 초과로 5건이 실패했고, 파일별 단독 재실행에서 모두 통과했다(역할 관리 1건은 변경 전후 모두 단독 통과).
- 서버·DB 변경 없음. 서버는 정렬 순서와 개수를 정수로 저장·집계만 한다.

## 확인하지 못한 것

- 실제 브라우저에서 정렬 입력의 소수점 차단과 레이아웃(375/768/1280px)은 확인하지 않았다.
- 붙여넣기(`1.5`)와 행 폼 입력은 막지 않고 기존처럼 확정 때 정수로 정규화한다(소수 부분을 버림, 정책의 반올림이 아님).
- 이번 변경으로 정책이 0자리인 다른 모듈의 일반 숫자 컬럼에서도 소수점 키 입력이 막힌다. 관련 F1-Grid 테스트는 통과했지만 각 모듈 화면을 직접 확인하지는 않았다.

## 커밋 제목·내용 (복사용)

제목: `feat(settings): 환경설정 숫자 컬럼을 공통 소수점 정책으로 적용하고 0자리 소수점 입력 차단`

내용: `F1-Grid 숫자 편집기가 0자리일 때 소수점 키 입력을 공통으로 막고, 환경설정 숫자 컬럼을 계약 JSON과 정책을 따르게 한다. 가드 테스트 대상에 환경설정을 등록한다.`
