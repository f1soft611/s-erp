## 구현 내용

- **페이지 레이아웃을 문서작성 화면과 같은 구조로 교체**: 헤더 우측 상단에 `새 글`·`방 설정`, `ContentSplitLayout`(좌 목록, 우 패널), `PinnedViewToolbar`의 보기 전환(칸반·피드·리스트·첨부), 행 클릭 시 우측 `PageAreaOverlay` 상세 패널.
- **우측 패널**: 요약(방 정보) 패널은 없애고, 맨 위에 개발용 사용자 전환, 그 아래에 내 협업방 목록과 방 만들기를 둔다.
- **툴바**: 왼쪽에 `글 N건` + 필터 아이콘(누르면 내가 쓴 글·검색, 적용 조건은 해제 가능한 칩) + 컬럼 설정(칸반일 때), 오른쪽에 보기 버튼. (처음에는 컬럼 설정을 보기 버튼 왼쪽에 두었다가 사용자 요청으로 왼쪽 그룹으로 옮겼고, 그때 추가했던 공통 `trailingAction` 슬롯은 제거했다.)
- **칸반 카드·리스트 행·첨부 행 클릭이 모두 같은 우측 상세 패널**을 연다(사용자 지시).
- **피드 카드**: `FeedCard`(아바타·작성자·날짜·상태 배지·제목) + `FeedBodyContent`(더보기, 접힘 상태의 본문 이미지 미리보기 줄) + `AttachmentList`(파일 아이콘, 이미지 첨부 미리보기, 내려받기) + `FeedReactionBar` + `FeedCommentsSection` + 공통 `CommentThread`(서식 댓글, 파일 첨부, 답글, 본인 댓글 수정·삭제) + `ImageViewerDialog`.
- **글 작성창**: 공지·문서작성과 같은 서식 에디터(`RichTextEditor`, 이미지 붙여넣기·끌어놓기) + `AttachmentList` 편집 모드.
- **상세 패널 = 피드 카드**: 우측 상세 패널 안에도 피드와 같은 카드를 그대로 그린다(처음에는 상세 전용 간단 모양이라 달라 보였다). 상세 전용 분기를 없앴다.
- **컬럼 색상**: 방 설정에서 컬럼 색 지정(관리자), 컬럼 설정에서 사용자별 색 변경(개인 색 우선, 방 기본 색으로 되돌리기). 색 선택은 서식 에디터 글자색 팔레트와 같은 견본 목록(공유 상수 `TEXT_COLOR_SWATCHES`)·배치를 따른다. 칸반 컬럼 배경·위쪽 띠와 피드·상세 상태 배지에 반영한다.
- **반응 줄·구분선 간격**: 첨부와 반응 줄 사이 구분선을 없애고, 반응 줄 바로 아래의 구분선을 카드 좌우 끝까지 닿게 했다(간격은 위아래를 맞춤: 첨부→반응 줄 8px, 반응 줄→구분선 8px, 구분선→첫 댓글 12px로 측정 확인). 공통 댓글에 `commentListSx` 선택 옵션을 추가해 댓글 목록의 기본 위 여백·구분선을 덮어쓴다. 처음에는 `Stack spacing`이 음수 여백을 덮어써서 구분선이 카드 끝까지 닿지 않았고(카드 24~805px, 구분선 45~784px), 브라우저 측정으로 발견해 `useFlexGap`으로 고쳤다(구분선 25~804px).
- **칸반 컬럼이 많을 때**: 보드 안 가로 스크롤 + 스크롤 스냅 + 더 볼 내용이 있는 쪽 가장자리 흐림 + 보드 높이 제한(제목 줄 고정), 카드를 끌 때 가장자리 자동 스크롤, 좁은 화면은 컬럼 탭 보기. 레이아웃 폭은 좌측을 칸반 4컬럼 폭(1036px)까지만 쓰고 남는 폭을 우측 패널(최소 320px)이 가져가게 했다(공통 `ContentSplitLayout`에 `leftMaxWidth`·`rightMinWidth`·`fillHeight` 선택 옵션). 가로 스크롤바는 보드가 남은 높이를 채워 컬럼이 아래까지 늘어나므로 보드 하단이자 화면 아래에 놓인다.
- **문서관리·공지사항에도 같은 처리 적용**: 반응 줄 위 구분선 제거, 반응 줄 아래 좌우 끝까지 닿는 구분선, 위아래 간격 대칭, 댓글 목록 위 기본 여백 제거를 공통 컴포넌트 `FeedEngagementSection`으로 묶어 세 화면이 같은 모양을 쓴다. 문서 상세 패널은 카드 안쪽 여백이 피드 카드와 달라(16px 대 20px) 구분선이 4px 튀어나왔고, `bleed` 옵션으로 각 컨테이너에 맞췄다(구분선 좌우 끝이 카드 안쪽 가장자리와 오차 0px로 일치함을 측정). 기존 문서·공지 테스트 중 옛 구분선 구성을 고정해 둔 3건은 새 구성(반응 줄 → 구분선 → 댓글, 구분선 개수)에 맞게 갱신했다.
- **데이터**: 글·댓글 본문은 서식 HTML(옛 일반 텍스트는 화면에서 문단으로 변환), 첨부에 1MB 이하 파일의 data URL, 댓글 첨부·수정·삭제 서비스(삭제는 표시만 남겨 답글 구조 유지).
- **공통 컴포넌트 변경(선택 옵션)**: `CommonViewMode`에 `kanban` 추가, `ViewModeToggle`·`PinnedViewToolbar`에 `enableKanbanView`(기본 꺼짐).
- 제거: 자체 `FeedList`, 자체 `CommentThread`, `PostDetailDialog`, `ViewToolbar`(공통 컴포넌트로 대체).

### 구현 중 발견·해결한 문제

- 공통 HTML 정리 함수(`sanitizeHtml`)는 `data:` 주소를 안전하지 않다고 보고 `<img src>`를 지운다. 백엔드 저장소가 없는 동안 본문 이미지는 data URL이라서, 정리하는 동안 자리표시자로 바꿨다가 복원한다(래스터 형식 png/jpeg/gif/webp만 허용, SVG 제외). `workspace-feed-data` 테스트가 보호한다.
- 공통 첨부 목록은 이미지 미리보기에 `blob:` 주소를 요구해서, 보관한 data URL을 blob으로 바꾸고 화면이 사라질 때 해제하는 훅(`useWorkspaceAttachmentUrls`)을 두었다.
- 에디터는 도구 모음 버튼이 아니라 붙여넣기·끌어놓기로 이미지를 넣는다. 작성창 안내 문구를 그렇게 고쳤다.

## 한계와 미확인 사항

- 문서관리·공지사항 화면은 실제 데이터가 필요해 브라우저로 직접 띄우지 못했다. 공통 `FeedEngagementSection`을 피드 카드와 문서 상세 패널 카드를 흉내 낸 임시 화면에 넣어 구분선 좌우 끝을 측정했고, 두 화면의 실제 렌더링은 기존 단위 테스트(409개)로 확인했다. 두 화면의 모양은 직접 한 번 확인해 주시길 권한다.

- 드래그 자동 스크롤은 처음에 브라우저 기본 동작에 기대려 했으나 자동화 입력에서는 동작하지 않아(scrollLeft 0) 직접 구현했다. 구현 후에는 같은 절차로 보드 끝까지(906px) 스크롤되는 것을 확인했다. 터치 기기의 드래그는 HTML5 드래그를 지원하지 않으므로 카드 이동 메뉴를 쓴다.
- 컬럼 설정의 "빈 컬럼 자동 접기" 옵션은 아직 만들지 않았다(요청 시 추가).

- 실제 메뉴(사이드바)로 진입하는 흐름은 로그인이 필요해 확인하지 못했다. 브라우저 검증은 앱의 테마·알림 프로바이더로 협업공간 화면만 렌더링하는 임시 하네스(검증 후 삭제)로 했다.
- 좋아요·북마크는 문서작성 피드처럼 화면 상태만이며 저장하지 않는다.
- 첨부 크기는 공통 규칙에 따라 정책 없이 바이트로 표시된다(`312,400 B`). 소수점 정책 연동은 백엔드·정책 사양 단계에서 정한다.
- 1MB 초과 파일은 이름·크기만 기록되어 내려받을 수 없고, 내려받기를 시도하면 안내 경고를 보여준다.
- 댓글 첨부는 수정 시 추가만 가능하고, 기존 첨부 삭제는 지원하지 않는다.
- 컬럼 색은 리스트형 보기의 상태 배지에는 적용되지 않는다(공통 `ListView`가 색 이름만 받는다).
- 서식 에디터의 글자색 팔레트는 도구 모음 안에 묶여 있어 재사용하지 못하고, 같은 견본 상수(`textColorSwatches.ts`)만 공유해 에디터가 그 상수를 쓰도록 바꿨다.
- 이전 결과 문서(008)에서 미룬 경미한 결함 5건은 그대로다.
- 앞선 최종 검토에서 확인한 것처럼 `GW_WORKSPACE` 메뉴 행은 이미 DB에 있으며 이번 작업에서 DB는 건드리지 않았다.
