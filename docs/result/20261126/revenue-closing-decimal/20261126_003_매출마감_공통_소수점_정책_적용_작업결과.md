## 결과 요약

매출마감 상세 그리드의 수량·매출금액·부가세·합계가 출하 계약(`sales.delivery`)의 같은 필드 설정으로 표시된다. 화면의 직접 타입·소수점 설정을 제거했고, 가드 테스트 대상에 매출마감 폴더를 등록했다. 서버와 DB는 변경하지 않았다.

## 변경 내용

- `RevenueClosingDetailGrid.tsx`: 컬럼 정의를 `createRevenueClosingColumns()`로 분리하고 `decimalColumnOptions`로 계약에 연결.
- `tests/revenue-closing-decimal.test.ts`: 기본 계약과 예외 계약에서 컬럼 옵션 확인.
- `tests/decimal-contract-guard.test.ts`: `sales.delivery` 대상 폴더에 `src/pages/sales/revenue/closing` 등록.
- 사양서(001) 표시 전용 컬럼 표에 매출마감 추가.

## 서버·DB 판단

- 매출마감 서버는 금액을 계산·저장하지 않고 출하 상세의 값을 읽어 마감 표시와 명세서 발행만 한다. 서버 계약 필드를 추가하면 서버가 쓰지 않는 계약 필드가 되어 가드가 실패하므로 새 계약 문서를 만들지 않았다.
- DB 변경 없음. DB MCP 조회는 하지 않았다(스키마·쿼리 변경이 없음).

## 검증 결과

- `revenue-closing-decimal.test.ts` 2건, 기존 `sales-revenue-closing-page.test.tsx` 16건, 가드 테스트 6건 통과. TypeScript 검사 통과.

## 확인하지 못한 것

- 실제 브라우저에서 매출마감 값 표시와 레이아웃(375/768/1280px)은 확인하지 않았다. jsdom은 그리드 열 가상화 때문에 수량·금액 열이 렌더링되지 않아 화면 값은 컬럼 정의 테스트로만 확인했다.
- 거래명세서 헤더 합계는 서버 SQL에서 출하 상세 `total_amt`의 합계로 만들어진다. 출하 합계(`deliveryTotal`)에 예외를 넣으면 화면 표시는 그 규칙을 따르지만 저장된 명세서 합계는 합산값 그대로다. 현재 계약에는 예외가 없어 영향은 없으며 이번 범위에서 바꾸지 않았다.
