## 재현 및 원인

`문서가 재상신되었습니다.` 메시지의 `RESUBMITTED`가 미지원 이벤트에 포함되어 배지 정보 대신 undefined를 반환했다. 데이터 누락이 아니라 프런트엔드 표시 매핑 누락이다.

## 변경

- `documentPresentation.ts`: RESUBMITTED를 재상신/info/filled로 매핑한다. 기존 PENDING 표시 함수를 재사용한다.
- 문서 피드와 상세의 기존 `getApprovalSystemEventPresentation(event.eventType)` 연결 및 공통 Chip을 그대로 사용한다.
- `document-presentation.test.ts`, `feed-components.test.tsx`: 재상신 매핑 및 배지 표시 회귀 사례를 추가했다.
- 기존 배지 사양에 재상신을 추가했다.
- 8px 모서리, 본문/작성자/시각/페이지/읽기 전용, 취소 배지 빨강 및 미지원 이벤트 안내 아이콘 정책을 유지한다.
- 진행 중인 상세 댓글 갱신 변경은 수정하지 않았다. 백엔드/API/DB 변경 및 DB 조회 없음.

## 검증

`frontend`에서 실행:

```powershell
node .\node_modules\vitest\vitest.mjs run tests\document-presentation.test.ts
node .\node_modules\vitest\vitest.mjs run tests\document-presentation.test.ts tests\feed-components.test.tsx
npm run build
```

- 구현 전 재상신 매핑 1개 실패(undefined)를 확인했다.
- 구현 후 두 테스트 파일 총 66개 통과.
- TypeScript/Vite 빌드 통과. 기존 1000kB 초과 청크 경고 유지.
- 전체 문서작성 회귀 테스트는 실행하지 않았다.

## 실제 브라우저

기존 4173 Vite 서버를 재사용했다. 격리 Chromium의 합성 페이지가 실제 이벤트 표시 함수, CommentThread, 앱 테마를 import한다. 실제 계정/테넌트 행이나 인증 정보는 사용하지 않았다. 전체 앱 배치가 아닌 공통 시스템 메시지 렌더링 검증이다.

- 재상신 명칭과 info/filled 클래스를 확인했다.
- 아홉 배지, 미지원 안내 아이콘 1개, 조작 버튼 0개.
- 375px/768px/1280px에서 모든 배지의 양의 크기 및 뷰포트 내 배치, 8px 모서리, 가로 넘침 없음.
- 두 취소 배지의 기존 빨간 글자/테두리도 유지됨.
- JavaScript 오류 없음. 검증용 Chromium 종료, 기존 서버 유지.
