# 대시보드 사이드바 반응형 결과

## 1. 변경 내용

- 모듈 선택 레일은 기존 92px 영역으로 모든 화면 크기에서 유지했다.
- 중앙 콘텐츠 폭이 부족하면 `DashboardMenuTree` 메뉴 패널만 자동으로 숨긴다.
- 데스크톱 앱 바에서 메뉴 패널을 수동으로 접고 펼칠 수 있다.
- 모바일에서는 모듈 레일을 유지하고 메뉴 패널을 temporary Drawer로 열고 닫을 수 있다.
- 메뉴 패널 헤더에 모바일 닫기 버튼을 제공했다.
- 중앙 콘텐츠 flex item의 `minWidth: 0`과 F1-GRID 내부 수평 스크롤 경계를 유지했다.

## 2. 자동화 검증

| 항목                              | 결과           |
| --------------------------------- | -------------- |
| 대시보드 사이드바 Vitest          | 통과: 6 tests  |
| 대시보드/F1-GRID 관련 회귀 Vitest | 통과: 65 tests |
| TypeScript 및 Vite build          | 통과           |
| 문서 전체 가로 오버플로우         | 세 뷰포트 통과 |

실행 명령:

```bash
npm run test -- tests/dashboard-sidebar.test.tsx
npm run test -- tests/dashboard-sidebar.test.tsx tests/f1-grid.test.tsx tests/menu-management-f1-grid.test.tsx
npm run build
BASE_URL=http://127.0.0.1:4174 node scripts/capture-dashboard-sidebar-responsive.js
```

## 3. 실제 브라우저 측정

| 뷰포트 | 모듈 레일 | 메뉴 패널         | 문서 폭 | 판정 |
| -----: | :-------- | :---------------- | ------: | :--- |
|  375px | 표시      | 280px Drawer 표시 |   375px | 통과 |
|  768px | 표시      | 자동 접힘         |   768px | 통과 |
| 1280px | 표시      | 287px 표시        |  1280px | 통과 |

문서와 body의 `scrollWidth`가 모든 뷰포트에서 viewport 폭을 초과하지 않았다.

종합현황, 문서관리, 권한관리, 메뉴관리, F1-GRID 테스트 화면도 같은 세 뷰포트에서 측정했으며, 모든 화면에서 문서 전체 가로 오버플로우가 발생하지 않았다.

서버 API, 데이터베이스, 메뉴 데이터 구조, localStorage 설정 저장은 변경하지 않았다. 모듈 선택 레일은 접힘 대상에서 제외했다.
