## 재현 조건과 원인

좌측 메뉴 패널을 접은 뒤에도 종합현황 본문이 화면 중앙의 제한된 폭으로 남고, 세로 스크롤 막대가 본문 오른쪽에 붙어 넓은 화면에서 추가 여백이 보였다.

원인은 `OverviewPage`가 `maxWidth="xl"`인 MUI Container에 세로 스크롤을 두고 있었기 때문이다. MUI의 최대 폭 제한으로 본문과 스크롤 경계가 앱 콘텐츠의 전체 폭을 사용하지 못했다.

## 변경 결과

- `OverviewPage` 본문 Container를 `maxWidth={false}`로 변경하여 좌측 메뉴 뒤의 앱 콘텐츠 가용 폭을 사용하게 했다.
- 기존 세로 스크롤, 반응형 패딩, 공통 앱 셸과 다른 페이지는 유지했다.
- 세로 콘텐츠가 화면보다 긴 경우의 스크롤은 유지되며, 제한된 가운데 컨테이너 옆에 남던 빈 여백이 없어졌다.
- 데이터/API, 권한, 테마, 카드 배치는 변경하지 않았다.

## 검증

| 검증 | 결과 |
|---|---|
| 수정 전 회귀 테스트 | `MuiContainer-maxWidthXl`이 렌더링되어 새 테스트 실패 확인 |
| 종합현황 Vitest | 1개 파일, 13개 테스트 통과 |
| 변경 파일 Oxlint | 오류/경고 없이 통과 |
| 프론트엔드 빌드 | TypeScript + Vite 통과 |
| 브라우저 | 기존 S-ERP 4173 서버에 합성 API 응답을 주입해 실행, 런타임 오류 0건 |

좌측 메뉴 패널을 접은 상태에서 측정한 폭 결과:

| 뷰포트 | 본문 폭 | 본문 오른쪽 여백 | 문서 가로 넘침 | 본문 가로 넘침 | 세로 스크롤 |
|---:|---:|---:|---|---|---|
| 1920px | 1828px | 0px | 없음 | 없음 | 가능 |
| 1280px | 1188px | 0px | 없음 | 없음 | 가능 |
| 768px | 676px | 0px | 없음 | 없음 | 가능 |
| 375px | 283px | 0px | 없음 | 없음 | 가능 |

브라우저 확인은 합성 업무·공지·수주 데이터를 사용한 레이아웃 검증이며 운영 데이터나 실제 사용자 업무를 조회하지 않았다. 세로 스크롤 막대는 페이지 내용을 이동할 수 있도록 남겨 두고, 넓은 앱 콘텐츠의 오른쪽 경계에 위치하도록 했다.
