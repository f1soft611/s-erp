# 상세검색 조건 제출 및 현황 기준일 필수화 결과

## 구현 내용

- 상세검색 조건 칩의 X는 선택 조건의 편집값만 비우고 검색은 실행하지 않는다. 초안에서 여러 조건을 연속 제거해도 이전 제거가 유지된다.
- 지운 조건의 칩은 즉시 화면에서 사라지고, 다른 칩은 유지된다. 실제 그리드 결과와 마지막 실행 검색조건은 상세검색 패널의 조회 전 변경 안내와 함께 명시적인 조회 전까지 유지한다.
- 조회 전 안내는 조건 칩 아래 전체 너비를 사용하고, 초기화/조회/닫기 버튼은 우측 맨 위 행에 고정했다. 좁은 화면에서는 버튼과 칩을 별도 행에 배치해 칩 내용이 잘리지 않게 했다.
- 필수 조건 칩의 X는 비활성화한다. 필수 기준일을 제거해 상단 조회에서 빈 날짜로 검색할 수 없도록 한다.
- 업무현황 요청의 결재신청일 조건은 해당 날짜 상세검색 필드가 있는 기존 문서현황 페이지에 적용했다. `submittedAt`을 필수 메타데이터로 선언하고, 시작일/종료일 누락 시 상세검색 조회를 차단한다.
- 날짜가 빠지거나 유효하지 않은 이전 탭 세션은 서버 제공 최근 1개월 기본 날짜로 보정한 뒤 첫 조회를 실행한다. 기존 키워드와 다른 상세조건은 보존한다.
- 향후 신규 현황 페이지에 기준일 필수 검색조건을 적용하도록 `frontend/AGENTS.md` 및 F1-GRID 문서에 규칙을 추가했다.

## 검증

- `npm run test -- tests/page-search-area-detail.test.tsx tests/document-status-page.test.tsx`: 55개 통과.
- `npm run build`: 통과.
- 변경된 TypeScript 파일 oxlint: 오류 없음. 기존 `react(set-state-in-effect)` 경고가 출력됐다.
- 브라우저 375px / 768px / 1280px 확인: 데스크톱에서는 버튼이 칩과 같은 맨 위 행에, 모바일에서는 버튼이 첫 행에 고정되고 칩/안내가 아래에 표시되며 가로 넘침이 없다. 제거 직후 칩이 사라지고 조회 전 안내가 노출되는 레이아웃을 캡처했다.
- 상세검색 패널이 그리드 로딩 덮개보다 위에 표시되고, 제거만 했을 때 조회 횟수 0 및 상세검색 `조회` 클릭 후 1회인 동작도 확인했다.

## 화면 캡처

### 모든 칩 해제 후 안내 위치 보완

- 재현: 마지막 조건 칩을 해제해도 안내가 두 번째 행에 남아 하단에 빈 줄이 생겼다.
- 원인: 데스크톱 안내의 `gridRow`가 항상 2로 고정되어 있었다.
- 해결: 남은 칩이 없을 때만 안내를 첫 행 왼쪽으로 이동하고 버튼은 첫 행 오른쪽을 유지한다. 모바일은 겹침 방지를 위해 버튼 아래에 안내를 둔다.
- 회귀 검증: 실제 브라우저 375px / 768px / 1280px에서 마지막 칩 제거 전후의 위치와 가로 넘침 없음을 확인했다.
