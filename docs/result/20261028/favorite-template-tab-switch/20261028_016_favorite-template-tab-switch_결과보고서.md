# 문서작성 즐겨찾기 탭 전환 오류 조사 결과

## 상태: 미재현, 제품 코드 수정 보류

기안서 자주 쓰는 결재선 목록 확인 → 취소 → 업무연락 이동 → 자주 쓰는 참조자 조회 순서를 현재 코드에서 확인했다. 합성 응답을 사용한 테스트와 실제 브라우저에서 모두 정상 조회되어 원인을 확정하지 못했다. **실제 사용자 환경의 오류가 해결되었다는 의미가 아니다.**

## 확인 근거

- `DocumentComposerDialog`는 결재선/참조자 설정을 열 때마다 `approvalSettingsSession`을 증가시켜 설정 모달을 재생성한다.
- 기안서는 `001`, 업무연락은 `008`로 목록을 요청하며, 설정 모달의 `open` 및 조회 콜백 변경 시 목록을 조회한다.
- 서비스는 목록 응답의 문서 코드와 형식을 검사한다. 백엔드 Controller → Service → DAO → Mapper 경로도 전달받은 문서 코드로 조회하는 것을 확인했다.
- 공개 배포본의 문서작성 청크에서도 참조자 모드, 세션 증가 및 문서 코드별 조회 흐름을 확인했다. 사용자의 열린 탭에 실제 로드된 코드/응답까지 확인한 것은 아니다.
- 기본 DB MCP `list_tables` → `describe_table(tb_electronic_approval_line_template)`로 문서 코드, 이름, 갱신시각 컬럼의 존재와 타입만 확인했다. 데이터 행, 사용자/테넌트 정보 및 인증 정보는 조회하지 않았다. 백엔드/API/DB 변경은 없다.

## 변경 및 검증

| 항목 | 결과 |
| --- | --- |
| 추가한 작성 모달 회귀 테스트 | 기안서 목록 조회 후 취소하고 업무연락에서 `008` 요청 및 해당 옵션 표시를 확인. 현재 구현에서 통과하여 실패 재현에는 이르지 못함 |
| 실제 브라우저 | 기존 `http://127.0.0.1:4173` 서버 재사용. 실제 컴포넌트/목록 서비스와 합성 API 응답으로 선택 목록 및 F1-Grid 관리 목록 정상 표시 |
| 375 / 768 / 1280px | 각 화면에서 참조자 설정 표시, 문서 전체 가로 넘침 없음 |
| 최종 선택 테스트 | `npx vitest run tests\document-write-page.test.tsx -t "loads reference favorites after cancelling"`: 1개 통과, 나머지 125개 제외 |
| 대상 린트 | `npx oxlint tests\document-write-page.test.tsx`: 종료 코드 0 |
| 공백 검사 | `git diff --check`: 통과 |
| 제품 빌드/전체 회귀 | 제품 코드 변경이 없어 생략 |

최초 `npm run test -- ... -t ...` 호출은 현재 PowerShell/npm 조합에서 `-t`가 전달되지 않아 전체 작성 모달 테스트를 실행했다. 해당 프로세스를 중지하고 `npx vitest run`으로 선택 테스트를 실행했다.

## 미확인 사항과 필요한 추가 근거

- 실제 증상이 선택 상자의 빈 옵션인지, 관리 목록의 빈 화면인지, 로딩 지속인지, 오류 표시인지 구분되지 않았다.
- 실제 실패 요청의 상태 및 오류 문구, 해당 사용자에게 저장된 문서 종류별 목록 유무는 확인하지 못했다.
- 오류 문구 또는 재현 화면을 요청했으나 사용자가 현재 응답할 수 없어 조사를 여기서 보류한다. 실패 증거 없이 제품 코드나 API/DB 계약을 추측으로 변경하지 않는다.
