# 20261013_002 이전 댓글 상태 유지 및 카운트 결과

## 결과 요약

공지사항과 전자결재에서 이전 댓글을 불러온 뒤 새 댓글 또는 답글을 등록해도 화면에 이미 로드된 댓글과 이전 페이지 상태를 유지하도록 구현했다. 공통 이전 댓글 버튼에는 아직 로드되지 않은 댓글 수를 표시한다. 375px 화면에서 카운트 레이블이 줄바꿈되던 문제도 공통 버튼의 한 줄 표시로 보완했다.

## 원인 및 조치

- 전자결재는 댓글 등록 성공 후 첫 페이지를 다시 조회해 로드된 이전 댓글과 커서를 초기화하고 있었다. 등록 응답 댓글과 첨부를 기존 목록에 추가하고 총 댓글 수만 갱신하도록 변경했다. 이전 페이지 커서 및 `hasPrevious` 상태는 유지한다.
- 공지사항은 서버 댓글과 화면 로컬 댓글을 병합하는 흐름을 유지하고, 동일 ID 댓글의 중복 삽입을 방지한다. 남은 수 계산은 삭제되지 않은 댓글과 답글을 포함한다.
- 공통 댓글 섹션은 선택적으로 남은 댓글 수를 표시한다. 좁은 화면에서 카운트 문구가 여러 줄로 나뉘지 않도록 `white-space: nowrap`을 적용했다.
- 전자결재 시스템 이벤트는 사용자 댓글 수에 포함하지 않는다. API 및 DB 계약은 변경하지 않았다.

## 검증

### 집중 회귀 테스트

최종 집중 실행 결과는 **4개 파일, 8개 테스트 통과, 142개 선택 제외**다.

```powershell
npx vitest run tests/feed-components.test.tsx tests/notice-page-local-updates.test.tsx tests/notice-page.test.tsx tests/document-write-page.test.tsx -t "optional previous-comments action|remaining previous-comment count|keeps all loaded notice comments|renders a reply immediately when its parent was loaded from previous comments|requests the previous cursor once|preserves loaded older roots and cursor|keeps loaded approval comments|records a comment-area interaction only when more is unavailable"
```

포함한 주요 검증:

- 공통 버튼의 카운트·기본 레이블·한 줄 스타일
- 공지사항에서 이전 댓글 로드 후 새 댓글과 답글 등록 시 로드 목록과 남은 수 유지
- 이전 댓글에서 답글 등록 후 답글 작성기가 닫히고 기존 댓글이 유지됨
- 공지사항의 이전 페이지 커서 및 중복 없는 댓글 병합
- 댓글 입력 영역의 기존 읽음 상호작용 유지
- 전자결재에서 이전 페이지 로드 후 루트 댓글·답글 등록 시 기존 댓글, 커서, 남은 수 유지 및 첫 페이지 재조회 없음

### 관련 파일 전체 실행

최종 전체 관련 테스트 파일 실행은 **4개 파일 중 1개 통과, 3개 실패; 150개 중 133개 통과, 17개 실패**로 종료했다. 실패는 notice 로딩, 화면 상태, 댓글·첨부 및 CRUD 관련 여러 검증에서 발생했다. 그중 `increments the server count for a locally created reply`는 답글 텍스트는 표시되지만 `댓글 2` 카운트 assertion을 만족하지 못했다. 이는 이번 집중 이전 페이지 상태 유지 테스트와 별도로 남아 있는 문제다. 따라서 전체 관련 테스트 파일 실행은 통과로 보고하지 않는다. 집중 댓글 페이지네이션 회귀 테스트는 통과했다.

### 브라우저 확인

공유 S-ERP 브라우저에서 공지사항과 전자결재의 이전 댓글 버튼 및 상세 패널을 확인했다. 전자결재에서는 화면에 표시된 21개 댓글과 `이전 댓글 보기 (13)`을 확인하고 이전 댓글을 불러와 버튼이 사라지는 것을 확인했다. 실제 공유 데이터에 테스트 댓글을 저장하지 않기 위해 브라우저에서는 댓글 등록을 수행하지 않았으며, 등록 후 동작은 Vitest 회귀 테스트로 검증했다.

375px, 768px, 1280px에서 두 화면을 확인했다. 버튼의 computed `white-space`는 모든 뷰포트에서 `nowrap`이었고, 측정한 document `scrollWidth`는 각 viewport 너비를 넘지 않았다. 결과 캡처는 실제 사용자 이름, 제목, 댓글 본문 및 이미지가 노출되지 않도록 텍스트·이미지를 가린 상태로 저장했다.

## 미완료 및 범위

- 전체 관련 테스트 파일의 17개 실패는 해결되지 않았다. 관련 회귀 시나리오 6개, 빌드, diff 검사는 통과했지만 전체 테스트 통과로 간주하지 않는다.
- 브라우저에서는 공유 데이터 보호를 위해 쓰기 작업을 하지 않았다. 등록 후 동작은 통합 회귀 테스트로 검증했다.
- 댓글 수정·삭제, 백엔드/API/DB 변경은 이번 변경 범위가 아니다.
