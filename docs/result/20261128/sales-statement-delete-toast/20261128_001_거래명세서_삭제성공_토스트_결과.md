## 검증

### 자동화

- T1은 구현 전 실패(토스트 없음)를 확인했고 구현 후 통과. T2는 기존 동작 회귀 방지용으로 전후 통과.
- 거래명세서 관련 7개 파일 35건, `npx tsc -b`, `npm run build` 통과. `oxlint`의 경고 2건(`useSalesStatementCreate.ts:119`, `StatementSourcePicker.tsx:35`)은 이번 변경과 무관한 기존 경고.
- 영업 전체 38개 파일을 한 번에 실행하면 실행마다 다른 테스트 1~3건이 5초 제한으로 실패했고, 해당 파일(`quotation-create-page`, `sales-revenue-closing-page`, `sales-statement-page`)을 따로 실행하면 모두 통과했다(동시 실행 부하로 인한 기존 시간 초과).

### 브라우저(개발 서버, 1280×900)

현황 → 상세 → 더보기 → 수정 → 삭제 → 확인 순서로 진행하되, DELETE 요청은 브라우저에서 가짜 응답으로 대체해 서버로 보내지 않았다.

| 경우 | 결과 | 스크린샷 |
| --- | --- | --- |
| 성공(가짜 200) | 수정 창 닫힘, 토스트 `거래명세서가 삭제되었습니다. 명세번호: TS-20261126-0001` | `screenshots/statement-delete-toast.png` |
| 실패(가짜 500) | 수정 창 유지, 창 안에 `테스트용 삭제 실패`, 토스트 없음 | `screenshots/statement-delete-fail.png` |

- 확인 후 읽기 전용 DB MCP로 `TS-20261126-0001`이 그대로 있고 `updated_at`이 비어 있음(수정 없음)을 확인했다.
