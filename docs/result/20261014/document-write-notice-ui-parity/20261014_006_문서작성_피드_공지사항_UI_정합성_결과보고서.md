# 문서작성 피드 공지사항 UI 정합성 결과보고서

## 결과 요약

문서작성 화면에서 리스트/피드 전환 시 현재 필터로 다시 조회하고, 선택된 보기 방식의 스켈레톤을 표시하도록 변경했다. 피드에서는 `includeDetails=true` 문서 목록 응답에 포함된 본문, 결재선, 첨부, 초기 댓글을 사용해 응답이 모두 준비된 뒤 전체 카드를 렌더링한다. 카드별 초기 상세/댓글 조회와 viewport 지연 렌더링은 제거했다.

상세 패널 편집은 기존 패널을 유지한다. Composer 종료 후 목록은 quiet refresh하며, 열린 상세 패널도 skeleton 없이 갱신한다. 기존 댓글 페이징/조작과 로컬 좋아요 동작은 유지했다.

## API 및 DB 계약

- `GET /api/v1/groupware/approvals/documents`의 기본 요청은 기존 경량 `resultList` 계약을 유지한다.
- 피드 요청에만 `includeDetails=true`를 전달하며 문서 본문, 결재선, 첨부, system events, 최초 댓글 페이지 및 댓글 커서 메타데이터를 추가한다.
- 피드 hydration은 기존 목록 접근 범위로 반환된 문서만 처리하고 조회 이력 삽입/조회수 증가를 수행하지 않는다.
- 피드 row 중 하나라도 필수 hydration에 실패하면 전체 목록 요청을 실패 처리한다. 클라이언트는 부분 피드를 표시하지 않고 오류 및 재시도 버튼을 제공한다.
- DB 스키마 변경은 없다.

구현 전 PostgreSQL 읽기 전용 MCP로 `list_tables`와 아래 테이블의 `describe_table`을 확인했다. tenant 데이터 행은 조회하지 않았다.

| 테이블 | 확인한 계약 필드 |
|---|---|
| `tb_electronic_approval_main` | `electronic_approval_id`, `tenant_id`, `drafting_work_category_id`, `document_type`, `document_status`, `title`, `contents_json`, `contents_html`, `contents_text`, `view_count` |
| `tb_electronic_approval_line_info` | `electronic_approval_line_id`, `tenant_id`, `electronic_approval_id`, `stage_order`, `participant_order`, `participant_type`, `participant_user_id`, `participant_name`, `action_status` |
| `tb_common_comment` | `comment_id`, `tenant_id`, `owner_type`, `owner_id`, `parent_comment_id`, `content`, `writer_id`, `writer_name`, `comment_type`, `event_type`, `deleted_yn` |
| `tb_common_file` | `file_id`, `tenant_id`, `owner_type`, `owner_id`, `file_name`, `file_size`, `mime_type`, `file_usage_type`, `deleted_yn` |
| `tb_electronic_approval_view_history` | `view_history_id`, `tenant_id`, `electronic_approval_id`, `login_id`, `viewed_at` |

## 검증 결과

| 검증 | 결과 |
|---|---|
| `npx vitest run tests/document-approval-service.test.ts` | 통과, 13개 |
| `npx vitest run tests/document-feed-item.test.tsx tests/document-write-page.test.tsx --testTimeout=15000` | 통과, 71개 |
| `npx vitest run tests/document-write-page.test.tsx --testTimeout=20000 --reporter=dot` (리뷰 후속 검증) | 통과, 71개. quiet refresh 이후 필터 재조회 실패 시 이전 피드 카드가 남지 않는 회귀 테스트 포함 |
| `mvn '-Dtest=DocumentApprovalServiceImplTest,DocumentApprovalApiControllerTest' test` (`backend`) | 통과, 50개 |
| `npm run build` (`frontend`) | 통과. 번들 중 `index` 청크가 1,000 kB를 넘는다는 기존 Vite 크기 경고가 출력됨 |
| 기존 `http://127.0.0.1:4173/groupware/doc/write` 브라우저 | 테스트용 응답을 가로채 피드/첨부/초기 댓글/이전 댓글 페이지/좋아요를 확인. 375px, 768px, 1280px에서 document/body scroll width가 viewport와 일치 |

코드 리뷰에서 quiet refresh 옵션이 이후 필터/보기 전환 재조회에도 남아, 그 조회가 실패하면 이전 결과를 보존하는 문제를 확인했다. quiet 동작을 reload version이 실제 증가한 요청에만 적용해, 이후 일반 재조회 실패 시 stale 목록/피드를 비우도록 수정했다. 회귀 테스트는 피드 로드 → Composer 취소로 quiet refresh → 업무구분 필터 재조회 실패 흐름을 검증한다.

브라우저의 기존 `localhost:8080` API는 이 작업의 상세 피드 필드가 포함되지 않은 응답을 반환해 클라이언트의 피드 응답 검증에 실패했다. 이에 실제 문서 데이터를 스크린샷이나 결과물에 복사하지 않도록 브라우저 확인은 `QA` fixture API 응답으로 수행했다. 백엔드 서비스/컨트롤러 테스트는 새 응답 분기와 기존 경량 분기를 검증했다. 실제 서버 배포/재시작 후 live API 응답은 별도로 확인해야 한다.

기존 우측 상세 패널 유지와 quiet refresh, 초기 카드의 상세/댓글 재호출 부재, mode-switch skeleton 및 늦은 피드 응답 무시, 이전 댓글 cursor 호출은 집중 테스트에서 확인했다.
