# 20261014_001 전자결재 상세 작성자 헤더·결재선·조회수 결과

## 작업 결과

- 상세 피드에 작성자 Avatar/이름과 `기안자 · YYYY.MM.DD · 조회 N`을 결재선 패널 위에 표시했다.
- 읽기 전용 결재선에서 승인 카드 사이를 꺾쇠로 연결하고, 카드의 순번+이름을 가운데 정렬하고 긴 이름은 말줄임 처리했다.
- 합의와 참조를 별도 행으로 분리하고 저장된 결재 순번을 표시했다.
- 상세 API 계약에 사용자별 최초 조회수 저장 및 `viewCount` 반환을 구현하고 회귀 테스트를 추가했다.
- 조회수 migration, 변경 이력, rollback을 날짜별로 문서화했다. 실제 DB에는 migration을 적용하지 않았다.

### 브라우저 상세

화면 검증에는 개인정보를 사용하지 않도록 이름·부서·본문을 합성한 브라우저 전용 응답을 사용했다. 댓글 영역과 실제 문서 목록은 캡처에서 숨겼다. 이 fixture는 브라우저에서만 사용했고 서버나 DB에는 저장하지 않았다.

## 실행 중 API 계약 제한

실행 중인 `GET /api/v1/groupware/approvals/documents/5`를 확인한 결과 HTTP 200과 기존 `result.item` 응답은 반환했지만 `viewCount` 필드가 없었다. 프론트엔드는 `viewCount`를 필수 필드로 검증하므로 실제 API 응답으로 상세 화면을 열면 `전자결재 상세 응답을 확인할 수 없습니다.` 오류가 발생한다.

따라서 브라우저의 시각·반응형 검증은 API 연동 성공을 의미하지 않는다. 이 검증에서는 합성 `viewCount: 0`을 포함한 응답을 브라우저 내부에서만 사용했다. 실행 중 백엔드가 변경된 소스와 다른 계약을 제공하는 이유는 이 작업에서 확인하지 않았으며, 이를 숨기기 위한 기본값 처리나 DB 변경은 하지 않았다.

**남은 확인:** 승인된 migration을 정상 절차로 적용하고 변경된 백엔드를 실행한 뒤 상세 API가 0 이상의 정수 `item.viewCount`를 반환하는지 재검증해야 한다. 그 전까지 실 API 연동 확인은 미완료다.
