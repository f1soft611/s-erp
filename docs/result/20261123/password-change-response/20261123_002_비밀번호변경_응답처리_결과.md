# 비밀번호 변경 필요 응답 처리 결과

## 변경

- JSON 외 Blob, 다운로드, 이벤트 스트림에서도 403의 `PASSWORD_CHANGE_REQUIRED` 응답을 공통으로 감지하여 세션에 비밀번호 변경 필요 상태를 반영한다.
- 기존 일반 오류와 정상 응답 처리는 유지한다. 계정 상세사양의 응답 필드를 실제 서버와 같은 `resultCode`로 수정했다.
- 인증 정책이나 API 경로 및 DB 스키마는 변경하지 않았다.

## 검증 및 후속 조치

- 인증·네트워크·스트림 집중 테스트를 포함한 프론트 관련 8개 파일 99건 통과. typecheck, lint, build 성공; lint 및 번들 크기 경고가 남아 있다.
- 공유 설치를 변경하지 않고 Windows 격리 복사본에서 Node 22와 `npm ci`로 lockfile 의존성을 설치했다. lint, typecheck, build와 관련 테스트 8개 파일 100건이 통과했다. 전체 테스트는 사용자 요청에 따라 중단했으며, 미커밋 변경에 대한 GitHub Actions Ubuntu 실행은 수행하지 않았다.
- 접근 가능한 `f1soft611` GitHub 저장소에서 오류 코드와 비밀번호 변경 API 경로를 검색했으나 별도 연동 클라이언트는 식별하지 못했다. 검색 범위 밖의 외부 시스템은 미확인이므로 배포 전 연동 소유자가 403 `resultCode: PASSWORD_CHANGE_REQUIRED` 처리와 비밀번호 변경·재인증 흐름을 확인해야 한다.
- 브라우저 캡처는 공통 결과의 [합성 데이터 화면](../statement-detail-limit/screenshots/revenue-limit-375.png)이며, 외부 클라이언트 인증 흐름을 검증한 자료는 아니다.
