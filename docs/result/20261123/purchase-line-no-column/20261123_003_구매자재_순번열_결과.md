# 20261123_003 구매자재·수입검사 "행" 열 이름·정수 표시 / 매입마감 구매처 No 열 결과

기준: [작업지시서](../../../directions/20261123/20261123_003_purchase-line-no-column_작업지시서.md), [계획서](../../../plan/20261123/20261123_003_purchase-line-no-column_계획서.md), [상세사양서](../../../spec/20261123/20261123_003_purchase-line-no-column_상세사양서.md)

## 원인
`lineNo` 열이 숫자(`number`) 열이라 정책 관리의 모듈 소수점 정책이 적용되어 `1.00`처럼 보였다(열에 `decimalPlaces`를 주면 정책보다 우선한다).

## 변경 내용
- **"행" → "순번"**: 구매요청 등록(행 번호 열), 구매요청 현황·구매 확정·발주 현황·가입고 현황·입고 현황·**수입검사 현황**의 `lineNo` 열, 구매 확정의 요청 선택 창, 그리고 현황 5곳의 상세 패널 머리글(표 8곳 + 패널 5곳).
- **정수 표시**: `lineNo` 열에 `decimalPlaces: 0`. 서버·DB 변경 없음.
- **매입마감 왼쪽 그리드**: 구매처별 요약 첫 열에 No(rownumber) 추가, 그리드 저장 키 `...supplier-grid-v3`.
- 점검 결과 발주·가입고·입고·수입검사 **등록** 화면의 표에는 "행" 열이 없어 변경하지 않았다.

## 검증
| 항목 | 결과 |
|---|---|
| 단위 테스트 | `purchase-line-number-column` 8건(열 머리글·소수점 0·구매처 요약 No) 신규, 관련 구매·품질 테스트 포함 16개 파일 225건 통과, `tsc` 오류 없음 |
| 브라우저(1600px) | 구매요청현황·발주현황·가입고현황·입고현황·수입검사현황: "행" 머리글 없음, "순번" 있음, 순번 값 `1`, `2`(소수점 없음). 구매요청등록: 첫 열 "순번". 매입마감처리: 구매처 요약 첫 열 No |
| 미확인 | 구매 확정·요청 선택 창은 불러온 데이터가 없어 브라우저로 값을 보지 못했다(열 정의는 단위 테스트로 확인) |

스크린샷: `screenshots/receipt-closing-1600`(매입마감 No 열), `order-status-1600` 외 화면별 1장.

## 복사용 커밋 메시지
제목: `fix(materials,quality): 표의 "행" 열을 "순번"으로 바꾸고 정수로 표시, 매입마감 구매처 요약에 No 열 추가`

내용:
- 구매요청·확정·발주·가입고·입고·수입검사 현황의 lineNo 열 머리글 순번, decimalPlaces 0(모듈 소수점 정책 무시)
