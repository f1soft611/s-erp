# 납품처 관리 및 수주 연계 결과

## 작업 내용

- 영업관리 기준정보에 거래처별 납품처 관리 화면과 메뉴 seed를 추가했다.
  공통코드 관리와 같은 분할 그리드, 패널 제목과 선택 거래처 표시를
  적용하고 등록 상태는 가운데 정렬된 배지로 표시한다.
- 납품처는 그리드에서 추가·편집 후 저장하며 수주에서 참조 중이면 삭제를
  제한한다. 납품처코드는 테넌트별 자동 발급한다.
- 수주등록에 거래처 선행 납품처 선택과 거래처 도움창을 이용한 매출처
  선택을 필수로 추가했다. 거래처 변경 시 납품처 선택을 초기화한다.
- 납품처 마스터·수주 참조 스키마, 단일 테넌트 초기화 SQL과 메뉴 seed,
  변경 이력 및 롤백 스크립트를 날짜별 DB 폴더 양쪽에 작성했다.

## 검증 및 한계

- 프론트 집중 테스트: 납품처 화면 9개, 서비스 1개, 수주 API 9개,
  수주등록 37개 통과. 수주현황 25개는 단독 실행에서 통과했다.
  다섯 파일을 동시에 실행한 경우 수주현황 2개가 조회 결과 대기 중
  실패했으며 단독 재실행에서는 재현되지 않았다.
- 프론트 lint와 빌드 종료 코드는 0이다. lint에는 신규 훅의
  `set-state-in-effect` 경고 2건을 포함한 경고가 있고 빌드에는
  번들 크기 경고가 있다.
- 백엔드 집중 테스트 38개와 스키마·초기화 스크립트 정적 테스트 2개가
  통과했다. 변경 운영 Java 파일 11개를 Lombok 프로세서와
  `javac --release 8`로 별도 컴파일해 Java 8 API 호환성을 확인했다.
- 기본 PostgreSQL 읽기 전용 MCP로 관련 테이블·외래 키·메뉴 메타데이터를
  확인했으며 업무 데이터 행은 조회하지 않았다. 실제 DB에 SQL을 적용하지
  않았고 PostgreSQL에서 일괄 저장의 트랜잭션 롤백이나 실제 메뉴 seed
  실행은 통합 검증하지 않았다.
- 브라우저 캡처는 독립 임시 페이지의 **가상 인증·가상 응답 데이터**로
  확인한 것이며 실제 서버 연동 검증을 대신하지 않는다.

## 적용 시 주의

- SQL은 실행되지 않았다. 권한 있는 운영자가 백업과 영향을 확인하고
  대상 테넌트를 명시한 후 스키마와 메뉴 seed를 적용해야 한다. 메뉴는
  역할별 권한을 별도 배정해야 표시된다.
- 초기화 SQL은 기본 `ROLLBACK`이며 구매요청이 수주를 참조하면 중단한다.
  테이블 잠금으로 다른 테넌트의 해당 테이블 쓰기도 대기할 수 있다.
  실행 전 대상과 건수를 검토해야 하며 커밋 후에는 백업 복원이 필요하다.
- 다른 테넌트의 기존 수주 보존을 위해 새 참조 열은 nullable이다. 기존
  수주를 수정할 때도 신규 필수 납품처·매출처를 선택해야 한다.
