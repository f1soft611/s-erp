시스템관리 > 권한관리/메뉴관리 화면과 대시보드 좌측 모듈-메뉴 트리를 실제 DB 데이터 기반으로 전환했다. 백엔드는 첨부된 `egovframework.let.documents.haccpbase.categories` 패키지 구조(controller / domain.model / domain.repository / service / service.impl)를 그대로 따랐다.

## 2. DB 작업

- 신규 테이블 2종: `tb_module`, `tb_menu` (`s-erp_central`)
- 에프원소프트(T1358606250) 테넌트에 기존 프론트 목업과 동일한 트리 시드: 그룹웨어(종합현황/문서관리), 환경설정(시스템관리 > 권한관리/메뉴관리/F1 Grid 테스트)
- 스크립트: [backend/DATABASE/20260831](../../../../backend/DATABASE/20260831), [docs/database/2026-08-31](../../../database/2026-08-31)

## 3. 백엔드 변경

### 신규 패키지

- `egovframework.let.system.modules` (모듈 CRUD): `SystemModuleApiController`, `SystemModuleService`/`Impl`, `SystemModuleDAO`, VO 3종
- `egovframework.let.system.menus` (메뉴 CRUD + 사용자 메뉴 조회): `SystemMenuApiController`, `MyMenuApiController`, `SystemMenuService`/`Impl`, `SystemMenuDAO`, VO 5종
- `egovframework.let.system.roles` (역할 목록/등록/수정, 삭제 제외): `SystemRoleApiController`, `SystemRoleService`/`Impl`, `SystemRoleDAO`, VO 3종 (기존 `tb_role` 테이블 재사용)
- 매퍼 XML: `egovframework/mapper/let/system/{modules,menus,roles}/*.xml`

### API

| Method              | URL                           | 설명                                          |
| ------------------- | ----------------------------- | --------------------------------------------- |
| GET                 | /api/v1/menus/my              | 로그인 사용자 테넌트/역할 기준 모듈-메뉴 트리 |
| GET/POST/PUT/DELETE | /api/v1/system/modules(/{id}) | 모듈 CRUD                                     |
| GET/POST/PUT/DELETE | /api/v1/system/menus(/{id})   | 메뉴 CRUD                                     |
| GET/POST/PUT        | /api/v1/system/roles(/{id})   | 역할 목록/등록/수정                           |

- 권한 정책: 메뉴별 권한 매핑 테이블 없이, 역할코드 기준 기본 정책 적용(`PLATFORM_ADMIN`/`TENANT_ADMIN` → 전체 CRUD, `TENANT_USER` → read only)
- 관리 API(등록/수정/삭제)는 컨트롤러에서 `EgovAccessControlHelper.isTenantAdmin(user)`로 역할을 검사해 관리자가 아니면 403 반환
- **사전 존재하던 문제 수정(범위 외 블로커)**: `SecurityConfig`의 `.anyRequest().denyAll()` 정책으로 인해 인증된 사용자도 신규 API를 호출할 수 없던 문제를 확인, `/api/v1/**`에 대해 `.authenticated()` 규칙을 추가해 JWT 인증 사용자만 접근 가능하도록 보완

## 6. 영향 범위 및 주의사항

- DB 변경은 `s-erp_central`의 신규 테이블(`tb_module`, `tb_menu`)에 한정되며 기존 테이블 컬럼 변경 없음
- `SecurityConfig` 변경(`/api/v1/**` 인증 필요)은 기존 화이트리스트 경로(`/auth/*`, swagger 등)에는 영향 없음
- 메뉴별 세부 권한 매핑 화면/테이블, 역할 삭제 API, 메뉴관리 화면의 등록/수정 저장 연동은 이번 범위에서 제외됨(후속 작업 필요)
