# 20260831*001*로그인*JWT*백엔드*연동*결과

- 작업지시서: [20260831*001*로그인*JWT*백엔드*연동*작업지시서.md](../../../directions/20260831/20260831_001_로그인_JWT_백엔드_연동_작업지시서.md)
- 계획서: [20260831*001*로그인*JWT*백엔드*연동*계획서.md](../../../plan/20260831/20260831_001_로그인_JWT_백엔드_연동_계획서.md)

로그인 화면에서 실제 백엔드 `/auth/login-jwt` API로 로그인이 동작하도록 연동하고, `s-erp_central`(PostgreSQL) DB에 로그인용 스키마 6종과 초기 관리자 계정 시드 데이터를 구성했다.

## 2. DB 작업

- 신규 DB `s-erp_central` 생성 (PostgreSQL, `application-dev.properties`의 `Globals.postgresql.Url` 대상)
- 6개 테이블 생성: `tb_tenant`, `tb_department`, `tb_role`, `tb_login_account`, `tb_login_account_role`, `tb_user`
- 시드 데이터 삽입
  - 테넌트코드 `T1358606250` / 사업자번호 `1358606250` / 테넌트명 `에프원소프트`
  - 로그인 계정 `admin` / `f1soft@611` (`PLATFORM_ADMIN` 역할)
- 스크립트: [backend/DATABASE/20260831](../../../../backend/DATABASE/20260831), [docs/database/2026-08-31](../../../database/2026-08-31)

## 3. 백엔드 변경

- `LoginDAO`에 `selectTenantIdByCode` 추가, `EgovLoginUsr_SQL_postgresql.xml`에 대응 쿼리 추가
- `EgovLoginServiceImpl.actionLogin`이 `tenantCode`를 `tenantId`로 변환해 조회하도록 보완 확인
- **사전 존재하던 문제 수정(범위 외 블로커)**: `mapper-config.xml`의 삭제된 클래스 참조 typeAlias(`userSearchVO`, `mberVO`) 제거, 존재하지 않는 클래스를 참조하던 orphan 매퍼 `ConditionalId_SQL_postgresql.xml` 삭제 — 두 문제 모두 애플리케이션이 아예 기동되지 않게 막고 있던 기존 결함으로, 로그인 기능 검증을 위해 최소한으로 제거함

## 4. 프론트엔드 변경

- [authService.ts](../../../../frontend/src/shared/services/authService.ts): 목업 로그인 제거, 실제 `POST {API_BASE_URL}/auth/login-jwt` 호출로 교체. 응답의 `jToken`/`refreshToken`을 세션에 저장
- `API_BASE_URL`: `import.meta.env.VITE_API_BASE_URL` (미설정 시 `http://localhost:8080`)
- [login.test.tsx](../../../../frontend/tests/login.test.tsx), [setup.ts](../../../../frontend/tests/setup.ts): 전역 `fetch` 모킹 추가, 로그인 실패 케이스 테스트 추가

## 5. 검증 결과

### 5.1 실제 로그인 API 호출 (백엔드 기동 후 curl)

- 성공: `admin` / `f1soft@611` / `T1358606250` → `resultCode: "200"`, `jToken` 발급 확인
- 실패: 잘못된 비밀번호 → `resultCode: "300"`, `"로그인 정보가 올바르지 않습니다."` 확인

### 5.2 자동화 테스트

- 백엔드: `mvn -o test -Dtest=EgovLoginApiControllerTest` 통과
- 프론트: `npm run test` — 9개 파일, 99개 테스트 전체 통과

## 6. 영향 범위 및 주의사항

- DB 변경은 신규 DB(`s-erp_central`)에만 적용되며 기존 운영 DB(`haccp_cloud_central`, `tenant_*`)에는 영향 없음
- `application.properties`의 `Globals.jwt.secret` 등 민감 설정값은 배포 환경에서 반드시 실제 값으로 교체 필요(기존과 동일한 상태 유지, 이번 작업에서 변경하지 않음)
