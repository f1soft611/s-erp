## 2. 구현 결과

- 메뉴 관리 화면에 모듈 선택기를 추가하고, 선택 모듈의 `GET /api/v1/system/menus?moduleId={id}` 결과만 `F1Tree`로 표시한다.
- 활성 권한 마스터 `GET /api/v1/system/permissions` 결과로 `조회`, `등록`, `수정`, `삭제`, `엑셀` 등의 동적 checkbox 열을 구성한다.
- 메뉴 행은 `permissionCodes` 배열을 보유하며, 리프 메뉴에서만 권한 checkbox를 편집할 수 있다. 그룹 메뉴는 구조 메타데이터 기준으로 권한 편집과 삭제가 차단된다.
- `F1Grid`에 선택적 값 조회와 부분 변경 콜백을 추가해 동적 권한 열도 기존 행 변경 상태로 추적한다. `F1Tree`는 일반 grid 정렬/필터를 비활성화해 계층 순서를 유지한다.
- 저장은 메뉴 `POST`/`PUT`/`DELETE`를 먼저 완료하고, 신규 메뉴의 서버 ID를 연결한 다음 변경 리프 메뉴의 `PUT /api/v1/system/menus/{id}/permissions`를 호출한다.
- 저장 중 모듈 전환을 차단하고, 최신 메뉴 조회만 화면 상태를 갱신한다. 실패 시 로컬 메뉴/권한 변경과 저장 체크포인트를 유지해 재시도에서 성공한 CRUD 요청이 반복되지 않는다.

## 3. 백엔드 및 DB

- `tb_permission` 권한 마스터와 `tb_menu_permission` 메뉴별 허용 권한 매핑 테이블을 추가했다.
- 초기 권한 코드는 `READ`, `CREATE`, `UPDATE`, `DELETE`, `EXCEL`이며, 활성 권한만 정렬 순서대로 조회한다.
- 메뉴 목록 응답에 `permissionCodes`를 포함하고, 리프 메뉴의 권한 코드를 전체 교체하는 `PUT /api/v1/system/menus/{id}/permissions`를 추가했다.
- 권한 저장은 관리자만 허용하며, 그룹 메뉴, 비활성/존재하지 않는 권한 코드, 잘못된 테넌트/모듈/부모 메뉴 관계를 HTTP 400으로 거부한다.
- 메뉴 삭제 시 `tb_menu_permission`을 명시적으로 먼저 삭제한다. 기존 역할별 `tb_role_menu_permission`은 변경하지 않았다.
- 스키마 및 롤백 이력은 [backend/DATABASE/20260831](../../../../backend/DATABASE/20260831)와 [docs/database/2026-08-31](../../../database/2026-08-31)에 같은 내용으로 기록했다.
- 2026-08-31에 `20260831_004_create_menu_permission_schema.sql`을 `s-erp_central`에 적용했다. 적용 전 `tb_permission`은 없었으며, 적용 후 `tb_permission`, `tb_menu_permission`과 활성 초기 권한 5개를 확인했다.

## 5. 브라우저 검증

Vite 개발 서버는 `http://127.0.0.1:4173/`에서 정상 HTML과 로그인 화면을 반환하는 것을 확인했다. 이전 `4174` 주소는 프로젝트 루트에서 잘못 기동된 Vite 인스턴스로 `/`에 404 빈 응답을 반환해 사용하지 않는다.

375px, 768px, 1280px에서 관리자 로그인 후 메뉴 관리 화면의 모듈 전환, 리프 권한 checkbox, 그룹 노드 비활성화, 툴바 줄바꿈과 grid 내부 가로 스크롤을 추가로 캡처해야 한다.
