## 구현 내용

- 공정관리의 "공정그룹"을 "작업장"으로 표시한다(버튼, 검색 placeholder, 컬럼 헤더, 컨텍스트 메뉴). 테이블·API 경로·메뉴 URL은 그대로다.
- 공정(`tb_process`)을 테넌트 단위 마스터로 분리하고 `tb_process_group_process`로 작업장과 연결한다. 같은 공정을 여러 작업장에서 쓸 수 있다.
- 트리: 작업장(`g:`)과 연결 행(`m:`). 연결 행은 읽기 전용이며 작업장 이름·설명·미사용만 편집한다.
- `공정 추가`는 `공정 선택` 모달에서 사용 중이고 아직 연결되지 않은 공정 마스터를 다중 선택한다. 신규 직접 입력은 없다.
- `공정 설정` 모달(`CommonDialog`)에서 공정 마스터를 등록·수정·삭제한다. 미저장 트리 변경이 있으면 버튼이 비활성화되고, 모달 저장 후 트리를 다시 조회한다.
- 후속 변경: `공정 설정` 버튼을 `작업장 추가` 왼쪽으로 이동. 조회 권한이 있으면 `공정 추가`와 `저장` 사이에 `조회` 버튼을 표시하고, 저장하지 않은 변경이 있으면 공통 확인 모달로 확인한 뒤 조회한다. 공정 설정 모달 저장 시 토스트를 표시하고 트리를 조용히 재조회한다.
- 서버: 마스터 API(`/masters`, `/masters/save-batch`) 추가. 연결된 공정 마스터와 연결이 남은 작업장은 삭제할 수 없다. 중복 연결, 다른 테넌트의 공정·작업장, 비활성 공정은 거부한다. 같은 요청의 삭제는 연결 → 작업장 순서로 처리한다.

## 백엔드 패턴·정책 대조

창고관리 기준 구현과 `backend/AGENTS.md`를 확인해 다음을 맞췄다.

- 계층: `controller` / `service`(인터페이스) / `service/impl` / `domain/model` / `domain/repository`, 쓰기 서비스 `@Transactional(rollbackFor = Exception.class)`, `ResultVoHelper` 응답, 권한은 메뉴의 생성·수정·삭제 검사. 컨트롤러에 `@Tag`와 `@Parameter(hidden = true)` Swagger 표기 추가.
- Java 8: 변경 운영 코드를 `javac --release 8`로 컴파일해 통과했다.
- DB 스크립트: 최근 스크립트와 같이 `public.` 스키마 한정, 대상 테이블 `LOCK`, 사전 조건 `DO` 가드, 테이블·컬럼 `COMMENT ON`, 롤백 스크립트와 변경 이력 `.md`, `docs/database`·`backend/DATABASE` 동일 유지, `db-schema.md` 갱신.
- 이름 규칙: 신규 테이블은 기존 공정 테이블군(`tb_process*`)과 같은 이름 체계로 두었다. `tb_<모듈>_<업무>_<구분>` 모듈 접두어 규칙(예: `tb_purchase_*`)은 헤더/상세 업무 테이블 기준이고, 공정 테이블은 접두어 없는 기존 마스터 테이블(`tb_warehouse`, `tb_item_*`)과 같은 계열이라 이름 변경(RENAME)은 하지 않았다. 접두어 통일이 필요하면 별도 작업(RENAME + 건수 대조)으로 진행해야 한다.

## DB 확인 (MCP)

읽기 전용 `s-erp-postgresql-readonly`로 확인했다: `tb_process`·`tb_process_group` 컬럼, FK `tb_process_tenant_id_group_id_fkey`, 인덱스 `idx_process_group`, `process_id`를 참조하는 다른 컬럼 없음, 작업장 3건·공정 4건·병합 후 4건(이름만 병합과 속성 포함 병합이 같은 결과). 병합 기준은 이름 + 미사용 + 9개 플래그로 확정했다. DB 쓰기와 스크립트 적용은 하지 않았다.

## 검증

- 프론트엔드: 공정관리 테스트 15건 통과(버튼 순서·조회 권한·조회 확인 모달·저장 토스트 포함, 연결 행 읽기 전용, 공정 선택·연결 제출, 컨텍스트 메뉴, 권한·검색 시 비활성, 공정 설정 저장 후 재조회 등), 저장키·라우터 테스트 포함 3개 파일 23건 통과, `tsc -b`와 `npm run build` 성공(기존 chunk 크기 경고), `npm run lint` 오류 없음.
- 백엔드: `mvn test` 전체 1613건 통과(실패 0, 오류 0, 건너뜀 3). 공정 서비스 테스트 17건에 연결 생성·수정 거부·중복·삭제 순서·마스터 삭제 차단 등을 추가했다.

## 미검증

- **마이그레이션 SQL과 롤백은 실행하지 못했다.** 로컬에 PostgreSQL이 없다. `ProcessManagementPostgresIntegrationTest`를 새 스키마(생성 + 분리 스크립트)와 마스터 공유·테넌트 격리·삭제 차단 시나리오로 갱신했지만 `PROCESS_TEST_JDBC_URL` 격리 DB가 필요해 건너뛰었다(실행하면 분리 스크립트도 빈 테이블 기준으로 함께 검증된다). 운영 적용 전 격리 DB에서 이 테스트와 데이터가 있는 상태의 이관·롤백을 확인해야 한다.
- 실제 브라우저(375/768/1280px) 렌더링과 스크린샷은 확인하지 않았다. 모달 레이아웃과 반응형은 DOM 테스트로만 검증했다.
- 이름만 같고 속성이 다른 공정은 별도 마스터로 남는다. 필요하면 공정 설정에서 사람이 정리한다.
