# 출하등록 수주 선택 상세검색 결과

## 작업 내용

- 출하등록의 수주 선택 모달에 통합검색과 토글형 상세검색을 적용했다.
- 통합검색은 현황 화면처럼 별도 실행 버튼 없이 Enter로 조회하며, 입력된 검색어는 지우기 버튼으로 초기화한다. 상세검색 패널의 검색 적용 버튼은 유지했다.
- 상세검색 패널이 열린 동안 선택 모달 전체에 현황 상세검색 backdrop과 같은 `rgba(15, 23, 42, 0.12)` 딤을 적용하고, 상세검색 패널은 선명하게 유지한다. 결과 그리드는 inert 상태로 두며, 모달 바깥 앱 화면은 기존 backdrop 상태를 유지한다. 2026-11-20 전체 딤 적용 내용은 [결과 문서](../../20261120/source-order-picker-status-backdrop/20261120_001_출하등록_수주선택_전체딤_결과.md)를 참고한다.
- 상세검색의 필수 기준일은 수주일자이며, 서버 날짜 기준 기본값과 기존 빠른 날짜(오늘·이번주·이번달·전월·최근 30일)를 유지했다.
- 수주번호, 거래처, 품목, 계획번호 및 선택 계획일자를 조회 API와 Mapper 필터에 연결했다. 필드별 AND, 각 필드 내부 코드/명 OR 검색이며 tenant, 활성 상태, 미납 잔량, 200건 제한과 기존 선택 검증은 유지한다.
- 다이얼로그 검색 폼의 공통 사용 원칙과 `PageSearchArea mode="dialog"` 동작을 `frontend/src/pages/f1-grid-docs/F1-GRID.md`에 기록했다. 검색 폼만 공통화하고 대상별 조회 API와 결과 선택은 각 모달이 소유한다.
- DB 스키마 변경은 없다.

## 검증

- 프론트엔드 대상 테스트: 39개 통과
- 프론트엔드 빌드: 통과. 기존 대형 번들 크기 경고가 출력됐다.
- 백엔드 대상 테스트: `SalesDeliveryApiControllerTest`, `SalesDeliveryServiceImplTest`, `SalesDeliveryMapperTest` 통과
- 브라우저 확인: 375px, 768px, 1280px에서 상세검색 패널, 5개 빠른 날짜 버튼, 결과 그리드를 확인했다. 패널이 열린 동안 전체 모달은 현황과 같은 색상으로 딤되고 상세검색은 선명하며, 바깥 앱 화면은 기존 모달 backdrop 상태를 유지한다. 그리드 조작은 막히고 패널을 닫으면 다시 활성화된다. 문서 전체 가로 overflow는 없다.
- DB MCP: `s-erp-postgresql-readonly`의 테이블 목록과 수주·출하계획 관련 테이블 메타데이터를 확인했다. 업무 데이터 행 조회와 스키마 변경은 없었다.
