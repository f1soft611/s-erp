## 구현 내용
- **DB** `20261119_004`: `tb_user`에 사번·영문이름·직위·성별·근무형태·내외국인·국적·생일(음력/양력)·입사/퇴사/휴직/복직일·외국인 체류·근로계약일·주민등록번호 암호문/키버전/해시/마스킹·연락처·주소·실사용자·사진·감사 컬럼 31개, 사번·주민번호 해시 유일 인덱스, CHECK 3개, 사원등록 메뉴·권한, 계정이 있는 기존 사원의 실사용자 보정. `20261119_005`: 공통코드 5그룹(성별·내외국인·근무형태·생일 구분·직위 10개)과 국가 249개국(ISO 3166-1 alpha-3 코드, 기존 KR·JP는 KOR·JPN으로 변경).
- **백엔드** `let/hr/employee`, `let/hr/common/ResidentNumberCipher`: `/api/v1/hr/employees` 목록·상세·등록·수정·사번 중복 확인(전부 테넌트 관리자 전용, 삭제 없음). 사번은 직접 입력 또는 입사년월 `YYMM`+순번 2자리(99 초과 시 3자리)를 `tb_id_sequence`로 자동 부여하고 등록 후 수정할 수 없다. 주민등록번호는 AES-256-GCM 암호문, HMAC 해시(중복 방지), 마스킹 값만 저장하고 응답에는 마스킹만 나간다. 실사용자는 계정(`tb_login_account`, `DEFAULT_USER` 역할, 비밀번호 변경 시각 비움)을 같은 트랜잭션에서 발급하고 사진을 계정 프로필 이미지에도 기록한다.
- **1단계 후속**: 부서 소속 사원 조회·부서 사용안함 차단·부서장 자격·부서 사원 수에서 퇴직자 제외, `status`(재직·퇴직·전체) 구분, 사번·직위·재직상태 노출. 재직상태는 컬럼 없이 퇴사일·휴직일·복직일로 계산한다.
- **프론트** `pages/hr/employee`: 사원 목록(사진, 이름 파란 링크, 통합검색, 재직 구분 상세검색, 퇴직자 흐리게, 자택전화·주소 포함, 품목관리처럼 맨 오른쪽 고정 "상세"(연필) 열로도 등록·수정 팝업 열기), 등록·수정 팝업(기본·개인연락·내/외국인·시스템 사용 섹션, 부서 선택 도움창, 사번 중복 확인, 주민번호 마스킹 안내, 외국인 전용 항목 토글, 실사용자 체크 시 계정 입력, 사진 업로드·320px JPEG 축소). 부서관리 소속 사원 목록에 사번·직위·재직상태와 재직 구분 필터를 추가했다.

## 구현 중 발견·확정한 사항
1. **부서 선택 도움창 결함 수정**: 사원 팝업에서 부서를 고를 때 선택 이벤트가 반복 호출되어 화면이 멈추는 문제를 테스트에서 발견했다. 선택을 한 번만 전달하도록 고치고 회귀 테스트를 추가했다(도움창을 처음 부모가 다시 그려지는 화면에 연결한 사례였다).
2. **마스킹 컬럼 추가**: 목록·상세가 복호화 없이(키가 없거나 바뀌어도) 마스킹 값을 보여 주도록 `resident_no_masked`를 두었다(생년월일 6자리와 성별 1자리만, 뒷자리는 저장하지 않음).
3. **계정 있는 기존 사원 보정**: 기존 11명이 계정은 있는데 실사용자 값이 'N'이라 "계정 있는 사원의 실사용자 해제 불가" 규칙과 어긋나 `20261119_004`가 'Y'로 맞춘다.
4. **"상세" 열과 이름 링크**: 팝업 열기가 눈에 띄지 않아 품목관리와 같은 맨 오른쪽 "상세"(연필) 열을 추가했고, 이름 파란 링크는 그대로 둔다(둘 다 팝업을 연다). 재직상태는 퇴사일 뒤로 두었고 자택전화·우편번호·주소 컬럼을 목록에 추가했다.
4-1. **로그인 아이디 기본값**: 실사용자 계정 발급 시 로그인 아이디를 비우면 사번을 아이디로 쓴다. 사번이 4~30자 영문·숫자가 아니면 직접 입력하도록 안내하고, 중복은 팝업에서 포커스를 벗어날 때(`GET /check-login-code`)와 서버(409)에서 막는다. 아이디는 발급 후 수정할 수 없다.
4-2. **주소 검색(카카오 우편번호)**: 우편번호·주소는 읽기 전용이고 "주소 검색"으로만 채우며 상세주소는 직접 입력한다. MES는 `t1.daumcdn.net` 스크립트를 썼으나 이 도메인은 **2026-11-30 종료**되어(검색 창에 변경 안내가 뜸) `t1.kakaocdn.net`으로 연동했고, 서버 CSP `script-src`에 이 도메인을 허용했다. 스크립트는 처음 검색할 때 한 번만 불러온다. 개발 서버(4173)는 CSP 영향이 없으므로 **백엔드가 화면을 함께 서비스하는 운영 배포에서는 이 CSP 반영 여부를 확인**해야 한다.
4-2-1. **주소 검색 창 중복 열기 수정**: 검색 창을 열었다 닫으면 "팝업을 열 수 없습니다. 팝업 차단 기능을 확인해 주세요" 안내가 떴다. "주소 검색" 버튼 클릭이 우편번호 칸의 클릭으로도 전달되어 한 번 클릭에 검색 창을 두 번 열려던 것이 원인이었다(테스트에서 호출 2회로 재현). 칸 클릭은 입력창에만 걸고, 스크립트를 이미 불러왔으면 클릭 동작 안에서 바로 열며, 팝업을 열 때 스크립트를 미리 불러 두도록 고쳤다. 회귀 테스트로 클릭당 1회 호출을 검증하고 브라우저에서 열린 창이 1개임을 확인했다(자동 브라우저는 팝업 차단을 적용하지 않아 안내창 자체는 재현되지 않으므로, 실제 크롬에서 수동 확인이 필요하다).
4-3. **팝업 정렬·사번 안내**: 테마의 `TextField` 기본 여백이 날짜 입력과 달라 같은 줄의 칸이 16px 어긋나던 것을 팝업 그리드에서 여백 0·위쪽 정렬로 고쳤고(브라우저에서 모든 줄의 입력칸 윗선이 일치함을 확인), 사번 칸에 "부여한 사번은 변경할 수 없습니다" 안내를 항상 보여 준다.
5. **UI 보정**: 값이 비어 있는 선택 칸의 라벨과 "선택 안 함" 문구가 겹치던 것(라벨 고정), 이름 열 너비를 고쳤다. 외국인이 아니면 외국인 전용 항목은 숨기고 비워서 저장한다. 헤더 "조회"는 입력한 검색어·상세조건을 적용한다.
6. 사번 형식은 사용자 결정에 따라 직접 입력 또는 `YYMM`+순번이며 **입사일 기준**이다(MES는 등록일 기준이었다).

## DB MCP 확인 근거 (읽기 전용)
- 적용 후: `tb_user` 신규 컬럼 31개, 유일 인덱스 2개, CHECK 3개, 계정 있는 11명 `real_user_at='Y'`(불일치 0), 공통코드 `COUNTRY` 249·`POSITION` 10·나머지 그룹 2건씩, 메뉴 `HR_INFO_EMPLOYEE`(메뉴 권한 4, 역할 권한 16) 확인.
- 저장 확인: 주민번호는 암호문 41바이트(nonce 12+값 13+태그 16), 해시 64자, 마스킹 값, 키 버전 `v1`이며 암호문에 평문이 없음. 신규 계정은 `password_changed_at` 비어 있음, `DEFAULT_USER` 역할, 비밀번호 해시에 평문 없음, 사진이 프로필 이미지와 동일. `HR_EMPLOYEE_NO`/`2611` 카운터가 점검 등록 수만큼 증가.
- 점검 후 상태: 부서 11개 모두 사용 중·부서장 없음(점검 중 사용안함·부서장 지정을 모두 되돌림).
