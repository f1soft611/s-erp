## 구현 내용
- **DB** `20261119_002`: `tb_department`에 `manager_user_id`, `department_dc`, `created_by`, `updated_by`, 같은 상위 아래 부서명 유일 인덱스(최상위·하위 각각), HR 모듈과 메뉴·권한 시드. `20261119_003`: 메뉴를 그룹 "인사정보" 하나로 통합(제자리 이름 변경).

- **프론트** `pages/hr/department`: 좌측 폴더형 F1Tree(열림·닫힘·하위 없음 아이콘), 맨 위 회사 노드(회사정보의 회사명, 편집 불가), 우클릭 "하위 부서 추가·편집·사용안함·복원", 등록·편집 팝업(CommonDialog), 우측 소속 사원 목록(회사 선택 시 부서 미지정 사원), "사용안함 포함" 토글.
- **공통 F1Tree 확장(옵션형, 미지정 시 기존 동작 동일)**: `treeNodeIcon`, `treeContextMenu.items`. F1-GRID.md·API 레퍼런스·문서 화면·테스트 반영.
- AGENTS.md 테이블 이름 규칙 한 줄 동봉.

## 사양과 달라진 점
1. **메뉴 구조**: 사양 작성 후 그룹 "인사정보" 하나에 부서·사원·인사명령을 담기로 결정해 코드·URL을 `HR_INFO`/`HR_INFO_DEPARTMENT`, `/hr/info/...`로 변경. 002가 먼저 적용되어 003 스크립트로 제자리 변경했다(메뉴 ID·권한 유지).
2. **`/hr/*` 라우트 추가**: `AppRouter.tsx`는 모듈별 경로를 나열하므로 신규 모듈은 라우트 등록이 필요했다. 처음에는 놓쳐 브라우저에서 "페이지를 찾을 수 없습니다"가 나왔고, 추가 후 해결했다. 이후 신규 모듈 작업의 체크 항목이다.
3. **상위 부서 선택**: 사양 초안은 읽기 전용이었으나 팝업에서 선택하도록 했다(자기 자신·하위 제외, 서버에서도 순환 차단).
4. **우클릭 메뉴 사용자 정의 항목**: 승인한 "편집/사용안함" 메뉴를 위해 `treeContextMenu.items` 확장이 추가로 필요했다.
5. **회사 최상단 노드(방법 A)**: 사양 작성 후 추가. 회사 노드는 DB 행이 아니라 화면에서만 만들고 이름은 `tb_tenant.tenant_nm`을 읽어 온다(목록 응답 `companyName`). 최상위 부서는 `parent_department_id = NULL` 그대로이며, 회사 선택 시 부서 미지정 사원 API(`/unassigned/users`)를 쓴다. 팝업 상위 부서 맨 위에 "회사명(최상위)".
6. **부서장 규칙**: 초안은 "같은 테넌트의 사용 중 사원"이었으나 사용자 지적으로 "그 부서의 소속 사원"으로 변경했다. 전체 사원을 주던 `manager-options` API를 없애고 `GET /{id}/users`를 재사용한다. 신규 부서는 소속 사원이 없어 부서장 지정이 막히며(편집에서 지정), 부서장을 바꿀 때만 소속 여부를 검사한다.
7. **부서 선택 도움창 추가(공통)**: `shared/components/department-picker`. 별도 API 없이 목록 API 재사용, 회사는 선택 불가.
8. 서버 오류 코드(`duplicateName` 등)는 별도 코드 없이 HTTP 상태(400/409)와 한국어 메시지로 구분한다.

## DB MCP 확인 근거 (읽기 전용)
- 작업 전: `tb_department` 컬럼·제약·인덱스, 참조 FK(`tb_user`, `tb_warehouse`, `tb_purchase_*_hd`, `tb_quality_inspection_hd`), IDENTITY 채번, 부서 0건, `tb_module`·`tb_menu`·권한·역할 권한(`CO_WAREHOUSE` 기준) 조회.
- 적용 후: 신규 컬럼 4개, 유일 인덱스 2개, `HR` 모듈 1건, 메뉴 `HR_INFO`(66)/`HR_INFO_DEPARTMENT`(67), 권한 메뉴 3건·역할 12건 확인. 003 적용 후 메뉴 이름·URL 변경 확인.

## 미확인·후속
- 소속 사원이 있을 때의 사용안함 차단과 부서장 지정 성공 경로는 사원등록(2-1) 이후 실서버로 확인했다.
- 소속 사원 목록의 재직/퇴직 필터와 사번·직위·재직상태 표시는 2-1에서 반영했다(아래 "2-1 후속 반영").
- 기존 `tb_department` 소비 화면(창고, 구매요청 등)의 부서 선택 목록은 `use_at`을 걸러 내지 않는 곳이 있어 사용안함 부서가 계속 보일 수 있다. 이번 범위에서는 바꾸지 않았다.
- 다른 테넌트에는 메뉴를 만들지 않았다(기존 메뉴 시드와 동일하게 테넌트 1).
- 점검용 부서 6건(`테스트…`)이 사용안함 상태로 DB에 남아 있다(삭제 기능 없음).
- 사용자 요청으로 부서 11건(임원, 경영지원팀, 영업팀>내부·외부, 생산팀>생산1·2팀, 품질팀, 연구개발팀, 마케팅팀)을 등록했다.
- 부서 선택 도움창은 사원등록(2-1)에서 쓰이며 실제 브라우저로 확인했다(선택 이벤트 반복 호출 결함을 이때 발견해 수정). 부서→사원 선택 도움창은 첫 사용처가 생길 때 만든다.
- 사원등록(2-1)으로 사원을 부서에 배정할 수 있게 되어 부서장 지정이 가능하다. 사원이 다른 부서로 옮겨 갈 때 부서장을 자동 해제하는 처리는 사원 부서 변경을 다루는 인사명령(3단계)에서 정한다.
