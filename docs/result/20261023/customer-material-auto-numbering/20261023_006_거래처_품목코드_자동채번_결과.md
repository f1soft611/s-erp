# 거래처·품목 코드 자동채번 결과

## 작업 요약

- 거래처코드와 품목코드는 목록에 표시하되 신규·수정 행 폼, 셀 편집, 붙여넣기에서 제외했습니다.
- 신규 저장 시 요청 본문의 코드 값과 관계없이 기존 eGov ID Generator가 생성한 6자리 코드를 사용합니다.
- 수정 저장 시 요청 코드 값을 무시하고 기존 코드를 보존하도록 서비스와 Mapper를 변경했습니다.
- DB 스키마, ID Generator 설정, 기존 코드 데이터는 변경하지 않았습니다.

### 브라우저 스크린샷

스크린샷은 로컬 Vite 화면에서 API 응답을 테스트용 값으로 대체하고, 빈 등록 폼만 캡처했습니다. 실제 테넌트 데이터는 포함하지 않습니다.

## DB 확인 및 적용 범위

- 읽기 전용 `s-erp-postgresql-readonly` MCP로 테이블 목록을 확인한 뒤 `tb_customer_info`, `tb_material_info`, `ids` 메타데이터를 확인했습니다.
- 코드 컬럼과 기존 ID Generator 계약을 확인했으며, 업무 데이터 행은 조회하지 않았습니다.
- DB 쓰기·DDL·마이그레이션은 수행하지 않았고 스키마 변경 스크립트도 필요하지 않습니다.

## 회귀 동작

- 기존 6자리 생성 형식, 초기화·범위 오류, tenant 범위 중복 검사와 재시도, DB unique 오류 처리를 유지했습니다.
- 기존 이름·사업자번호·품목 업무 필드 검증과 저장 흐름을 유지했습니다.
- 고객·품목 수정 요청에서 코드 값이 누락되거나 비어 있거나 임의 값이어도 코드가 변경되지 않는 것을 서비스 테스트와 Mapper SQL 검증으로 확인했습니다.
