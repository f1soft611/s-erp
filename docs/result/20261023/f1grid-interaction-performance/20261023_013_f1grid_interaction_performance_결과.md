품목·거래처 각 100건 적용 후 선택·편집·저장 지연 보고를 조사했다. 공용 그리드 렌더 및 두 화면의 저장 후 재생성 시점을 수정했다. API/DB/스키마 변경은 없으며 실제 저장 요청은 테스트하지 않았다.

## 원인과 수정

1. 전역 draftValue가 모든 셀의 memo를 무효화했다. 편집 셀에만 입력값을 전달한다.
2. 고정 위치 객체가 새로 생성돼 고정열을 다시 렌더링했다. 방향·위치·그림자 값으로 비교한다.
3. 실제 품목 화면의 열 가상화는 표시 인덱스가 같아도 새로운 Set으로 모든 행의 memo를 무효화했다. 동일 집합을 재사용한다.
4. 전역 포커스·선택 참조를 행마다 그대로 비교했다. 일반 행은 자신의 표시 영향만 비교하고 병합 열은 전역 포커스/편집 갱신을 보존한다.
5. 드래그 플래그 변경이 모든 리사이즈 버튼을 다시 만들었다. 부모 데이터 속성/CSS로 비활성화를 전달하고 이벤트는 최신 플래그로 차단한다.
6. 편집 중 헤더가 다시 렌더링되고 비체크박스 열까지 전체 행 체크 상태를 계산했다. 헤더를 memo로 보호하고 계산을 체크박스 헤더에 한정한다.
7. 저장 응답 직후 이전 목록으로 그리드를 재생성했다. 재조회 종료 후 초기화한다. 저장 실패 시 변경 유지, 저장 성공/재조회 실패 시 중복 저장 방지 및 오류 알림은 유지한다.

표시 memo가 과거 이벤트 클로저를 유지하지 않도록 셀·행·헤더 이벤트는 최신 props를 전달하는 안정적인 핸들러를 사용한다.

## 측정

### 합성 품목 100행

| 항목 | 초기 측정 | 최종 측정 |
| --- | --- | --- |
| 단일 선택 중 표시 renderer 호출 | 1,602회 | 1회 |
| 입력값 변경 중 비편집 표시 renderer 호출 | 1,099회 | 0회 |
| 입력 한 번의 React commit actualDuration | 약 308ms | 약 19.8ms |

개발 빌드 React Profiler 결과다. 초기 합성 화면에는 행 폼 버튼이 없었고 최종 합성 검증에는 포함했다. 따라서 엄밀히 같은 UI 구성의 성능 비율로 해석하지 않는다. 시스템 부하에 따라 시간은 달라지며 결정적 회귀 기준은 렌더 호출/행 방문 횟수다.

### 사용자 공유 품목 화면

- 103행, 표시 셀 1,133개, 전체 표시 대상 열 12개 중 가상화로 10개 렌더 상태에서 조사했다.
- 1차 셀 최적화 후에도 선택 지연은 343~775ms였다. 실제 화면의 열 가상화 참조 무효화와 헤더 비용을 추가 수정했다.
- 최종 공유 화면 선택 측정 5회: **72, 83, 84, 84, 84ms**.
- 편집 진입: **97ms**, 입력 변경: **55ms**.
- 이벤트 발생부터 두 번의 requestAnimationFrame 대기까지 포함한다. 순수 렌더 시간이나 운영 환경 보장 수치가 아니다.
- 임시 입력은 Escape로 취소했으며 업무 데이터 저장은 하지 않았다. 업무 데이터 값은 이 결과나 스크린샷에 기록하지 않는다.

## 테스트

- 집중 묶음: 성능 8개, 병합 5개, 고정열 범위 1개, 폼 47개, 품목 22개, 거래처 19개 — **102개 통과**.
- 행별 렌더 생략 이후 다른 행에서 Escape로 선택을 취소하고 이전 행에서 드래그를 재시작하는 회귀를 추가했다. 오래된 이전 드래그 셀만으로 mousedown을 생략하던 조건을 제거해 새 드래그는 항상 시작하도록 했다.
- 드래그 중 행 높이 조절 금지의 기존 테스트도 별도 실행해 통과했다.
- `npm run build`: 통과. 기존 1,000KB 초과 청크 경고는 남아 있다.
- 기타 F1-Grid 테스트 20개 파일 실행: 196개 통과, 13개 실패. 이어 광역 실패 파일 5개를 격리된 `f36fb7ee` 스냅샷과 비교했다.
- 격리 기준에서도 동일한 광역 실패 59개를 확인했다. 기존 깨진 문자열 기대값, 테스트 페이지/스토리지 키 계약, 문서 검색 타임아웃 등의 문제다. 최적화 중 추가된 드래그 리사이즈 실패 1개는 부모 속성 위치 수정 후 집중 재실행으로 통과했다.
- 전체 테스트가 모두 통과한 것은 아니다. 관련 집중 묶음과 빌드는 통과했고 기존 광역 실패는 범위 밖으로 남겼다.

각 뷰포트에서 document 폭과 grid 폭이 375/768/1280px로 같아 페이지 전체 가로 넘침은 없었다. 고정열 너비가 좁은 화면보다 큰 기존 동작은 그대로다. 레이아웃이나 고정열 정책은 변경하지 않았다.

## 남은 확인

- 저장 후 중복 그리드 생성은 테스트로 제거했지만 실제 저장 API·DB 응답시간은 미측정이다. 서버 저장 지연까지 해결했다고 단정하지 않는다.
- 실제 거래처 화면 시간 측정은 미수행이다. 공용 그리드 변경과 거래처 저장 후 조회 흐름은 관련 테스트로 검증했다.
- 기존 개발 서버를 재사용했으며 새로 시작하거나 종료하지 않았다.
- 작업 도중 중간 변경이 `f36fb7ee`로 커밋된 것을 확인했다. 에이전트는 스테이징·커밋하지 않았으며 무관한 역할 관리 변경을 수정하지 않았다.
