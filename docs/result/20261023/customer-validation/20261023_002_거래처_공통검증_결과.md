## 재현 조건과 원인

1. 거래처 사업자번호 컬럼에 `required`가 없어 헤더·폼 필수 표시가 없고 빈 값으로 적용할 수 있었다.
2. 거래처명 필수 검사는 공통 컬럼 설정 외에 저장 훅에서도 중복 수행했다.
3. 번호 자리수는 기존 `validateGridRow`에서 이미 검사하지만 폼 오류를 페이지로 전달하는 공통 계약은 없었고, 최종 저장은 모든 오류를 일반적인 필수 안내로 표시했다.
4. 오류 셀에 포커스가 남으면 파란 outline이 오류 빨간 강조보다 우선했다.

## 구현

- 거래처명·사업자번호의 필수 표시와 검증을 컬럼 `required`로 통일했다.
- 번호 자리수 검사는 기존 `inputFormat` 공통 검증을 그대로 재사용했다.
- 선택적 `onValidationErrors` 콜백에 `{ rowId, field, message }[]`를 전달한다. 폼 적용과 `validate()` 모두 사용하며 성공 시 빈 배열을 전달한다.
- 거래처 페이지는 오류 메시지를 중복 제거 후 기존 상단 메시지영역에 표시한다. 저장 훅의 거래처명 필수 검사를 제거했다.
- 폼의 첫 오류 포커스·빨간 테두리·하단 설명과 그리드 툴팁을 유지한다. 포커스된 오류 셀은 빨간 outline을 우선한다.
- 모달이 열린 동안 페이지 상단 메시지는 배경에 있으며, 폼 내부 오류 설명으로 즉시 확인한다.
- 기존 수정 코드·사용여부·삭제 방지·API 오류 처리 및 다른 화면의 boolean 검증 계약은 유지한다.
- 백엔드·API·DB 변경은 없다. 이번 작업은 DB 관련 구현이 아니므로 DB MCP 확인과 SQL 변경 대상이 아니다.

기존 실패는 `f1-grid-form-modal.test.tsx`의 `renders fixed modal regions, responsive grid span contracts, and final-save guidance`다. 구현 전 최초 실행부터 동일하게 모달의 `maxWidth: 960px`/`maxHeight: 85vh` 스타일 단언이 실패했다. 현재 공통 모달은 lg 990px 및 내부 paper 스타일을 사용한다. 관련 없는 모달 크기/테스트는 수정하지 않았다. 기존 MUI select 범위 경고도 관찰했다.

브라우저 확인은 기존 4173 S-ERP Vite 서버를 재사용하고 독립 브라우저 컨텍스트와 가상 API fixture를 사용했다. 실제 계정/테넌트 데이터와 DB에는 접근하지 않았다. 브라우저는 `finally`에서 종료했으며 기존 서버는 종료하지 않았다.
