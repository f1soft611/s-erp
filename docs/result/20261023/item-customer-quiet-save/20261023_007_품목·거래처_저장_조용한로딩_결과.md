# 품목·거래처 저장 조용한 로딩 결과

## 변경 내용

- 원인: 품목·거래처 페이지가 Grid의 `loading` 값으로 목록 조회뿐 아니라 `saving` 상태까지 전달해 저장 중 전체 Grid 오버레이를 띄웠다.
- 수정: 두 페이지는 Grid에 조회 `loading`만 전달한다. 저장 버튼 진행 아이콘과 저장 중 추가/편집/조회 차단은 그대로 유지하며, 저장 후 조용한 재조회 흐름도 변경하지 않았다.
- 문서: [F1-GRID 사용 문서](../../../../frontend/src/pages/f1-grid-docs/F1-GRID.md)에 저장 상태와 Grid 로딩 분리를 명시했다.
- 회귀 테스트: 저장 요청과 조용한 재조회 각각에서 저장 진행 표시가 유지되고, 전체 로딩 오버레이 없이 기존 행이 노출되는지 품목·거래처 페이지에서 확인한다.

## 검증 결과

- RED: 구현 전 새 품목·거래처 테스트가 모두 `f1-grid-loading-overlay`가 나타나는 문제로 실패했다.
- GREEN: `npx vitest run --testNamePattern="keeps the .* grid visible during save" tests/customer-management-page.test.tsx tests/material-management.test.tsx` 통과(2개).
- `npx vitest run tests/customer-management-page.test.tsx --maxWorkers=1 --testTimeout=15000` 통과(18개). 거래처 테스트 중 하나가 기본 5초 제한을 넘어, 검증 명령에서만 제한을 늘렸다.
- 최종 통합 실행: 31개 통과, 3개 실패. 거래처 18개는 통과했고 품목 저장 회귀도 통과했다. 실패한 소비기한 검증(`requires a positive integer expiry count...`, `clears the expiry count...`, `derives the expiry count...`)은 별도 품목 변경 작업의 테스트이며 이 변경의 저장 로딩 동작과는 무관하다.
- `npm run build` 실패: `src/pages/co/master/materials/components/MaterialGrid.tsx:65`에서 `MaterialTextField` 정의에 `align` 속성이 없다는 TS2339 오류. 해당 파일은 별도 품목 변경과 함께 수정 중이므로 이 작업에서는 건드리지 않았다.

## 브라우저 확인

실제 브라우저 확인과 화면 크기별 스크린샷은 완료하지 못했다. 공유 페이지의 브라우저 ID가 탐색/조작 도구에서 유효하지 않다고 반환됐고, 별도 페이지에서 관리 화면 URL을 열면 로그인 화면으로 이동했다. 계정 로그인을 시도하거나 업무 데이터를 변경하지 않았다. 저장 중 동작은 자동화된 실제 페이지 테스트로 검증했다.
