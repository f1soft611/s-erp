# 품목·거래처 샘플 데이터 시드 결과

## 요약

- 지정 tenant에서 거래처 100건과 품목 100건을 생성하도록 psql 시드 SQL을 추가했다.
- tenant ID는 SQL에 저장하지 않고 실행 시 `target_tenant_id` 변수로 받는다.
- 기존 6자리 ID Generator 카운터를 잠금 후 코드 100개씩 예약하고, 거래처와 품목을 같은 트랜잭션으로 생성한다.
- 기존 샘플 마커/이름/사업자번호 충돌, 필수 활성 공통코드 누락, 코드 소진, 테넌트 오류 또는 행 수 불일치는 전체 롤백 대상이다.
- 실제 업무 데이터는 삽입하지 않았다. 따라서 현재 테넌트 목록에 샘플이 생긴 것은 아니다.

## 안전 동작

- psql `target_tenant_id` 값이 없거나 정수가 아니면 실행이 실패한다.
- 거래처·품목 IDS 카운터 행을 정렬된 순서로 먼저 `FOR UPDATE` 잠근 뒤 두 관리 테이블 전체에 `SHARE ROW EXCLUSIVE` 잠금을 잡는다. 기존 쓰기 트랜잭션을 기다리며 시드가 끝날 때까지 모든 tenant의 해당 테이블 INSERT/UPDATE/DELETE가 대기한다. SELECT는 가능하다.
- 기존 숫자 코드를 포함해 각 ID 카운터의 다음 값을 확인하고, 두 시드 코드 범위를 각 100개씩 원자적으로 예약한다. `ITEM_TYPE`, `ITEM_UNIT`은 tenant 활성 코드만 사용하고 필수 항목이 없으면 중단한다.
- 회사명/품목명과 마커는 가상 샘플이다. 사업자번호는 10자리 형식이지만 표준 체크섬에 맞지 않는 고유 테스트 값으로 구성한다. 실재 사업자번호로 사용할 수 없으며, 실제 주소·연락처·대표자·계좌 데이터는 만들지 않았다.
- 거래처명, 사업자번호 또는 마커 충돌 시 덮어쓰기나 건너뛰기 없이 전체를 중단한다. 샘플 데이터와 IDS 카운터는 동일 트랜잭션에 있어 오류 시 함께 롤백된다.
- 데이터만 추가하는 시드이며 DDL은 없다. 위험한 기존 샘플 자동 삭제를 피하기 위해 삭제용 롤백 SQL은 제공하지 않는다.

## DB MCP 확인 범위

기본 `s-erp-postgresql-readonly` MCP에서 `list_tables` 후 `tb_customer_info`, `tb_material_info`, `ids`, `tb_common_code_group`, `tb_common_code_item`의 컬럼 메타데이터를 확인했다. 테이블 데이터 행, tenant 행, 사용자/계정 정보, IDS 카운터 값은 조회하지 않았다. MCP는 읽기 전용으로 사용했으며, SQL 실행이나 쓰기 작업은 하지 않았다.

## 수동 실행 전 확인

- 대상 tenant ID를 승인된 값으로 준비한다.
- 대상 tenant에서 활성 `ITEM_TYPE`·`ITEM_UNIT` 코드가 있고 각 코드가 컬럼 최대 길이(각각 14자/6자) 이내인지 확인한다.
- `public.ids`에 `tb_customer_info`, `tb_material_info` 카운터 행이 이미 존재해야 한다. 없다면 해당 프로젝트의 ID Generator 초기화 절차를 먼저 검토한다.
- 실행 중 두 테이블의 모든 tenant 쓰기 요청이 일시 대기하므로 저사용 시간에 psql로 실행한다.
- 예시 명령: `psql -v ON_ERROR_STOP=1 -v target_tenant_id=<tenant_id> -f <script.sql>`

## 확인 한계

- 사용자가 실행 tenant ID를 지정하지 않아 스크립트 생성만 완료했다.
- 실제 데이터베이스에서 행 수, 공통코드 활성 상태, ID 카운터 시작값, SQL 적용 성공 여부는 확인하지 않았다.
- SQL은 psql 메타 명령을 포함하므로 psql로 실행해야 한다. 현재 산출물은 수동 실행용이며, 이 결과 문서는 실제 데이터 반영을 뜻하지 않는다.
