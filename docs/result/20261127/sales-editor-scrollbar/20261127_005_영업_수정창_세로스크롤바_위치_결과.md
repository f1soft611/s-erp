## 원인

수정 창 본문(`DialogContent`)이 좌우 24px·상하 16px 여백을 갖고, 실제 세로 스크롤은 그 안의 등록 화면 영역(`overflowY: auto`)에서 일어나 스크롤바가 창 끝에서 약 25px 안쪽에 생겼다.

## 변경

| 파일 | 내용 |
| --- | --- |
| `shared/components/commonDialogLayout.ts`(신규) | `COMMON_DIALOG_BODY_PADDING = { px: { xs: 2, sm: 3 }, py: 2 }` — 대화상자 본문 기본 여백(컴포넌트 파일 밖에 두어 Fast Refresh 경고 회피) |
| `shared/components/CommonDialog.tsx` | `disableBodyGutters?: boolean` 추가. true면 본문 여백 0, 기본값은 기존과 같은 값 |
| `QuotationCreatePage`, `SalesOrderCreatePage`, `SalesDeliveryCreatePage`, `SalesStatementCreatePage` | 스크롤 영역 여백: embedded면 `COMMON_DIALOG_BODY_PADDING`(기존 0), 메뉴 화면은 `px/pt/pb: 2` 유지 |
| `QuotationEditorDialog`, `SalesOrderEditorDialog`, `DeliveryEditorDialog`, `StatementEditorDialog` | `disableBodyGutters` 지정 |
| `SalesDeliveryPlanStatusPage` | 수정 창 `disableBodyGutters`, 내부 스크롤 상자에 `COMMON_DIALOG_BODY_PADDING` |
| `frontend/AGENTS.md` | "embedded 본문 패딩 0" 규칙을 수정 창 스크롤 기준으로 갱신 |
| `tests/quotation-create-page.test.tsx` | 수정 창 본문 여백 0·스크롤 영역 상하 16px(S1), 메뉴 화면 16px 유지(S2) |

- 창 오른쪽 1135와 1px 차이는 창 테두리다. 스크롤바(15px)가 창 오른쪽 끝(1119~1134)에 붙고, 내용 위치는 변경 전과 같다.
- 확인은 수정 창을 열어 좌표만 읽고 저장하지 않고 닫았다(데이터 변경 없음).
- 스크린샷: `screenshots/{quotation,order,delivery,statement,deliveryplan}-before.png`, `*-after.png`, `{delivery,statement,deliveryplan}-after-h650.png`, `quotation-after-375.png`

### 자동화

- 신규 테스트 S1은 구현 전 실패(본문 상단 여백 16px)를 확인했고 구현 후 통과. S2는 회귀 방지용으로 전후 통과.
- 좌우 여백은 MUI 반응형 값이 `xs`도 미디어 쿼리로 출력되어 jsdom에서 계산되지 않으므로 브라우저 측정으로 확인했다.
- `npm run test:ci` 영업·대화상자 관련 44개 파일 452건 통과, `npx tsc -b`, `npm run build`, `oxlint`(변경 파일 경고 없음) 통과.
- `CommonDialog` 사용처 60곳은 새 옵션을 쓰지 않아 기존과 같은 여백 값으로 렌더링된다.
