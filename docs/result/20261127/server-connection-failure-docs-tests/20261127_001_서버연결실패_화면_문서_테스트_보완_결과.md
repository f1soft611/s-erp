## 변경 내용

운영 코드·API·DB 변경은 없다. 문서 4종과 테스트만 추가·변경했다.

| 파일 | 내용 |
| --- | --- |
| `frontend/tests/page-load-boundary.test.tsx` | `toPageLoadError` 5종 분류, `isApiNetworkError`, `networkOnly`(500·401·403은 null, network는 표시), `SalesDecimalPolicyError`의 `network` 숨김 — 11건 추가 |
| `frontend/tests/grid-decimal-policy.test.tsx` | 정책 조회 실패 시 연결 실패면 `network: true`, 500이면 false — 2건 추가 |
| `frontend/tests/sales-page-network-failure.test.tsx` (신규) | 영업 10개 화면에서 연결 실패 시 오류 화면 1개·헤더 유지·다른 오류 문구 없음·그리드 없음·다시 시도 시 재조회, 납품처관리 500 오류는 화면 내 메시지 유지 — 11건 |

화면 테스트는 실제 앱(`DashboardPage`)과 같게 `GridDecimalModuleProvider`와 데이터 라우터 안에서 렌더링한다. 처음에 `DashboardContent`만 렌더링했을 때 등록 화면은 `useBlocker` 오류로 실패했고, 출하계획등록은 정책 Provider가 없어 정책 조회가 일어나지 않아 오류 화면이 나오지 않았다.

## 변형 확인 (V9)

운영 코드를 일시로 바꿔 테스트 실패를 확인하고 `git checkout`으로 원복했다(원복 후 `git status` 변경 없음).

| 변형 | 실패한 테스트 |
| --- | --- |
| `useInitialLoadState`의 `networkOnly` 분기 제거 | 4건 — `networkOnly` 단위 3건, 납품처관리 500 화면 1건 |
| `SalesDecimalPolicyError`가 `network`를 무시 | 1건 — 단위 테스트 |
| `usePolicyDecimalStatus`의 `network`를 항상 false | 2건 — 정책 단위 1건, 출하계획등록 화면 1건 |

`SalesDecimalPolicyError`의 `network` 숨김은 화면 테스트에서는 드러나지 않는다. 모든 적용 화면에서 이 안내가 `PageLoadBoundary` 안에 있어, 오류 화면이 뜨면 함께 가려지기 때문이다. 경계 밖으로 옮겨지는 경우를 대비한 방어 코드로 보고 단위 테스트로만 고정했다.
