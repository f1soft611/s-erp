## 검증

### 자동화

- 신규 수정 창 테스트는 구현 전 실패를 확인했다(견적 저장·삭제 토스트 2건 실패, 저장 실패 1건은 원래 통과. 출하계획 실패 위치 테스트는 오류가 3곳에 표시되어 실패 → 수정 후 통과. 레이아웃 단언도 수정 전 실패 확인).
- `npm run test:ci` 영업·초기 오류·정책 관련 42개 파일 434건 통과(레이아웃 수정 후 출하계획 파일 38건 재통과)
- `npx tsc -b`, `npm run build`, `oxlint`(변경 파일, `showSuccess` 의존성 경고 0) 통과

### 로컬 브라우저(8080 개발 서버·개발 DB, 사용자 로그인)

| 확인 | 결과 | 스크린샷 |
| --- | --- | --- |
| 견적 수정 창 저장 → 창 닫힘 + 토스트 "견적이 수정되었습니다. 견적번호: QT-20261125-0001" | 통과 | `quotation-toast-3-saved.png` |
| 수주 수정 창 저장 → 창 닫힘 + 토스트 | 통과 | `order-toast-3-saved.png` |

| 출하계획 수정 창 오류 영역 폭·여백 | 기본정보 패널과 좌우 경계 일치, 상단 위치·간격이 다른 수정 창과 같음 | `deliveryplan-fail.png` |

- 성공 확인에 쓴 비고는 원래 값(`decimal policy verification 20261125`)으로 되돌렸다. 두 문서의 `updated_at`은 바뀌었다.
- 확인 중 Vite 개발 서버가 일괄 편집 도중의 변환본을 계속 제공해 출하계획현황이 `notice is not defined`로 멈춘 적이 있다. 소스에는 참조가 없었고(`tsc` 통과) 파일을 다시 저장하자 정상이었다. 코드 결함이 아니라 개발 서버 감시 누락으로 판단한다.

## 남은 사항

- **수정 창 저장 후 조용한 로딩**(사용자 피드백): 거래명세서현황(`useSalesStatementStatus.saved/deleted` → `setLoading(true)`)과 출하계획현황(저장 중·저장 후 `runSearch`가 페이지 `loading` 사용)은 목록 로딩 표시가 나타난다. 견적·수주·출하현황은 조용한 갱신이 적용되어 있다. 별도 작업 [20261127_004]로 진행한다.
- 거래명세서 삭제는 성공 문구가 원래 없다(메뉴 화면 포함). 문구 추가 여부는 결정이 필요하다.
- 구매자재·품질 현황 수정 창도 같은 구조다. 각 모듈 담당 작업에서 이 규칙을 적용한다.
