# 20261118_009 단가등록 거래처 기준 탭 결과

관련: [작업지시서](../../../directions/20261118/20261118_009_단가등록_거래처기준탭_작업지시서.md) · [계획서](../../../plan/20261118/20261118_009_단가등록_거래처기준탭_계획서.md) · [상세사양서](../../../spec/20261118/20261118_009_단가등록_거래처기준탭_상세사양서.md) · 선행 [007](../item-partner-price-history-vat-foreign/20261118_007_단가등록_이력부가세외화_결과.md), [008](../item-price-overview-tree/20261118_008_단가등록_품목기준트리화면_결과.md)

## 변경 내용
- **백엔드**: `GET /api/v1/co/master/item-partner-prices/customer-overview` 추가 — 사용 중 거래처(코드순, 2,000건 초과 시 400)와 거래처별 등록 건수(기준일에 적용 중·예정인 품목+구분 수, 기본단가 제외), 조건은 검색어(코드·명·사업자번호), 등록 여부(전체/등록/미등록), 기준일. 단가 목록 API에 `customerId` 조건과 응답 `materialSpec` 추가. DB 변경 없음.
- **프론트**: 탭이 "품목 기준 · 거래처 기준 · 단가 이력 조회"가 되었다. 거래처 기준 탭은 좌측 거래처 목록(No·거래처코드·거래처명·사업자번호·등록 건수, 행 클릭 선택)과 우측 선택 거래처의 단가 그리드(No·거래구분·품목 선택·규격·원화단가·부가세·외화단가·통화·…, 필수 표시 *, 상세 폼)로 구성한다. 768px 미만에서는 위아래로 쌓는다. 조회조건: 거래처 통합검색, 단가 등록 여부, 단가 이력(현재·예정만/이력 포함).
- **저장**: 기존 `save-batch`를 재사용한다. 한 행 = 품목+구분으로 008과 같은 규칙(값만 변경=정정, 더 늦은 적용일=새 기간, 예정=수정, 과거 잠금, 앞당기기 오류)을 `itemPriceCustomerChanges.ts`에서 변환한다. 거래처/탭 이동 시 저장하지 않은 변경 확인.
- **엑셀**: 007 양식(거래처코드 포함) 다운로드·업로드를 이 탭에 연결했다. 신규 단가만 추가하고 오류가 있으면 전체 미반영하며, 검증 후 "저장" → 확인 창 → 바로 저장·재조회한다(그리드에 추가하지 않음).
- 거래처가 고정되므로 우측 그리드는 거래처 컬럼과 중복되는 품목 코드·명 컬럼을 숨기고, 종료일은 읽기 전용으로 한다.

## 사양과 달라진 점
- 엑셀 양식은 007 양식 그대로이며 헤더는 "단가"(원화단가)다. 선택 거래처 고정 양식은 후속(사양 6절 결정).

## 검증
- 백엔드: 거래처 목록(필터·기준일·상한), 단가 목록 `customerId` 조건, Mapper, 컨트롤러 테스트와 007·008 테스트 전체 통과.
- 프론트: 변경 집합 변환·서비스 8건, 탭 라우팅·거래처 선택→단가 조회 포함 단가 관련 9개 파일 52건 통과, `tsc`·`oxlint` 통과.
- 실서버·실브라우저(Playwright): 거래처 105건(등록 1/미등록 104), 필터 400 처리, 거래처 선택→우측 단가(에프투소프트 5~6건) 표시, 셀 정정 저장, 엑셀 양식 다운로드→작성→업로드→검증→저장→재조회 통과. 1700/768/375px 가로 넘침 없음. 스크린샷: [screenshots](screenshots/) (`customer-desktop/tablet/mobile`, `customer-selected`, `excel-validated`, `customer-excel-saved`).
- 확인 중 발견해 고친 것: 저장 후 거래처 목록을 다시 불러오면 그리드가 새로 그려지며 빈 선택 이벤트가 발생해 "저장하지 않은 변경사항" 확인 창이 뜨고 선택이 풀렸다. 목록이 다시 그려질 때의 빈 선택은 무시하도록 했다. 또 "등록 건수" 컬럼이 좌측 패널 폭 때문에 가려져 컬럼·패널 폭을 조정했다.
- 테스트 중 생긴 데이터(삭제 기능 없음): 거래처 213231(에프투소프트)의 매입 단가 정정 값, 매출 단가 몇 건(엑셀 업로드 시험용 품목). 필요하면 이력 조회 탭에서 확인하고 사용여부로 정리한다.

## 2차 수정(2026-11-18, 사용자 피드백): 조회조건 통일·거래처 컬럼 정리
- **거래처 기준 우측 그리드에 거래처 선택·코드·명이 보이던 문제**: 이력 조회 탭과 그리드 `storageKey`(저장된 컬럼 설정)를 공유해, 이전에 저장된 컬럼 표시 설정이 복원된 것이 원인이었다. 탭마다 키를 분리했다(거래처 기준 `co-master-item-price-by-customer-v1`, 이력 조회 `co-master-item-price-history-v1`, 편집 그리드 `…-grid-v2`). 거래처 기준 우측은 거래처 컬럼 없이 No·거래구분·품목 선택·규격·원화단가·…만 보인다.
- **조회조건 통일**: 세 탭이 같은 정의(`data/priceSearchFields.ts`)를 쓴다. 통합검색 + 상세검색의 "선택" 그룹(같은 크기·순서·라벨)만 사용한다 — 품목 기준: 단가 상태 / 거래처 기준: 단가 등록 여부·단가 이력 / 단가 이력 조회: 거래구분·사용여부·단가 이력. 라벨은 "단가 상태·단가 등록 여부·거래구분·사용여부·단가 이력"이고 기본값이 있는 필드는 빈 "전체" 선택지를 숨긴다.
- **제거한 조건**: "적용 기준일". 공통 상세검색의 날짜 필드는 항상 시작일~종료일 범위로 그려지는데 화면 코드는 단일 날짜 문자열만 읽어서 값이 서버에 전달되지 않던 버그였다(선택해도 적용되지 않음). 기준일은 서버 날짜(기본 오늘)를 쓴다.
- 검증: 단가 관련 프론트 테스트(조회조건 정의 테스트 추가) 통과, `tsc`·`oxlint` 통과, 실브라우저에서 세 탭 상세검색 라벨 확인과 우측 그리드 거래처 컬럼 비표시 확인(스크린샷 `search-overview/customer/history`, `customer-right-grid`).

## 후속
- 기준정보 모듈 소수점 정책 연결(현재 이 화면은 2자리 고정), 단가 노출 권한 분리, 선택 거래처 고정 엑셀 양식은 범위 밖이다.
