# 20261118_002~004 발주 수정 잠금 · 출력 후 변경 경고 · 등록화면 메시지 정리 결과

관련 문서: 002 [작업지시서](../../../directions/20261118/20261118_002_발주수정_가입고행_잠금_작업지시서.md)·[계획서](../../../plan/20261118/20261118_002_발주수정_가입고행_잠금_계획서.md)·[사양서](../../../spec/20261118/20261118_002_발주수정_가입고행_잠금_상세사양서.md) / 003 [작업지시서](../../../directions/20261118/20261118_003_발주수정_출력후_변경경고_작업지시서.md)·[계획서](../../../plan/20261118/20261118_003_발주수정_출력후_변경경고_계획서.md)·[사양서](../../../spec/20261118/20261118_003_발주수정_출력후_변경경고_상세사양서.md) / 004 [작업지시서](../../../directions/20261118/20261118_004_구매자재_등록화면_메시지정리_작업지시서.md)·[계획서](../../../plan/20261118/20261118_004_구매자재_등록화면_메시지정리_계획서.md)·[사양서](../../../spec/20261118/20261118_004_구매자재_등록화면_메시지정리_상세사양서.md)

## 점검 결과(뒷단계가 있으면 앞단계 수정을 막는 규칙)
구매요청(확정되면 수정·삭제 불가), 구매확정(발주되면 취소 불가), 가입고(입고·검사 행 잠금), 수입검사(입고된 합격분 제한), 입고(매입마감 행 수정·취소 불가)는 이미 적용되어 있었고 **발주(가입고 진행 중)만 빠져 있었다.**

## 변경 내용
- **002 발주 수정 잠금**: 가입고가 있는 행은 수량·단가·납기·창고·검사대상·세액을 바꿀 수 없고 삭제할 수 없다(서버 409). 가입고가 하나라도 있으면 발주일·부가세 설정도 바꿀 수 없고 비고만 수정할 수 있다. 가입고가 없는 행·발주는 그대로 수정된다. 발주 상세 응답에 행별 `arrivedQty` 추가, 화면은 해당 행·헤더를 잠그고 안내(가입고 수량 컬럼 포함), 가입고 행 빼기는 거부 메시지.
- **003 출력 후 경고**: 출력된 발주를 수정하면 수정 창 상단 경고와 저장 직전 확인창. 막지 않고 출력 표시는 유지한다. 입고대기마감 저장은 해당 없음.
- **004 메시지 정리**: 공통 훅 `usePageMessages`로 구매요청·구매요청확정·발주·가입고·입고·수입검사 등록 화면(수정 창 포함)의 검증·오류·경고·성공 메시지를 통일. 값 수정·동작 시작 시 모두 비우고 상태 안내(취소됨·확정과 다름·출력됨·잠금 안내)는 유지. 그리드 재구성 직후의 빈 변경 콜백은 성공 메시지를 지우지 않는다.

## 검증(묶음 마무리 시 일괄)
- 백엔드 전체 1291건, 오류 1(기존 `MinioStorageConfigTest`), 스킵 3. 신규·수정: 가입고 행 값 변경 거부, 헤더 잠금, 허용 범위, 상세 `arrivedQty`, 잠금 조회 쿼리 컬럼.
- 프론트 관련 파일 단위 테스트·`tsc` 통과, 훅 단위 테스트, 발주·가입고·입고 수정 창 메시지 지우기 회귀 테스트. 린트는 기준선과 같은 기존 경고 7건뿐.
- **실서버 확인 중 결함 발견·수정**: 헤더를 바꾸지 않아도 가입고가 있는 발주는 항상 헤더 잠금 409가 났다. 잠금 조회 쿼리(`selectOrderForUpdate`)가 발주일을 읽지 않아 비교가 항상 달랐기 때문이며, 쿼리에 `order_dt`를 추가하고 회귀 테스트를 더했다. (단위 테스트의 가짜 데이터가 발주일을 채워 줘서 가려졌던 결함.)
- 실서버(PO-20261113-0002: 가입고 있음·출력됨): 수량·단가·납기 변경, 발주일·부가세구분 변경, 가입고 행 삭제 모두 409와 안내 문구 확인. 브라우저(1600·768px): 헤더 잠금, 잠금·출력 안내, 가입고 행 빼기 오류 → 비고를 고치면 오류가 사라지고 상태 안내는 유지, 저장 시 출력 확인창(취소), 가로 스크롤·페이지 오류 없음. 스크린샷: [screenshots](screenshots/)

## 한계
- 가입고 취소 후 잠금이 풀리는 흐름과 가입고가 없는 발주의 실제 저장(데이터 변경)은 실서버에서 따로 저장하지 않았다(단위 테스트로 확인).
- 입고대기마감 저장·발주 취소 규칙은 변경하지 않았다.
- 구매요청·확정·가입고·입고·수입검사 화면의 메시지 정리는 단위 테스트(훅, 발주·가입고·입고 수정 창)로 확인했고 모든 화면을 실서버에서 눌러 보지는 않았다.
