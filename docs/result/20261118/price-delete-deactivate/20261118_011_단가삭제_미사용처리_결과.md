# 20261118_011 단가 삭제·미사용 처리 결과

관련: [작업지시서](../../../directions/20261118/20261118_011_단가삭제_미사용처리_작업지시서.md) · [계획서](../../../plan/20261118/20261118_011_단가삭제_미사용처리_계획서.md) · [상세사양서](../../../spec/20261118/20261118_011_단가삭제_미사용처리_상세사양서.md)

## 변경 내용
- **서버**: 기존 `save-batch`의 `deletedRows`로 삭제를 받는다(처리 순서 삭제 → 수정 → 신규, 한 트랜잭션). 종료된 과거 단가는 409, 적용 중·예정 단가는 물리 삭제하고, 삭제 행이 자동 종료시켰던 직전 사용 단가의 종료일을 삭제 행의 종료일(없으면 NULL)로 다시 연다. 미사용(`use_at = N`) 행을 지울 때는 직전 단가를 건드리지 않는다. 같은 ID를 수정·삭제하거나 삭제 ID가 중복되면 400.
- **품목 기준 탭**: "단가 삭제" 액션(관리자 + 삭제 권한, 저장하지 않은 변경이 있으면 비활성)과 확인 창 — 매입·매출 구분 선택(단가가 없는 구분은 비활성), 처리 방식 삭제(오등록 정정) / 미사용 처리(이력 유지). 삭제는 `deletedRows`, 미사용은 같은 값으로 `useAt = N` 수정.
- **거래처 기준 탭**: 그리드 행 삭제(컨텍스트 메뉴, 삭제 권한)를 켜고 저장된 행만 서버로 보낸다(저장 전 신규 행은 화면에서만 제거, 과거 행은 오류 안내). 조회는 사용 중 단가만 불러오므로 사용여부를 N으로 바꾸면 다음 조회에서 목록에서 빠진다.

## 검증
- 백엔드: 삭제 서비스(적용 중 삭제와 직전 행 재개방 순서·종료일 승계, 예정 삭제, 직전 행 없음·미사용 행 삭제 시 재개방 생략, 과거 409, 입력 검증), 배치(삭제 → 수정 → 신규 순서, 삭제만 요청, 수정·삭제 중복/삭제 ID 중복 400), Mapper SQL 테스트 통과.
- 프론트: 품목 기준 삭제/미사용 변경 집합, 거래처 기준 삭제 행 변환(신규 행 제외·과거 행 오류), 삭제 확인 창 테스트 통과, `tsc`·`oxlint` 통과.
- **실서버 API**: 기본단가에 내일부터 적용되는 새 기간을 등록하면 오늘 행이 오늘 종료로 닫히고, 새 행을 삭제하면 직전 행의 종료일이 NULL로 다시 열린다. 종료된 과거 단가 삭제는 409 "종료된 과거 단가는 삭제할 수 없습니다.", 미사용 처리(수정) 후 구매 단가 조회에서 제외된다. 단가 목록 API는 사용여부 N 행도 반환하므로 화면별로 사용 중만 조회한다.
- **실브라우저**: 품목 기준 탭에서 특별단가 행을 선택해 "단가 삭제" → 미사용 처리하면 해당 단가가 사용여부 N이 되어 목록에서 빠지고, 기본단가 행을 선택해 삭제하면 서버에서 삭제된다. 거래처 기준 탭에서 거래처를 선택하고 행 우클릭 "행 삭제" 후 저장하면 서버에서 삭제된다(스크린샷 `remove-dialog`, `after-deactivate`, `after-delete`, `customer-context-menu`, `customer-after-delete`).

## 후속
- 정정 이력 감사 로그는 범위 밖이다.
- 예정 단가의 거래처·품목 변경은 삭제 후 재등록으로 안내한다(서버는 예정 행의 키 수정을 계속 허용).

- 품목 기준 탭 삭제/미사용 확인 창, 거래처 기준 탭 행 삭제 지원
