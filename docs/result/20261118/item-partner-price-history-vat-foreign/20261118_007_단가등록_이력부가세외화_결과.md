# 20261118_007 단가등록 이력·부가세·외화·기본단가 개선 결과

관련: [작업지시서](../../../directions/20261118/20261118_007_단가등록_이력부가세외화_작업지시서.md) · [계획서](../../../plan/20261118/20261118_007_단가등록_이력부가세외화_계획서.md) · [상세사양서](../../../spec/20261118/20261118_007_단가등록_이력부가세외화_상세사양서.md) · [DB 변경 이력](../../../database/20261118/20261118_001_change_item_partner_price_history_vat_foreign.md)

## 확인 결과
- MES 구매단가(WCO315) SP를 확인했다: 현재 단가 `TCO408`(품목+거래처당 1행)과 이력 `TCO410`을 따로 두고, 부가세구분·부가세포함·원화/외화단가·외화통화·적용일·처리자를 관리한다. 겹침 방지·종료일 자동 마감은 없다.
- 사용자 결정: 부가세구분·포함·통화는 공통코드 연결, 외화단가는 원화단가와 별도 컬럼, 환율은 단가 화면에서 계산하지 않음, 외주가공·기본 거래처 체크·발주구분·단가단위 제외, 단위는 품목 마스터 값을 보여 주기만 함, 매입·매출은 한 화면에서 관리.
- 기본 거래처 체크는 "품목만 맞고 거래처가 없을 때 쓸 단가"였다. 거래처가 비어 있는 행을 **품목 기본단가**로 두어 대체했다(모든 거래처를 등록하지 않아도 됨).
- DB 현재 구조(MCP): 컬럼·유니크 인덱스를 확인했고 데이터는 `KRW` 5건·`USD` 1건. 공통코드 항목 조회는 MCP 쿼리 실패로 직접 확인하지 못했고, 기존 발주 시드(`20261113_001`: `TAXABLE`/`ZERO_RATED`/`EXEMPT`)를 근거로 했다. `CURRENCY` 그룹 항목 코드는 미확인이라 서버가 공통코드 존재 여부로 검증한다.

## 변경 내용
- **DB** `20261118_001`: `customer_id` NULL 허용, `tax_type`·`vat_included_at`·`foreign_unit_price` 추가, `currency` 선택화(KRW→NULL, 외화 행은 단가를 외화단가로 복사), 기본단가 부분 유니크 인덱스. 롤백·변경 이력·`db-schema.md` 갱신.
- **백엔드**: 저장 규칙(외화단가↔통화, 공통코드 검증, 기간 겹침 거부, 직전 종료일 없는 행 자동 종료), 종료된 과거 행 수정 409, 적용 중 행의 시작일·품목·거래처·거래구분 변경 409, 목록 `includeHistory`(기본 현재·예정만)와 적용상태(`priceStatus`)·품목 단위 응답, 엑셀 검증(거래처 비움=기본단가, 부가세·외화 항목), 일괄 저장은 수정 먼저·신규는 적용일 순.
- **단가 조회**: 구매확정 `selectDefaultUnitPrice`가 거래처 일치 단가를 먼저, 없으면 기본단가를 쓴다. 단가는 원화단가이므로 통화를 비워 서비스가 `KRW`로 보정한다.
- **프론트**: 컬럼(원화단가·부가세구분·부가세포함·외화단가·통화·단위·적용상태), 거래처 선택 창에 "기본단가(거래처 공통)" 항목, 조회조건 "이력"(현재·예정만/이력 포함), 과거 행·적용 중 행 키 잠금, 엑셀 양식·업로드(12열, 부가세구분·통화는 이름 또는 코드), 메뉴 설명에 기본단가 안내 추가, 수량·단가 컬럼 고정 소수점 제거(정책 따름). 그리드 저장키 `co-master-item-partner-price-grid-v2`.

## 사양과 달라진 점
- 물리 삭제는 기존 규칙(사용여부로 비활성화)을 유지했다. 사양의 "현재 행 삭제 허용"은 적용하지 않았다.
- 엑셀은 신규 행 추가만 지원하며(기존 단가 수정·업서트 없음) 기존 단가가 있는 키는 검증에서 막는다.

## 검증
- 백엔드: `ItemPartnerPrice*Test`(서비스·배치·컨트롤러·Mapper)와 `PurchaseRequestConfirm*Test` 통과.
- 프론트: 단가 관련 4개 테스트 파일 21건 통과, `tsc` 통과, `oxlint` 경고 없음.
- **실서버**: DB 스크립트 적용(컬럼·기본단가 부분 유니크 인덱스, `KRW`→NULL 정리) 확인. 기본단가 저장, 새 기간 등록 시 직전 단가 자동 종료, 기간 겹침 400, 과거 단가 수정 409, 적용 중 단가 시작일 변경 409, 목록 기본/이력 포함 조회가 의도대로 동작했다. 상세는 [008 결과](../item-price-overview-tree/20261118_008_단가등록_품목기준트리화면_결과.md)의 실서버·실브라우저 항목과 같은 점검이다.
- **미확인**: "단가 목록(이력)" 탭의 엑셀 양식 다운로드→업로드 왕복(신규 12열 양식)은 브라우저로 직접 조작하지 않았다(양식·파서는 단위 테스트로만 확인, 목록 탭 화면 스크린샷은 008 결과 폴더에 있음).

## 후속·주의
- 적용 시 `USD` 1건은 원화단가를 검토해야 한다(원화 환산값을 알 수 없어 단가는 그대로 둠).
- 구매확정·발주는 원화단가만 쓴다. 외화단가를 발주 통화로 연동하는 것은 후속이다.
- 단가 노출 권한 분리, 환율 연동은 이번 범위 밖이다.
- 영업 코드에서 이 테이블을 쓰는 곳은 없음을 확인했다(구매확정·단가등록 Mapper만 사용).
