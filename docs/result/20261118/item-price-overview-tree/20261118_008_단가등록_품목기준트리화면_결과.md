# 20261118_008 단가등록 품목 기준 트리 화면 결과

## 변경 내용
- **백엔드** `GET /api/v1/co/master/item-partner-prices/overview`: 사용 중인 품목을 코드순으로 모두 내려주고(2,000건 초과 시 400 "검색 조건을 좁혀 주세요"), 부모(품목+매입·매출 기본단가)와 자식(거래처 특별단가)을 평면 목록 + `parentId`로 구성한다. 기준 행은 기준일에 적용 중인 단가를 우선하고 없으면 가장 빠른 예정 단가. 조건: 검색어, 단가 상태(전체/매입 기본단가 미등록/매출 기본단가 미등록/특별단가 있는 품목), 기준일. 신규 서비스·VO·Mapper(`selectOverviewMaterials`, `selectOverviewPrices`). DB 변경 없음.
- **저장**: 기존 `save-batch`를 재사용한다. 화면이 변경 집합을 만들고(`itemPriceOverviewChanges.ts`) 서버가 겹침·자동 종료·과거 잠금을 검증한다.
  - 단가 없던 칸에 입력 → 신규(적용일 비우면 서버 오늘).
  - 적용일 그대로 값만 변경 → 정정(종료일·MOQ 유지).
  - 현재 단가의 적용일을 더 늦게 → 새 기간(MOQ 승계). 앞당기기·단가 지우기는 오류. 예정 단가는 적용일 이동도 수정.
  - 외화단가는 통화 필수, 단가를 입력하면 비어 있는 적용일을 서버 오늘로 채움.
- **프론트**: 메뉴 안에 탭 "품목 기준"(기본) · "단가 목록(이력)"(007 평면 그리드 그대로). 품목 기준은 `F1Tree`로 품목 부모 행 + 거래처 특별단가 자식 행(기본 접힘, "특별 N건"), 매입·매출 각각 원화단가·부가세구분·부가세포함·외화단가·통화·적용일 컬럼, "특별단가 추가"(부모/자식 선택 후 거래처 선택 창), 조회조건(단가 상태·적용 기준일), 탭 전환 시 저장하지 않은 변경 확인. 기존 단가 화면은 `ItemPartnerPriceListPage`로 이름을 바꾸고 탭 호스트가 `ItemPartnerPriceManagementPage`가 되었다(DashboardContent 연결은 그대로).
- **엑셀(품목 기준)**: 현재 단가가 채워진 전체 품목 양식 다운로드, 업로드 시 빈 칸·같은 값은 무시하고 오류(없는 품목코드, 중복, 금액·날짜·부가세포함·공통코드·외화-통화)를 엑셀 행 번호로 보여 준 뒤, 오류가 없으면 확인 창을 거쳐 같은 저장 규칙으로 반영한다. 파일 안 품목코드 중복 검사에서 `Set.add`가 불리언이 아니어서 동작하지 않던 버그를 테스트로 찾아 고쳤다.

## 2차 수정(2026-11-18, 사용자 피드백)
- **품목 기준 그리드**: 첫 컬럼에 No 추가, 트리 열 머리글을 "품목 / 거래처"에서 "품목"으로 변경. 거래처 선택·매입/매출 원화단가·적용일 머리글에 필수 표시(*). 모든 빈 행이 검증 오류가 되지 않도록 `required`가 아니라 표시 전용 `requiredMark`를 공통 그리드에 추가해 사용했다(헤더·행 폼 라벨만 표시, 검증 없음, 기존 화면 영향 없음).
- **상세 폼**: 맨 오른쪽 "상세" 아이콘으로 행 폼을 열어 입력한다(품목 정보 읽기 전용, 매입 단가/매출 단가 그룹). 특별단가 추가도 폼 창에서 입력한다.
- **단가 이력 조회 탭(구 "단가 목록(이력)")은 조회 전용**: 단가 추가·저장·엑셀 업로드·양식 다운로드·행 폼과 헤더 필수 표시를 없앴다. 기본은 이력 포함으로 조회하고, 품목·거래처 선택 컬럼은 숨기고 거래처 없는 행은 "기본단가(거래처 공통)"로 표시, 부가세구분은 공통코드 이름으로 보인다.
- 기준정보(`co`) 모듈에는 소수점 정책(`GRID_DECIMAL_*`)이 연결되어 있지 않아(`moduleCode`가 `co`) 007에서 고정 자릿수를 뺀 단가가 소수 없이 보였다. 이 화면의 단가·외화단가·최소주문수량은 다시 2자리로 고정했다(정책 연결은 후속).
- 이 변경으로 007의 단가 목록 신규 행·엑셀 업로드 UI는 화면에서 빠졌다(`ItemPartnerPriceImportDialog`·엑셀 서비스·행 폼 코드는 거래처 기준 탭 재사용을 위해 남겨 둠).
- 검증: 단가 관련 8개 테스트 파일 43건(공통 그리드 `requiredMark` 테스트 포함) 통과, `tsc`·`oxlint` 통과, 실브라우저에서 헤더(No·품목·*), 상세 아이콘→폼 입력→저장, 이력 조회 탭(* 없음·입력 버튼 없음·소수 2자리·공통코드 이름) 확인. 스크린샷: `overview-v2`, `detail-form`, `history-tab`.

## 사양과 달라진 점
- 엑셀에서 적용일이 비어 있는 칸은, 이미 단가가 있으면 기존 적용일(= 정정), 단가가 없던 칸이면 서버 오늘로 처리한다(사양은 "비우면 오늘").
- 부가세·외화 컬럼은 컬럼 설정 지원 여부 확인 대신 모두 기본 표시했다(가로 스크롤, 품목/거래처 열 고정).
- 거래처 선택 창에는 "기본단가(거래처 공통)" 선택 항목을 넣지 않았다(특별단가 행은 항상 거래처가 있다). 자식 행 삭제는 지원하지 않는다.

## 검증
- 백엔드: 품목 기준 서비스(피벗·기준 행·필터·상한), Mapper, 컨트롤러 테스트와 007 테스트 전체 통과.
- 프론트: 변경 집합 변환 12건, 엑셀 양식·업로드 5건, 트리 렌더링 2건, 탭 라우팅·기존 단가 테스트 포함 단가 관련 7개 파일 40건 통과, `tsc`·`oxlint` 통과.
- **실서버(백엔드 재구동 후, DB 스크립트 적용 확인 뒤)**: 목록 기본 4건/이력 포함 6건, 품목 기준 조회(부모 103·자식 3, 특별단가 있는 품목 3건), `priceFilter` 오류값 400. 기본단가 신규 → 새 기간 등록 시 직전 단가 종료일이 전날로 자동 설정, 겹침 400, 과거 단가 수정 409, 적용 중 단가의 시작일 변경 409.
- **실브라우저(Playwright, 4173)**: 품목 기준 탭에서 셀 입력→저장(정정, 적용일 오늘), "특별단가 추가"→거래처 선택 창→단가 입력→저장(부모에 "특별 1건" 표시), 엑셀 양식 다운로드(14열)→단가 수정→업로드→확인 창→반영까지 통과. 1600/768/375px에서 가로 넘침 없음. 스크린샷은 [screenshots](screenshots/)에 있다(`overview-desktop/tablet/mobile`, `overview-expanded`, `child-saved`, `excel-confirm`, `list-tab`).
- 확인 중 발견해 고친 것: 값이 없는 단가·외화단가·최소주문수량이 그리드 숫자 서식 때문에 "0"으로 보였다. 공통 서식은 건드리지 않고 이 화면의 해당 컬럼만 빈 칸으로 그리도록 했다(`blankWhenEmptyCell.ts`, 값이 있으면 그리드 서식·정책 그대로).
- 테스트 중 생긴 데이터(삭제 기능이 없어 남음): 품목 000001 기본 매입단가(1,111, 11/28부터 1,222), 품목 000002 기본 매입단가와 특별단가 "테스트"(거래처). 필요하면 단가 목록 탭에서 사용여부를 N으로 바꾼다.

## 후속
- 거래처 기준 탭(009), 단가 노출 권한 분리, 외화단가의 발주 통화 연동은 범위 밖이다.
- 품목이 2,000건을 넘는 테넌트는 검색 조건을 좁혀야 한다. 필요하면 서버 페이징으로 확장한다.
