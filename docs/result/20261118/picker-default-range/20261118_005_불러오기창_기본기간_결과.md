# 20261118_005 구매자재·품질 불러오기 창 기본 조회 기간 결과

관련: [작업지시서](../../../directions/20261118/20261118_005_불러오기창_기본기간_작업지시서.md) · [계획서](../../../plan/20261118/20261118_005_불러오기창_기본기간_계획서.md) · [상세사양서](../../../spec/20261118/20261118_005_불러오기창_기본기간_상세사양서.md)

## 변경 내용
- 불러오기 창 6곳(구매요청 선택, 구매요청확정 선택, 확정 품목 선택, 발주 품목 선택, 수입검사 합격분 선택, 검사 대기 가입고 선택)에 기간(시작·종료) 조건을 두고 처음 열 때 서버 날짜 기준 한 달(종료일=오늘, 시작일=한 달 전)로 채워 조회한다. 기준일은 창마다 요청일·확정일·발주일·검사일·가입고일이다.
- 기존 세 창의 브라우저 기본 날짜 입력은 공통 달력으로 바꾸고, 날짜 조건이 없던 세 창은 새로 추가했다.
- 서버 날짜를 못 받으면 브라우저 날짜로 대체하지 않고 기간 없이 조회, 기간을 지우면 전체, 시작일>종료일이면 조회하지 않고 안내.
- 기본 기간은 `PICKER_DEFAULT_RANGE_MONTHS`(1) 한 곳에서 정의해 업체별 기준으로 바꿀 때 한 곳만 고치면 된다.
- 백엔드: 구매요청 후보·확정 목록 API에 `fromDt`/`toDt` 추가(요청일·확정일, 역순은 400). DB 변경 없음.

## 검증
- 백엔드 서비스 테스트(기간 전달, 역순 400), 전체 백엔드 1291건 중 오류 1(기존 `MinioStorageConfigTest`).
- 프론트: 훅 단위 테스트와 6개 창 테스트(기본 기간 표시, 첫 조회 1회에 `fromDt`/`toDt` 포함), 관련 등록 화면 테스트 94건, `tsc` 통과.
- 실서버: 구매요청 후보 10건 → 먼 미래 기간 0건, 확정 목록 25건 → 0건, 역순 기간 400. 브라우저: 6개 창 모두 2026-10-18 ~ 2026-11-18로 채워져 열림. 스크린샷: [screenshots](screenshots/)

## 한계
- 업체별로 기본 기간을 다르게 두는 정책 저장은 하지 않았다(상수만 분리).
- 불러오기 창이 아닌 다른 화면(현황 등)의 기본 기간은 기존 방식(상세검색 기본값)을 따른다.
