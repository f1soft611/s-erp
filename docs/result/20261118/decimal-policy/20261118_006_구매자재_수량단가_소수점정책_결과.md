# 20261118_006 구매자재·품질 수량·단가 소수점 정책 적용 결과

관련: [작업지시서](../../../directions/20261118/20261118_006_구매자재_수량단가_소수점정책_작업지시서.md) · [계획서](../../../plan/20261118/20261118_006_구매자재_수량단가_소수점정책_계획서.md) · [상세사양서](../../../spec/20261118/20261118_006_구매자재_수량단가_소수점정책_상세사양서.md)

## 확인 결과
- 정책은 정상 등록되어 있다: 서버 정책 조회 결과 MATERIALS·QUALITY 모두 2자리·항상 표시(FIXED)·반올림(HALF_UP), SALES는 3자리, COMMON·GROUPWARE·PRODUCTION·SETTINGS도 등록되어 있다. 대시보드가 현재 모듈 코드(`materials`, `quality`)로 정책을 연결한다.
- 구매자재·품질 컬럼 정의에 `decimalPlaces: 2`가 박혀 있어 정책을 바꿔도 이 화면들에는 반영되지 않았다(컬럼 옵션이 정책보다 우선).

## 변경 내용
- 수량·단가 컬럼 약 40곳의 고정 `decimalPlaces: 2`를 제거해 정책이 적용되게 했다(등록 화면, 현황, 불러오기 창, 입고마감, 수입검사).
- 현황 화면의 수량·단가·금액 혼합 도우미를 `quantityColumn`(정책 따름)과 `amountColumn`(금액 2자리 고정)으로 분리했다.
- 금액(공급가·세액·합계·금액), 건수(0자리), 비율(`passRate` 1자리)은 그대로 둔다(사용자 결정: 금액 유지).
- 백엔드·DB 변경 없음.

## 검증
- 구매자재·품질 관련 프론트 테스트 15개 파일 205건 통과, `tsc` 통과.
- 실서버: 발주현황(발주수량 232,323.00 · 발주단가 2,323.00 · 입고잔량 0.00), 수입검사현황(합격량 4.00 · 불합격량 1.00), 입고현황(입고수량 7.00 · 입고단가 1,250.00) 모두 정책(2자리·항상 표시)대로 표시.

## 한계
- 정책 값을 바꿔서(예: 3자리) 화면이 따라 바뀌는지는 운영 정책 데이터를 임의로 바꾸지 않아 확인하지 않았다. F1Grid의 정책 적용 우선순위는 기존 문서·테스트로 보장된다.
- 등록 화면의 입력 셀 편집 중 표시 자릿수와 합계 행 표시는 이번에 별도로 확인하지 않았다.

## 커밋 메시지 예시
```
refactor(materials): 수량·단가 소수점 자릿수를 정책 관리 값으로 통일

- 구매자재·품질 수량·단가 컬럼의 고정 자릿수를 제거해 모듈 소수점 정책 적용
- 현황 컬럼 도우미를 수량·단가용과 금액용으로 분리(금액은 2자리 유지)
```
