## 2. 기준 실패와 원인 분류

두 메뉴관리 테스트 파일의 변경 전 집중 실행은 64개 중 40개 통과·24개 실패다. 전체 저장소 리뷰의 90개 실패와 다른 집계다.

- 역할 목록 mock 누락으로 초기 필수 조회가 실패한다.
- 권한 미선택 시 조회하지 않는 현재 계약과 달리 일부 테스트는 권한 자동선택을 전제한다.
- 과거 신규 행 생성·툴바 변경 건수·고정 컬럼 위치·스켈레톤 식별자에 종속된 단언이 남아 있다.
- 검색어 초기화는 실제 운영 결함도 포함한다. 아래 항목은 테스트만 바꾸지 않고 기존 세션 사양에 맞게 수정했다.

## 3. 검색어 초기화 세션 결함

### 재현과 원인

1. 모듈·권한과 검색어를 저장한 상태로 메뉴관리에 진입한다.
2. 검색어 초기화 버튼을 누른다.
3. 메뉴관리에서 나갔다가 다시 진입하면 이전 검색어가 돌아온다.

입력 시에는 세션 검색어도 갱신하지만 초기화 시에는 화면 상태만 비우고 있었다. 기존 세션 사양은 검색어 변경을 세션에 반영하도록 요구한다.

### 수정과 회귀 검증

- 초기화 핸들러에서 기존 모듈·권한을 유지하며 세션의 검색어도 빈 값으로 변경한다.
- 기존 필수선택 테스트 파일에 초기화 → 세션 값 → 재진입 → 선택 보존을 검증하는 테스트 1개를 추가했다.
- 수정 전에는 저장된 검색어가 비어야 하는 단언에서 실패했고, 수정 후 같은 테스트가 통과했다.
- 테스트 이름으로 집중 실행할 때 표시되는 다른 9개 제외는 이름 선택 실행 결과이며 `skip` 코드를 추가한 것이 아니다.

```powershell
cd frontend
node .\node_modules\vitest\vitest.mjs run tests\menu-management-required-selection.test.tsx --pool=threads --maxWorkers=1 --reporter=default --no-color --testNamePattern="keeps the cleared search"
```

## 4. 실제 브라우저 검증과 스크린샷

Orca의 별도 isolated 프로필과 합성 데이터만 사용했다. 실제 사용자 로그인·인증 세션·테넌트 데이터·DB는 사용하지 않았다. 운영 `MenuManagementPage`를 직접 렌더링하고 페이지 내 요청을 합성 응답으로 제한했다.

각 크기에서 검색어가 있는 세션 준비 → 실제 초기화 버튼 동작 → 컴포넌트 재진입 후 빈 검색어와 원래 모듈·권한 보존을 확인했다. 문서 수준 가로 넘침도 없었다. 그리드 내부 스크롤은 유지한다.

기존 24개 실패를 복구했고 검색어 초기화 회귀 테스트 1개가 추가되어 총 65개다. 기존 성공 40개도 유지한다. 구형 변경 건수 문구 대신 실제 변경 상태와 저장 동작, 고정 컬럼 인덱스 대신 컬럼 식별, 현재 생성 다이얼로그와 로딩 계약을 검증한다. 운영 변경은 검색어 초기화 세션 동기화 4줄뿐이다.

새 검증용 worktree에는 검증을 위해 이번 운영 파일 1개와 테스트 2개를 복사했다. 해당 경로와 원본의 변경 파일이 같은 상태에서 집중 검사와 정적 검사를 실행했으며, 잠금 파일과 기존 공유 설치는 바꾸지 않았다.

## 6. 적용 범위와 남은 검증

- 현재 API·DB·페이지 세션 형식은 변경하지 않았다. DB MCP 확인이나 스키마 변경 대상이 아니다.
- 메뉴관리 집중 복구는 완료했다. 전체 저장소 테스트와 다른 업무의 잔여 실패는 아직 최종 집계하지 않았으므로 전체 통과로 표현하지 않는다.
- 후속 의존성 작업에서도 공유 설치와 새 검증용 worktree를 분리한다. 강제 업데이트나 공유 `npm ci`는 실행하지 않는다.
