## 검증 기준

- 전체 실행은 별도 검증 worktree의 `22bd60b8` 프론트 소스 오버레이와 이번 복구 변경을 고정한 결과다. 검증 worktree의 Git HEAD는 최초 `9a9b0729`에 두었으며 공유 브랜치를 merge/reset하지 않았다.
- 오버레이 99개와 후속 4개 파일의 hash를 확인했고, 이번 작업 소유 운영·테스트·사용 문서 22개도 공유 작업 공간과 검증 입력이 같은지 재확인했다.
- 잠금 설치 Vite 8.3.8 / Vitest 4.1.12를 사용했다. 공유 설치의 Vite 8.2.2 / Vitest 4.1.11은 최종 근거로 사용하지 않았다.
- 검증 중 다른 작업이 공유 HEAD를 `bf6cf0bb`으로 이동했다. 해당 구간의 `PageSearchArea.tsx` backdrop Portal 변경은 고정 전체 실행에 포함하지 않았다. 공유 서버의 실제 브라우저 확인은 별도 증거다.
- 이번 모수는 **226개 파일·2,631개 테스트**다. 최초 리뷰의 211개 파일·2,440개 테스트와 달라 최초 90개 실패에서 단순히 몇 개를 해결했다고 계산하지 않는다.

### 시간 제한 초과 9개

전체 실행 직후 동일 코드·동일 기본 시간 제한으로 정확히 위 9개만 다시 실행하면 **9개 전부 통과**했다. 함께 수집된 나머지 201개는 이름 선택으로 실행하지 않았으며 소스 skip을 추가한 것이 아니다.

이는 선택 재실행 결과일 뿐 전체 검사의 9개 실패를 통과로 바꾸는 근거가 아니다. 이어 같은 코드·기본 시간 제한·worker 1개로 관련 두 파일 **전체 210개**를 실행했다.

| 별도 전체 파일 재검증 | 결과 |
|---|---|
| 권한관리 | 53 통과 |
| 문서작성 | 156 통과·1 실패 |
| 합계 | 209 통과·1 실패·제외 0, 370.82초 |

남은 실패는 `renders compact accessible badges, seals, removal actions, and ellipsized names`의 기본 5,000ms 제한 초과다. 이 사례는 최초 전체 실행에서 5,998ms로 실패하고, 9개 선택 실행에서는 2,599ms로 통과하고, 두 파일 전체 실행에서는 5,591ms로 실패했다. 실행 범위·누적 상태·부하의 영향을 의심할 수 있지만 정확한 원인을 확정하지 않았다. 성공할 때까지 반복 실행하거나 시간 제한을 상향하지 않았다.

기존 `document-write-page.test.tsx:5562`에는 `mockResolvedValue`의 두 번째 인수로 `15000`이 전달된다. 설치된 mock API는 반환값 인수 하나만 받으므로 이 숫자는 테스트 시간 설정이 아니며 실제 실행에도 기본 5초가 적용된다. 이 호출은 변경하지 않았다. `npm run typecheck`는 `src`와 `vite.config.ts`만 검사하므로 테스트 파일까지 타입 검사를 통과했다는 근거도 아니다.

따라서 두 파일 재검증을 전체 2,631개 통과로 대체하지 않으며, 문서작성의 장시간 사례와 테스트 타입 검증 범위는 잔여 확인 사항이다.

## 후속 단계

- 테스트 복구의 전체 안정성은 아직 확보되지 않았다.
- 남은 트리 계층 정책과 문서작성 장시간 테스트의 원인을 먼저 정리해야 한다. 기존 화면을 보호하기 위해 트리 기능을 강제로 켜거나 테스트 시간 설정만 늘려 통과시키지 않았다.
- 빠른 날짜 요청 경합 수정, 의존성 업데이트, PR #76·CI 후속 조치는 진행하지 않았다. 기존 화면 영향 확인을 우선하고 변경 범위를 더 넓히지 않았다.
- 공유 HEAD의 별도 backdrop 변경은 빠른 날짜 비동기 경합의 해결 근거가 아니다.
- DB·API 데이터 계약 변경이 없어 DB MCP·SQL 생성 대상은 아니다. 공유 서버·설치와 다른 작업의 파일을 보존했다.
