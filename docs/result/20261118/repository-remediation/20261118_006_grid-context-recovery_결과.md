## 확정 수정

가상 행 삽입 테스트는 `rowHeight={32}`를 표시 배율 적용 후에도 32px로 가정했다. 실제 28.8px 행에 32px 기준 scrollTop/clientHeight를 주어 선택 행이 의도한 viewport 아래 끝에 있지 않았다.

렌더링된 행 높이 조절기의 `aria-valuenow`로 실제 표시 높이를 읽고 scrollTop/clientHeight/scrollHeight를 같은 기준으로 설정했다. 아래 삽입 후 스크롤 증가·신규 행 렌더링·포커스 단언을 보존했다. 운영 코드는 변경하지 않았다.

## 보류한 위험한 공개 변경

기존 트리 정렬/필터 회귀 2개는 F1Tree가 두 기능을 강제로 비활성화해서 실패한다. 20260909 사양 및 과거 사용 문서와 달리, `d9f27102`의 엔진 변경에서 강제 비활성화가 재도입됐다.

두 속성만 제거한 후보는 평면 root fixture의 기존 회귀를 통과시켰지만 안전한 해결이 아니었다. 현재 F1Grid는 계층 투영 이후 일반 query를 적용한다. 격리 worktree에서 **부모 Zulu / 자식 Alpha**를 오름차순 정렬하자 **자식 Alpha / 부모 Zulu**로 뒤집혔다.

따라서 후보를 철회하고 공유 작업 공간과 검증 worktree의 F1Tree를 원본으로 돌려놓았다. 임시 정책 조합 및 계층 probe 테스트는 제거했다. 기존 실패 2개는 유지하며 skip이나 단언 변경으로 감추지 않는다.

계층 인지 정렬/필터를 구현하려면 형제 정렬, 조상 표시/필터 일치, 펼침/접기, 사용자 지정 순서의 우선순위를 먼저 확정해야 한다. 이 작업에서 전역 공개 동작을 임의 변경하지 않는다.

## 검증

`22bd60b8` 프론트 소스 오버레이 + 복구 변경, 잠금 Vitest 4.1.12 기준:

| 검증 | 결과 |
|---|---|
| 속성 제거 전 정책 집중 RED | 4 실패 / 1 통과, 나머지는 이름 선택으로 미실행 |
| 속성 제거 후보의 계층 순서 probe | 실패, 자식이 부모보다 먼저 정렬됨 |
| 후보 철회 후 컨텍스트 + F1Tree 전체 | 60 통과 / 기존 정렬·필터 2 실패 |
| 가상 삽입 스크롤·렌더링·포커스 사례 | 통과 |
| 후보 확인 과정의 메뉴관리 2개 파일 | 65 통과 |
| typecheck / 변경 범위 lint | 종료 코드 0, F1Tree의 기존 경고 2개 |

최종 운영 변경이 없어 신규 브라우저 스크린샷·DB MCP·SQL은 해당 없음이다. F1-Grid 사용 문서에 현재 제약과 미해결 사항을 반영했다.

후속 2,631개 전체 실행에서도 동일한 컨텍스트 정렬·필터 2개가 실패했다. 다른 시간 제한 초과 사례와 [종합 검증 결과](20261118_009_repository-remediation-validation_결과.md)에서 구분했다.
