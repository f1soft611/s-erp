# 문서 참여자 표시·조회 비용 개선 결과

## 결과

- 문서작성 156개와 fields-theme 4개: **160/160 통과**, source skip·선택 제외·timeout 변경 없음.
- 실제 DocumentApprovalFields로 옮긴 표시 케이스는 424ms로 통과했다. 표시·접근성·삭제 노출·말줄임 단언은 원본과 문자열 대조해 모두 그대로 보존했음을 확인했다.
- 운영 컴포넌트는 변경하지 않았다. 사용자 선택·추가·삭제·후보 제외 통합 케이스도 유지한다.
- 기존 fields-theme fixture에 현재 필수 callback `onOpenApprovalSettings`를 전달했다.

## 원인 조사와 검증 이력

- 기존 표시 케이스는 전체/파일 실행에서 5,998ms/5,591ms로 실패했다.
- 임시 계측에서는 준비 1,984ms, 결재 추가 완료 3,055ms, 합의 추가 완료 3,971ms, 표시 단언 완료 4,043ms였다. 표시 자체보다 중복 통합 준비가 대부분이었다.
- 표시 케이스 이동 후 첫 160개 실행은 158통과/첨부 케이스 2개 시간 초과였다. 이 실패도 숨기지 않는다.
- 해당 두 케이스 선택 실행은 2,856ms/2,159ms로 통과했다. 공통 준비 role 조회/대기는 458ms/263ms, 같은 공개 라벨 조회는 71ms/74ms로 측정됐다.
- 공통 준비는 같은 기안자 값 조건을 라벨로 확인하고, 해당 첨부 케이스의 입력·버튼·오류 조회는 실제 작성 dialog로 한정했다. 기존 API 호출·오류/성공 단언은 유지했다.
- 변경 후 전체 두 파일 160개가 280.07초에 통과했다. 로그: 세션 산출물 `document-presentation-scoped.log`. 임시 계측은 제거했다.
- 이는 집중 파일 검증이다. 이전 전체 프론트엔드 실행의 11개 실패를 소급해 통과로 바꾸지 않으며 최종 전체 검사는 후속 변경을 반영한 뒤 실행한다.

## 범위와 복사용 커밋 문구

테스트·문서 전용으로 운영/UI 변경과 신규 스크린샷은 해당 없음이다. 커밋은 생성하지 않았다.

```text
test: 문서 참여자 표시 회귀의 중복 준비 비용 제거

- 실제 표시 컴포넌트로 동일 표시·접근성 단언 이동
- 준비 대기 및 첨부 통합 테스트의 DOM 조회 범위 축소
- 사용자 선택 통합 검증과 기본 시간 제한 유지
```
