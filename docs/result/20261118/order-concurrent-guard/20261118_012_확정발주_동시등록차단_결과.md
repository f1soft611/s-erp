# 20261118_012 확정 기준 발주 동시 등록 차단 결과

## 배경
화면 후보에서는 잔량이 없는 확정 행이 빠지지만, 두 화면을 동시에 열고 같은 확정 행을 저장하면 서버가 둘 다 받아 초과 발주가 생길 수 있었다(연결 테스트에서 API 직접 호출로 확인).

## 변경
- 확정 기준 발주 저장(`PurchaseOrderServiceImpl.prepareConfirmRows`): 확정 행을 잠근 뒤 저장 전 발주수량이 확정수량 이상이면 409("발주할 확정 품목이 변경되었습니다. 화면을 다시 조회해 주세요.").
- 잔량이 남은 행에 잔량보다 많이 주문하는 것은 그대로 허용하고 저장 후 `overOrderedLineNos` 경고만 한다(정책 유지).
- 수정(PUT)·직접 발주 경로는 변경 없음.

## 검증
- 단위 테스트: 이미 전량 발주된 행 거부, 부분 발주 행 허용·초과 경고(`PurchaseOrderServiceImplTest`), 발주 관련 테스트 전체 통과.
- 실서버: 전량 발주된 확정 재발주 409, 6/10 부분 발주 후 8 추가 발주 201+경고, 그 뒤 추가 발주 409.
- 연결 흐름(단가→요청→확정→발주→가입고→검사→입고→매입마감→해제) 31개 확인 중 마감 목록 통화 컬럼 부재 1건만 미통과(외화 마감 요구 시 추가하기로 보류).

## 커밋 메시지 예시
```
fix(materials): 이미 전량 발주된 확정 행의 중복 발주 저장 차단

- 확정 행 잠금 후 발주수량이 확정수량 이상이면 409로 거부해 동시 등록 시 초과 발주 방지
- 잔량이 남은 행의 초과 주문은 기존처럼 허용하고 경고만 표시
```
