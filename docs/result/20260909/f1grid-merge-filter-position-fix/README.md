## 재현 원인과 조치

### 병합 마지막 행 경계선

병합 셀은 시작 행의 DOM 노드가 여러 행을 span하지만, 기존 코드는 시작 행 자체가 그리드 마지막 행일 때만 하단 보더를 적용했다. `GridCell.tsx`에 `getGridCellBottomBorder`를 추가해 병합 시작 셀에도 하단 보더를 적용했다. 병합 내부의 숨겨진 셀은 기존처럼 보더를 그리지 않는다.

### 같은 그룹의 이후 행 선택 시 경계선 유지

같은 머지 그룹 안에서 어떤 행이 선택/포커스되든, 실제로는 그 행이 속한 그룹의 시작 행을 기준으로 경계선을 계산해야 한다. `GridRow.tsx`는 이제 편집 중/포커스/선택된 모든 활성 행을 함께 확인해 각 그룹의 시작 인덱스를 다시 계산하고, 해당 시작 셀만 하단 경계선을 유지하도록 조정했다. 이로써 첫 행이 아닌 이후 행을 클릭해도 동일 머지 그룹의 경계가 보인다.

병합 내부 셀을 클릭하면 시각적 포커스를 병합 시작 셀로 정규화한다. 행 선택 ID는 클릭한 실제 행을 유지하지만, 셀 outline은 병합 span 전체를 대표하는 시작 셀에 표시되므로 병합 그룹의 어느 행을 클릭해도 그룹 단위 선택 경계를 확인할 수 있다. 또한 숨은 병합 셀은 실제 그리드 마지막 행이어도 하단선을 생략해 중간 병합 그룹의 경계선이 이중으로 그려지지 않도록 한다.

병합 그룹 활성화는 행 전체 선택 상태가 아니라 현재 포커스/편집 셀의 `columnIndex`까지 확인한다. 따라서 병합된 행에서 수량 등 다른 컬럼을 클릭하면 해당 병합 컬럼의 border가 함께 활성화되지 않는다.

### 컬럼 필터 위치

기존 구현은 부모 컬럼 메뉴의 `필터` 항목을 필터 메뉴 앵커로 저장했다. 부모 메뉴가 닫히면 해당 항목도 제거되므로 MUI가 필터 메뉴를 잘못된 좌표에 표시할 수 있었다. `GridHeader.tsx`는 이제 컬럼 메뉴를 연 헤더 버튼을 별도로 보관하고, 필터 메뉴를 열 때 그 지속되는 버튼을 앵커로 사용한다.

```text
npx vitest run tests/f1-grid.test.tsx -t "row merge|column filter"
```

- 결과: 4 passed, 123 skipped, 0 failed
- 추가 회귀 테스트:
  - 병합 span 시작 셀의 하단 경계선 계산
  - 필터 메뉴의 헤더 메뉴 버튼 앵커 유지

```text
npm run build
```

- 결과: TypeScript 컴파일 및 Vite 프로덕션 빌드 성공
