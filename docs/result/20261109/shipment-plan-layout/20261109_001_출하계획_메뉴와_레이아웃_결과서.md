# 출하계획 메뉴와 레이아웃 결과서

## 결과

- 독립 출하계획 상위 메뉴를 정리하고 출하관리 아래에 계획등록·계획현황을 배치하는 [메뉴 보정 SQL](../../../database/20261109/20261109_001_move_sales_shipment_plan_menus.sql)을 작성했다. 기존 계획 메뉴 ID와 역할 권한을 유지한다.
- 기존 독립 상위 메뉴에 다른 자식, 권한 또는 즐겨찾기가 있거나 메뉴 설정이 충돌하면 SQL은 중단한다. 기존 메뉴 삭제용 `20261105_002_rollback_sales_delivery_plan_menu.sql`은 자식 메뉴와 권한을 삭제할 수 있으므로 보정에 사용하지 않는다.
- 출하계획등록은 출하등록처럼 기본정보 안에 수주 선택을 배치하고 상세와 수주 선택에 F1-Grid를 사용한다. 계획현황은 출하현황처럼 공통 검색 영역, 그리드와 상세 패널을 사용한다.
- 현황 수정은 기존 현황 수정 권한 또는 읽기가 허용된 계획등록 메뉴의 수정 권한으로 제공한다.
- 프론트엔드 지침에 기존 동종 화면과 레이아웃을 비교·통일하도록 기록했다. 결과 문서에 짧은 커밋 문구를 기록하는 기준도 추가했다.

## DB 적용 및 복구

- MCP로 `tb_menu`와 `tb_role_menu_permission` 메타데이터를 확인했다. 업무 데이터 행은 조회하지 않았다.
- **SQL은 실제 DB에 적용하지 않았고 PostgreSQL 실행 검증도 하지 않았다.** 승인된 대상 DB를 백업한 뒤 SQL의 `v_tenant_id`를 지정하고 검토 후 적용해야 한다.
- 이전 상태가 신규·기존 메뉴에 따라 다르므로 자동 역변경은 차단했다. 복구는 적용 전 백업을 통해 수행한다. [변경 이력과 복구 지침](../../../database/20261109/20261109_001_change_sales_shipment_plan_menus.md).
