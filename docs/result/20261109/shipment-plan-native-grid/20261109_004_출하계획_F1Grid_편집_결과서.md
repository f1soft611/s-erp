# 출하계획 F1Grid 셀 편집 결과

## 원인과 수정

출하계획 등록·현황 수정은 F1Grid를 공유했지만 계획일과 수량을 셀 안에 별도 입력란으로 상시 표시해 수주·출하의 기본 셀 편집과 달랐다. 공통 폼의 두 컬럼을 F1Grid `date`·`decimal` 편집기로 변경하고 활성 행을 합계, 분할·삭제와 저장에 반영했다. 신규·수주 전환 및 저장 결과를 다시 불러올 때 그리드 상태도 갱신한다.

행 높이를 임의로 44px로 지정했고 기본정보 여백과 대화상자 스크롤 구조도 기준 화면과 달랐다. 출하 화면과 동일한 기본 행 높이·필드 간격·상세 영역 여백과 대화상자 구조를 적용했다. 상세 패널은 수주·출하 패턴의 작성자·요약·정보 그룹과 품목 표로 정렬했다.

상세 조회에 작성자 이름·사진·등록일을 추가하고, 목록과 잠금 조회에서는 사진을 조회하지 않는다. 기존 테이블만 사용하며 스키마 변경은 없다.

## 검증

- 등록과 현황에서 셀 더블클릭·편집, Enter 확정과 편집 중 저장을 확인했다.
- 분할 행 편집·합계·저장, 수량 검증, 읽기 전용 및 저장 실패 후 값 보존을 확인했다.
- 375/768/1280px Chromium에서 합성 API 데이터로 등록·현황 편집과 저장 요청을 확인했다. 실제 테넌트 데이터는 사용하지 않았다.
- 세 화면 크기에서 출하와 출하계획 자세히보기의 행 높이, 기본정보 내부 간격·패딩 및 대화상자 상단 여백을 실제 치수로 대조했다. 출하계획 수정과 자세히보기의 치수도 비교하고 프로필 이미지 로딩을 확인했다.
- 읽기 전용 DB MCP의 `list_tables`와 `describe_table`로 계획 헤더, 사용자, 로그인 계정의 관련 컬럼을 확인했다. 행을 반환하지 않는 제한 SELECT로 테넌트 범위 작성자 조인의 SQL을 확인했다.
- 계획 Mapper·서비스 테스트 및 변경 Java 모델의 `javac --release 8` 검증을 수행했다.
