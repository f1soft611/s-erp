# 출하계획·수주 도움창과 공통 수정 폼 결과

## 변경 내용

- 출하계획등록 수주 도움창의 검색 필드와 버튼을 출하등록 출하계획 도움창과 동일한 높이 40px, 버튼 최소 폭 88px로 맞췄다.
- 두 도움창의 번호 셀에 번호만 표시한다. 번호 클릭 시 기존대로 해당 수주의 모든 상세가 선택되고, 다른 셀 클릭 시 단일 행이 강조된다.
- 출하계획등록과 현황 상세보기·수정에서 동일한 기본정보 및 F1Grid 폼을 사용한다. 수정에서 기존 등록 화면과 같이 계획일·수량 및 분할을 편집하고 동일한 검증을 적용한다.
- `frontend/AGENTS.md`에 현황 상세·수정과 등록 폼의 실제 컴포넌트 공유 및 동작 비교 규칙을 추가했다. F1-Grid 문서도 갱신했다.

## 재발 원인과 회귀 기준

- 기존에는 현황 수정 그리드를 등록 그리드와 별도로 정의해 분할 컬럼과 편집 동작이 누락됐다.
- 공통 `DeliveryPlanForm`으로 폼과 그리드를 공유하고, 등록·수정 양쪽과 분할 저장 및 검증을 함께 확인한다. 상세보기는 같은 폼을 읽기 전용으로 표시한다.
- 분할 신규 행은 상세 ID 없이 전송하고 삭제한 행은 요청에서 제외한다. 출하 이력이 있는 행의 수정·삭제 등 서버 거절 시 입력을 유지한다.

## 검증

- 관련 Vitest 3개 파일 36개 통과. 번호 선택, 수주 그룹, 행 강조, 분할, 수량 검증, 권한, 오류 보존 및 기존 API 응답을 확인했다. 이전 용어 변경에 따라 API 테스트의 오래된 오류 문구 기대값도 갱신했다.
- 변경 파일 lint 및 프론트엔드 빌드 통과.
- 기존 개발 서버를 재사용해 합성 데이터로 375/768/1280px 검색 크기, 번호 선택, 행 강조와 등록·수정 폼을 확인했다. 화면 전체 가로 넘침과 브라우저 런타임 오류는 없었다. 모바일의 넓은 그리드는 내부 가로 스크롤을 사용한다.
- 백엔드·API·DB 스키마는 변경하지 않았다.
