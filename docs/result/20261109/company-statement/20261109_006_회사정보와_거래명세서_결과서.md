# 회사정보와 거래명세서 작업 결과

## 구현 내용

- 기준정보 관리에 회사정보 관리 화면과 테넌트별 조회·수정 API를 추가했다.
- 출하관리 아래 거래명세서 등록·현황을 추가했다. 출하 한 건당 활성 명세서 한 건을 허용하고, 삭제 후 재등록할 수 있다.
- 저장 시 회사·거래처·출하 품목과 금액을 스냅샷으로 보존한다. 수정은 명세일과 비고만 허용한다.
- 등록과 현황 상세 수정에 같은 폼과 F1Grid를 사용하며, 저장된 정보로 A4 거래명세표 미리보기와 인쇄를 제공한다.
- 회사정보 컬럼, 명세서 테이블, 메뉴·권한의 날짜별 SQL과 이력·롤백 안내를 `docs/database/20261109`와 `backend/DATABASE/20261109`에 작성했다. 메뉴 롤백은 기존 권한의 안전한 복원을 위해 적용 전 백업을 이용한다.

## 검증

- 프론트엔드 집중 테스트 7건, 프로덕션 빌드 통과.
- 백엔드 회사정보·명세서 테스트 16건과 출하 매퍼 테스트 5건 통과. 변경 운영 Java 코드는 별도로 `javac --release 8` 검증을 수행했다.
- 합성 데이터 브라우저 검사: 375·768·1280px에서 회사정보, 등록, 현황, 수정, 미리보기 및 인쇄 확인. 80개 품목의 A4 PDF가 4페이지로 생성됨.
- 변경 범위 린트는 오류 없이 통과했으며 React effect 관련 경고 3건이 있다.
- 전체 프론트엔드 린트는 기존 `tests/common-code-management-page.test.tsx:53`의 조건부 Hook 오류로 실패했다.
- DB MCP 읽기 전용 테이블 메타데이터로 기존 계약을 확인했으며 업무 데이터 행은 조회하지 않았다. **SQL은 실제 DB에 적용하지 않았고**, 실제 PostgreSQL에서 신규 스키마 적용 후 저장·동시성·출력 전체 흐름은 검증하지 못했다.
- 운영 반영 전 006 회사정보, 007 명세서, 008 메뉴 스크립트 순서로 적용 여부와 기존 메뉴·권한 백업을 DBA가 확인해야 한다.
