# 20261008_003 문서 결재 저장 스키마 결과

## 결과 요약

승인된 저장 구조에 맞춰 문서 본문/결재선 저장 테이블, 공통 댓글 SYSTEM 이벤트 식별, 일반 댓글 좋아요 DDL 초안을 작성했다. 실제 저장 API 구현이나 데이터베이스 적용은 수행하지 않았다.

## 저장 구조 검토

- 문서 본문/초안은 `tb_electronic_approval_main`, 단계별 결재·합의·참조 참여자는 `tb_electronic_approval_line_info`에 저장한다. 참조 행은 `REFERENCE`로 구분하고 처리 상태를 갖지 않는다.
- 결재 참여자의 처리 상태, 처리 시각, 처리 의견은 결재선 행에 저장한다. 결재 성공 트랜잭션에서 같은 문서의 `tb_common_comment`에 `SYSTEM` 메시지를 추가하는 것은 후속 서비스 구현 사항이며 두 변경은 원자적으로 처리해야 한다.
- 일반 댓글과 결재 시스템 메시지는 공통 댓글 타임라인을 공유한다. 기존 댓글의 `comment_type`은 기본값 `USER`로 호환하고, 시스템 메시지는 `APPROVED`/`REJECTED`/`RETURNED` 이벤트 코드로 구분한다.
- 좋아요는 `tb_common_comment_like`에서 tenant/comment/user별로 관리한다. unlike는 본인 관계 행 삭제이며 SYSTEM 댓글에는 좋아요를 허용하지 않아야 한다.
- 첨부는 기존 `tb_common_file`에서 `owner_type='APPROVAL'`, `owner_id=<electronic_approval_id>`로 연결한다. 기안 양식 테이블도 재사용한다.
- 기존 공통 댓글/파일 API에 결재 문서별 접근 권한 검사가 보장된다는 근거가 없으므로 문서 권한 검증을 구현하기 전에는 전자결재 데이터와 연결하지 않는다.

## 확인 및 검증

- 계약 근거: 앞선 설계 확인에서 읽기 전용 DB MCP로 중앙/tenant 테이블 목록과 공통 테이블 존재 여부를 확인했다. 현재 실행 맥락에는 MCP 호출 도구가 노출되지 않아 재조회하지 않았으며, `docs/database/db-schema.md`, 기존 날짜별 SQL, `LoginVO`, 공통 댓글 VO/Mapper, 문서작성 및 양식 UI 타입으로 대체 확인했다. 민감한 행 데이터는 조회하지 않았다.
- forward/rollback 대칭성: 신규 결재 본문, 결재선, 댓글 좋아요 테이블 각각의 생성/삭제 대응을 확인했다. `comment_type`, `event_type`, 댓글 복합 unique 제약 및 check 제약의 추가/삭제 대응도 확인했다.
- mirror 검사: backend/docs의 forward SQL SHA-256 `863EAEFD51D9CFDED41AEEDF0D6A4E7280F046E31E294656ADC825472F22AA38`, rollback SQL `BBCE667C60544C0BE556729DF1C2B12B96B25E51127DC4BF0B6C4D85DDB13FA9`, 변경 이력 `040065713BADC3EC801CC8E5B08854C0EB2CA3C20D952AFDC12CB09EBF660D0B`가 각각 일치한다.
- 범위 확인: SQL에 `tb_document_attachment`, `tb_electronic_approval_history_main`, `tb_electronic_approval_history_like` 생성이 없고, 프론트엔드/백엔드 런타임/MCP 설정 파일은 변경하지 않았다.
- `git diff --check`를 실행해 통과했다.
- PostgreSQL `psql`, `pg_format`, Docker 실행기가 없어 파서/격리 DB 구문 검증은 수행할 수 없었다. SQL 전체를 정적으로 검토했으며 실제 실행 검증으로 표현하지 않는다.
- 변경 범위가 요구사항/DDL/스키마 문서에 한정되어 별도 프론트엔드 빌드, 백엔드 테스트 및 화면 스크린샷은 생성하지 않았다.

## 미적용 및 후속 사항

- 이 migration은 검토용 초안이며 중앙 DB나 tenant DB 어디에도 적용하지 않았다.
- 실제 API 연결 전 시스템 댓글 수정·삭제·답글·좋아요 차단, 참여자 tenant 소속 검증, 문서/첨부/댓글의 문서별 권한 검사를 구현해야 한다.
- 결재선 상태 변경과 시스템 메시지 등록은 동일 트랜잭션으로 묶어야 한다. 이번 작업에는 해당 서비스/API가 포함되지 않는다.
