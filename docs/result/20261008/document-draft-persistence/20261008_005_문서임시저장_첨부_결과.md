# 20261008_005 문서 임시저장 및 첨부 저장 결과

## 결과 요약

문서작성 화면의 명시적 임시저장을 전자결재 저장 API에 연결했다. 문서 본문, 결재선, `SYSTEM/DRAFT_SAVED` 이력은 하나의 DB 트랜잭션에서 저장하며, 첨부는 결재 문서 권한을 확인하는 전용 API를 통해 기존 공통 파일 저장 기능을 사용한다. 결재 신청·승인·반려와 일반 댓글 기능은 이번 작업 범위에 포함하지 않았다.

## 구현 및 보완

- 임시저장 API와 서비스·매퍼를 추가해 본문, 검증된 결재/합의/참조 참여자 및 시스템 이력을 저장한다. 같은 작성 세션의 재저장은 기존 문서 ID를 유지한다.
- 결재 전용 첨부 API에서 문서 tenant 및 작성자 권한을 검사한다. 범용 댓글·파일 API는 결재 자료 접근 경로로 사용할 수 없도록 제한했다.
- MinIO object key를 업로드별 고유값으로 생성하고, 파일 메타데이터 저장 실패 때 해당 요청의 객체만 보상 삭제하도록 처리했다.
- 프런트엔드에 저장 진행/오류 상태, 문서 ID 재사용, 파일별 업로드 상태와 개별 재시도를 연결했다. 결과가 불명확한 파일은 목록 확인 전 자동 재전송하지 않는다.
- 저장 응답에서 받은 문서 ID는 본문에서 제거하고 공통 다이얼로그 제목 바로 아래 description 영역에 표시하도록 정리했다.
- 브라우저 점검에서 좁은 화면의 결재선 액션 버튼들이 한 줄 너비를 넘는 문제를 확인했다. 버튼 컨테이너를 줄바꿈 가능하게 보완하고 회귀 테스트를 추가했다.

## DB 계약 및 migration 상태

현재 세션에는 `s-erp-postgresql-readonly` MCP 도구가 제공되지 않아 중앙 DB의 실제 컬럼·제약 메타데이터를 확인할 수 없었다. 대체 근거로 저장소 날짜별 DDL, MyBatis Mapper XML, VO 및 도메인 코드를 대조했다. 사용자 확인에 따라 `comment_type`과 `event_type` 컬럼을 다시 추가하지 않았다.

저장소의 `20261008_003` DDL이 시스템 이벤트 목록에서 `DRAFT_SAVED`를 허용하지 않아 `20261008_004` forward/change record/rollback 초안을 양쪽 날짜별 폴더에 기록하고 `docs/database/db-schema.md`를 동기화했다. 양쪽 사본은 일치 여부를 확인했으며, migration은 실제 DB에 적용하지 않았다. 실제 제약 확인과 운영 검토 전에는 적용하지 않는다.

따라서 중앙 DB에서 초안 저장이 end-to-end로 성공하는지는 아직 확인되지 않았다. 실제 제약이 저장소 DDL과 같고 `DRAFT_SAVED`가 허용되지 않는다면 migration 검토·적용이 선행되어야 한다.

## 후속 범위

- 읽기 전용 DB MCP가 제공되는 환경에서 중앙 DB의 실제 이벤트 CHECK 정의를 확인하고 migration 필요성을 재판정한다.
- 결재 신청, 승인/합의, 반려/반송 및 일반 사용자 댓글은 별도 작업지시서 범위다.
