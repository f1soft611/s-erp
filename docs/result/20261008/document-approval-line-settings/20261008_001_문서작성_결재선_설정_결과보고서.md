# 20261008_001 문서작성 결재선 설정 결과보고서

## 작업 결과

문서작성 모달의 `결재 추가`, `합의 추가` 옆에 `결재선 설정` 버튼을 추가했다. 별도 설정 창은 작성 중인 결재 단계와 참조자를 복사해 표시하고, 적용할 때만 두 상태를 함께 반영한다. 취소 또는 닫기 시 임시 변경은 버린다.

- 결재 및 합의 단계를 드래그하거나 위/아래 버튼으로 재정렬한다. 고정 기안자와 합의 그룹 단위 동작을 유지한다.
- 결재자/합의자 및 참조자를 기존 선택기로 추가·삭제하고, 결재와 참조 간 중복 선택을 막는다.
- 적용한 뒤 새 결재 단계를 추가해도 단계 ID가 충돌하지 않도록 다음 ID를 보정한다.
- 최초 작성 정보 로딩이 끝나기 전에는 설정 창을 열 수 없도록 하여, 열 때 현재 결재선/참조선 상태를 정확히 초기화한다.
- 즐겨찾기 저장/불러오기 버튼은 테이블/API 계약과 명명 규칙이 정해지지 않아 비활성화하고, 준비 후 제공 안내를 표시한다. 로컬 저장 및 서버/API 요청은 추가하지 않았다.
- 백엔드, DB, API 계약은 변경하지 않았다.

## 결재선 드래그 시각 개선

- 단계 카드 전체가 아니라 전용 드래그 핸들에서만 드래그를 시작하도록 했다. 드래그 중인 단계는 테두리, 배경, 그림자, 투명도로 구분한다.
- 대상 단계의 위쪽/아래쪽 절반에 놓을 때 해당 가장자리에 삽입선을 표시하고, 표시된 위치와 동일한 순서로 재배치한다.
- 재배치 후 짧은 모션 피드백을 제공하며 `prefers-reduced-motion: reduce`에서는 애니메이션과 전환 효과를 끈다.
- 고정 기안자, 기존 위/아래 이동 버튼, 합의 그룹 단위 이동은 유지한다.

## 검증

| 구분 | 결과 |
| --- | --- |
| Vitest: 설정 창 및 문서작성 통합 테스트 | 2개 파일, 51개 테스트 통과 |
| 단계 ID 회귀 테스트 | 설정 적용 후 다음 결재 단계 추가 및 순번 확인 통과 |
| 프론트엔드 빌드 | `npm run build` 통과 (TypeScript 및 Vite) |
| 정적 진단 | 변경한 TSX 파일 오류 없음 |
| 반응형 브라우저 확인 | 375px, 768px, 1280px에서 화면 가로 넘침 없음. 각 뷰포트에서 드래그 시작 상태, 위/아래 삽입 표시 및 재배치 결과 확인 |
| 접근성 모션 확인 | `prefers-reduced-motion: reduce`에서 애니메이션 `none`, 전환 시간 `0s` 확인 |
| 즐겨찾기 상태 | 저장/불러오기 모두 비활성화, 준비 안내 표시 |

이번 드래그 개선 최종 실행에서 설정 창 테스트 9개와 문서작성 테스트 42개가 모두 통과했다.

브라우저의 통합 포인터 자동화는 드래그 좌표가 의도한 대상 대신 인접 카드/오버레이에 전달되어 실제 마우스 이동을 검증하지 못했다. 대신 Chromium 페이지에서 `DataTransfer`를 포함한 `DragEvent`를 발생시켜 세 뷰포트 각각에서 드래그 소스 강조, `before`/`after` 삽입 표시와 해당 순서를 확인했다. 실제 입력 장치로 수행하는 수동 드래그 확인은 별도 환경에서 필요하다.

## 회귀 확인

- 취소 후 기존 결재 순서와 참조자가 유지된다.
- 적용 후 변경한 결재 순서 및 참조자가 작성 화면에 함께 반영된다.
- 적용 이후 새 결재 단계를 추가해도 기존 단계 ID와 충돌하지 않는다.
- 사용자 선택 후보가 없거나 로드되지 않은 동안 추가 버튼이 비활성화된다.
- 드래그 핸들 시작만 허용되고, before/after 삽입선과 결과 순서가 일치한다.
- 드래그 종료 후 소스/대상 표시가 제거되고, reduced-motion 설정에서는 모션 효과가 비활성화된다.
