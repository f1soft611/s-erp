# 20261029_004 문서·공지 공유 링크 및 공통 미리보기 결과

## 구현 내용

- 기존 문서 공유 토큰과 링크 호환성을 유지하면서 공지 전용 tenant-bound 토큰과 발급/해석 API를 추가했다. 두 도메인은 암호화 문맥을 분리했으며 API는 인증되지 않은 사용자를 거부한다.
- 공지 작성자 메뉴에 `공지 공유하기`를 추가했다. 발급된 canonical URL을 클립보드에 복사하고, 발급 또는 복사 실패 시 성공 알림 대신 오류 알림을 표시한다.
- 문서 공유 링크, 공지 공유 링크, 외부 HTTP(S) 링크의 추출·분류·카드 상태/표시를 shared feed 컴포넌트로 통합했다. 기존 문서 `documentId` 링크와 외부 OG API를 유지했다.
- 문서와 공지의 본문 및 댓글/답글에서 내부 공유 링크와 외부 OG 카드를 구분해 미리보기한다. 같은 기능 링크는 기존 상세 패널을 열고, 교차 기능 링크도 현재 화면과 URL을 유지한 채 공통 우측 패널에서 권한 확인된 상세를 연다.
- 공유 토큰 및 미리보기 결과 저장, DB 스키마 변경은 없다.

## DB 및 보안

구현 단계에서 읽기 전용 PostgreSQL MCP의 `list_tables`를 확인했다. 토큰과 OG 메타데이터는 저장하지 않으며 테이블/컬럼/SQL 변경이 없다. 공유 링크 해석은 인증 사용자와 tenant를 확인하고 기존 공지/문서 조회 경로의 접근 정책을 사용한다. 내부 공유 URL은 외부 OG endpoint로 보내지 않는다.

## Java 8 테스트 컴파일 오류 후속 수정

- 원인: Maven은 Java 8 source/target을 지정하지만 `NoticeShareApiControllerTest`와 `ShareTokenCodecTest`에서 Java 11부터 제공되는 `String.repeat()`를 사용했다. JDK 19의 source/target 검사만으로는 최신 JDK API 사용을 차단하지 못했다.
- 재현: 두 실제 테스트 파일을 `javac --release 8`로 컴파일하여 `repeat(int)` 심볼 오류 4건을 확인했다.
- 수정: 기존 테스트 패턴인 `new String(new char[n]).replace('\0', 'A')`로 교체했다. 토큰 접두사, 길이 경계값, 테스트 동작 및 Maven 설정은 유지했다.
- 검증: 수정한 두 파일의 `javac --release 8` 컴파일과 `mvn -q -Dtest=NoticeShareApiControllerTest,ShareTokenCodecTest test`가 통과했다.
- 테스트 문자열 생성만 수정했으므로 API/DB 계약과 화면 변경은 없으며 DB 조회 및 추가 화면 스크린샷은 필요하지 않다.

## 외부 OG 카드 라벨 제거

- 사용자 요청에 따라 공통 외부 카드 상단의 독립된 `웹 링크` caption만 제거했다. 문서·공지의 본문/댓글에 함께 반영되며 사용자가 입력한 링크 텍스트, 사이트명·제목·설명·이미지, 내부 카드 구분과 클릭 동작은 유지한다.
- 공통 feed/문서 wrapper 테스트에서 기존 caption으로 인한 실패 2건을 먼저 확인한 뒤 수정했다. 집중 Vitest 17건, targeted oxlint와 frontend production build가 통과했다.
- 문서·공지 공유 및 문서 외부 OG Chromium 시나리오가 각각 375/768/1280px에서 통과했다. 미리보기 내 caption 부재, 상세 이동, 외부 새 탭과 가로 overflow 부재를 확인하고 기존 스크린샷을 갱신했다.
- API 및 DB 변경은 없다.

## 교차 기능 우측 상세 패널

- 문서에서 공지, 공지에서 문서 미리보기 선택 시 내부 anchor 이동 대신 공통 우측 Drawer를 연다. 기존 동일 기능 콜백을 유지하며 외부 웹 링크만 새 탭으로 연다.
- 현재 화면과 URL을 유지하고 닫기/ESC/배경 클릭으로 복귀한다. 패널 안에서 다시 내부 미리보기를 누르면 context를 통해 같은 패널의 대상만 교체한다.
- 기존 문서 상세와 공지 feed/댓글 hook을 재사용한다. 상세 API를 통해 현재 권한으로 다시 조회하며 공지 로딩/실패를 표시하고 언마운트 후 응답을 버린다. 연결 상세에서는 지원하지 않는 관리 메뉴를 숨기며 원래 기능 화면은 그대로 유지한다.
- 회귀 테스트에서 기존 anchor fallback으로 인한 실패 2건을 확인한 뒤 구현했다. 최종 집중 Vitest 23건, 신규/변경 공통 패널 파일 targeted lint 및 frontend production build가 통과했다. NoticeFeedList의 기존 lint 경고는 유지했다.
- Chromium 375/768/1280px에서 두 방향 열기, 패널 내부 대상 교체, 원래 URL/단일 탭 유지, 닫기/ESC 후 원래 상세 유지, 모바일 전체 폭/데스크톱 72vw 패널 폭, 가로 overflow 부재 및 외부 새 탭을 확인했다. 기존 문서 외부 OG 시나리오도 세 너비 모두 통과했다.
- 프론트엔드 상세 열기만 변경했다. 기존 API/DB 계약을 수정하지 않았으며 추가 DB 조회나 스키마 변경은 없다.

## 공지 미리보기 구분명 수정

- 원인: 문서/공지 미리보기 resolver가 `mapNoticePost`에 공지 구분명 map을 제공하지 않아 `OPS` 같은 원시 코드로 fallback했다.
- 수정: 공지 도메인의 공통 `resolveNoticeLinkPreview`에서 기존 `NOTICE_GUBUN` 그룹/항목 API로 명칭을 조회하고 문서·공지의 본문/댓글 renderer가 함께 사용한다. 하드코딩 번역 및 API/DB 계약 변경은 없다.
- 미등록 코드 또는 공통코드 조회 실패 시 `공지`를 표시해 원시 코드 노출을 방지한다. 공지 본문/제목 미리보기와 상세 열기는 유지한다.
- 기존 코드 노출로 인한 회귀 테스트 실패를 먼저 확인했다. 집중 Vitest 26건, targeted lint, frontend production build가 통과했다.
- Chromium 375/768/1280px에서 공지 댓글 및 문서 상세의 공지 카드에 `운영공지`가 표시됨을 확인했다. 우측 패널·원래 화면 유지·외부 새 탭 회귀도 통과했으며 기존 스크린샷을 갱신했다.

## 공지 미리보기 작성자 표시

- 문서 카드와 동일하게 공지 subtitle을 `공지구분 · 작성자` 형식으로 변경했다. 공통 resolver에서 기존 `writerName`을 사용하므로 문서·공지의 본문/댓글에 함께 반영된다. 이름이 누락되거나 공백이면 구분명만 표시하며 작성자 ID를 대신 표시하지 않는다.
- 작성자 미표시 상태에서 회귀 테스트 실패를 확인한 뒤 수정했다. 집중 Vitest 26건, targeted lint, frontend production build가 통과했다.
- Chromium 375/768/1280px에서 공지 댓글 및 문서 상세의 공지 카드에 구분명과 작성자가 함께 표시됨을 확인하고 기존 스크린샷을 갱신했다. 상세 패널과 외부 링크 동작은 유지하며 API/DB 변경은 없다.
