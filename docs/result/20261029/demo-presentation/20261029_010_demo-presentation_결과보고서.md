## 원인과 수정

시드가 승인 결재선에 임의 의견을 넣었고, 일반 텍스트인 시스템 이력 필드에 HTML과 식별 주석을 저장했다. 화면 처리나 권한을 변경하지 않고 데이터 생성 계약을 바로잡았다.

- 신규 시드의 승인 의견은 NULL, 시스템 이력은 일반 텍스트.
- 이미 적용한 데모는 004 증분 보정 SQL로 정확한 합성 원문만 정규화한다. 승인 상태/도장/시각, 반려/보완 사유, 일반 댓글/답글을 유지한다.
- 변경값은 문서 메타데이터에 백업하고 대응 복원 SQL을 제공한다. 결재선 변경이 있으면 보정 중단, 보정 후 결재선/시스템 변경이 있으면 복원 중단.
- 최초 생성/삭제 롤백도 시스템 일반 텍스트 지문을 지원하도록 맞췄다. 사용자 수정 공지분류 설정은 되돌리지 않았다.
- 양쪽 날짜별 DB 폴더에 SQL과 변경 이력을 동일하게 관리한다. 스키마 변경이 없어 db-schema.md 구조는 변경하지 않는다.

## 확인과 검증

현재 기본 DB MCP 리소스 검색 결과 0개로 재확인이 불가능했다. 앞서 확인한 메타데이터와 Mapper/Service/날짜별 DDL을 대체 근거로 사용했다. `.env`나 연결 정보를 확인하지 않았다.

기존 테스트에 신규 시드 표시 계약과 구버전 보정/복원 회귀 사례를 추가해 37개 SYSTEM의 HTML 오류를 먼저 재현했다. 메모리 PGlite 합성 데이터에서 일반 텍스트 변환, NULL 의견, 반려 사유 보존, 재실행 무변경, 다른 테넌트/실제 문서/일반 댓글 보존, 원본 복원 및 수정 시 복원 거부를 검증했다.

실행 명령(임시 설치 모듈 경로를 PGLITE_MODULE_PATH에 지정):

```powershell
node --test tools\tests\test_groupware_demo_seed.cjs tools\tests\test_customer_material_sample_seed.cjs
```

최종 결과: **14개 통과, 실패/생략 0** (데모 8개, 기존 마스터 시드 6개). 양쪽 SQL/이력 사본과 변경 파일 공백 검사도 확인했다.

실DB에는 적용하지 않았다. psql 메타명령은 정적 확인이며 SQL 본문만 PostgreSQL 엔진에서 실행했다. UI 변경이 없어 브라우저 스크린샷은 해당 없음이다. 계정 표시가 포함된 사용자 첨부 이미지는 저장소로 복사하지 않았다.
