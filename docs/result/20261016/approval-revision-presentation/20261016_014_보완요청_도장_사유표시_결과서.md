## 재현 및 원인

- 서버가 시스템 이벤트를 `처리 문구 + " 사유: " + 입력 사유`로 생성하므로 처리 문구와 사유 첫 줄이 붙어 보였다.
- 보완요청 도장은 원형 안에 네 글자를 자동 줄바꿈하여 `보완요`/`청`처럼 나뉘었다.
- 기존 메시지 아이콘 조건은 반려만 포함하고 보완 상태의 의견은 도장 아래 한 줄로 표시했다.

## 구현

- 전자결재 표시 helper에서 `REJECTED`/`RETURNED`의 알려진 시스템 문구 뒤 첫 공백을 개행으로 변환한다. 기존 데이터에도 적용되며 이미 개행된 내용과 사유 본문, 다른 이벤트는 유지한다.
- 상세 및 피드 공통 댓글 변환 경로에서 helper를 사용한다. HTML 변환 없이 기존 일반 텍스트/`pre-wrap` 렌더링을 유지한다.
- 보완 도장은 `보완\n요청`으로 명시하고 줄 높이 1.05와 가운데 정렬을 적용했다. 원형 48px, 상태 색상 및 개인 도장 이미지는 유지했다.
- 보완 사유 인라인을 제거하고 반려와 같은 메시지 버튼/팝오버를 사용한다. 버튼 색은 상태에 맞추고 제목/접근성 이름은 `보완요청 사유`로 제공한다. 빈 사유에는 아이콘이 없다.
- 기존 승인 의견, 입력 공통 다이얼로그 및 처리 요청은 유지했다. DB 변경 없음. 관련 API/DB 계약 구현을 변경하지 않아 MCP 확인 대상 없음.

## 검증

### 자동 테스트

- 수정 전 포맷 함수 및 보완 아이콘 검증 7건의 실패를 확인했다.
- 최종 **34개 통과**:
  - 표시 메타데이터 전체 29개: 반려/보완 메시지 개행, 내부 개행/빈 줄/`사유:` 보존, 멱등성, 비대상 원문 유지.
  - 상세/피드 기존 시스템 메시지 표시 2개.
  - 반려·보완 팝오버/빈 사유/도장 두 줄/승인 의견 유지 통합 1개.
  - 기존 상세 반려·보완 입력/취소/실패 재시도 2개.
- 빌드 통과(TypeScript + Vite). 기존 번들 크기 경고 유지.
- 변경 파일 oxlint 오류 없음. 기존 effect 관련 경고 5개 유지.
- `git diff --check` 통과.

```powershell
Set-Location frontend
node .\node_modules\vitest\vitest.mjs run tests\document-presentation.test.ts tests\document-write-page.test.tsx --testNamePattern="document presentation metadata|legacy system reasons|rejection and revision reasons|processes a detail" --testTimeout=20000
npm run build
```

확대 검증 중 병행 변경으로 Dashboard 테스트 mock에 `getDocumentApprovalScopeLabel`이 빠져 기존 피드 입력 테스트가 실패했다. 해당 무관 mock을 이 작업에서 변경하지 않았다. 이 작업의 표시/팝오버 테스트는 실제 대상 컴포넌트 직접 렌더링으로 독립 검증했으며 전체 문서작성 테스트 통과를 주장하지 않는다.

### 실제 브라우저

기존 4173 Vite 서버를 재사용한 격리 Chromium에서 375/768/1280px 각각 검증했다. 합성 API 응답만 사용하며 실제 업무 문서/데이터에 쓰지 않았다.

- 저장 형식에 개행이 없는 기존 보완 시스템 메시지에서 처리 문구와 사유가 별도 줄로 표시됨.
- 도장 `textContent = "보완\n요청"`, 실제 크기 48×48px 및 개행 스타일 확인.
- 도장 아래 사유가 없고 메시지 버튼 클릭 시 해당 보완 사유 원문/빈 줄을 팝오버로 표시.
- 반려·보완 입력 다이얼로그 및 정확한 여러 줄 요청 본문 회귀 확인.
- 페이지 가로 넘침 및 pageerror 없음.
- 생성한 검증 브라우저는 종료했고, 기존 개발 서버는 유지했다.
