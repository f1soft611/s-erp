# 전자결재 참여자 문서목록 조회 누락 결과 보고서

## 결과 요약

- 원인: 문서 목록·요약 SQL은 `participantUserId`로 로그인 사용자의 결재선 참여 여부를 판단하지만, 서비스 공통 파라미터 생성부가 이 키를 전달하지 않았다. 따라서 결재자에게 관련 문서가 없거나 처리 대기 건수가 0인 것처럼 보일 수 있었다.
- 수정: `DocumentApprovalServiceImpl.actorParams`가 `LoginVO.uniqId`를 `participantUserId`로 전달하도록 추가했다. 기안자 ID, tenant 범위, SQL, API와 UI는 변경하지 않았다.
- 회귀 테스트는 수정 전 누락 파라미터 assertion에서 실패하고 수정 후 통과함을 확인했다.

## DB MCP 확인

- `s-erp-postgresql-readonly`에서 `list_tables` 및 `describe_table`로 `tb_electronic_approval_main`, `tb_electronic_approval_line_info`, `tb_user`, `tb_login_account` 메타데이터를 읽기 전용 확인했다.
- 결재선의 `participant_user_id` 컬럼과 로그인 계정/사용자 식별 연결을 확인했다. 데이터 조회는 대상 로그인 계정에 대한 제한된 집계만 수행했으며, 문서 제목·ID·결재자 이름 등 행 값은 읽거나 기록하지 않았다.
- 집계 결과 대상 사용자에게 관련 문서와 처리 대기 문서가 존재했다. 이로써 빈 목록이 단순히 결재 배정이 없어서 생긴 현상은 아님을 확인했다.
- 스키마 변경이 없으므로 migration 및 롤백 스크립트는 생성하지 않았다.

## 브라우저 확인 및 개인정보 제한

이번 변경은 서버 조회 파라미터만 수정했다. 실제 tenant 문서의 제목·본문이 노출될 수 있는 브라우저 화면 캡처는 생성하지 않았다. 결과 스크린샷 대신 회귀 테스트에서 목록/요약 DAO에 로그인 사용자의 `uniqId`가 전달되는 것을 검증했다.
