## 재현 조건 및 원인

기안자가 문서를 임시저장하면서 다른 사용자를 결재선에 등록하면, 등록된 사용자의 `ALL` 피드·리스트에도 문서가 포함됐다. 기존 서버 조건은 기안자 또는 결재선 참여자인지만 확인했고 `DRAFT` 상태를 제한하지 않았다. 상신 취소 시에도 결재선이 유지되어 같은 문제가 발생할 수 있었다.

## 해결

- `documentReadAccess` 공통 SQL 조각으로 본인 문서는 기존대로, 타인 문서는 `document_status != 'DRAFT'`인 결재선 참여 문서만 허용한다.
- 목록, 페이지 목록/건수, 요약, 알림, 단건·배치 상세, 참여 권한 검사까지 8개 조회 경로에 같은 조건을 적용했다.
- 피드는 일반 목록에서 문서 ID를 선택한 후 배치 상세를 가져오므로 두 단계 모두 차단된다.
- 본인 임시저장, 기존 상신 상태, 참조/합의 참여자, tenant/삭제 범위, 필터·정렬·응답 형식은 유지한다.
- 프론트엔드, DB 스키마·데이터 및 기존 미커밋 기능 변경은 수정하지 않았다. 같은 Mapper와 테스트에 있던 문서현황 필터/정렬 변경도 보존했다.

## 검증

### Red / Green

테스트 탐색 도구에서 Java 테스트를 발견하지 못하여 저장소의 Maven 테스트 러너로 검증했다.

1. 신규 테스트만 실행:
   `mvn -f backend\pom.xml "-Dtest=DocumentApprovalMapperTest#documentReadsAllowOwnDraftsButRequireNonDraftStatusForOtherParticipants" test`
   - 수정 전 1개 실패: `selectRelatedDocumentList`, `ALL`의 참여자 접근 조건에 `DRAFT` 제한이 없었다.
2. 수정 후 관련 테스트 실행:
   `mvn -f backend\pom.xml "-Dtest=DocumentApprovalMapperTest,DocumentApprovalServiceImplTest,DocumentApprovalApiControllerTest" test`
   - Mapper 16개, 서비스 54개, 컨트롤러 14개: 총 **84개 통과**, 실패/오류/건너뜀 0.
   - 신규 테스트는 8개 조회 경로 × 7개 scope에서 조건의 괄호 구조 및 인증 파라미터 바인딩을 검사한다.
   - 기존 MySQL 의존성 relocation, Java 8 bootstrap/deprecation/unchecked 경고는 남아 있으나 테스트는 성공했다.
3. `git diff --check`: 통과.

### DB MCP 직접 확인

기본 `s-erp-postgresql-readonly` 서버에서 다음을 수행했다.

- `list_tables`: 전자결재 원장·결재선 테이블 확인.
- `describe_table`: 원장의 `document_status` NOT NULL/기본값 `DRAFT`, 기안자/tenant/삭제 필드와 결재선 참여자 식별 필드 확인.
- `query_readonly(maxRows=1)`: 실테이블 대신 가상의 `VALUES` CTE에 동일 접근 조건을 적용하여 기대값과 비교.
- 결과: `checked_cases = 15`, `failed_cases = 0`, `visible_cases = 7`.

| 가상 검증 사례 | 기대 결과 |
|---|---|
| 본인 미삭제 임시저장 / 본인 상신 | 허용 |
| 타인 임시저장 + WAITING 결재선 | 차단 |
| 타인 임시저장 + 남아 있는 PENDING 결재선 | 차단 |
| 타인 상신 대기 + 본인 PENDING 결재선 | 허용 |
| 타인 진행 + 본인 WAITING 합의선 | 허용 |
| 타인 완료 + 본인 참조선 | 허용 |
| 타인 반려 / 보완요청 + 본인 참여선 | 허용 |
| 타인 상신 + 다른 사용자만 참여 | 차단 |
| 타 tenant 문서 또는 다른 tenant의 참여선만 존재 | 차단 |
| 삭제 문서(본인 포함) | 차단 |
| 본인 문서라도 다른 tenant | 차단 |

실제 테넌트 문서·계정·인증정보는 조회·기록하지 않았다. 조건 검증은 가상 데이터 SQL이며 실사용 화면 검증으로 간주하지 않는다.

## 최종 점검 및 반영 시 주의

- 요구사항 → 계획 → 상세 사양 → 실패 테스트 → 수정 → 검증 → 결과 문서 순서로 진행했다.
- 단순 화면 숨김이 아니라 서버 조회/접근 조건을 수정했다.
- 스키마 변경이 없어 신규 SQL 마이그레이션·롤백·누적 스키마 갱신은 비대상이다.
- UI 구조를 수정하지 않은 백엔드 조회 변경이며, 실사용 데이터가 포함되는 화면 캡처는 수행하지 않았다. 스크린샷은 미첨부다.
- 실행 중 백엔드의 재시작 또는 Mapper 리소스 재로딩은 수행하지 않았다. 배포 반영 후에는 두 사용자가 결재선에 연결된 임시저장/상신/상신취소 문서로 피드·리스트 및 상세 접근을 확인해야 한다.
