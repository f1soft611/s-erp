상세 화면에서 반려·보완요청을 누르면 사유 팝업 없이 즉시 처리 함수로 진입했다. 하단 처리 의견이 비어 있으면 필수 사유 검증에서 차단되고 오류도 하단에 표시되어 버튼이 반응하지 않는 것처럼 보였다. 피드는 이미 사유 입력 팝업을 사용하고 있었다.

시스템 댓글은 일반 텍스트를 안전하게 렌더링하지만 개행 보존 CSS가 없어 원문의 줄바꿈과 빈 줄이 화면에서 합쳐졌다.

## 변경 내용

- 상세와 피드의 반려·보완요청은 같은 사유 입력 팝업을 사용한다.
- 팝업 안에서 공백 사유를 검증하며 API 오류 후 입력을 보존하고 재시도할 수 있다. 취소는 요청 없이 초기화한다.
- 내부 줄바꿈과 빈 줄은 기존 서비스로 그대로 전송한다. 승인 선택 의견 및 취소 기능은 유지한다.
- 시스템 댓글의 텍스트 영역에 `white-space: pre-wrap`을 적용했다. HTML로 변환하지 않으며 일반 리치 텍스트 댓글은 변경하지 않았다.
- 백엔드/API/DB 및 스키마 변경 없음. DB MCP 확인 대상 계약을 변경하지 않았다.
- 작업 시작 전 및 진행 중 다른 작업의 변경은 유지했다.

## 검증

### 실패 재현

- 수정 전 상세 사유 팝업 테스트는 팝업을 찾지 못해 실패했고, 시스템 메시지 테스트는 `pre-wrap` 스타일 누락으로 실패했다.
- 최초 테스트 도구는 테스트를 탐색하지 못하여 저장소의 Vitest CLI를 사용했다.

### 최종 통과

1. 문서작성 집중 테스트 **9개 통과**:
   - 상세 반려·보완요청: 팝업, 취소, 공백 사유 차단, 여러 줄 요청, 오류 후 입력 유지 및 재시도, 성공 콜백.
   - 상세 승인: 기존 선택 의견을 포함한 직접 승인.
   - 상세 상신 취소·승인 취소: 확인 전 미전송 및 확인 후 서비스 호출.
   - 피드 승인 오류 표시, 피드 반려·보완요청의 필수 사유.
2. 공유 피드 **32개**, 결재 서비스 **14개** 전체 통과. 합계 **55개 통과**.
3. 최종 `npm run build` 통과. 초기 실행에서는 병행 작업의 문서현황 타입 오류로 실패했지만 최종 재실행은 TypeScript와 Vite 모두 성공했다. 해당 오류를 이 작업에서 수정하지 않았다. 번들 크기 경고는 남아 있다.
4. 변경 소스/테스트 대상 oxlint는 오류 없이 종료했다. 기존 effect/ref/Fast Refresh 관련 경고 9개는 범위 밖으로 유지했다.
5. `git diff --check` 통과.
6. 격리된 Chromium에서 실제 컴포넌트를 렌더링하여 **375/768/1280px** 각각 확인:
   - 반려·보완요청 팝업 및 빈 사유 안내.
   - 여러 줄 사유의 정확한 요청 본문.
   - 시스템 메시지의 원문/빈 줄 보존, 실제 높이가 5줄 이상, HTML 비해석.
   - 페이지 가로 넘침 없음, 브라우저 pageerror 없음.
   - API는 합성 fixture로 전부 가로채 실제 문서 또는 업무 데이터에 쓰지 않았다. 테스트 브라우저는 종료했으며 기존 4173 서버는 유지했다.

최종 테스트 명령:

```powershell
Set-Location frontend
node .\node_modules\vitest\vitest.mjs run tests\document-write-page.test.tsx --testNamePattern="processes a detail|submits a detail approval|submits the detail|reason before a feed|feed approval error|detail approval actions" --testTimeout=20000
node .\node_modules\vitest\vitest.mjs run tests\feed-components.test.tsx tests\document-approval-service.test.ts
npm run build
```

### 확대 검증에서 확인한 기존 테스트 불일치

전체 문서작성 테스트가 통과했다고 주장하지 않는다. 확대 selector 실행에서 다음 기존 테스트의 기대값 불일치를 확인했으며 무관한 변경을 피하기 위해 수정하지 않았다.

- `shows the ordered approval toolbar to a feed approver`: 현재 툴바에 없는 separator 및 과거 버튼 스타일을 기대한다.
- `lets the drafter cancel a pending submission after confirmation`: 현재 outlined 버튼에 contained 스타일을 기대한다.
- `lets an approver cancel their own approval only before a later stage acts`: 현재 확인 팝업의 `승인 취소` 대신 `승인 취소 확인` 이름을 기대한다.

취소 기능 자체는 현재 UI 이름을 기준으로 추가한 상세 서비스 호출 테스트 2개로 검증했다. 실제 백엔드 상태 전이/저장까지 수행한 E2E 검증은 아니며, 기존 백엔드 테스트와 코드는 이 작업에서 변경하지 않았다.

## 완료 점검

- 작업지시서 → 계획서 → 상세 사양 → 구현 → 결과/화면 순서 이행.
- 요청한 상세 반려·보완 사유 흐름과 줄바꿈 표시 반영.
- 승인·상신 취소·승인 취소 및 피드 동작 회귀 검증.
- 프론트엔드 빌드 및 지정 너비 브라우저 확인 완료.
- DB 변경 및 마이그레이션 없음.

## 추가 요청 반영: 사유 입력 공통 다이얼로그

- 사용자 승인에 따라 반려·보완요청 사유 입력을 기존 `CommonDialog size="xs"`로 교체했다.
- 공통 헤더/설명/닫기(X)/본문/하단 액션 및 최대 480px 폭을 사용한다. 공통 셸 자체 및 다른 확인 팝업은 변경하지 않았다.
- 닫기(X), 취소, Escape/backdrop에 동일한 초기화 함수를 사용하며 처리 중에는 닫기를 무시한다.
- 여러 줄 입력, 필수 사유, 실패 시 입력 보존/재시도 및 기존 확인 버튼 스타일을 유지했다.
- 공통 셸 연결 검증을 먼저 추가하여 실패 2건을 확인한 뒤 교체했다.
- 최종 검증: 상세/피드 사유 테스트 4개 및 공통 다이얼로그 전체 9개, 총 **13개 통과**. 상세 테스트는 공통 최대 폭·설명 연결·actions 슬롯 및 닫기(X) 초기화도 검증한다.
- TypeScript/Vite 빌드 통과(기존 번들 크기 경고만 유지).
- 기존 비식별 Chromium 시나리오를 재실행하여 375/768/1280px의 반려/보완 팝업과 줄바꿈/요청 본문을 확인하고 위 스크린샷 9개를 갱신했다. 가로 넘침/pageerror 없음. 실제 업무 데이터 쓰기 없음.
