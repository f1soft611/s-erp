# 20261016_006 전자결재 시스템메시지 통합 댓글 페이지 결과 보고서

## 작업 결과

문서작성의 댓글 페이지에서 사용자 댓글 루트와 시스템 메시지를 하나의 최신순 항목 집합으로 조회하도록 변경했다. 기존에는 사용자 댓글 페이지와 전체 시스템 이력을 별도로 다뤄 기본 표시량, 전체 건수, 이전 cursor가 서로 다른 기준을 사용했다.

- 최초 조회는 USER 스레드 루트와 SYSTEM 메시지를 합쳐 최대 3개를 표시하고, 이전 조회는 최대 20개를 요청한다.
- 답글은 USER 루트 스레드 안에 포함하며 페이지 항목/건수에서 별도로 세지 않는다.
- 삭제된 루트라도 삭제되지 않은 답글이 있으면 삭제 표시 스레드로 한 번 포함한다. 루트와 모든 답글이 삭제된 스레드는 제외한다.
- 상세 댓글 API와 문서 피드 선조회가 같은 `comments`, `systemEvents`, `resultCnt`, `hasPrevious`, `nextBeforeCommentId` 계약을 사용한다.
- 시스템 메시지는 기존 읽기 전용 표시를 유지한다. 프런트엔드가 `commentId`, 유형, 소유 문서 등 페이지 응답 필드를 검증하고, 댓글 mutation 대상에 포함하지 않는다.
- 댓글 합계는 통합 `resultCnt`를 그대로 사용한다. 남은 수는 USER 루트 수와 로드된 SYSTEM 수로 계산하며 답글은 제외한다.
- 이전 페이지 요청 실패 시 이미 표시된 항목과 cursor를 유지하고, 재시도는 실패한 동일 cursor로 실행한다.
- 최초 페이지 요청에서는 cursor가 없으므로 cursor CTE와 `comment_id` 비교 자체를 생성하지 않도록 수정했다. 이전 페이지 요청에서만 cursor CTE를 생성한다.

## 변경 파일 및 범위

- 백엔드에 전자결재 전용 페이지 응답 DTO와 혼합 루트 조회, 스레드 조회, 통합 건수, cursor 검증 매퍼 쿼리를 추가했다.
- 사용자 댓글과 시스템 메시지의 기존 테이블 및 저장 정책은 유지했다. 스키마 변경, 공지사항 댓글 변경, 시스템 메시지 생성 규칙 변경은 없다.
- 프런트엔드 타입/서비스에 페이지 SYSTEM 항목 검증을 추가하고, 상세 피드에서 USER와 SYSTEM 목록을 교체/이전 페이지 추가 흐름으로 연결했다.
- 답글 등록은 통합 최상위 항목 건수를 증가시키지 않도록 맞췄다.

## DB 확인

- 구현 전 `s-erp-postgresql-readonly` MCP에서 `tb_common_comment` 테이블 메타데이터를 확인했다. tenant 데이터 행은 조회하지 않았다.
- DB 스키마 변경은 없으며, 매퍼 검증은 MyBatis statement 구성과 동적 SQL 바인딩을 대상으로 수행했다. alias 대소문자는 PostgreSQL SELECT 표현식으로 확인했으나, 실제 댓글/페이지 쿼리를 실행하는 통합 검증은 수행하지 않았다.

## PostgreSQL 타입 오류 후속 수정

- 보고된 `bigint = character varying` 오류의 SQL 위치 2909를 MyBatis 생성 페이지 SQL과 대조했다. 해당 위치는 cursor 조회의 `c.comment_id = ?` 조건이며, 바인딩 목록에서 해당 파라미터는 null인 최초 요청의 `beforeCommentId`였다. `comment_id` 컬럼은 PostgreSQL `bigint`다.
- 원인은 최초 페이지에서도 불필요한 cursor CTE를 만들고 null cursor를 bigint 컬럼과 비교하도록 생성한 SQL이었다. 최초 페이지는 모든 혼합 루트를 대상으로 하므로 cursor CTE가 필요하지 않다.
- cursor CTE를 `beforeCommentId != null`일 때만 생성하고, 최초 페이지에서는 `beforeCommentId` 바인딩 자체가 SQL에서 제외되도록 수정했다. 이전 페이지용 cursor 비교와 strict tuple 경계는 유지했다.
- 회귀 테스트는 수정 전 최초 페이지 SQL에 `beforeCommentId` 바인딩이 남아 실패하는 것을 확인했고, 수정 후 최초 페이지에는 cursor CTE/바인딩이 없으며 이전 페이지에는 모두 포함되는 것을 확인했다.
- 다음 예외(`전자결재 댓글 건수 조회 결과가 올바르지 않습니다`)는 count 쿼리 결과 Map의 키 검증에서 발생했다. PostgreSQL 읽기 전용 조회 `SELECT 1 AS ownerId, 2::bigint AS totalCount` 결과 키가 `ownerid`, `totalcount`로 반환되어 unquoted alias가 소문자로 접히는 사실을 확인했다. 서비스는 `ownerId`, `totalCount` 키를 기대한다.
- count 쿼리 alias를 `"ownerId"`, `"totalCount"`로 따옴표 처리해 PostgreSQL이 camelCase 라벨을 보존하도록 수정했다. PostgreSQL 읽기 전용 SELECT로 unquoted alias가 소문자로 접히고 quoted alias가 camelCase로 유지되는 것을 확인했다. 매퍼 회귀 테스트는 이 alias 계약을 확인한다. 테스트는 수정 전 실패했고, 수정 후 통과했다.
- 실제 댓글 API를 PostgreSQL에 재호출하는 통합 검증은 수행하지 못했다. 생성 SQL과 PostgreSQL alias 동작에 대한 검증은 통과했으나, 공유 런타임의 HTTP 500 해소 여부는 수정된 백엔드를 반영한 환경에서 재확인해야 한다.

## 후속 확인 사항

- 배포/재시작된 백엔드가 반영된 환경에서 문서 상세 댓글 API의 HTTP 500 원인을 확인하고, 실제 USER/SYSTEM 혼합 응답과 이전 페이지 동작을 브라우저에서 재검증한다.
- Mapper 테스트는 PostgreSQL 데이터 실행 검증이 아니므로, 연결된 통합 테스트 환경에서 동일한 쿼리 경계와 tenant/owner 조건을 확인한다.
