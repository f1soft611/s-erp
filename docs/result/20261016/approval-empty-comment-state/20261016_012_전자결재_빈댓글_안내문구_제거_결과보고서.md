# 20261016_012 전자결재 빈 댓글 안내문구 제거 결과보고서

## 변경 내용

- 전자결재 상세 댓글에서 USER 댓글과 SYSTEM 메시지가 모두 없을 때 `등록된 댓글이 없습니다.` 문구를 표시하지 않도록 했다.
- 댓글 입력창과 등록 버튼, 로딩 상태, 오류/재시도, 페이지 이동 및 댓글 렌더링은 유지했다.
- 백엔드, API 및 DB는 변경하지 않았다.

## 변경 파일

- [DocumentApprovalDetailFeed.tsx](../../../../frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx): 빈 상태 문구 조건 렌더링 제거.
- [document-write-page.test.tsx](../../../../frontend/tests/document-write-page.test.tsx): 빈 목록에서 안내 문구가 사라지고 composer가 남는지 검증.
- [상세 사양서](../../../spec/20261016/20261016_006_전자결재_시스템메시지_통합댓글페이지_상세사양서.md): 빈 상태 동작 명시.

## 검증 결과

| 검증 | 결과 |
|---|---|
| `npx vitest run tests/document-write-page.test.tsx -t "hides the empty comment message"` | 통과: 1 passed, 90 skipped |
| `npm run test -- tests/document-write-page.test.tsx` | 부분 실패: 62 passed, 31 failed. 추가한 빈 상태 회귀 테스트는 통과했고, 실패는 다른 approval cancellation, attachment, UI 테스트에서 발생 |
| `npm run build` | 통과. TypeScript와 Vite 빌드 성공; 기존 대용량 청크 경고 출력 |
| 실제 브라우저 검증 | 수행 불가. 공유 브라우저에서 백엔드 CORS/HTTP 500 오류와 `DocumentWritePage` hook 순서 오류가 발생해 빈 댓글 상태를 확인할 수 없었음 |

## 참고

- 전체 테스트 파일에서 실패한 31개 항목은 이번 빈 안내문구 회귀 테스트가 아니다. 동시 수정이 포함된 작업 트리에서 실행되었으므로 이 보고서는 이를 기존 실패로 단정하지 않는다.
- UI 화면에서 빈 상태를 직접 확인하거나 스크린샷을 저장하지 못했다. 브라우저 런타임이 정상화되면 댓글이 비어 있는 문서를 열어 안내문구가 없는지 확인할 필요가 있다.
