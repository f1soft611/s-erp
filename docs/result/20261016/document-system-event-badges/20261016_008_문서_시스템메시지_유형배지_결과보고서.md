# 문서 시스템 메시지 유형 배지 결과보고서

## 최종 수정: 두 취소 배지의 글자색도 빨강

- 사용자 최종 요청에 따라 `결재신청 취소`, `결재 승인 취소` 모두 기존 MUI error/outlined로 표시한다. 글자색과 테두리가 모두 빨강이며 8px 모서리는 유지한다.
- 테두리만 변경하기 위해 추가했던 선택적 borderColor 모델/스타일은 제거하고 기존 Chip color/variant만 사용한다. 실제 문서 상태 및 취소 처리 동작은 변경하지 않는다.
- MUI outlined error의 기본 정책에 따라 light 테마 글자색은 `rgb(211, 47, 47)`, 테두리는 `rgba(211, 47, 47, 0.7)`이다. 테두리의 기존 투명도 정책을 덮어쓰지 않는다.
- 수정 전 매핑/색상 회귀 실패를 확인했으며 최종 관련 테스트 65개 통과, `npm run build` 통과(기존 청크 크기 경고 유지).
- 합성 Chromium에서 375px/768px/1280px 모두 두 취소 배지의 정확한 계산된 글자색/테두리색, 8px 모서리, 가로 넘침 없음 및 JavaScript 오류 없음을 확인했다. 스크린샷도 최종 색상으로 갱신했다.
- 아래 과거 기록의 기본 글자색/테두리 전용 속성 정책은 이 최종 요청으로 대체한다.

## 추가 수정: 승인 취소 누락 및 취소 테두리 빨강

- 재현: `결재 승인이 취소되었습니다.` 시스템 메시지가 안내 아이콘으로 표시된다.
- 원인: `APPROVAL_CANCELED`가 기존 매핑에서 제외되어 있었다. 해당 매핑의 실패 테스트로 누락을 확인했다.
- 수정: `결재 승인 취소` 배지를 추가했다. 후속 사용자 요청에 따라 `결재신청 취소`와 `결재 승인 취소` 모두 테두리만 기존 테마 `error.main` 빨강으로 표시한다. 기본 글자색/outlined/8px 모서리는 유지한다.
- 공통 배지 모델에 선택적 `borderColor`를 추가하고 `sx.borderColor`로 전달한다. 다른 배지에 테두리 색상은 지정하지 않으며 문서 상태, 본문, 페이지, 취소 처리 로직, API/DB 계약을 변경하지 않았다.
- 매핑/빨간 테두리 테스트 4개가 수정 전 실패하는 것을 확인했다. 수정 후 문서 표시 테스트 29개 및 공통 피드 테스트 36개, 총 65개 통과했다.
- `npm run build` 통과. 기존 청크 크기 경고만 표시된다. `git diff --check`로 공백 오류를 점검했다.
- 실제 컴포넌트와 매핑을 import하는 합성 Chromium에서 375px/768px/1280px 모두 배지 8개와 미지원 아이콘 1개를 확인했다. 두 취소 배지의 계산된 테두리 색상이 light 테마의 `rgb(211, 47, 47)`이고 글자색은 그 색상이 아님을 확인했다. 모든 배지의 모서리는 8px이며 가로 넘침과 JavaScript 오류가 없다.
- 아래 스크린샷을 두 취소 배지의 빨간 테두리가 포함된 화면으로 갱신했다. 기존 개발 서버를 재사용하고 검증용 Chromium은 종료했다.
- 아래 과거 기록의 취소 기본색 테두리 정책은 이 요청으로 대체한다.

## 추가 수정: 결재신청 취소 배지

- 재현: `결재신청이 취소되었습니다.` 시스템 메시지에 배지 대신 안내 아이콘만 표시된다.
- 원인: 기존 배지 매핑에서 `SUBMISSION_CANCELED`를 제외하여 공통 댓글 컴포넌트의 기본 아이콘 표시로 처리되었다.
- 사용자 승인 기준: `결재신청 취소` 명칭, 기존 DRAFT의 default/outlined, 기존 `8px` 모서리를 재사용한다.
- 수정: 문서 표시 데이터의 `SUBMISSION_CANCELED` 매핑만 추가했다. 공통 댓글 UI, 본문, 이벤트 생성, API/DB 계약은 변경하지 않았다. `APPROVAL_CANCELED` 등 다른 이벤트는 이번 범위에 포함하지 않는다.
- 회귀 검증: 구현 전 `SUBMISSION_CANCELED` 매핑 테스트가 `undefined`로 실패하는 것을 확인했다. 구현 후 `document-presentation.test.ts` 29개 및 `feed-components.test.tsx` 33개, 총 62개 통과했다. 취소 명칭, 기본색/테두리, 8px 모서리, 시스템 항목 읽기 전용 및 기존 일반 댓글 동작을 검증했다.
- `npm run build`: 종료 코드 0으로 통과했다. 기존 1000kB 초과 청크 경고는 유지된다. 앞선 후속 수정 시점의 빌드 제한은 이번 실행에서 재현되지 않았다.
- 실제 컴포넌트와 표시 매핑을 import하는 합성 Chromium 검증에서 375px/768px/1280px 모두 배지 7개와 미지원 아이콘 1개를 확인했다. 결재신청 취소 Chip의 default/outlined 클래스와 모든 배지의 계산된 8px 모서리를 확인했고 페이지 가로 넘침 및 JavaScript 오류는 없었다. 아래 세 스크린샷을 최신 화면으로 갱신했다.
- 기존 4173 서버를 재사용했으며 검증용 Chromium은 종료했다. 실제 계정/테넌트 데이터를 캡처하지 않았다.

## 후속 수정: 모서리 통일 및 완료 이벤트

### 원인

- 시스템 배지는 MUI Chip 기본 모서리를 사용했으나 기존 문서 상태 배지는 `DocumentApprovalDetailFeed.tsx`의 `approvalBadgeBorderRadius='8px'`을 사용하여 모양이 달랐다.
- 최초 작업에서는 요청된 다섯 이벤트만 매핑하고 `COMPLETED`를 미지원 유형으로 두었다. 기존 순차처리 사양 및 서버 코드는 개별 승인 `APPROVED` 외에 최종 완료 시 `COMPLETED`와 `문서 결재가 완료되었습니다.` 메시지를 별도로 기록한다. 따라서 데이터 누락이 아니라 표시 매핑 누락이었다.

### 수정

- 시스템 메시지 배지의 border-radius를 기존 문서 상태 배지와 동일한 `8px`로 지정했다.
- `COMPLETED` 이벤트는 `완료`, 기존 success/filled로 표시한다. `APPROVED`는 계속 `승인`으로 표시한다.
- 문서 상태 자체의 기존 명칭이나 이벤트 생성/API/DB 계약은 변경하지 않았다.
- 아래 최초 결과에 기재된 다섯 유형/미지원 완료 정책은 이 후속 수정으로 대체한다.

### 검증

- 구현 전 완료 매핑 1개 및 여섯 배지 모서리 테스트 6개 실패를 확인했다.
- `document-presentation.test.ts` 23개와 `feed-components.test.tsx` 31개 모두 통과했다.
- 상세 시스템 메시지 테스트 1개 통과. 확장된 여섯 이벤트 피드 테스트는 빌드와 동시 실행 시 5초 제한을 한 번 초과했으나, 단독 재실행에서 3.5초에 통과했다. 재실행 명령은 `node .\node_modules\vitest\vitest.mjs run tests\document-write-page.test.tsx --testNamePattern='renders type-specific system badges' --testTimeout=20000`이다.
- 합성 Chromium 페이지에서 375px/768px/1280px 각각 배지 6개, 미지원 유형 아이콘 1개, 조작 버튼 0개를 확인했다. 각 배지의 `getComputedStyle(...).borderRadius`가 정확히 `8px`이고 페이지 가로 넘침이 없음을 확인했다. 아래 스크린샷을 완료 배지가 포함된 최신 화면으로 교체했다.
- 후속 빌드는 이 작업에서 수정하지 않은 `frontend/src/pages/groupware/documents/write/services/documentApproval.service.ts`의 진행 중인 변경 때문에 실패했다. 최초 실행은 필수 `systemEvents` 반환 누락, 재실행은 320행 `number | undefined`를 `number`에 할당하는 TS2322 오류였다. 해당 서비스는 검증 중에도 변경되고 있어 무관한 수정 충돌을 피하려고 수정하지 않았다. 현재 전체 빌드 통과는 미확인이다.

문서 피드 및 상세 패널의 시스템 메시지에 `eventType`별 배지를 전달한다.

| 유형 | 명칭 | 기존 상태 color / variant |
|---|---|---|
| DRAFT_SAVED | 임시저장 | default / outlined |
| SUBMITTED | 결재신청 | info / filled |
| REJECTED | 반려 | error / filled |
| APPROVED | 승인 | success / filled |
| RETURNED | 보완요청 | warning / filled |

기존 상태 표시 함수에서 색상과 variant를 가져오며 새 색상값을 정의하지 않았다. 지원 유형은 안내 아이콘을 배지로 교체하고 미지원 유형은 기존 아이콘을 유지한다. 시스템 메시지 헤더만 줄바꿈을 허용한다.

메시지 본문/작성자/시각, 읽기 전용 제한, 일반 댓글과 공지사항 동작은 유지한다. 기존 작업 중인 통합 댓글 페이지 및 반려 사유 표시 변경을 보존했다. 백엔드/API/DB 계약은 변경하지 않았으며 이 작업에서 DB MCP 조회나 데이터 변경을 수행하지 않았다.

## 실제 브라우저 검증

4173에서 이미 실행 중인 Vite 서버를 재사용했다. 별도 서버를 시작하거나 기존 서버를 종료하지 않았다. 격리된 Chromium에서 라우트로 제공한 합성 페이지가 실제 `CommentThread`, 이벤트 표시 매핑, 앱 테마를 직접 import하여 렌더링한다. 실제 테넌트 행, 계정, 인증 정보는 사용하거나 캡처하지 않았다. 앱 전체 페이지 배치가 아니라 시스템 메시지 컴포넌트의 반응형 렌더링 검증이다.

- 다섯 배지의 텍스트가 정확히 일치함.
- 미지원 유형 안내 아이콘 1개 유지.
- 시스템 항목 조작 버튼 0개.
- 375px / 768px / 1280px 각각 문서 scrollWidth가 viewport 너비와 일치.
- 다섯 배지 모두 뷰포트 안에서 양의 너비/높이로 표시.
- 최종 실행에서 브라우저 JavaScript 오류 없음. Chromium은 검증 후 종료했다.
