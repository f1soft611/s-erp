# 20261015_002 업무작성 자주 쓰는 결재선 결과 보고서

## 1. 작업 결과

업무작성 모달의 결재선 설정 창에 사용자별 자주 쓰는 결재선 템플릿 기능을 구현했다. 서버에 여러 템플릿을 저장하고, 현재 문서 종류의 템플릿만 불러와 이름 변경 및 삭제할 수 있다.

- 문서 코드별 분리: 기안 `001`, 업무 `008`, 지출 `004`, 근태 `031`
- 결재·합의 단계와 참여자 순서, 참조자를 저장하고 다시 불러온다.
- 고정 기안자 단계는 템플릿에 넣지 않으며 현재 작성자의 단계로 유지한다.
- 불러오기는 결재선 설정 창의 임시 상태만 교체한다. 작성 화면에는 기존 `적용`을 눌렀을 때만 반영되고, 취소/닫기는 임시 변경을 폐기한다.
- 저장 및 불러오기 실패 시 오류를 표시하고 기존 임시 상태를 보존한다.
- 서버는 인증된 사용자와 tenant로 소유권을 검증한다.

## 2. 구현 범위

- 백엔드에 템플릿 목록·상세·생성·이름 변경·삭제 API와 서비스 검증을 연결했다.
- 프론트엔드 API 서비스에 타입, 요청/응답 검증과 CRUD 호출을 추가했다.
- 결재선 설정 창에 저장, 불러오기, 이름 변경, 삭제 및 삭제 확인 흐름을 연결했다.
- 템플릿 참여자 ID가 현재 활성 사용자 목록에 모두 존재하는지 확인한 후에만 임시 결재선에 반영한다.
- DB 변경 스크립트, 변경 이력, 롤백 및 누적 스키마를 날짜별 관리 절차에 반영했다. DB 마스터/상세 테이블을 사용하며 기존 문서 결재 처리 테이블은 재사용하지 않는다.

## 3. 검증 결과

| 검증 | 결과 |
|---|---|
| 프론트엔드 결재선 템플릿 서비스 및 설정 창 테스트 | 19개 통과 |
| 프론트엔드 빌드 (`npm run build`) | 성공 |
| 관련 업무작성 페이지 테스트 포함 실행 | 총 102개 중 101개 통과, 1개 실패 |
| 백엔드 API·서비스·매퍼 테스트 | 16개 통과 |
| 백엔드 결재선 템플릿 서비스 테스트 (`ApprovalLineTemplateServiceImplTest`) | 8개 통과 |
| 백엔드 패키징 (`mvn -f backend/pom.xml -DskipTests package`) | 성공 |
| `git diff --check` | 오류 없음 |
| `docs/database/20261015`와 `backend/DATABASE/20261015`의 파일 비교 | 동일 |

검증 중 이름 길이 테스트에서 Java 11에 추가된 `String.repeat()` 사용이 발견되어, Java 8 호환 API인 `String.join()`과 `Collections.nCopies()` 조합으로 교체했다. 결재선 템플릿 서비스 테스트 8개를 다시 실행해 모두 통과했다.

업무작성 페이지 테스트의 단일 실패는 `renders compact accessible badges, seals, removal actions, and ellipsized names` 테스트의 참여 순번 배지 `toHaveStyle` assertion이다. 결재선 템플릿 테스트는 통과했으며, 이 실패는 템플릿 기능 검증과 무관한 기존 참여자 표시 스타일 검사다. 앞선 기준 실행에서도 해당 업무작성 테스트 파일에는 기존 실패가 보고되어 있었다.

브라우저에서 저장 다이얼로그를 확인하고 캡처했으나, 통합 브라우저의 뷰포트 값과 실제 `visualViewport`가 일치하지 않는 경우가 있었다(요청 너비 375/768/1280에서 실제 너비가 각각 250/512/853으로 보고된 실행이 있음). 따라서 캡처는 렌더링 참고 자료이며, 세 너비 각각에서의 정확한 픽셀 단위 반응형 검증을 완료했다고 간주하지 않는다.

## 6. 후속 변경: F1-Grid 템플릿 관리

업무작성의 결재선 설정에서 자주 쓰는 결재선을 관리하는 화면을 F1-Grid로 전환했다.

- `결재선명` 셀에서 이름을 인라인 편집하고, 하단 `저장`으로 수정된 이름을 일괄 저장한다.
- 행별 `적용`과 `삭제` 액션은 해당 행의 템플릿만 처리한다.
- 빈 이름·100자 초과·중복 이름을 저장 전에 검증한다. 일부 이름 변경만 실패하면 성공 행은 반영하고 실패 행의 수정값은 재시도할 수 있게 유지한다.
- 저장하지 않은 이름 수정이 있을 때 행별 적용·삭제·관리 창 닫기를 요청하면 폐기 확인을 표시한다. 취소하면 편집 내용과 요청 동작을 보존한다.
- 최초 원인 분석에서는 드래그 범위 선택을 문제로 잘못 판단했다. 사용자 확인 후 실제 재현은 결재선명을 편집한 뒤 같은 Grid의 다른 셀을 클릭해도 기존 editor가 열린 채로 남고 dirty 변경이 반영되지 않는 현상임을 확인했다.
- 첫 수정은 같은 Grid 안의 다른 셀 포커스 이동은 해결했으나, 모달 footer/toolbar를 클릭하는 흐름은 해결하지 못했다. document-level mousedown handler도 모든 `.MuiModal-root`를 editor popup처럼 취급하고 있었기 때문이다.
- 실제 editor popup은 클릭/포커스 도착 대상이 popup 안에 있고 해당 popup이 Grid를 감싸지 않는 경우로 판별하도록 고쳤다. 중첩 모달의 저장/닫기 버튼 클릭은 편집을 먼저 commit해 dirty/save 상태가 갱신되며, 실제 Grid 외부 editor popup 클릭은 계속 commit을 보류한다.
- 잘못된 진단에 따라 추가했던 `disableCellRangeSelection` 옵션과 관리 Grid 적용은 제거했다. 기존 셀 범위 선택 기본 동작은 유지한다.
- 기존 결재선 임시 적용 경계와 CRUD API 계약은 유지했다. 백엔드와 DB는 변경하지 않았다.

| 검증 | 결과 |

| 결재선명 편집 후 다른 셀 클릭 시 commit/dirty/save 및 rename API 회귀 테스트 | 통과 |
| 결재선명 편집 중 모달 저장 액션 클릭 및 rename API 회귀 테스트 | 통과 |
| 이름 변경 확인창의 취소/계속 동작 회귀 테스트 | 3개 통과 |
| 공통 F1-Grid 기본 범위 드래그 선택 동작 | 변경하지 않음 |
| F1-Grid 포털/사용 가이드 테스트 | 28개 통과 |
| F1-Grid 편집 모달 회귀 테스트 | 통과 |
| 프론트엔드 빌드 (`npm run build`) | 이번 실행은 실패: 병행 변경된 `useDocumentComposer.ts` 890-891행에서 `attachment.file` nullable TypeScript 오류 |
| 지정 프론트엔드 파일 Problems 진단 | 오류 없음 |
| 전체 F1-Grid 핵심 및 문서 테스트 일괄 실행 | 184개 중 136개 통과, 48개 실패(타임아웃·접근성 조회·스타일 assertion 포함); 별도 집중 회귀 및 문서 테스트는 통과 |
| 브라우저 375px / 768px / 1280px | 기존 검증에서 요청 폭과 `innerWidth`/`visualViewport`가 일치했고, 각 폭에서 페이지 가로 넘침이 없었음 |
| 캡처 데이터 | 합성 템플릿만 사용. 현재 캡처는 행 액션 이름 변경 전의 이미지이며 실제 사용자·문서 데이터는 포함하지 않음 |

이름 변경 확인창 테스트는 버튼 의미에 맞춰 취소 시 변경을 유지하고, 계속 시 요청 작업을 진행하도록 검증한다. 설정 창 및 서비스 집중 테스트는 `--testTimeout=15000`으로 실행했다. 현재 프론트엔드 빌드 실패는 결재선/F1-Grid 변경 파일 진단이 아니라 `useDocumentComposer.ts`의 nullable 타입 오류다.

캡처 파일은 결재선 관리 모달만 포함한다.

참고: 기존 캡처의 행 액션 레이블은 `불러오기`이며, 현재 화면의 레이블 `적용`과 일치하지 않는다. 현재 세션에서 브라우저 연결을 사용할 수 없어 캡처는 다시 생성하지 않았다. 화면 구조 참고용이며 최신 레이블의 시각적 검증 자료로 보지 않는다.
