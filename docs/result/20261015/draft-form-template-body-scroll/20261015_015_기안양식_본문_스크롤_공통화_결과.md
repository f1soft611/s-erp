문서 양식 작성/수정 모달은 기존 `CommonDialog` 셸을 계속 사용한다. 에디터 프레임의 위·아래 구분선을 제거하고, 편집기 내부의 세로 스크롤 대신 공통 다이얼로그 본문이 스크롤하도록 바꿨다. 제목과 푸터의 툴바/저장/취소는 고정된다.

`RichTextEditor`에는 선택형 `scrollMode`를 추가했다. 기본값 `editor`는 기존 내부 스크롤을 유지하고, 기안양식 편집 모달만 `container`를 사용하므로 공지사항 작성 등 기존 소비 화면의 동작은 유지된다.

## 검증 결과

### 자동 검증

- 통합 Vitest:

```powershell
npx vitest run tests/draft-form-template-dialog.test.tsx tests/rich-text-editor.test.tsx tests/notice-composer-dialog-theme.test.tsx --reporter=verbose --testTimeout=30000
```

결과: 3개 테스트 파일, 45개 테스트 모두 통과. 기본 편집기 스크롤 동작과 공지 작성 모달 회귀 테스트도 통과했다.

- `npm run build`: 통과. 번들 크기 1000 kB 초과 경고가 있으나 빌드는 완료됐다.
- 변경 파일 `npm run lint -- ...`: 종료 코드 0. 기존 `set-state-in-effect` 및 `only-export-components` 경고가 출력됐으며 이번 변경으로 수정한 코드에서는 lint 오류가 없다.
- Problems: 변경된 소스/테스트 파일 오류 없음.
- `git diff --check`: 오류 출력 없음.

최초 기준 실행에서 RichTextEditor 테스트 1건이 실패했으나, 개별 실행과 통합 재실행에서는 재현되지 않았고 최종 통합 실행에서 모두 통과했다. 신규 레이아웃 회귀 테스트는 구현 전에 구분선/내부 스크롤 계약 불일치로 실패하는 것을 확인한 뒤 구현 후 통과했다.

### 브라우저 확인 및 스크린샷

대상 모달의 375px, 768px, 1280px 실제 화면 확인과 스크린샷은 수행하지 못했다. 공유 브라우저의 `openBrowserPage`/`readPage` 연결이 CDP 타임아웃으로 실패했다. 설치된 로컬 Playwright로 별도 접속도 확인했지만 인증되지 않은 세션이 `/login`으로 이동해 기안양식 화면에 접근할 수 없었다. 인증 상태를 변경하거나 임의 계정으로 접근하지 않았으며, 따라서 이 결과 폴더에는 화면 스크린샷이 없다.

## 범위 및 후속 영향

- `CommonDialog` 구현, 문서 작성/공지사항 작성의 기본 편집기 스크롤, API, 백엔드 및 DB는 변경하지 않았다.
- 실제 뷰포트별 브라우저 확인은 인증된 브라우저 세션을 사용할 수 있을 때 보완할 수 있다.
- 작업 중 공유 작업공간의 `f1e2257` 커밋이 생성되어 본 작업의 소스/테스트/계획 파일도 함께 포함됐다. 해당 커밋에는 이번 범위 밖의 변경도 포함되어 있으며, 이 실행에서는 커밋을 추가 생성하거나 해당 변경을 되돌리지 않았다.
