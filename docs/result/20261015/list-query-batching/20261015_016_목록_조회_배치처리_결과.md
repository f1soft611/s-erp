# 20261015_016 목록 조회 배치 처리 결과

## 결과 요약

공지사항 목록과 전자결재 피드 내부의 문서/게시글별 관계 조회를 ID 목록 기준 batch 조회로 변경했다. 사용자 API 경로와 응답 DTO는 유지했으며, 한 개의 거대 SQL로 합치지 않고 관계 종류별 조회 횟수가 결과 행 수에 따라 증가하지 않도록 했다.

## 변경 사항

### 공지사항 목록

- 목록 결과가 비어 있으면 댓글/파일 관계 조회를 생략한다.
- 공지 댓글을 페이지 형태로 batch 조회하고, 기존 단건 count와 같이 삭제되지 않은 최상위 댓글만 `commentCount`에 포함한다.
- 최신 3개 root group 및 답글을 반환하고, `hasPreviousComments`와 `nextBeforeCommentId`를 추가 root sentinel로 복원한다.
- 댓글 첨부 대상 ID를 목록 전체에서 모아 `NOTICE_COMMENT` 파일을 한 번 batch 조회한다.
- 삭제된 댓글에는 첨부파일을 붙이지 않는다.

### 전자결재 피드

- 문서 상세를 tenant, 기안자/결재 참여자 predicate가 포함된 batch SQL로 조회한다. 상세가 조회되지 않은 문서는 다른 관계 쿼리 전에 기존과 같이 404로 종료한다.
- 결재선, 사용자 댓글 페이지/최상위 댓글 수, 댓글 첨부를 문서 ID 전체 기준으로 batch 조회한다.
- 기존 batch 문서 파일/시스템 이벤트 조회를 유지한다.
- 댓글 수는 삭제되지 않은 최상위 `USER` 댓글 수이며, 최신 3개 root group, 답글 및 페이지 metadata를 유지한다.
- 내부 결재선 batch ID는 기존 `DocumentApprovalLineVO`로 복사해 API 응답에 그룹화용 필드를 추가하지 않는다.
- 피드 목록 조회는 뷰 이력/조회수를 갱신하지 않는다. 상세 API 동작은 변경하지 않았다.

## 조회 구조 비교

| 영역 | 변경 전 | 변경 후 |
|---|---|---|
| 공지 댓글 첨부 | 게시글 hydrate마다 별도 batch 호출 | 페이지 내 댓글 ID 전체로 최대 한 번 |
| 공지 댓글 페이지 metadata | flat comment batch 및 고정 `false`/`null` | root sentinel 기반 페이지 응답, root-only count |
| 전자결재 피드 상세/결재선 | 문서별 권한 확인, 상세, 결재선 조회 | 문서 ID 전체 상세/결재선 batch 조회 |
| 전자결재 사용자 댓글/수/첨부 | 문서별 페이지, count, 첨부 조회 | owner ID 전체 댓글 페이지/count batch 및 첨부 한 번 |

이 변경은 브라우저 HTTP 요청을 하나로 합치는 작업이 아니다. 피드 API는 이미 목록을 한 HTTP 요청으로 반환하며, 이번에는 해당 서비스 내부 DB의 문서별 N+1 조회를 제거했다. StrictMode, 고정 공지 요청, 요약 API, 상세 패널 추가 요청은 변경하지 않았다.

## DB 계약 및 변경 여부

- PostgreSQL read-only MCP의 `list_tables` 및 `describe_table` 결과로 `tb_common_comment`, `tb_common_file`, `tb_board_post`, `tb_electronic_approval_main`, `tb_electronic_approval_line_info`의 관련 owner/tenant/type/삭제/상위 댓글 컬럼을 확인했다.
- MCP로 행 데이터를 조회하거나 기록하지 않았다.
- DB schema/DDL 및 데이터 변경은 없다. 따라서 날짜별 SQL migration, schema 누적 문서 수정은 비대상이다.
