# 문서 작성 첨부파일 상태 뱃지 결과보고서

## 작업 요약

문서작성 모달의 첨부파일 상태를 파일 박스 아래의 문장 대신 파일 행 내부의 짧은 뱃지로 표시했다. 뱃지는 파일명과 제거 동작 사이에 배치했으며, 실패 재시도 및 업로드 상태 확인 동작을 같은 행에 유지했다.

| 업로드 상태 | 표시 |
|---|---|
| `uploaded` | 초록 `완료` |
| `pending` | 중립 `대기` |
| `failed` | 빨강 `실패` |
| `unknown` | 황색 `확인 필요` |

공용 `AttachmentList`에는 선택적 상태 뱃지 슬롯만 추가했다. 슬롯을 전달하지 않는 기존 호출부의 기본 표시 동작은 유지한다. 업로드 상태 전이, API, 데이터 계약은 변경하지 않았다.

## 변경 파일

- `frontend/src/shared/components/feed/AttachmentList.tsx`
  - 선택적인 `statusBadge`를 파일명 다음, 기존 제거/다운로드 버튼 직전에 렌더링한다.
- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`
  - 4개 업로드 상태를 승인된 라벨과 색상으로 표시하고, 기존 아래쪽 상태 설명 문구를 제거했다.
  - `재시도`와 `상태 확인` 동작을 뱃지 옆에 유지했다. 저장 중 비활성화와 unknown 상태의 기존 제거 제한도 유지했다.
- `frontend/tests/document-write-page.test.tsx`
  - 완료/대기/실패/확인 필요 뱃지, 뱃지와 제거 버튼의 순서, 기존 아래쪽 문구 부재, 재시도 및 상태 확인 액션을 검증한다.

## 검증 결과

- 회귀 테스트:
  - `npx vitest run tests/document-write-page.test.tsx -t "shows and preserves existing attachments|keeps failed attachments and retries them individually|marks an ambiguous upload as unknown and does not retry it automatically" --testTimeout=20000`
  - 결과: 선택한 3개 테스트 통과, 82개 미선택.
  - 새 완료 뱃지 검증은 구현 전 `document-composer-attachment-status` 요소 부재로 실패함을 확인한 뒤 구현했다.
- 테스트 시간 제한 참고:
  - 기존 5초 테스트 기본 제한으로 `상태 확인` 시나리오가 구현 전 단독 기준 실행에서 시간 초과됐다. 최종 검증은 명령행에서만 20초 제한을 적용했으며, Vitest 설정이나 개별 테스트의 영구 제한은 변경하지 않았다.
- 프로덕션 빌드: `npm run build` 성공. 기존 1MB 초과 번들 경고가 출력됐다.
- Problems: 수정한 두 컴포넌트와 테스트 파일 모두 오류 없음.
- `git diff --check`: 공백 오류 없음.

## 브라우저 확인

`http://127.0.0.1:4173/groupware/documents/write`에 접근했을 때 `/login`으로 이동해 인증된 작성 모달을 확인할 수 없었다. 따라서 화면 스크린샷은 생성하지 않았으며, DOM 회귀 테스트와 빌드로 검증했다.

## 범위 확인

- 백엔드, DB, API 데이터 계약 변경은 없다.
