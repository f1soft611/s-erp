# 20261015_019 문서 수정 이미지 리사이즈 미리보기 결과보고서

## 작업 요약

문서 수정 모달에서 기존 본문 이미지를 리사이즈하면 인증 Blob 미리보기가 사라지고 보호 API 주소로 되돌아가던 문제를 수정했다. 편집기 모델은 원래 이미지 URL을 그대로 보유하고, TipTap 업데이트 후 화면 DOM에만 Blob 미리보기를 다시 적용한다.

리사이즈 시 사용자가 조정한 너비/높이는 기존처럼 ProseMirror 모델에 남고, 저장 HTML/JSON에는 원래 전자결재 이미지 URL과 조정된 크기가 저장된다. Blob URL은 저장 콘텐츠에 포함되지 않는다. Blob 로드 실패 이미지는 이후 편집기 업데이트에서도 `src`를 제거한 상태로 유지한다.

## 원인

기존 이미지 Blob 로드 후 `useDocumentComposer`가 현재 `<img>` DOM의 `src`만 Blob URL로 변경했다. 이미지 리사이즈는 TipTap의 `updateAttributes('image', { width, height })`를 호출해 이미지를 다시 렌더링하므로, ProseMirror 모델에 남아 있던 보호된 API URL이 DOM에 복원됐다. 인증 헤더 없는 이미지 요청이 실패하며 엑박이 나타났다.

## 변경 파일

- `frontend/src/pages/groupware/documents/write/hooks/useDocumentComposer.ts`
  - 기존 승인 이미지 원본 URL과 Blob URL을 매핑하고, 에디터 업데이트 후 현재 DOM에 미리보기를 다시 적용한다.
  - 실패 원본 URL은 업데이트 후에도 이미지 `src`를 제거한다.
  - effect 정리 시 업데이트 리스너를 해제하고 DOM의 Blob URL을 원본으로 복원한 뒤 object URL을 해제한다.
- `frontend/tests/document-write-page.test.tsx`
  - 실제 southeast 리사이즈 핸들 이벤트를 통해 재현 및 회귀를 검증한다.
  - 리사이즈 후 Blob `src`, 너비 `400px`, 높이 `250px`, 저장 HTML/JSON의 원본 URL 및 치수를 확인하고 Blob URL 부재를 확인한다.
- 관련 설계, 작업지시서, 계획서, 상세 사양서 및 결과보고서를 추가했다.

## 브라우저 확인

`http://127.0.0.1:4173/groupware/documents/write` 접속이 `/login`으로 이동했고, 인증 갱신 요청에 연결할 수 없어 수정 모달에서의 직접 리사이즈 시각 검증은 수행하지 못했다. 인증 우회는 하지 않았다. 따라서 스크린샷은 만들지 않았으며 실제 resize handle 동작은 DOM 통합 회귀 테스트로 검증했다.
