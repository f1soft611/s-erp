# 문서 결재 툴바 재배치 결과

## 적용 내용

- 문서 피드/상세에서 사용하는 결재 툴바 레이아웃을 문서 기능 전용 컴포넌트로 분리했습니다.
- 승인 액션, 결재상태, 구분선, 상단고정, 더보기, 문서구분 순서를 유지하도록 구성했습니다.
- 기존 결재 권한 및 액션 처리 로직은 상세 피드 컴포넌트에 두고, 툴바 컴포넌트는 배치와 간격만 담당합니다.
- 실제 브라우저의 진행 중 문서 상세에서 상신 취소 버튼, 결재상태, 구분선, 상단고정, 문서구분을 확인했습니다. 더보기 메뉴는 표시되지 않아 이 상태에서 삭제 메뉴에 접근할 수 없었습니다.
- 상세 화면에서 결재선이 표시된 상태를 확인했습니다. 본문 접힘 전환에 따른 결재선 숨김 동작은 직접 전환하지 못했고, 툴바의 취소/삭제 요청도 실행하지 않았습니다.

## 검증 결과

| 항목 | 결과 |
|---|---|
| `npx vitest run tests/document-approval-toolbar.test.tsx` | 통과: 2 tests |
| Frontend Problems 검사 | 툴바 및 통합 컴포넌트 오류 없음 |
| `npm run build` | 통과. 기존 큰 번들 경고 출력 (index JS 1,052.87 kB) |
| `git diff --check` | 통과 |
| 실제 문서 상세 화면 | 1280px에서 툴바 표시 확인. 375px에서는 페이지 영역이 뷰포트 바깥으로 밀려 상세 패널이 잘림 |
| `mvn spring-boot:run` | 실행 불가: 8080 포트를 이미 사용 중인 프로세스가 있어 백엔드가 시작되지 않음. 기존 프로세스는 중단하지 않음 |

초기에는 문서 상세 API가 `ERR_CONNECTION_REFUSED`였으나, 이후 기존 `localhost:8080` 서비스에서 문서 상세가 표시되었습니다. 새 백엔드 실행은 포트 점유로 시작되지 않아 기존 프로세스는 중단하지 않았습니다. 상세 화면의 1280px 스크린샷에서는 결재 툴바를 확인했으며, 375px 스크린샷과 DOM 측정에서 문서 페이지 영역이 `x=380, width=0`으로 뷰포트 밖에 위치하는 문제를 확인했습니다. 이는 툴바 자체가 아니라 앱 셸/오버레이 배치 영역에서 발생한 것으로 보여 이번 범위에서는 수정하지 않았습니다.

## 후속 확인

375px 상세 패널 잘림은 후속 작업으로 페이지 루트의 최소 너비를 제한해 수정했습니다. 구현 및 검증 내역은 [반응형 너비 수정 결과](../document-write-responsive-width/20261015_010_document_write_responsive_width_result.md)를 참고합니다. 본문 접힘 전환에 따른 결재선 숨김 동작은 여전히 실제 브라우저에서 직접 확인하지 않았습니다.
