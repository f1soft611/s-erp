## 재현 조건 및 원인

`disableFiltering`과 `disableSorting`이 모두 활성화되어 필터 해제/정렬 해제 메뉴가 숨겨지면, 행 작업 뒤 구분선과 설정 복원 앞 구분선이 연속으로 표시됐다. 해제 작업 그룹이 비어 있는데도 해당 그룹 앞 구분선이 항상 렌더링된 것이 원인이다.

## 수정 내용

- 필터 해제/정렬 해제 중 하나라도 표시될 때만 해당 그룹 앞 구분선을 렌더링한다.
- 두 항목이 모두 숨겨질 때는 그룹 앞 구분선을 생략하고 설정 복원 앞 구분선만 유지한다.
- 일반 F1Grid에서 한 항목만 보이는 경우의 메뉴 순서/구분선과 기존 항목 동작을 유지한다.
- 테스트와 F1-Grid 컨텍스트 메뉴 문서를 갱신했다.

## 검증 결과

- 회귀 테스트: `npx vitest run tests/f1-grid-context-menu.test.tsx -t "clear-action group divider"` — 통과 (2 tests).
- 전체 컨텍스트 메뉴 테스트 파일: `npx vitest run tests/f1-grid-context-menu.test.tsx` — 최종 실행에서 27개 중 25개 통과, 2개 실패.
  - F1Tree 정렬 메뉴 테스트에서 `내림차순 정렬` 항목 조회 실패
  - F1Tree 필터 메뉴 테스트에서 `필터` 항목 조회 실패
  - 두 실패는 수정 전 기준 실행에서도 재현되어 본 작업에서 변경하지 않았다. 기준 실행에서 추가로 나타난 엑셀 내보내기 테스트 시간 초과는 최종 실행에서 재현되지 않았다.
- 프론트엔드 빌드: 최종 `npm run build`는 F1-Grid 외의 진행 중인 변경인 [DocumentComposerDialog.tsx](../../../../frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx) 16행에서 사용하지 않는 `Typography` import(TS6133) 오류로 중단됐다. 본 작업 파일의 Problems 검사는 오류가 없었다. 앞선 빌드 실행에서는 통과했으나, 최종 상태 기준으로는 위 무관 변경 오류가 남아 있다.
- 브라우저: `/f1-grid-docs`의 F1-Tree 예제로 검증했다. 375px, 768px, 1280px 뷰포트에서 필터/정렬 해제 항목이 숨겨지고 구분선 두 개(상단 액션/설정 복원 경계)만 표시됐으며, 메뉴가 각 viewport 안에 들어왔다.
- 1280px 브라우저 캡처: [context-menu-disabled-clear-actions.png](./screenshots/context-menu-disabled-clear-actions.png)

## 회귀 테스트 세부 사항

- 두 해제 항목을 모두 숨기는 경우 메뉴 구분선 수가 3개에서 2개로 줄어드는지 검증한다.
- 필터 해제만 숨기고 정렬 해제가 표시되는 경우 구분선 3개가 유지되는지 검증한다.
