# 20261012_001 문서작성 저장 피드백 및 로딩 개선 결과

## 작업 결과

- 문서 임시저장 성공은 공통 `NotificationContext` 토스트로만 알리고, 다이얼로그 안에 성공 Alert를 중복 표시하지 않습니다.
- 문서 저장 및 첨부 후속 처리의 실패·미확정 상태는 다이얼로그 상단 오류 영역에 표시하며 기존 문서 ID와 첨부별 재시도 상태를 유지합니다.
- 초기 작성 정보 조회와 기안양식 본문 조회 중에는 탭 아래 전체 본문을 중앙 로딩 스피너로 대체합니다. 공통 헤더와 footer는 유지하고 폼 입력, 탭, 첨부 및 저장 동작을 비활성화합니다.
- 로딩 중 기존 폼 subtree를 마운트된 상태로 숨겨 조회 완료 후 에디터와 작성 상태가 유지되도록 했습니다.
- 문서 저장 API, 첨부 API, 서버 동작 및 DB 계약은 변경하지 않았습니다.

## 브라우저 확인

초기 조회와 기안양식 조회 중 공통 제목 및 footer가 유지되고 중앙 스피너가 표시되는 것을 확인했습니다. 초기 조회 지연을 해제한 뒤 기안양식 필드와 작성 폼이 복구되는 것도 확인했습니다. 브라우저 도구에 요청한 화면 크기별 초기 로딩 캡처:

- 초기 조회: [375](./screenshots/composer-loading-375.png), [768](./screenshots/composer-loading-768.png), [1280](./screenshots/composer-loading-1280.png)
- 기안양식 조회: [375](./screenshots/composer-template-loading-375.png), [768](./screenshots/composer-template-loading-768.png), [1280](./screenshots/composer-template-loading-1280.png)
- 폼 복구: [1280](./screenshots/composer-ready-1280.png)

브라우저 도구에 375px, 768px, 1280px 화면 크기를 요청했을 때 문서의 `clientWidth`는 각각 277px, 450px, 853px으로 보고됐습니다. 각 크기에서 `body.scrollWidth`는 `clientWidth`와 같아 문서의 수평 overflow는 없었습니다. 이 렌더러가 요청한 화면 크기와 문서 내부 CSS viewport를 다르게 보고하므로, 정확히 375/768/1280 CSS px인 독립 viewport 검증이 필요한 경우에는 별도 브라우저 환경에서 추가 확인해야 합니다.

- 문서 API/DB 계약에는 변경이 없습니다.
