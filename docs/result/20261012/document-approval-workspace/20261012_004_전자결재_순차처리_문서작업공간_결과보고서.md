## 결과 요약

- 결재 신청·순차 승인·합의·반려·보완요청·재상신과 공통 시스템 이력 연결을 구현했다.
- 문서 목록·요약·상세·결재 액션과 작성 화면의 저장/상신 흐름을 API에 연결했다.
- 보완요청 문서를 작성 화면에서 다시 여는 회귀 테스트를 지원되는 기안서 유형으로 정정했다. 비활성 상태인 지출결의 탭을 열고 기안서 전용 입력 필드를 기대하던 기존 fixture를 수정했으며, 저장된 결재선은 결재 단계별 표시값으로 검증한다.
- API 기반 목록 테스트 fixture에 지출결의 문서를 추가해 문서 유형 매핑을 검증하고, 피드 전환 테스트는 API 로딩 완료를 기다리도록 보완했다.

## 브라우저 확인 제한

초기 문서작성 모달 검증 당시에는 문서 목록/요약 API가 HTTP 404를 반환해 실제 DB 문서 연동을 확인하지 못했다. 아래 후속 피드 검증에서는 현재 메뉴 경로(`/groupware/doc/write`)를 통해 목록/상세 조회와 표시를 확인했으며, 데이터 변경 요청은 실행하지 않았다.

초기 순차결재 구현에는 별도 DB migration이 실제 적용되지 않았다. 이번 피드 구현 전 PostgreSQL metadata를 읽기 전용으로 확인했으며, 이 기능에 필요한 신규 테이블/컬럼/제약이 없어 migration은 생성하거나 적용하지 않았다. 행 데이터는 조회하지 않았다.

## 전자결재 피드/상세 후속 구현

- 문서 목록 행과 피드 카드는 모달 대신 페이지 우측 상세 패널을 연다. 본문 HTML/인증된 본문 이미지, 문서 첨부, 결재선, SYSTEM 이력 및 USER 댓글을 표시한다.
- 사용자 댓글·대댓글 및 댓글 첨부는 approval 전용 API에 연결했다. 댓글 이미지 미리보기는 인증된 API Blob을 사용하고 임시 object URL을 정리한다. 실패 상태는 빈 결과나 성공으로 바꾸지 않는다.
- 좁은 화면에서는 피드 카드의 작성자/일시와 문서 종류·상태 배지를 줄바꿈해 표시해 이름이 세로로 분리되지 않도록 조정했다.

브라우저에서는 실제 문서/결재 내용의 조회·렌더링만 확인하고 댓글 작성, 업로드, 결재 처리 등 DB 변경 동작은 실행하지 않았다. 이미지/첨부/댓글 쓰기 및 권한 경계는 위 자동화 테스트로 검증했다. 저장한 반응형 피드 스크린샷은 Playwright가 가상의 검증 문서만 반환하도록 별도 API fixture를 주입해 생성했으며, tenant 문서 행이나 인증 정보를 포함하지 않는다.
