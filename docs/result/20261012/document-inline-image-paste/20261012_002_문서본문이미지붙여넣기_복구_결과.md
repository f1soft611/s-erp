# 20261012_002 문서 본문 이미지 붙여넣기 복구 결과

> 구현 및 자동 검증은 완료했습니다. 브라우저 paste는 확인했지만 draft 저장 및 모든 viewport의 editor 확인은 미완료입니다.

## 작업 결과

- 문서작성 화면에 공통 RichTextEditor 이미지 업로드 adapter와 저장 lifecycle을 연결했습니다.
- 임시저장 요청에 본문 이미지 참조 및 현재 작성 세션의 임시 이미지 목록을 포함하고, 저장 시 approval owner로 승격·본문 URL 재작성·불필요 이미지 정리를 처리합니다.
- 전자결재 전용 임시 업로드/삭제 및 작성자 소유 draft의 본문 이미지 조회 경로를 추가했습니다.
- 기존 공통 파일 저장소와 metadata를 재사용했으며 DB 테이블이나 컬럼 변경은 없습니다.

## 변경 파일

- 백엔드: `DocumentApprovalEmbeddedImageVO`, `DocumentApprovalDraftSaveRequestVO`, `DocumentApprovalService`, `DocumentApprovalApiController`, `DocumentApprovalServiceImpl` 및 관련 controller/service 테스트
- 프런트엔드: `documentWrite.types.ts`, `documentApproval.service.ts`, `useDocumentComposer.ts`, `DocumentComposerDialog.tsx`, `useRichTextEditorSaveLifecycle.ts` 및 관련 서비스/화면 테스트
- 요구사항 및 설계: [작업지시서](../../../directions/20261012/20261012_002_문서본문이미지붙여넣기_복구_작업지시서.md), [계획서](../../../plan/20261012/20261012_002_문서본문이미지붙여넣기_복구_계획서.md), [상세 사양서](../../../spec/20261012/20261012_002_문서본문이미지붙여넣기_복구_사양서.md)

## DB 계약 근거

- 작업 도구에서 `s-erp-postgresql-readonly`를 사용할 수 없어 live DB MCP 조회는 수행하지 않았습니다.
- 신규 DB 객체는 없습니다. 기존 `CommonFile_SQL_postgresql.xml`, common-file 날짜별 schema history, `EmbeddedImageStorageService`/`EmbeddedImageDocumentProcessor` 구현과 테스트를 대체 근거로 확인했습니다.
- 저장소의 owner metadata와 `file_usage_type='EMBEDDED'`를 사용하므로 별도 스키마 변경 스크립트는 생성하지 않았습니다.

## 브라우저 확인 및 제한사항

- 375px, 768px, 1280px 브라우저에서 composer loading dialog의 `body.scrollWidth`와 `body.clientWidth`가 같아 해당 화면에서 페이지 가로 overflow가 없음을 확인했습니다. 캡처는 lookup spinner가 표시되는 상태입니다: [375px](./screenshots/composer-lookup-pending-375.png), [768px](./screenshots/composer-lookup-pending-768.png), [1280px](./screenshots/composer-lookup-pending-1280.png).
- 인증된 브라우저에서 편집기가 열린 뒤 PNG clipboard paste로 이미지 node와 임시 이미지 metadata가 추가되고 upload 상태가 완료되는 것을 확인했습니다. 다만 API mock이 실제 요청을 가로채지 못해 임시 이미지는 개발 API로 업로드되었습니다. 작성 중 화면을 닫아 공통 lifecycle의 임시 이미지 cleanup을 호출했으며, draft 저장 API는 호출하지 않았습니다. 서버 측 cleanup 응답은 독립적으로 확인하지 못했습니다.
- 브라우저 API mock 경로가 준비되기 전에 실제 임시 업로드가 발생했습니다. 작성 중 화면을 닫으며 공통 cleanup을 호출했으나 cleanup response는 독립 확인되지 않았습니다. draft payload metadata 및 저장 후 stable URL 재작성은 자동 테스트로만 검증했으며, 업무 문서나 결재 데이터는 저장하지 않았습니다.
- 브라우저 검증이 끝날 때까지 계획서의 작업 7, Step 4와 Step 5는 미완료로 유지합니다.
- 이미지 metadata `width`의 숫자 JSON 값이 `DocumentApprovalEmbeddedImageVO`의 문자열 필드로 역직렬화되는 동작은 `numericImageWidthCanBeReadIntoStringMetadata` controller target test로 확인했습니다.
