# 20261012_003 문서 임시저장 BIGINT 바인딩 오류 수정 결과

## 원인

오류가 난 컬럼 `tb_electronic_approval_main.drafting_work_category_id`는 nullable BIGINT입니다. `draftingWorkCategoryId`는 선택 입력이고, 전역 MyBatis 설정은 null 값을 VARCHAR로 처리합니다. 전자결재 INSERT/UPDATE mapper는 해당 parameter의 JDBC type을 지정하지 않아 null이 VARCHAR로 전달되면 PostgreSQL이 BIGINT 컬럼에 VARCHAR 표현식을 대입할 수 없었습니다.

DB MCP는 작업 도구에 제공되지 않아 live schema를 조회하지 않았습니다. 대체 근거는 [누적 스키마](../../../database/db-schema.md)의 nullable BIGINT 정의, [날짜별 전자결재 schema](../../../database/20261008/20261008_003_create_document_approval_schema.sql), `mapper-config.xml`의 `jdbcTypeForNull=VARCHAR`, 그리고 전자결재 mapper의 INSERT/UPDATE 구문입니다. 테이블/컬럼 변경은 하지 않았습니다.

## 수정

- `insertDocumentApprovalMain`과 `updateDocumentApprovalMain`의 `draftingWorkCategoryId`에 `jdbcType=BIGINT`를 명시했습니다.
- INSERT/UPDATE 두 문장 모두를 확인하는 MyBatis mapper regression test를 추가했습니다.
- 클라이언트 계약, null 허용 동작, DB schema 및 데이터는 변경하지 않았습니다.

## 검증

| 검증 | 결과 |
| --- | --- |
| RED: `mvn -Dtest=DocumentApprovalMapperTest test` (수정 전) | 실패 확인: `draftingWorkCategoryId`의 JDBC type이 null |
| GREEN: `mvn "-Dtest=DocumentApprovalMapperTest,DocumentApprovalServiceImplTest,DocumentApprovalApiControllerTest" test` | 통과: 3개 test class, 22개 테스트 |
| UI/브라우저 회귀 | 화면 변경이 없는 mapper binding 수정으로 해당 없음 |
