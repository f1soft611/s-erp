# 공지 피드 확장 본문 이미지 표시 수정 결과

## 작업 요약

공지 피드에서 `더보기`로 본문을 펼친 뒤 재렌더링이 발생하면 본문 이미지가 사라지는 문제를 수정했다. 보호된 이미지는 기존 `apiGetBlob` 인증 요청으로 가져오고, blob URL이 포함된 본문 HTML을 React 상태로 유지하도록 변경했다. 접기·본문 교체·컴포넌트 해제 시 생성한 object URL을 정리하며, 이미지 요청 실패는 본문 안에 접근 가능한 오류 안내로 표시한다.

백엔드, API 경로, DB 및 공지 저장 형식은 변경하지 않았다.

## 재현 및 원인

- 공지 81의 확장 본문에서 보호 이미지 API 요청은 HTTP 200이었고 이미지가 처음에는 로드됐다.
- 이후 피드의 다른 상태가 바뀌어 재렌더링되면 React가 이미지 `src`가 제거된 deferred HTML을 다시 적용했다. 이미지 hydration 효과는 재실행되지 않아 본문 이미지가 깨졌다.
- 접힌 미리보기와 상세 이미지 뷰어는 기존 인증 blob 흐름을 사용해 별도로 표시되고 있었다.

## 수정 내용

- 확장 본문의 deferred 이미지 URL을 기존 `apiGetBlob`으로 요청하고, 성공한 blob URL을 반영한 HTML을 React 상태에서 렌더링한다.
- 본문 이미지 요청 실패 시 `role="alert"`로 `본문 이미지를 불러오지 못했습니다.`를 표시한다.
- 접기, 본문 교체, 컴포넌트 해제 및 정리 뒤 완료된 요청에서 생성된 object URL을 폐기한다.
- 회귀 테스트에 재렌더링 후 이미지 유지, 실패 안내, 접기 시 URL 폐기를 추가했다.

### 별도 확인된 테스트 실패

`notice-page.test.tsx`에서 초기 스켈레톤 표시 1건과 이전 댓글 로딩/커서 관련 6건이 실패했다. 실패는 이 테스트 파일을 단독 실행했을 때도 확인됐고 이미지 표시 변경과 무관한 페이지 로딩 및 댓글 동작에 해당해 이번 작업에서는 수정하지 않았다. 저장소의 기존 `frontend/notice-test-output.txt`에도 같은 범주의 이전 실패가 기록되어 있다.

## 20261012_006 확장 본문 이미지 로딩 표시 개선

### 동작

- 크기 정보가 있는 보호 이미지는 본문을 펼친 직후 선언된 크기/비율의 스켈레톤으로 자리를 유지하고, 인증 blob 요청과 이미지 디코드가 끝나면 실제 이미지로 교체한다.
- HTML에 크기 정보가 없는 이미지는 요청 중 깨진 `<img>`나 임의 크기의 스켈레톤을 표시하지 않는다. blob 디코드로 자연 크기를 확인한 다음 해당 비율의 스켈레톤을 표시하고, 렌더 프레임 이후 실제 이미지로 교체한다.
- 최종 이미지는 본문 너비를 넘지 않으며 비율을 유지한다. 주변 텍스트와 표는 이미지 로딩 중에도 유지한다.

### 검증

| 검증 | 결과 |
|---|---|
| `npm run test -- tests/notice-embedded-image-service.test.ts` | 통과: 10개 |
| `npm run build` | 통과: `tsc -b` 및 Vite production build |
| `git diff --check` | 통과 |
| 확장 이미지 테스트 + `notice-page.test.tsx` 결합 실행 | 전체 36개 중 29개 통과. 이미지 서비스 테스트 10개는 모두 통과하고, `notice-page.test.tsx`에서 스켈레톤/이전 댓글 관련 7개 실패가 다시 확인됨 |
| 인증 브라우저에서 대기/완료 상태 측정 | 미완료: 현재 `localhost:8080`의 embedded-image API 연결 실패로 이미지 요청이 완료되지 않음 |
| 이번 로딩 개선용 브라우저 스크린샷 | 미촬영: API 연결 복구 후 재검증 필요 |

브라우저 요청은 기존 인증 페이지에서 공지 81의 embedded-image URL로 발생했으나, 백엔드에 연결되지 않아 대기 스켈레톤과 완료 이미지 상태를 시각적으로 측정하지 못했다. 따라서 이 개선분의 실제 브라우저 치수 및 스크린샷은 확보되지 않았다. 이전 결과에 적힌 펼침 이미지, 접힌 미리보기 및 상세 뷰어의 브라우저 확인은 선행 수정의 증거이며, 이번 로딩 표시의 검증으로 간주하지 않는다.

`notice-page.test.tsx`의 7개 실패는 이미지 전용 테스트와 별도로 발생하는 초기 스켈레톤 및 이전 댓글 로딩/커서 관련 항목이다. 해당 테스트는 이번 이미지 로딩 변경 범위 밖이므로 수정하지 않았다.
