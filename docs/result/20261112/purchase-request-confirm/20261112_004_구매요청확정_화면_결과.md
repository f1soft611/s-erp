# 구매요청확정 화면 작업 결과

## 작업 내용

- `구매관리 > 구매요청확정` 메뉴 seed를 작성했습니다(테넌트 1, READ/UPDATE, 역할 권한은 수주등록에서 복사, 정렬 15).
  테이블 변경은 없습니다. 확정 컬럼은 20261112_002에서 만들어 두었습니다.
- 백엔드 `egovframework.let.materials.request.confirm` (`/api/v1/materials/purchase-request-confirms`)
  - `GET /candidates`: 확정 대상 목록(요청 기본, 확정·전체 선택, 최대 200건)
  - `GET /{id}`: 요청·확정 정보 조회(창고·발주구분·구매처 이름 포함)
  - `POST /{id}/confirm`: 확정. 모든 행 확정수량 > 0, 확정납기일·입고창고·발주구분·구매처 필수, 행 목록이 저장값과 같아야 함(아니면 409)
  - `PUT /{id}/order-close`: 확정 건의 행별 발주대기 마감 Y/N(바뀐 행만 갱신)
  - `POST /{id}/cancel-confirm`: 확정 취소. 요청 상태로 되돌리고 확정값·마감 초기화
  - `GET /unit-price`: 단가관리의 거래구분 **매입** 유효 단가 중 적용 시작일이 가장 늦은 1건. 통화가 없으면 KRW
  - 상태 전환은 헤더 `FOR UPDATE` 잠금 후 상태를 확인하고, UPDATE 문에도 상태 조건을 둡니다.
- 프론트 `pages/materials/request/confirm`: 출하등록과 같은 배치(기본정보 + 상세 F1-Grid, "요청 불러오기" 다이얼로그).
  - 요청 상태: 확정수량(기본 요청수량)·확정납기일(기본 요청납기일)·입고창고·발주구분·구매처·단가·확정비고 입력 후 [확정]
  - 구매처를 고르면 기본 매입 단가와 통화를 채우고 금액(확정수량 × 단가)과 합계금액을 다시 계산
  - 확정 상태: 발주대기 마감 체크 후 [저장], [확정 취소](확인 대화상자)
  - 미저장 변경이 있으면 다른 요청 불러오기·화면 이동 전에 확인
- 사용자 결정 반영: 확정수량 0 없음, 통화는 단가 정보의 통화(없으면 KRW), 입고창고는 기본값 없이 직접 선택,
  기본적용단가 설정은 이후 추가(지금은 적용 시작일이 가장 늦은 단가).

## 확인이 필요한 사항

- **합계금액 통화 혼합**: 한 요청 안에 KRW와 USD 행이 섞이면 헤더 합계금액이 통화 구분 없이 더해집니다(0005: 34,292.5). 통화별 합계 또는 합계 미표시 등 처리 방식 결정이 필요합니다.
- 화면의 실제 메뉴 확인은 사용자가 `20261112_004` seed를 실행한 뒤 진행합니다(API와 화면 코드는 메뉴와 무관하게 동작 확인).
- 일괄적용(여러 행에 같은 창고·구매처·발주구분 입력)은 F1-Grid 공통 기능 결정 후 별도 작업으로 보류 중입니다.
