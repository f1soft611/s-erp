# 구매요청확정 품목 단위 확정 작업 결과

## 작업 내용

- 사용자 결정(2026-11-12): 구매요청의 **품목 행**을 골라 확정한다(MES 방식). 같은 요청의 나머지 품목은 다른 확정번호로
  따로 확정할 수 있고, 수량 분할은 없다. 요청 상태는 요청 / 부분확정 / 확정.
- DB `20261112_006`: 확정 연결을 `tb_purchase_request_dt.purchase_confirm_id`(복합 FK)로 옮기고 헤더 연결 삭제,
  상세 CHECK(확정 ID와 확정수량은 함께 있거나 함께 없음), 요청 상태 CHECK에 `PARTIALLY_CONFIRMED` 추가, 기존 확정 데이터 이전.
  롤백은 부분확정이 있거나 한 요청이 여러 확정에 나뉘어 있으면 중단한다. `db-schema.md` 갱신.
- 백엔드 확정 모듈
  - 후보 목록을 품목 행 단위로(요청·부분확정 요청의 확정 안 된 행, 품목명·규격·단위 포함, 최대 500행)
  - 상세 불러오기·확정을 상세 행 ID 기준으로 변경(1~200행), 상세 행 `FOR UPDATE` 잠금 후 미확정 확인,
    UPDATE에 `purchase_confirm_id IS NULL` 조건
  - 확정·확정 취소 후 영향받은 요청의 상태·합계를 상세 기준 SQL 한 번으로 재계산
  - 구매요청등록 단건 조회의 헤더 확정일 조인 제거(`confirmDt` 필드 삭제)
- 프론트
  - 요청 선택 창: 품목 행 다중 선택(구매요청번호·요청일·요청자·상태 병합, 행·품목코드·품목명·규격·단위·요청수량·요청납기일·사용용도·비고)
  - 확정 화면: [선택 행 빼기], 기본정보 "요청 건수 / 품목 수"
  - 상태 라벨 "부분확정" 추가(등록·현황·확정), 현황 상세 패널 칩 색 `warning`

## 검증 결과

- SQL 정적 테스트 9개 통과(006 컬럼·FK·연결 CHECK·상태 CHECK·이전 순서·롤백 중단, 사본 동일).
- 격리된 PGlite: 002 → 005 → 006 적용, 기존 확정 요청의 모든 행에 확정 ID 이전, 부분확정 저장, 신규 제약 거부
  (확정 ID만 있음, 확정수량만 있음, 잘못된 상태), 부분확정 상태에서 롤백 중단, 정리 후 롤백 성공.
- 백엔드 구매요청 테스트 36개 통과(확정 Service 10: 품목 행 확정·상세 ID 정렬 잠금·확정 ID 연결·요청 상태 재계산,
  이미 확정·누락·동시 변경 409, 통화 혼합 거부, 선택 개수·필수값 검증, 취소 순서(요청 ID 조회 → 행 초기화 → 재계산 → 확정 메인 N),
  마감 대상 검증 / Mapper 5: 상태 재계산 SQL 포함). JDK 8로 운영 코드 컴파일 통과.
- 프론트 구매요청 테스트 21개 통과(품목 행 선택 → 상세 ID로 불러오기, 요청 불러오기 시 그리드 교체, 확정번호 취소 등). `npm run build` 통과.
- 브라우저 `node tests/purchase-request-confirm.browser.mjs`: 합성 응답으로 375/768/1280px 품목 행 선택(2 / 3) → 초안 검증 → 확정 화면, 오류 없음.
