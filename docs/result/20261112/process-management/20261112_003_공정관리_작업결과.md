# 공정관리 작업 결과

- 생산관리 > 기준정보 > 공정관리에서 F1Tree로 공정그룹과 하위 공정을 통합 관리한다.
- 공정 속성과 이미지 컬럼을 추가했다. 이미지는 PNG/JPEG, 512KB 이하이며 저장 시 서버에서 실제 형식과 크기를 검사한다.
- 서버에 테넌트별 조회·일괄 저장과 메뉴별 생성·수정·삭제 권한 검사를 추가했다. 그룹과 공정은 별도 테이블에 저장하며 자식 공정이 남은 그룹은 삭제하지 않는다.
- F1Grid 이미지 컬럼과 모바일 상세 폼을 지원하고 사용법을 F1-GRID 문서에 반영했다.
- 브라우저 확인은 실제 로그인이나 DB에 쓰지 않는 독립 미리보기와 샘플 데이터로 수행했다. [1280px](screenshots/desktop-1280.png), [768px](screenshots/tablet-768.png), [375px](screenshots/mobile-375.png), [모바일 이미지 선택](screenshots/mobile-image-form.png). 실제 인증·권한과 DB를 연결한 종단 저장은 확인하지 않았다.

## 화면 접근 오류 수정

- 재현: 메뉴 경로 `/pr/master/process-management`로 이동하면 페이지를 찾을 수 없다는 화면이 표시됐다.
- 원인: 최상위 라우터에 생산관리 `/pr/*` 경로가 없어 대시보드에 도달하지 못했다.
- 조치: 기존 업무 경로와 동일하게 인증 보호 대시보드 라우트를 추가했다. 로그인 상태의 메뉴 진입과 비로그인 상태의 로그인 이동을 회귀 검증했다.
- [실제 앱 라우팅 화면](screenshots/route-fix.png)은 별도 탭에서 인증·메뉴·공정 응답을 샘플로 대체해 촬영했다. 실제 계정의 메뉴 권한이나 백엔드 연결 검증은 아니다.

## 검색 영역 정렬 수정

- 재현: 실제 앱 테마에서 공정 검색 입력이 아이콘보다 아래로 밀렸다.
- 원인: 공정 화면에서 `TextField` 기본 여백을 해제하지 않아 테마의 상단 16px 여백이 적용됐다.
- 조치: 창고관리·작업표준서와 같은 여백 제거 및 40px 높이·테두리·배경을 적용했다. 기존 검색과 편집 중 검색 제한은 유지한다.
- 회귀 검증: 실제 앱 테마 테스트와 샘플 인증·데이터를 사용한 브라우저에서 검색 아이콘과 입력의 높이·상단 정렬 및 페이지 가로 넘침을 확인했다. [1280px](screenshots/search-aligned-1280.png), [768px](screenshots/search-aligned-768.png), [375px](screenshots/search-aligned-375.png).

## 트리·이미지 및 구조 정리

- 우클릭 추가 메뉴는 공정그룹·공정 명칭을 사용하며 선택한 공정의 소속 그룹에도 공정을 추가한다. 권한이 없거나 검색·저장 중이면 추가할 수 없다.
- 코드 컬럼은 표시하지 않되 검색 데이터는 유지한다. 그룹 이미지 셀은 비우고 공정 이미지 셀은 60×60 미리보기 또는 빈 이미지를 표시한다. 이미지 클릭으로 선택하고 Delete로 삭제하며 행 폼에서는 선택·삭제 버튼을 유지한다. 체크 컬럼은 중앙 정렬한다.
- 트리 하위 행에 ㄴ 표시를 추가하고 최하위 행의 표시를 이름 가까이 배치했다.
- 이미지 저장 실패 재현: 제공 파일은 `.png` 확장자이나 실제 형식은 JPEG여서 브라우저 MIME과 서버 형식 검증이 불일치했다. 클라이언트가 PNG/JPEG 서명에 맞춰 MIME을 정규화하며 서버의 실제 이미지 검증은 유지한다.
- 프론트엔드는 창고관리 패턴에 맞춰 페이지·트리 컴포넌트·관리 훅·서비스·타입·행 데이터로 분리했다. 백엔드는 모델·DAO를 `domain`으로 옮기고 서비스 인터페이스와 구현을 분리했으며 API·SQL·권한과 트랜잭션 계약은 유지한다. 두 영역의 `AGENTS.md`에도 기준 화면과 계층별 책임 분리 원칙을 명시했다.
- 앱 테마와 샘플 응답을 사용한 격리 미리보기: [1280px](screenshots/tree-image-1280.png), [768px](screenshots/tree-image-768.png), [375px 터치](screenshots/tree-image-375.png). 60×60, 그룹 이미지 제거, 연결선 간격, 페이지 가로 넘침과 JPEG를 PNG로 지정한 파일의 모의 저장 요청을 확인했다. 실제 DB에는 쓰지 않았다.
- 변경 후 서비스·컨트롤러·매퍼 및 스프링 트랜잭션 프록시 테스트와 Java 8 API 컴파일을 확인했다. PostgreSQL 통합 테스트는 별도 격리 DB가 준비되지 않아 이번 구조 변경 후 재실행하지 않았다.

## DB 및 적용

읽기 전용 `s-erp-postgresql-readonly` MCP로 테이블 목록, 공정 테이블·메뉴 관련 컬럼, 공정 테이블의 테넌트 복합 FK를 확인했다. 해당 DB에는 공정 테이블과 생산관리 모듈·공정관리 메뉴가 이미 존재한다. 메뉴 존재 여부는 전체 DB 기준이며 특정 테넌트의 설정·역할 권한은 확인하지 않았다. MCP 대상 DB에는 쓰기나 스크립트 실행을 하지 않았다.

신규 환경 적용 전 기존 객체와 충돌 여부를 점검하고 날짜별 생성·메뉴 스크립트를 검토한다. 메뉴 스크립트는 승인된 테넌트 지정이 필요하며 역할 권한은 관리자 화면에서 별도 부여한다. 상세 이력과 데이터 보호 롤백 조건은 [DB 변경 이력](../../../database/20261112/20261112_003_change_process_management_schema.md)을 따른다.

## 검증

- 프론트엔드 빌드, 공정관리·이미지 테스트와 기존 F1Grid 테스트.
- 백엔드 서비스·권한·매퍼 테스트 및 변경 Java 소스의 `javac --release 8` 컴파일.
- 별도 PostgreSQL 테스트 DB에서 실제 MyBatis 매퍼와 트랜잭션으로 그룹·공정 동시 저장, 다른 테넌트 삭제 차단, 실패 시 롤백 및 자식이 있는 그룹 삭제 차단을 확인했다. 인증 주체·메뉴 권한은 테스트에서 대체하고 HTTP 컨트롤러의 저장·조회 응답을 확인했다.
- 격리 PostgreSQL 호환 DB에서 스키마 생성, 메뉴 재실행·비활성화, 테넌트 간 FK 및 데이터 존재 시 롤백 차단.
