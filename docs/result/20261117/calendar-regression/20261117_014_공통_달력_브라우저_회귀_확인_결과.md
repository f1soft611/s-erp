# 20261117_014 공통 달력 변경 브라우저 회귀 확인 결과

공통 달력(`DateEditor` 등) 변경 후, 아직 브라우저로 보지 못한 영업·공지 화면의 날짜 입력을 확인했다. 코드 변경 없음, 확인 전용.

## 방법
- Playwright(headless Chromium)로 로컬(프론트 4173, 백엔드 8080)에 로그인해 각 화면의 날짜 입력을 조작.
- 폭 1600px, 375px. 스크린샷: [screenshots](screenshots/)
- 자동 검증 87건 + 그리드 셀 편집 1건 모두 통과, 페이지 오류(pageerror) 없음.

## 결과
| 화면 | 확인 내용 | 결과 |
| --- | --- | --- |
| 수주등록 (수주일자, 납기일자) | 직접입력, 달력 선택, 패널 위치, 년/월 선택칸 잘림, 가로 스크롤 | 통과 (1600·375) |
| 출하등록 (출하일자) | 동일 | 통과 |
| 거래명세서발행 (명세일) | 동일 | 통과 |
| 견적서작성 (견적작성일, 견적제출일) | 동일 | 통과 |
| 현황 5곳 (수주, 출하, 명세서, 출하계획, 견적) | 상세검색 날짜 달력 열기·선택, 오류 없음, 조회 실행 | 통과 |
| 공지 팝업 종료일 | 직접입력, 달력 선택, 패널이 모달 안에서 가려지지 않음 | 통과 (1600·375) |
| 그리드 날짜 셀 (수주등록 상세 납기일) | 셀 더블클릭 편집, `20261201` 입력 후 Enter → `2026-12-01` | 통과 |

## 확인하지 못한 것
- 출하계획등록 폼의 그리드 날짜 컬럼(`planDt`): 화면이 모드·원천 데이터에 따라 열려 이번에는 조작하지 못했다.
- 거래명세서발행의 출하일자는 원천 표시용(읽기)이라 선택 동작은 확인 대상이 아니다.
- 작업표준서 등록(레시피)의 날짜 입력은 브라우저 기본 `type="date"`라 공통 달력 변경 영향이 없다(확인 대상 아님).
- `DateTimeEditor`/`TimeEditor`는 editing 폴더 밖에서 사용하는 화면이 없어 화면 확인 대상이 없다(단위 테스트만 존재).
- 달력 클릭 편집(셀 안 달력 버튼)은 확인하지 않았고, 셀 직접 입력과 정규화만 확인했다.
- 저장 후 재조회 시 날짜가 하루 어긋나는지는 이번 범위에서 저장을 하지 않아 확인하지 않았다(저장 없는 UI 확인).

## 결론
영업·공지 화면에서 공통 달력 변경으로 인한 회귀는 발견되지 않았다. 영업 담당자에게 알릴 문제는 없다.
