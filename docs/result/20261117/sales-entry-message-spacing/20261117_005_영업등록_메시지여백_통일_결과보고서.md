## 변경

- 수주등록, 견적서작성, 출하등록, 출하계획등록, 거래명세서등록의 성공·입력 검증·서버 오류 메시지를 모두 본문 직계 Alert로 맞췄다. 메시지와 기본정보의 좌우 경계가 같고, 본문 위 여백은 8px, 다음 영역 간격은 16px이다. 오류 발생 여부로 본문 패딩을 바꾸지 않는다. embedded 본문은 패딩 0을 유지한다.
- 앞선 검사는 수주등록의 서버 오류만 기준으로 삼아 사용자가 제시한 입력 검증 오류와 다른 여백을 그대로 복제했다. 이번에는 실제 신규 수주에서 품목 상세 미입력 오류를 발생시켜 기준으로 사용하고, 서버 오류와 성공 메시지도 같은 위치인지 비교했다.
- 출하계획의 미출하 수량 분할 및 출하된 상세 편집 제한은 유지했다.
- `frontend/AGENTS.md`에 메시지 종류와 관계없는 여백 통일, 메시지 전용 추가 패딩 금지, 실제 성공·입력 검증·서버 오류의 반응형 비교 규칙을 추가했다.

## 검증

- 합성 데이터와 API 모의 응답을 사용하는 실제 브라우저 검사에서 다섯 화면의 성공·오류 메시지 좌우 위치와 위·아래 간격이 375, 768, 1280px에서 수주등록과 일치했다. 가로 넘침도 없었다.
- 출하계획 분할 브라우저 검사에서 5·5 분할 저장 및 출하된 행 비활성화를 확인했다. 375px은 768px에서 편집 후 축소해 여백을 확인했다.
- 수주·견적·출하·명세서 Vitest 63건과 출하계획 28건 통과. 출하계획의 복합 편집 테스트가 기본 5초를 넘어 `node node_modules\vitest\vitest.mjs run tests\sales-delivery-plan-page.test.tsx --testTimeout 15000`으로 확인했다. 프론트엔드 빌드 및 변경 파일 oxlint 통과(기존 effect 경고 4건).
- 커밋 시 공유 작업공간의 별도 날짜 입력·행 병합 작업은 제외하고 작업 단위로 스테이징했다. 스테이징된 프론트엔드만 별도 임시 경로로 추출하여 관련 5개 테스트 파일 81건, 빌드 및 변경 파일 lint를 다시 통과했다(기존 effect 경고 2건).
