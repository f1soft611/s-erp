# 20261117_012 구매자재 현황 검색필드 크기 수주현황 기준 통일 결과

## 결과 요약
구매자재 현황 화면 여섯 곳의 상세검색 필드 크기와 줄 구성을 수주현황과 같게 맞췄다. 텍스트·선택 필드는 한 칸(`span: 1`), 날짜 기간은 두 칸(`span: 2`)이고, 줄은 날짜 → 텍스트 → 선택 → 부가날짜 순이다. 검색 필드의 이름·라벨·필수·기본값·검색 동작은 바꾸지 않았다. 검색 컬럼 정의만 변경했으며 API·DB·공통 컴포넌트 변경 없음.

## 변경
검색 컬럼의 `search.span`·`group`·`order`만 바꿨다(구매 화면은 텍스트·선택이 두 칸, 날짜가 네 칸이었다).
- [구매요청현황](../../../../frontend/src/pages/materials/request/status/data/purchaseRequestStatusColumns.tsx): 요청일 / 구매요청번호·요청자·품목 / 상태·사용용도 / 요청납기일
- [구매발주현황](../../../../frontend/src/pages/materials/order/status/data/purchaseOrderStatusColumns.tsx): 발주일 / 발주번호·구매처·품목 / 상태·출처 / 납기일
- [가입고현황](../../../../frontend/src/pages/materials/arrival/status/data/materialArrivalStatusColumns.tsx): 가입고일 / 가입고번호·구매처·발주번호·품목 / 상태
- [입고현황](../../../../frontend/src/pages/materials/receipt/status/data/materialReceiptStatusColumns.tsx): 입고일 / 입고번호·구매처·가입고번호·발주번호·품목 / 상태
- [자재수입검사현황](../../../../frontend/src/pages/quality/inspect/status/data/materialInspectionStatusColumns.tsx): 검사일 / 검사번호·검사자·가입고번호·구매처·발주번호·품목 / 상태
- [매입마감처리](../../../../frontend/src/pages/materials/receipt/closing/data/materialReceiptClosingColumns.tsx): 입고일 / 발주번호 / 마감월·조회구분

## 검증
| 항목 | 결과 |

| 단위 테스트 | `purchase-search-field-layout.test.tsx` 8개: 수주현황 기준 구성 확인, 여섯 화면의 라벨·스팬·그룹 순서가 사양과 일치, 상태 필드의 필수·`allowEmpty: false`, 날짜의 필수·기본값, 마감월 월 입력·조회구분 설정 유지. 변경 전에는 실패하는 것을 확인(날짜 4칸) |

## 확인하지 못한 것
- 구매 화면의 검색 필드가 한 줄을 넘는 경우(입고현황 텍스트 5개는 한 줄, 수입검사현황 텍스트 6개는 두 줄) 줄바꿈 위치는 수주현황 폭 기준으로 자연스럽게 넘어가는 동작이며 별도 사양은 두지 않았다.
- 이번 작업과 별개로 화면 상단 "통합검색" 입력의 폭은 변경하지 않았다.
