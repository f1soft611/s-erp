# 출하계획 API 전환 결정 결과

## 결론

**현재 API 계약으로 전환하고 별도 버전은 만들지 않는다.** 사용자가 구버전 호환을 요구하지 않는다고 확인했으므로 동일 URL에 구·신 계약을 병행하지 않는다. 현재 경로 `/api/v1/sales/delivery-plans`를 유지하고 현재 프론트엔드와 백엔드를 함께 배포한다.

운영 애플리케이션의 실제 artifact 버전과 운영 DB의 식별은 접근 가능한 근거로 확인되지 않았다. 따라서 이 결과는 전환 방침과 배포 절차를 확정한 것이며, 운영 배포나 DB 마이그레이션을 실행했다는 뜻은 아니다. 배포할 artifact SHA와 대상 DB 스키마가 확인되지 않으면 배포를 시작하지 않는다.

## 확인한 근거

| 구분 | 확인 결과 | 범위와 한계 |
|---|---|---|
| 현재 소스 | 작업 시점 저장소 HEAD는 `45c5669d`; 다중수주 계약 변경은 `578a828c`, 상세 행 현황은 `cead60bc`, MANUAL 수주별 조회 제한은 `a259b627`에 반영됨 | 저장소 소스 버전이지 운영 실행 버전은 아님 |
| API 계약 | 요청 상세별 `salesOrderId`·`salesOrderDetailId`, 상세 행 단위 현황을 사용. 주소는 `/api/v1/sales/delivery-plans` 유지 | 구버전 계약과는 같은 경로에서 호환되지 않음 |
| 저장소 소비자 | 프론트엔드 `salesDeliveryPlan.service.ts`가 직접 호출하고 Controller 및 프론트·백엔드 테스트가 존재 | 검색 가능한 저장소 밖 API 소비자·캐시된 브라우저 세션은 확인하지 않음. 사용자 결정상 구버전 호환은 유지 대상 아님 |
| 배포 근거 | GitHub Releases 목록, 최근 Actions 실행 목록, Git tag에서 운영 artifact를 특정할 기록을 찾지 못함 | 배포가 없었다는 뜻이 아니며 운영 서버·배포 담당자의 기록은 조회되지 않음 |
| 기본 DB MCP | 계획 헤더에 `sales_order_id`가 없고 `(sales_delivery_plan_id, tenant_id)` 고유키가 있음. 상세의 `sales_order_id`·`sales_order_detail_id`는 필수이고 헤더 및 원 주문상세 복합 FK를 보유 | `20261112_009` 목표 스키마 형태와 일치. 기본 MCP DB가 운영 대상인지는 확인되지 않았으며, 메타데이터만 조회하고 업무 데이터 행은 조회하지 않음 |

## 확정 배포 절차

1. 배포 담당자가 환경, 현재 배포 백엔드·프론트엔드 artifact, 대상 빌드 SHA 및 대상 DB를 식별한다. 버전 분리를 하지 않으므로 현재 계약에 맞는 두 artifact를 한 배포 변경으로 묶는다.
2. 대상 DB가 현재 스키마인지 메타데이터로 확인한다. 이미 현재 구조면 009 스크립트를 재적용하지 않는다. 구 구조면 백업·선행 제약 확인·승인 후에만 한 번 적용한다.
3. 출하계획 쓰기를 중지하고 진행 중 요청을 배출한다. DB 변경 중 구버전 백엔드가 동작하는 혼합 상태를 만들지 않는다.
4. 현재 백엔드와 프론트엔드를 함께 전환하고 정적 자산 캐시를 갱신한다. 사용 중인 화면은 새로고침하도록 한다.
5. 합성 데이터로 MANUAL 다중수주 등록·수정, 상세 행 단위 현황, AUTO 수주별 조회, 납품의 계획 상세 연결을 검증한다. 로그 및 DB 제약 오류가 없을 때만 쓰기를 재개한다.
6. 실패 시 쓰기를 유지 차단하고 현재 스키마와 데이터를 보존한다. 구버전 애플리케이션 또는 DB 롤백은 자동 수행하지 않는다. DB 롤백은 기존 스크립트 가드와 별도 승인·백업을 통과할 때만 가능하다.

## 잔여 조치

- 배포 담당자가 배포 전 현재 운영 artifact SHA와 운영 DB 스키마를 확인해 변경 기록에 남겨야 한다.
- 기본 MCP 관측이 직전 호환성 결과에 기록된 DB 관측과 다르므로, 운영 대상으로 사용할 DB가 어느 환경인지 분명히 식별한다. 이 차이를 운영 마이그레이션 완료 증거로 해석하지 않는다.
- 외부 소비자 식별 및 구버전 지원 설계는 사용자가 호환 유지 불필요를 결정했으므로 이번 완료 조건에서 제외한다.

## 검증 및 범위

- 소스·문서 계약과 기본 DB MCP의 제한된 스키마 메타데이터를 대조했다.
- 운영 배포, DDL, 업무 데이터 조회, 코드 변경은 수행하지 않았다.
- 화면 동작 변경이 없어 스크린샷은 해당하지 않는다.
