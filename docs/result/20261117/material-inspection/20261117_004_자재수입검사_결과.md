# 20261117_004 자재수입검사 등록·현황 결과

기준: [작업지시서](../../../directions/20261117/20261117_004_자재수입검사_화면_작업지시서.md), [계획서](../../../plan/20261117/20261117_004_자재수입검사_화면_계획서.md), [상세 사양서](../../../spec/20261117/20261117_004_자재수입검사_화면_상세사양서.md)

## 결과 요약
품질관리 모듈(`QUALITY`)에 `수입검사 > 자재수입검사등록 / 자재수입검사현황`을 만들었다. 검사 대기 가입고 행을 불러와(여러 건 선택 가능) 한 검사번호(`QI-YYYYMMDD-NNNN`)로 묶어 합격량·불합격량을 기록하고, 검사를 등록한 가입고 행은 가입고에서 잠긴다. 검사를 취소하면 잠금과 검사 대기량이 복구된다. 불합격량은 발주 잔량에 더해져 조회된다. 현황은 입고현황과 같은 패턴(정상 기본/취소/전체)이다. 실서버(8080) API 종단 확인과 실제 브라우저(4173) 확인을 모두 통과했다.

## DB (MCP 확인 근거)
- 스크립트: [20261117_004 테이블](../../../../backend/DATABASE/20261117/20261117_004_create_material_inspection_schema.sql), [20261117_005 모듈·메뉴](../../../../backend/DATABASE/20261117/20261117_005_seed_quality_inspect_menu.sql), 롤백·변경이력과 [db-schema.md](../../../database/db-schema.md) 갱신. `docs/database`와 `backend/DATABASE` 사본은 같다(스키마 스크립트 테스트가 비교).
- 구현 전 MCP `list_tables`·`describe_table`로 수입검사 테이블과 `QUALITY` 모듈이 없음, `tb_module`(identity, `(tenant_id, module_code)` 유일), `tb_menu` 유일 제약, 입고등록·입고현황 역할 권한 각 4건을 확인했다.
- 사용자가 스크립트를 실행한 뒤 MCP로 컬럼 12·15개, PK·유일·FK(`ON DELETE SET NULL` 포함)·CHECK, 인덱스 5개, 모듈 `QUALITY`(`ClipboardCheck`, `/quality`, 정렬 5), 메뉴 3개와 메뉴 권한(등록 READ/UPDATE, 현황 READ/EXCEL), 역할 권한 각 4건이 스크립트와 일치함을 확인했다.
- 새 SELECT 쿼리(후보, 잔량 합, 검사 링크, 합격률)는 읽기 전용 MCP로 실제 DB에서 문법 오류 없이 실행됨을 확인했다.

## 구현
- 백엔드(`let/quality/inspect/{create,status}`): 후보 조회(정상 가입고의 검사 대상, 대기량 > 0, 전체 대기 건수), 등록(여러 행 한 번호, 가입고 행 ID 순 잠금 후 재조회로 대기량 검증, 중복 행·초과·0 이하 거부), 수정(수량·비고, 행 빼기·재정렬, 이 검사를 뺀 상한), 취소(헤더 `use_at='N'`), 현황(상태 3종, 합격률). 가입고 서비스는 검사번호가 있는 행을 입고와 같은 방식으로 잠그고 `수입검사 QI-…에서 처리해 주세요`를 안내한다. 발주 잔량 계산 4곳(가입고 후보, 발주 행 상태, 가입고 행 잔량, 입고 행 잔량)에 유효 불합격 합을 더했다.
- 프론트(`pages/quality/inspect`): 등록 화면(create/edit/view, 가입고 불러오기 창, 검사량 자동 계산, 합계), 현황 화면(검색·링크·상세 패널·수정 다이얼로그·검사 취소), 가입고 화면(검사 행 잠금, 안내, 검사번호 열과 링크), `DashboardContent` 라우팅, `AppRouter`의 `/quality/*` 경로.
- 그리드 `storageKey`: `quality-material-inspection-{create,detail,arrival-picker,status}-grid-v1`(저장키 검사 통과).

## 구현 중 보정과 사양서와의 차이
- 사양서 3.3의 `inspectionLocked` 필드는 만들지 않았다. 가입고 행의 `inspectionNo`가 있으면 잠긴 행이다.
- 검사자는 화면에서 바꾸지 않는 읽기 전용 표시다(가입고의 담당자와 같음). 신규는 서버가 로그인 사용자로 저장하고, 수정은 기존 검사자를 그대로 보낸다.
- 현황 상세 패널의 행별 실적은 가입고량, 이 검사를 제외한 기검사량, 이 검사의 합격·불합격량이다. 가입고 행 전체 누적 합격·불합격 합계는 응답에 없어 보여 주지 않는다(필요하면 응답에 추가).
- 불러오기 창의 검색은 가입고일 기간과 통합 검색어(가입고번호·발주번호·구매처·품목)이며 구매처·품목 별도 입력란은 두지 않았다.
- **실서버 확인 중 발견·수정**: 새 모듈 경로 `/quality`가 `AppRouter`에 등록되지 않아 화면이 404였다. `/quality/*` 경로를 추가하고 회귀 테스트(`app-router-not-found.test.tsx`)로 고정했다. 사양서 4.1에 반영했다.
- 구현 초기 Mockito가 같은 Map 객체를 재사용해 잠금 조회와 재조회의 인자를 구별하지 못해 두 테스트가 실패했고, 호출마다 새 Map을 쓰도록 구현을 고쳤다.

## 확인하지 못한 것
- 검사 합격분을 입고(MI)로 연결하는 흐름(입고 수동 등록, 입고 가능량, 합격분 입고 후 검사 취소 제한)은 범위 밖이며 다음 작업이다.
- 검사 대상과 무검사가 섞인 가입고, 검사 다중 행(서로 다른 구매처)의 실서버 확인은 개발 DB에 검사 대상 발주 행이 1건뿐이어서 하지 못했다. 다중 행 등록은 서비스·화면 테스트로 확인했다.
- `app-router-not-found.test.tsx`의 "keeps the dashboard root path valid while the menu list is loading"는 이번 변경 전 기준에서도 3번 중 2번 실패하는 기존 불안정 테스트다(기존 파일 상태로 재현). 이번 작업에서 고치지 않았다. 전체 프론트 테스트(205개 파일) 실행은 별도로 하기로 했다.
- 개발 DB에는 확인 과정에서 만든 가입고·검사가 취소 이력으로 남아 있다(정상 목록에는 나오지 않는다).
