## 실패 분류

| 분류 | 확인 결과 |
| --- | --- |
| 브랜치 원인, 수정 | AUTO 테스트 2건. 두 PR CI run에서 실패했고 정확한 lockfile로 실행한 base 전체 검사에서는 출하계획 테스트 파일이 실패하지 않았다. |
| 브랜치 원인 아님 | 각 PR run에서 실패한 테스트 중 85건은 같은 테스트가 base의 정확한 lockfile 전체 검사에서도 실패했다. base 전체 결과는 20개 파일에서 96건 실패, 2,266건 통과였다. |
| 미확인, 사용자 결정 필요 | base에서 재현되지 않은 `notice-summary`의 “calculates live stats…” 실패(두 CI run), `document-write-page`의 “renders every filtered document…” 실패(첫 run), `app-router-not-found`의 “keeps the dashboard root path valid…” 실패(두 번째 run), 그리고 `sales-order-create-page`의 “resets the header and detail grid…” 실패(두 번째 run). 해당 영역은 수정하지 않았다. 관련 두 sales-order 테스트 파일을 PR head에서 따로 실행했을 때는 통과했으나, 이것만으로 CI 단발 실패 원인은 확정되지 않는다. |

`frontend-required`는 프론트엔드 테스트 결과 실패를 전달한 게이트이며 별도 테스트 실패로 보지 않았다. base와 CI의 테스트 개수 및 실패 목록 차이는 전체 스위트의 간헐 실패를 포함하므로, base에서 재현되지 않은 실패는 브랜치 원인으로 단정하지 않았다.
