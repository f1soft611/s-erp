# 20261117_002 입고현황 결과

기준: [작업지시서](../../../directions/20261117/20261117_002_입고현황_화면_작업지시서.md), [계획서](../../../plan/20261117/20261117_002_입고현황_화면_계획서.md), [사양서](../../../spec/20261117/20261117_002_입고현황_화면_상세사양서.md)
공통 검증·DB 근거·환경·미확인 항목은 [입고등록 결과](../material-receipt-create/20261117_001_입고등록_결과.md)에 함께 기록했다.

## 구현 범위
- 백엔드: 목록(`GET /api/v1/materials/material-receipt-status`), 수정·취소(`/api/v1/materials/material-receipts/{id}`)는 입고등록과 같은 서비스에서 처리한다.
- 프론트: 입고현황 목록(헤더 셀 병합, 입고번호·가입고번호 링크) → 상세 패널 → 조회/수정 다이얼로그(입고등록 화면을 `embedded`로 재사용).

## 기준 화면
가입고현황(`materials/arrival/status`)의 페이지·컬럼·훅·상세 패널·에디터 다이얼로그 구조를 따랐다. 폼과 F1Grid는 입고등록 화면의 실제 컴포넌트를 공유하며 차이는 숨김·읽기 전용뿐이다(조회 모드는 입력 전체 읽기 전용, 취소된 입고는 조회만).

## 동작
- 검색: 입고일 기간(필수, 기본 최근 1개월~오늘), 입고번호, 구매처, 상태, 가입고번호, 발주번호, 품목, 빠른 검색.
- **상태 조회 규칙(2026-11-17 확정, 모든 현황 공통)**: 정상(기본) / 취소 / 전체(취소 포함). 상태를 고르지 않으면 정상만 조회하고 서버도 상태가 없으면 정상으로 본다. 검색 기본값에 상태=정상을 넣어 칩으로 보인다. 기존 현황 화면(구매요청·발주·가입고)은 입고 작업 후 별도 작업으로 맞춘다.
- 입고번호 링크 → 상세 패널(요약·품목 목록, 가입고번호 링크). 가입고번호 링크는 연결된 가입고가 정상일 때만 활성이며 `가입고현황?arrivalId=`로 이동해 해당 가입고 상세를 바로 연다(가입고현황 화면이 이 쿼리를 읽도록 보강했다).
- 수정·취소는 입고등록 메뉴의 UPDATE 권한을 쓴다. 취소 확인창과 행 빼기 저장 확인창에는 무검사 안내("가입고와 함께 취소/삭제됩니다")가 들어간다. 엑셀은 EXCEL 권한이 있을 때만 보인다.

## 사양과 구현의 차이
- 사양서의 파라미터명을 구현에 맞춰 `receiptDtFrom/receiptDtTo`로, 응답 필드를 구현 VO 기준(`headerSupplyAmt` 등)으로 정정했다.
- 목록 응답에 `arrivalLinked`(연결된 가입고가 정상이면 true)를 두어 링크 활성화 기준으로 쓴다.
