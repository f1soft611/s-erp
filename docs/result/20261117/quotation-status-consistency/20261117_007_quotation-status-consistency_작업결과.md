# 견적현황 UI 정합성 작업 결과

## 반영 내용

- [작업지시서](../../../directions/20261117/20261117_007_견적현황_UI정합성_작업지시서.md) → [계획서](../../../plan/20261117/20261117_007_견적현황_UI정합성_계획서.md) → [상세사양서](../../../spec/20261117/20261117_007_견적현황_UI정합성_상세사양서.md) 기준으로 수정했다.
- 견적 상세의 텍스트 `작업` 버튼을 수주현황과 동일한 MoreVert 아이콘 버튼으로 변경했다. 접근성 이름은 `견적 더보기`, 메뉴는 `자세히보기` 및 권한에 따른 `수정`이다.
- 견적현황 빠른 검색 입력을 수주현황과 동일한 PageSearchArea 패턴으로 추가했다. Enter/검색/상단 조회/상세검색 적용 시 현재 검색어와 필수 날짜·상세조건을 함께 전달한다.
- 검색어는 앞뒤 공백을 제거해 기존 GET API의 선택 `keyword`로 전달한다. 서버에서 견적번호, 거래처 코드/명, 상세 스냅샷 품목 코드/명을 OR 부분일치로 묶고 기존 날짜·테넌트·사용 중 조건과 AND로 결합한다.
- 검색어 입력만으로는 재조회하지 않으며 검색어 초기화, 전체 조건 초기화, 검색어/조건 세션 복원을 지원한다. keyword가 없는 이전 정상 날짜 세션도 유지한다.
- 견적작성일·견적제출일에 DateEditor의 disabled를 직접 전달했다. 상세보기에서는 두 날짜가 다른 비활성 필드와 같은 공통 읽기전용 배경을 사용하며 입력과 달력 버튼이 비활성화된다. 수정 가능 모드에서는 기존처럼 날짜를 편집할 수 있다.
- 기존 공통코드 연동·등록/현황 공유 폼·금액 계산·저장·권한과 다른 작업의 변경은 유지했다.

## 재현과 원인

- 더보기: 견적만 텍스트 Button을 사용하고 수주현황의 MoreVert IconButton 패턴을 사용하지 않았다.
- 통합검색: PageSearchArea에 searchField가 없고 프론트 검색 상태/필터, 서버 검색 VO/서비스/Mapper에도 keyword가 없었다.
- 날짜 색상: 상위 HTML fieldset만 disabled여서 입력 동작은 막혀도 MUI 입력 루트에 Mui-disabled 클래스가 없었다. 공통 theme의 disabled 배경 선택자가 매칭되지 않았다.
- 먼저 프론트엔드 테스트에서 검색 필터 누락·더보기/검색 입력 부재 실패를 확인했다. 백엔드는 신규 검색 VO의 keyword 접근자 부재로 테스트 컴파일 실패를 확인한 후 구현했다.

## DB 및 호환성 확인

- 기본 `s-erp-postgresql-readonly`의 `list_tables`, `tb_sales_quotation_hd`·`tb_sales_quotation_dt`·`tb_customer_info`의 `describe_table`을 직접 호출해 검색 컬럼과 tenant_id 계약을 확인했다.
- 업무 데이터 행이나 민감정보는 조회/기록하지 않았다. Mapper의 검색 조건만 추가했으며 테이블·컬럼·FK·기존 데이터 변경이 없으므로 마이그레이션 및 누적 스키마 구조 수정은 없다.
- Java 검색 VO와 서비스 운영 코드는 `javac --release 8`로 별도 컴파일하여 Java 8 표준 API 호환성을 확인했다. 의존성·운영 JDK·컴파일 기준을 변경하지 않았다.

| `git diff --check` | 통과 |
| `node tests/quotation-status-consistency.browser.mjs` | 375/768/1280px 모두 통과 |

- 브라우저는 실제 공통 theme을 적용해 견적현황 → 통합검색 → 상세 → 더보기 → 자세히보기 → 닫기 → 수정의 실제 컴포넌트 흐름을 실행했다.
- 검색 요청의 keyword trim 및 필수 날짜 동시 전달, MoreVert 아이콘, 날짜의 실제 computed background가 참조 입력의 disabled 배경과 같음, 날짜 입력/달력 버튼 비활성화, 수정 모드의 날짜 활성화, 페이지 가로 overflow 없음을 확인했다.
- 브라우저 API는 합성 fixture로 응답했다. 실제 업무 DB 검색 결과/쓰기 및 실행 중인 업무 백엔드의 반영 여부는 검증하지 않았다. 실행 중인 백엔드는 재시작 또는 재배포해야 신규 keyword 검색이 반영된다.
- 브라우저 확인은 `http://127.0.0.1:4173`에서 수행했다. 기존 서버가 없어 `npm run dev -- --strictPort`로 시작했으며 작업 종료 시 직접 시작한 서버를 종료하고 포트 해제를 확인한다.
- 커밋은 생성하지 않았다.

### 커밋 전 재검증 보완

- 초기 목록 비동기 렌더링이 기본 대기시간을 초과하는 경우를 확인해 해당 결과 대기를 최대 5초로 명시하고 두 화면 흐름 테스트의 실행 제한을 15초로 지정했다.
- 검색 입력 활성화 직후에는 초기 목록 요청이 아직 진행될 수 있으므로, 입력만으로 재조회하지 않는다는 검증은 초기 목록이 표시된 후 요청 횟수를 비교하도록 보완했다. 업무 코드의 검색 동작과 검증 기준은 변경하지 않았다.
- 최종 재검증: 견적·읽기전용 Vitest 6파일 43개 통과(`--maxWorkers=1`), 견적 백엔드 Maven 5개 통과, 변경 영역 lint 오류 없음(기존 경고 5건 유지).
