## 결과 요약
구매자재 > 입고관리 > **매입마감처리** 화면을 만들었다. 입고 행을 마감월로 마감하고 해제할 수 있다.
- 마감은 **입고 행 단위, 한 행을 전체 수량으로 한 번에** 처리한다(분할 마감 없음. 필요하면 마감 테이블을 추가하는 방식으로 확장한다 — 사용자 확정).
- 마감 시 단가·부가세구분·부가세포함을 고칠 수 있고, 금액은 서버가 입고수량과 마감 단가로 계산해 입고 행의 마감 컬럼에 저장한다. 입고의 원래 단가·금액은 그대로 둔다.
- 마감 행이 있는 입고는 입고등록에서 수정·행 빼기·취소할 수 없고 마감월을 안내한다. 마감을 해제하면 다시 가능하다.
- 화면은 공통코드 등록 화면과 같은 `Splitter` 좌우 분할(왼쪽 구매처별 요약, 오른쪽 입고 행)이며 좁은 화면에서는 위아래로 쌓인다.

## 실서버 확인 후 사용자 피드백 반영 (2026-11-17)
1. **사업자번호·열 순서가 그대로였던 원인**: F1Grid는 열 순서·너비를 `storageKey`로 브라우저 localStorage에 저장한다. 열 구성을 바꿨는데 같은 키(`…-v1`)를 쓰고 있어 예전 배치가 복원됐다. 두 그리드의 키를 `…-v2`로 올려 새 배치(사업자번호 맨 뒤, 입고 행은 No·입고번호 고정)로 시작한다.
2. **하단 합계 라벨**: 집계 행의 라벨 "집계"는 체크박스 열이 있는 그리드에만 있었고 왼쪽 그리드에는 없었다. 라벨을 "합계"로 바꾸고, 체크박스 열이 없으면 집계 값이 없는 첫 열 칸에 "합계"를 표시한다. 공통 F1Grid 변경이라 집계 행을 쓰는 다른 화면(수주등록 상세·수주현황 등)의 라벨도 "합계"로 바뀐다(접근성 이름 "집계"는 유지). [F1-GRID.md](../../../../frontend/src/pages/f1-grid-docs/F1-GRID.md)에 반영했다.
3. **마감월을 달력으로 선택**: 월 선택 달력 템플릿이 없어(날짜용 `DateEditor`만 있음) `MonthEditor`를 새로 만들었다. `search.inputType: 'month'`를 지정하면 상세검색 필드가 달력(연·월)이 있는 월 입력으로 바뀌고 값은 `YYYYMM`이다. 직접 입력(`YYYYMM`/`YYYY-MM`)도 되며 월이 올바르지 않으면 조회를 막는다. 적용조건 칩은 `2026-11`로 보인다. F1-GRID.md에 반영했다. 달력의 월 이름이 영문(Jan, Feb…)으로 보이는 것은 기존 날짜 달력과 같은 설정이다(한글화는 공통 작업으로 별도 결정 필요).
4. **입고현황에서 마감 여부 표시**: 입고 상세 패널에 "매입마감된 입고입니다(마감 N건, 마감월 …). 수정·취소하려면 매입마감처리에서 마감을 해제하세요." 안내와 "매입마감" 칩, 품목 표의 마감월 열을 추가했다. 자세히보기 창에도 같은 안내와 마감월 열이 보이고, 마감 행이 있으면 읽기 전용이며 "무검사 수정은 가입고에도 반영" 안내는 숨긴다.

## 설계 메모
- 마감·해제는 대상 입고 헤더 → 상세 순서로 `FOR UPDATE`를 잡는다(입고 수정·취소가 헤더를 먼저 잠그므로 같은 순서). 같은 행을 동시에 마감하면 한 건만 성공한다.
- 마감 대상에서 취소된 입고(`use_at='N'`)는 제외한다. 마감·해제 요청은 한 건이라도 상태가 맞지 않으면 전체를 거부한다.
- 구매처는 검색 조건이 아니라 왼쪽 요약 그리드에서 고른다(사양서에 반영). 마감월은 선택 목록(지난 12개월~이후 3개월), 입고일 기본은 최근 1개월이다.
- 오른쪽 그리드는 No·입고번호만 왼쪽에 고정해 가로 스크롤 여유를 확보했고, 구매처 요약의 사업자번호는 맨 뒤 열이다(사용자 요청).
- 단가 마스터에 부가세 여부 컬럼이 없어 부가세 기본값은 입고 헤더의 과세/별도를 따른다. 단가 정보의 부가세 설정을 기본값으로 쓰는 일은 후속 과제다.

## 확인하지 못한 것
- 구매처가 둘 이상인 행을 한 번에 마감하는 요청은 실서버에서 시험하지 않았다(개발 DB에 입고가 있는 구매처가 사실상 한 곳이다. 단위 테스트로는 여러 행을 확인).
- 전체 프론트 테스트(207개 파일)에는 이번 작업과 무관한 기존 실패 99건이 있다(`dashboard-sidebar`·`f1-grid-context-menu` 13건은 HEAD에서도 동일 실패 확인, 나머지는 단독 재실행에서도 실패하나 HEAD와 직접 비교는 하지 않음).
- 서비스·매퍼 테스트는 구현과 함께 작성했다(잠금 테스트만 구현 전에 실패를 확인).
- 개발 DB에는 확인 과정에서 만든 발주·가입고·입고가 남아 있고, 입고 2건(`MI-20261117-0020`, `MI-20261117-0021`)이 2026-11로 마감된 채 남아 있다(정리하지 않음).
