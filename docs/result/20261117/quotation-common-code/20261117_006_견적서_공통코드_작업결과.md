# 견적서 공통코드 작업 결과

## 변경 범위

- [작업지시서](../../../directions/20261117/20261117_006_견적서_공통코드_작업지시서.md) → [계획서](../../../plan/20261117/20261117_006_견적서_공통코드_계획서.md) → [상세사양서](../../../spec/20261117/20261117_006_견적서_공통코드_상세사양서.md) 순서로 작성하고 구현했다.
- Incoterms·결제조건·화폐단위 입력을 공통코드 select로 변경했다. 표시는 항목명, 저장값은 항목코드이다.
- 그리드 단위는 활성 ITEM_UNIT을 사용하는 F1Grid select로 변경했다. 직접 입력 품목과 마스터 품목 모두 단위 선택이 가능하며 마스터 연결을 해제하지 않는다.
- 코드 조회 중·오류·활성 항목 없음 상태를 처리하고 재시도를 제공한다. 기존 견적의 미등록 값은 원문 그대로 보존하며 신규 선택지로 추가하지 않는다.
- 작성·현황 보기/수정 공용 폼을 사용한다. 기존 375px 1열, 768px 2열, 1280px 4열 기본정보 배치와 저장·금액 계산·권한을 유지했다. 현황 요약 패널의 원문 표시는 변경하지 않았다.

## DB MCP 및 스크립트

- 기본 `s-erp-postgresql-readonly`의 `list_tables`, `tb_common_code_group`·`tb_common_code_item`의 `describe_table`을 직접 호출했다.
- 그룹 목록 및 그룹별 활성 항목 집계로 CURRENCY·ITEM_UNIT 존재, INCOTERMS·PAYMENT_TERM 부재를 확인했다. 기본 DB 확인이며 개별 테넌트의 구성 상태까지 확인한 것은 아니다.
- 기존 CURRENCY·ITEM_UNIT은 재사용한다. 새 seed는 INCOTERMS 11종과 PAYMENT_TERM 5종(현금·선불·30일·60일·90일)만 추가한다. 결제조건은 초기 관리값이며 자동 기본선택이나 결제일 계산은 없다.
- `docs/database/20261117/20261117_006_*`의 seed·롤백·확인 SQL 및 변경 이력을 `backend/DATABASE/20261117`에 동일하게 보관했고 해시 일치를 확인했다.
- 승인된 대상 테넌트를 `target_tenant_id`로 명시해야 한다. 기존 행을 덮어쓰지 않으며 잘못된 대상 또는 비활성/부모 참조 그룹은 오류 처리한다.
- 롤백은 업무 사용 전에만 실행한다. 이번 seed에서 생성하고 이후 수정되거나 부모로 참조되지 않은 행만 삭제한다. 문자열 견적 참조는 FK로 확인할 수 없다.
- **업무 DB에 seed를 적용하지 않았다.** 따라서 누락 그룹은 승인된 대상 DB에 seed 적용 후 사용할 수 있다. 신규 테이블·컬럼·FK·Java/API 변경이 없어 누적 스키마 구조 수정 및 Java 호환성 검증 대상은 없다.

## 검증

| 검증 | 결과 |
|---|---|
| 견적 코드 서비스·작성·현황·API Vitest 5파일 | 21개 통과 |
| `npm run build` | 통과 |
| 변경 영역 `npm run lint -- ...` | 오류 없음. 기존 작성 폼의 `set-state-in-effect` 경고 2건 유지, 신규 경고 없음 |
| `node tests/quotation-common-code.browser.mjs` | 375/768/1280px 렌더링, 활성 코드만 표시, 항목명/코드 분리, 저장 payload, 단위 변경 후 materialId 유지, 과거 값 보존, 신규 행 단위 선택, 보기 편집 차단 통과 |
| `git diff --check` | 통과 |
| 격리 PostgreSQL(PGlite) SQL 실행 | seed 재실행·16개 항목·기존 비활성/사용자 정의 값 보존·화폐/단위 미변경·테넌트 격리·확인 쿼리·롤백 재실행·수정/부모 참조 행 보존·빈 대상 재등록·없는 테넌트/비활성 그룹 오류 확인 |

- 브라우저는 기존 프로젝트 Playwright 방식으로 `http://127.0.0.1:4173`의 실행 중인 Vite 서버를 확인 후 재사용했다. 기존 서버는 종료하지 않았다. 별도로 시작한 서버는 없다.
- 브라우저/API 및 SQL 테스트 데이터는 모두 합성 fixture다. 업무 API를 실제 저장하거나 운영 DB의 테넌트 행을 복사하지 않았다.
- PGlite 검증은 저장소의 기존 공통코드 DDL을 사용한 메모리 DB에서 psql 메타명령 제거 및 대상 변수 치환 후 실행했다. 실제 대상 DB의 psql 실행·배포, 동시 잠금 동작 및 테넌트별 설정은 미검증이다.
- 회귀 재현: 기존 폼은 세 헤더가 자유입력이고 단위는 편집 불가였다. 새 테스트에서 combobox 부재 및 단위 `text` 타입 실패를 먼저 확인한 뒤 구현했다.
- 원인/해결: 견적 폼에 공통코드 조회가 연결되지 않아 발생한 입력 일관성 문제로, 기존 공통코드 서비스를 연결하고 단위 변경 패치를 단위 값으로 한정했다.

## 최종 점검

- 요구사항 4개 항목을 반영했고 신규 API/스키마 변경 없이 견적 화면 및 날짜별 seed 범위로 제한했다.
- F1Grid 소비 화면의 단위 동작·옵션·검증 기준을 상세사양과 이 결과 문서에 반영했다.
- 작업 중 다른 작업의 루트 규칙 및 CI 문서 변경을 발견했으며 수정하거나 되돌리지 않았다.
- 커밋은 생성하지 않았다.
