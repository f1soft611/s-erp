# 수주관리 공통코드·필수납기·금액오류 처리 결과

## 작업 내용

- 수주상태와 상세 진행상태를 `SALES_ORDER_STATUS` 공통코드명으로 표시하고 배송방법을 `SALES_DELIVERY_METHOD` 기반 선택 필드로 변경했다. 공통코드 누락/조회 실패 시 안내와 재시도 기능을 제공하며, 기존 API 필드와 코드 값은 유지한다.
- 수주 상세 행 번호를 `No`로 변경하고, 헤더 납기일을 필수 검증하며, 새 상세 행에 생성 시점의 헤더 납기일을 기본값으로 전달한다. 상세 납기일은 계속 수정할 수 있다.
- 계산 지원 범위를 벗어나는 수량/금액 입력은 행에 적용하지 않고 기존 오류 영역에 메시지를 표시한다.
- 수주현황의 `업무상태`를 `진행상태`로 바꾸고 공통코드 검색/표시를 적용했다. 기존 `status`/`lineStatus` 검색 키와 견적번호 표시를 유지했다.
- 공통코드 seed, 확인, 제한적 rollback SQL 및 변경 이력을 `docs/database`와 `backend/DATABASE`에 동일 사본으로 추가했다. 실제 DB에는 적용하지 않았다.

## 검증

- Vitest: 관련 7개 파일, 84개 테스트 통과.
- Frontend build/type-check: `npm run build` 통과.
- Lint: 변경 영역 명령 종료 코드 0. `react(set-state-in-effect)` 경고 3건이 `usePageSearchDefaults.ts`, `useSalesOrderStatusSearch.ts`, `SalesOrderCreatePage.tsx`에 남아 있다.
- DB 스크립트 사본: seed, verify, rollback, 변경 이력 4쌍의 SHA-256 일치 확인.
- SQL 실행: `psql`을 사용할 수 없어 스크립트 구문 실행은 검증하지 못했다. DB는 변경하지 않았다.
- 브라우저 검증/스크린샷: 로컬 앱이 `/login`으로 이동해 수주 페이지에 접근할 수 없었다. 자격 증명을 사용하지 않았으며, 화면 기능 검증과 캡처는 완료하지 못했다.
