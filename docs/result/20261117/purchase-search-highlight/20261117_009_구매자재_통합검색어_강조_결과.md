요청 출처: Flow 글 [구매 그리드 통합검색어 강조 적용 안내](https://flow.team/l/QzH2C)(88354809, 대표님 요청 기능)

## 결과 요약
F1-Grid 공통 "통합검색어 강조"를 구매자재 현황 화면 전체에 적용했다. 글에 적힌 구매요청현황·구매발주현황 두 화면에 더해 구매자재에서 만든 가입고현황·입고현황·자재수입검사현황과 매입마감처리(입고 행)에도 같은 방식으로 적용했다. 조회에 적용된 검색어와 일치하는 글자가 지정 컬럼 셀에서 빨간색으로 보이고, 입력만 하고 조회하지 않으면 강조하지 않는다. 서버·DB 변경 없음.

## 적용 내용
`highlightKeyword`에는 `search.appliedFilters?.keyword`(조회에 적용된 값)를 넘기고, 서버 통합검색 SQL이 검색하는 컬럼에만 `highlightSearch: true`를 지정했다(컬럼은 매퍼 SQL에서 확인). 링크 컬럼은 `F1GridHighlightText`로 강조하고 링크 접근성 이름과 동작은 그대로다.

- 구매요청현황: 요청번호(링크), 요청자, 품목코드, 품목명 — [Page](../../../../frontend/src/pages/materials/request/status/PurchaseRequestStatusPage.tsx), [컬럼](../../../../frontend/src/pages/materials/request/status/data/purchaseRequestStatusColumns.tsx)
- 구매발주현황: 발주번호(링크), 구매처, 발주담당자, 품목코드, 품목명 — [Page](../../../../frontend/src/pages/materials/order/status/PurchaseOrderStatusPage.tsx), [컬럼](../../../../frontend/src/pages/materials/order/status/data/purchaseOrderStatusColumns.tsx)
- 가입고현황: 가입고번호(링크), 구매처, 담당자, 품목코드, 품목명 — [Page](../../../../frontend/src/pages/materials/arrival/status/MaterialArrivalStatusPage.tsx), [컬럼](../../../../frontend/src/pages/materials/arrival/status/data/materialArrivalStatusColumns.tsx)
- 입고현황: 입고번호(링크), 구매처, 담당자, 품목코드, 품목명. 가입고번호·검사번호는 통합검색 대상이 아니라 강조하지 않음 — [Page](../../../../frontend/src/pages/materials/receipt/status/MaterialReceiptStatusPage.tsx), [컬럼](../../../../frontend/src/pages/materials/receipt/status/data/materialReceiptStatusColumns.tsx)
- 자재수입검사현황: 검사번호(링크), 가입고번호(링크), 구매처, 검사자, 품목코드, 품목명 — [Page](../../../../frontend/src/pages/quality/inspect/status/MaterialInspectionStatusPage.tsx), [컬럼](../../../../frontend/src/pages/quality/inspect/status/data/materialInspectionStatusColumns.tsx)
- 매입마감처리: 입고 행의 품목코드·품목명(구매처 요약 그리드는 키워드로 구매처를 검색하지 않아 제외) — [Page](../../../../frontend/src/pages/materials/receipt/closing/MaterialReceiptClosingPage.tsx), [컬럼](../../../../frontend/src/pages/materials/receipt/closing/data/materialReceiptClosingColumns.tsx)
- 문서: [F1-GRID.md](../../../../frontend/src/pages/f1-grid-docs/F1-GRID.md) "통합검색어 강조"에 구매자재 적용 화면 추가

## 구현 중 바로잡은 것
- 링크 컬럼에 일괄 치환을 적용하다가 링크의 `aria-label` 템플릿 문자열까지 강조 컴포넌트로 바뀌어(`[object Object]` 이름이 될 뻔함) 되돌렸다. 테스트가 접근성 이름을 확인한다.

## 검증
| 항목 | 결과 |
| --- | --- |
| 신규 테스트 | `purchase-search-highlight.test.tsx` 11개: 여섯 화면의 강조 컬럼이 사양 표와 정확히 일치(입고현황은 가입고번호 제외), 링크 컬럼의 강조·대소문자 무시·모든 일치 구간, 검색어 없으면 기존 렌더, 접근성 이름·클릭 동작 유지, 미연결 가입고번호는 일반 텍스트로 강조 |
| 페이지 테스트 | 입고현황: 입력만 하면 강조 없음 → 조회 후 입고번호 강조(가입고번호는 강조 없음) → 검색어를 비워 조회하면 사라짐 |
| 회귀 | 구매요청·구매발주·가입고·입고·수입검사 현황, 매입마감, `f1-grid-highlight-keyword`, `f1-grid-docs`, `f1-grid-render-performance` 포함 10개 파일 130개 통과, `tsc` 통과 |
| 실서버·브라우저 1920/1280/768/375px | 여섯 화면 모두 조회 전·입력 중에는 강조 없음, 조회 후 지정 컬럼에서 검색어와 같은 글자만 강조(`2026`, 매입마감은 `샘플`). 가로 넘침 0px, 페이지 오류 0, 실패 API 0 (매입마감은 오른쪽 그리드 가로 스크롤 때문에 1920px에서만 강조 확인) |

## 확인하지 못한 것
- 매입마감처리의 강조는 1920px에서만 브라우저로 확인했다(좁은 폭에서는 품목 열이 가로 스크롤 밖이라 보이지 않음).
- 구매요청확정·발주등록의 불러오기 창(선택기) 그리드는 현황 화면이 아니어서 적용하지 않았다.
- 서버 통합검색 SQL의 검색 컬럼이 바뀌면 컬럼 지정도 같이 바꿔야 한다(사양서 유지 보수 메모).
