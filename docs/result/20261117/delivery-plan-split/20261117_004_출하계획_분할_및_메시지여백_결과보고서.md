# 출하계획 분할 및 메시지 여백 결과

> 메시지 여백은 이후 모든 메시지 종류에 동일하게 적용하도록 다시 통일되었다. 아래 최초 여백 조정 내용은 당시 이력이며 현재 기준은 [영업 등록 메시지 여백 결과](../sales-entry-message-spacing/20261117_005_영업등록_메시지여백_통일_결과보고서.md)를 따른다. 현재 오류 메시지와 기본정보의 좌우 경계는 같고 상단 여백은 8px, 다음 영역 간격은 16px이다.

## 변경

- AUTO 기존 계획의 수정 한도를 원본 조회 잔량과 현재 계획의 기존 수량 합으로 계산한다. 다른 계획이 차지한 수량은 제외하고 수주수량을 넘지 않는다. MANUAL 신규 잔량 및 현황 수정 검증은 유지한다.
- 출하수량이 있는 상세의 계획일·계획수량 편집, 분할, 분할행 삭제를 비활성화한다. 미출하 형제 행은 편집할 수 있고 서버의 출하 참조 검증은 유지한다.
- 출하계획등록 오류 메시지는 위아래 24px로 맞추고 기본정보 영역과 좌우 경계를 일치시킨다. 오류 표시 전후에도 본문 좌우 위치를 유지한다. 이전 성공 알림은 검증 오류 발생 시 제거한다. 다른 화면과 선택 대화상자는 변경하지 않았다.

## 재현과 원인

- 자동 생성 계획이 수주수량을 모두 차지한 경우 원본 조회 잔량은 0이다. 수정 시 기존 계획 수량을 더하지 않아 100을 50·50으로 나누어도 클라이언트가 수량 초과로 거부했다.
- 기존 합계를 현재 계획 한도에 포함하고, 저장 이후 한도를 중복 증가시키지 않도록 원본 조회 시점의 값을 유지한다.
- 화면에서는 출하된 행도 분할 버튼이 활성화되었지만 변경된 행의 저장은 서버에서 거부됐다. 출하수량이 확인되는 행을 화면에서도 비활성화했다. 출하수량만으로 식별되지 않는 참조 이력과 동시 변경은 서버가 최종 검증한다.
- 첫 여백 수정은 상하 간격만 확인하여 공통 메시지의 추가 좌우 패딩 24px이 남았다. 실제 브라우저에서 메시지와 기본정보의 양쪽 좌표 및 오류 전후 위치를 비교하도록 검증을 보완했다.

## 검증

- 출하계획 페이지 Vitest 28건 통과. 다른 계획이 사용한 수량의 경계값을 보완한 테스트도 별도로 통과했다.
- 프론트엔드 빌드 및 변경 파일 oxlint 통과.
- 합성 데이터와 API 모의 응답을 사용한 Playwright 브라우저 검사에서 768·1280px 분할 저장 및 출하된 행 비활성화를 확인했다.
- 375·768·1280px에서 오류 메시지 상하 간격이 각각 24px이고 메시지와 기본정보의 양쪽 경계가 일치하며 페이지 전체 가로 넘침이 없음을 확인했다. 오류 전후 기본정보의 좌우 위치도 일치한다. 375px 캡처는 768px에서 오류를 발생시킨 뒤 뷰포트를 축소한 결과이며 모바일 행 편집 흐름은 별도로 실행하지 않았다.
- 현재 수주등록 기준으로 다시 캡처한 화면: [375px](screenshots/plan-error-375.png), [768px](screenshots/plan-error-768.png), [1280px](screenshots/plan-error-1280.png)
- 기존 공유 개발 서버를 재사용했고 서버·업무 데이터·DB는 변경하지 않았다.
