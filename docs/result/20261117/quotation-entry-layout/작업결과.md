# 견적서작성 레이아웃 및 품목 입력 개선 결과

## 구현 내용

- 견적 기본정보를 수주등록과 같은 반응형 그리드 간격 및 거래처 picker 정렬 규칙으로 맞췄다. 기존 필드 순서와 데이터 계약은 유지했다.
- 견적작성일·제출일에 공통 `DateEditor`를 적용해 달력 및 축약 날짜 입력을 제공한다. 잘못된 날짜는 오류로 표시하고 저장을 막는다.
- 견적 상세의 품목코드는 F1-Grid 코드 선택 셀로 변경했다. 셀과 기존 툴바의 품목 선택에서 마스터를 선택할 수 있으며, 직접 입력 행은 품목명만 편집 가능하다. 품목명을 수기로 바꾸면 마스터 참조와 코드·규격·단위 스냅샷을 제거한다.
- 견적 API/DB와 수주등록 로직은 변경하지 않았다.

상세 기준은 [작업지시서](../../../directions/20261117/20261117_002_견적서작성_레이아웃_품목입력_개선_작업지시서.md), [계획서](../../../plan/20261117/20261117_002_견적서작성_레이아웃_품목입력_개선_계획서.md), [상세사양서](../../../spec/20261117/20261117_002_견적서작성_레이아웃_품목입력_상세사양서.md), [설계서](../../../superpowers/specs/2026-11-17-quotation-entry-layout-design.md)를 참고한다.

## 브라우저 확인

기존 `http://127.0.0.1:4173` iPlusMES 개발 서버에서 합성 API 응답으로 견적작성 화면을 열었다. 375px, 768px, 1280px에서 페이지 가로 넘침이 없었고, 날짜 달력 열기 및 `1118` 입력의 `2026-11-18` 정규화, 품목코드 셀 및 툴바의 품목 선택 다이얼로그를 확인했다. 1280px에서 기본정보 첫 행 필드의 상단 정렬도 확인했다.

## 검증

- `npm --prefix frontend run test -- tests/quotation-create-page.test.tsx tests/quotation-create-api.test.ts`: 10개 테스트 통과.
- `npm --prefix frontend run build`: 통과.
- 변경 파일 대상 Oxlint: 종료 코드 0. 견적 작성 파일의 기존 effect 관련 경고 2건이 출력됐다.
- `git diff --check`: 통과.
- 견적현황 회귀 테스트도 실행했으나 `quotation-status-page.test.tsx`가 상세 열기 전에 합성 목록 행 `QT-20261116-0001`을 찾지 못해 실패했다. 견적현황 소스는 이번 변경에 포함되지 않았으며, 견적 등록/API 테스트와 실제 견적작성 브라우저 확인은 통과했다. 이 회귀 테스트의 실패 원인은 이번 작업 범위에서 확인하지 못했다.
