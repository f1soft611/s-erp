# 20261026_005 커뮤니티 자료실 그리드 전체 높이 결과

## 원인 및 변경

자료실 페이지의 마지막 그리드 영역은 `flex: 1`이 있었지만 flex 컨테이너가 아니어서 자식 그리드로 남은 화면 높이가 전달되지 않았다. 그리드 호스트를 세로 flex 컨테이너로 바꾸고 내부 오버플로를 제한해 `ArchiveFileGrid`와 `F1Tree(height="100%")`가 가용 높이를 사용하게 했다.

현재 워크트리에 있던 자료실 로딩 변경은 보존했다. 검색, 경로, 권한 및 파일 동작, API와 공통 F1-Grid/F1Tree는 변경하지 않았다.

## 검증

- 변경 전 기준선: 자료실 페이지 테스트 18개 통과.
- 회귀 테스트: flex 컨테이너 검증을 먼저 추가했고, 구현 전 테스트가 그리드 컨테이너 부재로 실패하는 것을 확인했다. 변경 후 `npm run test -- tests/archive-page.test.tsx`에서 19개 테스트 모두 통과했다.
- 빌드: `npm run build` 통과. 기존 번들에서 1000 kB 초과 청크 경고가 있었으나 빌드는 성공했다.
- 전체 프런트엔드 테스트: `npm run test` 실행 결과 121개 파일 중 28개 실패/93개 통과, 1,497개 테스트 중 209개 실패/1,288개 통과, 런타임 오류 10건이 보고됐다. 실패 파일은 대시보드, 결재, 공통코드 등 이 레이아웃 변경 범위 밖을 포함한다. 변경 전 전체 테스트 기준선은 없으므로 사전 존재 여부나 원인은 확인되지 않았다.
- 브라우저: 기존 S-ERP 서버 `http://127.0.0.1:4173`의 자료실 화면에서 높이 900px로 확인했다.

| 뷰포트 | 그리드 호스트(top / bottom / height) | 그리드(bottom / height) | 문서 가로 스크롤 |
| --- | --- | --- | --- |
| 375 × 900 | 404 / 900 / 496px | 884 / 480px | 없음 (375 / 375px) |
| 768 × 900 | 360 / 900 / 540px | 884 / 524px | 없음 (768 / 768px) |
| 1280 × 900 | 324 / 900 / 576px | 884 / 560px | 없음 (1280 / 1280px) |

세 폭 모두 그리드 호스트가 뷰포트 하단까지 이어지고 그리드가 내부 하단 여백 16px을 제외한 공간을 채우는 것을 확인했다. 캡처는 파일 목록을 표시하지 않도록 일치하지 않는 임시 검색어를 적용한 상태다.
