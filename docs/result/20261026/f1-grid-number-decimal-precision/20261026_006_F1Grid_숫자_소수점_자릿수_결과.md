# F1-Grid 숫자 소수점 자릿수 결과

## 변경 내용

- 기존 `decimalPlaces` 컬럼 옵션을 유지하고 새 숫자 포맷 옵션은 추가하지 않았다.
- `number`/`decimal` 컬럼의 기본 화면 표시를 최대 소수점 이하 5자리로 변경했다. 소수부 끝의 0과 불필요한 소수점은 표시하지 않는다.
- 명시된 `decimalPlaces`는 기존처럼 고정 자릿수로 표시한다.
- Excel 기본 숫자 서식도 `#,##0.#####`로 맞췄다. 통화 기본 0자리와 명시 자릿수는 유지한다.
- F1-Grid API 문서와 Excel 내보내기 사양을 갱신했다.

## 원인 및 해결

일반 숫자 화면 표시와 Excel 기본 서식이 각각 최대 3자리(`maximumFractionDigits: 3`, `#,##0.###`)로 설정되어 있어 4~5자리 정밀도가 기본 표시에서 반올림되어 손실됐다. 화면 포맷터 기본 최대값을 5로 바꾸고 Excel 서식에 선택 자리표시자 5개를 적용했다. 편집 입력 제한 및 원본 데이터는 변경하지 않았다.

## 검증 결과

- `npm run test -- tests/f1-grid-date-format.test.tsx tests/f1-grid-excel-export.test.ts`: 통과, 36 tests. `F1Grid`를 실제 렌더링해 정수 `1`과 소수 `1.234567`이 각각 `1`, `1.23457`로 표시되는 것도 검증했다.
- `npx vitest run tests/f1-grid-docs.test.tsx -t "documents the full editing contract including plugins and number format"`: 통과, 1 test.
- `npm run build`: 통과. Vite는 기존 1MB 초과 번들 경고를 출력했으나 빌드에는 영향이 없었다.
- 브라우저의 F1-Grid 편집 문서에서 기본 숫자/명시 자릿수/통화 예제를 확인했다. 실제 셀 출력 정밀도는 회귀 테스트로도 검증했다.
- 기준선의 문서 포털 전체 테스트 실행에서는 검색 테스트 1건이 5초 시간 초과했으나, 해당 테스트 단독 재실행은 4.2초에 통과했고 변경과 관련된 편집 문서 계약 테스트도 통과했다.
- 전체 `npm run test`는 121개 파일 중 29개 파일, 1501개 테스트 중 224개 테스트 실패로 종료됐다. 다수는 이 작업과 무관한 화면의 접근성 역할/문구 및 시간 초과 관련 실패였으며, 전체 실패 원인은 별도로 조사하지 않았다. 이 때문에 전체 프론트엔드 테스트 통과로 간주하지 않으며, 위의 기능 관련 포커스 테스트 결과만 보고한다.
