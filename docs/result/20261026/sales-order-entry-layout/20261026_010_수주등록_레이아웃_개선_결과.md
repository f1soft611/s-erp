# 20261026_010 수주등록 레이아웃 개선 결과

## 작업 범위

- 기본정보 카드와 필드 순서를 유지하고, xs는 1열, sm은 2열, lg는 4열로
  배치한다. 1280px에서 첫 행은 수주번호·수주일자·거래처·견적번호,
  둘째 행은 납기일자·납품장소·배송방법·수주상태이며 비고는 전체 행을 쓴다.
- 거래처 선택 버튼은 입력 옆을 유지하고 높이와 최소 높이를 40px로 맞춘다.
- 브라우저에서 picker의 입력/버튼이 행의 다른 입력보다 16px 위에 있음을
  발견해 picker 상단 간격을 일반 입력 필드에 맞췄다.
- 375px에서 수주번호 read-only 안내가 잘리는 것을 확인해 xs 글자 크기만
  12px로 조정했다. 안내 값과 입력 동작은 그대로다.
- 거래처/품목 검색, 선택, 상세 그리드, API, 데이터 계약은 변경하지 않았다.

## 자동 검증

`frontend`에서 실행:

```text
npm run test -- tests/master-picker.test.tsx tests/sales-order-create-page.test.tsx tests/sales-order-scroll.test.tsx
```

결과: 3개 파일, 10개 테스트 통과. picker 높이와 상단 간격 테스트가 포함된다.
`npm run build`도 TypeScript 검사와 Vite 프로덕션 빌드까지 통과했다.

## 실제 브라우저 검증

`http://127.0.0.1:4173`의 기존 S-ERP Vite 서버를 재사용했다. 일반 브라우저
세션에서는 `/sales/order/create` 접속이 `/login`으로 이동했고 로그인도
거절되어, Chromium 격리 컨텍스트에만 임시 테스트 세션을 설정하고 메뉴/모듈
API를 모의해 실제 애플리케이션 라우트의 UI를 렌더링했다. 실제 인증정보나
업무 데이터는 사용하지 않았다.

| 뷰포트 | 결과 |
| --- | --- |
| 375px | `document`/`body` 폭 375px. 페이지 가로 넘침과 필드 이탈 없음. 수주번호 안내 렌더링 폭 184.4px, 가용 폭 209px로 전체 표시 확인. |
| 768px | `document`/`body` 폭 768px. 가로 넘침과 필드 이탈 없음. |
| 1280px | `document`/`body` 폭 1280px. 기본정보 첫째/둘째 행 필드가 각 행에서 세로 정렬됨. picker 입력/버튼 높이 각 40px이며 비고가 전체 행 너비를 사용. |

각 뷰포트에서 필드 경계와 페이지 overflow를 확인했으며 Chromium 페이지 오류는
없었다.
