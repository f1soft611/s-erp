# 20261026_012 수주등록 거래처·품목 도움창 디자인 개선 결과

## 작업 결과

- 거래처/품목 선택 다이얼로그에 공통 `CommonDialog`를 적용했다.
- 선택 필드 및 선택 버튼, 검색 필드 및 검색 버튼의 실제 렌더링 높이가 모두
  40px임을 확인했다.
- 검색 버튼에 검색 아이콘과 둥근 모서리를 적용하고, 검색 결과는 코드 칩과
  이름을 구분해 선택하기 쉽게 정리했다.
- 검색, Enter 입력, 선택 값 전달, 로딩/빈 결과/오류 및 오래된 응답 무시
  동작은 유지했다.

## 자동 검증

`frontend`에서 실행:

```text
npm run test -- tests/master-picker.test.tsx tests/sales-order-create-page.test.tsx tests/sales-order-scroll.test.tsx
```

결과: 3개 파일, 10개 테스트 통과.

```text
npm run build
```

결과: TypeScript 검사 및 Vite 프로덕션 빌드 통과.

수정 컴포넌트 대상 Oxlint도 통과했다. 저장소 전체 `npm run lint`는 수정과
무관한 기존 파일의 React 경고를 출력하며 종료 코드 1을 반환했다. picker 파일
범위에서는 오류가 없었다.

## 실제 브라우저 검증

기존 `http://127.0.0.1:4173` S-ERP 개발 서버를 재사용했다. 테스트 전용
Chromium 세션에 임시 인증 상태를 설정하고 메뉴/모듈 응답을 모의했다.
실제 로그인 정보나 거래처/품목 업무 데이터는 사용하지 않았다. 각 폭에서
거래처 도움창을 열고, 상세 행을 추가한 뒤 품목 코드 선택을 통해 품목
도움창도 열어 확인했다.

| 뷰포트 | 도움창 크기 | 컨트롤 높이 | 문서/본문 폭 | 결과 |
| --- | --- | --- | --- | --- |
| 375px | 전체 화면 375px | 입력/버튼 모두 40px | 375px / 375px | 잘림 및 페이지 가로 overflow 없음 |
| 768px | 480px | 입력/버튼 모두 40px | 768px / 768px | 잘림 및 페이지 가로 overflow 없음 |
| 1280px | 480px | 입력/버튼 모두 40px | 1280px / 1280px | 잘림 및 페이지 가로 overflow 없음 |

세 뷰포트 모두 거래처와 품목 도움창의 검색 영역 및 초기 안내가 정상
렌더링됐고, 브라우저 페이지 오류는 없었다.

## 후속 정렬 보정

화면 검토에서 검색 입력 테두리와 검색 버튼의 세로선이 어긋나는 문제가
확인됐다. 원인은 MUI `TextField`의 기본 세로 여백으로, 바깥 입력 컨트롤
영역과 내부 40px 입력 테두리의 기준선이 버튼과 달랐다. 검색 입력의 기본
여백을 제거하고 두 요소를 가운데 정렬해 수정했다.

수정 후 실제 Chromium 렌더링에서 375px, 768px, 1280px 모두 입력과 버튼의
상단/하단 좌표가 같고 높이가 각각 40px임을 확인했다. 거래처 및 품목 모두
페이지 가로 overflow와 브라우저 오류가 없었다. 아래 스크린샷은 수정 이후
다시 캡처한 이미지다.
