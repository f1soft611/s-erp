# 수주 선택 모달 레이아웃 결과서

## 보고 내용 및 원인

납품등록의 `수주 선택` 모달에서 검색/표가 깨져 보인다는 사용자 보고와 첨부 화면을 검토했다. 페이지용 `PageSearchArea`는 검색 영역을 최대 360px로 제한하므로 990px 모달 안에서도 검색 입력이 약 320px만 사용했고, 검색 버튼이 분리되어 남는 공간이 크게 보였다. 그리드 8개 열의 너비 합계는 1080px로 모달 내부 가용 폭(약 940px)보다 커서 데스크톱 화면에서도 `잔량` 열이 잘리고 가로 스크롤이 생겼다.

## 수정 내용

- 페이지용 검색 컴포넌트를 이 모달 전용 `<form>`으로 교체. 검색창이 가용폭을 채우며 버튼은 같은 줄 오른쪽에 위치한다.
- 폼 제출로 Enter와 검색 버튼이 동일 검색 요청을 호출한다.
- 검색 입력 테두리와 검색 버튼에 공통 40px 높이를 명시했다. 입력 크기 기준이 테마/기본 스타일에 따라 달라져 버튼과 어긋나지 않게 동일한 상수를 적용한다.
- 8개 그리드 열을 총 891px로 축소하고 수주번호 선택 버튼은 줄바꿈 없이 읽을 수 있게 유지한다.
- 모달 본문은 고정 420px 목록 대신 fill 레이아웃으로 구성해 높이를 활용한다. 작은 화면에서는 F1-Grid 내부 가로 스크롤만 사용한다.
- 수주/품목 데이터, 검색 API, 한 수주의 전체 잔량 라인을 선택하는 동작은 변경하지 않았다. 공통 Dialog/F1-Grid는 수정하지 않았다.

## 검증

| 검증 | 결과 |
|---|---|
| 회귀 테스트 | 기존 UI에서 검색 영역 form이 없는 상태로 새 회귀 테스트가 실패하는 것을 확인, 수정 후 통과 |
| 납품 페이지 테스트 | `npm run test -- tests\sales-delivery-page.test.tsx` 13/13 |
| 빌드 | `npm run build` 성공 |
| 변경 파일 lint | `npm run lint -- src\pages\sales\delivery\create\components\SourceOrderPicker.tsx tests\sales-delivery-page.test.tsx` 성공 |
| 브라우저 | 기존 S-ERP Vite 서버(127.0.0.1:4173)를 재사용; synthetic API fixture만 사용 |
| 뷰포트 | 375x800, 768x900, 1030x668(첨부 화면 비율), 1280x900 모두 페이지 가로 overflow 없음 |
| 검색/UI | 3개 뷰포트에서 검색 버튼, 1030x668에서 Enter 검색을 실제 브라우저로 확인 |
| 그리드 | 1030/1280px에서 8개 열 전부 한 화면에 보이고 내부 수평 overflow 없음. 375/768px는 표 내부 수평 스크롤만 사용 |
| 검색 높이 | Vitest computed-style 회귀 확인 및 네 뷰포트 브라우저 측정에서 입력/버튼 모두 정확히 40px |

브라우저 API는 합성 데이터만 사용했으며 운영 DB/API에 대한 검증은 아니다.
