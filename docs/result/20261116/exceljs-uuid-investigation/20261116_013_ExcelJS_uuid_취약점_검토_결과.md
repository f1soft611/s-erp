# ExcelJS uuid 취약점 검토 결과

## 확인

- 남은 audit 2건은 ExcelJS와 그 전이 의존성 `uuid`를 가리킨다. [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq)는 외부 버퍼를 사용하는 `v3`, `v5`, `v6`의 범위 검사 문제이며 `v4`는 해당 대상이 아니다.
- ExcelJS 4.4.0의 Node 소스에서 확인한 UUID 호출은 `v4()`다. 프로젝트의 ExcelJS 사용은 엑셀 다운로드와 업로드다. 이 확인만으로 모든 경로의 악용 가능성이 없다고 단정할 수는 없다.
- ExcelJS는 브라우저용으로 미리 묶인 `dist/exceljs.min.js`를 제공한다. 배포판의 대응 비압축 파일에는 취약 조건의 `v3`·`v5` 공통 구현이 포함되어 있다.

## 격리 실험

- 별도 스냅샷에서만 ExcelJS의 `uuid`를 `11.1.1`로 override했다. audit은 0건이 되었고 엑셀 관련 테스트 10건 및 빌드가 통과했다.
- override 전후 ExcelJS 브라우저 배포 파일의 SHA-256은 동일했고 실제 빌드 결과에도 UUID 네임스페이스 표식이 남았다. 따라서 audit 결과만 0건으로 만드는 override가 브라우저에 포함된 코드를 수정하지는 않는다.
- 사용자 작업 공간과 잠금 파일에는 실험용 override를 적용하지 않았다.

## 후속 조치

- 현재 처리 상태와 재개 기준은 [2026-11-19 ExcelJS 보류 결정](../../20261118/repository-remediation/20261118_027_dependency-remediation-boundary_결과.md#exceljs-보류-결정-2026-11-19)을 따른다.
- 브라우저 번들에 수정된 UUID가 반영되는 ExcelJS 배포본 또는 유지보수 가능한 대체 방식을 별도 검토한다. 지원하지 않는 주요 버전 강제 변경이나 취약점이 해결된 것처럼 보이게 하는 단순 override는 피한다.
- 전체 브라우저 사용 경로와 실제 악용 가능성은 확인되지 않았다. [과거 엑셀 메뉴 캡처](screenshots/historical-excel-export.png)는 참고용이며 이번 실험의 브라우저 검증 결과가 아니다.
