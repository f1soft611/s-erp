# 견적관리 화면 추가 작업 결과

## 작업 내용

- 영업관리 > 견적관리에 `견적서작성` 및 `견적현황`을 추가하고, 품목 마스터 선택과 수기 입력을 지원했다. 수기 품목은 견적 상세 스냅샷으로 저장하며 품목 마스터는 변경하지 않는다.
- 수주등록에 선택 사항인 견적 선택기를 추가하고 기존 `quotNo` 계약 및 직접 입력 동작을 유지했다.
- 테넌트별 견적 헤더·상세 스키마/API와 견적관리 메뉴 seed·롤백 SQL을 추가했다. 작업장, 소수점 정책 등 별도 요청 항목은 이 작업 범위에서 제외했다.
- 상세 기준은 [작업지시서](../../../directions/20261116/20261116_014_견적관리_작업지시서.md), [계획서](../../../plan/20261116/20261116_014_견적관리_계획서.md), [상세사양서](../../../spec/20261116/20261116_014_견적관리_상세사양서.md)를 참고한다.

## 검증 결과

- 견적 프론트엔드 집중 테스트: 18개 통과. 수주 견적 연결 및 견적 API 집중 테스트: 39개 통과.
- 프론트엔드 `npm run build`: 통과.
- 백엔드 전체 `mvn test`: 1,130개 테스트, 실패·오류 0개, 3개 건너뜀.
- 전체 프론트엔드 테스트 실행은 194개 파일 중 31개 파일이 실패했고 142개 테스트가 실패했다(2,137개 통과). 실패에는 시간 초과와 기존 수주현황·테마 테스트가 포함되어 있으며, 위 변경 범위의 집중 테스트는 통과했다.
- `git diff --check`: 통과.

## DB 및 메뉴 seed

- 읽기 전용 DB MCP의 테이블 목록과 필요한 테이블 메타데이터를 확인했다. 테넌트 업무 데이터 행은 조회하지 않았다.
- 설계 시점 MCP 조회에서는 견적 테이블이 없었으나, 이후 `list_tables`에서 견적 헤더·상세 테이블이 확인됐다. 본 작업에서 DDL을 적용하지 않았으므로 해당 테이블의 반영 주체와 시점은 확인되지 않았다. 상세 근거는 [스키마 변경 이력](../../../database/20261116/20261116_002_change_sales_quotation_schema.md)에 기록했다.
- 견적 메뉴 seed와 롤백 스크립트는 `docs/database/20261116/` 및 `backend/DATABASE/20261116/`에 동일하게 준비했다. 실제 DB DDL 또는 seed 쓰기는 수행하지 않았다.
- seed 실행 전 승인된 테넌트 ID를 스크립트의 `v_tenant_id`에 지정해야 한다. 메뉴 롤백은 행을 삭제하지 않고 비활성화하므로, 해당 메뉴 코드가 seed 이전부터 존재했다면 실행하지 않는다.
