# 출하현황 상세 작성자 프로필 적용 결과서

## 작업 결과

- 원인: 출하 상세 조회 응답에 작성자 ID만 포함되어 상세 패널이 사용자 ID를 이름으로 표시하고 프로필 이미지·등록일을 받지 못했다.
- `selectDelivery`에서 테넌트 범위 `tb_login_account`·`tb_user` 조인을 추가해 `createdByName`, `createdByProfileImage`, `createdAt`을 반환한다.
- 상세 패널은 이름과 프로필 이미지를 적용하고 등록일을 표시한다. 프로필 정보가 없으면 기존 ID 및 아바타 fallback을 유지한다.
- 등록·수정 흐름, 목록 및 DB 스키마는 변경하지 않았다.

## DB 계약 확인

- 기본 `s-erp-postgresql-readonly` MCP의 `list_tables`에서 `tb_login_account`, `tb_user`를 확인했다.
- `describe_table` 결과로 로그인 코드·로그인 ID·테넌트 ID·프로필 이미지와 사용자명·로그인 ID·테넌트 ID 컬럼을 확인했다. 개인정보가 포함될 수 있는 데이터 행은 조회하지 않았다.
- 스키마 변경 없음.

## 검증

- 회귀 테스트는 수정 전에 작성했으며, 프론트엔드 테스트에서 기존 작성자 ID만 표시되는 실패를 확인했다.
- `frontend`: `npm run test -- tests/sales-delivery-page.test.tsx` 통과 (22 tests).
- `frontend`: `npm run build` 통과.
- `backend`: `mvn "-Dtest=SalesDeliveryMapperTest,SalesDeliveryApiControllerTest" test` 통과 (11 tests).
- 실제 출하현황 상세를 Orca 브라우저에서 확인했다. 375px, 768px, 1280px에서 작성자명·프로필 이미지·등록일이 표시되며, 브라우저 콘솔 오류는 없었다.
