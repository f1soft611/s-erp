# F1Grid 저장키 누락 보완 결과

## 범위와 원인

실제 F1Grid/F1Tree 호출부 10곳에 `storageKey`가 없어 컬럼 순서·너비·숨김·고정 설정이 저장되지 않았다. 누락 호출부에 키를 지정하고 기존 키는 유지했다. 분류 종류와 선택 수준, 결재선/참조자 모드, 출하계획 등록/현황 상세를 구분했다. 자세한 기준은 [사양](../../../spec/20261116/20261116_004_F1Grid_저장키_누락_보완_사양서.md)에 기록했다.

## 검증

- 저장키 누락·정적 중복 및 분류/결재/공유 폼 저장 분리: 11건 통과.
- 연관 5개 테스트 파일 전체: 100건 통과, 2건 실패. 결재선 부분 이름 변경 실패 후 재시도와 출하계획 행 높이 기대값 실패는 해당 두 그리드의 신규 저장키를 일시 제거한 상태에서도 동일하게 재현됐다.
- 공정관리·출하·거래명세서 테스트: 31건 통과, 거래명세서 1건 시간 초과. 거래명세서 파일 단독 재실행 시 2건 모두 통과했다.
- 변경 파일 lint: 오류 0건, 기존 경고 3건. 프론트엔드 빌드 및 타입 검사 통과. 일부 기존 React `act` 경고가 출력됐다.
- 별도 포트와 가상 데이터로 공유 출하계획 폼을 실제 브라우저에 렌더링했다. 등록 폼에서 품목명 컬럼을 숨긴 뒤 새로고침해 복원됨을 확인했고, 현황 폼에는 영향을 주지 않음을 확인했다.
- 가상 데이터로 렌더링한 공유 폼에서 375/768/1280px 뷰포트를 확인했다. 페이지 가로 넘침은 없고 넓은 그리드는 내부에서 스크롤된다. [모바일](screenshots/mobile-375.png), [태블릿](screenshots/tablet-768.png), [데스크톱](screenshots/desktop-1280.png) 스크린샷을 보관했다. 전체 업무 화면 및 다른 호출부의 브라우저 검증은 수행하지 않았다.

## 후속 조치

- 남은 두 테스트 실패를 각각 조사한다.
- 격리된 테스트 계정으로 나머지 업무 화면의 저장·재진입을 확인한다.
