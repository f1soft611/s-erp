# 20261120_001 인사관리 2-2단계 계정관리 결과

기준: [작업지시서](../../../directions/20261120/20261120_001_hr-account_작업지시서.md), [계획서](../../../plan/20261120/20261120_001_hr-account_계획서.md), [상세사양서](../../../spec/20261120/20261120_001_hr-account_상세사양서.md)

## 1. 구현 범위
| 단계 | 내용 |
|---|---|
| A 계정관리 | 환경설정 > 시스템 관리 > 계정관리(`/settings/system/accounts`). 목록·통합검색·상태 필터(전체/사용/미허용/잠김/퇴직), 허용/미허용, 비밀번호 초기화(임시 비밀번호 1회 표시), 잠금 해제, 권한 변경. 자기 자신 미허용·마지막 관리자 제거·역할 0개는 서버가 거부 |
| 잠금 정책 | 정책관리 「계정·보안」: `LOGIN_LOCK_ENABLED`(기본 미사용), `LOGIN_LOCK_MAX_ATTEMPTS`(기본 5, 3~10). 미사용이면 로그인 동작 불변. 정책 3종은 정책관리를 열 때 없으면 자동 생성 |
| B 변경 강제 | 초기화·사원등록 발급 계정은 변경 전까지 비밀번호 변경 외 API 403(`PASSWORD_CHANGE_REQUIRED`), 화면은 변경 화면만. 변경 후 로그아웃·재로그인. 새 비밀번호는 현재와 달라야 함 |
| C 사진·내 정보 | `PROFILE_PHOTO_EDIT_MODE`(SELF/ADMIN_ONLY), 내 정보에 사번·직위 표시, 사진 변경 시 사원 마스터 동기화, 퇴직일이 지난 사원 로그인 차단 |

DB: [20261120_001](../../../../backend/DATABASE/20261120/20261120_001_change_extend_login_account_menu.md)(컬럼 2개·메뉴), [20261120_002](../../../../backend/DATABASE/20261120/20261120_002_change_seed_account_security_policies.md)(정책 시드·사진 보정). 사용자가 적용함(MCP로 컬럼 2·메뉴 1·정책 3 확인). 사진 보정 후 사원 사진 12건(적용 전 9건).

## 2. 구현 중 발견·수정한 것
1. **토큰 갱신이 DB를 보지 않음**: 미허용·퇴직 처리해도 갱신 토큰(7일)이 살아 있으면 계속 사용 가능했다. 갱신 때 계정 상태(허용·사용 중 사원·미퇴직)와 변경 필요 여부를 DB에서 읽도록 수정(`/auth/refresh`). 액세스 토큰은 15분이라 미허용은 최대 15분 안에 반영된다.
2. **내 정보 응답에 새 필드가 빠짐(실서버 점검에서 발견)**: 컨트롤러가 응답 필드를 직접 나열해서 `employeeNo`·`positionNm`·`photoEditable`이 나가지 않았다. 단위 테스트(서비스·모킹)는 통과했으나 실서버 응답으로 확인되어 컨트롤러 테스트를 추가하고 수정했다. 회귀 항목: 내 정보 응답 필드 계약.
3. **내 정보 저장 때마다 프로필 사진 재압축**: 사진이 바뀌지 않았으면(받은 값을 그대로 돌려보냄) 다시 해석·압축하지 않고 사원 마스터도 덮어쓰지 않는다.
4. 계정 목록 상태 열이 1280px에서 가로 스크롤에 가려져 앞쪽으로 옮겼다.

## 3. 검증
| 항목 | 결과 |
|---|---|
| 백엔드 `mvn test` 전체 | 1,476건 통과(실패 0, 건너뜀 3). 이후 내 정보 컨트롤러 테스트 1건 추가·통과 |
| `javac --release 8` 호환 컴파일 | 통과 |
| 프론트 관련 테스트 | 계정관리 12·변경 강제 11·내 정보 8·그리드 키 2 등 통과, `tsc` 오류 없음, 신규 파일 lint 경고 없음 |
| 프론트 전체 vitest | 기존 테스트 중 `push-login-navigation`은 `authService` 모의에 새 export가 없어 실패해 **수정**함. 그 외 실패(13건 시간 초과 + 3건)는 전체 실행 부하 탓으로, 해당 파일을 단독 실행하면 통과(370건 통과). CI 결과로 최종 확인 필요 |
| 실서버 API 점검 | 41건 모두 통과(아래) |
| 브라우저 | 1280/768/375px 가로 넘침 0px, 강제 변경 화면 375/1280 확인 |
| DB MCP 근거 | `tb_login_account`·`tb_user`·`tb_system_policy`·`tb_menu` 구조와 데이터(계정 13, 사진 대조)를 구현 전에 조회 |

실서버 API 점검(41건): 정책 3종 조회, 사원등록 발급 계정의 변경 필요 표시, 변경 전 일반 API 403, 같은 비밀번호 거부, 변경 후 정상 사용, 초기화·임시 비밀번호 로그인·변경, 잠금(3회 실패 후 올바른 비밀번호도 거부, 잠김 필터, 관리자 해제, 성공 시 횟수 초기화, 정책 미사용이면 미잠금), 사진 정책(관리자 전용 거부·변경 없는 저장 허용·본인 허용 시 사원 마스터 반영), 역할 규칙(0개 거부·교체·자기 미허용 409), 미허용 계정 로그인·갱신 401, 퇴직일 로그인 차단과 해제, 정책 기본값 복원.

## 5. 남은 점검 데이터·운영 메모
- 점검 계정 `acct.live.148127`, `acct.live.277516`(사원 `계정점검*`)은 미허용·퇴직 처리해 남겨 두었다. 사원 삭제 기능이 없다.
- 점검 중 바꾼 정책은 기본값(미사용·5회·본인 허용)으로 복원했다.
- 배포 시 **DB 스크립트 → 백엔드** 순서를 지켜야 한다(새 코드가 `password_change_required`를 읽는다).
- 로그인 화면의 "비밀번호를 변경했습니다" 안내(정보 색)는 단위 테스트만 했고 브라우저 로그인 흐름 스크린샷은 없다.
- 후속(범위 밖): 비밀번호 만료·복잡도 정책, 로그인 이력 화면, 시간 경과 자동 잠금 해제.
