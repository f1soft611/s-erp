## 1. 구현 내용
- **DB**: `tb_hr_order_hd`(명령 1건)·`tb_hr_order_dt`(사원별 변경항목 명령 전/후) 생성, 메뉴 `HR_INFO_ORDER`(인사정보 > 인사명령) 등록과 권한([20261120_006](../../../database/20261120/20261120_006_create_hr_order_schema.sql), 롤백·이력·`db-schema.md` 포함, **작성만 했고 적용 전**).
- **서버**(`let/hr/order`): `GET /api/v1/hr/orders/types`·`POST /process`·`GET /history`(모두 테넌트 관리자 전용). 유형 7종(부서이동·승진·승급·근무형태변경·휴직·복직·퇴직)을 즉시 처리하고 한 트랜잭션, 실패 시 전체 취소와 사원명이 붙은 오류. 명령일은 오늘 이하.
- **이력 자동 기록**(`HrOrderHistoryRecorder`): 신규 등록 → 입사 이력(입사일·부서·직위), 사원관리 직접 수정 → 부서·직위·직급·근무형태·입사/퇴직/휴직/복직일 중 **바뀐 것만**, 인사명령 처리 → 명령 1건. 인사명령 처리는 사원 서비스를 `recordHistory=false`로 호출해 중복을 막는다. 이력은 추가만 하고 수정·삭제 SQL이 없다.
- **화면**(`pages/hr/order`, `/hr/info/order-manage`): 탭 2개 — **인사명령 처리**(명령 유형·명령일·명령 후 값·비고 한 번 입력, 사원 선택 도움창 다중 선택으로 대상 담기, 표에서 명령 전 값 확인·사원별 명령 후 값 수정·선택 제외, 발령 처리 → 확인창 → 처리 후 대상 초기화·내역 갱신), **처리 내역**(처리일 기간 기본 최근 30일, 사원명·사번, 유형, 출처).
- 사원 선택 도움창 다중 선택([20261120_007](../../20261120/hr-employee-picker/20261120_007_사원선택_다중선택_결과.md))의 첫 사용처.

## 3-1. 적용 순서와 주의(적용 완료)
1. [20261120_006](../../../database/20261120/20261120_006_create_hr_order_schema.sql) 적용. **적용 전에는 사원 저장(신규 등록·수정)이 이력 테이블이 없어 실패한다**(이력 기록이 같은 트랜잭션이라서).
2. 메뉴 `인사명령`이 사이드바에 나타나고 처리가 가능하다. 부서·직위·입사일이 비어 있는 기존 사원 10명은 필수값 검증 때문에 먼저 사원관리에서 채워야 대상이 된다.

## 4. 남은 사항
- 예약 발령, 명령코드 마스터 관리 화면, 사업장·파견·직무·호봉 유형, 퇴직 취소(재입사), 기존 사원의 과거 이력 소급은 후속.
- 확인에 쓴 점검 사원(`명령점검가/나*`)은 퇴직 처리했다(삭제 기능 없음). 처리 내역에 이 점검 이력이 남아 있다.
