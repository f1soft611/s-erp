# 20261120_003 사원 선택 도움창 결과

기준: [작업지시서](../../../directions/20261120/20261120_003_hr-employee-picker_작업지시서.md), [계획서](../../../plan/20261120/20261120_003_hr-employee-picker_계획서.md), [상세사양서](../../../spec/20261120/20261120_003_hr-employee-picker_상세사양서.md)

## 1. 구현 내용
- **서버**: `GET /api/v1/hr/employee-picker?departmentId=&keyword=`. 관리자가 아니어도 호출할 수 있고, 선택에 필요한 8개 항목(`userId`, `employeeNo`, `userNm`, `departmentId`, `departmentNm`, `positionCode`, `positionNm`, `photoImage`)만 내려준다. 연락처·이메일·주소·주민번호·로그인 정보는 없다. 퇴직자 제외·휴직자 포함, 부서를 주면 그 부서 **직접 소속만**, 안 주면 회사 전체(부서 미지정 포함). 검색어는 사원명·사번·직위·부서명, 100자 초과는 400.
- **화면 공용 컴포넌트** `shared/components/employee-picker`의 `EmployeePickerDialog`: 왼쪽 회사·부서 트리(회사 선택 가능, 기본 선택), 오른쪽 통합검색 + 사원 목록(사진·부서명·직위·사번·사원명). 사원 행 **더블클릭**(또는 선택 후 Enter)으로 확정하고 닫힌다.
- **전달 값**: `{ departmentId, departmentNm, userId, positionCode, positionNm, employeeNo, userNm }`. 부서가 없는 사원은 `departmentId: null`, `departmentNm: ''`.
- **기존 화면에는 연결하지 않았다**(창고 담당자 등). 부서 선택 도움창과 같은 방식으로 필요한 화면에서 가져다 쓰면 된다.

사용 예:
```tsx
<EmployeePickerDialog
  open={open}
  onClose={() => setOpen(false)}
  onChange={(emp) => { /* emp.userId, emp.userNm, emp.departmentId, emp.departmentNm, emp.positionNm ... */ }}
/>
```

## 2. 검증
| 항목 | 결과 |
|---|---|
| 백엔드 테스트 | 신규 12건(서비스 6·매퍼 4·컨트롤러 2)과 기존 사원 테스트 통과 |
| 프론트 테스트 | 도움창 11건(회사/부서 조회, 상위 부서는 그 부서만, 검색, 더블클릭 전달값, 한 번 클릭은 미확정, 부서 없는 사원, 중복 호출 1회, 오류·빈 목록) 통과. `tsc`·lint 오류/경고 없음, `f1-grid-storage-keys` 통과 |
| 실서버 API | 일반 조회 200(재직 11명), 부서 조회 200(임원 1명), 검색 200, 101자 검색어 400, 응답에 개인정보 키 없음 |
| 브라우저(실서버) | 회사 선택 시 11행, 임원 클릭 시 1행, 더블클릭 시 7개 값이 위 형식으로 전달되고 창이 닫힘. 1280/768/375px에서 가로 넘침 0px |
| DB MCP 근거 | `tb_user`, `tb_department`, 공통코드 `POSITION` 구조 확인(DB 변경 없음) |

## 4. 메모·후속
- 사진이 목록 응답에 포함되어 사원이 수백 명이 되면 응답이 커진다(사원등록 목록과 같은 방식). 그때 사진을 따로 지연 로딩하도록 바꾼다.
- 좁은 화면(375px)에서는 사원 목록이 도움창 안에서 가로로 스크롤된다(페이지 자체의 가로 넘침은 없음).
- 사원을 고르면 부서를 같이 설정하는 화면(창고등록 담당자 등)에 연결하는 작업은 별도로 한다.
