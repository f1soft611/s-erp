# 20261120_009 계정관리 비밀번호 초기화 브라우저 점검 결과

기준: [20261120_001 사양서](../../../spec/20261120/20261120_001_hr-account_상세사양서.md) 비밀번호 초기화·강제 변경

## 점검 방법
점검용 사원·계정(`초기화점검******`)을 새로 만들고, 관리자 화면에서 초기화 → 사용자 로그인 화면에서 임시 비밀번호로 로그인 → 강제 변경 → 새 비밀번호 로그인까지 브라우저로 진행했다. 점검 후 사원은 퇴직 처리, 계정은 미허용으로 바꿨다. 임시 비밀번호·자격 증명은 기록하지 않고 스크린샷에서는 값을 가렸다. 로그인 화면 자체의 개발용 안내에 관리자 계정 정보가 표시되므로 로그인 화면 스크린샷은 문서에서 제외했다(개발 단계가 끝나면 이 안내는 제거할 예정).

## 결과 (17건 통과, 실제 동작)
| 단계 | 확인 |
|---|---|
| 초기화 전 | 기존 비밀번호 로그인 가능, 변경 필요 상태 |
| 관리자 | 초기화 버튼 → 확인창(계정명·안내) → 12자 임시 비밀번호(대·소문자·숫자) 1회 표시, "다시 볼 수 없습니다" 안내, 창을 닫으면 화면에 값 없음 |
| 서버 | 기존 비밀번호 로그인 거부, 임시 비밀번호 로그인 시 변경 필요 |
| 사용자 | 로그인 후 비밀번호 변경 화면(메뉴 없음), 임시와 같은 새 비밀번호는 거절, 변경 후 로그인 화면으로 돌아가며 안내, 임시 비밀번호 재사용 불가, 새 비밀번호로 로그인 시 더는 변경 요구 없음 |

## 발견한 문제와 수정
강제 변경 화면 위에 **"로그인 공지를 불러오지 못했습니다." 오류 팝업**이 떴다. 로그인 공지 팝업이 비밀번호 변경 전에도 공지 API를 호출하는데 서버가 변경 전 사용자의 API를 막아 실패하는 것이 원인이었다.
- **수정**: `NoticeLoginPopupHost`가 비밀번호 변경이 필요한 동안(`passwordChangeRequired`)에는 공지를 불러오지도, 팝업을 띄우지도 않는다. 비밀번호를 바꾸고 다시 로그인하면 평소처럼 공지를 불러온다.
- **회귀 테스트**: `notice-login-popup.test.tsx`에 "변경 필요 사용자는 공지 API를 호출하지 않고, 변경 필요가 풀린 세션에서는 다시 불러온다" 추가. 공지 팝업 관련 25건 통과, `tsc` 오류 없음.
- **재점검**: 같은 흐름을 새 점검 계정으로 다시 돌려 변경 화면 위에 공지 팝업·오류가 뜨지 않음을 확인(17건+1건 통과). 점검 사원은 퇴직 처리, 계정 미허용.
