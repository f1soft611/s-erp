# 20261120_005 사원등록 공통 행 폼 전환 결과

기준: [작업지시서](../../../directions/20261120/20261120_005_hr-employee-common-form_작업지시서.md), [계획서](../../../plan/20261120/20261120_005_hr-employee-common-form_계획서.md), [상세사양서](../../../spec/20261120/20261120_005_hr-employee-common-form_상세사양서.md)

## 1. 왜 바꿨나 (원인)
사원등록은 처음부터 F1Grid 공통 행 폼을 쓰지 않고 **전용 팝업**으로 만들었다. 공통을 못 쓸 기술적 사유가 있어서가 아니라, 한 명씩 즉시 저장·입력 중 중복 확인이 필요하다고 임의로 판단했고 그 판단을 확인하거나 기록하지 않았다. 부서·주소 선택(`code` 칸), 사진(`image` 칸), 조건부 칸(`editable` 함수)은 모두 공통에 이미 있었다. 프론트 지침(기준 화면과 폼 통일)에도 어긋났다. 사용자의 지적으로 **공통 폼으로 전환**했다.

## 2. 변경 내용
- **화면**: F1Grid 편집 그리드 + 공통 행 폼(섹션 카드, 연필 "정보 수정" 열, 대상 "사원: ○○○", 적용/취소, 필수값 빨간 테두리). 헤더 액션은 창고와 같은 **사원 추가·조회·저장**. 입력 후 **저장 버튼으로 일괄 저장**하고, 저장하지 않은 변경이 있으면 조회 때 확인창을 띄운다. 전용 팝업·읽기 전용 목록·사진 컴포넌트는 제거했다.
- **필수값 표시**: 이름·부서·직위·입사일을 비우면 해당 칸이 빨간 테두리와 안내 문구로 표시되고 첫 오류 칸으로 이동하며 상단 메시지에도 나온다. **근무형태는 필수가 아니다**(화면·서버 모두).
- **서버**: `POST /api/v1/hr/employees/save-batch`(관리자 전용, 한 트랜잭션, 실패 시 전체 취소·메시지에 사원명). 기존 단건 서비스를 그대로 재사용한다. 근무형태는 서버도 선택 입력으로 바꿨다.
- **공통(F1Grid) 확장 2건**(문서 갱신 포함): 행 폼 `form.inputType: 'password'`(초기 비밀번호 가림), `validate({ changedOnly: true })`(변경한 행만 검증).
- **동작이 바뀌는 점**: 사번 중복·계정 아이디 중복은 입력 도중 안내가 아니라 **저장할 때 상단 메시지**로 알린다. 주민등록번호는 이미 숨긴 상태 그대로다.

## 3. 검증 중 발견·수정
1. **서버가 근무형태 필수를 계속 요구**: 화면만 풀면 저장이 "근무형태을(를) 선택해 주세요."로 거절된다(실서버 점검에서 발견). 서비스·매퍼를 고치고 서비스 테스트(근무형태 비움 → null 저장)를 추가했다.
2. **기존 불완전 사원이 모든 저장을 막음**: 이전 테스트 데이터 10명이 부서·직위·입사일이 비어 있어 전체 행 검증에서 오류가 났다. 변경한 행만 검증하는 공통 옵션을 추가해 해결했다. 회귀 항목: 필수값이 비어 있는 기존 사원이 있어도 다른 사원의 등록·수정이 저장된다.
3. 타입·린트 경고(훅의 effect 상태 변경)를 창고 훅과 같은 형태로 정리했다.

## 6. 메모·후속
- 점검용 사원 `공통폼점검*` 1명(+ 이전 점검 사원)은 퇴직 처리하고 계정을 미허용으로 바꿨다(삭제 기능 없음).
- 기존 사원 10명(문서작성 테스트 계정)은 부서·직위·입사일이 비어 있다. 이제 저장을 막지는 않지만, 해당 사원을 수정할 때는 필수값을 채워야 적용된다.
- 서버의 사번·로그인 아이디 중복 확인 API(`check-employee-no`, `check-login-code`)는 화면에서 쓰지 않지만 남겨 두었다.
- **창고의 불용창고 = 미사용이 아니다**라는 별도 지적이 있어 사용 여부(미사용 처리) 컬럼 추가를 이 작업 뒤에 진행한다(메모 기록됨).

## 6-1. 추가 변경: 사원 사진 원형 표시 (2026-11-20)
- 공통 `type: 'image'` 칸에 컬럼 옵션 `imageOptions: { shape: 'circle', fallbackText }`를 추가했다(F1-GRID.md·API 참조·`f1-grid-image` 테스트 갱신). 미지정 칸은 기존 네모(60×60) 그대로라 다른 화면에 영향이 없다.
- 사원 사진은 목록 48px·행 폼 36px 원형이며, 사진이 없으면 이름 첫 글자를 원 안에 보여 준다(이름이 비어 있으면 이미지 아이콘).
- 검증: 이미지 칸·사원 화면·F1Grid 문서 테스트 71건 통과, `tsc` 오류 없음. 실서버 브라우저 스크린샷은 사용자 화면 확인 후 최종본으로 추가한다.

## 6-2. 전환 때 빠진 항목 복구 (2026-11-20)
공통 행 폼은 "수정 가능한 칸만" 보여 주고 칸 안내 문구 기능이 없어서, 전환하면서 아래가 조용히 사라졌다. 사용자에게 알리지 않고 "완료"로 보고한 것이 잘못이다.

| 이전 팝업 | 전환 직후 | 조치 |
|---|---|---|
| 사번 칸(수정 시 읽기 전용 + 안내) | 수정 폼에서 사라짐 | 공통 `form.visible`로 읽기 전용 표시 복구 |
| 사번 안내문(직접 입력/비우면 자동, 변경 불가) | 라벨에 짧게만 | 공통 `form.helperText`로 칸 아래 안내 복구, 라벨은 "사번"으로 원복 |
| 실사용자 설명 캡션(계정 발급 안내, 계정 연결 시 해제 불가 안내) | 사라짐, 계정 있으면 칸도 숨김 | 안내문·읽기 전용 표시 복구 |
| 로그인 아이디(계정 있으면 읽기 전용, 비우면 사번 안내) | 계정 있으면 사라짐 | 읽기 전용 표시·안내 복구 |
| 초기 비밀번호 안내("8자 이상, 최초 로그인 시 변경") | 사라짐 | 안내 복구 |
| 사번·로그인 아이디 입력 중 중복 확인("사용할 수 있는 사번입니다.") | 저장 시 서버 메시지만 | **미복구**(사용자 선택: 표시·안내까지만). 후속 요청 시 공통 비동기 검증 옵션으로 추가 가능 |

공통 F1Grid 확장: `form.helperText`, `form.visible`(F1-GRID.md·API 참조·테스트 추가). 사원 화면 전용 폼은 만들지 않았다. 칸 이름(생년월일 등)은 사용자 결정으로 현재 이름을 유지한다.

## 6-3. 사진 위치·크기 조정 (2026-11-20)
- 사진은 입력 항목이 아니라 첨부 성격이라 행 폼 **"시스템 사용" 섹션 맨 아래(한 줄 전체)**로 옮기고, 미리보기를 **120px 원형**으로 키웠다(사진이 없으면 이름 첫 글자). "사진 선택/삭제" 버튼과 안내문을 미리보기 옆에 둔다. 목록의 사진 열은 그대로 맨 앞(48px 원형).
- 이전 팝업에서 빠졌던 사진 기능 복구: 선택한 사진을 **긴 변 320px JPEG로 자동 축소 저장**(서버 한도 700KB), **WEBP 허용**(PNG·JPEG·WEBP 10MB 이하), 안내문 "계정이 있으면 내 정보 관리의 프로필 이미지도 같이 바뀝니다." 복구.
- 공통(F1Grid) 확장(옵션, 다른 화면 영향 없음, 문서·테스트 갱신): 이미지 칸 `imageOptions.formSize`·`compress`, 행 폼 `form.groupOrder`(목록 컬럼 위치와 폼 섹션 위치를 따로 정함).
- 검증: 관련 테스트 141 통과(이미지 칸·섹션 순서·사원 폼), `tsc` 오류 없음, 실서버 폼에서 섹션 순서·사진 위치·120px·버튼·안내문·WEBP 허용 확인(스크린샷 `08-form-photo-bottom-1280`). - **큰 사진 업로드 실서버 확인**: 3.0MB JPEG(2400×1600)를 올리면 오류 없이 미리보기가 나오고 저장 후 서버 사진이 JPEG 23KB·320×213(비율 3:2 유지)으로 줄어 저장되며 목록에는 48px 원형으로 보인다. 19.7MB PNG는 "10MB 이하" 안내로 거절된다(스크린샷 `09-form-big-photo-1280`, `10-list-big-photo-1280`). 점검 사원은 퇴직 처리했다.
