# 20261120_008 사원관리 명칭 변경·정렬 변경 결과

기준: [작업지시서](../../../directions/20261120/20261120_008_hr-employee-rename-sort_작업지시서.md), [상세사양서](../../../spec/20261120/20261120_008_hr-employee-rename-sort_상세사양서.md)

## 변경 내용
- **정렬**: 사원 목록 조회를 부서 > 직위 > 사원명 순으로 변경(부서는 부서 트리가 펼쳐진 순서 — 같은 부모 안에서 정렬순서→부서명→ID, 상위 부서 바로 아래에 하위 부서, 직위는 공통코드 POSITION 정렬순서, 부서·직위가 없으면 뒤). 기존은 부서 > 직위 > 사번. 사원 선택 도움창도 같은 정렬(공통 SQL 조각).
- **명칭**: 메뉴 `HR_INFO_EMPLOYEE` 이름을 사원관리로 변경하는 DB 스크립트 [20261120_005](../../../database/20261120/20261120_005_rename_employee_menu.sql)(롤백·이력·db-schema 포함, **작성만 했고 적용 전**). 코드 주석·테스트 입력의 화면명도 갱신. 메뉴 URL·코드·API 경로는 그대로.

## 검증
| 항목 | 결과 |
|---|---|
| DB MCP 확인 | 메뉴 68 `HR_INFO_EMPLOYEE`=사원등록, 직위 공통코드 sort_order 10~100 확인 |
| 백엔드 | 매퍼 테스트 10(정렬 순서 검증 신규) 통과 |
| 프론트 | 사원관리 페이지 테스트 14 통과 |
| 실서버 | 스크립트 적용 후 확인: `tb_menu` HR_INFO_EMPLOYEE=사원관리, 사원관리 목록·사원 선택 도움창 API가 모두 부서(트리 순서)→직위(정렬순번)→사원명 순(재직 11명), 화면 제목·브레드크럼이 사원관리(스크린샷 1장). 대량 데이터 성능은 미측정(후속 과제) |

## 복사용 커밋 메시지
제목: `feat(hr): 사원등록 화면명을 사원관리로 변경하고 목록 정렬을 부서>직위>사원명으로 변경`

내용:
- tb_menu HR_INFO_EMPLOYEE 이름 변경 스크립트(적용 전), 코드 주석·테스트 갱신
- 사원 목록 ORDER BY: 부서 → 직위 정렬순서 → 사원명 → 사원 ID
