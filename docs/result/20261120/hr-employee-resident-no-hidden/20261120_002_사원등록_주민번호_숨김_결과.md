# 20261120_002 사원등록 주민등록번호 항목 숨김 결과

기준: [작업지시서](../../../directions/20261120/20261120_002_hr-employee-resident-no-hidden_작업지시서.md), [계획서](../../../plan/20261120/20261120_002_hr-employee-resident-no-hidden_계획서.md), [상세사양서](../../../spec/20261120/20261120_002_hr-employee-resident-no-hidden_상세사양서.md)

## 1. 변경 내용
- 사용자 결정(2026-11-20): 연말정산·4대보험 신고가 한참 뒤의 일이라 **주민등록번호는 지금 관리하지 않고 생년월일로 대체**한다. 항목은 일단 숨긴다.
- 사원 등록·수정 팝업에서 주민등록번호 칸을 제거하고 요청 본문에서 `residentNo`를 뺐다(주민번호 13자리 검증도 제거). "생일"·"생일 구분" 라벨을 "생년월일"·"생년월일 구분"으로 바꿨다.
- **백엔드·DB는 그대로**다. 요청에 주민번호가 없으면 서버는 기존 값을 건드리지 않는다. 저장되어 있던 값이 있다면 DB에 남는다.
- 서버 암호화 키 환경변수(`HR_RESIDENT_NO_ENCRYPTION_KEY`, `_VERSION`)는 주민번호를 저장할 때만 필요하므로 **이제 설정하지 않아도 사원 등록·수정이 동작한다**(2-1 결과의 운영 메모를 대체).

## 4. 후속·메모
- 주민번호가 다시 필요해지면(연말정산·4대보험) 복호화 가능 여부와 키 보관 방식을 그때 결정한다(후보: 환경변수 키 유지, DB `pgcrypto`, 단방향 해시는 복원 불가). 기존 `ResidentNumberCipher`와 `resident_no_*` 컬럼은 남아 있어 되살릴 수 있다.
- 점검 중 입력된 주민번호 값이 DB에 남아 있을 수 있다. 정리가 필요하면 별도 작업으로 비운다.

## 5. 복사용 커밋 메시지
제목: `feat(hr): 사원등록에서 주민등록번호 항목을 숨기고 생년월일로 대체`

- 백엔드·DB는 변경 없음(미입력이면 기존 값 유지), 암호화 키 환경변수 설정 불필요
