# 20261007_003 문서작성 결재선 카드형 레이아웃 결과보고서

## 1. 작업 요약

- 결재선과 참조선을 왼쪽 라벨을 기준으로 두 행에 정렬하고, 확정 결재/합의 단계를 사용자 정보 카드로 표시한다.
- 카드, 활성 선택 필드, 결재/합의 버튼 높이는 40px로 맞췄다. 빈 선택 후보 안내는 표시하지 않는다.
- 문서작성 모달에만 공통 다이얼로그의 흰 표면 배경을 적용했다.
- 모달이 열리면 본문 에디터가 앞선 필드 아래 남은 높이를 채우고, 최소 높이 180px을 유지한다. 긴 본문은 에디터가 자연 확장되고 모달 본문이 스크롤한다.
- 양식의 첫/마지막 콘텐츠 블록 바깥 여백을 정리해 에디터의 위·아래 내부 여백이 같도록 했다. 다른 공통 에디터 사용처의 기본 스타일은 변경하지 않았다.

테스트 렌더링 중 Emotion이 `:first-child` 선택자의 SSR 사용 주의 메시지를 한 번 출력했다. 프로젝트는 Vite 클라이언트 렌더링을 사용하며 테스트는 통과했다. 실제 브라우저에서도 첫/마지막 블록 여백 정규화와 계산된 여백을 확인했다.

## 3. 브라우저 확인

900px 높이의 브라우저 뷰포트에서 375px, 768px, 1280px 너비를 각각 확인했다.

### 모달 오픈 직후

| 뷰포트 폭 | 본문 폭 / 스크롤 폭 | 모달 본문 client / scroll 높이 | 에디터 패널 높이 | 에디터 아래 여유 |
|---:|---:|---:|---:|---:|
| 375px | 375 / 375px | 694 / 694px | 239px | 16px |
| 768px | 768 / 768px | 694 / 694px | 337px | 16px |
| 1280px | 1280 / 1280px | 694 / 694px | 337px | 16px |

모든 뷰포트에서 에디터는 모달 본문의 남은 높이를 채웠고, 페이지 가로 스크롤은 발생하지 않았다.

### 긴 본문

가짜 검증 문단 24개를 입력했다. 에디터 내부 스크롤 없이 본문 높이에 맞춰 에디터가 확장되고, 모달 본문이 스크롤됐다.

| 뷰포트 폭 | 모달 본문 client / scroll 높이 | 에디터 패널 높이 | 에디터 client / scroll 높이 |
|---:|---:|---:|---:|
| 375px | 694 / 1771px | 1331px | 1329 / 1329px |
| 768px | 694 / 1020px | 679px | 677 / 677px |
| 1280px | 694 / 1020px | 679px | 677 / 677px |

375px에서 모달 본문을 끝까지 스크롤해도 다이얼로그 헤더와 푸터가 고정 위치에 남고 접근 가능했다. 페이지 본문 폭은 세 폭 모두 뷰포트와 같았다.

### 양식 가장자리 여백 및 결재 행

- 실제 양식 선택 후 측정한 첫/마지막 에디터 블록의 바깥 여백은 각각 0px이었고, 에디터 padding은 위/아래 모두 12px이었다. 수정 전 실제 DOM에서는 첫 블록의 8px 위 여백이 에디터 상단 간격에 더해져 위 20px/아래 12px로 달랐으며, 수정 후에는 동일한 12px로 정규화됐다.
- 결재 카드/선택 필드/결재 추가/합의 추가 버튼 높이는 375px, 768px, 1280px 모두 각각 40px이었다.
- 세 뷰포트 모두 document body client width와 scroll width가 같았다.
- 문서작성 모달의 paper, content, actions 표면은 모두 흰색이었다.
- 브라우저에서 결재 단계 하나를 추가한 뒤 전체 단계 삭제를 실행했다. 단계가 제거되고 그 후보가 다시 선택 목록에 나타나는 것을 확인했다.
- 사용자 선택/다중 결재 순서/합의 그룹 동작은 자동 테스트에서도 확인했다. 실제 사용자명/양식 본문이 포함될 수 있는 화면은 결과 캡처로 저장하지 않았다.
