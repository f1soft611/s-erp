# 20261007_007 문서작성 결재 단계·중복 방지·초기 결재자 결과

## 변경 내용

- 원인: 초기화 단계에서 로그인 프로필을 결재 사용자 선택 옵션에서만 찾고, 후보 목록에 계정이 없으면 오류로 종료해 첫 결재 단계가 생성되지 않았다.
- 동일 `userId` 선택 옵션이 없을 때 프로필의 사용자 ID, 이름, 부서, 직급, 프로필 이미지로 고정 1번 결재자를 구성한다. 다른 결재/합의/참조 선택 후보 목록은 변경하지 않는다.
- 프로필 이름 또는 사용자 ID 자체가 없으면 오류를 표시한다.
- 빈 결재 칸의 직위/직함 행 높이는 유지하면서 화면에 표시하던 텍스트를 제거했다.
- 로그인 사용자를 삭제할 수 없는 첫 결재자로 초기 설정한다. 사용자 옵션에 동일 ID가 없으면 프로필 정보를 사용한다.
- 결재·합의·참조 간 사용자 중복 배정을 차단한다.
- 승인 단계별 순번을 표시하며, 같은 합의 단계의 여러 사용자는 순번을 공유한다.
- 빈 결재 칸을 직위/직함·도장·이름 자리로 구성하고 점선 테두리를 적용했다.
- 결재와 합의 사이 구분선을 제거하고, 미결재 합의에는 도장을 표시하지 않는다.

## 후속 보완: 공백 ID, 빈 슬롯, 고정 기안자 이름

- 원인: 결재 후보 변환에서 `userId`의 앞뒤 공백을 보존해, 공백을 제거한 프로필 ID와 동일 계정을 역할별 후보에서 제외하지 못했다. 빈 결재 칸에는 남은 `도장`/`이름` 문구가 있었고, 고정 기안자 이름은 삭제 버튼 열과 `3em` 제한 때문에 좁게 표시됐다.
- 조치: 후보 ID 변환 시 앞뒤 공백을 제거했다. 이름 비교는 추가하지 않고 기존 ID 기반 중복 방지를 유지했다. 빈 칸은 접근성 레이블과 기존 행 높이/점선 구조를 보존하면서 화면 텍스트를 비웠다. 고정 기안자 행만 삭제 열과 이름 폭 제한을 없앴고, 일반 참여자 삭제 버튼과 기존 이름 제한은 유지했다.
- RED 확인: ID 공백 정규화, 빈 슬롯 텍스트 제거, 고정 기안자 이름 폭을 검증하는 집중 테스트가 각각 기대한 기존 동작으로 실패했다.

## 후속 보완: 프로필 ID 식별 및 참여자 호버 삭제

- 원인: 프로필 API의 `userId`는 로그인 코드(`tb_login_account.login_code`)인 반면, 결재 후보의 `userId`는 내부 사용자 키(`tb_user.user_id`)였다. 서로 다른 식별자를 비교해 로그인 기안자가 결재·합의·참조 후보에 남았다.
- 조치: 프로필 응답에 인증된 사용자의 내부 키를 `employeeId`로 추가하고 기존 `userId` 의미는 유지했다. 작성 화면은 정규화한 `employeeId`와 후보 사용자 ID를 비교하며, 이름 기준 제외는 하지 않는다. 기안자 후보가 제공되지 않는 경우에도 프로필 정보로 고정 1번 결재자를 구성하며 삭제 버튼은 표시하지 않는다.
- 삭제 UX: 비고정 결재자의 X는 직위 행 오른쪽에 배치하고, 합의자 삭제 아이콘도 X로 통일했다. 데스크톱에서 기본 opacity 0, 항목 호버 시 opacity 1을 확인했고, 터치 에뮬레이션에서는 `(hover: none)`/`(pointer: coarse)`가 참인 상태에서 결재·합의 X 모두 opacity 1로 표시됨을 확인했다. 키보드 포커스 표시는 관련 Vitest 회귀 테스트로 검증했다.
- 브라우저 반응형 검증:
  - 375px: 모달 너비 311px, `hover: none` 및 `pointer: coarse`, 화면 전체 가로 overflow 없음. 터치에서 결재/합의 X 상시 표시를 확인했다.
  - 768px: 모달 너비 704px, 화면 전체 가로 overflow 없음.
  - 1280px: 모달 너비 990px, 화면 전체 가로 overflow 없음.
  - 삭제 버튼은 데스크톱에서 호버 전 opacity 0, 호버 후 opacity 1이었다. 삭제 후 후보 복원 및 단계 순번 동작은 문서작성 테스트에서 확인했다.
- 검증 명령:
  - `cd backend; mvn -Dtest=ProfileSettingsApiControllerTest test` — 2개 테스트 통과.
  - `cd frontend; npx vitest run tests/document-write-page.test.tsx tests/profile-settings.service.test.ts tests/profile-settings-page.test.tsx --testTimeout=15000` — 45개 테스트 통과.
  - 변경 대상 파일 `npm run lint -- ...` — 통과.
  - `npm run build` — TypeScript 검사 및 Vite 빌드 통과.
  - `git diff --check` — 통과.
- DB 확인은 기존 테이블의 컬럼 메타데이터에 한정했다. `tb_user.user_id`와 `tb_login_account.login_code`의 타입·역할을 확인했으며 사용자 데이터 행은 조회하지 않았다. 스키마 변경이 없어 마이그레이션은 없다.
- 반응형 스크린샷은 기안자 및 참여자 표시 문자열·입력 값을 흐림 처리했다. 모바일은 X 표시를 확인할 수 있도록 모달의 결재 영역으로 스크롤한 상태다.
