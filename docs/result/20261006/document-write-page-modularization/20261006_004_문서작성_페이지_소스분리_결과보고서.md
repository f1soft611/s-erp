# 20261006_004 문서 작성 페이지 소스 분리 결과보고서

## 작업 결과

기존 `DocumentWritePage.tsx`에 있던 페이지 조립, 작성 모달, 목록 피드 항목, 결재 요약, 빈 상태, 페이지/편집 상태, 타입 및 샘플 데이터를 역할별 파일로 분리했다.

- 페이지는 헤더, 목록/피드 레이아웃, 공용 보기 도구, 작성 모달을 조립한다.
- 작성 모달은 `CommonDialog`를 그대로 사용하고 본문 편집 및 서식 툴바는 공통 `RichTextEditor`/`RichTextEditorToolbar`를 사용한다.
- 조회/저장 API가 없는 현재 기능에는 `services/` 또는 가짜 API를 추가하지 않았다.
- 문서 저장 기능을 추가하지 않았으며 저장 버튼은 계속 비활성화 상태다.

## 보존 및 회귀 검증

- 초기 리스트 보기, 샘플 문서와 상태, 상단 고정, 업무 구분 필터, 피드/리스트 전환, 결재 요약 및 알림을 유지했다.
- 문서 종류 탭 활성화 여부, 제목/본문 편집기, 서식 툴바, 첨부 UI, 취소 시 초기화 흐름을 유지했다.
- 후속 확인에서 페이지 전용 `useEditor`/`EditorContent`가 남아 있음을 확인해 공통 RichTextEditor/Toolbar 사용으로 바로잡았다. 회귀 테스트에서 공통 에디터 wrapper와 공통 표 삽입 도구를 검증한다.
- 작성 모달의 공통 셸 test id와 저장 비활성 상태에 대한 테스트를 추가했다.
- 모달을 닫고 애니메이션 종료 후 다시 열었을 때 제목이 초기화되는 회귀 테스트를 추가했다.

## 검증 결과

| 검증 | 결과 |
|---|---|
| 기준선 페이지 테스트 | 기존 3건 통과 |
| `npm run test -- tests/document-write-page.test.tsx` | 4건 통과 |
| `npm run build` | TypeScript 및 Vite 프로덕션 빌드 통과 |
| 타입/진단 확인 | 변경 파일에서 오류 없음 |
| `git diff --check` | 오류 없음 |
| 실제 브라우저 375px | document width 375px, dialog width 311px |
| 실제 브라우저 768px | document width 768px, dialog width 704px |
| 실제 브라우저 1280px | document width 1280px, dialog width 990px |
| 작성 모달 저장 버튼 | 비활성 상태 확인 |
| 공통 에디터 표시 | `rich-text-editor-content` 및 본문 placeholder 확인 |
| 공통 툴바 | 기본 서식 및 표 삽입 도구를 테스트와 브라우저에서 확인 |
| 반응형 스크린샷 | 공통 에디터 연결 후 375/768/1280px 목록 및 모달 화면 갱신 |

브라우저 검증은 개발 페이지 `/groupware/doc/write`에서 수행했다. 세 뷰포트 모두 문서 전체 가로 넘침이 없었으며 작성 모달, 편집기와 하단 액션이 표시되었다.

전체 프론트엔드 테스트도 실행했으나 73개 파일 중 24개 파일에서 171건이 실패했다(49개 파일, 583건 통과). 확인된 실패는 라우터 not-found 대체 페이지, 로그인 후 대시보드, 메뉴/권한 관리 등 이번 문서 작성 페이지 변경 범위 밖에서 발생했으며, `document-write-page.test.tsx`의 4건은 전체 실행에서도 통과했다. 전체 실패는 이번 변경과 무관하다고 단정할 수 없으므로 별도 기준선 비교 없이 원인을 확정하지 않았다.

## 제외 범위

실제 서버 연동과 API 계약이 없는 상태라 문서 저장, 임시 저장, 조회 서비스는 구현하지 않았다. 별도 작업에서 서버 계약을 확인한 후 기능별 `services/`를 추가해야 한다.
