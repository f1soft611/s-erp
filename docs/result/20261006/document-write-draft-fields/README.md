# 문서작성 기안서 탭 필드 재정의 결과

## 작업 요약

문서 작성 모달의 기안서 탭을 기안서 메타정보, 분류별 양식, 결재/합의 단계 및 참조자 중심으로 재구성했다. 기안양식 조회와 본문 조회는 기존 양식 관리 서비스를 사용하고, 결재·참조 사용자 선택은 기존 F1-Grid 사용자 선택기를 재사용한다.

## 반영 사항

- 기안일과 기안자를 읽기 전용 필드로 표시하고 F1-Grid 폼 필드와 같은 38px 최소 높이 스타일을 적용했다.
- 기안양식 분류는 `전체`를 기본값으로 표시하고, 분류 선택 시 해당 분류의 사용 중이며 본문이 등록된 양식만 제공한다.
- 양식을 선택하면 등록된 JSON/HTML 본문을 에디터에 적용한다. 본문을 편집한 뒤 다른 양식으로 바꾸려는 경우 확인을 거치며 취소 시 기존 본문을 유지한다.
- 양식 본문 조회 중에는 에디터를 읽기 전용으로 전환해, 비동기 조회가 끝나기 전에 입력한 내용이 확인 없이 교체되지 않도록 한다.
- 결재는 한 명을 순차 단계로 추가하고, 합의는 선택된 여러 사용자를 하나의 단계로 추가한다. 참조자는 결재선과 별도 목록으로 관리한다.
- 사용자 사진/이름/부서와 작성 중 빈 도장 자리를 표시한다. 모달을 닫으면 작성 중 선택 상태를 초기화한다.
- 조회 중·오류·빈 결과 안내를 제공하며 저장/실제 결재 제출은 이번 범위에 포함하지 않는다.

## 데이터 흐름과 범위

- 분류/양식 목록: `fetchDraftFormOptions`, `fetchDraftForms`
- 양식 본문: `fetchDraftFormTemplate`
- 기안자: `fetchMyProfile`
- 결재선/합의/참조 사용자 선택: F1-Grid `UserSelectEditor`
- 백엔드, DB 스키마, 공용 F1-Grid 구현은 수정하지 않았다.

## 검증 결과

- `npm run test -- tests/document-write-page.test.tsx`: 17개 테스트 통과
- `npm run build`: TypeScript 및 Vite production build 통과
- 수정 파일 대상 oxlint: 오류 없음
- 로컬 브라우저는 개인정보를 쓰지 않도록 합성 API 응답으로 검증했다. 분류 필터, 양식 선택에 따른 본문 적용, 결재 단계, 다중 사용자 합의, 참조자 표시를 확인했다.
- 375×812, 768×900, 1280×900에서 모달 내부 세로 스크롤과 폭을 확인했다. 문서 가로폭은 각 viewport와 같았고, 모달 내부의 가로 overflow는 없었다. 기안일/기안자 입력은 38px이며 Select는 MUI 소형 Select의 기본 렌더링 높이(40px)를 유지한다. 필드 컨테이너에는 기존 F1-Grid와 같은 `minHeight: 38` 규칙을 적용했다.
