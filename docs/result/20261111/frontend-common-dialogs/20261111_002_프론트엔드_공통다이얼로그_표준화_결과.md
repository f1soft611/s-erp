# 프론트엔드 공통 다이얼로그 표준화 결과

## 작업 내용

- 프론트엔드 기능 화면의 직접 MUI `Dialog` 사용을 `CommonDialog`로 통합했습니다. 직접 `Dialog` 렌더링은 공통 기반 컴포넌트에만 남겼습니다.
- 기본 브라우저 확인창 대신 `useCommonConfirmDialog`를 추가하고 출하, 출하계획, 수주, 거래명세서의 확인 흐름에 적용했습니다.
- 공통 미저장 확인창과 비동기 확인창에서 제목 아래에는 선택적 짧은 부가설명만 두고, 확인 사유와 전체 안내문은 본문에 표시하도록 정리했습니다. 문서 유형 변경 확인에도 같은 규칙을 적용했습니다.
- 대시보드, F1-Grid, 역할·정책 설정, 자료실, 알림, 문서관리, 이미지 뷰어 등 기존 다이얼로그를 공통 셸로 전환했습니다.
- `frontend/AGENTS.md`와 상세 사양서에 공통 다이얼로그 및 네이티브 대화상자 사용 규칙을 추가했습니다.

## 검증 결과

- `npm run build`: 통과
- 공통 다이얼로그 관련 Vitest: 8개 파일, 52개 테스트 통과
- 변경된 프론트엔드 소스·테스트 32개 파일 Oxlint: 오류 없이 완료. 기존 React 훅·effect 관련 경고는 출력됩니다.
- `npm run lint`: 실패. 수정하지 않은 `tests/common-code-management-page.test.tsx:53`에서 조건부 `useImperativeHandle` 사용으로 `react-hooks/rules-of-hooks` 오류가 발생합니다.
- 전체 Vitest: 190개 파일 중 150개 통과, 40개 실패; 2,191개 테스트 중 1,949개 통과, 242개 실패. 여러 기존 화면 테스트의 fixture, 런타임 ref, 기대 레이아웃 불일치 등이 남아 있어 전체 테스트는 통과하지 않았습니다.
- `node tests/common-dialogs.browser.mjs`: 375px, 768px, 1280px에서 확인창·문서 유형·폼·선택기·이미지 뷰어 브라우저 검증 통과
- `node tests/document-approval-actions-menu.browser.mjs`: 세 뷰포트에서 피드·상세 결재 메뉴 및 구분선 확인 통과
- `frontend/src`에서 직접 MUI `<Dialog>`는 `CommonDialog.tsx`만 남았고, `window.alert`/`window.confirm`/`window.prompt` 검색 결과는 없습니다. `PwaInstallPrompt`의 설치 이벤트 `prompt()`와 `useCommonConfirmDialog` 기반 확인 호출은 브라우저 기본 대화상자 사용이 아닙니다.
