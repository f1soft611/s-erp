## 변경 및 유지 사항

기존 공용 도구막대가 피드에서만 상신 취소·승인 취소를 숨기고 있었다. 사용자 승인에 따라 두 버튼의 피드 제외 조건만 제거했다.

- 본인 기안 + PENDING이면 상신 취소를 제공한다.
- 기존 본인 승인선/문서 상태/후속 단계 미처리 조건을 충족하면 승인 취소를 제공한다.
- 피드/상세 모두 기존 확인창을 사용한다. 닫기는 요청하지 않고, 실패는 오류 표시 및 재시도, 성공은 알림·부모 목록 갱신·댓글 재조회를 수행한다.
- 기존 API와 서버 권한·상태 검증을 그대로 사용한다. 새 API/DB/백엔드 변경은 없다.
- 리스트의 결재상태·업무구분만 표시, 피드 승인/반려/보완요청, 핀/메뉴 및 페이징은 유지한다.
- 버튼 스타일은 이번 작업에서 변경하지 않았다.

## 자동 검증

변경 전 새 상신/승인 취소 회귀 2건이 피드 버튼 부재로 실패함을 확인했다.

변경 후:

- 페이지 대상 **13건 통과**: 피드 취소 2종의 확인/닫기/오류 재시도/갱신, 불허 조건 4종, 기존 상세 취소 2종, 리스트 두 배지 및 상세 열기, 고정/피드 메뉴/승인 실패 회귀.
- 공용 도구막대/피드 항목/페이지네이션 **6건 통과**.
- 합계 **19건 통과**. 전체 테스트 결과를 의미하지 않는다.
- `npm run build`: TypeScript 및 Vite 성공. 기존 1000kB 초과 청크 경고 유지.
- 변경 컴포넌트/테스트 oxlint: 종료 코드 0. 기존 effect 내부 setState 경고 5건 유지.
- `git diff --check`: 통과.

## 브라우저 검증

기존 4173 서버를 재사용하고 임시 페이지에서 합성 문서/사원 응답으로 확인했다. 상신 취소 대상과 승인 취소 대상 각각의 피드 카드를 표시했다.

실제 innerWidth 375/768/1280px에서 두 취소 버튼의 확인창을 각각 클릭으로 열고 `닫기`로 닫았다. 각 너비에서 페이지 및 도구막대 가로 넘침은 없었다. 실제 취소는 실행하지 않았으며 비조회 요청은 차단했다. 임시 페이지는 종료했다.

- [상신 취소 확인창](screenshots/submission-confirmation.png)
- [승인 취소 확인창](screenshots/approval-confirmation.png)

이전 작업과 같은 통합 브라우저의 캡처 시 뷰포트 축소 현상이 있다. 첫 시도는 캡처 후 좌표가 어긋나 닫기 클릭이 실패했으므로 페이지를 정리하고, 재검증에서는 캡처 전에 모든 너비의 두 확인창 열기/닫기를 완료했다. 스크린샷은 합성 응답 표시 근거이며 요청 너비의 완전한 반응형 캡처로 주장하지 않는다.

백엔드를 수정하지 않아 이번 변경을 위한 재시작은 필요 없다. 실제 문서의 취소를 실행하는 운영 데이터 검증은 수행하지 않았다.
