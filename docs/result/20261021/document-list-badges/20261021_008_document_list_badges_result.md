## 반영

사용자가 승인한 대로 리스트형 행의 부가 표시를 **결재상태 → 업무구분** 두 배지로 제한했다. 구분선·고정핀 버튼·더보기 및 연결된 리스트 전용 수정/삭제 상태·핸들러·확인창을 제거했다.

ListView의 기존 배지 표시를 재사용하므로 공용 뷰 컴포넌트를 수정하지 않았다. 제목·작성자·날짜·상세 열기, 별도 상단고정 영역, 고정 문서의 일반 목록 포함, 기존 정렬/조회/페이징은 유지한다.

피드/상세의 핀 색상·고정 확인·더보기·수정·삭제는 변경하지 않았다. 백엔드/API/DB 계약 변경이 없으므로 이번 변경 때문에 백엔드를 재시작할 필요는 없다.

## 검증

- 구현 전 새 표시 회귀 2건이 기존 구분선/액션 노출 때문에 실패하는 것을 확인했다.
- 구현 후 페이지 대상 **13건 통과**: 상태·업무구분만 표시, 작성자/상태와 무관한 액션 부재, 상세 열기, 고정 문서 일반 리스트 유지, 피드/상세의 고정 및 메뉴 동작.
- 공용 뷰/고정/페이지네이션 **23건 통과**.
- 합계 **36건 통과**. 전체 테스트 실행을 의미하지 않는다.
- `npm run build`: TypeScript 및 Vite 성공. 기존 1000kB 초과 청크 경고 유지.
- 변경한 페이지/테스트 oxlint: 종료 코드 0, 경고/오류 출력 없음.
- `git diff --check`: 통과.

## 브라우저

기존 4173 서버를 재사용하고, 임시 페이지에서 합성 문서 응답으로 렌더링했다. 실제 문서 변경 없이 임시 페이지는 종료했다.

캡처 전에 실제 innerWidth가 각각 375/768/1280px임을 확인했다. 모든 너비에서 각 행 배지가 `임시저장/기안`, `결재진행중/업무` 순서이며 행당 배지 2개, 선택 버튼 1개였다. 핀/더보기 버튼 및 구분선은 0개였고 페이지 가로 넘침 및 배지의 리스트 경계 넘침은 없었다.

- [375px 요청 캡처](screenshots/list-375.png)
- [768px 요청 캡처](screenshots/list-768.png)
- [1280px 요청 캡처](screenshots/list-1280.png)

이전 작업과 동일하게 통합 브라우저는 스크린샷 촬영 시 뷰포트를 축소한다. 모바일 캡처에 보이는 잘림은 지정 너비의 DOM 측정 결과와 구분해야 한다. 캡처 파일은 요청 너비의 정확한 전체 시각 검증 근거가 아니며, 캡처 시점의 축소 문제는 해결하지 않았다. 위 너비별 결과는 캡처 전 측정값이고 합성 응답 기반 검증이다.
