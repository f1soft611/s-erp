## 재현 및 원인

- 피드형에서도 고정 문서를 별도 조회하지만, 고정 패널 렌더링이 리스트형으로 제한되어 영역이 누락됐다.
- 고정 패널에 별도 해제 액션을 전달해 공지사항과 달리 직접 해제 버튼이 표시됐다.
- 피드/상세 핀 아이콘에 고정 상태의 색상이 지정되지 않았다.
- 훅이 일반 목록의 고정 문서를 제외하고, 피드에는 별도 고정 결과를 앞에 삽입한 뒤 고정 우선 재정렬했다. 이 때문에 리스트에서 문서가 사라지고 피드 순서가 바뀌었다.

## 변경

- 피드형과 리스트형 모두 기존 별도 조회 결과로 같은 상단 고정 패널을 표시한다.
- 상단 고정 패널의 직접 해제 버튼을 제거하고 문서 선택/상세 열기는 유지한다.
- 고정 목록과 일반 목록 상태를 분리한다. 일반 피드/리스트는 일반 API 응답 순서를 유지하며 고정 문서를 제외하거나 앞에 삽입하지 않는다.
- 고정 문서가 일반 조회 결과에도 포함되면 두 영역 모두에 표시한다. 별도 고정 조회에만 있는 문서는 일반 목록에 억지로 삽입하지 않는다.
- 다음 페이지에서도 고정 ID를 기준으로 실제 고정 상태를 반영한다.
- 리스트/피드/상세의 고정 핀은 primary 색상, 미고정 핀은 기본색을 사용한다.
- 리스트의 고정 문서에도 올바른 해제 확인창을 연결한다. 기존 pending 비활성화, 확인 취소, 실패 알림 및 quiet refresh는 유지한다.
- 파일형 상세의 고정 상태, 필터와 페이지네이션은 기존 흐름을 유지한다.

## 검증

### 자동 검증

- 수정 전 표시/액션/색상 회귀 테스트 3건 실패 확인.
- 일반 목록 구성 변경 전 순서/포함 회귀 테스트 실패 확인.
- 문서작성 고정 UI 집중 테스트: **7건 통과**.
- 고정 훅, 페이지네이션 훅, 기존 문서작성 훅, 피드 항목: **23건 통과**.
- `npm run build`: 통과. Vite 대형 청크 경고가 남아 있다.
- 수정한 소스 3개에 oxlint 실행: 오류 없이 종료. 수정하지 않은 기존 effect 내부 setState 위치의 경고 7개가 남아 있다.
- `git diff --check`: 통과.

Vitest 에디터 도구는 테스트를 발견하지 못해 기존 로컬 Vitest 실행기를 직접 사용했다. 전체 테스트 스위트 통과를 의미하지 않는다.

### 브라우저 기능 검증

기존 `http://127.0.0.1:4173` S-ERP 서버를 재사용했다. 실제 문서의 고정 상태를 변경하지 않고 브라우저 응답만 합성 데이터로 대체했다.

- 두 보기에서 상단 고정 패널 표시와 직접 해제 버튼 0개 확인.
- 일반 문서 → 고정 문서의 일반 조회 순서 유지 확인.
- 두 보기 본문에서 고정 문서 잔류와 primary 핀 표시 확인.
- CSS viewport 375px, 768px, 1280px에서 두 보기의 문서 가로 넘침이 없음을 측정했다.
- 브라우저 응답 대체는 제거하고 실제 페이지를 다시 로드했다. 임시 검증 페이지는 종료했으며 기존 서버는 종료하지 않았다.

### 시각 검증의 제한

공유 브라우저는 캡처 시 렌더링 영역이 다시 축소되거나 잘리는 현상이 있었다. 저장된 스크린샷은 캡처 도구의 제약을 포함하므로 **세 너비의 완전한 시각 검증 완료 근거로 보지 않는다**. 특히 모바일에서 모든 컨트롤이 겹침 없이 표시되는지는 별도 실제 브라우저 확인이 필요하다. 이 현상을 우회하기 위해 제품 레이아웃 코드를 변경하지 않았다.

## 영향 범위

프론트엔드 문서작성 화면/훅 및 관련 테스트만 변경했다. 공지사항 자체, 공통 리스트 컴포넌트, 백엔드 API 계약 및 DB 스키마 변경은 없다. DB MCP 확인 대상 작업은 없으며 DB 조회를 수행했다고 주장하지 않는다.
