# 문서 리스트 도구막대 정합성 결과

## 근거와 적용 범위

- [작업지시서](../../../directions/20261021/20261021_007_document_list_toolbar_work_instruction.md)
- [계획서](../../../plan/20261021/20261021_007_document_list_toolbar_plan.md)
- [상세 사양서](../../../spec/20261021/20261021_007_document_list_toolbar_spec.md)

리스트형의 상태/문서구분은 행 선택 버튼 안에, 핀은 바깥에 따로 있어 피드와 도구막대 구성이 달랐다. 더보기는 상세/피드에만 있었고 목록 응답에는 작성자 여부가 없었다.

## 변경

- 리스트형도 결재상태 → 문서구분 → 구분선 → 고정핀 → 더보기 순서로 공용 도구막대를 사용한다.
- 공용 구분선은 높이 20px, 세로 중앙 정렬로 변경해 리스트/피드/상세에 동일하게 적용한다.
- ListView에 선택형 도구막대 슬롯을 추가했다. 사용하는 행에만 기존 내부 칩을 대체하며, 기본 소비자는 기존 표시를 유지한다. 모바일은 도구막대를 행 하단 별도 줄에 배치한다.
- 핀/더보기는 행 선택 버튼 외부에 있어 상세 열기와 독립적으로 작동한다.
- 기존 상세 메뉴를 재사용한다. 작성자 본인의 DRAFT는 수정·삭제, REVISION_REQUESTED는 수정 후 재상신만 표시한다. 그 외 상태/타인 문서/작성자 정보 없는 응답에는 더보기를 표시하지 않는다.
- 리스트 수정은 기존 상세 조회와 Composer에 연결했다. 조회 실패는 알림으로 표시한다.
- 리스트 삭제는 확인창과 기존 삭제 API에 연결했다. 실패는 확인창 안에 표시하고 재시도할 수 있으며, 성공 시 목록을 quiet refresh한다.
- 일반 목록/페이지 SQL에 현재 인증 사용자 기준 `isDrafter`를 추가했다. 작성자 식별자를 추가 노출하지 않는다. 피드 VO는 상위 목록 VO의 같은 속성을 상속한다.
- 앞선 006 작업의 고정 문서 포함 조회, 일반 페이지 정렬/건수, 별도 고정 영역, 핀 확인 절차를 유지했다.

## DB MCP 및 스키마

기본 `s-erp-postgresql-readonly`의 `list_tables` 후 `describe_table`로 기존 문서/고정 테이블 메타데이터를 확인했다. `tb_electronic_approval_main.drafter_id`와 현재 인증 사용자를 비교하며 tenant/읽기 권한 조건은 유지한다.

스키마·데이터 변경은 없어 SQL 마이그레이션/롤백 및 누적 스키마 수정은 필요하지 않다. 자격 증명이나 실제 데이터 행은 결과물에 기록하지 않았다.

## 자동 검증

- 페이지 대상 회귀: **16건 통과**. 리스트 순서·권한, 수정 조회 실패/Composer, 삭제 확인/실패 재시도, 핀 확인/색상/목록 유지, 기존 상세 및 피드 소유자 메뉴를 검사했다.
- 공용 도구막대 및 뷰 컴포넌트: **18건 통과**. 구분선 20px/중앙 정렬, 도구막대 선택 버튼 분리, 기존 배지 중복 방지, 기본 소비자/페이징을 검사했다.
- 페이지 훅/고정/페이징/피드 항목/서비스: **40건 통과**.
- 프론트엔드 대상 회귀 합계: **74건 통과**. 전체 테스트 실행 결과를 의미하지 않는다.
- `npm run build`: TypeScript 및 Vite 빌드 성공. 기존 1000kB 초과 청크 경고가 남아 있다.
- 수정한 소스/테스트 oxlint: 종료 코드 0. 기존 effect 내부 setState 경고 7건은 유지했다.
- 매퍼/서비스/컨트롤러 Maven 테스트: **105건 통과**, 실패/오류 0. 일반 목록/페이지 SQL 투영, MyBatis 속성 매핑, 목록 및 피드 JSON `isDrafter`도 검사했다.
- `git diff --check`: 통과.

기존 테스트를 추가 탐색하는 과정에서 `shows the ordered approval toolbar to a feed approver`는 기존 승인/반려 버튼을 contained로 기대하지만 현재 및 HEAD 소스는 outlined여서 실패했다. 이번 변경과 무관한 버튼 스타일은 수정하지 않았고, 이 기존 불일치를 대상 74건 통과 결과에 포함하지 않았다.

기존 페이지 테스트의 배열 응답을 현재 페이지 응답 형식으로 맞추고, 핀 버튼과 행 선택 버튼을 구분하도록 선택자를 구체화했다. 핀 테스트는 API 호출 및 갱신 결과를 기다리도록 보강했다.

## 브라우저 검증

기존 `http://127.0.0.1:4173` 서버를 재사용했다. 임시 페이지에서 합성 문서 응답만 가로채 실제 문서작성 페이지를 렌더링했다. 실제 문서를 수정/삭제/고정하지 않았고 임시 페이지는 종료했다.

스크린샷 전 실제 `innerWidth`와 DOM geometry:

| 실제 너비 | 구분선 높이 | 구분선/핀 중심 차이 | 페이지 가로 넘침 | 작성자 더보기 클릭 및 수정/삭제 메뉴 |
| --- | --- | --- | --- | --- |
| 375px | 20px | 0px | 없음 | 확인 |
| 768px | 20px | 0px | 없음 | 확인 |
| 1280px | 20px | 0px | 없음 | 확인 |

모든 너비에서 타인 문서에는 더보기가 없었다. 모바일은 제목/작성자와 도구막대가 별도 줄에 배치됐으며 도구막대가 행 폭 안에 들어갔다.

## 실제 서버 반영 상태와 남은 확인

실제 일반 목록/고정 API는 모두 HTTP 200이며, 일반 목록에 고정 문서가 함께 포함되는 것을 교집합으로 확인했다. 앞선 006의 실행 서버 제외 현상은 더 이상 재현되지 않았다. 실제 목록 응답에는 아직 새 `isDrafter` boolean이 없어 이번 작성자 메뉴 계약은 실행 서버에 반영되지 않은 상태다.

**이번 백엔드 수정까지 반영하려면 사용자가 백엔드를 다시 시작해야 한다.** 기존 서버는 임의로 종료하거나 재시작하지 않았다.

재시작 후 남은 검증:

1. 실제 일반 목록 응답의 `isDrafter`와 작성자/상태별 메뉴 노출 확인.
2. 실제 환경에서 리스트/피드의 고정 표시·정렬·페이징 유지 확인.
3. 캡처 시 뷰포트가 변하지 않는 브라우저에서 모바일/태블릿/데스크톱 스크린샷 재확인.

코드 및 대상 자동 검증은 반영했으나 실제 서버의 새 메뉴 계약과 전체 반응형 캡처까지 완료한 것으로 간주하지 않는다.
