# 영업 소수점 후속 검증 인수인계

## 상태

구현·부분 검증 상태이며 전체 배포 완료로 판단하지 않는다. 이 문서는 미검증 항목을 이어서 수행하기 위한 목록이다.

- 적용 범위: 모듈별 `number`(수량), `decimal`(단가), `currency`(금액) 정책과 프론트·서버 공통 컬럼 계약.
- 사용자 확인: 출하등록 저장, 재조회, 거래명세서를 확인했다. 해당 확인에서 소수점 입력값과 재조회값이 일치하는지는 별도로 보고되지 않았다.
- 직접 확인: 수주와 견적은 현재 정책으로 저장 후 수량·단가·금액을 재조회했고, 출하계획은 수정 저장 후 수량을 재조회했다.
- 테스트용 컬럼 예외와 격리 PostgreSQL을 사용한 수주 서비스·Mapper 저장 및 재조회는 확인했다. 견적·출하의 컬럼 예외 검증은 모의 DAO이며 실제 DB 저장이 아니다.
- 영업 소수점 확장 SQL은 사용자가 적용했고 읽기 전용 DB MCP로 대상 27개 컬럼의 `numeric(19,6)` 메타데이터를 확인했다. 추가 컬럼 생성 SQL은 필요하지 않다.
- 2026-11-25 커밋 전 관련 백엔드 테스트와 프론트 11개 파일 386개 테스트, 프론트 빌드를 확인했다. 프론트 병렬 실행은 시간 초과 등으로 실패해 단일 작업자로 재실행했다. 변경 파일 린트는 오류 없이 종료했으나 React 관련 경고가 있고, 빌드에는 번들 크기 경고가 있다.
- 상세 근거와 시점별 기록: [중간 결과](../../20261124/sales-decimal-policy/20261124_004_영업관리_타입별소수점_중간결과.md). 오래된 미완료 문장은 당시 상태이며 위 사용자 확인과 구분한다.

## 남은 검증

1. **컬럼별 예외의 전체 저장 경로**: 격리 환경에 테스트 계약의 `places` 또는 `rounding` 예외를 지정하고 프론트와 서버에 동일하게 배포한다. 수주·견적·출하·출하계획에서 입력, 계산, 저장, 재조회가 해당 필드별 규칙에 일치하는지 확인한다. 특히 행 금액과 헤더 합계가 다른 규칙인 경우 각각 검증한다. 서로 다른 계약을 배포한 경우 저장이 HTTP 409로 거부되는지도 확인한다.
2. **실제 정책관리 흐름**: 테스트 환경에서 `number`·`decimal`·`currency`를 다르게 설정해 저장하고 재조회한다. 정책 이력의 변경 전후, 저장 성공·실패, 재시도, 정책 갱신 후 열린 영업 화면의 입력 제한과 계산을 확인한다. 전역 정책 변경은 공유 사용자에게 영향을 줄 수 있으므로 격리 환경을 사용하거나 사전 협의한다.
3. **출하 소수점 값 일치**: 정책 자릿수에 맞는 수량·단가·금액을 입력하고 저장 전 표시, 출하현황 상세·수정 재조회, 자동 거래명세서 상세·인쇄를 비교한다. 입력값과 저장값이 바뀌지 않는지, 금액 계산은 적용된 `currency` 규칙을 따르는지 확인한다.
4. **연계 화면·반응형**: 수주·견적·출하·출하계획의 현황 및 거래명세서·매출마감 등에서 필드 의미와 2자리 제한 잔존 여부를 조사한다. 실제 로그인 화면에서 375·768·1280px 레이아웃과 저장 진행·성공·실패·dirty 초기화·저장 후 갱신을 확인하고 결과와 스크린샷을 남긴다.
5. **호환성과 경계값**: 컬럼별 예외가 없는 계약에 대해 구버전 스냅샷 미전송 호출과 타입만 바뀐 구버전 호출의 안전성을 검증한다. JSON 숫자 토큰 파서의 큰 지수 등 미검증 경계와 F1-Grid 정밀 모드 경계 사례를 확인한다.
6. **배포 계약**: `frontend/src/shared/config/decimal-column-contract.json`과 서버 WAR의 포함 파일이 일치하는지 확인한다. 백엔드 단독 소스 빌드에는 같은 상대 경로의 계약 파일이 필요하므로 누락 시 기능 실패 가능성을 확인하고 프론트·서버를 함께 배포한다.

## 이어서 작업할 때

- 기준 문서: [작업지시서](../../../directions/20261124/20261124_004_영업관리_타입별소수점_작업지시서.md), [계획서](../../../plan/20261124/20261124_004_영업관리_타입별소수점_계획서.md), [상세사양서](../../../spec/20261124/20261124_004_영업관리_타입별소수점_상세사양서.md).
- 관련 공통 계약: `frontend/src/shared/config/decimal-column-contract.json`, `frontend/src/shared/services/decimalColumnContract.ts`, `backend/src/main/java/egovframework/com/cmm/DecimalColumnRule.java`, `backend/src/main/java/egovframework/let/sales/common/SalesDecimalPolicy.java`. 재사용 방법은 `frontend/src/pages/f1-grid-docs/F1-GRID.md`를 참조한다.
- 기존 테스트 예시: 프론트 `npm run test -- tests/decimal-column-contract.test.ts` 및 백엔드 `mvn -q "-Dtest=DecimalColumnRuleTest,SalesDecimalColumnPolicyTest,DecimalColumnContractTest" test`. 실행은 각각 `frontend`, `backend` 디렉터리에서 한다.
- `SalesDecimalPostgresIntegrationTest`는 전용 빈 `sales_decimal_isolated_test` DB에서만 실행한다. 공유 DB에는 테스트용 테이블 생성이나 정책 변경을 실행하지 않는다.
- 사용자·테넌트 데이터와 인증 정보를 결과 문서, 테스트 출력 또는 채팅에 기록하지 않는다. 새 실제 검증은 테스트 데이터 사용과 환경 영향을 확인한 뒤 결과와 미확인 사항을 구분해 남긴다.
