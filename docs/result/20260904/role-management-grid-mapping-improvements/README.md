## 변경 결과

- 신규 F1-Grid 행을 저장 전에 삭제하면 모든 변경 집합에서 제거하도록 공통 상태를 보정했다.
- 역할 그리드는 선택 행 삭제·현재 행 내보내기 제어와 컨텍스트 메뉴 행 추가를 제공한다.
- 역할 저장은 신규 역할 POST와 기존 역할 PUT을 분리하고, 성공 후 서버 목록을 재조회해 dirty 상태를 초기화한다.
- 역할 ID별 사용자 매핑 조회에 요청 ID 보호를 적용해 늦은 응답이 현재 선택 역할을 덮어쓰지 않게 했다.
- 매핑 변경은 즉시 API 호출하지 않고 상단 저장에서 추가·해제 API를 일괄 호출한다.
- 미저장 매핑 상태에서 역할을 전환하면 계속 편집·저장 후 이동·변경 취소 후 이동을 선택하게 했다.
- 저장 재진입을 차단하고 다건 저장의 성공 항목을 체크포인트로 관리해 부분 실패 재시도 시 중복 요청을 막았다.

## DB 영향

- DB 스키마 변경 없음.
- 기존 `tb_role`, `tb_login_account`, `tb_login_account_role`와 기존 역할-사용자 매핑 API를 재사용했다.
- 따라서 날짜별 SQL, rollback SQL, `docs/database/db-schema.md` 갱신은 해당 없다.

## 잔여 검증

- Playwright 캡처는 `capture-role-management-grid-mapping.js`로 두 차례 실행했으나, 현재 대시보드 인증/메뉴 초기화 상태에서 `환경설정` 메뉴 locator를 찾지 못해 스크린샷을 생성하지 못했다.
- 기존 전체 `f1-grid.test.tsx`에는 이번 변경 이전부터 편집기 진입 입력 요소를 찾지 못하는 실패 20건이 남아 있다. 이번 신규 행 삭제 회귀 테스트는 전체 실행에서 통과했다.
