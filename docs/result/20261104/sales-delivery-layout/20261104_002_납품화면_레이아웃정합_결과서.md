# 납품 화면 레이아웃 정합 결과

## 요청과 원인

수주등록=납품등록, 수주현황=납품현황의 구조와 버튼 위치를 맞추라는 후속 요청이다. 최초 납품 화면은 별도 본문 액션바, 3열 입력, 상세 영역 밖 도구, 텍스트 합계, 번호 클릭 시 바로 편집모달로 작성되어 수주 화면과 달랐다.

## 변경

- 등록: 수주와 동일한 `PageHeader` 신규/저장/삭제 그룹(신규 문서의 삭제는 비활성), 본문 여백, 기본정보 제목, xs1/sm2/lg4열, 전체폭 multiline 비고.
- 상세: 같은 outlined Paper, 제목/설명 좌측과 도구 우측(좁은 공간에서는 동일한 wrapping), 내부 그리드, 공급가/부가세/총합계 3개 카드. 선택 행 삭제 버튼 대신 기존 우클릭 삭제 유지.
- 현황: 동일한 40px 빠른검색, Enter/검색어 초기화, 공통 조회 안내 메시지, 목록 여백, 좌측 No 및 문서 헤더 병합, 문서 링크/행 선택.
- 번호→같은 페이지 영역 상세패널→더보기→자세히보기/수정. 조회모달은 읽기 전용, 수정모달 하단 좌측 삭제 및 우측 저장/취소. 저장 후 목록/패널 갱신, 삭제 후 목록 복귀.
- 납품구분/연결 수주와 기존 수량·금액/권한 계약은 유지한다. 현황 READ만으로 상세를 볼 수 있으며 변경은 등록 메뉴 UPDATE/DELETE 기준이다. 작성자가 아닌 사용자도 해당 권한이 있으면 기존대로 수정할 수 있다.
- 납품에 없는 수주상태/납기/견적/작성자 이름·등록시각을 임의 필드로 만들지 않았다. 저장 후 상세 재조회 실패 복구용 재조회만 예외적으로 남겼다.

브라우저 API는 모두 합성 데이터로 응답했다. 실제 DB/API 연결, 실운영 데이터, SQL 적용 검증을 의미하지 않는다. 이번 수정은 프론트엔드만 변경하므로 백엔드 테스트/DB MCP/스키마 스크립트 변경은 해당하지 않는다.

### 위치 측정

원본 좌표는 [layout-metrics.json](layout-metrics.json)에 기록했다.

- 모든 폭에서 등록 헤더 버튼/본문/기본정보의 x·폭, 현황 검색/그리드/조회 버튼의 x·폭이 기준 수주와 일치한다.
- 375/1280px에서는 등록 신규·저장 및 현황 검색·목록 시작 y도 일치한다.
- 768px에서는 기준 수주의 페이지 설명이 한 줄 더 줄바꿈되어 등록/현황의 헤더 아래 시작 y가 약20px 차이 난다. 같은 PageHeader 구조에 내용 길이가 다른 경우이며 별도 고정 높이를 넣지 않았다.
- 모든 폭에서 상세패널·편집모달·하단 footer·저장/삭제 버튼의 x/y/폭/높이가 기준 수주와 일치한다.
- 모바일 납품 기본정보는 수주보다 실제 필드가 하나 적어 높이가48px 작다. 수주 전용 필드를 만들어 높이만 맞추지 않았다.
