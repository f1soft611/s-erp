# 초과납품 정책 Implementation Plan

**Goal:** 테넌트별 차단/경고확인 정책으로 수주·계획 초과납품을 지원한다.

**Architecture:** 기존 납품 저장 서비스가 수주 헤더 잠금 후 실제 누적수량을 계산한다. 경고 정책에서 확인되지 않은 요청은 409 경고로 반환하고 화면은 입력 스냅샷을 확인 후 다시 저장한다. DB는 실수량의 상한을 업무 정책에 맡기되 비음수·유한수 제약을 유지한다.

**Tech Stack:** Java 8, Spring/MyBatis, PostgreSQL, React/TypeScript, Vitest.

## 실행 단위

- [x] 백엔드: `SalesDeliveryServiceImplTest`에 BLOCK 거부, WARN 미확인 거부/확인 허용, 수주상세별 분할 합산, 수정 자기수량 복원, 삭제 및 DIRECT 회귀 테스트를 먼저 추가하고 실패를 확인한다.
- [x] 서버/Mapper: tenant 정책 조회, 요청 확인 플래그, 동일 트랜잭션의 수주·계획 누적량 검증 및 조건부 상한 갱신을 구현한다. 초과 후 AUTO 수주 변경과 계획 수정의 기존 가정도 점검한다.
- [x] DDL: `20261105_003` 변경·조건부 rollback·이력을 두 스키마 폴더에 동일하게 보관하고 누적 스키마를 갱신한다. DB 미적용 상태를 유지한다.
- [x] 프론트엔드: 기존 API/page 테스트에 경고 취소, 확인 후 같은 입력 재저장, 재시도 중 중복 방지, 잔량 없는 계획의 선택을 추가한다. 서비스에서 409 경고를 구분하고 확인 대화상자를 제공한다.
- [x] 검증: Maven 관련 테스트 및 Java 8 API 검증, 납품/계획 Vitest, build/변경파일 lint, 375/768/1280px 브라우저 스크린샷, DDL 사본 및 문서 링크 확인.
