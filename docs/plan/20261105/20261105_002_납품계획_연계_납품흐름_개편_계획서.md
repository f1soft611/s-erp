# 납품계획 연계 납품흐름 개편 계획서

## 목표

테넌트별 `MANUAL`/`AUTO` 납품계획 모드를 지원하고 수주→납품계획→납품의 데이터 일관성과 화면 흐름을 완성한다.

## 작업 단계

1. **스키마/이력:** tenant 모드, 계획 HD/DT, 납품상세 연결, 기존 주문·납품 backfill, 메뉴 seed/rollback 작성. `docs/database`와 `backend/DATABASE` 파일 동일성 및 누적 schema를 검증한다.
2. **백엔드 계약:** plan mode/config, plan CRUD/status/source endpoint와 모델/DAO/mapper를 TDD로 구현한다. tenant scope, 메뉴 권한 및 MANUAL/AUTO server guard를 적용한다.
3. **수주 연동:** AUTO order create/update에 계획 생성을 포함한다. 기존 상세 ID 유지 update 및 계획수량/납품이력 보호 테스트를 작성한다.
4. **납품 연동:** plan detail picker API 및 create/update/delete의 delivered/shipped quantity 원자 조정을 구현한다. DIRECT 회귀 테스트를 유지한다.
5. **화면/메뉴:** 수주 아래 계획 등록·현황 메뉴 및 전용 페이지, tenant mode별 탐색, 계획 선택 납품등록을 수주 화면 레이아웃 패턴에 맞춰 구현한다.
6. **검증/결과:** Maven, `javac --release 8`, 관련 Vitest/build/lint, SQL static checks, 브라우저 375/768/1280, 결과 문서와 영문 경로 스크린샷을 남긴다. SQL은 적용하지 않는다.

## 위험/통제

- 수주 상세 삭제 후 재생성은 계획/납품 참조를 파괴한다. update를 stable line-number sync로 바꾸고 참조된 행의 수량 감소/품목변경/삭제를 409로 막는다.
- 계획 상세와 납품 상세 카운터는 수주 헤더 lock 아래 같은 트랜잭션에서 변경한다.
- 기존 운영행 backfill이 가정한 참조/수량 무결성과 맞지 않으면 SQL을 적용하지 않고 preflight 실패로 멈춘다.
- tenant 설정 UI/실 DB 적용은 범위 밖이며, mode는 versioned SQL로 운영자가 정한다.
