# 공통 알림·쪽지함 통합 계획서

**목표:** 댓글 멘션과 새 쪽지를 사용자별 공통 알림함에 연결하고, 별도 읽음 상태를 가진 1:1 쪽지함을 구축한다.

**아키텍처:** `tb_notification`은 업무 발생원별 수신자 알림/읽음 상태를 관리한다. `tb_direct_message_thread`와 `tb_direct_message`는 1:1 메시지 대화와 수신자 읽음 상태를 독립 관리한다. 쪽지 발신과 알림 생성, 대화 읽음과 해당 알림 읽음 동기화는 트랜잭션으로 처리하고, 헤더의 알림/쪽지 뱃지는 서로 다른 요약 API를 사용한다.

**기술 스택:** Spring Boot/eGovFrame, MyBatis, PostgreSQL, React 19, TypeScript, MUI, React Router, Vitest/Testing Library, Maven.

## Task 3: 1:1 쪽지 서버

**Files:** message Controller/Service/DAO/VO/Mapper; service tests.

- [ ] 테스트를 먼저 작성해 same-tenant 활성 수신자만 새 thread를 만들 수 있고 sender=recipient, 타 tenant, 비활성 계정은 거부됨을 검증한다.
- [ ] 새 thread와 첫 message 및 `DIRECT_MESSAGE_RECEIVED` 알림을 하나의 transaction에서 저장한다.
- [ ] `INBOX`/`SENT` thread 목록과 현재 참여자만 볼 수 있는 상세 조회를 구현한다.
