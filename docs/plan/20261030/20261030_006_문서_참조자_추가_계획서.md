# 문서 참조자 추가 계획서

## 근거 문서

- 승인 설계: [문서 참조자 추가 설계](../../superpowers/specs/2026-10-30-document-reference-addition-design.md)
- 상세 구현 계획: [Document Reference Addition Implementation Plan](../../superpowers/plans/2026-10-30-document-reference-addition.md)

## 작업 범위

- 상신 후 문서 열람 권한이 있는 사용자가 기존 참여자 모델에 `REFERENCE` 참여자를 추가한다.
- 참여자 추가와 `REFERENCE_ADDED` 공통 SYSTEM 타임라인 이력을 원자적으로 저장한다.
- 문서 더보기 메뉴에 참조자 추가를 추가하고 공유 작업과 수정/삭제 작업을 구분선으로 그룹화한다.
- DB MCP에서 확인한 DB 계약은 동일 tenant/활성 로그인 사용자 조회, 참여자 사용자 및 위치 unique 제약, 참조 action 상태 CHECK 및 SYSTEM event CHECK다. `REFERENCE_ADDED` 추가를 위해 `chk_tb_common_comment_event_type` 변경 이력이 필요하다.
- 기존 `selectActiveParticipants`, `selectApprovalLines`, `selectDocumentApprovalForUpdate`, `selectIsDocumentParticipant`, `insertDocumentApprovalLine`, `insertSystemEvent` 경로를 재사용한다. 필요성이 테스트로 드러나지 않는 한 DAO/Mapper 쿼리를 추가하지 않는다.
- 상세 구현 단계와 테스트 명령은 [상세 실행 계획](../../superpowers/plans/2026-10-30-document-reference-addition.md)을 따른다.

## 검증

- 백엔드 서비스/API/매퍼 테스트에서 접근권한, 유효 사용자, 중복 방지, SYSTEM 이력 원자성을 확인한다.
- 프론트엔드 서비스/메뉴/선택 다이얼로그/타임라인 갱신 테스트와 빌드를 수행한다.
- 실제 브라우저 375px, 768px, 1280px 확인 후 `docs/result/20261030/document-reference-addition/`에 결과 및 스크린샷을 기록한다.

## 승인된 후속 수정 계획

1. 문서현황 통합 테스트에서 상세를 연 뒤 `onActionComplete`를 실행하면 상세가 유지되는지 확인한다.
2. 목록 조회 시작 콜백과 검색 조건 변경을 분리해, 참조자 추가에 따른 재조회는 상세를 닫지 않고 검색 조건 변경 시에는 기존처럼 닫도록 수정한다.
3. 참조자 SYSTEM 이력의 기대 문구를 `작성자님이 참조자(검토자, 관리자)를 추가했습니다.` 형식으로 검증하고 서비스 문구를 같은 형식으로 변경한다.
4. 대상 테스트, 프론트엔드 빌드, 백엔드 서비스 테스트와 `git diff --check`를 수행하고 결과 문서에 재현·원인·해결·검증을 추가한다. 스키마/API 구조 변경은 없으므로 migration은 추가하지 않는다.
5. 참조 추가 성공 후 문서현황 그리드·상세·타임라인을 기존 데이터가 보이는 상태로 백그라운드 재조회한다. 로딩 표시만 억제하고 조회 실패는 기존 오류 UI에 노출하는 회귀 테스트를 추가한다.
