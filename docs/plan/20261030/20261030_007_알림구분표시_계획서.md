## 실행 순서

1. 실패하는 프런트엔드 유형 표시/필터/숨김 테스트와 백엔드 서비스 테스트를 작성한다.
2. 관련 frontend 및 backend tests를 실행해 변경 전 실패를 확인한다.
3. API 유형 allowlist와 mapper filter를 추가하고, UI의 유형 필터/단건 hide/read bulk archive를 구현한다.
4. `archived_at` DDL/rollback/change record를 `docs/database`와 `backend/DATABASE`에 동일하게 추가한다. 실제 DB에는 적용하지 않는다.
5. 단건 archive는 인증된 사용자의 알림만 대상으로 하고 bulk archive는 읽은 알림만 선택 유형 범위에서 처리한다. 목록과 unread summary에서 archived rows를 제외한다.
6. focused frontend/backend tests, frontend build, 실제 375/768/1280px 브라우저 검증을 수행한다.
7. 결과 문서에 읽기 전용 DB MCP 근거와 migration 미적용 상태를 기록하고 스크린샷을 보관한다.

## 제외

알림 헤더 팝오버, 쪽지함, 알림 제목/요약 payload, 원본 댓글/쪽지 삭제는 변경하지 않는다. 알림 행은 물리 삭제하지 않는다.
