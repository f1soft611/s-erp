# 환경설정 조용한 저장 편집 잠금 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 권한·메뉴·모듈·창고 관리 화면에서 저장 요청부터 저장 후 조용한 재조회 종료까지 기존 데이터를 표시하고 변경·전환 조작을 잠근다.

**Architecture:** 이미 있는 페이지/패널 `saving` 상태를 사용하거나 명시적 prop으로 Grid에 전달한다. 두 권한 그리드, 트리, 모듈·창고 그리드의 편집·추가·삭제 경로와 조회/대상 전환 액션을 잠그고 일반 조회 `loading` 및 공통 F1-Grid 동작은 유지한다.

**Tech Stack:** React, TypeScript, F1-Grid/F1-Tree, Vitest, Testing Library.

- [ ] **Step 1: 역할 및 사용자 매핑의 저장 중 잠금 회귀 테스트 추가**

저장 API와 저장 뒤 조용한 사용자 목록 재조회를 지연시켜 두 단계 모두 잠금이 유지되는지 검증한다. 역할 행 편집, 사용자 매핑 편집/삭제, 사용자 추가 적용, 다른 역할 선택 및 조회는 막고 기존 역할·사용자 행은 유지한다. 저장 및 재조회 실패에서는 오류 전달과 dirty 데이터 보존을 확인하고 작업 종료 뒤 잠금 해제를 검증한다.
저장 버튼 반복 클릭이 중복 요청을 만들지 않고 초기/일반 조회 로딩이 유지되는지도 확인한다.

```tsx
expect(screen.getByRole('grid', { name: 'F1-GRID 권한 관리' })).toBeVisible();
expect(screen.getByRole('grid', { name: 'F1-GRID 사용자 매핑' })).toBeVisible();
expect(screen.queryByTestId('f1-grid-loading-overlay')).not.toBeInTheDocument();
```

- [ ] **Step 2: 역할관리 회귀 테스트가 기존 동작에서 실패하는지 확인**

Run: `cd frontend; npm run test -- tests/role-management-notification.test.tsx`

Expected: 추가한 저장 중 편집·대상 전환 assertion 중 최소 하나가 FAIL.

- [ ] **Step 3: 패널의 기존 saving 상태를 모든 변경 경로에 적용**

페이지의 저장 상태로 검색/저장 액션을 잠그고, 패널의 기존 `saving` 상태를 두 Grid의 `canEdit`, `beforeEdit`, 컨텍스트 동작과 사용자 추가·적용 버튼에 연결한다. 저장 전부터 열린 사용자 추가 다이얼로그의 적용도 차단하고, 취소/닫기는 허용한다.

```tsx
canEdit: () => !saving
```

```tsx
disabled={saving || userLoading || !candidateLoginId}
```

역할 전환 확인 다이얼로그의 기존 `disableContinue={saving || userLoading}` 동작을 유지하고, 역할/사용자 Grid의 `loading`에는 기존 일반 조회 상태만 전달한다.

Run: `cd frontend; npm run test -- tests/role-management-notification.test.tsx`

Expected: 테스트 파일 전체 PASS.

- [ ] **Step 1: 지연 저장 중 메뉴 트리와 매핑의 회귀 테스트 추가**

메뉴 저장과 역할별 메뉴 권한 저장을 각각 지연시킨다. 각 구간에 모듈/역할 선택이 잠기고 메뉴 트리의 추가·삭제·셀 편집과 권한 매핑 변경이 막히며 저장 진행 표시와 기존 데이터가 유지되는지 검증한다. 저장 및 재조회 실패 시 기존 오류/dirty 데이터 정책과 작업 종료 후 잠금 해제도 검증한다.
저장 액션 반복 클릭으로 요청이 중복되지 않고 일반 조회의 기존 로딩 표현이 유지되는지 확인한다.

```tsx
const moduleSelector = screen.getByRole('combobox', { name: '모듈 선택' });
const roleSelector = screen.getByRole('combobox', { name: '권한 선택' });
expect(moduleSelector).toHaveAttribute('aria-disabled', 'true');
expect(roleSelector).toHaveAttribute('aria-disabled', 'true');
expect(screen.queryByTestId('f1-grid-loading-overlay')).not.toBeInTheDocument();
expect(await screen.findByRole('gridcell', { name: '대시보드' })).toBeVisible();
```

- [ ] **Step 2: 메뉴관리 회귀 테스트가 기존 동작에서 실패하는지 확인**

Run: `cd frontend; npm run test -- tests/menu-management-f1-grid.test.tsx`

Expected: 저장 중 트리/권한 매핑 조작을 차단하는 새 assertion이 FAIL.

- [ ] **Step 3: 메뉴 저장 상태로 모든 트리 변경 경로를 잠금**

기존 `saving`을 `menuEditorPlugin`의 편집 허용 조건 및 `beforeEdit`에서 확인한다. 트리의 추가/삭제 메뉴 진입점을 `!saving`으로 제한하고, 권한 매핑 입력·적용과 저장 관련 액션도 같은 상태를 사용한다. 페이지의 모듈/역할 선택은 기존 `disabled={loading || saving || ...}` 계약을 유지한다.

```tsx
allowAddRowInContextMenu={!saving}
allowDeleteRowInContextMenu={!saving}
```

```tsx
if (saving) return false;
```

기존 메뉴 검증, 부모-자식 삭제 방지, API 응답 오류 및 dirty 데이터 정책은 변경하지 않는다.

- [ ] **Step 4: 메뉴관리 집중 테스트 실행**

Run: `cd frontend; npm run test -- tests/menu-management-f1-grid.test.tsx`

Expected: 테스트 파일 전체 PASS.

- [ ] **Step 1: 모듈·창고 저장 중 잠금 테스트 추가**

모듈 테스트는 기존 페이지/저장 테스트 harness를 사용해 저장 요청과 후속 GET을 지연한다. 창고는 실제 `WarehouseManagementPage`를 렌더링하고 API 모의를 추가해 같은 두 구간을 검증한다. 기존 행 유지, 오버레이 미표시, 편집/추가/삭제/조회 차단을 측정한다. 저장과 재조회 실패 시 오류 전달, dirty 데이터 보존 및 잠금 해제도 검증한다.
저장 액션 반복 클릭으로 중복 요청이 발생하지 않고 일반 조회의 로딩 표시가 기존처럼 동작하는지도 확인한다.

```tsx
expect(await screen.findByRole('grid', { name: 'F1-GRID 모듈 관리' })).toBeVisible();
expect(screen.queryByTestId('f1-grid-loading-overlay')).not.toBeInTheDocument();
expect(screen.queryByRole('menuitem', { name: '행 추가' })).not.toBeInTheDocument();
expect(screen.getByRole('button', { name: '조회' })).toBeDisabled();
```

창고 테스트는 화면의 실제 accessible name과 기존 페이지 버튼 label을 렌더 결과에 맞춰 사용하며, 컴포넌트 내부 구현에 결합한 얕은 mock 대신 Testing Library 사용자 동작을 사용한다.

- [ ] **Step 3: 페이지 saving 상태를 두 패널에 전달**

```tsx

```

```tsx
saving={saving}
```

- [ ] **Step 4: 패널의 편집·추가·삭제 진입점 잠금**

두 패널에서 각 컬럼의 `editable`, `beforeEdit`, 추가·복제·삭제 컨텍스트 메뉴 허용 여부를 `saving` 조건으로 갱신한다. 조회 액션은 비활성화하고 `loading`에는 기존 일반 조회 상태만 전달한다. 기존 코드/이름 권한별 편집 조건은 `saving` 검사와 AND 결합한다.

```tsx
editable: (row) => !saving && canEditModuleCode(row)
```

```tsx
allowAddRowInContextMenu={!saving}
allowDeleteRowInContextMenu={!saving}
```
