# 품목관리 공통코드·컬럼 정비 Implementation Plan

**Goal:** 승인된 품목관리 컬럼 순서·고정·정렬과 공통코드 select를 적용한다.

**Architecture:** 기존 품목 컬럼 metadata와 `createMaterialColumns`를 사용한다. 기존 옵션 API의 Mapper 조회 그룹에 `ITEM_TYPE`, `ITEM_UNIT`을 추가하고 API/DB 저장 계약은 유지한다.

**Tech Stack:** React, TypeScript, F1Grid, Vitest, Spring/MyBatis, JUnit.

## 2. 구현

대상: `frontend/src/pages/co/master/materials/types/materialManagement.types.ts`, `frontend/src/pages/co/master/materials/components/MaterialGrid.tsx`, `backend/src/main/resources/egovframework/mapper/let/co/master/material/MaterialInfo_SQL_postgresql.xml`.

- [ ] 품목계정 metadata를 맨 앞으로 옮기고 `codeGroup: 'ITEM_TYPE'`, 단위에는 `codeGroup: 'ITEM_UNIT'`을 설정한다.
- [ ] `matCataType`은 타입/정규화/저장에는 남기고 컬럼 생성에서는 제외한다.
- [ ] 세 업무 컬럼에 `pinned: 'left'`, 지정 컬럼에 `align`을 설정한다.
- [ ] 소비기한 옵션은 공통코드 중 `NONE/DAY/MONTH/YEAR`만 사용하고 현재 행의 기존 허용값은 보존한다. 선택되지 않은 코드를 정적 목록으로 만들어내지 않는다.
- [ ] 옵션 Mapper 그룹을 다섯 개로 확장한다. 기존 tenant·활성·정렬 조건은 그대로 둔다.
- [ ] 기존 컬럼 저장 설정이 새 기본 설정을 가리는지 확인하고 필요하면 품목 전용 storageKey만 버전 변경한다.
