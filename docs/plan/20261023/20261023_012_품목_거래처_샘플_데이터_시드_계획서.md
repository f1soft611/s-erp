# 품목·거래처 샘플 데이터 시드 계획서

## 목표

지정 tenant에서 품목 100건과 거래처 100건을 생성할 수 있는 안전한 PostgreSQL 시드 SQL을 추가하고, 실제 DB에는 실행하지 않는다.

- 정적 검증: `tools/tests/test_customer_material_sample_seed.cjs`
- SQL 시드: `docs/database/20261023/20261023_005_seed_customer_material_sample_data.sql`

프론트엔드/백엔드 애플리케이션 코드나 테이블 스키마는 수정하지 않는다. SQL 변경 사본에는 날짜별 스키마 변경 이력과 롤백 파일을 만들지 않는다. 샘플 데이터 삽입은 사용자가 수동 실행하는 별도 데이터 시드이며, 자동 삭제 스크립트는 제공하지 않는다.

## 구현 단계

### 1. 정적 검증 테스트

- [ ] Node 내장 `node:test` 테스트로 SQL 두 파일의 존재와 byte-for-byte 동일성을 확인한다.
- [ ] 필수 psql `target_tenant_id`, `ON_ERROR_STOP`, 단일 트랜잭션, tenant 검증, 기존 카운터/테이블 잠금, 충돌 시 `RAISE EXCEPTION`을 확인한다.
- [ ] 두 엔터티의 100건 생성 규칙, 6자리 범위, 활성 코드 조회, 기존 행 UPDATE/DELETE가 없는지 검증한다.
- [ ] SQL 파일을 아직 만들기 전에 테스트를 실행하여 누락 파일을 이유로 실패하는지 확인한다.

### 2. SQL 시드

- [ ] 실행 시 tenant 변수를 필수로 받으며, 변수 누락/숫자 변환 오류를 명시적으로 실패 처리한다.
- [ ] 하나의 트랜잭션 안에서 ID Generator 카운터 행을 `ORDER BY table_name FOR UPDATE`로 먼저 잠근다. 두 카운터 행이 모두 없으면 중단한다.
- [ ] `tb_customer_info`, `tb_material_info`를 `SHARE ROW EXCLUSIVE`로 잠근다. 테이블의 SELECT는 허용하고, 트랜잭션 종료까지 모든 tenant에 대한 해당 테이블의 INSERT/UPDATE/DELETE를 대기시킨다.
- [ ] tenant 존재와 활성 `ITEM_TYPE`, `ITEM_UNIT` 코드를 검사한다. 해당 코드가 하나라도 없으면 중단한다. `MATERIAL_TYPE`, `STORE_METHOD`는 활성값이 있으면 사용하고 없으면 NULL로 둔다.
- [ ] 기존 코드 최댓값과 `public.ids.next_id` 중 큰 다음 값부터 거래처/품목 코드를 각각 100개 예약한다. 6자리 허용 범위를 벗어나거나 카운터가 없는 경우 전체 롤백한다.
- [ ] `샘플 거래처 001`~`100`, `샘플 품목 001`~`100` 이름, 표준 검증 체크섬이 맞지 않는 고유 10자리 사업자번호, 안전한 필수값을 생성한다. 품목 제조사 코드는 같은 작업에서 생성한 거래처와 연결한다.
- [ ] 동일 샘플 마커/이름/사업자번호가 발견되면 기존 행을 건너뛰거나 수정하지 않고 전체를 중단한다. 생성 후 각 마커 기준으로 두 테이블의 건수가 정확히 100인지 검사한다.
- [ ] SQL 본문을 두 경로에 동일하게 복사한다.

### 3. 검증 및 결과 문서

- [ ] `node --test tools\tests\test_customer_material_sample_seed.cjs`를 실행한다.
- [ ] `git diff --check`와 PowerShell SHA-256 비교로 변경 공백 오류 및 두 SQL 사본 동일성을 확인한다.
- [ ] SQL을 읽기 전용 MCP로 실행하지 않으며, 다른 접속 수단으로도 실제 DB에 적용하지 않는다.
- [ ] 결과 문서에 DB MCP 메타데이터 확인 범위, 정적 테스트 결과, 코드/충돌 보호, 잠금으로 인한 쓰기 대기, 실제 DB 미실행을 기록한다.
- [ ] UI 변경이 없으므로 스크린샷은 만들지 않는다.

## 완료 기준

- SQL은 지정 tenant 변수 없이는 시작되지 않는다.
- 정상 실행을 설계하면 100개 거래처와 100개 품목이 모두 생성되며, 품목 코드는 가상 거래처 코드와 연결된다.
- 기존 ID Generator 코드가 예약된 코드 이후부터 계속 발급되며, 코드 범위가 초과되면 시드 전체가 롤백된다.
- 두 테이블에 대한 충돌 검사와 INSERT 사이에는 쓰기 잠금이 유지되고, 기존 업무 행을 갱신/삭제하지 않는다.
- 집중 정적 테스트, 두 사본 비교, diff 검사가 완료된다. 실제 DB에는 실행하지 않는다.
