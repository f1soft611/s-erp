# F1-Grid Row Save Implementation Plan

> **For agentic workers:** Use executing-plans to implement this plan task-by-task.

**Goal:** 거래처·품목 저장 응답을 전체 재조회 없이 해당 행에 확정한다.

**Architecture:** 기존 배치 결과 목록을 유지하고 `rowIdMappings`(요청 ID → 실제 ID)를 추가한다. 공통 응답 검증으로 `{ previousRowId, row }` 배열을 만들고 F1GridRef의 `acceptSavedRows`로 상태와 선택/포커스 ID를 전환한다. 화면 훅은 반환된 전체 행을 로컬 기준 목록으로 보관하되 그리드를 재생성하지 않는다.

**Tech Stack:** React, TypeScript, Vitest, Java, Spring, JUnit/Mockito.

## Task 1: 저장 계약
- [x] 배치 서비스 테스트에 기존 목록 및 명시적 ID 매핑 검증을 추가하고 실패를 확인한다.
- [x] 두 ResultVO와 BatchServiceImpl에 `Map<String, Long> rowIdMappings`를 추가한다. 기존 요청 ID를 키로 사용한다.
- [x] 중복 요청 ID는 쓰기 전에 거부하고 기존 클라이언트의 ID 생략은 호환 유지한다.
- [x] `cd backend; mvn "-Dtest=MaterialInfoBatchServiceImplTest,CustomerInfoBatchServiceImplTest" test` 실행.

- [x] `GridState.ts`에 `acceptSavedGridRows`, `grid.types.ts`에 `F1GridSavedRow<T>`와 `acceptSavedRows`를 추가한다.
- [x] 기존 인덱스와 수정 메타데이터를 복사하고 성공한 행의 메타데이터만 지운다. 모든 매핑 검증을 상태 변경 전에 완료한다.

- [x] 서비스의 기존 배열 반환은 유지하고 새 확정 결과용 호출을 추가하여 다른 호출자의 호환성을 유지한다.
- [x] 양 관리 훅에 저장 확정 콜백을 연결하고 `loadRows` 및 `gridKey` 초기화 대신 확정된 행을 기준 목록으로 보관한다.

- [x] 기존 테스트에서 재조회 기대를 제거하고 GET 증가 없음, 그리드 동일성, 자동 코드 반영과 후속 수정/폐기 기준을 검증한다.
