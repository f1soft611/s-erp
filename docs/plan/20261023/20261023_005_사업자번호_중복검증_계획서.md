# 사업자번호 중복 검증 계획서

**근거:** [작업지시서](../../directions/20261023/20261023_005_사업자번호_중복검증_작업지시서.md).

**목표:** 표기 차이가 있는 동일 사업자번호를 폼/그리드/서버/DB에서 중복으로 처리한다.

## 실행 계획

- `validation.unique?: boolean | 'digits'`로 기존 true/false 계약을 보존하면서 숫자 비교를 지원한다. `GridValidation.ts`의 공통 인덱스 생성/조회 모두 같은 정규화를 사용한다.
- 거래처 businessNo에 `validation: { unique: 'digits' }`를 선언한다. required/10자리 검증과 상단 메시지·빨간 표시·자기행 제외를 유지한다.
- 공통 unit, 거래처 폼/저장, 서버 등록/수정/동시 충돌 및 mapper 검증 테스트를 먼저 작성하고 실패를 확인한다. 기존 정상 신규 폼 fixture는 다른 번호로 수정한다.
- Service/DAO/Mapper에 숫자 정규화 사업자번호 사전 검사를 추가한다. NULL/빈 번호는 기존 서버 선택 필드 계약을 유지하며 고유성 검사만 제외한다. 번호 필수화·자리수 정책 추가 등 별도 서버 계약 변경은 하지 않는다.
- `20261023_002` migration으로 tenant/정규화 번호 partial unique index를 정의한다. 기존 비어 있는 번호는 제외하고, 중복이 있으면 값을 노출하지 않는 오류로 중단한다. 데이터 자동 수정 없음.
- F1-Grid 가이드·API 참조·OpenAPI 설명·누적 스키마·두 SQL 사본을 갱신한다.
- 집중 Vitest, customer Maven, build, 375/768/1280px fixture 브라우저 검증을 실행하고 결과·스크린샷을 기록한다.
