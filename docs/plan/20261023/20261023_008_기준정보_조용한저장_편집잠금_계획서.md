# 기준정보 조용한 저장 편집 잠금 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `subagent-driven-development` or `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공통코드와 기안양식관리에서 저장 요청부터 조용한 재조회 종료까지 기존 행을 유지하고 모든 데이터 변경 조작을 잠근다.

**Architecture:** 페이지가 소유한 저장 상태를 관리 패널과 Grid에 명시적으로 전달한다. 화면별 F1-Grid/F1-Tree 편집·추가·삭제 게이트와 조회/대상 전환 액션을 잠그며, 일반 조회용 `loading` 및 공통 F1-Grid 동작은 변경하지 않는다.

**Tech Stack:** React, TypeScript, F1-Grid/F1-Tree, Vitest, Testing Library.

## Task 1: 기안양식관리 저장 중 편집 잠금

**Files:**

- Modify: `frontend/src/pages/co/workflow/form/components/DraftFormGrid.tsx`

- [ ] **Step 1: 저장 중 재조회 지연을 이용한 회귀 테스트 추가**

기존 `keeps the form grid visible and shows quiet progress while saving` 시나리오를 확장한다. PUT 완료 뒤 목록 GET 응답을 지연시켜 저장 API 구간과 조용한 재조회 구간을 각각 확인한다. 두 구간 모두 기존 행과 `기안양식 저장 중` 진행 표시가 남고 로딩 오버레이는 없으며, 조회·추가·편집·행 폼 적용은 불가능해야 한다.
저장 버튼을 빠르게 반복해도 API 요청이 중복되지 않는지 확인하고, 저장 또는 재조회 실패에서는 오류 전달·dirty 데이터 보존·작업 종료 후 잠금 해제를 검증한다.

```tsx
expect(await screen.findByText('정기점검')).toBeVisible();
expect(screen.getByRole('progressbar', { name: '기안양식 저장 중' })).toBeVisible();
expect(screen.queryByTestId('f1-grid-loading-overlay')).not.toBeInTheDocument();
expect(screen.getByRole('button', { name: '조회' })).toBeDisabled();
expect(screen.queryByRole('menuitem', { name: '행 추가' })).not.toBeInTheDocument();
```

- [ ] **Step 2: 회귀 테스트가 기존 동작에서 실패하는지 확인**

Run: `cd frontend; npm run test -- tests/draft-form-management.test.tsx`

Expected: 새 잠금 assertion이 실패한다. 다른 기존 테스트가 실패하면 그 결과를 따로 기록하고 이번 요구사항과 구분한다.

- [ ] **Step 3: 페이지 저장 상태를 Grid의 모든 변경 경로에 연결**

페이지에서 저장 중 권한을 제거해 전달하고, Grid 컴포넌트에서는 명시적 `saving` prop을 사용해 폼 플러그인과 메뉴 진입점을 함께 막는다. `loading`에는 일반 조회 상태만 전달한다.

```tsx
<DraftFormGrid
  saving={management.saving}
  canCreate={
    pagePermissions.create &&
    management.categoryItems.length > 0 &&
    !management.saving
  }
  canUpdate={pagePermissions.update && !management.saving}
/>
```

```tsx
allowAddRowInContextMenu={canCreate && !saving}
allowDuplicateRowInContextMenu={canCreate && !saving}
```

Grid 내부의 행 폼 열기·적용 및 템플릿 열기 콜백도 `saving`이면 즉시 종료하게 하고, 검색/분류 전환 컨트롤은 `saving` 동안 비활성화한다. 저장 후 조용한 재조회가 완료되거나 실패해 페이지 저장 상태가 해제되면 원래 권한에 따라 다시 활성화한다.

- [ ] **Step 4: 기안양식관리 집중 테스트 실행**

Run: `cd frontend; npm run test -- tests/draft-form-management.test.tsx`

Expected: 해당 파일의 기존 테스트와 저장·재조회 중 잠금 테스트가 모두 PASS.

- [ ] **Step 1: 그룹·상세코드 저장 중 지연 테스트 추가**

기존 같은 그룹 재조회 테스트의 API 지연 패턴을 사용해 batch save 응답 및 성공 후 그룹/상세코드 재조회를 지연시킨다. 저장 중 기존 선택 그룹과 상세 행을 유지하고, 두 패널의 수정·추가·삭제, 조회 및 다른 그룹 선택을 차단하는 검증을 추가한다. 저장 API와 재조회 각각의 실패에서도 오류 전달과 dirty 데이터 보존, 작업 종료 후 잠금 해제를 검증한다.
저장 액션 반복 시 중복 batch 요청이 발생하지 않으며 일반 사용자 조회의 로딩 표현은 기존 테스트로 유지되는지 확인한다.

```tsx
expect(screen.getByRole('tree', { name: '공통코드 그룹 트리' })).toBeVisible();
expect(screen.getByRole('grid', { name: '공통코드 상세코드' })).toBeVisible();
expect(screen.queryByRole('menuitem', { name: '루트 추가' })).not.toBeInTheDocument();
expect(screen.queryByRole('menuitem', { name: '행 추가' })).not.toBeInTheDocument();
expect(screen.getByRole('button', { name: '조회' })).toBeDisabled();
expect(screen.queryByTestId('f1-grid-loading-overlay')).not.toBeInTheDocument();
```

- [ ] **Step 3: 저장 상태를 패널에 전달해 변경 진입점을 잠금**

`CommonCodeManagementPage`의 기존 `saving` 상태를 패널 prop으로 전달한다. `CommonCodeManagementPanel`은 저장 중 그룹 트리와 상세 Grid의 편집 가능 컬럼, 추가/삭제 메뉴, 그룹 선택, 셀/행 변경 콜백을 비활성화한다. 패널의 `loading`은 `groupsLoading`/`itemLoading` 그대로 유지해 저장 후 조용한 재조회에 오버레이가 생기지 않게 한다.

```tsx
saving={saving}
```

```tsx
allowAddRootInContextMenu={!saving}
allowAddRowInContextMenu={!saving}
allowDeleteRowInContextMenu={!saving}
```

컬럼 `editable` 및 선택/추가 핸들러도 `saving` 조건을 포함하고, 현재 그룹 및 dirty 데이터의 기존 선택·오류 처리 정책은 바꾸지 않는다.
