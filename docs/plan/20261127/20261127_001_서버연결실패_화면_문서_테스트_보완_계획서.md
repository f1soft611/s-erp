# 서버 연결 실패 화면 문서·테스트 보완 계획서

- 작성일: 2026-11-27
- 작업지시서: [서버 연결 실패 화면 문서·테스트 보완](../../directions/20261127/20261127_001_서버연결실패_화면_문서_테스트_보완_작업지시서.md)

## 현황

- 공통 규칙은 `frontend/AGENTS.md` "서버 연결 실패 화면 (모든 페이지 공통)"에 있다.
- 기존 테스트 `tests/page-load-boundary.test.tsx`는 `useInitialLoadState`의 기본 동작과 `PageLoadBoundary` 문구만 다룬다. `networkOnly`, `toPageLoadError`, 정책 `network` 플래그, 영업 화면별 적용은 테스트가 없다.
- `tests/page-initial-errors.test.tsx`는 `DashboardContent`로 화면을 렌더링하고 `apiClient`를 mock해 초기 실패를 검증한다. 영업은 수주현황(`status`)만 포함한다.

## 구현 단위

1. 공통 단위 테스트를 `tests/page-load-boundary.test.tsx`에 추가한다.
   - `toPageLoadError` 분류, `isApiNetworkError`, `networkOnly`의 network/500/401 처리
   - `SalesDecimalPolicyError`가 `network`일 때 표시하지 않음
2. 정책 조회 실패의 `network` 플래그 테스트를 `tests/grid-decimal-policy.test.tsx`에 추가한다.
3. 영업 10개 화면 테스트를 새 파일 `tests/sales-page-network-failure.test.tsx`로 만든다.
   - `page-initial-errors`와 같은 방식(`DashboardContent`, `apiClient` mock)으로 모든 GET을 `ApiNetworkError`로 실패시킨다.
   - 화면별로 단일 오류 화면, 헤더 유지, 다른 오류 문구 없음, 다시 시도 시 재조회를 확인한다.
   - `networkOnly` 화면 하나에서 500 오류가 페이지 오류 화면이 되지 않음을 확인한다.
4. 변형 확인: `networkOnly` 분기, `SalesDecimalPolicyError`의 `network` 분기를 일시로 되돌려 테스트 실패를 확인하고 원복한다.
5. 로컬 실행: 추가·변경 테스트 파일, `npm run build`.
6. 결과 문서 `docs/result/20261127/server-connection-failure-docs-tests`를 작성한다.

## 영향 범위

테스트 파일과 문서만 추가·변경한다. 운영 코드·API·DB 변경은 없다. 화면 변경이 없어 스크린샷은 대상이 아니다.
