# 영업 저장 성공 토스트 계획서

- 작성일: 2026-11-27
- 작업지시서: [영업 저장 성공 토스트](../../directions/20261127/20261127_003_영업_수정창_저장성공_토스트_작업지시서.md)

## 현황

- 공통 토스트: `shared/context/NotificationContext.tsx`(`App.tsx`에서 앱 전체를 감쌈), `useNotification().showSuccess(message)` → 우측 하단 Snackbar 4초. 기준정보·그룹웨어·인사·환경설정과 영업 납품처관리가 이미 사용한다(22개 파일).
- 영업 등록·현황 7개 화면은 `const [notice, setNotice] = useState('')`와 `<Alert severity="success">{notice}</Alert>`로 성공 문구를 화면 안에 표시한다.
- 수정 창 4개는 등록 화면을 `embedded`로 넣고 성공 시 `onSaved`/`onDeleted`로 창을 닫는다.

## 방식

각 화면에서 `notice` 상태와 성공 `Alert`을 없애고 성공 시 `showSuccess(기존 문구)`를 호출한다. 실패 처리(`setError`)는 바꾸지 않는다. 처음에는 수정 창(`embedded`)만 토스트로 보내는 분기 훅을 만들었으나, 범위가 "영업 전체"로 정해져 분기가 필요 없어져 제거했다.

## 구현 단위

1. 7개 화면: `notice` 상태 → `useNotification()`, `setNotice(문구)` → `showSuccess(문구)`, `setNotice('')`와 성공 `Alert` 제거, `useCallback` 의존성에 `showSuccess` 추가.
2. 테스트
   - 신규(먼저 작성·실패 확인): 견적·수주 수정 창을 현황 화면처럼 렌더링해 저장·삭제 성공 시 창이 닫히고 토스트가 남는지, 저장 실패 시 창 안 오류만 보이는지.
   - 갱신: 화면 안 성공 문구를 기대하던 기존 테스트 9건을 토스트 기준으로 바꾼다(견적·수주는 실제 `NotificationProvider`, 출하계획·매출마감은 `useNotification` spy).
3. `frontend/AGENTS.md`에 "성공·실패 메시지 표시 위치" 규칙을 추가한다.
4. 로컬 브라우저: 견적·수주 수정 창 저장 → 토스트 캡처 → 원복.
5. 결과 문서 `docs/result/20261127/sales-editor-save-toast`.
