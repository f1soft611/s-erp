# 20261007_006 문서작성 결재 표/합의 칩 배치 계획서

## 목표

문서작성 모달의 결재 그리드를 실제 콘텐츠 너비에 맞는 빈 슬롯으로 채우고, 참여자 없는 합의 행은 숨기며, 승인/합의 참여자를 기존 순서에 따라 하나의 컴팩트한 전역 순번으로 표시한다.

## 변경 범위

- `frontend/src/pages/groupware/documents/write/components/DocumentApprovalFields.tsx`: 결재 입력행, wrap 가능한 결재 표, 합의 사용자별 칩, 기존 참조 선택행을 렌더링한다.
- `frontend/src/pages/groupware/documents/write/hooks/useDocumentComposer.ts`: 참여자 한 명만 제거하고 합의 그룹이 비면 해당 단계를 제거한다.
- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`: 새 참여자 제거 콜백과 전체 참여자 기준 다음 결재 입력 번호를 전달한다.
- `frontend/tests/document-write-page.test.tsx`: 행 순서, 표/칩 내용, 사용자별 제거/후보 복원, 전역 번호, wrap 스타일 및 참조 동작을 검증한다.
- 날짜별 작업지시서, 계획서, 사양서 및 결과보고서와 합성 이름만 사용하는 개인정보 안전 반응형 캡처를 갱신한다.

## 실행 순서

1. 요구사항과 상세 사양서의 행 순서, 너비 측정, 슬롯 용량, 참여자 표시 및 삭제 기준을 함께 확인한다.
2. 그리드 콘텐츠 너비를 `ResizeObserver`로 측정해 `max(1, floor((contentWidth + 4) / 84))` 슬롯을 첫 행에 두고, 참여자 수가 더 많으면 뒤 행에 배치한다.
3. 빈 슬롯에는 낮은 강조의 도장 영역만 두고, 실제 결재 참여자는 직위/도장, 작은 소프트 블루 전역 원형 배지, 3자 안팎 말줄임 이름 및 사용자별 삭제를 표시한다. 전체 이름은 접근 가능 정보와 title/tooltip로 유지한다.
4. 합의 인원이 있을 때만 연회색 칩 행을 표시한다. 각 칩에는 전역 배지, 말줄임 이름, 도장 자리, 개별 삭제를 두며 아바타/단계 종류 문구는 두지 않는다.
5. 기존 stage/user 순서 기반 전역 순번, 삭제 후 후보 복원/재번호, 마지막 합의 인원 삭제 시 빈 단계 제거, 독립적인 참조 선택을 검증한다.
6. 테스트, lint, 빌드 및 375px/768px/1280px 브라우저 확인을 수행한다. 화면 캡처는 합성 이름만 사용한다.
