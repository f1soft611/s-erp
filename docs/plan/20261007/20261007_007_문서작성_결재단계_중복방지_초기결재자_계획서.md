# 문서작성 결재 단계·중복 방지·초기 결재자 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 문서작성 모달에 로그인 사용자 고정 1번 결재자, 결재/합의/참조 중복 방지, 단계 기준 공유 순번 및 요청된 표시 변경을 적용한다.

**Architecture:** `useDocumentComposer`가 현재 사용자 식별, 고정 결재 단계와 역할 간 선택 가능성을 관리한다. `DocumentApprovalFields`는 단계 순서로 표시 번호를 계산하고 결재 및 합의 참여자를 렌더링한다. 기존 API, 선택기와 작성 모달 외부 동작은 유지한다.

**Tech Stack:** React, TypeScript, MUI, Vitest, React Testing Library, Vite

- [ ] **Step 2a: 확인된 기존 편집기 높이 기대값을 현재 구현에 정렬**

  기준 실행에서 별도로 실패한 `lets the dialog content scroll while the editor surface grows naturally`의 `document-composer-editor-panel` 검증은 현재 구현의 `minHeight: 200`과 테스트의 `minHeight: 180`이 불일치한다. 런타임 스타일은 변경하지 않고 해당 테스트 기대값을 `200px`으로 수정한 뒤, 기준 테스트 파일을 실행해 이 한 건이 더 이상 실패하지 않는지 확인한다.

- [ ] **Step 3: 타입과 hook에 프로필 기반 보호 첫 단계를 추가**

  `DocumentApprovalStage`에 선택적인 고정 표시를 추가한다. 프로필과 사용자 옵션을 로드한 뒤 정확한 `userId` 일치 사용자가 있으면 해당 옵션을 쓰고, 없으면 프로필의 `userId`, 이름, 프로필 이미지, 직급, 부서로 고정 결재 표시 옵션을 생성한다. 프로필 이름 또는 사용자 ID 자체가 없으면 기존 `loadError`에 구체적인 메시지를 표시하고 불완전한 단계를 만들지 않는다. fallback 사용자는 선택 후보 목록에 추가하지 않는다. `removeApprovalUser`는 고정 단계를 제거하지 않는다.

- [ ] **Step 4: 역할 간 중복 방지를 양방향으로 구현**

  결재 후보는 기배정 결재/합의, 참조 선택, 현재 참조와 충돌하는 ID를 제외한다. 참조 후보는 기배정 결재/합의와 아직 확정되지 않은 결재 선택 ID를 제외한다. `handleApprovalUserChange`, `handleReferenceUserChange`, `addApproval`, `addAgreement`에서도 현재 허용 후보로 입력을 제한해 오래된 선택 상태가 중복 확정되지 않도록 한다. 삭제된 비고정 참가자는 두 선택기에서 다시 후보가 되어야 한다.

- [ ] **Step 5: 단계 단위 순번 테스트 추가 후 실패 확인**

  고정 기안자를 1번으로 둔 뒤 합의 사용자 2명을 한 번에 추가하고 후속 결재자 2명을 추가한다. 두 합의칩이 2를 공유하고 다음 결재 순번이 3, 4인지 확인한다. 5번째 synthetic user를 fixture에 추가한다. 이 테스트는 참여자 수가 아닌 `approvalStages` 단계 위치로 번호를 산출하는지 검증한다.

  ```tsx
  expect(agreementChips).toHaveLength(2);
  expect(agreementChips[0]).toHaveTextContent('2');
  expect(agreementChips[1]).toHaveTextContent('2');
  expect(approvalPeople.map((person) => person.getAttribute('aria-label'))).toEqual([
    '결재 1 홍길동',
    '결재 3 이수진',
    '결재 4 최민호',
  ]);
  ```

- [ ] **Step 6: 결재/합의 표시 번호를 stage index로 구현**

  stage를 순회할 때 해당 단계의 표시 번호를 `stageIndex + 1`로 계산하고, 그 stage 안의 각 사용자는 같은 번호를 받도록 한다. 결재 stage는 기존처럼 한 명씩 생성하므로 각각 다른 순번을 가진다. 다음 선택기 레이블의 번호도 전체 단계 수에 1을 더한다.

- [ ] **Step 7: 초기화, 누락 ID 오류, 역할 중복 및 순번 테스트 통과 확인**
