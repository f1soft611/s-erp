# 20261007_010 문서작성 기안자 식별 및 호버 삭제 계획서

## 목표

인증 프로필에 내부 사용자 키를 추가해 결재 후보 식별자와 같은 기준으로 로그인 기안자를 제외하고, 비고정 결재자/합의자에 접근 가능한 호버형 X 삭제 동작을 제공한다.

## 설계 요약

- 프로필 응답의 기존 `userId`는 `login_code`로 보존한다.
- 인증된 프로필에 `employeeId`를 추가해 현재 사용자의 `tb_user.user_id`를 반환한다.
- 문서작성 훅은 `employeeId`와 후보 옵션 `userId`를 trim 후 문자열로 비교한다.
- 결재 카드 상단 직위 우측 및 합의 항목에 X 버튼을 배치한다. 호버 가능한 환경에서는 기본 비표시 후 hover/focus에서 노출하고, 터치 전용 환경에서는 항상 노출한다.
- 고정 기안자 삭제 불가와 기존 단계별 삭제/후보 복원 규칙을 보존한다.
- DB 컬럼 변경이 없으므로 마이그레이션은 없다.

## 작업 단계

1. 현재 프로필/사용자 옵션의 ID 계약을 테스트로 고정한다.
2. 백엔드 프로필 응답에 `employeeId`를 추가하고 기존 `userId` 불변을 검증한다.
3. 프론트엔드 프로필 타입과 문서작성 초기 결재자 식별을 갱신한다.
4. 동일 ID 기안자 제외, 동명이인 유지, employeeId 누락 오류를 검증한다.
5. 비고정 결재/합의 호버 삭제, X 아이콘 위치, 접근성 이름, 터치 표시, 삭제 후 복원/순번을 검증한다.
6. 집중 테스트, lint, build, 반응형 브라우저 확인을 진행한다.
7. 결과 보고서와 개인정보를 흐리게 처리한 375px·768px·1280px 스크린샷을 갱신한다.

## 영향 범위

- Backend: `MyProfileVO`, `EgovLoginUsr_SQL_postgresql.xml`, `ProfileSettingsApiController`, 컨트롤러 테스트
- Frontend: `profileSettings.ts`, `useDocumentComposer.ts`, `DocumentApprovalFields.tsx`, 문서작성/프로필 테스트
- Documents: 본 지시서의 날짜별 사양서 및 결과물
