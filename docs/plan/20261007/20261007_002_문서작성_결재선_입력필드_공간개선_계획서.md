# 20261007_002 문서작성 결재선 입력 필드 공간 개선 계획서

## 목표

결재 입력을 번호 순서의 가로 흐름으로 구성해 세로 공간을 줄이고, 다중 선택을 결재/합의 역할에 맞게 확정하면서 다음 입력을 연속 제공한다.

## 근거

- 작업지시서: [20261007_002 문서작성 결재선 입력 필드 공간 개선](../../directions/20261007/20261007_002_문서작성_결재선_입력필드_공간개선_작업지시서.md)
- 승인 설계: [Document Write Approval Selector Fields Design](../../superpowers/specs/2026-10-07-document-write-approval-selector-fields-design.md)
- 이전 개선 사양: [20261007_001 결재선 및 에디터 사용성 개선](../../spec/20261007/20261007_001_문서작성_결재선_에디터_사용성_개선_사양서.md)

## 변경 범위

- `DocumentApprovalFields`: 단계별 읽기 전용 선택 칩 필드, 마지막 활성 다중 선택 필드, 활성 필드 전용 결재/합의 버튼, 결재선 내부 가로 스크롤.
- `UserSelectEditor`: 기존 `readOnly` prop이 칩 삭제 액션까지 막도록 보완하며 기본 편집 가능 동작을 보존한다.
- `useDocumentComposer`: 기존 `approvalStages`와 선택 사용자 상태 및 결재/합의 확정 로직을 유지하고 UI가 요구하는 순번/후보 계약을 검증한다. 필요한 상태 변경은 테스트 증거가 있을 때만 추가한다.
- `document-write-page.test.tsx`: 순차 필드 추가, 결재 사용자별 단계, 합의 그룹, 삭제/후보 복원, 역할 버튼, 참조선 독립성 및 가로 스크롤 회귀 검증.
- `referenceUserIds`의 다중 선택 동작은 재사용하고 의미를 바꾸지 않는다.

## 실행 순서

1. 사용자 선택기 read-only 칩 삭제 방지 및 문서작성 활성 입력의 번호 지정/다음 입력 생성 테스트를 먼저 추가한다.
2. 실패를 확인한 뒤 `DocumentApprovalFields`의 결재 입력을 확정 단계 + 활성 입력 구조로 바꾼다.
3. 다중 결재와 다중 합의의 확정/후보 제외/삭제 복원을 기존 composer 상태에 연결한다.
4. 참조 입력, 에디터의 자연 높이 및 `CommonDialog` 세로 스크롤이 유지되는지 확인한다.
5. 지정 테스트, 변경 대상 lint, 프론트엔드 빌드를 실행한다.
6. 브라우저에서 375px, 768px, 1280px 렌더링을 확인하고 캡처 및 결과 문서를 작성한다.

## 검증 명령

```powershell
Set-Location frontend
npm run test -- tests/document-write-page.test.tsx tests/user-select-editor.test.tsx
npm run lint -- src/pages/groupware/documents/write/components/DocumentApprovalFields.tsx src/pages/groupware/documents/write/hooks/useDocumentComposer.ts src/shared/components/f1-grid/editing/UserSelectEditor.tsx tests/document-write-page.test.tsx tests/user-select-editor.test.tsx
npm run build
```

브라우저에서 결재선의 가로 스크롤이 결재선 영역에만 생기고 375px 문서 너비가 뷰포트보다 넓어지지 않는지 확인한다. 긴 본문 입력 후 모달 콘텐츠의 세로 스크롤과 고정 헤더/푸터 접근성도 회귀 확인한다.

## 제외 범위

결재/합의 저장 또는 상신, 서버 API와 응답 계약, 권한, 라우팅, DB 변경, 참조선 중복 제한, 공통 에디터/다이얼로그 구현 변경은 포함하지 않는다.
