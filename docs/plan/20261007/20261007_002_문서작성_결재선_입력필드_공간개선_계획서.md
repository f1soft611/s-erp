# 20261007_002 문서작성 결재선 입력 필드 공간 개선 계획서

## 목표

결재선과 참조선을 왼쪽 라벨이 있는 두 행으로 정렬하고, 확정된 결재 단계는 프로필·사용자 정보·도장이 한 묶음인 카드로 표시한다.

## 변경 범위

- `DocumentApprovalFields`: 왼쪽 라벨과 오른쪽 콘텐츠를 두 행으로 구성하고, 순번/구분/프로필/이름/부서/도장/단계 삭제가 있는 결재 카드 및 활성 선택 입력을 표시한다. 카드/버튼/선택 필드 높이를 맞추고 가로 스크롤은 결재선 콘텐츠에만 적용한다. 빈 후보 안내는 표시하지 않는다.
- `DocumentComposerDialog`: 본문 에디터가 모달 내 남은 높이를 채우고, 양식 본문의 첫/마지막 블록 바깥 여백을 정리해 에디터 상·하단 공백을 맞춘다. 긴 본문 스크롤은 모달 본문이 담당한다.
- `CommonDialog`/`DocumentComposerDialog`: 선택적 표면 배경색 API를 추가하되 문서작성 모달에만 흰색을 지정한다. 그 외 공통 모달은 기존 배경을 유지한다.
- `UserSelectEditor`: 활성 결재 사용자와 참조 사용자 선택에 재사용한다. 확정 결재자는 공통 선택기 칩이 아니라 카드의 프로필/텍스트로 렌더링한다.
- `useDocumentComposer`: 기존 `approvalStages`, 선택 사용자 상태 및 결재/합의 확정/단계 제거 로직을 유지한다. 상태 모델/API를 변경하지 않는다.
- `document-write-page.test.tsx`: 행 순서와 라벨, 결재자 카드 메타데이터, 결재 사용자별 단계, 합의 그룹, 단계 전체 삭제/후보 복원, 참조선 독립성 및 스크롤을 검증한다.
- `UserSelectEditor`의 기존 필터, 순서 보존, 기본 칩 제거 회귀 동작을 유지한다.

## 실행 순서

1. 새 두 행 배치와 결재자 카드/그룹 삭제 동작의 회귀 테스트를 먼저 추가하고 현재 화면에서 실패하는지 확인한다.
2. `DocumentApprovalFields`를 좌측 라벨/우측 콘텐츠의 결재 행과 참조 행으로 바꾸고 확정 결재 단계를 카드로 표시한다.
3. 기존 선택·확정·제거 콜백을 재사용하여 결재별 카드와 합의 그룹 카드를 표시하고 단계 전체 삭제 및 순번 갱신을 확인한다.
4. 불필요해진 공통 선택기의 read-only 칩 삭제 변경만 원복하고, 필터·선택 순서 및 기본 칩 제거 동작은 유지한다.
5. 기존 지시서·계획서·사양서 및 결과 문서에서 이전 선택기 상자 레이아웃을 폐기 상태로 명시하고, 새 UI 결과/캡처에 에디터 남은 높이 채우기와 양식 가장자리 공백 검증을 기록한다.
6. 지정 테스트, 변경 대상 lint, 프론트엔드 빌드를 실행한다.
7. 브라우저에서 375px, 768px, 1280px 렌더링, 카드/필드/버튼 높이, 흰 배경, 단계 전체 삭제 및 본문 스크롤을 확인하고 캡처 및 결과 문서를 작성한다.

## 검증 명령

```powershell
Set-Location frontend
npm run test -- tests/document-write-page.test.tsx tests/user-select-editor.test.tsx
npm run lint -- src/pages/groupware/documents/write/components/DocumentApprovalFields.tsx src/pages/groupware/documents/write/hooks/useDocumentComposer.ts src/shared/components/f1-grid/editing/UserSelectEditor.tsx tests/document-write-page.test.tsx tests/user-select-editor.test.tsx
npm run build
```

브라우저에서 결재선/참조 라벨과 입력 정렬, 확정 카드의 프로필/이름/부서/도장/삭제, 카드/필드/버튼 높이, 문서작성 모달 전체의 흰 배경, 결재선 콘텐츠의 내부 가로 스크롤 및 전체 페이지 폭을 확인한다. 모달 오픈 직후 에디터가 남은 높이를 채우는지, 긴 양식 본문이 확장되어 모달 콘텐츠가 스크롤되는지, 에디터 상·하단 공백과 고정 헤더/푸터 접근성이 유지되는지도 확인한다.

## 제외 범위

결재/합의 저장 또는 상신, 서버 API와 응답 계약, 권한, 라우팅, DB 변경, 참조선 중복 제한, 공통 모달의 기본 테마 동작 변경은 포함하지 않는다. 공통 다이얼로그의 선택적 배경색 속성은 문서작성 모달의 흰 표면 요구에 한해 사용한다.
