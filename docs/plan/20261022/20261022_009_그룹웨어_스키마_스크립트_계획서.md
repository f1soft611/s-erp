## 작업 목표

공유 기반 테이블이 준비된 신규 환경에서 그룹웨어 테이블을 생성하고, 그룹웨어 공통코드 카탈로그를 활성 테넌트별로 중복 없이 시드할 수 있는 PostgreSQL 기준 스크립트를 제공한다. 스크립트는 기존 운영 DB에 실행하지 않는다.

## 구현 단위

1. PostgreSQL MCP에서 그룹웨어 13개 테이블의 컬럼·제약·인덱스, 공통코드 그룹/항목을 확인하고 기존 DDL/변경 이력과 대조한다.
2. `20261022_009_create_groupware_schema.sql`에 커뮤니티 4개, 기안 분류 3개, 전자결재 6개 테이블을 의존성 순서대로 만든다. 공유 스키마를 다시 생성하지 않는다.
3. `20261022_009_seed_groupware_common_codes.sql`에 5개 그룹과 23개 항목을 `tb_tenant.use_at = 'Y'`인 모든 테넌트에 시드한다. 그룹과 항목의 기존 유니크 키를 기준으로 `ON CONFLICT DO NOTHING`을 사용한다.
4. `20261022_009_rollback_groupware_schema.sql`은 테이블 FK 의존성의 역순으로 그룹웨어 13개 테이블만 제거한다.
5. 동일 번호 변경 이력과 3개 SQL을 `backend/DATABASE/20261022` 및 `docs/database/20261022`에 동일하게 보관한다.
6. `docs/database/db-schema.md`의 그룹웨어 구간을 현재 확인한 기준선과 대조한다. 동시 고객코드 변경을 보존하고 그룹웨어 구간 외에는 수정하지 않는다.
7. 정적 SQL 조건, 롤백 순서, 시드 충돌 조건, 사본 해시를 확인하고 결과 문서에 DB MCP 및 빌드 기준선 실패를 기록한다.

## 검증 기준

- DDL은 각 대상 테이블을 한 번씩 정의하고, FK 대상은 그룹웨어 DDL 또는 명시된 공유 기반 테이블이어야 한다.
- 공통코드 시드는 5개 그룹/23개 항목을 포함하고, 어떤 tenant 데이터 행이나 자유서술 설명값도 복사하지 않는다.
- 롤백은 DDL 대상 13개 테이블만 FK 역순으로 제거하며 공유 테이블을 대상으로 하지 않는다.
- `backend/DATABASE`와 `docs/database`의 같은 번호 SQL/이력 파일은 SHA-256 해시가 동일하다.
- `git diff --check`가 통과한다.
- 현재 DB는 읽기 전용 메타데이터 확인만 하며 스크립트를 실행하지 않는다.

## 검증 시 유의사항

기준 `mvn -f backend\\pom.xml test`는 동시 고객관리 작업의 미추적 테스트가 아직 없는 production 클래스를 참조하여 testCompile 단계에서 실패했다. 해당 작업은 수정하지 않고 실패 상태를 결과 문서에 기록한다. 이 작업은 Java 및 화면 코드를 변경하지 않는다.
