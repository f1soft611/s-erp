# 그룹웨어 프로필 이미지 표시 계획서

## 목표

문서·공지의 기존 사용자 프로필 표시 위치에서 저장된 프로필 이미지를 표시하고, 이미지가 없거나 로드되지 않으면 기존 이름/이니셜 fallback을 유지한다.

## 구현 단위

1. 읽기 전용 DB MCP를 사용해 nullable `tb_login_account.profile_image`, 각 관련 테이블의 tenant 키, `login_code` 매핑을 확인했다. 로그인 사용자 ID는 `login_code`이며 글/댓글/기안자 응답의 nullable 이미지는 같은 tenant의 계정 row와 LEFT JOIN한다. 신규 테이블/컬럼은 만들지 않는다.
2. 백엔드의 공지 작성자, 공통 댓글 작성자, 전자결재 기안자 응답에 nullable 프로필 이미지 필드를 추가한다. 목록·상세·댓글 페이징·댓글 생성 후 재조회 및 전자결재 피드 조립을 포함하여 실제 표시되는 모든 읽기 경로를 확인하고, 기존 행을 보존하는 tenant 범위 LEFT JOIN을 적용한다.
3. `ProfileAvatar` 공통 컴포넌트를 추가하고 제공된 image URL이 있으면 사진, 없거나 실패하면 caller가 제공한 현재 fallback을 표시한다.
4. 공지 작성자·댓글, 문서 기안자·댓글·결재 참여자의 타입/어댑터/화면을 연결한다. 이미 이미지 표시를 지원하는 문서 사용자 선택기는 기존 동작을 유지한다.
5. 컴포넌트 단위 및 화면 회귀 테스트를 먼저 작성한 뒤 구현하고, 백엔드 매퍼 및 API 응답 테스트를 갱신한다.
6. 프론트 집중 테스트와 build, 백엔드 집중 테스트를 실행한다. 브라우저에서 375px, 768px, 1280px를 확인하고 개인정보가 없는 캡처와 결과 문서를 작성한다.

## 완료 조건

- 설계 범위의 작성자·댓글 작성자·결재 참여자가 이미지가 있을 때 사진을 표시한다.
- 누락/로드 실패 시 기존 화면의 이름/이니셜 fallback과 치수·접근성·상호작용이 보존된다.
- 읽기 API 응답에서 프로필 이미지 필드는 선택적이며 nullable이고, tenant 분리 및 기존 결과 행 보존이 테스트된다.
- 프론트 집중 테스트/build, 백엔드 집중 테스트, 세 뷰포트 브라우저 확인 및 결과 문서가 완료된다.
