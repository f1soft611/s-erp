# 20261022_006 공지사항 피드·리스트 페이징 계획서

## 목표

공지사항 피드형과 리스트형에서 일반 공지를 20건씩 이어 불러오고, 상단 고정 공지는 별도 조회로 전체 표시한다. 문서작성 페이지의 공통 페이징 흐름과 같은 사용자 동작을 제공하면서 공지사항 기존 API 및 기능을 유지한다.

## 변경 범위

### 프론트엔드

- `frontend/src/pages/groupware/community/notice/hooks/useNoticeList.ts`
  - 일반 목록 20건 첫 페이지와 추가 페이지 상태를 관리한다.
  - 기존 API의 `isPinned='N'` 조건으로 고정 공지를 일반 목록에서 제외한다.
  - 별도 고정 조회는 기존 pinned 필터 API를 사용해 `resultCnt`까지 페이지 단위로 수집한다.
  - 현재 필터/재조회 generation 및 요청 중 페이지를 추적해 stale 응답과 중복 요청을 차단한다.
  - 실패 페이지 재시도와 명시적 오류 상태를 제공한다.
- `frontend/src/pages/groupware/community/notice/CommunityNoticePage.tsx`
  - 스크롤 컨테이너를 공유 페이징 root로 전달한다.
  - 피드와 리스트에 동일한 `hasNext`, `isLoadingMore`, 오류, load/retry 콜백을 연결한다.
- `frontend/src/pages/groupware/community/notice/components/NoticeFeedList.tsx`
  - 별도 `IntersectionObserver` 및 종료 sentinel을 제거한다.
  - `FeedView`에 공통 pagination 옵션을 전달한다.
- `frontend/src/shared/components/view-mode/ViewModePagination.tsx`, `FeedView.tsx`, `ListView.tsx`
  - 기존 동작과 문서 화면 기본 로딩 레이블은 유지한다.
  - 호출부가 필요한 접근성 로딩 레이블을 지정할 수 있게 한다.

### 테스트

- `frontend/tests/use-notice-list.test.tsx`: 첫 페이지, 다음 페이지, 전체 고정 결과, 실패/재시도, 중복 방지, stale 응답을 검증한다.
- `frontend/tests/notice-page-local-updates.test.tsx`: 일반/고정 필터 인자, pin/unpin 이후 분리 재조회, 보기별 pagination 연결을 검증한다.
- `frontend/tests/notice-page.test.tsx`: 리스트/피드 렌더와 기존 선택 흐름을 회귀 검증한다.
- `frontend/tests/common-view-mode.test.tsx`: 기본 레이블 유지 및 사용자 지정 로딩 레이블을 검증한다.

## 구현 순서

1. 작업지시서 및 본 계획서에 근거해 상세 사양을 작성한다.
2. 관련 Vitest 파일에 실패 테스트를 먼저 추가하고 선택 테스트가 기대대로 실패하는지 확인한다.
3. hook의 고정 전체 페이지 수집과 일반 목록 페이지 추가/재시도/요청 세대 보호를 구현한다.
4. 공통 페이징 컴포넌트의 선택 레이블을 추가하고 NoticeFeedList, CommunityNoticePage의 피드/리스트 양쪽에 연결한다.
5. 집중 테스트와 `npm run build`를 실행한다.
6. 실제 브라우저에서 375px, 768px, 1280px를 확인하고 스크린샷 및 결과 보고서를 작성한다.

## API 및 데이터 범위

- 일반 목록: `fetchNoticePosts(page, 20, '', category || undefined, 'N')`
- 고정 목록: `fetchPinnedNoticePosts(page, 20, '', category || undefined)`를 사용하고 전체 결과 수집이 끝난 뒤 표시한다.
- 댓글, 상세, 수정/삭제, 고정 변경 API, 백엔드 컨트롤러/서비스/매퍼 및 DB는 변경하지 않는다.
- 사용자 프로필 이미지 등 현재 워크트리의 기존 변경은 보존하고 이 작업과 무관한 수정은 추가하지 않는다.

## 완료 기준

- 피드와 리스트 모두 20건 단위로 추가 페이지를 불러오며 로딩/실패/재시도가 일관된다.
- 상단 고정 공지가 카테고리 필터에 따라 전체 수집되고 일반 결과에서 중복되지 않는다.
- 필터/재조회 이후 오래된 응답과 중복 호출이 새 목록을 오염시키지 않는다.
- 공지 및 공유 컴포넌트 테스트, 빌드, 실제 브라우저 확인과 결과 기록이 완료된다.
