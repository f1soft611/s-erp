## 영향 파일

- `frontend/src/pages/groupware/documents/write/components/DocumentApprovalSettingsDialog.tsx`: 요약 목록 조회, 선택, 오류/로딩, 관리 모달 종료 후 갱신, footer 저장 시작 버튼 배치
- `frontend/tests/document-approval-settings-dialog.test.tsx`: select 흐름과 footer 배치 회귀 검증
- `docs/result/20261015/document-approval-line-favorites/20261015_002_업무작성_자주쓰는결재선_결과보고서.md`: 후속 변경 및 검증 기록
- 결과 경로의 화면 캡처: 375px, 768px, 1280px

`CommonDialog.footerStart`와 기존 템플릿 서비스/API를 재사용하므로 공통 다이얼로그, API 서비스, F1-Grid 구현, 백엔드 및 DB는 변경하지 않는다. F1-Grid 사용자 가이드는 Grid 동작이 바뀌지 않으므로 변경하지 않는다.

## 구현 순서

1. 상세 사양의 성공/실패/빈 목록/관리 모달/저장 흐름을 테스트 케이스로 구체화한다.
2. 설정 창을 렌더링하면 현재 `documentCode`의 템플릿 목록을 조회하고, select 선택 성공 시 상세 결재선을 임시 상태에 적용하는 실패 테스트를 추가한다.
3. 상세 조회 실패 시 현재 임시 상태 보존, 선택 유지, 오류 표시를 테스트한다. 목록 조회 실패와 재시도도 검증한다.
4. F1-Grid 관리 모달에서 돌아온 뒤 목록을 다시 불러와 이름 변경/추가/삭제를 반영하되 임시 결재선은 유지하는 테스트를 추가한다.
5. 본문에서 저장 시작 버튼이 사라지고 footer 시작 영역에 표시되는지, 기존 저장 모달 및 생성 후 새 항목 선택이 유지되는지 테스트한다.
6. `DocumentApprovalSettingsDialog.tsx`에서 상태/목록 조회와 선택 동작을 구현하고 `CommonDialog.footerStart`로 기존 저장 시작 버튼을 이동한다.
7. 관련 테스트를 통과시키고 기존 관리 Grid 동작과 결재선 `적용`/`취소` 경계를 회귀 확인한다.
8. 결과 보고서를 갱신하고 합성 데이터로 반응형 브라우저 캡처를 만든다.

## 검증 명령

```powershell
cd frontend
npx vitest run --testTimeout=15000 tests/document-approval-settings-dialog.test.tsx tests/approval-line-template-service.test.ts
npm run build
```

추가로 지정 파일 진단, 375px/768px/1280px 브라우저 확인 및 `git diff --check`를 실행한다. 기존 공유 작업공간의 무관한 변경은 보존한다.
