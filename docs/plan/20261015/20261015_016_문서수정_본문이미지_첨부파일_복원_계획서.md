# 20261015_016 문서 수정 본문 이미지·첨부파일 복원 계획서

## 목표

전자결재 문서의 `문서 수정` 및 `수정 후 재상신` 모달에서 기존 첨부파일을 복원하고, 기존 본문 이미지의 인증된 미리보기를 제공한다.

## 근거 문서

- 작업지시서: [20261015_016 작업지시서](../../directions/20261015/20261015_016_문서수정_본문이미지_첨부파일_복원_작업지시서.md)
- 문서 수정 진입 및 초기화: `DocumentApprovalDetailFeed`, `DocumentComposerDialog`, `useDocumentComposer`
- 참고 이미지 표시: `useDocumentApprovalBody`, 공지사항 `NoticeComposerDialog`
- 기존 첨부 삭제/이미지 조회: `documentApproval.service`

## 원인과 접근

- `initialDocument` 분기에서 제목·양식·결재선을 설정하지만 `attachments` 상태를 설정하지 않는다. 기존 상세 타입의 첨부 응답을 업로드 대상 `DocumentDraftAttachment`와 구분해 다루고, 유지 파일은 새로 업로드하지 않는다.
- 상세 화면은 HTML의 승인 이미지 URL에서 파일 ID를 읽고 `fetchApprovalEmbeddedImageBlob`을 호출한다. 수정 모달도 같은 승인 전용 서비스/API를 재사용하되, 편집 원본 HTML은 기존 서버 경로를 보존하고 렌더링에만 Blob URL을 사용한다.
- Blob URL 객체 수명은 모달/문서 변경 시 정리한다. Blob URL이 저장용 HTML/JSON으로 유출되지 않는지 회귀 테스트로 검증한다.

## 변경 범위

- `frontend/src/pages/groupware/documents/write/hooks/useDocumentComposer.ts`: 수정 문서의 기존 첨부 초기화 및 기존 본문 이미지의 인증된 로드/정리
- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`: 기존 파일명 표시 및 기존 파일 제거 액션
- `frontend/src/pages/groupware/documents/write/types/documentWrite.types.ts`: 기존 첨부 상태와 신규 File 기반 첨부 상태의 타입 표현(필요한 최소 범위)
- `frontend/tests/document-write-page.test.tsx`: 수정 모달의 이미지 Blob URL 복원, 기존 첨부 표시·유지·제거와 저장 회귀 검증
- `docs/result/20261015/document-edit-attachments-images/`: 구현 및 검증 결과, 가능한 스크린샷

## 실행 순서

1. 문서 수정 통합 테스트에 기존 첨부 및 보호된 본문 이미지 사례를 추가하고 기존 동작에서 실패함을 확인한다.
2. 기존 첨부 데이터를 수정 상태에 로드하고 기존 첨부와 신규 첨부를 타입으로 구분한다.
3. 승인 전용 이미지 Blob API로 편집기 표시를 복원하며, 저장 데이터에서는 원래 승인 이미지 주소와 메타데이터를 보존한다.
4. 대상 테스트 및 공통 문서작성 테스트를 실행한다.
5. 프론트엔드 빌드와 변경 파일 진단을 실행한다.
6. 가능한 경우 375px, 768px, 1280px에서 수정 모달을 확인하고 결과를 기록한다.

npm run build

## 완료 기준

- 실패 테스트가 추가된 뒤 코드 수정으로 통과한다.
- 기존 첨부를 보존하고 선택 제거만 반영하며, 신규 첨부 업로드 재시도는 그대로 동작한다.
- 본문 이미지 미리보기 Blob 로드 오류가 사용자에게 표시되고, 저장 콘텐츠에는 Blob URL이 포함되지 않는다.
- 대상 테스트와 빌드 결과, 브라우저 확인 또는 제한 사유가 결과 문서에 남는다.
