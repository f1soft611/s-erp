# 20261015_002 업무작성 자주 쓰는 결재선 계획서

## 목표

문서작성의 결재선 설정 창에서 로그인 사용자별 결재선 템플릿을 서버에 저장하고, 문서번호 코드 `001`(기안), `008`(업무), `004`(지출), `031`(근태)에 따라 조회·저장·수정·삭제한다.

## 적용 설계

- DB 마스터/상세 테이블과 전용 MyBatis DAO, service, controller를 추가한다.
- 인증 tenant/사용자 소유권을 모든 API 조회·변경에 적용한다.
- 결재/합의 단계, 참여자 순서, 참조자를 저장한다. 고정 기안자는 템플릿에서 제외한다.
- 불러온 값은 설정 창 임시 상태에만 적용하고, 기존 `적용`에서만 작성 상태에 반영한다.
- DB MCP에서 현재 PostgreSQL 테이블을 확인했다. `tb_electronic_approval_line_info`는 문서 ID와 결재 처리 상태에 종속되어 있어 템플릿 저장용으로 재사용하지 않는다.

## 구현 단계

1. 승인 설계와 이 계획을 구체화한 날짜별 상세 사양서를 작성하고 API, DB, 화면, 오류 및 검증 기준을 고정한다.
2. 새 테이블 DDL/롤백과 MyBatis 매퍼 계약 테스트를 작성하고 날짜별 스키마 관리 문서를 갱신한다.
3. 백엔드 템플릿 CRUD 및 인증 사용자·tenant·코드·참여자 검증을 테스트 우선 구현한다.
4. 프론트엔드 API 타입/서비스와 테스트를 추가한다.
5. 결재선 설정 창에 저장, 코드별 불러오기, 이름 수정, 삭제 및 확인 흐름을 연결하고 기존 적용/취소 동작을 검증한다.
6. 프론트엔드/백엔드 관련 테스트와 빌드, 실제 브라우저 375px/768px/1280px 검증 후 결과 문서와 스크린샷을 남긴다.

세부 파일 목록, 테스트 우선 순서, API 계약, 명령은 [상세 구현 계획](../../superpowers/plans/2026-10-15-document-approval-line-favorites.md)에 따른다.

## 완료 기준

- 코드별 템플릿 CRUD와 사용자/tenant 격리가 자동 테스트로 검증된다.
- 단계 및 참조 순서가 보존되고, 불러오기 후 적용/취소가 현재 결재선 설정 동작을 유지한다.
- 날짜별 SQL·변경 이력·롤백이 `docs/database` 및 `backend/DATABASE`에 동일하게 기록되고 `db-schema.md`가 최신화된다.
- 관련 테스트/빌드와 3개 뷰포트 브라우저 확인, 결과 문서/캡처가 완료된다.
