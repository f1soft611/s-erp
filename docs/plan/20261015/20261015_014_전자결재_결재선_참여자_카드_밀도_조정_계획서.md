# 20261015_014 전자결재 결재선 참여자 카드 밀도 조정 계획서

## 목표

합의·참조 카드가 남는 줄 너비를 균등하게 채우고 높이를 56px로 줄이며, 결재·합의·참조 참여자 이름과 합의·참조 부서/상태 텍스트를 14px로 정리한다.

## 변경 범위

- `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`: 읽기 전용 상세 결재선에 표시되는 결재/합의/참조 참여자 카드의 이름 typography 및 합의·참조 카드의 폭/높이/패딩/아바타/보조 텍스트 typography만 변경한다.
- `frontend/tests/document-write-page.test.tsx`: 기존 읽기 전용 상세 결재선 회귀 테스트에서 사용자명 글꼴, 합의·참조 카드 크기와 flex 값, 부서/상태 글꼴을 검증한다.
- 날짜별 작업지시서, 상세사양서, 결과 문서를 작성한다.

## 실행 순서

1. 작업지시서와 상세사양서에 사용자 승인 수치와 기존 동작 보존 기준을 명시한다.
2. 상세 문서 테스트에 공통 flex/geometry assertion, 14px typography assertion을 작성한다.
3. `frontend`에서 `.\node_modules\.bin\vitest.cmd run tests/document-write-page.test.tsx -t "read-only system events" --testTimeout 15000`를 실행해 기존 구현에서 신규 assertion이 실패하는지 확인한다.
4. 합의·참조 카드 flex를 `1 1 240px`, 외곽 높이를 `56px`, 아바타를 32px, padding을 `px: 1, py: 0.75`로 맞춘다. 결재/합의/참조 사용자명에 `fontSize: '0.875rem'`을 적용하고, 합의/참조의 부서 및 합의 상태 배지에는 14px와 18px line-height를 적용한다.
5. 동일한 집중 테스트를 재실행해 통과를 확인한다.
6. 대상 파일 Oxlint, `npm run build`, Problems, `git diff --check`를 수행한다.
7. 기존 공유 브라우저에서 375/768/1280px 폭을 확인하고, 가능한 경우 개인정보가 노출되지 않는 캡처를 결과 폴더에 저장한다.
8. 실제 검증 결과 및 브라우저/캡처 제한을 날짜별 결과 문서에 작성한다.

## 제외 범위

- 결재 카드의 너비·높이·아바타·배치 변경
- 승인 상태/처리 동작, 참여자 순서/데이터, 부서 fallback 변경
- 문서작성 편집 결재선, API, 서버, DB 변경
- 관련 없는 작업트리 변경 처리

## 완료 기준

- 승인된 flex/height/avatar/padding/type geometry가 테스트 assertion으로 검증된다.
- 변경 전 실패와 변경 후 통과가 동일한 집중 테스트에서 확인된다.
- build, lint/Problems 및 diff 결과가 기록된다.
- 브라우저 검증이 수행되거나 미수행 원인이 결과 문서에 정확히 기록된다.
