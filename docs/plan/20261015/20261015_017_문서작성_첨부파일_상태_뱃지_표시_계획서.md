## 파일 범위

- `frontend/src/shared/components/feed/AttachmentList.tsx`: 선택적 뱃지 슬롯을 파일명과 제거 아이콘 사이에 그린다.
- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`: 상태를 짧은 라벨/색상으로 매핑하고 뱃지 및 기존 보조 액션을 전달한다.
- `frontend/tests/document-write-page.test.tsx`: 상태별 렌더 및 액션 보존을 검사한다.
- `docs/result/20261015/document-attachment-status-badges/`: 결과 문서 및 브라우저 캡처(가능한 경우)를 보관한다.

## 실행 순서

1. 완료 상태 첨부 및 신규 대기 상태 첨부 테스트를 추가하고 현재 동작에서 실패함을 확인한다.
2. `AttachmentList`의 optional `statusBadge` 슬롯을 구현해 삭제 액션 직전에 렌더링한다.
3. 문서작성 파일 행에서 상태별 MUI `Chip`을 전달하고 박스 아래 상태 텍스트를 제거한다. 실패/unknown 보조 액션은 같은 행에 유지한다.
4. 테스트 파일의 실패/unknown 상태 테스트에서 뱃지와 보조 액션을 확인한다.
5. 관련 Vitest, build, Problems, `git diff --check`를 확인한다.
6. 인증된 브라우저 화면에 접근할 수 있으면 375/768/1280px 확인 후 결과를 남긴다. 접근 불가 시 사유를 기록한다.

## 검증 명령

`frontend`에서:

```powershell
npx vitest run tests/document-write-page.test.tsx -t "attachment|첨부"
npm run build
```
