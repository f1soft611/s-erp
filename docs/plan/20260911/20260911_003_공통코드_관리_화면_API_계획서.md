## 2. 요구사항 분석 및 목적

이번 작업은 S-ERP의 공통코드 관리 기능을 새로 구현하는 것으로, 기존 레거시 `TB_CommonCode`를 재사용하지 않고 테넌트 단위의 그룹/상세코드 구조를 새로 설계한다.

핵심 목표는 다음과 같다.

1. `/co/master/cmncodes` 경로에서 공통코드 관리 화면을 제공한다.
2. 좌측 F1Tree에서 그룹 계층(`parent_group_id`)을 표시하고, 우측 F1Grid에서 해당 그룹의 상세코드를 관리한다.
3. 자식 그룹의 상세코드는 자기 부모 그룹의 상세코드만 상위코드로 선택할 수 있다.
4. 트리/그리드의 우클릭 컨텍스트 메뉴는 활성화되지만, 행 추가/삭제 전용 버튼과 전용 메뉴는 제외한다.
5. 등록/수정/삭제와 중복/참조 검증을 서버에서 보장한다.

## 3. 프론트엔드 작업 범위

### 3.1 화면 및 라우팅

- `/co/master/cmncodes` 경로를 Dashboard 메뉴 구조에 연결한다.
- 공통코드 관리 페이지를 기존 시스템 관리 페이지 패턴에 맞춘 레이아웃으로 구성한다.
- 좌측 트리 영역은 그룹/하위 그룹 계층 표시, 우측 그리드 영역은 상세코드 표시를 담당한다.

### 3.2 F1Tree/F1Grid

- F1Tree로 부모그룹-자식그룹 구조를 렌더링한다.
- 그룹 선택 시 해당 그룹의 상세코드 목록을 F1Grid로 조회한다.
- 자식 그룹 선택 시 부모 그룹의 상세코드를 상위코드 옵션으로 제한한다.
- F1Tree와 F1Grid 모두 기본 컨텍스트 메뉴를 활성화한다.
- 행 추가/행 삭제 버튼과 전용 추가/삭제 메뉴는 비활성화 또는 미표시한다.

### 3.3 액션 및 권한

- 페이지 헤더 액션은 기존 관리 페이지와 동일하게 조회/저장/엑셀을 사용한다.
- 권한 체크는 기존 메뉴 권한 패턴을 따라 동작한다.
- 저장 시 그룹과 상세코드 변경을 일괄 반영하며, validation 실패 시 저장을 중단한다.
- `parent_item_id`는 그리드에서 직접 입력하지 않고 선택 모달창으로 선택한다.
- `use_at` 값은 체크박스 형태로 표시하고, 서버로는 `Y`/`N` 문자열로 정규화한다.
- `sort_order`는 숫자 입력값으로 유지하고, 정렬순서 편집은 숫자형 필드로 처리한다.

## 4. 백엔드 작업 범위

### 4.1 도메인 구조

- `tb_common_code_group` 테이블을 기준으로 그룹 CRUD 구현
- `tb_common_code_item` 테이블을 기준으로 그룹별 상세코드 CRUD 구현
- 그룹/상세코드 조회, 등록, 수정, 삭제 API 작성
- 부모 그룹 상세코드 조회 API를 통해 상위코드 선택 목록을 제한한다.

### 4.2 검증 로직

- 테넌트 범위 검증
- 그룹 코드 중복 검증
- 같은 그룹 내 상세코드 중복 검증
- 부모그룹이 실제 현재 그룹의 부모인지 검증
- `parent_item_id`가 부모 그룹의 상세코드인지 검증
- 자기 자신 또는 허용되지 않은 상위코드 지정 거부
- 사용 중인 그룹/상세코드 삭제 시 참조 여부 검증

### 4.3 API 설계

- `GET /api/v1/system/common-code-groups`
- `POST /api/v1/system/common-code-groups`
- `PUT /api/v1/system/common-code-groups/{groupId}`
- `DELETE /api/v1/system/common-code-groups/{groupId}`
- `GET /api/v1/system/common-code-groups/{groupId}/items`
- `POST /api/v1/system/common-code-groups/{groupId}/items`
- `PUT /api/v1/system/common-code-groups/{groupId}/items/{itemId}`
- `DELETE /api/v1/system/common-code-groups/{groupId}/items/{itemId}`
- `GET /api/v1/system/common-code-groups/{groupId}/parent-items`
