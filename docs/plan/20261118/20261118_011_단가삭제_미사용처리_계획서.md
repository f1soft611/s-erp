# 20261118_011 단가 삭제·미사용 처리 계획서

기준: [작업지시서](../../directions/20261118/20261118_011_단가삭제_미사용처리_작업지시서.md)

| 순서 | 단위 | 내용 |
| --- | --- | --- |
| 1 | 백엔드 | `deleteItemPartnerPrice`·직전 행 재개방 쿼리, `ItemPartnerPriceService.deletePrice`(과거 409, 적용 중·예정 삭제, 직전 종료일 복원), 배치 저장이 삭제 행을 삭제 → 수정 → 신규 순으로 처리 |
| 2 | 프론트 변환 | 품목 기준: 선택 행·구분별 삭제/미사용 변경 집합 생성(미사용은 기존 값 그대로 `useAt = N` 수정). 거래처 기준: 삭제 행·사용여부 변경을 일괄 저장 변환에 반영 |
| 3 | 프론트 화면 | 품목 기준 "단가 삭제" 버튼과 확인 창(삭제/미사용, 매입·매출 선택), 거래처 기준 행 삭제(컨텍스트 메뉴) 활성화 |
| 4 | 검증 | 단위 테스트, 실서버·브라우저에서 삭제·미사용·직전 단가 재개방 확인 |

## 결정과 이유
- **기존 `save-batch` 재사용**: 이미 있는 `deletedRows` 자리에 삭제를 받아 트랜잭션 하나로 처리한다. 새 엔드포인트를 만들지 않는다.
- **처리 순서(삭제 → 수정 → 신규)**: 같은 키를 삭제하고 다시 등록하는 오등록 정정을 한 번의 저장으로 할 수 있게 한다.
- **직전 단가 재개방**: 삭제 행이 만든 자동 종료를 되돌려 가격이 없는 공백 기간이 생기지 않게 한다.
- **미사용은 수정으로 처리**: 서버가 이미 `use_at` 수정을 지원하므로(현재·예정 행의 키 불변 수정) 별도 API가 필요 없다. 미사용 처리는 직전 단가를 되돌리지 않는다(중지 기록).
