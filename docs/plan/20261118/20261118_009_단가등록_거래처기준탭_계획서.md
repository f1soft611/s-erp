# 20261118_009 단가등록 거래처 기준 탭 계획서

기준: [작업지시서](../../directions/20261118/20261118_009_단가등록_거래처기준탭_작업지시서.md), 선행 [007 사양서](../../spec/20261118/20261118_007_단가등록_이력부가세외화_상세사양서.md), [008 사양서](../../spec/20261118/20261118_008_단가등록_품목기준트리화면_상세사양서.md)

| 순서 | 단위 | 내용 |
| --- | --- | --- |
| 1 | 백엔드 | `customer-overview` API(거래처 + 등록 건수, 등록 여부 필터), 단가 목록 API에 `customerId` 조건 추가. 서비스·Mapper 테스트 |
| 2 | 프론트 모델 | 거래처별 단가 행 변환, 셀 변경 → `save-batch` 변경 집합(신규/정정/새 기간/잠금) 단위 테스트 우선. 008의 변환 규칙을 행 단위로 재사용 |
| 3 | 프론트 화면 | 탭 추가, 좌측 거래처 그리드 + 우측 단가 그리드(No·필수 표시·상세 폼), 거래처 선택 시 조회, 행 추가(품목 선택 창) |
| 4 | 엑셀 | 007 업로드 창·양식을 이 탭에 연결하되 "그리드에 추가"가 아니라 확인 후 바로 저장·재조회 |
| 5 | 검증 | 단계 중에는 관련 단위 테스트와 `tsc`만, 실서버·브라우저·스크린샷은 마지막에 한 번 |

## 결정과 이유
- **DB 변경 없음**: 특별단가는 이미 `customer_id`가 있는 행이다.
- **우측은 피벗하지 않고 한 행 = 품목+구분**: 거래처 기준에서는 같은 품목의 매입·매출을 각각 행으로 보는 편이 입력(구분 선택, 품목 선택)과 이력 규칙에 단순하다. 품목 기준 탭만 매입·매출을 한 행에 나란히 둔다.
- **저장·검증 재사용**: 겹침·자동 종료·과거 잠금은 서버 규칙을 그대로 쓰고, 화면은 정정/새 기간 판단만 한다(008과 같은 규칙, 행 단위).
- **엑셀은 007 코드 재사용**: 검증 API와 양식이 이미 거래처코드를 포함한다. 달라지는 점은 반영 방식(staging → 확인 후 바로 저장)뿐이다.
- **기본단가(거래처 비움)는 이 탭에서 다루지 않는다**: 기본단가는 품목 기준 탭에서 입력한다. 거래처 목록에서 "기본단가"는 나오지 않는다.
