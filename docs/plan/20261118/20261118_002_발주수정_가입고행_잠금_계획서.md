## 결정과 이유
- **서버가 최종 판단, 화면은 안내**: 클라이언트 잠금만으로는 우회가 가능하므로 서버가 값 비교로 409를 반환한다. 화면은 같은 기준(행별 가입고수량 > 0)으로 편집을 막고 이유를 보여 준다.
- **"바뀌었는지"를 비교**: 잠긴 행을 그대로 다시 저장하는 요청(다른 행만 수정)은 허용한다. 저장된 값과 요청 값(수량·단가·납기·창고·검사대상·공급가·세액·합계)을 비교한다.
- **헤더 잠금**: 부가세구분·포함 여부는 모든 행 금액에 영향을 주므로 가입고가 있으면 헤더 값을 바꿀 수 없게 한다. 발주일도 같이 묶는다(가입고 헤더 선례).
- **상세 응답에 `arrivedQty` 추가**: 화면이 별도 조회 없이 잠금을 알 수 있다. 현황·등록 목록 API는 바꾸지 않는다.
- **메시지**: 사유와 해결 방법(가입고를 먼저 취소)을 함께 안내한다.

## 위험과 대응
- **동시 저장**: 가입고가 저장과 동시에 생기는 경우는 기존 발주 행 잠금(`FOR UPDATE`)과 가입고 저장 쪽 발주 행 잠금이 같은 행을 잠그므로 한쪽이 순서대로 처리된다.
- **기존 데이터**: 이미 가입고된 발주를 열어 수정하려는 사용자에게는 이제 잠금 안내가 나온다. 저장된 값은 바뀌지 않는다.
