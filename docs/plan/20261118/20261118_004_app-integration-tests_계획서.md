# 앱 통합 테스트 복구 계획서

## 기준과 범위

- [작업지시서](../../directions/20261118/20261118_001_repository-remediation_작업지시서.md)의 테스트 복구 단계다.
- 대상: `frontend/tests/dashboard-sidebar.test.tsx`, `login.test.tsx`, `overview-page.test.tsx`, `page-initial-errors.test.tsx`.
- 공통 `tests/setup.ts`는 변경하지 않는다. 다른 테스트의 전역 응답을 바꾸지 않고 필요한 모듈·권한·메뉴 fixture를 해당 파일에서 제공한다.
- 운영 예외는 재현된 로그아웃 결함 하나다. `DashboardPage.tsx`가 공통코드 키만 제거하고 메뉴관리 키는 남기므로 동일한 기존 처리에 메뉴 키 제거를 추가한다.

## 순서

- [x] 고정 `e9ba60f6` 프론트 스냅샷에서 관련 실패를 재현한다.
- [x] 실제 App의 lazy 로그인, 현재 로그인 문구, 기본 전역 메뉴 mock과 사이드바의 기대 모듈 간 불일치를 확인한다.
- [x] 로그인 입력은 lazy 화면 준비 후 조작한다. 기존 인증·세션·비밀번호 검증을 유지한다.
- [x] 사이드바의 그룹웨어·환경설정 탐색 테스트에 해당 메뉴·모듈·권한 fixture를 명시한다. 기본 단일 dashboard fixture에 암묵적으로 의존하지 않는다.
- [x] 명시적인 텍스트 변경·비동기 메뉴 조회·필수 역할 선택은 현재 화면 계약에 맞추고 실제 탐색·프로필·로그아웃·권한 단언을 보존한다.
- [x] 한 테스트에서 로그인과 두 관리 화면의 전체 lazy 로딩을 연달아 실행하는 구조는 실제 인증 세션 fixture의 직접 진입 두 테스트로 분리한다. 기존 화면 단언은 두 테스트에 보존하고 탐색은 앞선 전환 테스트가 검증한다. 시간 제한을 상향하지 않는다.
- [x] 종합현황 참조 확인 테스트는 현재 `지금 결재할 업무` 영역과 분리해 단언하고 quiet refresh 중 데이터·상세 보존 검증을 유지한다.
- [x] 최초 실패 테스트는 실제 데이터 화면 경로와 현재 오류 경계 계약을 검증한다.
- [x] 관련 집중 검사와 최종 정적 검사 결과를 기록한다. 운영 변경이 없는 개별 테스트 복구는 새 스크린샷 대상이 아니다.
- [x] 유효한 메뉴 세션 fixture의 로그아웃 후 잔존을 실패 테스트로 확인한 뒤, 키 상수와 제거 호출만 추가한다.
- [x] 합성 세션을 사용하는 격리 브라우저에서 375/768/1280px 로그아웃·세션 제거를 확인하고 스크린샷을 남긴다.

최종 검증은 공유 브랜치 이동을 반영한 `22bd60b8` 프론트 소스 오버레이와 이번 복구 변경을 기준으로 수행했다. [결과](../../result/20261118/repository-remediation/20261118_004_app-integration-tests_결과.md)를 참고한다.
