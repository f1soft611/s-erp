# 20261118_001 발주현황 가입고수량·입고잔량 컬럼 및 입고대기마감 검색 계획서

## 결정과 이유
- **수량 계산은 가입고 대상 조회와 같은 정의**를 쓴다. 두 화면이 같은 발주 행에 다른 잔량을 보이면 혼란이므로 같은 서브쿼리(가입고 합 − 불합격 합)를 상태 mapper에 둔다(namespace가 달라 fragment를 공유하지 못하므로 같은 SQL을 복제한다).
- **검색 조건은 `receiptCloseType`(OPEN/CLOSED)**: 매입마감의 `closeType` 선례를 따르되 입고대기마감 의미가 분명하도록 이름을 구분한다. 값이 없으면 전체. 컬럼 표시값(`-`)을 검색 선택지에 쓰지 않으려고 검색 전용 숨김 컬럼을 둔다.
- **그리드 레이아웃 저장 키 갱신**: 컬럼을 추가하면 사용자 브라우저에 저장된 컬럼 구성 때문에 새 컬럼이 안 보이므로 `storageKey` 버전을 올린다(지난 작업과 같은 방식).
- DB 변경 없음. 인덱스는 기존 조회 범위(테넌트·발주일) 안에서 서브쿼리를 한 번 더하는 수준이라 이번에는 추가하지 않는다.

## 위험과 대응
- **조회 성능**: 가입고 서브쿼리가 테넌트 전체 가입고를 집계한다. 가입고 대상 조회가 이미 같은 방식이다. 실제 데이터 규모가 커지면 발주일 범위로 좁히는 방안을 후속으로 검토한다.
- **취소된 발주·가입고**: 가입고는 `use_at = 'Y'`만 집계한다. 취소된 발주 행도 현황에서 보이므로 수량은 0이 될 수 있다.
