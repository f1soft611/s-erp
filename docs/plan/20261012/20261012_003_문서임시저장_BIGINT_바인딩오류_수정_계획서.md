# 문서 임시저장 BIGINT 바인딩 오류 수정 계획

## 목표

nullable `drafting_work_category_id`의 JDBC parameter type을 PostgreSQL 컬럼 타입과 일치시켜 임시저장 INSERT/UPDATE 오류를 방지한다.

## 원인 및 범위

MyBatis 전역 `jdbcTypeForNull=VARCHAR`와 전자결재 mapper의 미지정 nullable parameter가 조합되어 null이 VARCHAR로 바인딩될 수 있다. 변경 범위는 approval mapper, mapper regression test, 관련 작업 문서로 제한한다. Schema 변경은 없다.

## 실행 단계

1. [작업지시서](../../directions/20261012/20261012_003_문서임시저장_BIGINT_바인딩오류_수정_작업지시서.md) 및 상세 사양의 타입 계약을 확인한다.
2. `DocumentApproval_SQL_postgresql.xml`의 INSERT/UPDATE `draftingWorkCategoryId` parameter mapping을 검사하는 회귀 테스트를 작성한다.
3. 회귀 테스트를 실행해 JDBC type이 명시되지 않은 현재 코드에서 실패하는지 확인한다.
4. 두 mapper binding에 `jdbcType=BIGINT`를 선언하고 회귀 테스트를 통과시킨다.
5. approval service/controller 테스트와 전체 백엔드 테스트를 실행한다.
6. 결과 문서, `git diff --check`, worktree 상태를 확인한다.

## 검증 기준

- INSERT/UPDATE parameter mapping의 `jdbcType`이 모두 `BIGINT`다.
- 회귀 테스트가 RED 후 GREEN 순서로 실행된다.
- Maven approval 관련 테스트와 전체 test suite가 통과한다.
- nullable category contract와 schema에 변화가 없다.
