# DB MCP 세션 도구 검색 오류 수정 계획서

> **For agentic workers:** 이 계획의 체크박스를 순서대로 수행한다. 각 단계의 파일 범위를 지키고 자격 증명이나 DB 행을 출력하지 않는다.

**목표:** 로컬 Copilot 세션에서 읽기 전용 PostgreSQL MCP 도구를 발견할 수 있도록 workspace 설정을 표준화한다.

**구조:** 루트 `.mcp.json`의 portable `mcpServers` 형식은 유지한다. 두 로컬 stdio 서버의 타입을 `stdio`로 맞추고 미지원 `tools` 필드를 제거한다. 서버 구현 및 접속 비밀값은 변경하지 않는다.

**기술 스택:** VS Code Copilot MCP JSON, Node.js, TypeScript, Vitest, 기존 `@modelcontextprotocol/sdk`.

**근거 설계:** `../../superpowers/specs/2026-10-12-db-mcp-session-discovery-design.md`

- [ ] **1단계: 현재 설정에서 표준 전송 타입과 허용 필드만 통과하는 테스트 작성**

  Vitest에서 `.mcp.json`을 읽고 Zod 스키마로 검증한다. primary와 tenant 서버가 모두 `type: "stdio"`, `command: "node"`, 단일 실행 인수를 갖도록 요구한다. tenant에만 `S_ERP_DB_NAME=tenant_1212123312`가 존재해야 한다. strict object 스키마를 적용해 `tools` 같은 미지원 속성도 거부한다.

  ```typescript
  import { readFile } from 'node:fs/promises';
  import { fileURLToPath } from 'node:url';

  import { describe, expect, test } from 'vitest';
  import { z } from 'zod';

  const configPath = fileURLToPath(new URL('../../../.mcp.json', import.meta.url));
  const serverArgs = z.tuple([
    z.literal(
      'D:/f1soft/dev/react/S-ERP/tools/mcp-postgresql-readonly/dist/index.js',
    ),
  ]);
  const primaryServerSchema = z
    .object({
      type: z.literal('stdio'),
      command: z.literal('node'),
      args: serverArgs,
    })
    .strict();
  const tenantServerSchema = z
    .object({
      type: z.literal('stdio'),
      command: z.literal('node'),
      args: serverArgs,
      env: z
        .object({
          S_ERP_DB_NAME: z.literal('tenant_1212123312'),
        })
        .strict(),
    })
    .strict();
  const workspaceConfigSchema = z
    .object({
      mcpServers: z
        .object({
          's-erp-postgresql-readonly': primaryServerSchema,
          's-erp-postgresql-readonly-tenant-1212123312': tenantServerSchema,
        })
        .strict(),
    })
    .strict();

  describe('workspace MCP configuration', () => {
    test('registers both read-only servers with supported stdio fields', async () => {
      const source = await readFile(configPath, 'utf8');
      const config = workspaceConfigSchema.parse(JSON.parse(source));

      expect(Object.keys(config.mcpServers)).toHaveLength(2);
      expect(
        config.mcpServers['s-erp-postgresql-readonly-tenant-1212123312'].env,
      ).toEqual({ S_ERP_DB_NAME: 'tenant_1212123312' });
    });
  });
  ```

  ```powershell
  @'
  import { Client } from '@modelcontextprotocol/sdk/client/index.js';
  import { StdioClientTransport } from '@modelcontextprotocol/sdk/client/stdio.js';

  const transport = new StdioClientTransport({
    command: process.execPath,
    args: ['dist/index.js'],
  });
  const client = new Client({ name: 'mcp-config-validation', version: '1.0.0' });
  try {
    await client.connect(transport);
    const { tools } = await client.listTools();
    console.log(JSON.stringify(tools.map(({ name }) => name)));
  } finally {
    await client.close();
  }
  '@ | node --input-type=module
  ```

  Expected output is exactly `["list_tables","describe_table","query_readonly"]`. This calls only MCP initialization and `tools/list`, not a database tool.
