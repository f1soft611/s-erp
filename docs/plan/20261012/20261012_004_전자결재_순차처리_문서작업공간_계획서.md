# 전자결재 순차처리 및 문서작업공간 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 서버 트랜잭션으로 순차 결재·합의·반려·보완·재상신과 시스템 이력을 보장하고, 문서작성 화면의 우측 결재 요약·문서 상태·알림을 독립 영역으로 제공한다.

**Architecture:** 백엔드가 문서·결재선 상태 전이와 이력 기록의 유일한 기준이며, 이 변경은 한 DB 트랜잭션에서 처리한다. 참여자 범위로 보호되는 목록·요약·상세 API를 제공하고 프런트엔드는 서비스 계층으로 연결한다. 좌측 문서 영역의 기존 컴포넌트 트리·조건부 고정 목록 표시·피드/리스트 구조는 유지하며, 우측은 결재 요약·문서 상태·놓치지 마세요 컴포넌트를 별도 카드로 조립한다.

**Tech Stack:** Java 17, Spring Boot/eGovFrame, MyBatis, PostgreSQL, React, TypeScript, MUI, Vitest, JUnit 5, Mockito.

## 완료 기준

- 순차 결재 및 동시 합의·활성 처리자 권한·반려 종료·보완 후 재상신 규칙이 서버에서 보장된다.
