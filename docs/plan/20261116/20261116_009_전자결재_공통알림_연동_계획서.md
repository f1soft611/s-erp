# 전자결재 공통 알림 연동 Implementation Plan

> **For agentic workers:** Follow the date-scoped work instruction and detailed specification before implementation. Use checkbox steps and run each focused test before broad checks.

**Goal:** Connect approval workflow transitions to the existing shared notification inbox and Web Push channel.

**Architecture:** Reuse the approval transaction and its generated system-comment ID as the notification source ID. The notification service validates a single new event/source pair, while the existing notification mapper derives the approval document target from the comment owner. Email is feasibility documentation only and is not sent by this change.

**Tech Stack:** Java 8-compatible Spring/eGovFrame services, MyBatis/PostgreSQL, React/TypeScript, Vitest, Maven.

---

## Files and responsibilities

- `backend/src/main/java/egovframework/let/groupware/approval/common/service/DocumentApprovalDraftSupportService.java` and its implementation: return the persisted system-event comment ID.
- `backend/src/main/java/egovframework/let/groupware/approval/domain/repository/DocumentApprovalDAO.java` and `backend/src/main/resources/egovframework/mapper/let/groupware/approval/DocumentApproval_SQL_postgresql.xml`: return currently pending notification recipients using tenant-scoped approval lines and active-user predicates.
- `backend/src/main/java/egovframework/let/groupware/approval/shared/service/impl/DocumentApprovalInteractionServiceImpl.java`: create workflow notifications at submit/action transitions.
- `backend/src/main/java/egovframework/let/groupware/notification/service/impl/NotificationServiceImpl.java`: allow and validate `APPROVAL_WORKFLOW`/`APPROVAL_STATUS_EVENT`.
- `backend/src/main/resources/egovframework/mapper/let/groupware/notification/Notification_SQL_postgresql.xml`: resolve approval event `targetId` from the existing approval system comment.
- `frontend/src/shared/types/notification.types.ts`, `frontend/src/shared/services/notificationService.ts`, `frontend/src/shared/utils/notificationPath.ts`, and `frontend/src/pages/groupware/notifications/NotificationInboxPage.tsx`: validate, route, classify, and filter the new event.
- `docs/database/20261116/*`, `backend/DATABASE/20261116/*`, and `docs/database/db-schema.md`: update the notification event/source CHECK contract and record rollback/history.
- Focused server tests: `DocumentApprovalInteractionServiceImplTest`, `NotificationServiceImplTest`, `NotificationMapperXmlTest`.
- Focused frontend tests: `notification-service.test.ts`, `notification-inbox.test.tsx`, and `notification-center.test.tsx`.
