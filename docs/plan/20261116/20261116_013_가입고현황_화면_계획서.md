## 의존·재사용
- 발주현황(`order/status`: 페이지, 컬럼 정의, 상세 패널, 에디터 다이얼로그)의 구조를 그대로 따른다.
- 폼·그리드·컬럼·금액 계산은 가입고등록과 공유하고 차이는 숨김·읽기 전용뿐이다.
- 수정 권한은 가입고등록 메뉴의 UPDATE 권한(발주현황과 같은 방식). 테이블 변경은 없다.

## 위험과 대응
- **수정 중 잔량 초과**: 수정 저장 시 대상 발주 행을 잠근다. 2026-11-17부터 "이 행을 뺀 가입고 합 + 수정 수량"이 발주수량을 넘어도 서버는 차단하지 않고, 화면 확인창에서 예/아니오를 묻는다.
- **취소 후 재사용**: 취소는 `use_at='N'`으로만 처리하고 잔량은 유효 가입고 합으로 계산하므로 별도 복원 로직이 없다.
- **후속 잠금**: 입고·수입검사 잠금은 해당 작업에서 수정·취소 API 앞단에 검증만 추가하면 되도록 서비스에 검증 메서드를 분리해 둔다.

## 검증 계획
- 서비스 테스트: 목록 필터·날짜 오류, 수정 재계산·행 삭제 후 행번호 재정렬, 모든 행 삭제 거부, 취소된 가입고 거부, 잔량 초과 허용, 취소 후 잔량 복원.
- 프론트 테스트: 상세 패널, 조회 모드 읽기 전용, 수정 저장, 가입고 취소.
- 백엔드 `mvn test`, 프론트 `npm run test`·`npm run build`, JDK 8 컴파일.
