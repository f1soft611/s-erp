## 의존·재사용

- 화면 패턴은 `frontend/src/pages/materials/order/create`(헤더 폼, 행 그리드, 선택 창, 서비스 계층, `embedded` 모드)를 따른다. 같은 구매처 칩 고정 방식도 확정 불러오기 창과 같다.
- 번호는 발주와 같은 `IdSequenceService` 패턴, 키는 가입고 전용(`MATERIAL_PROVISIONAL_NO`, 형식 `MP-YYYYMMDD-NNNN`).
- 단가 기본값은 발주 행 `unit_price`를 쓴다(별도 단가 조회 없음).
- 부가세·금액 계산은 발주등록의 `PurchaseOrderAmountCalculator`(서버)와 `calculateOrderAmounts`(화면)를 재사용한다(2026-11-16 사용자 결정: 가입고도 발주와 같은 부가세 룰).
- 발주 서비스(`PurchaseOrderServiceImpl`)의 행 삭제·취소·수정 경로에 가입고 검증을 추가한다. 기존 발주 로직의 다른 동작은 바꾸지 않는다.

## 위험과 대응

- **동시 저장**: 같은 발주 행을 두 사람이 동시에 가입고하면 잔량을 넘길 수 있다. 저장 시 대상 발주 행을 `FOR UPDATE`로 잠그고 잔량을 다시 계산한다. 2026-11-17부터 잔량 초과는 차단하지 않고 화면 확인창이 맡으며, 잠금은 동시 저장 시 합계를 일관되게 읽기 위해 유지한다.
- **발주 수정과의 충돌**: 가입고가 생긴 발주 행의 삭제·수량 축소를 막는다(4단계).
- **입고 연동 미정**: 무검사 자동 입고, 수입검사 잠금은 대상 테이블이 생기는 후속 작업에서 구현한다. 가입고 행에 `inspect_at`을 저장해 분기 기준을 확보한다.
- **LOT·재고 미정**: LOT번호 컬럼만 확보한다.

## 검증 계획

- 서비스 단위 테스트: 잔량 계산, 같은 구매처 검증, 잔량 초과 허용(0 이하는 거부), 단가 필수, 번호 발급, 입고대기마감 행 제외, 발주 연동 409.
- 매퍼/스키마 정적 테스트: 기존 `20261113` 패턴.
- 프론트 테스트: 구매처 칩 잠금, 단가 필수 안내, 수량 초과 경고, 행 빼기.
- 백엔드 `mvn test`, 프론트 `npm run test`·`npm run build`, JDK 8 `--release 8` 컴파일.
