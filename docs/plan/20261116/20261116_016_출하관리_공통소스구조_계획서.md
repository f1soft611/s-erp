# Shipment Source Layout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 출하관리 프론트·백엔드 소스를 `sales/shipment/{delivery,deliveryplan,statement}`로 통일한다.

**Architecture:** 소스 폴더와 모듈·Java 패키지 경로만 이동한다. 기능 내부 책임 분리, SQL, Bean/Mapper 이름, HTTP 계약 및 화면 동작은 유지한다.

**Tech Stack:** React, TypeScript, Vite, Vitest, Playwright, Java 8 호환 Spring/eGovFrame, MyBatis, Maven.

## Task 4: 검증·결과

- [x] 이전 빌드의 클래스·Mapper 중복을 피하도록 Maven의 정상 clean 절차 후 집중 테스트와 Java 8 API 호환 컴파일을 실행한다.

```powershell
cd backend
mvn -q clean test '-Dtest=SalesDelivery*Test,SalesStatement*Test,SalesOrderServiceImplTest' '-Dmaven.compiler.release=8' '-Dmaven.compiler.testRelease=17'
cd ..\frontend
npm run test -- tests\sales-delivery-api.test.ts tests\sales-delivery-page.test.tsx tests\sales-delivery-plan-api.test.ts tests\sales-delivery-plan-page.test.tsx tests\sales-statement-page.test.tsx tests\sales-statement-routing.test.tsx tests\statement-print-layout.test.tsx
npm run build
npm run lint -- src\pages\sales\shipment src\pages\dashboard\components\DashboardContent.tsx
node tests\sales-statement-flow.browser.mjs
```

- [x] 기존 출하 품목 브라우저 흐름도 실행하되 과거 결과 스크린샷은 덮어쓰지 않는다.
- [x] 활성 소스·테스트의 이전 모듈/패키지/Mapper 참조 부재와 기존 API·SQL 유지 여부를 확인한다.
- [x] `docs/result/20261116/shipment-source-layout`에 실제 명령 결과, MCP 근거, 스크린샷, 복사 가능한 커밋 제목·내용을 기록한다.

운영 코드의 `release=8`과 개발·테스트 코드의 `testRelease=17`을 분리한다.
기존 다른 테스트에는 Java 9+ API가 있어 모든 테스트 소스에 `release=8`을 적용하지 않는다.
프론트 테스트가 동시 빌드와의 자원 경합으로 5초 제한에 도달하면 제한 시간을 늘리거나 운영 코드를 바꾸지 않고 빌드가 끝난 후 재확인한다.
