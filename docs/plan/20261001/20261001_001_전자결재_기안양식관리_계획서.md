# 20261001_001 전자결재 기안양식관리 구현 계획서

> **For agentic workers:** 구현은 계획서·상세 사양서 승인 후 시작한다. 태스크별로 TDD와 독립 리뷰를 수행하고, 구현 방식은 F1Workflow 06단계에서 사용자와 확정한다.

**상태:** 사용자 승인 완료 (2026-10-01); Inline Execution 선택

**목표:** `CO_WF_FORM` 메뉴에서 S-ERP 공통 화면 패턴과 F1-Grid를 사용하는 기안양식 메타데이터 관리 기능을 제공한다.

**구조:** `/co/workflow/form`은 기존 대시보드의 `co` 모듈 페이지 키 `form`으로 연결한다. HACCP 원본의 category group/work/authority 테이블과 업무 컬럼을 이관하고 `category_item_id`, `reg_term_id`를 추가해 S-ERP 공통코드 항목을 참조한다. 기존 `code_name`은 양식명으로 보존하고 `reg_term`은 주기 항목명으로 동기화한다. 분류 항목은 페이지 내 공통코드 상세 도움창에서 관리한다.

**기술:** React, TypeScript, MUI, `PageHeader`/`PageSearchArea`/`PageMessageArea`, F1-Grid, Vitest, Playwright, Java/eGovFrame, MyBatis, PostgreSQL.

## 인터페이스

- 메뉴 page key `form` -> `DraftFormManagementPage`.
- `DraftWorkRow`: `draftingWorkCategoryId`, `cataTypeCode`, `codeName`, `categoryItemId`, `categoryName`, `regTermId`, `regTerm`, `reviewerId`, `approverId`, `assigneeIds`, `useAt`, `createdByName`, `createdAt`, `hasDocument`.
- save payload: `cataTypeCode`, `codeName`, `categoryItemId`, `regTermId`, `reviewerId`, `approverId`, `assigneeIds`, `useAt`; blank create `cataTypeCode` invokes the existing generator.
- common-code helper props: `open`, `groupId`, `items`, `canEdit`, `onClose`, `onCreateItem`, `onUpdateItem`, `onReload`.
- `reg_term_id` holds cycle item ID; `reg_term` mirrors that item name. `code_name` remains the source form name.
- `GET /api/v1/co/workflow/forms/users` returns active tenant users (`userId`, `loginId`, `userNm`, `departmentNm`) for form assignment options. `reviewerId`/`approverId` are `loginId`; authority `employee_no` receives the selected `userId` string (max 10 chars).

## 위험·검증 기준

- Cross-tenant common-code item IDs are invalid even when the numeric FK exists; service checks tenant + group code + `use_at='Y'`.
- category item name is selected by `category_item_id`, not copied into `code_name`; cycle `item_nm` and `reg_term` are saved together in one transaction.
- `tb_drafting_work_category_group` remains for source compatibility, but the new screen uses `WF_FORM_CATEGORY` codes. Do not conflate the two models.
- common-code create/update remains tenant-admin-only. The dialog does not add or mutate groups and does not expose item deletion.
- Migration/rollback files are drafts; no DDL/DML has been applied. Existing 20261001_002 scripts and unrelated 20260915 SQL edits are out of scope and must remain untouched.
