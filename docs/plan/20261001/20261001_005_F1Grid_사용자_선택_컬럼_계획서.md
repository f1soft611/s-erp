# 20261001_005 F1-Grid 사용자 선택 컬럼 계획서

## 목표

F1-Grid의 신규 `user` 타입이 셀 편집과 행 폼 모달에서 같은 UI와 단일/다중 값 계약을 사용하도록 구현하고, 기안양식관리 사용자 API에 사진/직급 표시 정보를 추가한다.

## 구현 순서

1. RED 테스트를 추가해 현재 F1-Grid 편집기/폼 모달이 `user` 타입을 처리하지 못하는 것을 확인한다.
2. 옵션/타입 계약과 공용 사용자 선택 편집기를 추가한다. 셀 편집 임시값은 단일 문자열 ID 또는 다중 ID 배열을 지원하고, 커밋 때 옵션의 원래 ID 타입을 복원한다.
3. 기본 셀 표시, Grid `CellEditor`, `GridFormField`에서 공용 사용자 선택기를 연결하고 필수/읽기 전용/검증 오류를 전달한다.
4. 사용자 API VO/매퍼에 `profileImage`, 활성 `LEVEL` 항목명 `levelNm`을 추가한다. tenant 및 활성 계정 필터는 기존 조건을 유지한다.
5. 프론트 사용자 옵션 타입/응답 정규화를 확장하고 기안양식의 검토자·승인자·담당자 컬럼을 사용자 타입으로 바꾼다. 담당자 편집 금지 예외를 제거하고 저장 ID 계약을 보존한다.
6. API/F1-Grid 문서와 결과 원장을 작성하고 테스트·빌드·브라우저 검증을 진행한다.

## 위험과 대응

- 셀 편집기의 기존 `draftValue`가 문자열이므로 다중 선택 임시 배열과 원래 숫자/문자열 ID를 명시적으로 지원하고 RED/GREEN 테스트로 확인한다.
- `getValue`가 표시 요약을 반환하는 다중 담당자 컬럼은 폼 선택기 값과 혼동하지 않도록 raw field 값은 선택기가 사용하고, 셀 표시 요약은 `renderCell`에서 유지한다.
- `tb_user.level_id`와 `LEVEL` 코드 조인은 `LEFT JOIN`으로 구성해 직급 누락 사용자를 제외하지 않는다. 모든 조인에 tenant 조건을 포함한다.
- 작업 트리에 기존 기안양식 보정 변경이 있으므로 관련 파일의 현재 diff를 확인하고 그 변경을 보존한 채 필요한 코드만 추가한다.
- 수정 전 기준선에서 `f1-grid.test.tsx`는 194개 중 148 통과/46 실패했고, 실패는 파일의 기존 mojibake 한국어 fixture와 접근성 이름 불일치에 집중된다. 새 사용자 셀 테스트는 이름 필터로 별도 실행하며 전체 파일 결과는 변경 전후 비교로만 사용한다. `f1-grid-form-modal.test.tsx`는 수정 전 통과했다.
