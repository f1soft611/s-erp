## 변경 범위

### 분류 설정 도움창

- `frontend/src/shared/components/common-code/CommonCodeItemHelpDialog.tsx`에서 모달 콘텐츠와 Grid의 flex/min-height/overflow 제약을 점검해 Grid가 가용 영역을 채우고 자체 스크롤을 사용하게 한다.
- 별도 row form modal은 도입하지 않는다. 추가 버튼 및 허용된 행 추가 동작으로 행을 만든 후 Grid 셀을 편집한다.
- 신규행과 실제 수정행을 각각 inserted/updated 변경으로 저장하며, 저장된 행을 편집하지 않았거나 원래 값으로 되돌린 경우 불필요한 dirty가 남지 않게 한다.
- 저장 중에는 전체 Grid를 덮는 로딩 오버레이를 피하고, 저장 버튼/작은 진행 표시 등 조용하고 비차단적인 피드백을 사용한다. 중복 저장 방지와 오류 표시를 유지한다.

### 기안양식 그리드

- `frontend/src/pages/co/workflow/form/components/DraftFormGrid.tsx`와 관련 페이지/훅에서 select 값의 원본/편집 값을 비교하는 경로를 점검한다.
- 미변경 select 편집은 dirty로 만들지 않는다. select 컬럼의 데이터 값과 저장 payload는 기존 ID를 유지하고, 비편집 표시에서는 옵션 label을 보여준다.
- 검토자/승인자 null 값은 옵션 label `선택 안 함`으로 표시하고 null 계약을 보존한다.
- `DraftFormManagementPage.tsx`의 Grid 상단 간격을 모듈관리 화면 패턴과 일치시킨다.
- F1-Grid 코어 변경이 근본 해결에 필요하다고 확인되면, 구현하지 않고 변경 범위를 사용자에게 다시 승인받는다.

### 회귀 검증 및 문서

- 기존 `frontend/tests/common-code-item-help-dialog.test.tsx` 및 `frontend/tests/draft-form-management.test.tsx`를 우선 확장해 신규/수정/미변경 select/label/null 시나리오를 검증한다.
- 수정한 경로에 따라 관련 F1-Grid 테스트만 추가 실행한다.
- `frontend/src/pages/f1-grid-docs/F1-GRID.md`에 변경된 사용자 동작과 회귀 기준을 반영한다.
- 결과 원장/보고서와 375px, 768px, 1280px 브라우저 캡처를 `docs/result/20261001/drafting-work-form-management/`에 기록한다.

## 검증 계획

- RED: 추가/수정/미변경 및 select label/null을 확인하는 회귀 테스트를 구현보다 먼저 작성하고 실패를 확인한다.
- GREEN: 최소 수정으로 테스트를 통과시킨다. F1-Grid 공통 코어 수정이 필요하면 중단 후 별도 승인을 요청한다.
- Focused tests: `npm run test -- tests/common-code-item-help-dialog.test.tsx tests/draft-form-management.test.tsx`
- Build: `npm run build`
- Browser: 기존 캡처 스크립트/Playwright 경로를 재사용해 메뉴 UI로 진입하고 375/768/1280px에서 그리드 크기, 내부 스크롤, 저장 상태, label 표시 및 화면 간격을 확인한다. 스크린샷은 결과 폴더에 저장한다.
- 전체 테스트가 요구되면 focused 결과 후 `npm run test`를 실행하고 기존 기준선 실패와 구분해 기록한다.
