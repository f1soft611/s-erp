## 변경 범위

### 분류 설정 도움창

- `frontend/src/shared/components/common-code/CommonCodeItemHelpDialog.tsx`에서 모달 콘텐츠와 Grid의 flex/min-height/overflow 제약을 점검해 Grid가 가용 영역을 채우고 자체 스크롤을 사용하게 한다.
- 별도 row form modal은 도입하지 않는다. 추가 버튼 및 허용된 행 추가 동작으로 행을 만든 후 Grid 셀을 편집한다.
- 신규행과 실제 수정행을 각각 inserted/updated 변경으로 저장하며, 저장된 행을 편집하지 않았거나 원래 값으로 되돌린 경우 불필요한 dirty가 남지 않게 한다.
- 저장 중에는 전체 Grid를 덮는 로딩 오버레이를 피하고, 저장 버튼/작은 진행 표시 등 조용하고 비차단적인 피드백을 사용한다. 중복 저장 방지와 오류 표시를 유지한다.

### 기안양식 그리드

- `frontend/src/pages/co/workflow/form/components/DraftFormGrid.tsx`와 관련 페이지/훅에서 select 값의 원본/편집 값을 비교하는 경로를 점검한다.
- 미변경 select 편집은 dirty로 만들지 않는다. select 컬럼의 데이터 값과 저장 payload는 기존 ID를 유지하고, 비편집 표시에서는 옵션 label을 보여준다.
- 검토자/승인자 null 값은 옵션 label `선택 안 함`으로 표시하고 null 계약을 보존한다.
- `DraftFormManagementPage.tsx`의 Grid 상단 간격을 모듈관리 화면 패턴과 일치시킨다.
- `DraftFormManagementPage.tsx`의 조회와 상세검색 적용 전에 Grid 변경 집합을 확인한다. dirty이면 `UnsavedChangesConfirmDialog`로 감싸고 요청 필터를 보류한다. 취소 시 보류 요청을 폐기하고 편집 상태를 유지하며, 계속 시 변경 상태를 초기화한 뒤 보류한 조회를 한 번 수행한다.
- F1-Grid 코어 변경이 근본 해결에 필요하다고 확인되면, 구현하지 않고 변경 범위를 사용자에게 다시 승인받는다.

### 변경 유실 방지

- `CommonCodeItemHelpDialog.tsx`에서 Cancel/X 닫기 요청 시 inserted/updated 변경이 있으면 동일 공용 확인 다이얼로그를 표시한다.
- 모달 확인 취소는 다이얼로그와 변경 상태를 유지한다. 계속은 dirty/grid 상태를 초기화하고 모달을 닫는다.

## 상세 실행 계획

### Interfaces

- 기안양식 조회는 `DraftFormManagementPage`가 검색 조건을 보류하고, `useDraftFormManagement`가 조회/변경 상태를 관리한다. F1-Grid `getChanges()`가 dirty의 기준이다.
- 분류 모달은 `CommonCodeItemHelpDialog`가 Grid 변경과 닫기 확인을 관리하며 기존 `onCreateItem`, `onUpdateItem`, `onReload` 계약을 유지한다.
- 확인창은 shared `UnsavedChangesConfirmDialog`를 재사용한다. API payload, 권한 및 DB 계약은 변경하지 않는다.

### Global Constraints

- 실행 방식은 6단계 사용자 선택 후 확정한다. 사용자 응답 전 테스트 또는 구현에 착수하지 않는다.
- 현재 브랜치 `socra710`에서 진행하고 Worktree는 만들지 않는다. 이미 변경된 계획서/사양서와 다른 사용자 작업은 보존한다.
- 테스트 우선(RED-GREEN)을 적용한다. 단계마다 아래 focused 명령으로 해당 변경을 검증한다.
- F1-Grid 공통 코어 수정, 백엔드/API/DB 수정은 승인 범위 밖이므로 필요성이 드러나면 즉시 중단하고 승인을 요청한다.
- 커밋은 별도 요청이 없으므로 만들지 않는다.
