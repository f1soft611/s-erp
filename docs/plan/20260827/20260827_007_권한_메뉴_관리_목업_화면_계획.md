# 20260827_007 권한/메뉴 관리 목업 화면 계획

## 1. 목표

기존 대시보드 구조에 권한관리와 메뉴관리의 실제 ERP용 화면을 추가한다. 구현 범위는 프론트엔드 샘플 데이터 기반이며, 현 단계에서는 실제 백엔드 연동 없이 데이터 모델과 UI 흐름을 완성한다.

## 2. 요구사항 정리

- 권한관리 화면: 역할 목록 + 선택 역할 상세 + 권한 체크박스
- 메뉴관리 화면: 메뉴 트리/표 + 기본 정보 입력 + 사용 여부/정렬 관리
- 사용자 문맥은 기존 `DashboardPage` 구조를 유지하고, `currentMenu.pageKey` 값을 기준으로 컴포넌트 분기
- 샘플 데이터는 `dashboardData.tsx` 또는 별도 mock 파일에서 관리

## 3. 구현 단위

| 순번 | 항목           | 파일                                                     | 내용                                      |
| ---- | -------------- | -------------------------------------------------------- | ----------------------------------------- |
| 1    | 화면 분기 로직 | `src/pages/dashboard/components/DashboardContent.tsx`    | `kind` 값에 따라 권한/메뉴 관리 UI 렌더링 |
| 2    | 목업 데이터    | `src/pages/dashboard/services/dashboardData.tsx`         | 역할/메뉴 샘플 데이터 구성                |
| 3    | 관리 화면      | `src/pages/dashboard/components/RoleManagementPanel.tsx` | 역할 테이블 + 상세 권한 편집              |
| 4    | 관리 화면      | `src/pages/dashboard/components/MenuManagementPanel.tsx` | 메뉴 목록 + 상세 편집                     |
| 5    | 검증           | `frontend/tests/*.test.tsx`                              | 권한/메뉴 관리 UI 렌더링 검증             |

## 4. 화면 설계 원칙

- 공통 상단 타이틀과 카드 요약은 기존 `DashboardContent` 포맷을 유지한다.
- 테이블과 편집 패널은 `Card`, `Stack`, `Chip`, `Checkbox`, `TextField` 조합으로 구성한다.
- 데이터는 정적 mock 배열로 유지하고, 사용자 선택 시 컴포넌트 상태로 반영한다.
- 배치와 색상은 기존 MUI 테마와 일치시킨다.

## 5. 검증 계획

- `npm run build`
- `npm run test`
- 권한관리와 메뉴관리 각각의 메인 제목/테이블/검증 체크 항목 표시 여부 확인

## 6. 리스크

- 기존 대시보드 콘텐츠 컴포넌트는 요약형만 담당하므로, 권한/메뉴 관리용 분기 로직을 안전하게 추가해야 한다.
- 샘플 데이터만 사용하므로 상태 변경은 UI 반영 수준으로 관리한다.
