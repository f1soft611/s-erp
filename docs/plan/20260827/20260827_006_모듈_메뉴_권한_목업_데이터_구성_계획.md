# 20260827_006 모듈-메뉴 권한 목업 데이터 구성 계획

근거 문서: [20260827*006*모듈*메뉴*권한*목업*데이터*구성*작업지시서.md](../../directions/20260827/20260827_006_모듈_메뉴_권한_목업_데이터_구성_작업지시서.md)

## 1. 현황

- `frontend/src/pages/dashboard/services/dashboardData.tsx` 에 6개 모듈의 트리가 하드코딩되어 있다.
- 트리 노드에 권한 정보가 없고, 로그인 사용자와 메뉴의 연관관계가 표현되지 않는다.
- 화면(`DashboardPage`)은 `moduleItems`를 직접 참조해 라우팅/렌더링한다.

## 2. 목표

서버 응답을 가정한 단일 목업 JSON을 데이터 원천으로 삼아,
모듈-메뉴 부모/자식 관계와 메뉴별 admin 권한을 화면 모델로 변환한다.

## 3. 구현 단위

| 순번 | 단위             | 대상                                         | 내용                                                                            |
| ---- | ---------------- | -------------------------------------------- | ------------------------------------------------------------------------------- |
| 1    | 데이터 계약 타입 | `pages/dashboard/types/dashboard.ts`         | `MenuPermission`, `MenuNode`, `UserMenuResponse` 추가, `MenuTreeNode` 필드 확장 |
| 2    | 목업 데이터      | `pages/dashboard/data/adminUserMenus.json`   | 그룹웨어/환경설정 2개 모듈, 하위 메뉴 4개, admin 전권 부여                      |
| 3    | 변환 서비스      | `pages/dashboard/services/menuService.ts`    | JSON → 모듈 디스크립터/메뉴 트리 변환, 권한 조회 함수 제공                      |
| 4    | 대시보드 데이터  | `pages/dashboard/services/dashboardData.tsx` | 모듈 아이콘 매핑 후 `moduleItems` 생성, 페이지 콘텐츠 맵 정비                   |
| 5    | 테스트           | `frontend/tests/*`                           | 새 모듈/메뉴 구성 및 권한 데이터 검증                                           |

## 4. 데이터 매핑 규칙

- 모듈 = `parentMenuId`가 `null`인 루트 메뉴
- 모듈 ID = 루트 메뉴 `path`의 첫 세그먼트 (`/groupware` → `groupware`)
- 메뉴 ID(라우팅 키) = 하위 메뉴 `path`의 마지막 세그먼트 (`/groupware/overview` → `overview`)
- `pageKey` = 메뉴 ID와 동일
- 좌측 트리 = 루트 메뉴의 `children`

## 5. 영향 범위

- 프론트엔드 대시보드 데이터/서비스 계층, 관련 테스트
- 백엔드 및 DB 변경 없음

## 6. 검증 계획

- `npm run build`
- `npm run test` (Git Bash 실행)
- 메뉴 트리, 모듈 전환, 직접 URL 진입, 권한 데이터 단위 검증

## 7. 리스크

| 리스크                                             | 대응                                                       |
| -------------------------------------------------- | ---------------------------------------------------------- |
| 기존 URL(`/dashboard/groupware/approval`)과 불일치 | 유효하지 않은 메뉴 ID는 기존 fallback 정책(첫 리프)로 처리 |
| 트리에 그룹 노드가 없어 확장 동작 미검증           | `DashboardMenuTree`의 그룹 렌더링 로직은 변경하지 않음     |
