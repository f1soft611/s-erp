# 20260918_009 공지사항 구분명·강조색상·모달여백 상세 실행 계획

## Global Constraints

- 현재 브랜치에서 진행한다.
- 승인된 사양 범위만 수정한다.
- DB 스키마는 변경하지 않는다.
- `isNotice`와 `noticeGubunCode`를 서로 다른 의미로 유지한다.
- 공통코드 상세 옵션에는 전체를 넣지 않고 목록 필터에서만 별도 전체를 제공한다.
- 기존 사용자 변경사항과 기존 댓글 테스트 실패를 되돌리지 않는다.

- 파일: `backend/src/main/java/egovframework/let/groupware/community/notice/controller/NoticeBoardApiController.java`, `backend/src/main/java/egovframework/let/groupware/community/notice/service/NoticeBoardService.java`, `backend/src/main/java/egovframework/let/groupware/community/notice/service/impl/NoticeBoardServiceImpl.java`, `backend/src/main/resources/egovframework/mapper/let/groupware/community/notice/NoticeBoard_SQL_postgresql.xml`, `frontend/src/pages/groupware/community/notice/services/noticeBoardService.ts`

- RED 검증: 기존 공지 서비스 테스트에 `isNotice` 파라미터 전달/매퍼 조건 계약을 검증한다.
- GREEN 검증: `mvn -q "-Dmaven.resources.skip=true" "-Dtest=NoticeBoardServiceImplTest" test`
- 인터페이스: 프론트 필터의 중요 공지 항목은 `isNotice=Y`, 공통코드 항목은 `noticeGubunCode`를 사용한다.
