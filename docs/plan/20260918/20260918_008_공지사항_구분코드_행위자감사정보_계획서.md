# 20260918_008 공지사항 구분코드 및 행위자 감사정보 계획서

## 근거

- 작업지시서: [20260918*008*공지사항*구분코드*행위자감사정보\_작업지시서.md](../../directions/20260918/20260918_008_공지사항_구분코드_행위자감사정보_작업지시서.md)
- DB 확인: `tb_board_post`, `tb_common_comment`, `tb_common_code_group`, `tb_common_code_item` MCP 스키마 조회

## 목표

공지사항 구분을 `NOTICE_GUBUN` 공통코드로 통일하고, 공지 및 댓글/답글의 등록·수정·삭제 행위자 정보를 백엔드 인증 사용자 기준으로 저장한다. 감사 이력 테이블은 추가하지 않고 최신 행위자만 보존한다.

## 작업 범위

### 1. DB

- `tb_board_post.notice_gubun_code` 추가
- `tb_board_post.last_modified_by_name` 추가
- `tb_common_comment.last_modified_by`, `last_modified_by_name` 추가
- `backend/DATABASE/20260918`와 `docs/database/20260918`에 동일 SQL/변경이력/롤백 작성
- `docs/database/db-schema.md` 갱신

### 2. 백엔드

- 공지 VO에 구분 코드 및 수정자명 반영
- 공지 Controller가 `LoginVO.id/name`을 Service로 전달
- 공지 등록·수정·삭제에서 payload 작성자 값을 사용하지 않도록 수정
- 공지 Mapper의 조회/등록/수정/삭제 SQL에 구분·행위자 컬럼 반영
- 댓글 VO/Mapper에 최신 행위자 필드 반영
- 댓글 등록은 인증 사용자 ID/이름, 수정·삭제는 인증 사용자 ID/이름으로 최신 행위자 저장
- 기존 작성자 기준 수정·삭제 권한 검사는 유지

### 3. 프론트엔드

- 공통코드 서비스 계약을 재사용하여 `NOTICE_GUBUN` 그룹의 사용 중 상세코드 조회
- 목록 상단 필터와 게시글 표시값을 `item_code`/`item_nm` 기준으로 연결
- 작성·수정 모달 제목 위에 구분 선택 필드 배치
- 목록/상세/저장 타입에 `noticeGubunCode`, 표시명 필드 반영
- 작성자 ID/이름을 저장 payload에서 제거하거나 서버가 무시하는 계약으로 정리

### 4. 테스트 및 검증

- 백엔드 Controller/Service/Mapper 계약 테스트 추가 또는 보강
- 프론트엔드 공통코드 필터·작성/수정 payload 테스트
- `cd frontend; npm run test -- ...; npm run build`
- `cd backend; mvn test`
- UI 변경은 375px, 768px, 1280px 브라우저에서 확인하고 결과 문서에 캡처 경로 기록

## 검증 기준

- 요청 payload에 다른 작성자 값을 넣어도 공지 등록·수정·삭제 행위자는 `LoginVO` 기준으로 저장된다.
- 댓글/답글 수정·삭제 시 기존 작성자 권한 제한이 유지되고 최신 행위자 정보가 저장된다.
- 공통코드 상세 항목이 필터와 작성/수정 선택지에 표시된다.
- DB 마이그레이션은 재실행 가능하고 롤백 스크립트가 신규 컬럼만 제거한다.
