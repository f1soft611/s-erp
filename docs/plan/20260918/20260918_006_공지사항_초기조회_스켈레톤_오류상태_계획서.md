# 20260918_006 공지사항 초기조회 스켈레톤 및 오류 상태 개선 계획서

## 근거 문서

## 요구사항 분석

- `CommunityNoticePage`는 초기 목록 조회와 무관한 1.5초 `setTimeout`으로 `isInitialLoading`을 종료하고 있다.
- API 응답이 늦으면 스켈레톤이 실제 데이터보다 먼저 사라질 수 있다.
- 목록 API 실패 시 오류 상태에서 콘텐츠가 렌더링되지 않아 사용자가 재조회할 수 없다.
- `DashboardPage`의 중앙 정렬 재시도 아이콘 패턴을 공지사항 오류 상태에 적용한다.

## 작업 범위

### 1. 초기 로딩 상태를 API 생명주기에 연결

- `CommunityNoticePage.tsx`의 초기 로딩 타이머와 cleanup을 제거한다.
- `loadNoticePosts`의 API 처리 `finally`에서 silent 여부에 따라 초기 로딩 또는 새로고침 상태를 종료한다.
- API 성공 시 기존 목록 매핑과 서버 revision 갱신을 유지한다.
- API 실패 시 기존 목록 초기화 및 오류 상태 저장을 유지한다.

### 2. API 실패 재조회 UI 추가

- `ReplayOutlined`와 `IconButton`을 사용해 오류 문구 없는 재조회 버튼을 추가한다.
- 오류 상태는 `minHeight: 100vh`, 중앙 정렬 레이아웃으로 표시한다.
- 버튼 클릭은 `loadNoticePosts()`를 호출한다.
- 재조회 중에는 `isInitialLoading`을 다시 true로 설정해 기존 스켈레톤을 표시한다.

### 3. 회귀 테스트 보강

- 초기 API가 지연되는 동안 스켈레톤이 유지되는지 검증한다.
- API 실패 후 스켈레톤이 제거되고 재조회 버튼만 표시되는지 검증한다.
- 재조회 버튼 클릭으로 API가 다시 호출되고 성공 목록이 표시되는지 검증한다.
- 기존 성공/빈 목록/작성 후 silent refresh 테스트와 충돌하지 않는지 확인한다.

## 영향 범위

- 프론트엔드 화면 컴포넌트 1개
- 공지사항 페이지 Vitest 테스트 1개
- 작업 계획/사양/결과 문서
- 백엔드, DB, API 계약 변경 없음
