# 20260918_007 공지사항 본문 이미지 즉시 업로드 계획서

## 근거

- 작업지시서: [20260918*007*공지사항*본문이미지*즉시업로드\_작업지시서.md](../../directions/20260918/20260918_007_공지사항_본문이미지_즉시업로드_작업지시서.md)
- DB 확인: `tb_board_file.post_id` NOT NULL 및 `tb_board_post` FK, `tb_common_file.owner_id` NOT NULL

## 목표

Tiptap 공지사항 에디터에서 클립보드 이미지를 저장 전 즉시 MinIO에 업로드하고 공개 URL을 본문 이미지 노드에 삽입한다. 본문 위치와 크기를 유지하고, 피드 접힘 상태의 미리보기와 펼침 상태의 원문 표시를 일관되게 제공한다.

## 작업 범위

### 프론트엔드

1. `NoticeComposerDialog`에 이미지 확장과 붙여넣기 업로드 흐름을 추가한다.
2. 업로드 중 플레이스홀더, 성공 교체, 실패 제거 및 알림 상태를 구현한다.
3. 이미지 너비 속성과 에디터 폭 기준 자동 축소를 직렬화한다.
4. 게시글 저장/수정 payload에 사용된 임시 이미지 참조를 포함한다.
5. `NoticeFeedList`와 콘텐츠 스타일에서 접힘/펼침 표시 및 반응형 이미지를 구현한다.
6. 공지사항 서비스/타입과 Vitest 테스트를 갱신한다.

### 백엔드

1. 게시글 ID 없이 호출 가능한 임시 이미지 업로드 API를 추가한다.
2. 업로드 파일을 허용 MIME/크기와 이미지 signature 기준으로 검증한다.
3. 임시 객체는 테넌트·사용자·토큰 prefix로 저장하고 공개 URL을 응답한다.
4. 게시글 생성/수정 시 payload의 임시 이미지 참조를 검증하고 `tb_board_file`에 `EMBEDDED`로 귀속한다.
5. 게시글 첨부 조회·삭제·게시글 삭제에서 `ATTACHMENT`와 `EMBEDDED`를 구분한다.
6. 만료된 미귀속 임시 객체 정리 정책과 실패 시 보상 삭제를 추가한다.

### DB

- `tb_board_file.file_usage_type varchar(20) NOT NULL DEFAULT 'ATTACHMENT'` 추가
- 허용값은 `ATTACHMENT`, `EMBEDDED`
- SQL, 변경 이력, 롤백은 `backend/DATABASE/20260918`와 `docs/database/20260918`에 동시 보관한다.
- 누적 스키마 문서 `docs/database/db-schema.md`를 갱신한다.

## 영향 범위

- 공지사항 작성/수정/목록/상세 및 일반 첨부파일 표시
- MinIO object key 및 공개 URL 설정
- 게시글 저장 요청 DTO와 파일 메타데이터 매퍼
- 기존 텍스트/Excel 붙여넣기, 이미지 없는 게시글에는 회귀가 없어야 한다.

## 검증 계획

- 프론트 집중 Vitest: 이미지 붙여넣기 위치, 실패 상태, HTML/JSON 직렬화, 피드 접힘/펼침
- 백엔드 집중 Maven 테스트: 임시 업로드 계약, MIME/크기 검증, 게시글 귀속, 일반 첨부 필터
- `npm run build`, `mvn test`
- Playwright 브라우저 검증: 375px/768px/1280px에서 작성·저장·피드 전환 및 스크린샷
- SQL 적용 후 `file_usage_type` 기본값/제약과 기존 첨부 조회 회귀 확인

## 제외

- 공개 URL 정책을 인증 URL 또는 서명 URL로 변경
- 동영상·오디오 본문 임베드
- 공지사항 전체 레이아웃 재설계
