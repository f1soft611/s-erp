## 목표

공지사항 작성 모달에서 `isNotice`를 선택하고 저장하며, 피드에는 실제 `NOTICE_GUBUN.itemNm`을 표시한다. 목록에는 `isNotice = 'Y'` 기준의 중요 공지 필터를 별도로 제공하고, 중요 공지만 강조색상을 사용하도록 화면 표시 규칙과 모달 여백을 정리한다.

## 작업 범위

### 1. 공지 페이지 데이터 표시

- `CommunityNoticePage.tsx`에서 `noticeGubunCode`를 공통코드 명칭 Map과 결합한다.
- `toNoticeFeedItem` 또는 호출부 변환 단계가 실제 구분명을 `NoticeFeedItem`에 전달한다.
- 구분명 미확인 시 코드값을 표시하고, 코드값도 없으면 기존 호환 라벨을 사용한다.
- 피드 상태 라벨은 고정된 `중요 공지/공지` 이분법을 사용하지 않는다.
- `isNotice = 'Y'`는 구분명과 별개로 중요 공지 강조 상태로 전달한다.

### 2. 필터와 모달 옵션

- `NoticeFilterBar.tsx`의 전체 항목은 목록 필터에서만 렌더링한다.
- `NoticeComposerDialog.tsx`는 전달받은 상세코드 옵션만 렌더링하며 전체 항목을 자체 생성하지 않는다.
- 신규 작성·수정 시 구분 선택 필드가 기존 코드값을 유지한다.
- 신규 작성·수정 시 `isNotice` 체크 상태를 payload에 포함하고 수정 초기값을 복원한다.
- 중요 공지 필터를 공통코드 필터보다 앞에 배치하고 `isNotice` query 계약으로 조회한다.

### 3. 강조 색상

- `isNotice === 'Y'`인 경우에만 기존 중요 공지 강조 배경/텍스트 색상을 적용한다.
- 기타 구분명은 일반 색상 토큰을 사용한다.
- `isNotice`는 기존 고정 여부 기능으로 유지하되 구분명 표시와 색상 판단을 대체하지 않는다.

### 4. 모달 여백

- 작성 모달 콘텐츠 내부의 상단 여백을 하단 여백과 동일 기준으로 정리한다.
- 구분·제목·본문 사이 간격은 동일한 spacing 값을 사용한다.
- 375px에서 입력 필드가 잘리거나 세로 겹침이 없도록 유지한다.
