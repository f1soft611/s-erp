# MinIO 공지첨부 업로드 오류 수정 계획서

## 목표

공지사항 첨부 업로드에서 MinIO 버킷 관리 권한이 없어도 사전 생성된 버킷에 파일을 업로드할 수 있게 하고, 실패 시 실제 원인을 추적할 수 있도록 한다.

## 원인 가설

- 현재 `CommonFileServiceImpl`은 MinIO 업로드 중 발생한 모든 예외를 cause 없이 500 예외로 다시 생성한다.
- 현재 `MinioStorageService.upload`는 업로드 전 항상 `bucketExists`와 필요 시 `makeBucket`을 호출한다.
- 배포 가이드는 버킷을 사전에 생성하는 흐름이므로, 애플리케이션 계정이 객체 업로드 권한만 가지고 있으면 버킷 조회/생성 단계에서 실패할 수 있다.
- 추가 로그에서 `SignatureDoesNotMatch`가 확인되었고, Maven 의존성 트리에서 중복 선언 때문에 실제 런타임 MinIO Java client가 의도한 버전보다 낮은 `8.5.7`로 해석되는 것이 확인되었다.
- 추가 검색에서 `CommonFileServiceImpl`이 `storage.bucket` 대신 `document-attachments` 상수를 직접 업로드 bucket으로 사용하고 있어, `STORAGE_BUCKET` 변경 시 공통 첨부 업로드에는 반영되지 않는 것이 확인되었다.

## 작업 항목

### Task 1: 원인 보존 테스트 및 구현

- `CommonFileServiceTest`에 MinIO 업로드 실패 원인 예외가 보존되는지 검증을 추가한다.
- `CommonFileServiceImpl`에서 업로드 실패를 로그로 남기고 `ResponseStatusException` cause로 전달한다.

### Task 2: 버킷 자동 생성 정책 분리

- `MinioStorageServiceTest`를 추가해 기본 업로드가 `bucketExists`에 의존하지 않음을 검증한다.
- `MinioStorageService`에 `storage.autoCreateBucket` 설정을 추가한다.
- 기본값은 `false`로 두고, `true`일 때만 기존 `ensureBucketExists`를 수행한다.
- `CommonFileServiceImpl`이 업로드 bucket을 `storage.bucket` 설정에서 읽도록 변경한다.
- 공지사항 서비스에 남아 있던 미사용 bucket 설정 필드를 제거한다.

### Task 3: 설정과 문서 정합화

- dev/prod properties에 `storage.autoCreateBucket=${STORAGE_AUTO_CREATE_BUCKET:false}`를 추가한다.
- 중복된 오래된 MinIO client 의존성을 제거한다.
- `MinioStorageConfigTest`가 새 속성과 MinIO client 단일 버전 선언을 검증하도록 확장한다.
- Windows MinIO 배포 가이드에 기본 버킷 정책을 기록한다.

### Task 4: 검증 및 결과 문서

- `cd backend; mvn dependency:tree "-Dincludes=io.minio:minio"`로 실제 MinIO client 버전을 확인한다.
- `cd backend; mvn "-Dtest=CommonFileServiceTest,NoticeBoardServiceImplTest" test`를 실행한다.
- `cd backend; mvn "-Dtest=CommonFileServiceTest,MinioStorageServiceTest,MinioStorageConfigTest" test`를 실행한다.
- 결과 문서에 원인, 변경 파일, 검증 결과, 운영 확인 사항을 기록한다.

## DB 영향

DB 스키마 및 데이터 변경은 없다.
