## 요구사항 분석

- `TiptapCommentThread`는 각 댓글 항목이 렌더링될 때 본문과 답글 버튼이 그대로 유지된 상태로 수정 입력을 별도의 하위 블록으로 추가하고 있다.
- 수정 버튼을 누르면 `isEditing` 상태가 true가 되지만, 원래 본문 영역은 그대로 남아 있고 에디터가 이후에 붙는 구조다.
- UX 요구사항은 기존의 이름/날짜/내용/답글 부분 자체를 수정 입력 UI로 교체하라는 것으로, 이는 컴포넌트 렌더 구조를 재배치하는 작업으로 볼 수 있다.

## 작업 범위 분해 (프론트엔드 전용)

1. **수정 상태 렌더 구조 재구성**
   - `CommentItem`의 수정 상태에서 기존 프로필/본문/답글 섹션이 그대로 남지 않도록 조건부 렌더링을 재배치한다.
   - 편집 중인 댓글/답글은 본문 내용을 에디터로 교체하고, 수정 취소 버튼을 유지한다.
2. **기존 기능 영향 최소화**
   - 생성, 삭제, 첨부파일, 답글 작성 로직은 기존 로직을 유지한다.
   - 수정 진입 방식은 `댓글 메뉴 > 수정` 기존 플로우를 유지한다.
3. **회귀 검증 추가**
   - 기존 `feed-components.test.tsx`에서 수정 동작의 렌더 구조를 검증하는 테스트를 보강한다.
   - 반드시 기존 편집 로직이 동작하는 상태(수정 저장, 취소)를 확인한다.
