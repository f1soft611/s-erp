# 영업관리 타입별 소수점 계획서

## 목표

모듈과 기존 숫자 컬럼 타입별로 정책을 관리하고 영업 화면의 입력·계산·저장 결과가 일치하도록 한다.

## 작업

1. 읽기 전용 DB MCP와 기존 코드로 영업 데이터의 컬럼 정밀도, 계산·검증, 화면별 컬럼과 사용처를 조사한다.
2. 정책관리의 모듈별 세 타입 값 및 기존 정책 호환, 읽기 쉬운 변경 이력, F1-Grid 우선순위와 정책 변경 후 캐시 갱신을 구현한다.
3. 영업 숫자 컬럼을 수량·순서·No와 나머지로 분류하고 행 번호, 문자 번호, 명시적 예외의 동작을 확인한다.
4. 영업 스키마를 최대 6자리까지 확장하고 역변환 시 데이터 손실을 방지하는 롤백과 양쪽 스키마 이력을 작성한다.
5. 영업 API와 프론트의 자릿수 검증 및 계산에 동일한 정책·컬럼별 우선순위를 적용한다. 관련 타 업무 공통 계산의 기존 동작을 보존한다.
6. 입력값과 계산값의 저장·재조회, 0~6자리, 반올림 및 오류 경로를 자동화 테스트하고 관련 빌드·브라우저 흐름을 검증한다.
7. F1-Grid 문서와 결과 문서, 스키마 누적 문서를 갱신한다.
8. 그리드 숫자 붙여넣기에서도 수량·단가 편집과 같은 계산 콜백을 순서대로 적용하고, 동일 행의 여러 값을 붙여넣는 회귀 사례를 검증한다.
9. 영업 저장 중 정책을 조회하지 못한 경우 기본값을 실제 정책으로 오인하지 않도록 조회 성공 상태를 분리하고 저장을 차단한다.
10. 수주·견적·출하의 표시된 금액이 현재 정책과 다르면 수동 부가세를 보존하면서 저장 전 재계산 필요성을 안내한다. 자동 재계산과 서버 동시 변경 방지는 별도 검증한다.
11. 영업 저장 요청에 선택적인 소수점 정책 스냅샷을 포함하고 서버에서 계산에 사용할 정책과 비교해 불일치 시 저장을 거부한다. 기존 스냅샷 없는 API 호출은 호환한다.
11. (후속 피드백) 정책 변경 이력은 변경 전·후를 항목 단위로 비교해 바뀐 자릿수·0 표시·반올림·값만 강조하고 두 값 사이에 화살표를 둔다.
12. 숫자 원문을 십진 문자열로 보존하는 공통 계산을 먼저 테스트하고, 이후 영업 입력·API 응답·계산·표시·전송을 단계적으로 연결한다. 기존 숫자 기반 타 업무 계약은 유지한다.
13. 후속 피드백에 따라 정밀 십진 셀 직접 편집에서 정책의 자릿수를 초과하는 입력을 거부한다. 유효한 기존 입력과 원문 정밀도는 유지하고, 그리드 셀 붙여넣기의 검증 동작은 별도로 유지한다.
14. 금액은 `currency`, 단가는 `decimal` 정책으로 분리한다. 서버·프론트의 금액 계산과 입력 검증, 정책 스냅샷, 모든 영업 목록·상세·인쇄 표시를 함께 변경하고 서로 다른 자릿수와 반올림의 저장·재조회 사례를 검증한다.
15. 수주 데이터가 정책보다 먼저 조회되거나 열린 화면의 금액 정책이 변경될 때 현재 상세 행의 합계가 새 정책으로 표시되는지 회귀 검증한다.
16. 다른 개발자도 재사용할 수 있도록 타입 정책과 저장에 영향을 주는 컬럼별 예외의 공통 계약을 마련한다. 프론트가 기준 파일을 사용하고 서버 빌드가 동일한 파일을 리소스로 포함한다. 수주·견적·출하·출하계획의 입력 검증, 계산, 저장 충돌 확인을 연결하고, 타입 기본값과 컬럼별 부분 예외 및 서로 다른 배포 버전의 충돌을 검증한다.
17. 서버의 컬럼별 규칙 해석을 영업 정책 래퍼에서 공통 도우미로 분리해 다른 모듈도 자신의 타입별 기본 규칙을 제공하여 사용할 수 있게 한다. 모듈별 정책 조회와 업무 계산은 각 업무의 책임으로 유지한다.
18. 출하 저장을 막는 거래명세서 조회 오류를 기존 출하 헤더와 테넌트 범위를 사용해 수정하고 회귀 검증한다. 공유 DB 스키마는 변경하지 않는다.

## 검증 원칙

- 테스트를 먼저 작성하여 기존 2자리 계산과 단일 모듈 정책으로 실패하는 것을 확인한다.
- 프론트와 서버 계산 결과가 같은지, 타입별 정책과 별도 컬럼 설정이 각각 반영되는지 검증한다.
- 스키마 변경은 기존 정수부 범위를 유지하고 롤백 시 정밀도 손실 가능성을 검사한다.
