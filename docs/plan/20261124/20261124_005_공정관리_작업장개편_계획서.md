# 공정관리 작업장 개편 계획서

- 작업지시서: [작업장 개편 작업지시서](../../directions/20261124/20261124_005_공정관리_작업장개편_작업지시서.md)

## 단계

1. 읽기 전용 MCP로 `tb_process`, `tb_process_group`, 외래키, `process_id` 참조 여부와 병합 후보 건수를 확인한다. (완료: 작업장 3, 공정 4, 병합 후 4)
2. DB: 매핑 테이블 생성, 기존 공정 병합·이관, `tb_process.group_id` 제거 스크립트와 롤백·변경 이력을 `docs/database/20261124`, `backend/DATABASE/20261124`에 작성하고 `db-schema.md`를 갱신한다.
3. 백엔드: 트리 조회/저장 계약을 작업장(`g:`)과 연결 행(`m:`)으로 바꾸고, 공정 마스터 조회·저장 API(`/masters`, `/masters/save-batch`)를 추가한다. 기존 레이어(controller/service/impl/domain) 구조를 유지한다.
4. 프론트엔드: 트리 문구를 "작업장"으로 변경하고 연결 행은 읽기 전용으로 표시한다. `공정 설정` 모달과 `공정 선택` 모달을 `components/`에 추가하고 훅·서비스·타입을 확장한다.
5. 테스트: 백엔드 서비스·매퍼·컨트롤러 테스트와 프론트엔드 공정관리 테스트를 새 계약에 맞게 갱신·추가한다.
6. 검증: 프론트 빌드·테스트, 백엔드 `mvn test`, `javac --release 8`, 실제 브라우저 화면 확인 후 결과 문서를 작성한다.

## 위험과 대응

- 데이터 이관은 되돌릴 수 없는 변경이므로 롤백 스크립트에서 마스터를 매핑 수만큼 복제해 `group_id`를 복원한다.
- 로컬에 PostgreSQL이 없으면 마이그레이션 SQL은 실행 검증하지 못한다. 이 경우 결과 문서에 미검증으로 기록한다.
