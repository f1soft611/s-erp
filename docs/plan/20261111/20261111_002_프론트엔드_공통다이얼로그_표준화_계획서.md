# 프론트엔드 공통 다이얼로그 표준화 계획서

## 목표

프론트엔드에서 공통 셸을 사용하지 않는 MUI 다이얼로그를 `CommonDialog`로 통일하고 기존 동작을 보존한다.

## 구현 범위

- 공통 기반: `CommonDialog.tsx`, `UnsavedChangesConfirmDialog.tsx`
- 비동기 브라우저 확인창 대체: `frontend/src/shared/hooks/useCommonConfirmDialog.tsx`
- 대시보드/F1-Grid: `MenuFavoriteContextMenu.tsx`, `TimeEditor.tsx`, `F1GridTestPage.tsx`
- 시스템 설정: `RoleManagementPanel.tsx`, `SystemPolicyPage.tsx`, `PolicyEditor.tsx`
- 공통코드/자료실/알림: `CommonCodeManagementPanel.tsx`, `ArchiveBoardPage.tsx`, `ArchiveFileEditDialog.tsx`, `NotificationInboxPage.tsx`
- 문서관리/공유 UI: `DocumentApprovalDetailFeed.tsx`, `DocumentReferenceAddDialog.tsx`, `ImageViewerDialog.tsx`
- 브라우저 확인창 사용처: sales statement, delivery, delivery plan, and sales order create/status components
- 테스트: 공통 다이얼로그, 공유 확인창, 이미지 뷰어 및 위 각 기능의 기존 회귀 테스트
- 지침: `frontend/AGENTS.md`

## 실행 순서

1. `common-dialog.test.tsx`에 `sm` 600px 및 `xl` 1200px 너비, 사용자 지정 제목 ID와 닫기 버튼 이름의 테스트를 추가한다.
2. `unsaved-changes-confirm-dialog.test.tsx`에 공통 닫기 버튼과 기존 액션 순서를 확인하는 테스트를 추가한다.
3. 테스트를 실행해 새 동작의 실패를 확인한 후 `CommonDialog`의 크기/접근성 API를 보완한다.
4. `UnsavedChangesConfirmDialog`를 공통 셸 기반으로 전환한다.
5. 비동기 `useCommonConfirmDialog` 훅을 테스트 우선으로 구현하고 브라우저 확인창을 쓰는 기능에 적용한다.
6. 대시보드와 F1-Grid 다이얼로그를 전환하고 해당 회귀 테스트를 실행한다.
7. 시스템 정책/역할 관리 다이얼로그를 전환하고 해당 회귀 테스트를 실행한다.
8. 공통코드, 자료실, 알림, 문서관리, 이미지 뷰어의 다이얼로그를 전환하고 기존 업무 테스트를 실행한다.
9. `frontend/AGENTS.md`에 공통 다이얼로그 사용 원칙과 네이티브 대화상자 금지 원칙을 추가한다.
10. `rg "<Dialog\\b" frontend/src` 및 네이티브 대화상자 검색 결과를 확인한다.
11. 전체 Vitest, `npm run build`, 필수 뷰포트 브라우저 렌더링을 확인하고 결과 문서를 작성한다.

## 검증 기준

- 크기 옵션은 `xs=480px`, `sm=600px`, `md=820px`, `lg=990px`, `xl=1200px`을 사용한다.
- `titleId` 및 닫기 버튼 접근성 이름은 기존 의미를 보존하고 기본값은 자동 생성 ID 및 `닫기`이다.
- `useCommonConfirmDialog`는 `Promise<boolean>`을 반환하고 확인은 `true`, 취소·Escape·바깥 클릭은 `false`로 완료한다.
- 네이티브 브라우저 확인창의 각 메시지와 진행/취소 결과가 그대로 유지된다.
- 기존 submit/cancel, 확인, 선택, 에러, 로딩, Escape/바깥 클릭 처리와 모달 내부 콘텐츠를 보존한다.
- 일반 모달만 `CommonDialog` 셸로 바꾸며 팝오버, 메뉴, 드로어 및 인쇄 포털은 유지한다.
- PWA 설치 이벤트의 `prompt()` 호출은 설치 UX API이므로 네이티브 `window.prompt()` 대화상자와 구분해 유지한다.
- 전체 테스트와 빌드가 통과하고 375px, 768px, 1280px에서 콘텐츠와 액션이 표시된다.

## 범위 통제

프론트엔드 공통 모달, 네이티브 확인창 대체 훅, 적용 호출부, 테스트 및 지침만 변경한다. 백엔드, API, 데이터베이스 및 무관한 화면/레이아웃은 변경하지 않는다.
