- 상세 사양서: [20261111_003 상세사양서](../../spec/20261111/20261111_003_작업표준서_등록_레시피_화면_상세사양서.md)

## 판단 및 가정

- 메뉴는 DB(`tb_menu`) 기반이므로 메뉴 추가는 seed SQL로 관리한다. 현재 DB에 `CO_WORK_STD*` 메뉴와 `/co/work-standard*` 경로는 없음을 읽기 전용 MCP로 확인했다.
- 상위 메뉴 `작업표준서 관리`는 신규 루트 메뉴(`CO_WORK_STD`, `/co/work-standard`)로 만들고 샘플처럼 `기준정보 관리`와 `전자결재 관리` 사이(sort_order 2)에 둔다. 기존 `전자결재 관리`가 2이면 3으로 이동한다.
- 하위 메뉴 URL은 `/co/work-standard/work-standard-recipe`, 화면 pageKey는 마지막 세그먼트 `work-standard-recipe`이다.
- 샘플의 `작업표준서 현황`, `배합비 역전개`, `원료 대체 등록`은 이번 범위가 아니므로 추가하지 않는다.
- 백엔드 미구현이므로 목록·상세는 프론트엔드 예시 데이터로 표시하고, 저장·삭제와 기본정보 상단 업무 버튼(복사/버전 개정/샘플→양산 이관)은 비활성 상태로 레이아웃만 둔다.
- 품목명·원료 선택은 이미 운영 중인 품목 마스터 조회 API(`fetchMaterials`)와 공통 `MasterPicker`를 재사용한다.
- 샘플의 `엑셀` 버튼은 배합비 F1Grid 컨텍스트 메뉴의 기본 엑셀보내기로 대체하지 않고 이번 범위에서 제외한다.

## 구현 단위

1. DB: `20261111_003` 메뉴 seed/변경 이력/롤백 (docs·backend 동일 사본)
2. 프론트엔드 `frontend/src/pages/co/work-standard/recipe/`
   - `WorkStandardRecipePage.tsx`: 화면 조립(헤더·검색·목록·기본정보·탭)
   - `components/WorkStandardSearchArea.tsx`: 통합검색 + 상세검색
   - `components/WorkStandardListGrid.tsx`: 좌측 목록(F1Grid, 행 선택)
   - `components/WorkStandardBasicInfo.tsx`: 기본정보 폼
   - `components/WorkStandardFormulaTab.tsx`: 배합비 툴바·F1Grid·합계
   - `data/`: 예시 데이터, 검색 필드, 배합비 컬럼/계산
   - `services/`: 예시 데이터 조회·필터, 품목 picker 검색
   - `types/`: 작업표준서/배합비 타입
3. 대시보드 연결: `DashboardContent.tsx` 분기, `dashboardData.tsx` 페이지 설명
4. 테스트: `frontend/tests/work-standard-recipe-page.test.tsx` (필터링·선택·배합비 계산)
