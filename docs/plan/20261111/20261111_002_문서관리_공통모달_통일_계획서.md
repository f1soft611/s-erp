# 문서관리 공통 모달 통일 계획서

## 목표

문서관리의 일반 확인·입력 모달을 `CommonDialog`로 통일하되 기존 처리 흐름과 화면별 동작을 유지한다.

## 구현 파일

- `frontend/src/shared/components/CommonDialog.tsx`: 기존 너비 체계를 유지하기 위한 `sm` 크기(600px)를 추가한다.
- `frontend/tests/common-dialog.test.tsx`: `sm` 크기 너비를 검증한다.
- `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`: 상단 고정/해제 확인을 `CommonDialog`로 전환한다.
- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`: 문서 유형 변경과 본문 교체 확인을 전환한다.
- `frontend/src/pages/groupware/documents/write/components/DocumentApprovalSettingsDialog.tsx`: 템플릿 변경 폐기 확인을 전환한다.
- `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`: 결재 취소·문서 삭제 확인을 전환한다.
- `frontend/src/pages/groupware/documents/write/components/DocumentReferenceAddDialog.tsx`: 참조자 추가 입력창을 전환하고 기존 `sm` 너비를 유지한다.
- `frontend/tests/document-write-page.test.tsx`, `frontend/tests/document-approval-settings-dialog.test.tsx`: 기존 확인/취소/제출 흐름의 회귀를 확인한다.
- `docs/spec/20261111/20261111_002_문서관리_공통모달_통일_상세사양서.md`: 확정 동작과 검증 기준을 기록한다.
- `docs/result/20261111/document-management-common-dialogs/`: 실제 변경과 검증 결과 및 스크린샷을 기록한다.

## 실행 순서

1. `common-dialog.test.tsx`에 `size="sm"`일 때 600px 너비를 기대하는 테스트를 추가하고 단독 실행해 실패를 확인한다.
2. `CommonDialogSize`에 `sm`을 추가하고 너비 계산을 `xs=480`, `sm=600`, `md=820`, `lg=990`으로 갱신한 뒤 해당 테스트를 통과시킨다.
3. 문서관리 테스트에서 상단 고정/해제, 문서 유형 변경, 본문 교체, 템플릿 변경 폐기, 결재 취소, 문서 삭제, 참조자 추가 흐름을 실행해 기준 동작을 확인한다.
4. 직접 MUI `Dialog`를 쓰는 취소·삭제·참조자 추가 창을 `CommonDialog`로 옮긴다. 참조자 추가는 `size="sm"`을 사용한다.
5. 문서관리 내부의 `UnsavedChangesConfirmDialog` 사용처를 `CommonDialog`로 바꾸고 버튼 순서, 라벨, 기본 포커스, 비활성화, 닫기 콜백을 보존한다.
6. 문서작성·설정 관련 테스트를 실행해 모든 기존 확인 및 변경 흐름이 통과하는지 확인한다.
7. `npm run build`를 실행하고 375px, 768px, 1280px 브라우저에서 대표 확인/입력 모달을 확인한다.
8. 결과 문서와 비식별 화면을 결과 디렉터리에 기록한다.

## 테스트 기준

- 새 `sm` 옵션은 600px 너비를 사용하고 기존 `xs`/`md`/`lg` 크기 기대를 바꾸지 않는다.
- 각 모달은 기존 제목·설명·라벨·오류/안내 메시지 및 액션 핸들러를 유지한다.
- 제출 중 닫기·취소·확인 버튼은 기존과 같은 활성/비활성 조건을 따른다.
- 문서관리 영역 내 일반 확인·입력 모달은 `CommonDialog`를 사용하고 이미지 뷰어·팝오버는 유지한다.
- 관련 Vitest, 빌드, 모바일/태블릿/데스크톱 브라우저 검증을 완료한다.

## 범위 통제

공유 `UnsavedChangesConfirmDialog` 자체와 다른 메뉴의 호출부는 수정하지 않는다. API, 백엔드, 데이터베이스, 이미지 뷰어 및 결재 업무 로직도 변경하지 않는다.
