# 최근 사용 메뉴 PC 유지 계획서

**근거:** [작업지시서](../../directions/20261103/20261103_003_최근사용메뉴_PC유지_작업지시서.md)

**목표:** 같은 PC·브라우저에서 최근 사용 메뉴 5건을 세션과 관계없이 유지한다.

**설계:** 최근 메뉴만 `localStorage`로 옮긴다. 기존 키와 자료 구조를 유지하고 최초 복원 시 현재 `sessionStorage` 기록을 대체 근거로 읽는다. 서버 저장은 PC 범위를 넘어가며 DB 변경이 필요하므로 제외한다. 페이지 상태 공통 훅은 그대로 둔다.

## 구현 및 검증

- [x] `frontend/tests/dashboard-sidebar.test.tsx`: 최근 메뉴 저장 후 로그아웃·재로그인·앱 재마운트 시 유지, 기존 세션 기록 이관, 잘못된 저장값 복구 테스트를 추가하고 실패 확인.
- [x] `frontend/src/pages/dashboard/DashboardPage.tsx`: 최근 메뉴 lazy initializer가 local 우선/session 대체로 읽고 자료 구조를 검사하도록 변경. `usePageSessionState` 대신 `useState`로 최근 메뉴를 관리하고 기존 write effect를 local 저장으로 변경. local 저장 성공 후 기존 session 키 제거. 로그아웃에서는 최근 메뉴를 지우지 않고 공통코드 상태 삭제 유지.
- [x] 기존 최신순·중복 제거·5건 제한·검색 페이지 제외를 유지.
- [x] `frontend`에서 관련 테스트, `npm run build`, `npm run lint -- src\pages\dashboard\DashboardPage.tsx tests\dashboard-sidebar.test.tsx` 실행. npm의 인자 전달 문제로 targeted 테스트는 아래 직접 러너를 사용했다. 관련 파일 전체 실행의 기존 실패는 결과 문서에 별도 기록했다.
- [x] 기존 4173 S-ERP 서버를 재사용해 가상 데이터만으로 브라우저 재접속·로그아웃·재로그인·최근 메뉴 클릭을 확인. 375/768/1280 화면을 캡처하고 결과 문서에 기록. 기존 서버는 종료하지 않는다.

```powershell
node node_modules\vitest\vitest.mjs run tests\dashboard-sidebar.test.tsx tests\page-session-state.test.tsx -t 'persistent recent menus|page session state|shows recent menu history'
```

## 영향 범위

프론트엔드 저장 정책만 변경한다. 기존 PC 단위 키를 유지하며 계정별 저장 정책을 새로 도입하지 않는다. 인증 정보·사용자 프로필·업무 데이터는 최근 메뉴에 추가 저장하지 않는다. 백엔드/DB 변경 및 MCP 조회는 해당하지 않는다.
