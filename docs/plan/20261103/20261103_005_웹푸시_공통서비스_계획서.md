# 공통 Web Push 서비스 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 현재 공통 알림으로 발행되는 업무 멘션과 쪽지 도착 알림을 명시적으로 동의한 브라우저 기기에 하나의 백엔드 Web Push 서비스로 전달한다.

**Architecture:** 기존 인앱 알림과 쪽지 저장/읽음 기능을 유지한다. 공통 알림 저장 트랜잭션에 outbox 작업을 함께 기록하고, 공통 워커가 기기 구독별 delivery 상태를 관리하면서 표준 Web Push를 발송한다. 브라우저 Service Worker와 인증된 구독 API는 기기별 동의/해제만 담당하며, 알림 상세 권한 검증은 기존 API를 계속 사용한다.

**Tech Stack:** Java 8 호환 Spring Boot/eGovFrame, PostgreSQL/MyBatis, Spring scheduling, React/TypeScript/Vite, Browser Service Worker/Push API, 표준 VAPID Web Push, Vitest 및 JUnit/Mockito.

## 근거와 범위

- 승인 설계: [공통 웹 푸시 서비스 설계](../../superpowers/specs/2026-11-03-web-push-design.md)
- 작업지시 및 단계 경계: [공통 기능 후속 확장 작업지시서](../../directions/20261102/20261102_007_공통기능_후속확장_작업지시서.md)
- 현재 공통 알림 생성은 `NotificationServiceImpl.createEvent`에서만 두 유형(`APPROVAL_COMMENT_MENTION`, `DIRECT_MESSAGE_RECEIVED`)을 허용한다. 쪽지 알림은 `DirectMessageServiceImpl.saveMessage`에서 기존 계약을 사용한다.
- 새 결재 요청·승인·반려 이벤트를 추가하지 않는다. 후속 로드맵 3단계에서 이벤트·수신자 정책을 확정한다.
- DB MCP를 통해 `tb_notification`, `tb_direct_message`, `tb_direct_message_thread` 메타데이터와 현재 테이블 목록을 확인했다. 푸시 관련 테이블은 없고, 행 데이터는 조회하지 않았다.
- Java 운영 코드는 Java 8 호환을 유지한다. Web Push 라이브러리는 구현 사양 전에 유지 상태, Java 8 지원 여부, payload 암호화/VAPID 및 라이선스를 검토하고 선택한다. 검증된 라이브러리가 없으면 의존성 추가 전 별도 설계 결정을 요청한다.
- 실제 DB에는 DDL을 적용하지 않는다. migration 및 rollback은 저장소의 날짜별 이력으로만 작성한다.
