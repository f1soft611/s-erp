# 현황 검색결과 안내 및 통합검색 일치어 강조 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 문서현황·수주현황의 결과 안내를 통일하고, 통합검색의 제목과 설명에서 검색어 일치 텍스트를 강조한다.

**Architecture:** `PageMessageArea`에 기본 스타일을 유지하는 선택적 compact 간격을 추가하고, 새 `SearchResultMessage`가 두 현황 화면의 성공 결과 건수와 닫기 동작을 공통 처리한다. `UnifiedSearchPage`는 현재 안전한 React `<mark>` 강조기를 제목과 설명 모두에 사용한다.

**Tech Stack:** React, TypeScript, MUI, Vitest, Testing Library, Playwright.

## Task 1: 공통 결과 메시지 테스트 및 컴포넌트

**Files:** `frontend/tests/notification.test.tsx`, `frontend/src/shared/components/PageMessageArea.tsx`, `frontend/src/shared/components/SearchResultMessage.tsx`, `frontend/src/shared/components/EmptySearchResultMessage.tsx`

- [x] **Step 1: compact 레이아웃 테스트 추가**

`notification.test.tsx`에 `PageMessageArea`의 `compact` 사용 시 외곽 Box가 `paddingTop: 8px`, `paddingBottom: 0px`이고, prop 없이 렌더링한 일반 오류는 기존 `16px` 간격이라는 회귀 검증을 추가한다. 아래쪽은 각 페이지 그리드의 기존 `pt: 1`이 더해져 Alert와 그리드 사이 간격이 8px이 된다.

- [x] **Step 2: 새 결과 메시지 테스트 추가**

`frontend/tests/search-result-message.test.tsx`에 다음 동작 테스트를 작성한다.

```tsx
it('shows a dismissible empty-result status without a reset action', () => {
  render(<SearchResultMessage resultCount={0} />);
  const message = screen.getByRole('status');
  expect(message).toHaveTextContent(
    '조회 결과가 없습니다. 조회 기간을 넓히거나 검색 조건을 변경해 주세요.',
  );
  expect(within(message).getByRole('button', { name: 'Close' })).toBeVisible();
  expect(within(message).queryByRole('button', { name: '검색 조건 초기화' })).not.toBeInTheDocument();
});

it('formats a positive result count and hides after close', () => {
  const { rerender } = render(<SearchResultMessage resultCount={1234} />);
  expect(screen.getByRole('status')).toHaveTextContent('조회 결과 총 1,234건입니다.');
  fireEvent.click(screen.getByRole('button', { name: 'Close' }));
  expect(screen.queryByRole('status')).not.toBeInTheDocument();
  rerender(<SearchResultMessage resultCount={1234} />);
  expect(screen.queryByRole('status')).not.toBeInTheDocument();
});
```

- [x] **Step 3: RED 확인**

Run: `cd frontend; node .\node_modules\vitest\vitest.mjs run tests\notification.test.tsx tests\search-result-message.test.tsx`

Expected: 새 prop/import/component가 아직 구현되지 않아 실패한다.

- [x] **Step 4: compact prop 구현**

`PageMessageAreaProps`에 `compact?: boolean`을 추가하고 wrapper `sx`의 세로 여백만 opt-in으로 바꾼다. compact result Alert 아래에는 그리드 컨테이너의 `pt: 1`이 남아 있으므로 wrapper의 `pb`를 0으로 둔다.

```tsx
<Box sx={{
  px: { xs: 1.5, sm: 3 },
  pt: compact ? 1 : 2,
  pb: compact ? 0 : 2,
}}>
```

- [x] **Step 5: SearchResultMessage 구현**

`resultCount` 숫자 prop을 받고, 0일 때 상세검색 조건 변경 안내, 양수일 때 `toLocaleString()` 건수 문구를 사용한다. 첫 렌더에는 열려 있고 Alert 닫기 시 닫힌다. `PageMessageArea`에 `severity="info"`, `role="status"`, `compact`, `onClose`를 전달하며 action/reset은 전달하지 않는다. 기존 `EmptySearchResultMessage.tsx`를 제거한다.

Expected: compact 및 결과 메시지 테스트 통과, 기존 PageMessageArea 오류 테스트 동작 보존.

## Task 2: 문서현황·수주현황 결과 메시지 연결

**Files:** `frontend/src/pages/groupware/documents/status/DocumentStatusPage.tsx`, `frontend/src/pages/sales/order/status/SalesOrderStatusPage.tsx`, `frontend/tests/document-status-page.test.tsx`, `frontend/tests/sales-order-status-page.test.tsx`

- [x] **Step 1: 기존 0건 테스트를 새 동작으로 갱신**

문서현황 및 수주현황의 “검색 조건 초기화” 버튼 클릭/기본 날짜 복구 기대를 제거한다. 대신 0건 안내 문구, info status, Alert X 버튼, 초기화 action 부재를 검증한다.

- [x] **Step 2: 양수 결과 및 닫힘 테스트 추가**

각 페이지에서 성공 응답 후 양수 count가 안내되는지 검증한다. 닫은 뒤 성공 조회를 새로 시작하여 결과가 다시 도착하면 메시지가 재노출되는지 확인한다. 문서현황은 API `totalRowCount`, 수주현황은 결과 `rows.length`에 맞는 수를 사용한다.

- [x] **Step 3: 페이지 RED 확인**

Run: `cd frontend; node .\node_modules\vitest\vitest.mjs run tests\document-status-page.test.tsx tests\sales-order-status-page.test.tsx`

Expected: 기존 컴포넌트 API/초기화 버튼 때문에 새 결과 건수 및 닫기 기대가 실패한다.

- [x] **Step 4: 페이지 연결**

두 페이지 import를 `SearchResultMessage`로 바꾸고 현재 빈 상태 조건을 보존한다. 문서현황은 기존 `list.totalRowCount === 0` 조건을 유지하며 성공한 양수 결과에도 안내를 표시한다. 수주현황은 `list.hasLoaded && !list.loading && !list.initialLoad.loading && !search.defaultsError && !list.error` 조건을 유지하고 양수/0건 모두 결과 메시지를 렌더링한다. 문서현황의 상응하는 성공 gate도 그대로 사용한다.

```tsx
{successfulListLoad ? (
  <SearchResultMessage resultCount={list.totalRowCount} />
) : null}
```

수주현황은 `resultCount={list.rows.length}`를 전달한다. 두 페이지에서 공통 메시지는 검색 영역 아래, 그리드 위에 둔다.
