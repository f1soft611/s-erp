# 20261002_011 기안양식 본문 에디터 구현 계획서

> 작업지시서: [20261002_011 기안양식 본문 에디터 작업지시서](../../directions/20261002/20261002_011_기안양식_본문에디터_작업지시서.md)

**목표:** 기안양식 행의 문서 액션에서 본문 작성/수정 모달을 열고, 본문과 붙여넣은 표·이미지를 기존 기안양식/공통 파일 저장 구조에 tenant 범위로 영속화한다.

**방식:** F1-Grid의 공개 `renderCell`로 행 액션을 제공하고, `CommonDialog` 안의 Tiptap 편집기로 선택 양식 본문을 관리한다. 기존 기안양식 템플릿 JSONB/HTML과 `tb_common_file`을 사용한다. 이미지 업로드는 전용 임시 API 및 `drafting-work-form-temp` 객체 prefix를 사용하며 임시 객체에는 `s-erp-temp-owner=drafting-work-form` tag를 붙인다. 저장 시 tag를 제거하며 영구 prefix로 이동하고 인증된 고정 이미지 URL로 다시 쓴다. 신규 DB 컬럼/테이블은 만들지 않는다.

**기술 스택:** React 19, TypeScript, MUI, Tiptap, Vite/Vitest, Spring/eGovFrame, MyBatis, PostgreSQL, MinIO.

## 설계 근거와 DB 영향

- read-only PostgreSQL MCP `list_tables`에서 `tb_drafting_work_category` 및 `tb_common_file`이 있음을 확인했다.
- `describe_table(tb_drafting_work_category)`에서 `drafting_work_template_json JSONB`, `drafting_work_template_html TEXT`를 확인했다. `drafting_work_template_text`는 존재하지 않으므로 추가하지 않고 텍스트는 편집기/HTML에서 파생한다.
- `describe_table(tb_common_file)`에서 `tenant_id`, `owner_type`, `owner_id`, object metadata, `file_usage_type`을 확인했다. 기존 `EMBEDDED` 용도를 `DRAFTING_WORK_TEMPLATE` owner type과 함께 사용한다.
- 업무 데이터 행은 조회하지 않았다. 신규 테이블/컬럼/FK는 필요하지 않으므로 SQL migration 및 rollback은 해당 없음.
- 사용자는 비정상 종료로 남은 임시 객체 중 prefix `tenant/`와 tag `s-erp-temp-owner=drafting-work-form`가 함께 일치하는 객체의 MinIO lifecycle 만료를 7일로 승인했다. permanent image에는 이 tag를 복사하지 않는다. 모달 취소 및 템플릿 저장 중 미사용 객체는 API가 즉시 정리한다.

## 범위 통제

- 기안양식 기본정보 등록/수정 payload와 결재 상신 흐름은 변경하지 않는다.
- 목록 응답은 본문 전문을 반환하지 않고 기존 `hasDocument` 표시만 유지한다.
- notice 도메인의 업로드 URL, file owner, 저장 흐름은 재사용하지 않는다.
- 7일 lifecycle은 prefix 및 전용 object tag가 모두 일치하는 기안양식 임시 객체에만 적용한다. lifecycle 설정 권한이 없어 운영환경에 적용할 수 없으면 결과 문서에 미적용 환경과 잔여물 정리 방법을 기록한다.
- DB 스키마 변경이 새로 필요하다는 사실이 발견되면 구현 전에 사용자에게 별도 범위 승인을 요청한다.
- 현재 테스트 기준선은 승인 전 단계에서 실행하지 않았다. 계획/사양 승인 후 구현 단계에서 baseline 및 focused checks를 수행한다.
