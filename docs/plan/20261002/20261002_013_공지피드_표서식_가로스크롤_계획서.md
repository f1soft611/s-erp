## 목표

공지 body 저장과 피드 표시에 notice 전용 안전 정리를 사용한다. 공통 sanitizer 기본 동작은 유지하고, 피드 표시 단계에서만 표 wrapper를 넣어 작성기와 같은 타이포그래피 및 가로 스크롤을 제공한다.

## 파일 책임

- `frontend/src/shared/utils/sanitizeHtml.ts`: 기본 호출 결과는 그대로 유지하면서 opt-in 텍스트 서식 허용 옵션 제공
- `frontend/src/pages/groupware/community/notice/utils/noticeHtml.ts`: notice sanitizer 호출 및 피드용 표 wrapper 정규화
- `frontend/src/pages/groupware/community/notice/CommunityNoticePage.tsx`: notice body 저장에 notice 전용 sanitizer 적용
- `frontend/src/pages/groupware/community/notice/components/NoticeFeedList.tsx`: 피드 표시 HTML에 notice 전용 sanitizer와 wrapper 적용
- `frontend/tests/sanitize-html.test.ts`: 기본 정책과 opt-in 텍스트 서식 allowlist 검증
- `frontend/tests/notice-html.test.ts`: notice 서식/안전성/table wrapper 검증
- `frontend/tests/notice-page.test.tsx`: 피드의 접힘/펼침 렌더 검증
- `docs/result/20261002/notice-feed-table-rendering/`: 결과 문서와 브라우저 캡처

## 작업 순서

1. sanitizer의 opt-in 텍스트 서식 테스트를 먼저 작성해 기본 sanitizer는 계속 `span`을 제거하고 opt-in일 때만 안전한 font-family/font-size/font-style/font-weight/color/line-height/text-decoration을 보존하는지 확인한다.
2. `sanitizeHtml(value, options?)`에 opt-in 옵션을 추가하되 기본값 결과를 바꾸지 않는다. 위험 태그, URL, event handler 제거 정책을 유지한다.
3. notice HTML 유틸리티의 failing test를 추가한다. 저장용 sanitizer는 wrapper를 만들지 않고, 피드용 함수는 wrapper가 없는 각 table만 `.tableWrapper`로 감싼다.
4. 유틸리티를 구현하고 notice helper focused 테스트를 통과시킨다.
5. 공지 저장과 피드 렌더 경로를 notice 유틸리티에 연결하고 접힘/펼침 피드 테스트를 추가한다.
6. focused 테스트, production build, Chromium 1280px/375px 검증을 수행하고 결과 문서/스크린샷을 남긴다.

## 검증 명령

```powershell
npm --prefix frontend run test -- tests/sanitize-html.test.ts tests/notice-html.test.ts tests/notice-page.test.tsx
npm --prefix frontend run build
```

## 위험 및 범위 통제

- shared sanitizer option의 기본값은 기존과 같아야 댓글 및 비공지 호출 경로를 보호한다.
- wrapper는 피드 DOM에만 존재하며 저장 HTML, payload 필드, API 계약에 포함하지 않는다.
- CSS는 기존 `noticeContentStyles`의 `.tableWrapper`를 재사용하고 페이지 전체 가로 스크롤은 허용하지 않는다.
- DB 및 백엔드 변경은 없다.
