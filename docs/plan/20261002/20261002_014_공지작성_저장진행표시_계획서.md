## 구현 계획

1. `frontend/tests/notice-composer-payload.test.ts`에 지연된 `onSubmit`을 사용한 RED 테스트를 작성한다. 저장 중 `저장 중…` 문구, progressbar 표시, 저장 버튼 비활성, 두 번 클릭해도 한 번만 제출되는지 확인한다.
2. 성공/실패 경로에서 요청 종료 후 progressbar 제거와 버튼 문구 `저장` 복구를 확인한다.
3. `NoticeComposerDialog.tsx`에 `saving` 상태를 추가한다. 제출 전에 true로 설정하고 `finally`에서 false로 되돌린다. 저장 중 재호출은 무시한다.
4. 저장 버튼에 `CircularProgress size={16}`를 연결하고 `{saving ? '저장 중…' : '저장'}` 문구를 표시한다. 저장 중 저장/취소 버튼을 비활성화하고 구분 검증에는 saving 상태를 진입시키지 않는다.
5. focused 테스트, frontend build, diff 검사 후 결과 문서를 기록한다.

## 검증 명령

```powershell
npm --prefix frontend run test -- tests/notice-composer-payload.test.ts
npm --prefix frontend run build
```

## 범위 통제

- 프론트엔드 모달 상태와 테스트/문서만 변경한다.
- API, 저장 데이터, 백엔드, 공용 모달 동작은 변경하지 않는다.
