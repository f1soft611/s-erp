# 20261002_010 전자결재 문서작성 페이지 계획서

> 작업지시서: [20261002*010*전자결재*문서작성*페이지\_작업지시서.md](../../directions/20261002/20261002_010_전자결재_문서작성_페이지_작업지시서.md)

**목표:** `/groupware/doc/write`에 공지사항형 문서작성 화면을 제공하고, 결재상태와 문서 구분을 목록에서 확인할 수 있게 한다.

**방식:** 기존 `ContentSplitLayout`, `PinnedViewToolbar`, `PinnedItemsPanel`, `FeedView`, `ListView`, `NoticeFilterMenu`, `PageHeader`, `CommonDialog` 등 공통 UI를 재사용한다. 작성 모달은 공지사항의 `CommonDialog` 크기와 Tiptap 편집/툴바/첨부 푸터 배치를 따른다. 상단고정은 본문에서 분리하고 검색 입력은 두지 않는다. 목록/요약은 로컬 샘플 데이터에 한정한다.

## 변경 파일

- `frontend/src/pages/dashboard/components/DashboardContent.tsx`: 그룹웨어 `write` 페이지 연결
- `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`: 문서작성 목록/피드, 우측 결재 요약, 작성 모달
- `frontend/src/shared/components/view-mode/commonViewTypes.ts`, `ListView.tsx`: 선택적 상태 라벨을 분류 라벨 옆에 표시
- `frontend/src/pages/groupware/community/notice/components/NoticeFilterMenu.tsx`: 기존 필터 컴포넌트의 aria 이름을 재사용 가능하도록 선택 지원
- `frontend/tests/document-write-page.test.tsx`: 기본 보기, 구분/상태, 모달/탭, 라우팅 테스트
- `frontend/tests/common-view-mode.test.tsx`: 선택적 상태 라벨 회귀 테스트
- `docs/result/20261002/groupware-document-write-page/`: 결과와 화면 캡처

## 진행 순서

1. 문서현황/F1-Grid가 작성 페이지와 분리되어 있음을 상세 사양에 고정한다.
2. 페이지 테스트를 먼저 추가하고 실행해 미구현 상태를 확인한다.
3. `DocumentWritePage`를 구현한다. 공지사항과 동일한 툴바/상단고정/FeedView/ListView 구조를 사용하고 기본 mode는 `list`로 둔다.
4. 데이터 항목에 사용자 지정 업무구분 및 표시용 결재상태를 넣고, 우측 요약은 같은 샘플 데이터에서 계산한다.
5. `DashboardContent`에 `groupware/write` 분기를 연결하고 지정 URL에서 확인한다.
6. 좁은 화면/데스크톱 브라우저, 프론트엔드 테스트 및 빌드를 확인한 뒤 결과를 기록한다.

## 검증 명령

- `cd frontend; npm run test -- tests/document-write-page.test.tsx`
- `cd frontend; npm run build`
- 브라우저에서 `http://127.0.0.1:4173/groupware/doc/write` 확인

## 범위 통제

- 상태 라벨과 건수는 화면 표시 예시이며 서버 코드 계약으로 취급하지 않는다.
- 실제 저장/상신, 결재선, 문서현황/F1-Grid는 구현하지 않는다.
- 기존 작업트리의 공통코드 관련 변경은 수정하거나 되돌리지 않는다.
