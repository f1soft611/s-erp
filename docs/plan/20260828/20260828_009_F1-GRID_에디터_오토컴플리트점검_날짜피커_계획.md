# F1-GRID Autocomplete Fix and MUI Date/Time Pickers Implementation Plan

**Goal:** Fix autocomplete cell commit so every commit path (Enter, Tab, focus move) stores the option value consistently, and replace the native `date`/`datetime`/`time` cell editors with MUI X Date/Time Pickers so editing uses the Material calendar/clock UI instead of the browser-native control.

**Architecture:** `core/F1Grid.tsx` owns `commitEdit`, which currently special-cases numeric coercion only. Add autocomplete value normalization there (match `draftValue` against `column.options` by label or value, falling back to the raw text when no match) so the fix applies regardless of which key/interaction triggered the commit. Editor components stay presentation-only: `DateEditor`, `DateTimeEditor`, and `TimeEditor` swap their `InputBase` + native `input type` for `@mui/x-date-pickers` `DatePicker`/`DateTimePicker`/`TimePicker` wrapped in a local `LocalizationProvider` (dayjs adapter), keeping the same `value: string` / `onChange(value: string)` / `onKeyDown` contract used by `CellEditor`.

**Tech Stack:** React 19, TypeScript, MUI 9, `@mui/x-date-pickers` (new dependency) + `dayjs` (new dependency), Vitest, Testing Library.

### Task 1: Fix autocomplete commit normalization

- [ ] In `commitEdit`, when `column.type === 'autocomplete'` and `column.options` is set, resolve the committed value by matching `draftValue` against `option.label` or `String(option.value)`; use the matched `option.value`, otherwise keep `draftValue` as free text.
- [ ] Add a regression test: start autocomplete edit, change the input to a matching option label, commit via `Tab` (not `Enter`), and assert `getChanges().updatedRows` stores the option `value`, not the label text.

### Task 2: Install MUI X Date/Time Pickers

- [ ] Add `@mui/x-date-pickers` and `dayjs` to `frontend/package.json` and install.

### Task 3: Replace DateEditor with MUI DatePicker

- [ ] Wrap in `LocalizationProvider` (`AdapterDayjs`).
- [ ] Parse `value` (`YYYY-MM-DD` string) to `dayjs`, `null` when empty.
- [ ] `enableAccessibleFieldDOMStructure={false}` so a single native `<input>` remains queryable by `getByDisplayValue` for tests and keyboard flow.
- [ ] On change, format back to `YYYY-MM-DD` string (or `''` when cleared), forward `onKeyDown` through `slotProps.textField`.

### Task 4: Replace DateTimeEditor with MUI DateTimePicker

- [ ] Same pattern as Task 3 with format `YYYY-MM-DDTHH:mm`.

### Task 5: Replace TimeEditor with MUI TimePicker

- [ ] Same pattern as Task 3 with format `HH:mm`.

### Task 6: Update grid tests for new picker DOM and verify

- [ ] Update `f1-grid.test.tsx` date/datetime/time editing tests to interact with the MUI picker input while keeping the same value assertions.
