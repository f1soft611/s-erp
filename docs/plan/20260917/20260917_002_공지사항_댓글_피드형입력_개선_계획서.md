# 20260917_002 공지사항 댓글 피드형 표시·입력 개선 계획서

## 1. 목적

공지사항 댓글 영역을 피드형 대화 UI로 정리한다. 댓글과 답글의 표시 깊이를 최상위 댓글 + 답글 1단계로 제한하고, 댓글·답글 입력을 한 줄 시작 및 키보드 중심 등록 흐름으로 개선한다.

## 2. 작업 범위

### 2.1 프론트엔드

1. `TiptapCommentThread`의 댓글 표시를 최대 2단계로 제한한다.
2. 하위 답글에서 답글을 작성해도 추가 들여쓰기와 재귀 렌더링이 발생하지 않도록 최상위 댓글 기준으로 답글 대상을 정규화한다.
3. 댓글·답글 에디터를 한 줄 높이로 시작하도록 조정한다.
4. `Enter` 등록, `Shift+Enter` 줄바꿈 키 동작을 추가한다.
5. 첨부파일 아이콘을 입력창 우측 액션 영역에 유지하고, 선택 파일·등록 실패 시 상태를 보존한다.
6. 댓글 본문, 답글, 입력창 사이 간격을 피드 항목 수준으로 조정한다.
7. 관련 Vitest 회귀 테스트를 추가·수정한다.

### 2.2 백엔드 및 DB

- 백엔드 API와 `parentCommentId` 데이터 계약은 변경하지 않는다.
- DB 스키마 변경은 없다.
- DB 스크립트: 해당 없음, 영향 검토 완료.

- 구현 결과 문서 및 진행 원장

## 4. 실행 계획

### Task 1. 실패 기준 고정

- 재귀 답글이 3단계 이상 렌더링되는 현재 계약을 테스트로 고정한다.
- Enter가 등록, Shift+Enter가 줄바꿈으로 분리되는 기대 동작을 테스트로 고정한다.
- 입력창의 초기 높이와 첨부 아이콘 접근성 이름을 검증한다.

### Task 2. 표시 계층 및 답글 대상 정규화

- 댓글 컴포넌트에 최상위 댓글 식별자를 전달한다.
- 재귀 데이터는 표시용으로 한 단계 답글 목록으로 평탄화한다.
- 답글 액션은 최상위 댓글을 부모 ID로 전달하도록 연결한다.
- 기존 수정·삭제·첨부파일 액션과 로컬 트리 갱신은 유지한다.

### Task 3. 입력 UX 수정

- Tiptap `handleKeyDown`에서 조합 중인 키 입력은 보존한다.
- `Shift+Enter`는 기본 줄바꿈을 허용하고, 일반 `Enter`는 등록을 실행한다.
- 에디터 최소 높이와 여백을 한 줄 기준으로 줄인다.
- 등록 실패 시 에디터 내용과 첨부파일을 유지한다.

### Task 4. 집중 검증 및 문서화

- 관련 Vitest를 실행하고 실패 시 같은 범위에서 수정·재실행한다.
- `npm run build`로 타입 및 번들 검증을 수행한다.
- 실제 브라우저에서 375px, 768px, 1280px 댓글 피드와 입력 동작을 확인한다.
- 결과 문서와 `progress.md`에 검증 명령, 결과, 스크린샷 경로를 기록한다.

## 5. 검증 계획

- 단위/컴포넌트: `cd frontend && npm run test -- tests/notice-page.test.tsx tests/notice-page-local-updates.test.tsx`
- 빌드: `cd frontend && npm run build`
- 브라우저: 공지사항 화면에서 3단계 이상 답글 데이터, Enter 등록, Shift+Enter 줄바꿈, 첨부 아이콘, 375/768/1280px 레이아웃을 확인한다.

## 6. 리스크

- 서버는 깊은 `parentCommentId`를 계속 반환할 수 있으므로 화면 평탄화와 API 부모 ID 전달을 분리해야 한다.
- Tiptap의 IME 조합 중 Enter 처리 시 한글 입력 확정을 방해하지 않도록 `event.isComposing`을 고려해야 한다.
- 기존 테스트가 답글의 재귀 트리 구조를 기대할 수 있으므로 테스트 계약을 새 표시 기준에 맞게 갱신한다.
