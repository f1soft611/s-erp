# 20260917_001 공지사항 오류 수정 계획서

## 1. 목적

공지사항의 댓글 작성 오류, 첨부파일 포함 저장 오류, 저장 후 목록 맨뒤 이동, 저장 후 제목 잔류를 재현하고 최소 범위로 수정한다.

## 2. 작업 범위

### 2.1 수정 및 검증 대상 기능

1. 공지사항 저장, 수정, 삭제
2. 첨부파일 포함 공지사항 저장, 수정, 삭제
3. 댓글 저장, 수정, 삭제
4. 답글 저장, 수정, 삭제
5. 댓글 작성 실패 상태 처리
6. 저장 후 서버 정렬 위치와 작성 모달 초기화
7. 브라우저 기반 회귀 검증

### 2.2 대상 화면

- `http://127.0.0.1:4173/groupware/community/notice`
- 관련 페이지 파일: `frontend/src/pages/groupware/community/notice/**`
- 관련 서비스 파일: `frontend/src/pages/groupware/community/notice/services/**`
- 관련 공통 API: `frontend/src/shared/services/commonContentApi.ts`

## 3. 현재 코드 구조와 영향 범위

### 3.1 공지사항 페이지 로직

- `CommunityNoticePage.tsx`는 목록 로딩, 생성, 수정, 삭제, 댓글 등록을 담당한다.
- `NoticeComposerDialog`는 공지 작성/수정 모달이며, 본문 HTML/첨부 파일 데이터를 전달한다.
- `NoticeFeedList`는 목록, 댓글, 첨부 영역의 UI를 렌더링한다.

### 3.2 API 연동 흐름

- 목록 조회: `fetchNoticePosts`
- 상세 조회: `fetchNoticePostDetail`
- 생성: `createNoticePost`
- 수정: `updateNoticePost`
- 삭제: `deleteNoticePost`
- 첨부 업로드: `uploadNoticeAttachment`
- 첨부 삭제: `deleteNoticeAttachment`
- 댓글 조회/생성: `fetchCommonComments`, `createCommonComment`

생성/수정 API와 첨부 업로드 API는 기존 계약을 유지한다. 게시글 저장 성공 후 목록은 서버 응답 또는 재조회 결과를 기준으로 갱신하고, 첨부 업로드 실패는 성공 상태로 확정하지 않는다.

### 3.3 직접 영향 파일

- `frontend/src/pages/groupware/community/notice/CommunityNoticePage.tsx`
- `frontend/src/pages/groupware/community/notice/components/NoticeComposerDialog.tsx`
- `frontend/src/pages/groupware/community/notice/components/NoticeFeedList.tsx`
- `frontend/src/pages/groupware/community/notice/services/noticeBoardService.ts`
- `frontend/src/shared/services/commonContentApi.ts`

## 4. 오류별 수정 시나리오

### 4.1 댓글 작성 오류

1. 댓글 또는 답글을 입력하고 저장한다.
2. API 오류를 재현해 오류 메시지가 표시되는지 확인한다.
3. 실패한 댓글이 로컬 트리에 추가되지 않고 다시 입력할 수 있는지 확인한다.

### 4.2 첨부파일 포함 저장

1. 제목/본문/첨부파일을 입력하고 저장한다.
2. 게시글 생성 응답의 ID로 첨부 업로드가 이어지는지 확인한다.
3. 업로드 실패 시 성공 메시지나 완료 상태가 남지 않는지 확인한다.
4. 수정 시 기존 첨부 삭제와 신규 첨부 업로드가 함께 정합성을 유지하는지 확인한다.

### 4.3 저장 후 목록 위치와 제목 초기화

1. 새 공지를 저장한다.
2. 서버 목록 정렬 기준에 맞는 위치에 표시되는지 확인한다.
3. 저장 완료 후 작성 모달을 다시 열어 제목·본문·첨부파일이 초기화되는지 확인한다.

### 4.4 공지사항 CRUD 회귀

1. 새 공지 작성 버튼으로 작성 모달을 연다.
2. 제목/본문을 입력하고 저장한다.
3. 수정 버튼으로 기존 공지를 편집하고 저장한다.
4. 삭제 버튼으로 공지를 삭제한다.
5. 각 성공/실패 상태가 사용자 메시지와 목록에 일치하는지 확인한다.

### 4.5 첨부파일 포함 CRUD 회귀

1. 첨부 파일을 포함한 공지를 저장한다.
2. 첨부 목록이 보이는지 확인한다.
3. 수정 시 첨부 추가 또는 삭제가 반영되는지 확인한다.
4. 삭제 시 첨부가 실제로 제거되고 목록 재조회가 정상인지 확인한다.
5. 첨부 다운로드 링크가 정상적으로 동작하는지 확인한다.

### 4.6 댓글/답글 CRUD 회귀

1. 공지 상세를 연다.
2. 댓글을 작성한다.
3. 목록에 즉시 반영되는지 확인한다.
4. 댓글 수정 기능이 정상인지 확인한다.
5. 댓글 삭제 기능이 정상인지 확인한다.
6. 답글을 작성한다.
7. 답글 수정/삭제가 정상인지 확인한다.
8. 답글 계층 구조가 올바르게 보이는지 확인한다.

## 5. 실행 태스크

### Task 1: 기준선과 오류 재현

- 관련 Vitest/빌드 상태와 실제 브라우저 오류를 확인한다.
- 네트워크 요청 payload, 응답 ID, 목록 순서, draft 상태를 기록한다.

### Task 2: 저장·첨부 상태 수정

- 게시글 생성 후 첨부 업로드 흐름과 실패 시 보상 삭제를 점검한다.
- 저장 성공 후 서버 기준 목록 갱신과 작성 draft 초기화를 적용한다.

### Task 3: 댓글 오류 상태 수정

- 댓글/답글 생성 실패 시 로컬 트리 갱신이 발생하지 않도록 한다.
- 오류 메시지와 재시도 가능한 입력 상태를 유지한다.

### Task 4: 회귀 검증 및 결과 문서

- 관련 테스트와 `npm run build`를 실행한다.
- Playwright로 375px, 768px, 1280px에서 저장·첨부·댓글 시나리오를 검증하고 결과 문서에 기록한다.

## 6. 검증 계획

### 브라우저 검증

- 로컬 개발 서버에서 실제 페이지를 직접 여는 흐름으로 검증한다.
- 필요 시 네트워크 탭/개발자 도구를 사용해 API 응답과 에러 상태를 확인한다.

### 코드 검증

- TypeScript 빌드 검증: `cd frontend && npm run build`
- 관련 테스트 확인: `cd frontend && npm run test -- tests/<공지사항 테스트 파일>`

### 예외 상황

- 백엔드 API가 미구현이거나 네트워크 차단 상태라면, 프론트 쪽에서 발생하는 예외 메시지와 재조회 흐름을 수정해 브라우저 동작을 안정화한다.
- 다른 화면에 영향이 큰 변경은 즉시 중단하고 범위를 좁힌다.

## 7. 리스크와 위험 요소

- 게시글 생성 응답에 ID가 없으면 첨부 업로드를 진행할 수 없으므로 응답 계약을 확인해야 한다.
- 저장 후 로컬 append만 사용하면 서버 정렬과 달라질 수 있으므로 재조회 또는 서버 기준 결과를 사용해야 한다.
- 모달 close와 draft reset 순서가 어긋나면 제목이 다음 작성에 남을 수 있다.
- 댓글 실패를 컴포넌트가 삼키거나 재던지면 입력 상태와 오류 메시지가 어긋날 수 있다.

## 8. 완료 기준

- 네 가지 오류 현상이 재현되고 원인별 수정이 검증된다.
- 공지사항 저장/수정/삭제와 첨부파일 포함 시나리오가 정상 동작한다.
- 댓글 및 답글 실패 시 상태와 메시지가 일관된다.
- 결과 문서와 필요한 모바일/데스크톱 스크린샷이 정리된다.
- 결과 문서와 필요 시 스크린샷이 정리된다.
