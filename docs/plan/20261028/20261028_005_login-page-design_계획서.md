# 20261028_005 로그인 페이지 디자인 개선 계획서

근거: [작업지시서](../../directions/20261028/20261028_005_login-page-design_작업지시서.md), [상세사양서](../../spec/20261028/20261028_005_login-page-design_상세사양서.md)

## 1. 범위

- 로그인 페이지의 기존 카드 디자인과 로그인 레이아웃을 정돈한다.
- 인증, API, 검증 규칙, 입력 필드 구성, 라우팅은 변경하지 않는다.
- UI 테스트, 반응형 브라우저 검증, 결과 문서 및 스크린샷까지 수행한다.

## 2. 구현 단계

### 2.1 기존 동작 기준선

1. `frontend/tests/login.test.tsx`를 실행해 로그인 관련 기준선 결과를 확보한다.
2. 현재 테스트가 확인하는 필드/검증/로그인 실패/로그인 성공 동작을 변경하지 않는다.

### 2.2 테스트 우선 UI 수정

1. 로그인 화면에 대해 필요한 실패 테스트만 추가한다. 기존 동작 검증을 재사용하고 새 인증 로직 테스트는 추가하지 않는다.
2. `AuthLayout.tsx`에서 배경, 남은 화면 높이 사용, 중앙 정렬, 좁은 화면 좌우 여백 및 세로 스크롤 동작을 정돈한다. 부모 앱의 `overflow: hidden`과 양립하도록 레이아웃 자체가 `flex: 1`, `minHeight: 0`, `overflowY: auto`를 처리하는지 확인한다.
3. `LoginForm.tsx`에서 카드 표면/경계/그림자, 제목 위계, 콘텐츠 간격, 버튼 상태를 테마 기반으로 조정한다. 기존 DEV 계정 안내·세션 오류·필드 연결은 유지한다.
4. `LoginFormField.tsx`의 라벨을 입력 위에 고정하고 `useId`로 input과 연결한다. 입력 글씨 18px, 높이 56px, `margin="none"`을 명시해 MUI 기본 margin 중복을 제거한다.
5. 개발용 계정 안내의 정보는 유지하면서 배경/테두리 대비를 낮추고, 보조 글씨 크기로 바꾼다.
6. 새 field component 회귀 테스트를 먼저 작성해 label 연결/글자 크기/높이를 검증한다. 수정 전후 로그인 집중 테스트와 프론트엔드 검증을 수행한다.

### 2.3 실제 브라우저와 결과 정리

1. `frontend/AGENTS.md`의 포트 지침에 따라 4173 포트를 확인한다. S-ERP 서버면 재사용하고, 다른 서버면 다른 포트로 우회하지 않는다.
2. 실제 브라우저에서 라이트/다크 테마와 375px/768px/1280px 뷰포트를 확인한다. 가로 넘침 및 짧은 화면에서 폼 접근성을 검사한다.
3. 영문 경로 `docs/result/20261028/login-page-design/screenshots/`에 검증 화면을 저장하고 결과 문서를 작성한다.
4. 작업 중 직접 시작한 개발 서버만 종료하고 포트 해제를 확인한다. 기존 서버는 종료하지 않는다.

## 3. 검증 명령

```powershell
cd frontend
npm run test -- tests/login.test.tsx
npm run build
```

추가로 프로젝트 검증 규칙에 맞춰 실제 브라우저 반응형 확인을 수행한다.

## 4. 완료 조건

- 로그인 관련 집중 테스트와 `npm run build` 성공
- 현재 로그인 흐름과 오류/검증/세션 안내 보존
- 고정 라벨, 18px 입력 글씨, 56px 필드 및 간결한 보조 계정 안내 확인
- 라이트/다크 및 375px/768px/1280px에서 콘텐츠 잘림·가로 넘침 없음
- 결과서와 반응형 스크린샷 작성
