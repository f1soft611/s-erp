## 목적

역할 선택에 따른 사용자 매핑 조회를 역할 ID 기준으로 안정화하고, 역할·사용자 매핑의 F1-Grid 변경 상태와 저장 흐름을 메뉴 관리 페이지의 제어 패턴에 맞춘다.

## 작업 범위

### 프론트엔드

1. `RoleManagementPanel`의 선택 역할을 문자열 ID로 분리하고, 역할 ID 변경 시에만 사용자 매핑 조회를 수행한다.
2. 역할 매핑 조회에 요청 식별자를 적용해 이전 역할 요청의 늦은 응답을 무시한다.
3. 역할 관리 카드에 선택 행 삭제와 현재 행 내보내기 아이콘 버튼을 추가한다.
4. 역할 변경 집합을 `insertedRows`와 `updatedRows`로 나누어 생성 API와 수정 API로 저장한다.
5. 역할 저장 성공 후 역할 목록 재조회와 그리드 재마운트를 수행해 기준 데이터 및 dirty 상태를 초기화한다.
6. 사용자 매핑 영역의 `행 추가`는 미할당 사용자 선택 다이얼로그를 열고, 선택 결과를 매핑 변경 집합에 추가한다.
7. 사용자 매핑 변경은 상단 저장 액션에서 역할 변경과 함께 저장하며, 저장 성공 후 선택 역할의 매핑 목록을 재조회한다.
8. `RoleManagementPage`는 메뉴 관리와 동일한 아이콘 포함 조회·저장 액션을 제공하고 역할/매핑 dirty 상태를 합산한다.
9. 미저장 사용자 매핑이 있는 역할에서 다른 역할을 선택하면 저장·변경 취소·현재 역할 유지 선택을 제공한다.
10. 저장 중 선택 전환과 다건 저장 부분 실패에 대해 요청/완료 체크포인트를 유지해 stale 응답과 중복 저장을 방지한다.

### 공통 F1-Grid

1. 신규 상태 행을 삭제하면 해당 행을 `deleted`로 남기지 않고 그리드 상태에서 제거한다.
2. 이 규칙으로 `getChanges()`가 빈 배열을 반환하게 하여 저장 버튼 dirty 상태가 해제되는지 회귀 테스트한다.

### 백엔드 및 DB

- 역할 수정 및 사용자 매핑 API를 재사용한다.
- 테이블, 컬럼, 제약조건, 데이터 마이그레이션 변경은 없다.
- DB 스크립트: 해당 없음. 기존 `tb_role`, `tb_login_account`, `tb_login_account_role` 스키마 영향 검토 완료.

## 상세 실행 계획

### T1. 신규 행 삭제 dirty 상태

**파일**

- 수정: `frontend/src/shared/components/f1-grid/state/GridState.ts`
- 수정: `frontend/tests/f1-grid.test.tsx`

**인터페이스**

- `markRowsDeleted(data, rowKey, rowIds)`는 삽입 상태(`inserted`) 행을 삭제할 때 `rows`, `stateById`, `previousStateById`, `dirtyFieldsById`, `originalRowsById`에서 해당 ID를 제거한다.
- 기존 행은 현재와 같이 `deleted` 상태로 유지한다.

**단계**

1. 삽입 행을 삭제한 뒤 `getGridChanges()`의 inserted/updated/deleted 목록이 모두 빈 배열인지 검증하는 실패 테스트를 추가한다.
2. `markRowsDeleted`에서 삽입 행 제거 규칙을 구현한다.
3. `npm run test -- tests/f1-grid.test.tsx`를 실행한다. 기존 편집기 관련 기준선 실패와 신규 회귀 테스트 결과를 구분해 기록한다.

### T2. 역할 선택, 상단 제어, 저장

**파일**

- 수정: `frontend/src/pages/settings/system/roles/RoleManagementPage.tsx`
- 수정: `frontend/src/pages/settings/system/roles/components/RoleManagementPanel.tsx`
- 수정: `frontend/src/pages/settings/system/roles/services/roleManagement.service.ts`
- 수정: `frontend/tests/role-management-notification.test.tsx`

**인터페이스**

- `RoleManagementPanelHandle`에 `deleteSelectedRows()`와 `exportCurrentRows()`를 추가한다.
- `saveCurrentChanges()`는 역할 생성/수정과 사용자 매핑 저장을 완료한 뒤 최신 역할 목록을 반환하거나, 페이지 콜백으로 재조회 완료를 보장한다.
- `onDirtyChange`은 역할·사용자 매핑의 실제 변경 집합을 합산해 전달한다.

**단계**

1. 역할 수정 저장 시 `apiPut('/api/v1/system/roles/{id}', payload)` 호출과 저장 후 dirty 해제를 검증하는 실패 테스트를 추가한다.
2. 역할 ID 기준 사용자 매핑 조회와 최신 요청 보호를 구현한다.
3. 메뉴 관리와 동일한 역할 그리드 툴바의 삭제·내보내기 아이콘 버튼 및 ref 메서드를 구현한다.
4. `getChanges()`의 insertedRows에는 `createRole`, updatedRows에는 `updateRole`을 호출하도록 저장을 구현하고, 성공 시 페이지가 역할 목록을 재조회해 그리드 key를 변경하도록 연결한다.
5. `npm run test -- tests/role-management-notification.test.tsx`를 실행한다.

### T3. 사용자 매핑 추가와 일괄 저장

**파일**

- 수정: `frontend/src/pages/settings/system/roles/components/RoleManagementPanel.tsx`
- 수정: `frontend/tests/role-management-notification.test.tsx`

**인터페이스**

- 매핑 사용자 선택은 현재 응답의 `unassignedUsers`만 후보로 사용한다.
- 매핑 그리드 컨텍스트 메뉴의 행 추가는 다이얼로그를 열고, 선택 완료 시 `assigned: true` 변경을 그리드 변경 집합에 반영한다.
- 저장은 assigned 변경 방향별로 `assignUserToRole` 또는 `removeUserFromRole`을 호출한다.

**단계**

1. 미할당 사용자 선택 후 저장 시 역할 사용자 추가 API가 호출되는 실패 테스트를 추가한다.
2. 사용자 추가 다이얼로그, 후보 검색, 선택 상태를 구현한다.
3. 매핑 dirty 상태와 상단 저장 결합, 성공 후 사용자 매핑 재조회 흐름을 구현한다.
4. 매핑 dirty 상태에서 다른 역할을 선택할 때 저장·변경 취소·현재 역할 유지 다이얼로그를 구현한다. 저장 후 전환은 저장 성공 이후에만 대상 역할 선택을 적용한다.
5. 역할 및 사용자 매핑의 다건 저장에 완료 체크포인트와 재진입 잠금을 추가해 부분 실패 재시도와 저장 후 stale 응답을 방지한다.
6. 역할 전환 중 저장 완료 재조회가 현재 선택 역할을 덮어쓰지 않는지 실패 테스트로 검증한다.
7. `npm run test -- tests/role-management-notification.test.tsx`를 실행한다.

## 전역 제약

- 현재 브랜치의 기존 미커밋 변경을 되돌리거나 정리하지 않는다.
- 역할 삭제 API, DB 스키마 변경, 사용자 마스터 변경은 구현하지 않는다.
- 공통 F1-Grid 편집기 기준선 실패는 신규 변경이 해당 실패를 악화했는지 비교해 기록하며, 본 작업에서 재현·원인이 확인될 때만 별도 수정한다.
- 태스크별 커밋은 현재 브랜치에 기존 미커밋 변경이 있어 실행하지 않는다. 완료 시 사용자에게 변경 분리 또는 커밋 방식을 확인한다.
