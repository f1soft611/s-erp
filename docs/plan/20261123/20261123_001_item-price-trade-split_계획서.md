# 20261123_001 단가등록 매입/매출 화면 분리 계획서

근거: [작업지시서](../../directions/20261123/20261123_001_item-price-trade-split_작업지시서.md)

## 구현 단위와 순서

화면이 열려 있는 상태에서 기존 동작이 깨지지 않도록 **백엔드 → 프론트 → 메뉴 SQL** 순서로 진행한다(메뉴는 마지막에 반영해야 새 화면 키가 먼저 배포되어 있다).

1. **문서**: 작업지시서, 계획서, [상세사양서](../../spec/20261123/20261123_001_item-price-trade-split_상세사양서.md).
2. **백엔드 권한 검사**
   - 단가 모듈에 `ItemPriceAccessService`(내 메뉴 트리에서 거래구분 화면 키의 권한 확인)를 두고 컨트롤러가 호출한다.
   - 일괄 저장·엑셀 검증은 행의 거래구분을 모아 확인한다(삭제·수정은 기존 행의 거래구분을 DB에서 조회).
3. **백엔드 조회**
   - 품목 기준·거래처 기준·목록에 `tradeType` 필수 파라미터. 해당 구분의 단가만 조회·집계한다.
   - 필터 값을 정리한다(NO_PURCHASE/NO_SALES → NO_COMMON_PRICE, NO_DEFAULT_SUPPLIER는 매입 전용).
4. **백엔드 테스트**: 권한(허용/거부/구분 혼합), 조회 파라미터·필터, 매퍼 SQL. JDK 8 컴파일.
5. **프론트 구조**
   - 페이지·훅·서비스가 `tradeType`을 받는다. 서비스는 조회에 `tradeType`을 보낸다.
   - 품목 기준 트리 열·행 폼·변경 집합을 한쪽 거래구분만 다루게 한다(필드 이름의 `purchase*`/`sales*` 접두어는 유지해 변경량을 줄인다).
   - 거래처 기준·이력 조회 탭도 같은 `tradeType`을 쓰고, 거래구분 컬럼·검색 필드는 고정값으로 숨긴다.
   - 엑셀 양식·검증을 구분별로 나눈다(매입만 발주구분·기본거래처).
6. **화면 연결**: 대시보드에 `item-purchase-prices`·`item-sales-prices` 연결, 기존 키 제거, 화면 설명, F1-Grid 문서 갱신.
7. **프론트 테스트 정리**: 기존 단가 테스트 10여 개 파일을 구분 속성 기준으로 수정하고 매입/매출 각각의 열·폼·저장 케이스를 추가.
8. **메뉴 SQL**: 날짜별 스크립트(변경·롤백·이력 문서), `db-schema.md`는 테이블 변경이 없어 해당 없음(메뉴 데이터 변경만 이력에 기록). 사용자가 실행하고 MCP로 확인한다.
9. **검증 묶음**: 관련 전체 테스트, 빌드, 브라우저(375/768/1280px) 확인, 결과 문서(`docs/result/20261123/item-price-trade-split`)와 커밋 문구.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 메뉴 SQL 적용 전에 코드가 배포되면 새 화면 키 메뉴가 없다 | 메뉴 SQL을 마지막 단계로 두고, 적용 전에는 기존 메뉴가 새 화면을 열지 않는다는 점을 문서에 명시 |
| 권한 복제 누락으로 기존 사용자가 메뉴를 못 본다 | 스크립트에서 역할 권한을 새 메뉴로 복제하고 MCP로 건수 대조 |
| 삭제 행 거래구분을 클라이언트가 속일 수 있다 | 삭제·수정은 DB의 기존 행 거래구분으로 판단 |
| 기존 필터 값(NO_PURCHASE 등) 사용처 | 프론트·테스트·검색 정의에서 함께 교체 |
