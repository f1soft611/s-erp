# 비밀번호 변경 필요 응답 처리 계획

## 근거

- [계정관리 작업지시서](../../directions/20261120/20261120_001_hr-account_작업지시서.md)
- 사용자 승인: JSON API와 Blob, 다운로드, 이벤트 스트림에서 동일한 변경 필요 응답을 처리한다.

## 순서

1. 상세사양에 실제 `resultCode` 응답과 각 클라이언트 경로의 처리 범위를 정의한다.
2. 각 경로의 변경 필요 403, 다른 403, 정상 응답 회귀 테스트를 먼저 작성한다.
3. 공통 클라이언트 오류 처리만 개선하고 정상 Blob·스트림 및 기존 일반 오류 동작을 유지한다.
4. 관련 프론트 테스트, typecheck/build/lint를 수행하고 결과를 `docs/result/20261123/password-change-response`에 기록한다.

인증 정책, 서버 응답, API 경로와 DB 스키마는 변경하지 않는다.

## 구현 단위

- `frontend/tests/password-change-required.test.tsx`: `apiGetBlob`, `apiDownload`, `apiGetEventStream` 각각의 변경 필요 403이 세션을 표시하며 다른 403은 표시하지 않는지 확인한다.
- `frontend/src/shared/services/apiClient.ts`: 오류 본문에서 `resultCode` 또는 기존 호환 `code`를 식별하는 공통 함수를 둔다. 해당 코드에만 `markPasswordChangeRequired()`를 호출하고, 기존 일반 오류 및 정상 스트림/Blob 흐름은 유지한다.
- `docs/spec/20261120/20261120_001_hr-account_상세사양서.md`: 서버가 실제 반환하는 `resultCode`로 표기한다.
- 실행: `cd frontend; npm run test:ci -- tests/password-change-required.test.tsx tests/api-network-error.test.ts tests/realtime-service.test.ts`; 추가로 `npm run typecheck`, `npm run lint`, `npm run build`.
