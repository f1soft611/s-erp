# 20261123_002 단가등록 개편 계획서

근거: [작업지시서](../../directions/20261123/20261123_002_item-price-redesign_작업지시서.md)

## 구현 단위 (순서대로)

| 단계 | 내용 | 비고 |
| --- | --- | --- |
| 1 | DB: 매입 공통단가 백업·삭제 스크립트(+롤백·이력), `db-schema.md` 갱신 | 사용자가 실행. 현재 매입 공통 8행, 매출 0행(읽기 전용 DB 조회) |
| 2 | 백엔드 단가 조회 공통 서비스 개편(구매요청확정 규칙, 수주용 조회) | 구매요청확정 서비스 호출부 정리 |
| 3 | 백엔드 저장·검증: 거래처 필수, 매입 기본 거래처 규칙, 엑셀 검증 | 공통단가 저장 경로 제거 |
| 4 | 백엔드 조회: 품목 계정분류 필터(`itemTypes`), 공통단가 필터·집계 제거 | 품목 기준 조회를 좌우 그리드용 응답으로 정리 |
| 5 | 프론트 공통: `PageSearchArea` select `multiple` 옵션 | 김차장 확인 후 반영. 값은 쉼표 구분 문자열 |
| 6 | 프론트 화면: 품목 기준 좌우 그리드, 컬럼 순서, 계정분류 조건, 기본 거래처 UI, 공통단가 요소 제거 | 매입/매출 같은 컴포넌트 |
| 7 | 테스트·브라우저 확인·결과 문서 | 단계별로는 관련 단위 테스트와 `tsc`만, 전체 실행은 마지막에 |

## 주요 결정과 위험

- **공통단가 폐지**는 데이터(매입 8행)·조회 서비스·저장·엑셀·필터·화면에 걸친 변경이다. 영업 소스는 단가 테이블·조회 서비스를 참조하지 않아(코드 검색) 영향이 없다.
- **기본 거래처 규칙의 기존 데이터**: 매입에서 거래처 2곳 이상인데 기본 거래처가 없는 품목이 1개 있다(품목 ID 8). 테스트 데이터이므로 같은 DB 스크립트에서 기본 거래처를 지정한다(실행일 유효 단가 거래처 우선, 상세사양서 §5).
- **`customer_id` NOT NULL 제약**: 사용자 확정. 공통단가 행 삭제와 같은 스크립트에서 적용하고 롤백으로 되돌린다.
- **부가세구분·부가세포함**: 조회 결과에 이미 있으며 선택된 단가 행에서 같이 내려준다(구매요청확정 채우기 유지·수주용 조회 포함).
- **수주 연동**: 영업 담당자 영역이므로 서비스 계약(입력: 테넌트·품목·수주처·기준일, 출력: 단가·통화)만 만들고 안내문을 결과 문서에 둔다.
- **좌우 그리드 전환**은 품목 기준 탭의 화면·저장·엑셀 업로드를 다시 짜는 큰 작업이다. 거래처 기준 탭의 좌우 구조와 저장 흐름을 재사용한다.
- `PageSearchArea` 변경은 영향 범위가 넓어 기존 사용처 테스트를 함께 돌린다.

## 검증 계획

- 백엔드: 조회 서비스(거래처 1곳/2곳 이상/없음, 기본 거래처 단가 없음, 수주처+품목), 저장 검증, 매퍼 필터, JDK 8 컴파일.
- 프론트: 검색 필드(멀티선택 기본값), 컬럼 순서, 좌우 그리드 선택·저장·기본 거래처, 엑셀 양식 변경분.
- DB: 스크립트를 PGlite로 시험하고, 사용자 실행 후 읽기 전용 조회로 확인.
