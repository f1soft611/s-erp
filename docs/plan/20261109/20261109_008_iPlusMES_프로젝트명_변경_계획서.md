# iPlusMES 프로젝트명 변경 계획서

## 목표

현재 제품 브랜드 표기 `S-ERP`를 `iPlusMES`로 변경하되, 저장소 및 런타임 호환성을 위한 기존 내부 식별자와 과거 문서 이력은 유지한다.

## 대상 파일 및 책임

- `frontend/index.html`: 브라우저 탭 제목
- `frontend/src/pages/auth/components/LoginForm.tsx`: 로그인 브랜드
- `frontend/src/pages/dashboard/components/DashboardModuleSection.tsx`: 대시보드 브랜드
- `frontend/src/pages/errors/NotFoundPage.tsx`: 오류 화면 푸터
- `frontend/public/sw.js`: 푸시 알림 제목
- `frontend/public/dashboard-panel-preview.html`: 현재 UI 미리보기 페이지 제목/브랜드
- `backend/src/main/resources/static/index.html`: 백엔드 기본 정적 안내 제목/본문
- `backend/pom.xml`: 사람이 읽는 `<name>`만 변경하고 `artifactId`/`finalName`은 기존값 유지
- `frontend/tests/app-router-not-found.test.tsx`, `frontend/tests/dashboard-module-section.test.tsx`, `frontend/tests/login.test.tsx`, `frontend/tests/push-service-worker.test.ts`, `frontend/tests/push-presentation.browser.mjs`: 사용자 노출 브랜드에 대한 회귀 검증
- `README.md`, `backend/README.md`, `frontend/AGENTS.md`, `.github/instructions/team-rules.instructions.md`, `.github/f1workflow/README.md`, `.github/f1workflow/skills/{01-project-analysis,03-design-validation,07-implementation-tdd,10-code-review,11-finalize}.md`, `.github/f1workflow/tech-stacks/{s-erp-react-vite,s-erp-java-egov}.yml`, `.github/skills/f1workflow/SKILL.md`: 현재 프로젝트명 안내

## 실행 순서

1. 테스트 기대 문자열을 `iPlusMES`로 바꾸고 실패를 확인한다.
   - `cd frontend; npm run test -- tests/dashboard-module-section.test.tsx tests/push-service-worker.test.ts`
   - 예상: 화면/알림이 아직 `S-ERP`를 표시하므로 해당 브랜드 assertion이 실패한다.
2. 사용자에게 노출되는 코드와 HTML 문자열을 `iPlusMES`로 변경한다. 저장소 키와 이벤트명은 수정하지 않는다.
3. 현재 프로젝트 안내 문서, Maven 프로젝트 표시명, 워크플로우 표시명을 `iPlusMES`로 정합화한다. artifactId/finalName, 스택 파일명, MCP 서버 ID는 유지한다.
4. `README.md`는 UTF-16 인코딩이므로 PowerShell의 `-Encoding Unicode`로 읽고 제목 문자열만 교체해 원래 인코딩을 보존한다.
5. 대상 테스트를 재실행한다.
   - `cd frontend; npm run test -- tests/dashboard-module-section.test.tsx tests/push-service-worker.test.ts`
   - `cd frontend; npx vitest run tests/login.test.tsx -t="renders the enterprise login fields"`
   - `cd frontend; npx vitest run tests/app-router-not-found.test.tsx -t="renders the NotFound page"`
   - 예상: 각 명령의 대상 테스트 통과.
6. `cd frontend; npm run build`, `cd frontend; npm run lint`, `cd frontend; npm run test`를 실행한다.
   - 예상: TypeScript/Vite 빌드, lint, 전체 Vitest 통과.
7. 개발 서버에서 로그인 및 대시보드 브랜드 표시를 확인하고 스크린샷을 `docs/result/20261109/iplusmes-branding/screenshots/`에 저장한다.
8. `S-ERP`를 검색하여 남은 런타임 키·기술 ID·역사 문서가 제외 기준에 맞는지 확인한 후 결과 문서를 작성한다.

## 제외

- GitHub 저장소명, 로컬 경로, 패키지/아티팩트 ID, MCP 서버 이름, API 경로, 환경변수, 브라우저 저장소 키·이벤트명
- 과거 작업 기록 및 제품명 교체가 불필요한 기술 예시
- DB 스키마와 백엔드 비즈니스 로직

## 완료 검증

- 대상 Vitest 두 파일 통과
- `npm run build`와 `npm run test` 통과
- 브라우저에서 iPlusMES 로그인/대시보드 화면 확인 및 스크린샷 저장
- 남은 `S-ERP` 검색 결과가 보존 대상임을 확인
- 미커밋 작업 파일을 포함한 기존 변경사항을 덮어쓰거나 되돌리지 않음
