# 회사정보와 거래명세서 구현 계획서

**목표:** 회사정보를 관리하고 출하 단위 거래명세서를 저장·조회·인쇄한다.

**구조:** 기존 테넌트의 회사 관련 정보를 재사용하고 누락된 공급자 정보를 추가한다. 명세서는 출하를 참조하면서 공급자·거래처·품목과 금액을 별도로 보존한다. 현황 상세와 등록은 동일한 폼을 사용한다.

**기술:** Spring Boot, MyBatis, PostgreSQL, React, TypeScript, F1Grid, 브라우저 인쇄.

## 구현 단계

1. `backend` 회사정보 API와 `tb_tenant` 추가 컬럼 및 메뉴 SQL을 작성한다. 인증 테넌트만 조회·수정하며 기존 관리 계정 정보를 대표자 정보로 사용하지 않는다.
2. 출하 스냅샷을 생성하는 거래명세서 테이블과 API를 작성한다. 테넌트와 출하의 복합 참조 및 중복 방지를 DB에서 보장하고 동시 저장도 검증한다.
3. 회사정보 화면을 기준정보 기존 화면 패턴에 연결한다. 거래명세서 등록과 현황은 출하 화면의 검색, 상세, 폼, F1Grid 패턴을 따른다.
4. 상세에서 저장된 스냅샷을 A4 거래명세표로 미리보고 브라우저 인쇄한다. 출력 시 화면의 검색·버튼은 제외하고 품목 행이 여러 페이지로 이어지게 한다.
5. 해당 API·서비스·화면의 실패 테스트를 먼저 작성하고 구현 후 통과시킨다. SQL 이력과 롤백, 누적 스키마를 갱신한다.
6. 프론트 테스트·빌드·린트와 백엔드 테스트·Java 8 API 검증, 실제 브라우저 375/768/1280px 및 출력 확인을 수행한다.

## 소유 경계

- 회사정보 API: `backend/src/main/java/egovframework/let/co/master/company`, 회사 Mapper와 회사 전용 테스트.
- 명세서 API: `backend/src/main/java/egovframework/let/sales/statement`, 명세서 Mapper와 전용 테스트.
- 화면: `frontend/src/pages/co/master/company`, `frontend/src/pages/sales/statement` 및 대시보드 메뉴 연결.
- SQL과 이력: `docs/database/20261109`, `backend/DATABASE/20261109`에 동일 사본.
- 모든 화면, API, 데이터 계약의 세부 내용은 같은 번호의 상세사양서를 따른다.
