# 20261120_009 품목 기본 거래처 및 구매요청확정 자동 설정 계획서

## 기준 문서

- [작업지시서](../../directions/20261120/20261120_009_item-default-supplier_작업지시서.md)
- [상세 사양서](../../spec/20261120/20261120_009_item-default-supplier_상세사양서.md)

## 목표

품목별 매입 기본 거래처를 도입하고, 단가등록에서 지정·관리하며, 구매요청확정이 요청 불러오기 때 기본 거래처·단가·발주구분을 자동 설정하게 한다.

## 실행 순서

1. **사양서**: 테이블, 저장 규칙, API 변경, 화면 항목을 확정한다.
2. **DB 스크립트** `docs/database/20261120/20261120_006_*` (기존 001~005와 번호 충돌 없음)
   - `create`: `tb_item_default_supplier` 생성, `tb_item_partner_price.order_type` 추가, 한 곳뿐인 품목 자동 지정.
   - `rollback`: 사용자가 만든 기본 거래처·발주구분이 있으면 중단, 없으면 컬럼·테이블 삭제.
   - `change` 이력, `backend/DATABASE` 사본, `db-schema.md`, SQL 정적 테스트.
3. **백엔드 단가 모듈** (`let/co/master/itempartnerprice`): 저장 검증·기본 거래처 반영·자동 해제, 조회 응답 확장, 필터 `NO_DEFAULT_SUPPLIER`, 엑셀 검증.
4. **공통 단가 조회 서비스**(단가 모듈에 신설, 사양 4.0): 거래처 지정 조회와 기본 거래처 기준 일괄 조회를 한 곳에 두고, 확정 모듈의 기존 단가 쿼리·결정 코드를 이 서비스로 옮긴다.
5. **백엔드 확정 모듈** (`let/materials/request/confirm`): `request-details`와 `unit-price`가 공통 서비스를 호출하게 하고, 기본값 일괄 설정과 발주구분을 추가한다.
6. **프론트 단가등록**: 타입·서비스·변경 집합, 트리·거래처 기준·이력 탭 컬럼, 행 폼, 문구, 엑셀.
7. **프론트 구매요청확정**: 불러오기 응답 반영, 구매처 변경 시 발주구분 처리.
8. **검증(마지막에 한 번)**: 백엔드·프론트 집중 테스트, 빌드, JDK 8 컴파일, SQL 정적·임시 DB 검증.
9. **사용자 스크립트 실행 후**: MCP 확인 → 실제 서버 시나리오 → 브라우저·스크린샷 → 결과 문서.

중간 단계(3~7)에서는 해당 영역 단위 테스트와 `tsc`만 돌리고, 전체 실행·실서버·브라우저는 8~9에서 묶어서 한다.

## 의존 관계

- `tb_item_partner_price`(20261118 단가등록 보강 이후 구조), 공통코드 `PURCHASE_ORDER_TYPE`(20261112_001).
- 구매요청확정 단가 조회 규칙(20261118_010)과 같은 선택 규칙을 재사용한다(거래처 단가 → 공통단가, 기준일 유효, 최신 시작일).

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 단가등록은 기준정보 공통 화면이라 매출과 함께 쓴다 | 기본 거래처·발주구분은 매입 행에서만 입력·저장되게 서버에서 검증하고, 매출 관련 응답·화면은 바꾸지 않는다. |
| 기본 거래처가 가리키는 단가가 사라짐 | 비활성화·삭제 저장 시 서버가 자동 해제한다. 확정 조회는 사용 중 거래처만 기본으로 인정한다. |
| 요청 불러오기의 단가 조회가 품목마다 쿼리 | 품목 목록을 한 번에 조회하는 쿼리로 처리한다(최대 200행). |
| 기본 거래처 단가의 통화가 섞임 | 기존 확정의 통화 혼합 경고를 그대로 쓴다. |
| 롤백 시 입력 데이터 손실 | 사용자가 만든 값이 있으면 롤백을 중단한다. |
