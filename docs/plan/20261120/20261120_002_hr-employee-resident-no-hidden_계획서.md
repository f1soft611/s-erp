# 20261120_002 사원등록 주민등록번호 항목 숨김 계획서

기준: [작업지시서](../../directions/20261120/20261120_002_hr-employee-resident-no-hidden_작업지시서.md)

## 구현 단위
1. **테스트 먼저**: 폼 값·요청에 주민번호가 없고 팝업에 주민등록번호 칸이 없으며 생년월일 칸이 있음을 확인하는 테스트로 바꾼다.
2. **프론트**: `EmployeeFormDialog`(칸 제거, 라벨 변경), `employeeForm.ts`(폼 값·검증·요청에서 제거), `employee.types.ts`(폼 값·요청 타입에서 제거).
3. **문서**: 2-1 사양서·결과에 변경 사실을 남기고 이 작업의 사양서·결과를 만든다.

## 영향 범위와 위험
- 백엔드는 그대로다. 요청에 `residentNo`가 없으면 서버는 "미입력(기존 값 유지)"으로 처리하므로 기존 데이터가 지워지지 않는다(저장된 값이 있다면 DB에 남는다).
- 조회 응답의 마스킹 값(`residentNoMasked`)은 계속 내려오지만 화면에서 쓰지 않는다(`EmployeeRow` 타입은 API 계약대로 유지).
- 사번·부서 등 다른 입력과 계정 발급 흐름은 영향이 없다.
- 되돌리기: 팝업 칸과 폼 값·요청 항목을 복구하면 된다(서버·DB는 그대로라 데이터 이전이 필요 없다).
