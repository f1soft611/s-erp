# 20261120_005 사원등록 공통 행 폼 전환 계획서

기준: [작업지시서](../../directions/20261120/20261120_005_hr-employee-common-form_작업지시서.md). 기준 화면: 창고관리(`WarehouseManagementPage`), 일괄 저장 기준: 창고 `save-batch`.

## 구현 단위 (테스트 먼저)
1. **백엔드 일괄 저장**: `EmployeeBatchService`(트랜잭션 하나로 기존 `createEmployee`/`updateEmployee` 호출, 실패 메시지에 사원명 접두), 요청·결과 VO, `EmployeeApiController`의 `POST /save-batch`(관리자 전용). 기존 단건 API는 그대로 둔다.
2. **공통 행 폼 옵션**: `F1GridColumnFormOptions.inputType: 'password'`를 추가해 행 폼의 텍스트 칸을 비밀번호 입력으로 가린다. `F1-GRID.md`와 API 참조 데이터를 같이 갱신한다.
3. **프론트 재구성**(`pages/hr/employee`): 타입(그리드 행), 서비스(일괄 저장), 데이터(컬럼 정의·새 행·payload 변환), 훅(조회·저장), 페이지(창고 페이지와 같은 구조). 부서 선택은 `DepartmentPickerDialog`, 주소는 기존 우편번호 서비스, 사진은 공통 `image` 칸.
4. **정리**: `EmployeeFormDialog`, `EmployeeGrid`, `EmployeePhotoField`, 사번·계정 중복 확인 API 호출부를 제거한다(백엔드 확인 API는 남겨 둠).
5. **검증·문서**: 단위·페이지 테스트, 실서버 브라우저, 2-1 사양·결과 갱신, 결과 문서.

## 위험과 대응
- **저장 방식 변경**: 입력 후 저장 버튼을 눌러야 저장된다 → 변경이 있을 때만 저장 버튼이 활성화되고, 저장하지 않은 변경이 있으면 조회·이탈 시 확인창을 띄운다(창고와 같은 공통 동작).
- **계정 발급 중 일부 실패**: 하나의 트랜잭션이라 전부 취소되고 메시지에 사원명을 붙인다.
- **조건부 칸**: 외국인 전용 칸, 로그인 아이디·초기 비밀번호 칸은 `editable` 함수로 조건에 맞을 때만 폼에 나타난다. 계정이 이미 있는 사원의 실사용자·사번은 읽기 전용이라 폼에서는 보이지 않고 목록 열로만 보인다.
- **사진**: 변경하지 않은 사진은 다시 보내지 않는다(원본과 비교해 바뀐 경우만 전송, 삭제는 빈 값).
- **필수 검증은 클라이언트와 서버 이중**이다. 서버 규칙(사번·이메일 형식, 날짜 순서 등)은 기존 단건 서비스가 그대로 검사한다.
- 사번 중복 즉시 안내가 사라지는 대신 저장 시 메시지로 알린다(사용자 승인된 방향에 포함).
