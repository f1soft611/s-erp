# Document Approval Line Settings Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an approval-line settings dialog to the document composer that edits the current approval stages and references transactionally, with favorites visibly unavailable until persistence contracts exist.

**Architecture:** Keep the existing `DocumentApprovalStage[]` and reference IDs as the source of truth in `useDocumentComposer`. A feature-local `DocumentApprovalSettingsDialog` owns cloned draft state while open and submits both lists only on Apply; `DocumentComposerDialog` wires it to the current state. The dialog reuses `CommonDialog` and `UserSelectEditor`; no persistence service or database contract is invented.

**Tech Stack:** React 19, TypeScript, MUI, Vitest, Testing Library, Vite.

- [ ] **Step 3: 임시 상태와 재정렬 컨트롤 구현**

다음 타입으로 컴포넌트 props를 선언한다. 열릴 때 `approvalStages`의 각 stage와 `users` 배열을 복사하고 참조 ID 배열을 복사한다. 변경 이벤트는 이 로컬 상태만 갱신한다.

```tsx
type DocumentApprovalSettingsDialogProps = {
  open: boolean;
  userOptions: F1GridUserOption[];
  approvalStages: DocumentApprovalStage[];
  referenceUserIds: string[];
  onClose: () => void;
  onApply: (
    approvalStages: DocumentApprovalStage[],
    referenceUserIds: string[],
  ) => void;
};
```

`CommonDialog`를 사용하고, 각 고정되지 않은 stage에 drag handle 및 `"<stage> 위로 이동"`/`"<stage> 아래로 이동"` 버튼을 제공한다. reorder 함수는 `isFixed` stage의 위치를 바꾸지 않고 stage 전체를 이동한다. 결재 추가는 선택된 사용자당 `approval` stage 하나를 만들고, 합의 추가는 사용자 배열 전체를 하나의 `agreement` stage로 만든다. 사용자 삭제는 해당 그룹 내 한 사용자만 제거하며 합의 그룹이 비면 그룹을 삭제한다. 참조는 별도의 다중 `UserSelectEditor`로 편집한다.

즐겨찾기 액션은 disabled로 렌더링하고 눈에 보이는 “저장 테이블/API 준비 후 제공” 설명을 추가한다. API/로컬 저장 호출은 작성하지 않는다. `적용` 시 복사된 두 배열을 `onApply`에 넘기고 `취소`/닫기는 `onClose`만 호출한다.

문서 작성 모달을 열고 `결재선 설정`을 눌렀을 때 결재자/참조자가 현재 작성 상태와 일치하는지 검사한다. 설정 창 안에서 이동 후 취소하면 작성 화면의 기존 순서가 유지되어야 하며, 다시 열고 이동 후 적용하면 단계 순서와 참조자가 부모 작성 상태에 함께 반영되어야 한다. 적용 뒤 새 결재자를 추가했을 때 각 승인 인원은 고유 stage ID를 유지해야 한다.

```tsx
await user.click(screen.getByRole('button', { name: '결재선 설정' }));
await user.click(screen.getByRole('button', { name: '결재 1 아래로 이동' }));
await user.click(screen.getByRole('button', { name: '취소' }));
expect(screen.getByRole('group', { name: '결재 2 기존결재자' })).toBeInTheDocument();
```

통합 테스트에는 고정 기안자, 결재자 1명, 합의 그룹 1개를 구성한다. 취소 후 기존 결재자의 단계 순번은 2로 유지되는지, 재오픈 후 같은 이동을 적용하면 합의 뒤 순번 3으로 변경되는지 확인한다.

- [ ] **Step 3: 편집/반영 흐름 연결**

`DocumentApprovalFields`에 필수 `onOpenApprovalSettings: () => void` prop을 추가하고 `결재 추가`, `합의 추가` 바로 뒤에 `결재선 설정` 버튼을 배치한다. `DocumentComposerDialog`가 `approvalSettingsOpen` 상태와 설정 dialog를 소유한다. Apply callback은 hook의 다음 함수를 사용한다.

```tsx
const replaceApprovalLine = useCallback(
  (stages: DocumentApprovalStage[], references: string[]) => {
    const nextId = stages.reduce((maxId, stage) => Math.max(maxId, stage.id + 1), 1);
    nextStageId.current = Math.max(nextStageId.current, nextId);
    setApprovalStages(stages);
    setReferenceUserIds(references);
  },
  [],
);
```

hook에서 callback을 반환하고 설정 창 Apply에 전달한다. Apply에서는 배열과 각 `users` 배열을 복사해 hook 상태에 전달한다. 설정 창을 여는 동안에는 원본 hook 상태를 수정하지 않는다.
