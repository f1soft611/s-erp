## 목표

일반 F1Grid 행 컨텍스트 메뉴에서 기준 행 바로 위/아래에 새 행을 삽입한다. 현재 `행 추가`/`addRow()` 맨 아래 추가와 F1Tree의 계층형 행 추가는 유지한다.

## 파일 범위

- `frontend/src/shared/components/f1-grid/state/GridState.ts`: 지정 인덱스 삽입 및 ID/index 상태 맵 재구성
- `frontend/src/shared/components/f1-grid/core/F1Grid.tsx`: 메뉴, sort/filter 차단, 행 폼 생성 anchor, 신규 행 스크롤/포커스
- `frontend/tests/f1-grid-row-insertion.test.ts`: 순수 GridState 삽입/변경 추적
- `frontend/tests/f1-grid-context-menu.test.tsx`: 컨텍스트 메뉴 위/아래 삽입, 정렬/필터 차단, append/F1Tree 회귀
- `frontend/tests/f1-grid-form-modal.test.tsx`: 폼 적용 시 기준 위치 삽입 및 취소/검증 실패 회귀
- `frontend/src/pages/f1-grid-docs/F1-GRID.md`: 사용자 동작과 제한 조건 문서화
- `docs/result/20261008/f1-grid-row-insertion/`: 검증 결과와 반응형 브라우저 캡처

## 구현 순서 및 검증

1. `insertGridRow(data, row, rowKey, index)`에 대해 앞/뒤 인덱스, 경계 clamp, duplicate ID 무변경, ID/index map 재구성 및 inserted 변경 추적 테스트를 먼저 추가한다.
2. 테스트 실패를 확인한 뒤 GridState 구현을 추가한다. 기존 `addGridRow`는 새 helper의 끝 인덱스를 사용해 append 계약을 유지한다.
3. 우클릭한 데이터 행 ID를 anchor로 받는 두 메뉴 액션을 추가한다. 빈 영역 또는 F1Tree 컨텍스트에서는 표시하지 않는다.
4. sort/filter가 하나라도 활성일 때 두 액션을 비활성화하고 해제 안내를 표시한다. 사용자 sort/filter 값은 변경하지 않는다.
5. 신규 행 폼이 활성인 경우 anchor와 before/after 방향을 폼 세션에 보관하고, Apply 성공 후 삽입한다. 일반 `addRow()` 폼은 기존처럼 끝에 추가한다.
6. 삽입 후 선택/포커스 상태를 설정하고, 고정/측정 행 높이 모드에 맞춰 신규 행을 viewport 안으로 스크롤한다.
7. F1-GRID 문서 갱신 후 지정된 세 테스트 파일과 프론트엔드 빌드를 실행한다.
8. 대표 F1-Grid 화면을 375px, 768px, 1280px에서 확인하고 결과 폴더에 캡처와 결과 보고서를 저장한다.

## 완료 조건

- 신규 행이 의도한 위치와 변경 추적 데이터에 정확히 반영된다.
- 정렬/필터 활성 중 삽입이 방지되고 기존 설정은 보존된다.
- 대용량/가상 스크롤 및 행 폼 Apply에서도 신규 행이 보이고 편집 가능하다.
- 기존 append, F1Tree 동작, 관련 테스트와 빌드가 모두 정상이다.
- 상세 사양서, F1-GRID 문서, 결과 보고서, 스크린샷이 구현과 일치한다.
