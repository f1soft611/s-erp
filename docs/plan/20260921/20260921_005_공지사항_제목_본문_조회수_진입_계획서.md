# 20260921_005 공지사항 제목·본문 조회수 진입 계획서

## 1. 작업 목적

`더보기` 버튼이 없는 짧거나 본문이 없는 공지는 제목·본문·이미지·첨부파일·댓글 클릭으로 상세 조회 API에 진입한다. `더보기` 버튼이 있는 공지는 기존처럼 `더보기` 클릭에서만 상세 조회 API에 진입한다.

## 2. 기존 구현 및 원인

- `NoticeFeedList`는 `item.body !== item.summary`일 때만 `더보기` 버튼을 렌더링한다.
- 짧은 본문 또는 빈 본문은 `더보기` 버튼이 없고, 현재 제목·본문에는 상세 조회 이벤트가 없다.
- `CommunityNoticePage.handleToggleNoticeExpand`는 기존 더보기 콜백에서 상세 API를 호출하고 서버 응답으로 피드 항목을 갱신한다.

## 3. 설계 결정

- `더보기`가 없는 공지의 제목과 본문을 클릭 가능한 영역으로 만든다.
- 클릭 시 기존 `handleToggleNoticeExpand`를 재사용해 상세 API를 호출한다.
- 서버 응답의 `viewCount`를 포함한 상세 데이터를 기존 피드 항목에 병합한다.
- `더보기`가 있는 공지의 제목·본문·이미지·첨부파일·댓글 클릭은 조회수 트리거에서 제외한다.
- `더보기`가 없는 공지의 이미지 미리보기, 첨부파일, 댓글 입력·버튼은 기존 동작을 유지하면서 상세 조회를 한 번 시도한다.
- 메뉴와 카드 여백은 조회수 트리거에서 제외한다.
- 요청 중인 공지는 중복 상세 요청을 막고, 실패 시 카드 표시와 현재 확장 상태를 유지한다.

  - 키보드 접근성 속성 및 요청 중 표시 상태 적용

- 백엔드·DB 변경 없음
- 조회수 증가는 기존 사용자별 조회 이력 정책에 따름

1. 제목 클릭 시 `onToggleExpand`가 호출되는지 테스트한다.

3. 더보기 버튼이 있는 기존 공지의 동작이 유지되는지 테스트한다.
4. `더보기` 없는 공지의 이미지·첨부파일·댓글 인터랙션이 기존 동작과 상세 조회를 함께 실행하는지 테스트한다.
5. `더보기` 있는 공지의 제목·본문·이미지·첨부파일·댓글 인터랙션이 조회를 호출하지 않는지 테스트한다.
6. 메뉴와 카드 여백이 상세 조회를 호출하지 않는지 테스트한다.
