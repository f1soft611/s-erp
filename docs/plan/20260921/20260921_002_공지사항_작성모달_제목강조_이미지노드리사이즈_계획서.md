# 20260921_002 공지사항 작성 모달 제목 강조 및 이미지 노드 리사이즈 계획서

## 1. 작업 목적

공지사항 작성·수정 모달의 제목 입력 텍스트를 피드 제목과 같은 굵기로 표시하고, 본문 이미지 선택 시 이미지 노드 경계에서 직접 크기를 조절할 수 있도록 편집 UI를 보완한다. 백엔드 API와 DB 스키마는 변경하지 않는다.

## 2. 기존 구현 및 원인

- `NoticeComposerDialog`는 Tiptap `Image` 확장을 확장한 `NoticeImage`를 사용한다.
- 현재 이미지 선택 시 문서 바깥에 고정된 단일 우측 핸들 버튼을 생성한다.
- 현재 포인터 이동은 이미지 노드의 `width`만 갱신하며, 높이·비율·방향별 조절을 지원하지 않는다.
- 제목 `TextField`에는 입력 텍스트의 굵기를 지정하는 스타일이 없다.
- 피드 제목은 `NoticeFeedList`에서 `fontWeight: 700`으로 렌더링된다.

## 3. 설계 결정

### 3.1 이미지 리사이즈

기존 이미지 선택 및 `updateAttributes` 흐름을 유지하는 선택 이미지 오버레이 방식을 사용한다.

- 선택된 이미지의 `getBoundingClientRect()`를 기준으로 오버레이 경계를 계산한다.
- 오버레이에 네 모서리와 네 변의 포인터 조절 영역을 둔다.
- 모서리 조절은 시작 이미지의 종횡비를 이용해 `width`와 `height`를 함께 계산한다.
- 좌우 변은 너비, 상하 변은 높이를 조절한다.
- 너비는 120~1200px로 제한하고 높이는 양수 및 에디터 영역에 맞는 최소값으로 제한한다.
- 포인터 이동 중 `updateAttributes('image', { width, height })`를 실행한다.
- 에디터 업데이트, 선택 변경, 스크롤, 창 크기 변경 시 오버레이를 재배치한다.
- 별도 우측 고정 핸들 버튼과 해당 스타일은 제거한다.

### 3.2 제목 스타일

제목 `TextField`의 입력 슬롯에 `fontWeight: 700`을 적용한다. placeholder는 기존 색상과 표시 정책을 유지한다.

## 5. 데이터 및 API 영향

- API 엔드포인트, HTTP 메서드, 요청·응답 필드 변경 없음
- 이미지 크기는 기존 Tiptap 본문 JSON/HTML의 이미지 `width`·`height` 속성으로 유지
- 백엔드 및 DB 변경 없음

## 6. 검증 계획

1. 관련 Vitest에서 제목 스타일과 이미지 크기 계산을 좁게 검증한다.
2. `npm run build`로 TypeScript와 Vite 번들을 검증한다.
3. 실제 브라우저에서 이미지 클릭 후 노드 경계 표시를 확인한다.
4. 375px과 1280px 이상에서 네 모서리·네 변 리사이즈와 화면 잘림 여부를 확인한다.
5. 이미지 크기 변경 후 저장하고 수정 모달 재진입 시 크기가 유지되는지 확인한다.
6. 결과 문서에 명령 결과와 브라우저 스크린샷 경로를 기록한다.

## 7. 태스크 분해

1. 이미지 방향별 크기 계산 규칙과 테스트를 정의한다.
2. 기존 단일 핸들을 제거하고 선택 이미지 경계 오버레이를 구현한다.
3. 제목 입력 굵기 스타일과 관련 렌더링 테스트를 추가한다.
4. 관련 Vitest 및 프론트 빌드를 실행한다.
5. 브라우저 검증과 결과 문서를 작성한다.
