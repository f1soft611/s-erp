# 20260921_003 공지사항 조회수 등록 상세 실행 계획

## Global Constraints

- 현재 브랜치에서 진행하며 Worktree를 생성하지 않는다.
- 사용자당 공지글 최초 1회만 증가하는 승인 사양을 준수한다.
- 중복 키는 `tenant_id + post_id + login_id`이며, DB 유니크 제약을 최종 기준으로 한다.
- 기존 사용자 변경을 되돌리지 않는다.
- 커밋·병합·Push는 사용자 요청 없이는 수행하지 않는다.
- 각 태스크 완료 후 지정된 좁은 검증을 실행하고 결과를 원장에 기록한다.

## Interfaces

- `NoticeBoardApiController`는 인증 사용자 식별자를 서비스에 전달한다.
- `NoticeBoardService`와 구현체는 `tenantId`, `postId`, `loginCode`를 이용해 상세 조회를 처리한다.
- DAO/Mapper는 로그인 계정 PK 해석, 조회 이력 최초 등록, 조회수 원자 증가를 제공한다.
- DB DDL은 양쪽 날짜별 폴더에 동일하게 유지한다.

## 실행 태스크

### Step 1: DB 변경 스크립트와 문서 계약 점검

- 파일: `backend/DATABASE/20260921/20260921_003_create_board_post_view_history.sql`, `docs/database/20260921/20260921_003_create_board_post_view_history.sql`
- 파일: 양쪽 `*_change_schema.md`, `*_rollback.sql`, `docs/database/db-schema.md`
- 작업: `tb_board_post_view_history` 테이블, FK, 복합 유니크 제약, 조회 인덱스가 사양과 일치하는지 확인하고 현재 MCP 메타데이터와 충돌이 없는지 확인한다.
- 검증: SQL 정적 검토 및 `git diff --check`
- 완료 조건: 양쪽 SQL이 동일하고 rollback이 역순으로 동작하며 스키마 문서가 테이블 계약을 포함한다.

### Step 2: RED 테스트 작성

- 파일: `backend/src/test/java/egovframework/let/groupware/community/notice/service/impl/NoticeBoardServiceImplTest.java`
- 작업: 최초 조회 증가, 동일 사용자 재조회 미증가, 다른 사용자 증가, 삭제·미존재 미기록을 검증하는 실패 테스트를 기존 테스트 패턴에 맞춰 추가한다.
- 검증: `cd backend; mvn "-Dtest=NoticeBoardServiceImplTest" test`
- 완료 조건: 새 테스트가 구현 전 의도대로 실패하고 실패 원인이 미구현 조회수 처리로 식별된다.

### Step 3: DAO와 MyBatis Mapper 구현

- 파일: `backend/src/main/java/egovframework/let/groupware/community/notice/domain/repository/NoticeBoardDAO.java`
- 파일: `backend/src/main/resources/egovframework/mapper/let/groupware/community/notice/NoticeBoard_SQL_postgresql.xml`
- 작업: `login_code + tenant_id`로 로그인 계정 PK를 찾는 조회, `ON CONFLICT DO NOTHING RETURNING` 기반 최초 이력 등록, `view_count = view_count + 1` 원자 UPDATE를 추가한다.
- 검증: `cd backend; mvn "-DskipTests" compile`
- 완료 조건: Mapper XML이 PostgreSQL 문법과 기존 MyBatis 스타일에 맞고 컴파일된다.

### Step 4: 서비스·컨트롤러 계약 연결

- 파일: `backend/src/main/java/egovframework/let/groupware/community/notice/service/NoticeBoardService.java`
- 파일: `backend/src/main/java/egovframework/let/groupware/community/notice/service/impl/NoticeBoardServiceImpl.java`
- 파일: `backend/src/main/java/egovframework/let/groupware/community/notice/controller/NoticeBoardApiController.java`
- 작업: 인증 사용자 로그인 코드를 전달하고, 트랜잭션 내부에서 최초 이력 등록 성공 시에만 증가한 뒤 재조회하여 응답한다. 기존 목록 조회와 외부 API 구조는 유지한다.
- 검증: `cd backend; mvn "-Dtest=NoticeBoardServiceImplTest" test`
- 완료 조건: 최초/중복/다중 사용자 테스트가 통과하고 삭제·미존재 흐름이 기존 404 정책을 유지한다.
