# 20260923_001 공지사항 리스트·상단고정 우측 상세 패널 계획서

## 1. 목표

공지사항 리스트형 보기와 상단 고정 영역에서 게시글을 선택하면 목록을 유지한 채 우측 상세 패널에서 피드형 게시글 카드 하나와 동일한 전체 기능을 제공한다. 데스크톱은 `ContentSplitLayout`의 우측 슬롯을 사용하고, 모바일은 전체 화면 드로어/모달로 표시한다. 상세 패널은 공지사항 어댑터를 첫 적용 대상으로 삼되, 게시판·자료실에서도 데이터·액션 어댑터를 교체해 재사용할 수 있는 구조로 만든다.

## 2. 작업 분류 및 대상

- 분류: `bounded`
- 대상: 프론트엔드
- 화면: `/groupware/community/notice`
- 주요 영역: `CommunityNoticePage`, `NoticeFeedList`, `ListView`, `PinnedItemsPanel`, 공통 상세 패널 컴포넌트
- 백엔드/DB: 변경 없음

## 3. 요구사항 분석

- 리스트형 항목과 상단 고정 항목은 선택 시 같은 상세 패널을 연다.
- 다른 항목을 선택하면 상세 대상과 패널 내용이 교체된다.
- 닫기 버튼은 선택 상태를 해제하고 기존 요약 패널을 복원한다.
- 상세는 본문, 이미지, 첨부, 좋아요, 북마크, 댓글·답글, 댓글 수정·삭제, 게시글 수정·삭제를 포함한다.
- 게시글 더보기 메뉴는 현재 사용자와 게시글 작성자가 일치할 때만 표시한다.
- 게시글 작성자 판정은 표시명 문자열이 아니라 API의 `writerId`와 인증 사용자 식별자를 사용한다. 현재 화면 모델에 필요한 필드가 없으면 공지 어댑터에서 연결한다.
- 피드형 보기의 기존 인라인 동작은 회귀 없이 유지한다.
- 모바일에서는 우측 슬롯을 억지로 유지하지 않고 전체 화면 상세로 전환한다.

## 4. 구현 범위

### 4.1 공통 상세 패널

- 게시글 데이터, 댓글, 첨부, 이미지, 반응, 관리 액션을 props/어댑터 계약으로 받는 재사용 가능한 상세 패널을 구성한다.
- 기존 피드 게시글 카드의 렌더링과 상호작용을 공통 패널에서 재사용할 수 있도록 책임을 분리한다.
- 패널 닫기, 선택 게시글 교체, 상세 조회 중/실패 상태를 공통 상태 계약으로 표현한다.
- 공지사항에만 필요한 API 변환·액션 연결은 공지 어댑터에 둔다.

### 4.2 공지사항 페이지

- 선택된 게시글 ID 또는 선택된 게시글 상태를 `CommunityNoticePage`에서 관리한다.
- 리스트형 `ListView`와 `PinnedItemsPanel`에 `onItemClick` 및 선택 상태 표시를 연결한다.
- 기존 `fetchNoticePostDetail` 및 상세 응답 병합 흐름을 선택 패널 진입에 연결한다.
- 우측 슬롯에는 선택된 상세 패널을 표시하고, 선택이 없으면 `NoticeSummaryPanel`을 표시한다.
- 모바일에서는 동일 상세 패널을 전체 화면 드로어/모달로 렌더링한다.
- 상세 패널의 수정/삭제 액션은 기존 작성 모달과 삭제 핸들러를 재사용한다.

### 4.3 모델·권한

- `NoticeBoardPostApi.writerId`를 화면 모델까지 보존하거나 공지 상세 어댑터가 작성자 판정에 사용할 수 있도록 한다.
- 인증 저장소의 현재 사용자 ID를 기존 방식으로 읽는다. 새로운 사용자 식별 체계는 추가하지 않는다.
- `isPostOwner`는 `writerId`와 현재 사용자 ID의 정규화된 비교 결과로만 계산한다.
- 댓글별 `isEditable` 권한은 기존 API 응답과 `CommentThread` 흐름을 유지한다.

### 4.4 문서·검증

- 공지 페이지 테스트에 리스트/고정 선택, 패널 교체·닫기, 작성자 메뉴 표시, 전체 기능 렌더링 회귀를 추가한다.
- 실제 브라우저에서 375px, 768px, 1280px 화면을 캡처해 패널 전환, 가로 스크롤, 겹침, 텍스트 잘림을 확인한다.
- 결과 문서와 작업 원장에 테스트·빌드·브라우저 증거를 기록한다.

## 5. 제외 범위

- 백엔드 API, DB 스키마, 권한 정책 변경
- 게시판·자료실 화면에 이번 작업에서 직접 적용
- 게시글 상세 URL 또는 라우팅 추가
- 피드형 목록의 기존 인라인 상세 UX 개편
- 전역 레이아웃과 패널 너비의 대규모 개편

## 6. 영향 범위

- 화면 상태: 선택 게시글, 상세 로딩, 패널 닫기/교체
- 공통 UI: 게시글 상세 패널과 기존 피드 카드 렌더링 책임 분리
- 목록 UI: 리스트형·상단 고정 클릭과 선택 표시
- 서비스 계약: 기존 상세 조회 API와 `writerId` 모델 전달
- 테스트: 공지 페이지/피드 관련 Vitest, 반응형 브라우저 검증

## 7. 검증 계획

1. 공지 관련 단위·컴포넌트 테스트로 선택, 닫기, 작성자 메뉴, 기능 보존을 확인한다.
2. `cd frontend; npm run build`로 타입과 번들을 검증한다.
3. `cd frontend; npm run test`로 전체 프론트 회귀를 확인한다.
4. 개발 서버와 Playwright로 375px, 768px, 1280px에서 리스트/고정 선택, 패널 표시, 모바일 전체 화면 전환을 확인한다.
5. 실패 시 결과 문서에 원인과 재검증 결과를 기록한다.

## 8. 완료 조건

- 작업지시서와 상세 사양서에 명시된 모든 동작이 구현된다.
- 리스트형·상단 고정 선택, 패널 교체·닫기, 모바일 전환이 동작한다.
- 패널이 피드 게시글 카드와 동일한 전체 기능을 제공한다.
- 작성자 본인 글에서만 게시글 더보기 메뉴가 보인다.
- 피드형 기존 동작이 회귀하지 않는다.
- 빌드·테스트·브라우저 검증과 결과 문서가 남는다.
