# 20260923_009 프로필 내 정보 관리·보안 설정 상세 실행 계획

## Global Constraints

- 현재 브랜치 `socra710`에서 진행하고 기존 사용자 변경사항은 보존한다.
- 승인된 작업지시서·계획서·상세 사양서 범위만 수정한다.
- 본인 식별자는 요청 본문이 아니라 인증된 `LoginVO`에서 결정한다.
- 신규 DB 스키마는 만들지 않고 기존 `tb_user`·`tb_login_account` 컬럼만 사용한다.
- 비밀번호·토큰·원본 이미지 데이터는 로그와 테스트 출력에 기록하지 않는다.
- 백엔드 Java 소스/테스트는 프로젝트의 Java 8 컴파일 설정과 호환되게 작성한다.
- 각 태스크 완료 후 지정된 좁은 검증을 수행한다. 커밋은 사용자가 통합 방식을 선택하기 전에는 생성하지 않는다.

## Interfaces

- Frontend profile service ↔ `GET/PUT /api/v1/users/me/profile`
- Frontend security service ↔ `PUT /api/v1/users/me/password`
- Dashboard profile actions ↔ `/dashboard/profile`, `/dashboard/security`
- Backend controller ↔ authenticated `LoginVO` and profile/password service
- Existing `GET /api/v1/menus/my` profile summary ↔ updated profile response

## Task 2: 백엔드 프로필 도메인 계약

- 파일: `backend/src/main/java/egovframework/let/uat/uia/service/impl/LoginDAO.java`, `backend/src/main/resources/egovframework/mapper/let/uat/uia/EgovLoginUsr_SQL_postgresql.xml`
- 생성 파일: 사용자 프로필 DTO/서비스/컨트롤러는 기존 `egovframework.let` 도메인 패턴에 맞춰 배치한다.
- 작업: 본인 프로필 조회, 이메일·프로필 이미지·도장 이미지 갱신 SQL과 서비스 검증을 구현한다. 인증 주체의 tenant/login 식별자를 사용하고 요청 대상 ID는 받지 않는다.

- 테스트: 컨트롤러/서비스 테스트에서 성공, 잘못된 이미지, 타 사용자 대상 지정, 이메일 오류를 검증한다.
- 검증: `mvn "-Dtest=UserProfileApiControllerTest,UserProfileServiceImplTest" test`
- 완료 인터페이스: Task 4 프론트 서비스가 사용할 응답 envelope와 오류 상태.

## Task 3: 백엔드 비밀번호 변경 계약

- 파일: `backend/src/main/java/egovframework/let/uat/uia/service/impl/LoginDAO.java`, `backend/src/main/resources/egovframework/mapper/let/uat/uia/EgovLoginUsr_SQL_postgresql.xml`
- 생성 파일: 보안 설정 요청 DTO/서비스/컨트롤러는 기존 로그인 서비스 계층과 같은 패키지 규칙으로 배치한다.
- 작업: 현재 비밀번호를 기존 암호화 방식으로 검증하고, 새 비밀번호 정책과 확인값을 검증한 뒤 `password_hash`, `password_changed_at`을 갱신한다.
- 작업: 인증된 로그인 계정만 수정하며 성공 응답에 비밀번호나 토큰을 포함하지 않는다.
- 테스트: 현재 비밀번호 불일치, 확인값 불일치, 성공 해시 갱신, 타 사용자 대상 차단을 검증한다.
- 검증: `mvn "-Dtest=PasswordChangeApiControllerTest,PasswordChangeServiceImplTest" test`
- 완료 인터페이스: Task 5 프론트 보안 서비스가 성공 후 `logout()`을 호출할 수 있는 200 응답 계약.
