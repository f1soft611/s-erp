# 20260923_002 최근 사용 메뉴 세션 유지 계획서

## 1. 목적

로그인 세션 동안 사용자가 최근에 방문한 메뉴를 기억하고, 좌측 모듈 사이드바 하단에서 빠르게 다시 이동할 수 있도록 한다. 기존 경로 기반 구조와 사이드바 선택 로직은 유지하고, 최근 사용 메뉴는 보조 UX로만 제공한다.

## 2. 작업 범주

- 대상: 프론트엔드
- 화면: 대시보드/사이드바 전체 레이아웃, `DashboardPage`, `DashboardSidebar`, `DashboardMenuTree`
- 범위: 최근 사용 메뉴 저장/복구, 세션 스코프 히스토리, 하단 프로필 영역 정리, 메뉴 선택 UX 유지
- 제외: 상단 탭형 네비게이션, 전역 페이지 상태 영구 복원, 서버 DB 기반 저장

## 3. 현재 상태와 문제점

- 현재 구조는 경로와 모듈/메뉴를 계산해 상태를 재구성하는 방식이라 세션 동안 최근 경로를 보관하지 않는다.
- 사용자가 여러 화면을 오가면 최근에 작업하던 메뉴를 빠르게 복귀하기 어렵다.
- 모듈 사이드바 하단의 사용자 프로필 영역이 메뉴와 어색하게 섞여 있어 공간 활용이 떨어진다.
- 기존 구조는 탭형 네비게이션을 추가하지 않고도 세션 히스토리를 제공할 수 있는 여지가 있다.

## 4. 요구사항 분해

### 4.1 최근 사용 메뉴

- 로그인 세션 동안 최근 방문 메뉴를 저장한다.
- 동일 메뉴를 다시 방문하면 기존 기록이 최신 순으로 갱신된다.
- 오래된 기록은 자동 제거한다.
- 최근 메뉴는 최대 5~8개로 제한한다.
- 클릭 시 해당 경로로 즉시 이동한다.
- 세션 종료 시 기록은 제거된다.

### 4.2 사이드바 하단 프로필

- 기존 사용자 프로필은 좌측 모듈 사이드바 하단에 유지한다.
- 프로필은 사진 중심의 간결한 구성으로 정리한다.
- 전체 이름/이메일 전부를 메인 구성으로 두지 않고, 핵심 정보는 간략한 형태로 제공한다.
- 메뉴 우선 UX를 유지하면서 프로필 영역은 보조 UI로 배치한다.

### 4.3 구조 유지

- 기존 모듈 선택, 메뉴 트리, 라우팅, 선택 표시 로직을 유지한다.
- 상단 탭형 구조를 도입하지 않는다.
- 현재 `sessionStorage` 기반으로 최근 메뉴를 관리하는 최소 구현을 적용한다.

## 5. 구현 계획

### 5.1 최근 메뉴 관리 로직

- `DashboardPage` 또는 사이드바 관련 훅에서 최근 메뉴 상태를 계산한다.
- `sessionStorage` 키를 하나 정해 선택/이동 이벤트를 저장한다.
- 메뉴 선택 시 중복 제거, 최신화, 개수 제한, 정렬을 처리한다.
- 초기 진입 시 저장된 히스토리를 읽어 UI에 반영한다.

### 5.2 사이드바 하단 UI

- `DashboardMenuTree` 내부 하단 영역을 프로필 카드 레이아웃으로 정리한다.
- 프로필 영역은 avatar 중심으로 축약하고, 불필요한 텍스트는 축소하거나 팝오버로 비활성화한다.
- 최근 사용 메뉴 영역은 sidebar 하단 리스트로 배치하되 구조적 우선순위는 메뉴 트리보다 낮게 유지한다.

### 5.3 유저 흐름

- 로그인 후 메뉴를 이동할 때마다 히스토리가 업데이트된다.
- 사이드바 하단에서 최근 항목을 클릭하면 해당 화면으로 즉시 이동한다.
- 선택된 메뉴와 최근 메뉴는 각각 별도 상태로 유지하되, 현재 선택 로직과 충돌하지 않도록 한다.

## 6. 검증 계획

1. 최근 메뉴 기록이 세션 동안 유지되는지 확인한다.
2. 같은 메뉴를 반복 방문해도 중복 기록이 하나만 남는지 확인한다.
3. 최근 5~8개만 노출되는지 확인한다.
4. 사이드바 하단 프로필이 모듈 하단에 고정되어 보이는지 검증한다.
5. 메뉴 트리 선택 상태와 라우팅 동작이 유지되는지 확인한다.
6. 브라우저에서 실제 사이드바 레이아웃을 확인한다.

## 7. 완료 기준

- 최근 메뉴 히스토리가 세션 스코프에서 유지된다.
- 하단 프로필 영역이 모듈 사이드바 하단에 유지된다.
- 최근 메뉴를 클릭해 이동할 수 있다.
- 사이드바 메뉴 우선 UX를 유지한 상태로 구현된다.
- 관련 문서와 결과 기록이 작성된다.

## 8. 승인 조건

구현을 시작하기 전에 이 계획서와 상세 사양서의 내용이 사용자 요구와 일치하는지 확인한다. 내용에 대한 명시적 승인이 있어야 코드 수정 단계로 넘어간다.
