# 20260923_004 페이지영역 우측 오버레이 상세 패널 계획서

## 1. 목표

공지사항 상세 오버레이가 공통 상단 헤더와 로그아웃 영역을 덮지 않고, 헤더 아래 `DashboardContent` 페이지 영역만 덮도록 조정한다. 기존 넓은 우측 패널의 본문·댓글·첨부·독립 스크롤·닫기 동작은 유지한다.

## 2. 범위

- 대상: 프론트엔드
- 화면: `/groupware/community/notice`
- 주요 파일: `DashboardContent`, `CommunityNoticePage`, `PostDetailPanel`, 공지 관련 테스트
- 백엔드·DB·API: 변경 없음
- 공지사항 외 게시판·자료실·그룹웨어 적용: 제외

## 3. 구현 계획

### Step 1. 페이지 영역 오버레이 RED 테스트

- 상세 패널의 부모 호스트가 `data-page-overlay-host`를 제공하는지 테스트한다.
- 헤더와 로그아웃 버튼이 패널 오버레이의 DOM/레이어 밖에 유지되는 레이아웃 계약을 추가한다.
- 패널 경계가 페이지 영역 기준이라는 테스트용 속성을 정의한다.

### Step 2. 페이지 콘텐츠 오버레이 호스트 추가

- `DashboardContent`를 감싸는 페이지 콘텐츠 래퍼 또는 공지 페이지용 호스트를 `position: relative; min-height: 0; overflow: hidden` 기준으로 구성한다.
- 공지 페이지가 해당 호스트 내부에 상세 패널을 렌더링할 수 있도록 공통 페이지 오버레이 슬롯을 추가한다.
- 헤더가 포함된 `DashboardPage` 상위 셸과 오버레이 레이어를 분리한다.

### Step 3. Drawer를 페이지 영역 기준으로 변경

- `CommunityNoticePage`의 body 포털 Drawer 사용을 제거하거나 페이지 호스트에 연결한다.
- 패널은 `position: absolute; inset: 0 0 0 auto`로 페이지 영역의 오른쪽에 배치한다.
- 데스크톱 폭은 `min(960px, 72vw)`, 모바일은 `100vw`를 유지한다.
- 백드롭, Escape, 닫기 버튼, 독립 스크롤을 유지한다.
- 목록은 오버레이 뒤에 남기고 헤더는 오버레이 위 또는 오버레이 범위 밖에 둔다.

### Step 4. 회귀 검증

- 공지 상세 기존 기능과 선택 교체 동작을 유지한다.
- 패널이 열렸을 때 공통 헤더의 로그아웃 버튼이 계속 렌더링되고 클릭 가능한지 검증한다.
- 375px·768px·1280px에서 패널 rect가 헤더 아래 시작하고 viewport 오른쪽을 벗어나지 않는지 확인한다.

### Step 5. 빌드·브라우저·결과 문서

- 관련 Vitest
- `npm run build`
- 개발 서버 + Playwright 브라우저 캡처
- 결과 문서와 원장 갱신

## 4. 리스크 및 대응

- MUI Drawer 포털은 기본적으로 body에 렌더링되므로 페이지 영역 경계를 보장하지 못한다. 페이지 호스트 내부 렌더링 또는 포털 컨테이너 지정으로 해결한다.
- 페이지 영역의 높이가 콘텐츠에 따라 줄어들지 않도록 `flex: 1`, `min-height: 0`, `position: relative`를 함께 적용한다.
- 공통 헤더 z-index를 변경하지 않아 로그아웃·알림 액션의 접근성을 보존한다.

## 5. 제외 범위

- 헤더·로그아웃 UI 변경
- 게시글 API·권한·DB 변경
- 패널 내부 콘텐츠 기능 개편
- 다른 게시판 화면 적용
