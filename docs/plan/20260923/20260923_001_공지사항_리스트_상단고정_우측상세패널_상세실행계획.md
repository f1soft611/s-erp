# 20260923_001 공지사항 리스트·상단고정 우측 상세 패널 상세 실행 계획

## Global Constraints

- 현재 브랜치 `socra710`에서 진행하며 새 Worktree는 생성하지 않는다.
- 기존 사용자 변경 및 날짜별 문서 파일은 되돌리거나 덮어쓰지 않는다.
- 작업 범위는 프론트엔드 공지사항 화면과 재사용 가능한 상세 패널 UI로 제한한다.
- 백엔드·DB·API 엔드포인트는 변경하지 않는다.
- 피드형 기존 인라인 상세 동작은 유지한다.
- 게시글 작성자 여부는 표시명 비교가 아니라 `writerId`와 현재 인증 사용자 ID의 정규화 비교로 판단한다.
- 각 구현 태스크는 관련 테스트를 먼저 RED로 추가하고 최소 GREEN을 만든 뒤 리팩터링한다.
- 같은 파일을 수정하는 태스크는 병렬로 실행하지 않는다.

## Step 1: 공통 상세 패널 테스트 계약 작성

- 파일: `frontend/tests/notice-detail-panel.test.tsx` 신규
- 작업: 피드 카드와 동일한 제목·본문·첨부·반응·댓글·게시글 메뉴·닫기 요소의 렌더링 계약을 실패 테스트로 정의한다. `isPostOwner=true`일 때 메뉴가 보이고 false/undefined일 때 게시글 수정·삭제 메뉴가 숨겨지는 케이스를 추가한다.
- 검증: `cd frontend; npm run test -- tests/notice-detail-panel.test.tsx`
- 예상 결과: 아직 패널 컴포넌트가 없어 모듈/요소 관련 RED 실패
- Interface: 공통 패널은 공지 데이터와 명시적 액션 props를 받아 렌더링한다.

## Step 2: 공통 상세 패널과 공지 어댑터 구현

- 파일: `frontend/src/shared/components/feed/PostDetailPanel.tsx` 신규 또는 기존 공통 feed 영역의 동등한 파일

- 예상 결과: Step 1 RED가 GREEN으로 전환되고 기존 공지 피드 렌더링 계약이 유지된다.
- Interface: 패널은 API 호출을 직접 수행하지 않고 데이터·액션 props만 사용한다.
