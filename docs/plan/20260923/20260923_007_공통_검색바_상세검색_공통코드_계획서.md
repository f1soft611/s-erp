# 20260923_007 공통 검색바 상세 검색 및 공통코드 적용 계획서

## 1. 목적

공통 `PageSearchArea`를 기본 한 줄 검색과 화면 덮개형 상세 검색 오버레이 구조로 확장하고, 공통코드 관리 그룹 목록에 F1-Grid 컬럼 기반 동적 검색 필드를 적용한다. 검색 실행은 프론트 목록 필터링이 아니라 공통코드 그룹 조회 API에 조건을 전달하는 서버 조회로 수행한다.

## 2. 작업 범위

### 프론트엔드

- `PageSearchArea`의 기본 한 줄 레이아웃, 우측 토글, 상세 검색 오버레이, 검색 닫기/실행 동작 구현
- F1 컬럼 메타데이터를 검색 필드 정의로 변환하는 공통 타입/유틸리티 구현
- `text`, 숫자 계열, `date` 범위(from/to), `select`, `checkbox` 타입 매핑
- 폼모달의 `form` 옵션과 대칭적인 `search.hidden/label/group/order/span` 옵션 지원
- 데스크톱 상세 검색 최대 5열 및 태블릿/모바일 반응형 축소
- 공통코드 관리 그룹 컬럼을 검색 기준으로 연결
- 기본 검색어와 상세 검색 조건 상태를 공통코드 페이지에서 관리
- 검색 실행 시 그룹 조회 API 호출 및 로딩/오류/미저장 변경 확인 흐름 유지
- 프론트 단위/컴포넌트 테스트와 반응형 브라우저 검증

### 백엔드

- 공통코드 그룹 조회 Controller에 선택적 query parameter 수신
- Service/DAO에 tenant ID와 검색 조건 전달
- MyBatis PostgreSQL 조회문에 기본 keyword OR 검색 및 상세 조건 AND 검색 추가
- 기존 응답 envelope, tenant 제한, 정렬, 권한 정책 유지
- Controller/Service/Mapper 관련 테스트 추가 또는 보강

### 데이터베이스 및 문서

- DB 스키마 변경 없음
- `tb_common_code_group`의 기존 `tenant_id`, `group_code`, `group_nm`, `group_dc`를 조회 조건으로 사용
- PostgreSQL 읽기 전용 MCP로 대상 테이블 컬럼 계약 확인 완료
- 날짜별 SQL/롤백/스키마 누적 문서 변경 없음
- 구현 후 `docs/result/20260923/common-searchbar-detail-search/`에 원장, 검증 결과, 스크린샷 작성

## 3. 영향 범위

- 공통 UI: `frontend/src/shared/components/PageSearchArea.tsx`
- 공통 F1 검색 타입/유틸리티: `frontend/src/shared/components` 내 기존 구조에 맞춰 최소 추가
- 대표 화면: `frontend/src/pages/co/master/common-code/`
- API: `backend/src/main/java/egovframework/let/co/master/commoncode/` 및 PostgreSQL Mapper XML
- 테스트: 대표 화면/공통 컴포넌트 프론트 테스트와 공통코드 백엔드 테스트
- 제외 화면: 현재 공통 검색바를 사용하는 나머지 4개 화면의 상세 검색 적용

## 4. 구현 단계 개요

1. 실패 테스트로 검색 필드 타입 매핑, 날짜 범위 상태, API query parameter 계약을 고정한다.
2. 공통 검색 필드 타입과 컬럼 변환 유틸리티를 구현한다.
3. `PageSearchArea`에 기본 한 줄 UI와 화면 덮개형 상세 오버레이를 구현한다.
4. 공통코드 그룹 컬럼을 검색 어댑터로 연결하고 검색 실행 상태를 페이지에 연결한다.
5. 백엔드 Controller, Service, DAO, Mapper에 선택적 그룹 검색 조건을 연결한다.
6. 프론트와 백엔드 테스트를 실행하고 실패 원인을 수정한다.
7. 375px, 768px, 1280px에서 브라우저 레이아웃과 실제 검색 흐름을 검증한다.
8. 결과 문서, 검증 명령, 스크린샷, 잔여 위험을 기록한다.

## 5. 검증 계획

### Frontend

- `cd frontend; npm run test -- ...`로 공통 검색 컴포넌트 및 공통코드 검색 테스트
- `cd frontend; npm run build`
- 필요 시 `npm run lint`

### Backend

- `cd backend; mvn test` 또는 영향 범위의 공통코드 테스트
- Controller query parameter와 Mapper 조건 테스트

### Browser

- 개발 서버를 실행하고 Playwright로 공통코드 관리 화면에 진입
- 상세 검색 열기/닫기, text/날짜 범위 필드 확인
- 검색 실행 후 API 요청 및 결과 갱신 확인
- 375px, 768px, 1280px 캡처

## 6. 완료 기준

- 계획서와 상세 사양서에 정의된 범위 안에서만 구현된다.
- 기본 검색은 한 줄로 유지되고 상세 검색은 콘텐츠 높이를 늘리지 않는다.
- `date`는 from/to 범위 검색으로 동작한다.
- 공통코드 그룹 조회 API가 기본/상세 조건을 실제 SQL에 반영한다.
- tenant 조건, 기존 저장 경고, 응답 구조가 회귀하지 않는다.
- 관련 테스트/빌드/브라우저 검증 증거와 결과 문서가 남는다.

## 7. 승인 조건

이 계획서와 상세 사양서가 승인된 뒤에만 4단계 워크트리 확인과 5단계 상세 실행 계획을 진행한다.
