# 20260923_006 프로필 부서·직급 및 페이지 상태 복원 계획서

## 1. 목적

로그인 사용자 프로필에 부서명과 직급명을 동적으로 표시하고, 공통코드 관리 화면의 검색·선택·상세 조회 상태를 로그인 세션 동안 복원할 수 있는 재사용 공통 훅을 적용한다.

## 2. 작업 범위

### 백엔드

- `tb_user.level_id` nullable 컬럼과 `tb_common_code_item` FK 추가
- 로그인 사용자 조회 SQL에 부서명과 직급 ID/코드/명 추가
- `LoginVO`, JWT claims, JWT 복원 로직 확장
- `/api/v1/menus/my`의 사용자 요약에 부서·직급 필드 추가

### 프론트엔드

- 프로필 타입 및 AppBar 팝오버에 `departmentName`, `levelId`, `levelCode`, `levelName` 반영
- 기존 역할 표시를 보조 정보로 유지하고 부서·직급을 우선 표시
- 페이지 key 기반 `usePageSessionState` 저장·복원 패턴 정리
- 공통코드 관리에서 검색어, 그룹 선택 ID, 상세 데이터 선택 상태 복원
- 공통코드 관리 스플리터 크기 복원
- 저장된 그룹이 유효하지 않을 때 첫 번째 접근 가능 그룹으로 대체
- 로그아웃 시 최근 메뉴 및 페이지 상태 초기화

### 데이터베이스 및 문서

- 양쪽 스키마 이력 폴더에 동일한 SQL, 변경 이력, 롤백 파일 작성
- 누적 `docs/database/db-schema.md`에 `level_id` 반영
- 결과 문서와 반응형 UI 캡처 기록

## 3. 영향 범위

- 인증 계약: JWT 및 내 메뉴 사용자 요약
- 화면: 대시보드 프로필, 공통코드 관리
- 공통 훅: 페이지별 sessionStorage 상태 저장/복원
- DB: `tb_user` 컬럼 및 FK만 변경
- 제외: F1-Grid 렌더링·편집 엔진 리팩터링, 전체 관리 화면 일괄 적용, 프로필 수정 API
- 허용: 선택 행 복원을 위한 F1-Grid/F1-Tree 최소 ref API 확장

## 4. 단계별 실행 계획

1. DB SQL·롤백을 기준으로 스키마 변경 계약을 고정한다.
2. 실패 테스트를 먼저 추가한다.
3. 로그인 VO/JWT/내 메뉴 응답에 부서·직급 데이터를 연결한다.
4. 프로필 팝오버를 API 데이터 기반으로 변경하고 fallback을 추가한다.
5. 공통 훅에 페이지 key·초기 복원·reset 계약을 적용한다.
6. 공통코드 관리 페이지에 검색어·그룹 선택·상세 선택 상태를 연결한다.
7. 저장된 ID가 삭제·권한 제외된 경우 안전하게 대체한다.
8. 프론트와 백엔드 단위 테스트를 실행한다.
9. 375px/768px/1280px에서 브라우저 UI를 확인한다.
10. 결과 문서와 검증 증거를 작성한다.

## 5. 검증 계획

- Frontend: `npm run build`, 공통 훅 테스트, 공통코드 상태 복원 테스트, 프로필 팝오버 테스트
- Backend: `mvn test`, JWT·로그인 매퍼·내 메뉴 응답 테스트
- DB: SQL 구문 및 FK 대상 확인, 롤백 SQL 검토
- Browser: 기존 캡처 스크립트로 프로필 팝오버와 공통코드 복귀 화면 확인

## 6. 완료 기준

- 프로필 팝오버에 API 기반 부서명·직급명이 표시된다.
- 직급은 ID FK로 저장되고 LEVEL 공통코드명으로 표시된다.
- 공통코드 관리에서 검색어·그룹·상세 조회 상태가 복원된다.
- 유효하지 않은 저장 상태는 오류 없이 현재 유효한 상태로 대체된다.
- 로그아웃 시 페이지 상태와 최근 메뉴가 삭제된다.
- DB 변경 이력·롤백·누적 스키마 문서가 동기화된다.
- 관련 테스트와 빌드, 브라우저 검증 결과가 결과 문서에 남는다.
