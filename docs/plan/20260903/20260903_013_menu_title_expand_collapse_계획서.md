## 요구사항 분석 및 목적

메뉴 관리 화면에서 전체 펼치기/접기 버튼은 제목 영역과 분리된 하단 툴바에 배치되어 있어, 제목과 액션이 같은 행에 묶여 있지 않은 상태다. 사용자는 해당 버튼을 제목 라인 우측에서 바로 찾고 싶어 하며, 타이틀과 이 제어 영역이 시각적으로 연관되어야 한다.

이번 작업은 메뉴 관리 타이틀 라인의 레이아웃을 정리하고, 기존 트리 확장/축소 동작을 그대로 유지하면서 버튼 배치를 타이틀 우측으로 이동시키는 것을 목표로 한다.

## 작업 범위 분해 (프론트엔드 전용)

### A. 레이아웃 정리

1. `MenuManagementPanel.tsx`의 타이틀 영역 구성을 재배치한다.
2. `메뉴 관리` 타이틀과 전체 펼치기/접기 아이콘 버튼을 같은 행에 배치한다.
3. 타이틀 왼쪽, 버튼 우측 정렬 구조를 유지하면서 반응형 간격을 정리한다.
4. 기존 하단 툴바에서 버튼을 제거하고, 관련 `Box` 구조를 정리한다.

### B. 동작 유지

1. `treeRef.current?.expandAll()` / `treeRef.current?.collapseAll()` 호출은 기존과 동일하게 유지한다.
2. `selectedModule` 미선택 또는 `saving` 상태에서 버튼 비활성화 조건은 그대로 유지한다.
3. 필요 시 `aria-label`과 접근성 속성은 기존 기준을 유지한다.

### C. 검증

1. UI 레이아웃 변경이므로 관련 화면 렌더링 검증을 수행한다.
2. 기존 F1Tree 확장/축소 기능이 정상 동작하는지 확인한다.
3. 메뉴 관리 테스트 또는 회귀 검증을 통해 버튼 상태가 유지되는지 점검한다.

## 기존 코드/아키텍처 영향 범위

- 변경 범위는 `frontend/src/pages/settings/system/menus/components/MenuManagementPanel.tsx`에 국한한다.
- 트리 동작 로직 자체는 변경하지 않고, 표시 위치와 레이아웃만 조정한다.
- `F1Tree` 내부 로직에는 영향이 없으며, 현재 버튼 클릭 시 호출되는 메서드는 그대로 유지한다.
- 다른 화면의 메뉴 관리 구조나 전역 레이아웃은 수정하지 않는다.

## 검증 계획

- **빌드**: `cd frontend && npm run build`
- **테스트**: `cd frontend && npm run test -- tests/menu-management-f1-grid.test.tsx`
- **브라우저 확인**: 메뉴 관리 화면에서 타이틀 우측에 버튼이 위치하는지 UI 검증
- **회귀 확인**: 전체 펼치기/접기 기능 호출이 정상 동작하는지 확인
