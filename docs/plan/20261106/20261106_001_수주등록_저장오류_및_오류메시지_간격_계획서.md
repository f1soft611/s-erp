## 1. 조사 범위

- 수주 생성 트랜잭션 → 자동 납품계획 생성 → 헤더/상세 삽입 → `selectPlanByOrder` 재조회 조건을 추적한다.
- DB 테이블 메타데이터와 Mapper/서비스 구현을 대조한다. 사용자/테넌트 데이터 행은 조회하거나 기록하지 않는다.
- 실제 저장 오류를 재현할 수 없거나 런타임 로그가 없으면 백엔드 수정의 근거로 간주하지 않는다.

## 2. 프론트엔드 변경

| 파일 | 작업 |

| `backend/src/test/java/egovframework/let/sales/deliveryplan/service/impl/SalesDeliveryPlanServiceImplTest.java` | 자동 계획 생성이 사후 재조회 실패에 영향받지 않는지 검증 |

## 3. 검증

- 저장 흐름 관련 백엔드 테스트 및 Mapper SQL 계약을 확인한다.
- 수주등록 화면 테스트와 프론트엔드 빌드를 실행한다.
- 브라우저에서 오류 메시지가 좁은 화면과 데스크톱에서 과도한 간격 없이 표시되는지 확인한다.
- 백엔드 원인을 확정하지 못하면 결과 문서에 코드상 확인된 경로와 미확인 경계를 분리해 기록한다.
