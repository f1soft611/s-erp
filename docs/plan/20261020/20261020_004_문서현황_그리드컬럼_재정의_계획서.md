# 20261020_004 문서현황 그리드 컬럼 재정의 계획서

## 목표

문서 식별에는 전자결재 PK를 사용하고, 사용자가 목록에서 자신의 결재 참여상태와 현재 처리 단계를 파악하고 검색할 수 있도록 프런트엔드·목록 API를 함께 갱신한다.

## 구현 단위

1. **프런트엔드 목록 테스트/계약**
   - `frontend/tests/document-status-page.test.tsx`: 컬럼 순서와 검색 metadata를 새 업무 컬럼으로 변경한다. 검색 UI에서 문서번호, 역할, 처리상태, 현재 결재담당자 값을 적용하는 테스트를 추가한다.
   - `frontend/tests/document-status-service.test.ts`: ID/역할/처리상태/담당자 필터와 ID 정렬 직렬화를 검증한다.
   - `frontend/src/pages/groupware/documents/status/types/documentStatus.types.ts`: `electronicApprovalId`와 새 목록 파생값 및 검색 필터 타입을 반영한다.
   - `frontend/src/pages/groupware/documents/status/components/DocumentStatusGrid.tsx`: `eabusNo` 및 참여자 요약 표시 컬럼을 제외하고 문서 ID, 내 역할/상태, 현재 결재 단계 컬럼을 정의한다. 숨김 참여자 컬럼은 검색 metadata를 계속 제공한다.
   - `frontend/src/shared/components/page-search/searchFields.ts`: 숨김 F1-Grid 컬럼에 명시된 검색 metadata는 상세검색 필드로 유지하도록 처리한다.
   - `frontend/src/pages/groupware/documents/status/DocumentStatusPage.tsx`: 빠른검색/상세검색 값을 올바른 필터에 연결한다.
   - `frontend/src/pages/groupware/documents/status/services/documentStatus.service.ts`: 새 query 파라미터를 보내고 새 목록 필드를 검증한다.

2. **백엔드 목록 query**
   - `DocumentApprovalListQueryVO`: 양의 문서 ID, 참여유형, 결재선 처리상태, 현재 결재담당자 검색 필드를 추가한다.
   - `DocumentApprovalApiController`: 기존 `@ModelAttribute` 목록 검색 흐름에 새 필터를 유지한다.
   - `DocumentApprovalServiceImpl`: 허용 값 검증, ID exact filter, 내 참여유형/처리상태, 현재 결재담당자 검색용 파라미터와 정렬 whitelist를 추가한다. 권한과 날짜 검증은 유지한다.
   - `DocumentApprovalStatusListItemVO` 및 MyBatis `statusListItem`: 현재 사용자 참여유형/상태와 현재 활성 결재단계·담당자를 응답에 포함한다.
   - `DocumentApproval_SQL_postgresql.xml`: 목록과 count 공통 필터를 일치시키고 기존 테이블의 결재선 정보로 파생값을 계산한다. tenant/user access predicate를 보존한다.
   - `DocumentApprovalMapperTest`, `DocumentApprovalServiceImplTest`, `DocumentApprovalApiControllerTest`: query binding, 허용/거부 입력 및 결과 보안 조건을 검증한다.

3. **문서 및 검증**
   - `frontend/src/pages/f1-grid-docs/F1-GRID.md`와 날짜별 작업지시서/사양서를 갱신한다.
   - 프런트엔드 타깃 Vitest 및 `npm run build`, 백엔드 타깃 Maven 테스트를 수행한다.
   - `docs/result/20261020/document-status-grid-columns/result.md`에 구현/테스트/제약을 기록한다.

## 데이터 계약

- DB MCP 메타데이터 확인: `tb_electronic_approval_main.electronic_approval_id`는 bigint PK, `eabus_no`는 varchar(3) 문서유형별 코드.
- `tb_electronic_approval_line_info`에는 `stage_order`, `participant_type`, `participant_user_id`, `participant_name`, `action_status`가 존재한다.
- 새 DB 컬럼/테이블은 필요하지 않다. 실제 행/문서 데이터는 조회하지 않는다.
- 목록과 count는 같은 tenant, 사용자 접근, 검색조건을 사용한다.
- 그리드에서는 참여자 이름 요약을 표시하지 않지만, 숨김 컬럼 metadata에서 참여자 이름 검색은 유지한다.
