# 20261020_008 문서현황 검색조건 세션 복원 계획서

## 목표

승인된 검색조건 스냅샷만 페이지 전용 `sessionStorage` 상태로 저장하고, 문서현황 재진입 시 검색 UI와 목록을 함께 복원한다.

## 구현 단위

1. **회귀 테스트**
   - `frontend/tests/document-status-page.test.tsx`에 저장된 검색조건의 UI/API 복원, 미적용 입력 비저장, 초기화 시 결재신청일 기본값 복원 및 재진입 유지, 새 세션 기본 날짜 범위 유지 테스트를 추가한다.
   - 테스트를 먼저 실행해 신규 동작 미구현에 의한 실패를 확인한다.
2. **세션 상태 연결**
   - `frontend/src/pages/groupware/documents/status/DocumentStatusPage.tsx`에서 `usePageSessionState`를 페이지 key `s-erp:page:document-status` 및 버전으로 사용한다.
   - 세션 데이터는 마지막 검색에서 적용된 `keyword`와 `detailValues`로 제한한다. 구조와 각 필드 값을 확인하는 validator를 적용한다.
   - 훅의 초기 fallback은 기존 최근 1개월 날짜 입력값을 포함해 기존 첫 진입 동작을 유지한다.
3. **검색/초기화 통합**
   - 검색 실행 시 현재 입력값을 복사한 스냅샷을 저장하고, 동일 스냅샷에서 API 필터를 구성한다.
   - 검색 입력 변경만으로는 페이지 세션 상태를 갱신하지 않는다.
   - 초기화 버튼은 빠른 검색어와 결재신청일 외 상세조건을 비우고, 결재신청일을 초기 진입과 동일한 최근 1개월 범위로 되돌려 조회 및 저장한다.
   - 저장된 상태가 복원되면 해당 입력값을 표시하고 그 값에서 필터를 계산해 자동 조회한다.
4. **문서 및 검증**
   - `frontend/src/pages/f1-grid-docs/F1-GRID.md`의 문서현황 상태 동작을 갱신한다.
   - `docs/result/20261020/document-status-search-session/result.md`에 구현 및 검증을 기록한다.
   - 타깃 Vitest, `npm run build`, `git diff --check`를 실행한다.

## 상태 처리 원칙

- 세션 상태 필드: `{ keyword: string, detailValues: Record<string, PageSearchFieldValue> }`.
- 세션 상태 key/version은 문서현황 전용으로 고정하고 validator에서 객체 구조, 문자열 검색어 및 허용된 상세 검색 primitive/date-range 값을 검증한다.
- `DocumentStatusFilters`를 별도로 세션 저장하지 않는다. 기존 `toDocumentStatusFilters(keyword, detailValues)`가 동일 값으로 다시 계산한다.
- 초기 fallback과 초기화 상태는 모두 최근 한 달 결재신청일 범위를 둔다. 초기화 스냅샷은 `{ keyword: '', detailValues: { submittedAt: { from, to } } }`이며 다른 검색조건은 포함하지 않는다.
- 저장/복원 범위에서 선택 행, 상세 패널, 그리드 레이아웃은 제외한다.

## 검증 명령

```powershell
Set-Location frontend
npm run test -- tests/document-status-page.test.tsx
npm run build
Set-Location ..
git --no-pager diff --check
```

테스트에서는 `sessionStorage`에 버전 envelope를 가진 기존 검색 스냅샷을 사전 입력한 뒤, 페이지 재진입 시 검색 필드 값과 API query가 동일한지 검증한다. 미적용 입력 테스트는 입력 후 unmount/remount해 이전 적용 조건만 복원되는지 확인한다. 초기화 테스트는 버튼 실행 후 결재신청일 UI, API 날짜 파라미터, 초기화 세션 스냅샷, remount 이후 복원 상태를 함께 확인한다.
