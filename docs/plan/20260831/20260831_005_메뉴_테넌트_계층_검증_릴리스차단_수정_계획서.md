# 메뉴 테넌트 계층 검증 릴리스 차단 수정 계획서

## 목표

기존 메뉴 생성(POST) 및 수정(PUT) 요청의 `parentMenuId` 데이터를 검증하여, 요청 테넌트 밖의 모듈 또는 메뉴를 참조하지 못하게 한다.

이 문서는 004 작업의 릴리스 차단 보정 계획이며, 별도 005 작업지시서는 만들지 않는다.

## 구현 단위

1. `SystemModuleService.listModules(tenantId)`로 생성 요청 모듈의 테넌트 소유 여부를 확인한다.
2. POST/PUT 요청에 `parentMenuId`가 지정되면 테넌트 범위 `SystemMenuDAO.selectMenuById` 조회 후 같은 모듈인지 확인한다.
3. PUT은 대상 메뉴의 기존 `moduleId` 소유권을 먼저 확인하고, 기존 `moduleId`를 기준으로 요청 `parentMenuId`를 확인한다.
4. 검증 실패 시 insert/update 전에 명확한 `IllegalArgumentException`을 발생시키고 API는 400을 반환한다.
5. 서비스와 컨트롤러 단위 테스트 및 오프라인 Maven 컴파일로 검증한다.

## 제외 범위

- DB 스키마, MyBatis SQL, 프론트엔드, 메뉴 이동 또는 모듈 변경 API는 수정하지 않는다.
- 부모 메뉴 이동 UI를 도입하지 않으며, 부모 이동은 004 범위에 포함하지 않는다. 이 보정은 기존 POST/PUT 요청 데이터의 서버 검증만 다룬다.
