# 20260831*002*모듈*메뉴*권한관리*백엔드*연동\_계획서

## 1. 목표

작업지시서([20260831_002](../../directions/20260831/20260831_002_모듈_메뉴_권한관리_백엔드_연동_작업지시서.md))에 따라 모듈/메뉴/역할 관리 기능을 DB-백엔드-프론트엔드까지 실제 데이터로 연동한다.

## 2. 구현 단위

### 2-1. DB 스키마

- `tb_module`, `tb_menu` 테이블 신규 생성 (`backend/DATABASE/20260831`)
- 시드 데이터: 그룹웨어(종합현황/문서관리), 환경설정(시스템관리 > 권한관리/메뉴관리/F1 Grid 테스트) — 에프원소프트 테넌트 기준
- `docs/database` 변경 이력 갱신

### 2-2. 백엔드 - 모듈 관리

- 패키지: `egovframework.let.system.modules`
- `SystemModuleApiController` : `GET/POST/PUT/DELETE /api/v1/system/modules`
- `SystemModuleService`/`Impl`, `SystemModuleDAO`
- 모듈 코드 중복 검증, 테넌트 코드 → tenant_id 변환

### 2-3. 백엔드 - 메뉴 관리 및 사용자 메뉴 조회

- 패키지: `egovframework.let.system.menus`
- `SystemMenuApiController` : `GET/POST/PUT/DELETE /api/v1/system/menus`, `GET /api/v1/menus/my`
- 메뉴 트리 조회(모듈별, 부모/자식), 역할코드 기반 권한 부여 로직 포함

### 2-4. 백엔드 - 역할 관리

- 패키지: `egovframework.let.system.roles`
- `SystemRoleApiController` : `GET/POST/PUT /api/v1/system/roles` (삭제 제외)

### 2-5. 접근 제어

- 관리 API(모듈/메뉴/역할 등록·수정·삭제)는 `@AuthenticationPrincipal LoginVO`의 roleCode가 `PLATFORM_ADMIN`/`TENANT_ADMIN`이 아니면 403(`ResponseCode.AUTH_ERROR`) 처리

### 2-6. 프론트엔드 연동

- `shared/services/apiClient.ts` 신설 (저장된 JWT를 Authorization 헤더에 부착하는 공통 fetch 래퍼)
- `dashboard/services/menuService.ts` : 로컬 JSON → `/api/v1/menus/my` 호출로 전환
- `settings/system/menus`, `settings/system/roles`의 `services/*.ts`, `data/*.ts`를 API 연동으로 교체(타입은 최대한 유지, 필요한 필드만 보강)

## 3. 검증 계획

- 백엔드: `mvn -o compile` (전체 `mvn test`는 DB 연결 필요 시 생략 가능, 컴파일 검증 우선)
- 프론트: `npm run build`, `npm run test`
- 수동: 관리자 로그인 → 대시보드 메뉴 트리 확인, 권한관리/메뉴관리 화면 데이터 확인
