# 20260831*001*로그인*JWT*백엔드*연동*계획서

## 1. 범위

- DB: `s-erp_central` PostgreSQL 스키마 생성 + 초기 시드 데이터
- 백엔드: 로그인 시 테넌트 코드 → 테넌트 ID 변환 로직 추가
- 프론트엔드: `authService.ts` 목업 제거, 실제 `/auth/login-jwt` 호출로 교체

## 2. 작업 단계

### 2.1 DB 스키마/시드

1. `docs/database/db-schema.md`에 문서화된 3개 테이블(tb_tenant, tb_login_account, tb_user)과, 로그인 매퍼([EgovLoginUsr_SQL_postgresql.xml](../../../backend/src/main/resources/egovframework/mapper/let/uat/uia/EgovLoginUsr_SQL_postgresql.xml))가 참조하는 연관 테이블(tb_department, tb_role, tb_login_account_role)의 DDL을 기존 운영 스키마(동일 서버의 `haccp_cloud_central`) 구조를 참고해 작성한다.
2. `backend/DATABASE/20260831`와 `docs/database/2026-08-31`에 CREATE 스크립트, 시드 스크립트, 롤백 스크립트, 변경 이력 문서를 남긴다.
3. 스크립트를 실제 `s-erp_central` DB에 적용한다.

### 2.2 백엔드 연동 보완

1. `LoginDAO`/매퍼에 테넌트 코드로 `tenant_id`를 조회하는 기능을 추가한다.
2. `EgovLoginServiceImpl.actionLogin`에서 `tenantId`가 없고 `tenantCode`만 있는 경우 이를 변환해 조회하도록 보완한다.
3. 비밀번호 해시 방식(`EgovFileScrty.encryptPassword(password, id)`, SHA-256 + Base64)에 맞춰 시드 비밀번호 해시를 생성한다.

### 2.3 프론트엔드 연동

1. `authService.ts`의 `login()`을 실제 `POST /auth/login-jwt` 호출로 교체하고, 응답의 `jToken`/`resultVO`를 세션(`localStorage`)에 저장한다.
2. API Base URL은 `import.meta.env.VITE_API_BASE_URL`(미설정 시 `http://localhost:8080`)을 사용한다.
3. 로그인 실패 시 백엔드 `resultMessage`를 에러 메시지로 노출한다.
4. 관련 vitest(`login.test.tsx`)가 실제 fetch 호출을 모킹하도록 갱신한다.

## 3. 검증 계획

- 백엔드: `mvn -q -DskipTests=false test -Dtest=EgovLoginApiControllerTest` 또는 전체 컴파일 확인.
- 프론트: `npm run test -- tests/login.test.tsx`.
- DB: 시드 계정으로 실제 `/auth/login-jwt` 호출 결과 확인(가능한 경우).

## 4. 영향 범위

- 백엔드: `egovframework.let.uat.uia` 패키지 내 로그인 관련 파일, postgresql 로그인 매퍼.
- 프론트: `frontend/src/shared/services/authService.ts`, 관련 테스트.
- DB: `s-erp_central` 신규 테이블 6종 + 시드 데이터(기존 운영 DB인 haccp_cloud_central 등은 변경하지 않음).
