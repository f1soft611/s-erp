## 목표

확정 메인 테이블을 추가하고, 구매요청확정 API·화면을 "여러 요청 → 확정번호 1개" 구조로 바꾼다.

## 실행 순서

1. **사양서**: 테이블 계약, API, 상태 전환, 통화 검증, 화면 동작을 확정한다.
2. **DB 스크립트** `20261112_005`
   - `create`: 확정 메인 생성, 요청 헤더에 확정 ID 추가, 기존 확정 데이터 이전(통화 혼합 시 중단),
     `confirm_dt`·`confirmer_id` 삭제, 상태 제약 교체, 확정번호 채번값 맞춤.
   - `rollback`: 요청 헤더에 확정일·확정자 복원 후 확정 메인 제거.
   - `change` 이력, `db-schema.md` 갱신, SQL 정적 테스트 추가.
3. **기존 테스트 데이터 정리**: `MR-20261112-0005` 확정을 현재 API로 취소(KRW·USD 혼합).
4. **백엔드**: 실패 테스트 → 확정 모듈 재작성(DAO·Mapper·Service·Controller), 구매요청등록 조회 쿼리 수정.
5. **프론트**: 실패 테스트 → 서비스·타입·그리드·요청 다중 선택·확정 선택 다이얼로그·페이지 수정.
6. **검증**: 집중 테스트, `npm run build`, 백엔드 구매요청 테스트, JDK 8 컴파일, 브라우저 스크립트.
7. **실제 서버**: 사용자 스크립트 실행 → MCP 확인 → 묶음 확정, 통화 혼합 차단, 마감, 확정 취소, 현황 반영 확인.
8. **결과 문서**: `docs/result/20261112/purchase-request-confirm-batch`.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 여러 요청 동시 확정 시 교착·중복 확정 | 요청 ID 오름차순으로 헤더 `FOR UPDATE`, 모두 요청 상태인지 확인. UPDATE에도 상태 조건 |
