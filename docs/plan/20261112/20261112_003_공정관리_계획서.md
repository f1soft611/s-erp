# 공정관리 구현 계획

**목표:** 공정그룹과 공정을 트리에서 관리하고 이미지 등록과 저장을 제공한다.

**구조:** 공정그룹과 공정을 테넌트별 별도 테이블로 저장하고 트리 노드로 표시한다. 이미지 컬럼은 F1Grid의 공통 타입으로 구현하고 공정 이미지는 기존 회사 직인과 같은 소형 데이터 URL 패턴을 따른다.

1. 기존 창고관리와 공통 그리드·메뉴 권한 및 회사 직인 이미지 패턴을 확인한다.
2. 공정그룹·공정의 API, 검증, 테넌트 격리 및 스키마·메뉴 이력과 롤백을 작성한다.
3. 이미지 그리드 타입과 공정관리 F1Tree 화면을 구현한다.
4. 관련 테스트, Java 8 호환성, 빌드와 반응형 브라우저 화면을 검증한다.
5. 결과와 스크린샷 및 MCP 확인·미확인 범위를 기록한다.
6. `/pr/*` 라우트의 누락을 회귀 테스트로 재현하고 기존 보호 라우트 패턴으로 연결한다.
7. 실제 앱 테마의 검색 입력 여백을 회귀 검증하고 기준 화면의 검색 입력 높이·테두리·배경을 적용한다.
8. F1Tree 우클릭 메뉴의 라벨과 추가 동작을 공정 계층·권한에 연결하고 기존 기본 메뉴는 유지한다.
9. 이미지 셀의 미리보기·빈 이미지·파일 선택·Delete 삭제 및 공정 체크박스 정렬을 구현하고 공통 그리드 문서와 테스트를 갱신한다.
10. 이미지 파일의 실제 서명과 전송 MIME이 일치하도록 보정하고 서버 검증은 유지한다. 코드 데이터 계약을 유지하며 화면 컬럼만 숨긴다.
11. F1Tree의 기존 깊이 들여쓰기 공간에 하위 행 연결 표시를 추가해 기존 접기·펼치기와 편집 동작을 유지한다.
12. 공정그룹의 이미지 셀을 비우고 최하위 행의 계층 표시와 이름 사이의 간격을 줄인다.
13. 창고관리 구조를 기준으로 공정관리의 트리 렌더링·컬럼은 `components/ProcessManagementTree.tsx`, 행 초기값은 `data/processManagement.data.ts`, 조회·검색·저장 및 선택 상태는 `hooks/useProcessManagement.ts`, API는 `services/processManagement.service.ts`, 데이터 계약은 `types/processManagement.types.ts`로 이동한다. 페이지는 공통 화면 조립과 버튼 연결만 담당한다.
14. `frontend/AGENTS.md`에 복잡한 관리 화면의 책임 분리와 기준 화면 사전 확인을 명시하고 기존 테스트의 모의 서비스 경로를 변경한다. 공정·이미지·트리 회귀 테스트와 빌드, 브라우저 확인으로 동작 보존을 검증한다.
15. 창고관리 백엔드를 기준으로 공정 DTO를 `domain/model`, DAO를 `domain/repository`, 서비스 계약을 `service`, 구현을 `service/impl`로 이동한다. 컨트롤러와 MyBatis 모델 참조를 갱신하되 JSON·SQL·테넌트·권한·트랜잭션 계약은 바꾸지 않는다.
16. `backend/AGENTS.md`에 기준 기능의 계층 구조 사전 확인을 명시한다. 공정 서비스·컨트롤러·매퍼 테스트와 Java 8 API 호환성을 확인한다.
