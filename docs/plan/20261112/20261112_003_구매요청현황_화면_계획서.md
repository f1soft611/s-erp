## 목표

구매요청을 품목 행 단위로 조회하고, 상세 패널과 조회/수정 다이얼로그로
기존 건을 확인·수정·삭제할 수 있게 한다.

## 실행 순서

1. 20261112_002 완료(테이블, 단건 API, 등록 화면 embedded 모드)를 확인한다.
2. **메뉴 seed** (`20261112_003`): `MATERIALS_REQUEST_STATUS` 메뉴, READ/EXCEL
   권한, `ORDER_STATUS` 역할 권한 복사, 롤백, 변경 이력.
3. **백엔드 실패 테스트**: 목록 Controller, Mapper 테넌트 범위·검색 조건 테스트.
4. **백엔드 구현**: `egovframework.let.materials.request.status`
   Controller / Service / DAO / SearchVO / RowVO, Mapper XML.
5. **프론트 실패 테스트**: 검색 → API 파라미터, 목록 렌더링, 상세 패널 열기,
   확정 건 수정 비활성, 수정 저장 후 재조회.
6. **프론트 구현**: 페이지, 검색 영역, 그리드 컬럼, 상세 패널, 편집 다이얼로그,
   hooks, 서비스, 타입.
7. **라우트**: `DashboardContent`에 `materials` + `request-status` 분기 추가.
8. **검증**: 프론트 집중 테스트·빌드, `mvn test`, 브라우저 3개 뷰포트.
9. **결과 문서**: `docs/result/20261112/purchase-request-status/`.

## 의존 관계

- 단건 조회·수정·삭제 API와 등록 화면 embedded 모드는 002 결과물을 쓴다.
- 브라우저 확인은 로컬 DB에 001~003 스크립트를 적용한 환경이 필요하다.

## 완료 기준

- 상세사양의 검색 조건·컬럼·패널 항목이 화면과 API에 일치한다.
- 백엔드·프론트 테스트와 빌드가 통과한다.
- 조회 → 상세 → 수정 → 재조회 흐름을 브라우저에서 확인한다.
