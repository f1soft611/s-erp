## 목표

요청 상태의 구매요청을 불러와 확정하고, 확정 건의 발주대기 마감과 확정 취소를
한 화면에서 처리한다. DDL 변경 없이 메뉴 seed와 백엔드·프론트 구현만 한다.

## 실행 순서

1. **사양서 작성**: API 계약, 상태 전환 규칙, 검증 규칙, 화면 컬럼을 확정한다.
2. **메뉴 seed**: `MATERIALS_REQUEST_CONFIRM`(구매요청확정, 정렬 15) seed·롤백·변경 이력을
   docs/database와 backend/DATABASE에 같은 내용으로 작성한다. 사용자가 실행한다.
3. **백엔드 실패 테스트**: 확정 검증(행 누락, 수량 음수, 수량 > 0 행의 필수값), 상태 전환
   (요청만 확정, 확정만 마감·취소), 금액 계산, 기본 단가 조회 조건, Mapper 테넌트 범위.
4. **백엔드 구현**: `egovframework.let.materials.request.confirm` 패키지.
   구매요청 단건 조회는 확정 컬럼과 이름(구매처·창고·발주구분)을 포함한 확정 전용 쿼리를 둔다.
5. **프론트 실패 테스트**: 서비스 payload, 불러오기 → 확정 → 상태 변경 표시, 상태별 버튼,
   구매처 선택 시 단가 기본값, 금액 계산.
6. **프론트 구현**: 페이지, 요청 선택 다이얼로그, 상세 그리드, 서비스, 타입.
7. **라우트 연결**: `DashboardContent`의 `materials` 분기에 `request-confirm`을 추가한다.
8. **검증**: 집중 테스트, `npm run build`, 백엔드 테스트, JDK 8 컴파일, 브라우저 375/768/1280px.
9. **실제 서버 확인**: seed 실행 후 MCP 확인, 확정 → 마감 → 마감 취소 → 확정 취소 흐름과
   구매요청현황 반영을 확인한다. 테스트 데이터는 남긴다.

## 위험과 대응

| 위험 | 대응 |
| --- | --- |
| 확정 중 다른 사용자가 요청을 수정·삭제 | 확정 시 헤더 `FOR UPDATE` 잠금 후 상태·상세 행 목록이 화면과 같은지 확인, 다르면 409 |
| 매입 단가 구분값이 한글(`'매입'`)로 저장됨 | 기본 단가 쿼리에서 단가관리 화면과 같은 값을 쓰고, 사양서에 근거를 남긴다 |
| 같은 품목·거래처에 유효 단가가 여러 건 | 시작일이 가장 늦은 1건을 쓴다 |
| 행마다 창고·구매처 입력이 번거로움 | 일괄적용 보류를 결과 문서에 다시 기록하고, 팀 결정 후 추가 |
