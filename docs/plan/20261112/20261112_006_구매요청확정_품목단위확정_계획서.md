## 실행 순서

1. 사양서: 테이블·상태 계산·API·화면 차이를 005 대비로 정리한다.
2. DB `20261112_006`
   - 적용: 상세에 확정 ID 추가·이전, 헤더 확정 ID 삭제, 상태 CHECK 교체, 상세 연결 CHECK 추가.
   - 롤백: 요청마다 확정 ID가 하나뿐이고 부분확정이 없을 때만 헤더로 되돌린다(아니면 중단).
3. 백엔드: Mapper(후보·상세 잠금·확정 연결·상태 재계산·취소), Service(상세 ID 기준 검증), Controller(파라미터), 테스트.
4. 프론트: 타입·서비스(상세 ID 기준), 선택 창(품목 행·병합), 페이지([선택 행 빼기]), 상태 라벨, 테스트.
5. 검증 → 사용자 실행 → 실제 서버 확인 → 결과 문서.

| 위험 | 대응 |
| --- | --- |
| 같은 품목 동시 확정 | 상세 행을 ID 순서로 `FOR UPDATE` 잠그고 확정 ID가 비어 있는지 확인, UPDATE에도 `purchase_confirm_id IS NULL` 조건 |
