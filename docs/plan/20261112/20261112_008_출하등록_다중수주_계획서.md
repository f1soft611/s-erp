# 출하등록 다중 수주 구현 계획

> **For agentic workers:** 이 저장소의 날짜별 문서와 기존 패턴에 따라 각 단계에서 대상 테스트를 먼저 추가하고 실패를 확인한 후 구현한다.

**Goal:** 같은 거래처의 여러 수주를 한 출하 문서로 등록하고 상세별 원 수주 참조를 유지한다.

**Architecture:** 도움창은 체크된 수주를 고유화하고 각 수주의 모든 계획 상세 행을 선택한다. 출하 API는 대표 수주 ID를 유지하면서 상세행별 원 수주 ID를 저장·검증하고, 헤더 단일 수주 복합 FK를 제거해 실제 수주 참조를 상세 수준에서 보장한다. 기존 거래처/수량/권한/초과출하 검증과 DIRECT 흐름은 유지한다.

**Tech Stack:** React, TypeScript, MUI, F1Grid, Vitest, Java 8, Spring Boot, MyBatis, PostgreSQL DDL.
