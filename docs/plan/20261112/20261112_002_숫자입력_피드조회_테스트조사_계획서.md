# 숫자 입력·피드 조회·테스트 지연 개선 계획

**목표:** 정수 입력 시 소수부 손실 방식을 바로잡고, 조건 변경 조회 실패 시 이전 결과의 오인을 방지하며 테스트 지연 원인을 확인한다.

**구조:** F1Grid 숫자 공통 정규화 함수와 문서 작성 페이지 조회 훅의 실패 처리만 각각 수정한다. 테스트 지연은 타임아웃 변경 전에 개별 실행과 전체 실행의 시간·목 상태를 비교한다.

**기술:** React, TypeScript, Vitest, Testing Library.

## 작업

1. `frontend/tests/f1-grid.test.tsx`의 기존 실패를 재현하고, 음수·천 단위 구분자와 소수 자릿수 유지 사례를 검증한 다음 `frontend/src/shared/components/f1-grid/utils/grid.utils.ts`의 정수 분기를 수정한다. 셀 편집기와 행 폼에서 입력 중 소수부를 임시 표시하고 값은 정규화하며 포커스를 잃으면 정수를 표시한다. `frontend/src/pages/f1-grid-docs/F1-GRID.md`에 사용 동작을 반영한다.
2. `frontend/tests/document-write-page.test.tsx`의 필터 조회 실패와 조용한 갱신 실패를 재현한다. `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`에서 조건 변경 등 일반 조회 실패 시 결과를 비우고 조용한 갱신 실패 시 보존한다.
3. 같은 테스트 파일의 실행 시간을 확인하고 `vi.clearAllMocks`와 일회성 목 응답의 격리를 조사한다. 필요할 때에만 관련 테스트의 격리 문제를 수정한다.
4. 대상 테스트, 프론트엔드 타입 검사 및 관련 lint를 실행하고 `docs/result/20261112/frontend-test-regression-cleanup`에 결과와 남은 실패를 기록한다.

사용자가 요청하지 않은 커밋은 생성하지 않는다.
