# 출하계획·출하등록 품목기준 연계 계획서

## 목표

수주·계획 헤더가 아닌 품목 상세 행을 기준으로 출하계획을 등록하고, 여러 계획의 개별 상세 행으로 출하를 등록하며, 출하계획현황도 계획상세 품목별로 조회한다. 거래명세서는 범위에서 제외한다.

## 진행 순서

1. 승인된 설계를 바탕으로 API 요청/응답, 선택기, 잔량/초과수량 처리, DB 변경, 검증 기준을 상세사양서에 기록하고 커밋한다.
2. 구현 전 read-only PostgreSQL MCP로 주문·계획·출하 테이블 계약을 재확인한다.
3. 계획 헤더의 단일 수주 참조를 제거하는 20261112_009 마이그레이션·롤백·이력을 작성하고 누적 스키마를 갱신한다.
4. 계획 서비스/API를 상세별 수주 참조로 전환하고, MANUAL 다중수주 계획과 AUTO 1:1을 보장한다.
5. 계획현황 API/UI를 계획상세 한 행으로 전환한다.
6. 출하 원본 조회/선택을 계획상세 한 행으로 전환하고 잔량·거래처·트랜잭션 규칙을 유지한다.
7. 관련 테스트, Java 8 API 검증, frontend build/lint, 375/768/1280px 브라우저 검증을 수행한다.
8. 결과 문서와 영문 경로 스크린샷을 작성하고 기능·문서 변경을 구분해 커밋한다.

## 핵심 검증

- 계획 가능량은 주문상세 수량에서 다른 활성 계획들의 계획량 합계를 제외하며, 계획 수정 때 현재 계획량을 반영한다.
- 출하 원본은 계획상 잔량이 양수인 상세행만 표시한다. 선택한 계획의 다른 품목행은 자동 포함하지 않는다.
- 한 출하는 단일 거래처이며, 부분 출하·초과출하 WARN 확인·수정/삭제 역보정·직출하 동작을 유지한다.
- 계획현황 한 행은 한 계획상세 품목에 대응한다.
- paired migration/history/rollback 파일이 `docs/database`와 `backend/DATABASE`에서 동일하고 실제 DB에는 적용하지 않는다.
