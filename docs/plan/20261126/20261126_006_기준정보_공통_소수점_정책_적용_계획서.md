# 기준정보 공통 소수점 정책 적용 계획서

- 작업지시서: [20261126_006](../../directions/20261126/20261126_006_기준정보_공통_소수점_정책_적용_작업지시서.md)

## 조사 결과

- `GRID_DECIMAL_COMMON` 정책: number 0자리, decimal 3자리, currency 3자리(HALF_UP, FIXED). DB MCP로 확인했다.
- 기존 데이터(품목 103건, 단가 11건)는 안전재고·최소주문수량이 모두 정수이고 단가가 3자리 이내라서 정책 적용으로 값이 깨지지 않는다.
- 서버는 단가·MOQ를 소수 둘째 자리로 고정 검증하고 있었고(정책 무시), 안전재고·중량·소비기한은 정책 검증이 없었다.

## 구현 단위

1. 계약 JSON에 기준정보 문서를 추가한다. 서버가 쓰는 문서: `co.itemPartnerPrice`(`unitPrice` 단가, `foreignUnitPrice` 단가, `moq` 수량), `co.material`(`materialWeight`, `safeInvoice`, `expiryedCount` 수량). 화면 전용 문서: `co.itemPartnerPriceSummary`(등록 건수, 거래처 수), `co.classification`(정렬순서), `co.commonCode`(정렬순서). 골든 파일을 갱신한다.
2. 서버: `SalesDecimalPolicy`에 모듈 코드를 받는 `forModule`과 안내용 `places`를 추가하고, 품목단가·품목 서비스가 `COMMON` 정책과 계약으로 검증·저장하게 한다.
3. 서버 가드 테스트가 `let/co` 소스도 검사하게 확장하고 화면 전용 문서를 허용 목록에 추가한다.
4. 화면: 숫자 컬럼이 `decimalColumnOptions`로 계약을 따르게 하고 `decimalPlaces: 2`와 고정 2자리 검증 정규식을 제거한다.
5. 가드 테스트 대상에 기준정보 폴더를 등록한다.
6. 사양서·결과 문서를 갱신한다.

## 범위 밖

- 작업표준(레시피): 투입량·배합비·1판당의 업무 자릿수(3·2·1)와 화면의 계산 함수(`roundTo` 등)를 정책으로 바꾸는 작업은 업무 판단이 필요해 별도 작업으로 둔다. 서버 구현도 없다.
- 컬럼 예외(필요 시 나중에 계약 JSON으로 추가), 서버 정책 스냅샷(409) 비교, 거래처·창고·기안양식(숫자 컬럼 없음).
