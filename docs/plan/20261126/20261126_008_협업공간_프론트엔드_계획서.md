- 상세 구현 계획: [superpowers 계획](../../superpowers/plans/2026-11-26-community-workspace-frontend.md)

## 구현 단위

1. 타입, 샘플 데이터, 권한 판정·개인 설정 보정 순수 함수 (단위 테스트)
2. 가짜 저장소 서비스: 방·글·댓글 CRUD, 카드 이동, 규칙 검증, localStorage 오류 대응
3. 상태 훅(방, 글, 개인 보기 설정)
4. 칸반·피드·댓글 컴포넌트
5. 글 작성, 방 설정, 권한 그룹 다이얼로그
6. 페이지 조립과 메뉴 연결
7. 실제 브라우저 검증과 결과 문서

## 접근

- 화면은 `services/`만 호출한다. 백엔드가 생기면 서비스만 API 호출로 교체한다.
- 드래그는 신규 의존성 없이 브라우저 기본 드래그앤드롭과 "이동" 메뉴를 함께 제공한다.
- 기준 화면: 공지(`community/notice`)의 피드·댓글 패턴, 자료실(`community/archive`)의 헤더·권한 처리.

## 검증 계획

- 단위: `tests/workspace-permissions.test.ts`, `workspace-prefs.test.ts`, `workspace-service.test.ts`
- 화면: `tests/workspace-page.test.tsx`
- 전체 `npm run test`, `npm run build`
- 실제 브라우저(4173): 375/768/1280px, 사용자 전환별 권한, 드래그·키보드 이동

## 영향 범위와 위험

- 영향: 프론트엔드만. 대시보드 업무 화면 등록부 3개 파일에 분기 추가.
- 위험: 메뉴 항목이 서버 데이터이면 `workspace` 메뉴 행이 필요하다. 없으면 DB를 변경하지 않고 사용자에게 알린다.
