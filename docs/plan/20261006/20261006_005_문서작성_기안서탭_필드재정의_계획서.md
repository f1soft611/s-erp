# 20261006_005 문서작성 기안서 탭 필드 재정의 계획서

## 목표

## 변경 범위

- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`: 필드 순서, 38px 필드 스타일, 결재선/합의/참조 UI, 오류/로딩 표시
- `frontend/src/pages/groupware/documents/write/hooks/useDocumentComposer.ts`: 프로필/분류/양식/사용자 조회 상태, 작성자·기안일, 단계 구성, 템플릿 변경 보호 및 초기화
- `frontend/src/pages/groupware/documents/write/types/documentWrite.types.ts`: 기안양식 선택과 결재 단계 타입이 필요한 경우에만 추가
- `frontend/tests/document-write-page.test.tsx` 및 필요 시 새 focused test: 접근성 이름과 사용자 흐름 검증
- `docs/result/20261006/document-write-draft-fields/`: 완료 결과와 반응형 스크린샷

기안양식관리 API, F1-Grid 공통 사용자 선택기, 공용 에디터/다이얼로그 구현은 우선 변경하지 않는다. 현재 문서작성 소스 분리 변경이 이미 작업트리에 있으므로 해당 변경을 덮거나 되돌리지 않고 그 결과 위에서 필요한 파일만 수정한다.

## 구현 순서

1. 현재 문서작성 테스트와 작업트리 상태를 기준선으로 확인한다.
2. 기존 서비스의 `fetchDraftFormOptions`/`fetchDraftForms`와 템플릿 조회, 기존 프로필 서비스 및 사용자 선택 API의 데이터 계약을 확인한다. 필요한 경우 DB MCP를 읽기 전용으로 확인한다.
3. 실패 기준을 명확히 하는 모달 테스트를 추가한다: `전체`/분류 필터, 사용 중이며 본문이 존재하는 양식만 표시, 사용자 한 명 결재 추가, 다중 합의 그룹 추가, 참조 다중 선택, 템플릿 본문 적용/교체 취소.
4. 기존 패턴으로 메타데이터 조회와 사용자 후보를 연결하고, 오류 및 로딩 UI를 제공한다.
5. 공통 사용자 선택기를 결재선의 단일 다중 선택 필드로 재사용하고 역할 버튼에 따라 순차 결재 단계 또는 단일 합의 그룹을 추가한다. 각 선택자는 사진·이름·부서 정보를 표시한다.
6. 양식 본문 JSON/HTML을 기존 리치 텍스트 에디터에 적용하고, 편집 중 양식 교체 확인 및 취소 복원을 구현한다.
7. 저장 비활성/모달 닫기 초기화 등 기존 동작을 회귀 검증한다.
8. focused 테스트, 프론트엔드 빌드, 375/768/1280px 브라우저 확인을 수행하고 결과 문서 및 스크린샷을 남긴다.
