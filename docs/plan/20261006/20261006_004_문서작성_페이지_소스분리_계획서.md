## 변경 파일과 책임

- `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`: 페이지 조립과 공통 화면 구조
- `frontend/src/pages/groupware/documents/write/components/DocumentComposerDialog.tsx`: 기존 공용 `CommonDialog`를 쓰는 문서 편집 모달
- `frontend/src/pages/groupware/documents/write/components/DocumentFeedItem.tsx`: 피드 카드와 상태 표시
- `frontend/src/pages/groupware/documents/write/components/ApprovalSummaryPanel.tsx`: 결재 요약과 알림 카드
- `frontend/src/pages/groupware/documents/write/components/EmptyDocumentList.tsx`: 빈 상태와 작성 액션
- `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`: 보기 방식, 필터, 목록 파생값, 모달 열림 상태
- `frontend/src/pages/groupware/documents/write/hooks/useDocumentComposer.ts`: 공통 에디터 인스턴스, 제목, 탭, 첨부 및 닫기 초기화
- `frontend/src/pages/groupware/documents/write/types/documentWrite.types.ts`: 페이지와 문서 타입
- `frontend/src/pages/groupware/documents/write/data/documentWriteData.ts`: 업무구분과 기존 샘플 데이터
- `frontend/tests/document-write-page.test.tsx`: 페이지 동작 및 작성 초기화 회귀 검증

실제 API 호출이 없어 `services/`는 만들지 않는다. 이를 위해 가짜 저장·조회 계약이나 네트워크 처리를 추가하지 않는다.

## 구현 순서

1. 작성 모달 닫기 후 재오픈 시 제목 초기화 회귀 테스트를 추가하고 기존 페이지 테스트 기준선을 실행한다.
2. 기존 타입·샘플 데이터·상태 색상 매핑을 각각 `types/`, `data/`로 이동한다.
3. 페이지 목록·보기 상태와 파생 데이터를 `useDocumentWritePage`로 이동한다.
4. 공통 `RichTextEditor`에서 제공되는 에디터 인스턴스 상태, 문서 종류, 제목, 첨부 및 모달 종료 초기화를 `useDocumentComposer`로 이동한다.
5. 피드, 요약, 빈 상태 컴포넌트와 공통 `CommonDialog` 및 `RichTextEditor`/`RichTextEditorToolbar` 기반 작성 모달을 `components/`로 분리한다.
6. 페이지를 컴포넌트 조립 중심으로 정리한다.
7. 기존 페이지 테스트와 빌드를 실행하고 375px·768px·1280px 브라우저에서 표시를 확인한다.
8. 결과 문서와 스크린샷을 작성한다.

## 검증

- 구현 전/후 `cd frontend; npm run test -- tests/document-write-page.test.tsx`
- 구현 후 `cd frontend; npm run build`
- 브라우저에서 375px, 768px, 1280px 표시 및 작성 다이얼로그 확인
- 변경 후 `git diff --check`; 변경 범위가 문서 작성 기능과 결과물에 한정됐는지 확인

## 완료 기준

- 현재 샘플 목록, 필터, 리스트/피드, 상태 요약, 에디터와 첨부 UX가 유지된다.
- 작성 모달은 기존 `CommonDialog`와 공통 `RichTextEditor`/`RichTextEditorToolbar`를 사용하고 저장은 비활성 상태 그대로다.
- 페이지 테스트와 프론트엔드 빌드가 통과한다.
- 3개 뷰포트에서 레이아웃이 유지되고 결과 보고서 및 스크린샷이 저장된다.
