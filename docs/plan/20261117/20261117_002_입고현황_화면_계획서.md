# 20261117_002 입고현황 화면 계획서

기준: [작업지시서](../../directions/20261117/20261117_002_입고현황_화면_작업지시서.md)

## 구현 단위

| 단계 | 내용 | 산출물 |
| --- | --- | --- |
| 1 | 메뉴 SQL | `20261117_003` 입고현황 메뉴 등록·롤백·변경이력(입고등록 바로 다음) |
| 2 | 백엔드 목록 | `/api/v1/materials/material-receipt-status` 품목 행 단위 목록, 상태 3종 필터 |
| 3 | 프론트 현황 화면 | 입고현황 페이지, 상세 패널, 조회/수정 다이얼로그(입고등록 `embedded`) |
| 4 | 검증·결과 문서 | 테스트, 빌드, JDK 8 컴파일, 브라우저, 결과 문서 |

## 의존·재사용
- 가입고현황(`materials/arrival/status`)의 페이지·컬럼·훅·상세 패널·에디터 다이얼로그 구조를 그대로 따른다.
- 수정·취소는 입고등록 사양(`20261117_001`)의 API를 사용한다.
- 상태 검색은 정상(기본)/취소/전체 3종이다. 화면의 기본값은 `status=ACTIVE`이고, 전체는 서버가 상태 조건 없이 조회한다.

## 위험과 대응
- **상태 3종 규칙**: 기존 현황은 기본값이 없어서 취소건이 섞여 나온다. 입고현황은 처음부터 기본 정상으로 만들고, 기존 화면 정비는 별도 작업으로 예약한다.
- **연결 표시**: 목록의 가입고번호가 취소·삭제된 가입고를 가리킬 수 있다. 입고 상세에 복사한 가입고번호를 쓰고, 링크는 가입고가 남아 있을 때만 활성화한다.

## 검증 계획
- 서비스 테스트: 목록 필터·날짜 오류, 상태 3종, 기본값 정상.
- 프론트 테스트: 기본 조회 정상만, 취소·전체 선택, 번호 링크, 수정 다이얼로그, 취소 안내문.
- 백엔드 `mvn test`, 프론트 `npm run test`·`npm run build`, JDK 8 컴파일, 브라우저 375/768/1280/1920.

## 후속 작업 예약
기존 현황 화면(구매요청·발주·가입고)의 상태 조회 규칙 정비.
