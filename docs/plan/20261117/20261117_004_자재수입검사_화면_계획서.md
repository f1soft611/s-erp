## 의존·재사용

- 화면 패턴은 입고 `receipt/create`·`receipt/status`(헤더 폼 + F1Grid, `embedded`, 선택 창, 현황 상세 패널)를 기준 화면으로 따른다. 검사는 구매처 고정이 없고 행 단위로 가입고를 참조한다는 점이 다르다.
- 번호는 `IdSequenceService` 패턴, 키는 `MATERIAL_INSPECTION_NO`(형식 `QI-YYYYMMDD-NNNN`).
- 가입고 DAO·행 조회를 재사용하고 가입고 서비스의 잠금 확인(`requireReceiptRowsUntouched`류)에 검사 잠금을 추가한다. 가입고의 다른 동작은 바꾸지 않는다.
- 패키지는 신규 `quality` 모듈 아래 `inspect/create`, `inspect/status`로 입고(`materials/receipt/create|status`)와 같은 계층 구조를 쓴다.

## 위험과 대응

- **새 모듈**: 모듈 등록(`tb_module`)과 사이드바 아이콘·라우팅이 처음이다. 기존 모듈(구매자재) 등록 스크립트·`dashboardData.tsx` 아이콘 맵(`ClipboardCheck`)을 그대로 따르고, 모듈 경로는 `/quality`로 한다. 모듈 목록 순서(sort)는 생산관리(4) 다음(5)이다.
- **발주 잔량 계산 지점이 여러 곳**: 가입고 후보, 가입고 저장 검증, 발주 행 변경 409 검증, 발주현황 등에서 가입고 합으로 잔량을 계산한다. 구현 전에 계산 지점을 전수 확인하고 한 곳씩 테스트로 고정한다. 확인 결과 영향이 크면 사양서에 기록하고 사용자에게 알린다.
- **동시 검사**: 같은 가입고 행을 두 사람이 동시에 검사하면 대기량을 넘을 수 있다. 가입고 행을 `FOR UPDATE`로 잠근 뒤 대기량을 다시 계산한다(정렬된 id 순서로 잠가 교착을 피한다).
- **이력 보존과 FK**: 검사 취소 이력이 남은 가입고 행은 삭제될 수 있다. 검사 상세의 가입고 행 FK는 `ON DELETE SET NULL`이고 가입고번호를 복사해 둔다(입고와 같은 방식).
- **입고 수동 등록과의 경계**: 합격분 입고 연결·취소 제한은 다음 단계에서 추가한다. 이번 스키마는 합격량 컬럼만 두고 입고 연결 컬럼은 만들지 않는다.

## 검증 계획

- 서비스 단위 테스트: 후보 조회(검사 대상만, 대기량 0 제외), 등록(여러 행 한 번호 묶기, 대기량 초과 거부, 중복 행 거부, 번호 발급), 수정(행 빼기·수량 변경 범위), 취소(재취소 409), 가입고 잠금 409(행 수정·삭제·헤더 수정·취소)와 검사번호 안내, 취소 후 잠금 해제, 발주 잔량에 불합격 합 반영.
- 매퍼/스키마 정적 테스트: 기존 입고 패턴(`flushCache` 확인 포함).
- 프론트 테스트: 등록 화면(불러오기 창, 검사량 자동 계산, 초과 입력 안내, 취소 안내), 현황(상태 3종, 링크·상세·수정 다이얼로그), 가입고 화면 잠금 안내.
- 백엔드 `mvn test`(집중), 프론트 집중 테스트·`tsc`·`npm run build`, JDK 8 `--release 8` 컴파일, 실제 브라우저 375/768/1280px.

## 후속 작업 예약
입고 수동 등록(검사 합격분 불러오기, 입고 가능량, 취소 제한)을 수입검사 다음으로 이어서 진행한다. 이후 재고·LOT 연결, 매입마감, 기존 현황 화면의 취소건 기본 조회 규칙 정비.
