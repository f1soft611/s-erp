## 결정과 이유
- **직접 구현**: MUI `DateCalendar`는 연·월 드롭다운 헤더와 범위 칠하기를 슬롯으로 바꾸기 번거롭고 한국어·모양을 맞추기 어렵다. 요구한 모양이 단순하고(격자 + 헤더) 필요한 날짜 계산은 이미 쓰는 `dayjs`로 충분하므로 얇은 자체 컴포넌트로 만든다. 새 라이브러리는 추가하지 않는다. 시간 선택(`DateTimePicker`)은 기존 MUI 컴포넌트를 유지한다.
- **기간 선택 단순화**: 첫 클릭이 곧바로 "그 하루" 범위(시작=종료)를 입력에 반영하고 팝업은 열어 둔다. 두 번째 클릭이 범위를 완성하고 닫는다. 두 번째 클릭 전에 팝업을 닫아도 값이 비어 있지 않다.
- **`DateEditor` 호환**: 입력 텍스트 필드, 달력 열기 버튼 이름(`… 달력 열기`), 정규화·`disabled`·오류 표시는 그대로이고 팝업 내용만 바꾼다. `PageSearchArea`의 두 입력(시작일·종료일)은 같은 범위 달력을 각자의 아이콘에서 연다.

## 위험과 대응
- **공통 컴포넌트 영향**: 영업·공지·F1Grid가 모두 `DateEditor`를 쓴다 → `DateEditor` 기존 테스트(`f1-grid`, `page-search-area-detail`, 영업 폼, 공지)를 모두 실행하고 브라우저로 영업 폼·공지 작성을 확인한다.
- **`disabled`**: 영업 폼에서 비활성 날짜는 팝업이 열리지 않아야 한다 → 기존 동작을 테스트로 고정.
- **그리드 셀 편집**: 셀 편집기 안에서 팝업이 열려도 셀 편집 흐름(Enter/Escape/blur)이 깨지지 않아야 한다 → 그리드 날짜 셀 테스트 실행.
- **모바일 폭**: 팝업 폭을 `min(100vw - 32px, 296px)`로 제한하고 375px 브라우저로 확인한다.
- 영업 담당자에게 공통 컴포넌트 변경을 알린다(전달 안내문).

## 검증 계획
- 단위: 격자 생성(월 경계·윤년·주 시작), 범위 판정, 각 패널 동작.
- 연동: `DateEditor`(직접 입력·달력 선택·`disabled`), `PageSearchArea`(범위 선택 두 번 클릭, 역순 교체, 필수·오류), `MonthEditor`.
- 회귀: 위 기존 테스트 파일 전부. 브라우저 375/768/1280px.
