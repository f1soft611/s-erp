## 구현 단위

| 순서 | 단위 | 내용 |
| --- | --- | --- |
| 1 | DB | `tb_material_receipt_dt`에 마감 컬럼 추가, 마감월 인덱스, 롤백·변경이력 md, `db-schema.md`. 메뉴 시드(구매자재 > 입고관리 > 매입마감처리) |
| 2 | 백엔드 조회 | 구매처 요약, 입고 행 목록 (신규 패키지 `materials/receipt/closing`) |
| 3 | 백엔드 마감·해제 | 행 잠금(`FOR UPDATE`), 검증, 금액 재계산(`PurchaseOrderAmountCalculator`), 마감/해제 |
| 4 | 백엔드 잠금 | `MaterialReceiptServiceImpl`의 수정·행 빼기·취소에서 마감 행 검사 |
| 5 | 프론트 | 매입마감처리 화면(Splitter 좌우), 서비스·타입·열 정의 |
| 6 | 프론트 연동 | 입고현황 마감월 열, 입고등록 잠금 안내, 라우팅(`DashboardContent`) |
| 7 | 검증·문서 | 테스트, 빌드, JDK 8 컴파일, 실서버·브라우저 확인, 결과 문서 |

## 위험과 대응

- **금액 이중 관리**: 입고 행 금액과 마감 금액이 어긋날 수 있다. 마감된 행은 입고에서 못 고치므로(잠금) 마감 컬럼이 마감 시점 확정값이 된다. 마감 전 행의 금액은 입고 값을 그대로 보여 준다.
- **동시 처리**: 같은 행을 두 사람이 마감/해제하지 못하도록 대상 행을 `FOR UPDATE`로 잡고 상태를 다시 검사한다.
- **입고 취소와 충돌**: 마감 행이 있으면 입고 취소를 막는다. 반대로 취소된 입고(`use_at='N'`)의 행은 마감 대상에서 제외한다.
- **MES와 차이**: 전표 연동 없음, 해제 이력 없음, 마감 시 금액 서버 재계산. 사양서에 명시한다.

## 검증 계획
- 백엔드: 서비스·매퍼·스키마 스크립트 테스트, 전체 관련 테스트, `javac --release 8`.
- 프론트: 화면·서비스 테스트, `tsc --noEmit`, 빌드.
- 실서버: 구매처·입고 여러 건으로 조회·마감·해제·잠금, 1280/768/375px 브라우저 확인.
