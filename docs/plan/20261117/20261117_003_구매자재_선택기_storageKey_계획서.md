# 20261117_003 구매자재 선택기 storageKey 보강 계획서

기준: [작업지시서](../../directions/20261117/20261117_003_구매자재_선택기_storageKey_작업지시서.md)

## 구현 단위
| 단계 | 내용 |
| --- | --- |
| 1 | 선택기 5곳 `F1Grid`에 `storageKey` 지정(`frontend/src/pages/materials`) |
| 2 | F1-Grid 사용 문서(`F1-GRID.md`)에 선택기·팝업 그리드 키 지정 대상 명시 |
| 3 | 검증: 저장키 검사, 선택기 관련 테스트, 타입·빌드, 브라우저 열 설정 복원·독립성(375/768/1280px) |
| 4 | 결과 문서 |

## 위험과 대응
- **키 충돌**: 같은 키를 두 그리드가 쓰면 열 설정이 섞인다. 기존 키를 목록으로 확인하고 중복 검사 테스트로 고정한다.
- **기존 사용자 저장값**: 선택기는 지금까지 저장하지 않았으므로 기존 저장값이 없어 마이그레이션이 필요 없다.
- **선택기 다이얼로그가 열릴 때마다 마운트**: 열 설정 복원은 `storageKey`로 읽으므로 재진입 시 복원되는지 브라우저로 확인한다.

## 검증 계획
- `tests/f1-grid-storage-keys.test.ts`(필수 키, 중복)
- 선택기가 쓰이는 `material-arrival-create`, `purchase-order-create`, `purchase-request-confirm` 테스트
- `tsc --noEmit`, `npm run build`
- 실제 브라우저: 선택기를 열어 열 숨김·폭 변경 → 닫고 다시 열어 복원 확인, 다른 선택기에 영향 없음 확인

## 후속
구매 테스트 잔여 실패(7건)는 전체 프론트 테스트 별도 실행에서 재확인한다.
