## 의존·재사용

- 화면 패턴은 `frontend/src/pages/materials/arrival/create`(헤더 폼, 행 그리드, 선택 창, 서비스 계층, `embedded` 모드)를 그대로 따른다. 입고 화면은 구매처 고정·발주 불러오기가 없고 불러오기 창은 수입검사 합격분 틀만 둔다.
- 번호는 `IdSequenceService` 패턴, 키는 입고 전용(`MATERIAL_RECEIPT_NO`, 형식 `MI-YYYYMMDD-NNNN`).
- 부가세·금액 계산은 `PurchaseOrderAmountCalculator`(서버)와 `calculateOrderAmounts`(화면)를 재사용한다.
- 가입고 서비스(`MaterialArrivalServiceImpl`)의 저장 경로와 수정·취소 경로(`validateEditable`)에 연동을 추가한다. 가입고 로직의 다른 동작은 바꾸지 않는다.
- 입고 서비스가 가입고 행·헤더를 갱신할 때는 가입고 DAO를 재사용한다(별도 쿼리 중복 금지).

## 위험과 대응

- **두 서비스 간 순환**: 가입고 저장이 입고 생성을 호출하고, 입고 수정·취소가 가입고 DAO를 쓴다. 서비스 간 호출은 한 방향(가입고 → 입고 생성)만 두고, 입고 → 가입고는 DAO 수준으로 처리해 순환을 막는다.
- **동시 수정**: 입고·가입고를 같이 바꾸므로 입고 헤더와 연결 가입고 행·발주 행을 잠그는 순서를 고정한다(가입고 서비스와 같은 순서: 발주 행 → 가입고 → 입고).
- **이력 보존과 FK**: 무검사 입고 취소 시 가입고 행이 물리 삭제되므로 입고 상세의 가입고 행 FK는 `ON DELETE SET NULL`이고, 가입고번호를 입고 상세에 복사해 둔다.
- **무검사/검사 혼합 가입고**: 가입고 헤더에 두 종류가 섞일 수 있다. 입고가 생긴 행만 행 단위로 잠그고 나머지는 수정 가능하다.
- **수입검사 연결**: 불러오기 창 후보 조회와 수동 등록 저장은 수입검사 작업에서 추가한다. 이번에는 화면 틀과 안내 문구만 둔다.

## 검증 계획

- 서비스 단위 테스트: 자동 입고 생성(무검사만, 헤더 1건 묶기), 입고 수정의 가입고 반영, 입고 취소·행 빼기의 가입고 정리(헤더 취소 포함), 잔량 초과 허용, 가입고 잠금 409(행 수정·삭제·헤더 수정·취소), 번호 발급.
- 매퍼/스키마 정적 테스트: 기존 가입고 패턴.
- 프론트 테스트: 입고 화면 view/edit, 잠금 표시, 초과 확인창, 취소 안내문, 자동 입고 안내 문구.
- 백엔드 `mvn test`, 프론트 `npm run test`·`npm run build`, JDK 8 `--release 8` 컴파일.
