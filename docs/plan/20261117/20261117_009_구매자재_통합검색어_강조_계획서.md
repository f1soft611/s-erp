# 20261117_009 구매자재 현황 통합검색어 강조 적용 계획서

기준: [작업지시서](../../directions/20261117/20261117_009_구매자재_통합검색어_강조_작업지시서.md)

## 구현 단위

| 순서 | 단위 | 내용 |
| --- | --- | --- |
| 1 | 구매요청현황 | 페이지가 그리드에 `highlightKeyword`를 전달, 컬럼 `highlightSearch` 지정(요청번호 링크 포함) |
| 2 | 구매발주현황 | 동일 |
| 3 | 가입고현황 | 동일 |
| 4 | 입고현황 | 동일 |
| 5 | 자재수입검사현황 | 동일(검사번호·가입고번호 링크 두 개) |
| 6 | 매입마감처리 | 입고 행 그리드에 품목 컬럼 강조 |
| 7 | 문서·검증 | 테스트, `F1-GRID.md` 적용 화면 갱신, 브라우저 확인, 결과 문서 |

## 방식 (영업 구현과 동일)
- 그리드에는 **조회에 적용된 검색어**(`search.appliedFilters?.keyword`)를 `highlightKeyword`로 넘긴다. 입력 중인 `search.keyword`는 쓰지 않는다.
- 링크 컬럼은 `renderCell`의 context `highlightKeyword`를 `F1GridHighlightText`에 넘긴다. 링크 버튼의 접근성 이름(`… 상세 보기`)은 그대로 둔다.
- 컬럼 배열은 검색어에 의존하지 않게 `useMemo`로 유지한다(성능 규칙).

## 위험과 대응
- **링크 컬럼 병합 셀(`mergeRows`)**: 입고현황 등은 번호 열이 병합이다. 링크 안의 글자만 감싸므로 병합·클릭 영역은 바뀌지 않는다. 기존 병합 테스트를 실행한다.
- **강조 컬럼과 서버 SQL 불일치**: 서버가 검색하지 않는 컬럼을 강조하면 오해를 준다. 작업지시서 표를 매퍼 SQL로 검증했고, 이후 검색 컬럼이 바뀌면 같이 고친다는 점을 사양서에 적는다.
- **기존 테스트**: 강조가 `<span>`으로 글자를 나누므로 텍스트 단일 노드를 찾는 기존 테스트가 깨질 수 있다. 검색어가 없을 때는 기존 렌더와 같으므로 영향이 적고, 검색어가 있는 테스트가 있으면 갱신한다.

## 검증 계획
- 화면별: 검색 실행 전에는 강조 없음, 실행 후 일치 글자가 `data-f1-grid-highlight` 요소로 표시, 링크 동작·접근성 이름 유지.
- 회귀: `purchase-order-status`, `purchase-request-status`, `material-arrival-status`, `material-receipt-status`, `material-inspection-status`, `material-receipt-closing`, `f1-grid-highlight-keyword`, `f1-grid-docs`, 병합 셀 테스트.
- 실제 브라우저: 각 화면에서 검색어를 입력·조회해 빨간 글자 확인(1920/1280/768/375px).
