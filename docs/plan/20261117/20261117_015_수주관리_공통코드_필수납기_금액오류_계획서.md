# 수주관리 공통코드·필수납기·금액오류 처리 계획서

> **For agentic workers:** 이 계획을 순서대로 실행하고 각 단계의 체크박스를 갱신한다. 기능 구현 전 날짜별 상세사양서를 작성한다. 사용자 미커밋 수정은 보존하고 커밋하지 않는다.

**Goal:** 수주등록·현황에서 공통코드 표시/선택을 사용하고, 필수 납기·행 기본값·계산 범위 오류를 올바르게 처리한다.

**Architecture:** 기존 공통코드 그룹/항목 API를 읽는 수주업무 공용 프론트 서비스를 추가한다. `SALES_ORDER_STATUS`는 수주상태와 진행상태가 공유하고, `SALES_DELIVERY_METHOD`는 배송방법을 제공한다. 기존 API 문자열과 데이터베이스 컬럼 계약은 유지한다. 그룹과 초기 항목은 대상 테넌트를 명시하는 멱등 SQL seed로 제공하되 실제 DB에는 적용하지 않는다.

**Tech Stack:** React, TypeScript, MUI, F1-Grid, Vitest, Playwright, PostgreSQL/psql.

## Task 4: 공통코드 seed와 F1-Grid 문서

- [x] 현재 DB 계약 근거를 상세사양서에 기록한다: 기본 MCP `list_tables`; 관련 네 테이블 `describe_table`; 그룹 부재에 대한 집계 `EXISTS` 확인. 민감한 행 데이터는 문서화하지 않는다.

- [x] 각 SQL과 변경 이력 문서를 `docs/database` 및 `backend/DATABASE`에 byte-identical하게 둔다. 실제 DB에는 적용하지 않는다.
