## 변경 대상

- `frontend/src/pages/sales/order/create/SalesOrderCreatePage.tsx`: 기본정보
  그리드를 xs 1열, sm 2열, lg 4열로 맞춰 승인된 필드 순서를 데스크톱
  두 행으로 표시한다. 비고는 sm 이상에서 전체 행을 차지한다.
- `frontend/src/shared/components/master-picker/MasterPicker.tsx`: 거래처
  입력 옆 선택 버튼을 40px로 맞추고 기본정보 그리드의 일반 입력 필드와
  세로 정렬한다.
- `frontend/src/pages/sales/order/create/SalesOrderCreatePage.tsx`: 좁은 화면에서
  읽기 전용 수주번호 안내가 잘리지 않도록 해당 입력 글자 크기만 반응형으로
  줄인다.
- `frontend/tests/master-picker.test.tsx`: picker 버튼 높이와 행 정렬 간격의
  회귀 테스트를 포함한다.
- `docs/spec/20261026/20261026_010_수주등록_레이아웃_개선_상세사양서.md` 및
  날짜별 결과 문서/스크린샷: 검증 계약과 결과를 기록한다.

## 실행 절차

1. picker 버튼의 40px 높이와 인접 일반 입력 필드 정렬을 검증하는 실패
   테스트를 먼저 추가하고 실행한다.
2. picker 정렬, read-only 안내의 모바일 글자 크기, 기본정보 그리드 breakpoint만
   최소 수정한다.
3. picker, 수주등록 페이지, 스크롤 테스트를 실행한다.
4. 프론트엔드 빌드를 실행한다.
5. 실제 브라우저에서 375px, 768px, 1280px의 정렬 및 overflow를 확인하고
   결과 스크린샷을 저장한다.
6. 상세사양서와 결과 문서를 실제 확인 결과에 맞춰 갱신한다.

## 추가 브라우저 관찰 및 조정

첫 실제 브라우저 렌더링에서 picker 내부 입력/버튼이 그리드 행의 다른
`TextField`보다 16px 위에 배치되는 것을 확인했다. 또한 375px에서 read-only
수주번호 안내 텍스트의 실제 표시 폭이 필드의 가용 폭보다 커 일부가 잘렸다.
picker 상단 간격을 MUI 기본 입력 여백에 맞추고 xs에서만 안내 글자 크기를
12px로 조정해 두 현상을 수정했다. 수주번호 값과 입력 동작은 변경하지 않았다.

## 실행 결과 (2026-10-26)

- 집중 회귀 테스트: `master-picker`, `sales-order-create-page`,
  `sales-order-scroll` 3개 파일, 10개 테스트 통과.
- `npm run build`: TypeScript 및 Vite 프로덕션 빌드 통과.
- Chromium 격리 컨텍스트에서 실제 수주등록 라우트의 UI를 375px, 768px,
  1280px에서 확인했다. 임시 테스트 세션과 메뉴/모듈 API 응답만 모의했으며
  실제 인증정보/업무 데이터는 사용하지 않았다.
- 페이지 수평 overflow와 필드 경계, 1280px의 행 정렬 및 40px picker,
  375px의 수주번호 안내 문자열 표시를 확인했다. 세 뷰포트 캡처는
  [결과 문서](../../result/20261026/sales-order-entry-layout/20261026_010_수주등록_레이아웃_개선_결과.md)에
  포함했다.
