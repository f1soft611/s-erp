## 목표

현재 S-ERP 테넌트 및 거래처/품목 마스터에 안전하게 연결되는 수주 헤더/
상세 DDL을 작성하고, `/sales/order/create`에서 로컬 수주 초안을 입력할
F1-Grid 화면과 재사용 가능한 거래처/품목 선택기를 제공한다.

## 실행 순서

1. 작업지시서, 본 계획서, 상세사양서 간에 승인된 범위와 필드 계약을 맞춘다.
2. Node.js 기반 SQL 정적 검증을 먼저 작성해 DDL 사본, 컬럼, 키, 복합 FK
   요구사항의 미충족 실패를 확인한다.
3. 헤더/상세 SQL과 guarded rollback 및 변경 이력을 두 스키마 경로에
   byte-identical로 만들고 누적 스키마를 갱신한다.
4. 공통 picker 검색/선택/로딩/빈 결과/오류 테스트를 먼저 작성한 뒤
   data-source-injected 공통 UI를 구현한다.
5. 금액 함수 테스트를 먼저 작성한 뒤 수량×단가, 10% VAT 반올림, VAT 수정,
   상세/헤더 합계 계산을 구현한다.
6. 기존 `fetchCustomers`/`fetchMaterials`를 picker에 연결하는 어댑터를
   작성하고 헤더 입력 폼과 상세 F1-Grid를 구현한다.
7. `/sales/*` 인증 대시보드의 `sales/create`에만 페이지를 연결하고
   F1-GRID 문서를 보완한다.
8. 관련 집중 테스트, 빌드, SQL 정적 검사, 브라우저 3개 뷰포트 확인을
   마치고 결과 문서와 스크린샷을 기록한다.

## 의존 관계 및 제외 범위

- 상세사양 작성은 작업지시서와 승인 설계에 의존한다.
- SQL 작성은 DB MCP metadata 확인 결과와 상세사양에 의존한다.
- 판매 상세 화면 통합은 공통 picker와 금액 함수 구현에 의존한다.
- 최종 브라우저 확인은 페이지 라우트 연결과 F1-Grid 문서 갱신 후 수행한다.
- 수주 저장/목록조회 API, 백엔드 서비스, 견적 테이블/전환, 메뉴 데이터
  변경, DB 적용은 이 계획의 범위가 아니다.
- 현재 기준선에서 `dashboard-data.test.tsx`의 기존 아이콘 초기화 테스트
  1건이 실패했다. 기능 구현과 무관하므로 수정하지 않고, 새 경로 테스트는
  개별 테스트명 필터로 확인하며 기존 실패는 결과에 분리 기록한다.

## 완료 기준

- 상세사양과 DDL, 타입, 화면 컬럼이 일치한다.
- 양쪽 SQL/변경이력 사본이 동일하고 DDL 정적 테스트가 통과한다.
- picker, 금액 계산, 새 화면 분기 테스트가 통과한다.
- 프론트엔드 빌드가 통과한다.
- 375px/768px/1280px 브라우저 렌더링 및 동작을 확인한다.
- 실제 DB 미적용과 저장 API 미연결을 결과물에 명확히 기록한다.
