# 출하등록 수주 선택 상세검색 구현 계획

> **For agentic workers:** 이 저장소의 날짜별 문서와 기존 패턴에 따라 각 단계에서 대상 테스트를 먼저 추가하고 실패를 확인한 후 구현한다.

**Goal:** 출하등록의 수주 선택 모달에서 필수 수주일자와 빠른 날짜 버튼을 포함한 통합·상세검색을 제공한다.

**Architecture:** 모달은 `PageSearchArea`의 상세검색 동작과 날짜 프리셋을 재사용하고, 모달 전용 레이아웃 옵션으로 검색바가 대화상자 폭을 채우게 한다. 대상별 필드와 결과 선택은 `SourceOrderPicker`가 소유하며, 서버는 필수 수주일자·상세 조건을 기존 tenant 제한/잔량 제한 조회에 적용한다.

**Tech Stack:** React, TypeScript, MUI, F1Grid, PageSearchArea, Vitest, Java 8, Spring Boot, MyBatis, PostgreSQL.

---

## 파일 구조 및 책임

- `frontend/src/shared/components/PageSearchArea.tsx`: 기존 화면 동작을 유지하면서 `mode="dialog"`에 한해 폭 제한과 페이지용 여백을 제거한다.
- `frontend/src/pages/sales/shipment/delivery/create/components/SourceOrderPicker.tsx`: 상세검색 필드/defaults, draft/applied 조건, 검색 오류 및 기존 선택 흐름을 조립한다.
- `frontend/src/pages/sales/shipment/delivery/create/types/salesDelivery.types.ts`: 수주 선택 검색 조건 타입을 정의한다.
- `frontend/src/pages/sales/shipment/delivery/create/services/salesDelivery.service.ts`: 검색 조건을 `/source-orders` query parameters로 변환하고 응답 envelope를 검증한다.
- `backend/src/main/java/egovframework/let/sales/shipment/delivery/domain/model/SalesDeliverySourceOrderSearchVO.java`: keyword, 수주일자, 수주번호, 거래처, 품목, 계획번호/계획일자 조건을 표현한다.
- `backend/src/main/java/egovframework/let/sales/shipment/delivery/controller/SalesDeliveryApiController.java`: `/source-orders`의 선택 검색 파라미터를 기존 tenant 사용자와 함께 서비스에 전달한다.
- `backend/src/main/java/egovframework/let/sales/shipment/delivery/service/SalesDeliveryService.java` 및 `service/impl/SalesDeliveryServiceImpl.java`: 필수 수주일자 검증, 날짜 역전 검증 및 조회 조건 전달을 담당한다.
- `backend/src/main/resources/egovframework/mapper/let/sales/shipment/delivery/EgovSalesDelivery_SQL_postgresql.xml`: 기존 tenant/활성/잔량 조건을 유지하며 검색 조건을 limit 적용 전에 AND 방식으로 반영한다.
- `frontend/tests/sales-delivery-page.test.tsx`, `frontend/tests/sales-delivery-api.test.ts`: 모달 UI 흐름, 기본/상세 검색 파라미터 및 선택 회귀를 검증한다.
- `backend/src/test/java/egovframework/let/sales/shipment/delivery/controller/SalesDeliveryApiControllerTest.java`, `service/impl/SalesDeliveryServiceImplTest.java`, `mapper/SalesDeliveryMapperTest.java`: HTTP 파라미터, 입력 검증, Mapper SQL 조건을 검증한다.
- `docs/directions/20261119/20261119_007_출하등록_수주선택_상세검색_작업지시서.md`, `docs/spec/20261119/20261119_007_출하등록_수주선택_상세검색_상세사양서.md`, `docs/result/20261119/delivery-order-picker-detailed-search/`: 기준·상세 계약·검증 결과를 보관한다.

- [ ] 백엔드 Service 테스트에서 빈/역전 날짜 거부와 tenant/limit/각 검색 조건 Map 전달을 검증한다.

## Task 2: 모달 상세검색 UI와 검색 상태 구현

- [ ] `PageSearchArea`에 기본값 `page`인 `mode?: 'page' | 'dialog'`를 추가하고, `dialog`일 때만 padding/background/border와 빠른검색 최대폭 360px 제한을 제거한다.
- [ ] `SourceOrderPicker`의 상세검색 필드를 `orderDt`(필수 날짜, 서버 오늘 기준 전월 시작~오늘 기본값), `orderNo`, `customerName`(거래처코드/명), `materialName`(품목코드/명), `planNo`, `planDt`(선택 날짜)로 정의한다.
- [ ] 검색 기준은 기존 `usePageSearchDefaults`/`PageSearchArea` 경로를 통해 초기화하고, 기준일 초기화 실패 시 재시도/오류를 표시하며 브라우저 날짜로 대체하지 않는다.
- [ ] 필수 수주일자 시작·종료가 없거나 역전되면 API를 부르지 않는다. 상세검색의 빠른 날짜 버튼은 기존 서버 기준 preset을 유지한다.
- [ ] 통합검색은 별도 실행 버튼 없이 Enter로 현재 검색어와 마지막 적용 상세조건을 조회한다. 상세검색 실행은 새 상세조건을 적용하고, 초기화는 keyword 및 상세조건을 비운 뒤 필수 날짜 기본값으로 다시 조회한다.
- [ ] 검색 완료마다 기존처럼 선택을 초기화하고, 미납 잔량 행 필터·같은 거래처 검증·선택 콜백을 보존한다.

## Task 3: 검색 서비스/백엔드 계약 확장

- [ ] TypeScript `SourceOrderSearchFilters`로 `keyword`, `orderDtFrom`, `orderDtTo`, `orderNo`, `customerKeyword`, `materialKeyword`, `planNo`, `planDtFrom`, `planDtTo`를 전달한다.
- [ ] 백엔드 검색 VO와 controller/service signature를 확장하되 tenant ID는 계속 인증 principal에서만 가져온다.
- [ ] 서비스는 수주일자 양쪽 값이 ISO date이고 from <= to인지 검증한다. 계획일자는 optional이며 입력된 각 끝점만 조건으로 적용한다.
- [ ] Mapper는 keyword OR 검색을 유지하고, 상세 필드는 각각 검색 대상 OR, 필드 간 AND 조건으로 적용한다. 모든 조건은 기존 tenant/use/status/positive balance 조건과 LIMIT 200 이전에 처리한다.
- [ ] 날짜 parameter는 PostgreSQL date 비교로 명시 처리하고, 응답 envelope와 정렬을 유지한다.
