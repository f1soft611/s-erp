# 20261119_009 인사관리 2-1단계 사원등록 계획서

기준: [작업지시서](../../directions/20261119/20261119_009_hr-employee_작업지시서.md)

## 구현 단위
1. **DB**: `20261119_004` `tb_user` 확장(컬럼·제약·인덱스)과 사원등록 메뉴, `20261119_005` 공통코드 시드(성별·내외국인·근무형태·음력양력·직위)와 국가 시드(ISO 249개국). 각 롤백·변경 이력, `db-schema.md`.
2. **백엔드 공통**: `ResidentNumberCipher`(AES-256-GCM + HMAC 해시, 환경변수 키), 사번 채번(`tb_id_sequence`, 입사년월 범위).
3. **백엔드 사원**: `let/hr/employee` Controller·Service·DAO·Mapper, 검증, 계정 동시 발급.
4. **1단계 후속**: 부서 소속 사원 조회·사용안함 차단·부서장 자격에서 퇴직자 제외, 재직/퇴직/전체 필터, 사번·직위 노출.
5. **프론트**: `pages/hr/employee`(목록·상세 팝업), 부서관리 소속 사원 목록 보강, 대시보드 연결.
6. **검증·문서**: 테스트, 실서버·브라우저, 결과 문서.

## 순서
DB 스크립트 작성 → 백엔드(테스트 먼저) → 프론트 → 문서. DB 적용과 암호화 키 환경변수 설정은 사용자가 하므로 코드가 끝난 뒤 요청한다(키가 없으면 주민번호 저장만 안내 메시지와 함께 막히고 나머지는 동작).

## 위험과 대응
- `tb_user`는 결재·알림·구매 등이 많이 참조한다. 새 컬럼은 모두 null 허용이라 기존 INSERT·조회가 깨지지 않고, 기존 11명은 사번·입사일이 비어 있어 편집할 때 채운다.
- `UNIQUE (tenant_id, email_addr)`가 이미 있어 개인이메일 중복은 409로 안내한다.
- 퇴직 판정은 `retire_dt <= 오늘`이다. 1단계의 소속 사원 쿼리는 `use_at`만 보므로 퇴직자가 부서 사용안함을 막거나 부서장 후보가 되지 않게 함께 고친다.
- 주민번호 암호화 키 분실 시 복호화할 수 없다. 키와 버전을 같이 저장하고(AAD) 키 보관은 운영 절차에 맡긴다.
- 사진은 데이터 URL 텍스트라 목록 응답이 커질 수 있어 클라이언트에서 축소(최대 320px JPEG)하고 서버가 크기를 제한한다.
