# 20261119_008 인사관리 1단계 부서관리 계획서

기준: [작업지시서](../../directions/20261119/20261119_008_hr-department_작업지시서.md)

## 구현 단위
1. **DB**: `tb_department` 컬럼·제약 추가, `HR` 모듈과 부서관리 메뉴·권한 시드(테넌트 1), 롤백, 변경 이력, `db-schema.md`.
2. **F1Tree 확장**: 선택 옵션 `treeNodeIcon`과 문서 갱신, 회귀 테스트(먼저 실패 테스트).
3. **백엔드**: `let/hr/department` Controller·Service·Impl·VO·DAO·Mapper XML, 서비스 규칙 테스트(순환·차단·중복명·부서장 검증).
4. **프론트**: `pages/hr/department` 페이지, 부서 트리, 부서 입력 팝업, 소속 사원 목록, 서비스·타입·훅, 라우트·메뉴 연결.
5. **검증·문서**: 백엔드/프론트 테스트, 실서버·브라우저 1회, 결과 문서·스크린샷.

## 순서
2(F1Tree) → 1(DB, 사용자가 적용) → 3(백엔드) → 4(프론트) → 5. DB 적용은 사용자가 스크립트를 직접 실행하므로 3 완료 후 요청한다.

## 위험과 대응
- `tb_department`는 창고·구매요청·발주·가입고·입고·수입검사·`tb_user`가 참조한다. 삭제 기능이 없고 사용안함만 허용하므로 참조 무결성이 깨지지 않는다. 기존 조회 SQL은 `use_at`을 가정하지 않는 곳이 있어 사용안함 부서가 다른 화면 선택 목록에 계속 나올 수 있으며, 1단계는 이 범위를 바꾸지 않고 결과 문서에 후속 사항으로 기록한다.
- F1Tree 공통 변경은 옵션 미사용 시 렌더링이 동일함을 테스트로 고정한다.
- 현재 부서 데이터가 0건이라 제약 추가에 데이터 충돌이 없다(적용 직전 MCP로 재확인).
