# 문서·공지 공유 링크 및 공통 미리보기 계획서

## 목표

문서와 공지의 내부 공유 링크 및 외부 웹 링크를 두 기능의 본문/댓글에서 공통으로 미리보기하고, 내부 링크 선택 시 해당 상세 패널을 연다.

## 설계 요약

- 기존 문서 AES-GCM 토큰과 API 계약을 유지하며 공지에 별도 도메인 문맥을 갖는 tenant-bound 토큰/API를 추가한다.
- 공지 공유 메뉴는 기존 공지 작성자 메뉴를 사용해 링크를 복사한다.
- 링크 추출/분류/카드 상태 UI는 shared feed 컴포넌트가 담당하고, 문서·공지 resolver/API와 상세 패널 콜백은 각 도메인 service/page가 제공한다.
- 같은 기능의 링크는 기존 패널을 열고 교차 기능 링크는 현재 페이지를 유지하는 공통 우측 패널에서 기존 상세 UI를 사용한다.
- 외부 OG 조회는 기존 인증 API를 재사용한다. DB 변경과 링크 데이터 저장은 없다.

## 구현 단계

1. 작업지시서 및 상세사양을 확정한다.
2. 공통 토큰 codec 및 공지 공유 API를 테스트 우선으로 구현한다.
3. 공용 링크 분류기와 미리보기 카드를 구현하고 문서 renderer를 adapter 형태로 유지한다.
4. 공지 작성자 메뉴, 토큰 기반 상세 패널 진입, 교차 기능 우측 패널을 연결한다.
5. 공지 본문/댓글과 문서 본문/댓글에 공통 링크 미리보기를 연결한다.
6. 회귀 테스트, 빌드/lint, 375/768/1280px Chromium 검증을 수행하고 결과 문서/스크린샷을 저장한다.

## 검증 및 DB 확인

- `s-erp-postgresql-readonly`의 `list_tables`로 공개 테이블 목록을 확인했다. 공유 토큰/미리보기 메타데이터를 영속화하지 않으므로 테이블, 컬럼, SQL 변경은 없다.
- Backend: token round-trip 및 domain/tenant isolation, notice share issue/resolve, authentication 및 not-found 처리.
- Frontend: 모든 링크 분류, 공유 메뉴/복사 오류, 본문/댓글/답글 렌더링, same/cross-feature 상세 열기, 외부 미리보기 실패 fallback.
- Chromium: 375px, 768px, 1280px에서 mixed-link 카드와 상세 이동 및 가로 overflow를 확인한다.

## Java 8 테스트 컴파일 후속 수정

- 공유 API/codec 테스트의 `String.repeat()`를 기존 테스트에서 사용하는 `new String(new char[n]).replace(...)` 방식으로 교체한다.
- 토큰 길이와 검증 시나리오를 유지하고 Maven 컴파일 설정은 변경하지 않는다.
- 두 테스트 파일을 `javac --release 8`로 컴파일한 뒤 해당 Maven 테스트를 실행한다.

## 외부 카드 라벨 제거 후속 계획

1. 공통 feed 및 문서 wrapper 테스트에서 `expect(screen.queryByText('웹 링크', { exact: true })).not.toBeInTheDocument()`로 요구사항을 고정하고 실패를 확인한다.
2. `FeedLinkPreviews.tsx`의 외부 카드 상단 caption만 삭제한다.
3. 기존 브라우저 테스트는 미리보기 컨테이너 안에 해당 caption이 없음을 검증하도록 변경한다. 본문에 사용자가 입력한 링크 텍스트는 그대로 유지한다.
4. 집중 Vitest, targeted lint, build 및 375/768/1280px 브라우저 검증 후 결과와 스크린샷을 갱신한다.

## 교차 기능 우측 패널 후속 계획

1. `frontend/tests/feed-link-previews.test.tsx`에 콜백 없는 내부 카드도 버튼으로 열리고 경로 이동 없이 공통 패널에 대상 kind/id를 전달하는 회귀 테스트를 먼저 작성한다.
2. `frontend/src/shared/components/feed/FeedLinkPreviews.tsx`의 내부 anchor fallback을 공통 패널 열기로 바꾼다. 제공된 기존 콜백은 우선 유지한다.
3. `frontend/src/shared/components/feed/ContentDetailContext.ts`로 열린 공통 패널 안의 후속 링크도 같은 패널에서 대상을 교체하도록 연결한다.
4. `frontend/src/pages/groupware/shared/components/SharedContentDetailPanel.tsx`는 MUI 우측 Drawer와 기존 문서 상세/공지 상세 adapter를 lazy-load한다. 모바일 전체 폭, 데스크톱 기존 패널 폭을 사용하며 닫기/ESC/오류/로딩을 제공한다.
5. 공지 adapter는 기존 상세 조회·댓글 hook·feed를 재사용한다. 편집/삭제/고정은 원래 기능 화면에서 수행하도록 관리 버튼을 숨긴다. 문서도 기존 조회용 상세 UI를 재사용한다. 서버 권한 정책과 API/DB 계약은 변경하지 않는다.
6. 집중 Vitest/lint/build와 Chromium 375/768/1280px에서 두 방향 열기, 원래 URL/화면 유지, 닫기, 외부 새 탭을 확인하고 결과와 스크린샷을 저장한다.

## 공지 미리보기 구분명 후속 수정

- 작성자 표시 후속: 공통 notice resolver의 subtitle에 기존 `writerName`을 구분점으로 연결한다. 공지 본문/댓글 테스트에 작성자를 추가해 실패를 확인하고, 문서 미리보기의 이름 누락 fallback은 유지한다. 집중 테스트/lint/build 및 세 너비 브라우저에서 확인한다.

1. 문서/공지 미리보기 테스트에 공통코드 `OPS` → `운영공지` 매핑과 코드 미노출 기대값을 추가하고 실패를 확인한다.
2. 공지 도메인 공통 resolver에서 기존 공통코드 그룹/항목 API를 사용해 이름을 조회하고, 문서/공지 두 adapter의 중복 resolver를 대체한다.
3. 명칭 조회 실패/미등록 시 `공지`로 표시하며 공지 상세/권한 오류는 기존 unavailable 처리를 유지한다.
4. 집중 Vitest/lint/build 및 375/768/1280px 브라우저에서 한글 구분명을 확인하고 결과 문서와 스크린샷을 갱신한다.
