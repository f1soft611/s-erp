# 댓글 수정 권한 및 이미지 첨부 구분선 계획서

## 목표

문서와 공지에서 본인 댓글만 수정/삭제 메뉴를 사용할 수 있게 하고, 댓글 수정 중 이미지 미리보기와 파일명 사이를 구분선과 여백으로 분리한다.

## 설계 요약

- 공통 `TiptapCommentThread`는 `FeedCommentItem.isEditable === true`일 때만 더보기 버튼과 수정/삭제 메뉴를 렌더링한다.
- 공지 댓글 adapter는 댓글의 `writerId`와 `getStoredAuth()?.userId`를 문자열로 비교해 소유자 여부를 설정한다. 작성자 또는 로그인 ID가 누락되면 false로 설정한다.
- 공통 첨부 목록에서 이미지 미리보기는 유지하고, 미리보기와 파일명 영역 사이에 장식용 구분선과 간격을 표시한다.
- 서버 API는 기존 작성자 ID 제한을 유지하며 DB 변경은 없다.

## 파일 구성

- `frontend/src/shared/components/feed/TiptapCommentThread.tsx`: 댓글 소유자에게만 메뉴 표시
- `frontend/src/pages/groupware/community/notice/data/noticePostAdapter.ts`: 공지 댓글 소유자 판별
- `frontend/src/shared/components/feed/AttachmentList.tsx`: 이미지와 파일명 사이 구분선/간격
- `frontend/tests/feed-components.test.tsx`: 메뉴 권한 및 이미지 구분선 UI 회귀 검증
- `frontend/tests/notice-comment-tree.test.ts`: 공지 댓글의 작성자 ID 비교 검증

## 구현 단계

1. `feed-components.test.tsx`에 `isEditable: false` 댓글은 메뉴가 없고 `true` 댓글은 메뉴가 있는 테스트를 추가한다.
2. `notice-comment-tree.test.ts`에 로그인 사용자 소유 댓글만 편집 가능하고 타인/미확인 작성자 댓글은 편집 불가인 테스트를 추가한다.
3. `feed-components.test.tsx`에 이미지 미리보기 유지 및 이미지와 파일명 사이 구분선 렌더링 테스트를 추가한다.
4. 집중 Vitest를 실행해 변경 전 실패를 확인한다.
5. 댓글 메뉴 조건, 공지 adapter의 소유자 비교, 첨부 목록 구분선을 최소 수정으로 구현한다.
6. 집중 Vitest, TypeScript/Vite build, lint와 Chromium 375/768/1280px 렌더링을 검증한다.
7. 완료 기준과 검증 결과를 결과 문서에 기록한다.

## 검증 계획

- `cd frontend && npm run test -- tests/feed-components.test.tsx tests/notice-comment-tree.test.ts`
- `cd frontend && npm run build`
- `cd frontend && npm run lint`
- Chromium에서 소유자 메뉴, 이미지 미리보기/구분선 및 375px, 768px, 1280px 가로 넘침을 확인한다.
- DB/API 계약 변경은 없다.
