# 통합검색 전용 페이지 Implementation Plan

> **For agentic workers:** Use executing-plans inline, task-by-task. Preserve unrelated worktree changes. No commit requested.

**Goal:** 헤더의 직접 검색 입력과 가독성 있는 구분별 전용 결과 페이지로 기존 모달 검색을 대체한다.

**Architecture:** 기존 shared 서비스/타입과 서버를 유지한다. 공통 헤더 UnifiedSearch는 입력·이동만 담당한다. pages/search/UnifiedSearchPage는 URL 조건으로 결과를 조회하고 전체 집계와 개별 페이지 요청을 분리한다. DashboardPage/AppRouter에 인증된 공통 /search 경로를 등록한다.

**Tech Stack:** React, TypeScript, React Router, MUI, Vitest, Playwright.

- [x] 초기 조건 `/search?keyword=공지&type=ALL&page=1`, 더보기 `type=NOTICE&page=1`, 다음 `page=2`를 검사한다.

## Task 2: 헤더와 결과 페이지

- [x] `frontend/src/shared/components/search/UnifiedSearch.tsx`를 `<form>`+검색 입력+버튼으로 교체한다. trim 2~100자 검증 후 URLSearchParams로 `/search`로 이동한다. URL 검색어로 입력을 동기화한다.
- [x] `frontend/src/pages/search/UnifiedSearchPage.tsx`를 생성한다. URL의 keyword/type/page를 파싱하고 기존 API offset `(page - 1) * 10`으로 변환한다.
- [x] 전체 summary 조회는 keyword별, 개별 목록 조회는 keyword/type/page별 effect로 분리하고 cleanup으로 과거 응답을 무효화한다. 기존 결과와 URL 키가 다르면 표시하지 않는다. 명시적 재검색은 history state의 요청 키를 바꿔 같은 검색어도 새로 조회한다.
- [x] 전체/메뉴/문서/공지 탭에 전체 집계 건수를 표시한다. 전체는 각 5개/더보기, 개별은 10개/이전/다음, 제목 강조와 보조 설명을 제공한다. 방향키/Home/End로 탭을 조작한다.
- [x] 페이지 안 검색은 URL을 갱신한다. 새 검색은 전체/1페이지로 초기화한다. 조회 오류/재시도와 빈 결과를 구분한다.
- [x] `frontend/src/routes/AppRouter.tsx`에 ProtectedRoute `/search`를 등록한다. DashboardPage의 유효 경로·헤더 제목·본문 분기에 `/search`를 연결하고 검색 페이지를 최근 메뉴로 기록하거나 다른 메뉴 즐겨찾기로 등록하지 않게 한다.
- [x] 모바일에서 헤더 입력을 숨기지 않고 유동 폭/줄바꿈을 적용한다.
