# 메뉴 즐겨찾기 구현 계획

**목표:** 로그인 사용자가 권한 메뉴를 루트/폴더로 관리하고 좌측 가상 즐겨찾기 모듈에서 빠르게 여는 기능을 구현한다.

**아키텍처:** 즐겨찾기는 실제 `tb_module`과 분리된 사용자·tenant별 DB 리소스다. 백엔드는 인증 사용자와 사용 가능한 메뉴 권한을 검증하며, 프런트엔드는 기존 `DashboardPage`의 모듈 선택·라우팅 흐름을 재사용해 즐겨찾기 가상 모듈과 관리 컨텍스트 메뉴를 표시한다. 메뉴 하나는 루트 또는 단일 폴더에만 둘 수 있고, 폴더는 루트 아래 1단계다.

**기술 스택:** Java 17, Spring Boot/eGovFrame, MyBatis, PostgreSQL, React, TypeScript, MUI, React Router, Vitest/Testing Library, JUnit 5.

## 실행 순서와 단계별 검증

1. 설계·작업지시서의 범위, 단일 위치, 1단계 폴더, 빈 폴더 삭제 제약을 상세 사양서와 대조한다.
2. 구현 세션 시작 시 DB MCP `list_tables` → `describe_table(tb_menu)` 및 `describe_table(tb_user)`를 확인한다. 데이터 행은 조회하지 않고, 실제 DB에 DDL을 실행하지 않는다.
3. DDL을 날짜 폴더 양쪽에 작성하고 유니크/FK/삭제 정책과 rollback guard를 검토한다. `docs/database/db-schema.md`와 두 SQL 사본을 비교한다.
4. 백엔드 서비스 테스트를 먼저 작성한다: 사용자/tenant 격리, permission leaf 검증, 중복 차단, folder create/rename/delete, empty-only deletion, move/unfavorite, 권한 상실 메뉴 filtering.
5. 테스트를 통과시키는 DAO/Mapper 및 service/controller를 최소 구현한다. 모든 조회/수정은 principal에서 나온 `(tenantId,userId)`로 제한한다.
6. 프런트엔드 API 서비스 실패 테스트를 작성하고 API 호출 함수를 구현한다. 기존 API client와 공통 오류 정책을 사용한다.
7. 즐겨찾기 트리 및 context menu 컴포넌트 테스트를 작성한다. 빈 별/채운 별 토글이 현재 메뉴를 선택하지 않고, `READ` 권한이 없는 메뉴에는 별이 없으며, 우클릭에서 폴더 관리가 되는지 확인한다.
8. Dashboard에서 실제 모듈과 분리된 `__favorites__` 식별자의 가상 항목을 조건부로 표시한다. 선택된 즐겨찾기 leaf를 기존 menuId/path/permission으로 해석해 현재 메뉴 표시와 라우팅을 유지한다.
9. 타깃 테스트 후 `npm run build`, 백엔드 관련 Maven 테스트를 실행한다. 실패는 기존 baseline과 신규 변경 원인을 구분한다.
10. 기존 4173 서버를 S-ERP용인지 확인한 뒤 재사용한다(기존 프로세스 종료 금지). 브라우저에서 375/768/1280px의 일반 메뉴 우클릭/더보기, 추가, 이동, 폴더 관리, 가상 모듈 숨김/표시를 검증한다.
11. 결과 README와 스크린샷을 작성하고 `git diff --check` 및 SQL 사본 일치를 검증한다. 커밋은 하지 않는다.
