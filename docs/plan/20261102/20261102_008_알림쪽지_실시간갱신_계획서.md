# 알림·쪽지 실시간 갱신 Implementation Plan

> **For agentic workers:** Execute bounded backend and frontend units; preserve existing user changes. No commit requested.

**Goal:** 인증된 화면에서 다른 사용자의 알림/쪽지를 새로고침 없이 갱신한다.

**Architecture:** 서버 after-commit publisher가 SSE registry의 tenant/user 연결에 최소 변경 종류만 전송한다. 루트 브라우저 bridge는 인증된 fetch streaming, 재연결, 30초 재동기화와 이벤트 병합을 담당한다. 각 UI는 기존 REST와 조용한 갱신을 재사용한다.

**Tech Stack:** Spring MVC SseEmitter/transaction synchronization, React, Fetch ReadableStream, Vitest/Playwright.

## 1. 서버

- [x] `backend/.../groupware/realtime/`에 publisher/stream service/controller와 테스트를 추가한다.
- [x] 연결은 principal tenantId/uniqId에서만 소유자를 결정하고 `/api/v1/groupware/realtime`을 SSE로 제공한다.
- [x] `publish(tenantId,userId,area)`는 활성 트랜잭션의 afterCommit에만 전송한다. rollback은 무신호. 서비스 오류와 전송 실패를 분리한다.
- [x] NotificationServiceImpl/DirectMessageServiceImpl에서 저장/읽음/보관/숨김 뒤 적절한 소유자에게 신호를 예약한다. 쪽지 읽음은 상대 읽음 표시도 갱신한다. 기존 생성자 테스트를 일치시킨다.
- [x] 15초 heartbeat, 45초 연결 회전/정리, 준비 신호, disconnect cleanup을 구현하고 테스트한다.

## 2. 공통 클라이언트

- [x] 기존 apiClient의 토큰 갱신/인증을 재사용하는 `apiGetEventStream(path,signal)`을 추가한다. 토큰 query 금지.
- [x] `shared/services/realtimeService.ts`에 chunk-safe SSE 파싱/단일 연결/retry 1~30초/250ms 이벤트 병합/30초 재동기화를 구현한다.
- [x] `shared/components/RealtimeBridge.tsx`를 App에 1회 연결한다. 인증/계정 변경/숨김/unmount 시 abort/타이머 정리, 복귀 시 재연결 및 재동기화한다.
- [x] 전달 종류는 NOTIFICATION/MESSAGE뿐이며 콘텐츠/소유자 ID/URL은 전달하지 않는다.

## 3. UI 연결

- [x] NotificationCenter/MessageCenter 배지를 조용히 갱신하고 열린 팝오버는 목록도 갱신한다.
- [x] NotificationInboxPage는 필터/기존 목록을 유지하며 처음에 로딩된 범위를 조용히 갱신한다. 기존 load와 요청 경쟁을 피한다.
- [x] MessageInboxPage는 기존 refreshQuietly를 연결하되 중복/선택 변경/unmount/숨김 경쟁을 방어한다.
- [x] MessageChatView는 읽음 변경이나 새 메시지로 현재 위치를 강제 하단 이동시키지 않는다. 하단에 있을 때만 최신 메시지를 따라간다.
