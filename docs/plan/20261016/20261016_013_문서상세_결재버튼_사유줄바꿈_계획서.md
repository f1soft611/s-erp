# 문서 상세 결재 버튼 및 사유 줄바꿈 Implementation Plan

**Goal:** 상세 반려·보완요청을 기존 사유 팝업으로 연결하고 시스템 댓글의 개행을 보존한다.

**Architecture:** `DocumentApprovalDetailFeed.tsx`의 기존 사유 팝업을 상세/피드가 공유한다. `TiptapCommentThread.tsx`의 시스템 전용 일반 텍스트 영역에만 `whiteSpace: 'pre-wrap'`을 적용한다. API 및 DB는 변경하지 않는다.

**Tech Stack:** React, TypeScript, MUI, Vitest, Playwright.

## 근거

- [작업지시서](../../directions/20261016/20261016_013_문서상세_결재버튼_사유줄바꿈_작업지시서.md)
- 상세 버튼은 즉시 `handleAction`을 호출하지만 사유는 화면 하단에서만 입력할 수 있어 빈 사유 검증에서 중단된다.
- 시스템 이벤트는 일반 텍스트로 안전하게 렌더링되지만 CSS 기본 공백 처리로 개행이 합쳐진다.

## 실행

1. `frontend/tests/document-write-page.test.tsx`에 상세 사유 팝업 테스트를 추가한다. 반려/보완 각각 빈 사유 차단, 개행 보존 전송, 서버 오류 후 재시도, 취소 시 무전송을 검증한다. 상세 승인 성공 및 기존 취소 회귀도 실행한다.
2. `frontend/tests/feed-components.test.tsx`에 시스템 내용의 `textContent`와 `white-space: pre-wrap`, HTML 비해석 검증을 추가한다.
3. 집중 테스트 실패를 확인한다.
4. 상세 반려/보완 버튼을 `openReasonDialog`로 연결한다. 기존 사유 팝업의 피드 전용 open 조건과 성공 정리 조건을 제거한다. 하단 처리 의견은 승인 선택 의견으로 유지한다.
5. 시스템 텍스트 스타일에 `whiteSpace: 'pre-wrap'`을 추가한다.
6. 관련 문서작성·피드·서비스 테스트와 `npm run build`를 실행한다.
7. 기존 4173 서버를 재사용하고 비식별 mock API 브라우저 시나리오로 팝업 처리 및 줄바꿈을 375/768/1280px에서 확인한다. 실제 업무 문서는 수정하지 않는다.
8. 결과 및 화면을 `docs/result/20261016/document-approval-actions/`에 저장한다. 기존 작업 변경은 유지하며 자동 커밋하지 않는다.

## 추가 요청: 공통 다이얼로그 적용

1. 기존 상세 반려/보완 테스트에 공통 헤더 닫기, 설명 연결, 480px 최대 폭, 공통 actions 슬롯 검증을 추가하여 실패를 확인한다.
2. `DocumentApprovalDetailFeed.tsx`의 사유 입력용 MUI Dialog만 `CommonDialog size="xs"`로 교체한다. 제목/설명을 props로, 확인/취소 버튼을 `actions`로 전달한다.
3. 기존 닫기 초기화와 처리 중 가드를 하나의 `closeReasonDialog` 함수로 공유한다. 공통 셸과 다른 Dialog는 수정하지 않는다.
4. 상세/피드 사유 테스트와 공통 다이얼로그 테스트, 빌드 및 지정 3개 너비의 브라우저 시나리오를 실행하고 화면/결과를 갱신한다.
