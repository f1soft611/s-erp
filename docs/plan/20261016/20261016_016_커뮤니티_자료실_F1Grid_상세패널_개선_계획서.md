> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task after the dated detailed specification is approved. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Align `/groupware/community/archive` with the draft-form management search/F1-Grid pattern and the notice/document feed detail layout without changing backend contracts.

**Architecture:** Keep archive API, permission, category, composer, mutation, and download behavior. Adapt the existing archive-list hook into an F1-Grid paged data source, replace the HTML table with read-only F1-Grid columns, connect integrated and category detailed search through `PageSearchArea`, and compose the existing full-height detail overlay from shared feed and attachment UI.

**Tech Stack:** React, TypeScript, MUI, existing F1-Grid `dataSource`, `PageSearchArea`, shared feed components, Vitest, Vite.

## Task 2: Adapt the list hook and service for F1-Grid paging

- [ ] **Step 1: Extend the list service with an optional abort signal**

Add `signal?: AbortSignal` as the final optional `fetchArchivePosts` parameter and pass it to the existing request:

```ts
export async function fetchArchivePosts(
  pageIndex: number,
  pageUnit: number,
  keyword?: string,
  categoryCode?: string,
  signal?: AbortSignal,
): Promise<ArchivePageResult> {
  // Keep existing URLSearchParams construction and normalization.
  const path = `/api/v1/groupware/boards/archive/posts?${query.toString()}`;
  const response = signal
    ? await apiGet<ArchiveListApiResponse>(path, signal)
    : await apiGet<ArchiveListApiResponse>(path);
  // Keep the existing resultList/resultCnt response mapping.
}
```

Preserve all existing call signatures because the new argument is optional and last.

- [ ] **Step 2: Convert `useArchiveList` to applied filters plus a paged data source**

Use existing `F1GridDataSource`, `F1GridDataSourceQuery`, and `ArchivePost` types. Store only the applied integrated keyword and category; create a memoized source with the existing page size (`20`) and translate the grid query:

```ts
const pageIndex = Math.floor(query.offset / query.limit) + 1;
const result = await fetchArchivePosts(
  pageIndex,
  query.limit,
  keyword,
  categoryCode,
  query.signal,
);
return { rows: result.resultList, totalRowCount: result.resultCnt };
```

Expose `dataSource`, `keyword`, `categoryCode`, setters, and a retry token/action. Setters leave the opposite filter intact. Retry changes the source identity so F1-Grid reloads from offset zero. Remove list-only hook state that was exclusively required by `ArchivePostTable` (page index, result page, manual loading state); category loading remains in `useArchiveCategories`.

## Execution acceptance criteria

- Archive uses `PageHeader → PageSearchArea → PageMessageArea → F1-Grid`.
- Only one integrated keyword input exists; category is the only detailed-search field.
- Grid columns show title, category, writer, created date, and attachment count, with title-only detail activation.
- Existing API keyword/category/page contracts and newest-first ordering are preserved; F1-Grid uses server page loading and total count without duplicate table pagination.
- Detail follows top area → title/plain-text body → shared attachment list, in a full-height right-side overlay.
- Category and permission-gated edit/delete share the top actions area; file downloads remain individual.
- Existing CRUD, attachment, permission, and error behavior remains covered by passing tests.
- Build and `git diff --check` pass; required responsive evidence and result documentation exist.
