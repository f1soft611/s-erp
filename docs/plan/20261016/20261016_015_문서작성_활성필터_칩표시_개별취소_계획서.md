# 20261016_015 문서작성 활성 필터 칩 표시 및 개별 취소 계획서

## 목표

문서작성 화면의 공통 피드/리스트 툴바에 활성 조회 조건을 hashtag 칩으로 보여 주고 각 칩의 X로 그 조건만 제거한다.

## 변경 파일과 책임

- `frontend/src/pages/groupware/documents/write/data/documentPresentation.ts`
  - `DocumentApprovalScope`의 기존 패널 표시 라벨을 중앙 helper/record로 제공한다.
- `frontend/src/pages/groupware/documents/write/components/ApprovalSummaryPanel.tsx`
- `frontend/src/pages/groupware/documents/write/components/DocumentStatusPanel.tsx`
  - 기존 표시 문자열을 공통 scope label helper로 교체해 chip과 동일한 라벨을 사용한다.
- `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`
  - 필터 값에서 활성 칩 label 및 accessible delete name을 파생한다.
  - scope/kind/document 각각을 지우는 독립 callback을 제공한다.
  - 기존 전체 초기화 button API는 제거하고, 특정 문서 제목은 summary notice를 기준으로 표시한다. summary에 없으면 문서 ID 기반 fallback을 사용한다.
- `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`
  - 기존 `전체 조회` 버튼을 제거하고 `PinnedViewToolbar`의 동일한 filterAction 위치에 칩과 접근 가능한 X 버튼을 표시한다.
- `frontend/tests/use-document-write-page.test.tsx`
  - scope/kind/document 칩 파생과 각 제거 후 유지되는 상태 및 service request 인자를 테스트한다.
- `frontend/tests/document-write-page.test.tsx`
  - 활성 칩 표시, 제거 버튼 접근성, 개별 해제, 필터 없는 상태의 비표시, 피드/리스트 모드 유지 및 전체 조회 버튼 부재를 검증한다.
- `docs/result/20261016/document-write-filter-chips/`
  - 테스트/build/browser 검증 결과와 가능한 경우 3 viewport 스크린샷을 저장한다.

## 단계 및 검증

1. 훅 테스트에서 범위/업무구분/문서 선택별 칩 descriptor와 개별 제거 후 서비스 호출 조건을 검증한다. 현재 `resetFilters` 검증은 새 독립 해제 동작 테스트로 교체한다.
2. 페이지 테스트에서 기본 상태에 칩/전체 조회 버튼이 없고, 활성 필터 시 `#조건`과 이름이 있는 X 버튼이 노출되도록 검증한다.
3. 테스트가 의도대로 실패하는 것을 확인한 뒤 scope-label helper, hook descriptors/handlers, page chip controls 순으로 구현한다.
4. `npx vitest run tests/document-write-page.test.tsx tests/use-document-write-page.test.tsx` 또는 두 파일의 지정 테스트 이름을 실행한다. 페이지 테스트가 장시간인 점을 고려해 필터 칩 테스트부터 집중 실행한다.
5. `npm run build`, 변경 TS/TSX 파일 대상 `npx oxlint`, `git diff --check`를 실행한다.
6. 기존 4173 브라우저 세션만 사용한다. 인증된 문서작성 페이지에서 375px/768px/1280px 칩 줄바꿈 및 가로 overflow를 확인한다. 인증 불가 시 결과 보고서에 제한을 분리한다.
7. 결과 문서를 작성하고 변경 파일 범위를 확인하며 무관한 미커밋 변경을 보존한다.

## 범위 제외

backend/API/DB, 필터 저장, query URL, 상세 패널 동작, 새 전체 초기화 기능, 다른 목록 페이지의 필터 UX 변경.
