# 20261016_012 문서작성 전체 조회 필터 초기화 계획서

## 목표

문서작성 피드/리스트 화면에서 적용된 업무구분, 결재 범위, 특정 문서 필터를 한 번에 초기화해 전체 조회로 돌아갈 수 있도록 한다.

## 변경 파일과 책임

- `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`
  - 현재 세 필터 값에서 활성 필터 여부를 계산한다.
  - 범위, 업무구분, 특정 문서 ID를 한 번에 기본값으로 되돌리는 `resetFilters`를 반환한다.
  - 기존 목록 조회 effect와 API 계약을 재사용한다.
- `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`
  - 기존 업무구분 필터 옆에 조건부 `전체 조회` 버튼을 표시한다.
  - 초기화 후 현재 `viewMode`를 유지한다.
- `frontend/tests/document-write-page.test.tsx`
  - 버튼 표시/숨김, 클릭 후 전체 필터 요청, 피드/리스트 모드 유지를 검증한다.
- `frontend/tests/use-document-write-page.test.tsx`
  - 상태 훅의 범위/업무구분/특정 문서 초기화와 API 재조회 매개변수를 검증한다.
- `docs/directions/20261016/`, `docs/plan/20261016/`, `docs/spec/20261016/`
  - 작업지시서, 계획서, 상세 사양서를 추적한다.
- `docs/result/20261016/document-write-filter-reset/`
  - 검증 결과와 가능한 경우 세 화면 폭 스크린샷을 기록한다.

## 구현 및 검증 순서

1. `use-document-write-page.test.tsx`에 상태 초기화 회귀 테스트를 작성하고 단독 실행해 실패를 확인한다.
2. `document-write-page.test.tsx`에 범위 필터 적용 → `전체 조회` 클릭 → 초기화 후 요청 인자와 보기 모드 유지 검증을 추가한다.
3. 훅에 `hasActiveFilters`와 `resetFilters`를 추가하고 페이지의 필터 영역에 조건부 버튼을 연결한다.
4. 두 테스트 파일을 집중 실행한다.
5. `npm run build`를 실행한다.
6. 기존 4173 S-ERP 브라우저 세션이 사용 가능하면 375px/768px/1280px에서 버튼 표시, 레이아웃, 초기화 결과를 확인한다. 접근 불가 시 결과 문서에 제한을 기록하고 임의로 다른 포트의 서버에 접속하지 않는다.
7. 결과 문서 및 확인 가능한 스크린샷을 기록한다.

## 범위 제외

백엔드, DB, API 계약, 결재 요약 수치, 상세 패널 선택 상태, 보기 모드 전환 동작의 변경은 포함하지 않는다.
