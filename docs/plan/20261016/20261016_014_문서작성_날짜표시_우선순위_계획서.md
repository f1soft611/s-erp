# 20261016_014 문서작성 날짜 표시 우선순위 계획서

## 목표

## 변경 파일과 책임

- 생성 `frontend/src/pages/groupware/documents/write/data/documentDate.ts`
  - `submittedAt`, `updatedAt`, `createdAt` 중 첫 번째 사용 가능한 값을 선택하고 날짜 원천 라벨을 반환한다.
- 수정 `frontend/src/pages/groupware/documents/write/types/documentWrite.types.ts`
  - 화면 매핑 데이터에 선택 날짜 원천 라벨을 선택적으로 추가한다.
- 수정 `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`
  - 리스트/피드/우측 알림 목록을 같은 selector로 매핑한다. 날짜 포맷은 현재 규칙을 유지한다.
- 수정 `frontend/src/pages/groupware/documents/write/components/ApprovalNoticePanel.tsx`
  - 선택된 날짜와 실제 원천(`상신일`, `수정일`, `작성일`) 라벨을 표시한다.
- 수정 `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`
  - 피드, 상세 작성자 메타, 결재선 기안자 메타에서 기존 상세 응답 필드로 같은 날짜를 선택한다.
- 생성 `frontend/tests/document-date.test.ts`
  - 우선순위와 빈 값의 fallback을 selector 단위로 검증한다.
- 수정 `frontend/tests/use-document-write-page.test.tsx`
  - 리스트/알림 데이터 매핑의 날짜 및 원천 라벨을 검증한다.
- 수정 `frontend/tests/document-write-page.test.tsx`
  - 실제 리스트, 피드, 상세 패널, 결재선 메타, 알림 패널의 표시를 회귀 검증한다.
- 생성 `docs/result/20261016/document-write-display-date/result.md` 및 `screenshots/`
  - 실행 결과와 375px/768px/1280px 브라우저 캡처를 기록한다.

## 구현 및 검증 순서

1. 상세 사양서에서 날짜 원천, 빈 값, 각 UI 표시 규칙을 확정한다.
2. selector 단위 테스트와 hook 매핑 테스트를 먼저 추가하고 현재 구현에서 실패하는지 확인한다.
3. selector/type/mapping을 구현하고 unit 및 hook 테스트를 통과시킨다.
4. 상세 컴포넌트 통합 테스트를 추가해 먼저 실패시킨 뒤 피드와 상세 메타에서 selector를 사용한다.
5. 집중 테스트를 다시 실행하고 `npm run build`를 실행한다.
6. 기존 S-ERP 브라우저 페이지를 375px, 768px, 1280px에서 확인하고 결과 문서/스크린샷을 남긴다.

## 검증 기준

- 자동 테스트는 all-present, `submittedAt` 누락/빈 값, `updatedAt` 누락, 모든 날짜 부재를 포함한다.
- 날짜가 있으면 모든 표시 지점에서 같은 값을 사용하며, 알림 패널은 해당 원천을 라벨링한다.
- 프런트엔드 집중 테스트와 production build가 통과한다.
- 화면 너비별 확인이 불가한 경우 원인과 미확인 항목을 결과 문서에 명시한다.

## 작업 상태 및 주의사항

- 구현 전 기준 실행에서 `use-document-write-page.test.tsx` 5개는 통과했다. `document-write-page.test.tsx`는 95개 중 22개가 기존 미커밋 상태에서 실패했다. 해당 실패는 날짜 표시 수정 전 결과이며 결재 처리 assertion 및 작성기 관련 timeout이 포함되어 있다. 날짜 표시 관련 신규 실패와 구분하여 결과에 기록한다.
- `DocumentApprovalDetailFeed.tsx`, `document-write-page.test.tsx` 및 다른 파일에 기존 미커밋 변경이 있으므로 해당 변경을 덮어쓰거나 정리하지 않는다.
- 백엔드/API/DB 변경은 없다.
