# 반려·보완 사유 및 보완요청 도장 표시 계획서

## 목표와 범위

[작업지시서](../../directions/20261016/20261016_014_보완요청_도장_사유표시_작업지시서.md)를 기준으로 프론트엔드 표시만 변경한다.

1. `documentPresentation.ts`에 반려/보완의 알려진 처리 문구 뒤 첫 ` 사유: `만 `\n사유: `로 바꾸는 함수를 추가한다. 이미 개행된 내용 및 사유 본문의 동일 문구는 그대로 둔다.
2. `document-presentation.test.ts`에 기존/개행된 메시지, 여러 줄, 사유 안 `사유:`, 승인/일반 이벤트 비변경 테스트를 먼저 추가한다.
3. `document-write-page.test.tsx`의 기존 반려 팝오버 검증을 보완 상태까지 확장한다. 보완 도장 두 줄, 빈 보완 사유 미표시, 승인 의견 유지 및 팝오버 원문을 검증한다.
4. 테스트 실패를 확인한다.
5. `DocumentApprovalDetailFeed.tsx`에서 시스템 댓글 변환 시 포맷 함수를 사용한다. 반려 팝오버 상태에 제목을 추가하여 보완과 공유한다. `RETURNED` 도장 글자만 명시적인 개행과 가운데 정렬을 적용한다.
6. 집중 테스트, 기존 사유 입력 회귀, build를 실행한다.
7. 격리된 fixture로 375/768/1280px에서 기존 메시지 개행, 보완 도장과 아이콘/팝오버를 확인하고 `docs/result/20261016/approval-revision-presentation/`에 화면과 결과를 기록한다.

백엔드, DB, 공통 댓글 컴포넌트 및 상태 전이는 변경하지 않는다.
