# 20261016_010 전자결재 문서현황 페이지 추가 계획서

## 목표

기존 전자결재 문서목록 API와 F1-Grid의 원격 데이터 소스를 연결해 문서번호·제목·유형·상태·결재신청일·기안자/부서·결재 참여자 기준으로 과거문서를 검색한다. 화면은 기안양식관리의 검색영역 및 F1-Grid 구성 패턴을 따른다.

## 설계

- 현재 `/groupware/doc/read` 메뉴(`currentPageKey === 'documents'`)의 일반 요약 화면을 문서현황 전용 페이지로 교체한다.
- `F1GridColumn.search`와 `toPageSearchFields(columns)`를 사용해 상세검색 UI를 생성한다. `PageSearchArea`의 날짜 값은 `{ from, to }`를 사용하며 `submittedAt`에 최초 최근 1개월을 적용한다.
- 문서목록 조회는 인증 사용자/tenant 범위와 상세검색 조건을 서버에서 적용한다. F1-Grid `dataSource`의 `offset`, `limit`, 정렬을 목록 API 조회 계약으로 연결하고 전체 건수를 반환한다.
- 선택 행의 상세정보는 기존 문서 상세 조회 API로 가져와 읽기 전용 패널에 표시한다. 목록 조회에서는 문서 본문 전체를 적재하지 않는다.
- 스키마 변경 없이 기존 결재 기본/결재선 테이블의 컬럼을 활용한다. DB 변경 필요성이 구현 중 발견되면 본 계획의 범위를 중단하고 날짜별 SQL 및 롤백 절차를 추가한다.

## 파일 및 책임 범위

### 프런트엔드

- `frontend/src/pages/dashboard/components/DashboardContent.tsx`: 문서 메뉴에 문서현황 페이지 연결
- `frontend/src/pages/groupware/documents/status/DocumentStatusPage.tsx`: 페이지 조립, 검색 상태, 조회 오류/로딩/빈 상태 및 상세 패널 제어
- `frontend/src/pages/groupware/documents/status/components/DocumentStatusGrid.tsx`: 읽기 전용 F1-Grid와 컬럼 정의
- `frontend/src/pages/groupware/documents/status/services/documentStatus.service.ts`: 목록 조건/정렬/offset 조회 및 응답 검증
- `frontend/src/pages/groupware/documents/status/types/documentStatus.types.ts`: 검색조건, 목록 행, 원격 조회 응답 타입
- 관련 테스트: 검색조건 매핑, API 쿼리/응답, 화면 검색/행 선택/오류 상태
- `frontend/src/pages/f1-grid-docs/F1-GRID.md`: 기존 검색 메타데이터를 사용하는 업무 페이지 사례와 검색 데이터 흐름을 문서화

### 백엔드

- `DocumentApprovalApiController`: 목록 검색 및 원격 조회 파라미터 검증/응답 연결
- `DocumentApprovalService` / `DocumentApprovalServiceImpl`: 사용자·tenant 범위를 유지하며 검색 조건과 정렬/offset을 DAO로 전달
- `DocumentApprovalDAO` 및 `DocumentApproval_SQL_postgresql.xml`: 조건별 목록 및 전체 건수 조회, 결재선 참여자 검색/표시 데이터 결합
- `DocumentApprovalListItemVO` 또는 전용 목록 응답 모델: 목록 컬럼에 필요한 기안부서, 참여자 요약, 결재 진행 표시 값 제공
- 관련 테스트: 서비스 필터 전달, Mapper 조건 및 정렬/페이지 경계, 접근 범위 회귀 검증

## 실행 순서

1. 기존 API, Mapper, 상세패널 호출 조건 및 F1-Grid 원격 데이터 소스의 화면 연동 방식을 다시 확인한다. DB MCP의 읽기 전용 테이블 메타데이터를 기준으로 테이블/컬럼 계약을 검증한다.
2. API 검색 계약에 대한 백엔드 테스트를 먼저 작성한다. 현재 목록 검색/전체 건수 조회가 없는 동작을 고정하고 사용자/tenant 범위가 유지되는지 확인한다.
3. 목록 API 및 Mapper에 검색, 정렬, offset/limit, 전체 건수 반환을 구현한다. 응답은 기존 `resultList` 호환을 고려해 문서현황 화면과 문서작성 화면에 대한 API 영향을 점검한다.
4. 프런트엔드 문서현황 목록 서비스와 F1-Grid `dataSource`를 연결한다. F1Grid 검색값과 정렬/페이지 상태가 같은 API 조회에 반영되게 한다.
5. 페이지에 컬럼·상세검색 메타데이터, 최근 1개월 기본값, 읽기 전용 상세 패널, 명시적 오류/로딩/빈 상태를 적용한다.
6. 자동 테스트, 프런트엔드 빌드, 실제 브라우저 반응형 확인을 수행하고 F1-Grid 문서/결과 보고서/스크린샷을 작성한다.

## 검증 계획

- 백엔드: 전자결재 컨트롤러/서비스/매퍼 테스트를 대상으로 필터 매핑, 날짜 경계, 정렬 허용 목록, 전체 건수, tenant/사용자 범위를 확인한다.
- 프런트엔드: 문서현황 페이지 및 API 서비스 관련 Vitest로 최근 1개월 기본값, 상세검색 값, 원격 로드, 행 상세 열기, 오류 및 빈 상태를 확인한다.
- 빌드: `frontend`에서 `npm run build`.
- 브라우저: 기존 프로젝트 규칙에 따라 `http://127.0.0.1:4173`에서 375px, 768px, 1280px의 검색 영역 줄바꿈, 상세검색 패널, 그리드 내부 가로 스크롤, 상세 패널을 확인한다.
- 결과 기록: 원인/변경/검증, DB MCP 메타데이터 조회 범위, 미확인 사항을 결과 문서에 기록하고 테스트 스크린샷을 보관한다. DB 행 데이터는 기록하지 않는다.

## 승인된 기준값

- 기본 scope: 현재 사용자가 기안자 또는 결재선 참여자인 `ALL`
- 기본 상태: 전체 상태
- 기본 날짜: `submittedAt`(결재신청일) 최근 1개월
- 별도 본문 기안일: 이번 범위 제외
- 편집/결재 액션: 없음
