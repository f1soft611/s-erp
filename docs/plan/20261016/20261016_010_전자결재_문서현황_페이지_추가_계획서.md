# 전자결재 문서현황 페이지 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` or `superpowers:executing-plans` to implement this plan task-by-task. Track each step with a checkbox.

**Goal:** `/groupware/doc/read`에 F1-Grid 기반의 과거 전자결재 문서 검색과 기존 상세 패널의 권한별 문서 업무 기능을 제공한다.

**Architecture:** 기존 문서 메뉴의 일반 요약 화면을 문서현황 페이지로 교체한다. F1-Grid 컬럼의 `search` 메타데이터로 `PageSearchArea` 상세검색을 만들고, 검색/정렬/원격 범위는 전자결재 목록 API에서 서버 처리한다. 기존 사용자·tenant 범위를 보존한다. 선택 문서는 문서작성 페이지의 `DocumentApprovalDetailFeed` 및 `PostDetailPanel`을 우측 오버레이로 재사용하고, 기존 권한·문서 상태 조건에 따른 상세, 댓글, 첨부, 결재/수정/취소 및 작성 다이얼로그 흐름을 유지한다.

**Tech Stack:** React, TypeScript, MUI, F1-Grid `F1GridDataSource`, Spring Boot/eGovFrame, MyBatis, PostgreSQL, Vitest, JUnit 5.

## API 계약

문서현황은 `/api/v1/groupware/approvals/documents`에 검색조건과 F1-Grid 원격 조회값을 추가해 호출한다.

```text
scope=ALL
keyword
eabusNo
title
documentType
documentStatus
submittedAtFrom / submittedAtTo
drafterName
drafterDepartmentName
participantName
updatedAtFrom / updatedAtTo
offset / limit
sortField / sortDirection
```

응답 페이지에는 기존 `resultList`와 `totalRowCount`를 제공한다. 검색조건이 없는 기존 문서작성 화면의 호출은 현재 `resultList` 동작을 유지하고, `includeDetails=true` 피드 응답은 변경하지 않는다. `offset`은 0 이상, `limit`은 1~200으로 검증한다. 허용 정렬 필드는 `eabusNo`, `title`, `documentType`, `documentStatus`, `submittedAt`, `drafterName`, `drafterDepartmentName`, `participantName`, `approvalProgress`, `updatedAt`로 제한하고, 입력 문자열을 SQL 식별자에 직접 삽입하지 않는다. API의 `drafterName` 검색값은 내부 DAO 파라미터 `drafterNameFilter`로 분리해 기존 사용자 식별 파라미터와 충돌하지 않게 한다.
