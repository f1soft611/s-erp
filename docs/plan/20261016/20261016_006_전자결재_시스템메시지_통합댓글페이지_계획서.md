# 전자결재 시스템 메시지 통합 댓글 페이지 계획서

> 상세 구현 단계는 [Superpowers 구현 계획](../../superpowers/plans/2026-10-16-document-approval-system-messages-pagination.md)을 따른다.

## 목표

문서작성 화면의 사용자 댓글과 시스템 메시지를 최신순 통합 페이지로 바꿔 기본 표시량, 이전 페이지, 총 건수 및 남은 건수가 일관되게 동작하도록 한다.

## 구현 방향

- 최상위 USER 댓글 스레드와 SYSTEM 메시지를 각각 페이지 항목 하나로 취급한다.
- 삭제된 루트라도 살아있는 답글이 있으면 표시되는 스레드 하나로 세고, 완전히 삭제된 스레드는 제외한다.
- 초기 페이지는 최신 항목 3개, 이전 페이지는 최대 20개를 요청하며 댓글 답글은 부모 스레드에 포함한다.
- 현재 common comment 저장소를 재사용하고, approval 전용 응답 DTO로 시스템 메시지 컬렉션과 통합 cursor/count를 제공한다.
- DB 스키마, 공지사항 댓글, 댓글 작성·수정·삭제 권한은 변경하지 않는다.

## 작업 순서 및 체크포인트

1. 승인된 설계와 작업지시서를 기준으로 상세 사양서를 작성하고 DB MCP 메타데이터를 확인한다.
2. 백엔드 서비스/Mapper/API 테스트에서 mixed page, ID cursor, root count, 답글 유지 조건을 먼저 고정한다.
3. 백엔드 페이지 조회 및 feed/detail 응답을 통합 항목 기준으로 수정한다.
4. 프런트엔드 타입/API 응답 검증 및 상세 피드의 mixed page 상태/건수 계산을 수정한다.
5. 관련 백엔드/프런트엔드 테스트와 프런트엔드 빌드를 실행한다.
6. 375px/768px/1280px 브라우저 확인 및 스크린샷, 결과 보고서를 작성한다.

## 검증 기준

- 초기 3개와 이전 페이지 최대 20개가 사용자 댓글 루트와 시스템 메시지를 함께 센다.
- cursor와 남은 건수는 시스템 메시지를 포함하고 답글은 별도 항목으로 세지 않는다.
- 기존 USER 댓글 스레드, 첨부, 조작, 권한 및 에러 동작이 유지된다.
- DB MCP 메타데이터 확인 결과 또는 미확인 사유와 대체 근거를 결과 문서에 남긴다.
