# 문서작성 타인 임시저장 조회 제외 구현 계획

## 근거 및 목표

[작업지시서](../../directions/20261016/20261016_014_문서작성_타인임시저장_조회제외_작업지시서.md)에 따라 타인 임시저장 문서를 서버 조회 단계에서 제외한다.

## 구조 및 수정 범위

- `backend/src/main/resources/egovframework/mapper/let/groupware/approval/DocumentApproval_SQL_postgresql.xml`: 기안자 또는 임시저장이 아닌 문서의 결재선 참여자 조건을 공통 SQL 조각으로 관리한다.
- `backend/src/test/java/egovframework/let/groupware/approval/domain/repository/DocumentApprovalMapperTest.java`: 목록, 페이지, 건수, 요약, 알림, 단건·배치 상세, 참여 권한의 조건과 바인딩을 검증한다.
- 프론트엔드는 피드·리스트가 같은 목록 API를 사용하므로 수정하지 않는다.

## 실행 순서

- [x] 상세 사양 작성 및 자기 검토: 본인 `DRAFT` 허용, 타인 `DRAFT` 차단, 기존 상태/참여 유형 유지.
- [x] 모든 조회 경로에서 `m.drafter_id = ? OR (m.document_status != 'DRAFT' AND EXISTS (...))`가 생성되는 테스트 추가.
- [x] `mvn -f backend\pom.xml "-Dtest=DocumentApprovalMapperTest#documentReadsAllowOwnDraftsButRequireNonDraftStatusForOtherParticipants" test` 실행: 신규 테스트의 조건 누락 실패 확인.
- [x] 공통 `documentReadAccess` 조각을 만들고 기존 조회/참여 검사에 포함.
- [x] 동일 테스트와 서비스·컨트롤러 테스트 실행:
  `mvn -f backend\pom.xml "-Dtest=DocumentApprovalMapperTest,DocumentApprovalServiceImplTest,DocumentApprovalApiControllerTest" test`
- [x] PostgreSQL MCP에서 실테이블 대신 `VALUES`로 만든 가상 문서·결재선에 동일 조건을 실행하여 본인/타인, 각 문서 상태, 타 tenant, 삭제, 비참여를 확인.
- [x] `git diff --check` 확인 및 결과 보고서 작성.

## 검증 및 배포 한계

실제 테넌트 행은 조회하지 않는다. 가상 SQL 검증은 권한 조건의 동작 검증이며 운영 화면 검증을 대신했다고 보고하지 않는다. 백엔드 반영에는 실행 중 서버의 리소스 재로딩 또는 재시작이 필요하다. DB 스키마 변경은 없어 마이그레이션이 필요하지 않다.
