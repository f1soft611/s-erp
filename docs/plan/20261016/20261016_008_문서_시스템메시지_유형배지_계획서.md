# 문서 시스템 메시지 유형 배지 구현 계획

**Goal:** 승인된 다섯 시스템 이벤트를 기존 상태 색상의 명칭 배지로 표시한다.

**Architecture:** 문서 표시 데이터에서 이벤트를 기존 상태 presentation에 매핑한다. 공통 댓글 모델에는 선택적 배지 presentation만 전달하여 공통 컴포넌트가 문서 이벤트 코드를 알지 않도록 한다.

**Tech Stack:** React, TypeScript, MUI Chip, Vitest, Testing Library, Playwright.

## 1. 실패 테스트

- [ ] `frontend/tests/document-presentation.test.ts`에서 다섯 이벤트의 명칭/색상/variant 및 미지원 이벤트의 `undefined`를 검증한다.
- [ ] `frontend/tests/feed-components.test.tsx`에서 선택적 `systemEventBadge`를 전달하면 아이콘 대신 Chip이 보이고 조작 버튼은 없음을 검증한다. 배지가 없는 시스템 메시지의 기존 아이콘 테스트는 유지한다.
- [ ] `frontend/tests/document-write-page.test.tsx`에서 `SUBMITTED` 상세 메시지의 기존 아이콘 기대값을 `결재신청` 배지 및 info 색상 기대값으로 변경한다.
- [ ] `npm run test -- tests/document-presentation.test.ts tests/feed-components.test.tsx tests/document-write-page.test.tsx`로 새 테스트 실패를 확인한다.

## 2. 표시 계층 구현

- [ ] `frontend/src/pages/groupware/documents/write/data/documentPresentation.ts`에 `getApprovalSystemEventPresentation(eventType: string)`을 추가한다. 다섯 이벤트만 기존 상태 정의를 재사용하고 `SUBMITTED`의 표시 명칭만 결재신청으로 덮어쓴다.
- [ ] `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`의 시스템 메시지 변환에서 `systemEventBadge`를 전달한다.
- [ ] `frontend/src/shared/components/feed/TiptapCommentThread.tsx`의 `FeedCommentItem`에 선택적 배지 속성을 추가한다. 타입은 MUI `ChipProps`의 color/variant를 재사용한다.
- [ ] 시스템 메시지에 배지 정보가 있으면 작은 Chip을 표시하고, 없으면 기존 아이콘을 표시한다. 헤더는 좁은 화면에서 줄바꿈하여 본문과 겹치지 않게 한다.
