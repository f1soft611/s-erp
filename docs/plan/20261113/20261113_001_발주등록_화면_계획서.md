| 단계 | 내용 | 산출물 |
| --- | --- | --- |
| 1 | DB 스크립트 | `20261113_002` 발주 테이블 생성·롤백·변경이력, `20261113_003` 메뉴 등록·롤백·변경이력, `db-schema.md` |

## 의존·재사용

- 번호 발급은 구매요청확정과 같은 `IdSequenceService` 패턴을 쓴다(키는 발주 전용). 형식 `PO-YYYYMMDD-NNNN`.
- 단가 조회는 기존 `GET /api/v1/materials/purchase-request-confirms/unit-price`를 재사용한다.
- 직접 발주의 MR/MC 자동 생성은 구매요청·확정 서비스의 저장 규칙(번호 `MR`/`MC`, 상태 계산)을 따른다. 중복 구현을 피하려고 기존 서비스 메서드·매퍼를 최대한 재사용하고, 재사용이 어려운 부분만 발주 전용 매퍼로 둔다.
- 화면 패턴은 `frontend/src/pages/materials/request/confirm`(그리드, 선택 창, 서비스 계층)을 따른다.
- 부가세 반올림은 영업 수주의 `roundSalesOrderAmount`를 읽고 같은 규칙으로 구현한다.

## 위험과 대응

- **동시 발주**: 같은 확정 행을 두 사람이 동시에 발주하면 잔량을 넘길 수 있다. 저장 시 대상 확정 행을 `FOR UPDATE`로 잠그고 잔량을 다시 계산한다. 초과분은 경고 대상이므로 차단하지 않지만 응답에 초과 여부를 담는다.
- **확정 취소와의 충돌**: 발주 행이 있는 확정은 취소할 수 없게 막는다(4단계).
- **직접 발주 자동 문서**: MR/MC 생성이 실패하면 발주도 롤백한다(단일 트랜잭션).
- **재고 연결 미정**: 재고량은 필드만 확보한다.

## 검증 계획

- 서비스 단위 테스트: 잔량 계산, 같은 구매처 검증, 부가세 계산 4가지 조합, 직접 발주 자동 생성, 출처 혼합 거부.
- 매퍼/스키마 정적 테스트: 기존 `20261112` 패턴.
- 프론트 테스트: 구매처 잠금, 부가세 컨트롤 비활성, 확정과 다름 경고, 행 빼기.
- 백엔드 `mvn test`, 프론트 `npm run test`·`npm run build`, JDK 8 `--release 8` 컴파일.
