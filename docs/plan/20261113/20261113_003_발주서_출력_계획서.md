## 재사용·충돌 방지
- 영업 `StatementPrint`의 구조(미리보기 + 포털 숨김 영역 + `@media print`)와 한글 금액 로직을 그대로 따르되, CSS 클래스는 `order-print-*`로 분리해 영업 인쇄 CSS와 충돌하지 않게 한다.
- 영업 파일은 수정하지 않는다. 공통 함수 도입 후 영업 담당자가 import만 바꾸면 되도록 같은 입출력(숫자 → `…원 정`)을 유지한다.

## 위험과 대응
- **스냅샷 컬럼 수**: 약 25개 추가. 서버가 한 문장에서 복사하므로 화면 입력은 늘지 않는다. 이미지 컬럼(직인·로고)은 `text`다.
- **기존 발주**: 스냅샷이 없으므로 출력 시 현재 정보로 대체한다(영업과 같은 방식). 별도 이전 SQL은 만들지 않는다.
- **출력 기록 시점**: 브라우저는 실제 인쇄 여부를 알 수 없어 `인쇄` 버튼 클릭 기준으로 기록한다. 기록 실패가 인쇄를 막지 않도록 인쇄를 먼저 호출하고 기록 오류는 화면에 안내한다.
- **취소된 발주**: 화면에서 출력을 숨기고 서버도 409로 막는다.

## 검증 계획
- 서비스: 취소 발주 출력·기록 거부, 존재하지 않는 발주 404, 인증, 출력 기록 값.
- 매퍼·SQL: 스냅샷 복사 컬럼 전부, `COALESCE` 대체, 출력 기록이 출력 컬럼만 바꾸는지.
- 프론트: 한글 금액, 출력물 구성(행별 납기일, VAT 표기, 합계), 페이지 분할, 메뉴 노출 규칙, 인쇄 시 출력 기록, 변경 중 비활성.
- 브라우저: 미리보기 375/768/1280px, 24줄 초과 다중 페이지.
