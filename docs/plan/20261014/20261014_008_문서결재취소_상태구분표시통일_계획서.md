# 20261014_008 문서 결재 취소 및 상태·구분 표시 통일 계획서

## 목표

기안자 상신 취소와 결재자 본인 승인 취소를 기존 전자결재 흐름에 안전하게 추가하고, 문서 리스트·피드·상세의 상태/구분 배지 및 색상을 일관되게 표시한다. 긴 본문이 접힐 때 결재선도 함께 숨긴다.

## 파일 변경 지도

### 백엔드 결재 취소

- 수정 `backend/src/main/java/egovframework/let/groupware/approval/controller/DocumentApprovalApiController.java`: 인증 사용자 기반 상신 취소/승인 취소 POST 경로를 기존 `ResultVO` envelope로 노출한다.
- 수정 `backend/src/main/java/egovframework/let/groupware/approval/service/DocumentApprovalService.java`, `service/impl/DocumentApprovalServiceImpl.java`: 잠금, 사용자/상태 검증, 결재선/문서 갱신, 시스템 이력 기록을 개별 트랜잭션 메서드로 구현한다.
- 수정 `backend/src/main/java/egovframework/let/groupware/approval/domain/repository/DocumentApprovalDAO.java`, `backend/src/main/resources/egovframework/mapper/let/groupware/approval/DocumentApproval_SQL_postgresql.xml`: 기안 취소 복구, 1단계 자동 승인 기안선을 제외한 사용자 승인선 조회/초기화, 뒤 단계 처리 여부/초기화, 1단계 자동 승인 기안선을 제외한 잔여 처리 건수 조회를 추가한다. 기존 `updateDocumentApprovalStatus`를 재사용한다.
- 수정 `backend/src/test/java/egovframework/let/groupware/approval/service/impl/DocumentApprovalServiceImplTest.java`, `controller/DocumentApprovalApiControllerTest.java`, `domain/repository/DocumentApprovalMapperTest.java`: 권한, 상태 전이, 병렬 단계, 뒤 단계 경합, 매핑 SQL 및 응답을 검증한다.

### DB 이력

- `docs/database/20261014/`와 `backend/DATABASE/20261014/`에 같은 내용의 `20261014_003_add_approval_cancellation_events.sql`, 변경 이력 `.md`, 롤백 `.sql`을 생성한다.
- `docs/database/db-schema.md`에서 `tb_common_comment.event_type` 제약의 허용 이벤트를 갱신한다.
- 실 DB 제약에서 확인한 기존 이벤트 `APPROVED`, `REJECTED`, `RETURNED`, `DRAFT_SAVED`, `SUBMITTED`, `RESUBMITTED`, `COMPLETED`, `DELETED`와 `USER`/`SYSTEM` 조건을 보존한다. 신규 컬럼 및 테이블은 추가하지 않는다.

### 프론트엔드 표시와 동작

- 생성 `frontend/src/pages/groupware/documents/write/data/documentPresentation.ts`: 상태/문서구분 라벨과 색상 메타데이터 및 조회 함수를 한 곳에 정의한다.
- 수정 `frontend/src/pages/groupware/documents/write/types/documentWrite.types.ts`, `data/documentWriteData.ts`: 화면 표시 상태 타입과 샘플 상태를 공통 표시 규칙에 맞춘다.
- 수정 `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`: 공통 메타데이터로 목록/피드 항목을 생성한다. 기존 피드 quiet refresh 동작을 보존한다.
- 수정 `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`, `components/DocumentFeedItem.tsx`: 피드 진입 시 현재 사원 ID를 한 번 조회해 각 피드 카드에 전달하고, 조회 실패 시 페이지 단위 오류와 재시도를 제공한다. 카드별 프로필 중복 조회를 만들지 않는다.
- 수정 `frontend/src/shared/components/view-mode/commonViewTypes.ts`, `ListView.tsx`: 선택적 구분 배지 색상, 상태 variant 및 배지 반경 입력을 추가하고 다른 리스트 사용자의 기본 동작은 유지한다.
- 수정 `frontend/src/pages/groupware/documents/write/services/documentApproval.service.ts`: 두 취소 endpoint의 ID 및 응답 상태를 검증한다.
- 수정 `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`: 전달받은 피드 사용자 ID로 결재 권한을 계산하고, 공통 상태/구분 배지, 피드·상세 결재 툴바와 피드 사유 대화상자, DRAFT 전용 삭제, 상세 전용 취소 확인/오류 처리, 본문 확장과 결재선 표시 연동을 적용한다.
- 수정 `frontend/tests/document-write-page.test.tsx`, `frontend/tests/common-view-mode.test.tsx`, `frontend/tests/document-presentation.test.ts`: 표시/색상/variant/반경, 결재 툴바와 처리 요청, 삭제 메뉴, 취소 버튼/오류/갱신, 본문/결재선 접기 회귀를 검증한다.

## 구현 순서

1. 승인 설계에 따라 본 작업지시서, 계획서, 상세사양서를 작성하고 상태/취소 정책 및 파일 범위를 일치시킨다.
2. 백엔드 서비스/컨트롤러 취소 테스트와 MyBatis 매핑 계약 테스트를 먼저 작성한다. 집중 테스트로 미구현 취소 동작의 실패를 확인한다.
3. 두 취소 endpoint 및 서비스 트랜잭션을 구현한다. 기존 문서 행 `FOR UPDATE` 잠금을 재사용하고, 액터·테넌트·상태·결재선·뒤 단계의 처리 여부를 서버에서 확인한다.
4. 사용자 승인선 및 결재선 초기화 MyBatis statement를 추가한다. 조건부 변경 행 수와 이력 추가가 실패하면 전체 트랜잭션을 롤백한다.
5. 취소 이벤트 제약의 전진/변경이력/롤백 SQL을 작성하고 docs/backend 양쪽 파일이 바이트 단위로 같은지 확인한다. 읽기 전용 MCP에서 DDL을 실행하지 않는다.
6. 프론트엔드 표시/취소 테스트를 먼저 추가하고 실패를 확인한 뒤 공통 표시 메타데이터, 취소 service, 상세 UI와 접기 동작을 구현한다.
7. 백엔드 집중 테스트, 프론트엔드 집중 테스트 및 production build를 실행한다. 기존 피드 quiet refresh 회귀 테스트를 보존한다.
8. 기존 개발 서버를 재사용할 수 있으면 `/groupware/doc/write`를 375px, 768px, 1280px에서 확인한다. 배지 가독성, overflow, 상세 취소 버튼, 접기/더보기, 리스트/피드 전환을 점검한다.
9. 테스트/build 결과, 실제 확인 범위, DB MCP의 제약 근거, 마이그레이션 파일, 미적용 상태를 결과 보고서에 기록하고 비민감정보 스크린샷을 저장한다.
10. UI 보완은 [별도 구현 계획](../../superpowers/plans/2026-10-14-document-approval-ui-refinement.md)에 따라 실패 테스트부터 추가한다. 피드/상세 툴바 순서와 액션, DRAFT 삭제 제한, 공통 배지 스타일을 확인하고 결과 문서와 스크린샷을 갱신한다.

## 완료 기준

- 취소 허용/거부 경계와 롤백 조건이 자동 테스트로 검증되고 기존 승인/반려/보완요청/삭제 흐름이 보존된다.
- 승인된 상태·구분 라벨/색상 규칙이 리스트·피드·상세에 적용되고 상세 문서구분이 표시된다.
- 승인된 배지 반경/variant, 피드·상세 결재 동작/사유 대화상자, 툴바 배치/버튼 색상, 삭제 메뉴 제한 및 결재선 진행 색상이 일관되게 적용된다.
- 긴 본문의 확장 상태와 결재선 표시가 동기화되고 짧은 본문에서는 결재선이 계속 보인다.
- 집중 테스트/build가 통과하며, 실제 수행 여부를 구분해 결과 보고서와 지정 뷰포트 증거를 기록한다.
