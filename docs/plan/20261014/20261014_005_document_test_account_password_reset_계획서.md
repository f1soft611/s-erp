# 20261014_005 문서작성 테스트 계정 비밀번호 초기화 계획서

## 목표

문서작성 사용자 선택기 테스트 계정 10개의 비밀번호와 잠금/실패 상태만 초기화하는, 인증정보를 포함하지 않는 SQL 스크립트를 준비한다.

## 범위 및 안전

- 테넌트 `T1358606250`의 `doc-write-test-user-01`~`doc-write-test-user-10`만 대상으로 한다.
- 해시 10개는 실행 전에 같은 PostgreSQL 세션에 설정되어야 하며, SQL은 값의 존재와 형식을 먼저 검증한다.
- 대상 테넌트와 활성 계정이 각각 유일하고, 지정 계정이 정확히 10개가 아니면 중단한다.
- 한 트랜잭션에서 `password_hash`, `password_changed_at`, `login_attempt_count`, `locked_at`, `updated_at`만 변경한다. 계정 활성 상태, 프로필, 역할 및 권한은 유지한다.
- 데이터 스크립트는 문서 및 백엔드 스키마 이력 폴더에 동일하게 저장한다. 기존 스키마는 변경하지 않는다.
- 비밀번호와 해시는 파일/문서/테스트 출력에 기록하지 않는다. 이전 해시는 백업하지 않으므로 성공 후 역복구용 롤백 SQL은 제공하지 않는다.
- 작업자는 SQL을 직접 실행할 수 있으나, 본 작업에서 에이전트는 DB 쓰기나 로그인 검증을 수행하지 않는다.

## 구현 단계

1. 승인된 입력, 대상 계정, 갱신 컬럼 및 실패 조건을 [상세 사양서](../../spec/20261014/20261014_005_document_test_account_password_reset_상세사양서.md)에 정의한다.
2. 지정된 테스트 계정 10개와 동명 세션 설정의 일치, 선행 검증, 행 잠금, 테넌트 제한, 허용 컬럼 및 비밀값 비포함을 검사하는 Node 기본 테스트를 먼저 작성하고 실패를 확인한다.
3. 트랜잭션 및 예외 검증이 포함된 SQL을 작성하고 테스트를 통과시킨다.
4. 변경 이력을 작성한 후 SQL 및 이력의 동일 복사본을 `docs/database/20261014`와 `backend/DATABASE/20261014`에 둔다.
5. 결과 문서에 정적 검증만 수행했으며 DB 미적용/로그인 미검증임을 기록한다.

## 검증 계획

- `node --test tools/tests/test_document_test_account_password_reset.cjs`
- SQL 세션 해시 매핑 10개, 포맷/테넌트/활성 계정 사전 검증, 대상 행 잠금 및 업데이트 컬럼 범위를 정적으로 검사한다.
- docs/backend 데이터 스크립트 및 변경 이력 쌍의 SHA-256을 비교한다.
- 새 작업 파일의 후행 공백을 검사한다.
- 읽기 전용 MCP는 조회에만 사용한다. SQL 적용 및 실제 로그인 시도는 수행하지 않는다.

## 롤백 정책

초기화 후 이전 비밀번호 해시를 복원하지 않는다. 이전 해시를 저장하는 것은 인증정보 보관과 동등하므로 안전 기준상 제외한다. 이후 다른 비밀번호가 필요하면 새 해시를 준비해 초기화 스크립트를 다시 실행한다.
