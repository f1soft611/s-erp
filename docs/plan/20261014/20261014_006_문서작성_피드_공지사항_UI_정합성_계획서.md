# 20261014_006 문서작성 피드 공지사항 UI 정합성 계획서

## 목표

문서작성의 피드형을 공지사항과 같은 공통 카드 및 인라인 본문 펼침으로 맞추고, 상세 수정 모달의 종료 후 목록/상세 갱신을 조용히 처리한다.

## 파일 변경 지도

### 문서 피드 본문

- 수정 `frontend/src/pages/groupware/documents/write/components/DocumentFeedItem.tsx`: 공통 `FeedCard`와 `FeedBodyContent`로 카드 chrome 및 인라인 본문 UI를 조립한다. 카드 선택은 우측 상세 열기 콜백을 호출하지 않는다.
- 수정 `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`: 피드 상태/본문 데이터 콜백을 카드에 공급한다. 리스트 항목의 기존 상세 열기 callback은 보존한다.
- 수정 `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`: 문서 ID별 지연 상세 조회 캐시, 로딩/오류 상태와 retry-capable expand callback을 제공한다.
- 수정 `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`: 기존 본문 이미지 DOM 변환과 인증 Blob URL 수명주기를 공통으로 재사용할 수 있게 추출된 body hook을 사용하고, 조용한 상세 refresh token을 지원한다.
- 생성 `frontend/src/pages/groupware/documents/write/hooks/useDocumentApprovalBody.ts`: 상세 본문 HTML의 인증 이미지 참조를 처리하고, embedded image Blob URL을 생성/폐기하며 펼침/접힘에 필요한 HTML·이미지·오류 상태를 반환한다.
- 수정 `frontend/tests/document-feed-item.test.tsx`: 카드가 요약/본문/상태·구분을 렌더링하고, 펼침 컨트롤을 제공하며, 패널 열기용 버튼이 없음을 검증한다.
- 수정 `frontend/tests/document-write-page.test.tsx`: lazy detail fetch, inline loading/error/retry, list-only panel opening, modal-over-detail 유지 및 quiet refresh 회귀를 검증한다.

### 조용한 데이터 갱신

- 수정 `frontend/src/pages/groupware/documents/write/hooks/useDocumentWritePage.ts`: `refresh({ quiet: true })`를 추가하고 일반 필터/범위 변경에는 기존 로딩 표시를 보존한다.
- 수정 `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`: Composer 종료 시 상세 선택을 유지하고 quiet list/summary refresh를 요청한다. 상세 컴포넌트에 갱신 신호를 전달한다.
- 수정 `frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx`: 초기 상세 로딩과 구분하여 refresh 신호에 따른 상세 재조회는 기존 내용을 유지한 채 조용히 실행한다.
- 수정 `frontend/tests/document-write-page.test.tsx`: 편집 선택 시 패널이 언마운트되지 않고 모달이 열리는지, 저장/취소 후 로딩 스켈레톤 없이 열린 패널의 최신 내용을 반영하는지 검증한다.

## 구현 순서 및 검증

1. 본문 hook과 피드 동작의 컴포넌트/페이지 테스트를 먼저 추가한다. 테스트 명령은 `cd frontend; npm run test -- tests/document-feed-item.test.tsx tests/document-write-page.test.tsx`이며 새 동작이 아직 없어 실패하는지 확인한다.
2. `useDocumentApprovalBody`를 추출해 문서 상세와 피드 카드가 같은 인증 이미지 변환·URL 정리 규칙을 사용하도록 한다. 기존 상세 이미지 테스트를 통과시킨다.
3. 문서 목록 hook에 카드별 lazy detail, 로딩, 오류와 재시도 상태를 추가한다. 피드 카드는 `FeedBodyContent`로 요약/본문을 표시하고 더보기는 API fetch 후 인라인으로 확장한다.
4. 문서작성 페이지에서 피드 카드 클릭은 상세를 열지 않도록 하고, 리스트 항목 선택은 기존처럼 상세를 연다. 기존 보기 전환/상단 고정/필터 동작을 보존한다.
5. 목록 hook의 quiet refresh와 상세 refresh token을 추가한다. Composer 종료 시 상세 패널을 유지하고 문서 목록/요약/선택 상세를 스켈레톤 없이 갱신한다.
6. 대상 테스트 명령을 재실행하고 `cd frontend; npm run build`를 실행한다.
7. 375px, 768px, 1280px에서 브라우저 확인 후 스크린샷과 실제 검증 결과를 결과 문서에 기록한다.
