## 목표

기존 API와 동작을 유지하면서 수주현황 상세 패널의 핵심 요약, 기본정보 그룹, 품목 표를 가독성 좋고 반응형으로 정돈한다.

## 구조 및 변경 파일

| 파일 | 책임 |
|---|---|
| `frontend/src/pages/sales/order/status/components/SalesOrderStatusDetailPanel.tsx` | 요약 영역, 정보 그룹, 품목 표의 시각 계층을 구성한다. 공통 패널이나 데이터 흐름은 수정하지 않는다. |
| `frontend/tests/sales-order-status-page.test.tsx` | 상세 패널 렌더링 회귀를 확인한다. 기존 권한/편집/닫기 테스트를 보존한다. |
| `docs/result/20261027/sales-order-detail-design/README.md` | 적용 범위와 검증 결과 및 스크린샷을 기록한다. |
| `docs/result/20261027/sales-order-detail-design/screenshots/` | 375px, 768px, 1280px 브라우저 캡처를 저장한다. |

문서 변경은 작업에 필요한 날짜별 계획·사양·결과에 한정한다. API, 타입, 백엔드, DB, 공통 `PostDetailPanel`은 변경하지 않는다.

## 구현 단위

### 1. 회귀 테스트 우선

`frontend/tests/sales-order-status-page.test.tsx`에 기존 통합 테스트를 확장한다. 기존 `openOrderDetailPanel()` helper와 `createOrderItem()` 샘플을 사용하고 아래 동작을 확인한다.

```tsx
it('shows the redesigned summary, grouped order information, and readable detail table', async () => {
  renderStatusPage();
  const panel = await openOrderDetailPanel();

  expect(within(panel).getByText('거래처 10')).toBeInTheDocument();
  expect(within(panel).getByText('수주 정보')).toBeInTheDocument();
  expect(within(panel).getByText('납품 정보')).toBeInTheDocument();
  expect(within(panel).getByRole('table', { name: '수주 품목 목록' })).toBeInTheDocument();
  expect(within(panel).getByText('품목 20')).toBeInTheDocument();
  expect(within(panel).getByText('M-20')).toBeInTheDocument();
});
```

추가로 품목 건수 표기와 기존 값 `Q-1`, `택배`, `본사 창고`, `긴급` 보존, 상태·더보기·닫기 흐름 유지 및 긴 텍스트/빈 값의 표시를 필요한 최소 assertion으로 검증한다. 테스트는 스타일의 픽셀 값을 검증하지 않고 정보 구조 및 기존 동작 회귀를 검증한다.

### 2. 실패 확인 및 최소 구현

1. `frontend`에서 `npm run test -- tests/sales-order-status-page.test.tsx`를 실행해 새 구조 기대가 아직 만족되지 않음을 확인한다.
2. `SalesOrderStatusDetailPanel.tsx`에서 작성자·액션 영역 아래에 요약 영역을 구성한다. 거래처, 수주일자, 납기일자, 총 합계 값은 현재 `order` 객체만 사용한다.
3. 현재 기본정보 박스를 “수주 정보”(견적번호, 배송방법)와 “납품 정보”(납품장소, 비고) 그룹으로 교체한다. 중복 필드는 요약/품목 제목으로 옮기고 공란 표시 규칙은 유지한다.
4. 품목 섹션 제목에 `order.details.length`를 표시한다. 품목명/코드를 시각적으로 구별하고 숫자 정렬, 표 헤더/행 구분을 개선한다. `Table`의 기존 접근성 이름과 모든 열을 유지한다.
5. 기존 MUI theme token만 사용한다. 데스크톱/태블릿/모바일 배치를 `sx` breakpoint로 지정하고 좁은 화면에서 표 컨테이너만 가로 스크롤하게 한다.
6. 로딩·오류·더보기·수정·닫기 동작 및 패널 이름을 변경하지 않는다.

### 3. 자동 검증

실행 위치: `frontend`

```powershell
npm run test -- tests/sales-order-status-page.test.tsx
npm run build
npm run lint -- src/pages/sales/order/status/components/SalesOrderStatusDetailPanel.tsx tests/sales-order-status-page.test.tsx
```

각 명령은 종료 코드 0이어야 한다. 새 테스트가 깨지는 경우 구현을 수정하고 대상 테스트를 다시 실행한 뒤 빌드와 lint까지 확인한다.

### 4. 실제 브라우저 및 결과물

- 기존 S-ERP 서버가 `127.0.0.1:4173`에서 응답하는지 먼저 확인한다. 없으면 `npm run dev -- --strictPort`로 시작하고 작업 후 직접 시작한 서버만 종료한다.
- 로그인된 개발 환경에서 수주현황에 표시되는 기존/합성 테스트 데이터 한 건을 열어 Chromium으로 375px, 768px, 1280px에서 확인한다. 인증 정보와 실제 민감 데이터를 결과물에 남기지 않는다.
- 요약 헤더, 그룹 정보, 표의 내부 가로 스크롤, 페이지 가로 넘침, 더보기와 닫기를 확인한다.
- 캡처는 `docs/result/20261027/sales-order-detail-design/screenshots/` 아래 영문 파일명으로 저장한다. 모바일/데스크톱 화면에서 페이지 전체 가로 넘침이 없어야 한다.
- 결과 `README.md`에 변경 파일, 테스트/build/lint 결과, 브라우저 뷰포트 검증, 확인된 제한을 기록한다.

## 완료 조건

- 승인된 사양의 모든 시각 요구와 기존 상호작용이 유지된다.
- 대상 Vitest, TypeScript/Vite build, 대상 파일 lint가 통과한다.
- 375px, 768px, 1280px 실제 브라우저 확인과 스크린샷 및 결과 문서가 있다.
- 변경 범위에 API/타입/백엔드/DB/공통 패널이 포함되지 않는다.
