## 목표 및 제외

tenant 격리 분류 목록/추가/수정 API와 관리 페이지 내 설정 다이얼로그를 완성한다. 서버 권한은 메뉴별 READ/CREATE/UPDATE를 사용하고 tenant-admin 역할을 별도로 요구하지 않는다. 데이터베이스 DDL 적용, 마스터 폼 분류 저장/검색, 기존 데이터 backfill, 공통코드 API 재사용은 제외한다.

|---|---|

## 실행 순서

1. service/controller 실패 테스트에서 tenant는 인증 객체로 전달하고 메뉴 쓰기 권한 없는 요청은 403, 권한 있는 비관리자는 허용되는지 확인한다.
2. DAO/mapper를 구현해 `tenant_id` 조건을 모든 조회/수정 경로에 포함한다.
3. controller에서 메뉴 권한을 서버에서 확인하고 service에서 생성 레벨, 상위 노드 존재/활성/최대 깊이, 입력값, 자식이 있는 노드 비활성화를 검사한다.
4. 공통 API DTO는 도메인 독립형 분류 ID/이름/레벨/parent/sort/use 필드로 매핑한다.
5. frontend service 및 다이얼로그에 로딩·오류·저장·재조회, root/child 생성, 선택 노드 수정 기능을 구현한다.
6. 두 관리 페이지에 해당 메뉴의 CREATE 또는 UPDATE 권한 조건으로 설정 버튼을 추가한다. 기존 마스터 등록/수정의 역할 제한은 변경하지 않는다.
7. Maven test, 관련 Vitest, frontend build, 375/768/1280px 브라우저 확인을 실행한다.
8. 결과 문서에 DB가 미적용이고 통합 실행을 하지 않은 사실을 기록한다.

## 위험/완화

- 대상 테이블은 DDL 초안 상태다. 요청을 처리하려면 별도 검토/승인된 migration이 먼저 적용되어야 한다.
- 동적 도메인 테이블명 선택은 서버 내부 enum에 고정하고 사용자 문자열을 SQL 식별자로 사용하지 않는다.
- 메뉴 권한은 `SystemMenuService.getMyMenuTree` 결과에서 `/co/materials`, `/co/customers` 페이지 키로 각각 확인하고, 요청 종류와 다른 메뉴 권한은 대체할 수 없다.
- 삭제와 부모 이동을 지원하지 않아 참조 보존 및 자기참조 변경 문제를 제한한다.
- 부모 비활성화는 활성 자식이 있을 경우 거부한다.
