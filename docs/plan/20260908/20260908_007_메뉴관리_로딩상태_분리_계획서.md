## 목적

메뉴 관리 페이지가 권한 관리 페이지와 같은 로딩 UX를 제공하도록 수정한다. 최초 진입과 명시적 조회에서는 F1-Tree 행 스켈레톤을 표시하고, 저장 후 재조회는 기존 행을 유지하는 조용한 로딩으로 처리한다.

## 범위

### 프론트엔드

- `MenuManagementPage.tsx`
  - 메뉴 조회 함수에 스켈레톤 표시 여부를 명시하는 옵션을 도입한다.
  - 최초 진입과 `조회` 버튼은 스켈레톤 조회로 호출한다.
  - 저장 후 `onRefresh` 재조회는 조용한 조회로 호출한다.
  - 모듈·권한 변경 및 폐기 확인 후 컨텍스트 전환은 새 데이터 컨텍스트를 여는 조회이므로 스켈레톤 조회로 유지한다.
- `MenuManagementPanel.tsx`
  - `menuGridLoading` prop을 추가한다.
  - 해당 prop을 `F1Tree loading`에 전달한다.
- 관련 메뉴 관리 테스트
  - 최초 진입 스켈레톤
  - 조회 버튼 스켈레톤
  - 저장 후 조용한 재조회
  - 저장 실패 후 상태 복구
- 결과 문서 및 데스크톱·모바일 캡처 경로 기록

### 백엔드/DB

- 변경 없음
- 기존 `fetchMenuRows(moduleId, roleId)`, 저장 API, 권한 매핑 API 계약을 그대로 사용한다.

## 설계 영향

`RoleManagementPage`의 `loadRoles({ showSkeleton })` 패턴을 메뉴 조회에 적용한다. 메뉴 페이지의 기존 `loading`은 스켈레톤 표시 상태로 유지하고, 저장 상태는 기존 `saving`으로 분리한다. 조회 요청 ID 보호와 오류 메시지 흐름은 유지하여 오래된 요청이 최신 화면을 덮지 않게 한다.

## 실행 순서

1. 승인된 사양과 기존 권한 관리 패턴을 기준으로 실패하는 메뉴 관리 로딩 테스트를 추가한다.
2. 조회 함수의 `showSkeleton` 옵션과 호출부별 값을 구현한다.
3. 패널 prop을 `F1Tree`에 연결한다.
4. 메뉴 관리 대상 테스트를 실행하고 실패 원인을 수정한다.
5. 프론트엔드 빌드를 실행한다.
6. 실제 브라우저에서 데스크톱·모바일 화면의 진입/조회/저장 로딩 상태를 확인한다.
7. 결과 문서에 검증 명령, 결과, 캡처 경로를 기록한다.

## 검증 계획

- 좁은 검증: `npm run test -- tests/menu-management-*.test.tsx` 또는 변경 테스트 파일 지정
- 빌드: `npm run build`
- UI: 기존 캡처 스크립트/Playwright를 활용해 최소 1280px, 375px 화면 확인
- 백엔드: 해당 없음

## 완료 조건

- 최초 진입과 조회 중 `grid-loading-row-skeleton`이 표시된다.
- 스켈레톤 중 그리드 헤더와 레이아웃이 유지된다.
- 저장 후 재조회에서는 스켈레톤이 표시되지 않는다.
- 저장 실패 시 오류와 버튼 상태가 정상 복구된다.
- 관련 테스트와 빌드가 통과한다.
- 결과 문서와 UI 검증 경로가 남는다.
