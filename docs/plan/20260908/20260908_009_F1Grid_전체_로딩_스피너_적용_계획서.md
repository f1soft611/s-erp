# 계획서

## 제목

F1-Grid 전체 영역 로딩 스피너 적용

## 관련 작업지시서

[20260908*009_F1Grid*전체*로딩*스피너*적용*작업지시서.md](../../directions/20260908/20260908_009_F1Grid_전체_로딩_스피너_적용_작업지시서.md)

## 목적

모든 `F1Grid` 및 `F1Tree` 사용 페이지에 공통으로 적용되는 전체 그리드 로딩 스피너를 제공한다. 기존 `GridLoadingSkeleton` 렌더링과 테스트 식별자는 보존하고, 공통 컴포넌트 변경만으로 메뉴관리·모듈관리·권한관리·F1-Grid 테스트·문서 플레이그라운드에 동일한 로딩 UX를 적용한다.

## 범위

### 프론트엔드

- `frontend/src/shared/components/f1-grid/core/F1Grid.tsx`
  - 최상위 그리드 컨테이너의 로딩 오버레이와 새로고침 스피너를 추가한다.
  - 기존 `loading` prop, 헤더, 본문 스켈레톤 렌더링을 유지한다.
  - `aria-busy`와 입력 차단을 공통 로딩 상태에 연결한다.
- `frontend/src/shared/components/f1-grid/tree/F1Tree.tsx`
  - 별도 로딩 UI를 중복 구현하지 않고 기존 `F1Grid` 위임 구조가 공통 오버레이를 사용하도록 확인한다.
- `frontend/tests/f1-grid.test.tsx`
  - 공통 오버레이·스피너·스켈레톤 보존·로딩 종료 복구 회귀 테스트를 추가한다.
- `frontend/tests/role-management-notification.test.tsx`
  - 권한관리에서 사용하는 공통 그리드 로딩 기대값을 새 오버레이 동작과 일치시킨다.
- `frontend/tests/menu-management-required-selection.test.tsx`
  - 메뉴관리 `F1Tree`가 공통 오버레이를 통해 로딩 상태를 표시하는지 필요한 범위만 보강한다.
- `frontend/src/pages/f1-grid-docs/F1-GRID.md`
  - `loading` 동작, 전체 오버레이, 스켈레톤 보존 정책을 문서화한다.
- `docs/result/20260908/f1-grid-full-loading-spinner/`
  - 작업 원장, 검증 결과, 브라우저 캡처 경로를 기록한다.

### 적용 화면

공통 `F1Grid` 변경으로 다음 사용처에 일괄 적용한다.

- 메뉴관리 `F1Tree`
- 모듈관리 `F1Grid`
- 권한관리 역할·사용자 `F1Grid`
- F1-Grid 테스트 페이지 `F1Grid`
- F1-Grid 문서 플레이그라운드 `F1Grid`·`F1Tree`

### 백엔드/DB

- 변경 없음
- API, 권한 정책, DB 스키마 및 SQL 계약을 변경하지 않는다.

## 기존 구조 영향

- `F1Tree`는 내부에서 `F1Grid`를 렌더링하므로 공통 변경이 자동 전파된다.
- 각 페이지의 `loading` 전달 방식과 조회·저장 상태 분리는 변경하지 않는다.
- 로딩 중 본문은 기존 `GridLoadingSkeleton` 경로를 유지하고, 새 오버레이가 헤더와 본문 위에 표시된다.
- 그리드 컨테이너의 높이·최소 높이·내부 스크롤·가로 스크롤 규칙은 유지한다.

## 검증 계획

1. `npm run test -- tests/f1-grid.test.tsx tests/role-management-notification.test.tsx tests/menu-management-required-selection.test.tsx`
2. `npm run build`
3. 실제 브라우저에서 F1-Grid 테스트·메뉴관리·모듈관리·권한관리 화면의 로딩 상태를 확인한다.
4. 375px, 768px, 1280px 뷰포트에서 오버레이가 그리드 밖으로 넘치거나 가로 스크롤을 만들지 않는지 확인한다.
5. 검증 실패 시 원인을 원장에 기록하고 해당 범위 수정 후 동일 명령을 재실행한다.

## 완료 조건

- 모든 F1Grid/F1Tree 사용처가 공통 전체 로딩 오버레이와 스피너를 사용한다.
- 기존 스켈레톤 컴포넌트와 테스트 식별자가 유지된다.
- 로딩 중 상호작용이 차단되고 로딩 종료 후 복구된다.
- 관련 Vitest와 프론트엔드 빌드가 통과한다.
- 데스크톱·모바일 브라우저 검증과 결과 문서가 남는다.
