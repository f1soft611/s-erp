# 계획서

## 작업명

모듈관리·권한관리 메인 패널 외곽 레이아웃 정합성 개선

## 근거 문서

- 작업지시서: [20260908*010*모듈*권한관리*메인패널*레이아웃*정합성\_작업지시서.md](../../directions/20260908/20260908_010_모듈_권한관리_메인패널_레이아웃_정합성_작업지시서.md)
- 기준 구현: `frontend/src/pages/settings/system/menus/components/MenuManagementPanel.tsx`

## 목적

메뉴관리 패널에서 사용하는 외곽 `Box → Card → CardContent` 레이아웃 기준을 모듈관리와 권한관리 메인 패널에도 적용한다. 화면 기능, API, 상태 처리, 그리드 데이터는 변경하지 않고 패널 간 여백·높이·overflow·카드 스타일만 정렬한다.

## 작업 범위

### 프론트엔드

1. `frontend/src/pages/settings/system/modules/components/ModuleManagementPanel.tsx`
   - 메뉴관리 패널과 같은 외곽 Box 레이어를 추가한다.
   - Box의 반응형 패딩, flex 확장, 전체 높이, overflow 기준을 적용한다.
   - 기존 단일 Card와 CardContent의 제목 및 F1Grid 구조는 유지한다.
   - Card/CardContent를 메뉴관리 기준의 반경, 테두리, 패딩, 높이 확장 및 overflow로 정렬한다.

2. `frontend/src/pages/settings/system/roles/components/RoleManagementPanel.tsx`
   - 최상위 Box를 메뉴관리 기준의 외곽 Box 속성으로 조정한다.
   - 내부 권한 목록/사용자 매핑 2열 grid와 `lg` 이하 1열 전환은 유지한다.
   - 두 Card의 반경, 테두리, CardContent 패딩·높이·overflow를 메뉴관리 기준으로 정렬한다.
   - F1Grid 선택, 매핑 조회, 저장, 오류, 로딩 흐름은 변경하지 않는다.

### 백엔드 및 DB

- 백엔드 변경 없음.
- DB 스크립트: 해당 없음, 기존 스키마 영향 검토 완료.

## 영향 범위

- 페이지 상위 컨테이너와 라우팅은 변경하지 않는다.
- 컴포넌트 내부의 제목, 검색/액션 상위 영역, F1-Grid 데이터, CRUD 이벤트 및 권한 조건은 변경하지 않는다.
- 시각적 영향은 패널의 외곽 여백과 카드 경계, 높이 계산, overflow 범위로 제한한다.

## 구현 순서

1. 계획·사양 승인 후 현재 브랜치 진행 여부와 Worktree 사용 여부를 확인한다.
2. 모듈 패널에 메뉴 패널 기준 외곽 Box를 적용한다.
3. 권한 패널의 최상위 Box와 내부 카드 스타일을 기준에 맞춘다.
4. 변경된 패널의 타입/린트 오류를 확인한다.
5. 관련 Vitest를 실행하고 전체 프론트엔드 빌드를 실행한다.
6. Playwright 또는 기존 캡처 스크립트로 `375px`, `768px`, `1280px` 화면을 확인한다.
7. 결과 문서와 작업 원장에 변경 및 검증 결과를 기록한다.

## 검증 계획

- 정적 검증: `npm run build`
- 관련 테스트: 모듈관리·권한관리·메뉴관리 패널 또는 레이아웃 관련 Vitest를 우선 실행한다.
- 반응형 검증: 실제 브라우저에서 최소 `375x800`, `768x900`, `1280x900` 뷰포트 확인
- 확인 항목:
  - 세 화면의 메인 카드 시작 위치와 외곽 여백이 기준에 맞는지
  - 권한관리 2열/1열 전환이 유지되는지
  - 패널 내부 그리드가 페이지 전체 가로 스크롤을 만들지 않는지
  - 제목과 그리드가 잘리거나 겹치지 않는지
  - 기존 로딩 및 데이터 표시가 유지되는지

## 완료 조건

- 두 대상 패널의 외곽 레이아웃이 메뉴관리 기준과 일치한다.
- 권한관리의 2열 기능 구조와 기존 화면 동작이 유지된다.
- 빌드·관련 테스트·브라우저 반응형 검증 결과가 결과 문서에 기록된다.
- DB 변경 없음이 작업 원장과 결과 문서에 기록된다.
