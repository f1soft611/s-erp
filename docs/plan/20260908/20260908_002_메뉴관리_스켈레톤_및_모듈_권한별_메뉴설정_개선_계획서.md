# 메뉴관리 페이지 스켈레톤 UI 적용 및 모듈/권한별 메뉴 설정 개선 계획서

## 1. 개요 및 목적

본 계획서는 메뉴관리 페이지에 권한 관리 페이지 패턴의 F1-Grid/F1-Tree 스켈레톤 UI를 적용하고, 상단 검색 영역에 [모듈 선택] > [권한 선택] 연차 구조를 도입하여 모듈별·권한별 메뉴 및 기본기능 버튼권한(READ, CREATE, UPDATE, DELETE, EXCEL 등)을 설정할 수 있도록 프론트엔드 UI 및 상태 관리를 개선하는 것을 목적으로 합니다.

## 2. 작업 범위 분해

### 프론트엔드 (`frontend/src/pages/settings/system/menus/`)

1. **스켈레톤 UI 적용**:
   - `MenuManagementPage.tsx` 및 `MenuManagementPanel.tsx`에 `loading` (스켈레톤) 상태 추가.
   - 최초 데이터 조회, 모듈 변경, 권한 변경 시 F1Tree 컴포넌트의 `loading={true}` 적용으로 스켈레톤 UI 제공.
2. **상단 연차 검색 조건 및 버튼 영역 배치**:
   - `PageHeader` 우측 `actionGroups` 영역에 [저장] 등 주요 액션 버튼 배치.
   - `PageSearchArea`에 [모듈 선택] Dropdown과 [권한 선택] Dropdown 순차 배치.
   - 모듈 선택에 따라 권한(Role) 목록 및 해당 모듈의 메뉴 목록 연차 조회/동기화.
3. **권한별 메뉴 및 버튼 권한 설정 UI & 저장 흐름**:
   - 선택된 권한(Role) 관점에서 메뉴별 활성화 여부 및 버튼 권한(READ, CREATE, UPDATE, DELETE, EXCEL 등) 체크박스 열 제공.
   - PageHeader 우측 [저장] 버튼 클릭 시 선택된 권한(`roleId`) 관점의 메뉴 및 버튼 권한 매핑 정보를 백엔드로 일괄 저장.
4. **다중 권한 활성화 정책 지원**:
   - 사용자가 다중 권한(Role)을 소유할 때 어느 한 권한이라도 활성화되어 있으면 기능이 노출/작동하도록 정합성 유지.

### 백엔드 및 DB 영향

- 기존 백엔드 API 및 서비스 구조 활용.
- DB 변경 사항: **해당 없음** (기존 `tb_module`, `tb_role`, `tb_menu`, `tb_permission`, `tb_menu_permission`, `tb_role_menu_permission` 스키마가 이미 완비되어 있음).

### F1-Grid 공통 컬럼 확장

1. `frontend/src/shared/components/f1-grid/types/grid.types.ts`에 셀 렌더링 context, 셀 props 타입과 `F1GridColumn` 콜백(`renderCell`, `getCellStyle`, `getCellProps`)을 추가한다.
2. `GridCell.tsx`에서 표시 모드에만 커스텀 렌더러를 적용하고, 기본 표시·편집기·체크박스·dirty/error 표시 동작은 유지한다.
3. `F1Grid.tsx`에서 활성 editor plugin과 행별 `isCellEditable` 결과를 계산하여 헤더에 컬럼별 편집 가능 상태를 전달한다.
4. `GridHeader.tsx`에서 편집 가능한 컬럼의 헤더 하단 border 색상을 표시하되 기존 정렬, 필터, 고정, 리사이즈, 드래그 표시와 충돌하지 않도록 한다.
5. `frontend/tests/f1-grid.test.tsx`에 커스텀 태그 렌더링, 동적 스타일/props, editor plugin 기반 헤더 표시, 행별 editable 조건 회귀 테스트를 추가한다.
6. `frontend/src/pages/f1-grid-docs/F1-GRID.md` 및 관련 F1-Grid 문서에 컬럼 확장 API와 편집 가능 헤더 표시 기준을 반영한다.
