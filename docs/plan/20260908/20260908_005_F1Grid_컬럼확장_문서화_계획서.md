## 요구사항 분석 및 목적

- `F1GridColumn`의 `renderCell`/`getCellStyle`/`getCellProps`와 편집 가능 컬럼 헤더 표시는 이미 코드에 구현되어 있으나, `F1-GRID.md`에는 전혀 문서화되어 있지 않다.
- 목적: 코드 변경 없이 문서만 갱신하여 팀 규칙(F1-Grid 기능 변경/추가 시 문서 동기화 필수)을 충족시키고, 사용자가 "처리 안 됨"으로 오인하지 않도록 실제 구현 상태를 명확히 기술한다.
- 부가 목적: 문서 작성 과정에서 코드-문서 정합성을 검증하여, 결함이 있으면 별도 보고한다(현재까지 조사로는 결함 없음).

## 코드 조사 결과 (근거)

- 타입 선언: [frontend/src/shared/components/f1-grid/types/grid.types.ts](../../../frontend/src/shared/components/f1-grid/types/grid.types.ts)
  - `F1GridCellRenderContext<T>` (37~44라인): `row`, `rowId`, `column`, `field`, `value`, `rowIndex`
  - `F1GridCellProps` (46~51라인): `className`, `style`(CSSProperties), `title`, `aria-label`
  - `F1GridColumn.renderCell` / `getCellStyle` / `getCellProps` (89~95라인)
- 렌더링 반영: [frontend/src/shared/components/f1-grid/core/GridCell.tsx](../../../frontend/src/shared/components/f1-grid/core/GridCell.tsx)
  - `getCellProps`/`getCellStyle` 병합 (98~104라인): `customCellStyle`과 `customCellProps.style`을 병합해 `mergedCellStyle`로 적용, `className`/`title`/`aria-label`도 반영
  - 표시 모드 분기 (233~261라인): `checkbox` → `editing(CellEditor)` → `column.renderCell` → 기본 텍스트 표시 순서로 렌더링. **`renderCell`은 `editing`이 아닐 때만 적용되고, 편집 모드에서는 기존 `CellEditor` 흐름을 그대로 사용**함을 코드로 확인.
- 편집 가능 헤더 판정: [frontend/src/shared/components/f1-grid/core/F1Grid.tsx](../../../frontend/src/shared/components/f1-grid/core/F1Grid.tsx) 378~401라인
  - `editableColumnFields`는 `visibleColumns`를 순회하며, `visibleRows` 중 하나라도 `isCellEditable(column, row)`이 참이고 모든 활성 editor plugin의 `canEdit(context)`가 참(또는 미정의)인 경우에만 해당 컬럼 field를 포함.
  - 즉 **컬럼의 `editable` 선언만으로는 표시되지 않고, 행별 조건 + 활성 editor plugin의 `canEdit`까지 만족해야 함**.
- 헤더 표시 반영: [frontend/src/shared/components/f1-grid/core/GridHeader.tsx](../../../frontend/src/shared/components/f1-grid/core/GridHeader.tsx)
  - `isEditableHeader = editableColumnFields?.has(String(column.field)) ?? false` (351~352라인)
  - `data-editable-column` 속성 (372라인), `borderBottom: isEditableHeader ? 2 : undefined` + `borderBottomColor: 'primary.main'` (453~455라인)
  - 정렬 인디케이터, 필터 표시, 고정(pin), 드래그앤드롭 드롭 표시(`data-drop-target`)는 동일 헤더 셀에서 별도 속성/스타일로 병행 표시되므로 상호 배타적이지 않음을 확인.
