# Module Management Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 권한 관리 페이지와 같은 패턴으로 환경설정 > 시스템관리 하위에 F1-Grid 1개짜리 모듈 관리 페이지를 추가한다.

**Architecture:** 프론트엔드는 `settings/system/modules` 기능 폴더를 새로 만들고 Page 컴포넌트, Panel 컴포넌트, service, types로 분리한다. 기존 `/api/v1/system/modules` 백엔드 API를 재사용하되, 기존 수정 API가 `moduleCode`를 실제 UPDATE하지 않는 결함은 백엔드 SQL/Service 최소 수정으로 보완한다. 라우팅은 대시보드 메뉴 경로의 마지막 세그먼트 `modules`를 `DashboardContent`에서 분기한다.

**Tech Stack:** React 18, TypeScript, Vite, MUI, F1-Grid, Vitest, Playwright, Java 17, Spring Boot/eGovFrame, MyBatis PostgreSQL.

## 3. 영향 범위

- 프론트엔드 영향: 환경설정 > 시스템관리 화면 라우팅과 신규 모듈 관리 기능 폴더에 한정한다.
- 백엔드 영향: 기존 모듈 수정 API의 `moduleCode` 저장 누락 보완에 한정한다.
- DB 스키마 영향: 없음. 기존 `tb_module` 컬럼을 사용하고 신규 테이블/컬럼/제약조건을 만들지 않는다.
- DB 데이터 영향: 실제 좌측 메뉴 노출은 기존 DB 메뉴 데이터에 `/settings/system/modules` 항목이 있어야 한다. 이번 계획의 기본 범위는 프론트 fallback 메뉴 추가이며, 운영 DB seed DML 작성은 사용자가 별도 승인하거나 기존 메뉴 데이터 부재가 구현 중 확인될 때 추가 문서화 후 진행한다.

  ```ts
  const toNumber = (value: unknown, fallback = 0): number => {
    const parsed = Number(value);
    return Number.isFinite(parsed) ? parsed : fallback;
  };

  const toRow = (module: SystemModuleVO): ModuleManagementRow => ({
    id: String(module.moduleId ?? ''),
    moduleCode: String(module.moduleCode ?? ''),
    moduleName: String(module.moduleNm ?? ''),
    iconName: String(module.iconNm ?? ''),
    moduleUrl: String(module.moduleUrl ?? ''),
    sortOrder: toNumber(module.sortOrder),
    menuCount: toNumber(module.menuCount),
    use: String(module.useAt ?? 'Y') !== 'N',
  });
  ```
