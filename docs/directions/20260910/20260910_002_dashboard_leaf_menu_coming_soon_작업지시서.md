# 대시보드 하위 리프 메뉴 준비 중 페이지 표시 작업지시서

## 배경

대시보드 사이드바의 메뉴 트리에서 자식 메뉴가 없는 리프 메뉴는 독립 페이지가 될 수 있다. 현재는 상위 메뉴 중심의 선택 및 콘텐츠 판별로 인해, 실제 화면이 아직 연결되지 않은 리프 메뉴를 클릭해도 콘텐츠 영역이 해당 메뉴의 준비 중 화면으로 전환되지 않을 수 있다.

## 경로 분류

- 분류: `bounded`
- 사유: 프런트엔드 대시보드의 메뉴 클릭, 경로 선택, 콘텐츠 분기만 변경하며 API, 데이터베이스, 공용 F1-Grid 계약은 변경하지 않는다.

## 목표

1. 자식 메뉴가 없는 모든 리프 메뉴를 선택 가능한 콘텐츠 대상으로 처리한다.
2. 리프 메뉴에 구현된 화면이 없으면 해당 메뉴명을 사용한 공통 준비 중 페이지를 콘텐츠 영역에 표시한다.
3. 자식 메뉴가 있는 메뉴는 콘텐츠 선택 대상이 아닌 펼침/닫힘 전용으로 유지한다.

## 확정 요구사항

### 1. 메뉴 트리 상호작용

- 자식 메뉴가 없는 노드를 클릭하면 해당 메뉴 경로로 선택한다.
- 자식 메뉴가 있는 노드를 클릭하면 기존처럼 트리의 펼침/닫힘만 수행한다.
- 자식 메뉴가 있는 노드를 클릭해 준비 중 페이지를 표시하거나 현재 선택 메뉴를 변경하지 않는다.

### 2. 콘텐츠 판별 및 준비 중 표시

- 선택 경로가 자식 메뉴가 없는 리프 메뉴를 가리키면 해당 노드를 현재 메뉴로 사용한다.
- 리프 메뉴의 `pageKey` 유무는 선택 가능 여부를 제한하지 않는다.
- 구현된 화면에 대응하는 기존 `pageKey`는 현재 화면 렌더링을 유지한다.
- 구현된 화면에 대응하지 않는 리프 메뉴는 기존 공통 준비 중 화면을 렌더링한다.
- 준비 중 화면에는 선택한 리프 메뉴명을 사용해 "{메뉴명} 메뉴는 추후 서비스될 예정입니다."를 표시한다.
- 경로 해석 실패 또는 접근할 수 없는 메뉴의 기존 fallback 동작은 유지한다.

## 구현 범위

- `frontend/src/pages/dashboard/components/DashboardMenuTree.tsx`의 리프 메뉴 선택 유지 여부 확인
- `frontend/src/pages/dashboard/DashboardPage.tsx`의 현재 메뉴 및 경로 선택 조건 수정
- `frontend/src/pages/dashboard/components/DashboardContent.tsx`의 공통 준비 중 화면 분기 일반화
- 관련 대시보드 메뉴 선택 Vitest 회귀 테스트 추가 또는 수정
- 메뉴 클릭 후 실제 브라우저에서 콘텐츠 전환 확인 및 결과 문서화

## 제외 범위

- 자식 메뉴가 있는 메뉴를 준비 중 페이지 대상으로 변경하는 작업
- 신규 업무 화면, 메뉴 API, 권한 정책, 데이터베이스 스키마 변경
- F1-Grid/F1-Tree 행 폼 모달 플러그인 작업

## DB 영향

- DB 스크립트: 해당 없음
- 영향 검토: 프런트엔드의 기존 메뉴 응답을 소비하는 선택·렌더링 로직만 변경하며 API 데이터 계약과 DB 스키마는 변경하지 않는다.

## 검증 기준

- 리프 메뉴 클릭이 해당 경로 및 현재 메뉴로 반영되는지 검증한다.
- 화면 연결이 없는 리프 메뉴에서 메뉴명 기반 준비 중 문구가 표시되는지 검증한다.
- 화면이 연결된 기존 리프 메뉴가 기존 화면을 계속 표시하는지 검증한다.
- 자식이 있는 메뉴 클릭이 콘텐츠를 전환하지 않고 펼침/닫힘만 수행하는지 검증한다.
- 데스크톱과 모바일 브라우저에서 메뉴 선택 및 준비 중 콘텐츠가 겹치거나 잘리지 않는지 확인하고 스크린샷을 남긴다.

## 완료 기준

- 모든 리프 메뉴는 콘텐츠 선택 대상으로 동작한다.
- 미구현 리프 메뉴는 공통 준비 중 페이지를 표시한다.
- 자식 보유 메뉴의 펼침/닫힘 동작과 기존 구현 화면의 렌더링은 회귀하지 않는다.
- 테스트, 브라우저 검증, 결과 문서가 작업 범위와 일치한다.
