# F1-Grid/F1-Tree 행 폼 모달 플러그인 작업지시서

## 배경

마스터 데이터 등록·수정 화면은 컬럼 수가 많아 F1-Grid/F1-Tree의 가로 셀 편집만으로 관리하기 불편할 수 있다. 그리드 크기를 페이지 레이아웃보다 강제로 확장하지 않으면서 선택 행을 폼 형태로 편집할 수 있도록, 공용 컴포넌트와 자연스럽게 연동되는 선택형 모달 플러그인이 필요하다.

## 경로 분류

- 분류: `architectural`
- 사유: 공용 F1-Grid/F1-Tree의 공개 타입, 행 추가·수정 흐름, 변경 추적, 컬럼 렌더링 및 문서 계약에 영향을 주는 기능이다.

## 목표

1. 선택적으로 등록하는 F1-Grid/F1-Tree 공용 행 폼 모달 플러그인을 제공한다.
2. 플러그인이 등록되면 그리드에 전용 액션 컬럼을 자동 추가하고, 행별 버튼으로 수정 모달을 연다.
3. 플러그인이 등록된 상태에서 행 추가를 실행하면 빈 행을 먼저 만들지 않고 신규 등록 모달을 연다.
4. 기존 컬럼 정의를 폼 필드로 자동 변환하고, 컬럼 타입에 맞는 입력 컴포넌트를 사용한다.
5. 멀티헤더의 `headerGroup`을 모달 폼의 섹션으로 자동 변환한다.
6. 라이트·다크 테마 및 모바일·태블릿·데스크톱 화면에서 일관된 전용 모달 UI를 제공한다.
7. 플러그인이 없으면 현재 F1-Grid/F1-Tree 동작을 그대로 유지한다.

## 확정 요구사항

### 1. 선택적 플러그인 동작

- 행 폼 모달 기능은 명시적으로 플러그인을 등록한 F1-Grid/F1-Tree에만 활성화한다.
- 활성화 시 행 우측에 모달 열기용 액션 컬럼을 자동 구성한다.
- 플러그인이 없으면 액션 컬럼을 추가하지 않으며 기존 인라인 셀 편집과 행 추가 흐름을 변경하지 않는다.
- 기존 `F1GridEditorPlugin`과 행 폼 모달 플러그인의 책임과 공개 계약을 구분한다.

### 2. 수정 및 적용 계약

- 행 액션 버튼을 누르면 해당 행의 현재 값을 복사한 임시 폼 상태로 수정 모달을 연다.
- 모달 입력 중에는 그리드 행과 변경 상태를 직접 수정하지 않는다.
- `적용` 시 폼 값을 해당 행에 반영하고 기존 F1-Grid 변경 추적 규칙에 따라 수정 상태로 기록한다.
- `취소` 또는 닫기 시 모달 임시값을 폐기한다.
- 모달은 서버 API를 직접 호출하지 않으며, 최종 서버 저장은 기존 화면의 저장 흐름이 담당한다.

### 3. 신규 등록 계약

- 플러그인이 활성화된 상태에서 행 추가를 실행하면 신규 등록 모달을 연다.
- `적용` 시에만 신규 행을 추가하고 삽입 상태로 기록한다.
- `취소` 시 빈 행이나 변경 이력을 남기지 않는다.
- F1-Tree의 루트 추가와 하위 행 추가도 같은 모달을 사용한다.
- 하위 행 추가 시 대상 부모 식별자를 보존하고 `적용` 시 신규 행에 반영한다.

### 4. 컬럼 기반 폼 자동 생성

- 일반 데이터 컬럼은 별도 폼 스키마 없이 기본 폼 필드로 자동 변환한다.
- `headerName`을 기본 필드 라벨로 사용하고 컬럼 선언 순서를 기본 폼 순서로 사용한다.
- `text`, `number`, `decimal`, `currency`, `checkbox`, `date`, `datetime`, `time`, `select`, `autocomplete`, `code` 컬럼 타입에 대응하는 입력 UI를 제공한다.
- 행 번호, 선택 체크박스, 자동 액션 컬럼은 폼 필드에서 제외한다.
- 숨김 컬럼은 기본적으로 폼에서도 제외한다.
- 컬럼별 폼 설정으로 표시 제외, 읽기 전용, 순서, 그룹, 필드 폭을 재정의할 수 있게 한다.
- 컬럼별 폼 그룹 재정의 값이 있으면 `headerGroup`보다 우선한다.
- 기존 컬럼의 필수값, 최소·최대값, 선택 옵션 및 검증 규칙을 가능한 범위에서 재사용한다.

### 5. 멀티헤더 기반 섹션 구성

- 동일한 `headerGroup`의 컬럼을 같은 폼 섹션에 배치한다.
- 섹션과 필드의 기본 순서는 컬럼 선언 순서를 따른다.
- `headerGroup`이 없는 컬럼은 `기본 정보` 섹션에 모은다.
- 현재 F1-Grid가 지원하는 한 단계 `headerGroup` 계약을 기준으로 한다.

### 6. 모달 크기와 반응형 UI

- 모달 크기는 그리드 영역이 아니라 브라우저 뷰포트를 기준으로 계산하여 페이지에 종속된 작은 그리드에서도 충분한 편집 공간을 확보한다.
- 데스크톱에서는 최대 폭 약 960px, 최대 높이는 뷰포트의 약 85%를 기준으로 한다.
- 내용이 모달 높이를 넘으면 헤더와 하단 액션 영역은 유지하고 폼 본문만 세로 스크롤한다.
- 넓은 화면에서는 폼을 2~3열, 태블릿에서는 2열, 모바일에서는 전체 화면 모달과 1열로 자동 전환한다.
- 최소 375px, 768px, 1280px 뷰포트에서 겹침, 잘림 및 의도하지 않은 페이지 가로 스크롤이 없어야 한다.

### 7. 테마 및 디자인

- MUI 테마의 `background`, `text`, `divider`, `primary`, `action` 계열 토큰을 사용해 라이트·다크 테마에 자동 대응한다.
- 멀티헤더별 섹션은 얇은 경계선과 절제된 강조선으로 구분한다.
- 모달 헤더에는 신규 등록·수정 상태와 대상 행 식별 정보를 명확히 표시한다.
- 하단에는 `취소`와 `적용` 액션을 제공하고, 최종 저장이 기존 화면에서 수행됨을 혼동하지 않게 표현한다.
- 입력 포커스, 필수값, 읽기 전용 및 검증 오류 상태가 두 테마에서 명확히 구분되어야 한다.

## 구현 범위

- 공용 F1-Grid/F1-Tree 타입 및 선택적 플러그인 계약
- 자동 액션 컬럼과 신규/수정 모달 연결
- 컬럼 정의에서 폼 섹션·필드 모델을 생성하는 변환 로직
- 컬럼 타입별 폼 입력 컴포넌트와 검증 연동
- 신규 등록, 수정 적용, 취소 및 F1-Tree 부모 관계 처리
- 라이트·다크 테마 및 반응형 모달 UI
- 공용 Vitest 회귀 테스트와 실제 브라우저 검증
- F1-Grid 사용자 문서, 문서 포털 예제 및 결과 문서 갱신

## 제외 범위

- 백엔드 API 및 데이터베이스 스키마 변경
- 모달 내부의 직접 서버 저장 기능
- 모든 기존 업무 화면에 플러그인을 일괄 적용하는 작업
- 두 단계 이상의 중첩 멀티헤더 모델 신설
- 서버사이드 폼 스키마 또는 폼 빌더 기능
- 플러그인이 없는 F1-Grid/F1-Tree의 기존 UX 변경

## DB 영향

- DB 스크립트: 해당 없음
- 영향 검토: 프론트엔드 공용 컴포넌트와 문서만 변경하며 API 데이터 계약 및 DB 스키마는 변경하지 않는다.

## 검증 기준

- 플러그인 유무에 따른 액션 컬럼, 행 추가 및 기존 동작 분기를 Vitest로 검증한다.
- 수정 모달의 임시 상태, 적용, 취소 및 변경 추적을 검증한다.
- 신규 등록 모달의 적용 및 취소 시 행·변경 이력 생성 여부를 검증한다.
- F1-Tree의 루트/하위 추가와 부모 식별자 보존을 검증한다.
- 컬럼 타입별 필드 변환, 멀티헤더 섹션 자동 구성 및 컬럼별 재정의를 검증한다.
- 라이트·다크 테마와 375px, 768px, 1280px 뷰포트를 실제 브라우저로 확인하고 스크린샷을 남긴다.
- 관련 F1-Grid/F1-Tree 테스트, 프론트엔드 전체 테스트 및 빌드를 실행해 회귀 여부를 확인한다.

## 완료 기준

- 선택형 행 폼 모달 플러그인이 F1-Grid와 F1-Tree에서 동일한 계약으로 동작한다.
- 멀티헤더와 컬럼 타입을 기반으로 폼이 자동 생성된다.
- 플러그인이 없는 기존 사용처의 동작이 유지된다.
- 신규·수정·취소·검증·변경 추적 흐름이 테스트로 확인된다.
- 라이트·다크 및 반응형 브라우저 검증 증거가 결과 문서에 포함된다.
- F1-Grid 관련 사용자 문서와 문서 포털이 구현 내용과 일치한다.
