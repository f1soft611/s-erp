# F1-Grid 가상화 엔진 확장 작업지시서

## 배경

F1-Grid 대용량 샘플에서 1,000행 조회 후 브라우저가 잠시 멈추고 스크롤과 셀 선택이 지연된다. 현재 구조는 데이터 전체를 DOM으로 렌더링하며, 선택 상태 변경 때도 전체 행/셀 파생 계산을 반복한다. 10,000~100,000행 ERP 데이터를 지원하려면 viewport 기반 렌더링과 스크롤 갱신 제한이 필요하다.

## 목표

1. 행 가상화를 공용 그리드 기본 동작으로 안정화한다.
2. 비고정 컬럼에 컬럼 가상화를 적용하고 pinned 컬럼은 항상 렌더링한다.
3. 스크롤 상태 갱신을 `requestAnimationFrame`당 1회로 제한한다.
4. 선택 상태는 셀별 state가 아니라 anchor/focus 범위 모델로 유지하고 렌더 셀에서 선택 여부를 파생한다.
5. 10,000행 이상에서는 고정 행 높이를 사용하고 overscan을 조절할 수 있게 한다.

## 확정 범위

- 자동 활성화와 prop 재정의를 함께 지원한다.
- 행 가상화는 기본 임계값 이상에서 자동 적용한다.
- 컬럼 가상화는 가로 overflow가 있고 임계 컬럼 수 이상일 때 적용한다.
- pinned 컬럼, 편집 중 컬럼, 범위 선택 경계 컬럼은 viewport 밖이어도 렌더링한다.
- 전체 행 데이터, 정렬/필터, 행 선택, dirty/edit 상태는 가상 window와 분리해 유지한다.
- 외부 Grid 라이브러리는 추가하지 않는다.

## 공개 옵션

- `virtualizeRows?: boolean`
- `virtualizeColumns?: boolean`
- `rowOverscan?: number`
- `columnOverscan?: number`
- `fixedRowHeightThreshold?: number`

옵션이 없으면 공용 기본값으로 자동 판단하며 기존 호출부는 수정하지 않는다.

## 검증 기준

- 1,500행을 렌더링해도 DOM row 수가 viewport + overscan 범위로 제한된다.
- 다수 컬럼에서 화면 밖 일반 컬럼은 DOM에 없고 pinned 컬럼은 유지된다.
- 한 프레임 안의 연속 scroll 이벤트는 viewport state를 한 번만 갱신한다.
- 스크롤 후에도 포커스, 범위 선택, 편집 대상의 전체 행/컬럼 index가 유지된다.
- 10,000행 이상에서는 행 리사이즈 핸들이 표시되지 않는다.
- 기존 F1-Grid, pinned column, range selection, form modal, tree 관련 회귀 테스트를 통과한다.

## 제외 범위

- 서버 사이드 정렬/필터/페이지네이션
- 백엔드 및 DB 변경
- 무한 스크롤 API
- F1-Grid 외 화면 리팩터링

## 완료 기준

- 코드, 테스트, F1-Grid 문서, 결과 문서가 동일한 가상화 계약을 설명한다.
- 프론트엔드 빌드와 관련 회귀 테스트가 통과한다.
- 실제 브라우저에서 1,000행/10,000행 샘플의 스크롤 및 셀 선택을 확인한다.
