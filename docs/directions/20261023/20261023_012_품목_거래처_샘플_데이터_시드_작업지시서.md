# 20261023_012 품목·거래처 샘플 데이터 시드 작업지시서

## 사용자 승인 요구사항

- 품목 100건과 거래처 100건, 총 200건의 가상 샘플 데이터를 생성하는 PostgreSQL 시드 SQL을 제공한다.
- 실행 대상 tenant는 파일에 고정하지 않고 psql 변수 `target_tenant_id`로 실행자가 지정한다.
- 동일한 SQL을 `docs/database/20261023` 및 `backend/DATABASE/20261023`에 둔다.
- 기존 거래처·품목의 6자리 ID Generator 코드 및 `public.ids` 카운터를 보존한다. 필요한 카운터 행이 없으면 생성하지 않고 오류로 중단한다.
- 샘플 데이터와 코드 카운터는 한 트랜잭션에서 처리한다. 기존 이름/번호/샘플 마커 충돌, 공통코드 누락, 코드 범위 초과, tenant 오류 시 전체를 롤백한다.
- 중복 검사와 추가 사이의 동시 쓰기를 막기 위해 IDS 카운터 행을 먼저 잠그고 `tb_customer_info`, `tb_material_info`를 `SHARE ROW EXCLUSIVE`로 잠근다. 실행 중 해당 테이블 전체의 INSERT/UPDATE/DELETE는 대기하고 SELECT는 가능하다.
- 기존 업무 행과 공통코드를 수정·삭제하지 않는다. 실제 DB에는 SQL을 실행하지 않는다.

## 데이터 내용

- 거래처명은 `샘플 거래처 001`부터 `샘플 거래처 100`, 품목명은 `샘플 품목 001`부터 `샘플 품목 100`으로 만든다.
- 사업자번호는 숫자 10자리 형식의 고유한 가상 테스트 값으로 만들고, 표준 검증 체크섬이 맞지 않게 해 실제 사업자번호로 사용될 수 없도록 한다.
- 품목계정 코드와 단위는 실행 시점의 지정 tenant에서 활성인 `ITEM_TYPE`, `ITEM_UNIT` 공통코드로 선택한다. 둘 중 필요한 활성 항목이 없으면 스크립트 전체를 중단한다.
- `MATERIAL_TYPE`, `STORE_METHOD`는 지정 tenant에 활성 항목이 있으면 선택하고, 없으면 선택 필드는 NULL로 둔다.
- 품목 소비기한은 `NONE`/NULL 조합으로 저장하며, 품목 제조사 코드는 같은 스크립트에서 생성한 거래처에 연결한다.
- 계좌, 주소, 연락처, 실제 대표자 등 불필요한 개인정보는 넣지 않는다.

## 실행 및 검증

- psql 실행 예시:

  ```text
  psql -v ON_ERROR_STOP=1 -v target_tenant_id=<tenant_id> -f <script.sql>
  ```

- `public.ids`에서 거래처/품목 코드 범위를 각각 100개 예약한다. 카운터 행을 잠금 갱신할 때 기존 숫자 코드 최댓값보다 낮아지지 않게 하고, 6자리 범위를 벗어나면 실행을 중단한다.
- 같은 tenant에 동일 샘플 이름, 테스트 사업자번호 또는 샘플 마커가 이미 있으면 전체를 중단한다. 스크립트를 재실행해 기존 샘플을 덮어쓰거나 건너뛰지 않는다.
- 실제 DB를 읽거나 변경하는 검증은 수행하지 않는다. 저장소 내 정적 Node 테스트로 SQL의 트랜잭션, 쓰기 잠금, 코드 범위, 건수 생성 규칙, 두 사본 일치를 확인한다.

## 진행 순서 및 완료 조건

1. 본 작업지시서에 따라 날짜별 계획서와 상세사양서를 작성한다.
2. SQL 안전 조건을 검증하는 실패 테스트를 먼저 작성한다.
3. 시드 SQL 두 사본을 작성하고 동일성을 확인한다.
4. `node --test tools\tests\test_customer_material_sample_seed.cjs` 및 diff 검사를 통과시킨다.
5. 결과 문서에 DB MCP 확인 범위, 검증 결과, 실제 DB 미실행 사실을 기록한다.

완료 시 SQL은 tenant 지정 없이는 실행되지 않으며, 거래처 100건과 품목 100건을 모두 안전하게 생성하도록 설계되어야 한다. 실제 데이터 생성은 실행자가 별도로 승인한 다음 수행한다. 화면 변경이 없으므로 브라우저 스크린샷은 범위에서 제외한다.

## DB 확인 근거

기본 `s-erp-postgresql-readonly` MCP에서 `list_tables`와 `describe_table`로 `tb_customer_info`, `tb_material_info`, `ids`, `tb_common_code_group`, `tb_common_code_item` 메타데이터를 확인했다. 업무 데이터 행, 사용자/계정 정보, 카운터 값은 조회하지 않았다. MCP는 읽기 전용이며 SQL 적용에 사용하지 않는다.
