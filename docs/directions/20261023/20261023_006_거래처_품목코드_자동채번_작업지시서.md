# 거래처·품목 코드 자동채번 작업지시서

## 사용자 승인

2026-10-23 거래처관리와 품목관리에서 거래처코드와 품목코드를 직접 입력하지 않고 자동 채번한다. 신규 등록 시 기존 서버 채번기를 사용하고 기존 코드는 변경할 수 없도록 한다. 사용자는 목록에서 코드를 확인하며 등록·수정 폼에서는 코드 필드를 보지 않는다.

## 기준 문서

- 승인 설계: [거래처·품목 코드 자동채번 설계](../../superpowers/specs/2026-10-23-customer-material-auto-numbering-design.md)

## 범위

- 거래처·품목 코드 열을 F1-Grid 목록에서 표시하되 행 폼에서 제외하고, 셀 편집·붙여넣기를 막는다.
- 신규 생성 요청에 코드가 포함되어도 사용자가 전달한 값은 쓰지 않는다. 기존 각 eGov ID Generator로 저장 시 코드를 생성한다.
- 수정 요청의 코드 값은 무시하며 SQL에서 코드 컬럼을 변경하지 않는다. 기존 코드는 보존한다.
- 기존 코드 형식, 코드 생성 설정, 중복 확인, 테넌트 범위, API 응답 속성 및 다른 저장 동작은 유지한다.
- 백엔드/API 계약 변경 전 `s-erp-postgresql-readonly`에서 테이블 메타데이터를 읽기 전용으로 확인한다. DB 변경이나 데이터 정리는 하지 않는다.
- F1-Grid 안내 문서와 결과·브라우저 스크린샷을 갱신한다.

## 작업 순서

1. 이 작업지시서를 기준으로 날짜별 계획서 및 상세 사양서를 작성한다.
2. 현재 DB 메타데이터를 MCP로 확인하고, 거래처·품목 프론트와 백엔드 회귀 테스트를 먼저 작성해 실패를 확인한다.
3. 프론트 코드 열을 목록 전용으로 만들고, 서버 생성/수정 경로를 불변 코드 정책으로 바꾼다.
4. 집중 테스트, 프론트 빌드, 실제 브라우저 375/768/1280px 검증을 수행한다.
5. F1-Grid 문서, 결과 문서와 스크린샷을 `docs/result/20261023/customer-material-auto-numbering/`에 기록한다.

## 완료 조건

- 신규 거래처·품목 등록에 코드가 비어 있거나 임의 값이 포함되어도 서버 생성값만 저장된다.
- 코드가 전달되지 않거나 다른 값이 전달된 수정 요청에서도 기존 코드는 그대로 유지되고 나머지 정상 필드 수정은 가능하다.
- 목록의 코드는 보이며 행 폼에서 입력할 수 없고 인라인 편집 및 붙여넣기로도 변경할 수 없다.
- 기존 6자리 채번, 충돌/범위 오류, tenant scope, 기존 저장 검증이 유지된다.
- 프론트엔드·백엔드 집중 검증이 통과하고, 세 뷰포트의 브라우저 검증과 결과 스크린샷이 남는다.
- DB 스키마·데이터 변경은 하지 않는다.
