# 20261023_011 커뮤니티 자료실 올린 날짜 기본값/초기화 작업지시서

## 1. 목적

자료실 상세검색의 `올린 날짜`가 최초 진입 시 서버 날짜 기준 최근 1년으로 설정되고, 검색 조건 초기화 후에도 같은 기간이 다시 적용되도록 한다. 문서현황의 날짜 기본값 처리와 공통 resolver를 재사용한다.

## 2. 사용자 승인 사항

- 기준일은 브라우저 시간이 아닌 공통 시스템 날짜 API가 제공하는 서버 날짜다.
- 최근 1년은 달력 기준으로 시스템 날짜에서 1년 전부터 시스템 날짜까지의 범위다.
- 첫 진입과 상세검색 초기화 모두 같은 범위를 표시하고 목록 검색 조건에 적용한다.
- 초기화 시 검색어와 파일 유형은 기본 상태로 되돌리고 현재 폴더 위치는 유지한다.
- 날짜 기본값을 불러오는 중에는 날짜 조건이 빠진 파일 목록 조회를 보내지 않는다.
- 날짜 기본값 조회가 실패하면 오류와 재시도 동작을 표시하며 브라우저 날짜로 대체하지 않는다.
- 백엔드, 데이터베이스, 파일 목록 API 계약 변경은 없다.

## 3. 구현 절차

1. 승인 설계를 바탕으로 계획서와 상세 사양서를 작성한다.
2. 자료실 날짜 기본값과 초기화 동작에 대한 회귀 테스트를 추가한다.
3. `PageSearchField` 기본값 metadata와 `usePageSearchDefaults`를 재사용해 서버 기준 날짜를 해석한다.
4. 해석이 완료된 경우에만 첫 파일 목록 조회를 시작하고, 실패 시 재시도할 수 있도록 한다.
5. 상세검색 입력값, 적용 검색 조건 및 초기화에 동일한 resolved 기본값을 사용한다.
6. 자료실 검색 사양과 결과 문서 및 375px·768px·1280px 브라우저 스크린샷을 갱신한다.
7. 관련 Vitest, 프런트엔드 빌드, `git diff --check` 및 브라우저 동작을 검증한다.

## 4. 완료 기준

- 첫 진입에서 서버 날짜 기준 최근 1년 범위가 입력란, 요약 및 파일 목록 검색 조건에 일치하게 반영된다.
- 기본값 해석이 끝나기 전에 날짜 조건이 비어 있는 목록 조회가 발생하지 않는다.
- 상세검색 초기화 후에도 최근 1년이 입력란과 적용 검색 조건에 복원되며 초기화된 키워드/유형과 현재 폴더가 기대대로 유지된다.
- 서버 날짜 조회 실패는 명시적으로 표시되고 재시도가 동작한다. 브라우저 날짜 fallback은 없다.
- 관련 테스트와 빌드가 통과하며 동작 변경이 문서와 결과물에 기록된다.
