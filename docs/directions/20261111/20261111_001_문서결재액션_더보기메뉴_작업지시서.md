# 문서 결재 액션 더보기 메뉴 작업지시서

## 목적

문서관리 피드와 상세에서 바로 보이는 결재 액션 버튼을 기존 더보기 메뉴 안으로 옮겨 화면을 간결하게 한다.

## 요구사항

- 결재/확인/취소 액션은 권한이 있을 때만 기존처럼 제공하되, 피드와 상세의 툴바에 직접 노출하지 않는다.
- 더보기 메뉴의 첫 그룹에 승인, 반려, 보완요청, 최종확인, 참조 확인, 상신 취소, 승인 취소 등 해당 문서에서 가능한 결재 액션을 먼저 표시한다.
- 결재 액션 그룹과 문서 공유·참조 그룹 사이에 구분선을 표시한다.
- 문서 공유하기와 참조자 추가하기 다음에, 문서 수정/수정 후 재상신/삭제가 제공되는 경우 별도 구분선으로 나눈다.
- 비어 있는 그룹의 앞뒤에 단독 구분선을 표시하지 않는다.
- 기존 권한 조건, 처리 로직, 확인/사유 대화상자, 오류 및 성공 처리, 버튼 비활성화 규칙은 유지한다.
- 상태/문서종류 배지, 상단 고정, 상세 처리 의견 입력은 변경하지 않는다.

## 작업 순서

1. 기존 문서작성 결재 액션과 더보기 메뉴의 권한 및 처리 동작을 확인한다.
2. 메뉴 순서, 구분선, 툴바 비노출에 대한 프론트엔드 회귀 테스트를 작성한다.
3. 결재 액션을 `DocumentActionsMenu`의 첫 메뉴 그룹으로 이동한다.
4. 기존 액션 흐름과 권한별 메뉴 노출을 검증한다.
5. 프론트엔드 테스트 및 빌드를 수행하고 375px/768px/1280px 화면을 확인한다.
6. 결과 문서와 비식별 화면을 `docs/result/20261111/document-approval-actions-menu/`에 기록한다.

## 제외 범위

- 결재 권한, 상태 전이, API/백엔드/DB 변경
- 상단 고정, 상태 배지, 처리 의견 입력 UI 변경
- 문서관리 이외 메뉴 변경

## 완료 기준

- 피드와 상세 툴바에서 실행 가능한 결재 액션 버튼이 사라지고 더보기 메뉴 안에서 같은 동작을 수행한다.
- 메뉴에 결재 액션, 공유·참조, 수정·삭제 순서와 그룹 구분선이 올바르게 표시된다.
- 권한 및 기존 액션 처리 회귀 테스트와 빌드가 통과한다.
- 모바일/태블릿/데스크톱 브라우저에서 메뉴와 툴바가 겹치거나 잘리지 않는다.
- 결과 문서 및 화면 기록이 남는다.
