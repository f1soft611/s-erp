# 프론트엔드 공통 다이얼로그 표준화 작업지시서

## 목적

프론트엔드 전체에서 일반 확인·입력·선택·정보 다이얼로그가 공통 `CommonDialog` 셸을 사용하도록 통일하고, 브라우저 기본 확인창을 대체한다.

## 요구사항

- `frontend/src`의 직접 MUI `Dialog` 사용처를 전수 확인하고, `CommonDialog` 자체를 제외한 일반 다이얼로그를 공통 셸로 전환한다.
- 공유 `UnsavedChangesConfirmDialog`도 내부에서 `CommonDialog`를 사용해 모든 호출부에 공통 스타일을 적용한다.
- `window.alert`, `window.confirm`, `window.prompt` 등 브라우저 기본 대화상자 사용을 없애고 공통 다이얼로그 또는 기존 알림 컴포넌트로 대체한다.
- 브라우저 기본 확인창의 취소/확인 흐름은 비동기 공통 확인 훅으로 전환하되 기존 처리 조건과 핸들러를 유지한다.
- 제목, 설명, 폼·선택 UI, 액션 순서, 처리 중 비활성화, 닫기 조건, 접근성 명칭 및 기존 업무 핸들러를 유지한다.
- 기존 너비를 최대한 보존할 수 있도록 `CommonDialog`의 크기 옵션을 보완한다.
- 이미지 뷰어와 시간 선택 등 특수 입력도 내부 콘텐츠 동작은 유지하면서 공통 셸을 사용한다.
- 향후 프론트엔드 작업은 확인·입력·선택 대화상자에 `CommonDialog`를 사용하고 네이티브 브라우저 대화상자를 사용하지 않도록 `frontend/AGENTS.md`에 규칙을 추가한다.
- `Popover`, `Menu`, `Drawer`, 인쇄용 포털 등 다이얼로그가 아닌 오버레이는 변경하지 않는다.
- API, 백엔드, 데이터베이스, 문서관리 외 업무 로직은 변경하지 않는다.

## 확인된 직접 MUI `Dialog` 사용처

- 대시보드 즐겨찾기 폴더 생성/이름 변경: `MenuFavoriteContextMenu.tsx`
- F1-Grid 시간 선택: `TimeEditor.tsx`
- F1-Grid 테스트 품목 선택: `F1GridTestPage.tsx`
- 역할 사용자 추가: `RoleManagementPanel.tsx`
- 시스템 정책 삭제/변경 이력: `SystemPolicyPage.tsx`
- 정책 추가/수정: `PolicyEditor.tsx`
- 자료실 상위 코드 선택 및 삭제 확인: `CommonCodeManagementPanel.tsx`, `ArchiveBoardPage.tsx`
- 알림 읽음 항목 정리: `NotificationInboxPage.tsx`
- 문서 결재 취소/삭제 및 참조자 추가: `DocumentApprovalDetailFeed.tsx`, `DocumentReferenceAddDialog.tsx`
- 자료실 파일 정보 수정: `ArchiveFileEditDialog.tsx`
- 이미지 보기: `ImageViewerDialog.tsx`
- 공통 미저장 변경 확인: `UnsavedChangesConfirmDialog.tsx`
- 기본 브라우저 확인창: `StatementEditorDialog.tsx`, `SalesStatementCreatePage.tsx`, `DeliveryEditorDialog.tsx`, `SalesDeliveryPlanStatusPage.tsx`, `SalesDeliveryCreatePage.tsx`, `SalesOrderEditorDialog.tsx`, `SalesOrderCreatePage.tsx`

`CommonDialog.tsx` 안의 MUI `Dialog`만 공통 셸 구현을 위해 남긴다.

## 작업 순서

1. 전체 사용처의 라벨, 크기, 닫기 및 처리 중 동작을 확인한다.
2. 크기·접근성 확장 테스트와 공유 확인창 공통 셸 테스트를 먼저 작성한다.
3. `CommonDialog`에 필요한 크기/접근성 옵션을 추가한다.
4. 공유 `UnsavedChangesConfirmDialog`를 `CommonDialog` 기반으로 바꾼다.
5. 직접 MUI 다이얼로그를 업무 동작별로 묶어 공통 셸로 옮긴다.
6. 비동기 공통 확인 훅을 추가하고 모든 네이티브 확인창을 전환한다.
7. 프론트엔드 개발 지침에 공통 모달 및 네이티브 대화상자 금지 규칙을 추가한다.
8. 관련 테스트, 전체 프론트엔드 테스트, 빌드 및 375px/768px/1280px 브라우저 검증을 수행한다.
9. 결과 문서와 비식별 화면을 `docs/result/20261111/frontend-common-dialogs/`에 기록한다.

## 완료 기준

- `CommonDialog.tsx` 외부에 직접 MUI `<Dialog>`가 남지 않는다.
- 사용자 상호작용 코드에 네이티브 `alert`, `confirm`, `prompt`가 남지 않는다. PWA 설치 이벤트의 `prompt()` API는 브라우저 확인 대화상자가 아니므로 유지한다.
- 일반 다이얼로그의 기존 업무 동작, 접근성, 오류 처리, 입력 및 닫기 규칙이 유지된다.
- 전체 테스트와 빌드가 통과하며 필수 뷰포트에서 모달이 잘리거나 겹치지 않는다.
- 결과 문서 및 화면 기록이 남는다.
