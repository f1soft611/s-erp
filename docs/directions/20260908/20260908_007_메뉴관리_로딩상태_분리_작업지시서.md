# 작업지시서

## 제목

메뉴관리 페이지 로딩 상태 분리 및 스켈레톤 UX 보정

## 작업 분류

- 경로: `bounded`
- 대상: 프론트엔드 `frontend/src/pages/settings/system/menus`
- 사유: 기존 권한 관리 페이지의 로딩 UX 패턴을 메뉴 관리 페이지에 정확히 적용하는 단일 화면 개선이다.

## 배경

메뉴 관리 페이지에 `loading` 상태와 선택 조건 처리는 추가되어 있으나, 메뉴 트리 컴포넌트에 그 상태가 전달되지 않아 실제 F1-Tree 스켈레톤이 표시되지 않는다. 또한 페이지 진입·조회·저장 후 재조회가 하나의 로딩 상태로 처리되면 저장 시 기존 화면을 불필요하게 스켈레톤으로 덮을 수 있다.

권한 관리 페이지는 다음 패턴을 사용한다.

- 페이지 진입: 최초 목록 요청 동안 그리드 행 스켈레톤 표시
- 조회 버튼: 명시적 조회 요청 동안 그리드 행 스켈레톤 표시
- 저장: 저장 후 목록 재조회는 조용히 처리하고 기존 그리드 화면 유지

## 목표

1. 메뉴 관리 페이지 진입 시 메뉴 목록 요청 중 F1-Tree 행 스켈레톤을 표시한다.
2. `조회` 버튼 클릭 시 메뉴 목록 요청 중 F1-Tree 행 스켈레톤을 표시한다.
3. 저장 성공 후 메뉴 목록 재조회는 스켈레톤 없이 조용히 처리한다.
4. 저장 중에는 기존 `saving` 상태로 버튼·편집 동작을 제한하고, 로딩 표현을 스켈레톤과 혼동하지 않는다.
5. 모듈·권한 변경처럼 새로운 메뉴 컨텍스트를 여는 동작은 기존의 이전 데이터 제거 및 조회 로직을 유지하되, 조회 목적의 스켈레톤을 표시한다.

## 요구사항

### 1. 로딩 상태 분리

- `MenuManagementPage`에서 사용자에게 보이는 스켈레톤 여부와 저장 후 조용한 재조회 여부를 구분한다.
- 페이지 진입 및 사용자가 누른 `조회` 요청은 스켈레톤 상태를 활성화한다.
- 저장 후 `onRefresh`로 수행하는 재조회는 스켈레톤 상태를 활성화하지 않는다.
- 요청 경쟁 상태 방지와 오류 처리 방식은 기존 `menuLoadRequestIdRef`, `error` 흐름을 유지한다.

### 2. F1-Tree 연결

- `MenuManagementPanel`에 메뉴 그리드 로딩 prop을 추가하고 `F1Tree`의 `loading` prop에 연결한다.
- 권한 관리 페이지의 `RoleManagementPanel` → `F1Grid loading` 패턴과 동일하게 `GridLoadingSkeleton`이 표시되어야 한다.
- 스켈레톤 표시 중에도 그리드 헤더와 레이아웃은 유지한다.

### 3. 저장 UX

- 저장 버튼 클릭 시 기존 조용한 `saving` 로딩을 유지한다.
- 저장 완료 후 목록이 갱신되어도 F1-Tree 스켈레톤이 나타나지 않아야 한다.
- 저장 실패 시 기존 오류 메시지와 저장 가능 상태를 유지한다.

## 제외 범위

- 메뉴/권한 API 계약 및 백엔드·DB 변경
- 메뉴 관리의 검색조건 필수화, 대시보드 메뉴 로딩, NotFound 라우팅 변경
- F1-Grid 공통 스켈레톤 컴포넌트의 시각 스타일 변경
- 모듈·권한 선택 정책 또는 메뉴 권한 저장 규칙 변경

## 영향 파일 후보

- `frontend/src/pages/settings/system/menus/MenuManagementPage.tsx`
- `frontend/src/pages/settings/system/menus/components/MenuManagementPanel.tsx`
- 관련 메뉴 관리 Vitest 테스트 및 결과 문서

## 검증 조건

1. 페이지 최초 진입에서 메뉴 요청을 지연시키면 `grid-loading-row-skeleton`이 표시되고 그리드 헤더는 유지된다.
2. `조회` 버튼 클릭 후 지연된 메뉴 요청 동안 동일한 스켈레톤이 표시된다.
3. 저장 후 재조회 요청이 지연되어도 스켈레톤은 표시되지 않고 기존 행 화면이 유지된다.
4. 저장 실패 시 오류 메시지가 표시되고 저장 상태가 복구된다.
5. 관련 Vitest 테스트와 프론트엔드 빌드가 통과한다.
6. UI 변경 결과는 데스크톱·모바일 브라우저에서 확인하고 결과 문서에 캡처 경로를 기록한다.

## 설계 대안

### 권장안: 명시적 `showSkeleton` 옵션

조회 함수가 `showSkeleton`을 선택적으로 받도록 하고, 진입·조회 버튼·컨텍스트 전환에는 `true`, 저장 후 재조회에는 `false`를 전달한다. 호출부에서 로딩 의도가 드러나고 기존 API 호출 구조를 최소 변경한다.

### 대안: `loading`과 `refreshing` 상태를 별도 도입

스켈레톤과 백그라운드 재조회를 완전히 분리할 수 있으나, 현재 화면에는 저장 중인 `saving` 상태가 이미 있어 상태 수가 늘고 중복 분기 가능성이 커진다.

권장안으로 구현한다.
