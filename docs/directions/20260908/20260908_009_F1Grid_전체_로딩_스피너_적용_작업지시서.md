# 작업지시서

## 제목

F1-Grid 전체 영역 로딩 스피너 적용

## 작업 분류

- 경로: `bounded`
- 대상: 프론트엔드 공용 F1-Grid/F1-Tree 로딩 표시 및 모든 사용 페이지의 관련 문서·테스트
- 사유: 기존 로딩 상태의 스켈레톤 본문 대체 동작은 보존하면서, 새로고침 때 사용하는 로딩 스피너를 전체 그리드 영역에 표시하는 공통 UX 변경이다.

## 배경

- 현재 `F1Grid`의 `loading` 상태는 그리드 본문을 `GridLoadingSkeleton`으로 대체한다.
- 메뉴관리·모듈관리·권한관리·F1-Grid 테스트·문서 플레이그라운드 등 여러 화면이 동일한 `loading` prop을 사용한다. `F1Tree`도 내부적으로 `F1Grid`를 사용하므로, 화면별 개별 수정 대신 공통 F1-Grid에서 동작을 일관되게 바꿔야 한다.
- 사용자는 새로고침 중 기존 그리드 구조를 계속 인지할 수 있어야 하며, 로딩 중임을 명확히 알 수 있는 스피너가 필요하다.

## 목표

1. `loading=true`일 때 헤더와 본문을 포함한 전체 그리드 영역 위에 로딩 오버레이를 표시한다.
2. 오버레이 중앙에 기존 새로고침 동작에서 사용하는 로딩 스피너와 동일한 시각 패턴을 표시한다.
3. 기존 `GridLoadingSkeleton` 컴포넌트와 스켈레톤 관련 공개 테스트 식별자는 삭제하지 않는다.
4. 로딩 중에도 그리드의 컬럼, 헤더, 기존 행 또는 기존 스켈레톤 구조가 불필요하게 제거되지 않도록 한다.
5. 로딩 완료 시 오버레이와 스피너만 제거하고 기존 그리드 상호작용을 복구한다.

## 적용 대상

- 메뉴관리: `MenuManagementPanel`의 `F1Tree`
- 모듈관리: `ModuleManagementPanel`의 `F1Grid`
- 권한관리: 역할 목록 및 사용자 목록의 `F1Grid`
- F1-Grid 테스트 화면: `F1GridTestPage`의 `F1Grid`
- F1-Grid 문서 플레이그라운드: `F1GridPlayground`의 `F1Grid` 및 `F1Tree`
- 공통 구현: `F1Grid` 및 내부 위임을 담당하는 `F1Tree`

위 화면들의 호출부 API와 각 화면의 로딩 상태 정책은 변경하지 않는다. 공통 `F1Grid`의 `loading` 표시 변경으로 일괄 적용한다.

## 요구사항

### 1. 공통 F1-Grid 로딩 표시

- `F1Grid`의 기존 `loading` prop 계약을 유지한다.
- 로딩 상태에서 그리드 최상위 레이아웃을 기준으로 오버레이를 배치한다.
- 오버레이는 헤더와 본문 전체를 덮어야 하며, 스피너는 시각적으로 중앙에 위치해야 한다.
- 로딩 중에는 사용자 입력이 그리드 셀 편집·선택·컨텍스트 메뉴를 변경하지 않도록 기존 상호작용을 차단한다.
- 로딩 완료 시 기존 입력 차단도 해제한다.

### 2. 스켈레톤 보존

- `GridLoadingSkeleton` 컴포넌트와 `grid-loading-skeleton`, `grid-loading-row-skeleton` 식별자를 유지한다.
- 스켈레톤을 완전히 삭제하거나 다른 화면의 로딩 정책을 임의로 변경하지 않는다.
- 오버레이를 적용할 때 기존 그리드 높이, 내부 스크롤, 반응형 폭을 변경하지 않는다.

### 3. 새로고침 스피너 패턴

- 프로젝트에서 새로고침 중 사용하는 `CircularProgress`의 크기·색상·표시 방식을 확인하여 동일한 패턴을 재사용한다.
- 새로운 아이콘, 임의의 CSS 애니메이션, 별도 로딩 API를 추가하지 않는다.
- 접근성 관점에서 로딩 상태를 식별할 수 있는 `aria-busy` 또는 기존 프로젝트의 동등한 표현을 유지·보완한다.

### 4. 문서 및 테스트

- `frontend/src/pages/f1-grid-docs/F1-GRID.md`에 `loading` 상태의 오버레이 스피너 동작과 스켈레톤 보존 정책을 반영한다.
- F1-Grid 관련 테스트에 로딩 중 전체 오버레이·스피너 표시, 기존 스켈레톤 식별자 보존, 로딩 종료 후 복구를 검증하는 회귀 사례를 추가한다.
- 메뉴관리·모듈관리·권한관리·F1-Grid 테스트·문서 플레이그라운드 등 기존 호출부의 loading 테스트가 새 동작과 충돌하지 않도록 필요한 기대값만 갱신한다.

## 제외 범위

- 메뉴·모듈·권한 API 계약 및 백엔드·DB 변경
- `MenuManagementPage`의 로딩 상태 분리 정책 변경
- `GridLoadingSkeleton`의 삭제 또는 시각 스타일 전면 개편
- F1-Grid의 정렬·필터·편집·선택·스크롤 동작 변경
- 새로고침 버튼 자체의 동작 또는 API 호출 방식 변경

## 설계 대안

### 권장안: F1-Grid 공통 오버레이 방식

기존 `loading` prop을 그대로 사용하고 F1-Grid 최상위 레이아웃에 오버레이와 스피너를 추가한다. 모든 호출부에 같은 UX가 적용되고, 스켈레톤 렌더링 경로와 공개 계약을 보존할 수 있다.

### 대안 1: 각 페이지에서 별도 스피너 표시

화면별 요구를 세밀하게 조정할 수 있지만, 동일한 loading prop을 쓰는 페이지마다 중복 구현이 생기고 헤더·본문 전체 범위가 화면마다 달라질 위험이 있다.

### 대안 2: 스켈레톤 컴포넌트를 스피너 컴포넌트로 교체

구현은 단순하지만 기존 스켈레톤 테스트와 문서 계약을 훼손하고, 사용자가 기존 데이터 구조를 확인할 수 없게 되므로 채택하지 않는다.

## 검증 조건

1. 위 적용 대상의 각 `F1Grid` 및 `F1Tree`에서 `loading=true`일 때 그리드 헤더와 본문을 덮는 오버레이 및 새로고침과 동일한 로딩 스피너가 표시된다.
2. 로딩 중 기존 스켈레톤 식별자와 그리드 레이아웃이 유지된다.
3. 로딩 중 셀 편집·선택·컨텍스트 메뉴 입력이 적용되지 않는다.
4. 로딩 완료 후 오버레이가 사라지고 기존 행 상호작용이 복구된다.
5. 기존 F1-Grid 관련 테스트와 추가 회귀 테스트가 통과한다.
6. 프론트엔드 빌드가 통과한다.
7. 최소 375px, 768px, 1280px 브라우저 뷰포트에서 오버레이와 스피너가 잘리지 않고 가로 스크롤을 유발하지 않는지 확인한다.
8. 결과 문서에 검증 명령과 브라우저 캡처 경로를 기록한다.

## DB 영향

없음. 프론트엔드 공통 컴포넌트의 로딩 표시와 테스트·문서만 변경한다.
