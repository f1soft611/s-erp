# 작업지시서

## 제목

메뉴관리 검색조건 개선(스켈레톤+필수선택), 새로고침 시 메뉴없음 UX 개선, NotFound 페이지 추가

## 작업 분류

- 경로: `bounded`
- 사유: 3개의 독립적이고 범위가 명확한 프론트엔드 개선 건. 신규 아키텍처 도입이나 대규모 구조 변경 없이 기존 패턴(권한관리 페이지 스켈레톤, 라우터 구조)을 재사용한다.

## 배경

1. 메뉴 관리 페이지는 권한 관리 페이지와 달리 조회 시 스켈레톤 로딩 UI가 없고, 모듈만 선택해도 조회/저장이 가능해 권한(Role) 컨텍스트 없이 메뉴/버튼 권한이 저장될 수 있는 문제가 있다.
2. 대시보드는 F5 새로고침 시 메뉴 API 응답을 기다리는 짧은 시간 동안 "접근 가능한 메뉴가 없습니다"라는 오해의 소지가 있는 안내 문구를 보여준다. 실제로는 메뉴가 없는 것이 아니라 로딩 중인 상태다.
3. 현재 라우터(`AppRouter.tsx`)는 정의되지 않은 모든 경로를 인증 상태에 따라 `/dashboard` 또는 `/login`으로 리다이렉트한다. 존재하지 않는 URL로 접속해도 마치 정상 페이지인 것처럼 보여 사용자가 혼란을 겪는다. 첨부 디자인(흰 배경, "요청하신 페이지를 찾을 수 없습니다" 문구, "돌아가기" 버튼, 하단 카피라이트)을 반영한 전용 NotFound 페이지가 필요하다.

## 목표

1. **메뉴관리 검색조건 필수화 + 스켈레톤 적용**
   - 모듈과 권한을 모두 선택해야 조회 및 저장이 가능하도록 변경한다.
   - 권한 관리 페이지(`RoleManagementPage`)와 동일한 `GridLoadingSkeleton` 패턴을 적용한다.
2. **새로고침 시 메뉴없음 UX 개선**
   - 메뉴 로딩 중에는 스피너/스켈레톤을 표시하고, 로딩이 완료된 이후에 실제로 메뉴가 없을 때만 안내 문구를 표시한다.
3. **NotFound 페이지 추가**
   - 인증 여부와 관계없이 정의되지 않은 모든 경로 접속 시 전용 NotFound 페이지를 표시한다.
   - 첨부 이미지 디자인을 반영하고, "돌아가기" 버튼은 인증 여부에 따라 대시보드 또는 로그인 페이지로 이동한다.

## 요구사항

### 1. 메뉴관리 검색조건 필수화 + 스켈레톤

- `MenuManagementPage.tsx`의 상단 검색 영역에서 모듈과 권한을 모두 선택하지 않으면:
  - 그리드/트리 영역을 비우고 "모듈과 권한을 모두 선택하세요" 등의 안내 문구를 표시한다.
  - 메뉴 조회 API를 호출하지 않는다.
  - 저장 동작도 비활성화한다(모듈/권한 미선택 상태에서는 저장 버튼 비활성화 또는 저장 시 검증 실패 처리).
- 모듈과 권한이 모두 선택된 이후에만 조회 API(`fetchMenuRows` 등)를 호출한다.
- 최초 진입, 모듈 변경, 권한 변경 시 `RoleManagementPage`와 동일한 `GridLoadingSkeleton` 스켈레톤 UI를 노출한다.
- 기존 저장/편집 로직(메뉴/버튼 권한 매핑)은 그대로 유지하고, 검색조건 필수화로 인한 진입 조건만 변경한다.

### 2. 새로고침 시 메뉴없음 UX 개선

- `DashboardPage.tsx`에서 메뉴 목록(`fetchMyMenus`) 로딩 상태를 명시적으로 관리한다.
- 로딩 중에는 스피너 또는 스켈레톤을 표시하고, "접근 가능한 메뉴가 없습니다" 문구는 로딩이 완료된 후 실제로 메뉴가 0건일 때만 표시한다.
- 기존 인증/토큰 검증 흐름, 라우팅 구조는 변경하지 않는다.

### 3. NotFound 페이지 추가

- 첨부 디자인을 참고해 신규 `NotFoundPage` 컴포넌트를 작성한다: 중앙 정렬 카드형 레이아웃, "요청하신 페이지를 찾을 수 없습니다" 제목, "주소가 변경되었거나 페이지가 삭제되었을 수 있습니다" 안내문, "돌아가기" 버튼, 하단 카피라이트(`© 2026 FoodLink Cloud · F1soft`).
- `AppRouter.tsx`의 catch-all 라우트(`path="*"`)를 대시보드/로그인 리다이렉트 대신 `NotFoundPage` 렌더링으로 변경한다.
- "돌아가기" 버튼은 인증 여부(`isAuthenticated()`)에 따라 `/dashboard` 또는 `/login`으로 이동한다.

## 제외 범위

- F1-Grid 컬럼 확장 API(`renderCell`, `getCellStyle`, `getCellProps`), 편집 가능 컬럼 헤더 표시 등은 이번 작업 범위에서 제외한다(기존 20260908_002 문서의 별개 항목이며 이번 요청과 무관).
- 메뉴/권한 매핑의 백엔드 API 계약 변경은 포함하지 않는다(프론트 검증/UX 개선 범위로 한정).
- 대시보드 사이드바 메뉴 트리 자체의 구조 변경은 포함하지 않는다.

## 검증 조건

1. 메뉴 관리 페이지에서 모듈만 선택하거나 권한만 선택한 상태에서는 조회/저장이 되지 않고 안내 문구가 표시되는지 확인한다.
2. 모듈+권한을 모두 선택하면 스켈레톤 로딩 후 정상적으로 메뉴 데이터가 조회/저장되는지 확인한다.
3. 대시보드 새로고침 시 메뉴 로딩 중에는 스피너/스켈레톤이, 로딩 완료 후 실제 메뉴가 없을 때만 안내 문구가 표시되는지 확인한다.
4. 정의되지 않은 경로(예: `/no-such-page`)로 접속 시 인증 여부와 무관하게 NotFound 페이지가 표시되고, "돌아가기" 버튼이 인증 상태에 맞는 경로로 이동하는지 확인한다.
5. Vitest 유닛 테스트로 각 변경 사항을 검증하고, UI 변경 건은 Playwright 스크린샷 캡처로 최종 확인한다.
