2. 이미 구현된 편집 가능 컬럼 헤더 표시(하단 border 색상) 동작 조건과 기준을 `F1-GRID.md`에 반영한다.
3. 문서화 과정에서 실제 코드 동작과 문서 설명이 일치하는지 재검증하고, 불일치하거나 누락된 세부 동작(예: 편집 모드에서 `renderCell` 미적용, 커스텀 컬럼 정렬/필터/고정 등과의 상호작용)이 있으면 함께 보완한다.

## 요구사항

### 1. 컬럼 확장 API 문서화 (`# 5. Grid Column Specification` 섹션 또는 인접 위치)

- `F1GridColumn`의 `renderCell`, `getCellStyle`, `getCellProps` 각 함수의 시그니처와 파라미터(`F1GridCellRenderContext`: row, rowId, column, value, rowIndex 등)를 명시한다.
- `renderCell`은 표시 모드에서만 적용되며 편집 모드에서는 기존 `CellEditor`/editor plugin 흐름이 유지됨을 명시한다.
- `getCellStyle`, `getCellProps.style`은 `React.CSSProperties` 객체를 사용하며, 문자열 CSS를 지양한다는 규칙을 명시한다.
- 기본 렌더러가 없는 컬럼은 기존 값 표시·편집 동작이 그대로 유지됨을 명시한다.
- 간단한 사용 예시 코드 스니펫을 포함한다.

### 2. 편집 가능 컬럼 헤더 표시 문서화 (`# 26. Status / UI` 섹션 또는 인접 위치)

- 활성 editor plugin이 존재하고, 해당 컬럼에서 `isCellEditable(column, row)`을 만족하는 행이 하나 이상 있을 때 편집 가능 컬럼으로 판단하는 로직을 설명한다.
- 컬럼의 `editable` 선언만으로는 표시되지 않으며, 행별 `editable` 함수와 editor plugin의 `canEdit` 조건이 함께 고려됨을 명시한다.
- 헤더 하단 border 색상 표시가 정렬·필터·고정·리사이즈·드래그앤드롭 표시와 공존한다는 점을 명시한다.

### 3. 문서-코드 정합성 재검증

- 문서 작성 과정에서 실제 `GridCell.tsx`, `GridHeader.tsx`, `grid.types.ts`, `grid.utils.ts` 코드를 재확인하여 문서 설명과 실제 동작이 다르면 문서를 코드 기준으로 정정한다.
- 코드에 명백한 결함(예: 타입 정의는 있으나 실제 반영되지 않는 경로)이 발견되면 별도로 사용자에게 보고하고, 코드 수정이 필요한지 확인한 뒤 진행한다(현재까지 확인된 범위에서는 코드 수정 필요성이 발견되지 않음).
