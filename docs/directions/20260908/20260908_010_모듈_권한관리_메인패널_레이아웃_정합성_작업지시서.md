# 작업지시서

## 제목

모듈관리·권한관리 메인 패널 외곽 레이아웃을 메뉴관리 패널 기준으로 통일

## 작업 분류

- 경로: `bounded`
- 사유: 모듈관리와 권한관리의 메인 패널 감싸기 구조가 메뉴관리 패널과 달라 패딩, 높이, overflow 및 카드 외곽 정렬이 화면별로 다르게 보이는 문제를 정리한다. 기존 화면 기능과 데이터 흐름은 유지하고 레이아웃 책임만 조정한다.

## 배경

현재 메뉴관리 패널은 다음 외곽 구조를 사용한다.

- 바깥 `Box`: 반응형 패딩, `flex: 1`, `height: 100%`, `overflow: hidden`
- `Card`: 전체 높이 확장, 세로 flex, 테두리와 `borderRadius: 1`
- `CardContent`: 콘텐츠 영역 전체 확장, 내부 overflow 제어

반면 모듈관리 패널은 `Card`부터 시작하고, 권한관리 패널은 2열 `grid Box`부터 시작하여 화면별 외곽 패딩·카드 반경·높이 확장 방식이 다르다. 사용자는 세 화면의 메인 패널 영역이 동일한 기준으로 감싸지기를 요청했다.

## 목표

1. 모듈관리 메인 패널의 외곽 감싸기 구조를 메뉴관리 패널 기준으로 정렬한다.
2. 권한관리 메인 패널의 최상위 감싸기와 카드 콘텐츠 영역을 메뉴관리 패널 기준으로 정렬한다.
3. 권한관리의 목록 카드와 사용자 매핑 카드 2열 기능 구조는 유지한다.
4. F1-Grid/F1-Tree의 데이터, CRUD, 권한, 로딩 및 이벤트 동작은 변경하지 않는다.
5. 모바일·태블릿·데스크톱에서 의도하지 않은 페이지 가로 스크롤이나 콘텐츠 잘림이 발생하지 않도록 기존 반응형 규칙을 유지한다.

## 요구사항

### 1. 모듈관리 패널

- `ModuleManagementPanel.tsx`에 메뉴관리 패널과 동등한 외곽 `Box` 레이어를 적용한다.
- 외곽 `Box`는 메뉴관리 패널의 `p`, `minWidth`, `flex`, `display`, `flexDirection`, `height`, `overflow` 동작을 기준으로 한다.
- 기존 모듈관리 `Card`와 `CardContent` 내부의 제목, 그리드, 로딩, 컨텍스트 메뉴, 저장 상태 동작은 유지한다.
- 메뉴관리 패널과 동일한 카드 외곽 기준을 적용하되, 모듈관리의 단일 카드 구조는 유지한다.

### 2. 권한관리 패널

- `RoleManagementPanel.tsx`의 최상위 레이아웃을 메뉴관리 패널과 같은 외곽 Box 기준으로 정리한다.
- 권한 목록과 권한별 사용자 매핑의 2열 카드 구조 및 `lg` 이하 1열 전환은 유지한다.
- 내부 카드의 제목, 그리드, 선택 역할 표시, 사용자 매핑 조회/저장 및 로딩 동작은 변경하지 않는다.
- 메뉴관리 패널과 시각적 정합성을 위해 카드 테두리, 반경, 콘텐츠 패딩, 높이 확장 및 overflow 적용을 동일 기준으로 조정한다.

### 3. 반응형 기준

- 최소 뷰포트 `375px`, `768px`, `1280px`에서 레이아웃을 확인한다.
- 작은 화면에서 권한관리 2열 영역은 기존처럼 1열로 전환한다.
- 패널 내부의 그리드가 페이지 전체 가로 스크롤을 유발하지 않도록 패널 높이·overflow 경계를 유지한다.

## 접근 방식 비교

### 권장안: 메뉴관리 패널 외곽 레이아웃을 공통 기준으로 직접 정렬

- 장점: 사용자가 지정한 기준 화면과 즉시 일치하고 변경 범위가 작다.
- 장점: 기존 컴포넌트 구조와 F1-Grid/F1-Tree 책임을 유지한다.
- 단점: 세 패널의 공통 스타일을 별도 컴포넌트로 추상화하지 않으므로 일부 `sx` 중복이 남는다.
- 판단: 이번 요청은 외곽 레이아웃 정합성 수정이므로 가장 안전한 선택이다.

### 대안 1: 공통 `ManagementPanelShell` 컴포넌트로 추출

- 장점: 이후 관리 화면 추가 시 스타일 재사용이 쉽다.
- 단점: 권한관리의 2열 레이아웃과 모듈관리 단일 카드의 구조 차이를 추상화해야 하며, 이번 요청보다 변경 범위와 회귀 위험이 커진다.
- 판단: 이번 작업에서는 과도한 구조 변경으로 제외한다.

### 대안 2: 페이지 상위 컨테이너만 조정

- 장점: 수정 파일 수가 줄어든다.
- 단점: 실제 차이를 만드는 패널 내부의 카드/콘텐츠 감싸기 불일치를 해결하지 못한다.
- 판단: 요청한 “메인 패널과 감싸는 부분” 정합성을 충족하지 못하므로 제외한다.

- 모듈관리·권한관리의 CRUD/API/권한 정책 변경
- F1-Grid/F1-Tree 공통 컴포넌트 리팩터링
- 권한관리의 2열 기능 구조 제거 또는 재설계
- 대시보드 상위 레이아웃 및 라우팅 변경

## 완료 기준

- 모듈관리 메인 패널이 메뉴관리 패널과 같은 외곽 감싸기 기준으로 렌더링된다.
- 권한관리 메인 패널의 외곽 감싸기와 카드 콘텐츠 기준이 메뉴관리 패널과 일관된다.
- 권한관리의 목록/사용자 매핑 기능과 반응형 2열→1열 동작이 유지된다.
- 메뉴·모듈·권한 화면에서 기존 조회, 편집, 저장, 삭제, 로딩 동작의 회귀가 없다.
- 프론트엔드 빌드와 관련 테스트를 실행하고 결과를 기록한다.
- 최소 `375px`, `768px`, `1280px` 브라우저 뷰포트에서 패널 겹침, 잘림, 의도하지 않은 페이지 가로 스크롤이 없음을 확인한다.

## 승인 필요 사항

이 작업지시서의 목표와 범위가 승인되면 다음 단계에서 계획서와 상세 사양서를 작성한다. 명시 승인 전에는 계획서, 사양서, 워크트리, 테스트, 코드 수정, 빌드, 배포를 진행하지 않는다.
