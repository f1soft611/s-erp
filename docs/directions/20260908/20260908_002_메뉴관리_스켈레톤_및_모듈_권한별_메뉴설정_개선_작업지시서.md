# 작업지시서

## 제목

메뉴관리 페이지 스켈레톤 UI 적용 및 모듈/권한별 메뉴 설정 개선

## 작업 분류

- 경로: `bounded`
- 사유: 메뉴관리 페이지에 권한관리 페이지 패턴의 F1-Grid/F1-Tree 스켈레톤 UI를 적용하고, 상단 검색 조건에 [모듈 선택] > [권한 선택] 순서의 연차 선택 구조를 도입하여 모듈별·권한별 메뉴 및 기본기능 버튼권한을 설정할 수 있도록 개선한다.

## 배경

현재 메뉴 관리 화면은 모듈 단일 선택 조건만 존재하며 메뉴 마스터 및 모듈별 메뉴 허용 버튼 권한(`tb_menu_permission`)을 다루고 있다. 하지만 권한 관리 페이지와 달리 조회 시 F1-Grid 스켈레톤 UI가 적용되어 있지 않아 사용자 경험의 일관성이 부족하다.

또한 실제 서비스 환경에서 사용자는 복수의 역할/권한(Role)을 가질 수 있고, 특정 권한에 특정 메뉴 및 버튼 권한(조회, 등록, 수정, 삭제, 엑셀 등)이 부여되어 있으면 해당 기능이 활성화되는 권한 체계를 갖추고 있다. 따라서 메뉴 관리 화면 상단 검색 조건에서 [모듈 선택] 후 [권한 선택]을 수행하고, 선택한 권한(Role) 관점에서 모듈별 메뉴 및 버튼 권한을 설정/저장할 수 있는 기능이 필요하다.

## 목표

1. **F1-Grid 스켈레톤 UI 적용**: 권한 관리 페이지와 동일하게 최초 조회 및 검색 조건 변경 시 F1-Grid/F1-Tree 스켈레톤 로딩 상태를 제공한다.
2. **모듈선택 > 권한선택 상단 검색 조건 구축**: `PageSearchArea`에 [모듈 선택] Select 후 [권한 선택] Select가 순차 동작하도록 배치한다.
3. **모듈별 · 권한별 메뉴 및 버튼 권한 설정**: 선택된 모듈과 권한(Role)을 기준으로 해당 권한에 부여된 메뉴 활성화 여부 및 기본기능 버튼권한(READ, CREATE, UPDATE, DELETE, EXCEL 등)을 조회·편집·저장할 수 있게 구성한다.
4. **다중 권한 활성화 정책 지원**: 사용자가 여러 개의 권한을 가질 때 그 중 하나의 권한에라도 해당 메뉴 및 버튼 권한이 포함되어 있으면 활성화될 수 있는 권한 매핑 데이터 정합성을 제공한다.

## 요구사항

### 1. F1-Grid/F1-Tree 스켈레톤 UI

- `MenuManagementPage` 및 `MenuManagementPanel`에 `loading` (스켈레톤) 상태를 도입한다.
- 최초 진입, 모듈 변경, 권한 변경 시 스켈레톤 UI를 노출하여 권한 관리 페이지와 일관된 로딩 경험을 선사한다.

### 2. 상단 검색 조건 (모듈 선택 > 권한 선택)

- `PageSearchArea` 내에 [모듈 선택] Dropdown과 [권한 선택] Dropdown을 순차 배치한다.
- 모듈을 변경하면 해당 모듈에 관련된 권한 목록(또는 전체 역할 목록)이 갱신되며, 권한을 선택하면 해당 (모듈, 권한) 기준 메뉴 데이터가 로드된다.

### 3. 모듈별 / 권한별 메뉴 및 버튼 권한 설정

- F1-Tree / F1-Grid 구조에서 메뉴 항목별로 권한 활성화 여부 및 버튼 권한(조회, 등록, 수정, 삭제, 엑셀) 체크박스를 제공한다.
- 사용자 저장 시 선택한 권한(Role)에 대한 메뉴 및 버튼 권한 매핑 정보가 정상적으로 백엔드/서비스에 저장된다.

### 4. 다중 권한 지원 및 활성화 검증

- 권한 매핑 구조는 N:M 사용자-역할, 역할-메뉴-권한 매핑을 지원한다.
- 사용자가 속한 복수 권한 중 하나라도 권한을 가지고 있으면 해당 메뉴와 버튼 기능이 활성화되도록 기존 권한 유틸리티/서비스와 정합성을 유지한다.

## 검증 조건

1. 메뉴 관리 페이지 진입 및 모듈/권한 변경 시 F1-Grid 스켈레톤 UI가 정상 노출되는지 확인한다.
2. 상단 검색 영역에서 [모듈 선택] 후 [권한 선택]이 정상 동작하는지 UI/유닛 테스트로 검증한다.
3. 선택된 권한에 대해 메뉴 및 버튼 권한을 수정 후 저장했을 때 데이터가 유지되는지 확인한다.
4. Vitest 유닛 테스트 및 필요 시 Playwright UI 스크린샷 캡처로 검증을 완료한다.
