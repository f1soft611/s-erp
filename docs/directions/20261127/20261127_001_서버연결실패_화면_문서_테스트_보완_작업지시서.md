# 서버 연결 실패 화면 문서·테스트 보완 작업지시서

- 작성일: 2026-11-27
- 근거: [2026-11-27 개발 진행현황](../../result/20261127/development-progress/20261127_001_S-ERP_개발_진행현황_관리.md) 미해결 이슈 1번. 커밋 `b176b9e8`·`95364d37`·`45d2f1a5`·`7e25c378`(PR #98)은 작업지시서·계획·사양·결과 문서와 전용 테스트 없이 병합되었다.
- 사용자 지시(2026-11-27): 미해결 이슈를 서버 연결 실패 화면부터 진행하고, 테스트는 로컬에서 진행한다.

## 요청

이미 구현된 "서버 연결 실패 시 페이지 오류 화면" 공통 처리와 영업관리 10개 화면 적용에 대해 사후 문서를 정리하고 회귀 테스트를 추가한다.

## 범위

- 공통: `useInitialLoadState`(`networkOnly`, `toPageLoadError`), `isApiNetworkError`, `usePolicyDecimalStatus().network`, `SalesDecimalPolicyError`의 `network`
- 화면: 견적등록, 수주등록, 출하계획등록·현황, 출하등록·현황, 거래명세서등록·현황, 매출마감, 납품처관리
- 운영 코드 동작은 변경하지 않는다. 테스트 작성 중 문서 규칙과 다른 동작이 발견되면 별도 이슈로 기록한다.

## 완료 기준

1. 작업지시서·계획서·상세사양서·결과 문서가 날짜 폴더에 있다.
2. 공통 함수의 오류 분류와 `networkOnly` 동작이 단위 테스트로 검증된다.
3. 10개 화면 각각에서 초기 조회가 서버 연결 실패이면 헤더는 유지되고 본문에 페이지 오류 화면 하나만 보이며, 다른 오류 문구(`소수점 정책을 불러오지 못했습니다` 등)는 보이지 않는다.
4. 각 화면의 다시 시도 버튼이 서버 조회를 다시 실행한다.
5. 서버 오류(500)는 `networkOnly` 화면에서 페이지 오류 화면으로 바뀌지 않는다.
6. 추가한 테스트가 해당 동작을 일부러 깨뜨렸을 때 실패하는지 확인한다.
7. 로컬에서 프론트 빌드와 관련 테스트를 실행한다.
