## 요청

현황 화면의 수정 창에서 저장·삭제한 뒤 목록을 다시 조회할 때, 기준 화면(출하현황)처럼 목록 그리드 로딩 표시 없이 조용히 갱신한다.

## 현황 조사

| 현황 화면 | 저장·삭제 후 목록 | 저장 중 | 판단 |
| --- | --- | --- | --- |
| 출하현황(기준) | `quietRefresh` → 로딩 표시 없음 | 수정 창 버튼만 | 적용됨 |
| 견적서현황·수주현황 | `refreshListQuietly` | 수정 창 버튼만 | 적용됨 |
| 거래명세서현황 | `setRefresh` → `setLoading(true)` | 수정 창 버튼만 | **미적용** |
| 출하계획현황 | `runSearch` → `setLoading(true)` | 페이지 `loading` 사용(목록 로딩·검색 잠김) | **미적용** |

상세 패널은 모든 화면에서 데이터가 없을 때만 로딩을 표시해(`loading && item === null`) 대상이 아니다.

## 완료 기준

1. 거래명세서현황: 수정 창 저장·삭제 후 목록 재조회 중 그리드 `aria-busy`가 켜지지 않고 기존 행이 유지된다. 사용자가 누른 조회·다시 시도는 기존처럼 로딩을 표시한다.
2. 출하계획현황: 수정 창 저장 중과 저장 후 재조회 중 목록 그리드에 로딩이 표시되지 않는다. 저장 중에는 수정 창의 저장·취소 버튼과 입력만 잠긴다.
3. 실패하는 테스트를 먼저 추가하고 구현 후 통과를 확인한다.
4. 로컬 브라우저에서 저장 후 목록 갱신을 확인한다.
