# 20261020_006 커뮤니티 자료실 파일/폴더 그리드 개선 작업지시서

## 1. 목적

`/groupware/community/archive`를 게시글 중심 화면에서 파일 브라우저형 자료실로 개선한다. 기존 `tb_board_post`, `tb_common_file`, `WF_ARCHIVE_CATEGORY` 공통코드를 유지하고, 분류를 폴더로 표시하며 실제 파일 하나당 그리드 행 하나를 제공한다.

## 2. 사용자 승인 사항

- `WF_ARCHIVE_CATEGORY` 공통코드 항목을 1단계 폴더로 사용한다. 폴더 추가/수정은 기존 `CommonCodeItemHelpDialog` 패턴을 사용한다.
- 루트에는 폴더와 루트에 직접 올린 파일을 함께 표시한다. 폴더 선택 시 해당 폴더 안으로 이동하고 경로/뒤로 이동을 제공한다. 중첩 폴더는 제공하지 않는다.
- 그리드 컬럼은 이름, 소유자, 올린 날짜, 크기, 행 작업으로 구성한다. 즐겨찾기 기능은 추가하지 않는다.
- `새 자료 등록`을 누르면 바로 운영체제 파일 선택창을 연다. 파일 선택 후 별도 정보 입력이나 확인 화면 없이 업로드한다. 여러 파일을 선택할 수 있고 파일마다 독립된 게시글/파일 행으로 생성한다.
- 새 파일의 `tb_board_post.title`은 원본 파일명으로 자동 설정한다. 루트 업로드는 `category_code`가 비어 있고, 폴더 안 업로드는 현재 폴더 코드가 저장된다. 파일 없는 신규 자료 등록은 허용하지 않는다.
- 업로드 후 파일별 더보기에서 이름 변경과 폴더 이동을 제공한다. 새 자료 등록과 이름/폴더 변경은 별도 흐름이다.
- 비활성 폴더와 기존 파일은 계속 조회/다운로드할 수 있으나 업로드, 이름 변경, 이동, 삭제는 금지한다.
- 기존 여러 첨부 게시글은 자료를 삭제하거나 복제하지 않고 파일별 행으로 표시한다. 첨부 하나를 다른 폴더로 이동하면 그 파일만 새 게시글에 재연결한다.
- 활성 첨부가 없는 기존 자료 게시글은 논리 삭제하여 화면에서 제거한다. 실제 행/파일은 물리 삭제하지 않는다.

## 3. 확인된 현재 구조

- `tb_board_post`에는 `board_type_code`, `title`, nullable `category_code`, tenant/writer 메타데이터 및 soft-delete 상태가 있다.
- `tb_common_file`에는 tenant, `owner_type`, `owner_id`, `file_name`, `file_size`, uploader, 생성 시각, soft-delete 상태가 있다. 현재 자료실 서비스는 `owner_type='ARCHIVE'`, `owner_id=post_id`로 게시글에 파일을 연결한다.
- 현재 자료실 목록 API는 게시글 기준이고, 게시글 생성 API는 파일 첨부 없이 호출 가능하며 서버 검증상 분류도 필수다. 파일 브라우저 동작을 위해 파일별 목록/직접 업로드/루트 분류 생략을 지원하는 API 변경이 필요하다.
- 현재 자료실 페이지에서만 게시글 생성/목록 서비스를 호출한다. API 변경 전 저장소 전체에서 사용처를 다시 검색하고 다른 소비자가 있으면 호환 정책을 명시한다.
- 기본 PostgreSQL 읽기 전용 MCP에서 관련 테이블 목록과 컬럼 메타데이터를 확인했다. 실제 데이터 행/개인정보는 조회하지 않았다.

## 4. 작업 범위

### 포함

1. 파일별 행 목록과 폴더/루트 탐색을 제공하는 자료실 화면
2. 즉시 파일 선택/업로드, 다중 선택의 파일별 처리 상태
3. 공통코드 폴더 관리와 비활성 폴더의 읽기 전용 표시
4. 파일 이름 변경, 폴더 이동, 다운로드, 삭제
5. 파일별 목록, 업로드, 이름/폴더 변경, 마지막 첨부 삭제 시 게시글 정리, 기존 파일 없는 게시글 soft-delete를 지원하는 자료실 백엔드
6. 기존 테이블을 유지하고 날짜별 데이터 정리 SQL/변경 이력/롤백 파일 기록
7. 프론트엔드/백엔드 회귀 테스트, 브라우저 반응형 확인, 결과 문서 및 스크린샷

### 제외

- 새 폴더/파일 테이블이나 새 공통코드 그룹
- 폴더 중첩, 즐겨찾기, 미리보기, 일괄 다운로드, 댓글, 서식 있는 본문
- 공지사항 및 다른 게시판의 API/화면 변경
- 다른 게시판을 위한 범용 파일관리 프레임워크

## 5. 완료 기준

- 루트 및 폴더 안에서 파일을 파일별 행으로 조회하고 이름/소유자/올린 날짜/크기를 확인할 수 있다.
- `새 자료 등록`은 파일 선택창부터 시작하며, 선택 후 입력 다이얼로그 없이 업로드한다. 다중 파일은 파일별 성공/실패가 명시되고 실패 항목을 재시도할 수 있다.
- 신규 파일은 파일명으로 게시글 제목이 생성되고, 루트 업로드는 분류 null, 폴더 업로드는 해당 분류 코드로 저장된다. 파일 없는 게시글은 신규 생성할 수 없다.
- 활성 폴더 파일은 권한에 따라 이름/폴더 변경, 삭제, 다운로드가 가능하다. 비활성 폴더 파일은 다운로드만 가능하다.
- 기존 게시글의 다중 첨부는 파일 행으로 표시되고, 파일 하나의 폴더 이동이 다른 첨부의 소속을 바꾸지 않는다.
- 첨부 없는 기존 자료 게시글은 `is_deleted='Y'`로 논리 삭제된다. 공지 및 다른 게시판의 데이터는 영향받지 않는다.
- 모든 조회/변경/다운로드 요청은 인증 tenant, `ARCHIVE` 게시판, 파일 소유권 및 기존 관리자 정책으로 서버에서 검증된다.
- 관련 Vitest, Maven 테스트, 프론트엔드 빌드 및 `git diff --check`가 통과한다. 브라우저 375px/768px/1280px 확인 및 결과 문서/스크린샷을 남긴다.

## 6. 실행 순서와 안전 중단점

1. 이 작업지시서에 따라 구현 계획서와 상세사양서를 확정한다.
2. 승인된 문서 기준으로 백엔드 파일 API와 테스트를 먼저 구현한다.
3. 프론트엔드 업로드/폴더 탐색/행 작업을 연결하고 관련 F1-Grid 문서를 갱신한다.
4. 기존 자료 정리 SQL을 작성하되 실제 적용 전 영향 건수와 대상 tenant 범위를 읽기 전용으로 확인하고 백업/배포 순서를 승인받는다. 확인이 불가능하면 정리 SQL 적용을 진행하지 않고 미확인 사실을 결과 문서에 기록한다.
5. 기능 검증 및 브라우저 검증 후 결과 문서와 캡처를 남긴다.

공유 워크트리에는 문서현황/결재선 등 이 작업과 무관한 변경이 존재한다. 본 작업 범위 밖의 파일은 수정·스테이징·커밋하지 않는다.
