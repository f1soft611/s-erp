# 20261020_008 문서현황 검색조건 세션 복원 작업지시서

## 목적

문서현황 페이지를 나갔다가 같은 브라우저 탭 세션에서 재진입해도 마지막으로 검색 실행한 조건을 복원하고 같은 조건으로 다시 조회한다.

## 승인된 요구사항

- 실제 검색 실행 시 적용된 빠른 검색어와 F1-Grid 상세검색 값만 저장한다.
- 검색하지 않고 변경한 입력값은 저장하지 않는다.
- 재진입 시 저장된 검색 입력을 표시하고 같은 필터로 즉시 조회한다.
- 검색 조건 초기화는 검색어와 결재신청일 외 상세검색 값을 비우고, 결재신청일은 초기 진입과 동일한 최근 1개월 기본 범위로 되돌려 즉시 조회한다. 해당 기본 날짜 범위를 포함한 초기화 상태를 세션에 저장하여 재진입 후에도 유지한다.
- 새로운 탭 세션에서 저장값이 없으면 기존 최근 1개월 결재신청일 범위 및 초기 조회 동작을 유지한다.
- 행 선택, 상세 패널, 그리드 레이아웃은 저장하지 않는다.
- 공통 `usePageSessionState`를 사용하고 화면 전용 key 및 버전 검증을 둔다.

## 범위

- 문서현황 검색 입력/적용 필터의 페이지 세션 상태 연동
- 검색 실행, 미적용 입력, 초기화, 재진입 및 기본 날짜 범위 테스트
- F1-Grid 사용자 문서와 날짜별 계획/사양/결과 문서 갱신
- 백엔드 API 및 DB 스키마는 변경하지 않는다.

## 구현 절차

1. 문서현황 페이지 테스트에 세션 복원·저장 계약의 실패 사례를 먼저 추가하고 red를 확인한다.
2. 기존 `usePageSessionState` 패턴으로 검색 스냅샷 타입, validator, 전용 session key를 적용한다.
3. 검색 실행에서만 스냅샷을 저장하고, 재진입 시 동일한 스냅샷으로 검색 필드 및 목록 조건을 복원한다.
4. 초기화 동작에서 검색어와 나머지 상세검색 조건을 비우고, 최신 최근 1개월 결재신청일 범위를 적용·저장하여 과거 조건이 복원되지 않게 한다.
5. 관련 Vitest, 프런트엔드 빌드, diff 검증을 실행한다.
6. 결과 문서에 변경 및 검증 내용을 기록한다.

## 완료 기준

- 동일 탭 세션에서 재진입할 때 마지막 검색 실행 조건이 검색 입력과 API 요청에 동일하게 복원된다.
- 검색 실행 전의 입력 변경은 세션 상태를 오염시키지 않는다.
- 초기화 후 결재신청일은 최근 1개월 기본 범위로 표시·조회되고, 다른 조건은 비워지며, 재진입 시에도 같은 검색 상태가 유지된다.
- 새 세션 첫 방문에도 기존 최근 1개월 기본값이 유지된다.
- 유효하지 않거나 구버전인 세션 값은 안전하게 초기 기본값으로 대체된다.
- 관련 테스트 및 빌드가 통과하고 결과 문서가 갱신된다.
