# 문서작성 공통 파일형 보기 작업지시서

## 사용자 요구 및 승인

- 문서작성의 피드형·리스트형에 파일형을 추가한다.
- 내가 작성하거나 결재·합의·참조로 포함된 문서의 파일을 보여준다.
- 사용자 확인에 따라 문서 직접 첨부와 댓글 첨부를 모두 포함한다.
- 첨부 이미지의 파일명·소유자·올린 날짜·크기 표 구성을 따른다.
- 파일 업로드 최신순으로 최초 20개, 스크롤 하단에서 다음 20개를 자동 조회한다.
- 서버 파일 전용 페이지 조회와 재사용 가능한 공통 파일형 컴포넌트 방식을 승인받았다.

## 승인 설계

- 파일명 클릭은 기존 경로로 다운로드하며 별도 원문 보기로 기존 문서 상세를 연다.
- 기존 문서 접근 권한과 업무구분·조회범위 필터를 유지한다.
- 본문 삽입 이미지, 폴더, 즐겨찾기는 이번 범위에서 제외한다.
- 파일형에는 문서 상단고정 순서를 적용하지 않는다.
- 다른 페이지의 기존 피드·리스트 보기에는 파일형을 자동 노출하지 않는다.

## 작업 순서

1. 이 작업지시서에 따라 계획서를 작성한다.
2. 계획서에 따라 상세 사양서를 작성하고 사용자 검토를 받는다.
3. 관련 회귀 테스트를 추가하고 실패를 확인한 뒤 구현한다.
4. 프론트엔드와 백엔드 대상 테스트 및 프론트엔드 빌드를 수행한다.
5. 375px, 768px, 1280px 실제 브라우저 검증과 스크린샷을 결과에 기록한다.
6. DB 스키마 변경 여부를 점검하고 변경 시 날짜별 SQL·이력·롤백을 관리한다.

## 범위 통제

- 기존 미커밋 문서현황·업무연락 변경을 보존한다.
- 문서·댓글 전체를 불러와 클라이언트에서 20개씩 숨기는 구현은 하지 않는다.
- 계정·인증·테넌트 데이터 행이나 저장소 연결 정보를 문서와 출력에 남기지 않는다.

## 후속 누락 수정 지시

- 파일형이 빈 목록을 표시하더라도 기존 관련 문서/댓글에 첨부파일이 있으면 누락 원인을 확인한다.
- 파일 조회에 임시저장 기본값이 불필요하게 전달되지 않도록 한다.
- ALL은 문서 상태와 무관하게 기존 권한의 모든 관련 문서 첨부를 포함한다. 명시적인 scope 필터와 접근 권한은 유지한다.
- 실사용 파일명·본문·작성자·계정/tenant 정보를 출력하거나 스크린샷으로 저장하지 않고 개수와 일치 여부로 확인한다.

## 파일형 표시 보완 지시

- 사용자 승인에 따라 마지막 페이지의 `모든 파일을 불러왔습니다.` 문구를 제거한다.
- 공통 파일형 그리드 머리글·행 영역의 기본 배경을 흰색으로 지정한다.
- 페이지 전체 배경, 행 hover, 로딩·오류·빈 목록 표시 및 자동 조회 종료 동작은 유지한다.
