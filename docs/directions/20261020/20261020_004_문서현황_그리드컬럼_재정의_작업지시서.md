# 20261020_004 문서현황 그리드 컬럼 재정의 작업지시서

## 목적

문서현황 그리드의 식별 정보와 결재 참여 정보를 실무 목적에 맞게 재정의하고, F1-Grid 상세검색을 같은 데이터 계약에 맞춘다.

## 승인된 요구사항

- `eabus_no`는 문서유형별 구분 코드다. 문서번호 표시는 `electronicApprovalId`로 한다.
- 문서종류는 `documentType`을 사용하며, 목록에서 구분 코드와 중복 표시하지 않는다.
- 결재 참여자 전체 이름 나열 컬럼을 제거한다.
- 대신 현재 결재단계·담당자와 현재 로그인 사용자의 결재 역할·처리상태를 그리드에 표시한다.
- 상세검색은 F1-Grid 컬럼의 검색 메타데이터에서 생성한다. 문서번호, 종류, 상태, 신청일, 제목, 기안자/부서, 내 역할/처리상태, 현재 결재담당자 및 최종 변경일을 검색할 수 있다.
- 빠른검색의 문서번호 조건은 `electronicApprovalId`에 적용한다.
- 기존 상세조회 패널의 전체 결재선, 댓글, 첨부 및 권한별 작업은 그대로 둔다.
- 새 DB 스키마는 만들지 않는다. 현재 결재선 테이블의 기존 열을 사용한다.
- 기존 작업트리의 미커밋 변경은 보존한다.

## 범위

- 프런트엔드 문서현황 행 타입, 컬럼/검색 metadata, 조회 필터 전송 및 테스트
- 백엔드 목록 query DTO, 입력 검증, 목록/건수 필터 및 결과 투영, Mapper 테스트
- F1-Grid 문서와 날짜별 계획/사양/결과 문서 갱신

## 완료 기준

- 표시되는 문서번호가 결재 문서 PK와 일치하며 eabus 유형 코드는 문서번호로 오표시되지 않는다.
- 선택 행의 종류, 상태 및 결재 검색 필드가 정확한 필드/API 파라미터에 연결된다.
- 참여자 요약 대신 현재 결재단계·담당자 및 내 역할·처리상태를 확인할 수 있다.
- 상세검색 결과 건수와 페이지 행이 동일한 필터를 적용한다.
- tenant 및 사용자 권한, 기존 목록/상세/댓글/첨부 흐름에 회귀가 없다.
- 관련 테스트와 프런트엔드 빌드가 통과하며 결과 문서를 작성한다.
