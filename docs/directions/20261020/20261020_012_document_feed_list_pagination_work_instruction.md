# 문서작성 피드형·리스트형 서버 페이징 작업지시서

## 사용자 요구 및 승인

- 문서작성 화면의 피드형과 리스트형 목록도 파일형처럼 자동 페이징한다.
- 서버에서 최신 수정 문서를 20개씩 가져오고, 실제 문서 목록 스크롤 시 다음 페이지를 자동 조회한다.
- 다음 페이지 로딩 중 기존 카드·행은 유지하고 텍스트 없이 접근성 라벨이 있는 스피너를 표시한다.
- 최초 목록 로딩의 기존 스켈레톤, 필터, 상세 보기, 요약 패널, 오류 재시도 및 빈 목록 동작은 유지한다.
- 필터 변경과 명시적 새로고침은 첫 페이지부터 다시 조회한다.
- 피드형의 댓글·첨부·결재선 상세는 현재 요청 페이지 문서에 대해서만 구성한다.
- 사용자는 개인별 고정/해제 기능을 별도 테이블·API로 먼저 구현하고, 그 뒤 페이징을 적용하는 2단계 설계를 승인했다.
- 개인별 고정 문서 전체는 현재 사용자·권한·scope·업무구분 조건으로 별도 조회하며, 일반 문서의 20개 페이지 제한에서 제외한다.
- 리스트형은 고정 문서를 별도 패널에 유지하고, 피드형은 고정 문서를 일반 피드보다 먼저 표시한다.
- 고정/해제 아이콘은 공지 피드의 PushPin 액션 위치를 따른다.
- 통합 설계 문서 [Personal Document Pins and Feed/List Pagination Design](../../superpowers/specs/2026-10-20-document-pin-and-feed-list-pagination-design.md)은 사용자가 검토·승인했다.

## 승인 설계

- 선행 작업에서 개인별 고정 테이블과 pin/unpin/고정 목록 API를 구현하고, 기존 문서 조회 API의 서버 offset/limit 페이지 흐름을 재사용한다.
- 페이지 크기는 20으로 고정하고 최신 수정일 내림차순, 문서 ID 내림차순으로 안정 정렬한다.
- 응답은 기존 `resultList`와 `totalRowCount` 형식을 사용하고, 클라이언트가 다음 페이지 여부를 계산한다.
- 피드형은 페이지의 문서 ID만 상세·결재선·첨부·최신 댓글 조회에 전달한다.
- 공유 `FeedView`/`ListView`는 선택적 자동 로딩 기능을 제공하되, 기존 사용처의 기본 동작을 바꾸지 않는다.
- DB 스키마 변경은 개인별 고정 테이블 한 건에 한정한다. 별도 pin 관리 기능은 선행 하위 작업으로 수행한다. 전체 목록을 클라이언트에서만 나누는 구현은 제외한다.

## 작업 순서 및 완료 기준

1. 선행 개인별 고정 기능의 작업지시서·계획서·상세 사양서를 별도 작성·검토하고 먼저 완료한다.
2. 이 작업지시서에 따라 페이징 계획서와 상세 사양서를 작성하고 사용자의 문서 검토를 받는다.
3. 백엔드 API 계약 변경 전 기본 읽기 전용 DB MCP의 `list_tables`와 필요한 테이블의 `describe_table`을 직접 확인한다. DB MCP 실패 시 이를 결과 문서에 기록하고 Mapper·도메인 코드 등 대체 근거를 구분한다.
4. 페이지 경계, 필터 유지, pinned 제외, 피드 페이지 범위 상세 조회, 오류 재시도 및 중복 스크롤 요청을 검증하는 실패 테스트를 먼저 추가한다.
5. 백엔드 페이지 조회와 프론트엔드 상태·공유 보기 연결을 구현한다.
6. 수정 파일에 한정한 프론트엔드·백엔드 테스트와 프론트엔드 빌드를 수행한다.
7. 기존 4173 개발 서버를 확인 후 재사용해 375px, 768px, 1280px에서 자동 로딩·스피너·가로 넘침을 확인한다. 기존 서버는 임의로 종료하지 않는다.
8. `docs/result/20261020/document-feed-list-pagination`에 결과 문서와 스크린샷을 기록한다.
9. DB 스키마 변경 여부와 현재 MCP 확인 근거를 기록하고, 기존 미커밋 변경은 보존한다.

## 영향 범위

- 프론트엔드: 문서작성 페이지 훅·API 서비스·타입·페이지 조립, 공통 `FeedView`/`ListView`, 관련 Vitest.
- 백엔드: 전자결재 문서 목록 API, 서비스, DAO/MyBatis 페이지 쿼리, 관련 JUnit. 핀 테이블·API는 선행 하위 작업에서 관리한다.
- 문서: 날짜별 계획서·상세 사양서·결과서 및 공통 보기 동작 문서.
- pagination 하위 작업 자체에는 DB 스키마 변경이 없다. 선행 pin 하위 작업에서 별도 날짜별 SQL·변경 이력·롤백과 누적 스키마 문서를 작성한다.
