# 댓글 첨부 이미지 분리 미리보기 작업지시서

## 사용자 요구 및 승인

- 문서작성과 공지작성의 댓글에 등록된 이미지 첨부를 파일 목록의 인라인 썸네일로 표시하지 않는다.
- 이미지 파일도 첨부파일 목록에서는 파일명과 파일 아이콘이 있는 일반 파일 항목으로 표시한다.
- 첨부파일 목록 아래에 본문 이미지 미리보기와 같은 별도 썸네일 영역을 표시한다.
- 썸네일을 클릭하면 기존 이미지 확대 뷰어를 연다.
- 이미 등록된 댓글과 답글의 이미지도 포함하며, 이전 댓글 조회 방식과 범위는 바꾸지 않는다.

## 승인 설계

- 공통 댓글 컴포넌트에서 첨부파일 목록과 이미지 썸네일 영역을 분리한다.
- 문서 댓글은 현재 사용하는 인증 Blob 미리보기 URL 생성 흐름을 재사용한다.
- 공지 댓글은 기존 인증된 공통 파일 조회 경로를 사용하고 댓글 파일 MIME 정보를 UI 모델에 보존한다.
- 이미지 미리보기 로드 실패 시 파일 다운로드는 유지하고 미리보기 오류를 별도로 알린다.
- API 저장 계약과 데이터베이스는 변경하지 않는다.

## 작업 순서

1. 이 작업지시서에 따라 계획서를 작성한다.
2. 계획서에 따라 상세 사양서를 작성하고 사용자 검토를 받는다.
3. 공통 댓글, 문서 댓글, 공지 댓글의 회귀 테스트를 추가하고 실패를 확인한 뒤 구현한다.
4. 관련 프론트엔드 테스트와 빌드를 수행한다.
5. 375px, 768px, 1280px 실제 브라우저 렌더링을 확인하고 결과 스크린샷을 저장한다.
6. 결과 문서에 재현 조건, 원인, 해결 내용, 회귀 검증을 기록한다.

## 범위 통제

- 댓글 첨부 업로드·삭제·다운로드, 댓글 편집, 답글, 권한 및 페이지네이션 동작은 변경하지 않는다.
- 미리보기는 현재 표시된 댓글과 답글에 이미 포함된 이미지 첨부를 대상으로 한다.
- 미리보기를 위해 이전 댓글을 자동으로 추가 조회하지 않는다.
- 댓글 본문 이미지와 문서/공지 본문의 이미지 표시 동작은 변경하지 않는다.
- DB 변경은 없다.

## 완료 조건

- 이미지 첨부의 파일 항목은 유지되고, 첨부 목록 안에 썸네일이 중복 노출되지 않는다.
- 이미지 미리보기는 첨부 목록 아래에 별도 표시되며 클릭 시 기존 확대 뷰어를 연다.
- 문서와 공지의 기존 댓글·답글 및 신규 댓글에서 동일하게 동작한다.
- 미리보기 URL의 수명 관리와 오류 표시가 검증된다.
- 관련 테스트, 빌드, 브라우저 화면 검증 및 결과 문서가 완료된다.
