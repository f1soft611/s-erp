# 20261117_001 입고등록 화면 작업지시서

## 작업 목적

가입고(MP) 다음 단계인 **입고(MI) 등록**을 만든다. 이번 작업의 핵심은 **무검사 품목의 자동 입고**다.
무검사 품목은 가입고를 저장하는 순간 입고가 같이 생기고, 이후 수정·취소는 입고에서만 처리한다.
검사 대상 품목의 입고(수입검사 합격분 불러오기)는 수입검사 작업에서 연결하므로, 이번에는 불러오기 창의 틀만 만든다.
기존 MES 입고등록(`WMA321_REMAKE_VW`, `TMA205/206`, `SP_WMA321_01/02/03_LIST·IUD`)은 업무 규칙 검토용으로만 참고하고, 화면 구조는 s-erp 기존 패턴(가입고등록/가입고현황)을 따른다.
MES는 불필요한 컬럼이 많아 **필요한 것만 담은 간소한 뼈대**를 만들고, 실무에서 필요해지면 그 위에 추가한다.

## 업무 흐름 (2026-11-16·17 사용자 확정)

발주(PO) → 가입고(MP) → [무검사] 가입고 저장 시 **입고(MI) 자동 생성** / [검사 대상] 수입검사(QI) → 입고(MI)

## 업무 규칙

### 입고 구성
- 입고 1건 = 구매처 1곳. 입고 행은 가입고 행을 참조한다(`tb_material_arrival_dt`).
- 한 가입고 행에 입고 여러 건(분할)이 가능한 구조다(유일 제약 없음). 다만 무검사는 가입고 행 1 : 입고 행 1로만 운영한다.
- 잔량 관리는 발주 기준 그대로다(발주수량 − 유효 가입고 합). 검사 대상의 입고 잔량(합격량 − 입고량)은 수입검사 작업에서 정한다.
- 입고수량·입고단가·입고창고·제조일·소비기한·비고를 입고 행에서 관리한다. 부가세는 가입고·발주와 같은 규칙(구분·포함 헤더, 공급가·세액·합계 저장)이다.
- 번호는 `MI-YYYYMMDD-NNNN`. LOCATION, 실입고량, 사용용도, 수주·생산 연결 정보, 도면번호, 매입마감, 재고·LOT 값은 이번에 관리하지 않는다(LOT번호 컬럼만 확보하고 비움).

### 무검사 자동 입고
- 가입고 저장 시 `inspect_at='N'`인 행으로 입고를 같은 트랜잭션에서 만든다. 같은 가입고의 무검사 행은 입고 헤더 1건으로 묶는다.
- 입고 헤더는 가입고의 구매처·통화·부가세 설정·담당자를 복사하고 입고일은 가입고일로 한다. 행의 수량·단가·금액·창고·제조일·소비기한은 가입고 행 값을 복사한다.
- 검사 대상 행은 입고를 만들지 않는다(수입검사 이후).

### 입고 수정·취소 (무검사는 가입고와 함께 움직인다)
- 입고 수정(수량·단가·세액·창고·제조일·소비기한·부가세 설정)은 연결된 무검사 가입고 행에도 반영하고 가입고 금액·헤더 합계를 다시 계산한다.
- 입고 수량이 발주 잔량을 넘으면 가입고와 같은 확인창(예/아니오)을 띄운다. 서버는 거부하지 않는다.
- 입고 취소 = 입고 헤더 `use_at='N'`(이력 보존). 행 빼기 = 물리 삭제 후 행번호 재정렬, 모든 행을 뺄 수는 없다(취소 사용).
- 무검사 행의 입고를 취소하거나 빼면 연결된 가입고 행도 같이 삭제하고 가입고 행번호·금액을 다시 계산한다. 가입고 행이 하나도 남지 않게 되면 행은 이력으로 남기고 가입고 헤더만 취소(`use_at='N'`)된다. 다시 입고하려면 가입고등록에서 새로 등록한다.
- 취소와 행 삭제 전에 이 결과를 확인창에 안내한다.

### 가입고 잠금 (이번 작업에서 구현)
- 입고가 생긴 가입고 행은 가입고에서 수정·삭제할 수 없다(행 단위 잠금). 입고가 없는 검사 대상 행은 기존대로 수정할 수 있다.
- 입고가 생긴 행이 하나라도 있으면 가입고 전체 취소와 헤더(가입고일·부가세 설정) 수정은 막고, 비고만 수정할 수 있다.
- 막힌 경우 어느 입고에서 처리해야 하는지 입고번호를 안내한다. 가입고현황 상세에는 입고번호를, 입고현황에는 가입고번호를 보여 준다.

### 사용자 안내와 편의
- 가입고 저장 직후 "무검사 품목 N건은 입고 MI-…에 자동 등록되었습니다"를 알린다.
- 잠긴 행은 화면에서 읽기 전용으로 표시하고 이유와 이동할 입고번호를 보여 준다.

## 범위

### 포함
- DB: 입고 헤더/상세 테이블, 메뉴(`입고등록`, 입고관리 그룹 아래), 롤백, 변경이력, `db-schema.md`(스크립트는 사용자가 실행).
- 백엔드: 무검사 자동 입고(가입고 저장 연동), 입고 단건 조회·수정·취소, 입고 수정·취소 시 가입고 반영, 가입고 잠금 검증(`validateEditable`).
- 프론트: 입고등록 화면(폼, 그리드, 수입검사 합격분 불러오기 창의 틀), 가입고 화면의 잠금 표시와 입고번호 안내.
- 테스트, 결과 문서(스크린샷 포함).

### 제외(별도 작업)
- 입고현황(`20261117_002`), 입고 수동 등록 저장(검사 합격분, 수입검사와 함께), 수입검사, 재고·LOT 연결, 매입마감.
- 기존 현황 화면의 취소건 기본 조회 규칙 정비(입고 작업 종료 후 별도 작업).

## 구현 절차
1. 계획서, 상세사양서
2. DB 스크립트와 `db-schema.md`, MCP 재확인
3. 백엔드 실패 테스트 → 구현
4. 프론트 실패 테스트 → 구현
5. 검증: 집중 테스트, 빌드, JDK 8 호환 컴파일, 브라우저
6. 사용자 스크립트 실행 후 MCP 확인, 결과 문서 `docs/result/20261117/material-receipt-create`

## 완료 조건
- 무검사 행이 있는 가입고를 저장하면 같은 트랜잭션에서 입고가 생기고 `MI-YYYYMMDD-NNNN` 번호가 발급된다. 검사 대상 행은 입고가 생기지 않는다.
- 입고를 수정하면 연결된 가입고 행과 금액이 같이 바뀐다. 입고를 취소하거나 행을 빼면 연결된 가입고 행도 정리된다.
- 입고가 생긴 가입고 행은 수정·삭제가 거부되고 입고번호가 안내된다.
- 잔량을 넘는 입고 수량은 확인창에서 '확인'을 눌러야 저장된다.
