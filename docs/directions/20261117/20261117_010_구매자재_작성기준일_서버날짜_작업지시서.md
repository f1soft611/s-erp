# 20261117_010 구매자재 작성 기준일 서버날짜 통일 작업지시서

## 작업 목적

Flow 글 [영업관리 작성 기준일을 서버날짜로 통일](https://flow.team/l/QzqMr)(88346262)의 원칙을 구매자재 작성 화면에 적용한다. 신규 작성폼의 오늘 날짜 기본값을 브라우저 시계(`new Date()`)가 아니라 `GET /api/v1/common/system-date`의 서버 날짜로 채운다. 서버 날짜를 못 가져오면 브라우저 날짜로 대체하지 않는다. 기준 구현은 영업 출하·수주 작성 화면과 사양서 [20261117_004](../../spec/20261117/20261117_004_sales-system-date-defaults_상세사양서.md)다. 이 글의 지침서 세 개(저장소 `AGENTS.md`, 팀 개발 규칙, `frontend/AGENTS.md`)는 확인했다(2026-11-17).

## 적용 대상 (모두 신규 작성 화면의 작성일 기본값)

| 화면 | 날짜 필드 | 현재 | 변경 |
| --- | --- | --- | --- |
| 구매요청등록 | 요청일 | 브라우저 날짜 | 서버 날짜 |
| 구매요청확정 | 확정일 | 브라우저 날짜(신규, 요청 불러오기 시 다시 설정) | 서버 날짜 |
| 발주등록 | 발주일 | 브라우저 날짜 | 서버 날짜 |
| 가입고등록 | 가입고일 | 브라우저 날짜 | 서버 날짜 |
| 입고등록 | 입고일 | 브라우저 날짜 | 서버 날짜 |
| 자재수입검사등록 | 검사일 | 브라우저 날짜 | 서버 날짜 |

## 규칙 (사양서 004와 동일)
- 신규 작성과 폼 초기화(신규 단추, 저장 후 새로 시작, 요청 불러오기)에서 서버 날짜를 쓴다. 초기화는 서버 날짜를 다시 조회한다.
- 서버 날짜를 불러오는 동안은 기본 날짜를 채우지 않는다(빈 값).
- 조회 실패 시 화면 오류 영역에 "서버 기준일을 불러오지 못했습니다. …"를 표시하고 날짜를 로컬 날짜로 채우지 않는다. 사용자는 직접 입력할 수 있다.
- 저장된 수정·조회 데이터의 날짜는 그대로 유지한다. 사용자가 날짜를 직접 바꿨다면 늦게 도착한 서버 날짜가 덮어쓰지 않는다.
- 서버 날짜가 기본값으로 들어와도 변경사항(저장하지 않은 내용)으로 보지 않는다.

## 범위
- 포함: 위 여섯 화면, 공통 훅 신규(`shared/hooks/useServerDateDefault.ts`), 테스트, 결과 문서.
- 제외: 현황 화면 검색조건의 날짜 기본값(이미 서버 날짜), 영업 파일, 빠른 날짜 세팅(`quickDates.ts`, 영업 담당자 구현), 날짜 입력 컴포넌트 교체(구매자재 작성 화면은 브라우저 기본 날짜 입력을 쓴다).
- 서버·DB 변경 없음.

## 구현 절차
1. 계획서, 상세 사양서(번호 `20261117_010`)
2. 공통 훅 실패 테스트 → 구현, 화면별 테스트 → 구현
3. 검증: 집중 테스트, `tsc`, 빌드, 실제 브라우저(서버 날짜와 브라우저 날짜가 다른 상황 포함)
4. 결과 문서 `docs/result/20261117/purchase-server-date-defaults`

## 완료 조건
- 여섯 화면의 신규 작성 기본 날짜가 서버 날짜이고, 서버 날짜 조회 실패 시 날짜가 비어 있으며 오류가 표시된다.
- 초기화 후 서버 날짜가 다시 적용된다. 저장된 자료를 열면 저장된 날짜가 유지된다.
- 기존 입력·검증·저장 동작과 테스트가 바뀌지 않는다.
