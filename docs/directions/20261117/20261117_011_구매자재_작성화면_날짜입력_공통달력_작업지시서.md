# 20261117_011 구매자재 작성화면 날짜 입력 공통 달력 적용 작업지시서

## 작업 목적

구매자재 작성 화면 여섯 곳의 날짜 입력이 브라우저 기본 `<TextField type="date">`라서 새로 만든 공통 달력(한국어, 연·월 드롭다운)과 입력 규칙(축약 입력, 정규화)을 쓰지 못한다. 영업 작성 화면(`20261117_003` 사양)과 같게 공통 `DateEditor`로 교체한다(2026-11-17 사용자 요청: "작성화면의 달력도 같이 바꿔 달라").

## 적용 대상

| 화면 | 날짜 필드 |
| --- | --- |
| 구매요청등록 | 요청일 |
| 구매요청확정 | 확정일 |
| 발주등록 | 발주일 |
| 가입고등록 | 가입고일 |
| 입고등록 | 입고일 |
| 자재수입검사등록 | 검사일 |

(수정·조회 다이얼로그는 같은 페이지 컴포넌트를 재사용하므로 함께 적용된다. 현황 화면의 검색 날짜는 이미 `DateEditor`다.)

## 규칙 (영업 사양서 20261117_003과 동일)

- 입력은 `DateEditor`(outlined, `autoFocus` 끔)를 쓴다. ISO 날짜, 8자리·6자리·월일·일 축약 입력과 달력 선택을 지원한다.
- blur에서 유효한 날짜는 `YYYY-MM-DD`로 확정한다. 잘못된 날짜는 입력을 보존하고 해당 필드에 "올바른 ○○일을 입력해 주세요." 오류를 표시한다.
- 저장은 blur에 의존하지 않고 저장 직전에 날짜를 다시 정규화한다. 비어 있지 않은 무효 날짜 또는 필수 누락이면 요청하지 않는다.
- 편집 불가 상태(권한 없음, 조회 전용, 로딩, 저장 중, 취소된 문서 등)는 입력과 달력 버튼 모두 비활성이며 달력은 열리지 않는다.
- 날짜 기본값은 `20261117_010`의 서버 날짜 규칙을 그대로 따른다(서버 날짜 도착, 사용자 입력 우선, 초기화 재조회).
- 날짜 수정 시 해당 날짜의 오류를 지운다. 신규·조회·저장 후 폼 적용 시 이전 오류가 남지 않게 한다.

## 범위

- 포함: 위 여섯 화면의 날짜 입력, 공통 폼 날짜 컴포넌트 `FormDateField` 신규(여섯 화면이 같은 오류·정규화 동작을 쓰도록), 테스트, 결과 문서(스크린샷).
- 제외: API·DB·서버 날짜 기본값 로직 변경, 영업 파일 수정, 현황 화면.

## 구현 절차
1. 계획서, 상세 사양서(번호 `20261117_011`)
2. 공통 컴포넌트·화면별 실패 테스트 → 구현
3. 검증: 집중 테스트, `tsc`, 빌드, 실제 브라우저 375/768/1280/1920px
4. 결과 문서 `docs/result/20261117/purchase-form-datefield`

## 완료 조건
- 여섯 화면의 날짜가 공통 달력으로 선택되고 축약 입력이 blur에서 `YYYY-MM-DD`로 확정된다.
- 무효 날짜는 필드 오류를 보이고 저장 요청을 보내지 않으며, 저장 payload의 날짜는 항상 ISO다.
- 편집 불가 상태에서 달력이 열리지 않는다. 기존 입력·검증·저장 동작과 테스트가 바뀌지 않는다.
- 375px에서 입력과 달력 아이콘이 겹치거나 넘치지 않는다.
