# 20261117_008 공통 달력 개선 작업지시서

## 작업 목적

공통 날짜·월 입력의 달력 팝업(MUI 기본 `DateCalendar`)이 영문이고 연·월 이동이 불편하다(연도를 고르려면 제목을 눌러 세로 목록을 스크롤해야 함). 사용자가 제시한 샘플(3·4번)처럼 **한글, 연·월 드롭다운, 주말 색, 오늘 표시**가 있는 달력으로 바꾸고, 기간(시작~종료) 검색에는 **범위 선택 달력**을 쓴다(2026-11-17 사용자 확정). 날짜 입력 규칙(직접 입력, 축약 입력, 정규화, 필수 검증, `disabled`)은 바꾸지 않고 달력 팝업만 교체한다.

## 확정한 사항 (2026-11-17 사용자 확인)

- 날짜 달력은 샘플 3번 모양: 이전/다음 달 화살표, 연도·월 드롭다운, 일~토(일 빨강·토 파랑), 오늘 날짜 점 표시, 이전·다음 달 날짜는 흐리게, 하단 좌 "오늘", 우 "삭제".
- 월 달력은 샘플 4번 모양: 이전/다음 연도 화살표, 연도 드롭다운, `1월`~`12월` 버튼 3×4, 선택 월 강조, 이번 달 점 표시, 하단 "이번 달"과 "삭제".
- **기간(from~to) 날짜 검색 필드의 범위 선택 달력(샘플 5번)은 이번에는 화면에 연결하지 않는다**(2026-11-17 사용자 결정). 실서버 확인에서 시작·종료가 동시에 바뀌고 종료일 달력에 시작일이 선택으로 보여 헷갈린다는 지적이 있어, 기간 필드는 시작일·종료일이 각각 단일 날짜 달력을 쓰고 자기 값만 바꾼다. 범위 달력 컴포넌트(`DateRangePanel`)는 만들어 두었으나 화면에 연결하지 않고 나중에 보강한다.
- 달력을 공통 컴포넌트로 한 곳에 만들어 날짜·월·기간이 같이 쓴다.
- 영업 담당자가 쓰는 공통 `DateEditor`의 `disabled` 속성과 입력 규칙은 그대로 유지한다. 영업 파일은 수정하지 않는다(공통 컴포넌트 내부만 변경).
- 같은 작업에서 마감월 기본값을 서버 날짜 기준으로 바꾼다(매입마감처리, 별도 문서 `20261117_007`에 반영). 소수점은 구매자재 모듈 정책이 등록될 때 한꺼번에 바꾼다(이번 범위 밖).

## 범위

### 포함
- 신규 공통 달력 컴포넌트(날짜, 월, 기간)와 `DateEditor`·`MonthEditor`·`PageSearchArea` 날짜 범위 연동.
- `DateTimeEditor`·`TimeEditor`는 달력 모양은 그대로 두고 한국어 표시만 맞춘다(MUI 한국어 로케일).
- 테스트, `F1-GRID.md`, 결과 문서(스크린샷 375/768/1280px), 영업 담당자 전달 안내문.

### 제외
- 날짜/시간(`DateTimeEditor`)·시간(`TimeEditor`) 선택 화면의 새 디자인.
- 영업 화면 코드 수정, 날짜 입력 규칙·검증 로직 변경, 서버/DB 변경(없음).

## 영향 화면
`DateEditor`를 쓰는 곳 전부: F1Grid 날짜 셀 편집, 상세검색 날짜(`PageSearchArea`), 공지 작성(팝업 종료일), 영업 수주·출하·명세서·견적 폼, F1-Grid 테스트 페이지. 월 입력은 매입마감처리 검색.

## 구현 절차
1. 계획서, 상세 사양서(번호 `20261117_008`)
2. 달력 유틸·컴포넌트 실패 테스트 → 구현
3. `DateEditor`·`MonthEditor`·`PageSearchArea` 연동 테스트 → 구현
4. 검증: 집중 테스트(날짜 입력을 쓰는 영업·공지 화면 포함), `tsc`, 빌드, 실제 브라우저(375/768/1280px)에서 날짜·월·기간 달력과 영업·공지 화면 회귀 확인
5. 결과 문서 `docs/result/20261117/common-calendar`

## 완료 조건
- 모든 날짜·월·기간 달력이 한국어이고 연·월을 드롭다운으로 바로 고를 수 있다.
- 기간 검색은 시작일·종료일 각각 단일 날짜 달력을 쓰고 자기 값만 바꾼다(범위 달력은 보류).
- 기존 입력 규칙과 `disabled`, 필수·오류 표시, 영업·공지 화면 동작이 바뀌지 않는다.
- 375px에서 달력이 화면 밖으로 넘치지 않는다.
