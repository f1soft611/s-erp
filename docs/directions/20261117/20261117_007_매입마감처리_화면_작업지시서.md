# 20261117_007 매입마감처리 화면 작업지시서

## 작업 목적

입고(MI)된 품목 행을 월 단위로 **매입마감**한다. 마감하면 그 달의 매입 금액(단가·공급가·부가세·합계)이 확정되고, 마감된 입고 행은 입고등록에서 고칠 수 없다. 기존 MES `WMA363_VW`(매입마감처리, 부가세 관리 화면 기준)를 참고하되 s-erp 구조에 맞게 간결하게 새로 설계한다. MES 화면·MS-SQL SP는 참조만 한다(2026-11-17 사용자 확정).

## 확정한 사항 (2026-11-17 사용자 확인)

- 마감 단위는 **입고 행**, 마감월은 사용자가 직접 선택한다(기본 이번 달). 한 입고의 일부 행만 마감하거나 입고일과 다른 월로 마감할 수 있다.
- 마감된 입고 행이 있는 입고는 입고등록에서 **수정·행 빼기·취소 불가**. 마감을 해제하면 다시 가능하다(수입검사 합격분 제한과 같은 방식).
- 저장은 **입고 행(`tb_material_receipt_dt`)에 마감 컬럼 추가**. 별도 마감 테이블과 해제 이력 테이블은 만들지 않는다.
- **부가세 화면 기준**으로 만들고(부가세 없는 별도 화면은 만들지 않는다), **마감 시 금액을 마감 컬럼에 저장**한다. 마감 전 초기값과 기본값은 입고에 이미 있는 부가세 설정(과세 / 부가세 별도가 기본)을 따른다.
- 메뉴 위치는 구매자재 > 입고관리 그룹 안.
- 화면은 좌우 2분할을 유지한다. 공통코드 등록 화면의 `Splitter` 패턴을 따라 크기를 조절할 수 있게 하고 오른쪽 그리드가 남는 폭을 쓴다.
- 단가 마스터(`tb_item_partner_price`)에 부가세 여부 컬럼이 아직 없다. 나중에 단가 정보의 부가세 설정을 마감·입고의 기본값으로 쓰도록 바꾼다(이번 범위 밖, 후속 과제로 기록).

## 조사 결과

| 항목 | 현재 |
| --- | --- |
| 입고 헤더 `tb_material_receipt_hd` | 이미 `tax_type`(TAXABLE/ZERO_RATED/EXEMPT, 기본 TAXABLE), `vat_included_at`(기본 N), 공급가·부가세·합계 보유 |
| 입고 행 `tb_material_receipt_dt` | 이미 단가, 공급가·부가세·합계 보유. 마감 관련 컬럼 없음 |
| 금액 계산 | 백엔드 `PurchaseOrderAmountCalculator`(과세/영세/면세, 포함/별도, HALF_UP) 재사용 |
| MES | 마감 시 입고 행에 마감월·마감일과 단가·부가세구분·포함여부·부가세·합계를 저장하고, 해제하면 마감월을 비우고 금액을 0으로 되돌림. 매입전표 처리된 행은 마감·해제 대상에서 제외 |

## 범위

### 포함
- DB: 입고 행 마감 컬럼 추가(+롤백·변경이력·`db-schema.md`), 메뉴 시드.
- 백엔드: 마감 대상 조회(구매처 요약 + 입고 행), 마감, 해제, 입고등록의 마감 잠금.
- 프론트: 매입마감처리 화면(좌 구매처 요약 / 우 입고 행, 선택 후 마감·해제), 입고현황 마감월 표시.
- 문서 3종 + 결과 문서(스크린샷 포함).

### 제외
- 매입전표 처리(MES의 INPUT_VC_FLAG)와 세금계산서 연동. 마감과 전표는 별개 업무이며 이번에는 만들지 않는다.
- 단가 마스터에 부가세 여부 컬럼 추가와 그 기본값 연동(후속).
- 마감 해제 이력 테이블, 월별 매입현황, 인쇄.

## 구현 절차
1. 계획서, 상세 사양서(번호 `20261117_007`)
2. DB 스크립트(적용은 사용자) → 백엔드 실패 테스트 → 구현
3. 프론트 실패 테스트 → 구현
4. 검증: 집중 테스트, 빌드, JDK 8 호환 컴파일, 실서버 API·브라우저에서 여러 건 마감·해제 확인
5. 결과 문서 `docs/result/20261117/purchase-closing`

## 완료 조건
- 입고일 기간·구매처·마감월로 조회하면 왼쪽에 구매처별 요약이, 구매처를 고르면 오른쪽에 입고 행이 나온다.
- 미마감 행을 여러 개 선택해 마감하면 마감월과 금액이 저장되고, 해제하면 비워진다.
- 마감 행은 입고등록에서 수정·행 빼기·취소가 막히고 마감월을 안내한다.
- 마감 시 단가·부가세구분·포함여부를 바꿀 수 있고 금액은 서버가 계산한다.
- 기존 입고 화면의 다른 동작은 바뀌지 않는다.
