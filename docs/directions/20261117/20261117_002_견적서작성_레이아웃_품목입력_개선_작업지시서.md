# 견적서작성 레이아웃 및 품목 입력 개선 작업지시서

## 목적 및 범위

- 견적서작성 기본정보 레이아웃을 수주등록 기본정보와 같은 반응형 행·열 및 입력 정렬 규칙으로 맞춘다.
- 견적작성일과 견적제출일에 공통 `DateEditor`를 사용해 달력 선택과 축약 날짜 입력을 제공한다.
- 견적 상세의 품목코드는 직접 입력할 수 없게 하고 품목 선택기를 통해서만 설정한다.
- 마스터를 선택하지 않은 상세 행은 품목명만 수기로 입력할 수 있게 한다.
- 기존 API/DB 계약, 계산, 저장·검증, 권한, 수주등록 및 견적현황 동작은 보존한다.

## 기준 및 구현 절차

1. 견적관리 기존 작업지시서·계획서·상세사양서와 견적 작성 코드를 확인한다.
2. 기본정보 레이아웃은 `docs/spec/20261026/20261026_010_수주등록_레이아웃_개선_상세사양서.md` 및 `SalesOrderCreatePage.tsx`를 기준으로 한다.
3. 공통 날짜 입력은 `shared/components/f1-grid/editing/DateEditor.tsx`, 품목 선택 셀은 수주 상세의 품목코드 컬럼을 기준으로 한다.
4. 계획서와 상세사양서를 확정한 뒤 관련 프론트엔드 테스트를 먼저 작성·실행하고, 실패를 확인한 후 최소한으로 구현한다.
5. 견적 작성, 견적현황 편집 재사용, 375px/768px/1280px 브라우저 동작을 확인하고 결과 문서를 작성한다.

## 완료 조건

- 기본정보가 375px 1열, 768px 2열, 1280px 4열이며 수주등록과 같은 간격·picker 정렬을 적용한다.
- 공통 날짜 입력기로 두 날짜를 지정할 수 있고 기존 업무일 기본값 및 선택/필수 정책이 유지된다.
- 품목코드 셀에서 품목 마스터를 선택할 수 있고 코드의 직접 타이핑은 불가하다.
- 직접 입력 행은 품목명만 편집 가능하며 품목 마스터 데이터는 생성·수정하지 않는다.
- 견적 계산·저장 및 현황의 보기/수정 폼에서 기존 동작이 유지된다.
- 관련 테스트와 빌드, 실제 브라우저 반응형 확인, 결과 문서 및 스크린샷이 완료된다.
