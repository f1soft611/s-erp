# F1-Grid 다중 컬럼 가로 스크롤 개선 작업지시서

## 요청과 범위

- 사용자 요청: 컬럼이 많아 가로 스크롤이 생길 때 움직임이 부자연스럽고 끊기는 현상을 개선한다.
- 기존 [고정 컬럼 스크롤 사양](../../spec/20261027/20261027_017_f1grid-smooth-pinned-scroll_상세사양서.md)을 기준으로 네이티브 스크롤, 고정 열, 편집, 선택, 합계와 양 끝 정렬을 유지한다.
- 프론트엔드 공통 F1-Grid, 회귀 테스트 및 기능 문서만 수정한다. 백엔드/API/DB 변경과 커밋 생성은 포함하지 않는다.

## 조사 근거

- 합성 데이터 120행 × 60열, 열 너비 100px, 좌우 고정과 하단 합계를 사용했다.
- 90프레임 동안 12px씩 이동할 때 18회 React commit, 누적 렌더 약 1,803ms와 DOM 변경 2,160건이 관측되었다. 환경 의존 수치이며 절대 성능 보장값은 아니다.
- 본문 1,200px를 헤더/합계에 동기화한 직후 본문이 1,240px로 이동하면, 대기 중인 헤더 scroll 이벤트가 본문을 1,200px로 되돌리는 경로를 재현했다.

## 완료 조건

1. 프로그램으로 동기화한 헤더/합계의 후속 이벤트는 새 본문 위치를 되돌리지 않는다.
2. 헤더/합계에서 직접 시작한 가로 이동은 계속 본문에 반영한다.
3. 현재 미리 렌더된 열로 viewport를 충족하면 열 창을 교체하지 않는다. 범위를 벗어나면 최신 위치로 교체하고 고정/보호 열은 유지한다.
4. 기존 테스트와 추가 회귀 테스트, 빌드/lint, 375/768/1280px 실제 브라우저 검증 및 스크린샷을 남긴다.

## 측정에 따른 보완

열 창 재사용 후 commit은 3회로 감소했지만 120행을 한꺼번에 교체하는 단일 렌더 지연이 남았다. 명시적 `virtualizeRows` 값을 우선 보존하고, 자동 모드에서 병합 컬럼이 없고 행 수 × 표시 대상 컬럼 수가 1,000 이상일 때도 기존 행 가상화를 활성화한다. 이는 행 데이터나 집계 범위가 아닌 DOM 렌더 범위만 줄인다. 병합 컬럼은 기존 행 수 기준을 유지한다.
