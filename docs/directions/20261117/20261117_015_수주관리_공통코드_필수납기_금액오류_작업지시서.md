# 수주관리 공통코드·필수납기·금액오류 처리 작업지시서

근거: 사용자 확인 요청 (2026-11-17)

- 수주등록의 수주상태를 공통코드명으로 표시하고 배송방법을 공통코드 select로 선택한다.
- 수주 상세의 행 번호 헤더를 `No`로 바꾸고, 헤더 납기일을 필수 입력으로 검증한다. 상세행 추가 시 헤더 납기일을 초기값으로 넣되 행에서 변경할 수 있게 한다.
- 상세 라인상태를 `진행상태`로 표시하고 수주상태와 같은 공통코드 그룹을 사용한다.
- 공통코드 그룹이 없으면 명시적 테넌트 대상 SQL seed/검증/롤백 스크립트를 제공한다. DB 직접 적용은 하지 않는다.
- 수주현황의 `업무상태` 표기를 `진행상태`로 바꾸고, 수주상태/진행상태 검색 선택지는 공통코드로 구성한다. 견적번호 컬럼은 표시 상태를 유지하고 회귀 검증한다.
- 공급가 계산이 지원 범위를 넘는 입력은 적용하지 않고 계산 오류를 화면에 표시한다.
- 기존 API 필드, 조회 파라미터, 수주상태 DB 허용값, 권한 및 화면 구조는 유지한다. 스키마/API 변경은 하지 않는다.
- 진행상태 공통코드는 기존 상세 기본값 `대기`를 포함한다. 수주상태 선택/검색에는 DB CHECK 허용값 5개만 제공한다.
- 기존에 공통코드 그룹을 찾지 못해 seed는 `SALES_ORDER_STATUS`와 `SALES_DELIVERY_METHOD`를 추가한다. 현재 소스의 배송방법 fixture에서 확인된 `택배`만 초기값으로 seed하며 추가 선택지는 공통코드 관리에서 운영한다.
- 작업 순서: 계획서 → 상세사양서 → 실패 테스트 → 최소 구현 → 대상 테스트/빌드/lint/브라우저 검증 → 결과 문서 및 스크린샷.
- 변경 파일의 사용자 미커밋 수정은 보존하고, DB 스크립트 사본은 `docs/database`와 `backend/DATABASE`에 동일하게 유지한다.
- DB 스크립트는 명시적으로 승인된 `target_tenant_id`만 처리하며 적용·커밋은 하지 않는다.
