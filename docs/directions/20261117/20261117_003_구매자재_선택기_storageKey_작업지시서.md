# 20261117_003 구매자재 선택기 storageKey 보강 작업지시서

## 작업 목적
저장소 검증(FLOW 게시글 88324869, 2026-11-17 [S-ERP] 저장소 검증·CI 반영 결과)에서 구매자재 선택기의 `F1Grid`에 `storageKey`가 없어 필수 키 검사(`frontend/tests/f1-grid-storage-keys.test.ts`)가 실패한다고 보고됐다. 구매 담당 변경 요청서의 항목 3-1을 적용한다.
`storageKey`가 없으면 열 순서·너비·숨김·고정 설정이 저장되지 않는다.

## 범위
### 포함
- 선택기 `F1Grid`에 서로 다른 `storageKey` 지정 5곳.
  - 게시글 지정 3곳: `PurchaseOrderConfirmPicker`, `PurchaseConfirmPicker`, `PurchaseRequestSourcePicker`
  - 같은 검사에서 함께 검출된 2곳(가입고·입고 작업에서 추가): `MaterialArrivalOrderPicker`, `MaterialReceiptInspectionPicker`
- F1-Grid 사용 문서에 선택기·팝업 그리드도 키 지정 대상임을 명시.
- 결과 문서(스크린샷 포함).

### 제외
- API, 검색, 선택, 저장 요청, 권한 변경(요청서에서도 변경 불필요로 명시).
- 구매 관련 테스트 7건 실패(요청서 3-2): 제 환경에서 단독 재현되지 않아 코드를 고치지 않고 결과 문서에 현황만 기록한다. 전체 프론트 테스트 실행은 별도 작업에서 한다.
- CI·브랜치 보호 설정.

## 업무 규칙
- 키는 기존 키와 중복되지 않는 안정적인 값이며 저장소 관례(`materials-…-grid-v1`)를 따른다. 게시글의 제안 이름(`purchase-order-confirm-picker` 등)을 키에 포함한다.
- 열 순서·너비·숨김·고정 설정이 선택기를 다시 열어도 복원되고 다른 선택기에 영향을 주지 않아야 한다.

## 구현 절차
1. 계획서, 상세사양서
2. `f1-grid-storage-keys` 검사로 누락 5곳 확인(완료) → 키 지정
3. 검증: 저장키 검사, 선택기 관련 테스트, 타입·빌드, 실제 브라우저 375/768/1280px(열 설정 변경 후 재진입 복원, 선택기 간 독립)
4. F1-Grid 문서와 결과 문서 `docs/result/20261117/picker-storage-keys`

## 완료 조건
- `f1-grid-storage-keys.test.ts`의 두 검사가 모두 통과한다.
- 선택기별로 열 설정이 재진입 후 복원되고 다른 선택기에 영향을 주지 않는다.
- 375/768/1280px에서 불필요한 가로 넘침이 없고 기존 선택 흐름이 유지된다.
