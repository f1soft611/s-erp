# 출하계획 API 전환 작업지시서

## 목적

2026-11-12 다중수주 출하계획 변경 이후 API 계약과 DB 스키마의 호환성 위험을 검토하고, 현재 계약을 기준으로 배포 방침과 절차를 확정한다.

## 결정 입력

- 사용자 결정: “구버전은 상관안해도 돼 지금버전으로 가면”
- 구버전 API 소비자와의 호환은 목표 범위에서 제외한다.
- 작업 기준 소스는 확인 시점 저장소 HEAD `45c5669d`이며, 이는 실제 배포 artifact 버전으로 간주하지 않는다.

## 작업 범위

- 현재 API 요청·응답, 저장소 내 소비자 및 읽기 전용 DB MCP 스키마를 확인한다.
- 동일 경로의 현재 계약을 유지하고 구버전 호환 API를 추가하지 않는다.
- 현재 프론트엔드와 백엔드의 동시 전환, DB 사전 확인, 검증 및 롤백 제한을 문서화한다.
- 운영 배포나 DB 변경은 실행하지 않는다.

## 완료 조건

1. 현재 계약 기준으로 버전 분리 여부를 결정한다.
2. 확인한 저장소·DB 근거와 운영 배포 상태의 미확인 범위를 구분한다.
3. 배포 전제조건, 동시 배포 순서, 검증 및 롤백 중단 조건을 계획·사양·결과 문서에 기록한다.
