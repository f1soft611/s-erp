# 그룹웨어 스키마 및 공통코드 스크립트 작업지시서

## 작업 목적

신규 환경에 재사용할 그룹웨어 전용 PostgreSQL 테이블 기준선, 그룹웨어 공통코드 시드 및 롤백 스크립트를 작성한다. 현재 연결된 DB에는 SQL을 적용하지 않는다.

## 작업 범위

- 그룹웨어 전용 테이블 13개의 현재 스키마 기준 DDL
- 활성 테넌트별 공통코드 그룹 5개 및 상세 항목 23개의 멱등 시드
- 그룹웨어 테이블 DDL 롤백 및 날짜별 변경 이력
- `backend/DATABASE/20261022`와 `docs/database/20261022`의 동일 파일 보관
- 현재 스키마에 대한 `docs/database/db-schema.md` 정합성 검토
- 결과 문서 작성

대상 테이블은 `tb_board_type`, `tb_board_post`, `tb_board_post_view_history`, `tb_notice_popup_dismissal`, `tb_drafting_work_category_group`, `tb_drafting_work_category`, `tb_drafting_work_category_authority`, `tb_electronic_approval_main`, `tb_electronic_approval_line_info`, `tb_electronic_approval_line_template`, `tb_electronic_approval_line_template_info`, `tb_electronic_approval_pin`, `tb_electronic_approval_view_history`다.

## 선행 조건 및 제외

- 테넌트, 메뉴, 로그인 계정, 사용자, 공통코드 그룹/항목, 공통 파일, 공통 댓글, 공통 댓글 좋아요 스키마는 별도 기반 스키마에서 먼저 생성되어야 한다.
- 공유 테이블 및 현재 DB의 데이터 행은 생성·수정·삭제하지 않는다.
- 기존 운영 DB용 증분 마이그레이션이 아니다. 해당 테이블이 없는 신규 그룹웨어 스키마의 기준선으로만 사용한다.
- 전자결재 문서 상태와 결재 참여자/행위 값은 현행 검사 제약으로 관리하므로 별도 공통코드 그룹을 추가하지 않는다.
- 기존 사용자 작업의 변경 파일을 수정·되돌리거나 테스트 실패를 고치지 않는다.

## 실행 순서

1. 이 작업지시서를 기준으로 계획서와 상세사양서를 작성한다.
2. 읽기 전용 PostgreSQL MCP 및 날짜별 DB 이력을 대조해 컬럼, 제약, 인덱스, 공통코드 항목을 명시한다.
3. 번호 `20261022_009`로 그룹웨어 테이블 생성, 공통코드 시드, 테이블 롤백, 변경 이력 파일을 작성하고 두 DB 이력 경로에 동일하게 복사한다.
4. 시드가 활성 테넌트만 대상으로 하고 그룹/항목 충돌을 건너뛰는지 확인한다.
5. 관련 `db-schema.md` 구간, FK 의존성, 역순 롤백, 파일 사본 동일성 및 SQL 정적 조건을 확인한다.
6. 결과 문서에 MCP 근거, 검증 내역, 미적용 사실과 기존 백엔드 기준 테스트 실패를 기록한다.

## 완료 조건

- DDL에 위 13개 테이블만 포함하고 현재 메타데이터 기준의 필드/제약/인덱스를 보존한다.
- 공통코드 시드에 `NOTICE_GUBUN`, `WF_ARCHIVE_CATEGORY`, `WF_DOC_CATEGORY`, `WF_FORM_CATEGORY`, `WF_FORM_CYCLE`과 각 기존 항목 23개가 포함된다.
- 시드는 모든 활성 테넌트를 대상으로 하며 `(tenant_id, group_code)`와 `(group_id, item_code)` 충돌을 멱등 처리한다.
- 두 DB 이력 경로의 동일 번호 파일이 바이트 단위로 일치한다.
- 현재 DB에는 DDL 또는 시드 데이터를 적용하지 않는다.
- DB 변경이 없는 작업이므로 화면 캡처는 해당 없음으로 결과 문서에 기록한다.
