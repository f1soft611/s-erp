# 그룹웨어 프로필 이미지 표시 작업지시서

## 작업 목적

문서·공지 흐름에서 사용자 프로필을 표시하는 기존 위치에 프로필 이미지가 있으면 이미지를 표시한다. 이미지가 없거나 로드되지 않으면 각 화면에서 현재 사용하던 이름/이니셜 fallback을 그대로 유지한다.

## 적용 범위

- 문서 작성/상세의 작성자, 결재·합의·참조 참여자 및 기존 사용자 선택 프로필 표시
- 공지 작성/상세의 작성자·댓글 작성자 등 현재 프로필/아바타를 표시하는 위치
- 공통 `ProfileAvatar` 컴포넌트 및 이 컴포넌트를 사용하는 범위의 테스트
- 프로필 이미지가 현재 읽기 응답에 없는 경우, 기존 계정 프로필 이미지 값을 제공하는 nullable 응답 필드와 tenant 범위 조회

현재 프로필 아바타가 없는 일반 텍스트 영역에 새로운 아바타를 추가하거나, 다른 그룹웨어 도메인·프로필 편집·이미지 업로드 기능을 바꾸지 않는다. 승인 상태 도장은 사용자 프로필 아바타와 다른 표시이므로 변경하지 않는다.

## 구현 및 검증 순서

1. 문서/공지 프로필 표시 지점과 읽기 API/매퍼, 현재 worktree 변경을 확인한다.
2. 백엔드 API/쿼리 변경 전에 읽기 전용 DB MCP에서 사용자·로그인 계정의 이미지 컬럼과 tenant/user 연결 조건을 확인한다.
3. 날짜별 계획서와 상세 사양서에 변경 파일, API 필드, 테스트 및 검증 기준을 기록한다.
4. 먼저 공통 아바타의 사진/빈 값/로드 실패 테스트를 작성하고, caller fallback을 보존하는 공통 컴포넌트를 구현한다.
5. 문서·공지 작성자 및 댓글 응답에 필요한 nullable 이미지 필드를 tenant 범위로 제공하고, 화면 모델에 전달한다. 기존 응답 구조와 행 반환 여부를 유지하며 DB 스키마를 변경하지 않는다.
6. 기존 문서·공지 프로필 표시 위치를 공통 컴포넌트로 연결하고 기존 크기, 레이아웃, fallback, 상호작용을 보존한다.
7. 집중 프론트/백엔드 테스트와 프론트 build를 실행하고, 브라우저에서 375px, 768px, 1280px를 확인한다.
8. 결과 문서와 개인정보가 포함되지 않은 화면 캡처를 `docs/result/20261022/groupware-profile-avatar/`에 기록한다.

## 완료 기준

- 프로필 이미지가 존재하는 대상은 이미지로 표시된다.
- 이미지가 없거나 로드 실패 시 해당 위치의 기존 이름/이니셜 표시가 유지된다.
- 문서 및 공지의 작성자·댓글·결재 참여자 프로필 데이터 전달과 표시를 확인한다.
- 이미지 때문에 기존 화면 크기/레이아웃, 상세·댓글·결재 동작이 바뀌지 않는다.
- 신규 DB 테이블/컬럼 및 마이그레이션 없이 기존 이미지 저장 계약을 재사용한다.
- 관련 프론트 테스트, 백엔드 매퍼/서비스 테스트, 프론트 `npm run build` 및 반응형 브라우저 확인 결과를 결과 문서에 남긴다.
