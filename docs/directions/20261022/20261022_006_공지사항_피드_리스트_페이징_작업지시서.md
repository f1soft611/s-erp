# 20261022_006 공지사항 피드·리스트 페이징 작업지시서

## 작업 목적

공지사항 페이지의 피드형과 리스트형 목록을 문서작성 페이지의 20건 단위 이어 불러오기 방식으로 통일한다. 상단 고정 공지는 일반 목록과 분리해 조회하고, 현재 카테고리 범위의 고정 공지 전체를 상단 고정 영역에 표시한다.

- 승인 설계: [공지사항 피드·리스트 페이징 설계](../../superpowers/specs/2026-10-22-notice-feed-list-pagination-design.md)
- 구현 계획: [공지사항 피드·리스트 페이징 계획](../../superpowers/plans/2026-10-22-notice-feed-list-pagination.md)
- 상세 사양: [공지사항 피드·리스트 페이징 상세 사양](../../spec/20261022/20261022_006_공지사항_피드_리스트_페이징_상세사양서.md)

## 승인된 동작

- 피드형과 리스트형 모두 일반 공지를 20건씩 조회한다.
- 다음 페이지는 실제 페이지 스크롤 영역의 공통 페이징 센티널이 노출될 때 자동으로 요청한다.
- 다음 페이지 요청 중에는 기존 항목을 유지하고 로딩 표시를 보여준다. 요청 실패 시 자동 재요청을 멈추고 실패한 페이지를 다시 시도할 수 있게 한다.
- 상단 고정 공지는 일반 목록과 별도 요청으로 가져오고, 카테고리 필터를 동일하게 적용한다.
- 기존 공지 API의 `isPinned` 필터 및 페이지 응답을 사용해 고정 공지의 `resultCnt`에 도달할 때까지 조회한다. 백엔드 API와 DB 스키마는 변경하지 않는다.
- 일반 피드/리스트에는 고정되지 않은 공지만 표시하고, 고정 공지는 상단 고정 패널에서만 표시한다.
- 카테고리 변경, 보기 전환에 따른 명시적 재조회, 새로고침 시 목록 페이징을 초기화한다. 이전 조건의 늦은 응답은 현재 결과에 반영하지 않는다.
- 상세 패널, 댓글, 수정/삭제, 고정 토글, 요약 영역, 빈 상태 및 기존 권한 동작은 유지한다.

## 작업 절차

1. [계획서](../../plan/20261022/20261022_006_공지사항_피드_리스트_페이징_계획서.md)와 [상세 사양](../../spec/20261022/20261022_006_공지사항_피드_리스트_페이징_상세사양서.md)을 본 지시서와 승인 설계에 맞게 작성한다.
2. `useNoticeList`의 기존 목록·고정 조회 테스트에 첫 20건, 후속 페이지, 전체 고정 페이지 수집, 오류 재시도 및 오래된 응답 차단 테스트를 추가한다.
3. 공지사항 피드와 리스트가 같은 공통 페이지 상태/센티널을 사용하도록 구현한다. 피드의 기존 독립 종료 감지기는 제거해 중복 요청을 방지한다.
4. 공유 페이징 컴포넌트는 문서작성에서 쓰는 기본 접근성 레이블을 보존하면서 공지 화면에서는 공지 전용 로딩 레이블을 사용한다.
5. 공지사항 집중 테스트와 프론트엔드 빌드를 실행한다.
6. `/groupware/community/notice`에서 375px, 768px, 1280px 뷰포트의 피드/리스트 페이지 이동, 고정 분리 및 실패 재시도를 확인한다.
7. 결과 보고서와 영문 소문자 경로의 스크린샷을 `docs/result/20261022/notice-feed-list-pagination/`에 기록한다.

## 완료 조건

- 피드와 리스트가 모두 일반 공지 20건씩 조회하고 다음 페이지를 중복 없이 추가한다.
- 고정 공지는 별도 조회로 `resultCnt`만큼 모두 표시되고 일반 목록에서 중복되지 않는다.
- 카테고리/보기 재조회 후 페이징 상태가 초기화되며 이전 요청 응답이 현재 데이터를 덮지 않는다.
- 다음 페이지 오류 시 이미 표시된 공지를 유지하고 실패 페이지 재시도 UI를 제공한다.
- 기존 문서작성 기본 레이블, 공지 상세/댓글/편집/삭제/고정 동작을 보존한다.
- 관련 테스트, production build, 3개 뷰포트 브라우저 확인 및 결과물이 완료된다.
