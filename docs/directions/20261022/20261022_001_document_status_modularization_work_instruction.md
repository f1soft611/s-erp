# 20261022_001 문서현황 소스 분리 작업지시서

## 목적 및 승인 범위

사용자가 승인한 책임별 분리안에 따라 문서현황을 문서작성과 같은 기능 폴더 구조로 정리한다. 페이지는 화면 조립만 담당하고 검색, 세션, 조회, 상세/편집 상태와 UI를 분리한다.

- 기존 미커밋 전체조회 변경을 보존한다.
- 빠른/상세검색, 적용된 조건만 세션 저장, 최근 1개월 기본값, 초기화, 요청 취소, 재시도, 전체조회, 로컬 정렬/필터, 선택/상세/수정, 엑셀 기능을 유지한다.
- API 경로, 요청/응답, 백엔드, DB, 공통 F1-Grid 동작은 변경하지 않는다.
- 문서작성의 상세 피드와 작성 다이얼로그를 재사용한다. 공통 영역으로 불필요하게 승격하지 않는다.
- 단순히 줄 수를 줄이기 위한 미세 분할은 하지 않는다.

## 순서

1. 이 작업지시서를 근거로 날짜별 계획을 작성한다.
2. 계획에 따라 상세사양과 회귀 검증 기준을 확정한다.
3. 기존 테스트 기준선을 기록하고 추출 경계에 대한 테스트를 먼저 추가한다.
4. 사양에 따라 기능 내부를 분리한다.
5. 관련 테스트, 빌드, 실제 브라우저 375/768/1280px 확인을 수행한다.
6. 결과와 스크린샷을 `docs/result/20261022/document-status-modularization/`에 기록한다.

## 기준선

코드 수정 전 문서현황 테스트 24개 중 22개 성공, 2개 실패를 확인했다. 기존 컬럼의 문서번호는 텍스트이고 최종 변경일 상세검색은 숨김인데 테스트는 숫자 입력과 노출된 날짜를 기대한다. UI를 변경하지 않고 테스트 기대를 현재 동작과 맞춘다.

## 완료 기준

화면/API 동작은 보존되고 컴포넌트, 훅, 서비스, 타입의 책임이 명확하며 관련 테스트와 빌드 및 브라우저 결과가 기록되어야 한다.
