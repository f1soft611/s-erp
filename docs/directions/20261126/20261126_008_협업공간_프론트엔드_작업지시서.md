# 협업공간 프론트엔드 작업지시서

- 작성일: 2026-11-26
- 근거: [설계 문서](../../superpowers/specs/2026-11-26-community-workspace-frontend-design.md)

## 요청 배경

- 사용자가 직접 "방"을 만들어 소통하는 게시판 기능이 필요하다. 용도(업무, 파일, 자유 소통)는 사용자가 정한다.
- 지라의 칸반처럼 방 1개를 칸반으로 보고, 그 안에서 스레드처럼 글을 쓰고 댓글을 달 수 있어야 한다.
- 사용자 결정(2026-11-26): 보기는 칸반/피드 전환, 방마다 권한 그룹, 컬럼 숨김·접기·순서는 사용자별 저장, 메뉴명 "협업공간"(그룹웨어 > 커뮤니티), 프론트엔드만 먼저 구현.
- 사용자 지시: UI/UX를 신경 쓰고 기존 ERP 디자인과 일관되게 한다.

## 작업 범위

- `frontend/src/pages/groupware/community/workspace/` 신규 화면(방 목록, 칸반·피드 보기, 글·댓글, 방 설정, 권한 그룹)
- 서비스 계층 뒤의 가짜 저장소(localStorage + 샘플 데이터)
- `DashboardContent`, `dashboardPages`, `dashboardData`에 `workspace` 연결

## 제외 범위

- 백엔드 API, DB, 실제 권한 판정, 파일 보기 탭, 부서 단위 구성원, 알림·멘션·실시간 동기화
- 사용자별 컬럼 정의(카드 상태는 방 공통)

## 완료 기준

1. 방 선택, 칸반↔피드 전환, 글 작성, 댓글·답글, 카드 이동(드래그와 "이동" 메뉴)이 동작한다.
2. 방 설정에서 이름, 기본 보기, 컬럼, 권한 그룹을 저장한다. 마지막 방 설정 권한 그룹 삭제와 카드가 있는 컬럼 삭제는 막힌다.
3. 사용자 전환 시 권한에 따라 버튼과 드래그가 제한되고, 같은 카드는 모든 사용자에게 같은 컬럼에 있다.
4. 컬럼 숨김·접기·순서와 필터가 사용자별로 저장되고 새로고침 후 유지된다.
5. 375/768/1280px에서 가로 스크롤과 겹침이 없고 공지·자료실과 헤더·여백이 일치한다.
6. `npm run test`, `npm run build` 통과, 결과 문서와 스크린샷 작성.
