# 대시보드 업무화면 청크 분할 작업지시서

## 요청 배경

- 2026-11-26 `frontend` `npm run build`에서 1,000 kB 초과 청크 경고가 다시 발생했다. 사용자가 이 경고의 조치를 요청했다.
- 원인 청크는 `DashboardPage`(1,778,872 bytes)다. `DashboardContent`가 업무 화면 48개를 정적으로 import해 모든 업무 화면과 편집기(tiptap/prosemirror)가 대시보드 청크 하나에 합쳐진다.
- [2026-10-26 조치](../../result/20261026/frontend-large-chunk-code-splitting/20261026_009_frontend_large_chunk_code_splitting_결과.md)는 라우트만 분리했고 당시 `DashboardPage`는 476 kB여서 업무 화면 분리를 제외했다. 이후 화면이 늘어 한도를 넘었다.
- 설정만으로 tiptap을 vendor 청크로 분리하는 방안은 측정 결과 `DashboardPage` 1,330,130 bytes로 여전히 한도를 넘어 채택하지 않는다.
- 사용자 결정(2026-11-26): 업무 화면 lazy 로딩 방식으로 조치한다. 경고 한도 상향은 하지 않는다.

## 작업 범위

- `frontend/src/pages/dashboard/components/DashboardContent.tsx`의 업무 화면 import를 `React.lazy` 동적 import로 바꾸고 `Suspense`로 감싼다.
- 지연 로딩 중 표시는 앱 진입 정책([20261026_009 스피너 제거](../20261026/20261026_009_app_initial_loading_spinner_removal_작업지시서.md), `AppRouter` `fallback={null}`)과 맞춰 본문 영역만 비운다. 사이드바·헤더는 유지한다.
- 동기 렌더링을 전제로 한 테스트가 있으면 화면 등장을 기다리도록 대기만 보정한다. 단언은 바꾸지 않는다.

## 제외 범위

- 업무 화면 선택 조건(module id, page key), props, 메뉴 URL, API, 백엔드, DB 변경
- `chunkSizeWarningLimit` 변경, vendor 청크 그룹 변경
- `DashboardPage`의 알림·메시지·검색 등 대시보드 자체 구성 요소 분리
- 공통 `AppLoadingSpinner` 변경

## 완료 기준

1. `npm run build`에서 1,000 kB 초과 청크 경고가 없다.
2. `DashboardPage` 청크가 1,000 kB 미만이고, 업무 화면은 각각 별도 청크로 분리된다.
3. 메뉴 선택 시 기존과 같은 업무 화면이 표시된다(선택 조건·props 동일).
4. `DashboardContent`/`DashboardPage`를 렌더링하는 테스트 21개 파일이 변경 전 기준선과 같은 결과다.
5. lint 통과, 실제 브라우저에서 업무 화면 전환과 375·768·1280px 확인, 결과 문서 작성.
