# 20260918_007 공지사항 본문 이미지 즉시 업로드 작업지시서

## 작업 목적

공지사항 작성 에디터에서 이미지를 붙여넣을 때 이미지를 본문 안의 파일로 즉시 업로드하고, 업로드 결과 URL을 본문에 삽입한다. 이미지가 텍스트 사이의 정확한 커서 위치에 유지되며, 에디터와 피드에서 자연스럽게 표시·크기 조정되도록 한다.

엑셀/표 붙여넣기 기능과 같은 수준으로 이미지 붙여넣기를 주요 공지 작성 경로로 지원한다.

## 대상 및 영향 범위

- 대상 화면: 공지사항 작성/수정 다이얼로그 및 공지 피드
- 프론트엔드:
  - `frontend/src/pages/groupware/community/notice/components/NoticeComposerDialog.tsx`
  - `frontend/src/pages/groupware/community/notice/components/NoticeFeedList.tsx`
  - `frontend/src/pages/groupware/community/notice/components/noticeContentStyles.ts`
  - 공지사항 서비스, 타입, 테스트, 브라우저 검증 스크립트
- 백엔드:
  - 공지사항 이미지 임시 업로드 및 게시글 귀속 API
  - 공개 이미지 접근 URL 제공 또는 공개 URL 생성 계약
  - 기존 공지사항 첨부파일/MinIO 저장 구조 재사용 가능성 검토
- DB:
  - 기존 파일 테이블 재사용을 우선한다.
  - 신규 테이블 또는 컬럼이 필요할 경우 별도 DB 작업지시와 날짜별 SQL/변경 이력을 추가한다.

## 확정 요구사항

### 1. 에디터 이미지 붙여넣기

- 클립보드에서 이미지 파일을 감지하면 일반 HTML/텍스트 붙여넣기보다 이미지 처리를 우선한다.
- 이미지를 붙여넣는 즉시 업로드 API를 호출한다.
- 업로드 중에는 사용자가 삽입 위치를 잃지 않도록 해당 커서 위치에 로딩 상태를 표시한다.
- 업로드 성공 시 같은 위치의 플레이스홀더를 업로드 결과 URL을 사용하는 이미지 노드로 교체한다.
- 텍스트 사이에 붙여넣은 이미지는 텍스트를 덮어쓰거나 본문 끝으로 이동하지 않고 원래 커서 위치에 들어가야 한다.
- 업로드 실패 시 본문을 손상시키지 않고 플레이스홀더를 제거하며 사용자에게 실패 상태를 알린다.

### 2. 이미지 파일 및 URL

- 이미지 파일은 MinIO 저장 구조를 사용한다.
- 본문에는 공개 접근 가능한 이미지 URL을 삽입한다.
- 업로드 응답에는 최소한 이미지 URL, 파일 식별자, object key, MIME type, 파일 크기를 포함한다.
- 공개 URL 사용으로 인증 없이 이미지가 노출될 수 있다는 운영·보안 영향을 결과 문서에 기록한다.
- 저장하지 않고 작성 창을 닫은 임시 이미지가 장기간 남지 않도록 정리 정책을 정의한다.

### 3. 자동 리사이즈 및 크기 조정

- 이미지가 에디터 폭보다 크면 에디터 영역을 넘지 않도록 자동 축소한다.
- 이미지의 원본 비율을 유지한다.
- 사용자가 이미지를 선택한 뒤 너비를 조정할 수 있어야 한다.
- 크기 정보는 Tiptap HTML/JSON 직렬화 결과에 보존되어 수정·재조회 후에도 유지된다.
- 모바일, 태블릿, 데스크톱에서 이미지가 본문 영역을 벗어나 가로 스크롤을 만들지 않아야 한다.

### 4. 피드 표시

- 접힌 피드에서는 첨부파일 영역 위에 본문 이미지가 있음을 확인할 수 있는 이미지 미리보기 형태로 표시한다.
- `더보기`를 누르면 이미지가 원문에서 저장된 위치에 텍스트와 함께 그대로 표시되어야 한다.
- 펼침/접힘 전환으로 이미지 위치가 첨부파일 영역으로 잘못 이동하거나 중복 표시되지 않아야 한다.
- 이미지 URL과 크기 속성은 기존 HTML sanitization 정책에 맞게 안전하게 처리한다.
- 이미지 로드 실패 시 깨진 이미지 아이콘만 남기지 않고 대체 표시를 제공한다.

### 5. 기존 기능 호환

- 일반 텍스트 붙여넣기와 Excel/표 붙여넣기 동작은 유지한다.
- 기존 첨부파일 업로드·삭제·다운로드 기능과 본문 이미지를 구분하여 관리한다.
- 공지사항 신규 작성과 수정 모두 같은 이미지 동작을 사용한다.
- 기존 본문 HTML/JSON 및 이미지가 없는 게시글은 변경 없이 표시한다.

## API 및 데이터 계약 방향

- 저장 전 이미지 업로드를 위해 게시글 ID 없이 호출할 수 있는 임시 이미지 업로드 계약을 추가한다.
- 게시글 저장 시 본문에 사용된 임시 파일을 게시글에 귀속시키고, 사용되지 않은 임시 파일은 정리할 수 있어야 한다.
- 기존 파일 테이블 재사용 시 임시 소유자/상태/게시글 귀속을 기존 필드로 표현할 수 있는지 먼저 확인한다.
- 기존 첨부 다운로드 API의 인증 전용 응답 계약은 유지한다.
- 본문 이미지는 만료되는 MinIO presigned URL을 저장하지 않고, 공지 소유권을 확인하는 고정 인증 API 경로로 제공한다.
- 기존 본문에 저장된 presigned URL도 조회 응답에서 `data-object-key` 기반 고정 인증 API URL로 치환한다.
- 파일 확장자와 MIME type 검증, 허용 이미지 형식, 최대 크기, 업로드 실패 응답을 명시한다.

## 검증 기준

- 이미지 클립보드 붙여넣기 시 업로드 요청이 발생하고 반환 URL이 본문에 삽입된다.
- 텍스트 앞·중간·뒤 각각의 커서 위치에서 이미지가 정확한 위치에 삽입된다.
- 업로드 중/성공/실패 상태가 본문과 사용자 알림에 일관되게 반영된다.
- 큰 이미지가 자동 축소되고, 사용자가 너비를 조정한 값이 저장·재조회 후 유지된다.
- 본문 이미지가 있는 접힌 피드와 펼친 피드의 표시 규칙이 요구사항과 일치한다.
- 일반 텍스트 및 Excel/표 붙여넣기 회귀가 없다.
- 이미지 URL sanitization과 허용 MIME/크기 검증이 동작한다.
- 375px, 768px, 1280px 브라우저 폭에서 본문 이미지가 잘리지 않고 가로 스크롤을 만들지 않는다.
- 관련 단위 테스트, 프론트엔드 빌드, 백엔드 테스트 또는 집중 빌드가 통과한다.
- 실제 브라우저에서 작성/붙여넣기/저장/피드 펼침 흐름을 검증하고 모바일·데스크톱 스크린샷을 결과 문서에 남긴다.
