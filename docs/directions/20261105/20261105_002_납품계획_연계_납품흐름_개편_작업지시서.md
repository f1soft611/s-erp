# 납품계획 연계 납품흐름 개편 작업지시서

## 사용자 요구

- 테넌트마다 납품계획을 직접 관리하거나 관리하지 않는 두 운영형태를 지원한다.
- 테넌트 설정을 기준으로 MANUAL은 수주 → 납품계획 → 납품등록, AUTO는 수주 저장 시 계획 자동생성 → 납품등록 흐름을 사용한다.
- 수주납품은 MANUAL/AUTO 모두 납품계획 잔량을 사용하고, 직납품은 두 모드 모두 유지한다.
- 계획/납품 테이블과 기존 테이블 변경 DDL을 현재 S-ERP 패턴에 맞춰 정리하고 화면 및 메뉴 흐름도 변경한다.

## 확정 설계

- `tb_tenant.delivery_plan_mode`: `MANUAL` / `AUTO`, 기본값 `AUTO`.
- `tb_sales_delivery_plan_hd`: 수주당 하나의 계획 헤더.
- `tb_sales_delivery_plan_dt`: 수주상세별 납품예정일/계획수량 행. 분할계획을 위해 한 수주상세의 여러 행을 허용한다.
- 수주 생성/수정, 계획 저장, 납품 생성/수정/삭제는 같은 수주 헤더 잠금 순서로 직렬화한다.
- 수주상세 수정은 기존 상세 ID를 보존하는 동기화로 전환한다. 계획/납품수량을 하회하는 수량축소와 납품이력 참조 상세 삭제/품목변경은 거부한다.
- 기존 수주/납품 이력은 마이그레이션에서 계획으로 backfill하고 실제 납품 상세를 계획상세에 연결한다. SQL은 문서·저장소에만 만들고 적용하지 않는다.
- MANUAL에서만 납품계획 등록/현황 메뉴를 제공한다. 서버도 모드별 작업을 검증한다.

## 실행 순서

1. [상세사양](../../spec/20261105/20261105_002_납품계획_연계_납품흐름_개편_상세사양서.md)과 [계획서](../../plan/20261105/20261105_002_납품계획_연계_납품흐름_개편_계획서.md)를 기준으로 범위를 확인한다.
2. 기본 `s-erp-postgresql-readonly` MCP로 tenant/order/delivery 테이블 계약을 확인한다.
3. DDL, rollback, migration history, menu seed, `db-schema.md`를 `docs/database`와 `backend/DATABASE`에 동일하게 작성한다.
4. 서비스/API 테스트를 먼저 추가하고 tenant mode, plan CRUD/status, order detail ID 보존, plan-linked delivery 수량 원자성을 구현한다.
5. frontend mode 조회/메뉴 노출, 납품계획 등록·현황, 계획 선택 납품을 구현하고 기존 주문·납품 패턴과 정합화한다.
6. Maven/Java 8 API, Vitest/build/lint, SQL 계약, 반응형 브라우저 테스트와 영문 경로 스크린샷을 결과 문서에 남긴다.

## 완료 조건 및 제외

- 기존 납품 수주선택은 계획 선택으로 대체되고, 직납품 동작은 회귀 없이 유지된다.
- AUTO 주문 저장과 MANUAL 계획 저장 전에는 ORDER 납품을 서버가 거부한다.
- 부분/분할계획, 계획수량·실납품수량 정합성, 납품 수정·삭제 역보정이 원자적이다.
- 기존 주문 상세 ID와 납품 이력을 보존한다.
- 실제 DB 적용, 업무 데이터 조회, 재고/회계/세금계산서 연동, 테넌트 설정관리 UI는 범위에서 제외한다. 테넌트 모드는 승인된 SQL 운영절차로 설정한다.
