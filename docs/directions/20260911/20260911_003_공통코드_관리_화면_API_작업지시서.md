# 20260911_003 공통코드 관리 화면/API 작업지시서

## 1. 작업 분류

- 분류: `architectural`
- 대상: 프론트엔드, 백엔드, PostgreSQL 스키마
- 사유: 신규 공통코드 그룹/상세 테이블, 테넌트 기반 API, F1Tree/F1Grid 관리 화면, 라우팅 및 권한 액션을 함께 추가한다.

## 2. 배경

레거시 공통코드 관리의 업무 개념을 S-ERP에 새로 구현한다. 기존 `TB_CommonCode`는 사용하지 않으며, S-ERP 멀티테넌트 구조와 현재 `system/*` 관리 기능의 Controller-Service-DAO-Mapper 및 F1 컴포넌트 패턴을 따른다.

공통코드는 그룹 계층과 상세코드로 구성된다.

```text
그룹코드 1: 첨부문서업무
├── 거래처
└── 품목

그룹코드 1-1: 첨부문서구분
└── parent_group_id = 그룹코드 1
    ├── 거래명세서 -> parent_item_id = 거래처
    └── 사업자등록증 -> parent_item_id = 품목
```

자식 그룹의 상세코드는 자신의 부모 그룹에 속한 상세코드만 상위코드로 선택할 수 있다.

## 3. 목표

1. `/co/master/cmncodes` 경로에 공통코드 관리 화면을 추가한다.
2. 좌측 `F1Tree`로 부모그룹/자식그룹 계층을 표시한다.
3. 그룹을 선택하면 우측 `F1Grid`에 해당 그룹의 상세코드를 표시한다.
4. 자식 그룹 상세코드의 상위코드 선택 목록은 해당 부모 그룹의 상세코드로 제한한다.
5. 페이지 우측 상단의 기존 메인 액션 패턴만 사용한다.
6. F1Tree와 F1Grid의 마우스 오른쪽 컨텍스트 메뉴는 활성화한다.

## 4. 확정 범위

### 4.1 프론트엔드

- `F1Tree` + `F1Grid` 기반 공통코드 관리 페이지
- 경로 및 대시보드 메뉴 연결: `/co/master/cmncodes`
- 좌측 트리:
  - 그룹코드, 그룹명, 부모그룹 표시
  - 부모그룹/자식그룹 계층 표시
  - 그룹 선택 시 상세코드 조회
- 우측 그리드:
  - 상세코드
  - 상세코드명
  - 부모 그룹 상세코드에서 선택하는 상위코드명
  - 사용 여부
  - 정렬 순서
  - 비고/설명
- 상위코드 선택:
  - 현재 그룹에 부모 그룹이 있는 경우에만 활성화
  - 부모 그룹의 상세코드만 선택 가능
  - 상위코드 선택은 기존 공통 선택 다이얼로그/팝업 패턴을 확인하여 적용
- 페이지 우측 상단 액션:
  - 조회
  - 저장
  - 엑셀 내보내기
  - 기존 메뉴별 권한에 따라 표시/비활성화
- 트리/그리드 컨텍스트 메뉴:
  - 엑셀 내보내기, 필터/정렬 초기화, 레이아웃 복원 등 공통 메뉴 활성화
  - F1Tree와 F1Grid의 컨텍스트 메뉴는 모두 활성화 유지
  - 행 추가/행 복제/행 삭제 메뉴는 이 화면에서 비활성화 또는 표시하지 않음
- 행 추가/행 삭제 전용 버튼은 만들지 않는다.

### 4.2 백엔드

- 그룹 목록 조회/등록/수정/삭제 API
- 그룹별 상세코드 조회/등록/수정/삭제 API
- 부모 그룹 상세코드 조회 API
- 그룹 및 상세코드 중복 검증
- 현재 테넌트 범위 검증
- 부모 그룹이 실제 현재 그룹의 부모인지 검증
- `parent_item_id`가 부모 그룹의 상세코드인지 검증
- 자기 자신 또는 허용되지 않은 그룹의 상세코드를 상위코드로 지정하는 요청 거부
- 사용 중인 그룹/상세코드 삭제 시 참조 여부 검증
- 기존 `system` 도메인의 응답/권한/예외 처리 패턴 준수

### 4.3 DB

신규 테이블을 생성한다.

- `tb_common_code_group`

  - `tenant_id`
  - `group_code`
  - `group_nm`
  - `group_dc`
  - `parent_group_id`
  - `sort_order`
  - `use_at`
  - 생성/수정 감사 컬럼
- `tb_common_code_item`
  - `common_code_item_id`
  - `tenant_id`
  - `group_id`
  - `item_code`
  - `item_nm`
  - `item_dc`
  - `parent_item_id`
  - `sort_order`
  - `use_at`
  - 생성/수정 감사 컬럼

필수 제약:

- 테넌트별 그룹코드 유일성
- 같은 그룹 내 상세코드 유일성
- 그룹의 부모그룹 자기참조 FK
- 상세코드의 그룹 FK
- 상세코드의 상위 상세코드 자기참조 FK
- 삭제 시 하위/참조 데이터 정책 명시

## 7. 완료 기준

- `/co/master/cmncodes`에서 인증된 사용자가 공통코드 화면을 열 수 있다.
- 부모그룹과 자식그룹이 F1Tree에서 계층으로 표시된다.
- 자식 그룹 선택 시 해당 그룹의 상세코드가 F1Grid에 표시된다.
- 자식 그룹의 상세코드 상위코드 선택 목록에 부모 그룹 상세코드만 표시된다.
- 잘못된 부모그룹/상위상세코드 조합은 백엔드에서 저장되지 않는다.
- 행 추가/삭제 버튼은 표시되지 않는다.
- F1Tree와 F1Grid의 우클릭 컨텍스트 메뉴는 활성화되어 있으며, 이 화면의 전용 행 추가/삭제 기능은 비활성화된 상태로 동작한다.
- 우측 상단 메인 액션과 트리/그리드 우클릭 메뉴가 기존 페이지 패턴과 동일하게 동작한다.
- 프론트엔드 테스트/빌드, 백엔드 테스트, 실제 브라우저 데스크톱/모바일 확인을 수행한다.
- 결과 문서와 스크린샷을 `docs/result/20260911/common-code-management/`에 보관한다.

## 8. 확인이 필요한 기본 가정

- 우측 상단 메인 액션은 기존 관리 페이지와 동일하게 조회/저장/엑셀 권한 액션으로 구성한다.
- 그룹 계층은 1차 구현에서 부모그룹-자식그룹 중심으로 제공하되, DB는 자기참조 구조를 사용한다.
- 자식 그룹 상세코드의 상위코드는 직접 부모 그룹의 상세코드만 선택한다.
- 데이터 저장은 그룹과 상세코드의 변경사항을 페이지의 저장 액션으로 일괄 반영한다.
