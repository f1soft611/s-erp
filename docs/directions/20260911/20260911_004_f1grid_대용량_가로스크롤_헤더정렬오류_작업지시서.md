# F1-Grid 대용량 가로 스크롤 헤더 정렬 오류 작업지시서

## 배경

F1-Grid는 대량 컬럼과 긴 표를 가로 스크롤로 처리하는 구조를 사용한다. 그러나 대용량 데이터셋에서 가로 스크롤을 끝까지 이동하면, 헤더와 본문 데이터의 컬럼 정렬이 어긋나거나 둘 사이의 좌표가 맞지 않는 현상이 발생한다.

이 버그는 사용자가 표를 끝까지 스크롤했을 때 데이터 열과 헤더 열이 서로 다른 위치를 가리키는 형태로 보이며, 결과적으로 셀 값의 가시 위치와 헤더 라벨의 기준점이 어긋나면서 정렬 깨짐을 유발한다.

이번 작업은 공용 F1-Grid의 가로 스크롤 계산과 가상화/헤더 동기화 로직을 점검해, 대용량 데이터에서 좌표 계산과 정렬이 유지되도록 개선하는 것을 목표로 한다.

## 분류

- 분류: `bounded`
- 사유: 공용 F1-Grid의 가로 스크롤/헤더 정렬 로직만 수정하고, 백엔드 API나 다른 화면 구조를 변경하지 않는다.

## 목표

1. 가로 스크롤이 발생하는 대용량 그리드에서 스크롤 끝까지 이동해도 헤더와 바디 열 정렬이 유지된다.
2. 헤더/바디의 좌표 계산이 가상화 영역, pinned 열, 스크롤 오프셋, column tracks 값과 일치한다.
3. 불필요한 재계산이나 stale 레이아웃이 발생하지 않도록 스크롤 동기화 로직을 정리한다.
4. 회귀 검증을 통해 기존 F1-Grid 기능이 유지된다.

## 확정 요구사항

### 1. 가로 스크롤 정렬 동기화

- 헤더와 본문 영역이 동일한 scrollLeft 값을 기준으로 정렬되도록 한다.
- 가로 스크롤을 끝까지 이동했을 때, 데이터 열과 헤더 열의 시작 위치가 정확히 맞도록 보정한다.
- pinned column, 숨김 column, virtualized column range와 함께 동작할 때도 정렬 경계가 유지되어야 한다.

### 2. column tracks/offset 계산 정합성

- `GridHeader`, `GridBody`, `GridVirtualization` 간의 column offset 계산이 동일한 기준을 사용하도록 점검한다.
- `scrollLeft`를 기준으로 계산되는 라벨 위치와 실제 셀 위치 간 차이가 생기지 않도록 한다.
- 사용 중인 `width`, `minWidth`, `flex` 계산과 pinned offset 계산이 서로 충돌하지 않도록 한다.

### 3. 대용량 성능과 정합성 유지

- 대용량 데이터에서 가로 스크롤 시 렌더 계산이 과도하게 반복되지 않도록 한다.
- scroll 이벤트/virtual window 계산과 header/body 레이아웃 계산이 일관되게 동작하도록 정리한다.
- 데이터량이 많아도 스크롤 최하단에서 열 정렬이 무너지지 않아야 한다.

### 4. 회귀 방지

- 기존 세로 스크롤, 컬럼 고정, 행 선택, 셀 선택 기능과 충돌하지 않아야 한다.
- row height, column resize, hidden columns, pinned columns 등 기존 동작이 유의미하게 깨지지 않는다.

- F1-Grid의 큰 구조 재설계
- 대규모 비즈니스 로직 변경

## 검증 기준

- 대용량 데이터셋에서 가로 스크롤을 끝까지 이동해도 헤더와 본문 열이 정렬된 상태를 유지한다.
- 기존 F1-Grid 테스트가 회귀 없이 통과한다.
- 예외 케이스로 pinned column/hidden column이 있을 때도 정렬이 유지된다.
- 문서와 결과 문서가 함께 갱신된다.

## 완료 기준

- 가로 스크롤 후 헤더/데이터 정렬 불일치 현상이 재현되지 않는다.
- F1-Grid 대용량 렌더링 경로가 안정적으로 동작한다.
- 필요한 결과 문서와 검증 로그를 남긴다.

## DB 영향

- DB 스크립트: 해당 없음
- 영향 검토: 프론트엔드 공용 F1-Grid의 레이아웃/스크롤 로직만 변경하며, 데이터베이스와 백엔드 API 계약은 유지한다.
