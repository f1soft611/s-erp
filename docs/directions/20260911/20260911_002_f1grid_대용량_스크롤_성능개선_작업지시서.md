# F1-Grid 대용량 스크롤 성능 개선 작업지시서

## 배경

현재 F1-Grid는 가상화 기반으로 동작하지만, 대용량 데이터셋에서 스크롤 시 빈 화면/지연 표시가 발생할 수 있다. 특히 행 수가 많은 경우, 스크롤 이벤트마다 계산이 누적되고 렌더 비용이 커지면서 사용자가 바로 데이터를 확인하지 못하는 현상이 나타난다.

이번 작업은 F1-Grid 공용 렌더링/가상화 로직을 대상으로, 스크롤 시 지연을 줄이고 대용량 데이터 대응성을 개선하는 것을 목표로 한다.

## 분류

- 분류: `bounded`
- 사유: F1-Grid 공용 컴포넌트의 렌더링 성능 개선에 한정되며, 전체 앱 구조 변경이나 백엔드 스키마 변경을 포함하지 않는다.

## 목표

1. row 높이를 고정화하여 가변 높이 계산과 재측정 비용을 줄인다.
2. rowOverscan 값을 2~4 수준으로 조정해 스크롤 시 과도한 오버스캔 렌더를 방지한다.
3. columns/selection props의 안정성을 높여 불필요한 재렌더와 memo 무효화를 줄인다.
4. 스크롤 중 heavy calculation을 제거하거나 경량화한다.
5. 10,000건 이상 대용량 데이터는 서버 페이지네이션 구조를 우선 고려한다.

## 확정 요구사항

### 1. row 높이 고정화

- F1-Grid 기본 행 높이를 고정값으로 유지한다.
- row height 자동 계산/재측정 로직이 필요하면, 프로퍼티와 캐시 구조를 명확히 분리한다.
- 가변 높이 계산이 대량 렌더에 부하를 주지 않도록 제한한다.

### 2. rowOverscan 축소

- rowOverscan 기본값을 2~4 범위로 조정한다.
- 과도한 overscan으로 인해 스크롤 시 더 많은 row가 렌더되는 상황을 줄인다.
- 가시 영역을 기준으로 보이는 데이터 수를 안정적으로 유지한다.

### 3. columns/selection props 안정화

- `columns`, `selection`, `visibleRows` 등 재렌더 의존성이 큰 props를 안정적으로 유지한다.
- `useMemo`/`memo` 기반으로 새 참조 생성이 반복되지 않도록 정리한다.
- 불필요한 re-render로 `GridRow`/`GridCell` 계산이 반복되지 않도록 한다.

### 4. 스크롤 중 heavy calculation 제거

- scroll 이벤트 시 가상화 계산, dirty map 계산, merge 계산, overlay 계산이 과도하게 반복되지 않도록 한다.
- RAF 스케줄링과 측정 로직을 유지하되, 중복 계산을 줄인다.
- 브라우저 프레임당 불필요한 작업이 한 번 더 실행되지 않도록 정리한다.

### 5. 10,000건 이상 대용량 데이터 대응

- 데이터량이 10,000건 이상일 때는 서버 페이지네이션 전략을 우선 적용한다.
- 필요한 경우 `dataSource` 기반 lazy loading 및 chunk 단위 조회 흐름을 고려한다.
- 로컬 메모리 전체 렌더 방식을 기본 전략으로 유지하지 않는다.

- 다른 영역의 UI/기능 수정

## 검증 기준

- 대용량 데이터에서 스크롤 시 빈 화면 지연이 줄어든다.
- 기존 F1-Grid 테스트가 회귀 없이 통과한다.
- rowOverScan, rowHeight, virtualization 관련 동작이 기존 기대치와 일치한다.
- 문서/결과 문서에 성능 개선 내용과 체크리스트가 반영된다.

## 완료 기준

- 대용량 스크롤 성능 현상이 개선된다.
- F1-Grid의 가상화와 렌더 구조가 더 안정적으로 동작한다.
- 필요한 성능 문서와 결과 문서가 함께 정리된다.
- 검증 명령이 정상 실행되고 결과를 기록한다.

## DB 영향

- DB 스크립트: 해당 없음
- 영향 검토: 프론트엔드 공용 F1-Grid 로직 및 렌더 성능만 수정하며, 데이터베이스 및 API 계약은 변경하지 않는다.
