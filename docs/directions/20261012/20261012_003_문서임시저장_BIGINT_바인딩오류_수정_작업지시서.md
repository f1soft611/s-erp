# 20261012_003 문서 임시저장 BIGINT 바인딩 오류 수정 작업지시서

## 작업 목적

문서 임시저장 시 `drafting_work_category_id`에 대해 PostgreSQL이 BIGINT 컬럼과 VARCHAR 표현식의 불일치 오류를 반환하는 문제를 수정한다.

## 확인된 원인

- `tb_electronic_approval_main.drafting_work_category_id`는 nullable `BIGINT` 컬럼이다.
- 공통 MyBatis 설정의 `jdbcTypeForNull`은 `VARCHAR`이다.
- 문서 저장 mapper는 선택적 `draftingWorkCategoryId`를 INSERT와 UPDATE에서 JDBC 타입 지정 없이 바인딩한다. 선택하지 않은 경우 null 값이 VARCHAR로 바인딩되어 PostgreSQL BIGINT 컬럼과 충돌할 수 있다.
- 이 작업은 DB schema를 변경하지 않고 mapper에서 해당 nullable key를 `BIGINT`로 명시한다.

## 작업 절차

1. 계획서와 상세 사양서를 작성해 nullable parameter binding 계약 및 검증을 고정한다.
2. INSERT/UPDATE mapper parameter mapping의 JDBC type을 확인하는 테스트를 추가하고 현재 구현에서 실패하는지 확인한다.
3. `draftingWorkCategoryId` mapper parameter를 INSERT와 UPDATE 양쪽에서 `jdbcType=BIGINT`로 명시한다.
4. mapper regression test와 전자결재 service/controller 관련 테스트를 실행한다.
5. 결과 문서에 원인, 수정, 검증, DB MCP 확인 한계를 기록한다.

## 완료 조건

- INSERT와 UPDATE 모두 `draftingWorkCategoryId` parameter를 `BIGINT`로 바인딩한다.
- 선택된 category의 기존 검증·저장 동작과 null 허용 계약을 보존한다.
- mapper 회귀 테스트 및 관련 Maven 테스트가 통과한다.
- schema 변경이나 데이터 수정은 수행하지 않는다.

## DB 확인

현재 작업 도구에는 `s-erp-postgresql-readonly`가 제공되지 않는다. 대체 근거는 `docs/database/db-schema.md`, `20261008` 전자결재 생성 schema, MyBatis 설정 및 저장 mapper다. 이 작업은 기존 nullable BIGINT 컬럼에 대한 JDBC parameter typing만 수정하며 DDL은 수행하지 않는다.
