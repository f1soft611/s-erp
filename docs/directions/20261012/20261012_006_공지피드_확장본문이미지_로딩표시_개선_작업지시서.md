# 20261012_006 공지 피드 확장 본문 이미지 로딩 표시 개선 작업지시서

## 작업 목적

공지 피드에서 `더보기` 클릭 후 인증된 본문 이미지가 준비되기 전 깨진 이미지처럼 보이는 현상을 없앤다. 접힌 이미지 목록처럼 이미지별 로딩 표시를 제공하고, 로딩 자리의 크기와 비율은 가능한 한 실제 본문 이미지와 일치시킨다.

## 승인된 설계

- 보호 이미지별로 이미지 로딩 스켈레톤을 표시하고, 인증 blob fetch 및 이미지 decode 완료 전에는 `<img>`를 렌더링하지 않는다.
- 기존 rich HTML의 텍스트와 표는 이미지 로딩과 관계없이 계속 표시한다.
- 저장 HTML의 `width`, `height`, 인라인 크기 정보가 있으면 이를 이용해 스켈레톤 자리를 예약한다.
- 크기 정보가 없다면 요청 중에는 크기를 추측한 스켈레톤을 보이지 않는다. 보호된 blob을 디코드해 실제 크기와 비율을 확인한 뒤, 그 크기에 맞는 스켈레톤을 최소 한 프레임 표시하고 이미지를 표시한다.
- 표시되는 스켈레톤과 이미지는 공지 본문 너비를 넘지 않게 축소하며 원본 비율을 보존한다.
- 기존 `apiGetBlob` 요청, 오류 안내, 재렌더링 보호 및 blob URL 정리 흐름을 유지한다.
- 기존 접힌 썸네일/상세 뷰어, 저장 형식, 백엔드 API 및 권한 정책은 변경하지 않는다.

## 완료 기준

1. 크기 정보가 있는 보호 이미지에는 확장 직후 깨진 아이콘 대신 해당 크기의 개별 로딩 스켈레톤이 표시된다.
2. 이미지 로딩 중에도 본문 텍스트와 표는 보인다.
3. 크기 정보가 없는 이미지는 API 요청/디코드 중 깨진 이미지나 임의 크기의 스켈레톤을 표시하지 않는다. 디코드 후 정확한 반응형 크기의 스켈레톤을 최소 한 프레임 표시한 뒤 이미지를 표시한다.
4. HTML의 선언 크기/비율을 보존하고, 크기가 선언되지 않은 이미지는 디코드된 자연 크기 비율로 표시하며 본문 너비를 넘지 않는다.
5. 로딩 성공, 실패, 접기/본문 교체/언마운트 정리 및 재렌더링 후 이미지 유지가 테스트된다.
6. 접힌 이미지 목록 및 상세 이미지 뷰어의 동작은 유지된다.
7. 관련 테스트, 프론트엔드 빌드, 브라우저 검증 및 결과 스크린샷이 기록된다.

## 검증 항목

- 요청이 지연된 동안 이미지별 로딩 상태가 있고 보호 API URL을 `<img src>`로 노출하지 않는지 확인한다.
- 정해진 HTML 치수가 있는 이미지와 치수가 없는 이미지를 각각 테스트한다.
- blob decode 완료 시 스켈레톤 교체, 본문 너비 제한, 원본 비율 보존을 확인한다.
- 기존 인증 실패 안내와 URL revoke 회귀 테스트를 유지한다.
- 브라우저에서 확장 본문을 열어 로딩 중·완료 상태를 확인하고 `docs/result/20261012/notice-feed-expanded-images/`에 캡처한다.
