# 20261012_005 공지 피드 확장 본문 이미지 표시 수정 작업지시서

## 작업 목적

공지사항 피드에서 본문을 `더보기`로 펼쳤을 때 본문 이미지가 깨져 보이는 현상을 수정한다. 접힌 피드 이미지 목록과 상세 이미지 뷰어에서는 이미지가 표시되는 기존 동작을 유지한다.

## 확인된 현재 구조

- 접힌 피드의 본문 이미지 미리보기는 `AuthenticatedNoticeImage`를 통해 인증 blob API를 사용한다.
- 펼친 본문은 sanitized HTML을 `dangerouslySetInnerHTML`로 표시하며, 별도의 전역 DOM 효과가 인증 이미지 URL을 찾아 blob URL로 치환한다.
- 펼친 본문 이미지 경로에는 접힌 미리보기와 같은 회귀 테스트가 없다.
- 데이터베이스, 백엔드, API 경로 및 저장 계약은 이번 범위에 포함하지 않는다.

## 요구사항

1. `더보기`로 펼친 본문 안에서 인증이 필요한 이미지가 본문 흐름에 표시되어야 한다.
2. 이미지 요청은 기존 `apiGetBlob` 인증 방식으로 처리하고, 보호된 이미지 API를 `<img>`가 직접 요청하지 않는다.
3. 펼침·접힘, 목록 교체 및 컴포넌트 해제 시 생성한 blob URL을 적절히 정리한다.
4. HTML sanitization, 표/텍스트 렌더링, 접힌 이미지 미리보기, 상세 이미지 뷰어 동작을 보존한다.
5. 이미지 API 실패가 성공처럼 취급되거나 오류가 조용히 숨겨지지 않도록 기존 사용자 오류 처리 패턴과 조화시킨다.
6. 확장 본문 이미지 로딩 및 접힘 이후 URL 정리를 검증하는 회귀 테스트를 추가한다.

## 제외 범위

- 백엔드/API/DB 또는 이미지 소유권·권한 정책 변경
- 공지 저장 HTML/JSON 및 첨부 데이터 구조 변경
- 접힌 썸네일, 상세 모달, 에디터 이미지 업로드의 재설계
- 공지 피드의 무관한 UI 변경

## 완료 기준

- 확장 본문에 포함된 보호 이미지가 인증 blob으로 로드되어 표시된다.
- 접힌 미리보기, 상세 이미지 뷰어, 텍스트/표 본문이 회귀하지 않는다.
- 이미지 blob URL의 생성 및 폐기 수명주기가 펼침 상태와 일치한다.
- 관련 공지 이미지 및 피드 테스트와 프론트엔드 빌드가 통과한다.
- 결과 문서와 브라우저 검증 자료를 `docs/result/20261012/notice-feed-expanded-images/`에 기록한다.
