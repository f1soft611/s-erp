# 20261012_004 전자결재 순차처리 및 문서작업공간 작업지시서

## 작업 목적

문서 임시저장 이후 결재신청·승인·합의·반려·보완요청·재상신까지 순서가 보장되는 공통 전자결재 흐름을 구현한다. 문서 상태와 결재선 상태를 서버에서 전이하고, 모든 시스템 이력을 `tb_common_comment`에 일관되게 기록한다. 문서작성 화면에는 사용자가 관련된 문서와 결재 요약을 연결하되 공통 좌측 문서 영역 구조는 변경하지 않는다.

## 승인된 설계

- [결재 처리 및 문서 작업공간 설계](../../superpowers/specs/2026-10-12-document-approval-workflow-design.md)
- 결재자·합의자 순서는 서버 상태 전이로 보장한다. 일반 결재자는 단계별 순차 처리하고 합의자는 같은 단계에서 동시에 처리한 뒤 전원 승인 시 다음 단계로 진행한다.
- 결재신청 시 작성 최신 본문과 결재선을 한 요청으로 보내고, 문서·결재선·시스템 이력을 하나의 트랜잭션으로 저장한다.
- 반려는 종료하고 보완요청은 기안자 수정·재상신으로 이어간다. 재상신 전후 시스템 메시지는 append-only로 보존한다.
- 시스템 메시지는 공통 이력 테이블을 사용하며 사용자 댓글·대댓글은 이번 범위에서 제외한다.
- 좌측은 현재 구현을 그대로 유지한다. `PinnedViewToolbar` 다음에 고정 문서가 있을 때만 `PinnedItemsPanel`을 표시하고, 이어서 현재 보기 모드의 `FeedView` 또는 `ListView`와 기존 빈 목록 안내를 사용한다. 고정 문서가 없을 때 별도 빈 고정 영역을 추가하지 않는다. 관련 문서 API·요약 행 선택·문서 선택 동작은 연결하지만 좌측 컴포넌트 트리와 레이아웃은 변경하지 않는다.
- 우측만 변경한다. `결재 요약`, `문서 상태`, `놓치지 마세요`를 각각 독립 카드와 소스 컴포넌트로 분리한다. `ApprovalSummaryPanel`은 기본 요약 3개, `DocumentStatusPanel`은 `완료`, `보완요청`, `반려` 건수, `ApprovalNoticePanel`은 결재 요청 및 보완 요청 문서를 표시한다.
- 관련 문서는 기안자·결재자·합의자·참조자로 연결된 모든 상태의 문서다. 기본 결재 요약 3개와 별도 문서 상태 영역의 상태별 건수를 제공한다.
- 문서 목록에서 항목을 선택하면 문서작성 화면 안의 상세 모달을 연다. 본문·첨부·결재선 진행·시스템 이력을 표시하며 전용 상세 경로는 만들지 않는다.
- 활성 처리자에게만 승인·반려·보완요청을 허용한다. 반려·보완요청 사유는 필수, 승인 사유는 선택이며, 사유는 현재 결재선과 시스템 이력에 남아 재상신 이후에도 관련 참여자가 볼 수 있어야 한다.
- 보완요청된 문서는 기안자만 수정·재상신할 수 있다. 처리 성공 후 상세 모달을 닫고 목록·요약을 갱신한다.

## 확인된 DB 계약

`s-erp-postgresql-readonly`로 실제 PostgreSQL 테이블·컬럼·제약조건 메타데이터를 읽기 전용 확인했다. 행 데이터는 조회하지 않았다.

- `tb_electronic_approval_main`에 `eabus_no`가 없고 상태 CHECK에 `REJECTED`가 없다.
- `tb_electronic_approval_line_info`에 `pending_at`이 없다.
- `tb_common_comment`의 현재 이벤트 CHECK에 `SUBMITTED`, `RESUBMITTED`, `COMPLETED`가 없다. 현재 메타데이터에는 `DRAFT_SAVED`가 허용되어 있으나 과거 저장 오류와의 시점·환경 차이는 확인되지 않았다.
- DB 스키마 변경 시 날짜별 SQL, 변경 이력, 롤백 파일을 `backend/DATABASE/20261012`와 `docs/database/20261012`에 동일하게 추가하고 `docs/database/db-schema.md`도 갱신한다.

## 작업 범위

### 백엔드

- 공통 문서결재 서비스에 결재신청, 순차 승인·합의, 반려, 보완요청, 재상신 상태 전이를 구현한다.
- 현재 인증 사용자와 문서 상태·활성 결재선을 검증하고 중복·동시 처리를 차단한다.
- 관련 문서 목록 및 요약 건수 조회에 필요한 API를 제공하고 사용자 범위 검증을 적용한다.
- 상세 모달에 필요한 문서 본문·첨부·결재선·시스템 이력 조회 API와 결재 처리 API를 제공한다. 결재 이력은 해당 문서의 기안자·결재자·합의자·참조자에게만 제공한다.
- 상신·승인·반려·보완요청·재상신·최종 완료와 임시저장 시스템 메시지를 `tb_common_comment`에 기록한다.
- `pending_at`, 문서 유형별 `eabus_no`, `REJECTED` 및 시스템 이벤트 제약의 DB 변경 스크립트와 변경 이력을 만든다.

### 프론트엔드

- 문서작성의 기존 좌측 필터·상단고정·피드/리스트 컴포넌트 트리와 표시 동작을 보존한다. `PinnedItemsPanel`은 기존처럼 고정 문서가 있을 때만 보이고, 고정 문서가 없을 때 별도 빈 고정 영역을 추가하지 않는다.
- 고정 문서 저장·고정/해제 기능이나 DB 필드는 추가하지 않는다.
- 샘플 문서 대신 사용자 관련 문서 목록과 요약 API 결과를 사용한다.
- 우측 `결재 요약`, `문서 상태`, `놓치지 마세요`를 각각 별도 컴포넌트로 구현하고, 문서작성 화면의 우측 영역에서 독립 카드로 조합한다.
- 결재 요약 3개와 별도 문서 상태의 `완료`, `보완요청`, `반려` 행을 클릭하면 좌측 결과를 다시 조회한다. 요약 상태 선택 시 업무구분은 전체로 초기화하고 현재 피드/리스트 모드는 유지한다.
- 「놓치지 마세요」 항목 클릭 시 업무구분을 전체로 초기화하고 해당 문서를 기존 좌측 구조에서 표시한다.
- 목록 항목 선택 시 기존 화면 안에서 상세 모달을 열어 문서·첨부·결재선·시스템 이력을 표시한다. 활성 처리자 작업 버튼, 보완요청 기안자 수정·재상신, 역할별 읽기/처리 권한을 적용한다.
- 반려·보완요청 사유 필수 검증과 승인 사유 선택 입력을 구현한다. 사유는 시스템 이력에 남기고 관련 참여자가 다시 조회할 수 있게 한다.
- 로딩·빈 결과·실패 상태를 기존 화면 패턴에 맞게 처리한다.

## 작업 절차

1. 본 작업지시서를 기준으로 계획서를 작성한다.
2. 계획서 기준으로 API 계약, 화면 동작, 상태 전이, DB migration 및 검증 기준을 상세 사양서로 고정한다.
3. 구현 대상 Java·Mapper·React 파일과 기존 테스트 패턴을 확인하고 각 동작의 실패 테스트를 먼저 추가한다.
4. 날짜별 DB migration과 이력·롤백을 `backend/DATABASE` 및 `docs/database`에 동일하게 작성하고 누적 스키마 문서를 갱신한다.
5. 백엔드 상태 전이/API를 구현하고 관련 서비스·매퍼·컨트롤러 테스트를 실행한다.
6. 프론트엔드 서비스·타입·상태 훅·요약 패널을 연결하고 문서작성 화면 테스트를 실행한다.
7. 최소 375px, 768px, 1280px 브라우저 화면에서 좌측 구조 보존과 우측 패널 반응형 배치를 확인한다.
8. 결과 문서와 검증 스크린샷을 `docs/result/20261012/document-approval-workspace`에 보관한다.

## 완료 조건

- 일반 결재자는 순서대로 활성화되고 합의 단계는 전원 승인이 있어야 다음 단계가 활성화된다.
- 기안자 단계 자동 완료, 활성 처리자만 결재 가능, 반려 종료, 보완 후 기안자 재상신이 규칙대로 동작한다.
- 문서·결재선·시스템 메시지 기록은 원자적이며 실패 시 전체 롤백된다.
- 상신·재상신·승인·합의·반려·보완요청·최종 완료의 시스템 이력이 공통 타임라인에 남는다. 임시저장 이력의 기존 동작도 유지한다.
- 관련 문서 범위·요약 건수·상태 필터·문서 바로 조회 동작이 승인 설계와 일치한다.
- 상세 모달에서 처리 권한이 올바르게 제한되고 반려·보완요청 사유가 재상신 이후에도 결재 이력에 보존·표시된다.
- 좌측 공통 필터·보기 전환·조건부 상단고정 목록·피드/리스트 영역의 구조와 표시 동작이 변경되지 않는다.
- 우측 결재 요약·문서 상태·놓치지 마세요가 별도 카드 및 소스 컴포넌트로 분리된다.
- 신규 DB 필드·제약 migration, 롤백, 변경 이력, `db-schema.md`가 양쪽 스키마 저장소에 일치하게 반영된다.
- 관련 테스트와 빌드가 통과하고 결과 문서 및 스크린샷이 작성된다.

## 범위 제외

- 사용자 댓글, 대댓글, 좋아요.
- 위임·대결·회수, 결재선 변경, 병렬 승인 유형, 별도 단계/처리 이력 테이블.
- 전체 전자결재 포털, 고급 검색 및 저장된 조회 화면.
- 문서별 상단고정/해제 기능과 해당 상태의 저장.
- 레거시 HACCP의 업무별 고정 검토자·승인자 흐름 이식.
