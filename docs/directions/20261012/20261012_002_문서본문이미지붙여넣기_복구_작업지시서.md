# 20261012_002 문서 본문 이미지 붙여넣기 복구 작업지시서

## 작업 목적

문서작성 본문에 클립보드 이미지를 붙여넣을 때 이미지가 에디터에 삽입되지 않는 문제를 해결한다. 공통 `RichTextEditor`, `useRichTextEditorSaveLifecycle`, `EmbeddedImageStorageService`, `EmbeddedImageDocumentProcessor`를 재사용하고 전자결재 초안 저장 흐름에 연결한다.

## 조사 결과와 원인

- 공통 `RichTextEditor`는 클립보드 이미지 붙여넣기 이벤트를 기본 동작보다 먼저 처리하며 `uploadImage` 어댑터가 없으면 기본 동작을 막고 이미지 삽입을 종료한다.
- 문서작성 화면은 `RichTextEditor`에 `uploadImage`를 전달하지 않으며 공통 저장 lifecycle의 referenced/temporary image snapshot도 문서 저장 요청에 연결하지 않는다.
- 브라우저에서 클립보드 이미지 파일을 붙여넣는 이벤트를 재현했을 때 기본 이벤트가 차단되고 이미지 노드가 생성되지 않았다.
- 공통 백엔드 이미지 저장·승격·문서 재작성기는 존재하지만 결재 초안 저장과 연결되어 있지 않다. 기존 임시저장 요청에는 본문 이미지 metadata 필드가 없다.
- 이 문제는 최근 저장 피드백/로딩 UI 변경으로 발생한 것이 아니라, 문서작성 에디터의 기존 연결 누락이다.

## 승인된 방향

- 공통 에디터의 paste 동작을 바꾸지 않고, 문서작성 화면에 결재 도메인 전용 임시 업로드/삭제 adapter와 공통 저장 lifecycle을 연결한다.
- 결재 초안 저장 시 공통 문서 processor로 이미지 참조를 검증하고 `APPROVAL` owner로 승격한 뒤 HTML/JSON에 문서 권한 확인이 적용되는 stable URL을 저장한다.
- 전자결재 이미지 조회는 현재 초안 소유자/tenant 권한을 확인한 뒤 common file owner metadata 기준으로 이미지를 스트리밍한다.
- 공통 파일 metadata 및 object storage를 재사용한다. 신규 이미지 테이블이나 무관한 notice/form API 변경은 만들지 않는다.
- 본문 이미지 업로드는 기존 첨부파일 목록과 별도 lifecycle로 처리한다.

## 작업 절차

1. 본 지시서에 따른 구현 계획을 `docs/plan/20261012/20261012_002_문서본문이미지붙여넣기_복구_계획서.md`에 작성한다.
2. API, 요청/응답 metadata, 권한 및 오류·트랜잭션 계약을 `docs/spec/20261012/20261012_002_문서본문이미지붙여넣기_복구_사양서.md`에 정의한다.
3. 프런트엔드 paste/upload/save lifecycle 회귀 테스트를 먼저 작성하고 실패를 확인한다.
4. 백엔드 temp image API, draft image processor 통합, stable image retrieval 권한 테스트를 먼저 작성하고 실패를 확인한다.
5. 승인된 공통 이미지 처리기와 저장소를 전자결재 draft 흐름에 연결한다.
6. 타깃 테스트, 관련 전체 회귀 테스트, backend/frontend build 및 브라우저 확인을 수행한다.
7. 변경 결과와 스크린샷을 `docs/result/20261012/document-inline-image-paste/`에 기록한다.
8. DB 계약은 공통 파일 테이블과 기존 Mapper/domain을 재사용하는지 점검한다. 스키마 변경이 필요해지는 경우에는 별도 승인 및 날짜별 SQL/변경 이력/롤백 절차 없이 변경하지 않는다.

## 완료 기준

- 이미지 clipboard paste가 문서작성 본문에 preview image node를 삽입하고 shared image adapter를 호출한다.
- 업로드 중 중복 저장을 막고, 실패 메시지를 제공하며, 실패한 paste placeholder는 저장 본문에 남지 않는다.
- 명시적 임시저장 요청에 sanitized HTML/JSON과 image reference/temporary session metadata가 함께 전달된다.
- 성공 저장은 referenced temp image를 tenant 및 `APPROVAL` owner 범위에 승격하고 안정적인 승인 이미지 URL로 본문을 재작성한다.
- 문서 생성/수정, 결재선, SYSTEM 이력 및 이미지 metadata promotion은 기존 초안 트랜잭션에서 원자적으로 처리되며, 실패 시 DB rollback과 object cleanup이 검증된다.
- 임시 업로드 삭제/저장 후 cleanup 및 본문에서 제외된 기존 이미지 정리가 검증된다.
- 이미지 조회는 타 tenant, 타 작성자, 일반 첨부 file ID 또는 타 approval ID에 대한 접근을 차단한다.
- 기존 일반 첨부 업로드 및 draft 저장 동작이 회귀 없이 유지된다.
- 계획서, 사양서, 결과 문서 및 브라우저 스크린샷이 작업 결과와 일치한다.

## 범위 제외

- base64/data URL 이미지 저장
