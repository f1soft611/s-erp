# 20261014_003 전자결재 상세 결재선 프로필·도장 표시 작업지시서

## 작업 분류

- 대상: 프론트엔드, 백엔드 상세 API 및 MyBatis 조회
- 화면: 전자결재 상세의 읽기 전용 결재선
- API: 기존 `GET /api/v1/groupware/approvals/documents/{electronicApprovalId}`
- 기준 설계: [결재선 상세 표시 보완 설계](../../superpowers/specs/2026-10-14-document-approval-line-refinement-design.md)
- DB 변경: 없음. 기존 `tb_login_account.profile_image`, `stamp_image`를 조회한다.

## 작업 목적

전자결재 상세 결재선을 기본 글자 크기와 분명한 단계별 레이아웃으로 표시한다. 처리된 결재자는 등록된 개인 도장을 우선 사용하고, 합의·참조 참여자에게는 프로필 사진과 부서를 표시한다. 현재 결재·댓글·첨부·권한 흐름은 유지한다.

## 확인된 현재 구조

- 상세 참여자 응답은 `DocumentApprovalLineVO`와 `DocumentApprovalLine` 타입으로 표현되고, 이미지 필드는 아직 없다.
- `DocumentApproval_SQL_postgresql.xml`의 `selectApprovalLines`는 결재선 테이블에서 참여자와 처리 상태를 조회하며 사용자 이미지 조인은 없다.
- 참여자 `participant_user_id`는 사용자 ID 문자열이고, 사용자 ID와 계정은 `tb_user.user_id/login_id` 및 `tb_login_account.login_id`로 연결된다. 두 사용자 테이블 모두 `tenant_id`로 분리된다.
- 로그인 계정의 프로필·도장 데이터는 nullable text 컬럼으로 이미 존재한다.
- 프론트 상세 결재선은 `DocumentApprovalDetailFeed.tsx`에 있고, 관련 회귀 검증은 `frontend/tests/document-write-page.test.tsx`의 읽기 전용 시스템 메시지/결재선 테스트에서 수행한다.
- Mapper 회귀 검증은 기존 `DocumentApprovalMapperTest`에서 MyBatis XML과 생성 SQL을 확인하는 패턴을 따른다.

## 요구사항

### 상세 API 및 데이터

1. 기존 상세 응답 envelope와 기존 `approvalLines` 경로를 유지한다.
2. 결재선 참여자 항목에 nullable `participantProfileImage`, `participantStampImage` 필드를 추가한다.
3. 프로필 이미지는 `APPROVAL`, `AGREEMENT`, `REFERENCE` 참여자에게 제공한다.
4. 도장 이미지는 `APPROVAL` 참여자의 처리 상태가 `APPROVED`, `REJECTED`, `RETURNED`일 때만 제공한다. 대기·진행 중이거나 다른 참여자 유형이면 `null`을 반환한다.
5. 결재선 테이블에서 `tb_user`를 tenant와 사용자 ID로 LEFT JOIN하고, `tb_login_account`를 tenant와 로그인 계정 ID로 LEFT JOIN한다. 계정/사용자 누락은 기존 결재선 행을 제거하지 않아야 한다.
6. 기존 상세 접근권한 확인, 문서 조회, 결재선 정렬 및 오류 처리 방식을 바꾸지 않는다. 신규 API, 이미지 저장소, DB migration을 추가하지 않는다.

### 상세 UI

1. 결재선 패널 제목 옆에 `기안자 {이름} · 기안일 YYYY.MM.DD`를 표시하고 독립된 `결재` 소제목은 제거한다.
2. 승인 카드의 상태 도장을 현재보다 크게 표시한다.
3. 처리 완료된 승인 참여자는 개인 도장 이미지가 있으면 사용하고, 이미지가 없거나 로드에 실패하면 상태 텍스트 도장을 표시한다. `WAITING`, `PENDING`은 항상 기존 상태의 시스템 도장을 표시한다.
4. 합의는 `stageOrder`별 테두리 그룹 카드로 표시하고 순번 원형 배지는 왼쪽에 한 번만 보인다. 참여자는 `participantOrder` 순으로 가로 배치·자동 줄바꿈하며, 개별 테두리 카드에 사진·이름 1행 및 부서·상태 배지 2행을 표시한다.
5. 참조는 순번 없이 테두리 카드에 사진·이름 1행 및 부서 2행을 표시하고, 가용 폭에 맞춰 자동 줄바꿈한다. 카드 하나일 때 행 전체로 늘어나지 않게 한다.
6. 합의·참조 프로필 이미지 누락 또는 로드 실패 시 이름 첫 글자를 Avatar 대체 표시로 사용한다.
7. 합의와 참조 참여자는 폭에 맞춰 자동 줄바꿈한다. 이 두 영역에 가로 스크롤을 만들지 않는다.
8. 결재선 제목, 참여자 이름, 부서, 상태는 MUI `body1` 기본 본문 크기를 기준으로 표시한다. 상태 의미는 텍스트와 접근성 이름을 유지한다.
9. 조회수, 결재 처리, 권한, 댓글, 첨부, 시스템 이력, 좋아요·북마크 동작은 변경하지 않는다.

## 완료 기준

- `approvalLines`에 nullable 이미지 필드가 기존 상세 API를 통해 반환되고, tenant 조건 LEFT JOIN이 기존 결재선 행을 보존한다.
- 처리 완료 승인자만 개인 도장을 사용하고 대기·진행은 시스템 도장을 유지하며 이미지 로드 실패도 상태 도장으로 복구한다.
- 합의 순번은 단계마다 한 번, 참여자는 프로필/이름 및 부서/상태의 2행이며 가용 폭에서 자동 줄바꿈한다.
- 참조는 순번 없이 프로필/이름/부서를 표시하고 자동 줄바꿈한다.
- 이름·부서·상태는 기본 `body1` 본문 크기이며 결재 처리 규칙과 API의 권한/envelope는 바뀌지 않는다.
- `DocumentApprovalMapperTest`와 `document-write-page.test.tsx` 회귀 테스트, 프론트 `npm run build`가 통과한다.
- 실제 브라우저 375px, 768px, 1280px에서 화면 전체의 불필요한 가로 넘침이 없고 합의·참조가 자동 줄바꿈한다.
- 결과 문서가 `docs/result/20261014/approval-line-detail-refinement/`에 작성되고 개인정보가 포함되지 않은 화면 캡처를 포함한다.
