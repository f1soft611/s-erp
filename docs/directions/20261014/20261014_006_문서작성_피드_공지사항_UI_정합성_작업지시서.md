# 20261014_006 문서작성 상세 피드 및 수정 모달 정합성 작업지시서

## 작업 목적

문서작성 페이지의 피드형을 공지사항처럼 문서 상세 내용을 카드 형태로 나열하도록 변경한다. 활성 업무구분/범위 필터 결과에 해당하는 모든 문서를 빠짐없이 표시하고, 각 카드에 문서 내용, 결재선 정보, 첨부, 댓글, 기존 문서 상세의 좋아요 토글을 제공한다. 승인·반려·보완요청 처리는 기존 우측 상세 패널에서만 제공한다.

문서 상세 패널의 수정 모달은 패널 위에 열리며, 모달 닫기/저장 후 목록과 선택 상세를 전체 로딩 화면 없이 조용히 갱신한다.

## 승인된 동작

### 피드와 리스트

- 기본 보기 방식은 기존과 같이 리스트형이다.
- 피드형은 현재 범위/업무구분 필터가 반환한 문서를 모두 문서 상세 카드로 표시한다. 고정 문서가 결과에 포함되면 카드에서 제외하거나 요약형으로 축소하지 않는다.
- 피드 카드는 작성자/날짜, 문서 종류/상태, 결재선 읽기 정보, 전체 본문과 인증 embedded image, 첨부파일, 좋아요/북마크 UI, 댓글 스레드를 포함한다.
- 공지사항 피드처럼 현재 문서 권한에 따라 작성자 메뉴를 표시하고, 기존 문서 수정/삭제 기능을 제공한다. 새 고정/반응 API 동작은 추가하지 않는다.
- 댓글 생성/답글/수정/삭제/첨부 조작 및 과거 댓글 조회는 기존 문서 상세 서비스와 권한 동작을 재사용한다.
- 문서 좋아요는 기존 문서 상세와 동일하게 화면 내 토글만 수행하고 표시 개수는 0으로 둔다. 공지사항 반응 API나 새 저장 API를 연결하지 않는다.
- 승인·반려·보완요청 의견 입력과 처리 버튼은 피드 카드에서 제공하지 않는다. 기존 리스트 항목 선택으로 여는 우측 상세 패널에서 계속 제공한다.
- 피드형과 리스트형을 전환할 때마다 문서 목록을 다시 조회하고, 선택된 보기 방식의 스켈레톤을 데이터 준비 완료까지 표시한다.
- 피드형은 기존 문서 목록 API에 `includeDetails=true`를 전달한다. 반환된 각 문서에 본문, 결재선, 첨부, 초기 댓글 페이지와 댓글 첨부 및 이전 댓글 커서를 포함하고, 전체 응답이 완료된 뒤 모든 카드를 한 번에 렌더링한다. 리스트형은 기존 요약 목록 응답을 유지한다.
- 초기 댓글은 공지사항처럼 최신 3개 root 댓글 페이지를 제공하며, 이전 댓글은 기존 댓글 페이지 API로 조회한다. 피드 선조회는 문서 조회수/조회 이력을 증가시키지 않는다.
- 피드 목록 응답 또는 필수 데이터 조립 실패 시 부분 데이터로 피드를 성공 표시하지 않고 명시적 오류와 재시도 수단을 제공한다. 카드별 초기 상세/댓글 요청이나 viewport 지연 요청은 사용하지 않는다.
- 피드 작성자 메뉴의 수정은 Composer를 열고 닫힐 때 목록과 이미 마운트된 상세 카드를 quiet refresh한다. 리스트 상세 패널에서 수정할 때는 앞 절과 같이 패널을 유지한다.
- 피드 내 카드 상호작용은 우측 상세 패널을 열지 않는다. 리스트 항목 선택은 기존대로 상세 패널을 연다.
- 필터, 범위 선택, 상단 고정 기능, 빈 상태, 요약 영역, 문서 작성 동작은 유지한다.

### 상세 수정 모달

- 상세 메뉴에서 수정을 선택해도 `detailDocumentId`를 초기화하지 않는다.
- 수정 모달은 상세 패널 위에 표시되며, 닫기·취소·저장 후에도 같은 상세 패널이 유지된다.
- Composer 종료 시 목록/요약 및 선택 상세를 조용히 재조회한다. 현재 내용을 유지하며 페이지/패널 전체 로딩 스켈레톤을 표시하지 않는다.
- 갱신 실패는 기존 오류 표현으로 노출하고 열린 상세 패널을 유지한다.

## 변경 범위

- `frontend/src/pages/groupware/documents/write/`의 문서 상세 컴포넌트, 피드 카드, 페이지 상태, 관련 테스트를 변경한다.
- 공통 `FeedCard`, 기존 `DocumentApprovalDetailFeed` 동작, 문서 상세/댓글 서비스, 인증 이미지 처리 코드를 재사용한다.
- 작업지시서, 계획서, 상세 사양, 결과 문서 및 375px/768px/1280px 스크린샷을 갱신한다.
- `backend/src/main/java/egovframework/let/groupware/approval/`의 목록 API 컨트롤러, 서비스, 피드 응답 DTO와 관련 테스트를 변경한다. `includeDetails=true`일 때만 응답을 확장하고 기본 목록 및 요약 응답을 유지한다.
- DB 스키마 및 공지사항 기능은 변경하지 않는다. 백엔드 API 계약 확장은 피드 요청에 한정한다.

## 작업 절차

1. 구현 전 DB MCP `list_tables` 및 관련 테이블 `describe_table`을 수행하고, 서비스/컨트롤러 테스트를 작성해 기존 목록과 신규 피드 계약을 검증한다.
2. 기존 목록 endpoint에 선택적 `includeDetails`를 추가한다. 피드 DTO는 기존 문서 상세/댓글/첨부를 반환하되 조회 이력/조회수는 변경하지 않는다.
3. 프런트엔드 서비스와 타입을 확장하고 보기 전환마다 모드별 재조회/스켈레톤을 표시한다. 피드는 일괄 응답 완료 후에만 표시하고 카드별 상세/댓글 조회를 제거한다.
4. 기존 상세 컴포넌트에 선조회 데이터를 주입하며 댓글의 이전 페이지 조회/댓글 조작, 반응, 권한 및 quiet refresh 동작을 유지한다.
5. 백엔드 대상 테스트, 프런트엔드 집중 테스트, production build를 실행한다.
6. `/groupware/doc/write`를 375px, 768px, 1280px에서 확인하고 결과 보고서/스크린샷을 기록한다.

## 완료 조건

- 피드 모드에서 필터 결과의 모든 문서가 문서 상세 카드로 표시된다.
- 카드에서 문서 본문/이미지, 결재선 정보, 첨부, 댓글, 기존 로컬 좋아요 토글이 동작한다.
- 피드/리스트 전환 때 재조회와 모드별 스켈레톤이 보이고, 피드는 하나의 상세 목록 응답이 끝난 후 본문·첨부·초기 댓글을 가진 전체 카드가 표시된다.
- 일반 목록 및 요약 API 응답은 기존 형태를 유지하고 피드 응답만 `includeDetails=true`로 확장된다. 피드 선조회는 조회수/조회 이력에 영향을 주지 않는다.
- 피드 카드에 승인·반려·보완요청 처리 컨트롤은 없고, 리스트형 상세 패널에는 기존대로 남는다.
- 상세 목록 실패는 부분 피드를 노출하지 않고 명시적 오류/재시도를 제공한다. 이전 댓글 페이지 조회는 기존 API를 계속 사용한다.
- 피드 상호작용은 상세 패널을 열지 않고, 리스트 항목 선택은 상세 패널을 연다.
- 수정 모달 종료 후 상세 패널이 유지되고 전체 로딩 스켈레톤 없이 목록/상세가 갱신된다.
- 관련 테스트/build/browser 확인과 결과 문서 및 3개 뷰포트 스크린샷이 존재한다.
