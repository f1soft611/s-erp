# 20261014_006 문서작성 피드 공지사항 UI 정합성 작업지시서

## 작업 목적

문서작성 페이지의 피드형을 공지사항 피드의 공통 UI 배치와 맞추고, 피드에서는 본문을 카드 안에서 펼쳐 보이도록 한다. 리스트형에서 상세 우측 패널을 여는 동작은 유지한다. 상세 메뉴의 문서 수정 모달은 패널을 닫지 않고 표시하며, 모달이 닫힌 뒤 데이터 갱신은 전체 로딩 화면 없이 처리한다.

## 승인된 동작

### 피드와 리스트

- 기본 보기 방식은 기존과 같이 리스트형이다.
- 피드형 카드의 공통 배치·간격·반응형은 공지사항 피드 UI 기준으로 맞춘다.
- 피드 카드는 문서의 업무구분과 결재상태를 표시한다.
- 피드의 `더보기`/`접기`는 카드 내부에서 본문을 확장/축소하며 우측 상세 패널을 열지 않는다.
- 문서 목록 응답은 요약만 제공하므로, 본문 확장 시 기존 상세 조회 API를 사용해 본문을 지연 조회한다. 확장된 본문은 현재 페이지 세션 안에서 문서 ID별 재사용한다.
- 본문 조회 중에는 카드 안에서 로딩을 표시한다. 실패 시 오류와 재시도 동작을 제공한다.
- 리스트형 항목 선택은 기존대로 우측 상세 패널을 연다.
- 상단 고정 문서, 보기 전환, 필터, 빈 상태, 요약 영역은 유지한다.

### 상세 수정 모달

- 상세 메뉴에서 수정을 선택해도 상세 우측 패널을 닫지 않는다.
- 수정 모달은 열린 상세 패널 위에 표시한다.
- 모달을 닫거나 저장한 뒤 목록·요약과 선택된 상세 정보를 조용히 갱신한다. 이때 페이지 또는 상세 패널의 전체 로딩 스켈레톤을 표시하지 않는다.
- 갱신 실패는 기존 페이지/패널 오류 표현으로 알리고 열린 상세 패널을 유지한다.

## 변경 범위

- `frontend/src/pages/groupware/documents/write/`의 피드 카드, 문서작성 페이지 상태, 상세 패널 갱신 상태를 변경한다.
- 문서 본문 표시와 인증 이미지 처리는 기존 전자결재 상세에서 사용하는 API와 인증 이미지 fetch를 재사용한다.
- 관련 프런트엔드 테스트, 날짜별 계획/사양/결과 문서, 브라우저 스크린샷을 갱신한다.
- 백엔드, API 계약, 권한, DB 및 공지사항 기능은 변경하지 않는다.

## 작업 절차

1. 계획서와 상세 사양서에 파일 범위·동작·오류·검증 기준을 확정한다.
2. 프런트엔드 실패 테스트로 피드 인라인 확장, 지연 본문 조회, 리스트 상세 진입, 상세 유지 및 조용한 갱신을 고정한다.
3. 기존 공통 피드 UI와 문서 본문 이미지 수명주기를 재사용해 피드 렌더링을 구현한다.
4. 문서작성 목록과 선택 상세의 조용한 갱신을 구현하고 회귀 테스트를 통과시킨다.
5. 대상 Vitest와 프런트엔드 production build를 실행한다.
6. `/groupware/doc/write`의 피드/리스트, 상세 수정 모달을 브라우저로 확인하고 375px, 768px, 1280px 스크린샷을 결과 폴더에 저장한다.

## 완료 조건

- 피드형 카드의 UI 배치가 공지사항 기준과 같고 문서 업무구분·결재상태를 유지한다.
- 피드 펼침/접힘은 본문을 인라인으로 표시하고 우측 패널을 열지 않는다.
- 지연 본문 조회의 로딩·오류·재시도가 카드 안에서 동작한다.
- 리스트 항목 선택과 우측 상세 패널 동작은 기존대로 유지된다.
- 수정 모달을 띄우고 닫거나 저장한 뒤에도 상세 패널이 유지된다.
- 모달 종료 후 데이터가 갱신되는 동안 전체 로딩 스켈레톤이 나타나지 않고, 오류는 숨겨지지 않는다.
- 관련 테스트, 빌드, 375px/768px/1280px 브라우저 확인 및 결과 문서/스크린샷이 존재한다.
