# 20261014_008 문서 결재 취소 및 상태·구분 표시 통일 작업지시서

## 작업 목적

문서작성 페이지에서 기안자가 결재 신청을 취소하고 결재자가 자신의 승인을 취소할 수 있는 조건을 명확히 적용한다. 문서 리스트·피드·상세의 결재 상태 및 문서 구분 배지와 색상을 통일하고, 본문이 접힌 동안에는 결재선도 함께 감춘다.

## 확정 요구사항

### 결재 취소

- 기안자는 문서가 `PENDING`이고 결재/합의 참여자가 아직 처리하지 않았을 때만 `결재신청 취소`를 할 수 있다.
- 기안 취소는 문서를 삭제하지 않는다. 문서 본문·첨부·결재선·기존 이력을 보존하고 상태를 `DRAFT`로 돌려 수정 가능한 임시저장으로 복구한다.
- 결재자/합의자는 자신의 `APPROVED` 결재선을 취소할 수 있다. 자신의 단계보다 뒤인 결재 단계에서 처리된 참여자가 없어야 한다.
- 뒤 단계가 활성 `PENDING`이더라도 아무도 처리하지 않았다면 취소할 수 있고, 해당 뒤 단계는 `WAITING`으로 복귀한다. 같은 병렬 단계 동료의 처리는 뒤 단계 처리로 보지 않는다.
- 최종 승인되어 `COMPLETED`가 된 문서, `REJECTED` 문서, `REVISION_REQUESTED` 처리 및 `RETURNED` 결재선은 취소 대상이 아니다.
- 상신 취소와 승인 취소 버튼은 리스트에서 연 문서 상세에만 제공하고, 실행 전 확인을 받는다. 승인·반려·보완요청 처리는 피드와 상세에 모두 제공한다. 피드에서 반려·보완요청을 실행할 때는 필수 사유 대화상자를 표시한다.
- 허용 여부는 서버가 인증 사용자, 테넌트, 문서 상태, 소유자/결재선, 뒤 단계 처리 여부를 잠금과 트랜잭션 안에서 최종 검증한다. 조건 경합은 오류로 알리고 성공처럼 처리하지 않는다.

### 표시 통일

- 모든 화면의 결재 상태 라벨과 상태 배지 색상은 공통 프론트 표시 메타데이터를 사용한다.
- 표시 상태는 `임시저장`, `결재진행중`, `승인`, `반려`, `보완요청`으로 통일한다. API 상태 코드 및 상태 전이는 변경하지 않는다.
- 문서 구분 배지는 짧은 라벨 `기안`, `업무`, `지출`, `근태`를 사용한다. 구분별 색상은 파랑, 청록, 주황, 보라로 고정한다. 문서 작성/검색의 정식 양식명은 유지한다.
- 상세에는 상태와 문서 구분을 함께 표시하고 리스트·피드·상세에서 동일한 라벨과 색상을 사용한다.

### 본문 및 결재선

- 긴 본문이 접혀 있고 더보기 동작이 가능하면 결재선도 감춘다.
- `더보기`에서 본문과 결재선을 함께 표시하고 `접기`에서 함께 감춘다.
- 본문이 짧거나 접기 기능이 필요하지 않으면 결재선은 항상 표시한다.

## 승인된 UI 보완 요구사항

- 리스트·피드·상세의 상태 및 문서구분 배지는 공통 `border-radius: 8px`을 사용한다. 임시저장 상태는 outlined, 나머지 결재 상태는 filled로 표시하며 리스트도 피드·상세와 같은 variant를 사용한다.
- 결재선의 `PENDING` 진행 테두리는 결재진행중 상태 배지와 같은 info 색상을 사용한다.
- 피드와 상세 상단 오른쪽 툴바 순서는 `가능한 결재 동작 → 결재 상태 → 문서구분 → 세로 구분선 → 상단고정 → 더보기`이다. 좁은 화면에서 항목이 겹치지 않도록 줄바꿈한다.
- 승인 버튼은 primary contained, 반려 및 결재 취소 버튼은 error contained, 보완요청은 기존 warning 계열을 유지한다.
- 상신된 `PENDING`/`IN_PROGRESS` 문서는 피드·상세 더보기에서 삭제할 수 없다. 삭제는 `DRAFT`에서만 허용한다. 수정 또는 삭제 메뉴가 모두 없으면 더보기 아이콘도 숨긴다.
- 기존 상신/승인 취소는 상세 전용이며, 툴바 순서상 결재 상태 앞에 배치한다. 상단고정 동작은 현재 기능을 확장하지 않는다.
- 구현·검증 범위는 [승인된 UI 보완 계획](../../superpowers/plans/2026-10-14-document-approval-ui-refinement.md)을 따른다.

## 변경 범위 및 절차

- 프론트엔드: 문서작성 페이지의 결재 API 서비스, 상태/구분 표시, 피드·상세 결재 툴바/사유 대화상자, 상세 취소 버튼, 본문 확장 및 공통 리스트 배지 타입을 변경하고 집중 회귀 테스트와 production build를 수행한다.
- 백엔드: 기존 승인 API·서비스·DAO/Mapper에 역할별 취소 endpoint 및 잠금 기반 트랜잭션을 추가하고 서비스/컨트롤러/매퍼 테스트를 작성한다.
- DB: 신규 테이블이나 컬럼은 만들지 않는다. `tb_common_comment.event_type` 제약에 `SUBMISSION_CANCELED`, `APPROVAL_CANCELED`를 허용하는 날짜별 변경·롤백 파일을 만든다.
- 구현 순서는 [계획서](../../plan/20261014/20261014_008_문서결재취소_상태구분표시통일_계획서.md)를 따르고, 각 동작은 실패 테스트 작성 후 구현한다.
- 375px, 768px, 1280px 브라우저 확인과 비민감정보 스크린샷 및 결과 보고서를 `docs/result/20261014/document-approval-cancel-status-consistency/`에 기록한다.

## 완료 조건

- 기안 상신 취소와 결재자 승인 취소의 권한·상태·뒤 단계 검증이 서버에서 수행되고, 취소 이력이 보존된다.
- 리스트·피드·상세의 결재상태/문서구분 문구와 색상이 같은 규칙을 사용한다.
- 배지 반경/상태 variant, 툴바 순서, 버튼 강조, 결재선 진행 색상, 피드 사유 입력 및 DRAFT 전용 삭제가 승인된 UI 규칙과 일치한다.
- 상세에 문서구분 배지가 표시되고, 긴 본문 접기와 결재선 표시가 연동된다.
- 관련 백엔드 및 프론트엔드 테스트, 프론트엔드 build, 지정 뷰포트 확인이 끝나고 결과물이 날짜별 결과 폴더에 저장된다.
