# 20261014_007 문서작성 테스트 계정 psql 직접 실행 SQL 작업지시서

## 목적

운영자가 `psql -f` 또는 psql 세션에서 그대로 실행할 수 있도록 기존 문서작성 테스트 계정 초기화 SQL에 비밀번호 프롬프트와 서버 측 계정별 해시 계산을 추가한다. 실행 기록에서 확인된 원인은 SQL 구문 오류가 아니라 해시 GUC 10개 누락이다.

## 확인된 근거

- 실행 오류: 기존 SQL이 `Ten account-specific SHA-256/Base64 hashes are required` 예외를 발생시켰다.
- psql 실행 기록 끝은 `ROLLBACK`이며 해당 시도에서 계정 업데이트가 커밋되지 않았다.
- 읽기 전용 DB MCP 메타데이터 조회에서 관련 계정/테넌트 테이블 컬럼을 확인했다.
- 읽기 전용 DB MCP는 PostgreSQL 18.4와 내장 `sha256(bytea)` 함수 존재를 확인했다.
- 해시 계약은 `EgovFileScrty.encryptPassword(password, login_code)`, 즉 UTF-8 로그인 코드 바이트 뒤에 비밀번호 바이트를 넣어 SHA-256 후 Base64 인코딩이다.

## 승인 범위

- 대상은 테넌트 코드 `T1358606250`의 `doc-write-test-user-01`~`doc-write-test-user-10`이다.
- 기존 SQL에 psql `\prompt`를 추가해 사용자가 새 비밀번호를 한 번 입력한다.
- SQL은 각 계정의 로그인 코드를 salt로 사용해 PostgreSQL 내장 SHA-256과 Base64로 해시 10개를 만든 뒤 기존 가드와 트랜잭션 업데이트를 수행한다.
- 비밀번호 입력은 psql 터미널에서 보이며 서버 쿼리 로그에도 포함될 수 있다는 위험을 사용자가 승인했다. 이 사실을 SQL 주석과 결과/상세 문서에 명시한다.
- 별도 PowerShell 도구는 제거한다. SQL 실행은 운영자가 직접 수행하며 에이전트는 DB에 쓰지 않는다.

## 안전 요구사항

1. 입력 원문을 SQL 파일, 명령행 인자, 별도 임시 파일 또는 저장소에 미리 기록하지 않는다.
2. psql은 `ON_ERROR_STOP`으로 실패 즉시 중단하고 미완료 트랜잭션을 롤백한다.
3. 비밀번호가 비어 있으면 정확히 열 개의 유효 해시가 만들어지지 않아 UPDATE 전에 명시적으로 중단한다.
4. 기존 테넌트/계정 개수 검증, 행 잠금, 다섯 개 갱신 컬럼과 갱신 행 수 검증을 유지한다.
5. 비밀번호 입력 뒤 psql 변수를 해제하고 성공 시 임시 해시 테이블을 커밋 전에 제거한다.
6. DB MCP 조회는 읽기 전용 계약 확인에만 사용한다.

## 완료 기준

- psql 전용 SQL에서 `\prompt` 후 각 고정 계정 코드의 UTF-8/SHA-256/Base64 해시를 계산한다.
- 기존 계정 제한, 트랜잭션 및 행 수 가드가 유지된다.
- 계약 테스트는 직접 실행 프롬프트/해시 구성과 기존 SQL의 보호 조건을 검증한다.
- docs/backend SQL 및 변경 이력 사본이 바이트 단위로 동일하다.
- 실제 DB 적용과 로그인 검증은 작업 범위에 포함하지 않는다.
