# 20260921_006 공지사항 상단 고정 영역 및 보기 전환 작업지시서

## 작업 분류

- 경로: `architectural`
- 대상: 프론트엔드
- 관련 화면: `/groupware/community/notice`
- 관련 컴포넌트: `CommunityNoticePage`, `frontend/src/shared/components` 공통 보기 컴포넌트, 도메인별 어댑터

## 작업 목적

공지사항을 시작점으로 게시판·자료실·그룹웨어 업무 화면에서 재사용할 수 있는 피드형·리스트형 공통 보기 기반을 마련한다. 공지사항 목록 상단에는 중요 공지를 빠르게 확인할 수 있는 고정 영역을 추가하고, 기본 보기 방식은 기존 피드형으로 유지한다.

## 요구사항

1. 기존 필터 영역과 공지 목록 사이에 상단 고정 영역을 추가한다.
2. 상단 고정 영역에는 현재 목록에서 상단 고정 대상으로 판별되는 공지를 표시한다.
3. 상단 고정 공지가 없을 때는 빈 상태를 표시하고 일반 공지 목록은 그대로 제공한다.
4. 상단 고정 영역 우측 끝에 피드형·리스트형 보기 전환 컨트롤을 제공한다.
5. 최초 진입 시 피드형을 기본 선택한다.
6. 리스트형 선택 시 공지 항목을 행 중심의 리스트 형태로 표시한다.
7. 피드형 선택 시 현재 카드 기반 피드 표시를 유지한다.
8. 보기 모드 선택값 자체는 서버에 저장하지 않지만, 피드형·리스트형 전환 버튼을 클릭하면 해당 모드로 목록을 다시 조회한다.
9. 피드형은 현재 카드 기반 표시를 유지하고, 리스트형은 제목·작성자·작성일시를 중심으로 간결하게 표시한다.
10. 리스트형 항목 클릭 후 우측 패널에서 요약 영역을 대체해 상세 현황을 표시하는 기능은 이번 작업에서 구현하지 않는다.
11. 리스트형 전환으로 인해 기존 피드 상세 패널·확장 기능을 새로 연결하거나 변경하지 않는다.
12. 피드형 전환 중에는 피드형 스켈레톤을, 리스트형 전환 중에는 리스트형 스켈레톤을 표시한다.
13. 재조회가 실패하면 선택한 모드의 목록 영역에 오류 상태를 표시하고 기존 재시도 흐름을 유지한다.
14. 피드형과 리스트형의 항목 렌더링 소스와 전용 스켈레톤을 별도 컴포넌트로 분리한다.
15. 페이지 조립부는 선택된 모드, 재조회, 로딩·오류 상태를 관리하고 각 전용 컴포넌트에는 필요한 데이터와 이벤트만 전달한다.
16. 피드형·리스트형 공통 컴포넌트는 공지사항 API 타입이나 공지 전용 액션을 직접 참조하지 않고, 제네릭 데이터와 렌더러·콜백을 전달받는다.
17. 게시판·자료실·그룹웨어 업무 화면은 각 도메인의 데이터 필드와 클릭·상세·다운로드 동작을 공통 컴포넌트가 요구하는 표시 모델로 변환하는 어댑터를 둔다.
18. 공통 컴포넌트는 피드형·리스트형 레이아웃, 모드 전환 컨트롤, 상단 고정 영역, 모드별 스켈레톤을 제공하고 도메인 비즈니스 로직은 소유하지 않는다.
19. 기존 필터, 새 공지 작성, 새로고침, 오류·로딩·빈 상태 동작은 변경하지 않는다.
20. 모바일·태블릿·데스크톱에서 상단 고정 영역과 보기 전환 컨트롤이 겹치거나 가로로 잘리지 않아야 한다.

## 현재 확인 결과

- `CommunityNoticePage`가 필터, 공지 목록, 요약 패널을 조립하고 있다.
- `NoticeFeedList`가 `FeedList`와 카드 렌더러를 통해 피드형 공지 항목을 직접 표시하고 있다.
- `NoticeFeedItem.highlight`와 API의 `isNotice === 'Y'` 매핑이 이미 존재하므로 상단 고정 대상 판별에 재사용할 수 있다.
- 기존 화면에는 피드형·리스트형 보기 상태나 상단 고정 전용 표시 영역이 없다.
- 현재 공지 재조회 함수가 필터 변경·재시도 흐름에서 사용되고 있으므로 보기 모드 전환 시에도 같은 조회 경로를 재사용할 수 있다.
- 피드형은 댓글·첨부·상세 확장 등 기존 상호작용이 많으므로 현재 `NoticeFeedList`를 피드 전용 소스로 유지하고, 리스트형은 별도 전용 컴포넌트로 분리하는 것이 책임 경계에 맞다.
- `frontend/src/shared/components/feed/FeedList.tsx`가 제네릭 목록 렌더링의 기존 기반이므로, 공통 보기 컴포넌트는 이 추상화와 기존 공통 첨부·댓글 컴포넌트 패턴을 우선 활용한다.
- 기존 테스트에는 공지 목록 및 피드 상호작용 회귀 케이스가 있어 보기 모드별 테스트를 추가할 수 있다.

## 접근 방식 비교

### 대안 A: 페이지에서 별도 상단 고정 목록과 보기 모드별 컴포넌트를 모두 분리

- 장점: 모드별 마크업과 상단 영역의 책임이 명확하다.
- 단점: 상세·댓글·첨부 이벤트 연결이 중복되고 기존 동작 회귀 범위가 커진다.
- 판정: 동작 중복이 커서 채택하지 않는다.

### 대안 B: 피드형·리스트형 전용 컴포넌트를 분리하고 페이지가 모드를 조립

- 장점: 피드형의 복잡한 상호작용과 리스트형의 단순 행 표시가 서로 영향을 주지 않고, 각 모드의 스켈레톤·테스트·반응형 규칙을 독립적으로 관리할 수 있다.
- 단점: 모드 전환을 위한 공통 props와 페이지 조립 코드가 필요하다.
- 판정: 소스 분리 요구와 기존 피드 동작 보존을 함께 만족하므로 채택한다.

### 대안 C: 하나의 목록 컴포넌트 내부에서 조건부로 피드형·리스트형을 렌더링

- 장점: 파일 수와 초기 연결 지점이 적다.
- 단점: 피드·리스트 마크업과 스켈레톤 조건이 한 파일에 섞여 변경 영향과 테스트 범위가 커진다.
- 판정: 소스 분리 요구에 맞지 않아 채택하지 않는다.

### 대안 D: 보기 모드를 전역 사용자 설정 또는 서버 설정으로 저장

- 장점: 재방문 시 사용자의 선택을 유지할 수 있다.
- 단점: 이번 요구사항에 없는 저장 계약과 초기화 정책이 필요하다.
- 판정: 범위를 벗어나므로 채택하지 않는다.

### 대안 E: 공지사항 폴더 안에 피드형·리스트형을 두고 다른 도메인에서 복사

- 장점: 공지사항 구현을 빠르게 끝낼 수 있다.
- 단점: 게시판·자료실·업무 화면마다 마크업과 스켈레톤이 복제되어 동작·접근성·반응형 수정이 분산된다.
- 판정: 공통 사용 요구와 유지보수 목적에 맞지 않아 채택하지 않는다.

## 구현 범위

- `frontend/src/shared/components` 아래에 도메인 중립적인 보기 모드 타입, 피드형 렌더러, 리스트형 렌더러, 모드 전환 컨트롤, 상단 고정 영역, 모드별 스켈레톤을 분리한다.
- 공통 피드·리스트 컴포넌트는 제네릭 표시 모델과 render prop/콜백을 사용하며 공지사항 타입·서비스를 import하지 않는다.
- `CommunityNoticePage`는 공지사항 데이터를 공통 표시 모델로 변환하는 어댑터와 공지 전용 상호작용 콜백을 제공한다.
- 기존 `NoticeFeedList`의 복잡한 피드 상호작용은 공통 기반을 사용하되 공지 전용 조립 계층으로 유지하고, 리스트형은 공통 리스트 렌더러에 공지 표시 모델을 주입한다.
- 게시판·자료실·그룹웨어 업무 화면이 동일한 공통 컴포넌트를 사용할 수 있도록 최소 계약과 사용 예시를 문서화한다.
- 페이지 조립부는 선택된 전용 컴포넌트와 모드별 스켈레톤을 렌더링한다.
- 상단 고정 공지는 기존 `highlight`/중요 공지 판별 결과를 이용해 표시한다.
- 보기 모드 전환 시 선택 모드를 먼저 반영하고 해당 모드의 공지 목록을 다시 조회한다.
- 재조회 중에는 선택한 모드에 맞는 피드형 또는 리스트형 스켈레톤을 표시한다.
- 피드형의 기존 제목 클릭, 확장·상세 조회, 첨부파일·댓글 등 동작은 유지한다.
- 리스트형은 제목·작성자·작성일시 중심의 표시만 구현하고, 항목 클릭에 따른 우측 상세 현황 패널은 후속 작업으로 남긴다.
- 관련 Vitest 회귀 테스트를 추가하고 프론트 빌드 및 375px·768px·1280px 브라우저 검증을 수행한다.
- `docs/result/20260921/notice-pinned-view-toggle/`에 결과 문서와 스크린샷을 기록한다.

- 공지 목록의 페이지네이션·정렬 정책 변경

## 완료 기준

- 공지 목록 상단에 상단 고정 영역과 피드형·리스트형 전환 컨트롤이 표시된다.
- 최초 진입 시 피드형이 선택되고 기존 카드형 화면이 보인다.
- 리스트형 선택 시 공지 목록이 행 기반 레이아웃으로 변경된다.
- 리스트형 행에는 제목·작성자·작성일시가 표시된다.
- 피드형과 리스트형의 목록 렌더링 소스가 별도 컴포넌트로 분리되어 있다.
- 피드형과 리스트형의 스켈레톤 소스가 별도 컴포넌트로 분리되어 있다.
- 공통 보기 컴포넌트가 공지사항 API 타입과 분리되어 있다.
- 게시판·자료실·그룹웨어 업무에서 재사용할 수 있는 제네릭 props/표시 모델 계약이 정의되어 있다.
- 공지사항은 도메인 어댑터를 통해 공통 컴포넌트를 사용한다.
- 피드형·리스트형 전환 시 목록을 다시 조회한다.
- 피드형 전환 중에는 피드형 스켈레톤, 리스트형 전환 중에는 리스트형 스켈레톤이 표시된다.
- 중요 공지가 상단 고정 영역에 표시되고, 없을 때 빈 상태가 표시된다.
- 피드형의 기존 상세 조회·확장, 첨부, 댓글, 수정·삭제 동작이 정상 동작한다.
- 리스트형 클릭 후 우측 상세 현황 패널은 표시되지 않으며, 해당 기능이 범위에서 제외되어 있음이 유지된다.
- 보기 전환 컨트롤과 목록이 375px, 768px, 1280px 뷰포트에서 겹침·잘림·가로 스크롤 없이 표시된다.
- 관련 테스트와 빌드, 브라우저 검증 결과가 결과 문서에 기록된다.
