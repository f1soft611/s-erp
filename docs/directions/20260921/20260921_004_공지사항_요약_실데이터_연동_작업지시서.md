# 20260921_004 공지사항 요약 실데이터 연동 작업지시서

## 작업 분류

- 경로: `bounded`
- 대상: 프론트엔드
- 관련 화면: `/groupware/community/notice`
- 관련 컴포넌트: `CommunityNoticePage`, `NoticeSummaryPanel`

## 작업 목적

공지사항 페이지의 요약 영역이 정적 샘플 숫자와 하드코딩된 이슈를 표시하지 않고, 현재 공지사항 API로 로드한 실제 게시글 목록의 조회수·댓글수·첨부파일·중요공지·작성일 데이터를 기준으로 표시하도록 구성한다.

## 확정 요구사항

1. 공지 요약 영역은 현재 `fetchNoticePosts`가 반환한 목록을 단일 데이터 원천으로 사용한다.
2. `전체 공지`는 현재 목록의 게시글 수를 표시한다.
3. `이번 주`는 현재 목록 중 현재 날짜 기준 이번 주에 생성된 게시글 수를 표시한다.
4. `중요 공지`는 `isNotice === 'Y'`인 현재 목록 게시글 수를 표시한다.
5. `첨부 문서`는 현재 목록 게시글의 첨부파일 개수를 합산해 표시한다.
6. `최근 이슈`는 각 게시글의 `viewCount + commentCount`를 이슈 점수로 계산하고, 점수가 높은 순서로 최대 3건을 표시한다.
7. 최근 이슈에는 게시글 제목과 조회수·댓글수 및 이슈 점수를 실제 값으로 표시한다.
8. 게시글이 없으면 요약 수치는 0으로 표시하고 최근 이슈에는 빈 상태를 표시한다.
9. 조회수·댓글수·첨부파일 수가 없거나 유효하지 않은 경우 0으로 정규화한다.
10. 기존 공지 목록, 상세 조회, 댓글·첨부파일 동작과 필터 동작은 변경하지 않는다.
11. 현재 목록 기반 집계임을 코드와 화면의 접근성/보조 설명에서 혼동 없이 표현한다.

## 현재 확인 결과

- `NoticeSummaryPanel`은 `summaryStats` 정적 배열을 받아 숫자를 표시한다.
- `NoticeSummaryPanel`의 최근 이슈는 세 개의 문자열 샘플을 하드코딩하고 있다.
- `CommunityNoticePage`는 `noticeItems`에 API 게시글을 `NoticeFeedItem`으로 변환해 보관한다.
- `NoticeBoardPostApi`에는 `viewCount`, `commentCount`, `isNotice`, `createdAt`, `attachments`가 이미 존재한다.
- 별도의 전체 건수·집계 API 응답 계약은 현재 존재하지 않는다.

## 권장 설계

- `CommunityNoticePage`에서 `noticeItems`를 입력으로 요약 통계와 최근 이슈를 `useMemo`로 파생한다.
- 날짜 계산, 수치 정규화, 이슈 정렬은 페이지 외부의 순수 함수로 분리해 단위 테스트 가능하게 한다.
- `NoticeSummaryPanel`은 정적 데이터에 의존하지 않고 계산된 요약 통계와 최근 이슈를 props로 받는다.
- 최근 이슈 항목은 기존 공지 피드에서 사용하는 게시글 ID를 key로 사용하며, 동점은 최신 작성일 순으로 정렬하고 그마저 같으면 게시글 ID 내림차순을 적용한다.
- 백엔드 API와 DB는 변경하지 않는다.

## 완료 기준

- 정적 `summaryStats`와 하드코딩된 최근 이슈가 화면 표시 경로에서 제거된다.
- API 목록이 변경되면 공지 요약 수치와 최근 이슈가 같은 렌더링에서 갱신된다.
- 최근 이슈가 조회수와 댓글수의 합산값 내림차순으로 최대 3개 표시된다.
- 조회수·댓글수·첨부파일 누락과 빈 목록에서 예외 없이 0/빈 상태가 표시된다.
- 필터로 목록이 변경되면 요약 영역도 해당 목록 기준으로 갱신된다.
- 관련 테스트, 빌드, 모바일·데스크톱 브라우저 검증 결과가 결과 문서에 기록된다.
