# 출하계획·출하등록 품목기준 연계 작업지시서

## 사용자 요구

- 출하계획 대상은 수주 헤더가 아니라 수주 상세의 품목 행 기준으로 조회·선택한다.
- MANUAL에서는 여러 수주의 상세 품목 행을 선택해 하나의 계획서에 등록할 수 있다. AUTO는 수주 1건당 계획 1건을 유지한다.
- 출하등록 대상은 계획 헤더가 아니라 출하계획 상세의 품목 행 기준으로 조회·선택한다.
- 하나의 출하에 여러 계획의 품목 행을 포함할 수 있으며, 선택하지 않은 형제 품목 행은 자동으로 포함하지 않는다.
- 출하계획현황은 출하현황과 같이 품목별 행으로 표시한다.
- 거래명세서는 이번 범위에서 제외한다.

## 확정 설계 기준

- 계획 가능 잔량은 수주상세 수량에서 해당 수주상세를 참조하는 활성 계획상세 수량 합을 뺀 값이다.
- 출하 가능 잔량은 계획상세 계획수량에서 해당 계획상세의 출하수량 합을 뺀 값이다.
- 계획 분할과 부분 출하를 유지한다. 각 수량은 저장 시 서버에서 다시 검증한다.
- 계획 헤더는 여러 수주의 상세 행을 담을 수 있고, 수주 ID는 계획 상세에 둔다.
- 출하 헤더는 단일 거래처 구조를 유지하므로 한 출하에 선택한 품목 행의 거래처는 모두 같아야 한다.
- 기존 직출하, AUTO 계획 생성, 권한/테넌트 범위, 초과출하 정책은 유지한다.

## 실행 순서

1. 이 작업지시서와 승인된 설계의 범위를 기준으로 날짜별 계획서와 상세사양서를 작성한다.
2. 구현 전에 `s-erp-postgresql-readonly` MCP로 관련 테이블 목록과 계획/출하 헤더·상세의 컬럼 및 제약을 확인한다. 업무 데이터 행은 조회하지 않는다.
3. 계획/출하 API, 상세행별 잔량 계산, 저장·수정·삭제의 트랜잭션 및 잠금 흐름을 조사하고 영향 파일을 확정한다.
4. 실패하는 테스트를 추가한 후 계획 헤더-수주 관계 제거, 상세행별 수주 참조, 품목 기준 계획/출하 선택, 품목별 계획현황을 구현한다.
5. 날짜별 SQL, 롤백, 변경 이력과 누적 스키마를 `docs/database` 및 `backend/DATABASE`에 동일하게 반영한다. DB에는 직접 적용하지 않는다.
6. 프론트엔드/백엔드 검증, 브라우저 375/768/1280px 확인, 영문 경로 스크린샷 및 결과 문서를 작성한다.
7. 관련 파일만 작업별로 분리해 커밋하고 각 커밋의 제목과 포함 내용을 결과 문서에 기록한다.

## 완료 조건

- 계획 선택기가 미계획 수주상세 품목 행만 표시하고, 여러 수주의 행 선택을 지원한다.
- 계획 등록에서 선택하지 않은 수주 품목은 자동 추가되지 않으며 분할 행을 유지한다.
- 출하 선택기가 미출하 출하계획상세 품목 행만 표시하고, 여러 계획의 개별 행 및 부분 수량 출하를 지원한다.
- 잔량 초과, 잘못된 원본 관계, 다른 거래처 혼합 출하는 서버가 거부한다.
- 출하계획현황 주 목록이 계획상세별 한 행이며, 문서 식별 정보와 품목·계획·출하·잔량 수량을 제공한다.
- 기존 AUTO, 직출하, 계획/출하 수정·삭제 역보정 동작이 회귀 없이 유지된다.
- 거래명세서와 무관한 테이블·화면·데이터 변경을 포함하지 않는다.
- 계획서, 사양서, 결과 문서, 스크린샷, 필요한 스키마 변경 기록이 모두 준비되고 검증 결과가 기록된다.
