# 20261112_003 구매요청현황 화면 작업지시서

## 작업 목적

등록한 구매요청을 조회하고, 필요하면 불러와 수정·삭제하는 구매요청현황 화면을
수주현황과 같은 구조로 만든다. S-ERP 규칙상 등록 화면은 신규 작성용이고,
기존 건의 조회·수정은 현황 → 상세 패널 → 조회/수정 다이얼로그 흐름으로 처리한다.

## 확정 범위

### 메뉴

- `구매관리 > 구매요청현황`(`/materials/request/request-status`) 메뉴를 추가한다.
- 메뉴 권한은 수주현황과 같게 READ, EXCEL을 부여하고, 역할 권한은
  `ORDER_STATUS`(수주현황)의 역할 권한을 복사한다. 대상 테넌트는 1이다.
- 모듈 `MATERIALS`와 상위 메뉴 `MATERIALS_PURCHASE`는 20261112_002에서 만든
  것을 사용한다.

### 백엔드

- 패키지 `egovframework.let.materials.request.status`에 목록 조회 API를
  수주현황 패턴과 같게 만든다.
- `GET /api/v1/materials/purchase-request-status`: 헤더+상세를 품목 행 단위로
  펼친 목록을 반환한다. 같은 테넌트, `use_at = 'Y'`만 조회한다.
- 단건 조회·수정·삭제는 20261112_002의 `/api/v1/materials/purchase-requests`
  API를 그대로 쓴다.

### 프론트엔드

- 위치 `frontend/src/pages/materials/request/status/`.
- 수주현황([SalesOrderStatusPage.tsx](../../../frontend/src/pages/sales/order/status/SalesOrderStatusPage.tsx))과 같은 구성:
  - 검색 영역(빠른 검색 + 상세검색, 검색 기본값 사용)
  - 품목 행 단위 F1-Grid, 같은 구매요청은 헤더 셀 병합
  - 구매요청번호 클릭 시 오른쪽 상세 패널
  - 상세 패널에서 조회/수정 다이얼로그. 다이얼로그는 구매요청등록 화면을
    embedded 모드로 띄운다.
- 상태는 영문 코드를 한글 라벨(요청/확정)로 표시한다. MES의 글자색 상태
  표시는 쓰지 않는다.
- `CONFIRMED` 상태는 수정 버튼을 비활성화하고 조회만 허용한다.

## 제외 범위

- 확정 처리, 발주대기 마감 처리 (구매요청확정 작업)
- 발주·입고 진행 수량 표시 (발주 테이블 생성 후)
- 일괄적용 (F1-Grid 공통 기능, 보류)
- SQL 실제 DB 적용

## 선행 작업

- 20261112_002 구매요청등록: 테이블, 모듈·메뉴, 단건 API, 등록 화면의
  embedded 모드가 먼저 있어야 한다.

## 구현 절차

1. 계획서와 상세사양서를 작성한다.
2. 메뉴 seed·롤백·변경 이력을 `docs/database/20261112`와
   `backend/DATABASE/20261112`에 동일하게 작성한다.
3. 목록 API 실패 테스트 → 구현.
4. 화면 실패 테스트 → 구현, 대시보드 분기 연결.
5. 테스트·빌드·브라우저 확인 후 결과 문서를 남긴다.

## 완료 조건

- 구매요청현황 메뉴에서 검색 조건으로 목록이 조회된다.
- 행 선택 시 상세 패널이 열리고, 조회/수정 다이얼로그에서 수정·삭제 후
  목록이 다시 조회된다.
- 확정 상태 건은 수정할 수 없다.
- 엑셀 권한이 있을 때만 엑셀 내보내기가 보인다.
- 테스트·빌드가 통과하고 결과 문서가 남는다.
