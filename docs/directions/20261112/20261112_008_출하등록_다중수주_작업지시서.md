# 출하등록 다중 수주 선택 작업지시서

## 목표

수주출하 등록에서 같은 거래처의 여러 수주를 한 출하 문서로 선택·등록할 수 있도록 한다.

## 작업 범위

- 수주 도움창에서 계획번호의 클릭 선택 동작을 제거하되, 계획번호는 표시용 컬럼으로 유지한다.
- 체크박스 선택 열 다음에 수주번호(같은 수주끼리 병합)와 계획번호를 표시하고, 하단에 `선택` 버튼을 `닫기` 옆에 둔다.
- 선택한 각 수주의 계획 상세 행을 출하 상세에 합친다. 여러 수주를 선택하더라도 거래처는 같아야 한다.
- 저장 API에서 상세행별 원 수주 ID를 처리하고, 출하 현황 및 재조회에서도 수주번호를 보존한다.
- DB 상세-헤더의 단일 수주 일치 제약을 제거하되, 상세-수주/계획 및 tenant 참조 제약은 유지한다.
- 날짜별 계획·상세사양·DB 이력·결과 문서를 작성하고 반응형 화면을 검증한다.

## 완료 조건

- 체크한 한 수주에 속한 전체 계획 상세 행이 선택되고, 여러 수주의 행이 한 출하 문서에 포함된다.
- 서로 다른 거래처 수주를 함께 선택하면 저장 대상에 반영하지 않고 도움창에 오류를 표시한다.
- 수주별 출하/계획 누계가 정확히 반영되고, 조회·수정·삭제 후에도 각 상세의 원 수주가 유지된다.
- 직출하와 기존 단일 수주출하 동작이 유지된다.
- 프론트엔드 테스트/빌드, 관련 백엔드 테스트, DB 마이그레이션 계약 검증이 통과한다.
- DB 변경 SQL, 롤백, 변경 이력을 `docs/database`와 `backend/DATABASE`에 동일하게 보관한다.
- 375/768/1280px 브라우저 검증과 결과 스크린샷을 남긴다.

## 기준 및 제약

- 기준 화면/컴포넌트: `frontend/src/pages/sales/delivery/create/components/SourceOrderPicker.tsx`
- 출하 상세 및 저장 계약: `SalesDeliveryCreatePage.tsx`, `salesDelivery.service.ts`, `SalesDeliveryServiceImpl.java`
- 날짜별 납품 API/스키마 기준: `docs/spec/20261104/20261104_001_납품관리_상세사양서.md`
- 기본 PostgreSQL MCP에서 출하 헤더/상세 테이블 컬럼 및 FK 메타데이터를 확인했다. 업무 데이터 행은 조회하지 않았다.
- 백엔드 Java 코드는 Java 8 문법 및 API와 호환되어야 한다.
- 본 작업에서는 출하 헤더의 `sales_order_id`를 대표 수주로 유지하고, 각 상세행 `sales_order_id`를 실제 원 수주로 사용한다. 여러 원 수주 수량을 동일 거래처/출하 문서에서 처리한다.
