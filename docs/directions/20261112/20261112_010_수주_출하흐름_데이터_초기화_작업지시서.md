# 수주·출하 흐름 데이터 초기화 작업지시서

## 목표

승인 설계에 따라 지정한 한 테넌트의 수주부터 출하등록까지 기존 업무 데이터를 제거하여 새 흐름을 다시 등록할 수 있는 PostgreSQL 초기화 스크립트를 작성한다.

## 작업 범위

- 실행자가 대상 `tenant_id`를 명시해야 한다. tenant 값이나 업무 데이터는 추정·조회해 넣지 않는다.
- 해당 테넌트의 수주, 출하계획, 출하등록과 대상 출하에 연결된 거래명세서를 FK에 맞는 역순으로 삭제한다.
- 수주를 참조하는 구매요청 상세가 있으면 해당 구매요청 문서 전체와 형제 상세를 삭제한다. 그 결과 더 이상 참조되지 않는 구매확정 헤더만 삭제한다.
- 테넌트, 거래처, 품목, 창고 등 마스터 데이터와 무관한 테넌트의 데이터는 보존한다.
- PK 및 문서번호 시퀀스는 초기화하지 않는다.
- SQL은 날짜별로 관리하고 `docs/database/20261112`와 `backend/DATABASE/20261112`에 동일 사본을 둔다. 스키마 변경은 포함하지 않는다.
- 애플리케이션 코드 변경이나 데이터베이스 직접 적용은 범위에서 제외한다.

## 실행 안전 기준

- 테넌트 ID 누락·비양수·미존재 시 삭제 전에 중단한다.
- 영향받는 행 수를 확인할 수 있도록 출력하고 모든 삭제를 한 트랜잭션으로 처리한다.
- FK 오류나 예상 밖 참조가 발생하면 전체 트랜잭션을 롤백한다.
- 기본 실행은 롤백되도록 구성하고, 운영자가 삭제 건수를 검토한 뒤 명시적으로 커밋하도록 안내한다.
- 실제 실행 전 별도 백업을 권고하며, 이번 작업에서는 DB에 적용하지 않는다.

## 완료 조건

- 작업지시서 기반 계획서와 상세사양서가 작성되어 있다.
- SQL 전방 스크립트가 tenant 범위를 모든 삭제 경로에 적용하며 FK 순서를 지킨다.
- 세션, 문서번호 시퀀스, 마스터 및 타 테넌트 데이터 변경이 없다.
- SQL 두 사본이 바이트 단위로 동일하고, 기본 롤백/수동 커밋 절차와 삭제 범위가 결과 문서에 기록되어 있다.
- 실제 DB 적용은 수행하지 않는다.
