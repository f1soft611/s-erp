# 작업지시서

## 목적

- F1-Grid의 기본 셀 편집은 기본 동작(텍스트/숫자/날짜 등)으로 유지하되, "플러그인 기반 에디터"를 추가해 확장 가능한 에디터 시스템으로 전환한다.
- 트리(Tree)와 일반 Grid 모두 기본적으로는 셀 편집이 비활성화되며, 에디터 플러그인이 등록된 경우에만 편집이 동작하도록 한다.
- 에디터에 대한 전/후 이벤트를 표준 인터페이스로 제공해서 개발자가 커스텀 로직을 주입할 수 있게 한다.

## 범위

### 포함

- `frontend/src/shared/components/f1-grid` 안의 컬럼/에디터/그리드 상태 구조 변경
- 에디터 플러그인 등록 방식 설계
- 에디터 시작 전/후 이벤트 훅 추가
- 트리/일반 Grid 공통 동작과 엔진 구조 반영
- 관련 문서 갱신 (`docs/guide/F1-GRID.md` 와 결과 문서)

### 제외

- 백엔드 API 변경
- DB 스키마 변경
- 다른 화면과 무관한 리팩터링

## 요구사항

1. 기본값 동작
   - `F1Grid`/`F1Tree`는 기본적으로 셀 편집을 하지 않는다.
   - 에디터 플러그인이 추가된 경우에만 편집 기능이 활성화된다.
2. 에디터 플러그인 분리
   - 기존 inline editor 로직은 핵심 그리드와 분리한다.
   - 각 에디터는 플러그인 형태로 등록 가능하도록 설계한다.
3. 이벤트 인터페이스
   - 에디터 진입 전 이벤트: `onBeforeEdit`, `beforeEdit`, 또는 동등한 이름의 표준 훅
   - 에디터 진입 후 이벤트: `onAfterEdit`, `afterEdit`, 또는 동등한 이름의 표준 훅
   - 개발자가 해당 이벤트를 정의해서 커스텀 처리 가능해야 한다.
4. 트리/그리드 공통 규칙
   - 기능은 공통 타입과 공통 컨트롤러를 통해 관리한다.
   - 트리와 일반 그리드 모두 동일한 에디터 플러그인 계약을 준수한다.
5. 문서화
   - F1-Grid 문서와 결과 문서에 새 옵션, 이벤트, 동작 의미를 반영한다.

## 완료 기준

- 기본 편집이 비활성화 상태에서 플러그인이 없으면 편집이 발생하지 않는다.
- 에디터 플러그인이 활성화된 경우만 편집이 가능하다.
- 에디터 전/후 이벤트가 호출되고 커스텀 개발자가 정의한 핸들러를 실행할 수 있다.
- 관련 테스트와 문서가 함께 갱신되어 있다.
