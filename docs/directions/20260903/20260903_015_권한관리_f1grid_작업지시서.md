# 작업지시서

## 제목

권한 관리 페이지 F1-Grid 기반 구현 및 권한별 사용자 매핑 화면 구성

## 배경

메뉴 관리 페이지는 기존 구조를 유지하면서 F1-Grid를 활용해 검색, 저장, 삭제, 엑셀 내보내기, dirty 상태 관리까지 포함한 화면으로 구성되어 있다. 권한 관리 화면도 동일한 페이지 구조와 동작 패턴을 적용해 사용자에게 일관된 설정 페이지 경험을 제공해야 한다.

현재 권한 관리 기능은 단순 목록/기본 화면 수준에 머물러 있고, 권한별 사용자 매핑 영역이 분리되어 있지 않다. 따라서 권한 마스터 관리와 권한별 사용자 매핑을 F1-Grid 기반으로 통합해, 메뉴 관리 페이지와 동일한 레이아웃 구조를 유지하면서 관리할 수 있도록 구현해야 한다.

## 요구사항

- 권한 관리 화면은 메뉴 관리 페이지와 동일한 구조를 사용한다.
  - 상단 경로 영역
  - 상단 버튼 영역
  - 검색 영역
  - 메시지 영역
  - 콘텐츠영역 1: 권한관리 F1-Grid
  - 콘텐츠영역 2: 권한별 사용자 매핑 F1-Grid
- 검색 영역은 권한별 기본 검색/필터 조건을 제공하고, 기존 페이지 구조와 스타일을 유지한다.
- 메시지 영역은 오류/성공 안내를 동일한 패턴으로 표시한다.
- 권한 관리 영역은 F1-Grid 기반 CRUD 동작을 사용한다.
- 권한별 사용자 매핑 영역도 F1-Grid 기반으로 구성하고, 권한과 사용자 연결 상태를 관리한다.
- dirty 상태/저장 버튼/확인 다이얼로그 흐름은 메뉴 관리 페이지와 동일한 UX를 우선 적용한다.
- 권한 관리 화면은 백엔드 API와 연동해 실제 데이터 조회/저장/삭제가 가능해야 한다.
- 권한 관리 및 사용자 매핑 데이터는 기존 S-ERP 권한/역할/사용자 모델과 맞물려 동작해야 한다.
- 관련 화면/서비스/컨트롤러/매퍼를 기존 구조에 맞게 유지한다.

## 변경 범위

### 프론트엔드

- `frontend/src/pages/settings/system/permissions/` 영역 또는 기존 설정 페이지 구조에 맞는 권한 관리 페이지 신규/확장 구현
- `frontend/src/shared/components/` 하위 공통 페이지 구조 재사용
- F1-Grid 기반 권한 관리 화면 구성
- 권한별 사용자 매핑 F1-Grid 구성
- 검색/메시지/버튼/dirty 상태 처리
- API 연동 서비스 및 타입 정의

### 백엔드

- 권한 마스터 조회/수정 API 검토 및 구현
- 권한별 사용자 매핑 조회/저장 API 구현
- 기존 controller/service/dao/mapper 패턴에 맞춘 API 확장
- 필요한 DB 조회/수정 로직 및 응답 구조 정합성 유지

### 문서

- 작업 완료 시 관련 문서와 결과 문서를 함께 갱신
- F1-Grid 관련 변경 사항은 문서 반영을 포함한다.

## 제외 범위

- 메뉴 관리 페이지 외 다른 설정 화면 재설계
- 기존 화면 구조를 벗어난 대규모 컴포넌트 리팩터링
- 불필요한 권한 정책 전반 개편
- 기존 기능과 무관한 백엔드 구조 대수정

## 완료 기준

- 권한 관리 페이지가 메뉴 관리 페이지와 동일한 레이아웃 구조를 유지한다.
- 상단 경로, 버튼, 검색, 메시지, 권한관리 F1-Grid, 사용자 매핑 F1-Grid 영역이 모두 표시된다.
- 권한관리 F1-Grid가 데이터 조회와 저장 흐름을 동작시킨다.
- 권한별 사용자 매핑 F1-Grid가 실제 권한과 사용자 연결 데이터를 표시하고 수정 가능하다.
- 저장/dirty 상태/에러 처리 흐름이 기존 설정 페이지와 일관되게 동작한다.
- 프론트엔드와 백엔드가 모두 실제 API 연동을 통해 동작한다.
- 관련 테스트 및 검증 로그를 확보하고, 결과 문서를 작성한다.
