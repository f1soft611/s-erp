# 앱 초기 진입 로딩 스피너 제거 작업지시서

## 요청 및 승인

- 앱 첫 진입 시 표시되는 두 스피너를 제거한다: 라우트 모듈 lazy-load 중 `AppRouter`의 `Suspense` fallback 스피너와, 대시보드 메뉴 정보를 불러오는 동안 표시되는 중앙 스피너.
- 라우트 모듈의 lazy loading 자체는 유지한다.
- 메뉴 정보가 준비되기 전까지 대시보드 콘텐츠를 렌더링하지 않는 기존 로딩 게이트를 유지한다. 대기 중에는 배경만 표시한다.
- 메뉴 조회 실패 안내와 재시도, 그 밖의 조회·저장 스피너는 유지한다.

## 범위

- `frontend/src/routes/AppRouter.tsx`의 `Suspense` fallback에서 스피너를 제거한다.
- `frontend/src/pages/dashboard/DashboardPage.tsx`의 초기 메뉴 조회 분기에서 스피너 표시만 제거한다.
- `frontend/tests/app-router-not-found.test.tsx`의 지연된 메뉴 응답 회귀 검증을 갱신한다.
- 날짜별 계획서, 상세사양서, 결과 문서 및 브라우저 스크린샷을 작성한다.

## 제외 범위

- 메뉴 조회·재시도 수명주기, 라우트 검증, 오류 처리 변경
- 공통 `AppLoadingSpinner` 변경 또는 다른 화면의 스피너 제거
- 메뉴 조회 완료 후 대시보드 레이아웃 변경
- API, 백엔드, DB 변경

## 완료 기준

1. 라우트 모듈 및 초기 메뉴 응답 대기 중 앱 진입 스피너가 렌더링되지 않는다.
2. 메뉴 응답 전 대시보드 메뉴 및 본문은 계속 표시되지 않는다.
3. 메뉴 응답 후 기존 대시보드가 정상 표시되고 오류/재시도 동작은 보존된다.
4. 집중 테스트, 프론트엔드 빌드, 375px·768px·1280px 브라우저 확인 및 결과 스크린샷이 완료된다.
