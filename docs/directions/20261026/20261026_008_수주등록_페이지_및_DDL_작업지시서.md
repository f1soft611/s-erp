# 20261026_008 수주등록 페이지 및 DDL 작업지시서

## 작업 목적

첨부한 `smart_haccp_schema_2.sql`의 수주 헤더/상세 구조를 현재 S-ERP의
테넌트와 기준정보 테이블 계약에 맞게 별도 DDL로 정리하고,
`/sales/order/create`에 F1-Grid 기반 수주등록 화면을 추가한다.

## 확정 범위

- 메뉴는 기존에 등록된 **영업관리 > 수주관리 > 수주등록**을 사용한다.
- 페이지 경로는 `/sales/order/create`이며 새 모듈/메뉴 데이터를 만들거나
  수정하지 않는다.
- DB 변경은 `tb_sales_order_hd`, `tb_sales_order_dt` 두 테이블의 DDL,
  롤백, 변경 이력, 누적 스키마 문서로 한정한다.
- 헤더는 `sales_order_id BIGSERIAL` 내부 PK와 tenant별 유일 `order_no`를
  모두 가진다.
- 상세는 `sales_order_detail_id BIGSERIAL` 내부 PK를 별도로 가진다.
  `(sales_order_id, line_no)`도 유일하게 유지한다.
- 거래처/품목 참조는 현재 마스터의 `(customer_id, tenant_id)` 및
  `(material_id, tenant_id)` 복합 FK로 격리한다.
- 현재 DB에 견적 테이블이 없으므로 `quot_no`는 nullable 값으로 유지하고
  FK는 만들지 않는다.
- 프론트엔드는 신규 수주 입력 전용이며 로컬 상세 행 편집/계산만 제공한다.
  수주 조회/저장 API와 백엔드 구현은 제외한다.
- 거래처 및 품목 선택기는 공통 UI로 만들고, 검색 함수를 주입받아 기존
  거래처/품목 조회 서비스를 연결한다.
- 공급가액은 수량×단가, 부가세는 공급가액의 10%(소수 둘째 자리 반올림),
  합계는 공급가액+부가세로 계산한다. 수량/단가 변경 시 부가세를 10%로
  재계산하며, 이후 사용자가 행의 부가세를 수정할 수 있다.
- 수주번호는 읽기 전용 안내로 표시하고 채번 정책은 저장 API 설계에서
  확정한다. 수주일은 로컬 날짜 기준 오늘, 상태는 `수주등록`을 기본값으로
  한다.
- DDL은 문서와 저장소에만 기록하며 MCP 또는 다른 DB 클라이언트로 실행하지
  않는다.

## DB 확인 근거

기본 `s-erp-postgresql-readonly` MCP에서 테이블 목록, 거래처/품목 컬럼 및
제약 메타데이터를 읽기 전용으로 확인했다. `tb_customer_info`의
`(customer_id, tenant_id)` 유니크 키와 `tb_material_info`의
`(material_id, tenant_id)` 유니크 키를 확인했다. 현재 기본 DB 테이블 목록에
견적 테이블은 없다. 업무 행과 테넌트 데이터는 조회하지 않았다.

## 구현 절차

1. 본 작업지시서를 기준으로 날짜별 계획서와 상세사양서를 작성한다.
2. 날짜별 계획과 상세사양에 따라 SQL 계약 정적 테스트와 프론트엔드 실패
   테스트를 먼저 추가하고, 미구현으로 실패함을 확인한다.
3. 두 테이블 DDL, 빈 테이블 전용 롤백, 변경 이력을 `docs/database`와
   `backend/DATABASE`에 동일하게 작성하고 `docs/database/db-schema.md`를
   갱신한다.
4. 공통 거래처/품목 picker와 금액 계산 도구를 구현하고, 기존 마스터 조회
   서비스를 주입한다.
5. 헤더 입력 및 F1-Grid 상세 행 편집을 구성하고 기존 `/sales/*` 인증
   대시보드의 `sales/create` 분기에 연결한다.
6. F1-GRID 안내 문서, 집중 테스트, 프론트엔드 빌드, 375px/768px/1280px
   브라우저 확인, 결과 문서와 스크린샷을 완료한다.

## 완료 조건

- 헤더/상세 내부 ID, 업무번호, 상세 순번 및 테넌트 안전 복합 FK가 승인된
  계약대로 생성 SQL에 포함된다.
- 생성 SQL, 롤백, 변경 이력의 `docs/database`/`backend/DATABASE` 사본이
  byte-identical이다. 롤백은 데이터가 있으면 중단한다.
- 수주등록 화면이 기존 메뉴 계층과 `/sales/order/create`에서 렌더링되고,
  고객/품목 picker가 기존 조회 서비스를 통해 검색·선택한다.
- 상세 행 추가/삭제, 금액 계산, VAT 수정/재계산, 헤더 합계가 동작한다.
- 저장 API 미연결 상태를 명확히 표시하고 저장 성공처럼 보이지 않는다.
- 집중 테스트와 빌드 결과, 3개 뷰포트 스크린샷 및 결과 보고서가 남는다.
- SQL을 실제 데이터베이스에 적용하지 않는다.
