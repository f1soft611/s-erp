# F1-Grid 조회 완료와 데이터 표시 시점 정합 작업지시서

## 요청

품목관리·거래처 관리 페이지에 처음 진입할 때 F1-Grid 로딩 스피너가 사라진 뒤 빈 그리드가 먼저 보이고, 잠시 후 조회 데이터가 나타나는 현상을 개선한다. 스피너가 사라지는 화면 프레임부터 조회된 행이 보이도록 한다.

## 원인

페이지의 조회 훅은 API 응답을 받은 뒤 `rows`와 `loading`을 갱신한다. F1-Grid는 전달된 `rows`를 내부 편집 모델과 동기화하는 작업을 passive `useEffect`에서 수행하므로, 부모의 `loading=false`가 반영된 화면이 내부 데이터 동기화보다 먼저 표시될 수 있다.

## 범위

- 공통 F1-Grid의 외부 `rows` 동기화 시점을 화면 페인트 이전으로 옮겨 조회 완료와 데이터 표시를 정합시킨다.
- 품목·거래처 페이지의 최초 조회뿐 아니라 같은 공통 그리드에서 발생하는 검색/재조회에도 일관되게 적용한다.
- 로딩 오버레이가 사라지는 프레임에 최신 행이 표시되도록 하고, 편집 중 외부 행 반영·선택·포커스·저장 행 확정 동작을 유지한다.
- API, 화면별 로딩 상태 생성·전달, 저장 로딩 정책, 백엔드 및 DB 계약은 변경하지 않는다.

## 완료 조건

1. 조회 중에는 기존 F1-Grid 로딩 오버레이가 계속 표시된다.
2. 새 행이 그리드 내부 데이터에 반영되기 전 빈 화면이 먼저 페인트되지 않는다.
3. 성공한 조회에서 스피너가 사라지는 시점에 조회 결과가 표시되고, 빈 결과는 빈 상태로 정상 표시된다.
4. 조회 오류, 편집 중 행 보존/리베이스, 저장 후 확정된 행 및 공통 F1-Grid/F1Tree 동작에 회귀가 없다.
5. 관련 회귀 테스트와 프론트엔드 빌드가 통과하고, 실제 브라우저 확인 결과와 캡처를 결과 문서에 남긴다.

## 검증 기준

- F1-Grid의 새 `rows` 반영과 로딩 종료를 함께 갱신하는 회귀 테스트를 추가한다.
- 대량 행 렌더링 및 기존 그리드 동작 테스트를 실행해 성능·편집 회귀를 확인한다.
- 프론트엔드 빌드를 실행한다.
- 가능한 인증된 브라우저 환경에서 품목관리·거래처 관리 화면을 확인하고 결과를 기록한다.
