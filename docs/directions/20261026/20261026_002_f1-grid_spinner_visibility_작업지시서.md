# F1-Grid 공통 로딩 스피너 작업지시서

## 요청

F1-Grid 로딩 스피너가 잘 보이지 않으며 다른 페이지의 기존 로딩 스피너와도 구현이 분리되어 있다. 모든 애플리케이션 로딩 스피너를 공통 컴포넌트로 통일하고 F1Grid/F1Tree의 표시를 더 잘 보이게 한다. 사용자는 2026-10-26에 공통 컴포넌트 통일과 화면별 크기 유지, Grid/Tree 2.4px 두께를 승인했다.

## 배경

- DashboardPage는 34px 기본 두께의 테마 스피너를 표시한다. 다른 페이지·다이얼로그·작업 버튼은 MUI `CircularProgress`를 직접 사용하며 서로 다른 크기와 색상을 지정한다.
- F1Grid와 일부 화면만 `AppLoadingSpinner`를 사용하고 있어 모든 로딩 표시의 구현을 일관되게 관리할 수 없다.
- Grid/Tree의 1.8px 스피너는 브라우저 렌더링에서 얇아 잘 보이지 않는다는 피드백이 있어 2.4px로 조정한다.
- 그리드 배경과 스피너가 섞이지 않도록 공통 F1Grid 로딩 오버레이의 시각 스타일을 조정한다.

## 범위

- `frontend/src`의 indeterminate MUI `CircularProgress` 사용처를 `AppLoadingSpinner`로 전환한다.
- 공통 컴포넌트는 기본 34px·3.6px를 유지하며, 호출부의 기존 크기, 두께, 색상, 접근성 라벨, 배치, 로딩 수명주기는 변경하지 않는다.
- F1Grid/F1Tree는 공통 컴포넌트의 34px 크기를 사용하고 Grid 오버레이에서만 2.4px 두께를 지정한다.
- 배경은 현재 테마의 `background.default`를 84% 불투명도로 사용한다.
- 로딩 상태, 입력 차단, 본문/그리드 구조, 스크롤, API 요청 및 완료 시점은 변경하지 않는다.
- F1-GRID 기능 문서, 관련 회귀 테스트, 375px·768px·1280px 브라우저 결과·캡처를 함께 갱신한다.

## 제외 범위

- 첫 접속 로더의 시각적 동작 변경
- 로딩 문구, 별도 아이콘, 스피너 크기 확대
- 화면별 loading 호출부와 저장/조회 정책 변경
- 백엔드, API, DB 변경

## 완료 조건

1. 앱 소스 내 모든 indeterminate 스피너 호출이 typed props를 전달할 수 있는 `AppLoadingSpinner`를 사용한다.
2. 공통 기본값과 화면별 기존 크기/색상/라벨이 보존된다. Dashboard는 34px·3.6px, Grid/Tree는 34px·2.4px이다.
3. 반투명 테마 배경 오버레이와 Grid/Tree 입력 차단 및 접근성 계약이 유지된다.
4. 공통/소비처 회귀 테스트와 프론트엔드 빌드가 통과하고, 소스 검색상 MUI `CircularProgress` 사용은 공통 래퍼 내부뿐이다.
5. 375px, 768px, 1280px 브라우저에서 로딩 중 실제 그리드 오버레이/스피너를 확인하고 결과 캡처를 남긴다.

## 검증 기준

- Vitest에서 기본 34px·3.6px 및 prop forwarding, 화면별 크기/색상/접근성, Grid/Tree 34px·2.4px 오버레이, `aria-busy`를 확인한다.
- 관련 소비처 테스트와 F1-Grid/F1-Tree 테스트를 실행하고 `npm run build`를 수행한다.
- 브라우저에서 10,000-row loading을 각 지원 뷰포트에서 트리거한다. 스피너 크기/두께, 중앙 배치, 오버레이 경계, 가로 넘침 없음, 로딩 완료 후 오버레이 제거를 확인하고 활성 로딩 중 화면을 캡처한다.
