# F1-Grid 공통 로딩 스피너 작업지시서

## 요청

F1-Grid 로딩 스피너가 잘 보이지 않으므로 S-ERP 첫 접속 때 사용하는 로딩 스피너와 같은 시각 방식으로 맞춘다. 사용자는 2026-10-26에 첫 접속 스피너와 동일한 방식(A)을 선택하고 설계를 승인했다.

## 배경

- DashboardPage 첫 접속 로더는 `CircularProgress size={34}`를 기본 두께와 테마 색상으로 표시한다.
- F1Grid와 DashboardPage는 같은 크기의 스피너를 별도로 구현하고 있어 공통 컴포넌트로 일관되게 관리할 필요가 있다.
- 사용자는 공통 구현을 사용하되 그리드 스피너만 얇게 표시하기를 요청했으며, 그리드 두께를 `1.8px`로 선택했다.
- 그리드 배경과 스피너가 섞이지 않도록 공통 F1Grid 로딩 오버레이의 시각 스타일을 조정한다.

## 범위

- 공통 F1Grid 오버레이에 한정하며, F1Tree 및 F1Grid 모든 사용 페이지가 동일한 오버레이와 스피너 두께를 사용한다.
- DashboardPage와 F1Grid는 `AppLoadingSpinner`를 공통으로 사용한다.
- 스피너 크기와 테마 기본 색상은 공통이며, DashboardPage는 `3.6px`, F1Grid/F1Tree는 `1.8px` 두께로 표시한다.
- 배경은 현재 테마의 `background.default`를 84% 불투명도로 사용한다.
- 로딩 상태, 입력 차단, 본문/그리드 구조, 스크롤, API 동작은 변경하지 않는다.
- F1-GRID 기능 문서, 회귀 테스트 및 작업 결과·브라우저 캡처를 함께 갱신한다.

## 제외 범위

- 첫 접속 로더의 크기·색상·두께 등 시각적 동작 변경
- 로딩 문구, 별도 아이콘, 스피너 크기 확대
- 화면별 loading 호출부 또는 저장/조회 정책 변경
- 백엔드, API, DB 변경

## 완료 조건

1. DashboardPage와 F1Grid가 공통 34px 스피너 구현을 사용한다.
2. F1Grid/F1Tree에서 스피너는 1.8px로 표시되고 DashboardPage 첫 접속 스피너는 기존 3.6px 외형을 유지한다.
3. 반투명 테마 배경 오버레이로 인해 스피너가 그리드 내용에 묻히지 않는다.
4. 공통 F1Grid 및 F1Tree 사용 화면에서 기존 loading 계약과 로딩 완료 후 상호작용이 유지된다.
5. 관련 F1-Grid 테스트와 프론트엔드 빌드가 통과한다.
6. 375px, 768px, 1280px 브라우저 뷰포트 검증 및 결과 캡처가 남는다.

F1Tree의 loading prop 전달이 F1Grid의 공통 오버레이에서 34px·1.8px 스피너로 렌더링되는지 회귀 테스트로 확인한다.

## 검증 기준

- Vitest에서 loading 오버레이, 34px 기본 스피너, 배경색, `aria-busy`를 확인한다.
- F1-Grid 관련 테스트를 실행하고 `npm run build`를 수행한다.
- 브라우저에서 지원 뷰포트 크기마다 오버레이가 그리드 영역 안에 표시되고 가로 스크롤을 만들지 않는지 확인한다.
