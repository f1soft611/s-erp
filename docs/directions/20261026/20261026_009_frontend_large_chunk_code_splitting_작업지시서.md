# 프론트엔드 대용량 청크 경고 해소 작업지시서

## 요청 배경

`frontend` production build에서 1,000 kB 초과 청크 경고가 반복된다. 현재 빌드에서 초기 `index` JavaScript는 1,192.30 kB이며 `exceljs`는 929.57 kB 별도 청크로 분리되어 있다. 경고 한도를 올려 숨기는 대신 실제 초기 번들을 줄인다.

## 작업 범위

- `AppRouter`의 페이지 모듈을 화면 진입 시 로드하도록 분리한다.
- 로그인 공지 팝업 호스트는 기존 인증 흐름과 동작을 유지하면서 별도 chunk로 분리한다.
- route 페이지 지연 로딩 중에는 공통 `AppLoadingSpinner`를 표시한다.
- `DashboardContent`의 기존 동기 화면 선택 동작과 테스트 계약은 변경하지 않는다.
- URL, 권한 보호, 메뉴와 업무 화면 매핑, 기존 chunk 경고 한도는 유지한다.

## 제외 범위

- 경고 임계값 상향 또는 경고 비활성화
- 페이지 기능, 권한, API, 업무 데이터, 백엔드 및 DB 변경
- 업무 화면 UI 재설계 또는 무관한 성능 최적화

## 완료 조건

1. 생산 빌드에서 1,000 kB 초과 chunk warning이 출력되지 않는다.
2. 모든 기존 라우트와 권한 보호 흐름이 유지된다.
3. Dashboard의 기존 메뉴 선택 시 대응 화면이 정상 표시된다.
4. 로그인 공지 팝업 호스트의 기존 인증 및 팝업 동작을 유지한다.
5. 집중 회귀 테스트에서 기존 기준 실패가 새 회귀로 증가하지 않고, production build 및 `git diff --check`가 통과한다.
6. 날짜별 계획서·상세사양서·결과 문서와 필요한 브라우저 캡처를 남긴다.
