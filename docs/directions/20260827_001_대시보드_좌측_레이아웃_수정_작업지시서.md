# 20260827*001*대시보드*좌측*레이아웃*수정*작업지시서

## 1. 작업 개요

현재 대시보드 좌측 영역은 모듈과 메뉴 구조가 혼재되어 있어, 화면 구조와 정보 계층이 명확하지 않다. 특히 Sales 영역이 대시보드에 잘못 추가되어 있어 해당 영역을 제거하고, 대시보드 기본 구조를 ERP형 네비게이션 패턴으로 정리해야 한다.

본 작업은 대시보드 화면을 단일 컴포넌트로 구성하지 않고, 기능 단위로 분리하면서 좌측 레이아웃을 재구성하는 것을 목표로 한다.

핵심 의도는 다음과 같다.

- 잘못 추가된 Sales 항목을 제거해 전체 대시보드 구조를 정리한다.
- 대시보드 화면을 페이지, 컴포넌트, 훅, 서비스 계층으로 분리한다.
- 좌측 영역은 상단 모듈 선택 영역과 하단 메뉴 트리 영역으로 분리한다.
- 사용자가 모듈과 하위 메뉴를 동시에 이해할 수 있는 ERP형 좌측 레이아웃을 구현한다.

---

## 2. 작업 목적

이번 작업의 목적은 다음 항목을 반영한 대시보드 구조를 구성하는 것이다.

- 잘못 배치된 Sales 항목을 제거한다.
- 대시보드 관련 UI 로직을 컴포넌트, 훅, 서비스로 분리해 유지보수성을 향상한다.
- 좌측 영역을 상단 모듈 영역 + 하단 메뉴 트리 구조로 변경한다.
- 사용자가 선택한 모듈과 하위 메뉴를 한눈에 인지할 수 있도록 시각적 계층을 정리한다.

---

## 3. 현재 문제점

현재 대시보드 구조는 다음과 같은 한계가 있다.

1. Sales 항목이 잘못 추가되어 있어 대시보드 구성의 의미가 흐려진다.
2. 대시보드 로직이 페이지 단일 컴포넌트에 집중되어 있어 재사용성과 확장성이 낮다.
3. 좌측 영역이 모듈 목록과 메뉴 목록이 혼합되어 있어 구조적 구분이 부족하다.
4. ERP형 레이아웃 기준으로는 모듈 선택 영역과 메뉴 트리 영역을 분리해야 하지만 현재 구조는 이를 충족하지 못한다.

---

## 4. 요구사항

### 4.1 Sales 제거

- 대시보드/좌측 네비게이션에서 Sales 항목을 제거한다.
- Sales와 관련된 경로, 메뉴 매핑, 상태 값, 더미 데이터, 섹션 표현이 있다면 함께 정리한다.
- 기존 구조에서 Sales가 사용된 데이터 정의 또는 레이아웃 조건도 함께 점검한다.

### 4.2 대시보드 구조 분리

- 대시보드 페이지를 단일 컴포넌트로 두지 않고 다음 계층으로 분리한다.
  - DashboardPage: 페이지 조립
  - DashboardSidebar: 좌측 네비게이션 영역
  - DashboardModuleSection: 좌측 상단 모듈 선택 영역
  - DashboardMenuTree: 좌측 하단 메뉴 트리 영역
  - DashboardContent: 메인 콘텐츠 영역
  - Dashboard hooks: 모듈/메뉴/선택 상태 관리
  - Dashboard services: 메뉴 데이터 조회 및 변환 로직
- 각 레이어는 책임을 분리하고, 기존 구조와 충돌하지 않도록 구성한다.

### 4.3 좌측 레이아웃 변경

- 좌측 영역은 다음 구조로 변경한다.
  - 상단: 모듈 선택 영역
  - 하단: 선택된 모듈의 메뉴 트리
- 좌측 전체 구조는 단일 리스트형 네비게이션이 아니라, ERP 스타일의 계층형 구조로 정돈한다.
- 모듈 선택과 메뉴 트리는 서로의 역할이 명확하게 구분되어야 한다.

### 4.4 상태 표현

- 현재 선택된 모듈은 시각적으로 강조되어야 한다.
- 하위 메뉴 트리에서 현재 선택된 메뉴도 구분되어야 한다.
- hover, active, selected 상태가 명확하게 구분된다.

### 4.5 화면 기준

다음 구조를 기준으로 구현한다.

```text
┌─────────────────────────────────────────────────────┐
│ 대시보드 영역                                       │
├───────────────┬─────────────────────────────────────┤
│ 좌측 네비게이션 │ 메인 콘텐츠 영역                     │
│ ┌───────────┐ │                                     │
│ │ 모듈 선택  │ │ 실제 업무 화면 / 카드 / 목록 / 통계    │
│ │ (상단)    │ │                                     │
│ └───────────┘ │                                     │
│ ┌───────────┐ │                                     │
│ │ 메뉴 트리  │ │                                     │
│ │ (하단)    │ │                                     │
│ └───────────┘ │                                     │
└───────────────┴─────────────────────────────────────┘
```

## 5. 구현 방향

### 5.1 컴포넌트 분리 방향

대시보드 로직을 아래와 같이 분리한다.

- DashboardPage
- DashboardSidebar
- DashboardModuleSection
- DashboardMenuTree
- DashboardContent
- useDashboardModules
- useDashboardSelection
- dashboardService

이 구조를 통해 다음을 보장한다.

- UI와 상태 관리 분리
- 메뉴 데이터 로직 재사용성 확보
- 대시보드 기능 확장 시 수정 범위 최소화
- 기존 대시보드 구조를 유지하면서 레이아웃 개선만 집중 반영

### 5.2 좌측 레이아웃 방향

- 좌측 영역 상단에는 모듈 목록 배치
- 모듈 선택 시 메뉴 트리 영역이 하단에 전개
- 좌측 영역은 고정 폭으로 유지하고 메인 콘텐츠 영역과 시각적 비중을 분리
- 선택 상태와 hover 상태를 명확히 구분해 ERP 스타일로 정리

### 5.3 데이터 구조 방향

다음과 같은 데이터 구조를 기준으로 구성한다.

```ts
const modules = [
  {
    id: 'system',
    name: '시스템',
    menus: [
      { id: 'dashboard', name: '대시보드', pageKey: 'dashboard' },
      { id: 'users', name: '사용자관리', pageKey: 'users' },
    ],
  },
];
```

Sales는 제외한다.
