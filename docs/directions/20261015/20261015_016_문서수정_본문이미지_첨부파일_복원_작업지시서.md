# 20261015_016 문서 수정 본문 이미지·첨부파일 복원 작업지시서

## 작업 분류

- 대상: 프론트엔드 전자결재 문서작성
- 화면: 문서 수정 및 보완 후 재상신 모달
- 참고 구현: 커뮤니티 공지사항 수정 모달의 기존 본문 이미지 및 첨부 처리
- DB/API 변경: 없음

## 작업 목적

기존 전자결재 문서를 수정할 때 본문에 저장된 이미지가 편집기에서 깨지지 않고 표시되며, 기존 첨부파일도 수정 모달에 나타나도록 한다. 수정 후 저장 시 유지된 첨부파일을 다시 업로드하지 않고, 사용자가 제거한 파일만 기존 삭제 API로 제거한다.

## 확인된 원인

- 수정 모달은 기존 문서의 `contentsHtml`을 편집기에 넣지만, 문서 상세 화면과 달리 인증이 필요한 임베디드 이미지 API 경로를 Blob URL로 변환하지 않는다.
- 수정 초기화 흐름에서 `initialDocument.attachments`를 첨부 상태로 설정하지 않아 기존 첨부파일 목록이 비어 있다.
- 공지사항 수정은 기존 이미지 URL의 Blob 로드와 기존 첨부 메타데이터 유지 처리를 제공한다. 문서 수정도 전자결재 전용 Blob 및 첨부 API 계약을 사용해 같은 사용자 경험을 제공한다.

## 요구사항

1. 수정 모달의 본문 기존 이미지는 전자결재 임베디드 이미지 API에서 인증된 Blob으로 불러와 표시한다.
2. 이미지 로드 실패는 편집기 안에 깨진 링크를 남기지 않고 기존 화면의 오류 표시 패턴에 따라 알린다.
3. 문서 수정 및 보완 후 재상신 모달은 서버 상세 응답의 기존 첨부파일을 파일명과 함께 표시한다.
4. 기존 첨부파일은 유지가 기본이며, 제거를 선택한 파일만 기존 첨부 삭제 API로 제거한다.
5. 유지된 기존 첨부파일은 새 첨부파일로 다시 업로드하지 않는다. 신규 파일 업로드/재시도 동작은 보존한다.
6. 문서 생성 모달과 상세 보기의 기존 이미지·첨부 동작은 변경하지 않는다.

## 작업 절차

1. 이 작업지시서를 기준으로 계획서와 상세 사양서를 작성한다.
2. 문서 수정 통합 테스트에 기존 첨부 표시/유지 및 이미지 Blob 로드 회귀 검증을 추가한다.
3. 상세 사양에 따라 전자결재 문서 수정 상태 초기화와 이미지 표시만 수정한다.
4. 대상 테스트, 프론트엔드 빌드, Problems 및 diff를 확인한다.
5. 가능한 인증된 브라우저 환경에서 데스크톱·태블릿·모바일 레이아웃을 확인하고 결과 문서와 캡처를 남긴다. 인증 화면 접근이 불가능하면 사유를 결과 문서에 기록한다.

## 비범위

- 백엔드, API 경로/응답 계약, DB 스키마 변경
- 새 첨부 다운로드 기능, 신규 업로드 정책, 문서 상세 화면 변경
- 공지사항 구현 변경 또는 RichTextEditor 전역 동작 변경

## 완료 기준

- 수정 모달이 기존 첨부파일을 표시하고, 저장 후 명시적으로 제거하지 않은 파일은 유지된다.
- 기존 임베디드 이미지가 인증된 Blob으로 표시되고, 저장 시 Blob URL이 콘텐츠에 기록되지 않는다.
- 신규 첨부 업로드, 이미지 업로드, 신규 문서 작성 및 상세 화면의 동작이 유지된다.
- 관련 회귀 테스트와 빌드가 통과하고, 브라우저 검증 여부·결과가 결과 문서에 기록된다.
