# 20261015_002 업무작성 자주 쓰는 결재선 작업지시서

## 작업 목적

업무작성 모달의 `결재선 설정` 창에서 자주 쓰는 결재선 저장, 불러오기, 이름 수정 및 삭제를 제공한다. 템플릿은 로그인 사용자별로 서버에 저장하고, 문서번호 코드에 따라 분리한다.

## 승인 요구사항

- 문서 코드별 분류는 기존 `eabus_no` 값을 사용한다.
  - 기안 `001`
  - 업무 `008`
  - 지출 `004`
  - 근태 `031`
- 템플릿에는 이름, 결재/합의 단계 순서, 단계별 참여자 순서, 참조자를 함께 저장한다.
- 기안자 고정 단계는 저장 템플릿에서 제외하고 불러올 때 현재 작성자의 고정 단계로 유지한다.
- 여러 템플릿 저장을 지원한다. 같은 사용자 및 문서 코드 안에서 템플릿 이름은 중복될 수 없다.
- 목록은 현재 작성 문서 코드에 속한 템플릿만 표시한다. 사용자는 템플릿 이름 변경 및 삭제를 할 수 있다.
- 불러오기는 설정 창의 임시 결재선과 참조자를 교체한다. 작성 화면 상태는 기존 `적용`을 눌렀을 때만 갱신한다. 취소/닫기는 모든 임시 변경을 폐기한다.
- 소유권은 인증된 tenant 및 사용자 ID로 검증한다. 요청 본문의 사용자 ID를 신뢰하지 않는다.
- 서버는 문서 코드, 이름, 참여자 및 순서값을 검증하고 오류를 기존 API/화면 오류 처리 패턴으로 명시한다.
- 현재 전자결재 문서용 `tb_electronic_approval_line_info`는 문서 처리 상태에 종속되므로 재사용하지 않는다.

## 작업 절차

1. 승인 설계와 기존 전자결재 데이터 계약을 기준으로 날짜별 상세 사양을 작성한다.
2. DB 테이블/제약, MyBatis 매핑, API 요청·응답의 실패 테스트를 먼저 작성한다.
3. 날짜별 마이그레이션과 백엔드 목록/생성/이름 변경/삭제 및 tenant·소유자 검증을 구현한다.
4. 프론트엔드 API 서비스 및 문서 코드별 템플릿 저장/불러오기/관리 UI를 테스트 우선으로 구현한다.
5. 작성 화면의 기존 결재선 설정 적용/취소 상태 흐름을 보존하며 통합한다.
6. 프론트엔드와 백엔드의 관련 테스트 및 빌드를 실행한다.
7. 브라우저에서 375px, 768px, 1280px 화면을 확인하고 결과 문서와 캡처를 기록한다.
8. `docs/database`와 `backend/DATABASE` 변경본 및 전체 `db-schema.md`가 일치하는지 확인한다.

## 완료 기준

- 네 문서 코드에 대해 사용자별 템플릿 CRUD가 동작하고 다른 코드/사용자/tenant의 템플릿은 노출되거나 수정되지 않는다.
- 결재/합의 단계 순서, 참여자 순서와 참조자 순서가 왕복 저장되어 보존된다.
- 불러온 템플릿은 설정 창의 임시 상태만 교체하고 기존 적용/취소 규칙을 따른다.
- 이름/코드/참여자 유효성 실패와 API 실패 시 사용자에게 오류를 표시하고 현재 임시 상태를 보존한다.
- 프론트/백엔드 테스트 및 빌드, 반응형 브라우저 확인, 결과 보고서/스크린샷이 완료된다.
- DB 스크립트, 변경 이력, 롤백, `db-schema.md`가 양쪽 스키마 폴더에 같은 내용으로 반영된다.

## 제외 범위

- 조직 공용 템플릿 및 타 사용자 템플릿 공유
- 기존 문서 저장·상신·결재 API 동작 변경
- 고정 기안자 단계 변경
- 목록에서 템플릿 참여자 구성을 직접 편집하는 기능
