# 공지분류 문서구분 스타일 통일 작업지시서

## 작업 목적

공지사항 피드의 공지분류 칩을 문서작성 화면의 문서구분 칩처럼 선명한 채움형 스타일로 변경한다. 공지분류별 색상 구분은 유지한다.

## 요구사항

1. 공지분류 코드를 기준으로 하는 분류별 색상 구분과 결정적 색상 생성 규칙을 유지한다.
2. 현재 파스텔 배경을 문서구분 칩처럼 선명한 채움색으로 변경하고, 테마에서 배경에 대비되는 글자색을 사용한다.
3. 분류 코드가 없거나 공백인 경우의 기본 파란색도 동일한 채움형 스타일로 표시한다.
4. 분류명, 공지 필터, 중요공지 표시, API/DB 계약은 변경하지 않는다.
5. 후속 승인(2026-10-15): 피드형과 같은 컴포넌트를 쓰는 상세 패널의 분류 칩을 문서구분처럼 높이 28px, 모서리 8px로 맞춘다. `item.state`가 `필독`인 칩은 라이트/다크 모두 흰색 글자를 사용하고, 다른 분류는 기존 대비 글자색을 유지한다.

## 작업 절차

1. 승인 설계, 계획서, 상세 사양서의 구현 범위와 검증 조건을 확인한다.
2. 공지분류 프레젠테이션과 피드 렌더링 테스트를 먼저 보강하고, 구현 전에 관련 검증이 실패하는지 확인한다.
3. 기존 코드 기반 결정적 색상 생성은 유지하면서 공지분류 칩의 배경을 채움형 스타일로 바꾼다.
4. 라이트/다크 테마, 코드 누락 fallback, 레이블 및 중요공지 동작을 확인한다.
5. 관련 Vitest, 프론트엔드 빌드, Problems 검사, `git diff --check`를 실행한다.
6. 가능한 경우 브라우저에서 공지분류 칩을 확인하고 결과 문서에 검증 근거를 기록한다.

## 비범위

- 공지분류 이름·코드, 필터 동작, 공지 데이터/API 및 DB 변경
- 중요공지/상단고정 표시 변경
- 문서구분 칩의 팔레트 또는 문서작성 화면 변경
- 공지 피드의 레이아웃 및 칩 배치 변경 (후속 승인된 칩 크기/모양은 적용)
- 기존 작업공간 변경사항의 되돌리기 또는 정리

## 완료 기준

- 공지분류 칩이 분류별 색상 구분을 유지하면서 문서구분처럼 선명한 채움형으로 표시된다.
- 라이트/다크 테마 및 코드 누락 fallback에서 텍스트 대비가 유지된다.
- 분류 레이블, 필터 및 중요공지 동작이 바뀌지 않는다.
- 관련 테스트, 빌드, 정적 진단과 diff 검증 결과가 결과 문서에 기록된다.
