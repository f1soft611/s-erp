# 20261015_005 커뮤니티 자료실 페이지 작업지시서

## 1. 목적

`/groupware/community/archive` 경로에 그룹웨어 커뮤니티 자료실을 제공한다. 사용자는 자료 게시글과 첨부파일을 조회·검색·다운로드하고, 관리자는 게시글과 첨부파일을 등록·수정·삭제할 수 있어야 한다.

## 2. 사용자 승인 사항

- 화면은 파일 정보 비교와 검색에 유리한 목록형으로 구성한다.
- 자료는 제목과 여러 줄 일반 텍스트 설명을 가진 게시글이며, 한 게시글에 여러 첨부파일을 연결한다.
- 공통코드 그룹 `WF_ARCHIVE_CATEGORY`의 활성 항목을 자료 분류로 사용한다.
- 공지 분류와 자료실 분류는 `tb_board_post`의 공통 `category_code` 컬럼에 저장한다. 기존 공지 API의 `noticeGubunCode` 계약은 유지하고 내부 저장 매핑을 변경한다.
- 자료실 분류와 공지 분류는 각각 해당 유형에 지정된 공통코드 그룹의 활성 항목인지 검증한다.
- 자료 등록·수정·삭제와 파일 업로드는 자료실 유형의 관리자 작성 정책을 따른다.

## 3. 확인된 현재 구조

- 실제 테이블명은 `tb_board_type`이다. 읽기 전용 DB MCP 조회에서 활성 `ARCHIVE` 유형 및 `/groupware/community/archive` 메뉴가 이미 확인되었다. 현재 유형은 읽기 `ALL`, 쓰기 `ADMIN`, 파일 업로드 `Y`로 구성되어 있으므로 중복 시드 생성을 피한다.
- `NOTICE_GUBUN`에는 활성 분류가 있으며, `WF_ARCHIVE_CATEGORY`에는 업무양식·메뉴얼·교육자료 활성 항목이 있다. 화면 표시는 공통코드 조회 결과를 사용한다.
- 현재 게시글 분류 컬럼명은 공지 전용 `notice_gubun_code`이므로 승인된 공통화 설계에 따라 `category_code`로 변경하는 DB 이력이 필요하다.

## 4. 작업 범위

### 포함

1. 대시보드 메뉴 키 `archive`에 전용 자료실 페이지 연결
2. 목록, 검색, 분류 필터, 상세 패널, 첨부파일별 다운로드
3. 관리자용 게시글 작성·수정·삭제 및 복수 파일 첨부 관리
4. 자료실 전용 API와 서비스에서 테넌트·게시판 유형·권한·분류·첨부 소유권 검증
5. 게시글 분류 컬럼 공통화 및 날짜별 SQL/변경 이력/롤백과 누적 스키마 문서 갱신
6. 프론트엔드/백엔드 회귀 테스트, 반응형 브라우저 검증, 결과 문서와 스크린샷

### 제외

- 자료 분류 코드 관리 화면 및 새 분류 코드 추가
- 공지사항 라우트 또는 기존 공지 JSON 필드명 변경
- 댓글, 좋아요, 북마크, 파일 미리보기, 일괄 다운로드
- 자료실 외 게시판의 기능 추가 및 범용 게시판 엔진 리팩터링

## 5. 완료 기준

- 지정 경로에서 목록 및 상세가 정상 동작하고 제목·작성자·본문 검색과 공통코드 분류 필터가 동작한다.
- 항목 상세에서 여러 첨부파일을 개별 다운로드할 수 있다.
- 관리자만 자료를 등록·수정·삭제·업로드할 수 있고, 서버가 요청마다 권한을 검증한다.
- 공지 분류 데이터는 보존되고 기존 공지 API 계약은 유지되며 공지/자료실이 동일한 `category_code` 컬럼을 사용한다.
- 분류 검증은 현재 테넌트의 해당 공통코드 그룹에 속한 활성 항목만 허용한다.
- 프론트엔드 테스트/build, 관련 백엔드 테스트가 통과하고 375px·768px·1280px 브라우저에서 확인한다.
- 결과 문서와 영문 소문자·숫자·하이픈 경로의 스크린샷을 `docs/result/20261015/community-archive/`에 남긴다.

## 6. 진행 순서 및 안전 중단점

1. 이 작업지시서를 기준으로 구현 계획서를 작성한다.
2. 계획서를 기준으로 상세 사양서를 작성한다.
3. 문서 단계 완료 후 사용자에게 확인하고, 공유 워크트리의 DB 문서/마이그레이션 변경이 정리되었는지 재확인한다.
4. DB 관련 기존 변경과 충돌이 없음을 확인한 다음에만 category 컬럼 migration, 백엔드, 프론트엔드 구현을 시작한다.
5. 구현 및 검증 후 결과 문서와 스크린샷을 남긴다.

현재 공유 워크트리에서 `docs/database/db-schema.md`, `docs/database/20261015/`, `backend/DATABASE/20261015/`의 다른 변경이 관찰되었다. 따라서 이 작업지시서·계획서·상세사양서 작성까지만 진행하며 해당 DB 파일이나 코드에는 아직 손대지 않는다.
