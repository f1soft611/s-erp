# 20261015_016 목록 조회 배치 처리 작업지시서

## 작업 분류

- 대상: 백엔드 공지사항 목록 및 전자결재 피드 목록
- 승인 설계: [목록 조회 배치 처리 설계](../../superpowers/specs/2026-10-15-list-query-batching-design.md)
- DB 스키마 변경: 없음
- 결과 문서: [목록 조회 배치 처리 결과](../../result/20261015/list-query-batching/)

## 작업 목적

목록 조회 결과를 각 항목별로 다시 조회하는 N+1 패턴을 제거하고, 댓글 수 및 댓글 페이지 메타데이터가 기존 API 계약과 일치하도록 한다. 기존 브라우저 요청 경로와 응답 필드는 유지한다.

## 요구사항

1. 공지 목록 페이지의 첨부파일, 댓글 트리, 최상위 댓글 수 및 댓글 첨부파일을 목록 전체 기준으로 배치 조회한다.
2. 공지 댓글 수는 현재 단건 조회 계약과 동일하게 삭제되지 않은 최상위 댓글만 계산한다.
3. 공지 댓글은 최신 최상위 3개와 답글을 반환하고, 추가 최상위 댓글 존재 여부 및 이전 조회 cursor를 정확히 설정한다.
4. 전자결재 피드에서 상세 본문, 결재선, 문서 첨부, 시스템 이벤트, 사용자 댓글 트리/수, 댓글 첨부를 문서 ID 전체 기준으로 배치 조회한다.
5. 피드 처리 중 문서별 단건 상세/권한/결재선/댓글 조회가 반복되지 않게 한다. 상세 본문 배치 조회는 tenant 및 기안자/참여자 권한 조건을 유지한다.
6. API 경로/응답 shape, 문서/공지 정렬, 삭제된 댓글 표현, 상세 패널의 별도 요청 동작은 변경하지 않는다.
7. React StrictMode 개발 모드 재실행, 고정 공지 별도 API, 전자결재 요약 API는 이 작업 범위에서 변경하지 않는다.

## 작업 절차

1. [승인 설계](../../superpowers/specs/2026-10-15-list-query-batching-design.md)를 기준으로 [계획서](../../plan/20261015/20261015_016_목록_조회_배치처리_계획서.md)와 [상세사양서](../../spec/20261015/20261015_016_목록_조회_배치처리_상세사양서.md)를 확인한다.
2. 공지 서비스 테스트를 먼저 갱신해 다중 게시글에서 bulk 호출 횟수, 최상위 댓글 수, 최신 3개 루트/답글, `hasPreviousComments`, cursor, 페이지 전체 댓글 첨부파일 매핑을 검증한다.
3. 공통 댓글 배치 페이지 서비스가 페이지 결과와 단건 조회와 같은 루트 카운트를 만들도록 구현한다.
4. 공지 목록 hydrate 전에 페이지 댓글 ID를 모아 댓글 첨부파일을 한 번에 조회하도록 변경한다.
5. 전자결재 피드 서비스 테스트를 먼저 갱신해 여러 문서의 관계 데이터가 일괄 조회되고 단건 조회는 호출되지 않는지 검증한다.
6. 전자결재 상세/결재선/사용자 댓글 페이지 및 카운트 배치 DAO/SQL과 응답 조립을 구현한다. 문서 목록 조회 권한 조건을 유지한다.
7. 집중 테스트, 전체 백엔드 테스트, `git diff --check`를 실행한다.
8. [결과 폴더](../../result/20261015/list-query-batching/)에 변경 및 검증 결과를 기록한다. 화면 변경이 없으므로 스크린샷 비대상임을 명시한다.

## DB MCP 확인

읽기 전용 MCP에서 `list_tables`를 실행하고 `tb_common_comment`, `tb_common_file`, `tb_board_post`, `tb_electronic_approval_main`, `tb_electronic_approval_line_info`의 컬럼 계약을 확인했다. 댓글 유형/삭제/부모 댓글, 파일 owner type/owner ID/삭제, 게시물 ID/tenant, 전자결재 문서 ID/tenant/본문, 결재선 문서 ID/tenant 컬럼을 근거로 사용한다. 조회 데이터 행은 사용하지 않았다.

## 비범위

- API endpoint/응답 DTO 계약, 페이지네이션 및 정렬 변경
- DB DDL, 스키마 이력 및 데이터 변경
- 공지 고정 목록/요약 요청을 합치는 프론트 변경
- 상세 패널 개별 요청과 댓글 이전 페이지 요청 최적화
- 기존 미커밋 또는 staged 변경의 정리/수정

## 완료 기준

- 페이지/문서 수가 둘 이상이어도 관계별 bulk DB 호출이 결과 항목마다 증가하지 않는다.
- 댓글 수, 표시 트리, 이전 페이지 여부 및 cursor가 기존 단건 기준과 일치한다.
- tenant 및 전자결재 접근 권한 조건과 API 응답 shape가 유지된다.
- 집중 테스트, `mvn test`, `git diff --check` 결과가 결과 문서에 기록된다.
- 다른 미커밋 변경을 덮어쓰거나 포함하지 않는다.
