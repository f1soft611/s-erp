# 20261015_009 전자결재 합의·참조 참여자 카드 크기 통일 작업지시서

## 작업 분류

- 대상: 프론트엔드 전자결재 상세 결재선
- 화면: 문서 상세의 합의·참조 참여자 카드
- 기준 설계: [합의·참조 참여자 카드 크기 통일 설계](../../superpowers/specs/2026-10-15-document-approval-participant-card-size-design.md)
- DB/API 변경: 없음

## 작업 목적

합의 사용자 카드와 참조 사용자 카드의 크기 및 프로필 이미지 크기를 참조 카드 기준으로 통일한다. 이름과 부서는 두 줄로 표시하고 부서 값이 없거나 공백이면 `부서없음`으로 표시한다.

## 요구사항

1. 합의 및 참조 사용자 카드에 같은 폭 규칙을 적용한다: `flex: 0 1 240px`, 최소 폭 `min(100%, 190px)`, 최대 폭 100%.
2. 두 카드의 바깥 높이를 `66px`로 고정하고 내부 여백을 동일하게 유지한다.
3. 두 카드의 프로필 이미지는 `36 × 36px`로 표시한다.
4. 사용자 이름을 첫 줄에, 부서를 둘째 줄에 표시한다. 부서 정보가 없거나 공백뿐이면 `부서없음`으로 표시한다.
5. 합의 상태, 단계 번호, 참여자 순서, 참조 순서 및 프로필 이미지 대체 표시 동작을 유지한다.
6. 좁은 화면에서 참여자 카드 목록 안에서 줄바꿈하고 페이지 전체 가로 넘침을 새로 만들지 않는다.

## 작업 절차

1. [구현 계획서](../../plan/20261015/20261015_009_전자결재_합의_참조_참여자_카드크기_통일_계획서.md)와 [상세사양서](../../spec/20261015/20261015_009_전자결재_합의_참조_참여자_카드크기_통일_상세사양서.md)에 파일 범위, 표시 규칙, 검증 기준을 유지한다.
2. 상세 결재선 회귀 테스트에서 합의·참조 카드 치수와 부서 fallback 검증을 먼저 작성하고, 기존 코드를 기준으로 신규 assertion이 실패하는지 확인한다.
3. [DocumentApprovalDetailFeed.tsx](../../../frontend/src/pages/groupware/documents/write/components/DocumentApprovalDetailFeed.tsx)의 상세 합의·참조 카드 표시만 수정한다.
4. 관련 상세 결재선 테스트, 프론트엔드 빌드 및 diff 검사를 실행한다.
5. 브라우저에서 375px, 768px, 1280px 폭을 확인하고 개인정보가 노출되지 않는 캡처를 결과 폴더에 보관한다. 인증 화면 접근이 불가능하거나 비식별 캡처가 불가능하면 수행하지 않은 사실을 기록한다.
6. [결과 폴더](../../result/20261015/document-approval-participant-card-sizing/)에 변경 및 검증 결과를 작성한다.

## 비범위

- 결재 상태 및 처리 로직, 승인 카드, 결재 단계/순서 동작 변경
- 문서작성 편집 결재선 변경
- API, 백엔드, 데이터베이스 변경
- 관련 없는 작업공간 변경 정리 또는 되돌리기

## 완료 기준

- 합의와 참조 카드가 공통 폭 규칙, `66px` 높이 및 `36 × 36px` 프로필 이미지를 사용한다.
- 부서 정보가 없거나 공백인 합의·참조 카드에 `부서없음`이 표시된다.
- 기존 합의 상태, 참여자 순서 및 프로필 이미지 대체 표시가 유지된다.
- 집중 테스트와 빌드가 성공하고 실제 브라우저 검증 결과 또는 검증 차단 사유가 결과 문서에 기록된다.
- 결과 문서와 가능한 경우 비식별 스크린샷이 보관된다.
