# 20261123_002 단가등록 개편(좌우 그리드·공통단가 폐지·계정분류 조회) 작업지시서

## 작업 목적

[20261123_001](20261123_001_item-price-trade-split_작업지시서.md)에서 매입단가등록/매출단가등록으로 나눈 뒤에도 품목 기준 탭이 트리(품목 행 + 특별단가 자식 행)라서 품목코드·품목이 한 열에 합쳐지고, 공통단가·기본 거래처 처리가 복잡하다. 단가는 항상 거래처에 붙는 구조로 단순화하고, 품목 기준 탭을 거래처 기준 탭처럼 좌우 그리드로 바꾼다. 조회조건에 품목 계정분류(멀티선택)를 추가한다.

## 사용자 결정 (2026-11-23)

- **공통단가(거래처 없는 단가)를 폐지한다.** 기존 공통단가 행은 삭제해도 된다.
- **매출에는 기본 판매처 개념이 없다.** 수주는 수주처를 먼저 정하고 품목을 고르므로 "수주처 + 품목"으로 단가를 찾는다.
- **매입 기본 거래처는 유지한다.** 한 품목의 단가 거래처가 2곳 이상이면 기본 거래처가 반드시 1개 있어야 하므로 기본값 관리가 필요하다. 거래처가 1곳이면 기본 지정은 선택이다.
- **구매요청확정 단가 채우기**: 요청 품목을 불러올 때 품목의 매입 단가 거래처를 찾는다.
  1. 거래처가 1곳이면 그 거래처와 기준일 유효 단가를 채운다.
  2. 거래처가 2곳 이상이면 기본 거래처와 그 거래처의 기준일 유효 단가를 채운다. 기본 거래처에 기준일 유효 단가가 없으면 단가는 비운다(기본 체크 여부와 상관없음).
  3. 거래처가 없으면 구매처·단가를 비운다.
- **수주 단가 채우기**: 수주처 + 품목이 일치하는 매출 단가(기준일 유효, 사용 중)를 채우고 없으면 비운다. 통화는 화면 값으로 고르지 않고 **단가 행의 통화를 그대로 적용**한다(수주 화면에는 통화가 없다. 단가와 함께 통화 정보를 돌려준다).
- 단가 행의 **부가세구분·부가세포함**도 단가·통화와 함께 구매요청확정(과 수주용 조회 결과)에 채운다.
- 기존 등록 데이터는 테스트 데이터다. 새 규칙에 맞게 기본 거래처를 지정한다(스크립트).
- `customer_id`는 NOT NULL로 바꾼다.
- 조회조건에 **품목 계정분류**(멀티선택)를 추가한다. 코드: `PRODUCT` 제품, `SEMI` 반제품, `GOODS` 상품, `RAW` 원재료, `SUB` 부재료, `SUPPLY` 소모품. 기본값은 매입 `RAW,SUB,SUPPLY`, 매출 `PRODUCT,SEMI,GOODS`. 멀티선택은 `PageSearchArea`의 기존 select 필드에 `multiple` 옵션을 추가해 구현하고, F1Grid 쪽은 바꾸지 않는다.
- 그리드 컬럼 순서: 품목코드·품목·규격·단위를 특별한 경우가 아니면 나란히 둔다.
- 품목 기준 탭은 거래처 기준 탭처럼 **좌우 그리드**(왼쪽 품목, 오른쪽 선택 품목의 거래처별 단가)로 바꾼다.

## 확정 범위

### 데이터베이스
- 매입 공통단가 행(조회 시점 8행, 매출 0행)을 백업 후 삭제한다. 백업·롤백(복원)·변경 이력 문서를 함께 만든다. SQL은 사용자가 직접 실행한다.
- `tb_item_partner_price.customer_id`를 NOT NULL로 바꾼다. 거래처 2곳 이상인데 기본 거래처가 없는 기존 품목은 기본 거래처를 지정한다.

### 백엔드
- 단가 조회 공통 서비스(`ItemPriceLookupService`): 공통단가 대체 제거, 위 구매요청확정·수주 규칙으로 정리(수주용 "거래처+품목+기준일" 조회는 통화 포함).
- 단가 등록·엑셀: 거래처 없는 단가 저장 금지. 매입은 거래처 2곳 이상 품목의 기본 거래처 필수 검증.
- 품목 기준·거래처 기준·목록 조회에 품목 계정분류 필터(`itemTypes`) 추가, 공통단가 관련 필터·집계 제거.

### 프론트엔드
- 품목 기준 탭을 좌우 그리드로 교체(트리·공통단가·특별단가 개념 제거), 매입 기본 거래처 관리 UI.
- 세 탭 컬럼 순서 정리, 조회조건에 계정분류 멀티선택, 공통단가 관련 필터·엑셀 안내 제거.
- `PageSearchArea` select 필드 `multiple` 옵션(공통 컴포넌트, 김차장 확인 필요).

## 범위 밖
- 영업 모듈(수주 등) 소스 수정: 영업 담당자 개발 중. 연동 안내문을 결과 문서에 적는다.
- 매출 기본 판매처, F1Grid 멀티선택 변경.

## 완료 조건
- 구매요청확정이 위 규칙대로 거래처·단가를 채우고, 수주용 조회 서비스가 수주처+품목으로 단가·통화를 돌려준다.
- 품목 기준 탭 좌우 그리드, 계정분류 멀티선택 기본값, 컬럼 순서가 매입/매출 화면에서 동작한다.
- 관련 백엔드·프론트 테스트, JDK 8 컴파일, 빌드, 375/768/1280px 브라우저 확인, DB 스크립트, 결과 문서(커밋 제안 포함).
