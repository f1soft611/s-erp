# 20260827*003*테마*화면크기*설정*기능*작업지시서

## 1. 작업 개요

현재 대시보드 상단 헤더에는 "테마"와 "화면크기" 드롭다운 UI가 노출되어 있으나(첨부 캡처 참조), 실제 테마 전환(밝은/다크) 및 화면 크기 조정 기능은 동작하지 않는 상태다.

본 작업은 두 드롭다운을 실제 기능으로 연결하여, 사용자가 화면에서 직접 테마와 화면 크기를 조정할 수 있도록 구현하는 것을 목표로 한다.

핵심 의도는 다음과 같다.

- 첨부 캡처의 "테마" 드롭다운(밝은 테마 / 다크 테마)을 실제 테마 전환 기능으로 구현한다.
- 첨부 캡처의 "화면크기" 드롭다운(작게 / 보통 / 조금 크게 / 크게 / 가장 크게 / 초기화)을 실제 화면 배율 조정 기능으로 구현한다.
- 기존 헤더 UI의 형태와 옵션 구성을 그대로 유지하면서 기능만 연결한다.

---

## 2. 작업 목적

- 사용자가 선호하는 테마(밝은/다크)를 선택하고 화면 전반에 즉시 반영되도록 한다.
- 사용자가 텍스트/화면 크기를 단계별로 조정할 수 있도록 하여 접근성을 개선한다.
- 선택한 테마와 화면 크기 설정이 새로고침/재방문 후에도 유지되도록 한다.

---

## 3. 현재 문제점

1. 헤더의 "테마" 드롭다운이 밝은 테마/다크 테마 항목을 보여주지만 선택해도 실제 테마가 바뀌지 않는다.
2. 헤더의 "화면크기" 드롭다운이 5단계(작게~가장 크게) 및 초기화 옵션을 보여주지만 선택해도 실제 화면 배율이 바뀌지 않는다.
3. 현재 `frontend/src/theme/theme.ts`는 단일 고정 테마만 정의되어 있어 다크 모드 팔레트가 없다.
4. 선택 상태를 저장하는 저장소(스토어/로컬스토리지)가 없어 새로고침 시 설정이 초기화된다.

---

## 4. 요구사항

### 4.1 테마 설정

- "테마" 드롭다운에서 "밝은 테마" 또는 "다크 테마"를 선택하면 즉시 화면 전체(배경, 텍스트, 컴포넌트 색상)에 반영되어야 한다.
- 현재 선택된 테마는 드롭다운에서 강조 표시되어야 한다(첨부 캡처의 "밝은 테마" 강조 표시 참고).
- 선택한 테마 값은 저장되어, 새로고침 또는 재로그인 후에도 동일하게 유지되어야 한다.
- 다크 테마는 기존 밝은 테마의 레이아웃/컴포넌트 구조를 유지하되 색상 팔레트만 다크 모드 기준으로 전환한다.

### 4.2 화면 크기 조정

- "화면크기" 드롭다운에서 작게 / 보통 / 조금 크게 / 크게 / 가장 크게 중 하나를 선택하면 화면의 글자 크기(및 이에 비례하는 레이아웃 요소)가 단계적으로 조정되어야 한다.
- "보통"을 기본값으로 하며, 현재 선택된 단계는 드롭다운에서 강조 표시되어야 한다(첨부 캡처의 "보통" 강조 표시 참고).
- "초기화" 선택 시 화면 크기를 기본값("보통")으로 되돌린다.
- 선택한 화면 크기 값은 저장되어, 새로고침 또는 재로그인 후에도 동일하게 유지되어야 한다.

### 4.3 공통 요구사항

- 기존 드롭다운의 위치, 아이콘, 옵션 문구, 레이아웃은 변경하지 않고 기존 UI 그대로 유지한다.
- 테마와 화면 크기 설정은 서로 독립적으로 동작해야 한다(하나를 변경해도 다른 하나에 영향을 주지 않음).
- 설정 변경 시 전체 페이지가 깜빡이거나 새로고침되지 않고 즉시 반영되어야 한다.

---

## 5. 구현 방향

### 5.1 테마 전환

- MUI `ThemeProvider`에 밝은/다크 두 개의 테마 객체를 구성하고, 선택 상태에 따라 전환한다.
- 테마 선택 상태는 전역 상태(Context 또는 기존 상태관리 패턴)로 관리하고, `localStorage` 등에 저장하여 재방문 시 복원한다.
- `frontend/src/theme/theme.ts`를 기준으로 다크 테마 팔레트를 추가 정의한다.

### 5.2 화면 크기 조정

- 화면 크기 단계는 배율(%) 또는 `rem` 기준 스케일 값으로 매핑하여 관리한다(예: 작게 90%, 보통 100%, 조금 크게 110%, 크게 120%, 가장 크게 130%).
- 선택된 배율은 전역 상태로 관리하고 `localStorage`에 저장한다.
- 배율 적용은 루트 요소의 `font-size` 조정 등 기존 레이아웃 구조에 최소 영향을 주는 방식으로 처리한다.

### 5.3 상태 관리 위치

- 헤더의 테마/화면크기 드롭다운 컴포넌트와 상태 관리 로직을 분리하여, UI 컴포넌트는 상태를 표시/변경 요청만 하고 실제 저장/적용 로직은 별도 훅 또는 컨텍스트에서 처리한다.
- 기존 프로젝트의 상태관리 패턴(Context, store 등)을 우선 확인하고 동일한 패턴을 따른다.

### 6.1 Frontend 범위

- 헤더의 "테마" 드롭다운 기능 연결(밝은/다크 전환)

- 다크 테마 팔레트 정의
- 화면 배율 조정 로직 구현
- 선택 상태 저장 및 복원(localStorage 등)

### 6.2 비범위

- DB 스키마 변경
- 헤더 레이아웃/디자인 자체의 변경(기존 UI 유지)
- 테마/화면크기 이외의 다른 설정 항목 추가
- 무관한 페이지의 리팩터링

- "테마" 드롭다운에서 밝은/다크 선택 시 전체 화면에 실제로 반영되는지
- 현재 선택된 테마가 드롭다운에서 강조 표시되는지
- "화면크기" 드롭다운에서 각 단계 선택 시 화면 크기가 실제로 변경되는지
- "초기화" 선택 시 화면 크기가 기본값으로 복원되는지
- 새로고침 후에도 선택한 테마/화면크기가 유지되는지
- 테마 변경과 화면크기 변경이 서로 간섭하지 않는지

## 8. 완료 기준

- 테마 드롭다운 선택에 따라 밝은/다크 테마가 실제로 전환된다.

- 두 설정 모두 새로고침 후에도 유지된다.
- 기존 헤더 UI 형태는 변경 없이 그대로 유지된다.
- 결과물과 스크린샷을 `docs/result`에 정리했다.
