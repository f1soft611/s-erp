# 문서 고정 확인창 및 액션 위치 개선 작업지시서

## 사용자 요구 및 승인

- 고정/해제는 공지사항과 같은 확인창에서 확인한 후에만 처리한다.
- 리스트형 고정 액션은 문서 업무구분 Chip 옆에 둔다.
- 리스트 행 클릭 버튼과 헤더/metadata 액션을 형제 요소로 분리해 중첩 버튼을 만들지 않는다.
- 피드형과 문서 상세 오버레이에서 고정 액션은 더보기 옆에 둔다.
- 고정 패널의 해제 동작에도 동일한 확인 절차를 적용한다.
- 파일형에서 연 상세 오버레이도 현재 필터 범위의 고정 상태를 전달해, 고정 문서이면 해제 확인을 표시한다.
- 확인창 문구는 고정 시 `이 문서를 상단에 고정하시겠습니까?`, 해제 시 `이 문서의 상단 고정을 해제하시겠습니까?`; 버튼은 `취소`와 `확인`으로 한다.
- 확인 취소는 API를 호출하지 않고, 확인은 기존 pin/unpin API를 호출한다. 성공 시 목록을 조용히 새로고침하고 실패 시 기존 알림을 사용한다.
- 승인된 설계: [문서 고정 확인 및 액션 위치 설계](../../superpowers/specs/2026-10-21-document-pin-confirmation-actions-design.md)

## 작업 순서

1. 이 작업지시서에 따라 날짜별 계획서와 상세 사양서를 작성한다.
2. 확인 취소/확인과 각 위치를 검증하는 실패 테스트를 먼저 작성한다.
3. 문서작성 화면에 공통 확인 흐름을 연결하고 리스트/피드/상세의 액션 위치를 변경한다.
4. 대상 Vitest와 프론트엔드 빌드를 실행한다.
5. 기존 S-ERP 개발 서버를 확인 후 재사용해 375px, 768px, 1280px에서 화면을 검증한다.
6. `docs/result/20261021/document-pin-confirmation-actions`에 결과 문서와 스크린샷을 기록한다.
7. 파일형에서 고정된 문서의 첨부파일을 열어 해제 상태 및 확인 동작을 회귀 검증한다.

## 영향 범위

- 프론트엔드 문서작성 화면, 공통 ListView 선택형 액션 슬롯, 문서 승인 툴바 및 상세 컴포넌트
- 관련 프론트엔드 테스트 및 날짜별 결과 문서
- 백엔드 API, DB 스키마 및 비문서 화면은 변경하지 않는다.
