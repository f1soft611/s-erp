# 20261021_011 문서현황 전체 조회 및 그리드 정렬·필터 작업지시서

## 목적

문서현황은 검색조건과 결재신청 기간에 일치하는 전체 문서를 한 번에 조회한 결과처럼 표시한다. 조회 완료 후 그리드 정렬과 필터는 로컬 데이터로 처리해 조작할 때 목록 API를 재호출하지 않는다.

## 사용자 승인 요구사항

- 문서현황 화면은 현재 검색조건을 API에 전달하고 조건에 맞는 전체 결과를 조회한다.
- 화면은 페이지 이동이나 다음 페이지 로딩 없이 조회한 전체 결과를 그리드에 표시한다.
- 헤더 정렬 및 필터는 전체 조회 행에 로컬 적용하며, 조작으로 목록 API를 다시 호출하지 않는다.
- 헤더 필터 메뉴를 표시하고 실제 필터 동작을 제공한다.
- 기존 페이지 조회 API 경로는 보존한다. offset/limit이 제공된 기존 호출은 현재 200건 제한 및 페이지 응답 동작을 유지한다.
- 기존 날짜 기본값, 상세검색, 세션 복원, 검색 초기화, 선택 행/상세 패널, 오류 표시, 엑셀 내보내기를 유지한다.
- DB 스키마는 변경하지 않는다.

## 범위

- 문서현황 검색 API의 전체조회 모드와 기존 페이징 모드 병행
- 프런트엔드 문서현황 전체 결과 로딩 및 로컬 그리드 연결
- 검색·정렬·필터·기존 페이지 조회 회귀 테스트
- F1-Grid 사용자 문서와 날짜별 결과 문서 갱신

## 구현 절차

1. PostgreSQL 읽기 전용 MCP로 현재 관련 테이블 메타데이터를 확인한다. 행 데이터는 조회하지 않는다.
2. 백엔드 서비스 및 Mapper 테스트에 전체조회와 기존 페이징 두 경로의 실패 사례를 추가한다.
3. 검색조건/권한/정렬 처리는 공유하고, offset/limit이 없는 요청에서만 SQL의 `LIMIT/OFFSET`을 생략한다. 페이징 요청의 기존 최대 200 제한을 유지한다.
4. 프런트엔드 검색 서비스에 offset/limit 없는 응답 처리를 추가하고 기존 `F1GridDataSource` 경로는 보존한다.
5. 문서현황 페이지는 검색 실행 후 전체 응답 행을 로컬 rows로 전달하고, 검색조건 변경/재시도/상세 작업 완료 시 목록을 다시 조회한다.
6. 필터 메뉴를 활성화하고 정렬·필터 변경에서 API 요청이 발생하지 않는지 테스트한다.
7. F1-GRID 문서와 날짜별 결과 문서를 갱신하고 백엔드/프런트엔드 검증을 실행한다.

## 완료 기준

- 날짜 및 상세검색 조건을 보낸 문서현황 전체조회 요청이 모든 일치 행을 반환한다.
- 페이징 파라미터를 보낸 기존 요청은 기존의 200건 제한과 offset 동작을 유지한다.
- 화면에는 전체 결과가 처음부터 로드되고, 정렬·필터 조작은 서버 재조회 없이 동작한다.
- 상세검색, 검색 세션, 날짜 초기값, 선택/상세 패널, API 오류/재시도 및 엑셀 동작에 회귀가 없다.
- 관련 테스트, 빌드, 문서 및 결과 기록이 완료된다.
