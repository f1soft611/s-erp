# 20261021_001 커뮤니티 자료실 업로드 및 F1Tree 개선 작업지시서

## 1. 목적

커뮤니티 자료실의 즉시 파일 업로드가 DB 오류로 실패하는 문제를 수정하고, 파일/분류 목록의 표현을 기존 F1-Grid에서 F1Tree로 변경한다. 검색, 폴더 위치 필터, 권한, 아이콘, 파일 작업은 유지한다.

## 2. 확인된 원인

- 사용자 화면에는 `데이터 처리 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.`가 표시된다. 이는 알 수 없는 `DataAccessException`에 대한 공통 메시지다.
- `ArchiveBoardServiceImpl.uploadFile`은 게시글 insert 파라미터에 `lastModifiedBy`/`lastModifiedByName`만 설정하고 작성자 `writerId`/`writerName`은 설정하지 않는다.
- `insertArchivePost`는 `writer_id`/`writer_name`에 이 파라미터를 바인딩한다. 읽기 전용 DB 메타데이터에서 `tb_board_post.writer_id`는 NOT NULL로 확인했다.
- 따라서 누락된 작성자 ID가 자료실 게시글 insert에서 DB 오류를 유발한다. 실제 DB 행은 조회하지 않았다.

## 3. 범위 및 요구사항

1. 파일 업로드에서 인증 사용자 ID와 이름을 게시글 작성자 및 최종 수정자로 기록한다. 다른 게시글 작성 흐름은 변경하지 않는다.
2. F1Tree의 최상위 행은 `폴더`, `파일` 두 개로 구성하고, 분류와 파일은 각 섹션의 자식 행으로 표시한다.
3. 폴더/파일 아이콘, 파일 메타데이터 컬럼, 다운로드·수정·삭제 작업, 검색 및 권한 동작을 유지한다.
4. 분류 선택은 기존처럼 현재 폴더 필터를 바꾸고 해당 분류의 파일을 조회한다. 중첩 폴더나 분류 아래 파일을 직접 계층화하는 동작은 추가하지 않는다.
5. 두 섹션은 기본 펼침 상태로 표시하고, 현재 폴더 위치에서는 기존과 같이 파일 섹션만 표시한다.
6. DB 스키마, API 경로/필드, 파일 저장 동작은 변경하지 않는다.

## 4. 작업 절차

1. 승인 설계와 날짜별 계획/상세사양서를 확인한다.
2. 서비스 테스트에 업로드 작성자 ID/명 바인딩 회귀 검증을 추가하고 실패를 확인한다.
3. 업로드 전용 게시글 insert 파라미터에 인증 사용자 ID/명을 설정하고 서비스 테스트를 통과시킨다.
4. 프론트엔드 테스트에서 F1Tree 섹션 계층, 분류 필터링, 업로드 동작을 확인한 뒤 자료실 목록을 F1Tree로 변경한다.
5. 대상 백엔드 테스트, 프론트 테스트, 프론트 빌드를 실행한다.
6. 브라우저에서 업로드 요청 흐름과 루트/폴더 트리를 확인하고 결과 문서 및 F1-Grid 문서를 갱신한다.

## 5. 완료 조건

- 업로드 insert map에 `writerId`, `writerName`, `lastModifiedBy`, `lastModifiedByName`이 인증 사용자에서 채워진다.
- 기존 직접 업로드 API가 파일 저장 서비스까지 진행하고 결과 파일을 반환하는 서비스 테스트가 통과한다.
- 자료실 화면에 `폴더`/`파일` 두 트리 루트와 각 자식 행이 표시되고, 분류 선택 시 기존 폴더 필터 요청을 수행한다.
- 검색, 날짜/유형 상세검색, 비활성 폴더 읽기 전용 동작, 권한별 파일 작업과 즉시 업로드 흐름이 유지된다.
- 대상 테스트와 빌드가 통과하고, 375px/768px/1280px 브라우저 확인 및 결과 문서 기록이 완료된다.
- DB 변경이 없으며, DB MCP 확인은 테이블 메타데이터만 사용하고 행 조회는 하지 않는다.
