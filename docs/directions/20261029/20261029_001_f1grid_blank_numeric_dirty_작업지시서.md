# 20261029_001 F1-Grid 빈 숫자 편집 dirty 오표시 수정 작업지시서

## 사용자 요청

- 품목관리의 소비기한 숫자 컬럼에서 값을 바꾸지 않고 에디터 편집을 마쳐도 dirty 표시가 남는 현상을 수정한다.

## 조사 근거

- 품목관리의 미관리(`NONE`) 소비기한 숫자 저장값은 `null`이다.
- 품목 행 조회 정규화는 nullable 숫자를 `number | null`로 유지한다.
- F1-Grid 숫자 에디터의 commit은 빈 draft를 `Number('')`로 변환해 `0`으로 만든다.
- 따라서 원본 `null`인 빈 숫자 셀을 변경 없이 확정하면 `0`이 저장되어 dirty로 오판된다.
- [F1-Grid 안내](../../../frontend/src/pages/f1-grid-docs/F1-GRID.md)는 빈 숫자는 `null`, 숫자 0은 0으로 유지하는 계약을 명시한다.

## 작업 범위

- 숫자/소수/통화 에디터에서 빈 입력 확정 시 `null`을 유지한다.
- `null` 원본의 빈 숫자 셀을 수정 없이 확정해도 dirty 변경을 만들지 않는다.
- 명시적으로 입력한 `0` 및 유효한 숫자의 변경·원복 동작은 유지한다.
- F1-Grid 회귀 테스트, 안내 문서, 결과 문서를 갱신한다.

## 작업 절차 및 검증

1. 이 작업지시서를 바탕으로 [계획서](../../plan/20261029/20261029_001_f1grid_blank_numeric_dirty_계획서.md)를 작성한다.
2. 계획서를 바탕으로 [상세 사양서](../../spec/20261029/20261029_001_f1grid_blank_numeric_dirty_상세사양서.md)를 작성한 뒤 구현한다.
3. nullable 숫자 셀의 빈 값 commit 회귀 테스트를 먼저 추가하고 실패를 확인한다.
4. 관련 Vitest, 프론트엔드 빌드 및 F1-Grid 실제 브라우저 동작을 확인한다.
5. [F1-Grid 안내](../../../frontend/src/pages/f1-grid-docs/F1-GRID.md)와 결과 문서를 최신화하고 결과 경로에 스크린샷을 보관한다.

## 완료 조건

- 빈 숫자 입력은 원본이 `null`이면 `null`로 유지되고 dirty/updated row를 만들지 않는다.
- 명시적 `0` 입력은 0으로 유지되며, 값 변경 후 원복할 때 dirty가 해제된다.
- 관련 회귀 테스트와 빌드가 통과하고 문서·결과·스크린샷이 포함된다.

## 제외 사항

- 품목관리 소비기한 유효성 및 저장 계약 변경
- 다른 컬럼이나 품목 화면 UI 변경
- API, 백엔드 또는 DB 스키마 변경
