# 문서·공지 공유 링크 및 공통 미리보기 작업지시서

## 사용자 요구

- 문서 외부 링크 OG 기능과 공지사항도 같은 공통 미리보기 구조를 사용한다.
- 공지사항에 `공지 공유하기`를 추가하고, 기존 문서 공유하기와 동일하게 로그인된 사용자가 공유 링크를 복사할 수 있어야 한다.
- 문서 공유 링크, 공지 공유 링크, 외부 웹 링크를 문서관리와 공지사항의 본문 및 댓글/답글에 붙여넣으면 각각 구분된 미리보기를 제공한다.
- 내부 공유 링크 카드를 누르면 해당 문서 또는 공지의 상세 패널을 연다. 후속 요청에 따라 다른 기능 영역의 링크도 현재 화면을 유지한 채 공통 우측 패널로 연다. 외부 웹 링크만 새 탭으로 연다.

## 범위와 원칙

- 후속 요청: 공지 공유 미리보기는 문서와 동일하게 `공지구분 · 작성자`로 표시한다. 기존 응답의 작성자 이름을 사용하며 이름이 없으면 구분명만 표시한다.

- 후속 요청: 문서/공지 본문·댓글의 공지 공유 미리보기는 `NOTICE_GUBUN` 공통코드 명칭을 표시한다. 조회 실패/미등록 코드이면 원시 코드 대신 `공지`를 표시한다.

- 후속 요청: 외부 OG 카드 상단의 독립된 `웹 링크` 문구를 제거한다. 사이트명, 제목, 설명, 링크 동작과 내부 문서/공지 구분은 유지한다.

- 기존 문서 공유 토큰, URL, 조회 권한 확인, 상세 패널 동작, legacy `documentId` 링크를 유지한다.
- 공지 공유는 로그인과 동일 tenant의 현재 게시글 조회 권한을 확인한다. 링크 토큰은 저장하지 않고 문서 토큰과 분리된 암호화 문맥을 사용한다.
- 링크 분류와 미리보기 카드/비동기 상태 관리는 shared feed 컴포넌트로 공통화한다. 공지·문서 API adapter와 대상 상세 패널 열기는 각 도메인에서 소유한다.
- 기존 외부 OG API 및 SSRF 방어를 재사용한다. 내부 문서/공지 링크는 외부 OG API에 전송하지 않는다.
- 미리보기 메타데이터와 공유 토큰을 DB에 저장하지 않으며 DB 스키마를 변경하지 않는다.
- 공지 로그인 팝업 화면은 공유 대상이 아니며, 공유 링크는 일반 공지 상세 패널을 연다.

## 실행 순서와 완료 기준

1. 설계/계획/상세사양을 확인한다.
2. 공용 공유 토큰 codec의 문서 토큰 호환성, 공지 토큰 tenant/domain 검증, 공지 API 회귀 테스트를 먼저 작성한다.
3. 공지 공유 링크 발급/해석 API 및 공지 메뉴의 링크 복사를 추가한다.
4. 문서/공지/외부 URL 링크 추출과 카드 렌더링을 shared feed 계층으로 공통화하고 두 기능의 본문·댓글·답글에 연결한다.
5. 동일 기능 링크는 현재 상세 패널을 열고 교차 기능 링크는 토큰 확인된 대상의 기존 상세 API/UI를 공통 우측 패널에서 사용한다.
6. focused backend/frontend 테스트, build, lint, 실제 Chromium 375/768/1280px 검증을 수행한다.
7. 결과 보고서와 스크린샷을 `docs/result/20261029/document-notice-sharing-previews`에 보관한다.

기존 변경을 보존하고 관련 없는 파일을 수정하지 않는다. DB 변경, 익명 공개 접근, 공지 팝업 공유, 외부 미리보기 위탁은 범위에서 제외한다.
