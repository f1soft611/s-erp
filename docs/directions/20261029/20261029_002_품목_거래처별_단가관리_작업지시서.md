# 20261029_002 품목·거래처별 단가관리 작업지시서

## 목적

제공된 `smart_haccp_schema_2.sql`의 품목/거래처별 단가 정의를 S-ERP의 tenant-aware DB 및 화면 패턴에 맞게 재설계하고, 기준정보 화면에서 단가를 검색·등록·수정하며 엑셀로 여러 건을 안전하게 등록할 수 있게 한다.

## 승인 설계 및 근거

- [단가관리 승인 설계](../../superpowers/specs/2026-10-29-item-partner-pricing-design.md)
- 원본 단가 테이블: `tb_item_partner_price`; 원본의 item/partner code FK는 S-ERP의 현재 마스터와 맞지 않으므로 직접 사용하지 않는다.
- central `s-erp-postgresql-readonly` MCP로 `list_tables`, `tb_material_info`, `tb_customer_info`, `tb_sales_order_hd`, `tb_sales_order_dt`의 컬럼 메타데이터와 item/customer 복합 unique 키를 확인했다. 현재 DB 목록에 단가 테이블은 없다. 데이터 행은 조회하지 않았고 DDL은 적용하지 않았다.
- S-ERP의 품목/거래처 식별자는 BIGINT이며 tenant 경계는 `(id, tenant_id)` 복합 FK로 보호한다. 금액은 기존 수주 상세와 동일하게 `NUMERIC(15,2)`를 사용한다.

## 승인 범위

- 신규 `public.tb_item_partner_price` 스키마 초안과 같은 내용의 날짜별 SQL, 변경 이력, 보호형 rollback을 `docs/database/20261029`와 `backend/DATABASE/20261029`에 작성하고 `docs/database/db-schema.md`를 갱신한다. DB에는 실행하지 않는다.
- 기준정보의 품목·거래처 단가 페이지를 추가한다. 페이지는 `PageHeader`, `PageSearchArea`, `PageMessageArea`, F1-Grid를 따르고 F1-Grid row form으로 단건 등록/수정을 지원한다.
- 품목/거래처는 기존 마스터 검색을 사용하여 코드/명으로 선택한다. 화면/API의 식별자는 S-ERP 내부 ID를 사용한다.
- 검색은 거래유형, 품목/거래처 코드 또는 명, 적용일, 사용여부를 지원한다.
- 신규 및 수정 변경 집합을 기존 품목·거래처와 같은 단일 batch-save 트랜잭션으로 처리한다. 물리 삭제는 제공하지 않고 `useAt`을 사용한다.
- 양식 다운로드, `.xlsx` 업로드, 파싱 미리보기, 행별 검증, 확인 후 신규 행 stage를 제공한다. 기존 자료는 엑셀에서 수정/업서트하지 않는다.
- 엑셀의 품목/거래처 코드를 tenant 범위에서 확인하고, 형식 오류/파일 내 중복/DB상 동일 업무키 충돌은 행 단위 오류로 보여준다. 오류가 있는 상태에서는 stage/저장을 허용하지 않는다.
- 엑셀의 확인된 행은 페이지의 F1-Grid 변경 집합에 신규행으로 추가한다. 수기 변경과 함께 기존 단일 원자적 저장 버튼으로 저장한다. 최종 save API도 검증과 DB unique 제약을 적용해 preflight 이후의 경합을 방어한다.
- 동일 tenant, 품목, 거래처, 거래유형, 적용시작일 업무키는 중복을 거부한다. 다른 시작일의 적용기간 중첩은 거부하지 않는다.
- 반응형은 375px, 768px, 1280px에서 확인하며 좁은 화면의 표는 grid 내부에서 스크롤한다.
- F1-Grid 동작 문서를 갱신하고 결과 문서/스크린샷을 `docs/result/20261029/item-partner-pricing/`에 남긴다.

## 데이터베이스 초안

- `price_id BIGSERIAL`, `tenant_id BIGINT`, `material_id BIGINT`,
  `customer_id BIGINT`.
- 원본 필드의 의미를 유지해 `trade_type VARCHAR(10)`, `unit_price NUMERIC(15,2)`,
  `currency VARCHAR(10) DEFAULT 'KRW'`, `start_dt DATE`, `end_dt DATE`,
  `moq NUMERIC(15,2)`, `use_at CHAR(1) DEFAULT 'Y'`.
- 감사 컬럼은 S-ERP 형식 `created_by/created_at/updated_by/updated_at` 및
  `VARCHAR(10)` 사용자 ID, `TIMESTAMP WITHOUT TIME ZONE`으로 둔다.
- `(material_id, tenant_id)` 및 `(customer_id, tenant_id)` 복합 FK, tenant 포함 업무키 unique, 거래구분/use 여부/기간 CHECK를 둔다.
- 롤백은 신규 테이블이 비어 있을 때만 삭제한다. 의존성, 행 또는 예상과 다른 스키마가 확인되면 중단하며 `CASCADE`를 사용하지 않는다.

## 작업 순서

1. 본 지시서와 승인 설계를 바탕으로 계획서를 작성한다.
2. 계획서에 따라 API, DB, 화면, 검증 계약을 상세 사양서로 확정한다.
3. 실제 작업 전 현재 작업트리 변경을 보존하고 품목·거래처, 수주, F1-Grid 저장 패턴과 테스트를 확인한다.
4. DB DDL/rollback/이력 문서를 양쪽 스키마 디렉터리에 동일하게 작성하고 누적 스키마 문서를 갱신한다. 실행하지 않는다.
5. Backend 목록/저장/엑셀 사전검증 API의 실패 테스트를 먼저 작성한 뒤 controller/service/DAO/mapper를 구현한다.
6. Frontend API, 행 폼, 품목·거래처 선택, ExcelJS 동적 로딩 기반 양식/업로드/검증 미리보기 및 F1-Grid stage를 테스트 우선으로 구현한다.
7. 제한된 backend/frontend 테스트, backend test, frontend test/build/lint를 수행하고 브라우저 3개 뷰포트를 확인한다.
8. F1-Grid 문서와 결과 문서/스크린샷을 갱신하고 DB DDL 복사본, 스키마 메타데이터, 테스트 및 미적용 상태를 점검한다.

## 완료 조건

- 신규 단가 페이지가 기존 메뉴 권한/tenant 경계에 따라 조회·변경된다.
- 단건 행 폼과 엑셀 신규 등록이 모두 동일한 유효성/중복 방어/단일 batch 저장 흐름을 사용한다.
- 오류 입력은 성공으로 표시되지 않고, 검증/저장 실패 시 사용자의 행과 입력이 보존된다.
- 파일 오류, 형식 오류, 코드 미존재, 파일 내 중복, DB 업무키 중복이 엑셀 행 번호와 함께 식별된다.
- `docs/database`/`backend/DATABASE` 날짜별 파일 사본이 동일하고 `db-schema.md` 및 F1-Grid 문서가 갱신된다.
- DDL은 미적용이며 이를 명시한다. 테스트, 3개 viewport 결과, 영문 경로 스크린샷이 결과 문서에 포함된다.

## 제외 범위

- DDL 적용, 기존 단가 일괄 수정/업서트, 기간 중복 금지, 환율 계산, 별도 통화 마스터.
- 품목·거래처 마스터 자체의 변경.
