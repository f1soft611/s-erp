# 출하 용어 변경 및 출하계획 편집 작업지시서

## 사용자 요구

- 영업관리의 `납품관리` 메뉴와 `납품등록`, `납품현황` 페이지를 출하 용어로 변경한다.
- 화면 안의 납품 업무 문구와 정책관리의 납품 정책 표시명을 출하 용어로 통일한다.
- `출하계획등록`, `출하계획현황` 메뉴/화면을 제공해 수주 저장 시 자동 생성된 계획도 편집할 수 있게 한다.
- 기존 API/DB/메뉴 식별자와 데이터 계약은 유지한다.

## 승인 설계

- [상세사양서](../../spec/20261106/20261106_004_출하용어변경_및_계획편집_상세사양서.md)를 구현 기준으로 한다.
- `AUTO`와 `MANUAL` 모두 출하계획 조회, 현황, 기존 계획 수정이 가능하다. 수동 신규계획 생성은 `MANUAL` 전용으로 유지한다.
- `AUTO` 출하계획등록 화면에서는 기존 자동 생성 계획을 불러와 수정하며 중복 계획을 만들지 않는다.
- `AUTO` 수주 수정은 기존 계획 일자/수량을 덮어쓰지 않는다. 새 수주 상세에만 초기 계획을 추가하고, 수주수량이 해당 계획합보다 작아지는 수정은 거부한다.
- 메뉴 표시명/설명과 기본 정책명/설명은 변경하지만 메뉴 코드·URL·권한과 정책 코드·값·타입은 유지한다.
- 실제 DB에는 마이그레이션을 적용하지 않는다.

## DB 및 저장소 근거

- 작업 전 기본 `s-erp-postgresql-readonly` MCP의 `list_tables`와 `describe_table`로 `tb_menu`, `tb_system_policy`, `tb_sales_delivery_plan_hd`, `tb_sales_delivery_plan_dt`, `tb_role_menu_permission` 구조를 확인했다. 관련 테이블과 기존 계획 데이터는 현재 대상 DB에 존재한다.
- `tb_menu`는 메뉴 코드, 이름, 설명, URL을 분리 저장하고, 정책은 `tb_system_policy`에 정책 코드·이름·설명·값·타입을 별도로 저장한다.
- 기존 메뉴 SQL/서비스에서 출하계획 메뉴는 AUTO 모드에서 숨기고, 계획 서비스는 AUTO 모드의 읽기/수정도 제한한다. 둘 다 승인 설계에 따라 변경 대상이다.
- DB MCP는 구조 확인에만 사용했으며 업무 행을 조회하거나 DDL을 적용하지 않았다.

## 구현 순서

1. [상세사양서](../../spec/20261106/20261106_004_출하용어변경_및_계획편집_상세사양서.md)와 [계획서](../../plan/20261106/20261106_004_출하용어변경_및_계획편집_계획서.md)를 확인한다.
2. 격리된 작업 worktree에서 AUTO 계획 조회/수정, 주문 계획 보존, 수량 감소 거부, 메뉴 노출에 대한 실패 회귀 테스트를 먼저 작성한다.
3. 백엔드에 인증 tenant 범위의 order-to-plan 조회를 추가하고 GET/status/PUT을 두 운영 모드에 허용한다. POST 신규 생성은 MANUAL 전용으로 유지한다.
4. AUTO 수주 수정이 기존 계획 상세를 변경하지 않고, 새 수주 상세에만 자동 계획을 추가하도록 서비스 계약을 수정한다.
5. 프론트 출하계획등록에서 모드별 대상 수주를 선택하고 AUTO는 기존 계획을 로드·수정하도록 구성한다.
6. 메뉴/계획/출하/정책의 사용자 표시 문구를 출하로 변경하고, 정책 안내 및 F1-Grid 문서도 갱신한다. API·DB·메뉴 식별자는 바꾸지 않는다.
7. 메뉴·정책 표시명/설명만 변경하는 날짜별 SQL, 안전한 조건부 rollback, 변경 이력을 docs와 backend 폴더에 동일 작성한다.
8. 관련 Maven/Vitest/build/lint/SQL 계약 테스트와 375/768/1280px 브라우저 확인을 수행하고 결과서와 스크린샷을 작성한다.

## 완료 조건

- AUTO 메뉴에서 출하계획등록/현황이 보이고, 계획의 등록화면과 현황에서 기존 계획을 조회·수정할 수 있다.
- AUTO 출하계획등록은 기존 계획을 PUT으로 수정하며 신규 POST 계획을 중복 생성하지 않는다.
- MANUAL 신규계획 생성과 기존 계획 편집은 유지된다.
- AUTO 수주 수정 시 기존 계획 일자/수량이 보존되고 수주수량 축소는 계획합 미만에서 거부된다.
- 출하관리/출하등록/출하현황/출하계획 및 정책 표시 문구가 일관되고, 안정 식별자·권한·직납품 흐름은 바뀌지 않는다.
- SQL은 두 경로에서 동일하고 실행되지 않았음을 결과서에 기록한다.
- 반응형 브라우저 확인, 테스트, 결과 문서, 스크린샷이 포함된다.
