# 20260826*002*좌측*네비게이션*모듈*메뉴*트리\_작업지시서

## 1. 작업 개요

현재 ERP 메인 화면은 좌측 네비게이션 중심의 단순 구조로 보이며, 상단에 모듈 선택 영역이 없거나 선택 영역과 하위 메뉴 구조가 분리되어 있지 않아 사용자가 전체 업무 흐름을 한눈에 파악하기 어렵다.

이번 작업은 좌측 영역을 정리하면서 상단에 모듈 섹션을 배치하고, 모듈 선택 시 하단에 해당 메뉴 트리를 표시하는 구조로 개선하는 것을 목표로 한다.

핵심 의도는 다음과 같다.

- 좌측 네비게이션을 단순 리스트 구조에서 ERP 스타일의 모듈 선택형 구조로 전환한다.
- 상단에 모듈 배치 영역을 추가해 사용자에게 현재 서비스 기능군을 빠르게 인지시킨다.
- 모듈 선택 시 하단에 해당 모듈의 세부 메뉴를 트리 형태로 확장한다.
- 선택 상태, hover 상태, 현재 위치를 시각적으로 명확하게 구분한다.

---

## 2. 작업 목적

이번 작업의 목적은 다음 사항을 반영한 화면 구조를 구성하는 것이다.

- 좌측 네비게이션의 과도한 정보 밀도를 줄이고, 상단 모듈 선택 영역을 통해 기능을 분류한다.
- 사용자가 클릭한 모듈에 맞는 하위 메뉴가 바로 아래에 보이도록 구성한다.
- 메뉴 트리와 메인 콘텐츠 영역이 분리되어 ERP 운영 구조처럼 보이도록 한다.
- 실제 화면 캡처와 유사한 UI 구현을 목표로 하며, 사용자 경험을 개선한다.

---

## 3. 현재 문제점

현재 구성은 다음과 같은 한계가 있다.

1. 좌측 네비게이션만 존재해 기능군의 계층 구조가 충분히 드러나지 않는다.
2. 모듈 선택 영역이 없어 전체 업무 영역을 빠르게 파악하기 어렵다.
3. 선택된 모듈의 하위 메뉴가 한눈에 보이지 않아 구조적 이해가 낮다.
4. 화면이 단순 사이드바형으로 인식될 수 있어 ERP 행위형 UI로 보기에 부족하다.

---

## 4. 요구사항

### 4.1 좌측 네비게이션 수정

- 좌측 영역은 기존 네비게이션을 유지하되, 모듈 표현 방식을 정리한다.
- 각 모듈은 아이콘 + 텍스트 조합으로 표현한다.
- 현재 선택된 모듈은 강조 색상으로 표시한다.
- 좌측 네비게이션은 전체 화면을 압도하지 않도록 폭을 적절히 유지한다.

### 4.2 상단 모듈 섹션 추가

- 화면 상단에는 모듈 섹션이 위치해야 한다.
- 모듈 섹션은 다수의 기능 그룹을 한 줄 또는 격자 형태로 배치한다.
- 사용자가 모듈을 클릭하면 하위 메뉴 트리가 즉시 갱신되어야 한다.
- 선택된 모듈은 상단 섹션과 좌측 네비게이션 모두에서 일관되게 강조되어야 한다.

### 4.3 클릭 시 하단 메뉴 트리 구조

- 모듈 클릭 시 하위 메뉴가 아래 영역에 트리 형태로 전개되어야 한다.
- 메뉴 트리는 계층 구조를 가지며, 각 항목을 확장/축소할 수 있는 형태가 적절하다.
- 선택 메뉴는 강조 표시를 통해 현재 위치를 명확하게 표현한다.
- 하위 메뉴는 상단 모듈 섹션 아래에 위치해 사용자의 시선 흐름을 유지한다.

## 5. 구현 방향

### 5.1 화면 구성 방향

- 상단에는 ERP 시스템 타이틀과 기능 모듈 버튼 배열을 배치한다.
- 좌측에는 기능군이나 고수준 메뉴가 유지된다.
- 하단 메뉴 트리는 모듈별로 세부 항목을 나열하는 구조로 구성한다.
- 메인 콘텐츠 영역은 선택된 메뉴에 따른 콘텐츠를 표시한다.

### 5.2 상태 표현 방향

- 기본 선택 상태: 활성화된 모듈 배경색 강조
- hover 상태: 약한 배경 전환
- selected menu: 청색/진한 배경 또는 좌측 테두리 강조
- 비활성 메뉴: muted tone

### 5.3 데이터 구조 방향

다음 형태의 데이터 구조를 사용할 수 있다.

```ts
const modules = [
  {
    id: 'sales',
    name: '영업관리',
    icon: 'sales',
    menus: [
      { id: 'customer', name: '고객관리', pageKey: 'customer' },
      { id: 'contract', name: '계약관리', pageKey: 'contract' },
      { id: 'order', name: '수주관리', pageKey: 'order' },
    ],
  },
];
```

이 구조를 통해 다음을 구현할 수 있다.

- 모듈 선택 상태 관리
- 하위 메뉴 트리 렌더링
- 선택된 메뉴에 대한 콘텐츠 전환
- 재사용 가능한 네비게이션 UI 구성

### 5.4 대시보드 페이지 분리 방향

메인 대시보드 화면은 단일 페이지 컴포넌트에 모든 로직을 담지 않고, 다음처럼 분리해서 구현한다.

- `DashboardPage`: 페이지 레벨의 조립 컴포넌트
- `DashboardHeader`: 상단 ERP 타이틀 및 모듈 섹션
- `DashboardSidebar`: 좌측 네비게이션 및 모듈 리스트
- `DashboardTreeMenu`: 선택된 모듈의 하위 메뉴 트리
- `DashboardContent`: 선택된 메뉴에 따른 메인 콘텐츠 영역
- `useDashboardModules`: 모듈/메뉴 데이터와 선택 상태 관리 훅
- `useDashboardSelection`: 현재 선택된 모듈, 메뉴, 페이지 전환 로직 관리 훅

이렇게 분리함으로써 다음을 보장한다.

- 페이지 로직과 UI 레이어의 책임 분리
- 모듈/메뉴 상태 관리 재사용성 확보
- 향후 메뉴 구조 확장 시 수정 범위 최소화
- 대시보드 화면을 페이지 단위로 유지하면서 구성 요소를 세분화
