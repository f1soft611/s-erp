# 20261120_005 사원등록 공통 행 폼 전환 작업지시서

## 배경
사원등록(2-1, [20261119_009](../../spec/20261119/20261119_009_hr-employee_상세사양서.md))은 목록 그리드(읽기 전용) + **전용 등록·수정 팝업**(`EmployeeFormDialog`)으로 만들어 한 명씩 바로 저장했다. 다른 화면(창고·품목 등)은 F1Grid의 **공통 행 폼**(섹션 카드, 연필 "정보 수정" 열, 필수값 빨간 테두리, 적용 → 화면 저장 버튼 일괄 저장)을 쓴다. 사용자가 화면마다 제각각이면 통일성이 없다고 지적했고, 공통으로 못 맞출 사유가 없는데 전용 폼을 만든 것은 제 판단 착오였다(프론트 지침: 기준 화면과 레이아웃·폼 통일, 별도 폼 신규 작성 지양).

## 결정 (사용자, 2026-11-20)
- 사원등록을 **공통 행 폼으로 전환**한다(권장안 채택). 연필 아이콘·입력 폼 구성·저장 방식(적용 후 화면의 저장 버튼으로 일괄 저장)을 창고관리와 같게 한다.
- **근무형태의 필수 표시를 제거**한다(선택 입력).
- **필수값을 비우고 적용/저장하면 해당 칸의 테두리를 빨갛게** 표시한다(공통 폼의 기본 동작: 오류 칸 빨간 테두리 + 안내 문구, 첫 오류 칸으로 포커스, 상단 메시지).

## 범위
- 포함: 사원 화면을 F1Grid 편집 그리드 + 행 폼(`rowFormPlugin`)으로 재구성, 일괄 저장 API(`POST /api/v1/hr/employees/save-batch`), 부서·주소(우편번호) 선택은 `code` 칸 + 기존 도움창, 사진은 공통 `image` 칸, 초기 비밀번호 칸을 가리기 위한 공통 행 폼 옵션 `form.inputType: 'password'` 추가(F1-Grid 문서 갱신 포함), 기존 전용 팝업·그리드 제거, 테스트·문서.
- 제외: 사원 저장 규칙(사번 채번, 계정 발급, 사진 정규화 등 기존 단건 서비스 로직은 그대로 재사용), 인사 DB 스키마, 부서관리 화면.

## 동작이 바뀌는 점
- 사원 정보를 고친 뒤 **상단 저장 버튼을 눌러야 저장**된다(행 폼의 "적용"은 화면 반영까지).
- 사번 중복 확인은 입력 도중이 아니라 **저장할 때** 서버가 검사해 메시지로 알려 준다.
- 모든 행은 한 번에 하나의 트랜잭션으로 저장되며 하나라도 실패하면 전체가 취소된다(메시지에 사원명 표시).

## 완료 조건
- 연필(정보 수정) 열과 행 폼 모양이 창고·품목과 같고, 근무형태에 필수 표시가 없으며, 필수값을 비우면 해당 칸이 빨간 테두리로 표시된다.
- 신규 등록(계정·사진 포함)·수정·재직/퇴직 조회·통합검색이 기존과 같은 결과로 동작한다(일괄 저장 포함).
- 관련 백엔드/프론트 테스트·`tsc`·`f1-grid-storage-keys` 통과, 실서버 브라우저(375/768/1280px) 확인, F1-Grid 문서 갱신.
