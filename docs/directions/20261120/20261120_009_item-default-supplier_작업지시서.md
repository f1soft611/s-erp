# 20261120_009 품목 기본 거래처 및 구매요청확정 자동 설정 작업지시서

## 작업 목적

1. 품목마다 **매입 기본 거래처**를 1곳 지정할 수 있게 하고, 구매요청확정에서 **요청 불러오기**를 하면 품목의 기본 거래처·단가·부가세·발주구분이 확정 행에 자동으로 설정되게 한다.
2. 단가등록의 "거래처가 없으면 기본단가" 해석을 바꾼다. 실제 업무는 거래처별 단가가 중심이므로, 거래처 없는 단가는 **공통단가(예비 단가)**로 이름을 바꾸고, "기본"은 **기본 거래처**를 뜻하게 한다.

## 사용자 결정 (2026-11-20)

- 기본 거래처는 품목당 1개. 저장은 단가 행이 아니라 **별도 테이블(품목당 1행)**에 둔다.
- 공통단가(거래처 없는 단가)는 거래처 단가가 없을 때의 예비 단가로 유지한다.
- 매입에만 적용한다(매출·영업 화면은 변경하지 않는다).
- 기본 거래처는 그 품목에 매입 단가가 등록된 거래처 중에서만 고른다.
- 기존 데이터 이전은 매입 거래처가 **한 곳뿐인 품목만** 자동 지정한다. 여러 곳인 품목은 직접 지정한다.
- **발주구분을 단가 행의 항목으로 추가한다**(사용자는 품목마스터가 더 맞다고 보지만, MES가 단가에 두고 있어 우선 단가화면에 추가하기로 함). 확정 불러오기에서 단가 행의 발주구분을 확정 행에 미리 채운다.

## MES 확인 결과 (참고만, 화면·구조는 s-erp 기존 패턴을 따른다)

| 확인 대상 | 결과 |
| --- | --- |
| `TCO408`(구매단가) | 기본키가 (품목, 거래처). 거래처가 필수라 거래처 없는 단가가 없다. `DEFAULT_CUST`(기본 거래처 표시)는 이 행에 있고 DB 제약은 없다. |
| `TCO410`(단가 이력) | (수정일, 품목, 거래처)당 1행. 기본 거래처 표시는 이력에 없다. |
| `SP_WCO315_02_IUD`, `SP_WCO318_02_IUD` | 기본 표시를 저장하면 같은 품목의 다른 거래처 표시를 모두 해제한다. 단가 행을 삭제하면 기본 표시도 사라진다. |
| `SP_WMA104_WIN01_01_LIST` | 확정 후보 조회가 요청 행에 거래처가 있으면 그 거래처, 없으면 기본 거래처를 쓰고, 단가·외화단가·통화는 기본 거래처 행의 값을 그대로 가져온다. 적용일은 확인하지 않는다. 후보 행의 발주구분은 구매요청 행의 값이다. |

- 차이: MES는 현재 단가 1행 + 이력 분리 구조이고, s-erp 단가는 기간별 행이 늘어난다. 그래서 기본 표시를 행에 두지 않고 별도 테이블로 둔다. 단가는 기준일에 유효한 행에서 고른다.
- 기본 범위에서 제외하는 MES 항목: 거래처 품목명·도면(`CUST_ITEM`, `CUST_DRAW`), 견적단가, 두 번째 단가, 단가단위, `REQUEST_RATE`(의미 미확인), 감사·옵션 컬럼. 확장 후보로 남긴다.

## 확정 범위

### 데이터베이스
- 신규 `tb_item_default_supplier`(품목 기본 거래처): 품목당 1행, 감사 컬럼 포함.
- `tb_item_partner_price`에 `order_type`(발주구분, 비워도 됨) 추가.
- 기존 데이터 이전(한 곳뿐인 품목 자동 지정), 롤백 스크립트, 변경 이력, `db-schema.md` 갱신. SQL은 사용자가 직접 실행한다.

### 백엔드
- 단가 저장(`save-batch`)·조회·엑셀에 발주구분과 기본 거래처 지정·해제를 추가한다. 품목당 하나는 서버가 보장한다.
- 단가 행 비활성화로 기본 거래처의 매입 단가가 하나도 남지 않으면 기본 거래처를 자동 해제한다.
- **공통 단가 조회 서비스**를 단가 모듈에 둔다. 단가·기본 거래처 조회는 이 서비스만 하고, 다른 업무는 호출만 한다(앞으로 단가를 쓰는 업무가 늘어도 규칙이 한 곳에 있게 한다). 확정 모듈의 기존 단가 쿼리는 이 서비스로 옮긴다.
- 구매요청확정 `request-details`(요청 불러오기)가 위 서비스로 기본 거래처·단가·부가세·통화·발주구분을 함께 내려준다(한 번의 쿼리). `unit-price` 응답에 발주구분을 추가한다.

### 프론트엔드
- 단가등록: "기본단가(거래처 공통)" 문구를 "공통단가"로 바꾸고, 매입 묶음에 **발주구분**과 **기본(거래처)** 항목을 추가한다(품목 기준 트리, 거래처 기준 탭, 이력 조회 탭, 행 폼, 엑셀). 검색 조건에 "매입 기본 거래처 미지정"을 추가한다.
- 구매요청확정: 요청 불러오기로 행이 들어오면 구매처·단가·부가세·통화·발주구분이 미리 채워진다. 사용자가 수정할 수 있고, 구매처를 바꾸면 기존처럼 단가를 다시 조회한다.

## 제외 범위

- 매출 단가의 기본 거래처, 영업 화면 변경.
- 요청 행에 거래처 지정, 두 번째 단가·단가단위·견적단가 등 위 MES 제외 항목.
- 기본 거래처 변경 이력 보관(감사 컬럼의 최종 수정만 남김), 공통단가 폐지, 일괄적용, 품목 선택 창 확장.
- 확정일을 바꿀 때 기본 단가 재조회(처음 불러올 때의 확정일 기준으로만 설정).

## 구현 절차

1. 계획서, 상세 사양서 (`docs/plan`, `docs/spec` 20261120, 번호 009)
2. DB 스크립트 `20261120_006`(적용·롤백·변경 이력, docs/database와 backend/DATABASE 동일 사본), `db-schema.md`, 정적 테스트
3. 백엔드 실패 테스트 → 구현 (단가 모듈 → 확정 모듈)
4. 프론트 실패 테스트 → 구현 (단가등록 → 구매요청확정)
5. 검증: 중간에는 관련 단위 테스트와 타입 검사만, 실서버·브라우저·전체 실행은 구현이 끝난 뒤 한 번에
6. 사용자 스크립트 실행 후 MCP 확인, 실제 서버 확인(데이터 남김), 결과 문서와 스크린샷 (`docs/result/20261120/item-default-supplier`)

## 완료 조건

- 단가등록에서 품목의 매입 거래처 중 하나를 기본으로 지정·변경·해제할 수 있고, 품목당 하나만 유지된다.
- 구매요청확정에서 요청을 불러오면 기본 거래처의 단가가 확정 행에 채워진다. 기본 거래처가 없으면 구매처가 비어 있다.
- 단가 행의 발주구분이 확정 행에 미리 채워지고 수정할 수 있다.
- 매출 단가와 영업 화면은 동작이 바뀌지 않는다.
- 결과 문서에 검증 결과, MCP 확인 근거, 커밋 제목·내용이 기록된다.
