# 20261120_002 매출마감관리 조회 API 및 프론트엔드 작업지시서

## 작업 목적

영업관리 > 매출관리 > 매출마감관리 화면과 조회 API를 추가한다. 출하현황의 통합검색과 펼침형 상세검색을 따르고, 출하일 기준 검색·거래처 복수 선택·매출대상 상세와 거래처별 요약을 구현한다.

## 확정 요구사항

- 통합검색은 출하현황처럼 한 칸으로 제공하고 화살표로 상세검색을 열고 닫는다.
- 상세검색의 기준일은 필수 출하일 기간이며 출하현황과 같이 당월을 기본값으로 하고 기존 빠른 날짜 선택을 사용한다.
- 수주처/매출처 구분 없이 거래처를 복수 선택한다.
- 좌측은 출하·수주·거래처·품목별 매출대상 상세 F1Grid, 우측은 고정 거래처별 요약이다.
- 거래처별 요약 행을 선택하면 좌측 상세를 해당 거래처로 필터링하고, 전체 행은 필터를 해제한다.
- 상세 F1Grid만 세로 스크롤을 소유한다. 요약 패널은 고정한다. 좁은 화면은 요약을 위, 상세를 아래로 배치한다.
- 기존 거래처 선택 호출부의 단건 선택 동작과 품목/구매처 도움창 동작을 유지하면서 거래처 도움창의 복수 선택을 지원한다.
- 기존 출하·수주·거래처·품목 및 거래명세서 테이블을 tenant 범위로 조회하는 읽기 전용 매출마감 API를 추가한다. 활성 거래명세서가 있는 출하를 마감으로 분류하고, 요약 건수는 거래처별 고유 출하 문서 수로 계산한다.
- 거래처 필드는 상세검색과 같은 그리드 간격으로 정렬하고, 여러 선택값은 첫 거래처명과 `외 N건`으로 요약한다. 선택한 거래처는 개별 칩으로 표시해 초안에서 빠르게 제거한다.
- 거래처별 요약은 전체/마감/미마감 수치를 카드형으로 표시하고 API 조회 중에는 요약 영역에 스켈레톤을 표시한다.
- 매출관리 > 매출마감관리 메뉴 seed와 롤백 스크립트를 추가한다. 스크립트는 명시적으로 승인된 tenant ID를 지정한 뒤 적용할 수 있게 하며 실제 DB에는 적용하지 않는다.
- DB 스키마 변경은 하지 않고 실제 매출 데이터를 임의로 만들지 않는다.

## 구현 범위

- 매출마감관리 화면과 전용 UI/타입/조회 서비스를 `frontend/src/pages/sales/revenue/closing/`에 추가한다.
- `backend`에 조회 전용 controller/service/DAO/model/Mapper와 tenant 범위 검증 테스트를 `sales/revenue/closing` 구조로 추가한다.
- 신규 상세 F1Grid의 컬럼/스크롤 동작을 `frontend/src/pages/f1-grid-docs/F1-GRID.md`에도 기록한다.
- `PageSearchArea`에 상세검색 추가 콘텐츠와 추가 활성 필터 수를 전달하는 선택적 확장점을 추가한다.
- 기존 master-picker 대화상자에 복수 선택을 추가하되 기존 단건 선택 계약을 보존한다.
- `DashboardContent` 및 페이지 콘텐츠 맵에 `revenue-closing` 페이지 키를 연결한다.
- `docs/database/20261120`와 `backend/DATABASE/20261120`에 동일한 메뉴 seed, 롤백, 변경 이력 문서를 추가한다.
- 관련 테스트, 빌드, 브라우저 화면 확인 및 결과 문서/스크린샷을 작성한다.

## 제외 범위

- DB 스키마 변경과 실제 DB 반영
- 실제 매출 자료처럼 보이는 화면용 하드코딩 데이터 및 DB 스키마 변경
- 매출 마감/마감 해제 기능과 저장 동작

## 완료 조건

1. 거래처 복수 선택 대화상자에서 검색 결과를 선택/해제하고 적용·취소할 수 있으며, 단건 선택 호출부는 회귀 없이 동작한다.
2. 상세검색에서 출하일 기간 필수 검증과 기존 날짜 프리셋을 사용할 수 있고, 거래처 선택은 상세검색 적용 시 반영된다.
3. 매출마감관리 화면이 대시보드 `revenue-closing` 키로 열리고, 좌측 상세 F1Grid와 우측 카드형 거래처 요약이 표시된다.
4. 인증 tenant 범위의 조회 API가 필수 출하일, 통합검색, 복수 거래처 조건으로 품목별 상세와 거래처별 출하 문서 수를 반환하며 마감 상태는 활성 거래명세서 존재로 판별한다.
5. 거래처 요약 선택 상태에 따라 좌측 목록을 필터링하는 순수 로직이 구현되고 테스트된다. 조회 결과가 없을 때 운영용 가짜 행은 표시하지 않는다.
6. 거래처 요약 조회 중 스켈레톤을 표시하고, 375px, 768px, 1280px에서 실제 브라우저로 배치를 확인해 세로 스크롤이 상세 F1Grid에만 있는지 확인한다.
7. 백엔드/프론트엔드 집중 테스트와 빌드/lint를 통과하고 메뉴 seed/롤백 파일의 대칭성과 정합성, F1-Grid 문서 갱신, 결과 문서와 영문 경로 스크린샷을 보관한다.
