# 20261120_003 매출마감 선택 마감 및 화면 개선 작업지시서

## 작업 목적

매출마감관리에서 미마감 출하를 선택해 거래명세서를 일괄 생성하고, 작은 화면과 다수 거래처에서도 상세 그리드와 거래처 요약을 모두 사용할 수 있도록 레이아웃과 요약 디자인을 개선한다.

## 확정 요구사항

- 매출대상 상세 F1Grid에 행 체크박스 선택 열을 표시하고 여러 행을 선택할 수 있게 한다.
- 마감/미마감 상태는 색상과 텍스트를 함께 보여주는 배지로 표시한다.
- 상세 행은 출하 상세 기준이며 마감 단위도 행(출하 상세) 단위다. 같은 `salesDeliveryId`라도 선택된 미마감 행별로 각각 마감한다.
- 마감 단위는 출하 상세 행이다. 같은 출하번호의 상세를 각각 선택할 수 있고 마감 건수도 선택한 미마감 상세 행 수로 계산한다. 거래처가 같은 여러 출하의 미발행 상세는 한 거래명세서로 묶을 수 있다. 마감일은 서버 기준일을 사용한다.
- 이미 마감된 행의 체크박스는 비활성화한다. 처리 전 확인창에 실제 처리할 미마감 행 수를 표시하고, 처리 후 상세와 요약을 다시 조회한다.
- 일괄 처리 API는 모든 출하를 하나의 트랜잭션으로 처리한다. 일부 성공 후 일부 실패하는 결과를 허용하지 않는다.
- 거래명세서 발행 화면에서 여러 출하를 선택하고 상세 행 체크박스로 발행 대상 품목을 선택한다. 서로 다른 출하번호를 한 거래명세서로 묶을 수 있지만 거래처는 모두 같아야 한다. 이미 발행된 상세는 대상에 표시하지 않는다. 출하 등록 자동 발행(AUTO)은 기존과 같이 해당 출하의 전체 상세를 한 번에 발행한다.
- 마감 상태는 활성 거래명세서 존재가 아니라 출하 상세의 명시적 매출마감 기록으로 판정한다. 출하등록 AUTO 발행이나 일반 거래명세서 발행만으로는 마감되지 않는다.
- API는 인증 tenant 범위에서만 출하와 상세 행을 잠그고 검증한다. 거래명세서 상세에 원본 `sales_delivery_detail_id`를 저장하고 출하 상세에 마감 시각/사용자를 기록한다.
- 기존 활성 거래명세서 상세는 출하 상세의 고유 `line_no`로 원본 상세 ID를 backfill한다. 기존 거래명세서가 연결된 상세도 매출마감 시각이 없으면 OPEN 상태로 유지한다.
- 마감 시 이미 활성 거래명세서가 있는 상세는 중복 발행하지 않고 마감만 기록한다. 아직 발행하지 않은 선택 상세는 거래처별로 묶어 거래명세서에 저장한다.
- 매출마감 메뉴에 CREATE 권한을 추가한다. 신규 API는 해당 권한을 검증하며 기존 조회/엑셀 권한을 유지한다.
- 넓은 화면에서는 상세 그리드와 요약 패널을 나란히 배치하고, 요약 거래처 목록은 패널 내부에서 스크롤한다.
- 작은 화면에서는 요약을 먼저 표시하고 상세 그리드를 아래에 둔다. 페이지 세로 스크롤을 허용하고 상세 그리드에 최소 표시 높이를 확보해 아래쪽 그리드가 잘리지 않게 한다. 거래처 목록은 요약 영역 안에서 별도로 스크롤한다.
- 우측 요약은 큰 카드 대신 전체 합계 요약과 조밀한 행 목록으로 재디자인한다. 각 행은 거래처명, 전체 건수, 마감/미마감 수를 한눈에 비교하게 하고 선택 행을 명확히 강조한다.
- DB 스키마 변경과 메뉴 권한 seed 변경을 날짜별 SQL/롤백/변경 이력에 기록하고, paired 폴더의 파일을 동일하게 유지한다. SQL은 실제 DB에 적용하지 않는다.

## 구현 범위

- `frontend/src/pages/sales/revenue/closing/` 상세 그리드 선택, 마감 액션/확인/오류/재조회, 반응형 높이와 요약 UI를 수정한다.
- 기존 거래처별 매출마감 요약 및 매출마감 서비스 테스트를 확장한다.
- `backend` 매출마감 API와 거래명세서 발행/서비스에 선택 상세 저장 및 tenant-scoped 일괄 생성을 추가하고 권한/원자성 검증 테스트를 작성한다.
- `docs/database/20261120`와 `backend/DATABASE/20261120`의 기존 메뉴 seed/롤백/변경 이력에 CREATE 권한 및 같은 tenant의 거래명세서 생성 역할 권한 연결을 반영한다.
- 작업지시서, 계획서, 상세사양서, 설계서와 결과 문서/스크린샷을 갱신한다.

## 제외 범위

- 거래명세서 날짜/비고 입력 UI 추가

## 완료 조건

1. 체크박스로 여러 상세 행을 선택할 수 있고 이미 마감된 행은 선택 체크박스가 비활성화된다.
2. 같은 출하번호의 상세 행을 각각 선택할 수 있으며 확인창은 미마감 선택 행 수를 표시한다.
3. 매출마감 상태는 명시적 마감 기록으로만 변경되며, AUTO/일반 거래명세서 발행만으로 닫히지 않는다. 이미 발행된 상세는 중복 문서를 만들지 않고 마감 처리할 수 있다.
4. 발행 화면은 여러 출하의 상세를 한 문서로 묶을 수 있고, 거래처가 다른 출하 상세는 한 문서로 만들 수 없다. 이미 발행된 상세는 재발행 대상에 나타나지 않는다.
5. 선택된 미발행 상세만 거래명세서에 포함되고, 매출마감 batch는 같은 거래처의 선택 상세를 한 문서로 묶는다. batch 중 하나라도 실패하면 전체가 롤백된다.
7. 권한 없는 사용자는 API를 호출해도 마감할 수 없고, 요청 tenant ID를 사용하지 않는다.
8. 좁은 화면에서 페이지 세로 스크롤로 상세 그리드까지 접근할 수 있으며, 요약 목록은 요약 영역 안에서 스크롤된다.
9. 거래처 요약이 조밀한 행 형태로 읽기 쉽고 고객 선택/전체 선택이 유지된다.
10. 관련 테스트, frontend build/lint, backend 집중 테스트가 통과한다.
11. 375px, 768px, 1280px 브라우저 화면을 개인정보 없이 확인하고 결과 문서와 영문 경로 스크린샷을 보관한다.
12. 메뉴 seed와 라인 단위 거래명세서 스키마 변경/롤백/변경 이력은 양쪽 DB 폴더에 동일하게 유지하고 실제 DB에는 적용하지 않는다.
