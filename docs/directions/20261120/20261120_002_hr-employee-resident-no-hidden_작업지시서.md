# 20261120_002 사원등록 주민등록번호 항목 숨김 작업지시서

## 배경
2-1 사원등록([20261119_009](../../spec/20261119/20261119_009_hr-employee_상세사양서.md))은 주민등록번호를 서버에서 AES-GCM으로 암호화해 저장하고 키를 서버 환경변수로 관리하도록 만들었다. 사용자가 관리 방식을 바꾸려고 검토하다가(DB 암호화·단방향 해시 비교) 아래와 같이 결정했다.

## 결정 (사용자, 2026-11-20)
- 인사급여의 연말정산·4대보험 신고 기능은 아직 없고 한참 뒤의 일이므로 **주민등록번호는 지금 관리하지 않는다. 생년월일로 대체한다.**
- 주민등록번호 항목은 **일단 숨긴다.** 필요해지면(연말정산·4대보험 등) 그때 저장·복원 방식(복호화 가능 여부, 키 보관)을 다시 결정한다.

## 범위
- 포함: 사원 등록·수정 팝업에서 주민등록번호 입력과 마스킹 표시 제거, 요청에서 주민번호 제외, 입력 검증 제거, "생일"·"생일 구분" 라벨을 "생년월일"·"생년월일 구분"으로 변경, 테스트·문서 갱신.
- 제외(그대로 둠): 백엔드 암호화 코드(`ResidentNumberCipher`)와 DB 컬럼(`resident_no_*`), 이미 저장된 값. 서버는 주민번호가 비어 있으면 기존 값을 그대로 두므로 백엔드 변경이 없다. DB 스크립트 변경 없음.

## 완료 조건
- 사원 등록·수정 팝업에 주민등록번호 칸이 없고 요청 본문에 `residentNo`가 없다.
- 생년월일(양력/음력 구분 포함)로 입력할 수 있다.
- 서버 암호화 키 환경변수(`HR_RESIDENT_NO_ENCRYPTION_KEY`, `_VERSION`)를 설정하지 않아도 사원 등록·수정이 모두 동작한다.
