# 20261120_001 인사관리 2-2단계 계정관리 작업지시서

## 배경
인사관리 모듈 2단계(인사정보관리)의 두 번째 작업이다. 2-1(사원등록)에서 사원 등록 시 계정(`tb_login_account`)을 같이 발급하게 했고, 이 단계에서는 발급된 계정을 관리하는 화면과 로그인 보안 규칙을 만든다. 결과 문서: [20261119_009](../../result/20261119/hr-employee/20261119_009_인사관리_사원등록_결과.md).

## 결정 (사용자 승인, 2026-11-20)
- 범위는 A + B + C 전부이며, 구현은 **A → 잠금 정책 → B → C** 순서로 쪼개서 단계마다 테스트한다.
  - A: 계정 목록·조회, 로그인 허용/미허용, 비밀번호 초기화, 권한(역할) 부여
  - 잠금 정책: 로그인 실패 횟수 잠금(정책관리에서 사용/미사용과 기준 횟수 설정), 관리자 잠금 해제
  - B: 비밀번호 초기화·최초 발급 계정의 최초 로그인 시 비밀번호 변경 강제
  - C: 사진 변경 정책, 내 정보 관리 연동, 퇴사자 로그인 자동 차단
- 화면 위치는 환경설정 > 시스템 관리 아래 "계정관리"(`ST_ACCOUNTS`, `/settings/system/accounts`). 계정 **발급은 사원등록**에서만 하고, 이 화면은 이미 발급된 계정의 관리만 한다.
- 로그인 실패 잠금은 정책관리(`tb_system_policy`)에서 제어한다. 기본값은 **미사용**이어서 배포해도 현재 로그인 동작이 바뀌지 않는다. 사용으로 바꾸면 기준 횟수(기본 5회, 3~10회)에 도달할 때 잠기고, 해제는 관리자만 한다.
- 사진 변경 정책도 정책관리에서 제어한다(본인 변경 허용 / 관리자만). 기본값은 현재 동작인 본인 허용이다.
- 사원 마스터(`tb_user`)가 사진·이메일·부서·직위의 원본이고 내 정보 관리는 이를 따른다.

## 현재 상태 (DB MCP·소스로 확인)
- `tb_login_account`에 `use_at`, `login_attempt_count`, `locked_at`, `password_changed_at`이 있으나 로그인 로직은 `use_at`만 쓰고 잠금 컬럼은 쓰지 않는다.
- 계정 13건 중 `password_changed_at`이 비어 있는 것이 2건이다. 이 값으로 변경 강제를 판단하면 기존 계정이 막히므로 별도 플래그 컬럼을 둔다.
- 퇴직일이 지난 사원 중 계정이 있는 경우가 2건이다. 퇴사자 로그인 차단을 넣으면 이 계정은 로그인할 수 없게 된다(점검용 데이터 여부를 사양서 확인 단계에서 점검한다).
- 비밀번호 변경은 본인용 `ProfileSettingsService.changeMyPassword`뿐이고 관리자 초기화는 없다. 로그인 비밀번호는 아이디를 솔트로 해시한다(`EgovFileScrty.encryptPassword`).
- 정책관리는 `BOOLEAN/NUMBER/SELECT` 타입, 최솟값·최댓값·단위를 지원하고 서버가 정책 코드별로 값을 읽는 방식(`getStatementIssueMode`)이 이미 있다.

## 범위
- 포함: DB 스크립트(계정 컬럼 추가·메뉴·권한·정책 시드·사진 보정), 백엔드 `let/system/accounts`와 로그인 서비스 변경, 정책값 읽기, 프론트 `pages/settings/system/accounts`와 최초 로그인 비밀번호 변경 화면, 내 정보 관리 사진 정책·사번·직위 표시, 테스트, 결과 문서·스크린샷.
- 제외: 계정 신규 발급(사원등록에서 수행), 다중 요소 인증, 비밀번호 만료 주기·복잡도 정책, 로그인 이력 화면, 자동 잠금 해제(시간 경과), 인사명령·이력(3단계).

## 완료 조건
- 계정 목록 조회(검색·상태 필터)와 허용/미허용, 비밀번호 초기화(임시 비밀번호 1회 표시), 권한 부여, 잠금 해제가 동작하고 서버에서 자기 자신 비허용·마지막 관리자 권한 제거·역할 없음을 막는다.
- 잠금 정책이 미사용이면 로그인 동작이 이전과 같고, 사용이면 기준 횟수 도달 시 잠기며 올바른 비밀번호도 거부된다. 관리자 해제·비밀번호 초기화로 풀린다.
- 초기화·최초 발급 계정은 변경 전까지 비밀번호 변경 외 API를 쓸 수 없고, 변경 후 정상 사용된다.
- 사진 정책이 관리자만이면 본인이 사진을 바꿀 수 없고, 퇴직일이 지난 사원은 로그인할 수 없다.
- 백엔드 `mvn test`, `javac --release 8`, 프론트 `tsc`·lint·`f1-grid-storage-keys` 포함 관련 테스트 통과, 375/768/1280px 브라우저 확인, DB MCP 확인 근거 기록.
