# 20260922_001 공지사항 중요 공지 기능 상단 고정 전환 작업지시서

## 작업 분류

- 경로: `bounded`
- 대상: 프론트엔드, 백엔드, DB 계약
- 관련 화면: `/groupware/community/notice`
- 주요 필드: 기존 `isNotice` 제거, 신규 `isPinned` 추가

## 작업 목적

공지사항의 기존 중요 공지 기능을 제거하고, 게시글을 목록 상단에 고정하는 기능으로 대체한다. 화면과 API의 의미를 `isPinned`로 통일해 사용자가 게시글 작성 시 상단 고정 여부를 지정하고, 게시글별 더보기 메뉴에서 고정 상태를 변경할 수 있도록 한다.

## 요구사항

1. 기존 중요 공지 기능을 제거한다.
   - 작성/수정 화면의 `중요 공지` 체크박스를 제거한다.
   - 중요 공지 전용 필터와 요약 수치를 제거한다.
   - 중요 공지용 색상 강조와 상태 라벨을 제거한다.
   - `isNotice`/`is_notice`를 공지 고정 상태 판별에 사용하지 않는다.
2. 신규 상단 고정 필드를 추가한다.
   - 프론트엔드/API 필드명은 `isPinned`를 사용한다.
   - DB 컬럼은 `is_pinned CHAR(1) NOT NULL DEFAULT 'N'`으로 추가한다.
   - 기존 데이터의 초기 고정 상태는 `N`으로 설정한다.
   - 저장 요청과 목록/상세 응답에 `isPinned`를 포함한다.
3. 게시글 작성/수정 모달에는 상단 고정 선택 UI를 제공하지 않는다.
   - 작성/수정 모달에 상단 고정 체크박스를 추가하지 않는다.
   - 작성/수정 payload에는 상단 고정 상태를 직접 입력받지 않는다.
4. 게시글 더보기 메뉴 옆에 상단 고정 아이콘과 동작을 추가한다.
   - 고정되지 않은 게시글은 상단 고정 아이콘/명령을 표시한다.
   - 고정된 게시글은 상단 고정 해제 아이콘/명령을 표시한다.
   - 상단 고정 상태 변경은 이 아이콘/명령을 통해서만 수행한다.
   - 고정 동작은 `isPinned = 'Y'`, 해제 동작은 `isPinned = 'N'`을 저장한다.
   - 동작 성공 후 목록, 상단 고정 영역, 카운터가 최신 상태로 갱신된다.
   - 기존 권한, 삭제, 수정, 상세 보기 동작은 유지한다.
5. 상단 고정 영역을 `isPinned = 'Y'` 게시글 전용으로 구성한다.
   - 일반 게시글 목록 조회와 상단 고정 게시글 조회를 별도 요청으로 수행한다.
   - 일반 게시글 목록은 기존 게시글 조회 흐름과 조건으로 조회한다.
   - 상단 고정 게시글은 `isPinned = 'Y'` 조건으로 별도 조회한다.
   - 좌측 상단 도구 행 아래에는 별도 조회한 고정 게시글만 표시한다.
   - 고정 게시글이 없으면 기존 공통 빈 상태 표현을 사용한다.
   - 고정 게시글은 일반 게시글 목록에서도 다시 표시될 수 있으며, 두 영역 간 중복을 허용한다.
   - 상단 고정 개수는 별도 고정 게시글 조회 결과의 수와 일치한다.
6. 일반 게시글 피드는 무한 스크롤 방식으로 과거 게시글을 추가 조회한다.
   - 최초 진입과 검색/구분 필터 변경 시 `page=1`, `size=20`으로 조회한다.
   - 일반 목록 끝에 도달하면 다음 페이지를 `size=20`으로 조회한다.
   - 추가 조회 결과는 기존 일반 목록 뒤에 이어 붙인다.
   - 추가 조회 중에는 목록 하단 로딩 상태를 표시하고 중복 요청을 방지한다.
   - 더 조회할 데이터가 없으면 추가 요청을 중단하고 끝 상태를 표시한다.
   - 검색어·구분 필터·새로고침·오류 재시도 시 페이지와 누적 목록을 초기화한다.
   - 상단 고정 영역은 일반 피드의 누적 페이지에 포함시키지 않고 별도 조회 결과를 유지한다.
7. 반응형 화면을 유지한다.
   - 375px, 768px, 1280px에서 아이콘, 제목, 더보기 메뉴, 상단 고정 영역이 겹치거나 잘리지 않아야 한다.
   - 기존 피드형/리스트형 보기 전환과 우측 요약 sticky 레이아웃은 유지한다.

## 영향 범위

- 프론트엔드 공지 타입, 어댑터, 일반 목록 조회, 상단 고정 별도 조회, 상단 고정 영역, 더보기 메뉴, 요약 데이터, 관련 테스트
- 작성/수정 모달에서는 기존 중요 공지 UI만 제거하고 상단 고정 UI는 추가하지 않음
- 백엔드 공지 저장 요청 VO, 조회 VO, Controller 파라미터, Service, MyBatis Mapper의 조회/저장/수정 계약
- `tb_board_post` 스키마 및 날짜별 DB 변경 이력 문서/SQL/rollback
- 기존 `isNotice` 기반 문서와 테스트의 의미 정리

## 제외 범위

- 공지 구분 코드(`noticeGubunCode`) 정책 변경
- 게시판·자료실 등 다른 게시판 화면에 상단 고정 기능을 확장하는 작업
- 상단 고정 우선순위, 고정 순서 수동 변경, 예약 고정
- 권한 정책 자체 변경
- 게시글 상세·댓글·첨부·좋아요·북마크 정책 변경
- 서버에 보기 모드(feed/list)를 저장하는 기능

## 권장 접근 방식

기존 API와 DB 계약을 단순히 화면에서만 이름 변경하지 않고, 저장 모델부터 조회 모델까지 `isPinned`/`is_pinned`로 명시적으로 전환한다. 기존 `is_notice`는 마이그레이션으로 제거하거나 호환 기간이 필요한지 계획/사양 단계에서 결정하며, 중요 공지용 필터·색상·요약 계산은 함께 제거한다. 고정 토글은 기존 게시글 수정 API의 최소 payload를 재사용해 별도 신규 엔드포인트를 만들지 않는 방향을 우선 검토한다.

## DB 영향

- `tb_board_post.is_pinned` 신규 컬럼 추가
- 기존 `tb_board_post.is_notice` 제거 여부와 데이터 이관 정책을 계획/사양서에서 확정
- `backend/DATABASE/20260922/` 및 `docs/database/20260922/`에 변경 SQL, 변경 이력, rollback 작성
- DB MCP에서 확인한 현재 계약: `tb_board_post`에 `is_notice CHAR(1) NOT NULL DEFAULT 'N'` 존재, `is_pinned` 미존재

## 검증 기준

- 중요 공지 문구, 필터, 색상, 요약이 화면과 코드에서 제거된다.
- 더보기 메뉴 옆 아이콘으로만 상단 고정/해제가 가능하고, 해당 값이 `Y/N`으로 저장된다.
- 더보기 메뉴에서 상단 고정/해제가 동작하고 실패 시 오류 상태를 유지한다.
- 상단 고정 영역에는 별도 조회한 고정 게시글만 표시된다.
- 목록/상세/API/DB의 필드 계약이 `isPinned`/`is_pinned`로 일치한다.
- 일반 게시글 목록과 상단 고정 게시글 목록이 별도 조회되고, 고정 게시글의 영역 간 중복이 허용된다.
- 일반 게시글이 최초 20건 이후 목록 끝에서 다음 20건씩 누적 조회되는 무한 스크롤로 동작한다.
- 관련 Vitest, 프론트 빌드, 375px·768px·1280px 브라우저 검증과 스크린샷을 결과 문서에 기록한다.
