# 20261013_002 이전 댓글 상태 유지 및 카운트 작업지시서

## 목적

공지사항과 전자결재에서 이전 댓글을 펼친 뒤 댓글 또는 답글을 등록해도 전체 로드 댓글이 계속 표시되도록 한다. 이전 댓글 보기 버튼에는 아직 로드하지 않은 댓글 수를 표시한다.

## 확인 근거

- 전자결재의 댓글 등록 처리에서 `loadComments()`를 인자 없이 호출해 최신 3개 첫 페이지로 댓글 목록과 커서를 덮어쓰는 흐름을 확인했다.
- 공지사항은 서버가 가진 최신 댓글과 화면 로컬 댓글 상태를 조합하므로 등록 후 전체 로드 댓글이 유지되는지 별도 회귀 검증이 필요하다.
- 승인된 동작과 범위는 [설계 문서](../../superpowers/specs/2026-10-13-previous-comments-persistence-design.md)를 따른다.

## 작업 지시

1. 공유 댓글 섹션에 선택적 남은 댓글 수를 입력받아 이전 댓글 버튼에 표시한다. 개수가 없으면 기존 레이블을 유지한다.
2. 공지사항의 댓글/답글 등록 후 이전 페이지까지 펼친 로컬 목록, 커서, `hasPrevious`가 초기화되지 않는지 검증하고 필요한 최소 수정만 한다.
3. 전자결재 댓글/답글 등록은 첫 페이지를 다시 불러와 상태를 초기화하지 않도록 한다. 저장 응답을 현재 전체 로드 댓글에 반영하고 총 개수와 남은 수를 올바르게 유지한다.
4. 두 기능 모두 전체 댓글 수에서 현재 로드 댓글 수를 빼서 아직 불러오지 않은 수를 표시한다. 전자결재 시스템 메시지는 댓글 수에 포함하지 않는다.
5. 기존 댓글 순서, 페이지네이션, 댓글 CRUD 및 오류 처리를 보존한다.
6. 관련 회귀 테스트, 프론트엔드 빌드, 375px/768px/1280px 브라우저 확인을 수행하고 개인정보를 가린 캡처를 결과 문서에 기록한다.

## 완료 조건

- 이전 댓글 펼침 후 댓글/답글 등록 시 공지사항·전자결재 모두 이미 로드된 댓글과 새 댓글이 함께 표시된다.
- 등록 직후 이전 댓글 버튼/페이지 커서가 첫 페이지 상태로 되돌아가지 않는다.
- 버튼에 아직 불러오지 않은 댓글 수가 정확히 표시되고, 새 댓글 등록만으로 그 수가 변하지 않는다.
- 관련 Vitest와 production build가 통과한다.
- 결과와 반응형 브라우저 검증 근거가 날짜별 결과 폴더에 기록된다.

## 범위 제외

- 백엔드/API/DB 변경
- 댓글 정렬·페이지 크기·권한·CRUD 정책 변경
