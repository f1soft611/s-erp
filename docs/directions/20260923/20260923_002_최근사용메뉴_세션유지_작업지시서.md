# 20260923_002 최근사용 메뉴 세션 유지 작업지시서

## 작업 분류

- 대상: 프론트엔드
- 관련 화면: 대시보드/사이드바 메뉴 전체 흐름, `DashboardPage`, `DashboardMenuTree`, `DashboardSidebar`
- 목적: 로그인 세션 동안 사용자가 이동한 메뉴를 유지하고, 최근 사용 메뉴를 좌측 사이드바 하단에 제한적으로 보여주도록 개선한다.
- 범위: 최근 사용 메뉴 히스토리, 세션 기반 저장, 사이드바 UI 노출, 메뉴 클릭 시 복귀 동작, 모듈 사이드바 하단의 사용자 프로필 영역 유지/조정
- 제외 대상: 전체 탭형 네비게이션 도입, 글로벌 페이지 상태 복원, 서버 세션/DB 저장, 보안 정책 변경, 사용자 정보 전체를 메인 영역으로 이동하는 레이아웃 개편

## 작업 목적

ERP 특성상 사용자는 로그인 후 여러 화면을 오가며 작업하는데, 현재 구조는 페이지 진입 시마다 새로 설정되고 상태가 리셋되는 문제를 겪고 있다. 이를 개선하기 위해, 각 로그인 세션 동안 최근에 방문한 메뉴를 유지하고 사이드바 하단에 제한된 개수만 표시해 사용자가 빠르게 복귀할 수 있도록 한다.

또한 기존 사용자 프로필 영역은 메인 네비게이션 영역을 압박하지 않도록 모듈 사이드바 하단에 유지하고, 사이드바 기능성과 메뉴 이동 경험을 우선시한다.

이 방식은 상단 탭형 구조를 도입하지 않고도, 최근 메뉴 히스토리와 모듈 하단 프로필 배치만으로 UX를 보완한다.

## 현재 문제

- `DashboardPage`는 경로 기반으로 현재 모듈/메뉴를 해석하고 상태를 계산한다.
- 페이지를 다시 진입할 때마다 메뉴 선택 상태가 초기화될 수 있어, 사용자가 최근에 작업하던 화면을 다시 떠올리기 어렵다.
- 사이드바 하단에 최근 사용 메뉴가 없어 로그인 세션 내에서 빠른 복귀 경로가 없다.
- 기존 사용자 프로필 영역이 메인 메뉴 영역과 혼재되어 있어, 사이드바 가독성과 작업 집중도가 낮아진다.
- 기존 구조는 전체 페이지 상태를 영구 복원하는 방식이 아니라, 현재 경로와 메뉴 정보를 재계산하는 구조라서 세션 스코프의 히스토리 관리가 필요하다.

## 요구사항

1. 로그인 세션 동안 사용자가 최근에 방문한 메뉴를 기록한다.
2. 최근 메뉴는 사이드바 하단 영역에 최대 5~8개까지만 제한적으로 노출한다.
3. 사용자가 이전에 방문한 메뉴를 클릭하면 해당 화면으로 즉시 이동한다.
4. 동일 메뉴를 다시 방문하면 최근 기록에서 정렬이 갱신된다.
5. 오래된 기록은 자동으로 제거된다.
6. 세션 종료 시 최근 메뉴 기록은 사라진다.
7. 기존 사용자 프로필 영역은 좌측 모듈 사이드바 하단에 유지한다.
8. 프로필 영역은 사진만 우선 노출하고, 이름·이메일 등 텍스트는 최소한만 표시하거나 보조 액션으로 분리한다.
9. 프로필 사진 클릭 시 작은 팝오버/메뉴가 열리고, 항목은 “내 정보”, “보안 설정”, “로그아웃” 등 간단한 계정 액션으로 구성한다.
10. 기본 상태는 사진만 보이도록 유지하고, 텍스트/상세 정보는 클릭 시 또는 보조 메뉴에서만 노출한다.
11. 메뉴 탭 전체를 새로 도입하지 않고, 기존 구조와 경로 기반 라우팅을 유지한다.
12. 최근 메뉴는 화면 상태 전체 복원보다 “빠른 이동 경로”로만 사용한다.
13. 현재 사이드바/메뉴 트리 구조 및 선택 표시 로직을 유지하고, 최근 메뉴 영역과 프로필 영역은 보조 UI로 추가/정렬한다.
14. 구현은 `sessionStorage` 기반으로 수행하고, 필요 시 보관 필드만 최소한으로 설계한다.
15. UI는 모바일/데스크톱 모두에서 자연스럽게 보이고, 사이드바 하단에 과하게 많은 항목이 노출되지 않도록 한다.
16. 기존 프로필 영역은 “프로필 사진만 모듈 바 하단에 위치”하도록 정리한다. 이름, 이메일, 상세 메타 정보는 기본 노출을 최소화하고 필요 시 팝오버/hover 액션으로 처리한다.

## 접근 방식 비교

### 대안 A: 상단 탭형 메뉴 추가

- 장점: 직관적인 브라우징 경험을 제공한다.
- 단점: 전체 화면 레이아웃을 바꾸고, ERP에서 많은 탭이 누적될 수 있으며 기존 사이드바 구조와 충돌 가능성이 높다.
- 판정: 현재 구조를 최소 변경하는 방향으로는 부적합하다.

### 대안 B: 최근 사용 메뉴 히스토리만 사이드바 하단에 유지

- 장점: 현재 구조를 거의 유지하면서 세션 기반 복귀 UX를 확보할 수 있다.
- 장점: 사용자에게는 “최근 작업하던 화면 복귀” 느낌을 주면서 탭 부담을 줄인다.
- 단점: 모든 화면 상태를 복원하는 것은 아니므로, 일부 페이지 내 입력 상태는 그대로 복원되지 않는다.
- 판정: ERP UI에 가장 적합하며, 현재 요구사항과 범위에 부합한다.

### 대안 C: 모든 페이지 상태를 전역 store로 영구 보존

- 장점: 섹션 단위 복원이 가능하다.
- 단점: 복잡도가 높고, Route/상태 동기화 오류가 많아지며 프로젝트 구조를 크게 바꾼다.
- 판정: 이번 작업의 범위를 벗어나므로 채택하지 않는다.

## 구현 범위

- `DashboardPage` 또는 하위 Dashboard 관련 컴포넌트에서 최근 사용 메뉴를 계산하고 보관하는 로직을 추가한다.
- 최근 사용 메뉴를 `sessionStorage`에 저장하고 불러오는 초기화 로직을 구현한다.
- 사이드바 하단에 최근 사용 메뉴 리스트를 표시하는 UI를 추가한다.
- 기존 사용자 프로필 영역을 모듈 사이드바 하단에 유지하도록 레이아웃을 정리한다.
- `onMenuSelect` 흐름과 기존 메뉴 선택 로직을 재사용한다.
- 최근 사용 메뉴는 중복 제거, 정렬 갱신, 개수 제한을 포함한다.
- 메인 메뉴 선택 시 최근 목록에 자동 반영되도록 한다.
- 로그인 세션 중 페이지를 이동해도 마지막 조회 상태와 선택 상태를 유지할 수 있도록, 각 화면은 페이지 수준 상태를 세션 보관한다.
- 공통코드 관리와 같은 관리 화면에서는 검색어, 선택된 그룹/행, 페이지 상태를 `sessionStorage`에서 복원한다.
- F1-Grid 자체는 수정하지 않고, 화면 state만 저장·복원하는 구조를 사용한다.
- 세션 종료 후 기록이 없어지는 동작을 검증한다.
- 관련 테스트 및 빌드 검증을 수행한다.

## 연계 요구사항: 페이지 상태 복원 패턴

다음 패턴은 최근 사용 메뉴와 함께 기본 정책으로 적용한다.

- 화면 위치는 URL 기반으로 복원한다.
- 조회 조건과 선택 상태는 화면 단위의 `sessionStorage`로 보존한다.
- 저장 값은 페이지 별 key로 분리한다.
- 예시: 공통코드 관리 페이지에는 검색어, 선택 그룹, 선택 행, 페이지 상태를 저장한다.
- F1-Grid 내부 상태를 직접 건드리지 않고, 화면이 필요한 값만 주입해 복원한다.
- 저장 범위는 로그인 세션 동안으로 제한하고, 세션 종료 시 초기화한다.
- 최근 사용 메뉴와 기타 페이지 상태 복원은 공통 훅으로 재사용할 수 있어야 한다.
- 공통 훅의 역할은 “페이지별 상태를 세션 스토리지에 저장/복원”하는 것으로 제한한다.
- 대시보드/공통코드/다른 관리 페이지는 동일한 훅 또는 동일한 패턴을 재사용해 구현한다.

이 정책은 최근 사용 메뉴와 같은 보조 UX와 조회 상태 복원을 동일한 사용자 흐름으로 묶어 관리한다.

## 제외 범위

- 상단 탭 네비게이션 도입
- 전체 페이지 상태 영구 복원
- 서버 DB 기반 최근 메뉴 저장
- 사용자별 수정 가능한 즐겨찾기 관리 대형 기능 추가
- 라우트 파라미터/모달 전체 복구 로직 변경

## 완료 기준

- 로그인 세션 동안 사용자가 페이지를 이동해도 최근 메뉴 히스토리가 유지된다.
- 사이드바 하단에서 최근 사용 메뉴를 확인할 수 있다.
- 기존 사용자 프로필 영역은 모듈 사이드바 하단에 유지되며, 간결한 사진 중심 배치로 정리된다.
- 최근 메뉴를 클릭하면 해당 메뉴로 이동한다.
- 중복 메뉴는 하나만 유지되고 최신 사용 시점이 갱신된다.
- 최근 메뉴 개수 제한 규칙이 적용된다.
- 기존 사이드바/모듈 선택 구조와 라우팅 동작을 유지한다.
- 빌드 및 관련 테스트가 통과하며, 결과 문서와 검증 로그가 작성된다.

## 승인 게이트

작업지시서 작성 완료. 사용자가 목표와 범위를 승인하기 전에는 계획서·상세 사양서 작성, 코드 수정, 테스트·빌드·브라우저 검증을 수행하지 않는다.
