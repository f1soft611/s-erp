# 20260923_003 공지사항 전체 우측 오버레이 상세 패널 작업지시서

## 작업 분류

- 경로: `bounded`
- 대상: 프론트엔드
- 관련 화면: `/groupware/community/notice`
- 연계 화면: 향후 게시판·자료실·그룹웨어 공통 상세 패널
- 선행 작업: `20260923_001_공지사항_리스트_상단고정_우측상세패널`

## 작업 목적

현재 상세 패널은 `ContentSplitLayout`의 우측 컬럼 안에 표시되어 목록과 동일한 콘텐츠 영역을 나눈다. 이를 페이지 전체 높이를 사용하는 우측 오버레이 패널로 변경한다. 사용자가 목록을 유지하면서도 화면 오른쪽의 넓은 영역에서 게시글 전체 내용을 확인할 수 있도록 하며, 에디터 본문과 첨부·댓글 등 콘텐츠가 많은 그룹웨어 화면에도 재사용할 수 있는 공통 패널 기반을 마련한다.

## 현재 문제

- 데스크톱 상세가 좌측 목록과 우측 컬럼으로 분할되어 상세 폭과 높이가 제한된다.
- 콘텐츠가 긴 게시글에서는 본문·첨부·댓글을 충분히 넓게 보기 어렵다.
- 페이지 전체 오른쪽 영역을 덮는 오버레이가 아니므로 목록과 상세의 시각적 우선순위가 분명하지 않다.

## 요구사항

1. 리스트형 또는 상단 고정 게시글을 선택하면 상세 패널이 페이지 오른쪽에서 열린다.
2. 상세 패널은 페이지 전체 높이를 사용하고, 우측의 넓은 영역을 덮는다.
3. 상세 패널이 열려 있어도 기존 목록은 배경에 유지한다.
4. 데스크톱 상세 패널 폭은 고정 협소 폭이 아니라 `min(960px, 72vw)` 수준의 넓은 유동 폭으로 구성한다.
5. 상세 패널 내부는 게시글 본문·에디터 HTML·첨부·댓글을 위한 독립 세로 스크롤을 사용한다.
6. 패널 우상단의 닫기 버튼으로 패널을 닫을 수 있다.
7. 패널 외부 백드롭 클릭과 `Escape` 키로 닫을 수 있다.
8. 다른 게시글을 선택하면 열린 패널 내부의 상세 대상만 교체한다.
9. 모바일에서는 패널이 뷰포트 전체 너비를 사용하고 전체 높이를 유지한다.
10. 상세 패널 내부의 기존 피드 게시글 전체 기능은 유지한다.
11. 패널은 특정 공지 API에 직접 의존하지 않는 공통 UI로 유지하고, 공지사항은 기존 데이터·액션 어댑터를 사용한다.
12. 375px, 768px, 1280px에서 본문·댓글·첨부가 겹치거나 잘리지 않고 페이지 가로 스크롤이 발생하지 않는다.

## 접근 방식 비교

### 대안 A: 기존 `ContentSplitLayout`의 우측 컬럼 확대

- 장점: 현재 구조를 거의 유지한다.
- 단점: 페이지 전체 높이를 덮지 못하고, 헤더·목록과 같은 레이아웃 제약을 계속 받는다.
- 판정: 사용자가 요청한 전체 우측 영역 오버레이를 충족하지 못해 채택하지 않는다.

### 대안 B: 공통 MUI Drawer 기반의 우측 오버레이

- 장점: 페이지 전체 높이, 백드롭, Escape 닫기, 독립 스크롤을 기본 제공한다.
- 장점: 공지사항·게시판·자료실·그룹웨어가 같은 패널 프레임을 재사용할 수 있다.
- 장점: 폭을 뷰포트 기준으로 유동 제어할 수 있다.
- 판정: 현재 MUI 구조와 요구사항에 가장 부합하므로 채택한다.

### 대안 C: 앱 셸 내부에 고정 `position: fixed` 패널 직접 구현

- 장점: 시각적 제어가 세밀하다.
- 단점: 포커스 관리, Escape, 백드롭, 스크롤 잠금, z-index 충돌을 직접 관리해야 한다.
- 판정: Drawer의 기존 접근성·상호작용 계약을 활용할 수 있어 우선 채택하지 않는다.

## 구현 범위

- `PostDetailPanel`을 전체 높이·넓은 폭·독립 스크롤을 지원하는 공통 패널 콘텐츠 프레임으로 조정한다.
- `CommunityNoticePage`에서 데스크톱도 `Drawer` 기반 우측 오버레이를 사용하도록 변경한다.
- 기존 `ContentSplitLayout` 우측 컬럼의 상세 렌더링을 제거하고, 선택이 없을 때만 요약 패널을 유지한다.
- Drawer 폭, 전체 높이, 백드롭, Escape 닫기, 목록 유지, 대상 교체를 구현한다.
- 모바일과 데스크톱 모두 동일한 상세 패널 콘텐츠와 액션을 사용한다.
- 오버레이 레이아웃 회귀 테스트와 375px·768px·1280px 브라우저 검증을 추가한다.
- 결과 문서와 스크린샷을 갱신한다.

## 제외 범위

- 게시판·자료실·그룹웨어 화면에 실제 적용하는 작업
- 게시글 상세 기능, API, DB, 권한 정책 변경
- 전체 앱 헤더·사이드바 구조 개편
- 새로운 탭 네비게이션 도입
- 게시글 데이터 모델 변경

## 완료 기준

- 데스크톱에서 상세 패널이 페이지 전체 높이의 우측 오버레이로 열린다.
- 상세 패널 폭이 기존 우측 컬럼보다 충분히 넓고 긴 본문을 읽기 쉽다.
- 목록은 배경에 유지되고 패널 내부만 독립 스크롤된다.
- X, 백드롭, Escape로 패널을 닫을 수 있다.
- 다른 게시글 선택 시 패널 대상이 교체된다.
- 모바일에서 전체 너비·전체 높이로 표시된다.
- 기존 게시글 전체 기능이 회귀하지 않는다.
- 375px·768px·1280px 브라우저 검증과 결과 문서가 남는다.
