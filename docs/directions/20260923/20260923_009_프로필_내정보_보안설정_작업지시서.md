# 20260923_009 프로필 내 정보 관리·보안 설정 작업지시서

## 작업 분류

- 대상: 프론트엔드 + 백엔드
- 경로 분류: architectural
- 관련 화면: 대시보드 프로필 팝오버, 내 정보 관리, 보안 설정
- 목적: 프로필 팝오버의 기존 액션을 실제 사용자 설정 화면으로 연결하고, 본인의 이메일·프로필 이미지·도장 이미지와 비밀번호를 안전하게 변경할 수 있도록 한다.

## 작업 배경

현재 대시보드 프로필 팝오버에는 `내 정보 관리`와 `보안 설정` 메뉴가 표시되지만 두 액션 모두 대시보드로 이동한다. 로그인 사용자 조회에는 이메일과 프로필 이미지가 연결되어 있고, 데이터베이스에는 `tb_user.email_addr`, `tb_login_account.profile_image`, `tb_login_account.stamp_image`, `tb_login_account.password_changed_at` 컬럼이 이미 존재한다.

읽기 전용 PostgreSQL 확인 결과 이번 기능에 필요한 저장 컬럼이 이미 있으므로 신규 테이블·컬럼·FK 마이그레이션은 발생하지 않는다. 이미지는 기존 TEXT 컬럼을 재사용하되 브라우저와 서버에서 작은 크기로 정규화하여 저장한다.

## 확정 요구사항

### 1. 내 정보 관리

- 프로필 팝오버의 `내 정보 관리` 클릭 시 독립된 내 정보 관리 페이지로 이동한다.
- 현재 로그인 사용자의 이름, 아이디, 부서, 직급은 조회 전용으로 표시한다.
- 이메일은 수정할 수 있고 저장 시 현재 사용자 본인 계정에만 반영한다.
- 프로필 이미지를 등록·교체·삭제할 수 있다.
- 도장 이미지를 등록·교체·삭제할 수 있다.
- 업로드 허용 형식은 PNG/JPEG이다.
- 이미지 최대 크기는 512x512 픽셀, 업로드 원본 최대 용량은 1MB로 제한한다.
- 저장 전 이미지를 512x512 이내로 리사이즈하고 기존 `tb_login_account.profile_image`, `tb_login_account.stamp_image` TEXT 컬럼에 저장한다.
- 이미지와 이메일 저장 성공 후 프로필 팝오버와 관련 사용자 상태가 최신 값으로 갱신된다.

### 2. 보안 설정

- 프로필 팝오버의 `보안 설정` 클릭 시 독립된 보안 설정 페이지로 이동한다.
- 입력 항목은 현재 비밀번호, 변경 비밀번호, 변경 비밀번호 확인이다.
- 현재 비밀번호가 일치하지 않으면 변경하지 않는다.
- 변경 비밀번호와 확인 값이 일치하지 않으면 변경하지 않는다.
- 기존 비밀번호 해시 검증과 현재 프로젝트의 비밀번호 정책을 서버에서 적용한다.
- 비밀번호는 평문으로 저장하거나 응답하지 않고 기존 해시 방식으로 갱신한다.
- 변경 성공 시 현재 access/refresh token과 세션을 폐기하고 로그인 화면으로 이동한다.

## 권장 구현 방향

### 저장 방식 대안 비교

1. 기존 계정 컬럼 재사용
   - `tb_user.email_addr`와 `tb_login_account`의 기존 이미지 TEXT 컬럼을 사용한다.
   - 기존 로그인·내 메뉴 프로필 계약을 확장하기 쉬우며 DB 변경이 없다.
   - 이미지가 작다는 전제에서 이번 요구사항에 가장 작은 변경 범위다.
2. 별도 파일 테이블 또는 객체 저장소 사용
   - 파일 메타데이터와 객체 수명주기를 분리할 수 있다.
   - 현재 요구사항보다 저장 계층·권한·삭제 정책의 범위가 커지고, 기존 프로필 컬럼과의 호환 처리가 필요하다.

이번 작업은 1번을 채택한다. 이미지 정규화와 서버 용량 검증으로 TEXT 컬럼의 저장 크기를 제한한다.

## API 범위

- 인증된 본인 프로필 조회/수정 API를 추가하거나 기존 사용자 서비스 패턴에 맞춰 구성한다.
- 이메일과 이미지 수정 요청은 인증 주체의 사용자 ID/로그인 ID를 서버에서 결정하고 클라이언트가 임의의 대상 ID를 지정하지 못하게 한다.
- 비밀번호 변경 API는 현재 비밀번호 검증 후 변경 비밀번호 해시를 저장하고, 성공 시 토큰 무효화 또는 재로그인 가능한 응답을 제공한다.
- 기존 `GET /api/v1/menus/my` 응답의 `email`, `profileImage` 등 프로필 표시 계약은 유지하고 저장 후 최신 값이 반환되도록 한다.
- 실패 응답은 기존 인증·검증 오류 envelope와 상태 코드 규칙을 따른다.

## 프론트엔드 범위

- 프로필 팝오버 액션의 라우팅을 실제 두 페이지로 연결한다.
- 기존 대시보드 콘텐츠·라우팅 패턴과 MUI 컴포넌트 스타일을 재사용한다.
- 폼 검증, 저장 중 상태, 성공/실패 메시지, 이미지 미리보기와 삭제 상태를 제공한다.
- 최소 375px, 768px, 1280px 뷰포트에서 입력 영역·버튼·이미지 미리보기의 겹침과 가로 넘침을 확인한다.

## 백엔드 범위

- 본인 프로필 조회·이메일/이미지 수정 서비스와 매퍼를 기존 계층 구조에 추가한다.
- 이미지 MIME 타입, 원본 크기, 디코딩 가능 여부, 픽셀 제한을 서버에서도 검증한다.
- 비밀번호 변경은 기존 비밀번호 암호화·검증 유틸리티와 계정 테이블을 사용한다.
- 인증 주체와 요청 대상이 일치하는지 검증하고, 다른 사용자의 프로필·비밀번호 수정은 허용하지 않는다.
- 이번 작업에서는 스키마 변경이 없으므로 SQL 마이그레이션·롤백 파일은 작성하지 않는다. 기존 컬럼 재사용 근거와 영향 검토는 계획서/결과 문서에 기록한다.

## 테스트 및 검증 범위

- 프로필 팝오버에서 두 메뉴가 각각 올바른 페이지로 이동하는지 검증한다.
- 이메일 저장, 이미지 등록·교체·삭제, 잘못된 이미지 형식·크기 검증을 테스트한다.
- 비밀번호 현재 값 불일치, 확인 값 불일치, 성공 후 로그아웃을 테스트한다.
- 본인 외 대상 수정 차단과 기존 `menus/my` 프로필 값 갱신을 검증한다.
- 프론트 관련 Vitest와 build, 백엔드 Maven 테스트를 실행한다.
- UI 변경 결과를 375px/768px/1280px 브라우저 캡처로 남긴다.

## 제외 범위

- 프로필 이미지·도장 이미지용 신규 DB 테이블, 신규 컬럼, 외부 객체 저장소 도입
- 이름·아이디·부서·직급 변경
- 관리자에 의한 타 사용자 프로필 일괄 수정
- 비밀번호 찾기, 이메일 인증, 다중 인증, 비밀번호 정책 자체 변경
- 프로필 팝오버의 기존 표시 정보와 무관한 대시보드 리팩터링

## 완료 기준

- 프로필 팝오버의 두 액션이 각각 실제 페이지로 이동한다.
- 본인 이메일과 프로필/도장 이미지를 저장·수정·삭제할 수 있다.
- 이미지 제한이 클라이언트와 서버 양쪽에서 적용되고 기존 TEXT 컬럼에 작은 데이터로 저장된다.
- 현재 비밀번호 검증을 통과한 경우에만 새 비밀번호가 저장된다.
- 비밀번호 변경 성공 후 세션/토큰이 폐기되고 로그인 화면으로 이동한다.
- 기존 프로필 표시와 `menus/my` 계약이 회귀하지 않는다.
- 관련 테스트·빌드·브라우저 캡처와 결과 문서가 남는다.

## 승인 게이트

작업지시서 작성 완료. 사용자가 목표와 범위를 승인하기 전에는 계획서·상세 사양서 작성, 코드 수정, 테스트·빌드·브라우저 검증을 수행하지 않는다.
