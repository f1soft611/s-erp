# 20260923_001 공지사항 리스트·상단고정 우측 상세 패널 작업지시서

## 작업 분류

공통화 방향: 게시판·자료실 등에서 재사용 가능한 게시글 상세 패널 UI
이번 적용: 공지사항 데이터·액션 어댑터 연결

- 대상: 프론트엔드
- 관련 화면: `/groupware/community/notice`
  공지사항을 리스트형으로 보거나 상단 고정 영역에서 선택했을 때, 피드형 게시글 카드 하나와 동일한 형태와 기능을 화면 오른쪽 상세 패널에서 제공한다. 목록을 유지한 채 본문, 첨부, 댓글, 반응, 게시글 관리 기능을 모두 사용할 수 있도록 한다. 첨부 예시처럼 데스크톱에서는 우측 상세 패널을 사용하고, 모바일에서는 전체 화면 드로어/모달로 전환한다. 상세 패널 UI는 향후 게시판·자료실에서도 데이터와 액션 어댑터만 교체해 사용할 수 있도록 설계한다.
- 제외 대상: 피드형 카드의 기존 인라인 상세 동작

## 작업 목적

공지사항을 리스트형으로 보거나 상단 고정 영역에서 선택했을 때, 목록을 유지한 채 화면 오른쪽 상세 영역에서 게시글 본문과 기존 상호작용을 확인할 수 있도록 한다. 첨부 예시처럼 데스크톱에서는 우측 상세 패널을 사용하고, 모바일에서는 전체 화면 상세 드로어/모달로 전환한다.

## 현재 문제

- 현재 공지 상세는 `expandedNoticeId`를 기준으로 피드 카드 내부에서 본문을 확장하는 구조이며, 피드 카드가 게시글의 전체 기능을 보유한다.
- `ContentSplitLayout`의 우측 슬롯은 공지 요약 패널로 사용되고 있어, 리스트형 및 상단 고정 항목을 선택해도 게시글 상세를 우측에서 확인할 수 없다.
- 리스트형 공지와 상단 고정 항목에는 공통 선택 콜백이 연결되어 있지 않다.
- 상세 패널에서 피드 카드의 전체 기능과 게시글 본인 전용 관리 메뉴를 재사용할 수 있는 공통 추상화가 없다.

## 요구사항

1. 리스트형 보기에서 공지 항목을 클릭하면 해당 공지를 선택하고 우측 상세 패널을 연다.
2. 상단 고정 공지 항목을 클릭하면 동일한 우측 상세 패널을 연다.
3. 다른 공지를 클릭하면 기존 패널의 상세 대상이 새 공지로 교체된다.
4. 우측 상세 패널 우상단의 닫기 버튼을 누르면 선택을 해제하고 기존 요약 패널 또는 빈 상태를 표시한다.
5. 데스크톱에서는 기존 `ContentSplitLayout`의 우측 슬롯을 사용해 페이지 우측 영역을 상세 패널로 표시한다.
6. 모바일에서는 상세를 전체 화면 드로어 또는 모달 형태로 표시하고, 닫기 동작을 제공한다.
7. 상세를 열 때 기존 공지 상세 조회 API와 서버 응답 병합·조회수 갱신 흐름을 재사용한다.
8. 상세 패널은 피드형 게시글 카드 하나의 표시 구조를 그대로 사용하며, 본문 이미지, 첨부파일 다운로드, 좋아요, 북마크, 댓글·답글, 댓글 수정·삭제, 게시글 관리 기능을 모두 제공한다.
9. 현재 로그인 사용자가 게시글 작성자인 경우에만 상세 패널의 게시글 더보기 메뉴를 노출하고, 수정·삭제 등 기존 메뉴 동작을 제공한다.
10. 현재 로그인 사용자가 작성자가 아닌 게시글에는 게시글 수정·삭제 메뉴를 노출하지 않는다. 댓글의 기존 작성자별 수정·삭제 권한은 유지한다.
11. 상세 패널은 공통 UI와 명시적인 데이터·액션 어댑터 경계를 갖도록 구성하고, 이번 작업에서는 공지사항 어댑터만 연결한다.
12. 리스트형 및 상단 고정 항목의 선택 상태는 시각적으로 구분하되 기존 목록 스타일과 접근성을 유지한다.
13. 피드형 보기의 기존 인라인 확장·댓글·첨부·조회수 동작은 이번 작업에서 변경하지 않는다.
14. 목록 로딩, 오류, 상세 로딩 실패 시 기존 화면의 오류 처리와 목록 표시를 유지한다.
15. 375px, 768px, 1280px 뷰포트에서 텍스트 잘림·겹침·가로 스크롤 없이 동작한다.

## 접근 방식 비교

### 대안 A: 리스트 항목마다 상세를 인라인 확장

- 장점: 새 패널 컴포넌트가 거의 필요 없다.
- 단점: 첨부 예시처럼 목록과 상세를 동시에 유지하기 어렵고, 긴 상세 콘텐츠가 목록을 밀어 사용성이 떨어진다.
- 판정: 우측 상세 요구와 맞지 않아 채택하지 않는다.

### 대안 B: 피드 카드 렌더링을 공통 상세 패널로 추출하고 우측 슬롯에 렌더링

- 장점: 현재 레이아웃과 상세 조회 API를 재사용하고, 목록과 상세를 동시에 보여줄 수 있다.
- 장점: 데스크톱·모바일 분기와 닫기/대상 교체를 명확히 구현할 수 있다.
- 단점: 기존 `NoticeFeedList`의 상세 렌더링 책임을 선택 상세 컴포넌트로 분리하거나 재사용 가능한 렌더 영역으로 정리해야 한다.
- 판정: 첨부 예시, 전체 기능 유지, 향후 공통 사용 요구에 가장 부합하므로 채택한다.

### 대안 C: 별도 라우트로 상세 페이지 이동

- 장점: 상세 화면의 독립성이 높다.
- 단점: 목록과 상세 동시 표시 요구를 충족하지 못하고, 현재 페이지의 조회·댓글 상태 재사용 비용이 커진다.
- 판정: 이번 요구 범위에서는 채택하지 않는다.

## 구현 범위

- `CommunityNoticePage`에 리스트/상단 고정 선택 상태와 선택·해제·상세 조회 흐름을 추가한다.
- `ListView`와 `PinnedItemsPanel`에 선택 콜백 및 접근 가능한 클릭 동작을 연결한다.
- 게시글 상세 패널과 피드 게시글 본체를 재사용 가능한 공통 컴포넌트/계약으로 분리한다.
- 공지사항용 데이터·액션 어댑터를 연결하고, 게시글 작성자 여부에 따라 더보기 메뉴를 제어한다.
- 기존 상세 API, 공지 데이터 타입, 댓글·첨부·이미지·액션 콜백을 재사용한다.
- 데스크톱은 우측 슬롯, 모바일은 전체 화면 드로어/모달로 표시한다.
- 공지 관련 Vitest 회귀 테스트와 브라우저 검증을 추가한다.
- 결과 문서와 375px·768px·1280px 스크린샷을 작성한다.

## 제외 범위

- 백엔드 API, DB 스키마, 권한 정책 변경
- 피드형 카드의 인라인 상세 UX 변경
- 게시글 상세 URL 라우팅 추가
- 게시글 데이터 모델 및 댓글·첨부 API 계약 변경
- 이번 작업에서 게시판·자료실 화면 자체에 상세 패널을 적용하는 작업
- 패널 너비·디자인의 전역 레이아웃 개편

## 완료 기준

- 리스트형 공지 클릭 시 우측 상세 패널이 열린다.
- 상단 고정 공지 클릭 시 우측 상세 패널이 열린다.
- 다른 공지 클릭 시 상세 대상이 교체된다.
- 닫기 버튼으로 상세 패널을 닫을 수 있다.
- 모바일에서 전체 화면 상세로 전환되고 닫을 수 있다.
- 상세 패널의 표시 형태와 기능이 피드형 게시글 카드와 동일하다.
- 상세 조회 응답의 본문·조회수·첨부·댓글이 패널에 표시된다.
- 작성자 본인 글에서만 더보기 메뉴가 표시되고 수정·삭제가 동작한다.
- 비작성자 글에는 게시글 수정·삭제 메뉴가 표시되지 않는다.
- 공통 상세 패널이 공지사항 어댑터를 통해 동작하고 향후 다른 게시판 어댑터를 연결할 수 있는 구조다.
- 기존 좋아요·북마크·댓글·첨부 동작이 유지된다.
- 피드형 기존 동작이 회귀하지 않는다.
- 관련 테스트, 프론트 빌드, 데스크톱·모바일 브라우저 검증 및 결과 문서가 남는다.

## 승인 게이트

작업지시서 작성 완료. 사용자가 목표와 범위를 승인하기 전에는 계획서·상세 사양서 작성, 코드 수정, 테스트·빌드·브라우저 검증을 수행하지 않는다.
