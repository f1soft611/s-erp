# 20260923_007 공통 검색바 상세 검색 및 공통코드 적용 작업지시서

## 작업 분류

- 경로: `bounded`
- 대상: 프론트엔드 + 백엔드 API
- 대표 화면: 공통코드 관리
- 작업 유형: 공통 검색 UI 개선 및 공통코드 그룹 조회 조건 연동
- 선행 작업: 공통 검색 영역(PageSearchArea), F1-Grid/F1-Tree 컬럼 계약 확인

## 작업 목적

페이지별 공통 검색바를 기본 한 줄 검색과 상세 검색 오버레이 구조로 개선한다. 상세 검색은 검색 영역의 높이를 확장하지 않고 화면 위에 오버레이로 표시하며, 기준이 되는 F1-Grid 또는 F1-Tree 컬럼 옵션을 이용해 검색 필드를 동적으로 생성한다. 대표 적용 화면은 공통코드 관리의 그룹 목록으로 한정하고, 검색 실행 시 백엔드 조회 API가 실제 조건을 적용하도록 연결한다.

## 확정 요구사항

1. 검색바는 기본 상태에서 한 줄로 표시한다.
2. 기본 상태에서는 페이지의 기본 검색 필드를 표시한다.
3. 검색바 우측 끝의 토글 버튼으로 상세 검색 오버레이를 연다.
4. 상세 검색은 기존 콘텐츠 영역을 아래로 밀지 않고 검색 영역 위에 겹쳐 표시한다.
5. 상세 검색 필드는 기준 F1-Grid/F1-Tree 컬럼 중 검색 가능한 컬럼 옵션을 이용해 동적으로 생성한다.
6. 컬럼 타입에 따라 필드 컨트롤을 생성한다.
   - `text` 또는 타입 미지정: 텍스트 입력

- `number`, `decimal`, `currency`: 숫자 입력
- `date`: 시작일(`from`)과 종료일(`to`) 두 입력으로 생성하는 날짜 범위 검색
- `select`: 선택 입력
- `checkbox`: 사용 여부 등 선택 입력
- 검색에 적합하지 않은 `rownumber`, `code`, 편집용 컬럼은 대표 화면에서 제외하거나 어댑터가 명시적으로 제외한다.
- 날짜 범위는 시작일만 입력하면 해당 일자 이후, 종료일만 입력하면 해당 일자 이전, 양쪽 입력 시 구간 조건으로 검색한다.

7. 검색 필드 옵션은 폼모달의 `form` 옵션과 대칭적인 검색 전용 `search` 옵션으로 제공한다.

- `search.hidden`, `search.label`, `search.group`, `search.order`를 지원한다.

- `search.span: 1`: 기본 1열
- `search.span: 2`: 2열 너비
- `search.span: 3`: 상세 검색 필드 영역 전체 너비
  - `search.span: 4`: 데스크톱 상세 검색 필드 영역 4열 너비
  - `search.span: 5`: 데스크톱 상세 검색 필드 영역 5열 너비
- 옵션이 없으면 `search.span: 1`을 적용한다.

8. 상세 검색 오버레이 우측 하단에 검색 닫기 버튼과 검색 실행 버튼을 제공한다.
9. 검색 닫기는 조회를 실행하지 않고 오버레이만 닫는다.
10. 검색 실행은 조건을 확정하고 공통코드 그룹 조회 API를 호출한다.
11. 대표 적용 범위는 공통코드 관리의 공통코드 그룹 목록으로 한다.
12. 기본 검색 대상과 상세 검색 대상은 공통코드 그룹 목록으로 한다. 상세 코드 목록은 이번 작업에서 제외한다.
13. 공통코드 그룹 조회 API는 tenant 조건을 유지하면서 전달된 검색 조건을 적용한다.

## 검색 API 계약

대상 API:

- `GET /api/v1/co/master/common-code/groups`

선택적 조회 파라미터:

- `keyword`: 기본 검색 입력값. 값이 있으면 `group_code`, `group_nm`, `group_dc` 중 하나라도 부분 일치하는 그룹을 조회한다.
- `groupCode`: 상세 검색의 그룹코드 조건
- `groupNm`: 상세 검색의 그룹명 조건
- `groupDc`: 상세 검색의 그룹 설명 조건

상세 조건은 입력된 조건만 적용하며, 여러 조건이 동시에 입력되면 `AND`로 결합한다. 빈 문자열은 미입력으로 처리한다. tenant 조건과 기존 정렬 순서는 유지한다. 기존 파라미터 없이 호출하는 동작은 전체 그룹 조회로 유지한다.

## 구현 범위

### 프론트엔드

- `frontend/src/shared/components/PageSearchArea.tsx`
  - 기본 한 줄 레이아웃과 우측 상세 검색 토글 유지
  - 화면을 덮는 상세 검색 오버레이 표시
  - 상세 검색 닫기/검색 실행 이벤트와 접근성 상태 제공
  - 컬럼 메타데이터와 페이지별 어댑터를 받을 수 있는 공통 타입 정의
  - 375px, 768px, 1280px에서 오버레이 폭, 버튼, 필드가 겹치지 않도록 반응형 처리
- 공통 검색 필드 생성에 필요한 shared 타입/유틸리티
  - F1 컬럼의 `type`, `headerName`, `field`, `options`를 검색 필드 정의로 변환
  - F1 컬럼의 `search.hidden/label/group/order/span`을 검색 필드 정의로 변환
  - 타입 미지정 컬럼은 text로 처리
  - `date` 컬럼은 `from`/`to` 쌍의 검색 상태와 컨트롤로 변환
  - 검색에서 제외할 컬럼을 어댑터에서 지정 가능하게 처리
- `frontend/src/pages/co/master/common-code/CommonCodeManagementPage.tsx`
  - 기존 그룹 검색 상태를 기본 검색 및 상세 검색 상태와 연결
  - 검색 실행 시 그룹 조회 서비스 호출
  - 미저장 변경사항 확인 흐름과 검색 재조회 흐름을 충돌 없이 유지
- `frontend/src/pages/co/master/common-code/components/CommonCodeManagementPanel.tsx`
  - 그룹 컬럼 정의를 검색 필드 생성 기준으로 재사용하거나 페이지 어댑터에 전달
- `frontend/src/pages/co/master/common-code/services/commonCodeManagement.service.ts`
  - 그룹 조회 서비스가 기본/상세 검색 조건을 API query parameter로 전달
- 관련 프론트 테스트
  - 기본 검색 필드 표시
  - 상세 오버레이 열기/닫기
  - 컬럼 타입별 검색 컨트롤 생성
  - 검색 실행 시 조건 전달
  - 모바일/데스크톱 레이아웃 회귀 검증

### 백엔드

- `CommonCodeGroupApiController`
  - 그룹 조회 GET 요청에서 선택적 검색 파라미터를 수신
- `CommonCodeGroupService` 및 구현체
  - tenant ID와 검색 조건을 DAO에 전달
- `CommonCodeGroupDAO`
  - 검색 조건을 매퍼에 전달
- `CommonCodeGroup_SQL_postgresql.xml`
  - `keyword`의 그룹 코드/명/설명 부분 일치 조건
  - 입력된 상세 조건의 AND 조건
  - 빈 값 미적용
  - 기존 tenant 조건과 정렬 유지
- 관련 백엔드 테스트
  - 파라미터 없는 전체 조회
  - 기본 keyword 검색
  - 개별 상세 조건 검색
  - 복수 상세 조건 AND 검색
  - tenant 조건 유지

## DB 영향 검토

- 신규 테이블/컬럼/FK/기본값 변경 없음
- 기존 `tb_common_code_group` 컬럼을 조회 조건으로만 사용한다.
- 확인된 대상 컬럼: `group_code`, `group_nm`, `group_dc`, `tenant_id`
- PostgreSQL 읽기 전용 MCP로 `tb_common_code_group` 테이블과 컬럼 계약을 확인했다.
- 날짜별 DB 스크립트, 롤백 스크립트, 스키마 변경 문서는 해당 없음

## 완료 기준

- 기본 검색바가 한 줄로 표시되고 기본 검색 필드가 보인다.
- 토글 시 검색 영역 높이가 늘어나지 않고 상세 오버레이가 표시된다.
- 공통코드 그룹 컬럼 기준으로 text 타입 검색 필드가 동적으로 생성된다.
- 상세 오버레이에서 검색 닫기와 검색 실행이 각각 동작한다.
- 검색 실행 시 실제 그룹 조회 API가 호출되고 검색 조건이 서버에 반영된다.
- 기존 tenant 필터, 정렬, 저장하지 않은 변경사항 보호 흐름이 유지된다.
- 관련 프론트/백엔드 테스트와 빌드가 통과한다.
- 375px, 768px, 1280px 브라우저에서 오버레이와 컨트롤이 잘리지 않거나 겹치지 않는다.
- 결과 문서와 브라우저 스크린샷을 `docs/result/20260923/common-searchbar-detail-search/`에 기록한다.
