# 회사정보와 거래명세서 작업지시서

## 사용자 요구와 승인

- 기준정보 관리 아래 회사정보 관리 메뉴를 추가해 거래명세서의 공급자 정보를 관리한다.
- 출하 건을 바탕으로 거래명세서 등록, 현황 및 거래명세표 인쇄를 제공한다. 수주출하와 직출하를 모두 지원한다.
- 승인된 기본 범위는 출하 1건당 거래명세서 1건이며, 여러 출하 합산과 출하 없는 별도 명세서 입력은 포함하지 않는다.
- 명세서에는 저장 당시의 공급자, 거래처, 출하 품목과 금액을 보존하여 이후 마스터 변경이 과거 출력에 반영되지 않게 한다.
- 화면 구조, 버튼 위치, 현황 번호 클릭 상세와 F1Grid는 기존 출하등록·출하현황을 기준으로 한다.

## 실행 순서

1. 이 작업지시서에 이어 계획서와 상세사양서를 작성한다.
2. 기본 `s-erp-postgresql-readonly` MCP로 목록과 관련 테이블 구조를 확인한다.
3. 회귀 테스트를 먼저 작성하고 회사정보, 명세서 API, 데이터 및 메뉴 스크립트와 화면을 구현한다.
4. SQL을 실제 DB에 적용하지 않는다. 스키마 이력, 롤백, 누적 스키마를 함께 작성한다.
5. 관련 테스트, Java 8 API 호환성, 빌드, 린트, 브라우저 및 인쇄 화면을 확인하고 결과와 스크린샷을 기록한다.

## DB 확인

기본 MCP의 `list_tables`와 `describe_table`로 `tb_tenant`, `tb_customer_info`, `tb_material_info`, `tb_sales_delivery_hd`, `tb_sales_delivery_dt`, `tb_menu` 구조를 확인했다. `tb_tenant`에는 회사명·사업자번호·업태·업종이 있지만 대표자·사업장 주소는 없다. 명세서 테이블은 목록에서 확인되지 않았다. 업무 행은 조회하지 않았다.
