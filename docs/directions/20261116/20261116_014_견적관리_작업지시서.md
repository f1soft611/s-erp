# 견적관리 화면 추가 작업지시서

## 목적 및 범위

- 영업관리 > 견적관리 메뉴에 `견적서작성`과 `견적현황` 화면을 추가한다.
- 화면 구성과 사용자 흐름은 기존 수주등록·수주현황을 우선 기준으로 삼고, 구형 화면의 업무 참고 자료로 WSA305(견적서 작성), WSA306(견적현황)을 확인한다.
- 견적 품목은 품목 마스터에서 선택하거나 직접 입력할 수 있다. 품목 마스터 선택은 필수가 아니며, 직접 입력한 품목은 해당 견적 상세 행에만 저장하고 품목 마스터를 생성·변경하지 않는다.
- 수주등록에서 관련 견적번호를 선택할 수 있도록 연계하되, 견적번호 입력은 필수가 아니다.
- 견적서작성·견적현황을 영업관리 메뉴에서 사용할 수 있도록 견적관리 메뉴 seed와 롤백 스크립트를 추가한다. 테넌트 메뉴·권한 데이터는 임의 조회·적용하지 않고 승인된 테넌트 ID를 스크립트에 명시한다.
- 견적 필드, 필수값, 상태 및 검증 규칙은 기존 업무·데이터 계약을 확인한 뒤 계획서와 상세사양서에서 확정한다. 구형 화면은 업무 흐름 참고 자료이며 현재 DB/API 계약의 근거로 사용하지 않는다.
- 작업장, 그리드 소수점 정책, 수주현황 표시 변경, 거래명세서 정책, 공통코드 분류, 테넌트별 품목 분류는 이 작업 범위에서 제외하고 각각 별도 작업으로 진행한다.

## 구현 및 검증

1. 이 작업지시서를 기준으로 날짜별 계획서와 상세사양서를 먼저 작성하고, 화면별 동작·필드·검증 기준 및 영향 범위를 확정한다.
2. 기존 수주등록·수주현황 화면의 구성과 권한·검색·상세·저장 패턴을 확인하고, 아래 구형 화면을 레이아웃과 업무 흐름 참고 자료로 검토한다.
   - `D:\f1soft\dev\sencha\SAMWOO2\iPlusERP\WebContent\app\view\SA\WSA300\WSA305.js`
   - `D:\f1soft\dev\sencha\SAMWOO2\iPlusERP\WebContent\app\view\SA\WSA300\WSA306.js`
3. 견적 등록·조회 및 수주-견적 연계의 현재 데이터 계약을 확인한다. DB/API 변경이 필요한 경우 구현 전에 `s-erp-postgresql-readonly` MCP로 테이블·컬럼·조회 계약을 확인하고 날짜별 스키마 변경 이력을 관리한다.
4. 기존 서비스·타입·공통 화면 컴포넌트 패턴에 따라 프론트엔드와 필요한 백엔드 기능을 구현한다. 품목 마스터 선택과 직접 입력 경로를 각각 검증하고, 직접 입력은 견적 상세에만 저장되는지 확인한다. 견적관리 메뉴 seed·롤백 SQL은 두 스키마 이력 위치에 동일하게 작성하고, 역할별 권한은 기존 수주 메뉴 권한을 기준으로 연결한다.
5. 관련 테스트와 빌드를 수행하고, 작성·현황 화면 및 수주등록의 견적번호 선택을 회귀 검증한다.
6. 실제 브라우저에서 375px, 768px, 1280px 화면을 확인하고 결과 문서와 필요한 스크린샷을 `docs/result/20261116/quotation-management/`에 기록한다.

## 완료 기준

- `견적서작성`과 `견적현황`을 영업관리 > 견적관리에서 사용할 수 있다.
- 승인된 테넌트에 적용할 수 있는 견적관리 메뉴·권한 seed와 데이터 보존형 롤백 스크립트가 준비되어 있다.
- 견적 상세 품목은 마스터 선택 없이 직접 입력할 수 있고, 이 경로에서 품목 마스터 데이터는 생성·변경되지 않는다.
- 수주등록에서 견적번호를 선택해 연결할 수 있으며, 견적 없이도 기존 수주 등록이 가능하다.
- 확정된 계획·사양과 구현 결과가 일치하고 관련 테스트, 빌드, 브라우저 확인 및 결과 문서화가 완료된다.
