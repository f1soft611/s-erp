# 20261007_007 문서작성 결재 단계·중복 방지·초기 결재자 작업지시서

## 목적

문서작성 모달에서 로그인 사용자를 삭제할 수 없는 1번 결재자로 초기 설정하고, 결재·합의·참조 간 사용자 중복을 막으며, 합의 그룹의 모든 사용자가 한 결재순번을 공유하도록 한다.

## 승인된 요구사항

- 프로필의 이름과 `userId`가 유효하면 로그인 사용자를 첫 결재 단계로 추가한다. 사용자 선택 옵션에 동일 `userId`가 있으면 해당 옵션을 사용하고, 없으면 프로필의 `userId`, 이름, 부서, 직급, 프로필 이미지로 고정 결재자 표시 옵션을 구성한다. 해당 결재자는 순번 1이며 삭제할 수 없다.
- 프로필 이름 또는 `userId`가 없으면 작성 모달의 기존 오류 영역에 명확한 오류를 표시한다. 단지 선택 후보 목록에서 로그인 사용자가 제외되었다는 이유로 초기 결재 단계를 실패 처리하지 않는다.
- 결재, 합의, 참조에 이미 배정된 사용자와 현재 결재 선택 중인 사용자는 나머지 선택기에서 후보로 제공하지 않는다.
- 결재 사용자는 한 명당 하나의 단계와 순번을 갖는다. 한 번의 `합의 추가`로 추가한 여러 합의자는 하나의 단계에 속하며 같은 순번을 공유한다.
- 순번은 단계 순서로 1부터 부여한다. 예: 기안자 결재 1, 합의자 2명 모두 2, 후속 결재자 3, 다음 결재자 4.
- 결재 행과 합의 행 사이 구분선을 제거한다.
- 빈 결재 칸은 직위/직함 영역을 글자 없이 공백으로 두고, 도장과 이름 영역을 포함해 점선 외곽선으로 표시한다. 순번과 삭제 동작은 표시하지 않는다.
- 미결재 합의자에는 도장 placeholder를 표시하지 않는다. 작성 모달에는 승인 상태 데이터가 없으므로 승인 결과 상태나 API를 새로 만들지 않는다.
- 기존 반응형 결재 슬롯, 합의 행 표시 조건, 사용자 개별 삭제/후보 복원, 참조 선택 흐름을 유지한다. 단, 중복 선택 제한은 적용한다.

## 작업 절차

1. 승인 설계서와 계획서를 기준으로 날짜별 상세 사양서를 작성한다.
2. 현재 문서작성 테스트에서 로그인 사용자 초기 결재, 고정 삭제 방지, 사용자 중복 차단, 단계 단위 순번, 점선 빈 결재 칸, 미결재 합의 도장 숨김 회귀 테스트를 먼저 추가한다.
3. 작성 hook 및 결재 단계 타입을 수정해 사용자 초기화, 고정 단계, 선택 간 중복 방지, 순번 상태를 구현한다.
4. 결재 필드 렌더링과 모달의 행 사이 구분선을 수정하고 접근성 있는 테스트를 추가한다.
5. 집중 Vitest, 변경 파일 lint, 프론트엔드 빌드를 실행한다.
6. 합성 사용자명만 사용해 375px, 768px, 1280px 브라우저를 확인하고 결과 문서와 개인정보 없는 스크린샷을 저장한다.

## 완료 기준

- 프로필 이름과 `userId`가 유효하면 선택 후보에 해당 사용자가 없어도 로그인 사용자가 삭제 불가한 결재 1번으로 표시된다. 프로필 식별 정보 자체가 누락되면 명시적으로 오류 처리한다.
- 어느 한 역할에 배정되었거나 결재 선택 중인 사용자는 다른 역할 선택기에서 선택할 수 없다. 삭제하면 비고정 사용자는 후보로 복원된다.
- 한 합의 그룹의 복수 인원은 같은 순번을 표시하고, 각 결재자는 고유 단계 순번을 표시한다. 순번 예시와 삭제 후 재계산이 테스트된다.
- 결재/합의 사이 구분선이 없고, 빈 결재 칸은 직위/직함 문구가 보이지 않는 전체 빈 양식과 점선 외곽선을 가지며, 미결재 합의자는 도장 표시가 없다.
- 기존 반응형 레이아웃과 참조 선택 동작을 유지하며 브라우저에서 375px, 768px, 1280px를 확인한다.
