# 20261007_002 문서작성 결재선 입력 필드 공간 개선 작업지시서

## 목적

문서작성 모달에서 결재자 선택과 결재 단계가 세로 공간을 과도하게 사용하지 않도록, 결재선 선택 필드를 번호 순서의 가로 흐름으로 배치한다. 참조선은 독립된 다중 선택 입력으로 유지한다.

## 승인된 요구사항

- 결재선은 `1`, `2`, `3` 순번으로 이어지는 가로 흐름으로 표시한다.
- 각 단계 입력은 다중 사용자 선택을 지원한다. 마지막 입력만 활성 상태이며, 사용자를 확정한 입력은 삭제 affordance가 없는 선택 칩을 보이는 읽기 전용 필드로 남는다.
- 마지막 활성 입력에서 `결재 추가` 또는 `합의 추가`를 눌러 선택값을 확정한다. 확정 후 다음 빈 다중 선택 입력을 오른쪽 끝에 추가한다.
- `결재 추가`는 선택된 각 사용자를 선택 순서대로 각각의 결재 단계로 추가한다.
- `합의 추가`는 선택된 모든 사용자를 하나의 합의 단계로 추가한다.
- 결재·합의 확정 단계에 등록된 사용자는 마지막 활성 결재선 입력의 후보에서 제외한다. 단계를 제거하면 해당 사용자는 다시 후보로 제공한다.
- 각 확정 단계에는 순번, 역할(결재/합의), 선택 사용자 칩, 기존 도장 자리 및 삭제 동작을 표시한다.
- 참조선은 별도의 다중 선택 입력 하나로 유지하며, 선택된 참조자는 입력 칩으로만 표시한다. 결재선과 참조선 간 중복 제한은 두지 않는다.
- 결재선만 자체 가로 스크롤을 사용해 좁은 화면에서 페이지 전체 가로 넘침을 방지한다.
- 공통 `UserSelectEditor`, `RichTextEditor`, `CommonDialog`를 재사용한다. API, 저장/상신, 백엔드, DB 동작은 추가하지 않는다.
- `UserSelectEditor`의 `readOnly` 값에서 칩 삭제 액션을 차단해 확정 입력은 값 변경이 불가능하게 한다. 기본 편집 가능 선택기 동작은 유지한다.

## 작업 순서

1. 상세 사양서와 계획서를 기준으로 결재선 순차 입력의 회귀 테스트를 먼저 추가한다.
2. 다중 선택 확정 시 결재 개별 단계, 합의 그룹 단계, 다음 빈 입력 추가, 후보 제외 및 삭제 복원을 검증한다.
3. 결재선 확정 단계를 읽기 전용 선택 칩 필드로 렌더링하고 마지막에 활성 다중 선택 입력 및 역할별 확정 버튼을 둔다.
4. 참조선 다중 선택 동작과 모달 본문 스크롤을 유지한다.
5. 지정 테스트, lint, 빌드를 실행하고 375px/768px/1280px 브라우저에서 레이아웃과 내부 가로 스크롤을 확인한다.
6. 날짜별 결과 보고서와 브라우저 캡처를 작성한다.

## 완료 기준

- 확정 결재선 입력은 읽기 전용이며, 마지막 입력만 사용자를 선택할 수 있다.
- 결재/합의 버튼은 마지막 입력의 다중 선택값에만 적용되고 선택이 끝나면 다음 빈 입력이 생성된다.
- 복수 결재자는 순서대로 개별 결재 단계가 되고, 복수 합의자는 하나의 합의 단계가 된다.
- 확정 사용자는 후보에서 제외되며 단계 삭제 후 다시 후보에 나타난다.
- 참조선은 다중 선택 칩을 유지하고 별도 사용자 요약 목록을 표시하지 않는다.
- 좁은 화면에서도 결재선 영역 내부에서 가로 스크롤되며 문서 전체는 가로로 넘치지 않는다.
- 기존 본문 에디터 자연 높이, 모달 세로 스크롤, 오류/로딩 및 문서작성 회귀 동작을 보존한다.
