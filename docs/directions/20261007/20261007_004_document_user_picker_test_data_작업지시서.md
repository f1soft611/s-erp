# 20261007_004 문서작성 사용자 선택 테스트 데이터 작업지시서

## 목적

문서작성 화면에서 결재선/참조 사용자 선택기를 테스트할 수 있도록 현재 한 명뿐인 사용자 외에 테스트용 사용자 10명을 선택 후보로 추가한다.

## 승인된 요구사항

- `tb_user`에 `문서작성 테스트 사용자 01`부터 `10`까지 테스트 프로필 10개를 추가한다.
- 테스트 이메일은 `doc-write-test-user-01@example.invalid`부터 `10`까지의 예약 도메인을 사용한다.
- 현재 활성 상태인 계정 연결 사용자와 같은 테넌트, 로그인 ID, 부서, 직급을 재사용한다.
- 사용자 선택기에서 조회되도록 테스트 사용자와 기존 활성 `tb_login_account`를 연결하고 두 테이블의 활성 여부를 유지한다.
- 로그인 계정, 암호, 부서, 테이블 또는 애플리케이션 로직은 새로 만들거나 변경하지 않는다.
- 반복 실행 시 중복 사용자를 만들지 않는 시드 SQL과 테스트 사용자만 제거하는 롤백 SQL을 제공한다.
- `docs/database`와 `backend/DATABASE`에 같은 SQL 및 변경 이력을 남긴다.

## 작업 순서

1. 계획서와 사양서에 사용자 선택기 조회 조건 및 테스트 데이터 계약을 기록한다.
2. 기존 계정 연결 사용자 부재 시 명시적으로 중단하는 PostgreSQL 시드 SQL을 작성한다.
3. 정확히 동일한 시드, 롤백, 변경 이력 파일을 두 DB 문서 경로에 작성한다.
4. 활성 상태, 테넌트/로그인 연결, 이메일 유일성, 반복 실행, 롤백 대상, 파일 동등성을 검증한다.
5. 결과 문서에 읽기 전용 DB 확인 범위와 한계를 기록한다. 실제 데이터 반영 후 확인 전에는 화면에 10명이 나타난다고 보고하지 않는다.

## 완료 기준

- 테스트 프로필 10개를 추가하는 실행 가능한 SQL과 대응 롤백 SQL이 있다.
- 시드와 롤백이 모두 멱등/대상 한정 원칙을 따르고 두 위치의 복사본이 일치한다.
- 변경 이력, 계획서, 사양서, 결과 문서가 작성되어 있다.
- 실제 DB 반영 없이 사용자 선택기 표시가 검증되었다고 주장하지 않는다.
