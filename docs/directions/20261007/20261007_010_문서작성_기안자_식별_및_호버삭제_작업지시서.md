# 20261007_010 문서작성 기안자 식별 및 호버 삭제 작업지시서

## 목적

문서작성 모달에서 로그인한 기안자가 결재선 사용자 목록에 다시 노출되는 원인을 바로잡고, 결재자와 합의자를 마우스 호버 또는 키보드 포커스로 삭제할 수 있게 한다.

## 확인된 원인

- 내 프로필 API의 `userId`는 `tb_login_account.login_code`이다.
- 기안양식 사용자 목록의 `userId`는 `tb_user.user_id`이다.
- 서로 다른 식별자를 비교해 로그인 기안자 필터가 동작하지 않는다.
- DB MCP 메타데이터 조회에서 두 컬럼이 서로 다른 타입(text/bigint)인 것을 확인했다. 사용자 데이터 행은 조회하거나 기록하지 않았다.

## 승인된 요구사항

1. 프로필의 기존 `userId` 의미를 유지하고, 인증된 사용자 본인의 내부 사용자 키를 `employeeId`로 추가 반환한다. 값은 기존 `tb_user.user_id`에서 조회하며 스키마 변경은 하지 않는다.
2. 문서작성 초기 결재자는 프로필의 `employeeId`와 결재 사용자 옵션 `userId`를 정규화해 일치시킨다. 선택 후보에 없으면 프로필 표시 정보로 고정 결재자 항목을 만들되 동일 `employeeId`를 키로 사용한다.
3. 해당 기안자는 결재, 합의, 참조 후보에서 제외한다. 이름이 같아도 ID가 다른 사용자는 제외하지 않는다.
4. 고정 1번 기안자는 기존 규칙대로 삭제할 수 없다.
5. 비고정 결재자는 결재 카드 상단 직위 행 우측에 X 버튼을 배치하고, 데스크톱에서는 카드 호버 또는 키보드 포커스 시 보이게 한다.
6. 합의자 삭제 버튼도 X 아이콘으로 바꾸고, 합의 항목 호버 또는 키보드 포커스 시 보이게 한다.
7. 터치 전용 화면에는 호버가 없으므로 결재/합의 X 버튼을 항상 표시한다.
8. 삭제는 기존 참여자 단위 동작을 유지한다. 결재 단계 삭제 후 순번을 재계산하고, 합의 그룹에서 한 명만 삭제하며 그룹의 마지막 인원을 삭제하면 해당 단계를 제거한다. 삭제된 사용자는 후보에 복원한다.

## 변경 범위

- 백엔드 내 프로필 응답의 추가 필드: `MyProfileVO`, 프로필 조회 Mapper, `ProfileSettingsApiController`, 해당 컨트롤러 테스트
- 프론트엔드 프로필 타입, 문서작성 초기화 훅, 결재 필드 UI와 관련 테스트
- 날짜별 계획/사양/결과 문서와 반응형 결과 스크린샷

프로필의 기존 `userId`, 기안양식 사용자 목록의 기존 `userId`, 선택기 API 계약, 계정 노출 범위는 변경하지 않는다. 테이블/컬럼/FK/데이터 변경이 없으므로 SQL 마이그레이션이나 롤백 스크립트는 생성하지 않는다.

## 작업 절차

1. 이 작업지시서를 기준으로 계획서를 작성한다.
2. 계획서에 따라 상세 사양서와 API 필드/검증 기준을 작성한다.
3. 프로필 응답 및 프론트엔드 중복 방지 회귀 테스트를 먼저 추가하고 실패를 확인한다.
4. 프로필 응답에 `employeeId`를 추가하고 문서작성에서 실제 사용자 키를 사용한다.
5. 결재/합의 삭제 버튼을 X 아이콘으로 변경하고 호버/포커스/터치 표시 동작을 구현한다.
6. 백엔드 및 프론트엔드 집중 테스트, lint/build를 실행한다.
7. 375px, 768px, 1280px 브라우저에서 선택/삭제/표시 동작을 확인하고 결과 문서와 개인정보 보호 스크린샷을 갱신한다.

## 완료 기준

- 로그인 프로필의 `employeeId`와 선택 후보의 내부 사용자 ID가 일치하여 기안자가 결재·합의·참조 후보에서 제외된다.
- 프로필 `userId`의 기존 의미가 유지되고, 동명이인은 ID가 다르면 후보로 남는다.
- 고정 기안자는 삭제 불가이며 비고정 결재자/합의자는 X 버튼으로 삭제 가능하다.
- 데스크톱 호버/키보드 포커스와 터치 환경의 항상 표시가 검증된다.
- 삭제 후 후보 복원과 단계 순번 재계산이 유지된다.
- 관련 백엔드/프론트엔드 검증과 결과 문서/스크린샷이 완료된다.
