# 20261007_005 문서작성 테스트 사용자 로그인 계정 보정 작업지시서

## 목적

문서작성 결재선/참조 선택기용 테스트 사용자 10명이 하나의 `login_id`를 공유하면서 기안양식 목록 조회 결과가 중복되는 문제를 바로잡는다. 테스트 프로필마다 고유 로그인 계정을 연결하고 실제 로그인에 필요한 일반 사용자 역할과 안전한 비밀번호 해시 입력을 제공한다.

## 확인된 원인

- 기존 `20261007_001_seed_document_user_picker_test_users.sql`은 10개 테스트 `tb_user` 행에 동일한 기존 `login_id`를 연결했다.
- `DraftingWork_SQL_postgresql.xml`의 `selectWorkList`는 검토자/승인자를 `tenant_id`와 `login_id`로 `tb_user`에 조인한다. 공유 로그인 ID에 여러 사용자 프로필이 연결되면 양식 행이 조인 결과만큼 반복된다.
- 사용자가 공유한 브라우저 상태에서 데이터 행 32개가 렌더링되었지만 안정 행 ID는 1, 2, 3만 반복되었고 React 중복 key 경고가 확인되었다.
- 사용자 선택 API가 활성 로그인 계정 내부 조인을 요구하므로, 프로필마다 고유한 활성 계정을 연결해야 한다.

## 승인된 변경 범위

- 10개 기존 테스트 프로필을 이름/예약 `.invalid` 이메일 기준으로 찾아 각각 고유한 `tb_login_account`에 연결한다.
- 로그인 코드는 `doc-write-test-user-01`부터 `doc-write-test-user-10`까지 사용한다.
- 각 계정에 같은 테넌트의 기존 활성 `DEFAULT_USER` 역할을 연결한다. 역할 또는 메뉴 권한은 생성·변경하지 않는다.
- 각 계정의 `password_hash`는 실행 시 같은 PostgreSQL 세션의 사용자 지정 설정에서 가져온다. 평문 비밀번호와 해시는 채팅이나 저장소에 기록하지 않는다.
- 데이터 변경은 두 날짜별 seed 파일에서만 제공한다. 읽기 전용 DB MCP로 SQL을 실행하지 않는다.
- 백엔드 조회 SQL과 F1-Grid 코드는 변경하지 않는다. F1-Grid 문서에는 고유하고 안정적인 `rowKey`가 필요한 입력 계약을 추가한다.
- seed SQL, rollback SQL, 변경 이력은 `docs/database/20261007`와 `backend/DATABASE/20261007`에 동일하게 둔다.
- 결과 문서에는 원인, 검증, 실제 DB 미반영 상태를 기록하고 테넌트 행 데이터/인증정보를 포함하지 않는다.

## 실행 요구사항

1. 계획서 및 사양서에 사용자 프로필, 고유 계정, `DEFAULT_USER`, 해시 입력, 재실행, 롤백 계약을 기록한다.
2. 활성 계정 연결 기준 프로필과 해당 테넌트 활성 `DEFAULT_USER` 역할이 없거나 해시 10개 중 누락/형식 오류가 있으면 쓰기 전에 SQL이 명시적으로 실패하도록 한다.
3. 재실행은 정확히 지정된 테스트 계정/프로필/역할 매핑만 갱신하며 다른 테넌트의 같은 로그인 코드는 충돌로 취급하지 않는다.
4. 롤백은 테스트 프로필과 테스트 계정의 역할 연결만 제거하고, 테스트 로그인 계정은 다른 프로필이 참조하지 않을 때만 삭제한다.
5. DB 파일 쌍의 SHA-256 일치, SQL 정적 조건 및 F1-Grid 문서 테스트를 확인한다.

## 완료 기준

- 테스트 프로필과 로그인 계정이 1:1이며 일반 사용자 권한 코드 `DEFAULT_USER`에 연결된다.
- 계정별 해시 설정 10개를 제공하지 않으면 데이터 변경 전에 실패한다.
- 두 위치의 seed, rollback, 변경 이력 파일이 바이트 단위로 동일하다.
- 결과 문서가 현재 SQL 동작과 DB 반영 여부를 정확히 설명한다.
- 활성 DB에 쓰지 않은 경우 계정 생성 및 실제 로그인 성공을 검증했다고 보고하지 않는다.
