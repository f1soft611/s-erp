# 20261007_009 문서작성 다크 테마 합의 칩/에디터 배경 작업지시서

## 목적

문서작성 모달 다크 테마에서 합의 참여자 칩과 에디터 표면이 라이트 테마 전용/다크 표면으로 남아 있는 문제를 일관되게 수정한다.

## 승인 요구사항

- 라이트 테마의 합의 칩은 기존 회색 배경을 유지한다.
- 다크 테마의 합의 칩은 어두운 슬레이트 표면과 테마 구분선, 가독성 있는 글자색을 사용한다.
- 에디터 표면은 테마에 따라 라이트 `#ffffff`, 다크 `#1e293b`로 표시한다.
- 편집 영역과 첨부 영역도 같은 테마별 표면을 사용하고, 본문 기본 글자와 placeholder는 각 배경에서 읽을 수 있어야 한다.
- 본문 placeholder는 제목 placeholder와 같은 흐릿한 테마 disabled 색을 사용한다. 제목 입력 글자는 굵게, 에디터 본문 글자는 일반 굵기로 표시한다.
- 모달 셸 및 제목 필드의 기존 테마별 색상, 합의 선택/삭제 동작은 유지한다.
- 기존 결재선 초기 사용자 등 다른 작업 변경을 보존한다.

## 작업 절차

1. 승인 설계·기존 결재선 사양 및 현재 워킹트리 변경을 확인한다.
2. 에디터 색상 통합 테스트와 합의 칩 테마 테스트를 먼저 작성해 기존 다크 렌더에서 실패하는지 확인한다.
3. 에디터 표면을 라이트 `#ffffff`/다크 `#1e293b`로 적용하고 테마별 본문/placeholder 대비를 맞춘다.
4. 합의 칩에만 테마-aware 색상을 적용하고 선택/삭제 로직은 변경하지 않는다.
5. 집중 테스트, lint, 빌드와 공유 브라우저의 375px/768px/1280px 확인을 실행한다.
6. 개인정보·문서 본문을 노출하지 않는 캡처와 결과 문서를 기록한다.

## 완료 기준

1. 다크 모드 합의 칩은 밝은 회색/흰 배경으로 남지 않으며 텍스트와 삭제 아이콘을 읽을 수 있다.
2. 라이트 모드 합의 칩 외관은 이전과 같다.
3. 에디터 캔버스는 라이트에서 흰색, 다크에서 `#1e293b`이며 양쪽 모두 기본 입력 글자와 placeholder가 읽힌다.
4. 모달 셸/제목 필드와 결재선 선택·삭제 동작은 유지된다.
5. 관련 테스트, lint, 프론트엔드 빌드 및 반응형 브라우저 검증을 완료한다.
