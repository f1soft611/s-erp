# 20261002_002 기안양식 백엔드 패턴 및 무결성 보완 작업지시서

## 작업 목적

기안양식관리 백엔드를 S-ERP 기준정보 API의 문서화 패턴에 맞추고, 양식 코드 동시 등록 중복 및 담당자 목록 명시적 null 처리 문제를 해결한다.

## 대상 및 범위

- `DraftingWorkApiController`에 기존 API의 OpenAPI 태그, 작업 설명, 응답 코드, 인증 principal 숨김 표기를 추가한다.
- 기안양식 도메인 VO 전체에 클래스 및 필드 `@Schema` 설명을 추가해 창고관리 VO 패턴과 일치시킨다.
- 생성 및 수정 모두 `assigneeIds == null`을 담당자 미지정인 빈 목록으로 처리한다.
- 테넌트 내 양식 코드 중복을 soft delete 되지 않은 행 기준 unique index로 방지하고, 충돌은 기존 입력 검증 400 응답으로 반환한다.
- 변경 SQL, 변경 이력, 롤백 파일을 `backend/DATABASE/20261002`와 `docs/database/20261002`에 동일하게 추가한다.
- 관련 단위 테스트와 Mapper statement 확인 테스트를 추가한다.

## 완료 기준

- 생성 payload에서 `assigneeIds`를 생략하거나 null로 전달해도 NPE 없이 빈 담당자 목록으로 처리된다.
- 동시 중복 등록은 PostgreSQL unique index가 최종 차단하고 API는 중복 코드 입력 오류를 반환한다.
- 삭제 처리(`delete_status = 'Y'`)된 행만 기존 코드를 재사용할 수 있다. `use_at = 'N'`은 삭제가 아니므로 코드를 계속 점유한다.
- 외부 API VO와 Controller OpenAPI 메타데이터가 기존 기준정보 API와 일관된다.
- `mvn "-Dtest=DraftingWorkApiControllerTest,DraftingWorkServiceImplTest" test` 통과 및 두 DB 변경본의 파일 내용이 동일하다.
- 결과 보고서를 `docs/result/20261002/draft-form-backend-consistency/`에 작성한다. UI 변경이 없으므로 스크린샷은 대상이 아니다.

## DB 사전 조건

- 읽기 전용 PostgreSQL MCP에서 대상 테이블과 인덱스를 확인한다.
- 마이그레이션 전 현재 테넌트 내 soft delete 되지 않은 중복 코드가 없어야 한다. 중복이 발견되면 자동 정리하지 않고 적용을 중단해 데이터 소유자 확인을 요청한다.
- SQL은 자동 실행하지 않는다.
