# 20261002_008 공통코드 상세코드 조건부 자동 발번 작업지시서

## 1. 작업 분류

- 분류: `backend`, `database`, `frontend`
- 대상: 공통코드 상세코드 저장 및 그룹별 번호 발급
- DB 방식: PostgreSQL 원자적 upsert

## 2. 배경

공통코드 상세코드를 저장할 때 `item_code`를 직접 입력하지 않아도 그룹별 숫자 코드를 자동 발급할 수 있어야 한다. 참고 프로젝트의 IDS2 조건별 카운터 개념을 적용하되, S-ERP 명명 규칙과 PostgreSQL에 맞춘다.

현재 상세코드의 `item_code`는 필수 입력이며 그룹 내 유일하다. 기존 공통코드 그룹/상세 테이블 및 API의 테넌트 범위는 이 작업에서 변경하지 않는다.

## 3. 확정 요구사항

- 신규 공용 카운터 테이블은 `tb_id_sequence`로 추가한다.
- `tb_id_sequence`에는 `tenant_id`를 추가하지 않는다.
- 카운터 키는 `generator_key`, `scope_key_1`, `scope_key_2`이며, 공통코드 상세코드는 발번 목적과 그룹 ID로 분리한다.
- 카운터는 원자적 upsert로 증가시키고 최초 발급값은 1로 한다.
- 상세코드가 비어 있을 때에만 그룹별 숫자 코드(`001`, `002`, ...)를 발급한다. 세 자리 초과 숫자는 자르지 않는다.
- 상세코드 직접 입력은 계속 허용한다. 숫자 코드를 직접 입력하면 이후 자동 발번이 그 값보다 낮은 값을 내지 않도록 카운터를 동기화한다.
- 공통코드 관리 화면과 공통코드 설정 모달(기안양식 분류 설정) 모두 신규 항목에서 상세코드를 비워 저장할 수 있어야 한다.
- 설정 모달의 상세코드는 기존처럼 읽기 전용이며, 빈 값 자동발급을 위해 필수 검증만 해제한다.
- 기존 숫자형 상세코드 데이터의 그룹별 최댓값을 마이그레이션 시 카운터에 반영한다.
- `tb_common_code_group` 및 `tb_common_code_item`의 `tenant_id`와 기존 API 테넌트 검증은 유지한다.

## 4. 완료 기준

1. 같은 그룹에서 빈 `item_code`를 저장하면 다음 숫자 코드가 발급된다.
2. 서로 다른 그룹은 별도의 카운터를 사용한다.
3. 수동 코드 저장은 유지되고, 수동 숫자 코드는 카운터를 동기화한다.
4. 기존 숫자형 코드가 있는 그룹은 기존 최댓값 다음 번호부터 발급한다.
5. 동시 발급은 중복 숫자를 만들지 않는다.
6. 신규 카운터 테이블에는 `tenant_id`가 없고 기존 공통코드 테이블은 변경하지 않는다.
7. 백엔드·프론트엔드 관련 테스트와 빌드가 통과한다.
