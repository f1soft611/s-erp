# 20261002_015 공통 리치 텍스트 에디터 및 공지 페이지 분리 작업지시서

## 작업 분류

- 대상: 프론트엔드 공지사항 및 기안양식 본문 편집기
- 목표: 공지 페이지의 책임을 컴포넌트·훅·서비스·타입으로 분리하고, 공지와 기안양식이 공통 에디터를 사용하게 한다.
- 승인 설계: [공통 리치 텍스트 편집기 및 공지 페이지 분리 설계](../../superpowers/specs/2026-10-02-rich-text-editor-and-page-modularization-design.md)
- 범위: React/TypeScript 프론트엔드만 변경한다. 백엔드/API 계약/DB는 변경하지 않는다.

## 현재 상태 및 근거

- `NoticeComposerDialog.tsx`와 `DraftFormTemplateDialog.tsx`가 Tiptap 확장, 툴바, clipboard 처리 및 이미지 붙여넣기를 각각 구현한다.
- 공지 편집기에는 폰트/색상, 표 셀 스타일과 이미지 크기 조절이 있으나 기안양식 편집기에는 동일 기능이 없다.
- Excel clipboard 정규화가 `groupware/community/notice/utils/noticeClipboard.ts`에 있어 기안양식이 공지 도메인 경로를 직접 import한다.
- 공지 API 일부는 `noticeBoardService.ts`에 있지만 `CommunityNoticePage.tsx`에 데이터 로딩, 페이징, 선택, 댓글/반응, CRUD 및 화면 조립이 집중되어 있다.
- 공지 API/폼 타입 일부가 service/dialog 파일 안에 선언되어 있고, 페이지 로직을 책임별로 관리하는 전용 훅이 없다.

## 요구사항

1. 공유 에디터 모듈을 `frontend/src/shared/components/rich-text-editor/` 아래에 만들고, 편집기 컴포넌트, 타입, clipboard 도구, 스타일/확장을 공통 책임으로 분리한다. 공통 파일명에 `notice`를 붙이지 않는다.
2. 공통 에디터는 공지에서 제공하던 텍스트 서식(굵게/기울임/취소선/목록/인용/되돌리기/다시 실행), 글꼴/크기/색상, 표 편집/Excel 붙여넣기, 일반 텍스트 붙여넣기, 이미지 붙여넣기 및 이미지 크기 조절을 제공한다.
3. 공지와 기안양식 다이얼로그는 공통 에디터를 그대로 사용한다. 두 도메인이 공통 편집기의 clipboard 정규화/toolbar/resize 구현을 중복 소유하지 않는다.
4. 이미지 업로드/복원/삭제와 본문 저장 payload는 각 화면의 기존 API/service에서 수행한다. 업로드 응답은 공통 에디터의 이미지 메타데이터 계약으로 매핑한다. 공지 endpoint, 기안양식 endpoint, object key 및 owner 정책을 통합하거나 변경하지 않는다.
5. `CommunityNoticePage.tsx`는 페이지 레이아웃과 하위 컴포넌트 조립을 중심으로 정리한다. 로딩/페이징/필터/선택과 사용자 액션은 관심사별 기능 훅으로 이동한다. 단일 훅에 모든 동작을 무조건 합치지 않는다.
6. 공지 API 및 폼 타입을 도메인 `types/`로 옮기고, 데이터 변환은 기존 `data/` 또는 `utils/` 책임으로 유지한다. 기존 공지 API는 `noticeBoardService.ts`, 댓글/공통 파일/공통코드는 기존 shared services를 사용한다.
7. 기존 notice와 draft form 저장 payload, 권한, 로딩/오류, 임시 이미지 정리 및 화면 동작을 보존한다. 기안양식 저장 JSON/HTML이 공통 스키마를 왕복하는지 검증한다.
8. 본 작업의 공통화로 변경된 기존 기안양식 에디터 작업지시서/계획서/사양서(20261002_011)와 공지 Excel 붙여넣기 작업지시서/계획서/사양서(20261002_012)의 적용 범위와 파일 책임을 현재 설계에 맞게 갱신한다.

## 제외 범위

- 백엔드/API/DB 스키마/인증/권한/파일 소유권 정책 변경
- 공지 및 기안양식의 저장 흐름 또는 payload 계약 변경
- 공지 피드/상세 화면 재설계, 라우팅 변경, 무관한 기능 리팩터링
- HTML/CSS 보안 allowlist의 임의 확장

## 검증 및 완료 조건

1. 공통 clipboard 테스트가 Excel 표 구조/병합/줄바꿈/허용 서식, 일반 텍스트 fallback, unsafe markup 제거를 검증한다.
2. 공통 에디터 테스트가 툴바 편집, 이미지 placeholder/업로드 성공·실패 및 크기 조절을 검증한다.
3. 공지와 기안양식 테스트에서 동일 공통 에디터가 사용되고 각각의 도메인 업로드 어댑터 및 기존 저장 payload가 유지되는 것을 검증한다.
4. 공지 페이지 테스트에서 목록/상세/페이징/필터/작성·수정·삭제/고정/댓글/좋아요/북마크 동작 회귀가 없다.
5. 관련 Vitest와 `npm --prefix frontend run build`를 통과한다.
6. Chromium에서 공지 작성과 기안양식 편집을 확인하고 375px, 768px, 1280px에서 툴바·표·이미지 배치가 겹치거나 잘리지 않는지 확인한다.
7. 결과 문서 및 실제 브라우저 스크린샷을 `docs/result/20261002/rich-text-editor-page-modularization/`에 기록한다.
8. 변경은 프론트엔드와 위에 열거한 문서 범위로 제한하고 `git diff --check`를 통과한다.

## 승인 상태

- 사용자는 전체 공통 편집기 기능을 공지와 기안양식이 공유하고, 각 도메인의 upload/save adapter는 유지하는 설계를 승인했다.
- 이 작업지시서에 따른 계획서와 상세 사양서를 작성한 후 구현한다.
