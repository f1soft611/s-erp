# 20261002_010 전자결재 문서작성 페이지 작업지시서

## 작업 목적

`/groupware/doc/write` 경로의 준비중 화면을 그룹웨어 문서작성 화면으로 연결한다. 공지사항 화면의 좌측 목록/피드와 우측 요약 레이아웃 및 작성 모달 패턴을 따른다.

## 승인 요구사항

- 페이지의 기본 보기 방식은 리스트이며, 피드/리스트 전환을 제공한다.
- 작성 페이지에는 F1-Grid를 사용하지 않는다.
- 좌측 툴바, 아이콘형 구분 필터, 상단고정 패널, 피드/리스트 항목 구조는 공지사항 페이지 패턴과 동일하게 구성한다. 별도 텍스트 검색 입력은 두지 않는다.
- 상단고정 항목은 전용 패널에만 표시하고 아래 피드/리스트에는 중복 표시하지 않는다.
- 리스트 항목의 제목 줄에는 업무구분과 결재상태를 공지사항의 분류 표시 위치에 나란히 표시한다.
- 상단 문서작성 액션은 작성 팝업을 연다.
- 팝업은 결재문서 구분 탭을 제공한다. 기안서와 업무연락을 우선 작성 유형으로 제공하고, 지출결의서와 근태신청은 구분 표시만 하며 비활성 처리한다.
- 팝업은 공지사항 작성 모달과 같은 `CommonDialog` 크기/셸, 제목 입력, 리치 본문 편집, 툴바/첨부, 저장·취소 푸터 구조를 사용하며 문서 구분 탭만 본문 상단에 추가한다.
- 좌측 문서 항목에는 결재상태와 업무구분을 함께 표시한다. 업무구분은 기안서, 업무연락, 지출결의서, 근태신청이다.
- 우측은 결재 처리 대기, 작성 중 문서 등 놓치기 쉬운 업무 요약 영역으로 구성한다.
- 문서현황 및 그 화면의 F1-Grid/상세검색, 실제 저장·상신 API는 이번 범위에 포함하지 않는다. 문서 현황 페이지는 별도 작업이다.
- API 계약이 아직 없으므로 목록/요약은 화면 검토용 로컬 샘플 데이터로만 구성한다.

## 구현 및 검증 범위

- 대시보드에서 `selectedModule.id === 'groupware' && currentPageKey === 'write'`일 때 작성 페이지를 표시한다.
- 프론트엔드 테스트, 빌드, 지정 경로 브라우저 확인을 수행한다.
- 데스크톱/태블릿/모바일 레이아웃을 확인하고 결과 문서에 스크린샷을 기록한다.

## 제외 범위

- DB/백엔드/API/권한 계약 변경
- 문서현황 페이지 및 F1-Grid 구현
- 결재선 설정, 실제 문서 저장, 결재 상신과 승인 처리
- 지출결의서/근태신청 작성 필드

## 완료 기준

1. `/groupware/doc/write`에서 준비중 화면 대신 문서작성 페이지가 표시된다.
2. 첫 렌더의 선택 보기 방식은 리스트이며 피드/리스트 전환이 동작한다.
3. 항목마다 결재상태와 네 종류의 업무구분 중 하나가 식별 가능하게 표시된다.
4. 상단고정 문서가 전용 패널에만 표시되고 본문 피드/리스트에는 중복되지 않는다. 별도 검색 입력은 없다.
5. 문서작성 액션이 팝업을 열고, 기안서/업무연락 탭을 선택할 수 있다.
6. 우측 결재 요약이 공지사항 요약 패널과 같은 카드 배치로 노출되고 화면이 반응형 규칙을 만족한다.
7. 관련 테스트, 빌드, 브라우저 확인 결과를 결과 문서에 기록한다.
