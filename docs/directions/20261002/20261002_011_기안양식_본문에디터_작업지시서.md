# 20261002_011 기안양식 본문 에디터 작업지시서

## 작업 분류

- 경로: bounded
- 대상: S-ERP 프론트엔드 및 백엔드 API
- 메뉴: 기준정보 > 전자결재관리 > 기안양식관리 (`/co/workflow/form`)
- 목적: 기안양식 목록의 문서 액션에서 선택한 양식의 본문을 작성·수정할 수 있는 모달을 열고, 공지사항 작성 에디터와 같은 표/이미지 붙여넣기 동작을 제공한다.

## 확인한 현재 상태

- 기안양식 목록은 `DraftFormGrid`의 F1-Grid 컬럼으로 구성되며, 각 행에 `hasDocument`가 있다.
- 현재 프론트 모델은 템플릿 본문을 포함하지 않고 목록 API는 템플릿 존재 여부만 전달한다. 기존 등록/수정 payload에도 본문 필드가 없다.
- 기존 기안양식 스키마에는 원본 호환 템플릿 컬럼 `drafting_work_template_json`, `drafting_work_template_html`이 있다. `drafting_work_template_text` 컬럼은 없으며 별도 추가하지 않는다.
- F1-Grid 공개 컬럼 메타데이터의 `renderCell`로 셀 액션을 표시할 수 있다.
- 공지사항과 기안양식은 공통 `shared/components/rich-text-editor/`의 Tiptap schema, icon toolbar, clipboard 정규화, 이미지 붙여넣기, 이미지 크기 조절 및 스타일을 사용한다. Toolbar에는 글꼴/크기/색상 선택기를 노출하지 않되 schema의 서식 parsing/rendering은 기존 콘텐츠 호환을 위해 유지한다. 이미지 임시 업로드/조회/삭제와 저장은 도메인별 API adapter로 유지한다.
- 기존 기안양식 상세 사양은 별도 템플릿 본문 에디터를 제외했으므로 이번 작업에서 해당 제외 범위를 변경한다.

## 작업 목적 및 문제

기안양식 메타데이터만 등록된 상태로는 실제 전자결재 문서에 사용할 본문 양식을 작성할 수 없다. 목록의 마지막 문서 액션에서 선택한 양식의 본문 편집 모달을 열고, 작성한 본문을 기존 템플릿 컬럼에 영속 저장해야 한다. 사용자는 공지사항 편집기와 같은 방식으로 Excel/스프레드시트 표와 이미지를 붙여넣을 수 있어야 한다.

## 접근 방식 비교

### 대안 A: 양식별 본문 모달과 전용 저장/API 연결 (권장)

- F1-Grid 문서 액션이 선택된 양식의 본문 작성 또는 수정을 연다.
- 기존 template JSON/HTML 컬럼을 읽고 저장하는 tenant-scoped API 계약을 추가한다.
- 본문 이미지는 양식 작성 흐름에 귀속되는 업로드/조회 계약을 사용한다.
- 장점: 양식별 저장, 재조회, 수정이 가능하고 공지사항 리소스 소유권과 기안양식 소유권을 혼합하지 않는다.
- 단점: 프론트 모달뿐 아니라 백엔드 조회/저장 및 이미지 업로드 계약 검토가 필요하다.

### 대안 B: 공지사항 작성 다이얼로그와 API를 그대로 재사용

- 공지사항 다이얼로그 및 공지 이미지 업로드 경로를 직접 호출한다.
- 장점: 초기 구현량이 적다.
- 단점: 공지사항 제목/첨부/저장 흐름이 기안양식 본문과 다르고, 공지 전용 이미지 소유권 계약을 재사용하면 양식의 보안·수명주기를 표현하지 못한다.
- 판정: 채택하지 않는다. 공통 편집기 로직은 재사용하되 공지 전용 도메인 저장/API를 양식에 직접 연결하지 않는다.

## 승인 요구사항 및 범위

- 기안양식 목록의 마지막 컬럼에 문서 액션을 추가한다. 각 행 액션은 해당 행의 양식 본문 작성 또는 수정을 연다. `hasDocument`를 기준으로 신규 작성/편집 상태를 표시한다.
- 액션 셀은 기존 F1-Grid `renderCell` 등 공개 API를 사용하며 F1-Grid 공통 코어 변경은 포함하지 않는다.
- 모달은 S-ERP 공통 다이얼로그 셸과 공지사항 작성 모달의 크기/헤더/본문/하단 액션 배치를 따른다. 선택된 양식명을 식별할 수 있고 본문 편집에 집중한다.
- Tiptap 기반 본문 에디터를 제공하며 Excel/스프레드시트에서 복사한 데이터는 행·열 구조가 가능한 한 표로 보존되고, 비표형 텍스트는 안전한 일반 텍스트로 붙여넣어진다.
- 이미지 클립보드 붙여넣기는 파일 감지를 우선하고, 기안양식관리 전용 임시 이미지 API 경로와 저장소 임시 객체 경로를 사용한다. 공지사항 임시 이미지 API 경로나 객체 namespace를 재사용하지 않는다. 업로드 중 커서 위치에 상태를 표시하며 성공 시 같은 위치에 이미지를 삽입한다. 실패 시 본문을 손상시키지 않고 오류를 표시한다. 이미지는 에디터 폭 안에서 비율을 유지한다.
- 본문 JSON/HTML은 기존 `tb_drafting_work_category` 템플릿 컬럼을 활용해 영속 저장하고 다시 열 때 복원한다. 텍스트 컬럼은 추가하지 않는다. 프론트 타입과 목록의 `hasDocument` 상태도 저장 결과와 동기화한다.
- 템플릿 상세 조회/저장 및 임시 이미지 업로드 계약은 tenant 경계, 양식 소유권, 권한, 파일 접근 정책을 지킨다. 임시 이미지 경로는 기안양식관리 전용으로 분리하고, 저장 후 본문 이미지 접근 경로와 임시 객체의 귀속/정리 정책을 계획서·사양서에서 기존 백엔드 계약 확인 후 확정한다.
- 공통 rich-text editor와 clipboard 동작은 공지사항 구현을 승격해 두 도메인에서 공유한다. 공지사항 전용 저장·첨부·이미지 소유권 API를 기안양식에서 직접 호출하지 않는다.
- 닫기/취소 시 변경 사항이 있으면 기존 공용 미저장 변경 확인 패턴을 적용한다. 저장 진행, 성공, 실패 상태를 구분한다.
- 백엔드 계약 수정 전 read-only PostgreSQL MCP와 기존 Mapper/서비스/스키마 이력을 확인한다. 2026-10-02 확인 결과 템플릿 JSONB/HTML 컬럼과 `tb_common_file` 소유권/임베디드 용도가 있어 신규 DB 스키마 변경은 하지 않는다. 텍스트는 HTML에서 파생하며 DB에 별도 저장하지 않는다.
- 기안양식 임시 객체 prefix에 `s-erp-temp-owner=drafting-work-form` object tag를 붙인다. MinIO lifecycle은 `tenant/` prefix와 해당 tag를 모두 만족하는 객체만 7일 후 만료한다. promotion copy에서는 tag를 제거해 영구 이미지가 만료 대상이 되지 않게 한다. 모달 취소 및 저장 시 미사용 임시 이미지는 API에서 즉시 정리한다.
- 관련 프론트 및 백엔드 테스트, 프론트 빌드, 브라우저 작성/저장/재열기, 375px·768px·1280px 화면 확인과 스크린샷을 수행한다.
- F1-Grid 문서 및 결과 문서에 새 문서 액션, 본문 저장, 표/이미지 붙여넣기와 회귀 검증을 반영한다.

## 제외 범위

- 전자결재 상신, 결재선 처리, 승인/반려 및 실제 결재문서 생성
- 기안양식 메타데이터 필드 및 기존 행 생성/수정 폼 재설계
- 공지사항 저장·첨부·이미지 API/소유권 변경. 공통 editor 승격과 동작 동일화는 별도 승인된 20261002_015 범위에서 수행한다.
- 공지사항 전용 업로드 API나 저장소 객체 경로를 기안양식에서 재사용하거나, 양쪽 API/소유권 정책을 공용화하는 광범위한 리팩터링
- F1-Grid 공통 코어 변경
- 사용자 승인 없이 정하는 신규 테이블/컬럼, 이미지 공개 정책, 임시파일 정리 정책 또는 권한 확대

## 완료 기준

1. 각 기안양식 행의 마지막 문서 액션이 올바른 양식 본문 모달을 연다.
2. 본문이 없는 양식은 작성으로, 본문이 있는 양식은 기존 내용 복원 및 수정으로 진입한다.
3. 저장 후 모달을 다시 열어도 본문 내용이 유지되고 목록의 `hasDocument`가 실제 상태와 일치한다.
4. 스프레드시트 표 붙여넣기에서 행·열 값이 누락되지 않고, 일반 텍스트 붙여넣기도 유지된다.
5. 이미지 붙여넣기 성공 시 원래 커서 위치에 이미지가 들어가고, 업로드 실패 시 본문이 손상되지 않으며 오류를 확인할 수 있다.
6. 기안양식 임시 이미지 API/저장소 경로가 공지사항 경로와 분리되고, 저장 후 본문 이미지가 재조회되며 임시 객체 정리 정책이 적용된다.
7. tenant/권한 범위 밖 양식과 이미지에 접근할 수 없고, 공지사항 첨부/저장 흐름에 회귀가 없다.
8. 관련 테스트, 빌드, 375px·768px·1280px 브라우저 확인 및 결과 스크린샷이 기록된다.
9. F1-Grid 문서와 `docs/result/20261002/<work-slug>/` 결과 문서에 변경 및 검증 근거가 기록된다.
