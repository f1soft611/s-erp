# 20261113_001 발주등록 화면 작업지시서

## 작업 목적

구매요청 → 구매요청확정(MC) 다음 단계인 **발주(PO) 등록 화면**을 만든다.
확정된 품목 행을 불러와 구매처별로 발주서를 만들고, 필요하면 품목을 직접 골라 발주한다.
기존 MES 발주등록(WMA202)은 참고만 하며, 핵심 항목만 관리해 입력 부담을 줄인다.

## 업무 규칙 (2026-11-13 사용자 확정)

### 발주서 구성
- 발주서 1건 = 구매처 1곳, 통화 1종.
- 확정 품목 불러오기: 여러 확정번호의 행을 함께 고를 수 있으나 **같은 구매처만** 가능하다.
  - 첫 번째로 체크한 행의 구매처를 칩으로 고정하고, 다른 구매처 행은 비활성(툴팁 안내)으로 둔다.
  - 칩의 ✕로 선택을 초기화한다.
- 분할발주 허용. 잔량 = 확정수량 − 기발주수량(유효한 발주 행 합). 잔량이 0이면 후보에서 빠진다.
  남은 수량을 더 발주하지 않을 때는 구매요청확정 화면의 발주대기 마감을 쓴다. 발주 화면에는 발주대기 마감을 두지 않는다.
- 확정값(구매처, 단가, 수량, 납기일, 창고)은 발주 기본값이며 모두 수정할 수 있다.
  확정과 다르면 행에 "확정과 다름" 경고 아이콘만 표시하고 저장은 막지 않는다.
- 직접 발주(품목 직접 선택, 품목 계정 RAW/SUB/SUPPLY): 저장 시 같은 트랜잭션에서 구매요청(MR) 1건과 확정(MC) 1건을 자동 생성한다.
  이를 위해 직접 발주는 **발주구분과 사용용도**를 헤더에서 한 번 선택한다.
- 한 발주서는 한 가지 출처(확정 불러오기 / 직접 발주)만 가진다.
- 단가는 모두 수정 가능, 단가가 없어도 저장 가능(업체별 정책은 후속).

### 화면 항목 (핵심 항목만)
- 헤더: 발주번호(저장 시 PO 번호), 발주일, 구매처, 입고창고(행 기본값), 부가세구분, 부가세여부, 사용용도·발주구분(직접 발주만), 비고, 공급가액·부가세액·합계액.
- 행: 품목, 규격, 단위, 납기일, 입고창고, 수량, 단가, 공급가, 세액, 합계, 검사대상, 사용용도, 구매요청번호·확정번호(읽기 전용), 재고량(컬럼만 확보), 비고.
- 제외: 긴급, 수입구분, 발주상태, 결제조건, 결제예정일, 납품처·주소, 외화·환율, 첨부, 업체송부여부, 수주번호, 환산수량, 구매소요일.
- 출력상태는 컬럼만 확보한다(발주서 출력 작업에서 사용). 재고량은 화면·API 필드만 확보하고 값은 비운다(재고 설계 후 연결).

### 부가세
- 부가세구분: 과세/영세/면세(공통코드 `PURCHASE_TAX_TYPE`, 20261113_001로 등록). 기본값 과세.
- 부가세여부: 포함/미포함. 과세일 때만 선택, 영세·면세는 미포함 고정. 기본값 미포함. 품목·구매처 단가에는 부가세 정보가 없다.
- 계산은 영업 수주(`roundSalesOrderAmount`)와 같은 반올림을 쓰고, 행에 공급가·세액·합계를 따로 저장한다.

### 검사대상
- `tb_material_info.inspect_type`(Y/N, 기본 N)을 행 기본값으로 읽고 발주에서 수정할 수 있다. 발주 행 값이 이후 가입고→수입검사 분기를 정한다.
- 품목마스터 화면·API는 이번에 바꾸지 않는다.

### 행 삭제 / 취소 (적용 단계 구분)
1. 저장 전: 잘못 불러온 행은 그리드에서 체크 후 [선택 행 빼기]로 제거한다(서버 영향 없음, 이 작업 범위).
2. 저장 후: 발주 행 삭제와 발주서 취소는 후속 **발주현황** 작업에서 구현한다. 가입고가 있는 행은 삭제·취소할 수 없다.
   이번 작업은 후속 작업이 쓸 수 있게 데이터 구조(행 삭제 시 잔량 자동 복원, 입고대기마감 컬럼)만 준비한다.

## 범위

### 포함
- DB: 발주 헤더/상세 테이블 생성, 메뉴 등록, `db-schema.md` 갱신(스크립트는 사용자가 실행).
- 백엔드: 후보 조회, 발주 저장(확정 불러오기/직접 발주 + MR/MC 자동 생성), 단가 조회(기존 API 재사용).
- 기존 확정 취소 API에 "발주 행이 있으면 취소 불가" 검증 추가.
- 프론트: 발주등록 화면, 확정 불러오기 창, 직접 품목 선택, 부가세 계산.
- 테스트, 결과 문서(스크린샷 포함).

### 제외(별도 작업)
- 발주현황(조회·행삭제·발주취소·MR/MC 자동 취소), 발주진행관리(입고대기마감), 발주대기마감 UI.
- 전자결재 연동과 [전자결재 등록] 버튼, 발주서 출력, 재고 연결, 품목마스터의 검사대상 입력, 공통 품목 선택 창 확장.

## 구현 절차
1. 계획서, 상세사양서
2. DB 스크립트(`20261113_002` 이후)와 `db-schema.md`, MCP 재확인
3. 백엔드 실패 테스트 → 구현
4. 프론트 실패 테스트 → 구현
5. 검증: 집중 테스트, 빌드, JDK 8 호환 컴파일, 브라우저
6. 사용자 스크립트 실행 후 MCP 확인, 실제 서버 시나리오 확인
7. 결과 문서 `docs/result/20261113/purchase-order-create`

## 완료 조건
- 확정 품목을 같은 구매처끼리 불러와 발주서가 저장되고, 분할발주 후 잔량만 후보에 나온다.
- 직접 발주 저장 시 MR 1건, MC 1건이 자동 생성되고 발주 행과 연결된다.
- 부가세 구분·여부 조합별 공급가·세액·합계가 사양대로 계산·저장된다.
- 발주 행이 있는 확정은 취소되지 않는다.
