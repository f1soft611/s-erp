# 20261113_002 발주현황 화면 작업지시서

## 작업 목적

등록한 발주(PO)를 조회하고, 상세를 보고, 잘못 담긴 행을 빼거나 발주서 전체를 취소하는 발주현황 화면을 만든다.
구조는 구매요청현황(`20261112_003`)과 같고, 그 근간은 영업관리의 수주현황·출하계획·출하등록 화면 구조다.
(2026-11-13 사용자 지시: 조회·상세·행 삭제·취소를 한 번에 만들고 함께 테스트한다.)

## 확정 범위

### 화면 흐름
- 메뉴 `발주관리 > 발주현황`(`/materials/order/order-status`). 권한은 READ, EXCEL, 역할 권한은 `ORDER_STATUS`(수주현황)에서 복사한다. 대상 테넌트는 1이다.
- 검색 영역(빠른 검색 + 상세검색) → 품목 행 단위 F1Grid(같은 발주서는 헤더 셀 병합) → 발주번호 클릭 시 오른쪽 상세 패널 → 조회/수정 다이얼로그.
- 다이얼로그는 발주등록 화면을 `embedded` 모드로 띄워 폼과 F1Grid를 공유한다.

### 수정과 행 삭제
- 수정 가능한 항목: 발주일, 부가세구분·부가세여부, 비고, 행의 수량·단가·납기일·입고창고·검사대상·세액·비고.
- 구매처, 통화, 출처, 품목은 바꾸지 않는다. 새 행 추가는 없다(필요하면 새 발주 등록).
- **행 삭제**: 수정 다이얼로그에서 행을 체크해 [선택 행 빼기] 후 저장한다. 모든 행을 뺄 수는 없고, 모두 빼려면 발주 취소를 쓴다.
  - 확정 불러오기 발주: 행을 지우면 확정 행의 잔량이 자동으로 되살아난다.
  - 직접 발주: 자동 생성된 구매요청 행도 함께 지우고 확정 합계를 다시 계산한다. 값을 수정하면 자동 생성된 구매요청·확정 값도 맞춰 갱신한다.
- 가입고가 있는 행은 삭제·취소할 수 없다. 가입고 테이블이 아직 없어 지금은 검증하지 않고, 가입고 작업에서 추가한다(사양서에 기록).

### 발주 취소
- 발주서 전체를 취소한다(`use_at = 'N'`, 이력 보존). 취소된 발주는 조회만 되고 수정할 수 없다.
- 확정 불러오기 발주: 확정 행의 기발주 수량에서 빠지므로 잔량이 복원되고 다시 발주할 수 있다.
- 직접 발주: 자동 생성된 확정(MC)을 취소하고 구매요청(MR)을 삭제 처리한다.

### 백엔드·DB
- `GET /api/v1/materials/purchase-order-status` 목록, `PUT /api/v1/materials/purchase-orders/{id}` 수정, `POST /api/v1/materials/purchase-orders/{id}/cancel` 취소. 단건 조회는 기존 `GET /{id}`를 쓰되 확정 기준값을 함께 돌려준다.
- 스키마 변경은 없다. 메뉴 seed·롤백·변경 이력(`20261113_005`)만 추가(발주관리 그룹은 `20261113_004`)한다. SQL은 사용자가 직접 실행한다.

## 제외 범위
- 발주서 출력, 전자결재 버튼, 입고대기마감, 가입고 연동·차단, 재고량 값 연결, 일괄적용.

## 구현 절차
1. 계획서, 상세사양서
2. 메뉴 SQL(`20261113_005`) 두 경로 사본
3. 백엔드 실패 테스트 → 구현(목록, 수정, 취소)
4. 프론트 실패 테스트 → 구현(현황 화면, 등록 화면 view/edit 모드, 대시보드 연결)
5. 검증: 집중 테스트, 빌드, JDK 8 컴파일, 브라우저
6. 사용자 SQL 실행 후 MCP 확인, 결과 문서 `docs/result/20261113/purchase-order-status`

## 완료 조건
- 발주현황에서 검색 조건으로 발주 목록이 조회되고 발주번호를 눌러 상세를 볼 수 있다.
- 수정 다이얼로그에서 값 수정과 행 삭제가 저장되고, 목록과 헤더 금액이 갱신된다.
- 발주 취소 후 확정 잔량이 복원되고, 직접 발주는 자동 생성된 MR/MC도 정리된다.
- 취소된 발주는 수정·취소할 수 없다.

## 추가 범위: 입고대기마감 (2026-11-13 사용자 확정)

- MES는 참고용이며 별도 화면(발주진행관리)을 만들지 않는다. 발주 행의 입고대기마감은 **발주현황**에서 처리한다. 발주대기마감은 발주 화면에 두지 않는다(구매요청확정에서 처리).
- 마감은 **마감만** 처리한다. 마감하면서 수량·단가 등 다른 값을 수정하는 동작은 없다. 수정과 마감은 분리한다.
- 상세 패널 더보기 메뉴: `자세히보기`, `수정`, `입고대기마감`. 입고대기마감 다이얼로그는 마감 체크박스 외 전부 읽기 전용이고 하단에 `저장`·`닫기`만 둔다. 체크를 풀고 저장하면 마감이 취소된다.
- 저장은 마감 전용 API(`PUT /api/v1/materials/purchase-orders/{id}/receipt-close`)로 `receipt_close_at`만 바꾼다.
- 발주현황 목록에 입고대기마감 컬럼(조회용)을 추가한다. 취소된 발주는 마감을 바꿀 수 없다.
- 권한은 수정과 같이 발주등록 메뉴의 UPDATE 권한을 쓴다(구매요청확정의 발주대기마감과 같은 방식).
- 마감된 행을 가입고 후보에서 제외하는 처리는 가입고등록 작업에서 한다. 스키마 변경은 없다(`receipt_close_at`은 `20261113_002`에서 생성).
