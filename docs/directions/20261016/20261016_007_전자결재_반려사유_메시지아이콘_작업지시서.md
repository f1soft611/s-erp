# 전자결재 반려 사유 메시지 아이콘 표시 작업지시서

## 작업 목적

전자결재 상세 결재선에서 반려 사유를 도장 아래에 직접 표시하지 않고, 반려 도장에 작은 메시지 아이콘을 두어 클릭할 때 사유를 확인할 수 있게 한다.

- 계획서: [20261016_007 계획서](../../plan/20261016/20261016_007_전자결재_반려사유_메시지아이콘_계획서.md)
- 상세 사양서: [20261016_007 상세 사양서](../../spec/20261016/20261016_007_전자결재_반려사유_메시지아이콘_상세사양서.md)

## 확정 요구사항

- 상세 결재선에서 `REJECTED`이며 `actionComment`가 공백이 아닌 승인 참여자에만 메시지 아이콘을 표시한다.
- 아이콘은 선택된 시안처럼 반려 도장의 오른쪽 위에 작게 겹친다. 결재 카드 크기, 순서, 도장 상태 표현은 유지한다.
- 아이콘은 접근성 이름을 가진 버튼이며 클릭 또는 키보드 활성화 시 해당 승인자의 반려 사유를 도장 옆 팝오버로 보여준다.
- 사유 전문이 줄바꿈되어 보이고 팝오버는 바깥 클릭 또는 Escape로 닫힌다.
- 반려 사유는 도장 아래에서 제거한다. 사유가 없는 반려선은 아이콘을 표시하지 않는다.
- 반려 이외 상태의 기존 의견 표시, 상세 API, 타입, 데이터 저장 및 결재 상태 전이는 변경하지 않는다.

## 작업 절차

1. 이 작업지시서와 승인된 설계, 계획서, 상세 사양서를 기준으로 범위를 확인한다.
2. `frontend/tests/document-write-page.test.tsx`에 반려 사유 아이콘/팝오버, 빈 사유, 반려 외 의견 유지 테스트를 추가하고 실패를 확인한다.
3. `DocumentApprovalDetailFeed.tsx`에 조건부 메시지 버튼과 앵커 팝오버를 추가하고 반려 사유의 인라인 표시만 제거한다.
4. 집중 테스트와 프론트엔드 빌드를 실행한다.
5. 375px, 768px, 1280px 실제 브라우저에서 결재선의 아이콘 위치와 팝오버 줄바꿈을 확인한다.
6. 비식별 캡처와 원인·변경·검증 결과를 [결과 폴더](../../result/20261016/rejection-reason-message-icon/)에 기록한다.

## 완료 기준

- 반려 사유가 있을 때 메시지 아이콘이 표시되고, 누르면 해당 사유가 팝오버에 나타난다.
- 반려 사유가 도장 아래에 인라인으로 노출되지 않고, 빈 사유에는 아이콘이 없다.
- 키보드 활성화, 바깥 클릭, Escape 동작이 검증된다.
- `RETURNED` 등 반려 외 상태의 기존 의견 표시 및 결재선 레이아웃이 보존된다.
- 관련 테스트, 프론트엔드 빌드, 지정 뷰포트 브라우저 확인 및 결과 문서/캡처가 완료된다.

## 제외 범위

- 백엔드, API, DB, 타입, 사유 입력·저장, 권한 및 결재 상태 전이 변경
- `RETURNED`, `APPROVED` 상태 의견 표시 변경
- 결재선 전반의 재배치 또는 반응형 동작 변경
