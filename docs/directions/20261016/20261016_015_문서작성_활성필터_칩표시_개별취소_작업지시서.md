# 20261016_015 문서작성 활성 필터 칩 표시 및 개별 취소 작업지시서

## 사용자 요청 및 승인 설계

문서작성 피드/리스트에서 `전체 조회` 버튼 대신 상단 기존 필터 위치에 현재 적용된 조건을 `#값 ×` 칩으로 보여 주고, 각 X로 해당 조건만 취소한다.

- [승인 설계](../../superpowers/specs/2026-10-16-document-write-filter-chips-design.md)
- 이전 `전체 조회` 버튼 작업은 [20261016_012 작업지시서](./20261016_012_문서작성_전체조회_필터초기화_작업지시서.md)에 기록되어 있다. 이번 지시서는 그 화면 동작을 대체한다.

## 승인된 동작

- 현재 선택된 결재 범위, 업무구분, 특정 알림 문서 조건만 같은 툴바 위치에 칩으로 표시한다.
- 칩 라벨은 범주 접두어 없이 `#결재 진행 중`, `#기안서`, `#문서제목`처럼 실제 선택값만 사용한다.
- 한 칩의 X는 해당 조건만 취소하고 나머지 조건은 유지한다.
- 취소 후 기존 조회 흐름으로 현재 피드/리스트 데이터가 갱신되며 보기 방식은 유지한다.
- 필터가 없으면 칩을 표시하지 않는다. 전체 초기화 버튼은 제거한다.
- 좁은 화면에서 칩은 줄바꿈하고 페이지 가로 넘침이 없어야 한다.
- 기존 메뉴/범위/알림 필터, 로딩 및 오류 처리를 유지한다. API, backend, DB는 변경하지 않는다.

## 작업 절차

1. [상세 사양](../../spec/20261016/20261016_015_문서작성_활성필터_칩표시_개별취소_상세사양서.md)과 [계획서](../../plan/20261016/20261016_015_문서작성_활성필터_칩표시_개별취소_계획서.md)를 확인한다.
2. 기존 reset 테스트를 독립 칩 생성/제거 테스트로 대체하고, 페이지 테스트에서 버튼 대신 칩과 개별 취소를 검증한다. 구현 전에 새 테스트의 실패를 확인한다.
3. 공유 scope label helper, 훅의 칩 descriptor/개별 취소 handler, 페이지의 칩 렌더링을 구현한다.
4. 집중 Vitest, production build, lint 및 diff 검사를 수행한다.
5. 인증 가능한 브라우저에서 375px/768px/1280px 레이아웃과 가로 넘침을 확인하고 결과 문서에 기록한다. 인증할 수 없으면 제한을 명시하고 캡처를 완료한 것처럼 표현하지 않는다.

## 완료 조건

- `전체 조회` 버튼은 더 이상 표시되지 않는다.
- 활성 조건에 맞는 `#값` 칩이 표시되고, X 버튼은 접근 가능한 이름으로 식별된다.
- scope, kind, 특정 문서 칩의 삭제가 각각 독립적으로 동작하고 남은 필터가 유지된다.
- 현재 피드/리스트 보기 방식이 유지되며 기존 조회 서비스에 남은 필터만 전달된다.
- 기본 상태는 칩이 없고 좁은 화면에서 가로 overflow가 없다.
- 관련 테스트/build 및 결과 문서가 존재하고 기존 미커밋 변경을 보존한다.
