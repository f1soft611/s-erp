# 20261016_014 문서작성 날짜 표시 우선순위 작업지시서

## 작업 목적

문서작성 화면의 피드, 리스트, 문서 상세 및 우측 패널에서 동일한 문서 날짜를 표시한다. 표시 우선순위는 상신일, 수정일, 작성일 순서로 적용한다.

## 기준 문서

- 승인 설계: [문서작성 날짜 표시 설계](../../superpowers/specs/2026-10-16-document-write-display-date-design.md)
- 구현 계획: [문서작성 날짜 표시 구현 계획](../../superpowers/plans/2026-10-16-document-write-display-date.md)

## 승인된 동작

- 날짜 필드는 `submittedAt` → `updatedAt` → `createdAt` 순서로 선택한다.
- 앞선 필드가 `null`, `undefined` 또는 빈 문자열이면 다음 필드를 사용한다.
- 선택된 날짜는 기존 `YYYY.MM.DD` 표시 형식을 유지한다.
- 피드 카드, 리스트 항목, 우측 상세 패널의 작성자/결재선 메타, 우측 `놓치지 마세요` 알림 패널이 동일한 우선순위를 사용한다.
- `놓치지 마세요` 패널은 선택된 날짜 원천에 맞춰 `상신일`, `수정일`, `작성일` 라벨을 표시한다. 표시 가능한 날짜가 없으면 기존 빈 날짜 표시를 유지한다.
- 좁은 화면에서 상세 패널의 작성자 메타가 날짜를 말줄임으로 숨기지 않도록 줄바꿈을 허용한다.
- 날짜 데이터가 세 필드 모두 없을 때 날짜를 생성하거나 다른 필드에서 추정하지 않는다.
- 댓글, 결재 이력 등 문서 이외의 날짜 표시는 변경하지 않는다.

## 변경 범위

- `frontend/src/pages/groupware/documents/write/`의 날짜 선택/매핑 및 표시 컴포넌트
- 문서 날짜 우선순위와 모든 화면 표시를 검증하는 프런트엔드 테스트
- 본 작업의 날짜별 지시서, 계획서, 상세 사양서 및 결과 문서/스크린샷

백엔드, API 계약, DB, 문서 날짜 저장 동작은 변경하지 않는다. 기존 미커밋 변경은 보존하고 날짜 표시와 직접 관련된 부분만 수정한다.

## 작업 절차

1. 계획서 및 상세 사양서와 코드의 날짜 표시 지점을 확인한다.
2. 날짜 selector와 날짜 매핑 테스트를 먼저 추가하고 실패를 확인한다.
3. 공통 날짜 선택 로직을 구현하고 피드, 리스트, 상세 패널, 알림 패널에서 재사용한다.
4. 회귀 테스트, 프런트엔드 빌드, 브라우저 375px/768px/1280px 확인을 수행한다.
5. 테스트/빌드/브라우저 결과와 스크린샷 경로를 결과 문서에 기록한다.

## 완료 조건

- 상신일이 존재하면 상신일을 표시한다.
- 상신일이 없고 수정일이 존재하면 수정일을 표시한다.
- 상신일과 수정일이 없고 작성일이 존재하면 작성일을 표시한다.
- 위 동작이 피드, 리스트, 문서 상세 및 우측 패널에 일관되게 반영된다.
- 알림 패널의 날짜 라벨이 실제 사용한 날짜 원천과 일치한다.
- 없는 날짜를 임의로 생성하지 않으며, 날짜 표시 외 동작/API/DB에는 변화가 없다.
- 테스트, 빌드, 가능한 브라우저 검증 및 결과 문서가 준비된다.
