# 20261016_012 문서작성 전체 조회 필터 초기화 작업지시서

## 사용자 요청

문서작성 페이지에서 피드/리스트로 필터 조회한 다음 전체 문서 조회로 돌아가는 방법이 없다.

## 승인된 동작

- 피드/리스트 공통 상단 필터 영역에 `전체 조회` 버튼을 제공한다.
- 업무구분, 결재 범위, 특정 문서 ID 중 하나라도 필터가 적용된 경우에만 버튼을 표시한다.
- 버튼을 누르면 업무구분을 미선택, 결재 범위를 `ALL`, 특정 문서 ID를 미선택으로 되돌린다.
- 현재 피드/리스트 보기 방식은 유지한다. 기존 목록 요청 흐름으로 전체 목록과 요약을 다시 조회한다.
- 기본 전체 조회 상태에서는 버튼을 표시하지 않는다.
- 기존 개별 필터 동작, 상세 패널 동작, 요청 오류 및 재시도 동작은 유지한다.
- 기존 사용자 미커밋 변경은 보존한다. 백엔드/API/DB는 변경하지 않는다.

## 작업 절차

1. 계획서 및 상세 사양서를 확인한다.
2. 훅과 페이지 테스트에 실패 테스트를 추가하고, 대상 테스트가 실패하는지 확인한다.
3. 훅의 단일 필터 초기화 동작과 페이지의 조건부 `전체 조회` 버튼을 구현한다.
4. 대상 Vitest, 프론트엔드 production build를 실행한다.
5. 가능한 경우 `/groupware/doc/write`에서 375px, 768px, 1280px 화면을 확인하고 결과/스크린샷을 기록한다.

## 완료 기준

- 결재 상태 범위, 업무구분, 특정 알림 문서 필터 뒤에 버튼으로 전체 목록에 돌아올 수 있다.
- 초기화 후 목록 요청은 `ALL`, `undefined`, `undefined` 필터를 사용하며 피드 요청에는 기존 `includeDetails=true`가 유지된다.
- 전체 조회 버튼은 활성 필터가 있을 때만 표시되고, 초기화 후 현재 보기 방식이 그대로 남는다.
- 기존 미커밋 변경을 덮어쓰지 않고, 집중 테스트/build 및 결과 문서가 남는다.
