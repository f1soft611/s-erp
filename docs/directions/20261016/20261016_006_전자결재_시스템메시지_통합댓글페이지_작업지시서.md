# 전자결재 시스템 메시지 통합 댓글 페이지 작업지시서

## 목적

문서작성 화면에서 시스템 메시지가 사용자 댓글 페이지와 별도로 전부 표시되는 동작을 수정한다. 사용자 댓글과 시스템 메시지를 하나의 최신순 페이지 흐름으로 제공해 기본 표시량, 이전 페이지, 전체/남은 건수가 서로 일치하도록 한다.

## 승인 요구사항

- 최상위 사용자 댓글 스레드 하나와 시스템 메시지 하나를 각각 페이지 항목 하나로 계산한다.
- 기본 페이지는 통합 항목 최신 3개, 이전 페이지는 통합 항목 최대 20개를 제공한다.
- 사용자 댓글의 답글은 부모 스레드에 포함하며 별도 페이지 항목으로 계산하지 않는다.
- 페이지 선택, 정렬, 커서, 이전 페이지 여부, 전체 건수, 남은 건수는 사용자 댓글과 시스템 메시지를 함께 기준으로 한다.
- 시스템 메시지는 기존 시스템 메시지 스타일을 유지하고 사용자 댓글 조작 대상이 되지 않는다.
- 기존 문서 피드 선조회와 상세 패널 댓글 조회가 같은 페이지 계약을 사용한다.
- 현재 공통 댓글 저장소를 재사용하고 DB 스키마는 변경하지 않는다.
- 공지사항 및 다른 댓글 기능은 변경하지 않는다.

## 작업 절차

1. 승인된 설계 문서와 이 작업지시서를 기준으로 날짜별 계획서와 상세 사양서를 작성한다.
2. 백엔드/API 데이터 계약을 수정하기 전에 등록된 읽기 전용 PostgreSQL MCP에서 테이블 목록과 공통 댓글 테이블 구조를 확인한다. 확인할 수 없으면 실패 사실과 저장소 대체 근거를 기록한다.
3. 통합 페이지의 사용자 댓글 루트·시스템 메시지·답글·커서 계약에 대한 백엔드 및 프런트엔드 회귀 테스트를 먼저 추가한다.
4. 백엔드 페이지 조회가 혼합된 최상위 항목을 최신순으로 선택하고, 선택된 사용자 댓글의 답글 및 첨부파일을 함께 반환하도록 수정한다.
5. 피드 선조회와 상세 댓글 API 응답에 시스템 메시지 페이지, 통합 건수 및 통합 커서를 적용한다.
6. 프런트엔드는 시스템 메시지 ID를 포함한 페이지 응답을 검증하고, 댓글·시스템 메시지를 같은 정렬/이전 페이지 흐름으로 표시한다.
7. 집중 백엔드·프런트엔드 테스트와 프런트엔드 빌드를 수행한다. 문서작성 화면을 375px, 768px, 1280px에서 확인하고 결과 문서에 스크린샷을 포함한다.
8. 결과 문서에 재현 조건, 변경 내용, DB MCP 확인 또는 미확인 근거, 검증 결과를 기록한다.

## 완료 기준

- 기본 화면에 사용자 댓글 루트와 시스템 메시지가 합쳐서 최대 3개 표시된다.
- 이전 페이지를 반복 조회하면 두 항목 유형 모두 최대 20개 단위로 중복 없이 추가되고 더 오래된 항목이 없을 때 버튼이 사라진다.
- 사용자 댓글의 답글은 부모 댓글에 계속 표시되며 페이지 개수를 늘리지 않는다.
- 통합 총 건수와 남은 건수는 시스템 메시지를 한 번만 포함하고 답글을 별도 항목으로 세지 않는다.
- 시스템 메시지 표시 스타일, 사용자 댓글 쓰기/답글/수정/삭제/첨부, 권한, 에러 및 재시도 동작이 유지된다.
- 일반 문서 상세와 피드 선조회에서 같은 페이지 동작이 검증된다.
- DB 스키마 변경 없이 백엔드/API 및 프런트엔드 테스트와 빌드가 통과한다.
- 결과 문서 및 375px/768px/1280px 브라우저 스크린샷이 기록된다.

## 제외 범위

- DB 테이블·컬럼·인덱스·데이터 변경
- 사용자 댓글 작성/수정/삭제/답글 권한 변경
- 시스템 메시지 생성 시점이나 문구 변경
- 공지사항 댓글 페이지 및 전자결재 이력 생성 로직 변경
- 문서 피드 카드의 레이아웃 재설계
