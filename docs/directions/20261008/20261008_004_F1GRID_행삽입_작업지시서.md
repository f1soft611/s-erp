# 20261008_004 F1-Grid 행 삽입 작업지시서

## 작업 목적

긴 F1-Grid에서 사용자가 기준 행을 지정해 신규 행을 바로 위나 아래에 삽입할 수 있도록 한다. 기존 목록 끝 행 추가와 F1Tree의 계층형 추가는 유지한다.

## 승인 요구사항

- 일반 F1Grid에서 데이터 행을 우클릭하면 `위에 행 삽입`과 `아래에 행 삽입`을 제공한다.
- 기준 행 바로 앞/뒤에 신규 행을 넣고, 신규 행을 선택해 첫 편집 가능 셀에 포커스를 주며 화면에 보이도록 스크롤한다.
- 행 폼 사용 화면에서는 폼 적용이 성공한 뒤 기준 행 위치에 삽입한다. 취소나 검증 실패로는 행 데이터를 변경하지 않는다.
- 정렬 또는 필터가 적용 중이면 두 삽입 메뉴를 비활성화하고 해제 필요 안내를 표시한다. 정렬/필터를 자동 변경하지 않는다.
- 기존 `행 추가`와 `F1GridRef.addRow()`는 계속 목록 끝에 추가한다.
- F1Tree의 루트/자식 추가 동작은 변경하지 않는다.

## 작업 절차

1. 날짜별 계획서/상세 사양서 작성 및 승인 요구사항 반영 여부 확인
2. GridState의 지정 인덱스 삽입과 inserted 변경 추적에 대한 실패 테스트 작성
3. 기존 append 경로를 유지하는 인덱스 삽입 기능 구현
4. 컨텍스트 메뉴의 기준 행 위/아래 삽입, 정렬/필터 비활성 상태, 행 폼 흐름을 테스트 우선으로 연결
5. 가상 스크롤에서도 신규 행이 렌더링되고 포커스되는지 검증
6. F1-GRID 문서, 결과 보고서, 375px/768px/1280px 스크린샷 갱신

## 완료 기준

- 위/아래 삽입 시 행 순서, row ID/index lookup, inserted 상태, 변경 데이터가 일치한다.
- 신규 행이 스크롤 위치와 무관하게 화면에 표시되고 편집 포커스를 받는다.
- 정렬/필터가 적용 중인 경우 삽입 메뉴가 비활성화되고 이유를 확인할 수 있다.
- 기존 append 및 F1Tree 추가 테스트가 계속 통과한다.
- 관련 Vitest와 프론트엔드 빌드가 통과하고, 결과 보고서와 세 화면 폭 스크린샷이 생성된다.

## 범위 제외

- 기존 `행 추가`의 위치 변경 또는 전역/화면별 추가 위치 설정
- 정렬/필터 상태 자동 해제 또는 정렬 결과에 대한 삽입 순서 재정렬
- F1Tree 자식/루트의 계층 순서 변경
- 백엔드/API/DB 변경
