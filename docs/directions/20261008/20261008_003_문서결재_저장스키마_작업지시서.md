# 20261008_003 문서 결재 저장 스키마 작업지시서

## 작업 목적

문서작성 화면의 본문 초안과 결재 참여자 처리 상태를 저장할 PostgreSQL 스키마 초안을 작성한다. 일반 댓글과 결재 처리 시스템 메시지는 기존 `tb_common_comment`를 확장해 함께 표시하고, 댓글 좋아요는 별도 관계 테이블에 저장한다.

## 승인된 범위

- 신규 테이블: `tb_electronic_approval_main`, `tb_electronic_approval_line_info`, `tb_common_comment_like`
- 기존 테이블 확장: `tb_common_comment.comment_type`, `tb_common_comment.event_type`
- 첨부 메타데이터는 `tb_common_file`을 `owner_type='APPROVAL'`, `owner_id=<electronic_approval_id>`로 재사용한다.
- 현재 기안 양식 기준 테이블과 공통 파일 테이블은 중복 생성하지 않는다.
- 참조 사용자는 결재선 테이블의 `REFERENCE` 참여 유형으로 보존하되 처리 상태를 갖지 않는다.
- 결재자별 처리 상태와 의견은 결재선 행에 저장하고, 같은 처리의 사용자 표시 메시지는 공통 댓글의 SYSTEM 행으로 표현한다.

## 범위 제외

- `tb_document_attachment`, `tb_electronic_approval_history_main`, `tb_electronic_approval_history_like` 신규 생성
- 기안 업무 분류 테이블 3종 복제
- 저장/상신/승인 API 또는 프론트엔드 저장 기능 구현
- 공통 댓글/파일 API의 문서 권한 검사 구현
- 어떠한 개발·공유·운영 데이터베이스에도 DDL 적용

## 작업 절차

1. 작성 화면, 인증 모델, 공통 댓글 매퍼 및 스키마 이력에서 실제 필드·식별자 계약을 확인한다.
2. 컬럼, 코드, 제약, 인덱스, 삭제/롤백 동작을 상세 사양으로 고정한다.
3. `backend/DATABASE/20261008`에 forward/rollback SQL과 변경 이력 문서를 작성한다.
4. 같은 파일을 `docs/database/20261008`에 복제하고 누적 스키마 문서를 갱신한다.
5. forward/rollback 대칭성, 양쪽 파일 일치, 정적 SQL 검토 및 저장소 변경 범위를 확인한다.
6. 결과 보고서에 계약 확인 근거, 검증 결과, 미적용 상태와 후속 권한 요구사항을 기록한다.

## 완료 기준

- 결재 본문, 결재 참여자, 참조자를 저장할 수 있는 2개 결재 테이블을 정의한다.
- 결재 참여자의 처리 상태/유형/시각/의견 및 시스템 메시지 구분을 표현한다.
- 기존 일반 댓글 행이 `USER`로 호환되고 SYSTEM 메시지는 일반 사용자 수정/삭제/좋아요 대상에서 제외되도록 규칙을 명시한다.
- 좋아요는 tenant/comment/user별 중복을 막고 본인 좋아요 취소 동작을 명시한다.
- 첨부/분류/댓글 기반 구조를 중복 생성하지 않고, 롤백은 본 변경분만 대상으로 한다.
- 두 디렉터리의 SQL/이력 파일은 바이트 단위로 동일하다.
- 실제 DB에 DDL을 실행하지 않았음을 기록한다.
