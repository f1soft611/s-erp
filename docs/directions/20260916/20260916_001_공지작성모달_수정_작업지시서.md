# 20260916_001 공지 작성 모달 전면 재수정 작업지시서

## 작업 목적

공지 작성 모달은 제목, 본문, 첨부 영역이 하나의 연속된 입력 영역처럼 보이도록 정리한다. 사용자가 첨부파일을 추가할 때, 첨부파일 목록이 공지사항 페이지의 첨부 리스트처럼 자연스럽게 아래에 표시되도록 구성하며, 기존의 분리된 하단 툴바 형태와 별도 첨부 섹션 감각을 제거한다.

## 대상 파일

- `frontend/src/pages/groupware/community/notice/components/NoticeComposerDialog.tsx`
- `frontend/src/shared/components/f1-editor/**`
- `frontend/package.json`

## 수정 범위

1. `NoticeComposerDialog`에서 커스텀 `f1-editor` 기반 입력 영역을 제거하고 Tiptap 에디터를 기본 메커니즘으로 적용한다.
2. 제목 입력 영역과 본문 에디터/첨부 영역을 하나의 연속된 구성으로 묶어, 마치 제목-본문-첨부가 한몸처럼 보이도록 레이아웃을 정리한다.
3. 첨부파일 목록은 공지사항 페이지의 첨부파일 리스트 스타일에 맞춰 파일명, 확장 아이콘, 삭제 버튼이 포함된 카드형 목록으로 표현한다.
4. 상단에 별도 첨부 영역을 분리하지 않고, 본문 영역 하단에 첨부 리스트가 자연스럽게 연결되도록 구성한다.
5. 불필요한 독립형 하단 툴바를 정리하고, 에디터의 기본 툴바 구조를 유지하되 필요한 첨부 기능은 본문 영역과 조화되게 배치한다.
6. 기존 `f1-editor` 전용 파일 및 구현이 남지 않도록 정리한다.
7. 커스텀 에디터 관련 불필요한 확장, 타입, 예제 코드의 남은 사용처를 정리한다.
8. 공지 작성 모달의 전체 시각 구조를 기존 그룹웨어 디자인과 일관되게 유지한다.

## 제외 범위

- 서버 업로드 API 신규 설계
- 공지 저장 API 연동 확장
- 다른 공지 페이지 레이아웃 전면 리팩터링
- 다른 화면의 에디터 관련 전역 변경

## 완료 기준

- `f1-editor`가 공지 작성 모달에서 더 이상 사용되지 않는다.
- 제목, 본문, 첨부 영역이 하나의 연속된 입력 블록처럼 보이는 레이아웃으로 구성된다.
- 첨부파일 리스트가 공지사항 페이지 첨부 리스트와 유사한 형태로 표시된다.
- 에디터 영역과 첨부 리스트가 시각적으로 분리되지 않고 자연스럽게 이어진다.
- 불필요한 하단 툴바/분리형 첨부 UI를 제거하고, 필요한 툴바는 기본 구조에 맞게 유지한다.
- `frontend/src/shared/components/f1-editor` 관련 파일이 제거되거나 더 이상 사용되지 않는다.
- 관련 테스트와 빌드 검증이 통과한다.
