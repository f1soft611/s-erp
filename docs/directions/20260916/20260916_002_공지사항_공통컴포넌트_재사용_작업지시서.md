# 20260916_002 피드/첨부/댓글 공통 컴포넌트 재사용화 작업지시서

## 작업 목적

공지사항 화면에 존재하는 첨부 파일 영역과 댓글 영역을 공통 컴포넌트 구조로 분리해, 공지사항 전용이 아니라 다른 게시판 또는 피드형 화면에서도 재사용할 수 있게 만든다.

핵심은 피드, 첨부, 댓글을 각각 별도 공통 컴포넌트 단위로 나누는 것이다. 한 번에 큰 단위의 피드 전체를 공통화하는 것이 아니라, 사용처별로 조합 가능한 3개 재사용 컴포넌트로 분리해 범용성을 확보한다.

기존에 공통 컴포넌트 이름이 `Notice*` 계열로 되어 있어 실제로는 공통 컴포넌트가 아니라 공지사항 전용 컴포넌트처럼 보인다. 따라서 이 작업은 이름과 역할을 기능 중심의 범용 컴포넌트로 정리하면서, 화면 동작은 그대로 유지하는 방식으로 진행한다.

## 명명 원칙

- `NoticeAttachmentList`처럼 공지사항 전용 이름은 공통 컴포넌트에 적합하지 않다.
- 공통 컴포넌트는 기능 중심으로 3개로 분리한다: `FeedList`, `AttachmentList`, `CommentThread`.
- 공지사항 페이지는 이 3개의 공통 컴포넌트를 조립하는 사용자 화면으로 두고, 공통 구현체는 게시판/피드 공통 계층으로 이동시킨다.
- `groupware`라는 역할 이름을 강제하지 않고, 재사용 범위를 기능 중심으로 넓게 잡는다.

## 수정 범위

1. 피드 영역을 공통 컴포넌트로 정리한다.
   - `NoticeFeedList`의 카드 레이아웃, 메타 정보, 본문 영역, 액션 영역 중 재사용 가능한 구조를 `FeedList`로 분리한다.
   - 상위 화면에서 제목/본문/작성자/상태/액션 콜백을 주입할 수 있도록 인터페이스를 모듈화한다.
   - 공지사항 페이지는 이 피드 컴포넌트를 재사용하는 화면으로 축소한다.

2. 첨부 파일 영역을 공통 컴포넌트로 정리한다.
   - 파일명, 확장 아이콘, 다운로드/삭제 액션, 빈 상태 처리, 다크 모드 색상 지원을 공통화한다.
   - 공지사항 외 다른 화면에서도 동일한 props로 재사용 가능하도록 인터페이스를 정리한다.

3. 댓글 영역을 페이지 전용 로직에서 분리해 공통 댓글 컴포넌트로 만든다.
   - 작성자, 시간, 본문, 답글 트리 렌더링을 공통적으로 처리한다.
   - 댓글 입력, 답글 버튼, 답글 트리 확장 구조를 재사용 가능한 형태로 추상화한다.
   - 현재 공지사항 페이지 동작과 동일한 UX를 유지한다.
   - 이름은 `NoticeCommentList` 대신 `CommentThread` 같은 범용 네이밍으로 정리한다.

4. 공지사항 페이지는 3개 공통 컴포넌트를 조립하는 형태로 리팩터링한다.
   - `NoticeFeedList`는 상세 렌더링만 담당하고, 첨부/댓글 UI는 공유 컴포넌트로 분리한다.
   - 기존 `NoticeFeedList`의 이벤트 핸들러와 데이터 구조는 유지하면서 구현을 모듈화한다.
   - 이 페이지 자체는 공지사항 UI라 하더라도, 내부 기본 컴포넌트는 공통 계층에 의존하도록 정리한다.

5. 컴포넌트 설계를 범용적으로 유지한다.
   - 각 컴포넌트는 단일 책임을 가진다: 피드는 게시글 카드, 첨부는 파일 목록, 댓글은 쓰기/답글/트리 구조.
   - 서로 조합 가능하도록 props와 이벤트 인터페이스를 분리한다.
   - 공통 컴포넌트는 기능 중심으로 관리하고, 해당 화면이 그룹웨어인지 여부보다 재사용 범위를 우선한다.

6. 기존 notice 특화 디자인과 경고/버튼/상태 표현을 유지한다.
   - 기존 공지사항 페이지의 색상, 간격, 타이포 그래피는 변경하지 않는다.
   - 공통화 과정에서 UI가 이상하게 변형되지 않도록 기존 시각 구조를 보존한다.

## 제외 범위

- 댓글 저장/삭제 백엔드 연동 확장
- 다른 기능 화면 전체 리팩터링
- 게시판 전반의 데이터 모델 전면 변경
- 불필요한 전역 상태 관리/리듀서 도입

## 완료 기준

- 피드, 첨부, 댓글이 각각 별도 공통 컴포넌트로 분리되어 재사용 가능하다.
- 공통 컴포넌트의 이름이 `Notice*` 전용이 아닌 기능 중심의 범용 네이밍으로 정리된다.
- 공지사항 페이지는 3개 공통 컴포넌트를 조립하는 화면으로 유지되면서 동작이 유지된다.
- 기존 첨부/댓글 UX와 접근성 속성이 보존된다.
- 다른 피드형 화면에서도 동일한 컴포넌트를 조립하는 방식으로 확장할 수 있다.
- 관련 테스트 및 빌드 검증을 통과한다.
