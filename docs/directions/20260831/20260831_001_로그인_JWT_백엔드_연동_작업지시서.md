# 20260831*001*로그인*JWT*백엔드*연동*작업지시서

## 1. 작업 개요

현재 로그인 화면([frontend/src/pages/auth/LoginPage.tsx](../../../frontend/src/pages/auth/LoginPage.tsx))은 [authService.ts](../../../frontend/src/shared/services/authService.ts)에서 목업(mock) 처리로 로그인 성공을 흉내내고 있으며, 실제 백엔드 JWT 로그인 API(`/auth/login-jwt`)와 연동되어 있지 않다.

백엔드에는 이미 JWT 로그인 컨트롤러/서비스/토큰 유틸이 구현되어 있으나([EgovLoginApiController](../../../backend/src/main/java/egovframework/let/uat/uia/web/EgovLoginApiController.java)), 실제 인증 대상 DB(`s-erp_central`)가 아직 생성되어 있지 않고, 로그인 화면에서 입력하는 "업체코드(테넌트 코드)"를 실제 `tenant_id`로 변환하는 로직이 없다.

또한 사용자가 [docs/database/db-schema.md](../../database/db-schema.md)에 `tb_tenant`, `tb_login_account`, `tb_user` 3개 스키마를 문서화하였다.

## 2. 작업 목적

- 로그인 화면에서 입력한 업체코드/사용자ID/비밀번호로 실제 백엔드 JWT 로그인(`/auth/login-jwt`)이 동작하도록 연동한다.
- `docs/database/db-schema.md`에 문서화된 3개 스키마(및 로그인 조회에 필요한 연관 테이블)를 실제 DB에 반영한다.
- 아래 초기 관리자 계정으로 로그인 가능한 시드 데이터를 구성한다.
  - 테넌트코드: `T1358606250`
  - 사업자번호: `1358606250`
  - 테넌트명: `에프원소프트`
  - 계정: `admin` / `f1soft@611`

## 3. 요구사항

1. `s-erp_central` DB(PostgreSQL)에 `tb_tenant`, `tb_login_account`, `tb_user`와 로그인 조회에 필요한 `tb_department`, `tb_role`, `tb_login_account_role` 테이블을 생성한다.
2. 위 테넌트/관리자 계정 시드 데이터를 삽입한다.
3. 백엔드 로그인 서비스가 프론트에서 넘어오는 테넌트 코드(`tenantCode`)를 `tenant_id`로 변환해 로그인 쿼리에 사용하도록 보완한다.
4. 프론트엔드 `authService.ts`가 실제 `/auth/login-jwt` API를 호출하고, 응답으로 받은 JWT를 세션에 저장하도록 수정한다.
5. 변경 이력을 `backend/DATABASE`와 `docs/database`에 날짜별로 기록한다.

## 4. 완료 기준

- 위 관리자 계정으로 로그인 화면에서 실제 로그인이 성공하고 JWT가 발급된다.
- 프론트/백엔드 기존 검증(vitest, 컴파일)이 통과한다.
- 결과 문서가 `docs/result/20260831`에 작성된다.
