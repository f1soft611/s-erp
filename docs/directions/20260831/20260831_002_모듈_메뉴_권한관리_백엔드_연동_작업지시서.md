# 20260831*002*모듈*메뉴*권한관리*백엔드*연동\_작업지시서

## 1. 작업 개요

로그인/JWT 연동([20260831_001](20260831_001_로그인_JWT_백엔드_연동_작업지시서.md))이 완료된 상태에서, 환경설정 > 시스템관리 하위의 **권한관리**, **메뉴관리** 화면과 대시보드 좌측 모듈-메뉴 트리가 아직 프론트엔드 로컬 mock(JSON/배열)만 사용하고 있다.

이번 작업은 실제 모듈/메뉴/역할 데이터를 DB에 등록하고, 백엔드 API로 노출하며, 프론트엔드가 이 API를 사용하도록 연동한다.

## 2. 참고 아키텍처(필수 준수)

백엔드 패키지 구조는 아래 첨부 구조를 그대로 따른다 (전자정부프레임워크 기본 구조 + mapper 추가).

```
<feature>/
  controller/XxxApiController.java
  domain/
    model/XxxVO.java, XxxSaveRequestVO.java, XxxSearchConditionVO.java
    repository/XxxDAO.java
  service/XxxService.java
  service/impl/XxxServiceImpl.java
```

참고 예시: `haccp-cloud`의 `egovframework.let.documents.haccpbase.categories` 패키지.

## 3. 요구사항

1. DB(`s-erp_central`)에 `tb_module`, `tb_menu` 테이블을 신규 생성한다(테넌트별 구성 가능).
2. 모듈 CRUD API, 메뉴 CRUD API, 역할 목록/등록/수정 API(삭제 제외)를 신설한다.
3. 로그인 사용자의 테넌트+역할코드 기준으로 접근 가능한 모듈-메뉴 트리를 반환하는 API(`/api/v1/menus/my`)를 신설하여 대시보드 좌측 메뉴가 이 API를 사용하도록 전환한다.
4. 메뉴별 세부 권한 매핑 화면/테이블은 이번 범위에서 제외한다. 권한은 역할코드 기준 기본 정책(PLATFORM_ADMIN/TENANT_ADMIN: 전체 CRUD, TENANT_USER: read only)으로 처리한다.
5. 관리 API(모듈/메뉴/역할 등록·수정)는 PLATFORM_ADMIN/TENANT_ADMIN 역할만 호출 가능하도록 제한한다.
6. 기존 프론트 mock 데이터(그룹웨어: 종합현황/문서관리, 환경설정 > 시스템관리: 권한관리/메뉴관리/F1 Grid 테스트)와 동일한 트리를 시드 데이터로 등록해 화면 회귀가 없도록 한다.
7. 프론트엔드 `settings/system/menus`, `settings/system/roles`, `dashboard`의 서비스 계층을 실제 API 연동으로 전환한다(화면 컴포넌트 구조는 최대한 유지).
8. 변경 이력을 `backend/DATABASE`와 `docs/database`에 날짜별로 기록한다.

## 4. 완료 기준

- 관리자 계정으로 로그인 후 대시보드 좌측 메뉴가 DB 기반 데이터로 렌더링된다.
- 권한관리/메뉴관리 화면이 실제 API 데이터를 표시하고, 등록/수정이 DB에 반영된다.
- 프론트/백엔드 기존 검증(vitest, 컴파일)이 통과한다.
- 결과 문서가 `docs/result/20260831`에 작성된다.
