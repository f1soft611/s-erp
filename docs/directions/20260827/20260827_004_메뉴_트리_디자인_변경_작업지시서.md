# 20260827*004*메뉴*트리*디자인*변경*작업지시서

## 1. 작업 개요

현재 좌측 메뉴 구조는 기능 구분이 명확하지 않고, 모듈 선택 영역과 하위 메뉴 영역의 계층이 흐려져 ERP형 운영 화면으로 보기 어렵다. 제공된 캡처 이미지를 기준으로 좌측 메뉴 트리를 재설계하고, 메뉴 구조를 더 직관적으로 표현하도록 UI 구성을 정리하는 것이 본 작업의 핵심이다.

본 작업은 메뉴 트리의 시각적 표현을 개선하고, 선택 상태, 그룹 구분, 계층 구조, 아이콘/텍스트 조합을 정리하여 사용자가 빠르게 메뉴를 이해할 수 있도록 하는 것을 목표로 한다.

핵심 의도는 다음과 같다.

- 캡처 이미지 기반의 ERP형 좌측 메뉴 구조를 반영한다.
- 최상위 모듈 영역과 하위 메뉴 트리 영역을 명확히 분리한다.
- 메뉴 그룹의 계층 구조를 시각적으로 구분한다.
- 선택/hover/expanded 상태를 일관되게 표현한다.
- 기존 React 구성에 맞게 재사용 가능한 컴포넌트 구조로 정리한다.

---

## 2. 작업 목적

이번 작업의 목적은 다음 항목을 반영한 메뉴 트리 레이아웃을 구성하는 것이다.

- 좌측 메뉴를 단순 나열형에서 계층형 트리 구조로 재구성한다.
- 상위 모듈 선택과 하위 메뉴 표시가 분리되어 정보를 우선순위별로 보이도록 한다.
- 사용자가 현재 위치를 쉽게 파악할 수 있도록 선택 상태와 확장 상태를 명확히 표시한다.
- 캡처 이미지와 유사한 ERP형 시각 스타일을 반영한다.
- React 컴포넌트 구조를 유지하면서 유지보수 가능한 UI로 정리한다.

---

## 3. 현재 문제점

현재 메뉴 트리는 다음과 같은 한계가 있다.

1. 상위 모듈과 하위 메뉴가 하나의 흐름으로 섞여 있어 구조적 구분이 약하다.
2. 메뉴 항목 간 계층이 부족해 어떤 메뉴가 상위/하위인지 파악하기 어렵다.
3. 선택된 항목, hover 상태, expanded 상태가 시각적으로 구분되지 않는다.
4. 캡처 기준보다 단순 리스트형 UI로 보여 ERP 운영 화면 느낌이 약하다.
5. 메뉴 구조는 있지만, ERP형 정보 계층 구조를 충분히 전달하지 못한다.

---

## 4. 요구사항

### 4.1 메뉴 트리 구조 재설계

- 좌측 메뉴는 최상위 모듈 선택 영역과 하위 메뉴 트리 영역으로 분리한다.
- 각 모듈은 아이콘과 텍스트 조합으로 표시한다.
- 하위 메뉴는 계층형 트리 형태로 나열하고, 선택 상태를 강조한다.
- 현재 선택 모듈과 현재 선택 메뉴를 구분해서 표현한다.
- 캡처와 유사한 ERP형 레이아웃을 우선 반영한다.

### 4.2 모듈 선택 영역

- 상단 모듈 영역은 화면 좌측 넓게 배치되며, 각 항목은 아이콘 중심으로 보이도록 구성한다.
- 선택된 모듈은 강조 배경 또는 테두리로 명확히 구분한다.
- hover 상태는 선택 상태와 구분되도록 약한 강조와 전환 효과를 둔다.
- 선택된 모듈의 하위 메뉴가 즉시 반영되도록 구조를 연결한다.

### 4.3 하위 메뉴 트리 영역

- 선택된 모듈에 따라 아래 메뉴 목록이 동적으로 변경된다.
- 메뉴는 일반 메뉴와 그룹 메뉴를 구분해 보이게 한다.
- 트리의 1depth, 2depth 구조를 들여쓰기, 아이콘, 라인, 배경 차이로 나타낸다.
- 현재 선택된 메뉴는 배경/굵기/텍스트 색상으로 강조한다.
- 확장/축소 상태는 화살표 또는 간단한 아이콘으로 표기한다.

### 4.4 상태 표현

- 기본 상태, hover 상태, active 상태, expanded 상태를 각각 구분한다.
- 선택된 메뉴는 현재 위치를 한눈에 식별할 수 있어야 한다.
- 그룹명과 하위 항목 간의 시각적 우선순위가 분명해야 한다.
- 메뉴가 많아도 전체 그룹 구조가 읽히도록 간격과 배경을 조절한다.

### 4.5 React 반영

- 컴포넌트는 `Sidebar`, `ModuleMenu`, `MenuTree`, `TreeItem` 등으로 분리하여 구성한다.
- 상태는 선택된 모듈 ID와 선택된 메뉴 ID를 분리해 관리한다.
- 데이터는 배열 기반으로 구성하고, 재귀적으로 트리 구조를 렌더링한다.
- 스타일은 기존 theme 및 공통 CSS 패턴을 유지하면서 시각 개선을 반영한다.

### 4.6 캡처 기준 반영

- 제공된 캡처 이미지는 좌측 메뉴 트리의 디자인 기준이 된다.
- 전체적인 배경 톤, 아이콘 크기, 메뉴 간격, 텍스트 스타일, 선택 강조를 캡처에 가깝게 맞춘다.
- 상단 모듈 선택 영역과 하단 메뉴 영역의 분리가 명확해야 한다.
- 메뉴 트리 전체가 ERP 운영 화면처럼 정리되어야 한다.

## 5. 구현 방향

### 5.1 컴포넌트 분리 방향

메뉴 트리 구조는 다음과 같은 단위로 조립한다.

- `DashboardLayout` 또는 메인 보드 레이아웃
- `SidebarPanel`
- `ModuleSelector`
- `MenuTree`
- `TreeNode`
- `useMenuTreeState`
- `menuTreeData` 또는 데이터 변환 유틸

이 구조를 통해 다음을 보장한다.

- UI와 상태 관리의 책임 분리
- 메뉴 구조 변경 시 영향 범위 최소화
- 선택/확장 상태 관리 일관성 유지
- 향후 메뉴 추가 확장 시 재사용성 확보

### 5.2 스타일 방향

- 좌측 패널 배경은 어두운 ERP형 톤으로 구성하되, 텍스트 가독성을 유지한다.
- 모듈 선택 영역과 메뉴 영역의 경계를 명확히 한다.
- 선택된 메뉴는 배경/테두리/폰트 굵기 차이로 시각적으로 강하게 표현한다.
- 그룹 구분 간격, 들여쓰기, 아이콘 크기, 행 높이를 정리해 계층을 보기 쉽게 한다.

### 5.3 데이터 구조 방향

메뉴 트리 데이터는 다음 형식으로 정리한다.

```ts
const menuTree = [
  {
    id: 'dashboard',
    label: '종합 대시보드',
    icon: 'dashboard',
    children: [],
  },
  {
    id: 'system',
    label: '시스템 관리',
    icon: 'settings',
    children: [
      { id: 'user', label: '사용자 관리' },
      { id: 'role', label: '권한 관리' },
    ],
  },
];
```

- 메뉴 데이터는 계층 구조를 반영해 구성한다.
- 선택 상태는 ID 기반으로 분리 관리한다.
- 확장 상태는 사용자 인터랙션에 따라 화면에서 토글된다.
