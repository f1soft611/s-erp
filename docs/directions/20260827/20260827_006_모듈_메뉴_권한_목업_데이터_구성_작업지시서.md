## 목적

현재 대시보드 좌측 메뉴는 컴포넌트 코드에 하드코딩된 모듈/메뉴 배열을 사용한다.
실제 서비스에서 서버가 내려주는 "사용자 기준 모듈-메뉴-권한" 응답을 가정한 목업 데이터를 구성하고,
화면이 해당 데이터 계약을 기준으로 동작하도록 전환한다.

## 범위

### 포함

- 모듈-메뉴 트리 목업 JSON 신설 (사용자 정보 + 메뉴 부모/자식 + 메뉴별 권한)
- 목업 데이터를 화면 모델(`ModuleItem`, `MenuTreeNode`)로 변환하는 서비스 계층 추가
- 대시보드 데이터 소스를 목업 JSON 기반으로 전환
- 관련 테스트 수정

### 제외

- 백엔드 API, DB 스키마 변경
- 권한 값에 따른 화면 제어(버튼 비활성화 등) 구현
- 그룹웨어/환경설정 외 모듈 데이터 작성

## 요구사항

1. 모듈은 그룹웨어, 환경설정 두 개만 구성한다.
2. 메뉴 구성
   - 그룹웨어: 종합현황, 문서관리
   - 환경설정: 권한관리, 메뉴관리
3. 메뉴 데이터는 부모/자식 관계를 갖는다. (모듈 루트 메뉴 → 하위 메뉴)
4. 각 하위 메뉴는 admin 계정 기준 권한(read/create/update/delete)을 포함한다.
5. 테스트 계정 admin은 `ADMIN` 역할로 모든 메뉴에 모든 권한을 가진다.
6. 데이터 구조는 아래 JSON 계약을 따른다.

```json
{
  "user": {
    "userId": "admin",
    "roles": ["ADMIN"]
  },
  "menus": [
    {
      "menuId": 100,
      "parentMenuId": null,
      "name": "기준정보",
      "icon": "Settings",
      "children": [
        {
          "menuId": 110,
          "parentMenuId": 100,
          "name": "거래처 관리",
          "path": "/master/customer",
          "permissions": {
            "read": true,
            "create": true,
            "update": true,
            "delete": false
          }
        }
      ]
    }
  ]
}
```

## 작업 순서

1. 문서 확인
2. 계획서 작성 (`docs/plan`)

4. 구현
5. 검증 (`npm run build`, `npm run test`)

7. 최종 체크리스트 확인

- 요구되지 않은 모듈/메뉴 임의 추가 금지
- 백엔드 및 DB 변경 금지
