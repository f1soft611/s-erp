# 20260827*002*메인보드*좌측패널*디자인*재수정*작업지시서

## 1. 작업 개요

현재 메인보드 좌측 패널은 ERP 운영 화면 기준으로 정리되지 않아, 기능 계층과 정보 우선순위가 불명확하다. 특히 상단 모듈 선택영역, 좌측 세부 메뉴 영역, 메인 콘텐츠 영역의 시각적 구분이 부족하고, 기존 배치 구조가 화면 캡처와 다르게 표현되어 있다.

본 작업은 제공된 캡처 이미지를 기준으로 메인보드 좌측 패널을 재설계하고, React 구조에 맞게 컴포넌트/스타일/상태 로직을 정리하는 것을 목표로 한다.

핵심 의도는 다음과 같다.

- 캡처 이미지의 ERP형 좌측 패널 구조를 반영한다.
- 좌측 패널을 상단 모듈 선택 영역과 하단 메뉴 트리 영역으로 구분한다.
- 기존 메인보드 구조에 비해 시각적 계층을 명확히 정리한다.
- 새 레이아웃을 React 컴포넌트 구조에 맞게 재구성한다.

---

## 2. 작업 목적

이번 작업의 목적은 다음 항목을 반영한 좌측 패널 레이아웃을 구성하는 것이다.

- 캡처 이미지 기반의 ERP형 화면 구성 원칙을 반영한다.
- 메인보드 좌측 영역을 단순 컬럼형 구조에서 계층형 구조로 재배치한다.
- 모듈/메뉴 선택 상태를 시각적으로 분명하게 표현한다.
- 상단 기능 아이콘 영역과 하단 실제 작업 메뉴가 독립적으로 보이도록 구성한다.
- React 컴포넌트 단위로 정리하여 유지보수성과 확장성을 확보한다.

---

## 3. 현재 문제점

현재 좌측 패널은 다음과 같은 한계가 있다.

1. 전체 구조가 기능 구분보다 단일 리스트형 네비게이션에 가까워 ERP 운영형 구성이 약하다.
2. 상단 모듈 선택 영역과 하단 메뉴 트리 영역이 분리되지 않아 정보 계층이 흐려진다.
3. 현재 선택 상태, hover 상태, active 상태의 구분이 모호하다.
4. 캡처 기준과 달리 대시보드/메인보드의 시각적 우선순위가 맞지 않는다.
5. 화면 구성이 React 컴포넌트 구조를 반영하지 못해 재사용성과 UI 정합성이 낮다.

---

## 4. 요구사항

### 4.1 화면 구조 재설계

- 좌측 패널은 "상단 모듈 영역 + 하단 메뉴 영역" 구조로 재구성한다.
- 메인보드 전체 레이아웃은 좌측 패널과 메인 콘텐츠 영역이 명확히 분리되도록 구성한다.
- 메뉴 계층은 단순 나열이 아니라 기능 군별 그룹화 구조로 보이도록 한다.
- 캡처 이미지와 유사한 ERP형 시각적 레이아웃을 우선 반영한다.

### 4.2 모듈 선택 영역

- 상단 모듈 선택 영역은 아이콘/텍스트 조합으로 구성한다.
- 현재 선택된 모듈은 강조 배경 또는 테두리로 구분한다.
- 선택 상태와 hover 상태를 명확히 구분한다.
- 모듈 영역은 좌측 패널 전체의 상단에 위치하며 화면 전체를 압도하지 않도록 폭을 조절한다.

### 4.3 메뉴 트리 영역

- 하단 메뉴 영역은 선택된 모듈에 맞는 메뉴 목록을 보여준다.
- 메뉴는 계층 구조를 드러내는 리스트 형태로 표현한다.
- 현재 선택된 메뉴는 강조 색상, 굵기, 좌측 라인 또는 배경 차이로 구분한다.
- 하위 메뉴와 최상위 메뉴가 동일 시각적 무게로 보이지 않고, 계층 구조를 명확하게 인지할 수 있게 한다.

### 4.4 React 반영

- 레이아웃 구성은 기존 React 구조에 맞게 컴포넌트 단위로 재정렬한다.
- 필요 시 `DashboardSidebar`, `DashboardModuleSection`, `DashboardMenuTree` 등으로 분리해 구성한다.
- 스타일은 기존 theme/tailwind 또는 CSS 모듈 패턴을 유지하되, 화면 설계 목적에 맞게 정리한다.
- 로직과 표현을 분리하여 중복 없이 재사용 가능한 구조를 유지한다.

### 4.5 캡처 기준 반영

- 제공된 캡처 이미지의 좌측 패널 전반적인 형태를 기준으로 구현한다.
- 좌측 패널은 전체적인 컬러 톤, 간격, 배경, 선택 강조, 메뉴 계층 구조를 캡처와 유사하게 맞춘다.
- 상단 고정형 아이콘/모듈 영역과 하단 세부 메뉴 영역의 시각적 분리감을 유지한다.

## 5. 구현 방향

### 5.1 컴포넌트 분리 방향

메인보드 좌측 패널은 다음과 같은 구조로 조립한다.

- `MainBoardLayout` 또는 대시보드 페이지 레이아웃
- `DashboardSidebar`
- `DashboardModuleSection`
- `DashboardMenuTree`
- `MainContentPanel`
- `useDashboardSelection`
- `dashboardService` 또는 데이터 변환 유틸

이 구조를 통해 다음을 보장한다.

- UI와 상태 관리의 책임 분리
- 좌측 패널 레이아웃 변경 시 메인 콘텐츠 영향 최소화
- 선택 상태 관리 일관성 유지
- 향후 메뉴 확장 시 수정 범위 축소

### 5.2 스타일 방향

- 좌측 패널 배경은 어두운 ERP형 톤으로 구성하되 가독성을 유지한다.
- 선택된 모듈은 밝은 강조색 또는 진한 배경으로 상호 구분한다.
- 비활성 메뉴는 약한 색으로 정리하고, 선택 메뉴는 눈에 띄는 배경과 텍스트 색상으로 표현한다.
- 여백, 아이콘 크기, 폰트 크기, 구분 선을 조정해 계층을 안정적으로 보이게 한다.

### 5.3 데이터 구조 방향

메뉴/모듈 구조는 다음과 같은 형태로 정리한다.

```ts
const modules = [
  {
    id: 'system',
    name: '시스템',
    menus: [
      { id: 'dashboard', name: '대시보드', pageKey: 'dashboard' },
      { id: 'users', name: '사용자관리', pageKey: 'users' },
    ],
  },
];
```

- 모듈별 메뉴 데이터는 독립적으로 관리한다.
- 현재 선택된 모듈과 메뉴를 상태로 분리한다.
- 메뉴 트리는 데이터 기반으로 렌더링한다.
