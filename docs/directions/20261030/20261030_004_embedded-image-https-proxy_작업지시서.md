# 본문 임시 이미지 HTTPS 백엔드 반환 작업지시서

## 요구사항

- 문서작성·공지작성에서 이미지 붙여넣기 후 HTTPS 배포 화면이 HTTP MinIO 미리보기 주소를 요청하여 Mixed Content로 차단되는 문제를 해결한다.
- 사용자가 선택한 백엔드 직접 반환 방식을 적용한다. MinIO HTTPS 전환, 브라우저 보안 완화, HTTP 리다이렉트는 사용하지 않는다.
- HTTPS 백엔드가 MinIO에서 이미지 바이트를 읽고 인증된 프론트 요청에 반환한다.

## 범위와 순서

1. 기존 임베디드 이미지 수명주기와 인증 조회 문서를 확인한다.
2. [계획서](../../plan/20261030/20261030_004_embedded-image-https-proxy_계획서.md)를 작성한다.
3. [상세 사양서](../../spec/20261030/20261030_004_embedded-image-https-proxy_상세사양서.md)를 작성한다.
4. 공통 임시 이미지 GET과 프론트의 인증 blob 조회를 구현한다.
5. focused 테스트, 프론트 빌드·린트, 실제 브라우저 붙여넣기 및 스크린샷을 기록한다.

## 완료 조건

- 임시 업로드 응답은 MinIO 서명 URL 대신 고정 백엔드 상대 경로를 제공한다.
- 문서·공지·공통 경로를 사용하는 기안양식에서 미리보기가 유지된다.
- 로그인 정보에서 테넌트를 결정하며 외부 URL·버킷·object key를 조회 API의 입력으로 받지 않는다.
- 저장 시 기존 영구 이미지 경로 재작성, 취소·orphan 정리와 접근 권한은 유지한다.
- DB 스키마·데이터 마이그레이션은 하지 않는다. DB MCP 메타데이터 확인 근거는 결과 문서에 남긴다.
- 운영 배포나 운영 데이터 변경은 수행하지 않는다.
