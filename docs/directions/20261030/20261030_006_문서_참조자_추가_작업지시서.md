# 문서 참조자 추가 작업지시서

## 요청 및 승인 범위

- 기안자가 결재신청한 뒤에도 해당 문서를 열람할 수 있는 사용자가 참조자를 추가할 수 있게 한다.
- 새 참조자는 기존 결재 참여자 모델에 `REFERENCE`로 저장하며 저장 직후 해당 문서를 열람할 수 있어야 한다.
- 추가 행위는 공통 SYSTEM 타임라인에 `REFERENCE_ADDED`로 기록한다. 실제 추가된 참조자 이름과 행위자가 식별되어야 하며 참여자 및 이력은 원자적으로 저장한다.
- 문서 더보기 메뉴에 `참조자 추가하기`를 두고, `문서 공유하기`와 참조자 추가 메뉴를 문서 수정/삭제 메뉴와 구분선으로 나눈다. 양쪽 메뉴 그룹이 모두 비어 있을 때 구분선이 남지 않아야 한다.
- 승인 설계: [문서 참조자 추가 설계](../../superpowers/specs/2026-10-30-document-reference-addition-design.md)

## 작업 순서

1. 읽기 전용 DB MCP와 기존 접근권한·참여자·활성 사용자·타임라인 구현으로 계약을 확인한다.
2. 상세사양을 확정하고 실패 회귀 테스트를 먼저 작성한다.
3. API 및 트랜잭션을 구현한다. 신규 참여자 삽입과 SYSTEM 이력 기록이 한 트랜잭션이어야 한다.
4. 프론트엔드 메뉴, 선택 다이얼로그, 서비스 및 타임라인 표시를 구현한다.
5. 날짜별 DB 변경 이력과 누적 스키마를 갱신하고, 테스트·빌드·브라우저 결과를 문서화한다.

## 권한 및 데이터 경계

- 요청자는 서버 인증 principal의 tenant 및 사용자 정보로 식별한다. 요청 본문에서 행위자, tenant, 이름, 시각을 받지 않는다.
- 삭제되지 않은 문서에 대한 기존 열람 권한을 서버에서 확인하고, `DRAFT` 문서는 거부한다.
- 참조 대상은 동일 tenant 내 활성 사용자와 활성 로그인 계정으로 제한한다. 일부라도 유효하지 않으면 요청 전체를 거부한다.
- 이미 참여 중인 사용자는 추가하지 않고 기존 참여·확인 상태를 보존한다. 모두 중복이면 새 SYSTEM 이벤트를 남기지 않는다.
- 참조자 제거, 결재선 변경, 별도 ACL 및 알림은 범위에서 제외한다.

## DB 및 검증

- 구현 전에 `s-erp-postgresql-readonly`의 `list_tables`, 관련 테이블 `describe_table`, 필요한 제약 메타데이터 조회를 수행한다. 행 데이터는 조회하거나 결과물에 기록하지 않는다.
- 기존 DB CHECK가 `REFERENCE_ADDED`를 허용하지 않으면 변경 SQL, 변경 이력 및 롤백을 `backend/DATABASE/20261030`과 `docs/database/20261030` 양쪽에 만들고 `docs/database/db-schema.md`도 갱신한다. MCP로 DDL을 실행하지 않는다.
- 백엔드 서비스/API/매퍼 테스트에서 권한, 상태, 대상 사용자, 중복 및 이력 실패 원자성을 확인한다.
- 프론트엔드 서비스/메뉴/다이얼로그/상세 갱신과 SYSTEM 이벤트 표시를 검증하고 빌드를 수행한다.
- 합성 데이터만 사용해 375px, 768px, 1280px 브라우저 화면 및 가로 넘침을 확인한다. 결과와 스크린샷은 `docs/result/20261030/document-reference-addition/`에 보관한다.

## 완료 조건

- 승인 설계와 상세사양에 따른 참조자 추가 및 즉시 문서 열람이 가능하다.
- 권한 없는 사용자, 임시저장/삭제 문서, 비활성·타 tenant·없는 대상은 서버에서 거부된다.
- 신규 참여자와 `REFERENCE_ADDED` 이벤트는 함께 저장되며 실패 시 모두 롤백된다.
- 메뉴 구분선과 기존 수정/삭제 조건을 보존한다.
- 관련 테스트/빌드와 가능한 브라우저 검증을 기록하고, 스키마 변경이 있으면 양쪽 변경 이력 및 누적 스키마를 함께 갱신한다.

## 승인된 후속 수정

- 문서현황 상세를 연 상태에서 참조자를 추가한 뒤에도 상세 패널을 유지한다. 참조 추가 성공 후 목록과 상세 데이터를 모두 갱신하되, 검색 조건 변경으로 시작한 목록 조회에서 상세를 닫는 기존 동작은 유지한다.
- 참조자 추가 성공 후 목록·상세·SYSTEM 타임라인은 기존 데이터를 유지한 채 백그라운드에서 조용히 갱신한다. 그리드 전체 로딩 표시나 상세 초기 로딩 화면을 띄우지 않고, 조회 실패는 기존 오류 UI로 알린다.
- SYSTEM 이력 문구는 `행위자님이 참조자(이름1, 이름2)를 추가했습니다.` 형식으로 표시한다. 실제 추가된 참조자만 이름에 포함한다.
- 재현 회귀 테스트로 상세 유지 및 SYSTEM 이력 문구를 확인한다. 이 수정은 테이블/컬럼/API 구조를 변경하지 않는다.
