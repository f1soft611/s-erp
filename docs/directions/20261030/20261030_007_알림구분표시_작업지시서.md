# 알림 구분 표시 작업지시서

## 목적

알림함 목록에서 각 항목의 종류를 제목과 별도로 표시해 사용자가 문서 멘션과 새 쪽지를 빠르게 구별할 수 있게 한다.

## 범위

- 알림함 리스트형 목록의 첫 번째 열에 `APPROVAL_COMMENT_MENTION` 문서 아이콘과 `DIRECT_MESSAGE_RECEIVED` 쪽지 아이콘을 표시한다. 읽음 표시와 제목보다 앞에 두고, 각 아이콘은 tooltip/accessible label로 구분명을 제공한다.
- 알림함에서 전체, 문서 멘션, 새 쪽지 유형별 필터를 제공한다.
- 사용자는 본인의 알림을 개별 숨김 처리할 수 있고, 현재 유형 범위의 읽은 알림을 일괄 정리할 수 있다. 원본 업무 데이터는 삭제하지 않는다.
- 표시값과 필터는 기존 `eventType`을 사용하며 선택형 event-type query parameter를 알림 목록 API에 추가한다.
- 숨김은 `tb_notification.archived_at`을 사용하는 사용자별 soft archive다. 실제 DB에는 migration을 실행하지 않는다.
- 제목, 요약, 일시, 읽음 상태, 필터, 이동 동작은 유지한다.
- 알림 헤더 팝오버 및 쪽지함은 변경하지 않는다.

## 절차 및 완료 기준

1. 프런트엔드 테스트에서 유형별 표시, 유형 필터, 단건 숨김, 읽은 알림 일괄 정리를 검증한다.
2. 공통 목록 항목에 선택적 첫 번째 열 분류 아이콘과 알림 행별 숨김 액션을 추가한다. 문서 작성 리스트형의 아이콘-본문 분리 레이아웃을 따른다.
3. API는 두 eventType만 허용하고 유형 조회 조건을 cursor/limit 전에 적용한다.
4. 단건 숨김은 인증 사용자의 알림만 대상으로 하고, 일괄 숨김은 `read_at IS NOT NULL`인 알림만 유형 필터 범위에서 처리한다.
5. 날짜별 `archived_at` migration, rollback, 변경 이력 및 양쪽 동일 사본을 만들고 누적 스키마를 갱신한다. 실제 DB에는 적용하지 않는다.
6. 알림함/헤더 테스트, 백엔드 서비스 테스트, 프런트엔드 빌드 및 브라우저 375/768/1280px를 검증한다.
7. 날짜별 계획·상세사양·결과 문서를 작성하고 스크린샷 및 MCP 근거를 기록한다.
8. 기존 제목·요약·읽음·탐색 동작은 유지하며 원본 댓글/쪽지는 삭제하지 않는다.
