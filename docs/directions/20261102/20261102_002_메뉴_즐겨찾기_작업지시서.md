## 목표

사용자가 권한이 있는 메뉴를 개인 즐겨찾기로 저장하고 루트 또는 1단계 폴더에서 바로 열 수 있게 한다. 즐겨찾기 항목이 하나 이상이면 좌측 모듈 레일에 실제 DB 모듈과 분리된 가상 즐겨찾기 모듈을 표시한다.

## 작업 범위

- 인증 사용자·tenant 기준 폴더와 메뉴 바로가기 저장소 및 API
- 메뉴별 단일 위치 제약: 루트 또는 한 폴더에만 등록하고 이동은 기존 항목의 위치 변경으로 처리
- 일반 모듈 leaf의 우클릭/더보기에서 즐겨찾기 추가 및 폴더 위치 선택
- 즐겨찾기 가상 모듈, 루트/폴더/메뉴 트리, 기존 메뉴 URL로 이동
- 루트/폴더/메뉴별 컨텍스트 메뉴 및 동등한 키보드·터치 접근
- 폴더 생성, 이름 변경, 빈 폴더 삭제; 메뉴 이동 및 즐겨찾기 해제
- 날짜별 DB migration/rollback/change record 및 `docs/database/db-schema.md` 갱신
- 백엔드·프런트엔드 테스트, 375/768/1280px 브라우저 검증, 스크린샷 및 결과 문서

## 제외

- 실제 `tb_module` 행 생성 또는 일반 모듈 권한 정책 변경
- 중첩 폴더, 같은 메뉴 중복 등록, 공유/공용 즐겨찾기
- 드래그 정렬, 즐겨찾기 전용 관리 페이지
- 최근 사용 메뉴 기능 대체

## 사용자 및 보안 규칙

- 소유 사용자와 tenant는 인증 `LoginVO`에서 도출한다. 요청의 사용자/tenant ID는 받거나 신뢰하지 않는다.
- 메뉴 추가/이동 시 현재 tenant의 활성 leaf 메뉴이고 현재 사용자에게 읽기 권한이 있는지 서버가 검증한다.
- 메뉴가 비활성화되거나 접근권한이 사라지면 조회 응답에서 숨기되 즐겨찾기 레코드는 유지한다. 권한 복구 시 다시 보인다.
- 폴더는 루트 바로 아래 1단계만 지원하며 양 끝 공백을 제거한 1~40자 이름을 사용한다.
- 비어 있지 않은 폴더 삭제는 거부한다. 즐겨찾기 메뉴가 0개면 가상 모듈은 숨기되 일반 메뉴의 위치 선택/관리 창에서 저장 폴더를 관리할 수 있다.
- 컨텍스트 메뉴 작업 실패 시 공통 오류로 알리고 화면의 즐겨찾기 상태를 서버 상태와 일치시킨다.

## 필수 순서

1. 승인된 설계와 본 작업지시서에서 `docs/plan/20261102/20261102_002_메뉴_즐겨찾기_계획서.md`를 작성한다.
2. 계획서에서 API·DB·화면·권한·오류·검증 계약을 `docs/spec/20261102/20261102_002_메뉴_즐겨찾기_상세사양서.md`로 상세화한다.
3. 실제 DB/API 구현 직전에 `s-erp-postgresql-readonly` MCP의 `list_tables`, `describe_table(tb_menu)`, `describe_table(tb_user)`로 현재 계약을 다시 확인한다. 호출이 불가하면 미확인 사실과 Mapper/스키마 이력 대체 근거를 결과 문서에 남긴다. MCP 확인 없이 DB 계약을 확인했다고 보고하지 않는다.
4. 날짜별 migration/rollback/change record를 `backend/DATABASE/20261102` 및 `docs/database/20261102`에 동일하게 작성하고 `docs/database/db-schema.md`를 갱신한다. DB에 직접 변경을 적용하지 않는다.
5. 백엔드 API/서비스/Mapper와 프런트엔드 UI를 RED-GREEN-REFACTOR로 구현하고 권한 경계 및 기존 모듈/최근 사용 회귀를 확인한다.
6. 프런트엔드 build/test, 백엔드 타깃 테스트를 실행한다. 실제 브라우저에서 375px/768px/1280px을 확인한다.
7. `docs/result/20261102/menu-favorites/`에 DB MCP 근거, 구현 범위, 테스트 결과 및 스크린샷을 기록한다.

## 완료 조건

- 메뉴 즐겨찾기 전 최초 상태에는 가상 모듈이 보이지 않고, 첫 메뉴 저장 후 나타난다.
- 루트와 폴더에서 메뉴를 열 수 있고 원래 메뉴 라우트/권한과 일치한다.
- 한 메뉴가 두 위치에 중복 저장되지 않고 이동 시 위치만 변경된다.
- 폴더 생성·이름 변경·빈 폴더 삭제가 가능하고, 비어 있지 않은 폴더 삭제는 명시적으로 거부된다.
- 마지막 메뉴 해제 후 가상 모듈이 사라져도 저장된 폴더를 일반 메뉴의 위치 선택/관리 경로로 다시 관리할 수 있다.
- 다른 tenant, 비활성, 비인가, 그룹 또는 경로 없는 메뉴는 저장/이동할 수 없다.
- 권한이 사라진 메뉴는 숨겨지고 권한 복구 시 복원된다.
- 마우스 우클릭과 키보드/터치 더보기 작업이 동등하고 반응형 화면에서 잘리지 않는다.
- migration/rollback/schema 문서, 테스트, 결과 README와 3개 뷰포트 스크린샷이 존재한다.
