# 공통 기능 후속 확장 작업지시서

## 사용자 지시

2026-11-02 사용자 요청: “추천 순서 기록해주고 순차적으로 진행하자”.

즐겨찾기·공통 알림/쪽지·통합검색 1차 구현 이후 아래 순서를 유지한다. 여러 단계를 한 작업으로 합치지 않고 각 단계의 설계·구현·검증을 마친 뒤 다음 단계로 진행한다.

| 순서 | 작업 | 완료 기준 |
|---|---|---|
| 1 | 알림·쪽지 실시간 갱신 | 다른 사용자의 새 이벤트가 페이지 새로고침 없이 배지/열린 목록/현재 대화에 반영. 기존 입력·스크롤·이전 메시지 보존 |
| 2 | 웹 푸시 | 명시적 수신 동의, 기기별 구독/해제, 만료 구독 정리, 중복 방지, 알림 선택 시 기존 권한 재검증 |
| 3 | 업무 알림 확대 | 결재 요청·승인·반려 등 합의한 이벤트부터 공통 알림 발행. 수신자·중복·자기 알림 제외 정책 검증 |
| 4 | 통합검색 대상 확대 | 합의한 업무부터 기존 접근 권한/테넌트 경계를 유지해 추가. 유형·건수·페이징·상세 이동 검증 |

## 단계별 진행 원칙

- 현재 착수 대상은 **1단계**다. 2~4단계 세부 기능과 데이터 계약은 아직 확정하지 않는다.
- 각 단계는 작업지시서 → 계획서 → 상세사양서 → 구현 → 결과 문서/스크린샷 순서를 따른다.
- 서버 방식, 새 API/DB 계약, 운영 제약은 해당 단계 설계에서 확인한다. DB 관련 구현 전 읽기 전용 MCP로 확인하고 실제 DDL은 적용하지 않는다.
- 실시간 갱신과 웹 푸시는 별도 기능이다. 화면 내부 갱신을 브라우저/운영체제 푸시 알림으로 표현하지 않는다.
