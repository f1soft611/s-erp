# 공정관리 작업장 개편 작업지시서

- 근거: [2026-11-17 회의 안건 설계안](../../superpowers/specs/2026-11-17-meeting-backlog-design.md) 1. 작업장(공정그룹) 개편
- 기존 구현: [공정관리 작업지시서](../20261112/20261112_003_공정관리_작업지시서.md)

## 작업 내용

- 생산관리 > 기준정보 > 공정관리의 "공정그룹"을 화면 문구상 "작업장"으로 변경한다. 테이블(`tb_process_group`)·API 경로·메뉴 URL·page key는 변경하지 않는다.
- 공정(`tb_process`)을 작업장 종속에서 분리해 테넌트 단위 **공정 마스터**로 독립시킨다. 같은 공정을 여러 작업장에서 재사용할 수 있어야 한다.
- 작업장과 공정의 연결을 신규 매핑 테이블 `tb_process_group_process`로 관리한다.
- 공정관리 화면에 **공정 설정** 버튼을 추가하고 `CommonDialog` 모달에서 공정 마스터를 등록·수정·삭제한다.
- 작업장에 공정을 추가할 때는 공정 설정에 등록된 공정을 조회·선택하여 연결한다. 트리에서 공정을 직접 신규 입력하지 않는다.
- 매핑이 존재하는 공정 마스터는 삭제할 수 없다. 연결된 공정이 있는 작업장은 삭제할 수 없다.
- 기존 `(작업장, 공정)` 데이터는 이름과 설정 플래그가 같은 공정을 하나의 마스터로 병합하고 매핑 행으로 이관한다.

## 확정한 결정

- 병합 기준: 같은 테넌트에서 **이름, 미사용 및 9개 공정 속성 플래그가 모두 같은 공정**. 설명과 이미지는 기준에 넣지 않고 가장 작은 `process_id`(마스터) 행의 값을 유지한다. 이름만 같고 속성이 다른 공정은 별도 마스터로 유지해 설정 손실을 막는다.
- 외부 참조: 읽기 전용 MCP로 확인한 결과 `tb_process.process_id`를 참조하는 다른 테이블이나 컬럼은 없다.

## 완료 조건

- 작업장 트리에서 작업장 추가·수정·삭제, 등록된 공정 선택 연결, 연결 해제가 가능하다.
- 공정 설정 모달에서 공정 마스터 CRUD가 가능하고 이미지·속성 검증은 기존과 같다.
- 마스터 삭제 차단, 작업장 삭제 차단, 중복 연결 차단, 테넌트 격리가 서버에서 보장된다.
- DB 스크립트, 롤백, 변경 이력, `db-schema.md`가 갱신된다.
