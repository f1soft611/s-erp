# 영업관리 타입별 소수점 작업지시서

## 요구사항

- 모듈별 그리드 소수점 정책을 기존 컬럼 타입 `number`, `decimal`, `currency`별로 관리한다. 기본 자릿수는 각각 0, 3, 3이다.
- 영업관리의 숫자 수량·순서·No 컬럼은 `number`, 단가는 `decimal`, 공급가·부가세·합계 등 금액은 `currency`를 사용한다. 자동 순번 컬럼은 기존 `rownumber`를 유지하고 문자 식별번호는 숫자로 변환하지 않는다.
- 그리드의 컬럼별 설정이 있으면 그 설정을, 없으면 해당 모듈의 타입별 정책을 사용한다.
- 영업 데이터 저장 범위를 정책의 최대 6자리까지 확장한다. 기존 테스트 데이터의 자릿수 변환은 요구하지 않는다.
- 계산 결과는 별도 설정이 없으면 정책의 자릿수와 반올림 방식을 따르고, 별도 설정이 있으면 해당 설정을 따른다.
- 입력값이 저장 후 다른 값으로 바뀌지 않도록 저장 및 재조회 경로를 확인한다.
- 정책 변경 이력은 원시 JSON 대신 변경 전·후 값을 사람이 읽기 쉽게 표시한다. 기존 숫자형·단일 규칙 이력도 확인할 수 있어야 한다.
- (후속 피드백) 정책 변경 이력에서 변경되는 부분을 더 눈에 띄게 강조하고 변경 전과 변경 후 사이에 화살표를 표시한다.
- (후속 피드백) 셀 직접 편집은 적용된 소수점 자릿수를 넘는 입력을 막는다. 0자리이면 소수점 자체를 입력할 수 없고 3자리이면 소수 셋째 자리까지 입력한다.
- (후속 피드백) 금액 컬럼은 `currency` 정책을 적용하고 단가는 `decimal`을 유지한다. 입력·계산·서버 저장과 상세·인쇄 표시에도 동일하게 적용한다.
- (후속 피드백) 정책과 컬럼별 설정을 다른 개발자도 사용할 수 있도록 공통화한다. 저장에 영향을 주는 컬럼별 설정은 프론트와 서버가 같은 신뢰 가능한 기준을 사용해야 하며, 요청에서 임의로 전달한 설정을 서버의 기준으로 삼지 않는다.
- 실제 출하 저장 검증 중 자동 거래명세서 조회가 기존 스키마에 없는 컬럼을 참조하는 오류를 해결하고 저장·재조회를 확인한다. 불필요한 스키마 변경은 하지 않는다.

## 범위와 완료 기준

- 공통 정책관리·F1-Grid 및 영업관리 화면, API·계산·데이터베이스 스키마를 대상으로 한다.
- 입력·계산·저장·재조회, 정책과 컬럼별 설정 우선순위, 자릿수 0과 6, 반올림 방식을 검증한다.
- 변경 SQL과 이력·롤백을 날짜별 디렉터리에 남긴다. 관련 결과와 브라우저 확인 사항을 기록한다.
