# 20261006_005 문서작성 기안서 탭 필드 재정의 작업지시서

## 작업 목적

`/groupware/doc/write`의 문서 작성 모달에서 기안서 탭의 메타데이터, 기안양식 선택, 결재선, 합의, 참조 UI를 실제 기안양식관리와 F1-Grid 사용자 선택 동작에 맞춰 제공한다.

## 승인된 요구사항

- 모든 폼 필드는 F1-Grid 행 폼 모달의 크기와 같은 38px 높이 및 small outlined 필드 스타일을 사용한다.
- 기안일은 오늘 날짜, 기안자는 로그인 사용자의 프로필 이름을 표시하고 둘 다 읽기 전용으로 제공한다.
- 구분은 기안양식관리에서 사용하는 활성 `WF_FORM_CATEGORY` 분류 목록이며 `전체`를 포함한다. 최초에는 `전체`를 선택한다.
- 기안양식 목록은 선택된 분류로 필터링한다. `전체`이면 모든 활성 분류의 양식을 대상으로 하며, 사용 중(`useAt='Y'`)이고 본문 양식이 등록된 항목만 표시한다.
- 기안양식을 선택하면 해당 양식의 JSON/HTML 본문을 기존 기안양식 본문 API로 읽어 에디터에 반영한다. 문서 제목은 자동 변경하지 않는다.
- 본문을 사용자가 수정한 뒤 다른 양식을 선택하면 교체 확인을 표시한다. 교체를 취소하면 기존 양식 선택과 본문을 유지한다.
- 결재선 구성에는 F1-Grid 사용자 선택기 다중 필드 하나와 `결재 추가`, `합의 추가` 버튼을 둔다.
  - `결재 추가`는 사용자 한 명이 선택된 경우에만 활성화하고 한 명을 다음 순번의 결재 단계로 추가한다.
  - `합의 추가`는 선택된 사용자들을 한 개 순번의 합의 단계로 묶어 추가한다.
  - 단계는 추가 순서대로 번호를 매기고 삭제할 수 있다. 이번 범위에는 드래그 재정렬을 넣지 않는다.
- 참조자는 결재선과 분리된 F1-Grid 사용자 선택기 다중 필드로 제공한다.
- 사용자 후보와 선택된 결재자/합의자/참조자에는 사진, 이름, 부서를 표시한다.
- 작성 중인 결재/합의 단계에는 비어 있는 도장 자리를 표시한다. 실제 처리 완료 도장은 후속 문서/결재 화면의 범위이며 작성 모달에서 완료 상태를 가장하지 않는다.
- 저장·상신 API 계약은 아직 없으므로 저장 버튼은 비활성 상태로 유지한다.

## 구현 기준

- 기안양식관리의 활성 분류/양식 조회 및 본문 조회 API와 내 프로필 API를 재사용한다. 사용자 옵션은 기존 기안양식 사용자 조회를 이용한다.
- 사용자 후보 선택은 `UserSelectEditor`의 사진·이름·직급/부서 검색 패턴을 따른다. 선택된 항목은 사진·이름·부서와 역할별 단계 구조를 읽을 수 있도록 표시한다.
- 기존 공용 `CommonDialog`, `RichTextEditor`, `RichTextEditorToolbar`를 유지한다.
- 조회 실패는 모달 안에 사용자에게 보이는 오류로 표시한다. 비어 있는 성공 결과나 임의의 대체 사용자로 오류를 숨기지 않는다.
- 페이지 저장, 임시저장, 상신, 승인 처리, DB/백엔드 변경은 포함하지 않는다.

## 진행 및 검증

1. 관련 문서와 기존 변경사항을 보존한 상태에서 구현 파일을 확인한다.
2. 기안서 작성 모달 테스트를 먼저 추가하거나 갱신해 필드/선택 흐름의 기준을 만든다.
3. 메타데이터 조회, 분류·양식 필터, 템플릿 적용 및 변경 확인을 연결한다.
4. 사용자 선택기와 결재/합의/참조 표시를 구성한다.
5. 테스트와 빌드를 실행하고 브라우저에서 375px, 768px, 1280px 레이아웃을 확인한다.
6. 결과 문서와 스크린샷을 `docs/result/20261006/document-write-draft-fields/`에 기록한다.

## 완료 기준

1. 기안서 탭의 날짜/기안자/분류/양식 필드가 정의된 값과 크기로 표시된다.
2. `전체` 또는 분류 선택에 따라 사용 중이며 본문이 등록된 양식만 기안양식 목록에 노출된다.
3. 기안양식 선택 시 본문이 에디터에 적용되고, 편집 내용 교체 확인이 동작한다.
4. 결재 추가는 사용자 한 명만 받아 다음 결재 순번을 만들고, 합의 추가는 여러 사용자를 한 순번으로 묶는다.
5. 참조자는 독립적으로 선택되며 모든 선택된 사용자의 사진/이름/부서가 보인다.
6. 결재/합의 단계에 도장 자리가 보이되 작성 모달은 실제 승인 도장을 표시하지 않는다.
7. 저장은 계속 비활성이며 테스트, 빌드, 세 뷰포트 브라우저 검증 및 결과 문서가 완료된다.
