# 20261006_001 공통 임베디드 이미지 저장 수명주기 통합 작업지시서

## 작업 목적

공지사항과 기안양식결재 본문 이미지의 임시 업로드, 미리보기, 저장 승격, `tb_common_file` 소유권 등록, 삭제를 재사용 가능한 공통 저장 서비스로 통합한다. 각 기능은 기존 권한과 고유 소유권을 유지한다.

## 승인된 방향

- 임시 이미지는 짧은 presigned URL로 작성 중 미리보기한다. URL 만료와 MinIO 객체 만료는 별도 정책이다.
- 저장 시 임시 객체를 tag 없는 영구 object key로 승격한 뒤 `tb_common_file`에 귀속한다.
- 공지사항 소유권은 `owner_type='NOTICE'`, `owner_id=postId`; 기안양식은 `owner_type='DRAFTING_WORK_TEMPLATE'`, `owner_id=draftingWorkCategoryId`로 구분한다. `file_usage_type='EMBEDDED'`를 사용한다.
- 취소, 업로드 orphan, 저장 성공 시 남은 임시 객체를 삭제한다. MinIO lifecycle rule은 비정상 종료의 안전망으로 문서화하며 애플리케이션이 운영 bucket 정책을 임의 변경하지 않는다.
- 저장되는 HTML/JSON의 `img src`는 각 도메인의 인증된 고정 API URL로 rewrite한다. presigned 또는 raw MinIO URL은 영구 본문에 저장하지 않는다.
- Notice와 Draft의 기존 API route, 권한, 응답 계약은 domain adapter에 남기고 공통 서비스가 권한을 추정하지 않는다.

## 필수 확인

- 구현 전 `s-erp-postgresql-readonly`의 `list_tables` 및 `describe_table(tb_common_file)` 결과에서 기존 소유권 컬럼을 확인한다. DDL은 추가하지 않는다.
- 기존 Notice HTML/JSON을 읽을 수 있도록 legacy `notice-temp` object key와 기존 owner records를 조회/삭제 시 계속 지원한다.
- MinIO lifecycle은 `tenant/` prefix와 공통 embedded temporary tag를 모두 조건으로 하며, 영구 object에는 tag를 복사하지 않는다.

## 변경 범위

- 백엔드 공통 embedded image storage service 및 공통 owner/file metadata 처리를 추가한다.
- Notice create/update/save/read/delete adapter와 Draft template upload/save/read/delete adapter를 공통 service에 연결한다.
- 두 consumer 모두 업로드 진행 중 저장/닫기를 막고, cancel/orphan cleanup을 일관되게 한다.
- Notice body HTML과 JSON 모두 stable image URL로 저장한다.
- 기존 이미지 보존/삭제, 트랜잭션 rollback compensation, 임시 객체 cleanup 테스트를 추가한다.
- 날짜별 plan/spec/result 및 MinIO 운영 문서를 갱신한다.

## 완료 기준

- 새 업로드는 공통 임시 prefix/tag를 사용하고 저장 시 영구 owner-scoped key로 승격된다.
- `tb_common_file` metadata의 tenant, owner type/ID, usage type, object key가 해당 도메인 계약과 일치한다.
- 취소/orphan/저장 후 잔류 temp 객체가 즉시 정리되고, 운영 lifecycle rule은 별도의 7일 backstop으로 문서화된다.
- Notice와 Draft의 HTML/JSON 저장 및 조회 결과에 presigned/`blob:` URL이 남지 않는다.
- 기존 legacy Notice 이미지, 일반 첨부, editor paste/resize/read flow가 회귀하지 않는다.
- Frontend와 backend focused tests/build가 통과하며 결과 문서에 MCP schema 근거와 운영 lifecycle 미적용 여부를 기록한다.

## 비목표

- DB table/column/FK 변경
- 일반 첨부파일 upload/save/delete 경로 변경
- 인증/권한 범위 확대 또는 client-supplied owner identity 허용
- 운영 MinIO bucket에 승인 없이 lifecycle rule을 직접 적용
