# 20261006_003 기안양식 에디터 스크롤 정렬 작업지시서

## 작업 목적

기안양식 본문 편집 모달의 스크롤바가 에디터 상단보다 아래에서 시작하는 듯 보이는 여백을 제거하고, 공지사항 작성 모달과 같은 스크롤 구조로 정렬한다.

## 확인된 원인

- `DraftFormTemplateDialog`는 `RichTextEditor` 외부 Box에 `overflow: auto`와 `p: 2`를 함께 적용한다.
- 공지사항 작성 모달은 바깥 에디터 프레임에서 overflow를 숨기고 `.ProseMirror` 본문에 스크롤과 본문 안쪽 여백을 적용한다.
- 두 모달의 스크롤 소유 요소가 달라 기안양식 에디터에서 스크롤 트랙이 바깥 프레임보다 안쪽에 놓이는 차이가 발생한다.

## 승인된 요구사항

- 기안양식 에디터 프레임 상단부터 본문 스크롤이 시작되어야 한다.
- 본문과 에디터 프레임 사이의 안쪽 여백은 유지한다.
- 변경은 `DraftFormTemplateDialog`의 스크롤/여백 적용 위치로 한정한다. 공통 에디터의 기본값 및 공지사항 모달은 변경하지 않는다.
- 저장, 이미지 업로드, 로딩/오류, 툴바 및 미저장 변경 확인 동작은 유지한다.

## 구현 및 검증 범위

1. 기존 draft-form dialog 테스트에 스크롤 스타일 회귀 검증을 추가한다.
2. 외부 에디터 프레임은 overflow를 숨기고, `.ProseMirror`가 세로/가로 스크롤을 소유하도록 옮긴다.
3. 기존 콘텐츠 안쪽 여백은 `.ProseMirror` 스타일로 옮겨 보존한다.
4. draft-form dialog 관련 테스트와 프론트엔드 빌드를 실행한다.
5. 데스크톱 및 좁은 화면에서 브라우저 렌더링을 확인하고 결과 문서와 스크린샷을 남긴다.

## 완료 기준

- 스크롤바가 에디터 프레임의 위쪽 경계에서 시작하고, 본문은 기존처럼 안쪽 여백을 가진다.
- 에디터 바깥 프레임 자체는 스크롤하지 않는다.
- draft-form dialog 테스트와 frontend build가 통과한다.
- 공지사항 작성 모달과 저장/이미지 동작에 회귀가 없다.
