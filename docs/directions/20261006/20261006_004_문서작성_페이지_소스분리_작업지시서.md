# 20261006_004 문서 작성 페이지 소스 분리 작업지시서

## 작업 목적

`DocumentWritePage.tsx`에 집중된 문서 목록·요약·작성 모달·편집 상태·샘플 데이터·타입을 페이지 기능 디렉터리 안에서 책임별로 분리한다. 기안양식관리의 기능 폴더 구조와 공지사항 페이지의 조립형 페이지 및 작성 다이얼로그 패턴을 따른다.

## 승인된 범위

- 기존 샘플 문서, 리스트/피드 보기, 업무 구분 필터, 상단 고정, 결재 요약, 작성 모달을 유지한다.
- 작성 모달은 별도 컴포넌트로 분리하고 기존 공통 `CommonDialog`를 그대로 사용한다.
- 작성 본문은 공통 `RichTextEditor`, 툴바는 `RichTextEditorToolbar`를 사용한다. 페이지 전용 `useEditor`/`EditorContent`와 중복 서식 툴바를 만들지 않는다.
- 페이지 조립, 페이지 상태, 작성 편집기 상태, 화면 컴포넌트, 타입, 샘플 데이터의 책임을 분리한다.
- 현재 문서 작성 기능에는 API 호출이 없으므로 `services/`를 억지로 만들지 않는다.
- 저장 버튼은 비활성 상태를 유지한다. API/저장/임시저장/권한 기능을 추가하지 않는다.
- 변경은 `frontend/src/pages/groupware/documents/write/`와 본 작업의 docs 문서 및 결과물로 제한한다.

## 작업 절차

1. 승인 설계를 기준으로 날짜별 계획서와 상세 사양서를 작성한다.
2. 기존 문서 작성 페이지 테스트를 구현 전 실행해 기준 동작을 확인한다.
3. `types/documentWrite.types.ts`, `data/documentWriteData.ts`로 기존 타입과 샘플 데이터를 이동한다.
4. `hooks/useDocumentWritePage.ts`에 보기 방식·필터·모달 열기 상태와 목록 파생 상태를 분리한다.
5. `hooks/useDocumentComposer.ts`에 문서 구분·제목·공통 에디터 인스턴스·첨부 및 닫기 초기화 상태를 분리한다.
6. 피드 항목, 결재 요약, 빈 목록, 작성 다이얼로그를 `components/` 하위 컴포넌트로 이동한다.
7. `DocumentWritePage.tsx`를 조립 중심으로 정리하고 모달은 공용 `CommonDialog`를 이용하는 작성 컴포넌트로 연결한다.
8. 기존 페이지 테스트, 프론트엔드 빌드 및 375px/768px/1280px 브라우저 표시를 확인한다.
9. 결과 보고서와 확인 스크린샷을 날짜별 결과 폴더에 기록한다.

## 검증 및 완료 기준

- `frontend/tests/document-write-page.test.tsx`에서 페이지 렌더링, 보기 전환, 샘플 상태·업무 구분, 작성 모달 탭/입력/툴바가 통과한다.
- `frontend`의 `npm run build`가 통과한다.
- 375px, 768px, 1280px 브라우저 표시에서 기존 레이아웃, 오버플로, 공통 다이얼로그 동작에 회귀가 없다.
- 문서 작성 페이지에서 기존과 동일하게 저장 버튼이 비활성화되어 있으며 새로운 API 호출이나 서버 동작이 없다.
- 작성 모달에서 공통 RichTextEditor/Toolbar를 사용하고, 본문 입력·공통 서식 도구가 동작한다.
- 소스 분리 결과를 반영한 결과 보고서와 스크린샷이 `docs/result/20261006/document-write-page-modularization/`에 있다.
