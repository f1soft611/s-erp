# 공통코드 삭제 메뉴 파생 상태 작업지시서

- 잔여 경고 순차 처리 요청의 다음 단위로 CommonCodeManagementPanel의 render 삭제 guard ref 조회 1건을 처리한다.
- [기존 작업지시서](../20260914/20260914_001_공통코드_관리_기능_점검_작업지시서.md)와 [사양](../../spec/20260914/20260914_001_공통코드_관리_기능_점검_사양서.md)의 삭제·미저장·저장 보호를 유지한다.
- 현재 render는 ref로 현재 삭제 목록을 읽지만 부모 dirty가 이미 true이면 추가 삭제만으로 부모가 다시 렌더되지 않을 수 있다. 실제 두 상세 행을 연속 삭제하는 회귀로 이를 먼저 확인한다. 재현 전 결함이라고 단정하지 않는다.
- 삭제 보호 제거/진단 숨김은 금지한다. contextmenu capture 시점에만 상태를 갱신하는 대안은 선택 갱신 순서에 의존하므로 채택하지 않는다.
- 권장안은 기존 onChangesChange payload에서 정규화한 삭제 ID만 동등성 검사 후 상태로 게시하고, render는 기존 getGroupDeleteBlockedMessage로 같은 정책을 계산하는 것이다. 실제 이벤트와 저장 경로의 ref 기반 최신 guard는 변경하지 않는다.
- 계획 → 사양 → 기존 기준선/RED → 최소 구현 → 관련 정적·실제 3폭 검증 → 결과/스크린샷 → 선행 CI 완료 후 별도 커밋·푸시 순서다.
- API/서비스/DB/SQL·F1Grid/F1Tree 공통 소스·삭제 정책·다른 경고·의존성은 범위 밖이다.
