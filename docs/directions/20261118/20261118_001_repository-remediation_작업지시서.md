# 저장소 리뷰 후속 순차 개선 작업지시서

## 요청과 기준

- 사용자 요청: 저장소 상태 리뷰 결과의 다음 조치를 순차적으로 진행한다.
- 시작 기준: `9a9b0729`. 프론트엔드 전체 테스트는 2,440개 중 90개 실패, 백엔드는 1,133개 통과·3개 제외다.
- 기존 [저장소 검증 작업지시서](../20261117/20261117_003_repository-validation-ci_작업지시서.md)의 실패 비은폐·공유 환경 보존 원칙을 유지한다. 이번 요청은 남은 실패의 복구를 허용하지만 커밋·푸시·병합 요청은 아니다.

## 실행 순서

1. 테스트 실패를 업무별로 재현하고 현재 사양에 맞게 복구한다. 메뉴관리부터 시작한다.
2. 공통 상세검색 빠른 날짜 요청과 사용자 입력 사이의 비동기 경합을 수정한다.
3. 의존성 업데이트를 호환 가능한 묶음으로 분리하고 advisory와 Java 8 호환성을 확인한다.
4. PR #76 충돌 및 백엔드·Java 8 CI의 보강 가능 범위를 확인한다. 원격 변경은 하지 않는다.

각 단계는 앞 단계의 변경과 검증 결과를 기록한 다음 진행한다. 서로 다른 업무의 요구사항을 한 번에 재설계하지 않는다.

## 공유 브랜치 이동 확인

- 조사 도중 공유 작업 공간 HEAD가 별도 작업에 의해 `e9ba60f6`으로 이동한 것을 확인했다. `9a9b0729` 이후 9개 커밋이며 원본 작업을 되돌리거나 재작성하지 않는다.
- 이후 프론트엔드 검증은 먼저 `e9ba60f6` 스냅샷을 고정했다. 기존 전용 검증 worktree의 브랜치를 merge/reset하지 않고 두 커밋 사이의 프론트 변경 패치만 적용했고, 변경 99개 파일의 blob hash 일치를 확인했다.
- 공유 HEAD가 다시 `22bd60b8`으로 이동한 뒤, `e9ba60f6..22bd60b8`의 프론트 변경 4개 파일만 추가 반영하고 해당 blob hash도 확인했다. 최종 집중 테스트와 정적 검사는 **`22bd60b8` 프론트 소스 오버레이 + 이번 복구 변경** 기준이다. 검증 worktree의 Git HEAD 자체는 최초 기준에 그대로 두었다.
- 전체 검사 실행 중 공유 HEAD가 `bf6cf0bb`으로 이동했다. 이 구간의 프론트 변경은 다른 작업의 `PageSearchArea.tsx` 상세검색 backdrop Portal 추가다. 실행 중인 고정 검증 입력은 바꾸지 않으며 이 별도 커밋까지 전체 검증했다고 표현하지 않는다. 실제 브라우저 검증은 공유 서버의 현재 소스에서 수행한 별도 증거다.
- 공유 작업 공간에 별도로 생긴 종합현황·수주현황 운영 파일 수정은 이번 패치에 포함하거나 되돌리지 않는다. 위 고정 기준 검증을 공유 작업 공간의 모든 미커밋 변경 검증으로 표현하지 않는다.
- 기존 실패 수는 시작 기준의 이력이지 최신 HEAD의 실패 수가 아니다. 특히 선택기 storageKey 누락은 별도 작업에서 이미 수정됐으므로 중복 구현하지 않는다.
- 미완료 상태의 이전 기준 일괄 검사는 중단하고 최신 고정 기준에서 다시 집계한다. 공유 브랜치·서버·설치는 변경하지 않는다.

## 안전 범위

- 시작 시 이미 수정된 `docs/result/20261117/development-progress` 문서를 변경하거나 되돌리지 않는다.
- 현재 작업 공간에서 변경 파일을 제한하고 공유 서버·다른 worktree·기존 설치를 임의 교체하지 않는다. 공유 설치와 잠금 파일의 불일치가 있으면 현재 기준 커밋에서 별도 검증용 worktree를 만들고 자동 setup은 실행하지 않는다. 기존 검증용 worktree도 다른 작업 소유일 수 있으므로 재사용하지 않는다.
- 단언 삭제·skip 추가·전역 시간 제한 상향·검사 제외로 실패를 숨기지 않는다.
- 현재 문서의 동작에 맞는 fixture, 요청 mock, 비동기 대기를 우선 수정한다. 제품 회귀가 입증된 경우에만 해당 운영 코드를 최소 수정한다.
- 실 DB, 인증 세션, 민감정보를 사용하지 않는다. DB/API 데이터 계약을 구현·수정할 경우 별도 DB MCP 사전 확인을 수행한다.
- 의존성의 강제 다운그레이드, 무관한 메이저 일괄 업데이트, Java 운영 기준 상향은 하지 않는다.
- 원격 브랜치 보호, 커밋·푸시·PR 병합은 이번 범위에서 제외한다.

## 완료 기준

- 업무별 관련 테스트와 최종 전체 검사 결과를 구별해 기록한다.
- 테스트만 변경한 단계는 UI 스크린샷 대상이 아님을 명시한다. UI 동작을 변경하면 해당 실제 브라우저 검증과 스크린샷을 결과에 포함한다.
- F1-Grid 관련 변경은 사용 문서와 결과 문서를 함께 갱신한다.
- 결과는 `docs/result/20261118/repository-remediation`에 모으고 미해결·보류 항목을 통과로 표현하지 않는다.

## 이번 실행의 종료 상태

- [종합 검증 결과](../../result/20261118/repository-remediation/20261118_009_repository-remediation-validation_결과.md)에 고정 전체 실행과 선택·파일 단위 재검증을 구분했다.
- 기존 화면 보존을 우선해 트리 계층 동작 재설계와 시간 제한 상향은 하지 않았다. 트리 정책 2개와 장시간 테스트 안정성이 남아 테스트 복구 전체 완료로 간주하지 않는다.
- 빠른 날짜 요청 경합, 의존성 업데이트, PR·CI 후속 단계는 보류했다. 추가 운영 변경이나 원격 변경 없이 종료 상태와 필요한 후속 조치를 기록한다.

## 사용자 후속 요청에 따른 재개

- 사용자의 “다음 계속 진행해서 마무리 해야해” 요청으로 위 종료 상태 이후의 작업을 순차 재개한다. 기존 실행 결과는 당시 증거로 보존한다.
- 트리 정책을 재조사한 결과 9월 9일 사양보다 최신인 10월 14일 공통 Grid 사양 §6이 Tree 정렬·필터 비활성화를 명시한다. 따라서 트리 기능을 새로 구현하지 않고 최신 계약에 맞춰 두 구형 테스트를 수정한다. 근거와 검증은 후속 계획·사양 010에 기록한다.
- 다음 단계는 문서작성 지연 테스트 원인 확인, 날짜 경합, 호환 의존성, PR·CI 순서다. 검사 제외·시간 제한 상향·원격 변경 금지는 유지한다.
- 재개 후 트리·문서작성·날짜 경합의 집중 회귀와 백엔드 의존성 전후 비교 및 Java 8 API 컴파일을 수행했다. 새 frontend exact-lock의 CI 동일 2-worker 전체 검증과 최종 잔존 항목은 [후속 종합 결과 015](../../result/20261118/repository-remediation/20261118_015_repository-remediation-final_결과.md)에 기록한다. 앞선 종료 상태와 당시 실패는 역사적 기록으로 유지한다.

## 커밋·푸시 승인 및 다음 단계

- 2026-11-18 사용자의 “현재까지 작업 내역별로 커밋 푸시 동기화 해주고 그 다음꺼 계속 진행해줘” 요청으로 이번 작업 소유 변경의 작업별 커밋과 현재 브랜치 원격 push를 승인받았다. 앞선 커밋 미생성 기록은 당시 실행의 이력이다.
- 기존 전체 검사 실패와 advisory·PR 충돌은 해결된 것으로 표시하지 않는다. 커밋·push는 병합 승인과 다르며 원격 PR merge·강제 push·보호 정책 변경은 하지 않는다.
- 별도 작업의 종합현황 문서·OverviewPage·수주현황 컬럼 수정은 커밋에서 제외한다. 원격이 앞서면 강제 덮어쓰지 않는다.
- 동기화 다음 단계는 문서작성 테스트의 대기·분리 DOM 및 접근성 조회 비용 계측과 최소 테스트 수정이다. 운영 화면을 재설계하거나 시간 제한을 상향하지 않는다.
- 후속 소유 작업은 [문서작성 017](../../result/20261118/repository-remediation/20261118_017_document-test-stability_결과.md), [CI 플랫폼 계약 018](../../result/20261118/repository-remediation/20261118_018_ci-contract-stability_결과.md), [router 현재 DOM 019](../../result/20261118/repository-remediation/20261118_019_router-dom-stability_결과.md)로 이어진다. 모두 테스트·문서 전용이며 이전 운영 변경 다섯 묶음의 범위를 넓히지 않았다. 이전 실패·중단 기록은 보존하고 가장 최신 전체 결과를 별도로 기록한다.
- 같은 공지 테스트 파일에 남아 있던 입력 전제조건은 canonical Tiptap의 지연 생성을 확인해 [후속 020](../../result/20261118/repository-remediation/20261118_020_comment-editor-readiness_결과.md)에서 일관되게 맞춘다. 상세 wrapper와 실제 메뉴 준비는 [후속 021](../../result/20261118/repository-remediation/20261118_021_document-detail-readiness_결과.md)에서 구분한다. 최신 전체 gate와 최종 동기화 상태는 021을 따른다.
- 최종 코드 8937faec의 원격 run 44253972552에서 frontend 226파일·2,641개 전체와 lint/typecheck/build/required가 모두 통과했다. backend 비공개 설정 의존 오류 2개와 잔여 advisory·검증 한계는 별도 보류로 기록하며 저장소 전체 무위험·자동 병합 승인으로 표현하지 않는다.
