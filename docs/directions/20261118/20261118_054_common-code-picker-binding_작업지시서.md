# 공통코드 상위 picker 이벤트 바인딩 작업지시서

- 잔여 경고 순차 처리 요청에 따라 CommonCodeManagementPanel의 ref 경고 2건 중 column factory로 이벤트 callback을 전달하는 1건을 먼저 처리한다. 삭제 가능 여부의 render ref 조회 1건은 별도 검토 대상으로 남긴다.
- [기존 작업지시서](../20260914/20260914_001_공통코드_관리_기능_점검_작업지시서.md)와 [사양](../../spec/20260914/20260914_001_공통코드_관리_기능_점검_사양서.md)의 조회/편집/선택·저장/미저장 보호를 유지한다.
- 기존 factory는 callback을 즉시 실행하지 않는다. 경고만으로 런타임 장애를 주장하지 않는다.
- factory는 활성 boolean만 받아 기존 컬럼 메타데이터를 만들고, 실제 onOpenCodePicker는 컴포넌트의 명시적 컬럼 조립에서 지연 이벤트로 바인딩한다. ref/저장 경합 guard/비동기 조회·선택·오류 함수는 변경하지 않는다.
- callback wrapper만 중첩하거나 lint를 숨기는 대신 순수 컬럼 구성과 이벤트 결합을 분리한다. picker 대상을 새 상태/effect로 옮길 필요는 없다.
- 계획 → 사양 → 기존 기준선/보존 회귀·lint RED → 최소 구현 → 실제 3폭/결과 → 선행 CI 완료 후 별도 커밋·푸시 순서다.
- 서비스/API/DB/SQL·F1Grid/F1Tree 공통 코드·삭제 정책·다른 경고는 범위 밖이다.
