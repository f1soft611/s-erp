# 영업 상세 요청 시작 상태 작업지시서

- 근거: 잔여 lint 순차 해결 요청, [수주 상세 원 지시서](../20261027/20261027_010_수주현황_상세패널_및_상태저장_작업지시서.md), [견적현황 정합성 지시서](../20261117/20261117_007_견적현황_UI정합성_작업지시서.md).
- 같은 요청 시작 패턴의 수주/견적 상세 훅 두 개만 대상으로 한다. ID/재조회 token 변경 첫 commit부터 loading=true와 빈 error를 함께 게시한다.
- 같은 ID 재열기의 기존 무요청 정책, 닫힌 상태 재조회 token의 무요청 정책, 기존 데이터 유지·편집 모드·요청 취소·늦은 응답 무시를 보존한다.
- effect의 두 동기 setter만 bounded request-identity guard로 옮긴다. 서비스 호출·API·응답 타입·화면·권한은 변경하지 않는다.
- 계획/사양 → 실제 훅 commit RED → 최소 구현 → 회귀·정적·3폭 native → 결과/스크린샷 → 선행 CI 성공 뒤 별도 커밋·푸시 순서다.
