# React Refresh export 경계 정리 작업지시서

## 목표

lint 기준 파일 `lint025-green.json`에 남은 `react(only-export-components)` 진단 56건을 실제 모듈 책임 분리로 제거한다. 화면, 그리드, 컨텍스트, 함수 시그니처, 데이터, DOM 요소와 props, 렌더링 및 effect 시점은 그대로 유지한다.

## 작업 범위

- 운영 대상: 진단에 기록된 26개 TSX 파일의 비컴포넌트 값·헬퍼·훅·컨텍스트와 관련 직접 소비자.
- 테스트 진입 파일: `frontend/tests/common-dialog-preview.tsx`의 미리보기 컴포넌트 경계를 분리한다.
- 변경은 프론트엔드 소스와 검증 문서로 제한한다. API, 권한, URL, 화면 레이아웃, DB, 의존성 manifest/lock, lint 설정은 변경하지 않는다.
- F1Grid 헬퍼를 옮길 경우 문서화된 패키지 공개 API는 비-TSX barrel에서 보존하고 `frontend/src/pages/f1-grid-docs/F1-GRID.md`의 모듈 경계를 갱신한다.

## 수행 순서

1. 계획서와 상세사양서를 확인해 대상 모듈 및 보존 계약을 확정한다.
2. 컴포넌트와 데이터·순수 함수·타입·컨텍스트/훅의 소유 위치를 분리하고 모든 내부·테스트 소비자 경로를 갱신한다.
3. 실제 Oxlint JSON에서 대상 규칙 경고 0건과 무관한 경고의 비증가를 확인한다.
4. 소유 검증 스냅샷에 의도한 프론트엔드 파일만 동기화한 뒤 typecheck, build 및 전체 Vitest(threads/2 workers)를 실행한다.
5. 결과 문서에 정확한 모듈 이동표, 진단/검증 수치, API 호환성과 UI 증거 범위를 기록한다.

## 금지

규칙 비활성화·예외·허용 목록, 경고 무시, 훅 이름 변경, 인위적 스케줄링, 테스트 제외·재시도·시간 증가, 동작 변경, 불필요한 의존성 변경은 하지 않는다. 검증용 소스 복사본은 지정된 소유 스냅샷만 갱신하며 그 외 공유 파일·ignored 파일은 건드리지 않는다.
