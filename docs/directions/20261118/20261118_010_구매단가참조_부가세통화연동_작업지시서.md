# 20261118_010 구매 단가 참조 시 부가세구분·부가세포함·통화 연동 작업지시서

## 배경
단가등록(20261118_007~009)에 부가세구분·부가세포함·외화단가·통화가 생겼지만, 구매 업무는 단가 조회 결과 중 원화단가와 통화(항상 KRW)만 가져간다. 부가세구분·포함은 발주 헤더에서 사용자가 따로 고르기 때문에, 단가가 "부가세 포함" 기준인 품목을 확정·발주하면 부가세가 이중으로 계산될 수 있다(2026-11-18 사용자 요청: 단가 테이블 정보를 처음 참고해 설정하는 곳에서 부가세구분·포함·통화를 함께 설정하고, 그 뒤로는 업무에 등록된 정보가 따라가야 한다).

단가 테이블을 참고하는 곳은 두 곳이다.
1. **구매요청확정**(구매요청 → 확정): 구매처가 정해질 때 단가를 조회해 확정 행의 단가를 채운다.
2. **발주 직접등록**(구매요청 없이 발주에서 바로 등록): 품목을 추가할 때 같은 단가 조회를 호출한다. (현재 단가와 통화는 채우지만 부가세는 채우지 않는다.)

## 정책 (사용자 요청 기반, 세부는 확인 후 확정)
- 단가를 **처음 참고하는 시점**에 단가 행의 부가세구분·부가세포함·통화가 함께 설정된다. 이후 단계는 그 시점에 등록된 값을 따른다(단가 테이블을 다시 읽어 덮어쓰지 않는다).
  - 구매요청확정: 확정 행에 부가세구분·부가세포함·통화를 저장한다. 발주는 확정 건에 저장된 값을 가져온다.
  - 발주 직접등록: 첫 품목의 단가 정보로 발주 헤더의 부가세구분·포함·통화를 정하고, 이후 품목은 헤더 값을 따른다.
- 한 발주서는 헤더에 부가세구분·부가세포함·통화가 하나씩만 있으므로, 서로 다른 값의 확정 건/품목은 같은 발주에 담을 수 없다(통화는 이미 같은 규칙이다).
- 단가에서 가져온 값은 화면에서 수정할 수 있다(사용자가 최종 결정).
- 부가세포함은 과세일 때만 허용한다(발주의 기존 규칙). 단가 저장 시에도 같은 규칙으로 검증한다.
- **원화단가와 외화단가는 둘 중 하나 이상만 있으면 등록할 수 있다**(외화단가만 관리하고 원화단가는 관리하지 않는 거래처·품목 허용). 구매에서 단가를 참고할 때의 기본 설정은 다음과 같다(사용자 확정).
  - 원화단가가 있으면 **원화(KRW) + 원화단가**가 기본이다. 외화단가도 같이 등록되어 있으면 통화를 그 외화통화로 바꿀 때 단가를 외화단가로 바꿔 채운다.
  - **외화단가만 등록되어 있으면 외화통화 + 외화단가**로 기본 설정한다.

## 범위
- 포함: 단가등록의 원화단가 필수 완화(DB 제약·저장 검증·화면), 단가 조회 API 확장, 구매요청확정(DB 컬럼·API·화면), 발주(확정 불러오기·직접등록 헤더 설정), 단가 저장 검증 보강, 테스트용 단가 데이터 등록 후 실제 작동 확인.
- 제외: 외화단가 자동 환산·환율, 입고·검사·마감 단계 변경(발주 헤더 값을 이미 따른다), 영업 파일.

## 완료 조건
- 구매요청확정에서 구매처를 정하면 단가와 함께 부가세구분·포함·통화가 채워지고 저장된다.
- 발주에서 확정 건을 불러오면 헤더의 부가세구분·포함·통화가 확정 값으로 채워지고, 다른 값이 섞이면 막힌다.
- 발주 직접등록에서 첫 품목 추가 시 헤더의 부가세구분·포함·통화가 단가 정보로 채워진다.
- 관련 테스트 통과, 실제 단가 데이터를 등록해 확정→발주와 직접 발주를 끝까지 확인한 결과 문서.
