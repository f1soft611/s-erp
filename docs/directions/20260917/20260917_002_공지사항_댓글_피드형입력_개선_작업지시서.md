# 20260917_002 공지사항 댓글 피드형 표시·입력 개선 작업지시서

## 작업 목적

공지사항 댓글 영역을 일반적인 피드형 대화 UI에 맞게 정리한다. 답글의 답글이 재귀적으로 깊어지지 않도록 표시 깊이를 제한하고, 댓글·답글 입력창은 기본 한 줄로 제공하면서 키보드 입력 흐름을 간결하게 만든다.

## 대상 페이지 및 범위

- 대상 페이지: `http://127.0.0.1:4173/groupware/community/notice`
- 주요 컴포넌트:
  - `frontend/src/shared/components/feed/TiptapCommentThread.tsx`
  - `frontend/src/pages/groupware/community/notice/components/NoticeFeedList.tsx`
  - 필요 시 `frontend/src/pages/groupware/community/notice/CommunityNoticePage.tsx`의 댓글 트리 변환 로직
- 관련 테스트와 공지사항 결과 문서도 동작 변경 범위에 맞춰 갱신한다.

## 요구사항

1. 댓글·답글 표시
   - 댓글에 답글, 답글에 답글이 계속 들여쓰기되는 무한 depth UI를 제거한다.
   - 서버의 `parentCommentId`와 기존 댓글 CRUD 계약은 유지한다.
   - 화면은 최상위 댓글과 그에 속한 답글을 피드 스타일의 최대 2단계로 표시한다.
   - 어느 깊이의 답글에서 답글을 작성하더라도 화면 표시가 추가 depth로 확장되지 않도록 최상위 댓글 기준으로 연결한다.
   - 기존 댓글/답글 수정·삭제·첨부파일 액션은 유지한다.

2. 댓글·답글 입력
   - 댓글과 답글 입력창은 최초 표시 시 한 줄 높이로 시작한다.
   - `Enter`는 댓글 또는 답글 등록으로 동작한다.
   - `Shift+Enter`는 등록하지 않고 입력 내용 안에서 줄바꿈한다.
   - 등록 중 API 실패 시 입력 내용과 선택한 첨부파일을 유지한다.
   - 입력창 우측 끝에 첨부파일 아이콘을 유지하고, 파일 선택·표시·등록 계약은 기존 동작을 따른다.
   - 여러 줄 내용이 있을 때만 입력 영역이 내용에 맞게 확장되며, 불필요한 기본 여백은 제거한다.

3. 댓글 피드 간격
   - 댓글 본문과 답글 사이의 수직 여백을 현재 피드 목록의 항목 간격 수준으로 조정한다.
   - 모바일 375px, 태블릿 768px, 데스크톱 1280px에서 텍스트·입력창·첨부 아이콘이 겹치거나 잘리지 않아야 한다.

## 권장 설계

- **권장: 표시 계층만 평탄화**
  - 서버 데이터 구조와 `parentCommentId`를 보존하고, 공통 댓글 컴포넌트에서 표시용 계층을 최상위 댓글 + 답글 1단계로 제한한다.
  - 기존 CRUD API와 페이지 로컬 트리 갱신 로직의 변경 범위를 최소화할 수 있다.
- **대안: 저장 시 부모 정규화**
  - 답글 작성 시 항상 최상위 댓글 ID를 서버에 전달한다.
  - 데이터 의미가 바뀌고 기존 데이터와의 호환·백엔드 계약 검토가 필요하므로 이번 작업에서는 적용하지 않는다.

## 제외 범위

- 백엔드 API 신규 설계 및 DB 스키마 변경
- 댓글 권한 정책, 정렬 정책, 페이지네이션 정책 변경
- 공지사항 외 다른 피드 화면의 일괄 개편
- 댓글 에디터의 서식 기능을 새로 추가하는 작업

## 완료 기준

- 댓글과 답글이 최대 2단계 피드 형태로 표시되고 답글의 답글 때문에 추가 들여쓰기가 생기지 않는다.
- 댓글·답글 입력창이 한 줄로 시작한다.
- `Enter` 등록, `Shift+Enter` 줄바꿈이 실제 브라우저에서 동작한다.
- 첨부파일 아이콘이 입력창 끝에 표시되고 기존 첨부파일 등록이 유지된다.
- 댓글·답글 CRUD 및 실패 시 재입력 상태가 회귀하지 않는다.
- 관련 Vitest 테스트와 `npm run build`를 통과한다.
- 375px, 768px, 1280px 브라우저 검증 결과와 스크린샷을 결과 문서에 기록한다.
