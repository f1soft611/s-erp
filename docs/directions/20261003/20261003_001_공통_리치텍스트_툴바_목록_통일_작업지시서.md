# 20261003_001 공통 리치 텍스트 툴바 목록 및 스타일 통일 작업지시서

## 작업 분류

- 대상: shared rich-text editor, 공지 작성, 기안양식 본문 작성
- 목적: 사용자가 제공한 toolbar reference에 맞춰 command 목록과 icon style을 통일한다.
- 관련 설계: [공통 editor 및 notice page 분리 설계](../superpowers/specs/2026-10-02-rich-text-editor-and-page-modularization-design.md)
- 범위: 프론트엔드. 백엔드/API/DB 변경은 없다.

## 요구사항

1. Toolbar 목록은 제공된 reference 순서대로 `문단`, 굵게, 기울임, 밑줄, 취소선, 글자색, 표 삽입, 링크, 번호 목록, 글머리 목록을 제공한다.
2. 별도 글꼴/font size 선택기는 두지 않는다. 단, 기존 Tiptap typography marks/extensions와 Excel paste style parsing은 유지해 저장된 기존 본문/붙여넣은 서식을 보존한다.
3. Underline과 Link는 현재 Tiptap StarterKit에 포함된 extension을 사용한다. StarterKit의 Link를 `openOnClick:false`로 configure하고 안전한 기본 protocol 정책을 유지한다. extension 중복 등록이나 별도 direct dependency를 추가하지 않는다.
4. Paragraph selector는 본문과 제목 1/2/3 block을 제공한다. 표 삽입은 기본 3행×3열, header 없는 표를 삽입한다. 링크 command는 URL 입력/적용/제거를 제공한다.
5. 공지와 기안양식의 footer toolbar trigger, icon button size/shape, panel background/border/spacing/scroll behavior는 공통 theme 기반 스타일을 사용한다. Notice 호출부 전용 `triggerSx`/`panelSx`를 제거한다.
6. 좁은 화면에서 toolbar는 기존 내부 horizontal scroll 및 vertical wheel → horizontal scroll 동작을 유지한다.
7. 툴바 내부 아이콘과 툴바 열기 버튼은 32px 정사각형이며 개별 border를 표시하지 않는다. 굵게/기울임/밑줄/취소선/링크/목록 등 현재 활성 상태인 command는 `action.selected` 배경으로 즉시 구분한다. Notice의 첨부 버튼은 툴바 밖의 별도 동작으로 기존 외곽 스타일을 유지한다.
8. 문단 선택은 `본문`(기본 paragraph, 16px/보통), `제목 1`(h1, 24px/굵게), `제목 2`(h2, 20px/굵게), `부제목`(h3, 18px/세미볼드)을 표시하고 실제 본문에도 해당 크기/굵기를 적용한다.
9. 글자색은 기본색 복귀, 12개의 고정 preset swatch, 최근 선택 색상 최대 6개로 구성한다. 최근색은 중복을 제거하고 가장 최근 항목을 앞에 둔다.
10. 링크 팝오버는 표시 텍스트와 URL 입력, 취소와 확인을 제공한다. 기존 URL 검증과 선택 링크 편집/제거 동작은 유지한다.

## 제외 및 보존

- Tiptap schema의 FontFamily/FontSize/Color support 제거
- 기존 본문 JSON/HTML, Excel clipboard allowlist, image upload/save/ownership contract 변경
- 공지와 기안양식의 dialog field/footer action layout 통합

## 완료 조건

- 공통 toolbar에 첨부 목록만 있으며 font/font-size 선택기는 없다.
- 공지/기안양식에서 공통 toolbar trigger 및 panel style override가 없다.
- Paragraph, underline, color, table insertion, link, numbered/bullet list가 실제 Tiptap command에 연결된다.
- focused editor, notice composer, draft form test 및 frontend build가 통과한다.
- 사용자 요청대로 screenshot은 저장하지 않고 결과 문서만 갱신한다.
