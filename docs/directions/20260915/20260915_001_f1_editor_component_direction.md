# 작업지시서: F1Editor 공통 컴포넌트 설계 및 기본 구현

## 1. 작업 개요

F1-Grid와 같은 구조로 재사용 가능한 공통 에디터 컴포넌트 `F1Editor`를 설계하고, 기본 문서형 에디터 스켈레톤을 구현한다.

목표는 다음과 같다.

- F1-Grid와 유사한 공통 컴포넌트 패턴을 유지한다.
- 에디터는 문서 데이터 모델 중심으로 설계한다.
- 기본 텍스트/Heading/List/Field/Section 구조를 지원한다.
- 이미지 붙여넣기, 폰트 크기, 표 생성, 엑셀 붙여넣기 확장 포인트를 포함한다.
- 공지사항 작성 dialog와 같은 실제 화면에 바로 연결 가능한 구조로 만든다.

## 2. 범위

### 포함 범위

- `frontend/src/shared/components/f1-editor/` 신규 생성
- `F1Editor.tsx` 기본 구현
- `types.ts` 문서/노드/스키마 타입
- `schema.ts` 또는 예시 schema 제공
- `extensions/` 내부 확장 코드 예시
  - 이미지 붙여넣기 확장
  - Excel 붙여넣기 확장
  - Font Size 확장
  - Table 확장
- 공지사항 작성 dialog에 F1Editor 적용 예시

### 제외 범위

- Tiptap 라이브러리 설치 및 적용
- 실제 백엔드 API 연동
- 이미지 서버 업로드 기능 완성본 구현
- 완전한 WYSIWYG 문서 편집기 기능 전체 구현
- 테이블 고급 병합/정렬/무한 스냅 기능 구현

## 3. 요구사항

### 3.1 공통 컴포넌트 요구사항

- `F1Editor`는 타입 안전한 문서 데이터 구조를 중심으로 동작해야 한다.
- `schema` 기반으로 입력 필드를 구성할 수 있어야 한다.
- 문서를 JSON 형태로 저장/복원할 수 있어야 한다.
- `onChange`, `onSubmit`를 통해 외부에서 상태를 관리할 수 있어야 한다.

### 3.2 확장 요구사항

- 이미지를 클립보드에서 붙여넣을 수 있어야 한다.
- 폰트 크기 변경 기능을 지원해야 한다.
- 표를 생성하고 삽입할 수 있어야 한다.
- Excel 셀 데이터를 테이블 노드로 변환하는 붙여넣기 로직을 제공해야 한다.

### 3.3 화면 연동 요구사항

- 기존 `NoticeComposerDialog`의 수동 TextField 기반 입력을 F1Editor 구조로 교체하는 예시를 제공한다.
- 구현 결과는 페이지별로 쉽게 재사용 가능해야 한다.

## 4. 비고

- 본 작업은 F1-Grid와 동일한 “공통 컴포넌트 + 재사용형 API” 설계 문서로 진행한다.
- 기능은 MVP 수준으로 설계하고, 이후 단계에서 기능별 확장을 추가한다.
- 문서와 구현이 일치해야 하며, 구현 범위가 지나치게 커지지 않도록 관리한다.
