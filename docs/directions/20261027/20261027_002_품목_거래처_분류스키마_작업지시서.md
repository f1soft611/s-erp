# 20261027_002 품목·거래처 분류 스키마 작업지시서

## 목적

`smart_haccp_schema_2.sql`의 품목/거래처 분류 모델을 S-ERP central DB 구조에 맞게 다시 정의하고, 실제 적용 전 검토 가능한 날짜별 DDL/롤백 초안을 작성한다.

## 승인된 데이터 방향

- `public.tb_cls_item`, `public.tb_cls_partner`를 생성한다. 각 테이블은 `BIGSERIAL` 분류 ID, `tenant_id`, 계층 부모 ID, 분류명, 레벨, 정렬순서, `use_at`, S-ERP 감사 필드를 가진다.
- 품목은 기존 `public.tb_material_info`에 nullable `item_cls_id BIGINT`를 추가하고 `(item_cls_id, tenant_id)` 복합 FK로 tenant별 분류를 참조한다.
- central DB의 `public.tb_customer_info.business_kind1/2`를 각각 거래처 대분류 ID/소분류 ID로 사용하고 `BIGINT NULL`로 전환한다.
- `business_kind1/2`의 기존 비공백 값은 자동 변환하지 않는다. migration 실행 시 하나라도 있으면 예외로 중단한다. NULL과 공백 문자열만 NULL로 정리한다.
- `business_kind3`, `tb_material_info.mat_cata_type` 및 그 외 기존 마스터 데이터는 유지하고 이관하지 않는다.
- 거래처 소분류는 `(business_kind2, business_kind1, tenant_id)` 복합 FK로 지정한 대분류의 직접 자식임을 보장한다. 계층 레벨 및 순환 참조는 후속 API가 검증한다.

## 범위

- 날짜별 계획서와 상세사양서 작성
- `docs/database/20261027`와 `backend/DATABASE/20261027`에 생성 DDL, 변경 이력, guarded rollback을 같은 내용으로 작성
- `docs/database/db-schema.md`에 미적용 초안으로 명시
- DB에는 적용하지 않는다.
- API, 화면, 데이터 backfill, 테넌트 전용 DB 변경은 범위에서 제외한다.

## 필수 안전 조건

1. 다운로드 SQL 전체를 실행하지 않는다. 원본에는 기존 테이블을 `DROP TABLE ... CASCADE`하는 구문이 포함되어 있다.
2. 적용 DDL은 transaction과 마스터 테이블 잠금을 사용한다.
3. 사전조건에서 기존 분류 테이블이 없고, 마스터 및 tenant 복합키가 예상대로 존재하는지 검사한다. 계약 불일치 시 중단한다.
4. `business_kind1/2`는 기존 타입·nullable·default 계약 및 NULL/공백 이외 값이 없는지 적용 직전 재확인한다.
5. 롤백은 분류 테이블과 마스터 참조에 데이터가 없을 때만 허용하고 `CASCADE`를 사용하지 않는다.
6. 두 스키마 폴더의 DDL/이력/롤백 파일을 동일하게 유지한다.

## 작업 순서

1. 이 작업지시서의 계약을 [계획서](../../plan/20261027/20261027_002_품목_거래처_분류스키마_계획서.md)로 분해한다.
2. 계획에 따라 [상세사양서](../../spec/20261027/20261027_002_품목_거래처_분류스키마_상세사양서.md)를 작성한다.
3. 기본 `s-erp-postgresql-readonly` MCP에서 central DB의 tenant, 품목, 거래처 컬럼/키를 다시 확인한다. tenant 전용 DB 계약과 혼용하지 않는다.
4. guard와 FK가 포함된 DDL/rollback 초안을 양쪽 날짜별 DB 폴더에 동일하게 작성하고 schema summary를 갱신한다.
5. SQL 정적 검토, 파일 동일성, `git diff --check`를 확인한다. 적용 테스트나 실제 DB 변경은 하지 않는다.

## 완료 조건

- S-ERP 테넌트 ID 및 BIGINT 식별자 규칙에 맞는 분류 DDL/연결 FK가 문서화되어 있다.
- 거래처 business_kind 데이터 및 기존 품목 분류값을 보존하는 migration guard가 있다.
- 롤백은 분류 데이터/참조가 있으면 중단하며 종속 객체를 cascade 삭제하지 않는다.
- DDL 적용 여부를 “미적용”으로 명확히 표기하고, 실행 권한이나 적용을 주장하지 않는다.
