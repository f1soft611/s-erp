# 20261027_003 품목·거래처 분류관리 API/UI 작업지시서

## 17:46 후속 요청: 변경 없는 저장 차단

- 품목/거래처 분류 설정 모달도 페이지와 동일하게 추가·수정된 행이 없으면 저장 버튼을 비활성화한다.
- 셀 편집 중 변경값은 저장할 수 있어야 하며, 원복 또는 저장 완료 후 변경이 없으면 다시 비활성화한다. 부분 실패 후 미저장 행은 재시도할 수 있어야 한다.

## 17:30 후속 요청: 조용한 저장

- 품목/거래처 분류 설정 저장은 거래처 관리처럼 저장 버튼의 작은 로딩 표시만 사용한다.
- 저장 및 저장 후 재조회 동안 트리 전체 로딩 오버레이를 표시하지 않고 기존 행을 유지한다.
- 최초 조회/수동 재조회 로딩, 저장 중 편집·추가·중복 저장·닫기 차단, 부분 성공과 오류 복구는 유지한다.

## 목적

`20261027_002` 분류 테이블 초안을 사용하는 tenant-scoped 분류 API와 품목·거래처 관리 화면의 분류 설정 다이얼로그를 구현한다.

## 기준 및 승인 범위

- [분류 스키마 설계](../../superpowers/specs/2026-10-27-item-partner-classification-schema-design.md)

- 품목/거래처 마스터 입력 폼의 분류값 연결은 후속 작업으로 분리한다.

## 구현 계약

- API base path: `/api/v1/co/master/classifications`; `items`는 3레벨, `partners`는 2레벨.
- 조회는 업무 메뉴 READ/CREATE/UPDATE 권한 중 하나 이상, 등록은 해당 메뉴 CREATE, 수정은 해당 메뉴 UPDATE 권한으로 제한한다. 별도 tenant-admin 역할 검사는 두지 않는다.
- tenant는 `LoginVO.tenantId`에서만 결정한다. payload에 tenant ID를 받지 않는다.
- 등록/수정/비활성 endpoint를 제공하고 물리 삭제, 부모 재지정, 레벨 변경은 제공하지 않는다.
- 상위 tenant/레벨/활성 상태와 입력 길이·정렬값·사용여부를 서버에서 검사한다.
- 두 페이지는 기존 `PageHeader` action group에서 공통 설정 다이얼로그를 연다. 버튼/폼은 `selectedMenuPermissions`로 권한을 구분한다.
- 다이얼로그는 로딩/오류/저장 및 모바일 세로형 배치를 지원하고 저장 후 재조회한다.
- 분류 컨트롤러의 메뉴 경로 분리와 분류 테스트 코드는 기존 Maven source/target 1.8에서 지원하는 API로 구현한다. 권한 동작이나 프로젝트 JDK 설정은 변경하지 않는다.

## F1Tree 직접 편집 변경 지시

- 분류 팝업은 기존 `CommonDialog`를 사용하고 안내 문구를 타이틀 바로 아래 description에 배치한다. 우측 상단 X도 기존 미저장 확인 경로로 닫으며 최상위/하위 추가 버튼은 본문 우측에 정렬한다. 품목 최대 3단계·거래처 최대 2단계는 유지한다.

- 사용자 요청에 따라 기존 목록/상세 입력 폼 대신 F1Tree에서 분류명·정렬순서·사용여부를 직접 편집하고 저장한다.
- 기존 페이지의 설정 버튼과 팝업 진입점은 유지한다. 최상위/하위 추가, 깊이 제한, 메뉴 권한, 미저장 변경 보호는 유지한다.
- API/DB 계약은 변경하지 않는다. 여러 변경 행은 기존 단건 API로 순차 저장하며 성공한 행은 재전송하지 않고 실패한 행과 미처리 행은 유지한다.
- 새 부모·자식을 함께 작성할 수 있고 저장 시 실제 부모 ID로 연결한다. 전체 저장 성공 후 재조회한다.

## 완료 조건

- API는 인증 tenant 범위만 조회/변경하고 해당 업무 메뉴의 쓰기 권한 없는 요청을 차단한다. 유효한 메뉴 권한을 가진 비관리자는 허용한다.
- 깊이 제한과 잘못된 부모/비활성화 조건이 테스트된다.
- 품목·거래처 각 헤더에서 설정을 열어 계층을 조회·등록·수정·비활성화할 수 있다.
- 관련 backend/frontend 테스트와 build가 통과한다.
- DDL은 적용하지 않았고 DB 통합 실행을 했다고 주장하지 않는다.
