# 20261027_001 수주등록 저장 API 및 사용성 개선 작업지시서

## 목적

수주등록 화면에서 유효한 수주를 실제 저장할 수 있도록 기존
전자정부프레임워크 계층 패턴의 생성 API를 추가하고, 사용자가 입력 오류와
페이지 이탈 없이 편하게 등록하도록 UX를 순차 개선한다.

## 확정 범위

- 생성 API: `POST /api/v1/sales/orders`
- 백엔드 구성: Controller → Service 인터페이스/구현 → DAO
  (`EgovAbstractMapper`) → PostgreSQL MyBatis XML
- 인증된 `LoginVO`에서 tenant와 audit 사용자를 가져온다. 요청 본문의
  tenant, audit, 내부 ID, 수주번호 및 서버 계산 금액을 신뢰하지 않는다.
- `tb_sales_order_hd`, `tb_sales_order_dt`에 헤더와 상세를 하나의
  트랜잭션으로 저장한다.
- 기존 `IdSequenceService`를 사용해 테넌트/수주일별
  `SO-YYYYMMDD-NNNN` 업무번호를 생성한다. 최소 자릿수는 4자리이며
  절삭하지 않는다.
- 기존 수주등록 화면에 필수값 검증, 실제 API 저장, 저장 중 중복 제출 방지,
  성공/오류 안내 및 입력값 보존을 적용한다.
- 이후 미저장 변경 이탈 경고, 품목 선택 발견성, 모바일 상세 입력을
  각각 구분해 개선한다.
- 사용자가 테이블을 직접 생성한다. 이 작업은 테이블 DDL, 마이그레이션,
  롤백 스크립트를 만들거나 실행하지 않는다.
- 수주 목록/조회/수정/취소 API, 견적 전환, 메뉴 설정 변경은 제외한다.

## 데이터 계약

- 요청 필드: `orderDt`, `customerId`, `quotNo`, `deliveryDt`,
  `deliveryPlace`, `deliveryMethod`, `remark`, `details`
- 상세 요청 필드: `materialId`, `orderQty`, `unitPrice`, 선택적 `vatAmt`,
  선택적 `deliveryDt`
- 서버는 tenant 내 거래처/품목을 확인한다. 수량은 0보다 커야 하며
  단가/VAT는 음수가 아니어야 한다. NUMERIC(15,2) 범위를 벗어나는 값을
  거부한다.
- 서버에서 공급가와 합계를 `BigDecimal`, 소수 둘째 자리
  `HALF_UP`으로 계산한다. 사용자가 지정한 VAT는 보존하며, 생략된 VAT는
  공급가의 10%로 계산한다.
- 상태는 헤더 `수주등록`, 상세 `대기`, 출하수량 0으로 서버에서 지정한다.
- 응답은 기존 `ResultVO` item envelope를 따르며 HTTP 201을 반환한다.

## 작업 절차

1. 이 작업지시서를 기준으로 날짜별 계획서와 상세사양서를 작성한다.
2. 백엔드 검증/번호/계산 테스트와 API 테스트를 먼저 작성한다.
3. 기존 eGovFrame 패턴에 따라 DAO/Mapper, Service, Controller를 구현한다.
4. 프론트엔드 요청 서비스/검증을 추가하고 수주등록 저장 흐름과 연결한다.
5. 미저장 이탈 경고, 품목 선택 발견성, 반응형 상세 입력을 순서대로
   개선한다.
6. 프론트엔드 F1-Grid 문서와 결과 문서를 갱신하고 집중 검증을 수행한다.

## 완료 조건

- 비인증 요청은 거부되고 모든 tenant 값은 로그인 문맥에서 파생된다.
- 번호 생성, 금액 계산, tenant 마스터 확인, 헤더/상세 원자적 저장이
  기존 eGovFrame 계층에서 수행된다.
- 잘못된 입력은 저장되지 않으며 UI는 필드 오류를 안내한다.
- 성공은 서버 응답 후에만 표시하고, 실패/네트워크 오류 시 입력을 보존한다.
- 변경된 미저장 폼의 이탈을 경고하며, 품목 선택과 작은 화면 상세 입력이
  키보드/반응형 사용 기준에 맞는다.
- 집중 테스트, 백엔드 빌드/테스트, 프론트엔드 빌드/테스트 및 실제
  브라우저 너비 375/768/1280px 결과를 기록한다.
- 테이블 DDL을 만들거나 DB에 적용하지 않는다. 사용자 생성 후 MCP로 테이블
  메타데이터를 확인하더라도 이 작업에서 실제 DB 저장 검증은 수행하지 않는다.
