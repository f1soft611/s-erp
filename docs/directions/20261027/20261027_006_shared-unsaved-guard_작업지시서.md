# 공통 미저장 브라우저 이탈 보호 작업지시서

## 요청과 확정 방향

- 수주등록의 내부 화면 이동 확인은 기존 `UnsavedChangesConfirmDialog`를 사용한다.
- 새로고침, 탭 닫기, 외부 페이지 이동은 브라우저 `beforeunload`로 보호한다.
- 각 화면의 기존 미저장 변경 판단을 공통 훅으로 연결한다. 검색/조회만 한 상태에는 경고하지 않는다.

## 범위

- 수주등록, 메뉴/모듈/권한/창고, 공통코드/거래처/품목/기안양식 관리.
- 기존 dirty 상태를 가진 공통코드 항목 도움창, 기안양식 본문, 분류설정, 자주 쓰는 결재선 이름 편집창.
- 새 dirty 기준이 필요한 문서/공지 작성, 댓글, 프로필 등의 전체 변경 추적 신설은 제외한다. 공통 경고가 무조건 모든 페이지를 보호하는 것으로 표현하지 않는다.
- 다른 화면의 내부 이동 정책, 공통 다이얼로그 디자인, 저장/API/DB 계약은 변경하지 않는다.

## 완료 조건

- 깨끗한 상태 및 저장/폐기 완료 후에는 브라우저 경고를 요청하지 않는다.
- 저장 실패 및 저장 대기 중 dirty가 남아 있으면 보호한다.
- 여러 소비자 중 하나만 해제/닫혀도 남은 dirty 소비자의 보호는 유지한다.
- unmount 시 등록한 이벤트를 정리한다.
- 수주등록은 계속 작성 시 입력 보존, 버리고 이동 시 원래 목적지로 이동한다.
- 계획/사양 → 실패 테스트 → 구현 → 집중 검증/브라우저/스크린샷/결과 순서를 적용한다.
