# 수주 저장 감사 사용자 길이 오류 작업지시서

## 요청과 근거

- 사용자 보고: 수주등록 저장 시 PostgreSQL `character varying(10)` 길이 초과 오류.
- 기존 [저장 API 작업지시서](../20261027/20261027_001_수주등록_저장API_및_사용성개선_작업지시서.md)의 인증 사용자 기반 audit 저장 계약을 유지한다.
- 기본 DB MCP 메타데이터에서 수주 헤더의 `created_by`, `updated_by`는 `varchar(10)`, 로그인 원본 `tb_login_account.login_code`는 `varchar(100)`으로 확인했다.
- 로그인 Mapper는 `login_code`를 `LoginVO.id`로 매핑하고 수주 API는 이를 서비스에 그대로 전달한다.

## 범위와 완료 기준

- 수주 헤더의 두 audit 컬럼만 `varchar(100)`으로 확장하는 변경 SQL을 작성한다.
- 사용자 키 절삭, 다른 ID로 치환, 프론트엔드 수정, 기존 SQL 이력 덮어쓰기는 하지 않는다.
- 날짜별 계획 → 상세 사양 → 구현 → 결과 문서 순서를 따른다.
- `docs/database`와 `backend/DATABASE`에 같은 SQL·변경 이력·안전 롤백을 남기고 누적 스키마를 갱신한다.
- 합성 데이터로 기존 10자 제한, 변경 후 11/100자 보존, 101자 거부 및 롤백 데이터 보호를 검증한다.
- MCP는 읽기 전용이다. 실제 업무 DB의 DDL 실행 및 수주 저장은 수행하지 않고 적용 필요 상태를 명확히 남긴다.
- UI 변경이 없으므로 화면 스크린샷 대신 DB 메타데이터 근거와 검증 결과를 결과 문서에 기록한다.
