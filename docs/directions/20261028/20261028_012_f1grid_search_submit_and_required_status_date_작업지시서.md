# 상세검색 조건 제출 및 현황 기준일 필수화 작업지시서

## 배경

상세검색 칩의 조건 해제는 현재 페이지 검색을 즉시 실행한다. 조건을 여러 개 제거할 때마다 목록 조회가 반복되어, 데이터가 많은 화면에서 불필요한 지연이 생길 수 있다. 또한 문서현황(사용자 요청의 업무현황)에는 결재신청일 검색 조건이 있지만 필수 조건으로 검증하지 않는다.

## 목표

- 칩 X는 검색 입력 초안만 변경하고, 상세검색의 `조회` 버튼을 누르기 전에는 검색/API 호출을 하지 않는다.
- 필수 조건 칩의 해제 버튼은 비활성화하여 적용 기준일 자체를 해제할 수 없게 한다. 따라서 상세 패널을 닫고 상단 조회를 눌러도 필수 기준일이 빠지지 않는다.
- 여러 조건을 차례로 제거해도 이전 초안 제거가 되살아나지 않는다.
- 실제 그리드 결과와 적용조건 칩은 다음 검색이 완료될 때까지 현재 적용 스냅샷을 나타낸다. 검색 전 변경을 알려 사용자가 명시적으로 조회하도록 한다.
- 문서현황의 결재신청일을 필수 검색 기간으로 지정한다.
- 상세검색 조건 변경 안내가 표시될 때도 초기화/조회/닫기 버튼을 우측 맨 위 행에 유지한다. 좁은 화면에서는 칩 영역이 잘리지 않도록 버튼과 칩을 별도 행에 둔다.
- 기존 세션에 결재신청일이 누락된 경우 초기 조회 전에 현재 서버 기본 기간을 보충한다.
- 이후 신규 현황 페이지는 기준일을 필수 상세검색 조건으로 선언한다.

## 범위

- 공통 `PageSearchArea` 및 관련 회귀 테스트
- 문서현황 검색 컬럼 메타데이터·세션 초기화·테스트
- `frontend/AGENTS.md`, `frontend/src/pages/f1-grid-docs/F1-GRID.md`
- 날짜별 계획·상세사양·결과 문서
- API, backend, database는 변경하지 않는다.

## 절차 및 완료 조건

1. 조건 칩 제거가 조회 callback을 호출하지 않는 실패 테스트를 추가한다.
2. 편집 중인 초안 기준으로 연속 제거를 처리하고, 필드가 이미 비워졌으면 해당 칩의 제거 버튼을 비활성화한다.
3. 적용조건은 기존 조회 스냅샷 그대로 보이고, 상세검색 패널에 조회 전 변경 안내를 표시한다.
4. 문서현황 `submittedAt`을 필수로 표시·검증하고, 구형 세션에서 기간이 누락되면 조회 기본값을 합친다.
5. 수동 조회 후에만 조건이 적용되고 필요한 경우 세션에 반영됨을 테스트한다.
6. 프론트엔드 빌드와 관련 테스트를 실행하고, F1-GRID 문서 및 결과 문서를 갱신한다.
