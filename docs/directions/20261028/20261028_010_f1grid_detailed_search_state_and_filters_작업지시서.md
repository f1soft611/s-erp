# F1-Grid 상세검색 조회 상태 및 필터 제거 개선 작업지시서

## 배경

공통 `PageSearchArea`의 상세검색은 접혀 있을 때 적용 여부를 알기 어렵고, 상세검색 입력값은 한 번에 초기화할 수 있지만 현재 적용된 상세조건 중 일부만 빠르게 제거할 수 없다. 또한 F1-Grid 상세검색을 사용하는 일부 페이지는 같은 탭에서 재진입할 때 마지막 조회조건을 복원하지 않는다.

## 목표

- 실제 조회에 적용된 상세검색 조건이 있을 때 접힌 상세검색 버튼에 활성 표시를 제공한다.
- 상세검색 패널 하단 왼쪽에 현재 적용된 조건을 개별 제거할 수 있는 칩으로 표시한다.
- 칩 제거는 해당 상세조건만 해제해 기존 조회 흐름을 다시 실행하고, 검색어와 나머지 조건을 보존한다.
- 조회 필수 상세조건은 실행 시 검증하고, 수주현황의 수주일자는 시작일과 종료일을 모두 요구한다.
- 상세검색을 연 상태로 조건을 해제하거나 초기화해 목록이 로딩되어도 그리드 로딩 덮개가 검색 패널 위에 나타나지 않게 한다.
- 검색 실행 전 입력값이 저장되지 않도록 하면서 품목관리, 거래처관리, 기안양식관리, 커뮤니티 자료실의 마지막 실행 검색조건을 탭 세션에 저장·복원한다.
- 이미 세션 조회 상태가 있는 공통코드관리, 수주현황, 문서현황의 동작은 유지한다.

## 범위 및 기준

- 공통 `PageSearchArea`와 F1-Grid 상세검색 페이지 및 관련 테스트를 수정한다.
- 활성 상태는 현재 폼 초안이 아닌 마지막으로 실제 적용한 상세검색 스냅샷을 기준으로 한다.
- 미저장 그리드 변경 확인을 취소하면 새 조회조건 및 활성 칩을 적용하지 않는다.
- `초기화`는 기존 기본값 복원 동작을 유지한다.
- 세션 저장은 `sessionStorage`와 기존 `usePageSessionState` 규칙을 사용하고, 조회조건 외 Grid 상태는 저장하지 않는다.
- backend/API/DB 및 F1-Grid 핵심 데이터 동작은 변경하지 않는다.

## 작업 절차

1. 본 작업지시서, [계획서](../../plan/20261028/20261028_010_f1grid_detailed_search_state_and_filters_계획서.md), [상세 사양서](../../spec/20261028/20261028_010_f1grid_detailed_search_state_and_filters_상세사양서.md)를 기준으로 범위를 고정한다.
2. 공통 검색영역 테스트에서 적용된 조건 표시, 개별 제거, 검색 전 입력 미표시의 실패 사례를 먼저 추가한다.
3. `PageSearchArea`의 적용조건 표시/제거를 구현하고, 기존 세션 패턴에 따라 누락된 네 페이지의 조회조건 복원 및 저장을 추가한다.
4. 검색 필수 메타데이터와 제출 전 검증을 추가하고 수주현황 수주일자 범위에 적용한다.
5. 미저장 변경 확인 취소/계속, 상세조건 개별 제거 후 검색어와 다른 조건 유지, 기존 세션 페이지의 회귀를 검증한다.
6. 로딩 덮개와 상세검색 패널의 겹침 순서를 확인한다. F1-GRID 사용자 문서와 결과 문서를 갱신하고, 375px/768px/1280px 브라우저 화면 및 스크린샷을 확인한다.

## 완료 조건

- 상세검색 조건을 실제 조회에 적용한 경우에만 접힌 버튼이 활성 표시되고 조건 개수가 접근 가능한 설명에 제공된다.
- 패널 하단 왼쪽에 실제 적용된 조건만 읽기 쉬운 값의 칩으로 표시되며 각 칩은 자기 조건만 제거한다.
- 개별 제거는 기존 조회/로딩/오류/미저장 변경 보호 흐름을 따른다.
- 필수 상세조건이 빠진 제출은 조회를 실행하지 않고 필드 오류를 표시한다. 수주현황은 수주일자의 양 끝 날짜가 모두 있어야 한다.
- 상세검색 패널이 열린 동안 그리드 로딩 덮개는 검색 패널 위에 표시되지 않는다.
- 네 누락 페이지는 실행한 검색어와 상세조건으로 같은 탭 세션에서 재진입 시 목록을 복원한다. 실행 전의 초안은 복원하지 않는다.
- 기존 세션 지원 페이지 및 상세검색 초기화 동작이 유지된다.
- 관련 테스트와 `npm run build`가 통과하고 F1-GRID 문서, 결과 문서, 브라우저 스크린샷이 포함된다.
