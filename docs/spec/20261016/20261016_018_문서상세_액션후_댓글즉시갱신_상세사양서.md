# 문서 상세 액션 후 댓글 즉시 갱신 상세 사양서

## 대상

- 문서작성 및 문서현황의 전자결재 상세에서 실행하는 승인, 반려, 보완요청,
  결재신청 취소, 승인 취소
- 프론트엔드 상세/피드 컴포넌트의 상세 상태 및 통합 댓글 페이지 상태

## 정상 흐름

1. 사용자가 기존 권한/상태 조건에 따라 액션을 실행하고 필요한 확인/사유를 입력한다.
2. API 요청이 성공하면 기존 액션별 성공 알림을 표시한다.
3. 컴포넌트가 상위 목록 새로고침을 요청하고 기존 상세 재조회 경로를 실행한다.
4. 댓글 API를 첫 페이지 조건으로 다시 요청한다: `limit: 3`, `beforeCommentId` 없음.
5. 최신 `comments`, `systemEvents`, `resultCnt`, `hasPrevious`,
   `nextBeforeCommentId`를 현재 컴포넌트 상태에 적용한다.
6. 문서 상세는 열린 상태를 유지하고 최신 시스템 메시지가 댓글 스트림에 표시된다.

## 액션별 동작

| 액션 | 성공 후 상세 | 상세 재조회 | 댓글 재조회 | 상위 목록 |
|---|---|---|---|---|
| 승인 | 유지 | 수행 | 최신 페이지 | 갱신 |
| 반려 | 유지 | 수행 | 최신 페이지 | 갱신 |
| 보완요청 | 유지 | 수행 | 최신 페이지 | 갱신 |
| 결재신청 취소 | 유지 | 수행 | 최신 페이지 | 갱신 |
| 승인 취소 | 유지 | 수행 | 최신 페이지 | 갱신 |

댓글 재조회는 이전 페이지까지 로드했던 상태를 최신 페이지 기준으로 교체한다.
이 동작은 방금 생성된 메시지를 바로 노출하기 위한 것이며 페이지 계약/페이지
크기는 변경하지 않는다.

## 오류 처리

- 액션 API 실패: 기존 액션 오류를 표시하며 성공 알림, 상세의 성공 갱신, 댓글
  재조회를 수행하지 않는다.
- 액션 성공 뒤 댓글 API 실패: 액션 성공 알림과 성공 결과를 유지한다. 기존
  댓글 오류 및 재시도 UI를 표시하고, 실패한 API 응답을 빈 댓글로 대체하지 않는다.
- 상세 재조회 실패: 기존 상세 재조회 오류 표시를 사용한다. 댓글 재조회는
  별도로 동작해 액션 성공과 댓글 오류 처리를 서로 덮지 않는다.
- 성공 핸들러에서 현재 상세를 닫지 않는다. 사용자가 직접 닫을 때의 동작은 유지한다.

## 회귀 테스트 기준

1. 승인 성공 후 `listApprovalComments`가 초기 요청과 액션 후 요청 두 번 호출되고,
   두 번째 응답의 시스템 메시지가 화면에 나타나며 `onClose`는 호출되지 않는다.
2. 반려와 보완요청의 사유 검증/요청/기존 오류 동작이 유지된다.
3. 각 취소 성공 후 댓글이 재조회되고 상세가 열린 상태이며 상세 API를 다시 요청한다.
4. 액션 성공 뒤 댓글 재조회가 실패해도 성공 알림을 유지하고 댓글 오류를 표시한다.
5. 액션 자체 실패 시 댓글 API 호출 수가 초기 조회에서 증가하지 않고 기존 액션
   오류가 표시된다.
6. 댓글 초기 페이지의 limit/cursor와 통합 시스템 메시지 렌더링 계약이 유지된다.

## 검증

- `cd frontend; npm run test -- tests/document-write-page.test.tsx`
- `cd frontend; npm run build`
- 375px, 768px, 1280px 브라우저 너비에서 액션 후 상세 유지와 댓글 갱신을 확인한다.
- 브라우저 액션은 승인된 테스트 문서에서만 수행하고, 결과 캡처에는 민감한 정보를
  포함하지 않는다.
