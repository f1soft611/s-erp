# 전자결재 참여자 문서목록 조회 누락 상세 사양서

## 1. 목적 및 근거

결재자 계정으로 문서작성 페이지를 열었을 때, 결재선에 참여자로 지정된 문서가 기본 목록 및 처리 대기 요약에서 누락되지 않도록 서비스의 조회 파라미터 전달을 보완한다.

- 작업지시서: [20261016_004 전자결재 참여자 문서목록 조회 누락 작업지시서](../../directions/20261016/20261016_004_전자결재_참여자문서목록_조회누락_작업지시서.md)
- 계획서: [20261016_004 전자결재 참여자 문서목록 조회 누락 계획서](../../plan/20261016/20261016_004_전자결재_참여자문서목록_조회누락_계획서.md)
- 기존 작업공간 사양: [20261012_004 전자결재 순차처리 및 문서작업공간 상세 사양서](../20261012/20261012_004_전자결재_순차처리_문서작업공간_상세사양서.md)

## 2. 확인된 계약 및 원인

- 인증 객체에서 `LoginVO.id`는 기안자 식별에, `LoginVO.uniqId`는 결재선 참여자 식별에 사용한다.
- `tb_electronic_approval_line_info.participant_user_id`는 결재선의 참여자 식별값이다.
- 목록 SQL의 참여자 관련 문서 조건, `MY_PENDING` 필터, 요약의 처리 대기 건수 및 알림 조회는 모두 `participantUserId` 파라미터를 참조한다.
- 서비스 공통 파라미터 생성부가 `drafterUserId`만 넣고 `participantUserId`를 넣지 않아 DAO 쿼리의 참여자 조건이 인증 사용자의 ID로 바인딩되지 않는다.
- `s-erp-postgresql-readonly`의 `list_tables` 및 `describe_table`로 관련 테이블과 식별 컬럼 메타데이터를 읽기 전용 확인했다. 행 데이터는 이 사양서에 기록하지 않는다.

## 3. 확정 동작

- 모든 공통 문서 조회 파라미터에 다음 값이 포함되어야 한다.
  - `tenantId = LoginVO.tenantId`
  - `drafterId = LoginVO.id`
  - `participantUserId = LoginVO.uniqId`
- 기본 `ALL` 문서 목록은 현재 tenant에서 로그인 사용자가 기안자인 문서 또는 임시저장이 아닌 결재선 참여 문서를 반환한다. 타인 `DRAFT` 제외 정책은 후속 [타인 임시저장 조회 제외 사양](20261016_014_문서작성_타인임시저장_조회제외_상세사양서.md)을 따른다.
- `MY_PENDING`은 해당 사용자의 결재선 `action_status = 'PENDING'` 문서만 반환한다.
- 요약의 처리 대기 건수와 알림은 동일한 참여자 식별값을 사용해 조회한다.
- 기존 tenant 조건, 접근 권한 검사, API 경로, 응답 형식, 정렬 및 문서 상태 전이는 변경하지 않는다.

## 4. 구현 범위 및 비범위

### 포함

- `DocumentApprovalServiceImpl.actorParams`에 `participantUserId` 전달을 추가한다.
- 서비스 테스트에서 목록 및 요약 DAO 호출 파라미터에 인증된 `uniqId`가 포함되는지 검증한다.

### 제외

- Mapper SQL, DB 스키마·데이터, API 요청/응답, 프런트엔드 코드 변경
- 다른 사용자 또는 tenant의 데이터 조회
- 문서 목록 UI 변경, 임의의 기본 필터 변경

## 5. 검증 기준

1. 수정 전 회귀 테스트는 목록/요약 DAO 파라미터에 참여자 ID가 없는 이유로 실패한다.
2. 수정 후 두 조회 경로 모두 `LoginVO.uniqId`와 같은 `participantUserId`를 전달한다.
3. `DocumentApprovalServiceImplTest`, `DocumentApprovalApiControllerTest`, `DocumentApprovalMapperTest`가 통과한다.
4. `git diff --check`가 통과하고 DB 마이그레이션 또는 tenant 행 조회가 발생하지 않는다.
