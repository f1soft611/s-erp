# 문서작성 활성 필터 칩 표시 및 개별 취소 상세 사양서

## 화면 위치와 표시

- 대상 경로: `/groupware/doc/write`
- 피드 및 리스트 공통 `PinnedViewToolbar`에서 기존 업무구분 필터/`전체 조회` 버튼 위치에 적용한다.
- 업무구분 메뉴는 유지한다. `전체 조회` 버튼은 제거한다.
- 활성 필터마다 한 개의 hashtag 칩을 렌더링한다. 활성 조건이 없으면 칩이 없다.
- 칩 텍스트는 접두어 `#`와 선택값이다:
  - scope: 승인 요약/문서 상태에서 사용 중인 scope 표시명
  - kind: 전체 업무구분 명칭
  - selected document: 알림 문서 제목; 제목을 얻을 수 없는 경우 `문서 {id}` fallback
- Chip 삭제 조작은 식별 가능한 접근성 이름을 제공하는 버튼이며 키보드로 실행 가능해야 한다.
- 칩 행은 유동 너비/줄바꿈을 사용해 375px에서도 페이지 가로 넘침을 유발하지 않는다.

## 필터 및 제거 계약

세 가지 독립 상태는 기존 `scope`, `selectedKind`, `selectedDocumentId`이다.

| 조건 | 활성 기준 | 칩 라벨 | X 클릭 결과 |
| --- | --- | --- | --- |
| 결재 범위 | `scope !== 'ALL'` | `#{scope 표시명}` | scope만 `ALL`로 설정 |
| 업무구분 | `selectedKind !== ''` | `#{selectedKind}` | kind만 `''`로 설정 |
| 알림 문서 | `selectedDocumentId !== undefined` | `#{문서 제목}` | document ID만 `undefined`로 설정 |

- 제거 시 나머지 조건을 그대로 유지한다.
- 제거된 필터 상태는 기존 hook effect에 의해 목록/요약을 다시 조회한다.
- 현재 `viewMode`와 선택된 상세 패널은 변경하지 않는다.
- 기존 scope 선택 및 알림 선택 동작은 유지한다.
- 재조회 중 loading, 실패, retry 동작은 기존 화면 lifecycle을 따른다.
- 별도의 전체 초기화 버튼/동작을 만들지 않는다.

## 라벨 일관성

- scope 표시명은 한 공통 helper에서 관리하고 승인 요약/문서 상태 패널과 chip이 동일한 값을 재사용한다.
- 알려진 scope 라벨은 기존 UI 그대로다: `MY_PENDING`→`내가 처리할 결재`, `IN_PROGRESS`→`결재 진행 중`, `DRAFT`→`작성 중 문서`, `COMPLETED`→`승인`, `REVISION_REQUESTED`→`보완요청`, `REJECTED`→`반려`.
- 업무구분은 `기안서`, `업무연락`, `지출결의서`, `근태신청` 같은 전체 이름을 사용한다.
- 선택 문서는 기존 summary notice 데이터에서 제목을 찾는다. 없으면 공백 칩 대신 `문서 {id}`를 표시한다.

## 테스트와 완료 조건

- 훅 테스트: scope, kind, document 각각 칩이 생성되고 X 동작 뒤 해당 상태만 제거되며 service call에 남은 조건이 유지되는지 검증한다.
- 페이지 테스트: 활성 조건별 `#` label, delete 버튼의 accessible name, 클릭 결과, 기본 상태에서 칩/전체 조회 버튼 없음, 리스트/피드 모드 유지 및 요청 includeDetails 계약을 확인한다.
- 검증: 집중 Vitest, `npm run build`, 변경 파일 `npx oxlint`, `git diff --check`.
- 브라우저: 인증 가능한 기존 4173 세션에서 375px/768px/1280px 줄바꿈과 가로 overflow를 검사하고 결과 폴더에 가능한 캡처를 저장한다.
- backend, API, DB 변경은 없다.
