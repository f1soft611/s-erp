# 전자결재 반려 사유 메시지 아이콘 상세 사양서

## 1. 목적 및 근거

전자결재 상세 결재선에서 현재 도장 아래에 노출되는 반려 사유를 메시지 아이콘 클릭 후 확인하게 한다. 반려 도장 주변은 기존 카드 크기와 흐름을 유지한다.

- 작업지시서: [20261016_007 작업지시서](../../directions/20261016/20261016_007_전자결재_반려사유_메시지아이콘_작업지시서.md)
- 계획서: [20261016_007 계획서](../../plan/20261016/20261016_007_전자결재_반려사유_메시지아이콘_계획서.md)
- 승인 설계: [반려 사유 메시지 아이콘 표시 설계](../../superpowers/specs/2026-10-16-rejection-reason-message-icon-design.md)
- 기존 결재선 표시 기준: [20261013_003 상세 사양서](../20261013/20261013_003_전자결재_상세_결재선_시각화_상세사양서.md)

## 2. 데이터 계약

- 상세 화면은 기존 `DocumentApprovalDetail.approvalLines` 배열의 `actionComment?: string | null`을 사용한다.
- 신규 endpoint, 응답 필드, 프론트 타입, 요청, 저장소, DB 변경은 없다.
- 팝오버에 표시할 값은 클릭한 개별 승인선의 사유다. 목록 순서나 참여자 상태는 바꾸지 않는다.

## 3. 확정 화면 동작

### 반려 사유 아이콘

- 대상은 `participantType === 'APPROVAL'`, `actionStatus === 'REJECTED'`인 승인선이다.
- `actionComment`에 trim 후 하나 이상의 문자가 있을 때만 메시지 아이콘을 표시한다. 표시는 공백을 정리한 새 사유가 아니라 저장된 원본 `actionComment`를 사용한다.
- 아이콘은 기존 상태 도장의 오른쪽 위에 겹치는 작은 버튼이다. 도장을 가리거나 기존 도장/카드의 크기를 변경하지 않는다.
- 접근성 이름은 참여자 이름을 포함해 `${participantName} 반려 사유 보기`로 제공한다. 키보드로 포커스 및 활성화할 수 있어야 한다.
- 빈 문자열, null, 공백 문자열에는 버튼을 표시하지 않는다.

### 팝오버

- 메시지 버튼 클릭 또는 키보드 활성화 시 해당 버튼에 앵커된 MUI 팝오버를 연다.
- 팝오버 본문에는 현재 버튼에 해당하는 `actionComment` 전문을 표시한다. 줄바꿈이 가능한 폭을 제한해 긴 문장이나 긴 문자열이 뷰포트를 벗어나지 않게 한다.
- 바깥 클릭과 Escape 키로 팝오버를 닫는다.
- 상세 결재선은 계속 읽기 전용이다. 팝오버는 내용을 표시하는 용도이며 결재 처리나 편집 동작을 제공하지 않는다.

### 기존 내용과 레이아웃 보존

- `REJECTED` 승인선의 사유를 상태 도장 아래 인라인 텍스트로 표시하지 않는다.
- `APPROVED`, `RETURNED`, `PENDING`, `WAITING` 등 반려 외 상태의 기존 의견 렌더링은 변경하지 않는다.
- 도장 상태 라벨/접근성 이름, 개인 도장 이미지, 카드 크기, 순서 및 connector는 유지한다.

## 4. 오류 및 상태 처리

- 상세 응답의 사유가 없는 반려선은 아이콘을 생략한다. 렌더링 오류를 사유 없음으로 가장하지 않으며 기존 상세 오류 처리를 변경하지 않는다.
- 버튼을 누르면 클릭한 행의 anchor와 사유를 함께 선택한다. 다른 반려선의 버튼을 누르면 팝오버는 새 행의 사유를 보여준다.
- 팝오버를 닫을 때 선택 상태를 비운다.
- 별도의 fetch, loading, retry 또는 비동기 에러 경로는 추가하지 않는다.

## 5. 범위 제외

- 반려·보완 요청 사유 입력 대화상자와 저장 동작
- 반려 외 상태의 의견 표시 방식
- 상세 API, 백엔드, 타입, DB, 접근 권한, 결재 상태 전이
- 결재선 카드의 전반적인 크기·순서·반응형 배치 변경

## 6. 검증 기준

1. 사유가 있는 `REJECTED` 승인선만 메시지 버튼을 표시한다.
2. 반려 사유 본문은 버튼을 누르기 전에는 도장 아래에 노출되지 않는다.
3. 버튼 활성화 후 클릭한 행의 전문 사유가 팝오버에 나타나며 다른 행의 사유를 혼합하지 않는다.
4. 키보드 활성화, Escape, 바깥 클릭 동작이 통과한다.
5. 빈 사유에는 아이콘이 없고, 반려 외 상태의 기존 의견 표시가 유지된다.
6. `document-write-page.test.tsx` 집중 및 관련 전체 테스트, `npm run build`가 통과한다.
7. 375px, 768px, 1280px 실제 브라우저에서 아이콘이 도장을 덮거나 카드 밖으로 나가지 않고 긴 사유가 화면에 맞춰 줄바꿈된다.
8. 결과 문서에 재현 조건, 해결 방식, 회귀 검증 및 개인정보 없는 캡처가 포함된다.
