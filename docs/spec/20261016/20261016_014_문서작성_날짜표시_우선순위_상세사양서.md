문서작성 화면에서 동일 문서의 날짜가 화면마다 달라지지 않도록 날짜 선택 순서를 통일한다.

- 계획서: [20261016_014 계획서](../../plan/20261016/20261016_014_문서작성_날짜표시_우선순위_계획서.md)

## 날짜 선택 계약

문서 레코드가 가진 날짜 필드 중 첫 번째 사용 가능한 값을 선택한다.

1. `submittedAt` — 표시 원천 라벨 `상신일`
2. `updatedAt` — 표시 원천 라벨 `수정일`
3. `createdAt` — 표시 원천 라벨 `작성일`

`null`, `undefined`, 빈 문자열은 사용할 수 없는 값으로 처리하고 다음 필드로 넘어간다. 사용할 값이 없으면 빈 문자열 및 원천 라벨 없음으로 반환하며, 날짜를 생성하거나 임의 필드로 대체하지 않는다. 선택한 값은 기존과 같이 첫 10자리 날짜를 `YYYY.MM.DD` 형태로 표시한다. 날짜 파싱이나 시간대 변환은 추가하지 않는다.

## 화면별 표시 동작

### 피드

- 피드 카드의 날짜 메타는 상세 데이터가 아직 준비되지 않았을 때 mapped list item의 `date`를 사용한다.
- 상세 데이터가 있는 경우 `submittedAt`, `updatedAt`, `createdAt` 선택 결과를 사용한다.
- 기안자 및 조회수 메타의 기존 구조를 유지하고 날짜 값만 통일한다.

### 리스트

- 리스트 아이템의 `dateLabel`에는 공통 선택 결과를 기존 날짜 포맷으로 표시한다.
- 리스트의 라벨/배지 순서와 클릭 동작은 변경하지 않는다.

### 문서 상세 및 우측 상세 패널

- 상세 패널의 기안자 메타 및 결재선의 기안자 날짜는 공통 선택 결과를 표시한다.
- 기존 기안자 텍스트, 조회수, 구분자와 날짜 없는 경우의 공백 동작을 유지한다.
- 댓글/시스템 이벤트/결재선 처리 시각은 이 사양의 대상이 아니다.

### 우측 `놓치지 마세요` 패널

- 문서별 날짜는 공통 선택 결과를 표시한다.
- 날짜 라벨은 사용된 원천에 맞춰 `상신일`, `수정일`, `작성일` 중 하나를 표시한다.
- 원천 날짜가 모두 없으면 값은 기존처럼 `—`로 표시하고 라벨은 중립값 `일자`를 사용한다.
- 업무구분, 기안자, 카드 클릭 동작은 변경하지 않는다.

## 데이터와 범위

- 필요한 필드(`submittedAt`, `updatedAt`, `createdAt`)는 기존 문서 목록, 상세, 요약 응답에 이미 존재하는 타입을 사용한다.
- 날짜 표시 변경을 위한 API, 데이터베이스, 서버 로직 변경은 없다.
- 현재 `submittedDate` 필드는 다른 사용처의 호환성을 위해 제거하지 않는다. 화면 표시 fallback의 기준은 공통 selector다.

## 테스트 및 완료 조건

- selector 테스트에서 상신일 우선, 수정일 fallback, 작성일 fallback, 모든 날짜 부재를 검증한다.
- hook 테스트에서 목록 및 알림 아이템에 같은 날짜와 원천 라벨이 매핑되는지 검증한다.
- 페이지 테스트에서 피드, 리스트, 상세 패널 작성자 메타, 결재선 날짜, 알림 패널의 날짜/라벨을 검증한다.
- 변경 전 기준 실행 결과와 신규 테스트 결과를 구분해 기록한다.
- 집중 Vitest 실행과 `npm run build`를 수행한다.
- 브라우저 페이지를 375px, 768px, 1280px에서 점검하고 가능한 경우 각 폭의 스크린샷을 결과 폴더에 보관한다.
