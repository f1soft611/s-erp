## 원인 및 DB 근거

임시저장에도 결재선이 존재하므로 결재선 참여 여부만으로 조회를 허용하면 상신 전 문서가 노출된다.
기본 PostgreSQL 읽기 전용 MCP의 `list_tables`, `describe_table`로 다음 메타데이터를 확인했다.

- `tb_electronic_approval_main`: `tenant_id`, `drafter_id`, NOT NULL `document_status`(기본값 `DRAFT`), `deleted_yn`, nullable `submitted_at`.
- `tb_electronic_approval_line_info`: `tenant_id`, `electronic_approval_id`, `participant_user_id`, nullable `action_status`.
- 개인정보·테넌트 행 조회 및 DB 변경은 하지 않는다.

## 접근 조건

기존 tenant 일치, 미삭제 조건을 유지하고 아래 조건을 함께 적용한다.

```sql
AND (
    m.drafter_id = #{drafterId}
    OR (
        m.document_status != 'DRAFT'
        AND EXISTS (
            SELECT 1
            FROM public.tb_electronic_approval_line_info l
            WHERE l.tenant_id = m.tenant_id
              AND l.electronic_approval_id = m.electronic_approval_id
              AND l.participant_user_id = #{participantUserId}
        )
    )
)
```

- 본인 문서는 `DRAFT` 포함 기존 조회를 유지한다.
- 타인 `DRAFT`는 결재선 역할이나 처리 상태와 무관하게 제외한다.
- 타인 `PENDING`, `IN_PROGRESS`, `COMPLETED`, `REJECTED`, `REVISION_REQUESTED`는 기존대로 결재선 참여자만 조회한다. 참조·합의 참여자도 기존 계약을 유지한다.
- 상신 취소는 `DRAFT`로 돌아가므로 동일 조건으로 제외된다.
- 날짜나 개별 결재선의 `PENDING` 여부로 상신 여부를 대신 판단하지 않는다.
- 기존 필터·정렬·페이징 및 `MY_PENDING` 조건은 추가 제한으로 유지한다.

## 적용 경로

공통 SQL 조각을 일반 목록(피드 원천 포함), 페이지 목록/건수, 요약, 알림, 단건 상세, 배치 상세, 참여 권한 검사에 적용한다. 기존 권한 실패 처리와 응답 계약은 변경하지 않는다.

## 회귀 기준

1. 각 조회 SQL의 공통 조건과 `tenantId`, `drafterId`, `participantUserId` 바인딩이 유지된다.
2. 본인 임시저장은 표시되고 타인 임시저장은 표시되지 않는다.
3. 타인 상신 문서는 참여자일 때만 표시된다. 이전/이후 결재 순서나 참조 여부로 불필요하게 제한하지 않는다.
4. 상신 취소 후 문서, 타 tenant, 삭제 문서는 타인에게 표시되지 않는다.
5. 관련 Mapper·서비스·컨트롤러 테스트가 통과한다.

UI 구조, DB 스키마 및 API 형식 변경은 없다. 화면 캡처에 실사용 문서·계정 정보를 남기지 않는다.
