# 문서현황 상세검색 그룹 행 배치 상세사양서

## 1. 화면 요구사항

`/groupware/doc/read`의 F1-Grid 상세검색은 다음 4개 행으로 표시한다.

| 행 | `search.group` | 필드 순서 |
|---:|---|---|
| 1 | 결재신청일 | 결재신청일(from), 결재신청일(to) — span 4 |
| 2 | 결재상태 | 결재상태 — span 2, 문서종류 — span 2 |
| 3 | 제목 | 제목 — span 4 |
| 4 | 기안정보 | 기안자 — 기본 span 1, 기안부서 — 기본 span 1, 결재 참여자 — 기본 span 1 |

그룹 이름은 행을 구분하는 내부 메타데이터이며 화면 제목으로 렌더링하지 않는다. 각 그룹은 독립된 기존 5열 grid 행으로 시작하고, 필드 너비는 `span` 값에 따른다. 좁은 뷰포트에서는 각 그룹 행 안의 필드가 반응형으로 아래에 배치될 수 있다.

## 2. 메타데이터 규칙

- `toPageSearchFields`가 만드는 기존 `group`을 행 레이아웃에 활용한다.
- `search.order` 오름차순을 유지하며, 연속된 동일 group 필드를 하나의 행으로 묶는다.
- 각 그룹 행 내부는 기존 5열 그리드를 사용한다. `search.span`은 그룹이 있거나 없어도 필드 너비를 계속 결정하고, 값이 없으면 1을 사용한다.
- 문서현황의 기존 span 값(결재신청일 4, 결재상태 2, 문서종류 2, 제목 4)을 유지한다.

## 3. 날짜 범위

- 날짜 필드 상단의 별도 `결재신청일` 캡션을 렌더링하지 않는다.
- 두 날짜 입력의 라벨 및 접근성 이름은 `결재신청일 시작일`, `결재신청일 종료일`로 유지한다.
- 값의 형태 `{ from, to }`, 기본 최근 1개월, 조회 파라미터 `submittedAtFrom`/`submittedAtTo`를 바꾸지 않는다.

## 4. 비기능 요구사항 및 영향

- 다른 화면에서 group을 지정하지 않은 검색 필드는 기존 배치와 너비를 유지한다.
- 상세 검색의 값 입력, 초기화, 조회, 닫기 흐름은 바뀌지 않는다.
- 모바일·태블릿·데스크톱에서 검색 필드가 가려지거나 페이지 가로 스크롤이 생기지 않아야 한다.
- 백엔드/API/DB는 변경하지 않는다.

## 5. 검증 기준

- 공통 `PageSearchArea` 테스트: 연속 그룹 묶기 및 그룹 경계 행 나눔, grouped/ungrouped 양쪽의 `searchSpan` 너비 유지.
- 날짜 입력 테스트: 별도 캡션은 없고 두 입력 라벨 및 `{ from, to }` 값 변경은 유지.
- 문서현황 테스트: 메타데이터 순서와 4개 group 배치 확인, 검색 API 필터 회귀 확인.
- `npm run test -- tests/page-search-area-detail.test.tsx tests/page-search-fields.test.ts tests/document-status-page.test.tsx tests/document-status-service.test.ts`
- `npm run build`
- 브라우저에서 375px, 768px, 1280px 확인. 화면 기록은 민감한 문서 행/본문을 포함하지 않는다.
