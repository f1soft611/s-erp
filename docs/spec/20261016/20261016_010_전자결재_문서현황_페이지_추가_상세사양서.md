# 20261016_010 전자결재 문서현황 페이지 추가 상세 사양서

## 1. 개요

### 목적

`/groupware/doc/read`에서 사용자가 과거 전자결재 문서를 검색하고 상세 내용을 확인할 수 있도록 한다. 검색 UI는 F1-Grid 컬럼 정의에서 생성하고, 실제 필터는 전자결재 목록 API에서 처리한다.

- 계획서: [20261016_010 전자결재 문서현황 페이지 추가](../../plan/20261016/20261016_010_전자결재_문서현황_페이지_추가_계획서.md)

## 2. 화면 구조

문서 메뉴의 현재 일반 요약 페이지 대신 아래 구조를 표시한다.

1. 기존 공통 `PageHeader`에 메뉴명/설명을 표시한다.
2. `PageSearchArea`에 기본 키워드 검색과 접이식 상세검색을 표시한다.
3. 오류/정보 메시지는 `PageMessageArea` 패턴을 사용한다.
4. 화면의 주 영역에 읽기 전용 F1-Grid를 표시한다.
5. 행을 선택하면 같은 페이지 안에서 문서 상세 패널을 열고, 상세 조회 API를 호출한다.

상태별 요약 카드, 상태 탭, 좌측 탐색 메뉴, 편집/삭제/결재 액션은 제공하지 않는다.

## 3. 조회 범위 및 기본값

- API 경로: 기존 `/api/v1/groupware/approvals/documents`에 문서현황 검색/원격 조회 조건을 확장한다.
- 기본 scope는 `ALL`이며, 인증 사용자가 기안했거나 해당 문서의 결재선 참여자인 문서만 포함한다.
- tenant 조건, 로그인 사용자 기안자 ID, 결재선 참여자 ID 검증을 기존 서비스/Mapper와 동일하게 유지한다.
- 문서 상태는 기본 전체다. 사용자가 상세검색에서 상태를 선택하면 해당 상태로 좁힌다.
- 최초 날짜 조건은 `submittedAt` 최근 1개월이다. `submittedAt`은 결재신청일이며 본문 기안일과 혼용하지 않는다.
- 조회 날짜는 사용자가 과거 기간으로 변경할 수 있다. 선택 날짜 범위는 API에 `submittedAtFrom`, `submittedAtTo`로 전달한다.
- 날짜 경계는 시작일과 종료일을 모두 포함한다. 종료일은 해당 일자의 마지막 시간까지 포함되도록 서버 조회 조건을 적용한다.

## 4. F1-Grid 컬럼 및 상세검색

`F1GridColumn.search` 정의를 `toPageSearchFields(columns)`에 전달하여 `PageSearchArea` 필드를 만든다. 검색 항목의 순서/이름/그룹은 컬럼 메타데이터를 사용한다. `PageSearchArea`의 날짜 값은 `{ from, to }` 구조로 변환한다. F1-Grid 코어 수정은 하지 않는다.

| 순서 | field | 헤더 | 그리드 표시 | 상세검색 |
|---:|---|---|---|---|
| 1 | `rowNumber` | No | 행번호, 검색 제외 | 없음 |
| 2 | `eabusNo` | 문서번호 | 좌측 고정, 기본 표시 | 키워드 및 상세 부분검색 |
| 3 | `title` | 제목 | 좌측 고정, 기본 표시 | 키워드 및 상세 부분검색 |
| 4 | `documentType` | 문서종류 | 기본 표시 | 선택 |
| 5 | `documentStatus` | 결재상태 | 상태 표시, 기본 표시 | 선택 |
| 6 | `submittedAt` | 결재신청일 | 날짜, 기본 표시 | 날짜 범위, 초기 최근 1개월 |
| 7 | `drafterName` | 기안자 | 이름, 기본 표시 | 이름 검색 |
| 8 | `drafterDepartmentName` | 기안부서 | 부서명, 기본 표시 | 부서 검색 |
| 9 | `participantName` | 결재 참여자 | 결재선 참여자 요약 | 참여자 이름 검색 |
| 10 | `approvalProgress` | 결재 진행 | 단계/처리 진행 요약 | 표시 전용 |
| 11 | `updatedAt` | 최종 변경일 | 날짜 | 날짜 범위 |

### 빠른 검색

기본 검색어 하나를 문서번호(`eabusNo`), 제목(`title`), 기안자(`drafterName`) 부분 검색에 사용한다. 빈 문자열은 조건에서 제외한다.

### 상세검색

- 문서종류: 현재 전자결재 문서 종류 옵션을 사용한다.
- 결재상태: `DRAFT`, `PENDING`, `IN_PROGRESS`, `REVISION_REQUESTED`, `COMPLETED`, `REJECTED`를 화면 표시명으로 제공한다.
- 결재신청일: `submittedAtFrom`, `submittedAtTo`; 최초값은 오늘 기준 최근 1개월이다.
- 기안자/기안부서/결재 참여자: 입력한 문자열을 기준으로 검색한다.
- 최종 변경일: `updatedAtFrom`, `updatedAtTo`. 값이 비어 있으면 조건을 적용하지 않는다.
- 결재 진행은 컬럼 표시용 파생값으로 두고 검색 필드로 노출하지 않는다.

컬럼 숨김, 순서, 너비, 고정 및 그리드 헤더 기능은 기존 F1-Grid 사용자 설정 기능을 사용한다. 이번 페이지만을 위한 컬럼 관리 UI를 별도로 추가하지 않는다.

## 5. API 및 데이터 흐름

### 현재 계약

현행 목록 API는 `scope`, `documentType`, `electronicApprovalId`, `includeDetails`만 받고, 목록 VO에는 문서번호/종류/상태/제목/기안자/생성·수정·상신 시각/요약 값이 있다. 현재 목록 API는 페이지 offset/limit, 검색어, 부서/결재 참여자, 전체 건수를 제공하지 않는다.

### 문서현황 조회 계약

기존 문서작성 화면과 호환되도록 신규 조건은 선택적으로 받는다.

- `keyword`
- `eabusNo`, `title`
- `documentType`
- `documentStatus`
- `submittedAtFrom`, `submittedAtTo`
- `drafterName`
- `drafterDepartmentName`
- `participantName`
- `updatedAtFrom`, `updatedAtTo`
- F1-Grid 원격 데이터 요청의 `offset`, `limit`, 정렬 필드/방향

응답은 현재 사용자 권한으로 조회 가능한 행만 포함하고, F1-Grid `dataSource`가 요구하는 현재 페이지 행 및 `totalRowCount`를 제공한다. 목록 투영에는 문서현황 컬럼에 필요한 `drafterDepartmentName`, `participantName`, `approvalProgress`를 포함한다. 승인선 정보는 기존 `tb_electronic_approval_line_info` 값을 문서 단위로 요약하고, 본문/첨부/댓글 전체를 목록 응답에 포함하지 않는다.

기존 `resultList` 응답을 사용하는 문서작성 화면의 동작 및 호환성을 테스트로 보장한다. 검색 파라미터가 없는 기존 호출은 기존 `scope` 기준으로 동작한다.

### 원격 조회

- F1-Grid 원격 데이터 소스가 제공하는 `offset`, `limit`, 정렬을 서버 목록 쿼리로 전달한다.
- 검색조건 변경 또는 새 조회 실행 시 원격 조회 시작 위치를 초기화한다.
- 날짜/검색조건과 정렬은 tenant 및 인증 사용자 조건과 함께 서버에서 적용한다. 클라이언트에서 전체 목록을 내려받아 사후 필터링하지 않는다.
- `totalRowCount`는 동일한 권한/검색 조건으로 필터링된 전체 건수다.
- 정렬 허용 필드는 목록 컬럼으로 제한하고, 임의 SQL 식별자를 입력받지 않는다.
- 허용 정렬 필드는 `eabusNo`, `title`, `documentType`, `documentStatus`, `submittedAt`, `drafterName`, `drafterDepartmentName`, `participantName`, `approvalProgress`, `updatedAt`이다. 행번호는 `updatedAt` 정렬로 대응한다.
- 사용자 이름 검색 파라미터 `drafterName`은 내부 DAO의 `drafterNameFilter`로 분리하여 로그인 사용자 ID 조건과 구분한다.

## 6. 문서 상세

- 행 선택 시 선택한 `electronicApprovalId`로 기존 상세 조회 API를 호출한다.
- 기존 전자결재 상세 데이터를 읽기 전용으로 표시한다. 상세 조회에서 현재 사용자/tenant의 접근 권한을 다시 검증한다.
- 문서현황에서는 작성/수정, 댓글 작성, 결재 승인/반려/회수 등 변경 액션을 노출하지 않는다.
- 상세 로딩, 오류, 닫기 동작은 메시지/버튼으로 명시하고 오류 시 목록을 성공처럼 대체하지 않는다.

## 7. 로딩, 오류 및 반응형 동작

- 최초 진입 및 검색 중에는 F1-Grid 로딩 표시를 사용한다.
- API 오류는 `PageMessageArea`에 원인을 표시하고 다시 조회할 수 있게 한다.
- 검색 결과가 없을 때는 필터 초기화 또는 기간 확대를 안내하는 빈 상태를 표시한다.
- 375px/768px에서는 검색 필드를 여러 줄 또는 접이식 영역으로 배치하고 페이지 전체 가로 스크롤을 만들지 않는다.
- 넓은 그리드는 그리드 내부에서 수평 스크롤을 허용하고, 문서번호/제목은 초기 좌측 고정 대상으로 한다.
- 상세 패널은 좁은 화면에서 전체 폭 패널 또는 기존 반응형 상세 표시 규칙에 맞춘다.

## 8. DB 확인 범위

2026-10-16 읽기 전용 MCP에서 `public`의 테이블 목록과 아래 테이블의 컬럼 메타데이터만 확인했다.

- `tb_electronic_approval_main`: `tenant_id`, `document_type`, `document_status`, `title`, `drafter_name`, `drafter_department_name`, `created_at`, `updated_at`, `submitted_at`, `eabus_no`, `contents_json` 등
- `tb_electronic_approval_line_info`: 문서 ID, 참여자 ID/이름/부서, 참여자 유형, 단계/참여자 순서, 처리 상태 및 처리 시각

문서현황 요구에 필요한 상신일/기안부서/결재선 데이터는 기존 컬럼을 사용할 수 있어 신규 DB 컬럼/테이블 변경은 계획하지 않는다. 실제 문서 행/본문 JSON은 읽거나 보고하지 않았다. 구현 전 Mapper 필터 및 인덱스/정렬 접근을 검토하고, 신규 스키마 요구가 생기면 이 사양을 수정하고 날짜별 SQL·변경 이력·롤백을 추가한다.

## 9. 검증 기준

### 자동 테스트

- `toPageSearchFields`가 승인된 검색 컬럼과 타입/순서를 생성하는지 확인한다.
- 기본 `submittedAt` 범위가 최근 1개월이며 사용자가 범위를 바꿔 API 조건으로 전달할 수 있는지 확인한다.
- 키워드, 문서종류, 상태, 기안자, 부서, 참여자, 최종 변경일 조건이 서버 쿼리에 정확히 전달되는지 확인한다.
- 원격 로드의 offset/limit/정렬/전체 건수, 빈 결과, 취소/오래된 요청 처리 및 오류 메시지를 확인한다.
- 기존 무조건 목록 호출, 문서작성 피드/상세 호출과 tenant/사용자 권한 범위가 회귀 없이 유지되는지 확인한다.
- 행 선택 상세 조회가 읽기 전용이며 목록 및 상세의 로딩/오류 상태가 노출되는지 확인한다.

### 브라우저 확인

`http://127.0.0.1:4173/groupware/doc/read`에서 375px, 768px, 1280px을 확인한다. 기본 검색, 상세검색 접기/펼치기, 날짜 범위 초기값, 그리드 가로 스크롤/고정 컬럼, 행 상세 패널, 빈 결과/오류 표시를 확인한다. 결과 스크린샷은 `docs/result/20261016/document-status-page/screenshots/`에 저장한다.
