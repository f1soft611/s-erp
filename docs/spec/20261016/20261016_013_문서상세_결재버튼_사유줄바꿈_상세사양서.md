## 화면 흐름

- 현재 처리 권한이 있는 사용자의 상세/피드 반려·보완요청 버튼은 각각 `반려 사유`/`보완요청 사유` 팝업을 연다.
- `처리 사유`는 여러 줄 입력이며 trim 후 빈 문자열은 전송하지 않고 팝업 안에서 안내한다.
- 확인 시 기존 결재 서비스에 해당 action과 사유를 전송한다. 내부 개행과 빈 줄은 그대로 유지한다.
- 처리 중 중복 제출 및 닫기를 차단한다. 실패하면 사유와 팝업을 유지하고 오류를 표시하며 다시 제출할 수 있다.
- 성공 시 팝업/사유를 정리하고 기존 목록 갱신 및 상세 닫기 동작을 유지한다.
- 취소 시 요청하지 않고 사유·오류를 초기화한다.
- 상세 하단 `처리 의견`은 승인의 선택 의견 입력 용도로 유지한다. 승인과 상신/승인 취소의 기존 동작은 바꾸지 않는다.

## 시스템 댓글

- 시스템 메시지는 HTML이 아닌 일반 텍스트로 유지한다.
- `white-space: pre-wrap`과 기존 `overflow-wrap: anywhere`로 개행, 빈 줄 및 긴 문자를 보존/줄바꿈한다.
- 신규 댓글뿐 아니라 기존에 저장된 시스템 메시지에도 적용한다. 일반 사용자 리치 텍스트 댓글은 변경하지 않는다.

## 사유 입력 공통 셸 (추가 승인)

- 반려/보완요청 모두 기존 `CommonDialog`를 `size="xs"`(최대 480px), 기본 content 모드로 사용한다.
- 제목은 반려 사유/보완요청 사유, 공통 설명은 `처리 사유를 입력해 주세요.`이다.
- 공통 헤더의 닫기(X), Escape, backdrop 및 하단 취소는 같은 초기화 경로를 사용한다. 처리 중에는 모두 무시한다.
- 본문은 기존 여러 줄 입력 및 오류, 하단 actions는 기존 취소/확인 버튼을 유지한다.
- 공통 컴포넌트 자체, 취소 확인/삭제 팝업, API 계약은 변경하지 않는다.

## 검증

- 상세 반려/보완 팝업 열기, 빈 사유 차단, 여러 줄 정확한 전송, 취소, 실패 재시도.
- 상세 승인 요청, 기존 상신 취소·승인 취소 및 피드 사유 팝업 회귀.
- 시스템 댓글 원문 보존, HTML 비해석 및 computed style 검증.
- 375px, 768px, 1280px 실제 렌더링과 비식별 화면 기록.
- 프론트엔드만 변경한다. 백엔드/API/DB 및 스키마 변경 없음.
