## 3. 페이지 프레임과 검색

페이지는 `PageHeader → PageSearchArea → PageMessageArea → F1-Grid`로 조립한다. 최상위 페이지는 `display: flex`, `flex-direction: column`, `flex: 1`, `min-height: 0`, full-height 레이아웃을 사용하고 그리드 본문이 목록 스크롤을 맡는다. 기존 본문 내부의 중복 페이지 제목은 제거한다.

### 통합검색

- 검색 입력은 한 개만 기본 검색 영역에 표시한다.
- 기존 `keyword` 계약과 검색 범위(제목, 본문, 작성자)를 그대로 쓴다.
- 입력 초안과 적용 검색어를 구분하고, 조회 버튼/Enter로 검색을 적용한다.
- 통합검색을 적용하면 F1-Grid data source를 재생성해 offset 0부터 다시 조회한다.
- 검색어 초기화 버튼은 입력 초안을 비운다. 빈 검색은 기존 API처럼 keyword 파라미터 없이 조회한다.

### 상세검색

- 기존 `WF_ARCHIVE_CATEGORY` 공통코드 조회에서 활성 분류를 가져와 상세검색의 단일 `분류` 선택으로 제공한다.
- F1-Grid 컬럼의 `search` 메타데이터와 `toPageSearchFields(columns)`를 사용한다.
- 분류 검색값은 기존 `categoryCode` 쿼리 파라미터로 전달한다. 빈 값은 전체 분류다.
- 상세검색의 조회는 적용된 통합검색어를 보존한 채 분류만 갱신한다.
- 작성자/일자 별도 조건과 새로운 API 필드는 추가하지 않는다.
- 상세검색 초기화/접기 등 `PageSearchArea` 공통 동작을 유지한다.

## 4. F1-Grid 목록 계약

### 표시 컬럼

| 데이터 필드 | 헤더 | 표시 |
|---|---|---|
| `title` | 제목 | 키보드로 실행 가능한 버튼. 클릭 시 해당 행의 상세 조회/패널 열기 |
| `categoryCode` | 분류 | 활성 공통코드 코드에 해당하는 이름, 없으면 코드값 |
| `writerName` | 작성자 | 작성자명, 없으면 `writerId`, 둘 다 없으면 `—` |
| `createdAt` | 등록일 | 기존 HTML 표와 같은 한국어 날짜 표시, 유효하지 않은 값은 원본 또는 `—` |
| `attachmentCount` | 첨부 수 | 0 이상 숫자 |

모든 컬럼은 읽기 전용이다. 상세검색에서는 분류 컬럼만 노출하고 다른 컬럼은 숨긴다. 그리드 내부 정렬/필터링/편집/문맥 액션/엑셀 내보내기는 활성화하지 않는다. 기본 최신순 API 정렬을 보존한다. 그리드에는 접근 가능한 `자료실` 레이블, 안정된 storage key, full-height와 최소 높이를 지정한다.

### 서버 페이지 data source

- F1-Grid `pageSize`는 기존 자료실 목록 기본 페이지 크기인 20을 사용한다.
- `load({ offset, limit, signal })`은 `pageIndex = floor(offset / limit) + 1`, `pageUnit = limit`로 변환해 `fetchArchivePosts(pageIndex, pageUnit, keyword, categoryCode, signal)`을 호출한다.
- API의 `resultList`를 `rows`, `resultCnt`를 `totalRowCount`로 반환한다.
- F1-Grid는 필요한 다음 페이지를 목록 본문 스크롤에 따라 요청한다. HTML 테이블의 별도 `TablePagination`은 제거한다.
- 검색어, 분류, 재시도 상태가 바뀌면 새로운 data source로 처음 offset부터 재조회한다.
- `AbortSignal`은 API 클라이언트까지 전달한다. 기존 호출부에서 signal을 생략하면 기존 호출 형태와 동작을 유지한다.
- 요청 실패는 F1-Grid의 `onDataSourceError`를 통해 명시적 오류 상태와 재시도 액션으로 전달한다. 실패를 성공 빈 목록으로 표시하지 않는다.

## 5. 상세 패널 구조와 동작

제목 버튼 선택은 기존 상세 API를 호출한다. 목록은 오버레이 뒤에 그대로 두며, 선택한 게시글의 상세는 기존 `PageAreaOverlay`와 전체 높이 우측 `PostDetailPanel` 안에서 독립 세로 스크롤한다. 좁은 폭에서는 패널이 뷰포트 너비를 넘지 않아야 한다.

### 상단 영역

- 피드 카드의 상단 계층을 사용해 작성자/작성일 메타, 분류 칩, 더보기 메뉴를 배치한다.
- 게시글 제목은 상단 정보 영역의 메타/액션 다음이자 본문 앞에 읽기 쉬운 제목으로 표시한다.
- 더보기는 MUI 메뉴를 열며, 사용자 권한에 따라 `수정`, `삭제` 항목을 각각 조건부 표시한다.
- 사용자가 수정/삭제 권한을 모두 갖지 않으면 더보기 버튼을 렌더하지 않는다.
- 삭제 항목은 삭제 진행 중 비활성화한다. 선택 시 기존 `자료 삭제 확인` 확인 다이얼로그를 연다.
- 수정은 기존 `ArchiveComposerDialog`를 열고 기존 post 데이터를 전달한다.

### 본문

- 기존 `contents` 문자열을 일반 텍스트 노드로 렌더링한다.
- `white-space: pre-wrap`으로 줄바꿈을 유지하고 `overflow-wrap: anywhere`로 긴 문자열이 가로 넘침을 만들지 않게 한다.
- HTML 파싱, `dangerouslySetInnerHTML`, RichTextEditor는 사용하지 않는다.
- 제목/본문은 데이터가 길거나 줄바꿈이 많아도 패널 폭을 넘지 않는다.

### 첨부 영역

- 첨부가 있으면 기존 shared `AttachmentList`의 view 모드와 파일별 다운로드 아이콘 스타일을 사용한다.
- 각 `ArchiveAttachment`를 `{ id: String(boardFileId), name: fileName }`로 표현한다.
- 파일 행의 다운로드 동작은 선택 게시글의 첨부 ID를 찾아 기존 `onDownload(post, fileIndex)` 경로로 연결한다.
- 한 파일의 실패가 다른 파일 표시나 게시글 조회 상태를 성공으로 위장하지 않으며, 기존 다운로드 실패 알림을 유지한다.
- 첨부가 없을 때 불필요한 빈 첨부 상자를 렌더하지 않는다.

## 6. 상태, 권한, 회귀 동작

- 목록/분류/상세의 로딩과 오류 상태, 각 오류의 재시도 액션을 유지한다.
- 읽기 권한이 없는 사용자는 기존 자료실 접근 거부 상태를 본다.
- 새 자료 작성 액션은 기존 tenant-admin 및 `create` 권한 판정에 따른다.
- 상세 수정/삭제 메뉴는 기존 tenant-admin 및 각 `update`/`delete` 권한 조합을 사용한다. 서버 검증을 대체하지 않는다.
- 삭제 확인, pending 상태, 수정 대화상자, 업로드/삭제 후 목록/상세 갱신, 파일 다운로드의 기존 API 인자를 보존한다.
- 다크 테마에서도 피드/첨부 공통 컴포넌트의 기존 theme surface를 사용한다.
- 신규 대화상자, API, DB 컬럼, 백엔드 DTO는 추가하지 않는다.

## 7. 테스트 및 검증 기준

### Vitest

`frontend/tests/archive-page.test.tsx`에서:

- 페이지가 `PageHeader`, 한 개 통합검색, F1-Grid를 렌더링하고 구 HTML table/별도 페이지네이션을 쓰지 않는다.
- F1-Grid 상세검색은 활성 분류만 보이며 선택 적용 시 기존 API 호출의 category/keyword를 갱신한다.
- 제목 버튼만 상세를 열며 선택 상세는 전체 높이 패널 안에 있다.
- 더보기 버튼/수정·삭제 메뉴가 권한별로 표시되고 삭제 확인/진행중 동작이 유지된다.
- 본문은 일반 텍스트이며 줄바꿈을 보존하고 에디터/HTML 렌더링을 사용하지 않는다.
- 첨부는 `AttachmentList` 형태로 표시되고 개별 다운로드는 기존 서비스로 연결된다.
- 기존 CRUD, 파일 업로드/제거, 오류/재시도 및 권한 테스트가 유지된다.

`frontend/tests/archive-board-service.test.ts`에서:

- data source offset/limit가 API pageIndex/pageUnit으로 변환된다.
- keyword/categoryCode가 기존 파라미터로 전달되고 total count가 F1-Grid 형식으로 반환된다.
- `AbortSignal` 전달과 생략 호출의 기존 API 계약을 확인한다.
