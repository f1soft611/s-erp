# 문서작성 전체 조회 필터 초기화 상세 사양서

## 화면과 상태

- 대상: `/groupware/doc/write`
- 피드/리스트 모드 모두 같은 `PinnedViewToolbar` 필터 영역을 사용한다.
- 필터 상태는 `scope`, `selectedKind`, `selectedDocumentId`이다.
- 업무구분 `전체` 항목은 기존처럼 단독으로 업무구분만 지운다.
- 새 `전체 조회` 버튼은 전체 조건을 초기화하는 명시적 기능이다.

## 동작 계약

다음 중 하나라도 참이면 상단 필터 영역에 `전체 조회` 버튼을 노출한다.

```ts
scope !== 'ALL' || selectedKind !== '' || selectedDocumentId !== undefined
```

버튼을 누르면 다음을 모두 설정한다.

```ts
scope = 'ALL';
selectedKind = '';
selectedDocumentId = undefined;
```

- 현재 `viewMode`는 변경하지 않는다.
- 기존 목록 조회 effect가 기본 필터 조건으로 목록 및 요약을 다시 요청한다.
- 리스트형 요청은 기존대로 세 번째 인자까지, 즉 `('ALL', undefined, undefined)`를 사용한다.
- 피드형 요청은 기존대로 `('ALL', undefined, undefined, true)`를 사용한다.
- 성공/로딩/실패/재시도 표현은 기존 흐름을 그대로 따른다. 초기화 클릭 자체를 조회 성공으로 표시하지 않는다.
- 버튼을 누르기 전 활성 조건이 모두 기본값이면 버튼은 렌더링하지 않는다.
- 이미 열린 상세 패널은 필터 초기화만으로 닫지 않는다.

## 비기능 및 범위

- MUI 기존 버튼/레이아웃 패턴과 접근 가능한 이름 `전체 조회`를 사용한다.
- 새 API, 로컬 저장, URL 상태, 백엔드 또는 DB 변경은 없다.
- 기존 피드/리스트 전환, 업무구분 메뉴, 요약 패널, 공지 문서 선택 동작은 유지한다.
- 기존 미커밋 변경을 보존한다.

## 검증

- 훅 테스트: 기본 상태에서는 비활성, 범위/업무구분이 선택된 상태에서 reset 후 상태와 서비스 요청이 기본값으로 돌아간다. 특정 문서 ID로 조회 후에도 reset 요청이 특정 ID 없이 발생한다.
- 페이지 테스트: 초기에는 버튼이 숨겨지고, 결재 범위 또는 업무구분 필터 적용 시 표시된다. 클릭 시 `ALL/undefined/undefined` 인자로 재조회하고 현재 피드/리스트 보기를 유지한다.
- 검증 명령: `npm run test -- tests/document-write-page.test.tsx tests/use-document-write-page.test.tsx`, `npm run build`.
- 브라우저 확인: 375px, 768px, 1280px에서 버튼과 필터 영역의 겹침/넘침을 확인한다.
