## 표시 계약

| eventType | 배지 명칭 | 재사용 문서 상태 | MUI color | variant |
|---|---|---|---|---|
| DRAFT_SAVED | 임시저장 | DRAFT | default | outlined |
| SUBMITTED | 결재신청 | PENDING | info | filled |
| REJECTED | 반려 | REJECTED | error | filled |
| APPROVED | 승인 | COMPLETED | success | filled |
| COMPLETED | 완료 | COMPLETED | success | filled |
| RETURNED | 보완요청 | REVISION_REQUESTED | warning | filled |

- 기존 안내 아이콘 위치에 작은 MUI Chip을 표시하고 같은 항목에 안내 아이콘을 중복 표시하지 않는다.
- 배지 모서리는 기존 문서 상태 배지와 동일한 `8px`로 표시한다.
- 개별 승인 `APPROVED`와 최종 결재 완료 `COMPLETED`는 명칭을 구분한다. 문서 상태 자체의 기존 `승인` 명칭은 변경하지 않는다.
- 위 표에 없는 이벤트(`RESUBMITTED`, 취소 이벤트 등)는 기존 안내 아이콘과 본문을 유지한다.
- 배지 명칭은 `eventType`으로만 결정하고 본문 문자열을 분석하지 않는다.
- 공통 댓글은 선택적 `{ label, color, variant }` 배지 정보를 받는다. 문서 이벤트와 문서 상태 매핑은 문서 표시 데이터 계층에서 처리한다.
- 문서 피드와 상세 패널은 기존 공통 변환 및 댓글 컴포넌트를 통해 같은 표시를 사용한다.

## 보존 동작 및 오류 처리

- 본문, 작성자, 시각, 첨부, 댓글 정렬/통합 페이지, 로딩/에러 UI를 변경하지 않는다.
- 시스템 항목에 답글/수정/삭제 조작을 노출하지 않는다.
- 일반 사용자 댓글과 공지사항에는 새 배지를 자동 추가하지 않는다.
- 미지원 이벤트는 오류로 취급하지 않고 기존 안내 표시를 유지한다. API 실패를 배지 처리로 숨기지 않는다.
- API, 백엔드, DB 스키마 및 저장 데이터는 변경하지 않는다. DB MCP 조회가 필요한 데이터 계약 변경은 없다.

## 검증 기준

1. 여섯 이벤트의 명칭, 기존 color 및 variant가 표와 일치하며 계산된 배지 border-radius는 8px이다.
2. 배지가 있는 시스템 메시지에는 안내 아이콘이 없고 읽기 전용 동작이 유지된다.
3. 미지원 이벤트는 기존 안내 아이콘, 일반 댓글은 기존 조작을 유지한다.
4. 실제 문서 상세의 SUBMITTED 메시지에 결재신청 배지가 전달된다.
5. 관련 세 테스트 파일과 프런트엔드 빌드가 통과한다.
6. 합성 데이터로 375px/768px/1280px 브라우저 렌더링을 확인하고 결과 문서와 스크린샷을 남긴다.
