## 1. DB (`20261113_006`, 사용자가 직접 실행)

## 2. 스냅샷 복사

- `insertOrderHeader`가 `INSERT … SELECT`로 `tb_tenant`·`tb_customer_info`·`tb_user`에서 위 값을 같은 문장에서 복사한다. 구매처·발주자가 없으면 해당 컬럼은 NULL이다.
- 발주 수정·취소는 스냅샷을 바꾸지 않는다(구매처·회사 변경은 수정 대상이 아니다).

## 3. API

### 3.1 `GET /api/v1/materials/purchase-orders/{id}/print`
출력 데이터를 돌려준다. 같은 테넌트의 발주만 조회한다. 없으면 404, 취소된 발주면 409(`취소된 발주는 출력할 수 없습니다.`).

응답 `item`: `purchaseOrderId, orderNo, orderDt, currencyCode, taxType, vatIncludedAt, supplyAmt, vatAmt, totalAmt, remark, printAt, company{name, businessNo, presidentName, postCode, address, telephoneNo, facsimileNo, stampImage, logoImage}, vendor{name, businessNo, presidentName, postCode, address, telephoneNo, facsimileNo, charge}, orderer{name, mobileNo}, details[{lineNo, materialCode, materialName, materialSpec, unit, orderQty, unitPrice, deliveryDt, supplyAmt, vatAmt, totalAmt, remark}]`.
- 각 값은 `COALESCE(스냅샷, 현재 정보)`다. 스냅샷이 있으면 마스터 변경과 무관하게 스냅샷을 쓴다.
- 금액은 저장된 값을 그대로 쓴다(재계산 없음).

### 3.2 `POST /api/v1/materials/purchase-orders/{id}/print-mark`
`print_at='Y'`, `printed_at=now()`, `printed_by=로그인 코드`로 갱신한다(이미 `Y`여도 일시·출력자를 갱신). 취소된 발주 409, 없으면 404. 응답은 발주(헤더 + 행).

### 3.3 현황 목록
`GET /purchase-order-status` 행에 `printAt`(`Y`/`N`)을 추가한다.

## 4. 화면

### 4.1 공통 한글 금액 `shared/utils/amountInKorean.ts`
`amountInKorean(value: number): string` — 영업 `StatementPrint`와 같은 규칙(정수가 아니면 빈 문자열, 0은 `영원 정`, 음수는 `마이너스 …`, 끝은 `원 정`). 영업 파일은 수정하지 않는다.

### 4.2 발주서 양식 (`pages/materials/order/print`)
A4 세로 한 부(폭 190mm). 구성은 사용자 제공 PDF를 따른다.
- 제목 `발 주 서`.
- 좌측 표: 일련번호(`발주번호` + 발주일), 수신(구매처명), 참조(구매처 담당자), TEL, FAX.
- 우측 표: 회사 로고, 사업자등록번호, 회사명/대표(+직인 겹침), 주소(우편번호), 담당/연락처(발주자명 / 휴대폰번호).
- 금액 줄: `금 액 : {한글 금액} (₩ {합계}원) / {부가세 표기}`. 부가세 표기: 과세+포함 `VAT포함`, 과세+미포함 `VAT별도`, 영세 `영세`, 면세 `면세`. 한글 금액은 합계가 안전한 정수일 때만 표시한다.
- 품목 표: 품목코드, 품목명[규격], 수량(단위 포함), 단가, 공급가액, 부가세, **납기일(행마다)**. 한 페이지 24줄이며 줄 수는 품명 길이로 계산해 페이지를 나눈다. 남는 줄은 빈 줄로 채운다.
- 하단 합계 줄: 수량 합, 공급가액 합, VAT 합, 합계(전체 발주 기준, 매 페이지 동일). 발주 비고가 있으면 표 아래에 표시한다.
- 값이 없으면 `-`를 표시한다. 로고·직인은 있을 때만 이미지를 표시한다.

### 4.3 미리보기와 인쇄
- 미리보기 다이얼로그 `발주서 미리보기`(`CommonDialog`)에 `인쇄`·`닫기`. 용지는 가운데 정렬하고 좁은 화면에서는 내부 가로 스크롤을 준다.
- `인쇄` 클릭: `window.print()`를 호출하고 `print-mark`로 출력을 기록한다. 기록에 실패해도 인쇄는 막지 않고 오류 안내만 보여준다. 성공하면 상세·목록을 다시 조회한다.
- 인쇄 CSS는 `.order-print-host`만 인쇄하고 `@page { size: A4; margin: 10mm }`를 쓴다. 영업 인쇄 CSS와 클래스를 분리한다.

### 4.4 진입점
- 상세 패널 더보기 메뉴 `출력`(발주 상태가 정상일 때만).
- 조회·수정 다이얼로그 하단 `출력` 버튼(정상 발주 + 저장하지 않은 변경이 없을 때만 활성).
- 발주현황 목록 컬럼 `출력상태`(출력/미출력, 조회용).
- 출력 권한은 발주현황 READ 권한이다(조회와 같다).

## 5. 검증 항목
- 취소된 발주 출력·기록 거부(서버 409, 화면 숨김).
- 스냅샷이 있는 발주는 마스터를 바꿔도 출력값 불변, 스냅샷이 없는 발주는 현재 정보로 출력.
- 행별 납기일, VAT 표기 4종, 합계·한글 금액, 24줄 초과 시 페이지 분할과 매 페이지 합계.
- `인쇄` 시 출력 기록과 목록의 출력상태 갱신, 변경 중에는 `출력` 비활성.
- 375/768/1280px 미리보기, 영업 인쇄 화면에 영향 없음.

## 6. 구현 시 확정한 사항
- 영업 인쇄 CSS(`statement-print.css`)가 앱 전체에 `body > :not(.statement-print-host) { display: none !important }`를 걸어 두므로, 발주서는 미리보기가 열려 있는 동안만 `body.order-printing`을 켜고 `html body.order-printing > .order-print-host { display: block !important }`로 우회한다. 영업 파일은 수정하지 않는다.
- 출력 조회 응답은 평평한 구조(`companyName`, `vendorName`, `ordererName` …)다. 사양 3.1의 중첩 객체 표기는 같은 필드를 묶어 설명한 것이다.
- 출력 데이터 응답에는 `useAt`를 포함한다(취소 판정은 서버가 먼저 하고 409로 거부한다).
