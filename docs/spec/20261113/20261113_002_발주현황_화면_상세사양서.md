# 20261113_002 발주현황 화면 상세 사양서

기준: [작업지시서](../../directions/20261113/20261113_002_발주현황_화면_작업지시서.md), [계획서](../../plan/20261113/20261113_002_발주현황_화면_계획서.md), [발주등록 사양서](20261113_001_발주등록_화면_상세사양서.md)

## 1. 메뉴 (DB)

- `MATERIALS_ORDER_STATUS`(발주현황, `/materials/order/order-status`, 정렬 20)를 `MATERIALS_ORDER`(발주관리) 그룹 아래에 등록한다. 그룹 구성은 `20261113_004`(구매요청관리 / 발주관리)가 만든다.
- 메뉴 권한 READ, EXCEL. 역할 권한은 `ORDER_STATUS`의 READ·EXCEL 역할 권한을 복사한다. 형식은 `20261112_003` 현황 메뉴 스크립트와 같다.
- 편집·취소 권한은 `MATERIALS_ORDER_CREATE`(발주등록)의 UPDATE 권한을 쓴다(구매요청현황과 같은 방식). 테이블 변경은 없다.

## 2. API

### 2.1 목록 `GET /api/v1/materials/purchase-order-status`
품목 행 단위로 펼친 발주 목록(같은 테넌트). 정렬 `발주일 내림차순, 발주번호 내림차순, 행번호`.

검색 조건(모두 선택): `keyword`(발주번호·구매처·품목코드·품목명·발주자), `orderNo`, `orderDtFrom/To`, `supplierKeyword`, `status`(`ACTIVE`/`CANCELED`, 없으면 전체), `materialKeyword`, `deliveryDtFrom/To`, `sourceType`.
시작일이 종료일보다 늦거나 날짜 형식이 틀리면 400.

응답 행: `purchaseOrderId, purchaseOrderDetailId, orderNo, orderDt, supplierName, ordererName, status, sourceType, taxType, taxTypeName, vatIncludedAt, headerSupplyAmt, headerVatAmt, headerTotalAmt, headerRemark, lineNo, confirmNo, requestNo, materialCode, materialName, materialSpec, unit, orderQty, unitPrice, deliveryDt, warehouseName, inspectAt, supplyAmt, vatAmt, totalAmt, orderTypeName, useTypeName, remark`.

### 2.2 단건 `GET /api/v1/materials/purchase-orders/{id}` (보강)
상세 행에 `confirmQty, remainQty, confirmSupplierId, confirmUnitPrice, confirmDeliveryDt, confirmWarehouseId`를 추가한다. `remainQty`는 이 행을 뺀 다른 유효 발주 수량을 제외한 확정 잔량이다(화면의 "확정 대비" 표시용).

### 2.3 수정 `PUT /api/v1/materials/purchase-orders/{id}`
요청 본문은 등록 저장 요청(`PurchaseOrderSaveRequestVO`)을 재사용한다. 사용하는 값은 `orderDt, taxType, vatIncludedAt, remark`와 `details[]`뿐이다. `details[]` 각 항목은 `purchaseOrderDetailId, orderQty, unitPrice, deliveryDt, warehouseId, inspectAt, vatAmt, remark`다. 구매처·통화·출처·품목은 저장된 값을 유지한다.

규칙:
1. 헤더를 `FOR UPDATE`로 잠근다. 없으면 404, 취소된 발주면 409(`취소된 발주는 수정할 수 없습니다.`).
2. `details[]`는 1건 이상이고, 모두 이 발주의 기존 행이며 중복이 없어야 한다. 아니면 400. 모든 행을 빼는 요청은 400(`모든 행을 뺄 수 없습니다. 발주 취소를 사용해 주세요.`).
3. 요청에 없는 기존 행은 삭제한다. 삭제는 먼저, 남은 행은 기존 행번호 오름차순으로 1부터 다시 매긴다.
4. 값 검증과 금액 재계산은 등록과 같다(수량 > 0, 납기일·창고 필수, 부가세 조합, 세액 규칙). 행의 발주구분·사용용도는 기존 값을 유지한다.
5. 헤더 금액은 남은 행 합으로 다시 계산한다. `updated_by/at`을 기록한다.
6. **직접 발주**: 삭제한 행은 연결된 구매요청 상세 행도 삭제한다. 수정한 행은 구매요청 상세의 `request_qty, request_delivery_dt, confirm_qty, confirm_delivery_dt, warehouse_id, unit_price, amount`를 맞춘다. 이후 확정 합계와 요청 상태를 다시 계산한다.
7. **확정 불러오기**: 확정 행은 건드리지 않는다. 수정 후 확정수량을 넘겨 발주된 행 번호를 응답 `overOrderedLineNos`로 돌려준다(경고용, 저장은 막지 않는다).
8. 응답은 저장된 발주(헤더 + 행)다.

### 2.4 취소 `POST /api/v1/materials/purchase-orders/{id}/cancel`
1. 헤더를 잠근다. 없으면 404, 이미 취소면 409.
2. 헤더를 `use_at='N'`으로 바꾼다(행은 이력으로 남긴다). 확정 불러오기 발주는 이것으로 끝이다. 확정 행의 잔량은 유효 발주 합으로 계산하므로 자동 복원된다.
3. **직접 발주**: 연결된 확정(MC)의 행을 초기화해 확정을 취소(`use_at='N'`)하고, 요청 상태를 다시 계산한 뒤 자동 생성된 구매요청(MR)을 삭제 처리(`use_at='N'`)한다.
4. 응답은 취소된 발주다.

### 2.5 가입고 연동 (후속)
가입고(MP) 테이블이 생기면 수정의 행 삭제·수량 감소와 취소에서 "가입고가 있는 행" 검증(409)을 추가한다. 지금은 검증하지 않는다.

## 3. 화면

### 3.1 발주현황 (`frontend/src/pages/materials/order/status`)
- 구매요청현황과 같은 구성: 빠른 검색 + 상세검색(발주일 기간 필수·기본 최근 1개월~오늘), 같은 발주서는 헤더 열 병합, 발주번호 링크.
- 컬럼: No, 발주번호(링크), 발주일, 구매처, 발주자, 상태(정상/취소), 출처(확정/직접), 행, 확정번호, 품목코드, 품목명, 규격, 단위, 발주수량, 발주단가, 공급가, 세액, 합계, 납기일, 입고창고, 검사대상, 비고. 상세검색: 발주번호, 구매처, 상태, 품목, 납기일 기간, 출처.
- 엑셀 내보내기는 EXCEL 권한이 있을 때만 보인다. 취소된 발주도 조회된다(상태 컬럼으로 구분).

### 3.2 상세 패널
- 발주번호, 작성자·수정 정보, 상태 칩, 요약(발주일, 구매처, 발주자, 부가세구분, 통화, 합계액), 비고, 품목 표. 더보기 메뉴에 `자세히보기`, 수정 가능할 때 `수정`.
- 수정 가능 조건: 발주 상태가 정상이고 발주등록 메뉴의 UPDATE 권한이 있을 때.

### 3.3 조회/수정 다이얼로그
발주등록 화면을 `embedded`로 띄운다(`mode='view'|'edit'`, `purchaseOrderId`).
- 불러오기: 저장된 발주를 읽어 헤더(발주번호, 발주일, 구매처, 부가세, 통화, 비고, 금액)와 행(확정 대비 포함)을 채운다.
- `view`: 모든 입력 읽기 전용. `edit`: 발주일, 부가세구분·여부, 비고, 행 값, 행 빼기만 가능하다. 구매처·확정 불러오기·품목 추가는 숨기고, 출처가 직접 발주면 발주구분·사용용도는 표시만 한다.
- 하단: 수정은 [저장], [취소(닫기)], 왼쪽에 [발주 취소]. 저장 성공 시 상세·목록을 다시 조회한다. 발주 취소는 확인창 후 실행하고 성공하면 다이얼로그를 닫는다.
- 변경 사항이 있는 채로 닫으면 확인창을 띄운다.

### 3.4 등록 화면과의 차이 기록
등록 화면(`create`)의 동작은 그대로다. 같은 폼·그리드·컬럼·금액 계산을 공유하며 차이는 위 3.3의 숨김·읽기 전용뿐이다.

## 4. 검증 항목
- 목록 조회와 필터, 날짜 범위 오류, 취소 건 표시.
- 수정: 값 변경 시 금액·헤더 합계 재계산, 행 삭제 후 행번호 재정렬, 모든 행 삭제 거부, 취소된 발주 거부.
- 직접 발주: 행 삭제·수정 시 구매요청·확정 동기화, 취소 시 MC 취소·MR 삭제 처리.
- 확정 불러오기: 행 삭제·취소 후 잔량이 복원되어 확정 불러오기 후보에 다시 나온다.
- 화면: 상세 패널, 조회 모드 읽기 전용, 수정 저장, 발주 취소.

## 5. 제외·후속
가입고 차단 검증, 발주서 출력, 전자결재 버튼, 입고대기마감, 재고량 값.

## 6. 입고대기마감 (추가)

### 6.1 API `PUT /api/v1/materials/purchase-orders/{id}/receipt-close`
요청 본문: `{ "details": [{ "purchaseOrderDetailId": 11, "receiptCloseAt": "Y" }] }`. 기존 행의 마감 값만 전달한다(바뀐 행만 보내도 되고 전체를 보내도 된다).
1. 헤더를 `FOR UPDATE`로 잠근다. 없으면 404, 취소된 발주면 409(`취소된 발주는 마감을 바꿀 수 없습니다.`).
2. `details`는 1건 이상이고 모두 이 발주의 기존 행이며 중복이 없어야 한다. 값은 `Y`/`N`만 허용한다. 아니면 400.
3. 값이 다른 행의 `receipt_close_at`, `updated_by/at`만 갱신한다. **수량·단가·납기 등 다른 값은 읽지도 바꾸지도 않는다.**
4. 응답은 저장된 발주(헤더 + 행)다.
가입고가 생기면 "입고가 끝나지 않은 행만 마감" 같은 검증은 가입고 작업에서 추가한다.

### 6.2 화면
- 상세 패널 더보기 메뉴에 `입고대기마감`을 추가한다(정상 발주 + UPDATE 권한일 때만).
- 다이얼로그(`mode='close'`): 발주등록 화면을 `embedded`로 재사용하되 헤더 입력, 행 값, 행 빼기, 발주 취소를 모두 숨기거나 읽기 전용으로 두고 "입고대기마감" 체크 컬럼만 편집할 수 있다. 하단은 `저장`·`닫기`. 바뀐 행이 없으면 저장은 비활성이다.
- 수정(`edit`)·상세보기(`view`) 그리드에도 입고대기마감 컬럼이 보이지만 수정에서는 읽기 전용이다.
- 목록에 입고대기마감 컬럼(대상/-)을 조회용으로 추가한다.

### 6.3 검증 항목
마감만 저장되고 다른 값은 그대로인지, 마감 취소(체크 해제), 취소된 발주 거부, 잘못된 행·값 거부, 수정 모드에서는 마감 컬럼이 읽기 전용인지.
