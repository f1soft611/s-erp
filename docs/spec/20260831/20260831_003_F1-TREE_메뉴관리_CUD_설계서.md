# 20260831_003 F1-TREE 메뉴 관리 CRUD 설계서

## 1. 목적

`F1Grid` 기반의 메뉴 관리 화면에서 계층형 메뉴를 안전하게 등록, 수정, 삭제할 수 있도록 재사용 가능한 `F1Tree`를 구현한다. 메뉴 전용 구현으로 고정하지 않고, 향후 BOM과 같이 평면 행 데이터의 부모-자식 관계를 표시하고 편집하는 화면에서 사용할 수 있는 공통 컴포넌트로 설계한다.

## 2. 범위

### 포함

- 평면 행 데이터의 계층 변환과 트리 표시
- 트리 노드의 펼치기/접기 및 깊이 들여쓰기
- 선택 노드의 하위 메뉴 등록과 루트 메뉴 등록
- 인라인 셀 편집과 기존 행 상태 추적
- 자식 메뉴 보유 노드의 삭제 사전 차단
- 메뉴 CRUD API와의 연동 및 성공 후 목록 재조회
- 키보드와 반응형 화면에서의 접근 가능한 트리 조작

### 제외

- 부모 메뉴 변경을 통한 노드 이동
- 드래그 앤 드롭 이동과 정렬 순서 재배치
- 삭제 시 후손 메뉴의 일괄 삭제
- 메뉴별 세부 권한 매핑 편집
- BOM 화면 구현

## 3. 아키텍처

React 함수형 컴포넌트에 클래스 상속을 적용하지 않는다. `F1Grid`와 `F1Tree`는 행 상태, 선택, 셀 편집, 유효성 검증, 키보드 조작을 공통 코어로 공유하고, `F1Tree`는 계층 변환, 펼침 상태, 깊이 렌더링, 트리 전용 ref 명령만 소유한다.

`F1Tree`는 API 호출이나 메뉴의 도메인 정책을 알지 못한다. 메뉴 관리 화면이 메뉴 API 응답을 행 타입으로 정규화하고 `parentMenuId`, 메뉴명 컬럼, `sortOrder`를 전달한다. 미래 BOM 화면은 동일 컴포넌트에 BOM의 행 키와 부모 키를 전달한다.

```text
MenuManagementPanel
  -> menuManagement.service (GET/POST/PUT/DELETE)
  -> F1Tree<MenuManagementRow>
       -> shared grid state and editing core
       -> tree data projection and expanded state
       -> tree row/cell renderer
```

## 4. 공통 타입 계약

```ts
type F1TreeProps<T extends object> = F1GridProps<T> & {
  parentKey: keyof T;
  treeColumn: keyof T;
  defaultExpanded?: 'all' | 'root' | F1GridRowId[];
  getRowLabel?: (row: T) => string;
  getRowOrder?: (row: T) => number;
  onExpandChange?: (expandedIds: F1GridRowId[]) => void;
};

type F1TreeRef<T extends object> = F1GridRef<T> & {
  expandRow(rowId: F1GridRowId): void;
  collapseRow(rowId: F1GridRowId): void;
  expandAll(): void;
  collapseAll(): void;
  isExpanded(rowId: F1GridRowId): boolean;
};
```

트리 데이터 변환은 렌더링과 분리된 순수 함수로 구현한다. 형제 노드는 `getRowOrder`가 반환하는 수와 기존 입력 순서를 기준으로 안정 정렬한다. 부모 행이 없거나 행이 자신을 부모로 참조한 경우에는 해당 행을 루트로 처리한다. 순환 참조는 방문 경로를 추적해 무한 순회 없이 루트 수준에서 한 번만 표시한다.

## 5. 메뉴 관리 동작

### 5.1 조회

`GET /api/v1/system/menus`의 평면 목록을 `MenuManagementRow`로 매핑한다. `menuId`는 `rowKey`, `parentMenuId`는 `parentKey`, `menuNm`은 `treeColumn`, `sortOrder`는 형제 순서에 사용한다. 서버 목록을 새로 받기 전에 저장되지 않은 변경분이 있으면 화면은 이를 유지하고, 저장 또는 명시적 새로고침 후에만 동기화한다.

### 5.2 등록

- `루트 메뉴 추가`: `parentMenuId: null`인 신규 행을 생성한다.
- `하위 메뉴 추가`: 선택한 메뉴의 `menuId`를 신규 행의 `parentMenuId`에 설정한다. 선택이 없으면 이 명령은 비활성화한다.
- 신규 하위 행을 추가할 때 부모 노드를 자동으로 펼쳐 새 행이 즉시 표시되게 한다.
- 모듈, 메뉴 코드, 메뉴명, 경로, 아이콘, 정렬 순서, 사용 여부의 저장 필드는 현재 메뉴 API 계약을 따른다.

### 5.3 수정 및 저장

기존 `F1GridChanges`의 `insertedRows`, `updatedRows`, `deletedRows`를 유지한다. 저장 시 신규 행은 `POST /api/v1/system/menus`, 기존 수정 행은 `PUT /api/v1/system/menus/{menuId}`, 삭제 행은 `DELETE /api/v1/system/menus/{menuId}`로 각각 전송한다. 모든 요청이 성공한 뒤 목록을 재조회해 ID, `hasChildren`, 정렬 상태를 서버 기준으로 맞춘다.

요청 실패 시 해당 행의 변경 상태와 입력값은 유지한다. 권한 오류, 메뉴 코드 중복, 부모-자식 제약 오류의 서버 메시지를 화면에 표시하며 성공하지 않은 변경분을 임의로 초기화하지 않는다.

### 5.4 삭제

`hasChildren`이 참이거나 현재 트리 변환 결과에서 후손이 존재하는 선택 행은 삭제 대상에서 제외하고 차단 메시지를 표시한다. 자식이 없는 행만 삭제 상태로 변경한다. 서버도 동일하게 하위 메뉴 존재 여부를 검증하므로 클라이언트 검사는 사용자 피드백 목적이며 서버 검증을 대체하지 않는다.

## 6. 화면과 접근성

메뉴 관리 툴바는 `루트 메뉴 추가`, `하위 메뉴 추가`, `삭제`, `저장`, `새로고침`, `전체 펼치기`, `전체 접기` 명령을 제공한다. 트리 토글은 마우스와 키보드로 접근 가능하며 펼침 상태를 ARIA 속성으로 제공한다.

트리 열은 아이콘, 깊이 들여쓰기, 메뉴명을 안정적으로 표시할 최소 폭을 가진다. 작은 화면에서는 툴바가 줄바꿈하고 그리드 본문만 가로 스크롤한다. 페이지 전체 가로 스크롤과 텍스트 또는 컨트롤 겹침은 허용하지 않는다.

트리 모드에서는 계층 순서를 훼손하지 않도록 정렬과 필터를 적용하지 않는다. 일반 `F1Grid`의 정렬과 필터 기능은 변경하지 않는다.

## 7. 검증 기준

- 순수 트리 변환 테스트: 부모 우선 순서, 형제 `sortOrder`, 펼침 상태, 누락 부모, 자기 참조, 순환 참조
- `F1Tree` 상호작용 테스트: 펼치기/접기, 키보드 토글, 행 선택, 셀 편집, 행 변경 상태
- 메뉴 관리 연동 테스트: 루트/하위 등록의 `parentMenuId`, 부모 자동 펼침, 자식 존재 삭제 차단, CRUD 요청, 성공 후 재조회, 실패 행 보존
- 회귀 검증: 기존 `F1Grid` 단독 테스트, 메뉴 관리 테스트, 전체 프론트엔드 테스트와 빌드
- 브라우저 검증: 375px, 768px, 1280px 뷰포트에서 관리자 메뉴 관리 화면을 확인하고 결과 문서에 캡처를 포함
