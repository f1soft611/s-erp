# 20260831_004 모듈별 메뉴 버튼 권한 관리 설계서

## 1. 목적

메뉴 관리 화면에서 모듈을 선택해 해당 모듈의 메뉴 계층을 `F1Tree`로 관리하고, 각 리프 메뉴가 제공하는 버튼/기능 권한을 등록한다. 역할별 권한 부여는 이 화면의 범위에서 제외하고 후속 역할 관리 화면에서 처리한다.

## 2. 범위

### 포함

- 모듈 선택기에 따른 모듈별 메뉴 트리 조회
- 선택 모듈의 메뉴 등록, 수정, 삭제
- 권한 코드 마스터 조회와 초기 권한 시드
- 리프 메뉴별 허용 버튼/기능 권한의 등록 및 해제
- 권한 코드 API 응답을 기반으로 한 동적 `F1Tree` 체크박스 열
- 메뉴 삭제 시 메뉴-권한 매핑의 트랜잭션 정리
- 권한 저장 오류, 모듈 전환 전 미저장 변경 확인, 반응형 화면 검증

### 제외

- 역할별 메뉴 또는 버튼 권한 부여
- 사용자별 예외 권한
- 부모 메뉴 변경, 드래그 앤 드롭 이동, 정렬 순서 재배치
- 권한 마스터를 화면에서 추가, 수정, 삭제하는 UI

## 3. 권한 모델

권한은 역할이 아니라 각 메뉴가 제공하는 기능 목록이다. 향후 역할 관리 화면은 메뉴별 허용 권한 목록을 기준으로 역할에 부여할 수 있는 권한을 제한한다.

### 3.1 tb_permission

권한 마스터 테이블은 다음 정보를 보관한다.

| 컬럼                    | 설명                          |
| ----------------------- | ----------------------------- |
| permission_id           | 권한 PK                       |
| permission_code         | 전역 고유 권한 코드           |
| permission_nm           | 화면 표시명                   |
| sort_order              | 메뉴 화면의 권한 열 표시 순서 |
| use_at                  | 활성 여부                     |
| created_at / updated_at | 등록 및 수정 일시             |

초기 시드 권한은 `READ`(조회), `CREATE`(등록), `UPDATE`(수정), `DELETE`(삭제), `EXCEL`(엑셀)이다. 향후 `PRINT`, `APPROVE` 등의 활성 권한 코드를 추가하면 화면은 별도 코드 변경 없이 열로 표시한다.

### 3.2 tb_menu_permission

메뉴별 허용 권한은 아래 매핑 테이블에 저장한다.

| 컬럼                    | 설명              |
| ----------------------- | ----------------- |
| menu_id                 | tb_menu FK        |
| permission_id           | tb_permission FK  |
| created_at / updated_at | 등록 및 수정 일시 |

`UNIQUE(menu_id, permission_id)`로 동일 매핑의 중복 저장을 막는다. 역할이나 사용자 식별자는 이 테이블에 저장하지 않는다.

## 4. API 계약

모든 API는 JWT 인증이 필요하며, 권한 마스터와 메뉴/메뉴-권한 매핑의 변경 API는 `PLATFORM_ADMIN` 또는 `TENANT_ADMIN`만 호출할 수 있다.

| Method | URL                                   | 설명                                  |
| ------ | ------------------------------------- | ------------------------------------- |
| GET    | /api/v1/system/modules                | 모듈 선택기용 모듈 목록               |
| GET    | /api/v1/system/permissions            | 활성 권한 코드 목록                   |
| GET    | /api/v1/system/menus?moduleId={id}    | 선택 모듈 메뉴 목록과 permissionCodes |
| POST   | /api/v1/system/menus                  | 메뉴 등록                             |
| PUT    | /api/v1/system/menus/{id}             | 메뉴 수정                             |
| DELETE | /api/v1/system/menus/{id}             | 메뉴 및 매핑 삭제                     |
| PUT    | /api/v1/system/menus/{id}/permissions | 리프 메뉴의 permissionCodes 전체 교체 |

권한 목록 응답은 `permissionCode`, `permissionName`, `sortOrder`를 포함한다. 메뉴 목록의 각 행은 `permissionCodes: string[]`을 포함한다.

권한 저장 요청은 다음과 같다.

```json
{
  "permissionCodes": ["READ", "CREATE", "EXCEL"]
}
```

백엔드는 대상 메뉴가 선택 모듈과 같은 테넌트 소속인지, 리프 메뉴인지, 요청 권한 코드가 활성 마스터에 존재하는지 검사한다. 그룹 메뉴의 권한 저장, 존재하지 않거나 비활성화된 권한 코드, 다른 테넌트/모듈 메뉴에 대한 요청은 `400` 또는 `404`로 거부한다.

## 5. 화면 동작

### 5.1 모듈 선택과 조회

메뉴 관리 화면 상단에 모듈 선택 드롭다운을 둔다. 모듈은 `GET /api/v1/system/modules`로 조회한다. 선택 모듈이 없으면 트리와 저장 명령을 비활성화한다. 모듈을 선택하거나 변경하면 `GET /api/v1/system/menus?moduleId={id}`와 권한 마스터 목록을 조회한다.

미저장 메뉴 또는 권한 변경분이 있는 상태에서 모듈 선택이나 새로고침을 시도하면 확인 대화상자를 표시한다. 사용자가 취소하면 기존 선택과 변경분을 유지한다.

### 5.2 F1Tree 열

트리에는 메뉴명, 메뉴 코드, 경로, 정렬 순서, 사용 여부를 표시한다. 권한 마스터의 활성 항목을 `permissionCode`별 체크박스 열로 동적으로 추가한다.

자식 메뉴를 보유한 그룹 노드의 권한 체크박스는 비활성화한다. 리프 메뉴의 체크박스만 편집할 수 있고, 체크 변경은 해당 행의 권한 변경분으로 추적한다. 신규 메뉴는 모든 권한이 해제된 상태로 생성한다.

### 5.3 등록, 삭제, 저장

- 루트 메뉴 추가는 선택 모듈 ID를 신규 메뉴에 설정한다.
- 하위 메뉴 추가는 선택 부모의 `menuId`와 `moduleId`를 상속하고 부모를 자동으로 펼친다.
- 자식이 있는 메뉴는 삭제할 수 없으며, 권한 체크박스를 가진 리프 메뉴만 권한을 저장한다.
- 저장은 메뉴의 POST/PUT/DELETE를 먼저 완료한다. 신규 메뉴가 서버 ID를 받은 뒤 해당 리프 메뉴 권한을 저장한다.
- 메뉴 저장이 모두 성공하면 변경된 리프 메뉴의 `PUT /permissions`를 호출한다.
- 모든 요청 성공 후 선택 모듈 목록을 다시 조회한다. 실패 시 메시지와 저장되지 않은 변경분을 유지한다.

## 6. 반응형 및 접근성

모듈 선택기와 툴바는 좁은 너비에서 줄바꿈한다. 권한 열이 많아져도 페이지 전체가 가로 스크롤되지 않으며, `F1Tree` 본문만 수평 스크롤한다. 트리 토글, 모듈 선택기, 권한 체크박스는 키보드와 접근 가능한 이름으로 조작할 수 있어야 한다.

375px, 768px, 1280px에서 선택기, 툴바, 트리 들여쓰기, 권한 열, 텍스트가 겹치거나 잘리지 않는지 검증한다.

## 7. 검증 기준

- 백엔드: 권한 시드/마이그레이션, 권한 마스터 조회, 모듈별 메뉴 조회, 리프 메뉴 권한 저장, 그룹 메뉴 거부, 권한 코드 검증, 메뉴 삭제 시 매핑 정리를 테스트한다.
- 프론트엔드: 모듈 선택의 API 요청과 트리 전환, 동적 권한 열, 리프/그룹 체크 편집 규칙, 메뉴와 권한의 저장 순서, 실패 시 변경 보존을 테스트한다.
- 회귀: `F1Grid`/`F1Tree` 단위 테스트, 메뉴 관리 통합 테스트, Maven 테스트/컴파일, Vitest와 프론트엔드 빌드를 실행한다.
- 브라우저: 관리자 로그인 상태에서 세 뷰포트의 스크린샷을 결과 문서에 포함한다.
