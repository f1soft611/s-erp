## 1. 공통 성공 토스트

`NotificationProvider`는 애플리케이션 전체에 하나의 성공 토스트를 표시한다.

- 공개 훅: `useNotification()`
- 공개 호출: `showSuccess(message: string): void`
- 표시 위치: 우측 하단
- 형태: MUI `Snackbar` 내부 성공 `Alert`
- 닫기: 자동 닫힘과 닫기 버튼을 모두 제공한다.
- 새 성공 메시지가 발생하면 현재 메시지를 새 메시지로 교체한다.

전역 Provider는 성공 토스트만 관리한다. 오류 메시지는 페이지 전환 뒤까지 남지 않도록 각 페이지가 소유한다.

## 2. 공통 페이지 오류 메시지 영역

`PageMessageArea`는 오류 문자열을 표시하는 재사용 컴포넌트다.

```tsx
<PageMessageArea message={error} onClose={() => setError('')} />
```

- `message`가 빈 문자열이면 아무것도 렌더링하지 않는다.
- 메시지가 있으면 페이지 헤더 바로 아래에 MUI 오류 `Alert`를 렌더링한다.
- 오류 `Alert`는 닫기 버튼을 제공하며 `onClose`를 호출한다.
- 컨테이너는 작은 화면에서도 페이지 너비에 맞게 표시되고 텍스트를 줄바꿈한다.

## 3. 권한관리 연동

- 역할 목록의 최초 조회 또는 재조회 실패 시 오류 메시지를 페이지 상단에 표시한다.
- 역할 등록 또는 수정 요청 실패 시 오류 메시지를 페이지 상단에 표시한다.
- 저장 API와 저장 후 목록 재조회가 모두 성공하면 저장 완료 토스트를 표시한다.
- 오류 메시지는 새 조회 또는 저장을 시작할 때 제거한다.

## 4. 메뉴관리 연동

- 기존 `error` 상태는 `PageMessageArea`에 전달한다.
- 메뉴 목록, 모듈, 권한 조회 실패 시 페이지 상단에 오류 메시지를 표시한다.
- 메뉴 저장 실패 시 페이지 상단에 오류 메시지를 표시한다.
- 메뉴 저장과 저장 후 새로고침이 모두 성공하면 저장 완료 토스트를 표시한다.
- 모듈 변경, 새 조회 또는 저장 시작 시 이전 오류를 제거한다.

## 5. 제외 범위

- 로그인 화면과 기타 업무 페이지의 알림 전환
- 실패 토스트, 알림 이력, 다중 메시지 큐
- API 및 DB 변경

## 6. 검증 기준

- 공통 성공 토스트는 호출한 메시지를 표시하고 닫을 수 있다.
- 공통 페이지 오류 메시지 영역은 오류를 표시하고 닫을 수 있다.
- 권한관리와 메뉴관리에서 저장 성공은 토스트로, 실패는 페이지 상단 오류로 표시된다.
- 375px, 768px, 1280px에서 메시지와 화면 UI가 겹치거나 잘리지 않는다.
- 관련 Vitest와 `npm run build`가 통과한다.
