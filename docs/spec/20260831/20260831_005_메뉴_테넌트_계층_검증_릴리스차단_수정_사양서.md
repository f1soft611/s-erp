# 메뉴 테넌트 계층 검증 릴리스 차단 수정 사양서

## 적용 대상

- `POST /api/v1/system/menus`
- `PUT /api/v1/system/menus/{id}`

## 검증 규칙

1. 생성 요청의 `moduleId`는 요청 테넌트의 모듈 목록에 존재해야 한다. 존재하지 않거나 타 테넌트 모듈이면 `IllegalArgumentException("유효하지 않은 모듈입니다.")`으로 거부한다.
2. `parentMenuId`가 있으면 요청 테넌트 범위에서 부모 메뉴를 조회해야 한다. 없으면 `IllegalArgumentException("유효하지 않은 상위 메뉴입니다.")`으로 거부한다.
3. 부모 메뉴의 `moduleId`는 생성 요청의 `moduleId`와 같아야 한다. 다르면 `IllegalArgumentException("상위 메뉴는 같은 모듈에 속해야 합니다.")`으로 거부한다.
4. 수정 요청의 부모 메뉴 검증 기준 모듈은 대상 메뉴의 기존 `moduleId`다. 요청 본문의 `moduleId`는 수정에서 모듈을 바꾸는 수단으로 사용하지 않는다.
5. 위 검증 오류는 API에서 HTTP 400으로 반환하며 DAO의 insert/update는 실행되지 않는다.

## 검증 기준

- 타 테넌트 또는 존재하지 않는 모듈 생성 거부
- 같은 테넌트의 다른 모듈에 속한 부모 메뉴 생성 및 수정 거부
- 유효한 동일 모듈 부모 메뉴 생성은 정상 insert
- 서비스 검증 실패 시 insert/update 미호출
- API 입력 오류 HTTP 400
