## 2. 백엔드 사양

### 2.1 테넌트 코드 → ID 변환

- `LoginDAO`에 `selectTenantIdByCode(String tenantCode)` 메서드를 추가하고, 매퍼에 `SELECT tenant_id FROM tb_tenant WHERE tenant_code = #{tenantCode} AND COALESCE(use_at,'Y')='Y'` 쿼리를 추가한다.
- `EgovLoginServiceImpl.actionLogin(LoginVO vo)`에서:
  - `vo.getTenantId()`가 null이고 `vo.getTenantCode()`가 존재하면 위 메서드로 조회한 `tenantId`를 `vo`에 설정한 뒤 기존 `loginDAO.actionLogin(vo)`를 호출한다.
  - 테넌트 코드로 조회한 결과가 없으면 로그인 실패(`new LoginVO()` 반환)로 처리한다.

### 2.2 API 계약 (변경 없음)

- `POST /auth/login-jwt`
  - 요청 바디: `{ "tenantCode": string, "id": string, "password": string }`
  - 성공 응답: `{ "resultCode": "200", "resultMessage": "성공 !!!", "jToken": string, "refreshToken": string, "resultVO": LoginVO }`
  - 실패 응답: `{ "resultCode": "300", "resultMessage": string }`

## 3. 프론트엔드 사양

### 3.1 `authService.ts`

- `login(credentials: LoginRequest)`:
  1. `fetch(`${API_BASE_URL}/auth/login-jwt`, { method: 'POST', headers: {'Content-Type':'application/json'}, body: JSON.stringify({ tenantCode: credentials.tenantCode, id: credentials.userId, password: credentials.password }) })` 호출.
  2. 응답 JSON의 `resultCode !== '200'`이면 `resultMessage`로 `Error`를 throw.
  3. 성공 시 `AuthSession`에 `accessToken: jToken`, `refreshToken`, `tenantCode`, `userId`, `expiresAt`(3시간 후, 백엔드 `JWT_TOKEN_VALIDITY` 3시간과 일치)를 구성해 `localStorage`에 저장.
  4. 기존과 동일하게 `/dashboard`로 라우팅 및 `notifyAuthChange()` 호출.
- `API_BASE_URL`은 `import.meta.env.VITE_API_BASE_URL ?? 'http://localhost:8080'`.
