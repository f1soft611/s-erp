# 상세검색 조건 제출 및 현황 기준일 필수화 상세사양서

## 1. 칩 제거 및 조회 적용

- 적용조건 칩의 X는 해당 필드의 상세검색 편집값만 비운다. `onDetailSearch`는 호출하지 않으며, 페이지 조회·로딩·오류·세션 적용도 시작하지 않는다.
- 삭제할 다음 값은 현재 `draftValues`에 합성한다. 반복 삭제 시 앞선 초안 삭제를 보존한다.
- 칩은 마지막 적용 스냅샷에서 시작하되 제거를 누른 조건의 칩은 즉시 숨긴다. 나머지 적용 칩은 표시하고, 실행된 검색조건과 그리드 결과는 명시적 조회 전까지 유지한다.
- 데스크톱에서는 칩과 초기화/조회/닫기 버튼을 첫 행에 배치하고, 조회 전 변경 안내를 다음 행 전체 너비로 표시한다. 좁은 화면에서는 버튼을 맨 위 행 오른쪽에 고정하고, 칩과 안내를 아래 행에 배치해 칩이 지나치게 좁아지지 않게 한다. 버튼 그룹은 줄바꿈하지 않는다.
- 편집 초안에서 이미 빈 필드의 X는 다시 동작하지 않도록 비활성화한다.
- 하나 이상의 칩 제거가 대기 중이면 상세검색 패널에 `조건 변경 내용은 조회 버튼을 눌러 적용하세요.` 안내를 표시한다. 안내는 상세검색 조회 성공 시 제거한다.
- 필수조건을 비운 초안도 허용한다. 필수조건 검증과 오류 표시는 명시적인 `조회` 클릭 때 실행한다.
- 필수 조건 칩의 해제 버튼은 비활성화하여 필수 기준일을 적용조건에서 제거할 수 없게 한다. 상단 조회가 현재 적용 스냅샷을 재사용해도 필수 기준일이 유지된다.
- 전체 초기화의 기존 페이지별 동작은 변경하지 않는다.

## 2. 문서현황 기준일

- 업무현황 요청의 대상은 `결재신청일` 상세검색이 정의된 기존 문서현황 화면이다.
- `submittedAt` 검색 메타데이터에 `required: true`를 설정한다. 검색 UI는 시작일/종료일 모두 필수로 표시하고, 둘 중 하나라도 비었거나 유효하지 않으면 조회를 차단한다.
- 기존 서버 제공 최근 1개월 기본 날짜 범위는 보존한다.
- 기존 탭 세션이 유효하지만 `submittedAt` 날짜 범위가 누락·부분·잘못된 값이면, 서버 기본 검색값의 `submittedAt` 범위를 병합한다. 복원된 화면 조건, 적용 세션, 첫 목록 필터가 같은 값을 사용한다.
- 구형 세션에 나머지 상세조건이나 키워드가 있으면 그대로 보존한다.
- 새 세션은 기존처럼 서버 기본값으로 초기화한다.

## 3. 신규 현황 페이지 규칙

- 신규 현황/상태 목록 페이지는 업무 기준일 검색 필드를 제공하고 필수 기준으로 선언한다. 필수 기준일은 적용조건 칩에서도 제거할 수 없다.
- 기준일이 기간인 경우 양쪽 endpoint를 모두 필수로 하고, 기존 상세검색 공통 검증과 date metadata 전달 경로를 재사용한다.
- 화면 기본값은 적절한 서버 제공 기본 범위를 사용할 수 있지만, 기본값 유무와 관계없이 검색 제출 검증을 유지한다.

## 4. 검증

1. X 클릭 후 `onDetailSearch`가 호출되지 않고 초안 필드만 비워진다.
2. 여러 칩을 지우면 앞선 제거가 보존되고 각 빈 필드의 제거 X는 비활성화된다.
3. 적용 칩은 조회 전까지 현재 실행 결과 조건을 나타내며 대기 안내가 보인다.
4. 조회 버튼은 비어 있는 필수 날짜 범위를 차단하고 오류를 보여준다.
5. 문서현황의 누락/부분 기간 세션은 기본 기간으로 보정된 검색을 첫 로딩부터 실행한다.
6. 기존 키워드, 정상 세션, 초기화, backend/API 계약 및 grid 동작이 바뀌지 않는다.
