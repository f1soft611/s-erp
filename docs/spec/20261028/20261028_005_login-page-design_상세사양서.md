# 20261028_005 로그인 페이지 디자인 개선 상세사양서

근거: [작업지시서](../../directions/20261028/20261028_005_login-page-design_작업지시서.md), [승인된 디자인](../../superpowers/specs/2026-10-28-login-page-design.md)

## 1. 화면 구성

- 인증 화면은 단일 중앙 카드형으로 유지한다. 별도의 마케팅/브랜드 분할 패널이나 새 로그인 옵션은 추가하지 않는다.
- 전체 배경은 현재 테마의 `background.default`를 기본으로 한 중립 표면으로 구성하고 블루 포인트는 약하게 사용한다.
- 로그인 카드는 라이트 모드에서 흰색 계열, 다크 모드에서 기존 `background.paper` 계열을 사용한다. 경계선과 그림자는 카드 윤곽이 보일 만큼만 적용한다.
- 내부 콘텐츠는 `S-ERP` 브랜드 표식, 로그인 제목, 한 줄 설명, 입력 필드, 제출 상태/오류, 개발 환경 전용 안내, 저작권 순으로 둔다.
- 제목과 설명의 시각 위계를 강화하고 좁은 화면에서도 제목이 잘리지 않도록 한다.
- 업체코드, 사용자 ID, 비밀번호 라벨은 각 입력 위에 고정 배치하고 실제 input과 `htmlFor`/`id`로 연결한다. 라벨은 14~15px, 입력 텍스트는 18px, input 높이는 약 56px로 한다.
- 각 TextField의 기본 위아래 margin을 제거해 Stack 간격과 중복되지 않게 한다. 필드 그룹은 읽기 쉬운 간격으로 분리하고 필드 helper text 영역을 보존한다.
- 입력 컴포넌트의 테마별 텍스트 색상과 포커스/오류 테두리를 보존한다.
- 제출 버튼은 전체 너비로 배치하고 기존 primary 팔레트를 사용한다. disabled 및 로그인 중 문구를 유지한다.

## 2. 기존 동작 보존

- 필드명/순서: `tenantCode`, `userId`, `password`; 각 필드 라벨과 autoComplete 값은 변경하지 않는다.
- 필수 입력 검증 문구와 제출 핸들러를 변경하지 않는다.
- 비밀번호 가시성 토글 버튼과 접근 가능한 이름을 유지한다.
- 서버 로그인 실패와 세션 만료 알림을 기존 텍스트로 표시한다.
- 개발 환경 테스트 계정 상자는 `import.meta.env.DEV`일 때만 노출하는 현재 조건과 텍스트를 유지한다. 테두리·배경 대비·글자 크기를 낮춰 보조 안내로 표시하며 입력/제출 요소보다 시각적 우선순위가 높지 않게 한다.
- 로그인 성공 후 기존 `/` 이동과 인증 세션 변경 알림 흐름을 유지한다.

## 3. 반응형 및 스크롤

- 데스크톱: 카드 너비 최대 450px, viewport 중앙 정렬. 컨테이너는 뷰포트보다 넓어지지 않는다.
- 태블릿/모바일: 카드 너비는 부모 폭을 따르고 좌우 여백을 최소 16px 확보한다. 콘텐츠는 내부에서 줄바꿈되며 수평 스크롤을 만들지 않는다.
- 375px, 768px, 1280px 폭에서 확인한다.
- 높이가 짧거나 개발 안내가 카드 높이를 늘려도 콘텐츠가 잘리지 않도록 `AuthLayout`의 세로 스크롤을 허용한다. 앱의 전체 화면 컨테이너가 overflow를 숨기는 구조를 고려하여 인증 레이아웃 자체가 남은 화면 높이를 차지하고 내부 세로 스크롤을 담당해야 한다.
- 카드 높이가 viewport보다 작을 때는 수직 중앙 정렬하고, 클 때는 콘텐츠의 시작 부분에 접근할 수 있도록 상단 정렬/스크롤 동작을 보장한다.

## 4. 테마 및 접근성

- `useTheme()` 및 MUI palette를 우선 사용하고 라이트/다크 모드에서 카드·텍스트·테두리·오류 대비를 확인한다.
- 색상만으로 필수 오류를 표현하지 않고 기존 helper text를 유지한다.
- 탭 순서, 입력 label, 비밀번호 토글의 `aria-label`, 제출 버튼의 텍스트를 보존한다.
- 세션 안내 및 제출 알림은 현재 Alert 의미 수준을 유지한다.

## 6. 테스트 기준

- `frontend/tests/login.test.tsx`: 필드 렌더, 필수 검증, 비밀번호 토글, 실패 메시지, 성공 후 대시보드 이동을 검증한다.
- `frontend/tests/login-form-field.test.tsx`: 고정 라벨과 입력의 접근성 연결, 18px 입력 글씨, 약 56px 높이, 기본 margin 제거를 검증한다.
- 스타일 회귀 테스트는 의미 있는 동작만 검증한다. 레이아웃 viewport와 긴 화면의 스크롤 지원은 DOM 단언으로 대체하지 않고 Playwright 실제 브라우저에서 확인한다.
- 프론트엔드 전체 build를 수행한다.
- 브라우저 검증: 4173 포트의 S-ERP 페이지에서 라이트/다크 × 375/768/1280px. 수평 overflow, 화면 높이보다 긴 콘텐츠의 접근성, 콘솔/런타임 오류, 폼 레이아웃을 확인하고 필요한 화면을 캡처한다.
