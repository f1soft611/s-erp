# 20261028_007 종합현황 전체 폭 및 스크롤 위치 보정 상세사양서

근거: [작업지시서](../../directions/20261028/20261028_007_종합현황_전체폭_스크롤_보정_작업지시서.md)

## 1. 원인

`OverviewPage`가 MUI `Container maxWidth="xl"`을 사용해 앱 콘텐츠 영역이 넓어도 본문 폭을 제한한다. 같은 Container에 `overflowY: auto`가 적용되어 있어 세로 스크롤 막대도 가운데 제한 폭의 끝에 붙고, 그 뒤에 넓은 화면의 빈 여백이 남는다.

## 2. 설계

- `OverviewPage` 본문만 `maxWidth={false}`로 변경해 MUI Container의 `xl` 최대 폭 제한을 해제한다.
- 기존 `flex`, `minHeight`, `overflowY: auto`, `overflowX: hidden` 및 반응형 좌우/상하 패딩은 유지한다.
- 따라서 세로 이동은 계속 가능하며, 스크롤 경계는 화면의 넓은 앱 콘텐츠 영역 끝에 위치한다.
- 공통 Dashboard 셸, PageHeader, 다른 화면의 Container와 내부 스크롤 정책은 변경하지 않는다.
- 카드·그리드 배치, 데이터/API, 권한, 테마는 변경하지 않는다.

## 3. 검증 기준

- Vitest에서 종합현황 Container가 `xl` 최대 폭 클래스 대신 최대 폭 제한 없는 클래스를 사용하는지 확인한다.
- 관련 종합현황 테스트와 프론트엔드 빌드를 실행한다.
- 실제 브라우저에서 좌측 메뉴를 접은 상태로 1900px급 넓은 뷰포트 및 1280px, 768px, 375px를 확인한다.
- 콘텐츠 폭이 가용 영역을 채우고 문서의 가로 스크롤이 발생하지 않는지 확인한다. 세로 스크롤은 필요한 경우 앱 콘텐츠 오른쪽 경계에서 유지한다.
- 결과 문서에 재현 조건, 원인, 변경, 검증 결과 및 스크린샷을 기록한다.
