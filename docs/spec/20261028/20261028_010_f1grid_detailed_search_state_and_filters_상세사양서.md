# F1-Grid 상세검색 조회 상태 및 필터 제거 상세 사양서

## 1. 공통 상세검색 활성 상태

- `PageSearchArea`는 페이지가 전달하는 `appliedDetailValues`를 조회 적용값으로 사용한다. `detailValues`와 내부 draft는 입력 편집값으로 계속 사용한다.
- 의미 있는 값이 하나 이상 적용되었을 때 상세검색 토글을 활성 상태로 표시한다. 공백 문자열/빈 문자열/빈 날짜 범위는 비활성이고, 숫자 `0` 및 boolean 값은 유효한 명시값으로 판단한다.
- 활성 조건 개수를 토글의 accessible description에 포함한다. 기존 접근 가능한 이름은 유지해 기존 자동화 및 화면 호환성을 보존한다.
- 미적용 입력을 변경해도 활성 여부나 조건 개수는 변하지 않는다.
- `search.required: true` 메타데이터는 상세검색 필드의 필수 상태로 전달한다. 필수 필드는 공백/빈 선택값으로 제출할 수 없다.
- 필수 날짜 필드는 시작일과 종료일을 모두 입력해야 하며, 두 날짜 모두 기존 날짜 정규화/유효성 검증을 통과해야 한다. 오류 시 상세검색을 닫거나 검색 콜백을 실행하지 않고 누락/잘못된 입력 위치에 오류를 표시한다.
- 수주현황의 `orderDt`는 필수 상세검색 조건이며 시작일과 종료일을 모두 요구한다. 초기 기본 날짜 범위는 기존 시스템 날짜 기준을 유지한다.

## 2. 적용조건 칩과 개별 제거

- 상세검색 패널의 기존 버튼 영역 아래, 왼쪽에 적용된 상세조건 칩을 표시한다. 적용값이 없으면 칩 영역을 숨긴다.
- 칩 라벨은 검색 필드 레이블과 사용자에게 읽히는 값으로 구성한다. select/checkbox는 metadata option의 label, date는 유효한 시작/종료 범위를 사용한다. 텍스트/숫자는 공백을 제거하고 문자열로 표시한다.
- 칩 X는 필드별 접근 가능한 이름을 가진다. 삭제 시 필드 타입에 따른 빈 값(`date: {from: '', to: ''}`, 그 외 빈 문자열)을 `onDetailValuesChange`에 전달하고 기존 `onDetailSearch` callback을 호출한다.
- 키워드, 제거 대상이 아닌 상세조건, 현재 화면/탭은 유지한다. API 호출 및 미저장 변경 확인은 기존 페이지 흐름을 사용한다.
- `초기화`, `조회`, `닫기` 버튼은 유지한다. 초기화는 해당 페이지의 기존 defaultValues를 복원하며 기존 자동 조회 여부를 바꾸지 않는다.
- 필수 조건 칩 제거가 유효하지 않은 조회를 만들면 폼의 초안만 변경하고, 오류를 표시하며 기존 적용조건/목록 조회 상태는 유지한다.

## 2.1 검색 패널과 로딩 덮개

- 상세검색 패널이 열려 있는 동안 검색영역의 stacking level은 F1-Grid 로딩 덮개(z-index 12)보다 높아야 한다.
- 겹침 순서는 다른 페이지 모달보다 낮게 유지한다. 목록의 로딩 상태·오류·조회 동작은 변경하지 않는다.

## 3. 조회 세션 적용 범위

- 기존 세션 보존: 공통코드관리, 수주현황, 문서현황.
- 신규 적용: 품목관리, 거래처관리, 기안양식관리, 커뮤니티 자료실.
- 저장 대상은 마지막 실행 검색의 keyword와 상세조건, 자료실의 현재 folder query scope다. 폼에 입력 중이나 조회하지 않은 값은 저장하지 않는다.
- 새 탭 세션은 기존 페이지의 첫 조회/default 조건을 유지한다. 유효하지 않거나 구버전인 값은 기존 기본 조회 상태로 처리한다.
- 복원 시 저장된 필터로 목록을 조회한다. 행/셀 선택, 편집 변경, grid layout, 열린 패널은 저장하지 않는다.
- 자료실은 시스템 날짜 기반 상세 기본값을 받은 뒤 저장된 조회값이 있으면 우선 적용하고, 없으면 기존 기본 최근 1년 조건을 적용한다.
- 미저장 행 변경 확인이 있는 품목/거래처/기안양식은 새 검색을 확인 후에 실행한다. 취소 시 기존 적용조건/세션을 유지하고 계속 시 새 조건/세션을 적용한다.
- 일반 keyword 조회는 기존에 적용된 상세조건을 보존한다. 상세검색 실행 및 chip 제거는 지정된 상세조건 전체 스냅샷을 사용한다.

## 4. 시험 기준

1. 적용값이 있을 때 토글이 활성 표시되고 정확한 조건 수를 제공한다.
2. 미적용 입력 변경만으로 활성 표시/칩이 생기지 않는다.
3. active chip은 label 및 select/date 값으로 표시되고 각 X는 해당 필드만 비운 뒤 callback을 실행한다.
4. 한 chip을 제거해도 keyword와 다른 상세조건이 callback 값에 유지된다.
5. 세션 저장/복원 페이지는 마지막 조회 실행값으로 화면과 목록을 복구하며 입력만 변경한 값은 복원하지 않는다.
6. 미저장 변경 확인을 취소하면 현재 조회조건 및 표시가 바뀌지 않고, 승인하면 신규 조건을 적용한다.
7. 기본 날짜 범위, 기존 reset/search behavior, API 계약은 보존한다.
8. 좁은 화면에서도 검색조건 칩/버튼이 겹치거나 페이지 가로 overflow를 만들지 않는다.
9. 필수 날짜 범위의 양 끝 중 하나가 비거나 유효하지 않으면 검색 callback이 실행되지 않고, 양 끝이 유효하면 정규화된 값으로 검색한다.
10. 상세검색 패널이 열린 상태에서 그리드가 로딩되어도 로딩 덮개가 패널 위에 렌더링되지 않는다.
