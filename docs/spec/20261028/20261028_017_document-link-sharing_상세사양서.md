# 문서 링크 공유 상세 사양서

> 후속 변경: URL 암호화, 링크 수정 감지, 상세 영역, 피드 응답의 현재 계약은 [018 후속 사양서](20261028_018_document-sharing-corrections_상세사양서.md)를 우선 적용한다. 아래는 최초 구현 이력이다.

## 링크와 메뉴

- 정식 링크는 현재 origin의 `/groupware/doc/write?documentId=<양의 안전한 정수>`이다.
- 피드·상세에서 조회 가능한 모든 문서에 `문서 공유하기`를 노출한다. 수정·삭제의 기존 권한 조건은 유지한다.
- 클립보드 쓰기 성공 후 성공 알림, 지원하지 않거나 거부되면 실패 알림을 표시한다.
- 링크는 권한을 부여하지 않는다. 외부 URL, 다른 origin, 잘못된 ID는 문서 카드로 처리하지 않는다.

## 미리보기

- 본문 및 댓글/답글의 작성·수정 중, 저장된 본문과 댓글 조회 시 내부 문서 URL을 감지한다.
- 일반 URL과 앵커 href를 모두 감지한다. 같은 내용 내 동일 문서는 카드 하나로 표시한다.
- 해당 콘텐츠 아래에 문서 아이콘, 종류, 제목, 기안자, 요약을 표시하는 반응형 카드를 렌더링한다.
- 카드 메타데이터는 저장하지 않는다. 현재 로그인 사용자의 기존 목록 API를 `scope=ALL`, `electronicApprovalId=id`로 호출한다.
- 결과가 없으면 `접근할 수 없거나 삭제된 문서입니다.`만 표시하고 제목·요약·기안자를 노출하지 않는다.
- 네트워크 오류는 내용 없는 오류 카드와 다시 시도를 제공한다. 조회 중에는 로딩 상태를 표시한다.
- 외부 OG 수집/이미지 요청을 하지 않는다. 미리보기 조회는 상세 조회수를 올리지 않는다.

## 상세 열기

- 카드 클릭과 저장된 내부 링크 클릭은 페이지 이동 대신 기존 우측 상세 패널을 연다.
- 상세 API는 열 때마다 기존 서버 권한을 다시 검사한다. 미리보기 후 권한이 회수되어도 상세 내용을 노출하지 않는다.
- 공유 URL 직접 진입 시 `documentId`를 해석해 같은 상세 패널을 연다.
- 본문 작성창에서 카드 클릭 시 작성 상태를 보존하고 그 위에 우측 상세를 표시한다. 상세를 닫으면 작성으로 돌아간다.
- 작성창이 이미 열려 있는 동안 링크 상세의 문서 수정/삭제 메뉴는 숨겨 기존 작성 내용을 덮어쓰거나 삭제하지 않도록 한다. 공유하기와 댓글은 유지한다.
- 문서현황에서 재사용하는 상세/작성창에도 같은 링크 상세 패널을 연결한다.
- 375px에서는 전체 너비 패널, 768/1280px에서는 기존 우측 패널 너비를 따른다.
- 양식 선택·교체처럼 `emitUpdate: false`로 본문을 바꾸는 경우도 미리보기를 즉시 동기화한다.
- 비로그인 사용자는 기존 로그인 이동 정책을 따른다. 로그인 후 원래 링크로 자동 복귀하는 인증 흐름 변경은 이번 범위에 포함하지 않는다.

## 검증

유효/잘못된 링크, 타 origin, 중복 URL, 권한 없는 문서, 실패 후 재시도, 복사 성공/실패, 피드와 상세의 메뉴, 작성·댓글·수정·답글의 붙여넣기, 직접 진입 및 우측 상세 열기를 검증한다.

## DB 및 권한 근거

읽기 전용 MCP의 `list_tables`와 `describe_table(tb_electronic_approval_main)`으로 문서 ID·제목·본문·tenant·삭제 상태 컬럼 존재를 확인했다. 데이터 행은 조회하지 않았다. 기존 Mapper의 `documentReadAccess`, `relatedWriteDocumentFilters` 및 상세 접근 서비스를 재사용하며 API/DB 변경은 없다.
