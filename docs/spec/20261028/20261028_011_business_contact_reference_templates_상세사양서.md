## 화면 요구사항

### 업무연락 작성 화면

- 참조자 입력 오른쪽에 접근 가능한 이름 `자주 쓰는 참조자`를 가진 버튼을 표시한다.
- 넓은 화면에서는 입력과 버튼을 한 행에 두고, 좁은 화면에서는 입력의 사용 가능한 너비를 보존하며 버튼이 아래 줄로 이동할 수 있다.
- 업무연락에서만 이 설정 진입 버튼을 표시한다. 기안서 참조 입력은 기존 결재선 설정 진입 흐름을 유지한다.
- 결재선 선택과 참조자 선택의 입력 컨트롤 높이는 참조 필드에 맞춰 40px로 통일한다. 각 필드 옆의 결재/합의/설정/참조 템플릿 버튼도 `height` 및 `minHeight`를 40px로 설정한다.

### 참조자 설정 모달

- 기존 `DocumentApprovalSettingsDialog`와 기존 템플릿 API/사용자별 권한 경계를 재사용한다.
- 모드 값은 `approval` 또는 `reference`이며, 생략 시 기존 `approval` 동작을 유지한다.
- `reference` 모달의 접근 가능한 제목은 `참조자 설정`이다. 설명/저장/목록 문구는 참조자 용어를 쓴다.
- 참조자 선택 영역과 템플릿 저장/불러오기/이름 변경/삭제 기능을 제공한다.
- 참조 모드에서는 결재 단계 목록, 결재자/합의자 변경, 결재 추가, 합의 추가를 표시하지 않는다.
- 공통 `적용` 및 `취소` 버튼을 유지한다.

## 데이터 및 상호작용

- 템플릿 문서 코드는 기존 업무연락 값 `008`이다. 요청/응답 타입, API 경로, 저장 구조는 변경하지 않는다.
- 참조자 템플릿 저장은 선택 순서를 유지한 `REFERENCE` 참여자만 직렬화한다. 결재/합의 단계는 저장하지 않는다.
- 템플릿 불러오기는 상세 응답의 모든 참여자가 `REFERENCE`인지 먼저 검사한다. 한 건이라도 `APPROVAL` 또는 `AGREEMENT`이면 오류를 표시하고 기존 임시 선택/목록 화면을 유지한다.
- 유효한 템플릿은 참여자를 저장 순서대로 현재 사용자 옵션에 매핑한다. 옵션에 없는 사용자나 반복 사용자가 있으면 상태를 변경하지 않고 오류를 표시한다.
- 불러오기는 모달의 임시 참조자만 교체한다. 작성 화면으로 전달하는 시점은 `적용` 버튼을 누를 때다.
- `취소`/닫기/바깥 클릭은 `onApply`를 호출하지 않고 작성 화면의 기존 참조자를 보존한다.
- 참조 모드는 적용 시 결재 단계를 빈 배열로 전달한다. 기존 기안서 모드는 현재 결재/합의 단계 및 참조자 적용 동작을 그대로 유지한다.
- 템플릿 이름 중복, 길이 제한, CRUD 실패는 기존 사용자 오류 노출 흐름을 유지한다. 참조 모드 문구는 참조 의미에 맞게 표시한다.

## 오류 처리

- 문서 코드 불일치, 잘못된 템플릿, 사용자 옵션 불일치, 중복 참여자, 목록/저장/이름변경/삭제 API 실패는 모달 내 오류 안내로 표시한다.
- 혼합 템플릿의 부분 적용, 잘못된 데이터를 성공으로 처리, 실패 후 임시 상태를 비우는 fallback은 허용하지 않는다.

## 회귀 및 검증

- 참조 전용 UI가 결재/합의 입력을 숨기는지 검증한다.
- 참조자 저장 payload가 `008` 및 순서가 보존된 `REFERENCE` 항목만 포함하는지 검증한다.
- 유효/혼합/사용자 누락/중복 템플릿 케이스에서 성공 적용 또는 오류 후 상태 보존을 검증한다.
- 모달 적용/취소와 작성 화면 진입 버튼을 검증한다.
- 같은 작성 화면의 결재선/참조자 입력 높이와 버튼 높이가 40px로 일치하는지 DOM 스타일 검증을 추가한다.
- 기존 기안서 결재선 설정의 단계 편집, 저장, 불러오기, 적용/취소 회귀 테스트를 실행한다.
- 실제 브라우저에서 375px, 768px, 1280px 레이아웃을 확인하고 결과 문서에 캡처를 연결한다.

## 제외 범위

- 신규 백엔드 API, DB 테이블/컬럼, 마이그레이션, 템플릿 타입 추가
- 조직 공용 또는 타 사용자 템플릿 공유
- 기존 혼합 템플릿 데이터 자동 변경/변환
- 기안서의 결재선 편집 정책 변경
