# 종합현황 스켈레톤 상세사양

근거: [계획서](../../plan/20261028/20261028_003_dashboard-skeleton_계획서.md)

- 초기 overview 로딩: 개인 업무 제목/보조문구 → 카드 3개 → 업무/공지 패널 2개. 카드 그리드는 실제와 동일하게 xs 1열/sm 3열, 패널은 xs 1열/md 2열이다.
- 권한 미확인 중 영업 데이터 영역은 미리 노출하지 않는다. overview 완료 후 기존 canReadSales 조건 아래 영업 전용 스켈레톤을 표시한다.
- 영업 로딩: 기존 영업 제목/월 선택 유지 → 카드 3개 → 수주 흐름/납기 패널. 패널은 실제와 동일하게 xs 1열/lg `1.15fr 1fr`.
- 카드 테두리·배경·패딩·제목/아이콘·수치/단위·하단 설명 위치를 실제 MetricCard와 공유한다. 패널도 OverviewPanel의 헤더·본문 패딩을 공유한다.
- 업무는 배지/제목 3행, 공지는 제목/날짜 3행, 차트는 6개 막대와 월 라벨, 납기는 날짜 타일/수주번호/거래처 3행으로 표현한다. 실제 목록 수·제목 길이에 따른 높이 변화까지 고정하지 않는다.
- 로딩은 이름이 구분된 status로 알리고 내부 장식은 접근성 트리에서 숨긴다. 스켈레톤은 클릭/탭으로 업무 이동을 일으키지 않는다.
- 밝은/다크 테마, 375/768/1280px에서 가로 넘침과 카드 외곽 치수를 확인한다.
- API/백엔드/DB/권한 정책 변경 없음. DB MCP/스키마 스크립트 대상 아님.
