# 현황 빈 조회 결과 공통 메시지 상세사양서

## 대상과 위치

사용자가 승인한 위치는 검색조건 아래의 기존 공통 메시지 영역이다. 적용 대상은 필수 수주일자를 사용하는 수주현황과 필수 결재신청일을 사용하는 문서현황(업무현황) 두 화면뿐이다. 그리드 내부 빈 행 표시와 오류 영역은 유지하고 문서현황 하단의 별도 빈 결과 박스는 제거한다.

## 공통 컴포넌트

- `PageMessageArea`는 기존 기본값 `severity="error"`, `role="alert"`를 유지한다.
- 기존 메시지 정규화와 닫기 동작을 유지하면서 선택적 action, role 및 닫기 콜백을 허용한다.
- `EmptySearchResultMessage`는 `onReset: () => void`를 받는다. 내부적으로 PageMessageArea의 `severity="info"`, `role="status"`를 사용하고 닫기 버튼은 제공하지 않는다.
- 안내 문구: `조회 결과가 없습니다. 조회 기간을 넓히거나 상세검색 조건을 초기화해 주세요.`
- 버튼: `검색 조건 초기화`. 두 페이지의 기존 resetSearch를 직접 호출한다. 날짜를 비우거나 전체 기간 조회를 새로 만들지 않는다.
- 작은 화면에서는 문구와 action이 줄바꿈되어 겹치거나 페이지 가로 스크롤을 만들지 않는다.

## 표시 상태

| 상태 | 빈 결과 안내 |
|---|---|
| 첫 목록 조회 전 / 기본값 로딩 | 숨김 |
| 최초 또는 재조회 진행 중 / 조용한 갱신 중 | 숨김 |
| 정상 조회 완료, 문서 totalRowCount=0 또는 수주 rows.length=0 | 표시 |
| 정상 조회 완료, 결과 존재 | 숨김 |
| 목록 오류 / 검색 기본값 오류 | 숨김, 기존 오류 처리를 유지 |

수주 목록 훅에 hasLoaded를 추가해 첫 성공 이전의 빈 배열과 정상 0건 결과를 구분한다. 조회 시작 시 false, 정상 응답 시 true로 변경하며 실패 시 false를 유지한다. 문서현황은 기존 hasLoaded와 totalRowCount를 재사용한다.

## 검증

- 두 페이지의 메시지가 info status로 표시되고 그리드보다 DOM 및 화면상 앞에 있는지 확인한다.
- 지연된 초기 조회와 재조회 동안 메시지가 보이지 않는지 확인한다.
- 재조회 오류 후 빈 결과 안내가 다시 나타나지 않고 오류만 표시되는지 확인한다.
- 초기화가 기존 날짜 기본값을 포함한 재조회를 실행하는지 확인한다.
- 정상 데이터가 있는 기존 목록과 오류 메시지 닫기 동작을 유지한다.
- 375px, 768px, 1280px 실제 브라우저에서 줄바꿈과 가로 넘침을 확인한다.
- 백엔드, API, DB, F1-Grid 자체의 옵션·이벤트·문서는 변경하지 않는다.
