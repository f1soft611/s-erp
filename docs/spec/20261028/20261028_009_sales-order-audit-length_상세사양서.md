## 원인과 변경 계약

- `EgovLoginUsr_SQL_postgresql.xml`의 `actionLogin`은 `tb_login_account.login_code`를 인증 객체의 `id`로 반환한다.
- `SalesOrderApiController`는 인증 객체의 `id`를 서비스에 전달하며 등록은 `createdBy`, 수정·삭제는 `updatedBy`로 바인딩한다.
- 기본 MCP에서 원본은 최대 100자이나 수주 헤더 두 컬럼은 최대 10자로 확인했다. 따라서 11~100자 인증 사용자 키는 정상 계약임에도 DB에서 거부된다.
- 실제 실패 요청의 사용자 키나 업무 데이터는 조회하지 않았다. 제공된 스택 일부만으로 실패 statement를 직접 확인한 것은 아니며, 코드와 메타데이터로 재현 가능한 계약 결함을 확인했다.
- `public.tb_sales_order_hd.created_by`, `updated_by`만 nullable `varchar(100)`으로 변경한다. 기존 값, NULL, 기본값, 제약, 작성자 판별·조회 join·인증 전달은 유지한다.
- API 경로, 요청/응답, 수주번호, 상세 테이블 및 프론트엔드는 변경하지 않는다.

## 배포 및 롤백

- 기존 DB에는 `20261028_009_expand_sales_order_audit_columns.sql`을 적용한다.
- 신규 DB에는 기존 `20261026_008` 생성 DDL 후 이번 변경 SQL을 적용한다. 과거 이력 파일은 수정하지 않는다.
- 트랜잭션 내 두 컬럼을 함께 변경하고 `lock_timeout = '5s'`를 사용한다. 잠금 대기 초과 시 부분 적용하지 않고 트랜잭션을 종료·재시도한다.
- 롤백은 `ACCESS EXCLUSIVE` 잠금을 획득한 후 `char_length(created_by) > 10 OR char_length(updated_by) > 10` 존재 여부만 검사한다.
- 긴 값이 있으면 행 값을 노출하지 않는 예외를 발생시키고 종료한다. 클라이언트는 실패한 트랜잭션을 `ROLLBACK`해야 한다.
- 긴 값이 없으면 두 컬럼을 `varchar(10)`으로 복구한다. 사용자 키 절삭이나 자동 삭제는 허용하지 않는다.
- MCP로 실제 DB에 DDL을 실행하지 않는다. DB 담당자가 대상 환경을 확인해 적용한다.

## 검증

| 조건 | 기대 결과 |
| --- | --- |
| 변경 전 합성 11자 등록/수정 | SQLSTATE 22001 |
| 변경 후 10/11/100자 및 다국어 100자 | 두 audit 값 그대로 보존 |
| 변경 후 NULL | 허용 |
| 변경 후 101자 | SQLSTATE 22001 |
| 확장 SQL 재실행 | 성공, 값 보존 |
| 어느 audit 컬럼이든 10자 초과 값 존재 시 롤백 | 실패, 두 컬럼과 데이터 보존 |
| 10자 이하 또는 NULL만 존재 시 롤백 | 성공, 두 컬럼 10자로 복구 |

- 검증용 DB에는 최소 테이블과 합성 값만 사용한다. 운영 데이터·계정·테넌트 행은 복제하지 않는다.
- 기존 수주 서비스·컨트롤러·Mapper 테스트로 인증 사용자 및 저장 흐름의 무변경을 확인한다.
- 화면 변경이 없어 스크린샷은 적용하지 않는다. 결과 문서에는 실제 DB 미적용/실저장 미검증과 격리 검증을 구분한다.
