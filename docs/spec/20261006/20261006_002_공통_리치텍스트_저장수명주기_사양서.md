## 2. Frontend contract

Shared lifecycle hook inputs:

- `editor`: nullable Tiptap editor instance
- `uploadImage(file)`: domain adapter returning `RichTextEditorImage`
- `deleteTemporaryImage(image)`: domain adapter deleting one temporary object

The hook exposes upload callbacks/count for `RichTextEditor`, orphan deletion callback, temporary-session cleanup, success-session completion, and a snapshot:

- `html`: `editor.getHTML()`
- `json`: `editor.getJSON()`
- `referencedImages`: current image node metadata for Notice-compatible request mapping
- `temporaryImages`: all current unexpired temporary uploads, including images no longer referenced so server completion can clean them

The hook must distinguish the current body references from the whole upload session. It must not swallow API save errors or close dialogs; consumers preserve their existing retry and close behavior.

Notice maps snapshot to existing `contentsHtml`, `contentsJson`, `embeddedImages`, `temporaryImages`. Draft maps it to existing `templateHtml`, `templateJson`, `embeddedImages`. No endpoint or field rename is allowed in this work.

### Clipboard rich-text preservation

When clipboard `text/html` contains no spreadsheet table, `normalizeClipboardHtmlForEditor` preserves safe HTML formatting and passes it through `sanitizeHtml(..., { preserveTextStyles: true })`; it must not reduce the content to `textContent`. Preserve safe `font-family`, `font-size`, color and emphasis from inline spans and supported block styles. Convert legacy `<font face="..." size="...">` to equivalent safe inline span styles (`size=1..7` maps to the existing 8/10/12/14/18/24/36pt scale). For Excel tables, preserve each clipboard `<br>` and text-node line break, indentation, spaces, and blank lines in source order without interpreting markers or inferring soft wraps. Plain-text clipboard tabs and spaces are preserved; CRLF may be canonicalized to LF. Loading stored JSON must not transform existing breaks. CSS `font` shorthand, class-based `<col>` widths, safe `white-space`, `word-break`, `overflow-wrap`, and `line-height` continue through their allowlists; table paragraphs inherit the cell font size. Frontend/backend HTML and JSON sanitizers preserve safe table-cell `font-family`, `font-size`, `font-style`, and `line-height`. Wrapping values are limited to the documented CSS enums in the shared design. Strip unsafe CSS, active tags and event attributes. Notice and Draft use this same editor pipeline.

## 3. Backend sanitizer and processor contract

`RichTextDocumentSanitizer` is the authoritative server-side sanitizer for both Notice and Draft. Its allowlist follows the shared Tiptap editor and Notice's existing shared `sanitizeHtml(..., { preserveTextStyles: true })` policy. It preserves `textStyle` attrs (`color`, `fontFamily`, `fontSize`), underline/link marks, table structure/attrs and supported styles, and bounded image dimensions. It removes unsupported nodes/attrs, event handlers, active embedded content, unsafe CSS, and dangerous URL protocols. CSS rejects `url()`, `expression()`, script protocols, braces, and markup delimiters. JSON null/missing fields are not converted into the strings `"null"` or other synthetic values.

The frontend `sanitizeHtml` remains for immediate client-side normalization, but neither domain may rely on client sanitization for server security. The backend common sanitizer processes both HTML and JSON before image processing and persistence. The common image processor then validates owner-bound image references and rewrites them to the server-selected domain's stable route. Temporary token/upload attrs are retained only until promotion succeeds, then removed. Domain services do not maintain a second editor sanitizer.

The processor receives tenant ID, server-selected owner type/ID, HTML, JSON, referenced image-node metadata, the separate full temporary upload session, uploaded-by identity, and a stable URL resolver. It returns rewritten HTML/JSON and retained file IDs. Referenced detail metadata supplies the preferred fileName for a referenced new token; only the full session authorizes a new promotion. If detail is absent, the session supplies fallback fileName. A file already verified in the current owner list may be retained without a current upload session.

Image processing rules after common sanitization:

1. Collect only textual, nonblank `data-upload-token` values from both HTML and JSON; JSON null/missing values are empty, never the string `"null"`.
2. Reject duplicate or malformed temporary session metadata.
3. Promote only tokens referenced by the current document and allowed by this request's temporary session. `embeddedImages` details take precedence; validated session token/fileName is the fallback.
4. Resolve retained images by server-owned file ID or object key. A stale token may identify an existing file only when it matches that file's established object-key token segment within the current tenant/owner list.
5. Validate promoted metadata tenant, owner type, owner ID, and `EMBEDDED` usage before using it.
6. Rewrite both HTML and JSON image source through the domain stable URL resolver; write stable file ID/object key metadata and remove all transient upload attrs.
7. Return retained IDs for existing `completeOwnerSave` or `completeTemplateSave` cleanup after the domain row save.
8. Reject an unreferenced owner, a different owner's stable URL, or an unowned file ID. The common sanitizer applies the same editor allowlist before this image-specific owner validation.

## 4. Domain adapters

- Notice continues validating post existence and saving its existing post columns. Owner is fixed to `NOTICE/postId`; stable URL is `/api/v1/groupware/boards/notice/posts/{postId}/embedded-images?objectKey=...`; legacy Notice keys remain supported.
- Draft continues applying its form row lock and existing authorization before save. Owner is fixed to `DRAFTING_WORK_TEMPLATE/formId`; stable URL is `/api/v1/co/workflow/forms/{formId}/template-images/{fileId}`. Draft's private editor HTML/JSON sanitizer is removed after equivalent content is covered by common sanitizer tests.
- Each domain converts its request VO to common `EmbeddedImageUploadVO` metadata and maps processor results back to its existing response/request lifecycle.
- Controllers remain responsible for authorization; common processor never accepts owner identity from request JSON.

## 5. Compatibility and validation

- No database schema, API route, request field, ordinary attachment, MinIO lifecycle, or owner policy change.
- Preserve text/table/image paste, upload progress gating, retries, saved-image hydration, and each dialog's existing close semantics.
- Tests cover common lifecycle hook, sanitizer allowlist/security and rich-text preservation parity, processor token/ownership cases, Notice/Draft request DTO compatibility, and row persistence behavior.
- Browser save/reopen validation must use a backend runtime that has reloaded `backend/target/s-erp-backend`; `mvn test` alone does not reload an already running IntelliJ Tomcat JVM.
