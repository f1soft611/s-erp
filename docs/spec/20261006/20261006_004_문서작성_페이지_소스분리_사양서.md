# 20261006_004 문서 작성 페이지 소스 분리 사양서

## 1. 목적 및 배경

문서 작성 페이지의 단일 소스 파일이 화면 조립, 샘플 문서, 목록 파생 데이터, 상태 요약, 작성 모달과 편집기 상태를 한꺼번에 소유하고 있다. 역할별 파일로 분리해 문서 작성 기능을 확장할 수 있는 기반을 만든다.

이 사양은 소스 구조 변경만 다룬다. 문서 조회·저장 API나 사용자 흐름은 추가하지 않으며 현재 UI와 동작은 동일해야 한다.

## 2. 기준 패턴 및 대상

- 기안양식관리의 기능별 `components/`, `hooks/`, `types/`, `services/` 폴더와 페이지 조립 패턴을 따른다.
- 공지사항처럼 작성 모달을 페이지와 분리한다.
- 작성 모달은 기존 공용 `CommonDialog`와 `RichTextEditor`/`RichTextEditorToolbar`를 사용한다. 페이지 전용 Tiptap editor 인스턴스나 서식 도구를 새로 만들지 않는다. `CommonDialog`, 공통 에디터 자체 및 공지사항 작성 페이지는 변경하지 않는다.
- 대상 코드: `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`
- 기존 회귀 테스트: `frontend/tests/document-write-page.test.tsx`
- 날짜별 작업지시서와 상세 계획은 각각 `docs/directions/20261006/20261006_004_문서작성_페이지_소스분리_작업지시서.md`, `docs/plan/20261006/20261006_004_문서작성_페이지_소스분리_계획서.md`를 따른다.

## 3. 파일 구조 및 책임

```text

  types/

```

### `DocumentWritePage.tsx`

페이지 조립을 담당한다. `PageHeader`, 콘텐츠 영역, 공용 보기 도구, `ContentSplitLayout`, 왼쪽 목록/피드, 오른쪽 요약 및 `DocumentComposerDialog`를 연결한다. 상세 편집기 마크업이나 샘플 데이터 선언을 소유하지 않는다.

### `components/`

- `DocumentFeedItem`: 저자·날짜·문서 종류·상태·제목·요약을 표현하는 기존 카드와 상태 칩을 표시한다.
- `ApprovalSummaryPanel`: 전체 샘플 목록의 대기/진행/임시저장 건수 및 기존 알림 3건을 표시한다.
- `EmptyDocumentList`: 기존 안내 문구와 문서 작성 진입 버튼을 표시한다.
- `DocumentComposerDialog`: 문서 종류 탭, 제목 필드, 공통 `RichTextEditor`, 공통 `RichTextEditorToolbar`, 첨부 목록 및 하단 액션을 표시한다. `CommonDialog`에 `title="문서 작성"`, `size="lg"`, `bodyMode="fill"`과 현재 footer 슬롯·액션을 전달한다.

### `hooks/`

- `useDocumentWritePage`: 초기 보기 모드는 `list`, 초기 업무 구분 필터는 전체(`''`), 작성 다이얼로그는 닫힘 상태로 관리한다. 필터 적용 목록, 상단 고정 목록, 비고정 목록, `PinnedItemsPanel`/`ListView` 입력 모델을 기존과 동일한 순서와 값으로 파생한다.
- `useDocumentComposer`: 초기 문서 종류는 `기안서`, 제목과 첨부는 비어 있는 상태로 시작한다. 에디터를 생성하지 않고 공통 `RichTextEditor.onEditorReady`에서 받은 Tiptap editor 인스턴스를 보관한다. 툴바 표시는 공통 툴바가 관리한다. 첨부 파일 선택 시 기존 선택 파일 뒤에 추가하고 input 값을 비워 동일 파일 재선택을 허용한다. 모달 닫기 시 제목·첨부·에디터 본문을 초기화한 후 페이지에 닫힘을 알린다.

### `types/` 및 `data/`

- `documentWrite.types.ts`는 기존 `DocumentKind`, `ApprovalStatus`, `DocumentWriteItem`, `DocumentWritePageProps` 선언을 옮긴다. 유니온 항목과 필드명·선택 여부를 변경하지 않는다.
- `documentWriteData.ts`는 기존 `documentKinds`, `sampleDocuments`, `statusColor`를 옮긴다. 샘플 수, 순서, 제목, 종류, 상태, 작성자, 날짜, 요약, 고정 여부 및 색상 매핑을 바꾸지 않는다.

### `services/` 미생성 사유

대상 페이지에는 API나 저장 동작이 없다. 따라서 빈 서비스 파일 또는 샘플 배열을 API처럼 가장하는 모듈을 만들지 않는다. 실제 문서 CRUD를 추가하는 별도 작업에서 API 계약과 함께 `services/`를 도입한다.

## 4. 사용자 흐름과 불변 동작

1. 페이지 진입 시 리스트 보기와 모든 문서가 기본 표시된다.
2. 사용자는 기존 보기 전환 버튼으로 리스트/피드 보기를 전환할 수 있다.
3. 업무 구분 메뉴 선택 시 같은 업무 구분 문서만 표시되며 상단 고정과 비고정 영역은 기존처럼 나뉜다.
4. 문서 작성 액션 또는 빈 상태의 작성 버튼은 `CommonDialog` 작성 모달을 연다.
5. 기안서/업무연락 탭은 사용 가능하고 지출결의서/근태신청 탭은 비활성 상태를 유지한다.
6. 제목, 공통 본문 에디터·서식 툴바와 첨부 추가·삭제 동작을 유지한다.
7. 저장 버튼은 기존대로 비활성 상태다. 취소 또는 닫기 후 다시 열면 제목, 첨부, 본문이 초기 상태여야 한다.
8. 요약 패널의 카운트와 알림 문구·정렬·표시 개수는 동일하게 유지한다.

## 5. 오류·로딩·권한 및 API

- 네트워크 호출이 없으므로 새 로딩, 성공, 오류, 재시도 상태를 만들지 않는다.
- 기존 작성 액션 노출을 바꾸지 않는다. 권한 검사를 새로 추가하지 않는다.
- 신규 API, 임시 저장, 문서 생성/수정, 저장 버튼 활성화, 유효성 검증은 이 범위에서 제외한다.
- 에디터 초기화나 파일 선택 예외에 대한 새 성공형 기본값·예외 삼키기를 추가하지 않는다.

## 6. 접근성 및 반응형

현재 aria-label, 테스트 ID, 공용 보기 도구의 접근성 이름을 보존한다. 반응형 CSS를 재설계하지 않는다. 컴포넌트 이동 후 375px, 768px, 1280px 브라우저 너비에서 페이지 전체 가로 넘침, 버튼/툴바 겹침 및 다이얼로그 사용 가능 여부를 확인한다.

### 완료 조건

- 페이지의 역할이 조립 중심으로 줄고, 승인된 파일 책임대로 코드가 분리된다.
- 기존 목록·피드·필터·요약·모달 동작과 샘플 데이터가 유지된다.
- 공용 `CommonDialog`를 계속 사용하고 저장 버튼은 비활성 상태다.
- 지정 테스트와 빌드가 통과하고, 3개 뷰포트 결과를 결과 보고서에 남긴다.
- 변경 범위에 공지사항, 공유 다이얼로그, 라우팅 또는 백엔드 파일이 포함되지 않는다.
