## 1. Database ownership contract

현재 `public.tb_common_file` schema에 필요한 컬럼이 모두 존재한다. 새 DDL은 만들지 않는다.

| Consumer              | `owner_type`             | `owner_id`                  | `file_usage_type` |
| --------------------- | ------------------------ | --------------------------- | ----------------- |
| Notice embedded image | `NOTICE`                 | `tb_board_post.post_id`     | `EMBEDDED`        |
| Draft template image  | `DRAFTING_WORK_TEMPLATE` | `drafting_work_category_id` | `EMBEDDED`        |

`tenant_id`와 `file_id`는 모든 select/update/delete 조건에 포함한다. Owner values는 controller/domain service가 고정하며 요청 JSON의 owner 값은 받거나 신뢰하지 않는다.

## 2. Common storage service boundary

공통 service는 MinIO 및 공통 파일 metadata의 storage mechanics만 소유한다.

- 안전한 파일명, MIME/signature, 최대 크기 검증
- tenant-scoped temporary upload key 및 `s-erp-temp-owner=embedded-image` tag 생성
- preview용 presigned URL 생성; 이 URL은 편집 중에만 사용하며 저장 HTML/JSON에 남기지 않는다.
- token/fileName/tenant 범위 temporary delete
- 임시 객체 `stat`, tenant/temp prefix 확인, permanent key로 tag 없는 copy
- server-supplied `owner_type`, `owner_id`로 `tb_common_file` metadata insert
- transaction rollback 시 permanent object 보상 삭제; DB commit 뒤 임시 객체 제거
- owner가 실제 문서에서 더 이상 참조되지 않는 file records soft delete 및 object after-commit cleanup
- tenant/owner/fileId를 모두 검증하는 owned image load/stream

Domain service는 post/form 존재 및 사용자 권한, owner binding, 본문 URL rewrite, request별 retained image 계산을 담당한다. 공통 service는 URL route 또는 도메인 권한을 추측하지 않는다.

## 3. Object lifecycle

1. Upload는 `tenant/{tenantId}/embedded-image-temp/{uploadToken}/{safeFileName}` 임시 key에 저장한다. Object tag는 `s-erp-temp-owner=embedded-image`로 제한한다.
2. Editor preview에는 bounded presigned GET URL을 반환한다. Presigned expiration은 object expiration과 별개다.
3. Save request는 본문 JSON/HTML에 존재하는 유효한 문자열 `data-upload-token`만 임시 이미지로 승격한다. JSON `null`/누락 값은 token으로 수집하지 않는다. `embeddedImages` metadata를 우선 사용하고, Notice는 현재 업로드 세션에서 검증된 `temporaryImages` token/fileName을 metadata fallback으로 사용할 수 있다. 본문이 참조하지 않는 session token은 승격하지 않는다.
4. Permanent key는 `tenant/{tenantId}/embedded-images/{ownerType}/{ownerId}/{uploadToken}/{safeFileName}`를 사용한다. Promotion copy는 임시 tag를 제거한다.
5. `tb_common_file`에 permanent key, bucket, storage provider, metadata, tenant, owner type/ID, `EMBEDDED`, `deleted_yn='N'`를 기록한다.
6. Persisted HTML과 JSON의 image source는 해당 consumer의 고정 인증 route로 바꾸고 token/transient attributes/presigned URL을 제거한다.
7. Save 성공 뒤 사용되지 않은 이번 요청 token을 삭제한다. Cancel/orphan은 즉시 DELETE한다. Transaction rollback은 새 permanent object를 보상 삭제하고 unpromoted temp를 TTL fallback에 맡긴다.
8. MinIO lifecycle은 `tenant/` prefix와 공통 temp tag를 함께 만족하는 객체만 7일 후 만료한다. 운영 rule은 문서화하되 앱이 production bucket lifecycle을 자동 변경하지 않는다.

## 4. Notice adapter

- Create: 게시글 row insert로 post ID를 얻고, 본문에서 참조된 temp images만 승격한다. HTML/JSON을 permanent file ID를 포함한 stable route로 rewrite한 뒤 최종 contents를 같은 DB transaction 안에서 저장한다.
- Update: 기존 embedded file metadata를 현재 본문 참조와 대조한다. 유지 파일은 owner mapping을 보존하고 신규 token만 승격한다. 제거 파일은 transaction 내 soft delete 후 commit 뒤 object delete를 수행한다.
- Update compatibility: 본문 token이 현재 upload session에 없어도, 해당 token이 현재 Notice owner 목록의 object key token segment와 일치하면 기존 파일로 매핑한다. 다른 owner 또는 미귀속 token은 계속 거절하며 HTML/JSON rewrite에서 transient token을 제거한다.
- Read: owner `NOTICE` + post ID + tenant + `EMBEDDED` metadata를 검증하고 stable notice image route를 응답한다.
- Feed/editor: 인증 stable URL은 `<img>`가 직접 요청하지 않는다. 프론트가 Authorization을 포함한 blob API로 조회해 object URL로 표시하며, 저장된 HTML/JSON URL은 stable route로 유지한다.
- Edit hydration: 이미 저장된 Notice 이미지의 `data-upload-token`/`data-upload-state`는 editor 설정 전에 제거한다.
- Existing records: `notice-temp` object key로 이미 저장된 소유 이미지는 read/delete 시 legacy key로 계속 접근한다. 신규 이미지는 common permanent prefix에 저장한다.

## 5. Draft adapter

- Existing form authorization, row lock, `DRAFTING_WORK_TEMPLATE` owner checks, stable `/api/v1/co/workflow/forms/{id}/template-images/{fileId}` URL을 유지한다.
- Domain image service는 공통 storage service 호출로 축소하고 template JSON/HTML rewriting, retained file calculation, form ownership validation을 유지한다.
- Frontend dialog는 현재 진행 중 upload가 있으면 save/close를 block한다. Cancel과 editor orphan callbacks는 공통 temporary DELETE를 호출한다.

## 6. Frontend contract

`RichTextEditor`는 file clipboard 우선 처리, local placeholder, local object URL, upload progress, orphan callback, error callback을 유지한다. Domain adapters는 response를 `RichTextEditorImage`에 mapping한다. Owner type/ID는 frontend에서 정하지 않는다.

Notice와 Draft 모두 upload in progress 동안 save/cancel/close를 block한다. 성공 저장 응답은 stable HTML/JSON으로 editor state를 재설정하거나 dialog를 닫고 다시 조회할 때 stable URL만 사용한다.

## 7. Compatibility and tests

- 기존 notice, draft embedded images는 owner metadata와 기존 경로 검증으로 계속 조회한다.
- 일반 attachment route/`ATTACHMENT` records에는 변경을 적용하지 않는다.
- 회귀 tests verify Notice feed authenticated image loading, editor metadata가 부족한 update의 session-token 승격, 기존 이미지 retention 및 stable URL 유지.
- Tests verify upload, preview, promote, owner metadata, URL rewrite in HTML/JSON, existing image retention, image removal, save rollback, cancel/orphan cleanup, lifecycle tag, and stable GET ownership validation.
- DB MCP `list_tables`/`describe_table(public.tb_common_file)` 증거를 결과 문서에 기록한다. No row data is queried.
- MinIO lifecycle live rule은 operator 권한 필요. 적용 여부를 확인하지 못하면 결과 문서에 미적용/미확인으로 기록한다.
