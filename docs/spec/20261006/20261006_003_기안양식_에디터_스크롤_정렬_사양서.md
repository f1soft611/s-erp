## 1. 문제 및 원인

기안양식 편집 모달에서 `data-testid="draft-form-template-editor"` Box가 `overflow: auto`와 `p: 2`를 함께 소유하고 있었다. 이 구조에서는 에디터 자체가 프레임 안쪽으로 밀리고 바깥 Box가 스크롤을 담당한다. 공지사항 작성 모달은 프레임의 overflow를 숨기고 Tiptap `.ProseMirror`가 본문 스크롤을 담당한다.

## 2. 기대 동작

- 세로/가로 스크롤 컨테이너는 기안양식 본문 `.ProseMirror`다.
- 스크롤 영역은 테두리 있는 에디터 프레임의 최상단 경계에서 시작한다.
- 프레임은 `overflow: hidden`으로 에디터 자체 스크롤을 대체하지 않는다.
- 기존 콘텐츠 주변 간격(16px)은 `.ProseMirror`의 `px: 2`, `py: 2`로 보존한다.
- 에디터가 비어 있거나 긴 본문/표가 로드된 경우에도 본문 스크롤 영역의 flex 높이 제약과 최소 높이를 유지한다.

## 3. 범위 및 비범위

### 범위

- `DraftFormTemplateDialog`의 에디터 frame 및 `.ProseMirror` 스타일
- `draft-form-template-dialog.test.tsx`의 스타일 회귀 테스트
- 본 변경의 작업지시서, 계획서, 사양서, 결과 및 브라우저 캡처

### 비범위

- `CommonDialog`, `RichTextEditor` 공통 기본 스타일 및 공지사항 모달 수정
- 다이얼로그 크기 또는 폭 변경
- toolbar, 저장/API, 템플릿 데이터, 이미지 처리 및 미저장 변경 동작 변경

## 4. 검증 기준

1. DOM 테스트에서 dialog의 editor frame이 `overflow: hidden`을 적용한다.
2. 편집 가능한 `.ProseMirror`가 `overflowX: auto`, `overflowY: auto` 및 16px 안쪽 padding을 가진다.
3. 템플릿 불러오기/저장 및 이미지 회귀 테스트가 통과한다.
4. `npm --prefix frontend run build`와 `git diff --check`가 통과한다.
5. 브라우저에서 데스크톱 및 좁은 화면을 확인하고, 스크롤바가 프레임 상단에서 시작하고 본문 여백이 유지되는지 스크린샷으로 기록한다.
