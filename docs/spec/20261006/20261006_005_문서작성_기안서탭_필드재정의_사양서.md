# 20261006_005 문서작성 기안서 탭 필드 재정의 사양서

## 1. 목적과 대상

`/groupware/doc/write`의 작성 모달에서 기안서 탭을 실제 기안양식 및 F1-Grid 사용자 선택 패턴에 맞게 구성한다. 목록/피드 페이지, 저장/상신, 실제 결재 처리 흐름은 바꾸지 않는다.

- 계획서: [20261006_005 문서작성 기안서 탭 필드 재정의 계획서](../../plan/20261006/20261006_005_문서작성_기안서탭_필드재정의_계획서.md)
- 관련 선행 사양: [기안양식관리](../20261001/20261001_001_전자결재_기안양식관리_사양서.md), [F1-Grid 사용자 선택](../20261001/20261001_005_F1Grid_사용자_선택_컬럼_사양서.md)

## 2. 기안서 탭 필드

기안서 탭 콘텐츠 순서는 다음과 같다.

1. 메타데이터: 기안일, 기안자
2. 양식 선택: 구분, 기안양식
3. 결재선, 참조
4. 기존 제목 필드
5. 기존 리치 텍스트 에디터

모든 입력은 F1-Grid 행 폼 모달의 small outlined 규격을 따른다. 필드 높이는 38px이며 전체 폭/좁은 폭에서 라벨과 컨트롤이 겹치지 않아야 한다. 사용자 다중 선택 입력은 칩이 늘어나는 공통 동작을 따르되 최소 입력 높이는 38px로 한다.

### 기안일과 기안자

- 기안일은 작성 모달 표시 시점의 오늘 날짜를 표시하고 읽기 전용으로 둔다.
- 기안자는 기존 `fetchMyProfile()`이 반환하는 로그인 사용자의 `name`을 표시하고 읽기 전용으로 둔다.
- 프로필 조회 실패 또는 표시 이름 누락을 임의의 사용자 이름으로 대체하지 않는다. 조회 실패/필수 표시값 누락은 모달의 오류 상태로 알린다.

### 구분과 양식 목록

- 구분 옵션은 활성 `WF_FORM_CATEGORY` 항목과 `전체`다. 기본값은 `전체`다.
- 분류별 양식은 해당 `categoryItemId`에 맞는 기안양식만 표시한다. `전체`에서는 모든 활성 분류를 대상으로 한다.
- 기안양식은 `useAt='Y'`이고 `hasDocument=true`인 행만 선택 가능하다. 옵션 표시는 양식명(`codeName`)을 사용한다.
- 활성 분류나 선택 가능한 양식이 없으면 적절한 안내 빈 상태를 표시한다.
- 이미 선택된 분류에서 다른 분류로 바뀌면 기안양식 선택도 새 분류 결과에 맞게 해제한다. 본문이 수정된 상태라면 본문 교체 확인을 표시한다. 교체를 취소하면 이전 분류/양식 선택과 본문을 모두 보존한다.

## 3. 사용자 및 결재선

### 사용자 정보 표시

사용자 선택 후보 데이터는 기존 기안양식 사용자 목록에서 가져온다. F1-Grid `user` 편집기의 검색/선택 동작과 옵션 정보를 재사용한다. 후보와 선택 완료된 결재자, 합의자, 참조자는 프로필 사진, 이름, 부서를 알아볼 수 있게 표시한다. 사용자가 없거나 옵션 로드가 실패했을 때 성공처럼 보이는 빈 선택기로 대체하지 않는다.

### 결재선 선택 및 등록

- 사용자 선택기는 결재선 영역에 한 개의 다중 선택 입력으로 제공한다.
- `결재 추가`는 선택자가 정확히 한 명일 때만 활성화한다. 추가한 사용자는 단독 결재 단계 하나가 된다.
- `합의 추가`는 선택 사용자 1명 이상을 받아 한 개의 합의 단계로 묶는다. 다중 합의자의 사진/이름/부서를 한 번호 아래 함께 보여준다.
- 두 버튼 모두 성공 시 새 단계를 기존 결재선 끝에 추가한다. 번호는 화면 순서대로 연속 부여하고 단계 삭제 시 번호를 다시 계산한다.
- 이번 범위는 단계 추가/삭제만 제공하며 드래그 재정렬은 제공하지 않는다.
- 결재/합의 단계에는 처리 전의 빈 도장 자리를 표시한다. 참조 항목은 승인 단계가 아니므로 도장 자리를 두지 않는다.
- 참조자는 결재선에 합치지 않고 별도 다중 선택 입력/목록으로 표시한다.

## 4. 양식 본문과 교체 보호

- 선택된 기안양식의 본문은 기존 `fetchDraftFormTemplate(formId)` 응답의 `templateJson`을 우선 사용하고, 없으면 `templateHtml`을 사용해 공통 리치 텍스트 에디터에 적용한다.
- 양식명은 문서 제목을 자동 채우지 않는다. 기존 제목 입력은 작성자가 계속 직접 입력한다.
- 사용자가 현재 템플릿에서 본문을 수정하지 않았다면 다른 양식 선택 시 새 본문으로 즉시 바꾼다.
- 본문 수정 후 분류 또는 양식을 변경하면 교체 확인을 표시한다. 확인 시 새 선택을 적용하고, 취소 시 이전 분류/양식 선택과 본문을 보존한다.
- 작성 모달 닫기/취소 후 재오픈하면 양식 선택, 사용자 선택, 단계, 제목, 본문 등 작성 중 상태를 초기화한다.

## 5. 오류, 저장 및 API 범위

- 기존 양식 분류/목록/본문/사용자 조회 서비스와 `fetchMyProfile()`을 통해 데이터를 읽는다.
- 프로필, 옵션, 양식 또는 템플릿 조회 오류는 모달 내 메시지로 표시한다. 오류를 삼키거나 샘플 데이터로 대체하지 않는다.
- 저장 버튼은 기존처럼 비활성 상태다. 새 문서 생성, 저장, 임시저장, 상신, 권한 검사, 결재 실행 요청을 추가하지 않는다.
- 실제 결재/합의/확인 후 도장 이미지 및 완료 상태는 후속 문서/결재 화면에서 처리할 별도 범위다. 이번 작성 화면에서는 빈 도장 자리만 렌더링한다.
- 사용자 선택 API에 현재 포함된 옵션 필드는 `userId`, `loginId`, `userNm`, `departmentNm`, `profileImage`, `levelNm`이다. 도장 이미지는 이 후보 API 계약에 없으므로 이번 모달에서 요청하거나 가짜로 표시하지 않는다.
- DB 및 백엔드 변경은 하지 않는다.

## 6. 테스트 및 완료 기준

### 자동 테스트

- 기안서 탭에서 기안일/기안자가 읽기 전용으로 표시되고 입력 필드가 38px 규격을 사용하는지 확인한다.
- 구분 기본값 `전체`, 분류 필터, `useAt='Y'` 및 `hasDocument=true` 필터를 확인한다.
- 양식 선택 후 에디터 본문 반영, 수정 후 교체 확인 취소/승인을 검증한다.
- 결재 버튼의 단일 사용자 제한, 합의 여러 명의 단일 단계 등록, 번호/삭제, 참조 다중 선택을 확인한다.
- 후보 및 선택 사용자에 사진/이름/부서가 표시되고 조회 실패 메시지가 노출되는지 확인한다.
- 저장 버튼 비활성, 닫기 후 입력 상태 초기화, 기존 탭/에디터 동작이 유지되는지 확인한다.

### 브라우저 확인

375px, 768px, 1280px에서 필드 높이, 사용자 선택 결과, 버튼/칩 줄바꿈, 결재선 스크롤, 모달 내부 스크롤 및 페이지 가로 넘침을 확인한다. 스크린샷과 결과 보고서는 `docs/result/20261006/document-write-draft-fields/`에 저장한다.
