## 2. 업로드 데이터 계약

### 원인

자료실 직접 업로드는 `tb_board_post` 행을 파일 첨부 전에 생성한다. SQL의 `insertArchivePost`는 `writer_id`/`writer_name`에 `writerId`/`writerName` 파라미터를 바인딩하지만, 업로드 서비스의 파라미터 map에는 최종 수정자 필드만 있었다. 실제 DB 메타데이터에서 `tb_board_post.writer_id`는 NOT NULL이므로 insert가 실패하고 공통 오류 메시지가 노출된다.

### 수정 계약

- 업로드 게시글 insert map에 다음 값을 모두 전달한다.
  - `writerId = user.getId()`
  - `writerName = user.getName()`
  - `lastModifiedBy = user.getId()`
  - `lastModifiedByName = user.getName()`
- `title`은 업로드 파일명, `categoryCode`는 현재 활성 폴더 코드 또는 루트의 `null`이다.
- 게시글 insert가 성공한 다음 기존 CommonFileService 경로로 실제 파일/메타데이터를 저장한다.
- 오류 발생 시 기존 트랜잭션과 soft-delete 보상 처리를 유지한다.
- 게시글 생성/수정의 다른 흐름, API 응답, 인증 및 권한 검증은 변경하지 않는다.

## 3. F1Tree 표현 및 동작

### 행 스키마

자료실 브라우저 행은 안정적인 고유 `rowKey`와 nullable `parentId`를 가진다. `parentId`는 F1Tree의 `parentKey`로 전달한다.

| rowType | rowKey | parentId | 표시 |
|---|---|---|---|
| section | `section:folders` | `null` | 폴더 루트 |
| folder | `folder:<itemCode>` | `section:folders` | 분류 폴더 |
| section | `section:files` | `null` | 파일 루트 |
| file | `file:<boardFileId>` | `section:files` | 파일 |

현재 폴더 위치에서는 기존 동작처럼 폴더 section 없이 파일 section과 해당 위치의 파일 행만 보인다.

### 화면 구성

- 자료실 루트에서 두 section은 기본 펼침으로 표시한다.
- F1Tree의 `treeColumn`은 기존 `이름` 컬럼이다. 분류/파일 아이콘, 비활성 폴더 상태, 반응형 파일 메타데이터, 다운로드/수정/삭제 버튼을 유지한다.
- 정렬·필터와 행 추가/삭제/복제 컨텍스트 동작은 비활성 상태로 유지한다. 2026-10-21 후속 요청으로 우클릭 메뉴의 루트 추가는 숨기고 엑셀 내보내기를 활성화한다. 세부 계약은 [20261021_002 컨텍스트 메뉴 상세사양서](./20261021_002_커뮤니티_자료실_F1Tree_컨텍스트메뉴_상세사양서.md)를 따른다.
- F1Tree를 감싸는 기존 grid aria label과 안정된 row key를 유지해 접근성과 행 식별을 보존한다.

### 상호작용

- 분류 이름을 선택하면 현재 `folderCode` 및 목록 검색 조건을 갱신하여 기존처럼 해당 폴더의 파일을 조회한다.
- section disclosure는 해당 자식 행만 펼치거나 접는다. 분류를 확장해 하위 파일을 표시하는 계층 동작은 만들지 않는다.
- 통합검색, 날짜/유형 상세검색, 비활성 폴더 열람 규칙, 권한별 파일 작업, 파일 업로드 버튼의 파일 선택 즉시 업로드는 기존 동작을 유지한다.

## 4. 검증 기준

### 백엔드

- 업로드 서비스 테스트는 `insertArchivePost` 인자 map에 인증 사용자 writer ID/name과 최종 수정자 ID/name, 업로드 파일명, 선택한 분류 코드가 모두 포함되는지 확인한다.
- DAO 반환 post ID를 받은 뒤 파일 저장 서비스가 같은 tenant/user/file로 호출되고 결과 파일이 반환되는 기존 흐름을 유지한다.
- archive service/controller/mapper 대상 테스트를 실행한다.

### 프론트엔드

- 자료실 그리드에 `폴더 접기` 및 `파일 접기` 트리 동작과 분류/파일 자식 행이 표시된다.
- 분류 선택은 `fetchArchiveFiles`에 현재 folderCode를 넣고, 자료실 루트 이동은 빈 folderCode를 요청한다.
- 즉시 업로드, 권한별 파일 행 작업, 날짜/유형 검색 테스트를 유지한다.
- 프론트 대상 테스트와 production build를 실행한다.
- 실브라우저 375px/768px/1280px에서 root section과 폴더 위치를 확인하고 전체 페이지 가로 overflow가 없어야 한다.

## 5. DB 및 범위

- DB MCP `list_tables`, `describe_table(tb_board_post)`, `describe_table(tb_common_file)`에서 메타데이터만 확인했다. 테넌트 데이터 행은 조회하지 않았다.
- 스키마 변경, SQL migration, API 경로/요청 필드 변경은 없다.
