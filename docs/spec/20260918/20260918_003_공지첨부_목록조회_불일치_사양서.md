## API 계약 (변경 없음, 유지 확인용)

- `GET /api/v1/groupware/boards/notice/posts?page=&size=&keyword=`
- `GET /api/v1/groupware/boards/notice/posts/{postId}`
- 응답 `result.resultList[].attachments[]` 필드는 기존과 동일하게 아래 구조를 유지한다:
  - `boardFileId`, `postId`, `fileName`, `filePath`, `objectKey`, `bucketName`, `storageProvider`, `fileSize`, `mimeType`, `contentType`, `deletedYn`, `uploadedBy`, `createdAt`, `updatedAt`
- `attachmentCount`는 정수형 필드로 유지하며, 값은 `attachments.length`와 항상 일치해야 한다.
- HTTP 상태 코드, 오류 메시지는 변경하지 않는다.

## 구현 사양

### 1. `NoticeBoardServiceImpl`에 매핑 헬퍼 추가

```java
private NoticeBoardFileVO toNoticeBoardFile(CommonFileVO source) {
    NoticeBoardFileVO target = new NoticeBoardFileVO();
    target.setBoardFileId(source.getFileId());
    target.setPostId(source.getOwnerId());
    target.setFileName(source.getFileName());
    target.setFilePath(source.getFilePath());
    target.setObjectKey(source.getObjectKey());
    target.setBucketName(source.getBucketName());
    target.setStorageProvider(source.getStorageProvider());
    target.setFileSize(source.getFileSize());
    target.setMimeType(source.getMimeType());
    target.setContentType(source.getContentType());
    target.setDeletedYn(source.getDeletedYn());
    target.setUploadedBy(source.getUploadedBy());
    target.setCreatedAt(source.getCreatedAt());
    target.setUpdatedAt(source.getUpdatedAt());
    return target;
}
```

- `uploadAttachment()`의 기존 수동 매핑 블록(현재 `NoticeBoardFileVO noticeBoardFile = new NoticeBoardFileVO(); ...` 구간)을 이 헬퍼 호출로 교체하여 중복을 제거한다. `checksumSha256`은 `CommonFileVO`에 필드가 없으므로 매핑하지 않는다(기존 `uploadAttachment`도 설정하지 않았으므로 동일).

### 2. `hydratePost()` 수정

기존:

```java
List<NoticeBoardFileVO> files = noticeBoardDAO.selectNoticeAttachmentList(fileParams);
post.setAttachments(files == null ? new ArrayList<>() : files);
```

변경 후:

```java
List<CommonFileVO> commonFiles = commonFileService.listFiles(tenantId, BOARD_TYPE_NOTICE, postId);
List<NoticeBoardFileVO> files = new ArrayList<>();
if (commonFiles != null) {
    for (CommonFileVO commonFile : commonFiles) {
        files.add(toNoticeBoardFile(commonFile));
    }
}
post.setAttachments(files);
post.setAttachmentCount(files.size());
```

- `fileParams`(postId/tenantId 맵) 생성 코드는 더 이상 필요 없으면 제거한다.
- `commonFileService.listFiles`가 이미 `tenantId`, `ownerType`, `ownerId` 검증(`CommonFileServiceImpl.listFiles`)을 수행하므로 별도 null 체크 외 추가 검증은 두지 않는다.

### 3. 변경하지 않는 부분

- `NoticeBoardDAO`, `NoticeBoard_SQL_postgresql.xml`은 수정하지 않는다. `selectNoticeAttachmentList` 등 메서드는 코드베이스에 남지만 더 이상 `hydratePost`에서 호출되지 않는다(사용처 없음, 삭제는 이번 범위에서 제외).
- `createPost()`의 `payload.getAttachmentIds()` 루프는 이번 작업 범위에서 다루지 않는다(별도 잠재 이슈로 결과 문서에 후속 검토 항목으로만 기록).

## 테스트 사양 (`NoticeBoardServiceImplTest`)

### `listPostsHydratesAttachmentsCommentsAndPaginationMetadata`

- `noticeBoardDAO.selectNoticeAttachmentList(...)` 모킹 제거.
- `CommonFileVO postFile = new CommonFileVO(); postFile.setFileId(201L); postFile.setOwnerId(7L);` 생성 후 `when(commonFileService.listFiles(1L, "NOTICE", 7L)).thenReturn(Arrays.asList(postFile));`, `when(commonFileService.listFiles(1L, "NOTICE", 8L)).thenReturn(Collections.emptyList());` 추가.
- 검증: `result.get(0).getAttachments()`의 첫 번째 요소 `getBoardFileId()`가 `201L`과 같음을 확인(`NoticeBoardFileVO` 매핑 결과이므로 `containsExactly(postFile)` 대신 필드 비교로 변경).
- 추가 검증: `result.get(0).getAttachmentCount()).isEqualTo(1)`, `result.get(1).getAttachmentCount()).isEqualTo(0)`.
- `verify(commonFileService).listFiles(1L, "NOTICE", 7L);`, `verify(commonFileService).listFiles(1L, "NOTICE", 8L);` 추가.

### `getPostHydratesAttachmentsForEachNoticeComment`

- `noticeBoardDAO.selectNoticeAttachmentList(...)` 모킹 제거.
- `when(commonFileService.listFiles(1L, "NOTICE", 7L)).thenReturn(Collections.emptyList());` 추가(게시글 자체 첨부는 이 테스트의 핵심 검증 대상이 아니므로 빈 값으로 설정).
- 기존 댓글 첨부 검증(`getComments().get(0).getAttachments()` 등)은 그대로 유지한다.

### 신규 테스트 (선택): `listPostsMapsCommonFileAttachmentsToNoticeBoardFileFields`

- `CommonFileVO`의 각 필드(`fileName`, `filePath`, `objectKey`, `bucketName`, `storageProvider`, `fileSize`, `mimeType`, `contentType`, `deletedYn`, `uploadedBy`, `createdAt`, `updatedAt`)를 채운 뒤 매핑된 `NoticeBoardFileVO`의 동일 필드가 일치하는지 검증한다.

## 영향받지 않는 범위 확인

- `deleteAttachment`, `downloadAttachment`, `deletePost`는 이미 `commonFileService.listFiles(tenantId, "NOTICE", postId)`를 사용 중이므로 변경하지 않는다.
- 댓글 첨부(`NOTICE_COMMENT`) 조회 로직은 변경하지 않는다.
