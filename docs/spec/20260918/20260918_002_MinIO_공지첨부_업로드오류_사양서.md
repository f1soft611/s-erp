# MinIO 공지첨부 업로드 오류 수정 상세 사양서

## 1. 배경

공지사항 첨부 업로드는 `NoticeBoardServiceImpl`에서 공통 파일 서비스로 위임되고, 공통 파일 서비스가 MinIO 저장 후 파일 메타데이터를 저장한다.

호출 흐름:

1. `NoticeBoardApiController.uploadAttachment`
2. `NoticeBoardServiceImpl.uploadAttachment`
3. `CommonFileServiceImpl.uploadFile`
4. `MinioStorageService.upload`

## 2. 오류 처리 사양

- MinIO 업로드 실패 시 HTTP 응답 메시지는 기존과 동일하게 `MinIO 업로드 중 오류가 발생했습니다.`를 유지한다.
- 서버 로그에는 bucket, objectKey, 원인 예외 stack trace를 기록한다.
- `ResponseStatusException`은 원인 예외를 cause로 포함해야 한다.

## 3. 버킷 정책 사양

| 항목         | 값                                                  |
| ------------ | --------------------------------------------------- |
| 설정명       | `storage.autoCreateBucket`                          |
| 환경변수     | `STORAGE_AUTO_CREATE_BUCKET`                        |
| 기본값       | `false`                                             |
| `false` 동작 | `bucketExists`/`makeBucket` 없이 `putObject` 호출   |
| `true` 동작  | 기존처럼 업로드 전 버킷 존재 확인 및 미존재 시 생성 |

운영 기본 계약은 사전 생성된 `document-attachments` 버킷에 애플리케이션이 객체를 업로드하는 방식이다.

공통 첨부 업로드에서 사용하는 bucket은 `storage.bucket` 또는 `STORAGE_BUCKET` 값으로 결정한다. 설정값이 비어 있을 때만 `document-attachments` fallback을 사용한다.

## 4. 호환성

- API 경로와 응답 구조는 변경하지 않는다.
- 공지사항 첨부 메타데이터 저장 구조는 변경하지 않는다.
- DB 스키마 변경은 없다.
- 버킷 자동 생성이 필요했던 로컬 환경은 `STORAGE_AUTO_CREATE_BUCKET=true`로 기존 동작을 복원할 수 있다.
- `STORAGE_BUCKET` 변경 시 공통 첨부 업로드의 MinIO bucket, DB `bucketName`, `filePath`가 같은 bucket 값으로 기록되어야 한다.

## 5. MinIO Client 버전 사양

- Maven에는 `io.minio:minio` 의존성을 한 번만 선언한다.
- 지원 버전은 `8.5.11`로 고정한다.
- 오래된 중복 선언이 지원 버전을 덮어쓰지 않아야 한다.
- `SignatureDoesNotMatch`가 발생하면 먼저 실제 런타임 `User-Agent`의 `minio-java/*` 버전과 Maven dependency tree를 비교한다.

## 6. 검증 기준

- `CommonFileServiceTest`가 MinIO 실패 cause 보존을 검증한다.
- `CommonFileServiceTest`가 공통 첨부 업로드 bucket이 `storage.bucket` 설정을 따르는지 검증한다.
- `MinioStorageServiceTest`가 기본 업로드에서 버킷 관리 호출을 하지 않음을 검증한다.
- `MinioStorageConfigTest`가 dev/prod 속성 계약과 MinIO client 단일 버전 선언을 검증한다.
- `mvn dependency:tree "-Dincludes=io.minio:minio"` 결과가 `io.minio:minio:jar:8.5.11:compile`이어야 한다.
- 원격 MinIO 헬스 endpoint는 HTTP 200이어야 한다.

## 7. 운영 확인 사항

- 운영 MinIO에 `document-attachments` 버킷이 존재해야 한다.
- 애플리케이션 계정에는 대상 버킷의 객체 업로드 권한이 필요하다.
- 서버 재배포 후 같은 업로드가 `SignatureDoesNotMatch`로 계속 실패하면 새 로그의 root cause를 기준으로 실제 주입된 access key/secret key, endpoint, region, bucket policy를 확인한다.
