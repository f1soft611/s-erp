## UI/동작 사양

### 1. 붙여넣기 이벤트 처리

- 사용자가 공지사항 에디터 영역에 표 형식 데이터를 붙여넣을 때 `paste` 이벤트가 발생한다.
- 이벤트에서 `clipboardData.items` 또는 `clipboardData.getData('text/html')`를 우선 확인한다.
- 표 형식 HTML이 있으면 표 구조를 보존한 상태로 에디터에 삽입한다.
- HTML이 없거나 표가 아닌 일반 텍스트면 `text/plain` 기반으로 안전하게 삽입한다.

### 2. Excel/표 형식 데이터 정규화

- 복사된 표는 셀값이 누락되지 않도록 각 행과 열을 순회한다.
- 빈 셀은 적절히 보존하고, 줄바꿈·공백은 의미를 유지하면서 정규화한다.
- 표가 여러 행/열로 구성되어 있으면 HTML table 구조로 변환해 자연스럽게 보이게 한다.
- 표 형식이 아니라 단순 문자열이라면 paragraph/line break 조합으로 처리한다.

### 3. 안전한 HTML 변환

- 외부 HTML을 에디터에 직접 삽입하지 않고, 허용 가능한 노드만 유지한다.
- `script`, `style`, `iframe`, `svg`, `object`, `embed`와 같은 비정상 요소는 제거한다.
- `table` 내부의 `td`/`th` 값은 텍스트 형태로 정리하고, 불필요한 inline style은 제거한다.
- 붙여넣기 후 본문이 비어 버리거나 과도한 빈 줄이 생기지 않도록 boundary를 정리한다.

### 4. fallback 처리

- 표 HTML 파싱이 실패하거나 데이터가 비정상적이면 `text/plain` fallback을 사용한다.
- 붙여넣기 실패 시에도 사용자가 마지막으로 복사한 내용을 유지할 수 있어야 한다.
- 일반 텍스트 붙여넣기와 표 복붙이 서로 간섭하지 않아야 한다.

### 5. 저장 시 직렬화

- 에디터에 붙여넣기된 내용은 `editor.getHTML()` 또는 JSON 직렬화 시에도 정상적으로 저장된다.
- 저장된 본문에 표 구조가 깨지지 않고, 기존 텍스트 본문과 같은 방식으로 서버 전송된다.

## 테스트 사양

### 케이스 1: Excel 표 복붙

- 표 형태의 Excel/Sheets 데이터가 클립보드에 있고, 에디터에 붙여넣기한다.
- 행/열 값이 보존되고 누락되지 않는지 확인한다.
- 붙여넣기 직후 본문이 table 구조를 유지하거나 안전한 paragraph 기반 구조로 표시된다.

### 케이스 2: 일반 텍스트 복붙

- 텍스트만 복사한 상태에서 붙여넣기하면 기존 에디터 입력 방식과 동일하게 동작한다.
- 불필요한 HTML 구조가 삽입되지 않는다.

### 케이스 3: 비정상 HTML fallback

- 복사된 HTML이 표 구조가 아니거나 비정상적인 경우, 안전하게 처리되며 에디터가 중단되지 않는다.
