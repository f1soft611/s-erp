# 20260918_007 공지사항 본문 이미지 즉시 업로드 상세 사양서

## 1. 화면 동작

### 작성/수정 에디터

- 대상: `NoticeComposerDialog`의 Tiptap 본문 영역
- 입력 우선순위: 이미지 clipboard item → HTML/표 정규화 → plain text fallback
- 이미지 붙여넣기 위치: 현재 ProseMirror selection에 block image 노드를 삽입한다.
- 업로드 중: 이미지 노드의 `data-upload-state="uploading"`와 대체 문구를 표시한다.
- 성공: `src`, `data-file-id`, `data-upload-token`, `width`를 가진 이미지 노드로 교체한다.
- 실패: 해당 노드만 제거하고 알림을 표시한다. 기존 텍스트와 다른 이미지 노드는 보존한다.
- 같은 위치에 여러 이미지를 붙여넣으면 clipboard 순서를 유지한다.

### 크기 규칙

- 기본 width는 원본 폭과 에디터 content width 중 작은 값으로 계산한다.
- width는 양의 pixel 값 또는 percentage 값만 허용한다.
- 비율을 유지하며 height는 자동 계산한다.
- 선택된 이미지에 width 조절 핸들 또는 숫자 입력을 제공한다.
- 저장 HTML/JSON에 width를 기록하고, 재조회 시 동일 값을 복원한다.

### 피드

- 본문 HTML의 이미지가 있으면 접힌 상태에서도 첨부파일 영역 위에 첫 이미지 또는 이미지 스트립을 표시한다.
- 접힌 미리보기 이미지는 본문 HTML과 같은 고정 인증 API URL을 사용하되, 원문 흐름은 표시하지 않는다.
- `더보기` 선택 시 미리보기 스트립은 숨기고 원래 본문 HTML을 전체 표시한다.
- 원문 표시에는 이미지와 텍스트의 저장 순서를 유지한다.
- 일반 첨부파일 영역에는 `file_usage_type=ATTACHMENT`만 표시한다.
- 이미지 로드 실패 시 `이미지를 불러올 수 없습니다.` 대체 텍스트를 표시한다.

## 2. 프론트엔드 API 계약

### 임시 이미지 업로드

`POST /api/v1/groupware/boards/notice/embedded-images/temp`

- Request: `multipart/form-data`, field `file`
- 성공 `201` item:
  - `uploadToken: string`
  - `fileId: string | number` (임시 참조 ID)
  - `fileName: string`
  - `fileSize: number`
  - `mimeType: string`
  - `objectKey: string`
  - `bucketName: string`
  - `imageUrl: string`
- 실패:
  - `400`: 빈 파일, 이미지 아님, 허용하지 않은 MIME/signature, 크기 초과
  - `401`: 인증 실패
  - `413`: 최대 크기 초과
  - `500`: 저장 실패

### 게시글 저장 계약 확장

기존 create/update request에 `embeddedImages` 배열을 추가한다.

```json
{
  "embeddedImages": [
    {
      "uploadToken": "...",
      "fileId": "...",
      "objectKey": "...",
      "imageUrl": "...",
      "fileName": "pasted-image.png",
      "fileSize": 12345,
      "mimeType": "image/png",
      "width": "640px"
    }
  ]
}
```

서버는 요청 사용자/테넌트가 업로드한 token만 허용하고, 본문 HTML/JSON에 실제 사용된 이미지 참조만 `tb_board_file.file_usage_type='EMBEDDED'`로 등록한다. 사용되지 않은 token은 저장 성공 후 삭제 대상으로 처리한다.

## 3. 백엔드 처리

- 임시 업로드는 DB 메타 행 없이 MinIO의 `tenant/{tenantId}/notice-temp/{uploadToken}/...` prefix에 저장한다.
- 임시 업로드 응답의 `imageUrl`은 편집 중 미리보기를 위한 임시 URL이다. 게시글 저장 후 조회 응답은 만료되는 URL을 사용하지 않는다.
- 게시글 조회 시 `data-object-key`와 `EMBEDDED` 파일 메타데이터를 연결해 `/api/v1/groupware/boards/notice/posts/{postId}/embedded-images?objectKey=...` 고정 경로를 생성한다.
- 고정 이미지 API는 인증 사용자의 테넌트와 공지 소유 파일을 확인한 뒤 MinIO 객체를 서버에서 스트리밍한다.
- 게시글 저장 트랜잭션에서 token 소유자/테넌트, object key prefix, MIME, 만료 시간을 검증한다.
- 저장 성공 후 `tb_board_file`에 `EMBEDDED` 메타데이터를 생성하고 게시글에 귀속한다.
- 기존 일반 첨부는 기본값 `ATTACHMENT`를 사용한다.
- 게시글 삭제 시 두 용도의 파일을 모두 soft delete하고 MinIO 객체를 삭제한다.
- 임시 객체는 TTL 기반 정리 작업으로 삭제한다. 정리 작업은 이미 게시글에 귀속된 object key를 제외한다.

## 4. 보안 및 예외

- 허용 형식: 프로젝트 정책에 따라 `image/png`, `image/jpeg`, `image/gif`, `image/webp`로 제한한다.
- MIME만 신뢰하지 않고 파일 signature를 확인한다.
- 최대 파일 크기는 설정값으로 주입하고 기본값은 계획 구현 시 기존 업로드 제한과 일치시킨다.
- 본문 이미지 API는 인증이 필요하고, 요청 공지의 `file_usage_type='EMBEDDED'` 및 `object_key` 소유권을 함께 확인한다.
- 본문 HTML sanitization은 허용된 `img[src|alt|width|data-file-id]`만 통과시키고 `javascript:`, `data:`, 임의 외부 URL은 제거한다.
- 업로드 성공 후 게시글 저장 실패 시 임시 객체를 보상 삭제한다.
- 저장 성공 후 일부 이미지 귀속 실패 시 게시글 저장을 실패 처리하고 등록된 메타/객체를 보상 정리한다.

## 5. 테스트 사양

- 이미지가 텍스트 앞/중간/뒤에 정확히 삽입된다.
- 여러 이미지의 순서와 커서 위치가 보존된다.
- 업로드 중/성공/실패 상태가 정상적으로 전환된다.
- width가 HTML/JSON에 저장되고 수정 재조회 후 유지된다.
- 접힌 피드에서 이미지 미리보기가 첨부파일 위에 표시되고, 펼치면 원문 위치로 복귀한다.
- 일반 첨부 이미지가 본문 이미지로 잘못 분류되지 않는다.
- 악성 URL, 허용하지 않은 MIME, 과대 파일이 거절된다.
- 기존 Excel/텍스트 붙여넣기와 이미지 없는 게시글 회귀가 없다.
- 375px, 768px, 1280px에서 이미지가 부모 폭을 넘지 않는다.
