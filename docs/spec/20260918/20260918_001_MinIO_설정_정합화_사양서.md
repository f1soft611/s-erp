# 20260918_001 MinIO 설정 정합화 상세 사양서

## 1. 설정 계약

| 속성                           | 환경변수           | 기본값 계약                     |
| ------------------------------ | ------------------ | ------------------------------- |
| `storage.provider`             | `STORAGE_PROVIDER` | `minio`                         |
| `storage.bucket`               | `STORAGE_BUCKET`   | `document-attachments`          |
| `storage.endpoint`             | `STORAGE_ENDPOINT` | 제공된 원격 MinIO HTTP endpoint |
| `storage.accessKey`            | `MINIO_ACCESS_KEY` | 제공된 access key fallback      |
| `storage.secretKey`            | `MINIO_SECRET_KEY` | 제공된 secret key fallback      |
| `storage.region`               | 해당 없음          | `us-east-1`                     |
| `storage.presignExpirySeconds` | 해당 없음          | `600`                           |

자격 증명 원문은 문서에 중복 기록하지 않으며 실제 properties와 배포 환경변수에서 관리한다.

## 2. 적용 범위

- `application-dev.properties`와 `application-prod.properties`는 동일한 7개 속성 계약을 사용한다.
- `MinioStorageConfig`는 프로필 속성이 없는 경우에도 endpoint, access key, secret key, region에 동일한 중첩 fallback을 사용한다.
- bucket은 `MinioStorageService`의 기존 `document-attachments` fallback을 유지한다.
- presign 만료시간은 현재 서비스에서 직접 소비하지 않지만 프로필 설정 계약을 유지한다.

## 3. 우선순위

provider, bucket, endpoint, access key, secret key는 Spring property 해석 순서를 따른다. 외부 환경변수 값이 있으면 이를 사용하고, 없으면 properties 또는 `@Value`에 선언된 fallback을 사용한다. region과 presign 만료시간은 프로필의 고정값을 사용한다.

## 4. 오류 처리

- endpoint에 연결할 수 없거나 인증이 실패하면 기존 MinIO SDK 예외 처리 흐름을 유지한다.
- 이번 변경에서 재시도, timeout, 버킷 자동 생성 정책은 변경하지 않는다.

## 5. 검증 기준

- dev/prod 파일에 7개 속성이 정확히 존재한다.
- Java 설정의 endpoint, access key, secret key, region fallback이 프로필 계약과 일치한다.
- `MinioStorageConfigTest`가 위 계약을 검증한다.
- 실제 원격 MinIO 연결과 버킷 권한 검증은 네트워크를 수반하므로 별도 운영 확인 항목으로 기록한다.

## 6. 영향 범위

- DB 스키마 변경 없음
- API 계약 변경 없음
- 저장 object key 및 bucket 생성 로직 변경 없음
