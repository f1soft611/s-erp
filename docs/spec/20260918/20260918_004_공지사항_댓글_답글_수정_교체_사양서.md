## UI 사양

### 1. 수정 진입

- 사용자가 댓글 또는 답글의 더보기 메뉴에서 "수정"을 선택하면 해당 항목의 수정 입력 창이 열린다.
- 수정 입력 창은 기존의 이름/날짜/내용/답글 영역을 대체한다.
- 원래의 댓글/답글 영역은 삭제되거나 하단에 중복 렌더링되지 않는다.

### 2. 수정 상태 렌더링

- 수정 상태에서는 다음 요소가 표시된다.
  - 작성자 이름
  - 작성 시간
  - Tiptap 편집기 (기존 본문 내용이 초기값으로 채워짐)
  - 파일 첨부 목록 (기존 첨부 유지)
  - 수정/취소 버튼
- 수정 상태에서는 기존의 "답글" 버튼과 원본 본문 텍스트를 함께 렌더링하지 않는다.

### 3. 취소 동작

- 사용자가 "취소"를 누르면 수정 입력 상태가 종료되고, 원래 댓글/답글 본문으로 돌아간다.
- 수정 중에 이미 작성한 내용은 유지하지 않는다. (기존 로직과 동일하게 취소 시 내용은 원래 상태로 복원)

### 4. 저장 동작

- 수정 완료 시 기존 `onEditComment` 콜백과 파일 업로드 로직을 그대로 사용한다.
- 저장 성공 후 수정 상태가 종료되고 정상적인 댓글 보기 화면으로 복귀한다.

## 테스트 사양

### 케이스 1: 댓글 수정 입력이 기존 본문 아래가 아니라 교체된다

- 댓글이 렌더링된 상태에서 `댓글 메뉴 작성자 > 수정`을 선택한다.
- 기존 텍스트 본문이 숨겨지고, `댓글 수정 입력` 영역이 표시되는지 확인한다.
- `답글` 버튼이 보이지 않는지 함께 검증한다.

### 케이스 2: 취소 시 원래 댓글 상태가 복구된다

- 수정 상태에서 취소 버튼을 누르면 원래 본문이 다시 표시된다.
