# 20260918_009 공지사항 구분명·강조색상·모달여백 상세 사양서

## 1. 데이터 표시 계약

### 공지 피드

- API 원본: `noticeGubunCode`
- 화면 표시: `NOTICE_GUBUN` 상세코드의 `itemNm`
- 변환 구조: `Map<itemCode, itemNm>` 또는 동등한 명칭 조회 구조
- 매칭 실패: `noticeGubunCode`가 있으면 코드값, 없으면 `공지`를 표시
- 화면 구분 라벨은 `isNotice`와 무관하게 실제 명칭을 표시한다.
- `isNotice === 'Y'`는 별도 중요 공지 강조 상태로 사용한다.

### 목록 필터

- 첫 항목은 `전체`이며 선택값은 빈 문자열이다.
- 두 번째 항목은 `중요 공지`이며 `isNotice = 'Y'`로 조회한다.
- 이후 `useAt === 'Y'`인 `NOTICE_GUBUN` 상세코드를 표시한다.
- 일반 구분 필터 선택 시 `noticeGubunCode`, 중요 공지 선택 시 `isNotice=Y` query를 사용한다.

### 작성/수정 모달

- 구분 선택지는 `useAt === 'Y'`인 상세코드만 표시한다.
- `전체` 항목은 표시하지 않는다.
- 수정 시 기존 게시글의 `noticeGubunCode`를 초기값으로 사용한다.
- `중요 공지` 체크박스를 구분 선택과 별도 필드로 표시한다.
- 체크됨은 `isNotice='Y'`, 해제는 `isNotice='N'`으로 저장한다.
- 수정 시 기존 `isNotice`가 `Y`이면 체크 상태로 초기화한다.
- 구분 코드가 없으면 첫 유효 항목을 기본값으로 사용하거나 기존 필수 검증을 표시한다. 기존 동작과 충돌할 경우 빈 값 검증을 우선한다.

## 2. 색상 규칙

- `isNotice === 'Y'`: 기존 중요 공지용 강조색상 적용
- `isNotice === 'N'`: 일반 텍스트 색상 및 일반 배경 사용
- 구분명 텍스트는 강조 여부와 무관하게 항상 실제 명칭을 표시한다.
- 중요 공지가 아닌 게시글에 경고/금색 스타일을 재사용하지 않는다.

## 3. 모달 레이아웃

- `DialogContent`의 상·하 padding은 동일한 spacing 기준으로 설정한다.
- 구분 선택, 제목 입력, 본문 에디터의 수직 간격은 동일한 `gap` 또는 동일 margin 값을 사용한다.
- 제목 위에 구분 선택을 배치한다.
- 375px 화면에서 모달은 내부 스크롤을 사용하고 필드가 화면 밖으로 밀려나지 않는다.
- 768px 및 1280px에서는 기존 최대 폭과 높이를 유지한다.

## 4. API 및 권한

- 기존 API endpoint와 HTTP method는 유지한다.
- 목록 API에 선택 query `isNotice=Y`를 추가하고, 저장 payload의 기존 `isNotice` 필드를 체크박스와 연결한다.
- 인증, 테넌트, 작성 권한, 구분코드 저장 검증은 선행 작업 계약을 그대로 사용한다.
- 본 작업은 프론트 표시·레이아웃만 변경한다.

## 5. 테스트 기준

- 피드가 `NOTICE_GUBUN.itemNm`을 렌더링한다.
- `isNotice=Y`인 피드만 강조 색상 조건을 만족한다.
- 다른 구분은 일반 색상 조건을 만족한다.
- 작성/수정 모달에서 중요 공지 체크 상태가 `isNotice`로 저장된다.
- 필터 맨 앞에 중요 공지가 표시되고 `isNotice=Y`로 동작한다.
- 작성 모달에 `전체`가 없고 상세코드만 있다.
- 수정 모달이 기존 구분코드를 초기값으로 복원한다.
- 375px, 768px, 1280px에서 구분·제목·본문이 겹치지 않는다.
