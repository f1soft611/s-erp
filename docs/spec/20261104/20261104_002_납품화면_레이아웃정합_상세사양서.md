# 납품 화면 레이아웃 정합 상세사양서

## 원인

최초 납품 화면이 수주 컴포넌트를 구조적으로 따르지 않고 별도 액션바·3열 입력·외부 상세도구·단순 합계/검색·직접 편집모달로 작성되었다. 단순 overflow 검증만으로 화면 패턴 정합을 확인하지 못했다.

## 등록 대응

| 수주등록 기준 | 납품등록 기대 |
|---|---|
| PageHeader actionGroups 신규/저장/삭제 | 같은 위치/아이콘/권한 그룹. 저장 후 재조회 실패 복구만 조회 액션 허용 |
| 내용 padding xs1.5/sm2/lg3, gap2 | 동일 |
| 제목 있는 기본정보 Paper, lg4/sm2/xs1열 | 납품 기본정보, 번호/일자/거래처/구분 순서 |
| 추가 정보 및 전체폭 multiline 비고 | 연결 수주 선택/장소/방법, 전체폭 비고 |
| 상세 Paper 내부 제목/설명 좌측, 도구 우측 | 동일. 직납품 상세 행 추가/품목 선택; 수주 선택은 기본정보에 유지 |
| 상세 그리드 px1, 최소높이260 | 동일 |
| 공급가/부가세/총합계 3개 bordered 카드 | 동일, 모바일 1열 |
| 선택 행 삭제 버튼 없음, 우클릭 삭제 | 동일. 중복 수주상세를 만들지 않도록 수주납품 행복사는 허용하지 않음 |

납품에 없는 수주상태/견적/납기 필드는 가짜로 추가하지 않는다. 입력/저장/권한/수량 계약은 그대로 유지한다.

## 현황 대응

- 수주현황의 PageHeader→PageSearchArea→PageMessageArea→SearchResultMessage→목록 순서와 동일 여백.
- 빠른검색 placeholder/aria-label/Enter/검색어 초기화, 높이40 및 검색버튼과 붙는 입력 모양 동일.
- F1-Grid 좌측 No 열, 헤더 데이터 병합, 문서 링크 스타일, row selection 및 context 설정 동일.
- 번호 클릭 시 같은 `PageAreaOverlay`+`PostDetailPanel` 상세패널을 연다. 등록자/구분, 거래처·금액 요약, 기본정보 그룹, 품목 테이블을 표시한다.
- 더보기의 자세히보기는 읽기 전용 등록 모달, 수정은 편집 모달을 연다. 현황 READ 사용자는 상세/보기 가능하고 수정/삭제는 등록 메뉴 권한을 유지한다.
- 편집 모달은 수주처럼 하단 좌측 삭제, 하단 우측 저장/취소. 읽기 전용은 하단 닫기. 본문에 별도 액션바를 중복 표시하지 않는다.
- 저장/삭제 후 패널 및 목록을 갱신하고, 기존 문서가 사라지거나 입력이 초기화되는 불필요한 전체 로딩 전환을 피한다.
- 375/768/1280px에서 기준 수주와 납품의 버튼·카드·검색/목록 시작 위치를 비교하고 스크린샷을 기록한다.

## 회귀 검증

신규/저장이 입력 영역 밖 헤더에 존재, 기본정보와 상세 구획/도구/합계 카드, 검색 Enter/초기화, 번호→패널→보기/수정 모달, 모달 footer 액션, 읽기 권한 분리 및 기존 납품 테스트 유지.
