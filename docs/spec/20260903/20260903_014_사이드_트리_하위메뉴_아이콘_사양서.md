## 1. UI 구성

### 1.1 Dashboard 사이드 트리

- `DashboardMenuTree.tsx`에서 각 메뉴 노드를 렌더링할 때, 자식 메뉴가 존재하는 노드에 대해 추가 하위 메뉴 마커를 표시한다.
- 마커는 문맥 상 `ㄴ` 형태의 계열 기호를 사용하여, 자식 노드가 한 단계 더 아래에 있음을 시각적으로 표현한다.
- 루트 메뉴와 자식 메뉴는 동일한 텍스트 스타일을 유지하되, 하위 메뉴는 추가로 들여쓰기와 마커를 통해 구분한다.
- 부모 메뉴의 expand/collapse 아이콘과 하위 메뉴 마커는 서로 충돌하지 않아야 한다.

### 1.2 F1-Tree

- `F1Tree.tsx`의 `cellAdornment` 렌더링에서 각 행의 `meta.depth`를 기준으로 하위 메뉴 표시 마커를 추가한다.
- `meta.depth > 0` 인 경우, 자식 행에 `ㄴ` 계열 표시 요소를 삽입하고 좌측 여백을 적절히 유지한다.
- 마커는 트리 체크박스 및 expand/collapse 아이콘의 앞쪽 또는 내부에 배치되며, 기존 구조를 해치지 않아야 한다.
- 자식이 없는 행은 마커를 표시하지 않고, 기존 고정 폭 스페이서 레이아웃을 유지한다.

## 2. 동작 규칙

- 기존 트리의 expand/collapse 동작은 유지되어야 한다.
- 선택된 메뉴 강조, hover 상태, 트리 펼침 상태는 기존 스타일을 유지한다.
- `defaultExpandedItems`, `selectedMenuId`, `expandedItemIds`의 상태 연동은 변경하지 않는다.
- F1Tree 내부 `meta.hasChildren`, `treeCheckbox`, `getTreeCheckboxState` 계산 로직은 그대로 유지한다.

## 3. 레이아웃 규칙

- 좌측 들여쓰기와 마커의 폭은 상하 정렬을 유지하면서 균형을 맞춘다.
- 화면이 좁아져도 텍스트가 줄바꿈되거나 겹치지 않도록 최소 가로 공간을 확보한다.
- 색상/폰트/업무자 중요도는 기존 트리 스타일과 동일하게 유지한다.

## 4. 예외 처리

- 루트 노드에는 하위메뉴 마커를 표시하지 않는다.
- `children` 없는 노드에는 자리 확보용 빈 공간만 유지한다.
- `TreeItem` 또는 F1Grid가 아직 렌더링되지 않은 초기 상태에서도 안전하게 본문을 표시한다.

## 5. 검증 항목

- Dashboard 사이드 트리에서 자식 노드가 하위 메뉴 마커로 구분된다.
- F1-Tree에서도 동일한 하위 메뉴 마커가 표시된다.
- 기존 expand/collapse, selection, checkbox 동작이 정상 유지된다.
- 레이아웃이 자연스럽게 정렬되고, 시각적으로 과도하게 넓어지거나 겹치지 않는다.
- UI smoke test 또는 브라우저 검증을 통해 회귀가 없음을 확인한다.
