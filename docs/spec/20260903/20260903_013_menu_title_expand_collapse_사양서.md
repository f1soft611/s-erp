## 1. UI 구성

### 1.1 타이틀 영역

- 메뉴 관리 화면의 상단 제목 영역은 `메뉴 관리` 텍스트를 좌측에 배치한다.
- 제목 우측에는 전체 펼치기/접기 아이콘 버튼 2개를 같은 행에 배치한다.
- 버튼 그룹의 정렬은 우측 정렬을 기본으로 한다.
- 줄바꿈이 발생하지 않도록 `flex`, `gap`, `alignItems`, `justifyContent` 조합을 사용해 안정적으로 정렬한다.

### 1.2 버튼 동작

- `전체 펼치기` 버튼 클릭 시 `treeRef.current?.expandAll()` 실행
- `전체 접기` 버튼 클릭 시 `treeRef.current?.collapseAll()` 실행
- `selectedModule`가 없거나 `saving` 상태 true이면 버튼은 disabled 상태로 유지한다.
- 버튼 `aria-label`은 기존 값을 유지하며, 테스트 시 접근 가능한 이름으로 확인 가능해야 한다.

## 2. 레이아웃 규칙

- 타이틀과 버튼이 같은 행에 위치해야 한다.
- 하단 별도 툴바 영역에는 해당 버튼을 배치하지 않는다.
- 기존 메뉴 그리드 제어 툴바는 유지하되, 전체 펼치기/접기 버튼은 타이틀 라인에 배치한다.
- 좁은 화면에서도 헤더와 아이콘이 겹치지 않도록 반응형 정렬을 유지한다.

## 3. 예외/에지 케이스

- `selectedModule`이 없으면 버튼은 비활성화되며, 클릭 이벤트는 발생하지 않는다.
- 저장 중(`saving` true)에는 버튼이 비활성화되어 중복 생성/변경 흐름을 막는다.
- `treeRef`가 아직 준비되지 않은 초기 렌더 시에도 앱이 정상적으로 렌더링되어야 한다.

## 4. 검증 항목

- 타이틀 라인 우측에 전체 펼치기/접기 버튼이 표시된다.
- 두 버튼의 `aria-label`이 사용 가능한 상태로 노출된다.
- 버튼 클릭 동작이 동일한 `expandAll` / `collapseAll` 로직으로 연결된다.
- 기존 화면의 레이아웃과 간격이 자연스럽게 유지된다.
- 테스트 또는 UI 검증을 통해 회귀가 없음을 확인한다.
