# F1-Grid 셀 dirty 표시 기능 사양서

## 1. 문제 정의

F1-Grid는 수정 여부를 추적하고 있으나, 사용자가 셀 수정 상태를 즉시 인식하기 어려운 경우가 있다. 셀 수정이 발생해도 시각적 표식이 충분치 않아, 실제 값과 변경 여부를 구분하기 어렵다.

## 2. 요구사항

### 2.1 기능 요구사항

- dirty 상태가 있는 셀에는 작은 시각적 표시를 노출한다.
- 표시 방식은 셀의 좌상단 또는 우상단 모서리가 가장 자연스럽고, 다른 셀 정보와 간섭이 적어야 한다.
- 수정된 셀의 마크는 편집 중인 상태와 함께 나타날 때는 숨기거나 우선순위를 조정한다.
- dirty 표시가 선택된 셀, 범위 선택, 드래그 보더와 겹치지 않아야 한다.
- 재렌더링 이후에도 dirty 상태가 유지되어야 한다.

### 2.2 비기능 요구사항

- 기존 F1-Grid의 선택/편집/drag 동작을 유지한다.
- 공통 셀 렌더링 로직에서만 범위를 제한한다.
- 관련 테스트를 통해 회귀 방지

## 3. 화면/동작 정의

1. 특정 셀의 값이 변경되면 해당 셀의 dirty flag가 true가 된다.
2. `GridCell`은 해당 셀을 렌더링할 때 작은 빨간 표시를 추가한다.
3. 표시 위치는 셀 내부 상단 좌측에 두되, 편집 중이거나 선택된 상태에서는 표시 우선순위를 조정한다.
4. 표시 마크는 배경과 대비가 충분하고, 텍스트 읽기와 선택 동작을 방해하지 않아야 한다.
5. dirty 표시가 있는 셀을 다시 원래 값으로 되돌리면 표시가 제거된다.

## 4. 컴포넌트별 상세 설계

### 4.1 `GridCell`

- `dirtyCell` prop을 기준으로 작은 marker UI를 렌더링한다.
- `editing` 상태일 때는 marker를 숨기거나 조정해 편집 UI와 충돌하지 않게 한다.
- 좌측 상단 위치를 기준으로 `position: absolute`와 `zIndex` 조정이 필요하다.
- 화면에서 인지 가능한 크기와 색상을 유지한다.

### 4.2 `GridRow` / `GridBody`

- dirtyMap 계산은 기존 로직 유지
- `GridCell`로 전달되는 `dirtyCell` 값은 그대로 유지
- 실제 마크 표시가 필요한 조건은 `dirtyCell && !editing`으로 제어한다.

### 4.3 `F1Grid`

- dirtyCellMap 생성 로직은 기존 값 유지
- 실제 필요 시 셀 렌더링과 결합되는 조건을 정리한다.

## 5. 예외 처리

- 셀 편집 중에는 dirty 마크 표시를 비활성화해 입력 필드와 겹치지 않게 한다.
- 선택 상태가 활성화된 셀에 대해서도 마크 표시가 CSS 레이어에서 가려지지 않도록 조정한다.
- row merge/column pinning 환경에서도 컨테이너 오버플로우와 sticky 속성에 의해 마크가 잘리거나 사라지지 않도록 한다.

## 6. 검증 기준

- dirty 상태가 true인 셀에 시각적 마크가 보인다.
- 편집 중인 셀에는 마크가 표시되지 않는다.
- 기존 선택/드래그 동작이 유지된다.
- 테스트 대상: `frontend/tests/f1-grid.test.tsx`
