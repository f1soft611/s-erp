# F1-Grid rowMerge 핀 고정 컬럼 적용 사양서

## 1. 문제 정의

F1-Grid에서 `mergeRows`가 활성화된 컬럼은 연속된 동일 값의 셀을 하나의 시각적 영역으로 병합한다. 그러나 핀 고정 컬럼(`pinned: 'left' | 'right'`)에서는 병합 상태가 보이지 않거나 미묘한 렌더링 불일치가 발생한다.

## 2. 요구사항

### 2.1 기능 요구사항

- `mergeRows`는 핀 고정 컬럼에서도 연속 동일 값 기준으로 병합한다.
- merge 시작 셀과 뒤쪽 셀 간 경계와 배경이 일관되게 표현된다.
- 고정 컬럼과 일반 컬럼이 혼재해도 병합 판단 기준이 동일하다.
- 병합 상태에서 편집/선택 상태는 기존 동작과 충돌하지 않는다.

### 2.2 비기능 요구사항

- 기존 일반 컬럼 mergeRows 동작을 유지한다.
- 다른 컬럼 동작 및 selection logic에 영향을 최소화한다.
- 테스트를 통해 회귀를 막는다.

## 3. 화면/동작 정의

1. 데이터의 특정 컬럼 값이 연속되어 같으면 첫 셀만 표시하고 나머지 셀은 병합 처리한다.
2. 핀 고정 컬럼에서도 태그/배경/테두리 및 span 계산이 동일하게 적용된다.
3. 병합된 셀을 더블클릭해 수정 시, 실제 병합 그룹에서 해당 행만 분리되도록 동작한다.
4. 핀 고정 컬럼의 sticky offset은 병합 span 계산과 충돌하지 않아야 한다.

## 4. 컴포넌트별 상세 설계

### 4.1 `GridBody`

- `getMerged`와 `getMergeEditing` 로직이 pinned 컬럼에서도 정상 동작해야 한다.
- 각 컬럼의 `mergeInfoByColumn` 값이 column index에 맞게 전달되어야 한다.

### 4.2 `GridRow`

- `merged` 값과 `mergeInfo` 값을 `GridCell`에 그대로 전달한다.
- sticky pinned 컬럼이 있는 경우에도 `gridColumn`/`gridRow` 및 스타일 계산이 유지된다.

### 4.3 `GridCell`

- `merged` 상태일 때는 빈 셀 영역/배경/테두리 스타일을 병합 기준대로 처리한다.
- 병합된 셀은 실제 데이터 영역의 첫 셀만 보이도록 한다.

## 5. 예외 처리

- 현재 행이 merge 시작 행이 아니면 `merged` 플래그를 true로 하고, 편집 중인 셀은 제외한다.
- 동일 컬럼의 병합 그룹 내부에서는 편집이 가능한 행만 분리 처리한다.
- 고정 컬럼 offset 계산은 기존 sticky 로직을 유지하며, 병합 span은 수직 방향만 계산한다.

## 6. 검증 기준

- 핀 고정 컬럼을 포함한 시나리오에서 `mergeRows`가 병합된다.
- row merge된 셀의 첫 셀만 `aria-label`/텍스트 노출이 유지된다.
- `getComputedStyle(...).gridRow` 값이 병합 span과 일치한다.
- 테스트 파일: `frontend/tests/f1-grid.test.tsx`
