# 20261015_015 기안양식 본문 스크롤 공통화 상세사양서

## 1. 목적 및 근거

기안양식 문서 본문 작성/수정 모달의 에디터 주변 위·아래 구분선을 없애고, 에디터 내부가 아닌 공통 다이얼로그의 본문 전체가 세로로 스크롤되도록 한다.

- 작업지시서: [20261015_015 작업지시서](../../directions/20261015/20261015_015_기안양식_본문_스크롤_공통화_작업지시서.md)
- 계획서: [20261015_015 계획서](../../plan/20261015/20261015_015_기안양식_본문_스크롤_공통화_계획서.md)
- 구현 상세 계획: [Draft form template body scroll plan](../../superpowers/plans/2026-10-15-draft-form-template-body-scroll.md)
- 승인 설계: [기안양식 본문 스크롤 공통화](../../superpowers/specs/2026-10-15-draft-form-template-body-scroll-design.md)

## 2. 적용 대상 및 구조

- 기안양식 본문 작성/수정: `frontend/src/pages/co/workflow/form/components/DraftFormTemplateDialog.tsx`
- 공통 편집기: `frontend/src/shared/components/rich-text-editor/RichTextEditor.tsx`
- 편집기 prop 타입: `frontend/src/shared/components/rich-text-editor/richTextEditor.types.ts`
- 공통 모달 셸: `frontend/src/shared/components/CommonDialog.tsx` (구조 변경 없음)

기안양식 본문 모달은 문서 작성 및 공지사항 작성 모달과 동일하게 `CommonDialog`를 사용한다. 새 모달 셸을 만들거나 공통 셸의 기본 레이아웃을 수정하지 않는다.

## 3. 레이아웃 동작

1. `CommonDialog` 제목/설명 헤더는 기존처럼 고정한다.
2. 푸터의 리치 텍스트 툴바와 저장/취소 액션은 기존처럼 고정한다.
3. `CommonDialog`의 본문 컨테이너가 편집 영역의 세로 스크롤을 소유한다. 본문 내용이 길면 에디터 콘텐츠 전체가 본문 컨테이너 안에서 이동한다.
4. 기안양식 에디터 프레임은 위·아래 테두리를 표시하지 않고 자체 overflow clipping을 하지 않는다.
5. 공통 셸의 헤더/푸터 구분선은 유지한다. 요구사항에서 제거하는 선은 에디터 프레임의 위·아래 선에 한정한다.
6. 표의 수평 스크롤은 기존 `.tableWrapper`가 계속 담당하며 페이지 전체 가로 스크롤을 만들지 않는다.

## 4. RichTextEditor 스크롤 모드 계약

- `RichTextEditorProps`에 `scrollMode?: 'editor' | 'container'`를 추가한다.
- 기본값 `editor`는 기존처럼 `.ProseMirror` 내부 세로 스크롤을 사용한다. 기존 호출부는 수정하지 않는다.
- `container`는 편집기 root와 콘텐츠 래퍼의 높이 제한 및 clipping을 제거하고 ProseMirror를 자연 높이/visible overflow로 배치한다. 바깥 스크롤 컨테이너가 세로 스크롤을 맡는다.
- ProseMirror에는 `overflowX`/`overflowY`를 각각 `visible`로 지정해 공통 스타일의 내부 `auto` 값을 명시적으로 덮는다. 표 자체의 수평 overflow는 `.tableWrapper`가 계속 처리한다.
- `DraftFormTemplateDialog`만 `scrollMode="container"`를 전달한다.
- 프레임 높이는 본문 높이에 맞춰 확장할 수 있어야 하며, 빈 편집기의 최소 높이와 기존 안쪽 padding은 유지한다.

## 5. 보존 동작 및 범위

- 문서 작성/수정 제목, 양식 식별 정보, 툴바 위치, 저장/취소 액션, 로딩/오류 상태를 변경하지 않는다.
- 서식 편집, 클립보드 붙여넣기, 이미지 업로드 및 리사이즈, 저장 payload, 미저장 변경 확인을 변경하지 않는다.
- 기본 `editor` 모드를 사용하는 공지사항 작성, 문서 작성 및 다른 화면의 RichTextEditor 스크롤 동작을 보존한다.
- API, 데이터 모델, 백엔드, DB 및 `CommonDialog` 구현은 변경하지 않는다.

## 6. 회귀 검증

### 자동 테스트

- `frontend/tests/rich-text-editor.test.tsx`
  - 모드를 생략하면 ProseMirror 내부 `overflowY: auto` 동작이 유지된다.
  - `scrollMode="container"`이면 editor root/content wrapper/ProseMirror가 높이에 제한되지 않고 세로 overflow를 소유하지 않는다.
- `frontend/tests/draft-form-template-dialog.test.tsx`
  - 에디터 프레임의 위·아래 선이 없고 overflow clipping이 없다.
  - ProseMirror의 세로 스크롤은 visible이며 16px 안쪽 padding이 유지된다.
  - 상위 `.MuiDialogContent-root`가 `overflowY: auto`로 본문 스크롤을 담당한다.
- 집중 명령:

```powershell
npm run test -- tests/draft-form-template-dialog.test.tsx tests/rich-text-editor.test.tsx
```

- 프론트엔드 빌드:

```powershell
npm run build
```

### 브라우저 확인

- 375px, 768px, 1280px에서 문서 양식 작성/수정 모달을 확인한다.
- 본문이 길 때 본문 영역 전체가 세로 스크롤되고 제목 및 푸터가 고정되는지 확인한다.
- 에디터 위·아래 구분선이 없고, 툴바/저장/취소가 겹치거나 잘리지 않는지 확인한다.
- 표 콘텐츠에서 수평 스크롤이 유지되고 페이지 전체 가로 넘침이 없는지 확인한다.
