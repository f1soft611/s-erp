# 20261015_011 업무작성 자주 쓰는 결재선 F1-Grid 상세 사양서

## 1. 목적

업무작성 모달의 결재선 설정에서 자주 쓰는 결재선을 관리하는 화면을 F1-Grid로 전환한다. 승인된 원 설계와 기존 CRUD API는 유지하고, 목록 선택 후 별도 이름 변경하는 흐름을 그리드 인라인 편집 중심으로 바꾼다.

## 3. 화면 구조

- 접근 가능한 이름이 `자주 쓰는 결재선 목록`인 F1-Grid를 사용한다.
- `결재선명` 컬럼은 인라인 텍스트 편집이 가능하다.
- 우측 `액션` 컬럼은 행별 `적용` 및 `삭제` 버튼을 제공한다. 적용 버튼은 자신의 행 template ID로 조회하며 불러온 값은 결재선 설정의 임시 상태에 반영한다. 두 버튼은 Grid 셀/행 선택과 분리된다.
- 결재선명 셀을 편집 중 같은 Grid 안의 다른 셀로 포커스가 이동하면 현재 편집을 commit하고 새 셀에만 포커스를 둔다. 관리 Grid가 중첩 MUI Dialog/Modal 안에 있어도 조상 모달을 editor popup으로 오인해 commit을 보류하지 않는다. 실제 editor popup으로 포커스가 이동하는 경우에만 commit을 보류한다.
- 목록 하단의 기존 `불러오기` 액션은 `저장`으로 바꾼다. 저장은 이름 변경이 있는 모든 행을 처리하고, 변경이 없거나 작업 중이면 비활성화한다.
- 신규 템플릿 생성 입력과 생성 기능은 현재 흐름을 유지한다.
- 로딩, 빈 목록, 조회 오류, 저장 오류, 삭제 확인 상태를 기존 모달 패턴으로 표시한다.

## 4. 동작 및 데이터 계약

### 4.1 인라인 이름 변경 및 저장

1. 사용자가 `결재선명` 셀을 수정하면 변경 집합에서 추적한다.
2. 이름은 trim 후 1~100자여야 하며, 현재 목록 안에서 정규화된 이름 중복을 거부한다.
3. 하단 `저장`을 누르면 변경된 행별로 기존 `renameApprovalLineTemplate(templateId, name)` 호출을 수행한다.
4. 성공 후 서버 반환 이름을 기준 목록에 반영한다. 모든 요청이 성공하면 Grid 변경 상태를 초기화한다.
5. 이름 변경은 행 단위 API이므로 일괄 저장은 서버 트랜잭션이 아니다. 일부 실패 시 성공 이름은 반영하고 실패 행의 편집 내용은 보존해 재시도할 수 있게 하며 오류를 명시한다.

### 4.2 행별 적용

- 행의 `적용`은 기존 상세 조회 API를 해당 template ID로 호출한다.
- 현재 문서 코드와 일치하는지 확인하고 모든 참여자가 현재 활성 사용자 옵션에 존재할 때만 현재 설정 모달의 임시 결재선/참조자 상태를 교체한다.
- 성공 후 템플릿 관리 창을 닫는다. 작성 화면 반영은 기존 결재선 설정 창의 `적용`에서만 수행하고, 고정 기안자는 현재 작성자로 유지한다.
- 오류 시 임시 결재선과 참조자 상태를 변경하지 않는다.

### 4.3 행별 삭제

- 각 행의 삭제는 기존 삭제 확인 절차 후 해당 template ID만 삭제한다.
- 성공 후 해당 행을 목록에서 제거한다. 실패 시 행을 유지하고 오류를 표시한다.

### 4.4 미저장 수정 폐기 확인

- 미저장 이름 수정이 있을 때 행 적용, 행 삭제, 관리 창 닫기를 시작하면 폐기 여부를 확인한다.
- 취소 시 요청한 동작을 실행하지 않고 편집 상태를 보존한다.
- 확인 시 미저장 이름 편집을 버린 다음 대기 중인 동작을 진행한다.
- 이름 저장 중에는 행 액션과 닫기를 비활성화한다.

## 5. 영향 범위 및 비범위

### 변경 대상

- `frontend/src/pages/groupware/documents/write/components/DocumentApprovalSettingsDialog.tsx`
- `frontend/tests/document-approval-settings-dialog.test.tsx`

### 변경하지 않음

- 결재선 템플릿 API 경로·요청 및 응답 계약
- 백엔드, 데이터베이스 및 마이그레이션
- F1-Grid의 셀 범위 선택 및 기본 동작
- 템플릿 참여자 구성 편집과 공유 기능
- 작성 화면 적용/취소 계약

## 6. 접근성 및 반응형

- 행별 버튼 이름에 해당 결재선명을 포함한다.
- 버튼은 키보드 조작이 가능하고 Grid 행 이벤트로 전파되지 않아야 한다.
- 375px, 768px, 1280px에서 내부 Grid 스크롤과 버튼 접근성을 확인하고 페이지 전체 가로 넘침이 없어야 한다.
- 테스트 캡처에는 템플릿 이름 외 사용자/문서 개인정보를 포함하지 않는다.

## 7. 검증 기준

- UI 테스트에서 Grid 컬럼, 행별 액션, 편집 셀, 일괄 저장, 변경 없음 비활성화, 이름 검증, 부분 실패/재시도, 폐기 확인 취소/확인, 임시 결재선 적용 경계를 검증한다.
- UI 테스트에서 결재선명을 편집한 뒤 다른 셀을 클릭하면 editor가 종료되고 저장 버튼이 활성화되며, rename API 호출과 단일 포커스 이동이 일어나는지 검증한다. 공통 F1-Grid의 기본 범위 선택 동작은 변경하지 않는다.
- 서비스 계약은 기존 테스트를 유지한다.
- 검증 명령:

```powershell
cd frontend
npm run test -- tests/document-approval-settings-dialog.test.tsx tests/approval-line-template-service.test.ts
npm run build
```

- 브라우저에서 세 필수 너비를 확인하고 `git diff --check`를 수행한다.
