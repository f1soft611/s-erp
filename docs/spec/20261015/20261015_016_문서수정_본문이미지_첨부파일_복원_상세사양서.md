# 20261015_016 문서 수정 본문 이미지·첨부파일 복원 상세 사양서

## 1. 목적

문서 상세의 `문서 수정` 또는 `수정 후 재상신`을 선택했을 때 편집 모달이 기존 본문 이미지 및 첨부파일을 누락하지 않도록 한다.

- 작업지시서: [20261015_016 작업지시서](../../directions/20261015/20261015_016_문서수정_본문이미지_첨부파일_복원_작업지시서.md)
- 계획서: [20261015_016 계획서](../../plan/20261015/20261015_016_문서수정_본문이미지_첨부파일_복원_계획서.md)

## 2. 기존 데이터 흐름 및 결함

1. 상세 피드에서 수정 액션을 선택하면 문서 상세 객체가 `DocumentComposerDialog.initialDocument`에 전달된다.
2. `useDocumentComposer`의 수정 초기화는 제목, 문서 종류, 양식, 결재선을 구성하고 `contentsHtml`을 에디터에 넣는다.
3. 해당 분기에서 `initialDocument.attachments`를 편집기 상태로 변환하지 않아 기존 파일 목록이 표시되지 않는다.
4. 저장된 본문 이미지의 `src`는 `/api/v1/groupware/approvals/{approvalId}/embedded-images/{fileId}` 형태다. 브라우저의 `<img>` 요청은 인증 헤더를 넣지 않으므로 이미지가 깨진다.
5. 상세 본문은 `fetchApprovalEmbeddedImageBlob`로 Blob을 받고 임시 Object URL을 만드는 반면, 수정 편집기는 그 처리가 없다.

## 3. 수정 모달 동작 계약

### 3.1 첨부파일

- 상세 응답 `attachments`를 수정 모달 열 때 기존 첨부 항목으로 초기화한다.
- 항목에는 `fileId`, 파일명, 크기, MIME 유형 및 기존 파일임을 식별하는 상태를 보관한다.
- 이름은 `fileName`이 없을 경우 기존 데이터에 근거한 명시적 대체 표시를 사용하되, 잘못된 파일 항목을 조용히 숨기지 않는다.
- 기존 항목은 모달의 첨부 영역에 파일명과 제거 액션으로 표시한다.
- 기존 파일을 유지하면 저장 시 별도 업로드를 하지 않으며 서버가 유지하도록 둔다.
- 기존 파일을 제거하면 `deleteDocumentDraftAttachment(electronicApprovalId, fileId)`를 호출한다. 실패 시 항목을 유지하고 기존 오류 표시 영역에 오류를 표시한다.
- 신규 파일은 현재처럼 `File`과 pending/uploaded/failed/unknown 업로드 상태를 갖고 기존 업로드·재시도·결과 확인 흐름을 유지한다.
- 신규 문서 생성 시 기존 파일 목록은 비어 있다.

### 3.2 본문 이미지

- 수정 모달은 편집기 문서에 포함된 승인 서버 이미지 주소에서 이미지 파일 ID를 식별한다.
- 현재 승인 문서 ID와 일치하는 파일 ID에 한해 `fetchApprovalEmbeddedImageBlob(approvalId, fileId)`를 호출한다.
- Blob을 Object URL로 바꾸어 편집기 렌더링에만 적용한다. 원본 문서의 `src`, `data-upload-token`, `data-file-id`, `data-object-key`, `data-file-size`, `data-mime-type`은 저장 데이터에서 보존되어야 한다.
- 이전 이미지 요청이 모달 닫힘/문서 변경 후 완료되면 에디터를 갱신하지 않는다. 생성한 Object URL은 효과 정리 시 해제한다.
- 이미지 로드 실패는 저장 오류 영역에 사용자에게 읽을 수 있는 메시지로 표시한다. 실패한 원본 URL이 깨진 이미지로 남지 않도록 한다.
- 신규 임시 업로드 이미지는 기존 `useRichTextEditorSaveLifecycle` 계약에 따라 처리한다.

## 4. 호환성 및 비범위

- 생성 모드에서 이미지 붙여넣기/업로드와 첨부 업로드는 기존과 동일하게 동작한다.
- 상세 피드가 자체적으로 수행하는 이미지 로딩/첨부 다운로드는 변경하지 않는다.
- 공지사항 모달과 RichTextEditor 공통 동작은 변경하지 않는다.
- 백엔드/API 요청 및 응답, 데이터베이스 스키마를 변경하지 않는다.

## 5. 회귀 검증 기준

### 자동 검증

- 수정 모달이 상세 응답의 기존 첨부파일 이름을 표시하고, 유지 파일을 다시 업로드하지 않는다.
- 기존 첨부 제거를 선택하면 정확한 문서 ID와 파일 ID로 삭제 요청을 하고, 삭제 실패 시 파일이 다시 제거되지 않는다.
- 수정 모달은 서버 이미지 경로의 파일 ID로 이미지 Blob을 조회하고 Blob URL을 미리보기에만 사용한다.
- Blob URL이 최종 저장 HTML/JSON에 포함되지 않고 원본 이미지 API 주소가 보존된다.
- 수정 이외의 생성/이미지 업로드 및 문서 상세 회귀 테스트가 통과한다.
- 집중 테스트 및 빌드:

```powershell
npm run test -- tests/document-write-page.test.tsx
npm run build
```

### 브라우저 검증

- 인증된 사용자 상태에서 375px, 768px, 1280px 뷰포트의 수정 모달에 기존 이미지와 첨부파일이 표시되는지 확인한다.
- 기존 파일 제거 및 저장 버튼이 화면 폭에 맞게 표시되고 콘텐츠 가로 넘침이 없는지 확인한다.
- 브라우저 인증 세션에 접근할 수 없는 경우, 사유 및 대체 검증 근거를 결과 문서에 남긴다.
