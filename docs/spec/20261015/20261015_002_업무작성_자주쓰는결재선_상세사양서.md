## 2. 문서 분류 및 사용 범위

결재선 템플릿은 기존 전자결재 문서번호 코드 `eabus_no` 값으로 분류한다.

| 화면 표시 | `eabus_no` | 내부 문서 유형 |
|---|---:|---|
| 기안 | `001` | `DRAFTING` |
| 업무 | `008` | `BUSINESS_CONTACT` |
| 지출 | `004` | `EXPENSE_RESOLUTION` |
| 근태 | `031` | `ATTENDANCE_APPLICATION` |

화면은 현재 작성 문서 종류의 템플릿만 조회한다. 이름과 문서 코드는 필수이며 이름은 trim 후 1~100자다. 같은 tenant·사용자·코드 안에서 이름 중복은 허용하지 않는다. 다른 사용자 또는 문서 코드의 같은 이름은 허용한다.

템플릿은 여러 개 저장할 수 있다. 사용자는 본인이 소유한 템플릿의 이름 변경과 삭제를 할 수 있다. 타 사용자 또는 조직 템플릿 공유는 포함하지 않는다.

## 3. 데이터 모델

기존 `tb_electronic_approval_line_info`는 실제 문서 결재 처리 상태와 연결되므로 재사용하지 않는다. 즐겨찾기는 다음 두 테이블로 분리한다.

### 3.1 `tb_electronic_approval_line_template`

| 컬럼 | 규칙 |
|---|---|
| `template_id` | 서버 발급 기본키 |
| `tenant_id` | 필수, `tb_tenant` 참조 |
| `owner_user_id` | 필수, 인증된 `LoginVO.id` |
| `eabus_no` | 필수, `001`, `008`, `004`, `031` 중 하나 |
| `template_name` | 필수, trim 후 1~100자 |
| `created_at`, `updated_at` | 서버 시각 |

Unique 기준은 `(tenant_id, owner_user_id, eabus_no, template_name)`이다. 모든 소유자 조건은 서버가 `LoginVO`에서 구성한다.

### 3.2 `tb_electronic_approval_line_template_info`

| 컬럼 | 규칙 |
|---|---|
| `template_line_id` | 서버 발급 기본키 |
| `tenant_id`, `template_id` | 부모의 tenant/template 복합키 FK, 부모 삭제 시 cascade |
| `stage_order` | 양수, 단계 순서 |
| `participant_order` | 양수, 단계 내 또는 참조선 내 순서 |
| `participant_type` | `APPROVAL`, `AGREEMENT`, `REFERENCE` 중 하나 |
| `participant_user_id` | 필수 사용자 ID |

템플릿 내 `(tenant_id, template_id, stage_order, participant_order)` 및 사용자 ID는 중복될 수 없다. 합의 참여자들은 같은 단계 번호를 공유하고 참여자 순서를 보존한다. 참조 행은 기존 문서작성 요청 계약처럼 결재 단계 뒤에 오며 참조자 순서를 보존한다. 고정 기안자 단계는 저장하지 않고 불러올 때 현재 작성자의 고정 단계로 유지한다.

DB 변경은 `docs/database/20261015`와 `backend/DATABASE/20261015`에 동일한 DDL/변경 이력/롤백 파일을 남기고, [누적 스키마](../../database/db-schema.md)를 갱신한다. DB MCP에서 `tb_electronic_approval_line_info`, `tb_user`, `tb_login_account` 메타데이터를 확인했다. 현재 즐겨찾기 테이블은 없으며 기존 결재 행은 템플릿 용도로 사용할 수 없다.

## 4. API 계약

공통 prefix: `/api/v1/groupware/approvals/line-templates`

모든 API는 인증된 `LoginVO.tenantId`와 `LoginVO.id`를 소유권 기준으로 사용한다. 요청 body의 소유자 값은 받지 않는다. 응답은 기존 `ResultVO` 규약과 프론트엔드 `apiClient`의 `resultList`/`item` 형식을 따른다.

### 4.1 템플릿 목록

`GET /api/v1/groupware/approvals/line-templates?eabusNo=001`

- 인증된 tenant·사용자 및 요청 코드가 일치하는 항목만 반환한다.
- `resultList` 항목: `templateId`, `name`, `eabusNo`, `updatedAt`.
- 이름 오름차순, 같은 이름은 `templateId` 오름차순으로 정렬한다.
- 미지원 코드는 `400 Bad Request`다.

### 4.2 템플릿 상세/불러오기

`GET /api/v1/groupware/approvals/line-templates/{templateId}`

- 인증된 tenant 및 사용자 소유 템플릿만 반환한다. 다른 사용자/tenant 항목 또는 없는 항목은 동일하게 `404 Not Found`로 처리한다.
- `item`에는 `templateId`, `name`, `eabusNo`, `approvalLines`를 반환한다.
- `approvalLines` 행은 `stageOrder`, `participantOrder`, `participantType`, `participantUserId`를 포함하며 순서 오름차순이다.
- 행의 참여자가 같은 tenant의 활성 사용자로 전부 확인되지 않으면 상세를 적용 가능한 값처럼 반환하지 않고 `409 Conflict`를 낸다.

### 4.3 템플릿 저장

`POST /api/v1/groupware/approvals/line-templates`

요청 형식:

```json
{
  "eabusNo": "001",
  "name": "기본 결재선",
  "approvalLines": [
    {
      "stageOrder": 2,
      "participantOrder": 1,
      "participantType": "APPROVAL",
      "participantUserId": "2001"
    },
    {
      "stageOrder": 3,
      "participantOrder": 1,
      "participantType": "AGREEMENT",
      "participantUserId": "2002"
    },
    {
      "stageOrder": 4,
      "participantOrder": 1,
      "participantType": "REFERENCE",
      "participantUserId": "2003"
    }
  ]
}
```

- `eabusNo`는 네 허용 코드 중 하나, 이름은 trim 후 1~100자여야 한다.
- 이름 중복은 동일 tenant·owner·code 범위에서 거부한다(`409 Conflict`).
- 참여자 유형은 `APPROVAL`, `AGREEMENT`, `REFERENCE` 중 하나이며, 순서는 양수다.
- 같은 사용자 ID를 템플릿의 둘 이상의 위치에 넣을 수 없다.
- 참여자는 모두 같은 tenant의 활성 사용자여야 한다. 알 수 없는/비활성/타 tenant 사용자, 잘못된 코드/유형/순서는 `400 Bad Request`다.
- 현재 작성 요청과 동일하게 기안자 고정 단계는 입력 템플릿에 포함하지 않는다. 결재·합의 단계는 고정 단계 뒤의 순서, 참조는 최종 단계 순서를 유지한다.
- 부모/상세 저장은 단일 트랜잭션이며 일부 상세 저장 실패 시 전체가 rollback된다.
- 성공 시 `201 Created` 및 `item`으로 `templateId`, `name`, `eabusNo`를 반환한다.

### 4.4 이름 변경

`PUT /api/v1/groupware/approvals/line-templates/{templateId}`

요청:

```json
{
  "name": "새 결재선 이름"
}
```

- 이름만 변경하며 참여자 구성은 변경하지 않는다.
- 소유권, 이름 길이/공백 및 중복 규칙을 저장과 동일하게 적용한다.
- 타 소유자/tenant 또는 없는 ID는 `404`; 이름 중복은 `409`다.
- 성공 시 `item`에 변경된 `templateId`, `name`, `eabusNo`, `updatedAt`을 반환한다.

### 4.5 템플릿 삭제

`DELETE /api/v1/groupware/approvals/line-templates/{templateId}`

- 소유자/tenant를 조건으로 삭제하고 상세 행도 함께 제거한다.
- 타 소유자/tenant 또는 없는 ID는 `404`다.
- UI는 삭제 전에 사용자 확인을 요구한다.
- 성공 응답에는 프로젝트 `ResultVO`의 성공 상태와 완료 메시지를 포함한다.

## 5. 화면 동작

1. `자주 쓰는 결재선 저장`을 누르면 이름 입력 UI를 연다. 현재 결재선 설정 창의 임시 결재/합의 단계 및 참조자 목록을 저장한다. 저장 완료 후 작성 화면에 적용하거나 설정 창을 닫지 않는다.
2. `자주 쓰는 결재선 불러오기`를 누르면 현재 문서 코드로 목록을 조회하고 템플릿 이름을 선택하게 한다. 선택 후 해당 template ID의 상세를 가져온다.
3. 모든 참여자가 현재 `userOptions`에서 활성 옵션으로 확인될 때만 임시 편집 결재선/참조자 상태를 교체한다. 누락/응답 오류 시 기존 임시 상태를 보존하고 명시 오류를 표시한다.
4. 적용은 기존 `적용` 버튼만 수행한다. `취소` 또는 닫기는 불러오기를 포함한 임시 변경을 모두 버린다.
5. 템플릿 목록에서 이름 변경 및 삭제를 제공한다. 삭제는 확인창을 거친다.
6. 저장/불러오기/수정/삭제 요청 중 중복 실행을 막고 로딩을 표시한다. 오류 발생 시 목록/임시 상태를 성공 형태로 대체하지 않는다.

## 6. 접근성 및 반응형

- 각 저장/불러오기/이름 변경/삭제/확인 컨트롤에 접근 가능한 이름을 제공하고 키보드로 사용할 수 있어야 한다.
- 기존 `CommonDialog`, MUI 테마와 오류 표시 패턴을 따른다.
- 375px, 768px, 1280px에서 모달 내부 줄바꿈과 스크롤을 확인하고 페이지 전체 가로 넘침을 만들지 않는다.
