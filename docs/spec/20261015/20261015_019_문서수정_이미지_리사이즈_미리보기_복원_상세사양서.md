# 20261015_019 문서 수정 이미지 리사이즈 미리보기 복원 상세 사양서

## 1. 목적

문서 수정 모달에서 기존 본문 이미지를 크기 조절한 후 이미지가 깨지는 현상을 방지한다.

- 계획서: [20261015_019 계획서](../../plan/20261015/20261015_019_문서수정_이미지_리사이즈_미리보기_복원_계획서.md)
- 승인된 설계: [이미지 리사이즈 미리보기 설계](../../superpowers/specs/2026-10-15-document-edit-image-resize-preview-design.md)

## 2. 원인과 동작 흐름

1. 수정 모달의 에디터 모델은 `/api/v1/groupware/approvals/{approvalId}/embedded-images/{fileId}` 주소를 `src`로 보관한다.
2. `useDocumentComposer` 이미지 로드 효과는 인증 Blob을 만든 뒤 현재 렌더링된 `<img>` DOM의 `src`만 임시 Blob URL로 바꾼다.
3. 리사이즈 핸들은 `updateAttributes('image', { width, height })`로 TipTap 모델을 갱신한다.
4. ProseMirror가 노드를 다시 렌더링하면 모델의 보호 API URL이 새 DOM의 `src`가 된다. 일반 `<img>` 요청에는 인증 정보가 없어 이미지가 깨진다.

## 3. 요구 동작

### 3.1 리사이즈 표시

- 이미지 조회 효과는 원본 보호 URL과 생성한 Blob URL의 관계를 보유한다.
- 에디터 업데이트 이벤트가 발생하면 새로 렌더링된 이미지 DOM을 확인하고, `src`가 매핑된 보호 URL이면 대응 Blob URL을 다시 적용한다.
- Blob 로드가 실패한 원본 URL은 업데이트 후에도 이미지 DOM에서 `src`를 제거해 깨진 이미지 요청이 다시 노출되지 않게 한다.
- 매핑/복원은 렌더링 DOM에만 적용한다. ProseMirror 이미지 노드의 `src`는 원본 보호 URL로 유지한다.

### 3.2 저장 및 정리

- 리사이즈한 이미지의 `width` 및 `height` 속성은 TipTap 모델과 저장 payload에 반영한다.
- 저장 HTML/JSON은 원본 보호 URL을 유지하고 임시 Blob URL을 포함하지 않는다.
- 효과 정리 시 editor update 리스너를 해제한다. 현재 DOM에 미리보기 Blob URL이 있으면 원본 URL로 복구한 다음 해당 object URL을 해제한다.
- 실패한 이미지의 오류 안내와 기존 문서 본문/첨부 기능은 유지한다.

## 4. 영향 범위와 비범위

- 수정 대상: `useDocumentComposer`의 기존 문서 이미지 hydration 효과 및 `document-write-page.test.tsx`
- 기존 문서 이미지 표시와 크기 변경만 보정한다.
- 신규 이미지 업로드, 상세 피드 이미지 조회, 리사이즈 크기 산출, API/DB 계약은 변경하지 않는다.

## 5. 회귀 검증

- 보호 이미지 Blob URL이 리사이즈 후에도 `<img src>`로 유지된다.
- 이미지 리사이즈 핸들로 변경한 너비/높이가 저장에 포함된다.
- 저장 시 원래 전자결재 이미지 API URL은 남고 Blob URL은 없다.
- 기존 첨부 유지 테스트와 프론트엔드 build가 통과한다.
- Problems와 `git diff --check`에 오류가 없다.
- 브라우저가 로그인으로 이동하면 인증된 UI 미확인 사실과 자동 테스트 대체 근거를 결과에 적는다.
