# 20260901_002 메뉴 기능권한/설명 연동 사양서

## 1. 목적

메뉴관리에서 저장한 메뉴명, 메뉴설명, 제공 기능 권한을 실제 로그인 사용자의 페이지 표시와 기능 버튼에 동일하게 적용한다.

## 2. 권한 규칙

공통 페이지 기능 버튼은 다음 네 종류만 제공한다.

| 저장 권한 코드         | 실제 페이지 버튼 |
| ---------------------- | ---------------- |
| `READ`                 | 조회             |
| `CREATE` 또는 `UPDATE` | 저장             |
| `DELETE`               | 삭제             |
| `EXCEL`                | 엑셀             |

- 등록과 수정 버튼은 제거한다.
- CREATE와 UPDATE 중 하나 이상이 있으면 저장 버튼을 표시한다.
- 메뉴관리 리프에 READ, CREATE/UPDATE, DELETE만 저장되어 있으면 조회, 저장, 삭제만 표시한다.
- 화면 버튼은 권한 마스터 전체 목록이 아니라 `/api/v1/menus/my`가 반환한 현재 사용자·현재 메뉴 권한만 사용한다.

## 3. 메뉴 데이터 계약

`tb_menu`에 `menu_dc varchar(500)` 컬럼을 추가한다.

| 필드                     | 역할                                       |
| ------------------------ | ------------------------------------------ |
| `menuNm`                 | 메뉴 트리와 실제 페이지 제목               |
| `menuDc` / `description` | 메뉴관리 설명 컬럼과 실제 페이지 헤더 설명 |
| `menuUrl` / `path`       | 라우팅 및 페이지 컴포넌트 식별             |

메뉴관리 조회/등록/수정 API는 `menuDc`를 왕복한다. 사용자 메뉴 API는 메뉴 노드에 `description`을 반환한다. null 설명은 빈 문자열로 표시한다.

## 4. 화면 동작

- 메뉴관리 그리드에 `메뉴설명` 편집 컬럼을 추가한다.
- 메뉴 저장 후 재조회하면 메뉴명과 메뉴설명이 저장값과 일치해야 한다.
- 대시보드는 메뉴명 비교가 아닌 선택 메뉴의 `pageKey`/경로로 전용 페이지 컴포넌트를 선택한다.
- breadcrumb는 선택 모듈부터 모든 상위 메뉴와 현재 메뉴까지 저장된 이름을 `>`로 연결한다.
- 환경설정의 시스템 관리 하위 메뉴관리라면 `환경설정 > 시스템 관리 > 메뉴관리`로 표시한다.
- 실제 페이지의 제목은 선택 메뉴의 저장된 이름, 설명은 저장된 설명을 우선 사용한다.
- 메뉴관리 페이지 상단에는 현재 권한에 해당하는 조회, 저장, 삭제, 엑셀만 순서대로 표시한다.
- 루트 메뉴 추가, 하위 메뉴 추가, 전체 펼치기, 전체 접기는 기존 그리드 전용 제어로 유지한다.

## 5. 오류 및 호환성

- `menuDc`가 없는 기존 데이터는 빈 문자열로 처리한다.
- 사용자 메뉴 API 조회 실패 시 기존 정적 메뉴 폴백 동작을 유지한다.
- 권한 데이터가 아직 로드되지 않은 동안 권한 버튼을 임의로 노출하지 않는다.

## 6. 검증 기준

- 백엔드 테스트에서 메뉴설명의 등록, 수정, 목록 조회, 사용자 메뉴 응답을 검증한다.
- 프론트엔드 테스트에서 메뉴설명 조회/저장 요청과 저장된 페이지 제목/설명을 검증한다.
- 프론트엔드 테스트와 실제 브라우저에서 3단계 이상 메뉴 breadcrumb가 생략되지 않는지 검증한다.
- 메뉴관리 권한 READ, CREATE/UPDATE, DELETE 조건에서 조회/저장/삭제만 표시되고 등록/수정/엑셀은 표시되지 않아야 한다.
- 프론트엔드 빌드와 백엔드 Maven 테스트를 통과해야 한다.
- 375px, 768px, 1280px 실제 브라우저에서 버튼과 메뉴설명 컬럼이 겹치거나 잘리지 않아야 한다.
