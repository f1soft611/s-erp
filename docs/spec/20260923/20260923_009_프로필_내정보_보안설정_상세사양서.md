# 20260923_009 프로필 내 정보 관리·보안 설정 상세사양서

## 1. 라우팅 사양

| 메뉴         | 경로                  | 접근 조건     |
| ------------ | --------------------- | ------------- |
| 내 정보 관리 | `/dashboard/profile`  | 인증된 사용자 |
| 보안 설정    | `/dashboard/security` | 인증된 사용자 |

프로필 팝오버에서 메뉴를 선택하면 해당 경로로 이동한다. 인증이 없거나 API가 401을 반환하면 기존 인증 인터셉터 정책에 따라 로그인 화면으로 이동한다.

## 2. 내 정보 관리 화면

### 표시·입력 항목

| 항목          | 표시 방식                     | 편집 |
| ------------- | ----------------------------- | ---- |
| 이름          | 현재 사용자 정보              | 불가 |
| 아이디        | 현재 사용자 정보              | 불가 |
| 부서          | 현재 사용자 정보              | 불가 |
| 직급          | 현재 사용자 정보              | 불가 |
| 이메일        | 텍스트 입력, 이메일 형식      | 가능 |
| 프로필 이미지 | 원형 미리보기, 등록/교체/삭제 | 가능 |
| 도장 이미지   | 사각 미리보기, 등록/교체/삭제 | 가능 |

저장 버튼은 이메일 또는 이미지 변경이 있을 때 활성화한다. 취소/뒤로가기 시 저장하지 않은 입력은 버린다. 저장 중에는 중복 제출을 막고, 성공 시 최신 사용자 요약을 다시 조회하거나 전역 프로필 상태를 갱신한다.

### 이미지 규칙

- 허용 MIME: `image/png`, `image/jpeg`
- 원본 최대 크기: 1MB
- 최대 가로/세로: 512px
- 브라우저에서 미리보기와 정규화를 수행하되 서버 검증을 우회할 수 없도록 한다.
- 서버는 MIME 선언만 신뢰하지 않고 실제 이미지 디코딩 가능 여부와 픽셀 크기를 검증한다.
- 저장 문자열은 기존 TEXT 컬럼에서 사용하는 Data URL 형식을 따른다.
- 삭제 시 해당 컬럼을 `NULL` 또는 기존 프로젝트의 빈 값 정책으로 갱신하며, API 응답은 프론트엔드가 빈 이미지로 처리할 수 있어야 한다.

## 3. 보안 설정 화면

### 입력 항목

| 필드               | 필수 | 검증                      |
| ------------------ | ---- | ------------------------- |
| 현재 비밀번호      | 예   | 서버에서 현재 해시와 검증 |
| 변경 비밀번호      | 예   | 기존 비밀번호 정책 적용   |
| 변경 비밀번호 확인 | 예   | 변경 비밀번호와 완전 일치 |

클라이언트는 즉시 입력 오류를 표시하지만 서버 검증을 대체하지 않는다. 성공 응답을 받으면 인증 상태를 정리하고 `/login`으로 replace 이동한다. 실패 시 입력 화면을 유지하고 서버 메시지 또는 기존 공통 오류 메시지를 표시한다.

## 4. API 계약

### 4.1 내 정보 조회

- Method: `GET`
- Path: `/api/v1/users/me/profile`
- 인증: Bearer access token

응답 성공 예시:

```json
{
  "resultCode": "200",
  "resultMessage": "OK",
  "result": {
    "userId": "admin",
    "name": "사용자명",
    "email": "user@example.com",
    "departmentName": "개발팀",
    "levelName": "사원",
    "profileImage": "data:image/png;base64,...",
    "stampImage": "data:image/png;base64,..."
  }
}
```

### 4.2 내 정보 수정

- Method: `PUT`
- Path: `/api/v1/users/me/profile`
- Content-Type: `application/json`
- 인증: Bearer access token

요청 필드:

```json
{
  "email": "user@example.com",
  "profileImage": "data:image/png;base64,...",
  "stampImage": null
}
```

`profileImage`와 `stampImage`는 미변경·변경·삭제를 구분할 수 있는 기존 API 규칙을 확인해 적용한다. 대상 사용자 ID는 요청 본문에서 받지 않고 인증 주체에서 결정한다.

응답은 갱신된 프로필 요약을 동일 envelope로 반환한다. 성공 상태는 200이다.

### 4.3 비밀번호 변경

- Method: `PUT`
- Path: `/api/v1/users/me/password`
- Content-Type: `application/json`
- 인증: Bearer access token

요청 필드:

```json
{
  "currentPassword": "현재 비밀번호",
  "newPassword": "변경 비밀번호",
  "newPasswordConfirm": "변경 비밀번호"
}
```

성공 시 200 응답을 반환한 뒤 서버의 세션/토큰 무효화 정책을 적용한다. 클라이언트는 access token, refresh token, 인증 관련 저장소를 정리하고 로그인 화면으로 이동한다.

## 5. 오류·권한 정책

| 상황                         | 상태                         | 처리                                      |
| ---------------------------- | ---------------------------- | ----------------------------------------- |
| 미인증                       | 401                          | 기존 인증 인터셉터 및 로그인 이동         |
| 대상 사용자 조작 시도        | 403 또는 400                 | 수정 거부, 서버 로그에 민감정보 없이 기록 |
| 이메일 형식 오류             | 400                          | 필드 오류 표시                            |
| 이미지 형식/크기/디코딩 오류 | 400                          | 해당 이미지 필드 오류 표시                |
| 현재 비밀번호 불일치         | 400 또는 기존 인증 오류 코드 | 비밀번호 변경 금지                        |
| 새 비밀번호 확인 불일치      | 400                          | 확인 필드 오류 표시                       |
| 저장 중 서버 오류            | 5xx                          | 폼 유지, 재시도 가능 메시지               |

비밀번호·이미지 원문·토큰은 로그와 오류 응답에 기록하지 않는다.

## 6. 구현 구조

### Frontend

- 대시보드 프로필 액션에서 `/dashboard/profile`, `/dashboard/security`로 navigate
- 기존 대시보드 페이지 분기와 페이지 헤더/컨테이너 스타일 재사용
- 프로필 기능 전용 서비스·타입은 해당 페이지 도메인 하위에 배치
- API 호출은 공통 API client를 사용하고 화면에 직접 fetch 로직을 흩어놓지 않는다.

### Backend

- Controller는 인증 주체를 받고 서비스에 본인 식별 정보를 전달한다.
- Service는 이메일/이미지 검증, 현재 비밀번호 검증, 해시 갱신을 담당한다.
- DAO/Mapper는 `tb_user.email_addr`, `tb_login_account.profile_image`, `tb_login_account.stamp_image`, `password_hash`, `password_changed_at`만 갱신한다.
- DB 변경이 없으므로 날짜별 SQL·롤백 파일은 생성하지 않는다.

## 7. 검증 기준

- 팝오버 두 메뉴가 서로 올바른 독립 화면을 연다.
- 조회 전용 필드가 편집되지 않고 이메일만 저장된다.
- PNG/JPEG 유효 이미지가 미리보기·저장·재조회된다.
- 잘못된 MIME, 1MB 초과, 512px 초과 이미지가 클라이언트·서버에서 거부된다.
- 이미지 삭제가 재조회 후에도 반영된다.
- 현재 비밀번호가 틀리거나 확인 값이 다르면 해시가 변경되지 않는다.
- 비밀번호 변경 성공 후 로그인 화면으로 이동하고 이전 토큰으로 보호 API를 사용할 수 없다.
- 375px/768px/1280px에서 수평 overflow와 컨트롤 겹침이 없다.
