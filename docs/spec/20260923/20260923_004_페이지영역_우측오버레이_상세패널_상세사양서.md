# 20260923_004 페이지영역 우측 오버레이 상세 패널 상세 사양서

## 1. 영역 정의

```text
DashboardPage
├── DashboardSidebar
└── contentRef 셸
    ├── AppBar (테마·알림·로그아웃, 오버레이 대상 아님)
    └── DashboardContent 페이지 영역 (오버레이 대상)
        ├── 공지 목록
        └── 페이지 영역 상세 오버레이
```

- 오버레이 기준 컨테이너는 `DashboardContent`가 렌더링되는 콘텐츠 영역이다.
- 공통 `AppBar`와 그 안의 로그아웃 버튼은 오버레이의 형제 또는 상위 비대상 영역으로 유지한다.
- 오버레이는 페이지 영역의 `position: relative` 호스트 안에서만 동작한다.

## 2. 오버레이 레이아웃

- 호스트: `position: relative; flex: 1; min-height: 0; min-width: 0; overflow: hidden`.
- 패널: `position: absolute; inset: 0 0 0 auto; height: 100%; width: min(960px, 72vw)`.
- 모바일 breakpoint: `max-width: 767px`에서 `width: 100%`.
- 패널 콘텐츠: `height: 100%; display: flex; flex-direction: column`.
- 본문 영역: `min-height: 0; overflow-y: auto; overflow-x: hidden`.
- 백드롭은 페이지 호스트 안에서 패널 좌측을 덮되, 공통 헤더에는 닿지 않는다.
- 패널 z-index는 페이지 영역 내부에서만 목록보다 높게 설정하며, 공통 헤더 z-index를 수정하지 않는다.

## 3. 상호작용

- 선택 전에는 상세 오버레이가 렌더링되지 않는다.
- 리스트 또는 상단 고정 게시글 선택 시 페이지 영역 오버레이가 열린다.
- 다른 게시글 선택 시 패널을 닫지 않고 콘텐츠만 교체한다.
- 패널 닫기 버튼, 페이지 영역 백드롭, `Escape`는 선택 상태를 해제한다.
- 헤더의 로그아웃·알림·테마 버튼은 오버레이가 열린 상태에서도 클릭 가능해야 한다.

## 4. 콘텐츠 계약

기존 상세 패널과 동일하게 본문 HTML, 이미지 뷰어, 첨부 다운로드, 좋아요, 북마크, 댓글·답글, 댓글 파일, 작성자 메뉴를 유지한다. API와 권한 모델은 변경하지 않는다.

## 5. 반응형 검증

- 1280px: 패널 상단 rect의 y가 AppBar 하단 y와 일치하고, 패널 right가 viewport right를 넘지 않는다.
- 768px: 패널이 페이지 영역 전체 폭을 사용해도 AppBar를 덮지 않는다.
- 375px: 가로 스크롤이 없고 로그아웃/헤더 영역이 계속 노출된다.
- 검증 항목: `document.documentElement.scrollWidth <= window.innerWidth`, 패널 rect, AppBar rect, 로그아웃 버튼의 pointer-events/가시성.

## 6. API·오류·DB

기존 공지 상세 API와 오류 처리를 유지한다. 백엔드·DB 변경이 없으므로 SQL 및 롤백 문서는 작성하지 않는다.

## 7. 회귀 테스트

1. 오버레이 선택 전 페이지 영역에 상세 패널이 없다.
2. 게시글 선택 시 페이지 영역 안에 상세 패널이 열린다.
3. 패널 top이 공통 AppBar 아래에 있다.
4. 로그아웃 버튼이 패널에 가려지지 않고 DOM/레이어상 접근 가능하다.
5. 패널 닫기·백드롭·Escape가 동작한다.
6. 기존 게시글 콘텐츠 기능과 대상 교체가 유지된다.
7. 375px·768px·1280px에서 영역 이탈과 가로 스크롤이 없다.
