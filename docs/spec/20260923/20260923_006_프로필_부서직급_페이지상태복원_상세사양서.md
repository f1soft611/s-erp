# 20260923_006 프로필 부서·직급 및 페이지 상태 복원 상세사양서

## 1. 프로필 API 계약

### Endpoint

- `GET /api/v1/menus/my`
- 인증: `Authorization: Bearer <access-token>`
- 성공: HTTP 200, 기존 메뉴 응답 envelope 유지
- 실패: 기존 인증·권한 오류 정책 유지

### `result.user` 필드

| 필드           | 타입        | 설명                          |
| -------------- | ----------- | ----------------------------- |
| userId         | string      | 로그인 사용자 ID, 기존 유지   |
| name           | string/null | 사용자명                      |
| email          | string/null | 이메일                        |
| departmentName | string/null | `tb_department.department_nm` |
| levelId        | number/null | `tb_user.level_id`            |
| levelCode      | string/null | LEVEL 공통코드 `item_code`    |
| levelName      | string/null | LEVEL 공통코드 `item_nm`      |
| groupName      | string/null | 기존 그룹명                   |
| roleName       | string/null | 기존 역할 코드 또는 표시명    |
| roles          | string[]    | 기존 역할 목록                |

직급 조인은 `LEVEL` 그룹, 동일 tenant, `use_at = 'Y'` 조건을 사용한다. 직급이 없으면 모든 level 필드는 null이다.

## 2. DB 사양

```sql
ALTER TABLE tb_user ADD COLUMN level_id BIGINT NULL;
ALTER TABLE tb_user
  ADD CONSTRAINT fk_tb_user_level
  FOREIGN KEY (level_id)
  REFERENCES tb_common_code_item(common_code_item_id)
  ON DELETE RESTRICT;
```

- 기존 행은 null 유지
- 공통코드 항목 삭제로 사용자 직급이 연쇄 삭제되지 않음
- 다른 tenant의 공통코드 ID가 저장되지 않도록 서비스/SQL에서 tenant와 LEVEL 그룹을 검증
- 롤백은 FK 제거 후 컬럼 제거 순서로 실행

## 3. 프로필 팝오버 UI

- AppBar 우측 Avatar 클릭으로 열린다.
- 상단: 프로필 이미지 또는 사용자명 첫 글자 Avatar
- 정보 순서: 사용자명, 부서명, 직급명, 이메일
- 역할명은 부서·직급 아래의 보조 정보로 표시할 수 있다.
- 데이터 누락 fallback: 사용자 ID, `부서 정보 없음`, `직급 정보 없음`, 기존 역할명
- 액션: 내 정보 관리, 보안 설정, 로그아웃
- 팝오버 폭은 모바일 viewport에서 화면 밖으로 나가지 않도록 제한

## 4. 공통 페이지 상태 훅

```ts
type PageSessionStateOptions<T> = {
  pageKey: string;
  initialState: T;
  version?: number;
  validate?: (value: unknown) => value is T;
};
```

현재 `usePageSessionState(pageKey, initialState)` 공개 API와 호환되도록 확장한다.

- 저장 key: `s-erp:page:${pageKey}`
- JSON 파싱 실패·version 불일치·validator 실패: 초기값 사용 및 저장값 제거
- 상태 변경 시 저장
- 마운트 시 저장값 복원
- `resetState()` 호출 시 메모리·sessionStorage 동시 초기화
- 로그아웃 시 등록된 페이지 상태를 정리할 수 있는 reset registry 또는 명시적 key 목록 사용

## 5. 공통코드 관리 상태

페이지 key: `common-code-management`

```ts
type CommonCodePageSession = {
  version: 1;
  searchQuery: string;
  selectedGroupId: string;
  selectedGroupRowIds: string[];
  selectedItemRowIds: string[];
  splitterSize: number;
};

- 스플리터 저장값은 desktop horizontal split의 좌측 픽셀 크기다.
- 허용 범위는 `minSize`와 `maxSize`로 보정한다.
- 모바일 stacked 모드에서는 저장된 desktop 크기를 적용하지 않는다.
```

복원 절차:

1. sessionStorage에서 상태를 읽는다.
2. 그룹 API 응답 후 검색어를 적용한다.
3. 저장된 그룹 ID가 필터 결과에 있으면 선택한다.
4. 없으면 첫 번째 그룹을 선택한다.
5. 선택 그룹의 상세 항목을 조회한다.
6. 상세 목록에 존재하는 선택 row ID만 적용한다.
7. 저장된 dirty 상태·미저장 변경값·스크롤 위치는 복원하지 않는다.
8. F1-Grid/F1-Tree에는 선택 행을 주입하는 최소 ref API만 추가하고 렌더링·편집 엔진은 변경하지 않는다. 정렬·필터는 저장·복원하지 않는다.

검색어 변경으로 저장 그룹이 필터에서 사라지면 선택 그룹을 첫 번째 결과로 대체하고 상세를 다시 조회한다.

## 6. 권한·오류 처리

- 프로필 정보는 인증된 사용자 자신의 `/menus/my` 응답에만 포함한다.
- 프로필 필드 누락은 메뉴 로딩 실패로 처리하지 않는다.
- 페이지 상태는 서버에 전송하지 않는다.
- sessionStorage 접근 불가 시 메모리 상태로만 동작한다.
- 삭제되었거나 권한 없는 그룹·행은 조용히 제거하고 현재 유효한 선택값을 사용한다.
- 미저장 그리드 변경값은 페이지 복귀 시 복원하지 않으며 기존 unsaved 경고 정책을 유지한다.

## 7. 테스트 사양

- JWT round-trip에서 이메일·부서·직급 필드 보존
- 내 메뉴 응답의 부서·직급 필드 생성
- 프로필 팝오버에서 부서명·직급명 표시와 fallback
- 훅 초기 복원, 변경 저장, reset 삭제, 잘못된 JSON 처리
- 공통코드 검색어·그룹 선택·상세 선택 복원
- 유효하지 않은 그룹 ID 대체
- 로그아웃 후 최근 메뉴·페이지 상태 삭제
- 375px/768px/1280px에서 overflow 없음
