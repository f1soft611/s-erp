# 20260923_001 공지사항 리스트·상단고정 우측 상세 패널 상세 사양서

## 1. 화면 범위

- 경로: `/groupware/community/notice`
- 데스크톱 기준 레이아웃: `ContentSplitLayout`의 좌측 목록과 우측 상세 슬롯
- 모바일 기준 레이아웃: 목록 위에 표시되는 전체 화면 드로어/모달
- 적용 항목: 리스트형 공지, 상단 고정 공지
- 미적용 항목: 피드형 보기의 기존 인라인 상세 흐름

## 2. 상태 모델

```ts
type NoticeDetailSelection = {
  noticeId: number;
  source: 'list' | 'pinned';
};

type DetailPanelState = {
  selected: NoticeDetailSelection | null;
  isLoading: boolean;
  errorMessage?: string;
};
```

- 선택이 없으면 데스크톱 우측 슬롯에 기존 `NoticeSummaryPanel`을 표시한다.
- 선택이 있으면 상세 조회 결과를 선택 게시글로 병합한 뒤 공통 상세 패널을 표시한다.
- 다른 항목을 선택하면 이전 선택을 즉시 새 선택으로 교체하고 상세 조회를 수행한다.
- 닫기 버튼은 `selected = null`로 변경한다.
- 상세 조회 실패 시 목록은 유지하고 패널에 오류 상태와 닫기 동작을 표시한다.

## 3. 목록 선택 동작

### 3.1 리스트형

- `ListView` 항목 전체를 접근 가능한 버튼으로 유지한다.
- 클릭 시 `{ noticeId, source: 'list' }`를 전달한다.
- 키보드 Enter/Space도 동일하게 동작한다.
- 선택 항목에는 기존 목록 스타일을 해치지 않는 선택 배경 또는 강조선을 표시한다.

### 3.2 상단 고정

- `PinnedItemsPanel`의 각 고정 항목을 접근 가능한 버튼 또는 버튼 역할 요소로 변경한다.
- 클릭 시 `{ noticeId, source: 'pinned' }`를 전달한다.
- 리스트형과 동일한 상세 패널을 사용한다.
- 같은 게시글이 일반 목록과 고정 영역에 중복되어 있어도 선택 상태는 게시글 ID 기준으로 동기화한다.

## 4. 상세 패널 UI

상세 패널은 피드형 게시글 카드 하나의 시각적 구조와 기능을 재사용한다.

1. 게시글 작성자 아바타/작성자명/작성 시각/조회수 메타
2. 게시글 제목
3. HTML 본문 및 본문 이미지 미리보기
4. 첨부파일 목록과 다운로드 버튼
5. 좋아요, 북마크, 댓글 수 등 반응 영역
6. 댓글 목록, 이전 댓글 로드, 댓글 입력, 답글, 댓글 수정·삭제
7. 게시글 작성자 본인에게만 표시되는 더보기 메뉴
8. 닫기 버튼

- 본문 이미지는 기존 이미지 뷰어를 사용한다.
- 첨부파일은 기존 다운로드 콜백과 파일 식별자를 사용한다.
- 댓글 입력·수정은 기존 `CommentThread`와 contentEditable 동작을 사용한다.
- 패널 내부 스크롤을 사용하며 페이지 전체 가로 스크롤은 발생하지 않아야 한다.
- 데스크톱 패널은 기존 우측 슬롯 너비 안에서 렌더링하고, 긴 본문·파일명은 줄바꿈 또는 내부 스크롤로 처리한다.
- 모바일 패널은 전체 화면으로 표시하고 상단에 닫기 버튼을 고정한다.

## 5. 게시글 관리 권한

- API 모델의 `writerId`와 현재 인증 사용자의 식별자를 정규화하여 비교한다.
- 작성자 ID 비교는 표시명, 메타 문자열, 화면 텍스트를 사용하지 않는다.
- `isPostOwner === true`일 때만 게시글 더보기 메뉴와 수정·삭제 액션을 렌더링한다.
- `isPostOwner === false`이거나 작성자 식별 정보가 없으면 게시글 수정·삭제 메뉴를 표시하지 않는다.
- 수정은 기존 작성/수정 모달을 열고, 삭제는 기존 확인·삭제 흐름을 호출한다.
- 댓글 권한은 댓글별 `isEditable`를 사용하며 게시글 권한과 혼합하지 않는다.

## 6. 데이터·액션 어댑터 계약

공통 패널은 게시판별 API를 직접 호출하지 않는다. 화면별 어댑터가 다음 데이터를 제공한다.

```ts
type PostDetailAdapter<TPost, TComment, TAttachment> = {
  getPostId: (post: TPost) => number;
  getTitle: (post: TPost) => string;
  getBody: (post: TPost) => { text: string; html?: string };
  getAuthor: (post: TPost) => {
    id?: string | null;
    label: string;
    meta: string;
  };
  isPostOwner: (post: TPost) => boolean;
  getAttachments: (post: TPost) => TAttachment[];
  getComments: (post: TPost) => TComment[];
  actions: {
    onClose: () => void;
    onEditPost?: () => void;
    onDeletePost?: () => void;
    onToggleLike?: () => void;
    onToggleBookmark?: () => void;
    onDownloadAttachment?: (attachment: TAttachment) => void;
  };
};
```

- 실제 구현에서는 기존 공지 타입과 콜백을 우선 사용하고, 불필요한 범용 타입을 과도하게 도입하지 않는다.
- 공지사항 어댑터는 `NoticeFeedItem`, `NoticeBoardPostApi`, 기존 인증 저장소와 공지 액션 핸들러를 연결한다.
- 게시판·자료실 적용은 이번 작업에 포함하지 않으며, 어댑터 경계만 재사용 가능하도록 만든다.

## 7. API 계약

기존 API를 재사용하며 백엔드 변경은 없다.

### 7.1 상세 조회

- Method: `GET`
- Path: `/api/v1/groupware/boards/notice/posts/{postId}`
- 성공: 기존 응답의 `item` 또는 `result`를 공지 화면 모델로 변환하고 본문·조회수·첨부·댓글·`writerId`를 선택 게시글에 병합한다.
- `401`: 기존 인증 오류 처리와 세션 로그아웃 정책을 유지한다.
- `403`: 목록을 유지하고 상세 패널에 접근 오류를 표시한다.
- `404`: 선택 게시글이 삭제된 상태로 처리하고 오류 메시지와 닫기 동작을 표시한다.
- 기타 오류: 목록을 유지하고 오류 알림/패널 오류 상태를 표시한다.

### 7.2 기존 액션

- 좋아요·북마크: 기존 공지 액션 API와 콜백을 사용한다.
- 댓글·답글·댓글 수정·삭제·댓글 첨부: 기존 공지 콜백을 사용한다.
- 첨부 다운로드: 기존 `boardFileId`, `objectKey`, `bucketName` 계약을 사용한다.
- 게시글 수정·삭제: 작성자 본인에게만 기존 수정 모달·삭제 핸들러를 연결한다.

## 8. 반응형 사양

- `1280px`: 좌측 목록과 우측 상세를 동시에 표시한다.
- `768px`: 기존 레이아웃 브레이크포인트에 맞춰 상세를 전체 화면 드로어/모달로 표시한다.
- `375px`: 상세가 뷰포트 전체 너비를 사용하고 본문·첨부·댓글이 내부 스크롤되며, 페이지 가로 스크롤은 없어야 한다.
- 패널의 닫기 버튼, 제목, 게시글 메뉴, 댓글 입력은 서로 겹치지 않아야 한다.
- 테스트는 DOM 존재 여부뿐 아니라 실제 브라우저의 `scrollWidth`, 주요 요소 rect, 스크린샷으로 검증한다.

## 9. 회귀 검증 기준

1. 리스트형 공지 클릭으로 상세 패널이 열린다.
2. 상단 고정 공지 클릭으로 동일 상세 패널이 열린다.
3. 다른 공지 선택으로 패널 내용이 교체된다.
4. 닫기 버튼으로 기존 요약 패널이 복원된다.
5. 상세 패널이 피드 카드와 동일한 본문·첨부·반응·댓글 기능을 제공한다.
6. 게시글 작성자 본인 글에만 더보기 메뉴가 표시된다.
7. 비작성자 글에는 게시글 수정·삭제 메뉴가 표시되지 않는다.
8. 댓글 작성자별 수정·삭제 권한이 유지된다.
9. 상세 조회 실패 시 목록이 사라지지 않는다.
10. 피드형 기존 인라인 상세 동작이 회귀하지 않는다.
11. 375px·768px·1280px에서 겹침·잘림·가로 스크롤이 없다.
12. 관련 테스트와 프론트 빌드가 통과한다.

## 10. DB 영향

DB 스키마 및 백엔드 API 계약 변경 없음. 별도 SQL, 롤백 스크립트, DB 스키마 문서 갱신은 작성하지 않는다.
