# 통합검색 Java 8 호환 상세사양서

근거: [계획서](../../plan/20261102/20261102_009_통합검색_Java8호환_계획서.md).

- `TYPES`는 변경 불가능한 MENU/DOCUMENT/NOTICE 순서를 유지하되 Java 8 API로 생성한다.
- 단일 유형은 `Collections.singletonList`, 권한 없는 결과는 `Collections.emptyList`로 생성한다.
- 사용자 ID 및 결과 설명의 null/빈값/Unicode whitespace 판정은 Spring `StringUtils.hasText`를 사용해 기존 `String.isBlank`의 의미를 유지한다. `trim().isEmpty()`로 Unicode 공백 처리를 축소하지 않는다.
- 테스트는 검색·실시간 패키지의 실제 production 소스를 Java 8 플랫폼 API 대상으로 컴파일하여 `source/target=1.8`만으로 누락된 API 검사를 보완한다. 다른 업무 전체의 Java 8 호환성을 보증하는 테스트가 아니다.
- 검색 API 응답, 인증/권한, Mapper/SQL/스키마는 변경하지 않는다. DB 계약 작업이 아니므로 이번 수정에 별도 DB 조회가 필요하지 않다.
- 운영 시작 실패는 검색 서비스 static 초기화의 `List.of` 연결 오류다. 이전 종료 로그의 DB close 경고를 직접 원인으로 처리하지 않는다.
- 개발 JDK는 기존 Java 17+ 기준을 유지한다. 이 패치는 운영 Java 8에서 확인된 검색 코드의 API 호출을 수정하며 전체 의존성·운영 기동 성공을 단정하지 않는다.
