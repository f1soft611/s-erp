# 메뉴 즐겨찾기 상세사양서

기준: [작업지시서](../../directions/20261102/20261102_002_메뉴_즐겨찾기_작업지시서.md), [승인 설계](../../superpowers/specs/2026-11-02-menu-favorites-design.md)

## 1. 데이터 계약

### `tb_user_menu_favorite_folder`

| 컬럼 | 타입/규칙 | 설명 |
|---|---|---|
| favorite_folder_id | BIGSERIAL PK | 폴더 ID |
| tenant_id | BIGINT NOT NULL, tenant FK | 테넌트 경계 |
| user_id | BIGINT NOT NULL, user FK | 소유 사용자 |
| folder_nm | VARCHAR(40) NOT NULL | trim 후 1~40자 |
| created_at | TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP | 생성 시각 |
| updated_at | TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP | 수정 시각 |

- 폴더는 루트의 직계 자식만 지원한다. 폴더 상위 폴더 ID는 저장하지 않는다.
- 동일 사용자에게 같은 이름의 폴더를 복수 생성할 수 있다. UI는 ID로 식별한다.
- 조회 정렬은 `favorite_folder_id ASC`로 고정하며 첫 버전에 사용자 정렬 변경 기능은 없다.

### `tb_user_menu_favorite`

| 컬럼 | 타입/규칙 | 설명 |
|---|---|---|
| favorite_id | BIGSERIAL PK | 즐겨찾기 항목 ID |
| tenant_id | BIGINT NOT NULL, tenant FK | 테넌트 경계 |
| user_id | BIGINT NOT NULL, user FK | 소유 사용자 |
| menu_id | BIGINT NOT NULL, menu FK | 원본 메뉴 |
| favorite_folder_id | BIGINT NULL | NULL이면 루트, 값이 있으면 지정 폴더 |
| favorite_nm | VARCHAR(100) NULL | 사용자 지정 표시명, NULL이면 권한 메뉴의 원래 이름 |
| created_at | TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP | 생성 시각 |
| updated_at | TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP | 이동/표시명 변경 시각 |

- UNIQUE `(tenant_id, user_id, menu_id)`로 메뉴 중복 저장을 방지한다.
- folder composite reference `(favorite_folder_id, tenant_id, user_id)`는 해당 사용자가 소유한 폴더만 참조하게 한다. FK 대상에 필요한 고유 키는 폴더 테이블에 선언한다.
- 물리적으로 삭제되는 원본 메뉴는 즐겨찾기 참조가 고아가 되지 않도록 FK cascade로 정리한다. 비활성/권한 상실 메뉴 레코드는 삭제하지 않는다.
- 소유자 및 tenant 일치 검증은 모든 API SQL에서 `(tenant_id,user_id)` 조건으로 강제한다.
- 저장 DDL, FK 가용성 및 기존 PK/고유 제약은 구현 시작 시 PostgreSQL MCP metadata와 대조한다. 실제 DB에는 DDL을 적용하지 않는다.

## 2. API 계약

모든 endpoint는 `/api/v1/menus/favorites` 하위이며 인증된 `LoginVO`를 사용한다. 요청은 `userId`, `tenantId`를 받지 않는다. 응답은 기존 `ResultVO` 패턴을 따른다.

| Method / path | 요청 | 응답/동작 |
|---|---|---|
| GET `/api/v1/menus/favorites` | 없음 | `{folders: FavoriteFolder[], favorites: FavoriteMenu[]}`. 모든 사용 폴더 포함, 현재 접근 가능한 메뉴 항목만 반환 |
| POST `/api/v1/menus/favorites/folders` | `{folderName}` | 생성된 `{folderId, folderName}` |
| PUT `/api/v1/menus/favorites/folders/{folderId}` | `{folderName}` | 소유 폴더명 변경 |
| DELETE `/api/v1/menus/favorites/folders/{folderId}` | 없음 | 비어 있는 소유 폴더만 삭제; 사용 중이면 409 |
| POST `/api/v1/menus/favorites` | `{menuId, folderId?, favoriteName?}` | 현재 사용자의 leaf 메뉴 추가; 이름은 trim 후 1~100자, `folderId` 누락/null은 루트 |
| PUT `/api/v1/menus/favorites/{favoriteId}/location` | `{folderId?, favoriteName?}` | 같은 사용자 소유 루트/폴더로 이동하고 표시명 저장; null folder는 루트, 이름 누락은 기존 이름 보존 |
| DELETE `/api/v1/menus/favorites/{favoriteId}` | 없음 | 현재 사용자의 즐겨찾기 해제 |

`FavoriteMenu` 응답은 `favoriteId`, `menuId`, nullable `folderId`, `favoriteName`을 제공한다. `favoriteName`이 NULL이면 화면은 현재 권한 메뉴 트리의 원래 이름을 표시한다. URL/모듈명은 현재 `GET /api/v1/menus/my` 권한 트리에서 `menuId` 기준으로 구성하며, 클라이언트 URL은 저장하거나 신뢰하지 않는다.

### 오류 상태

- 400: 잘못된/없는 ID, 잘못된 folder name, 이동 대상 형식 오류, 그룹/경로 없는 메뉴.
- 401: 인증 사용자/tenant principal 누락.
- 403: 메뉴가 다른 tenant, 비활성 또는 사용자 권한 밖임.
- 404: 현재 사용자가 소유하지 않은 폴더/즐겨찾기.
- 409: 메뉴 중복 등록, 비어 있지 않은 폴더 삭제.
- DB/API 오류는 기존 공통 ResultVO 오류 매핑으로 전파하고 빈 성공 응답으로 대체하지 않는다.

## 3. 권한 및 검증

- `tenantId`는 `LoginVO.getTenantId()`, 실제 사용자 PK는 `LoginVO.getUniqId()`를 양의 정수로 검증해 사용한다. 권한 메뉴 트리 확인에는 기존 `/menus/my`와 동일하게 로그인 코드/역할을 전달한다.
- 폴더 CRUD 및 즐겨찾기 CRUD는 모든 SQL에서 인증 소유자와 tenant 조건으로 제한한다.
- 메뉴 저장/이동 시 `SystemMenuService.getMyMenuTree`로 구성한 현재 권한 트리에서 `menuId`가 활성 leaf인지 확인하고 `permissions.read == true`인지 검사한다. 해당 트리에는 활성 메뉴가 모두 포함되고 비인가 leaf는 false 권한으로 나타날 수 있으므로 트리 존재만으로 권한을 인정하지 않는다. parent/group 또는 URL 없는 노드는 불가하다.
- GET 응답은 저장된 항목을 현재 권한 트리의 menu IDs와 inner intersection으로 필터한다. 폴더는 빈 폴더도 포함한다.
- 동일 메뉴 중복 추가 시 409, 이동은 같은 즐겨찾기 레코드의 `favorite_folder_id`를 갱신한다.
- 루트 추가/이동에서 nullable `folderId`는 MyBatis parameter에 `jdbcType=BIGINT`를 명시해 PostgreSQL의 nullable `BIGINT` 컬럼과 호환되게 바인딩한다.
- 폴더 삭제는 소유권 확인 후 연결된 favorite row가 0일 때만 삭제한다. 폴더 삭제/메뉴 추가와의 동시성은 FK/transaction으로 일관되게 처리한다.

## 4. 화면 상태 및 상호작용

### 가상 모듈과 메뉴 트리

- 가상 모듈 ID는 `__favorites__`로 고정하며 실제 module descriptors에는 저장하지 않는다.
- 레일/사이드바의 즐겨찾기 패널 선택은 URL에서 계산하는 실제 모듈 선택과 별도 상태다. 가상 패널 선택은 현재 메뉴의 콘텐츠, breadcrumb, 권한, URL 또는 최근 사용 기록을 바꾸지 않는다. 실제 모듈 선택 시 가상 패널 선택을 해제하고, 즐겨찾기 메뉴 선택 시 기존 허용 URL로 이동한다.
- `folders.length > 0` 또는 접근 가능한 favorite 메뉴 수가 0보다 큰 조건을 가상 모듈 표시 기준으로 삼지 않는다. 승인된 규칙은 **메뉴 즐겨찾기 수가 1개 이상**일 때 표시한다. 빈 폴더만 남으면 모듈은 숨고 일반 메뉴 위치 선택 창에서 폴더를 관리한다.
- 즐겨찾기 가상 모듈 선택 시 루트에 배치된 메뉴와 폴더 TreeItem을 보여준다. 폴더 TreeItem의 자식은 해당 폴더 메뉴다.
- 빈 폴더는 가상 모듈이 표시되는 동안 보이며, 빈 상태 안내와 헤더의 `새 폴더` 버튼을 제공한다. 버튼은 바로 폴더 생성 모달을 연다.
- 즐겨찾기 leaf 선택은 응답의 numeric `menuId`를 권한이 있는 `MenuTreeNode`/`MenuItem`의 numeric ID와 대조해 원래 module/menu/path/permission으로 이동한다. 기존 path 기반 string 메뉴 ID는 이동 후 기존 선택 표시/라우팅에만 사용하며, 즐겨찾기 식별자로 쓰지 않는다. path 문자열로 권한을 추측하지 않는다.
- 열려 있는 메뉴가 즐겨찾기 모듈에서도 선택 상태로 표시될 수 있도록 원본 menuId를 사용한다.

### Context menu와 접근성 대체

| 대상 | 제공 동작 |
|---|---|
| 일반 모듈의 `READ` 권한 leaf | 행 앞 별 아이콘으로 편집 모달 열기/루트 즐겨찾기 등록, 우클릭/키보드 메뉴로 위치 선택 및 폴더 관리. 별도 더보기 버튼은 제공하지 않음 |
| 즐겨찾기 모듈 헤더 | `새 폴더` 버튼으로 폴더 생성 모달 바로 열기; 우클릭으로도 폴더 만들기 |
| 폴더 | 이름 변경, 빈 폴더 삭제, 메뉴 이동 대상 |
| 즐겨찾기 메뉴 | 원래 메뉴 열기, 루트/다른 폴더로 이동, 즐겨찾기 해제 |

- 일반 메뉴는 권한 `READ`가 true인 leaf에만 별 아이콘을 표시한다. 미등록은 빈 별, 등록은 채운 별로 나타낸다.
- 빈 별 클릭은 루트 즐겨찾기를 등록한 뒤 편집 모달을 연다. 채운 별 클릭도 동일 편집 모달을 연다. 별 클릭은 현재 메뉴 선택/URL 이동을 유발하지 않는다.
- 편집 모달은 공통 `CommonDialog`를 사용하고 이름, 읽기 전용 URL, 루트 기본값의 폴더 선택, `더보기`, `완료`, `제거`를 제공한다. 편집 모달 안에서는 새 폴더를 만들지 않으며 폴더는 즐겨찾기 모듈의 헤더 버튼 또는 메뉴 컨텍스트 메뉴에서 생성한다.
- `완료`는 표시명과 폴더를 함께 저장하며, `제거`는 즐겨찾기를 삭제한다. 저장/삭제 실패 시 입력값과 모달을 유지하고 오류를 표시한다. 닫기는 추가 변경 없이 루트 등록 상태를 유지한다.
- `더보기`는 모달을 닫고 즐겨찾기 가상 모듈을 선택한다. 현재 메뉴 선택과 라우트는 변경하지 않는다.
- 우클릭/터치 길게 누르기는 브라우저 메뉴 대신 MUI 메뉴를 연다. 포인터 이벤트의 좌표를 기준으로 화면 안에 배치한다.
- 메뉴 행에 포커스한 뒤 `Shift+F10` 또는 키보드 메뉴 키로도 같은 MUI 메뉴를 열 수 있다.
- 일반 메뉴의 우클릭 메뉴에서는 즐겨찾기 위치 선택과 함께 폴더 생성/이름 변경/빈 폴더 삭제를 제공해 즐겨찾기 가상 모듈이 숨겨진 상태에서도 폴더를 관리할 수 있다.
- 별 버튼은 `aria-pressed`로 등록 상태를 제공하며, 접근성 이름은 추가/편집 상태를 구분한다.
- 폴더 생성/이름 변경은 공통 모달/폼에서 1~40자 검증한다. 이름은 trim하여 전송한다.
- 메뉴 위치 선택 창은 현재 루트와 모든 사용자 폴더를 제공하며, 0 favorites일 때에도 일반 메뉴 우클릭에서 폴더를 관리할 수 있다.
- 폴더를 비울 때 삭제를 허용한다. 비어 있지 않은 폴더 삭제는 서버 409 메시지를 안내하고 항목을 자동 이동/해제하지 않는다.
- 중첩 폴더 및 drag/drop 순서 변경은 제공하지 않는다.

### 오류와 동기화

- GET loading/error/empty 상태를 분리하고 조회 실패 시 재시도를 제공한다.
- 모든 변경은 성공 후 서버 목록을 다시 조회해 일관성을 확보한다. 요청 중 관련 action은 중복 제출을 막는다.
- 변경 실패 시 오류를 알리고 기존 항목/폴더 상태는 유지한다.
- 메뉴 접근권한이 바뀌어 server response에서 항목이 제외되면 UI가 그 항목을 렌더링하지 않는다. 저장 레코드는 서버에 남긴다.
- 로그아웃/계정 전환 시 메모리 캐시는 초기화하며 DB 데이터는 소유자별로 분리한다.

## 5. DB 및 Mapper 확인 내역

- 이전 읽기 전용 MCP에서 `list_tables`로 `tb_menu`, `tb_user`가 있고 즐겨찾기 전용 테이블은 없음을 확인했다.
- `describe_table(tb_menu)`에서 `menu_id`, `tenant_id`, `module_id`, `parent_menu_id`, `menu_url`, `use_at`을 확인했다.
- `describe_table(tb_user)`에서 `user_id`, `tenant_id`, `use_at`을 확인했다.
- 구현 시작 세션에서 도구 가용성에 따라 metadata를 다시 조회한다. 이 detailed spec 작성 시점에 직접 호출 가능한 DB MCP tool은 노출되지 않았으므로 FK 및 기존 constraint metadata는 구현 전 재확인 항목이다. DB 행 데이터는 조회하지 않았다.

## 6. 테스트 및 완료 기준

- 백엔드: 인증 소유권, tenant 격리, `READ` 권한이 있는 유효 leaf, 중복 방지, 폴더 이름 제한, empty-only delete, 이동/루트 이동, 접근 불가 항목 필터링, DB cascade/rollback 계약.
- 프런트엔드: API 서비스, 가상 모듈 표시 조건, 실제 메뉴 경로 이동, 별 등록 후 공통 편집 모달, 이름/폴더 저장, 삭제, 저장 실패 시 draft 유지, `더보기` 가상 모듈 전환, 직접 새 폴더 생성과 메뉴 비선택.
- 브라우저: 375px, 768px, 1280px에서 편집 모달 표시/필드 및 가로 overflow를 확인하고 스크린샷을 저장한다.
- 최종 결과 문서는 `docs/result/20261102/menu-favorites/README.md`와 `screenshots/`에 남긴다.
