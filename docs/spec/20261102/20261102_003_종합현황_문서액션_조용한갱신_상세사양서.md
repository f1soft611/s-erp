# 20261102_003 종합현황 문서 액션 조용한 갱신 상세사양서

## 동작 정의

### 상세 열기

- 종합현황의 결재/확인 목록 항목은 기존 전자결재 상세 오버레이를 즉시 연다.
- 오버레이의 최초 상세 로딩 및 권한 확인 흐름은 변경하지 않는다.

### 액션 처리 및 갱신

- 승인, 반려, 보완요청, 참조확인, 최종확인 API 요청 중 기존 처리 버튼은 비활성화된다.
- 액션 실패 시 기존 상세의 해당 오류 표시 영역을 사용하며 summary를 성공 상태로 처리하지 않는다.
- 액션 성공 시 기존 성공 알림을 유지하고 다음을 갱신한다.
  - 종합현황 overview summary: 기존 현황 콘텐츠를 유지한 상태로 재조회한다. 성공 응답을 받으면 새 값으로 교체한다.
  - 열린 상세 및 SYSTEM 이력: 기존 상세 콘텐츠를 유지하며 spinner/로딩 overlay 없이 재조회한다.
- 조용한 갱신 요청 실패는 기존 오류 처리 경로에서 표시한다. 이전 데이터가 계속 보이는 요청 중에는 오류를 숨기지 않는다.
- 액션이 끝난 뒤에도 문서 상세 오버레이는 열린 상태로 유지한다.

## 구현 계약

- overview hook의 `refresh`는 기존 일반 새로고침 동작을 보존한다. 별도 `refreshQuietly`는 진행 중 skeleton으로 전환하지 않고 마지막 overview 데이터를 반환한다.
- overview 데이터 객체가 새로 바뀌어도 권한 및 선택 월이 그대로면 수주 데이터는 재조회하지 않아, 액션과 무관한 수주 위젯이 로딩 skeleton으로 바뀌지 않게 한다. 월 또는 조회 권한 변경, 일반 새로고침 및 사용자의 수주 새로고침은 기존대로 동작한다.
- `OverviewPage`의 액션 완료 옵션 `{ quiet: true }`는 summary quiet refresh만 수행한다. 상세 갱신은 상세 feed 내부 quiet reload가 맡아 중복 요청을 피한다.
- 상세 feed의 결재/확인 성공은 상위에 `{ quiet: true }`를 전달하고 자체 상세 재조회도 quiet 모드로 실행한다.
- `quiet`는 표시만 조용하게 유지하는 옵션이며 요청 취소, 응답 생략, 실패 무시 의미가 아니다.

## 검증 기준

- 상세 진입 후 액션 완료 시 overview endpoint가 재호출되고, 두 번째 응답이 대기 중이어도 이전 summary 및 상세 DOM이 유지된다.
- 갱신 중 종합현황 전체 skeleton 또는 상세 loading overlay가 표시되지 않는다.
- 응답 완료 뒤 summary가 최신 값으로 바뀐다.
- 기존 액션 버튼 pending 및 API 오류 표시가 그대로 동작한다.
- 문서작성/문서현황의 기존 액션 갱신 동작과 기존 새로고침 동작을 회귀 검증한다.
- 프런트엔드 빌드, 관련 테스트 및 모바일/태블릿/데스크톱 실제 브라우저 레이아웃을 확인한다.
