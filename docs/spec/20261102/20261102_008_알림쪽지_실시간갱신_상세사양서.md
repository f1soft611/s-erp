# 알림·쪽지 실시간 갱신 상세사양서

근거: [작업지시서](../../directions/20261102/20261102_008_알림쪽지_실시간갱신_작업지시서.md), [계획서](../../plan/20261102/20261102_008_알림쪽지_실시간갱신_계획서.md).

## 계약

- `GET /api/v1/groupware/realtime`: 기존 Bearer 인증. principal에서 tenantId/양수 userId를 검증하며 요청에서 사용자/tenant를 받지 않는다.
- `Content-Type: text/event-stream`, cache 금지, 프록시 buffering 비활성 헤더.
- `event: ready`/`data: {}`는 연결 후 기존 상태 재조회 신호다.
- `event: change`/`data: {"area":"NOTIFICATION"}` 또는 `{"area":"MESSAGE"}`. 본문/계정/소유자/토큰/URL을 보내지 않는다.
- 15초 간격 comment heartbeat, 최대 45초 연결 후 종료 및 재인증 연결. 인증 실패는 기존 보안 정책을 적용하며 토큰을 URL에 넣지 않는다.
- 정리: completion/timeout/error/send 실패 때 연결을 제거한다. 소유자별 연결 수는 제한하고 오래된 연결을 정리한다.

## 발행과 수렴

- 활성 쓰기 트랜잭션 commit 이후에만 publish한다. rollback/DB 실패에는 신호가 없다. 전송 장애가 업무 저장 성공을 실패로 바꾸면 안 된다.
- 알림 생성/읽음/보관은 수신자 NOTIFICATION, 새 쪽지/답장/숨김은 관련 사용자 MESSAGE, 받은 대화 읽음은 본인 NOTIFICATION 및 양쪽 MESSAGE를 갱신한다. 변경 없는 읽음 반복은 불필요한 메시지 신호를 만들지 않는다.
- 서버 registry는 JVM 내 연결이다. 해당 JVM에서 commit된 변경은 즉시 전달한다. 별도 브로커를 추가하지 않으며 다중 서버의 즉시 fan-out을 보장하지 않는다.
- 표시 중인 클라이언트는 30초마다 양쪽 상태를 REST 재조회하고, 재연결/화면 복귀 시에도 재동기화한다. 다른 JVM/누락/네트워크 오류는 이 방식으로 수렴한다. 오프라인 동안 즉시 전달을 보장하지 않는다.

## 클라이언트

- 앱 루트에 인증 사용자당 탭별 연결 1개. 토큰은 기존 auth helper를 통해 갱신하고 Authorization 헤더로만 전송한다.
- 로그아웃/계정 변경/탭 숨김/unmount 시 abort, reader 및 retry/동기화 타이머를 정리한다. 복귀 시 연결/재동기화한다.
- fetch SSE 파서는 chunk 경계/CRLF/comment를 처리하고 ready/change만 받아 250ms 합쳐 `s-erp:realtime` CustomEvent의 areas 배열로 알린다. 잘못된 데이터는 무시한다.
- 끊김/실패는 최대 30초까지 backoff 재연결하며 매번 사용자에게 토스트를 반복하지 않는다. 재동기화 API 실패는 기존 화면을 유지한다.
- 배지와 열린 팝오버/알림함은 최신 상태를 반영한다. 알림함 필터를 보존하며 로딩된 범위에서 새 목록/읽음/보관 상태를 갱신한다.
- 쪽지함은 목록/선택 대화의 최신 날짜를 합치고 이전 날짜/작성 중 답장/스크롤을 보존한다. 선택한 대화가 갱신된 첫 목록에서 사라져도 선택 대화를 별도로 조회한다.
- 요청 중 추가 신호는 버리지 않고 병합 후 한 번 더 갱신한다. 선택 변경/unmount/새 조회 뒤 과거 응답을 적용하지 않는다.
- 메시지 읽음 변화만으로 스크롤을 하단 이동시키지 않는다. 기존 하단 근처에서 새 메시지를 받으면 하단을 따른다.

## 확인 및 비범위

기본 DB MCP `list_tables` → `describe_table`로 tb_notification의 owner/read/archive, tb_direct_message의 참여자/read/thread, tb_direct_message_thread의 참여자/hidden 컬럼을 확인했다. 행/자격 증명 조회는 하지 않았다. 신규 SQL/스키마/DDL은 없다.

기존 인증/테넌트/참여자/조회권한 정책과 데이터 응답은 유지한다. 웹 푸시/Service Worker/OS 알림/브로커/새 업무 이벤트/검색 대상은 포함하지 않는다. 프록시는 SSE streaming을 허용해야 하며 버퍼링 환경에서도 30초 REST 재동기화는 유지한다.
