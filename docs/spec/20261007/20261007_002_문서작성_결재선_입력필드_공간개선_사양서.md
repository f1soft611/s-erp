## 2. 결재선 필드 구조

- 결재선은 순번 기준 왼쪽에서 오른쪽으로 흐른다.
- 확정된 각 단계는 순서대로 번호와 역할을 표시한다. 역할 표기는 `결재 n` 또는 `합의 n`으로 한다.
- 확정 단계마다 `UserSelectEditor` 입력을 보여 주며 선택값은 사용자 칩으로 유지한다. 확정 필드는 `readOnly`이고 후보 옵션은 전체 사용자 목록에서 가져와 칩을 계속 표시할 수 있어야 한다.
- `UserSelectEditor`가 `readOnly`일 때 선택 칩에 삭제 액션을 렌더링하지 않는다. 편집 가능한 선택기의 현재 칩 삭제 동작과 기본값은 바꾸지 않는다.
- 확정 필드는 기존 단계 삭제 액션을 유지한다. 삭제 후 이후 단계 번호는 연속 번호로 다시 표시한다.
- 확정 단계의 기존 도장 자리 표시를 유지한다.
- 확정 단계 뒤에는 사용자를 추가할 수 있는 활성 다중 선택 입력을 항상 하나 둔다. 최초 활성 입력은 `결재선 1 사용자 선택`; `n`개의 확정 단계 뒤에는 `결재선 n+1 사용자 선택`으로 표시한다.
- `결재 추가`와 `합의 추가` 액션은 활성 입력에만 한 번 표시한다. 활성 입력 값이 비어 있으면 두 액션 모두 비활성이다.
- 확정 후 hook의 기존 동작대로 활성 선택값을 비우고 다음 번호의 입력을 표시한다.

## 3. 결재와 합의 확정 의미

- 활성 입력은 다중 선택이다.
- `결재 추가` 시 선택 배열의 각 사용자를 선택 순서대로 독립된 `approval` 단계로 만든다. 복수 사용자를 선택한 경우 각 사용자는 각각 번호를 차지하며, 해당 순서의 읽기 전용 입력 칩으로 표시한다.
- `합의 추가` 시 선택한 전체 사용자를 하나의 `agreement` 단계로 묶고 한 개의 읽기 전용 입력에 칩으로 표시한다.
- 각 확정 단계에 이미 등록된 사용자는 활성 결재선 후보 목록에서 제외한다.
- 단계를 삭제하면 해당 사용자들이 후보 목록에 다시 나타난다.
- 추가 입력이나 단계 목록은 클라이언트 작성 상태이며 저장/상신 API에 전달하지 않는다.

## 4. 참조선

- 참조선은 기존 사용자 옵션을 사용하는 다중 선택 입력 하나다.
- 이미 선택한 참조자는 드롭다운 후보에서 숨기고 입력 칩으로만 표시한다.
- 필드 아래에 참조 사용자 요약 목록을 중복 표시하지 않는다.
- 결재선과 참조선 간 중복 제한은 없다. 참조 선택은 결재 단계 추가/삭제 및 도장 표시에 영향을 주지 않는다.

## 5. 레이아웃 및 스크롤

- 결재 단계 입력과 마지막 활성 입력을 하나의 가로 흐름으로 배치하고 인접 단계 사이에 장식용 `>`를 유지한다.
- 결재선 가로 흐름에는 `overflow-x: auto`를 적용해 좁은 화면에서 흐름 내부만 스크롤한다. 전체 페이지/다이얼로그의 가로 폭은 확장하지 않는다.
- 각 단계/입력의 너비는 콘텐츠와 사용자가 읽을 수 있는 필드 크기를 고려해 제한하고 flex 축소가 부모 너비를 침범하지 않도록 한다.
- 참조선은 기존 반응형 그리드 배치를 유지한다.
- 긴 본문 에디터 자연 높이, `CommonDialog` 콘텐츠 세로 스크롤, 고정 헤더/푸터 동작은 선행 사양대로 유지한다.

## 6. 변경하지 않을 사항

- 공통 선택기/에디터/모달의 기본 동작, 프로필 및 양식 조회 계약, 페이지 라우팅은 변경하지 않는다.
- 저장, 상신, 실제 결재 API, 권한, 백엔드, 데이터베이스 변경을 추가하지 않는다.
- 템플릿 교체 확인, 오류/로딩 표시, 모달 종료 초기화, 첨부 동작은 보존한다.

## 7. 검증 기준

### 자동 테스트

- 최초 활성 입력의 접근성 이름이 `결재선 1 사용자 선택`이고 비어 있는 결재/합의 액션이 비활성인지 확인한다.
- 두 명 이상 선택 후 `결재 추가` 시 선택 순서대로 독립된 읽기 전용 결재 단계가 생기고 그 다음 번호의 빈 활성 입력이 추가되는지 확인한다.
- 두 명 이상 선택 후 `합의 추가` 시 한 합의 단계에 모두 유지되고 다음 번호의 빈 활성 입력이 추가되는지 확인한다.
- 확정 입력은 읽기 전용이고 활성 입력만 후보 선택 및 역할별 추가 동작을 허용하는지 확인한다.
- read-only 선택 칩에는 삭제 affordance가 없고 기본 편집 가능 선택기 칩은 기존 삭제 동작을 유지하는지 확인한다.
- 결재/합의 사용자 후보 제외, 단계 삭제 후 후보 복원 및 순번 갱신을 확인한다.
- 참조 다중 선택 칩, 후보 숨김, 요약 DOM 부재 및 결재선 독립성을 확인한다.
- 단계 스트립에 내부 가로 스크롤 스타일이 있고 문서작성 모달의 기존 에디터 스크롤 테스트가 유지되는지 확인한다.
