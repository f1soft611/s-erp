## 2. 결재선 필드 구조

- `결재선` 라벨은 왼쪽에 표시하고 오른쪽에 확정 단계 카드, 활성 사용자 선택 필드, `결재 추가`/`합의 추가` 버튼을 한 흐름으로 배치한다.
- `참조` 라벨과 다중 선택 필드는 결재선 바로 아래 별도 행으로 두고 결재선과 같은 라벨/필드 정렬을 사용한다.
- 각 확정 카드에는 순번, 구분(`결재`/`합의`), 프로필 이미지, 사용자 이름/부서, 도장 자리, 단계 전체 삭제(X)를 한 줄로 표시한다.
- 카드 높이와 결재 추가/합의 추가 버튼 높이는 활성 사용자 선택 필드의 렌더링 높이와 같게 맞춘다. 사용자 이미지와 도장은 필드 높이를 넘지 않게 한다.
- 결재 단계는 한 명씩 개별 카드로 표시하고 합의 단계는 한 카드 안에 합의자들을 함께 표시한다.
- 카드 삭제(X)는 결재/합의 단계 전체를 제거하며, 후속 순번을 갱신하고 제거된 사용자는 활성 선택 후보로 복원한다.
- 확정 사용자는 활성 결재선 후보에서 제외한다. 추가 선택 필드는 항상 하나를 유지한다. 최초 활성 입력은 `결재선 1 사용자 선택`; `n`개의 확정 단계 뒤에는 `결재선 n+1 사용자 선택`으로 표시한다.
- 활성 입력 값이 비어 있으면 `결재 추가`와 `합의 추가` 버튼은 비활성이다.
- 결재/참조 선택 후보가 비어 있을 때 `선택 가능한 사용자가 없습니다.` 안내 문구는 표시하지 않는다.
- 확정 후 hook의 기존 동작대로 활성 선택값을 비우고 다음 번호의 입력을 표시한다.

## 3. 결재와 합의 확정 의미

- 활성 입력은 다중 선택이다.
- `결재 추가` 시 선택 배열의 각 사용자를 선택 순서대로 독립된 `approval` 단계/카드로 만든다.
- `합의 추가` 시 선택한 전체 사용자를 하나의 `agreement` 단계/카드로 묶어 표시한다.
- 각 확정 단계에 이미 등록된 사용자는 활성 결재선 후보 목록에서 제외한다.
- 단계를 삭제하면 해당 사용자들이 후보 목록에 다시 나타난다.
- 추가 입력이나 단계 목록은 클라이언트 작성 상태이며 저장/상신 API에 전달하지 않는다.

## 4. 참조선

- 참조선은 결재선 바로 아래 독립 행의 다중 선택 입력 하나다.
- 이미 선택한 참조자는 드롭다운 후보에서 숨기고 입력 칩으로만 표시한다.
- 필드 아래에 참조 사용자 요약 목록이나 사용자 없음 안내를 중복 표시하지 않는다.
- 결재선과 참조선 간 중복 제한은 없다. 참조 선택은 결재 단계 추가/삭제 및 도장 표시에 영향을 주지 않는다.

## 5. 레이아웃 및 스크롤

- 결재 카드와 활성 입력/버튼을 같은 콘텐츠 행에 순서대로 배치한다. 카드 사이에 장식용 `>`는 표시하지 않는다.
- 결재선 오른쪽 콘텐츠에만 `overflow-x: auto`를 적용하고 라벨은 스크롤 밖에 유지한다. 페이지/다이얼로그 폭을 넓히지 않는다.
- 사용자 카드와 선택 입력은 콘텐츠를 읽을 수 있는 너비로 제한하고 flex 축소가 부모 너비를 침범하지 않게 한다.
- 참조 행은 결재선과 같은 라벨/입력 정렬을 유지하고 바로 아래 표시한다.
- 모달을 열면 본문 에디터가 앞선 입력 필드 아래 남은 높이를 채우며 최소 높이는 180px이다.
- 본문이 남은 높이를 초과하면 에디터가 콘텐츠에 맞게 확장되고 `CommonDialog` 본문이 세로 스크롤한다. 본문 에디터의 상·하단 공백은 동일하게 유지하며 첫/마지막 콘텐츠 블록의 바깥 여백으로 인해 달라지지 않게 한다.
- `CommonDialog`의 고정 헤더/푸터 동작은 유지한다.
- 문서작성 모달은 `CommonDialog`의 표면 배경 override를 사용해 paper/header/content/footer를 흰색으로 표시한다. override가 없는 다른 공통 모달은 기존 테마 배경을 유지한다.

## 6. 변경하지 않을 사항

- 공통 선택기/에디터/모달의 기본 동작, 프로필 및 양식 조회 계약, 페이지 라우팅은 변경하지 않는다.
- 저장, 상신, 실제 결재 API, 권한, 백엔드, 데이터베이스 변경을 추가하지 않는다.
- 템플릿 교체 확인, 오류/로딩 표시, 모달 종료 초기화, 첨부 동작은 보존한다.

## 7. 검증 기준

### 자동 테스트

- 최초 활성 입력의 접근성 이름이 `결재선 1 사용자 선택`이고 비어 있는 결재/합의 액션이 비활성인지 확인한다.
- 두 명 이상 선택 후 `결재 추가` 시 선택 순서대로 독립된 결재 카드가 생기고 그 다음 번호의 빈 활성 입력이 추가되는지 확인한다.
- 두 명 이상 선택 후 `합의 추가` 시 한 합의 카드에 모두 표시되고 다음 번호의 빈 활성 입력이 추가되는지 확인한다.
- 확정 카드에 순번, 구분, 프로필, 이름/부서, 도장 자리, 단계 전체 삭제 버튼이 표시되는지 확인한다.
- 카드, 사용자 선택 필드, 결재/합의 추가 버튼의 높이가 동일한지 확인한다.
- 활성 입력만 후보 선택 및 역할별 추가 동작을 허용하는지 확인한다.
- 결재/합의 사용자 후보 제외, 단계 전체 삭제 후 후보 복원 및 순번 갱신을 확인한다.
- 결재/참조 후보가 비어 있을 때 빈 후보 안내 문구가 표시되지 않는지 확인한다.
- 참조 다중 선택 칩, 후보 숨김, 요약 DOM 부재 및 결재선 독립성을 확인한다.
- 결재선 오른쪽 콘텐츠에만 내부 가로 스크롤이 적용되고 전체 페이지 가로 넘침이 없는지 확인한다.
- 문서작성 모달의 paper/header/content/footer가 흰색이고 다른 `CommonDialog`는 기존 기본 배경을 유지하는지 확인한다.
- 모달을 열면 에디터가 남은 높이를 채우고 장문 본문은 에디터와 모달 본문을 확장시키는지 확인한다.
- 양식의 첫/마지막 본문 블록에 기본 여백이 있어도 에디터 상·하단 내부 공백이 동일한지 확인한다.

### 브라우저 확인

375px, 768px, 1280px에서 카드/필드/버튼 높이, 라벨과 참조 행 정렬, 페이지 가로 폭 및 내부 결재선 스크롤을 확인한다. 모달 오픈 직후 에디터가 남은 높이를 채우고, 긴 양식 본문이 에디터를 확장시키면서 모달 세로 스크롤을 사용하는지 및 상·하단 공백이 같은지 확인한다. 고정 헤더/푸터 접근성도 확인한다. 새 캡처는 `docs/result/20261007/document-write-approval-card-row/screenshots/`에 저장하고 실측 결과를 결과 보고서에 기록한다.
