# 20261007_007 문서작성 결재 단계·중복 방지·초기 결재자 사양서

## 1. 목적 및 기준 문서

문서작성 모달에서 로그인 사용자를 고정된 첫 결재자로 자동 설정하고, 결재·합의·참조에 동일 사용자가 중복 배정되지 않게 한다. 단계 순번은 결재자 개인별 및 합의 그룹별로 부여하며 요청된 결재/합의 표시도 함께 반영한다.

- 작업지시서: [20261007_007 문서작성 결재 단계·중복 방지·초기 결재자](../../directions/20261007/20261007_007_문서작성_결재단계_중복방지_초기결재자_작업지시서.md)
- 계획서: [20261007_007 문서작성 결재 단계·중복 방지·초기 결재자](../../plan/20261007/20261007_007_문서작성_결재단계_중복방지_초기결재자_계획서.md)
- 승인 설계: [Document Composer Approval Stage Design](../../superpowers/specs/2026-10-07-document-composer-approval-stage-design.md)
- 이전 결재 표시 설계의 순번/빈 칸 요구사항은 본 사양에서 정한 범위로 대체한다. 너비 기반 슬롯, 행 순서, 개별 삭제 및 참조 동작은 본 문서에서 변경한다고 명시하지 않는 한 기존 동작을 유지한다.

## 2. 로그인 사용자 초기 결재 단계

1. 작성 모달을 열면 기존과 같이 기안서 옵션, 양식 목록, 로그인 사용자 프로필을 읽는다.
2. 사용자 옵션을 기존 `userId` 기반 F1Grid option으로 변환한다.
3. 프로필에 공백이 아닌 이름과 정규화한 `userId`가 있으면 첫 approval stage를 생성한다. 사용자 옵션 목록에서 동일한 정규화 `userId`를 찾으면 해당 옵션을 사용하고, 찾지 못하면 프로필의 `userId`, 이름, `profileImage`, `levelName`, `departmentName`을 F1Grid 사용자 표시 옵션의 `value`, `label`, `avatarUrl`, `positionName`, `departmentName`으로 매핑한다.
4. 첫 단계는 단계 순번 1이며 삭제할 수 없다. 화면에 삭제 버튼을 표시하지 않으며 hook의 제거 함수도 고정 단계를 제거하지 않는다.
5. 프로필 이름 또는 `userId` 자체가 없으면 작성 모달의 기존 오류 영역에 원인을 알려 주는 메시지를 표시한다. 후보 옵션 목록에 로그인 사용자가 없다는 이유만으로 오류 처리하지 않으며, 프로필에 없는 identity/name을 만들어내지 않는다.
6. 작성 모달 닫기/초기화 시 단계와 참가자 선택 상태를 지우며, 다시 열면 위 프로필/옵션 매칭을 새로 수행한다.

## 3. 결재·합의·참조 고유성

하나의 사용자 ID는 다음 범위 전체에서 최대 한 번만 선택 또는 확정될 수 있다.

- 결재 승인 단계
- 합의 단계의 모든 사용자
- 참조 선택

선택기 후보는 아래 기준으로 계산한다.

- 결재 선택기: ID 양쪽의 앞뒤 공백을 제거해 비교하며, 이미 승인/합의 단계에 배정된 사용자와 참조로 선택된 사용자를 제외한다. 현재 선택 중인 값은 해당 선택기에서만 유지한다.
- 참조 선택기: ID 양쪽의 앞뒤 공백을 제거해 비교하며, 승인/합의 단계에 이미 배정된 사용자 및 현재 확정 전 결재 선택 중인 사용자를 제외한다. 참조 입력에 이미 선택된 값은 해당 선택기에서 유지한다.
- 선택 변경 handler와 결재/합의 추가 handler도 허용 가능한 후보 ID만 수용해 오래된 입력 또는 연속된 상태 업데이트로 중복 사용자가 확정되지 않게 한다.
- 비고정 결재자나 합의자를 삭제하면 해당 사용자 ID가 결재 및 참조 후보에 다시 포함된다. 고정 로그인 사용자는 계속 제외한다.
- 참조 chip 삭제 시 그 ID는 결재 후보에 다시 포함된다.

## 4. 단계별 순번 및 합의 그룹 규칙

순번은 `approvalStages` 단계 순서에 따라 1부터 증가한다. 참여자 수가 아닌 단계 수가 순번을 결정한다.

- 하나의 approval stage에는 결재자 한 명이 들어가며 각 결재자 stage가 서로 다른 번호를 갖는다.
- 한 번의 합의 추가로 선택한 여러 사용자는 하나의 agreement stage에 들어가고, 그 단계 사용자 모두 동일 번호를 공유한다.
- 각 합의 그룹은 한 단계이며 한 번의 순번을 소비한다.
- 승인자 또는 합의 참여자 삭제 후 빈 합의 단계는 제거하고, 남은 단계 순서에 따라 번호를 다시 계산한다.
- 결재 선택기 레이블의 다음 번호는 추가될 다음 단계 번호를 표시한다.

확정 사례:

| 단계 순서 | 참가자 | 표시 번호 |
|---|---|---:|
| 1 | 로그인 사용자 결재 | 1 |
| 2 | 합의자 B, 합의자 C | B=2, C=2 |
| 3 | 결재자 D | 3 |
| 4 | 결재자 E | 4 |

## 5. 작성 모달 표시

1. 기존 행 순서를 유지한다: `결재선 → 결재 → (합의 참여자가 있을 때만) 합의 → 참조`.
2. 결재 행과 합의 행 사이의 Divider만 제거한다. 기안 메타데이터와 결재 영역 등 다른 구분선은 유지한다.
3. 빈 결재 슬롯은 확정 결재자와 동일한 3개 영역을 가진 미확정 칸으로 표시한다.
   - 위: 글자 없이 비워 둔 직위/직함 영역
   - 가운데: 글자 없이 비워 둔 도장 영역
   - 아래: 글자 없이 비워 둔 이름 영역
   - 칸 외곽선은 점선이다. 순번 배지와 삭제 버튼은 없다.
   - 접근성 라벨, 각 영역 높이 및 점선 구분은 유지한다.
4. 확정된 비고정 결재자는 기존 직위/도장/순번/이름 표시 및 개별 제거를 유지한다. 고정 로그인 결재자는 동일 표시를 하되 제거 버튼만 없다.
   - 고정 로그인 결재자의 이름 행은 삭제 버튼용 열을 예약하지 않고 이름에 임의 3em 최대 너비를 적용하지 않는다. 다른 참가자의 삭제 버튼 열과 동작은 유지한다.
5. 미결재 합의 chip에는 도장 자리나 도장 placeholder를 표시하지 않는다. 작성 모달의 `DocumentApprovalStage`는 승인 상태를 제공하지 않으므로 승인 flag, API 응답, DB 데이터를 새로 추정하거나 추가하지 않는다. 승인 상태가 실제로 존재하는 별도 표시 흐름이 주어지기 전까지 작성 모달 합의자에게 도장을 표시하지 않는다.
6. 합의 인원이 0명이면 합의 행을 표시하지 않는다. 합의자가 있으면 기존 개별 chip과 삭제/줄바꿈을 유지하되 같은 그룹 참가자는 동일 단계 번호를 나타낸다.
7. 참조 입력 자체와 기존 선택 값을 표현하는 방식은 유지하고 고유성 규칙에 필요한 후보 필터만 적용한다.
8. 결재 빈 슬롯 수/최소 너비/간격 및 실제 모달 콘텐츠 너비 기반 ResizeObserver 계산은 현재 동작과 회귀 테스트를 보존한다.

## 6. 영향 범위 및 제외

변경 대상은 문서작성 `DocumentApprovalStage` 타입, `useDocumentComposer`, `DocumentApprovalFields`, `DocumentComposerDialog`, 해당 Vitest 테스트와 날짜별 문서/결과물이다. 사용자 선택 공통 컴포넌트, API 계약, 라우트, 서식 본문 에디터, 백엔드 및 DB에는 변경을 하지 않는다.

## 7. 검증 기준

### 자동 검증

- 로그인 프로필 ID에 해당하는 옵션이 초기 결재 순번 1로 나타나고 삭제할 수 없으며 결재/합의/참조 후보에서 다시 선택할 수 없어야 한다. profile 및 candidate ID가 앞뒤 공백만 다른 경우에도 같은 ID로 처리한다.
- 프로필 ID가 유효하고 사용자 옵션에 동일 사용자가 있으면 해당 옵션으로, 없으면 프로필 정보로 고정 첫 결재자를 만들어야 한다. 프로필 이름이나 사용자 ID 자체가 없을 때만 오류 영역에 명시적인 오류가 나타나야 한다.
- 결재, 합의 또는 참조 중 이미 확정/선택 중인 사용자를 다른 선택기에서 선택할 수 없어야 한다. 비고정 결재/합의 참가자 또는 참조 chip 삭제 후에는 해당 사용자를 다시 선택할 수 있어야 한다.
- 다중 사용자 합의 그룹의 모든 chip이 같은 순번 2를 받고, 후속 결재 순번이 3과 4가 되는 예시를 검증한다. 합의 참여자 삭제 후 빈 그룹 제거와 재번호도 유지되어야 한다.
- 고정 결재자 제거 버튼 부재와 hook 제거 동작 보호를 확인한다.
- 빈 결재 칸의 세 영역에 보이는 텍스트가 전부 없는 상태, 접근성 라벨 유지, 점선 테두리, 순번 및 삭제 부재, 미결재 합의 도장 자리 부재, 결재/합의 사이 Divider 부재를 확인한다.
- 고정 결재자의 이름 행은 사용 가능한 너비를 사용해 현재 잘림을 방지하고, 삭제가 가능한 일반 결재자의 삭제 버튼은 유지되는지 확인한다.
- 기존 80px 최소 슬롯, 4px 간격, ResizeObserver 기반 용량, 줄바꿈, 행 순서와 참조 동작 회귀 테스트를 유지한다.
