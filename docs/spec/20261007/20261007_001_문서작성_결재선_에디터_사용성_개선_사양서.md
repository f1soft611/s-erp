# 20261007_001 문서작성 결재선 및 에디터 사용성 개선 사양서

## 1. 목적 및 범위

문서작성 모달의 기안서 탭에서 결재자/참조자 선택과 단계 배치를 개선하고, 긴 본문이 모달의 콘텐츠 스크롤 흐름에 포함되도록 한다. 저장·상신·결재 API, 공통 에디터 구현, 공통 다이얼로그 구현은 변경하지 않는다.

- 계획서: [20261007_001 문서작성 결재선 및 에디터 사용성 개선 계획서](../../plan/20261007/20261007_001_문서작성_결재선_에디터_사용성_개선_계획서.md)
- 승인 설계: [문서작성 결재선 및 에디터 사용성 개선 설계](../../superpowers/specs/2026-10-07-document-write-approval-editor-usability-design.md)
- 기존 기안서 동작: [20261006_005 문서작성 기안서 탭 필드 재정의](../../spec/20261006/20261006_005_문서작성_기안서탭_필드재정의_사양서.md)

이 사양은 이전 기안서 필드 사양의 결재 추가 인원 제한(한 번에 한 명)만 대체한다. 합의 단계, 필드 계약, 템플릿 및 나머지 기존 흐름은 유지한다.

## 2. 사용자 선택 동작

### 공통 선택기

- `UserSelectEditor`에 `hideSelectedOptions?: boolean` 및 `preserveSelectionOrder?: boolean` 선택 속성을 추가한다.
- 두 속성의 기본값은 `false`로 두어 속성을 사용하지 않는 다른 화면의 동작은 보존한다.
- `hideSelectedOptions=true`이면 이미 선택된 후보를 열린 목록에서 제외하되, 선택값은 입력 안의 기존 칩으로 계속 표시한다.
- `preserveSelectionOrder=true`이면 다중 값의 배열 순서대로 선택 옵션/칩을 표시한다.

### 결재선

- 결재/합의 단계의 모든 사용자는 결재선 후보에서 제외한다. 현재 입력에 선택 중인 사용자도 드롭다운 목록에서 즉시 숨기되 선택기 내부에는 칩으로 표시한다.
- 현재 사양과 달리 `결재 추가`는 선택 인원이 1명 이상일 때 활성화한다.
- 추가 시 선택된 각 사용자를 각각 단일 사용자 `approval` 단계로 만들고, 선택 배열의 순서대로 기존 단계 뒤에 추가한다.
- 결재 단계 ID는 추가 순서대로 유일하게 부여한다. 사용자가 한 번 추가된 뒤 동일 후보를 다시 선택할 수 없다.
- 단계 삭제 후 화면의 단계 번호는 기존과 같이 현재 목록 순서대로 다시 연속 번호를 사용한다.

### 합의

- `합의 추가`는 1명 이상 선택했을 때 활성화한다.
- 선택된 전체 사용자는 하나의 `agreement` 단계로 묶는다. 결재선 선택 순서를 보존하며 추가 후 입력 선택을 비운다.
- 결재·합의 카드의 기존 사진, 이름, 부서, 도장 자리 및 삭제 동작을 유지한다.

### 참조

- 선택된 참조자는 참조 선택기의 입력 칩으로 표시하고 열린 드롭다운 후보에서는 숨긴다.
- 참조 선택기 아래의 별도 수신자 요약 목록은 제거한다.
- 결재선과 참조선은 독립 선택이다. 서로 간 사용자 중복 제한은 적용하지 않는다.
- 참조 선택은 결재/합의 단계에 영향을 주지 않고 참조용 도장 자리를 만들지 않는다.

## 3. 결재선 레이아웃

- 결재선 사용자 선택 입력과 `결재 추가`/`합의 추가` 버튼 그룹을 한 행에 배치한다. 버튼은 선택 입력의 우측에 둔다.
- 단계 목록은 세로 카드 스택 대신 왼쪽에서 오른쪽으로 흐르는 가로 스트립으로 배치한다.
- 각 단계는 현재 순번, 역할(결재/합의), 사용자 정보, 도장 자리 및 삭제 액션을 표시한다.
- 인접 단계 사이에 장식용 `>`를 표시하고 스크린 리더의 단계 설명을 중복시키지 않는다.
- 가로 스트립은 자체 `overflow-x` 스크롤을 가질 수 있지만 전체 페이지/모달의 가로 폭을 늘리지 않는다. 좁은 화면에서 각 카드의 최소 너비와 입력/액션 그룹의 줄어듦을 제한한다.

## 4. 본문과 모달 스크롤

- 편집기는 기존 공통 `RichTextEditor` 인스턴스와 양식 본문 연동을 그대로 사용한다.
- 본문 표면은 최소 높이 180px을 유지하고 본문 길이에 따라 자연 높이로 확장한다.
- 본문 영역에 최대 높이, 고정 부모 높이 또는 내용을 가리는 세로 overflow 제약을 두지 않는다. 본문 요소에 독립된 제한 세로 스크롤을 만들지 않는다.
- 기안서 메타데이터, 선택기, 제목 및 본문을 감싸는 콘텐츠는 고정 100% 높이를 강제하지 않는다. 긴 콘텐츠의 세로 이동은 `CommonDialog` 내부 `DialogContent` 스크롤이 담당한다.
- 모달 헤더와 푸터는 기존과 같이 유지한다. 넓은 표/내용의 가로 넘침이 페이지 전체를 확장하지 않도록 기존 에디터의 가로축 보호를 유지한다.

## 5. 유지 및 제외 동작

- 결재 단계와 참조 목록은 모달 작성 상태이며 실제 저장/상신 요청을 수행하지 않는다.
- 합의 다중 사용자 단일 단계 semantics, 단계 삭제, 번호 재계산, 템플릿 선택/교체 보호, 기존 본문 에디터, 첨부 및 저장 비활성 상태를 보존한다.
- API 응답 계약, 권한, 라우팅, 백엔드, DB, 실제 승인 결과 및 결재선과 참조선 간 중복 검증은 추가하지 않는다.
- 공용 `RichTextEditor`, `CommonDialog`와 공지사항 작성 화면은 수정하지 않는다.

## 6. 검증 기준

### 자동 테스트

- 공통 선택기 opt-in 후보 숨김은 선택된 옵션만 목록에서 숨기며 선택 칩은 보존한다.
- 공통 선택기 opt-in 순서 보존은 입력 ID 배열 순서대로 칩을 표시하며 기본 동작은 기존과 같다.
- 두 명 이상을 역순으로 골라 `결재 추가`하면 역순에 맞는 단일 사용자 결재 단계들이 추가되고 선택값은 초기화된다.
- 추가된 결재/합의 단계 사용자는 이후 결재 후보로 노출되지 않는다.
- `합의 추가`는 여러 사람을 기존처럼 단일 합의 단계에 묶는다.
- 참조 선택자는 자체 칩을 보존하고 선택 후보를 숨기며, 필드 아래 별도 요약 DOM이 없다. 참조가 결재선을 변경하지 않는다.
- 편집기에는 최소 높이가 남고 본문 높이를 제한하는 `max-height` 또는 독립된 세로 overflow가 없으며, 조상 `DialogContent`가 세로 스크롤 영역이다.
- 기존 문서작성 페이지, 양식/템플릿, 모달 종료 초기화 테스트가 계속 통과한다.

### 브라우저 확인

375px, 768px, 1280px에서 필드와 액션 배치, 긴 가로 단계 스트립의 내부 스크롤, 페이지 가로 넘침 방지, 본문이 늘어날 때 모달 콘텐츠 세로 스크롤 및 헤더/푸터 접근성을 확인한다. 목록과 모달 화면 캡처는 `docs/result/20261007/document-write-approval-editor-usability/screenshots/`에 둔다.
