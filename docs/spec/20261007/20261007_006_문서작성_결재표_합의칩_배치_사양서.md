# 20261007_006 문서작성 결재 표/합의 칩 배치 사양서

## 1. 목적 및 범위

문서작성 모달의 결재 참여자 표시를 승인된 컴팩트 용량 설계에 맞춘다. 실제 모달 콘텐츠 너비를 기준으로 결재 그리드의 기본 빈 슬롯 수를 계산하고, 합의 참여자가 있을 때만 합의 칩 행을 표시한다.

- 계획서: [20261007_006 결재 표/합의 칩 배치](../../plan/20261007/20261007_006_문서작성_결재표_합의칩_배치_계획서.md)

## 2. 행 구조

1. **결재선**: 기존 다중 사용자 선택기, `결재 추가`, `합의 추가` 버튼을 표시한다. 확정 사용자는 이 행에 표시하지 않는다.
2. **결재**: 결재 슬롯 그리드를 표시한다. 첫 행은 실제 모달 콘텐츠 너비에 맞춰 빈 슬롯으로 채우며, 확정 결재자가 첫 행 수용량을 넘으면 뒤 행으로 이어간다.
3. **합의**: 합의 참여자가 한 명 이상 있을 때만 행을 표시한다. 각 참여자를 사용자별 연회색 칩으로 나타낸다.
4. **참조**: 기존 참조 행, 선택기와 동작을 그대로 유지한다.

행 순서는 `결재선 → 결재 → (합의 참여자가 있을 때만) 합의 → 참조`이다. 각 행은 일관된 왼쪽 라벨과 `min-width: 0`인 오른쪽 콘텐츠 영역을 사용한다.

## 3. 결재 그리드 용량 및 표시

- 각 슬롯의 최소 너비는 80px이고 슬롯 간격은 4px이다.
- `ResizeObserver`로 결재 그리드 콘텐츠 영역을 관찰해 실제 모달 콘텐츠 너비를 얻는다. 뷰포트 임계값을 추측해 수용량을 정하지 않는다.
- 첫 행 수용량은 다음 식으로 계산한다.

  ```text
  capacity = max(1, floor((contentWidth + 4) / 84))
  ```

- 렌더링 셀 수는 `max(capacity, committedApprovalCount)`이다. 따라서 첫 행은 빈 셀을 포함해 너비에 맞게 채우고, 참여자가 수용량을 초과하면 초과 참여자는 뒤 행으로 wrap한다. 그리드 또는 칩이 페이지 전체 가로 넘침을 만들지 않는다.
- 기본 빈 슬롯은 낮은 강조의 도장 영역만 표시한다. 순번 배지와 삭제 동작은 포함하지 않고, 순번을 예약하지 않는다.
- 실제 결재 참여자 셀은 기존 직위/직함과 도장 영역을 유지한다. 이어서 작은 소프트 블루 원형 전역 순번 배지, 한글 약 3자까지 보이는 말줄임 이름, 해당 참여자만 삭제하는 동작을 표시한다.
- 잘린 표시 이름의 전체 이름은 보조 기술로 접근 가능해야 하고 title/tooltip에서도 확인할 수 있어야 한다.

## 4. 합의 칩, 순서 및 삭제

- 합의 참여자가 없으면 합의 행을 렌더링하지 않는다.
- 합의 참여자가 있으면 한 명당 하나의 컴팩트한 연회색 칩을 표시한다. 칩은 결재와 합의 참여자가 공유하는 작은 원형 전역 순번 배지, 약 3자 기준 말줄임 이름, 도장 placeholder, 해당 참여자의 개별 삭제 동작으로 구성한다. 아바타와 단계 종류 문구는 표시하지 않는다.

- 다중 결재 선택은 기존 선택 순서대로 개별 승인 항목이 된다.
- 합의 선택은 기존처럼 하나의 agreement stage에 그룹으로 저장되지만 화면에서는 사용자별 칩으로 펼친다.
- 결재와 합의 사용자를 기존 stage/user 순서대로 평탄화해 1부터 전역 번호를 부여한다.
- 결재 참여자 삭제는 해당 approval stage를 제거한다.
- 합의 칩 삭제는 해당 사용자만 agreement stage에서 제거한다. 마지막 사용자를 지우면 빈 agreement stage를 제거한다.
- 삭제한 사용자는 결재 후보로 복원하고 나머지 참여자의 전역 순번을 다시 계산한다.
- 참조 선택은 결재 상태와 독립적이며 변경하지 않는다.

## 5. 표시 및 접근성

- 네 라벨 `결재선`, `결재`, `합의`, `참조`가 화면 순서와 일치한다.
- 합의 라벨과 행은 합의 참여자가 한 명 이상일 때만 존재한다.
- 실제 승인 열과 합의 칩의 삭제 버튼은 각각 대상 참여자와 순번을 식별할 수 있어야 한다. 말줄임된 이름도 전체 이름이 보조 기술 및 title/tooltip으로 제공되어야 한다.
- 결재 그리드와 합의 칩 목록은 필요한 경우 다음 줄로 감싸며 페이지 가로 폭을 늘리지 않는다.

## 6. 변경하지 않을 사항

공유 에디터, 사용자 선택기, 다이얼로그, API, 라우트, 데이터 계약, 저장/상신, 백엔드, 권한 및 DB를 변경하지 않는다.

## 7. 검증 기준

### 자동 테스트

- 라벨 순서와 합의 참여자 0명/1명 이상일 때의 조건부 표시를 확인한다.
- 그리드 너비 변경 시 `ResizeObserver` 기반 수용량 공식, 80px 최소 슬롯/4px 간격, 첫 행의 기본 빈 슬롯 수, 참여자 초과 시 후속 행 배치를 확인한다.
- 빈 결재 슬롯에 도장 영역만 있고 배지/삭제 동작이 없는지, 실제 결재 셀의 직위/도장/원형 전역 배지/말줄임 이름/개별 삭제가 있는지 확인한다.
- 합의 칩의 전역 배지/말줄임 이름/도장 placeholder/개별 삭제 및 아바타/단계 종류 문구 미표시를 확인한다.
- 전체 이름의 접근성 및 title/tooltip 제공, stage/user 순서의 전역 순번, 삭제 후 후보 복원과 재번호, 마지막 합의자 삭제 시 그룹 제거, 참조 동작 불변을 확인한다.
- 모달 또는 페이지에서 가로 넘침이 없는지 확인한다.

### 브라우저

375px, 768px, 1280px에서 그리드가 실제 모달 콘텐츠 너비에 반응하는지, 첫 행이 빈 슬롯으로 채워지는지, 초과 결재자가 다음 행으로 감기는지, 행 순서와 합의 조건부 표시 및 삭제 후 순번/후보 갱신을 확인한다. 페이지 가로 넘침이 없어야 한다. 캡처는 합성 이름만 사용하며 실제 사용자 식별정보나 문서 본문을 포함하지 않는다.
