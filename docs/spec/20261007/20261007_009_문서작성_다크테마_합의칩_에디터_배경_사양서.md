## 2. 합의 칩 색상

| 항목 | 라이트 | 다크 |
|---|---|---|
| 배경 | 현재 `grey.100` | `#334155` |
| 테두리 | 기존 `grey.300` | theme `divider` |
| 이름 | 기존 `text.primary` | 기존 `text.primary` |
| 삭제/도장 | 기존 theme 스타일 | 기존 theme 스타일 |

합의 칩 외관만 색상 반응형으로 바꾼다. 선택 상태, 전역 순번, 후보 복원, 개별 제거, 줄바꿈은 그대로 둔다.

## 3. 에디터 표면과 가독성

- 에디터 패널, 본문 편집 가능 영역, 첨부 영역 배경은 라이트에서 흰색(`#ffffff`), 다크에서 공통 모달 본문과 같은 슬레이트(`#1e293b`)로 한다.
- 에디터의 기본 본문 텍스트와 빈 본문 placeholder는 현재 테마의 `text.primary`/`text.secondary`를 사용해 각 표면에서 읽을 수 있도록 한다.
- 사용자가 본문에 지정한 개별 서식과 템플릿 콘텐츠는 보존하고, 데이터/HTML 변환은 변경하지 않는다.
- 공통 다이얼로그의 paper/header/body/footer 및 문서 제목 필드는 기존 승인된 테마별 색을 유지한다.

## 4. 자동 검증

- 다크 테마 합의 칩은 `rgb(51, 65, 85)` 배경, theme divider 테두리, 읽기 쉬운 텍스트 색으로 표시된다.
- 라이트 테마 합의 칩은 기존 `grey.100` 색상을 유지한다.
- 라이트 에디터 패널 및 `.ProseMirror` 배경은 `rgb(255, 255, 255)`, 다크 배경은 `rgb(30, 41, 59)`이다.
- 기본 에디터 텍스트는 라이트 `rgb(15, 23, 42)`, 다크 `rgb(226, 232, 240)`이다. Placeholder는 pseudo-element라 실제 브라우저에서 테마별 색상과 대비를 확인한다(JSDOM은 pseudo-element 스타일 계산을 지원하지 않는다).
- 기존 합의 추가/삭제/후보 복원 및 결재선 기능 테스트는 유지된다.

## 5. 브라우저 검증

375px, 768px, 1280px에서 라이트/다크 문서작성 모달을 검증한다. 합의 칩이 다크 배경에서 밝은 사각형으로 남지 않아야 하고, 에디터는 라이트에서 흰색, 다크에서 `rgb(30, 41, 59)`여야 한다. 기본 텍스트 및 placeholder는 각 테마에서 읽을 수 있어야 하며 페이지 전체 가로 넘침이 없어야 한다. 캡처에 개인 식별정보나 실제 문서 본문을 포함하지 않는다.
