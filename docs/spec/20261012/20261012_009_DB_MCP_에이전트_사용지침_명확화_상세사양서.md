# 상세 사양서: DB MCP 에이전트 사용 지침 명확화

## 목적

DB·스키마·백엔드 API 계약 작업을 수행하는 에이전트가 workspace에 등록된
읽기 전용 PostgreSQL MCP 도구를 직접 사용하고, 세션에서 도구를 사용할 수
없는 경우 이를 숨김없이 알리도록 한다.

## 수정 대상

- 루트 `AGENTS.md`: DB 관련 변경 전 MCP 직접 호출 의무와 상세 정책 링크
- `.github/instructions/database-mcp.instructions.md`: 서버 선택, 호출 순서,
  조회 안전성, 실패 대응

설정과 참고 문서:

- 루트 `.mcp.json` (읽기 전용)
- `tools/mcp-postgresql-readonly/src/mcpConfig.test.ts` (읽기 전용)
- 사람용 [PostgreSQL MCP 구성 사양서](../20260909/20260909_002_PostgreSQL_읽기전용_MCP_서버_구성_사양서.md) (읽기 전용)

## 동작 요구사항

1. 에이전트는 DB·테이블·컬럼·데이터 무결성·백엔드 API 데이터 계약을 구현하거나
   변경하기 전에 현재 세션에 노출된 `s-erp-postgresql-readonly` 도구를 직접
   호출한다. 실행 전에 단순히 연결 안내만 제공하거나 저장소 문서만으로 MCP
   확인을 대신하지 않는다.
2. 먼저 `list_tables`를 호출해 관련 테이블을 확인한다. 이후에만 해당 대상의
   `describe_table`을 호출한다. 메타데이터로 답을 확인할 수 없을 때에만
   `query_readonly`를 사용한다.
3. `query_readonly`는 단일 읽기 전용 SELECT 또는 CTE 조회만 사용하고,
   `maxRows`는 100 이하로 지정한다. 민감 행을 조회하거나 결과에 복사하지
   않는다. 어떤 상황에서도 MCP로 쓰기·DDL·트랜잭션 작업을 실행하지 않는다.
4. 기본 중앙 DB 서버는 `s-erp-postgresql-readonly`다. tenant 데이터베이스가
   명시적으로 필요한 요구사항만 현행 `.mcp.json`에 등록된 tenant 전용 서버를
   사용한다. tenant 서버 이름이나 대상은 사용자 요구 없이 추정하지 않는다.
5. 도구가 현재 세션에 노출되지 않았거나 MCP 호출에 실패하면 DB 실시간 계약
   확인이 완료되지 않았다고 명시한다. `.env` 또는 자격 증명을 직접 열람하지
   않고, MCP 설정·연결값을 변경하거나 다른 클라이언트 접속을 MCP 호출인 것처럼
   표현하지 않는다.
6. 복구가 필요하면 VS Code에서 workspace MCP 서버를 시작·신뢰하고 새 Copilot
   세션에서 다시 확인하도록 안내한다. 사용자가 실행하지 않은 서버 시작이나
   세션 확인을 완료했다고 말하지 않는다.
7. 사용 가능한 MCP가 없을 때만 날짜별 스키마 이력, Mapper XML, 도메인 코드 등
   저장소 자료를 대체 근거로 확인하고, 결과에 MCP 미확인 사실과 확인한 자료를
   구분해 기록한다.

## 안전·문서화 기준

- 호스트, 계정, 비밀번호, 연결 문자열 및 민감 데이터 행을 지침에 기록하지
  않는다.
- MCP는 읽기 전용 증거 확인 수단이며 SQL 변경·롤백 이력 절차를 대체하지 않는다.
- 기존 사람용 연결 사양서와 `.mcp.json`은 이번 작업에서 수정하지 않는다.
- 현재 MCP 세션의 실제 도구 노출을 UI에서 확인한 것처럼 주장하지 않는다.

## 검증 기준

- 지침의 서버명·전송 유형·도구명이 현행 workspace MCP 등록과 일치한다.
- DB 변경 전 MCP 직접 호출, 순차적 조회, 읽기 전용 제한, tenant 조건, 실패 시
  사실 기반 보고가 명시되어 있다.
- 변경된 `AGENTS.md` 및 DB MCP 전용 지침에 `git diff --check` 오류가 없다.
- 지침에 민감한 연결값이 포함되지 않고, 설정 및 사람용 연결 사양서는 변경되지
  않는다.
