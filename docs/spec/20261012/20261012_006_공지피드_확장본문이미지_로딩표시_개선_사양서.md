# 20261012_006 공지 피드 확장 본문 이미지 로딩 표시 개선 사양서

## 1. 목적

공지사항 피드에서 `더보기`를 누른 뒤 보호된 본문 이미지가 인증 blob 로드/디코드 완료 전 깨진 이미지처럼 보이지 않게 한다. 이미지마다 로딩 표시를 제공하고, 실제 본문 이미지의 크기와 비율에 맞춰 로딩 영역을 표시한다.

## 2. 기존 동작과 사용자 결정

- 확장 HTML은 sanitized/deferred HTML로 렌더링되며 보호된 embedded-image URL은 기존 `apiGetBlob` 인증 요청을 통해 blob URL로 hydration된다.
- 접힌 이미지 미리보기에는 MUI `Skeleton`이 있지만 고정 썸네일 크기여서 확장 본문 이미지 자리에 그대로 사용할 수 없다.
- 사용자는 큰 이미지도 본문 너비 안으로 축소하고 이미지 비율을 유지하는 동작을 선택했다.
- 저장 HTML에 크기 정보가 없으면 API 응답과 이미지 디코드가 완료되기 전 실제 비율을 알 수 없다. 사용자는 이 동안 임의 크기의 스켈레톤 대신 빈 이미지 자리를 원하며, 크기를 확인한 후 실제 표시 크기의 스켈레톤을 보여주도록 승인했다.

## 3. 표시 상태 및 흐름

### 크기 정보가 선언된 보호 이미지

1. 확장 직후 HTML의 `width`, `height`, 인라인 style 크기 정보를 읽는다.
2. 보호된 `src`는 DOM에 노출하지 않고 해당 자리에 크기/비율을 예약한 이미지별 로딩 스켈레톤을 표시한다.
3. 주변 텍스트, 표 및 비보호 콘텐츠는 그대로 표시한다.
4. `apiGetBlob` 요청 성공 후 blob URL의 이미지 decode가 완료되면 스켈레톤을 인증 blob 기반 `<img>`로 바꾼다.

### 크기 정보가 선언되지 않은 보호 이미지

1. 인증 요청과 이미지 decode가 끝날 때까지 깨진 `<img>`를 렌더링하지 않고 임의 크기의 스켈레톤도 표시하지 않는다. 주변 텍스트와 표는 계속 표시한다.
2. blob URL 이미지를 decode해 `naturalWidth`/`naturalHeight`와 비율을 얻는다.
3. 본문에서 사용할 반응형 너비/높이를 계산해 그 크기의 스켈레톤을 최소 한 번의 브라우저 렌더 프레임 동안 표시한다.
4. 스켈레톤을 같은 크기/비율의 인증 blob `<img>`로 교체한다.

두 흐름 모두 실제 이미지와 스켈레톤은 부모 본문 너비보다 넓어지지 않게 축소하고 원본 비율을 보존한다. 크기 정보를 가진 이미지에 기존 인라인 크기/정렬 스타일이 있으면 보존한다.

## 4. 오류 및 수명 관리

- 보호 이미지 요청은 계속 `apiGetBlob`만 사용한다. 보호 URL을 `<img src>`에 직접 넣지 않는다.
- API fetch 또는 blob decode가 실패하면 실패한 이미지 로딩 표시를 성공처럼 남기지 않고, 공지 본문에 기존 `role="alert"` 오류 `본문 이미지를 불러오지 못했습니다.`를 한 번 표시한다.
- 한 이미지가 실패해도 다른 이미지의 요청과 성공한 이미지 표시에는 영향을 주지 않는다.
- object URL은 확장 본문 교체, 접기 또는 컴포넌트 해제 때 revoke한다. 정리 뒤 완료된 요청에서 생성된 URL도 즉시 revoke한다.
- blob URL이 포함된 렌더 HTML은 React 상태로 유지해 피드의 무관한 재렌더링에서도 이미지를 보존한다.

## 5. 범위 및 비목표

### 포함

- `NoticeFeedList`의 확장 본문 이미지 loading 상태와 반응형 크기 처리
- pending/loading, decode 이후, 실패 및 cleanup 회귀 테스트
- 날짜별 작업 결과 문서와 브라우저 캡처

### 제외

- 접힌 미리보기 스켈레톤 크기/동작 변경
- 상세 이미지 뷰어, 이미지 업로드, 저장 HTML/JSON, API, 백엔드, DB 또는 권한 정책 변경
- 본문 전체 로딩 overlay 또는 rich HTML 전체의 React 노드 재구성
- 이미지 재시도 정책 추가

## 6. 회귀 검증 기준

1. 크기 속성이 있는 보호 이미지를 펼치면 즉시 이미지 크기/비율을 반영한 스켈레톤이 표시되고 실제 `<img>`는 요청 완료 전 나타나지 않는다.
2. 요청 pending 동안에도 본문 문장과 표가 표시된다.
3. 크기 속성이 없는 보호 이미지는 요청/디코드가 끝나기 전 깨진 `<img>`나 추정 크기 스켈레톤을 표시하지 않는다.
4. 크기 정보 없는 이미지가 decode되면 자연 크기 비율을 사용한 responsive 스켈레톤이 표시되고, 최소 한 번의 렌더 프레임 뒤 이미지가 이를 대체한다.
5. 큰 이미지의 최종 너비는 본문 너비를 넘지 않으며 높이는 원본 비율에 맞는다.
6. 요청/decode 실패 시 기존 접근성 오류가 표시되고 실패 이미지가 깨진 아이콘으로 남지 않는다.
7. 여러 이미지의 loading/성공/실패는 독립적이며, 무관한 재렌더링 뒤에도 완료 이미지가 유지된다.
8. 접기, 본문 교체, unmount 및 늦게 완료된 요청에 대한 object URL 정리와 기존 썸네일/상세 뷰어가 회귀하지 않는다.
