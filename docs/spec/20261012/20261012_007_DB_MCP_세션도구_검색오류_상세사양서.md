# DB MCP 세션 도구 검색 오류 수정 상세 사양서

## 1. 요구사항

S-ERP 저장소를 연 로컬 VS Code Copilot 세션에서 PostgreSQL 읽기 전용 MCP 서버의 도구를 사용할 수 있도록 workspace 등록 형식을 바로잡는다.

## 2. 현재 근거 및 원인 가설

- `.mcp.json`의 portable root 객체는 `mcpServers`다.
- primary 및 tenant 항목은 `type: "local"`과 `tools: ["*"]`를 사용한다.
- VS Code의 stdio 설정은 `type: "stdio"`를 요구하며 `tools` 속성을 정의하지 않는다.
- MCP 서버 실행 파일은 직접 시작 시 세 도구를 `tools/list`에 정상 반환한다.
- 따라서 세션에서 도구가 보이지 않는 원인은 서버 구현보다는 서버 등록 스키마 불일치일 가능성이 가장 높다. 정확한 과거 세션 로그는 확보되지 않아 실제 시작 실패 메시지까지는 확인되지 않았다.

## 3. 설정 계약

| 항목 | `s-erp-postgresql-readonly` | `s-erp-postgresql-readonly-tenant-1212123312` |
|---|---|---|
| 전송 유형 | `stdio` | `stdio` |
| 명령 | `node` | `node` |
| 실행 파일 | 기존 인수 유지 | 기존 인수 유지 |
| 환경변수 | 기존 항목 유지 | `S_ERP_DB_NAME=tenant_1212123312` 유지 |
| 추가 필드 | `tools` 필드 없음 | `tools` 필드 없음 |

기존 `.env`가 접속 정보를 공급한다. MCP 설정에는 자격 증명, 비밀번호, 연결 문자열을 기록하지 않는다.

## 4. 비기능 및 안전 요구사항

- MCP 서버는 로컬 stdio 전송과 기존 읽기 전용 권한을 유지한다.
- 두 서버 이름, 실행 명령/인수, tenant 데이터베이스 분리 동작을 바꾸지 않는다.
- 이 설정 수정 과정에서는 `list_tables`, `describe_table`, `query_readonly`를 포함한 DB 도구를 실행하지 않는다.
- 기존 사용자 변경 파일은 작업 범위에서 제외한다.

## 5. 검증 기준

1. 설정 회귀 테스트가 두 서버의 `stdio` 타입, 명령, 인수 및 tenant DB 환경변수를 확인한다.
2. strict 스키마가 미지원 `tools` 필드를 거부한다.
3. MCP 패키지의 Vitest 전체 테스트가 통과한다.
4. stdio MCP 연결이 도구 목록만 반환하고, 세 도구 이름이 기대값과 일치한다.
5. VS Code에서 서버를 신뢰/시작한 뒤 새 세션에서 도구가 제공되는 확인 절차가 결과 문서에 포함된다.
