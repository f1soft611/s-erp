# 상세 사양서: PostgreSQL 읽기 전용 MCP 연결 안내 개정

## 목적

기존 PostgreSQL 읽기 전용 MCP 구성 사양서를 현행 workspace 설정과
Copilot 세션 발견 절차에 맞게 갱신한다.

## 대상 문서 및 참고 기준

- 갱신 대상: `docs/spec/20260909/20260909_002_PostgreSQL_읽기전용_MCP_서버_구성_사양서.md`
- 설정 확인: 저장소 루트 `.mcp.json` (읽기 전용)
- 패키지 확인: `tools/mcp-postgresql-readonly/package.json`
- 환경 예시: `tools/mcp-postgresql-readonly/.env.example`
- 설계: [DB MCP 연결 문서 설계](../../superpowers/specs/2026-10-12-db-mcp-connection-documentation-design.md)

## 연결 안내 요구사항

1. VS Code MCP 등록 위치를 `.vscode/mcp.json`이 아닌 루트 `.mcp.json`으로
   명시하고, 현재 등록된 서버의 전송 유형이 stdio임을 설명한다.
2. 기본 읽기 전용 MCP 서버와 workspace에 등록된 선택적 tenant 서버의 용도를
   구분한다. tenant 식별 번호나 DB 연결값은 문서에 기록하지 않는다.
3. `tools/mcp-postgresql-readonly/.env.example`을 참고해 같은 패키지 디렉터리에
   로컬 `.env`를 준비하도록 안내한다. 필요한 `S_ERP_DB_*` 환경변수 이름은
   설명할 수 있으나 값, 비밀번호, 주소, 계정 및 접속 문자열은 문서에 쓰지
   않는다.
4. Windows PowerShell 기준으로 `tools\mcp-postgresql-readonly`에서 아래
   명령을 수행하는 절차를 제공한다.

   ```powershell
   npm install
   npm run build
   ```

5. 저장소 루트를 VS Code workspace로 열고 `MCP: List Servers`에서 대상 서버를
   시작하고 신뢰한 뒤, 새 Copilot 세션을 열어 MCP 도구가 제공되는지
   확인하도록 안내한다.
6. 기대 도구는 `list_tables`, `describe_table`, `query_readonly`로 명시한다.
   기존 세션에는 변경된 도구 목록이 반영되지 않을 수 있으므로 새 세션 확인을
   포함한다.
7. 서버 목록 누락, 시작 실패, 도구 목록 미갱신 시 workspace 경로, `.mcp.json`,
   로컬 환경변수, 빌드 상태, 서버 재시작과 새 세션을 확인하는 간결한 점검
   절차를 제공한다.

## 안전 및 범위

- 연결 설정, 자격 증명, DB 서버, MCP 구현, 실제 데이터는 변경하지 않는다.
- 실제 VS Code 세션 조작이나 DB 조회를 수행한 것으로 표현하지 않는다.
- UI 변경이 없으므로 스크린샷은 요구하지 않는다.

## 검증 기준

- 문서에 `.vscode/mcp.json`을 현재 등록 위치로 안내하는 문구가 남지 않는다.
- 접속 절차가 루트 `.mcp.json` 및 패키지 스크립트와 일치한다.
- 문서 내 모든 경로와 명령이 이 저장소에서 확인 가능하다.
- 비밀번호, DB 접속 주소, 계정, 접속 문자열, tenant 식별 정보가 문서에 없다.
- 변경 diff에 `git diff --check` 오류가 없다.
