# 문서 임시저장 BIGINT 바인딩 오류 수정 사양서

## 문제

문서 임시저장 요청에서 선택 가능한 기안 구분 ID는 생략될 수 있다. DB의 `tb_electronic_approval_main.drafting_work_category_id`는 nullable `BIGINT`이지만 전역 MyBatis `jdbcTypeForNull` 설정은 `VARCHAR`다. Approval mapper가 선택 구분 ID를 JDBC 타입 지정 없이 사용하면 null이 VARCHAR parameter로 전달되어 PostgreSQL에서 `bigint` 대 `character varying` 타입 오류가 발생할 수 있다.

## 요구되는 변경

- `insertDocumentApprovalMain`의 `draftingWorkCategoryId` parameter는 `jdbcType=BIGINT`로 지정한다.
- `updateDocumentApprovalMain`의 같은 parameter도 `jdbcType=BIGINT`로 지정한다.
- null은 여전히 null로 저장되며 선택 category ID는 기존 tenant/category 검증을 통과한 값만 저장한다.
- 모든 다른 parameter, SQL column, transaction behavior는 변경하지 않는다.

## 검증

- MyBatis mapper를 XML로 parse한 뒤 insert/update `BoundSql` parameter mappings에서 `draftingWorkCategoryId`의 JDBC type이 `BIGINT`인지 검사한다.
- 회귀 테스트를 수정 전 실행해 실패하는 것을 확인하고, mapper 수정 후 통과를 확인한다.
- DocumentApproval service/controller target tests와 전체 Maven suite를 실행한다.
- DB schema 변경은 없다. 도구에서 read-only PostgreSQL MCP를 제공하지 않는 경우 schema history, mapper, global configuration을 근거로 기록한다.
