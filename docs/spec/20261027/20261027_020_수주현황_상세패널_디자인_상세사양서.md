## 1. 목표와 범위

수주번호를 클릭해 여는 기존 상세 패널의 데이터와 동작은 유지하면서 메인정보와 수주 품목 테이블의 정보 위계 및 가독성을 개선한다. 선택한 디자인은 **요약 헤더 + 그룹형 기본정보 + 정돈된 품목 표**다.

- 상태, 거래처, 총액 등 핵심 정보를 빠르게 파악하도록 한다.
- 기본정보를 성격별 그룹과 반응형 그리드로 정돈한다.
- 품목 코드·명, 수량·금액, 납기·행상태를 구별하기 쉬운 표로 만든다.
- 기존 필드, 조회 API, 권한, 편집/상세보기 메뉴, 패널 열기·닫기 동작은 변경하지 않는다.
- 새 데이터, 계산 규칙, 메뉴, 화면 흐름은 추가하지 않는다.

## 2. 화면 구성

### 2.1 작성자 및 액션

작성자 아바타·이름·등록일, 현재 수주 상태 Chip, 더보기 메뉴는 현재 위치와 동작을 유지한다. 좁은 화면에서는 겹치지 않게 줄바꿈한다.

### 2.2 핵심 요약

작성자 영역 아래에 강조된 요약 영역을 둔다.

- 수주번호는 기존 패널 부제목, 수주상태는 기존 Chip으로 식별하며 중복 표시하지 않는다.
- 거래처명을 주 정보로, 수주일자와 납기일자를 보조 정보로 표시한다.
- 총 합계를 요약 영역에서 가장 눈에 띄는 수치로 표시한다.
- 값은 기존 `SalesOrderItem` 응답의 `customerName`, `orderDt`, `deliveryDt`, `totalAmt`만 사용한다.

### 2.3 기본정보

기존 평면 정보 박스를 아래 두 그룹으로 재배치한다.

- **수주 정보:** 견적번호, 배송방법
- **납품 정보:** 납품장소, 비고

각 항목은 라벨과 값을 분리하고 값은 줄바꿈할 수 있게 한다. 긴 납품장소 값은 더 넓은 공간을 사용한다. 요약 영역의 거래처·날짜·합계와 품목 섹션의 품목 수는 기본정보에서 중복 표시하지 않는다. 비어 있는 값은 기존처럼 `-`로 표시한다.

### 2.4 수주 품목

- 섹션 제목에 품목 건수를 표시한다.
- 품목명은 주요 텍스트, 품목코드는 보조 텍스트로 표시한다.
- 수량·단가·합계는 우측 정렬하고 기존 `ko-KR` 숫자 포맷을 유지한다.
- 헤더 대비, 행 구분, 셀 여백을 정돈한다. 합계는 읽기 쉽게 강조하되 상태색으로 오인될 색은 사용하지 않는다.
- 행 순서와 전체 필드(행, 품목코드, 품목명, 수량, 단가, 합계, 납기, 행상태)는 유지한다.
- 품목이 없으면 기존 데이터 계약을 바꾸지 않고 빈 목록임을 명확히 표시한다.

## 3. 반응형 및 접근성

- 1280px 이상: 요약·기본정보를 넓게 배치하고 표 비교가 용이해야 한다.
- 768px: 기본정보 열 수와 요약 요소의 줄바꿈을 조정한다.
- 375px: 기본정보는 좁은 그리드로 재배치하고 넓은 품목 표만 내부 가로 스크롤을 사용한다. 페이지 전체 가로 넘침은 허용하지 않는다.
- 기존 패널 이름, 닫기 접근성 이름, 로딩 상태, 표 접근성 이름을 보존한다.
- 의미를 색만으로 전달하지 않는다. 기존 테마 토큰과 MUI 패턴을 사용하고 전역 또는 공통 패널 스타일은 변경하지 않는다.

## 4. 데이터·동작·오류 처리

- 변경 대상은 `frontend/src/pages/sales/order/status/components/SalesOrderStatusDetailPanel.tsx`와 해당 표시를 검증하는 프론트 테스트, 결과 문서 및 스크린샷이다.
- API, 타입, 필드 의미, 상세/수정 권한 및 액션은 변경하지 않는다.
- 로딩 문구, 오류 Alert, 닫기, 더보기 동작은 기존대로 유지한다.

## 5. 검증 기준

- 핵심 요약, 두 기본정보 그룹, 품목 건수와 각 열이 기존 데이터로 렌더링된다.
- 긴 거래처/품목명과 빈 값이 레이아웃을 깨뜨리지 않는다.
- 375px, 768px, 1280px에서 품목 표 내부 스크롤 외 페이지 전체 가로 넘침이 없다.
- 로딩·오류·상세보기·수정·닫기 흐름은 그대로 동작한다.
- 관련 Vitest, 프론트 빌드, lint를 실행하고 375/768/1280px 실제 브라우저 화면을 확인한다.

## 6. 범위 밖

수주등록 화면, 수주 목록 그리드, API/백엔드, 신규 필드와 비즈니스 규칙, 품목 행 카드형 전환, 공통 `PostDetailPanel` 또는 전체 테마 변경은 포함하지 않는다.
