## 1. 조회조건 상태 저장

- `usePageSessionState<SalesOrderStatusSearchSession | null>('s-erp:page:sales-order-status', null, { version: 1, validate, persistWhen: v => v !== null })`
- 스냅샷: `{ keyword: string, detailValues: PageSearchFieldValues }`
- 최초 진입(세션 없음): 기본 상세검색값(수주일자 기간 = 시스템일자 기준 기본값) 적용 후 조회
- 재진입(세션 있음): 저장된 빠른검색어/상세검색값으로 즉시 조회, 검색 영역 입력값도 복원
- 검색 실행 시 세션 갱신

## 2. 수주번호 클릭 → 상세 패널

- 수주번호 셀: 텍스트 버튼(`aria-label="{수주번호} 상세 보기"`)
- 같은 수주가 여러 상세 행으로 표시되어도 `salesOrderId` 기준으로 패널을 연다.
- 병합된 수주번호(여러 상세 행)에서도 링크를 클릭할 수 있어야 한다. 링크는 `position: relative; z-index: 1`로 F1-Grid의 투명한 후속 병합 셀 위에 놓는다. F1-Grid의 병합 영역 행 선택 동작은 바꾸지 않는다.
- 구조(문서현황과 동일): `PageAreaOverlay` → `PostDetailPanel(title="수주 상세", subtitle=수주번호)`
  - 작성자 행: 아바타(`createdByProfileImage`, 없거나 로드 실패 시 이니셜) + 작성자명 + `등록 YYYY-MM-DD HH:mm`
  - 툴바: 수주상태 Chip, 더보기 IconButton(`aria-label="수주 더보기"`)
  - 메인 정보: 수주일자, 거래처, 견적번호, 납기일자, 납품장소, 배송방법, 총 합계, 비고
  - 상세 정보: 행 / 품목코드 / 품목명 / 수량 / 단가 / 합계 / 납기 / 행상태 (간단 표, 모바일은 가로 스크롤)
- 닫기: 닫기 버튼, 배경 클릭, Esc
- 로딩/오류: 로딩 문구 `수주 상세를 불러오는 중입니다.`, 오류 시 Alert

## 3. 더보기 메뉴

| 메뉴 | 표시 조건 | 동작 |
| --- | --- | --- |
| 자세히보기 | 항상 | 수주등록 화면을 읽기 전용(`mode="view"`)으로 다이얼로그 표시 |
| 수정 | `writer === true` AND 수주등록 메뉴(`/sales/order/create`) `update` 권한 AND 상태 `수주등록` AND 출하수량 0 | 수주등록 화면을 수정 모드(`mode="edit"`)로 다이얼로그 표시 |

## 4. 수주등록 화면 재사용 props

| prop | 설명 |
| --- | --- |
| `mode?: 'create' \| 'edit' \| 'view'` | 기본 `create`. `view`는 모든 입력/그리드 비활성, 신규/저장/삭제 숨김 |
| `salesOrderId?: number` | 지정 시 마운트 후 `getSalesOrder`로 불러와 상·하단 세팅 |
| `embedded?: boolean` | 다이얼로그 내 표시: 페이지 제목/경로·상단 액션바(신규/저장/삭제) 숨김, 본문 패딩 0으로 다이얼로그 본문을 꽉 채움 |
| `onSaved?(order)` | 수정 저장 후 호출(다이얼로그 닫고 목록·패널 새로고침) |
| `onDeleted?()` | 삭제 후 호출(다이얼로그·패널 닫고 목록 새로고침) |
| `onDirtyChange?(dirty)` | 미저장 변경 여부 전달(다이얼로그 닫기 확인) |
| `onEmbeddedActionsChange?(state)` | embedded일 때 `{ canSave, saveDisabled, canDelete, deleteDisabled, saving, save, remove }`를 상위로 전달(언마운트 시 `null`) |

- 다이얼로그: 공통 `CommonDialog size="lg" bodyMode="fill" fullScreenOnMobile`, 제목 `수주 상세보기`/`수주 수정`
- 하단 버튼(공통 모달 footer):
  - 수정: 우측 공통 스타일 `저장`(contained, 아이콘 없음, 저장 중 스피너, 변경 없거나 저장 중이면 비활성) → `취소`(text), 좌측 `삭제`(error outlined, 삭제 권한·삭제 가능 상태일 때)
  - 상세보기: 우측 `닫기`(text)만 표시
  - `취소`/`닫기`/X는 미저장 변경이 있으면 확인 후 닫음
  - `삭제` 클릭 시 공통 확인 모달(`UnsavedChangesConfirmDialog`, 제목 `수주 삭제`, `삭제`(error)/`취소`)로 확인 후 삭제(브라우저 confirm 사용 안 함)
- 수정 저장·삭제 후 메인 그리드는 조용한 로딩(`useSalesOrderStatusList.refreshQuietly`)으로 재조회: 그리드 로딩 오버레이·조회 버튼 비활성 없이 행만 갱신. 조회 버튼/조건 변경 조회는 기존처럼 로딩 표시.
- 수주 기본정보·수주 상세는 다이얼로그 본문 높이/너비를 꽉 채우고, 상세 그리드가 남은 높이를 차지한다.
- 수정 모드 권한은 수주등록 메뉴 권한(없으면 수정 불가 → 읽기 전용)

## 5. API 계약 확장 (`GET /api/v1/sales/orders/{id}`)

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `createdBy` | string | 작성자 로그인 코드 |
| `createdByName` | string \| null | 작성자명(`tb_user.user_nm`, 없으면 null) |
| `createdByProfileImage` | string \| null | 작성자 프로필 이미지(`tb_login_account.profile_image`, 문서 기안자와 같은 출처) |
| `createdAt` | string(datetime) | 등록일시 |
| `writer` | boolean | 로그인 사용자 = 작성자 여부 |

- 조인: `tb_sales_order_hd.created_by = tb_login_account.login_code` (테넌트 동일) → `tb_user.login_id`
- DB 변경 없음

## 6. 검증 기준

- 재마운트 시 검색어/상세검색 값 복원 및 같은 조건으로 조회
- 수주번호 클릭 시 패널 표시, 메인/상세 표시
- 작성자 아님 → `수정` 미표시, 작성자 → 표시
- `자세히보기` → 저장 버튼 없음, 입력 비활성
- `수정` → 저장 시 PUT 호출, 목록 재조회
