## 화면 계약

### 17:01 후속 요청 우선 적용

- 아래 최초 계약 중 선택창의 `선택 해제` UI는 폐기한다. 품목 및 거래처 대·소분류 선택창의 하단에는 `선택`, `취소`만 이 순서로 표시한다.
- 선택 버튼은 기존 유효한 활성 분류를 선택한 경우에만 활성화한다. 취소와 헤더 X는 기존 값을 변경하지 않고 닫는다.
- API의 명시적 null 처리 및 대분류 변경에 따른 소분류 초기화 계약은 유지한다. 별도 해제 UI를 추가하지 않는다.

- 품목 목록에 `품목분류`를 표시한다. 값은 `대 > 중 > 소` 경로이며 원하는 1~3단계 선택을 허용한다. 저장값은 선택 노드 ID 하나다. 기존 `matCataType` 문자열은 그대로 보존하고 새 분류와 혼용하지 않는다.
- 거래처 목록에 `거래처 대분류`, `거래처 소분류`를 표시한다. 각각 ID `businessKind1/2`와 표시명 `businessKind1Name/2Name`을 사용한다.
- 셀 더블클릭 → 코드 선택 버튼 → CommonDialog의 읽기 전용 F1Tree. 행 폼에서도 동일하게 선택할 수 있다. 직접 텍스트 입력 대신 선택/선택 해제로만 변경한다.
- 품목은 전체 활성 계층에서 선택한다. 거래처 대분류 선택창은 1단계만 선택 가능, 소분류 선택창은 2단계만 선택 가능하다. 대분류가 지정되어 있으면 해당 하위만 선택 가능하며 미지정 시 모든 활성 2단계 중 선택 후 대분류도 자동 지정한다.
- 대분류가 변경되면 소분류를 비운다. 대분류 해제는 두 값을 모두 비우고 소분류 해제는 대분류를 유지한다.
- 비활성 노드 및 비활성 조상을 가진 노드는 새로 선택할 수 없다. 기존 연결된 비활성 분류는 표시·유지하되 신규 지정은 금지한다.
- 로딩/조회 오류/재시도/빈 목록, 취소 및 헤더 X를 지원한다. 취소는 편집값을 바꾸지 않는다. 선택만으로 저장하지 않고 기존 페이지 저장으로 batch 요청한다.
- 현재 마스터의 등록/수정 권한 및 미저장 보호는 그대로 둔다. 분류 선택을 위해 tenant-admin 제한을 새로 추가하지 않는다.
- 375/768/1280px에서 공통 팝업과 트리 내부 스크롤을 확인한다.

## API 및 서버 검증

- 기존 materials/customers GET/POST/PUT/save-batch 경로를 확장한다. 조회와 canonical 저장 응답에 품목 `itemClsId: Long?`, `itemClsPath: String?`, 거래처 `businessKind1/2: Long?`, `businessKind1Name/2Name: String?`를 포함한다.
- 저장은 ID만 받고 표시명은 서버 조회 결과를 사용한다. null은 해제다. 기존 클라이언트가 분류 필드를 보내지 않은 업데이트는 기존 ID를 유지한다. 거래처 각 ID 필드의 미전송도 기존 값 유지로 해석하고 최종 조합을 검증한다.
- 인증 tenant만 사용한다. 선택 ID는 양수 정수, JS 안전 정수 범위 이내여야 한다. 존재하지 않거나 다른 tenant인 ID, 비활성 신규 지정 및 잘못된 계층은 HTTP 400의 기존 입력 오류로 반환한다.
- 품목: 최대 3단계, 조상 존재/레벨/활성을 검사한다. 거래처: kind1은 root/level1, kind2는 level2이며 kind1을 실제 부모로 가져야 한다. 소분류만 존재하는 조합은 금지한다.
- 업데이트에서 최종 ID(거래처는 두 ID 조합)가 기존과 같으면 비활성 분류 유지가 가능하다. 관련 없는 필드 수정 때문에 과거 참조를 삭제하지 않는다.
- 단건과 batch는 같은 서비스 검증을 거치며 잘못된 행이 있으면 기존 batch transaction 정책대로 롤백한다. 생성자/수정자/시간은 기존 서버 로직을 유지한다.
- DB 컬럼 및 FK 변경은 없으므로 새 SQL은 작성하지 않는다. Mapper의 표시명 조회도 tenant 조건을 포함하고 비활성 row는 표시명 조회에서 제거하지 않는다.
