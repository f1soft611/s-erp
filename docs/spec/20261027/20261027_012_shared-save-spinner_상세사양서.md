# 저장 버튼 소형 스피너 공통 사양

근거: [작업지시서](../../directions/20261027/20261027_012_shared-save-spinner_작업지시서.md), [계획서](../../plan/20261027/20261027_012_shared-save-spinner_계획서.md).

기존 조용한 저장/편집 잠금 및 공지 저장 진행 계약을 유지하며 작은 스피너 표현만 공통화한다.

## 공통 컴포넌트

`AppSaveButton`은 MUI Button props를 지원하되 MUI의 별도 loading 속성은 노출하지 않는다.

| 속성 | 계약 |
|---|---|
| saving | 기본 false. true일 때 AppLoadingSpinner 16px, color inherit를 기존 startIcon 대신 표시 |
| savingLabel | 선택. 저장 중 문구를 지정하며 생략 시 원래 children 유지 |
| progressLabel | 기본 `저장 중`. 기존 업무별 접근성 라벨도 전달 가능 |
| children | 기본 `저장`. 기존 화면 문구를 보존 |
| disabled | 기존 조건 또는 saving일 때 비활성화 |
| aria-busy | saving 상태 반영. 기존 버튼 aria-label은 우선 보존하며 문자열 문구의 접근성 이름에 스피너 이름이 중복되지 않도록 함 |

저장 실패/완료로 saving이 false가 되면 스피너가 사라지고 원래 아이콘·문구·disabled 조건으로 돌아온다. 컴포넌트는 요청 실행/dirty/권한/오류/닫기 상태를 관리하지 않는다.

## 페이지/모달 연결

PermissionActionDefinition은 `saving?: boolean`, `savingAriaLabel?: string`을 제공한다. 공통 페이지 액션은 AppSaveButton을 사용하되 저장 액션에만 saving을 전달한다. disabled라고 저장 중으로 추측하거나 버튼 문구로 저장 여부를 판별하지 않는다.

기존 저장 문구가 `저장 중...`, `저장 중…`, `처리 중...`, `변경 중...`, `저장 중`인 소비자는 그대로 유지하고 기존 정적 `저장` 버튼은 문구를 바꾸지 않고 스피너만 추가한다. 조회·삭제·선택·로컬 행 폼 적용에는 저장 spinner를 새로 추가하지 않는다.

적용: 공통코드/거래처/품목/기안양식/메뉴/권한/모듈/창고/수주등록 페이지; 프로필/보안 변경; 분류관리, 공통코드 도움말, 기안양식 본문, 공지 작성·로그인 팝업, 문서 작성·결재선 저장·이름 저장, 수주 편집, 자료실 파일 편집 모달.

이미 저장 스피너가 있는 버튼도 공통 컴포넌트로 이관해 중복하지 않는다. 저장 후 조용한 재조회까지 유지되는 기존 saving 수명은 변경하지 않는다. 문서 작성은 기존 isSaving이 두 액션에 공유되므로 기존 문구처럼 두 액션 모두 진행 표시하며 추가 상태를 만들지 않는다.

## 검증

일반/진행/완료/실패 상태, 중복 클릭 차단, 기존 disabled 보존, PageHeader 권한별 표시, CommonDialog에서 동일 표시, 기존 업무별 spinner 라벨, 실제 페이지/모달 저장 지연 회귀를 확인한다. 브라우저는 합성 데이터만 사용해 375/768/1280px에서 작은 spinner·텍스트·버튼 겹침/페이지 넘침을 확인한다. 전체 로딩 overlay나 DB/API 변경은 없다.
