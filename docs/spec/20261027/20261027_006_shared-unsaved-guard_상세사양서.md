# 공통 미저장 브라우저 이탈 보호 사양

## 근거

- [계획서](../../plan/20261027/20261027_006_shared-unsaved-guard_계획서.md)

## 공통 훅

- API: `useUnsavedChangesBeforeUnload(enabled: boolean): void`.
- enabled=true일 때만 window `beforeunload`에서 preventDefault 및 legacy returnValue를 설정한다.
- false 전환과 unmount에서 자신의 listener를 제거한다. 다른 인스턴스의 보호는 제거하지 않는다.
- 경고 표시 여부/문구는 브라우저가 결정한다. 사용자 상호작용 없는 페이지, 모바일 강제 종료 등에는 표시가 보장되지 않는다.
- 이 훅은 저장/자동복원/내부 SPA 이동 차단 기능이 아니며 dirty를 판별하거나 API를 호출하지 않는다.

## 수주등록

- 기존 `hasUnsavedChanges` 계산과 useBlocker를 유지한다.
- 내부 이동이 blocked이면 공통 UnsavedChangesConfirmDialog를 표시한다.
- 제목: `저장하지 않은 변경사항`.
- 설명: `저장되지 않은 수주 내용이 있습니다. 이동하면 입력 내용이 사라집니다. 이동하시겠습니까?`
- 취소: `계속 작성`; reset 후 입력 보존. Escape/backdrop 닫기도 취소다.
- 진행: `변경사항 버리고 이동`; proceed로 차단된 원래 목적지 이동.
- 깨끗하거나 저장 완료 상태면 확인창 없이 이동한다. window.confirm은 호출하지 않는다.
- 브라우저 전체 이탈은 같은 미저장 boolean으로 공통 훅을 사용한다.

## 적용 및 제외

- 계획서의 13개 기존 dirty 소유자에 연결한다. 관리 화면 9개(수주 포함), 편집창 4개다.
- 열린 편집창만 보호한다. 자주 쓰는 결재선은 관리창의 미저장 이름 변경만 연결한다.
- 조회 필터/행 선택만으로는 경고하지 않는다. 저장 성공/폐기 후 dirty 해제는 기존 정책을 따른다.
- 기존 dirty 판별이 없는 문서/공지 본문·댓글·프로필 등은 이번 작업으로 새 변경 감지 기준을 만들지 않는다.
- 현재 편집 중이지만 아직 grid change로 확정되지 않은 draft의 감지는 기존 dirty 계약 범위다. 전역 DOM 추적은 추가하지 않는다.
- 다른 화면 내부 메뉴 이동은 이번에 새로 차단하지 않는다.

## 검증

- hook의 깨끗함/변경/원복/해제/동시 소비자/재mount 생명주기를 검사한다.
- 수주 내부 이동의 진행·취소·Escape, dirty 브라우저 이탈, 저장 성공 후 보호 해제를 검사한다.
- 대표 관리 화면 저장 성공/실패와 편집창 닫힘 상태를 기존 테스트에서 확인한다.
- 실제 브라우저에서 공통 dialog와 native beforeunload를 각각 확인하고, 합성 데이터만 375/768/1280px 스크린샷에 남긴다.
- 백엔드/API/DB/스키마는 변경하지 않는다.
