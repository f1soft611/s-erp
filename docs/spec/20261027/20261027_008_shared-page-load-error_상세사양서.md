# 공통 최초 조회 실패 상세 사양

근거: [작업지시서](../../directions/20261027/20261027_008_shared-page-load-error_작업지시서.md), [계획서](../../plan/20261027/20261027_008_shared-page-load-error_계획서.md).

## 상태 계약

- 필수 자원 단위로 초기 미완료 → 요청 중 → 성공 또는 실패를 관리한다.
- 성공은 행 개수가 아니라 요청 완료로 판별한다. 0건 성공도 정상 레이아웃이다.
- 실패 전 최초 성공이 없으면 본문 전체를 오류 안내/재시도로 대체한다. PageHeader/앱 탐색은 유지한다.
- 실패 후 retry 중에는 오류 안내를 유지하고 버튼을 비활성화한다. 성공하면 정상 본문을 복구한다.
- 최초 성공 이후 조회 실패는 전체 본문 대체를 하지 않는다. 기존 rows/form을 유지하고 기존 인라인/알림 오류를 사용한다.
- 역할관리의 확인 후 재조회도 실제 목록 적용에 성공한 뒤에만 편집 기준을 초기화한다. 실패하면 저장 후 동기화 대기 내용과 재시도 기록을 유지해 중복 저장을 방지한다.
- 저장·삭제·업로드·상세·추가 페이지 오류는 전체 본문 대체 대상이 아니다.
- 최신 request id/AbortSignal/active 검증을 통과한 결과만 공통 상태를 갱신한다.
- 취소 요청은 연결 오류가 아니다.

## 오류 표시

| 원인 | 표시 |
|---|---|
| fetch 또는 본문 수신 실패 | 연결하지 못했습니다. 네트워크 상태를 확인한 뒤 다시 시도해 주세요. |
| 401 | 로그인이 필요합니다. 다시 로그인해 주세요. |
| 403 | 조회 권한이 없습니다. 접근 권한을 확인해 주세요. |
| 그 외 HTTP/업무 실패 또는 예상하지 못한 응답 | 정보를 불러오지 못했습니다. 잠시 후 다시 시도해 주세요. |

브라우저 fetch 실패만으로 실제 원인이 인터넷 단절/서버 중단/CORS/DNS 중 무엇인지 단정하지 않는다. 응답으로 받은 서버 오류에 ‘네트워크 상태’ 안내를 붙이지 않는다. 기존 인증 만료/로그아웃 정책을 우회하지 않는다. 내부 예외 내용과 민감한 응답은 공통 본문에 노출하지 않는다.

## 페이지 연결

| 화면 | 필수 초기 자원 / 재시도 |
|---|---|
| 모듈·역할·창고·공통코드 관리 | 기존 목록 조회, 기존 필터 |
| 메뉴관리 | 모듈·활성권한·역할 및 세션에서 선택된 메뉴 목록 |
| 거래처관리 | 거래처 목록 |
| 품목관리 | 품목 목록 + 옵션 |
| 기안양식관리 | 목록 / 분류·주기·사용자 옵션 각각 |
| 공지사항 | 일반·고정 목록 |
| 자료실 | 검색 기본값 / 분류 / 파일 목록 각각 |
| 문서현황 | 검색 기본값 / 문서 목록 각각 |
| 전자결재 작성 목록 | 일반·고정 목록 + 요약 |
| 수주현황 (병행 작업에서 추가된 화면) | 검색 기본값 / 수주 목록 각각 |
| 내 정보 | 내 프로필 |
| 앱 최초 진입 | 사용자 메뉴 + 모듈, 기존 자동 재시도 유지 |

수주 신규 작성·보안 설정·로그인·정적 종합현황/문서/예제/준비 중/404에는 필수 초기 데이터 조회가 없으므로 변경하지 않는다. 화면 내 편집창과 도우미의 오류는 해당 영역에 남긴다.

## 공통 인터페이스

`useInitialLoadState`는 stable `start/succeed/fail` 함수와 `error`, `loading`을 반환한다. `PageLoadBoundary`는 error, loading, label, onRetry, children을 받는다. error가 null이면 children을 그대로 반환한다. 오류가 있으면 반응형 중앙 안내와 접근 가능한 `<label> 다시 불러오기` 아이콘 버튼을 렌더링한다. 일반 본문의 fetch/저장 책임은 갖지 않는다.

## 검증

무응답/HTTP 500/401/403, retry pending 중 중복 클릭 차단, 실패 재시도 성공, 빈 성공, 최초 성공 이후 실패, 독립적인 필수 자원, 취소/오래된 요청 무시를 테스트한다. 대표 관리 화면에서 기존 rows 보존을 확인한다. 375/768/1280px 실제 브라우저로 오류 본문·정상 복구·페이지 가로 넘침을 확인하고 결과 스크린샷을 기록한다.

백엔드/API 데이터 계약/DB 변경은 없다. 순수 프론트엔드 오류 표시 및 lifecycle 변경이다.
