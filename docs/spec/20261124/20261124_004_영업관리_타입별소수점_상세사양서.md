# 영업관리 타입별 소수점 상세사양서

## 정책

- 정책의 기준은 모듈 코드와 F1-Grid의 기존 `number`, `decimal`, `currency` 타입이다.
- 새 타입별 정책의 기본 자릿수는 `number` 0, `decimal` 3, `currency` 3이며 각 타입에 0 표시와 반올림 방식을 지정한다. 허용 자릿수는 0~6이다.
- 옵션 우선순위는 항목별로 컬럼 `decimal` 객체, 컬럼 개별 옵션, 타입별 정책, 그리드 기본 순서다.
- 저장에 영향을 주는 영업 숫자 컬럼별 예외는 화면 코드에만 중복 기입하지 않고 프론트와 서버가 함께 배포하는 공통 계약에 정의한다. 계약은 업무·컬럼 식별자와 타입, 선택적인 자릿수·반올림·0 표시를 담는다. 지정한 항목만 타입 정책보다 우선한다.
- 서버는 배포된 공통 계약을 기준으로 검증·계산한다. 프론트의 계약과 서버의 계약이 다르면 서버는 저장을 HTTP 409로 거부한다. 클라이언트가 보낸 설정을 권위 있는 규칙으로 사용하지 않는다. 기존 스냅샷 없는 API 호환은 컬럼별 예외가 없는 경우에만 유지한다.
- 공통 계약은 `frontend/src/shared/config/decimal-column-contract.json`에 저장하고 Maven이 동일 파일을 서버 리소스에 포함한다. 업무 식별자와 필드 식별자로 구분하며 각 필드는 `type`과 선택적인 `places`, `rounding`, `trailingZeros`를 갖는다. 저장 요청은 해당 업무의 계약 전체를 `decimalColumns`로 전달하고 서버는 배포된 계약과 비교한다. 프론트와 서버는 계약을 함께 배포해야 하며 DB 스키마는 변경하지 않는다.
- 공통 계약에 없는 과거 숫자 컬럼의 그리드 동작은 변경하지 않는다. 이 계약은 영업 화면부터 적용하며 다른 모듈도 고유 업무·컬럼 식별자를 등록해 재사용할 수 있다. 저장 필드 간 의미가 다르면 화면 필드명만으로 동일 필드라고 추정하지 않는다.
- 서버 공통 규칙 해석기는 업무가 전달한 타입별 기본 규칙을 기준으로 컬럼별 부분 예외를 적용한다. 특정 모듈의 정책 조회·기본값이나 업무 계산 순서는 공통 해석기에 하드코딩하지 않는다.
- 정책이 바뀌면 이후 조회와 계산에 갱신된 정책을 적용한다.
- 수주 상세 데이터가 금액 정책보다 먼저 조회되거나 열린 화면에서 정책이 갱신되면 현재 상세 행의 합계를 해당 금액 정책으로 다시 표시한다. 편집 중인 행도 포함하며 상세 원본 금액은 변경하지 않는다.
- 영업 등록·수정 저장은 정책 조회가 완료되고 성공한 경우에만 허용하며 조회 실패를 정책 미등록과 구분한다.
- 정책 응답에 `item`이 없거나 타입별 규칙이 불완전하면 조회 실패로 처리한다. 빈 `item` 객체는 정책 미등록으로 처리하며 실패 후 다시 시도할 수 있다.
- 편집 중 정책 변경 또는 붙여넣기로 현재 수량·단가와 표시된 계산 금액이 불일치하면 저장을 차단하고 재계산이 필요하다고 안내한다. 수동 부가세는 다시 자동 계산하지 않는다.
- 자동 출하계획의 기존 계획수량과 계획잔량은 십진 합산하여 수정 가능한 수량을 계산하고, 부동소수점 오차로 허용 수량을 거부하지 않는다.
- 출하계획 현황 상세의 수량과 미출하·초과출하는 수량 정책의 자릿수와 반올림을 따르며 차이는 십진 계산한다.
- 수주·견적·출하·출하계획의 화면 저장 요청은 조회한 `number`, `decimal`, `currency` 규칙의 자릿수 및 반올림 스냅샷을 전달한다. 서버는 실제 계산·검증에 쓸 정책과 다르면 HTTP 409로 저장을 거부하고 재조회하도록 안내한다. 스냅샷을 보내지 않는 기존 API 호출의 동작은 유지한다.
- 기존 단일 규칙 스냅샷은 세 규칙이 모두 일치할 때 허용한다. `currency`가 누락된 타입별 스냅샷은 금액 계산의 동시 변경을 확인할 수 없으므로 HTTP 409로 거부한다.
- 이력에는 변경 전·후를 분리해 타입, 자릿수, 0 표시, 반올림 방식을 표시한다. 기존 단일 값은 전체 타입의 종전 규칙으로 표시하고 생성·삭제로 값이 없으면 `없음`을 표시한다. 다른 정책도 기존 선택지와 사용 여부를 읽기 쉬운 이름으로 표시한다.
- 이력의 변경 강조: 변경 전 → 변경 후 순서로 배치하고 사이에 화살표 아이콘을 둔다(좁은 화면은 위→아래 화살표). 소수점 정책은 타입별 실효 규칙을 비교해 다른 항목(자릿수, 0 표시, 반올림)만 강조한다. 변경 전 단일 규칙은 어느 타입과라도 다르면 해당 항목을 강조한다. 변경 전 강조는 붉은 배경·취소선, 변경 후 강조는 초록 배경·굵은 글씨이며 바뀐 행 왼쪽에 색상 막대를, 변경 후 제목 옆에 `N곳 변경`을 표시한다. 그 밖의 정책과 생성·삭제(`없음`)는 값 전체가 다르면 강조한다. 색상만으로 구분하지 않도록 취소선·굵기·막대를 함께 사용한다.

## 영업 화면과 저장

- 수량·순서·No에 대응하는 숫자는 `number`, 단가는 `decimal`, 공급가·부가세·합계 등 금액은 `currency`를 적용한다. 자동 순번 컬럼은 `rownumber`를 유지하고 식별자와 문자는 원래 의미를 유지한다.
- 입력 제한과 서버 검증은 유효 자릿수를 초과한 값이 저장 시 묵시적으로 변형되지 않게 한다.
- 숫자 셀에 붙여넣을 때 해당 컬럼의 `onValueChange`를 셀 직접 편집과 같이 실행한다. 같은 행의 여러 셀은 앞서 적용한 값을 다음 계산에 사용한다.
- 수주·견적·출하·거래명세서 현황의 상세 표와 요약도 수량은 `number`, 단가는 `decimal`, 금액은 `currency` 정책에 맞게 표시한다.
- 거래명세서 인쇄와 미리보기는 같은 정책으로 품목과 전체 합계를 표시하고 합계는 십진 계산한다.
- 출하계획의 분할 합계는 십진 계산으로 수주 잔량과 비교하고 `number` 정책으로 표시한다.
- 영업 수량·단가·금액 저장 컬럼은 기존 정수부 범위를 유지하면서 소수점 6자리까지 저장한다.
- 영업 숫자는 입력부터 재조회까지 십진 원문을 보존한다. 정확한 십진 계산은 정수 계수와 소수 자릿수를 사용하고, 중간에 JavaScript `number`로 변환하지 않는다. 기존 숫자 기반 업무는 기존 계약을 유지한다.
- 영업 API 응답의 지정된 금액·수량 숫자 토큰만 십진 문자열로 읽고 식별자와 다른 업무의 JSON 숫자 계약은 유지한다. 요청의 십진 문자열은 서버의 `BigDecimal` 입력으로 전달한다.
- F1-Grid의 십진 문자열 컬럼은 직접 편집 시 적용된 정책 또는 컬럼 자릿수를 넘는 입력을 거부한다. 0자리에서는 소수점을 입력하지 않으며, 3자리에서는 소수 셋째 자리까지만 입력한다. 유효한 입력은 숫자로 변환하지 않고 유지한다. 셀 붙여넣기에서 자릿수를 넘는 원문은 잘라내지 않고 저장 검증에서 거부한다. 이 설정을 지정하지 않은 컬럼은 기존 숫자 변환과 입력 제한을 유지한다.
- 읽기 전용 십진 문자열 셀은 초과 자릿수의 조회값을 정책에 따라 반올림해 표시하고 원본은 유지한다. 행별 `editable` 판정도 적용하며, 편집 가능한 셀의 초과 입력은 원문을 표시한다. 집계는 읽기 전용 표시 규칙을 따른다.
- 각 계산 결과는 해당 결과 컬럼에 별도 자릿수·반올림 설정이 있으면 이를, 없으면 해당 타입의 모듈 정책을 사용한다. 서버와 프론트는 같은 규칙을 사용하며 입력 단가를 먼저 2자리로 반올림하지 않는다.
- 기존 데이터의 이관·정리는 요구하지 않는다. 스키마 축소 롤백은 2자리로 표현할 수 없는 값이 있으면 중단한다.
- 거래명세서 헤더의 `customerId`는 기존 대표 출하 헤더에서 출하 ID와 테넌트 ID를 함께 사용해 조회한다. 거래명세서 헤더에 없는 컬럼을 참조하거나 DB 컬럼을 추가하지 않는다. 동일 거래처의 여러 출하는 한 명세서로 묶을 수 있다.

## 검증

- 타입별 기본값과 개별 정책, 컬럼별 부분 재정의, 0·3·6자리 및 반올림 방식을 확인한다.
- 영업 등록·수정에서 입력, 계산, 저장 및 재조회가 일치하고 유효하지 않은 값은 오류로 처리되는지 확인한다.
- 영업 외 업무에서 공통 계산과 기존 정책의 동작이 의도치 않게 바뀌지 않는지 확인한다.
- 정책 화면과 영업 화면은 실제 브라우저에서 반응형 및 저장 흐름을 점검하고 결과에 기록한다.
