## DB

| 테이블 | 변경 |
| --- | --- |
| `tb_process_group` | 변경 없음(개념상 작업장) |
| `tb_process` | `group_id`, FK `(tenant_id, group_id)`, 인덱스 `idx_process_group` 제거. `UNIQUE (tenant_id, process_id)` 추가. 테넌트 단위 공정 마스터가 된다. |
| `tb_process_group_process` (신규) | `map_id` identity PK, `tenant_id`, `group_id`, `process_id`, `sort_seq` 기본 0, `created_at`, `updated_at`. `UNIQUE (tenant_id, group_id, process_id)`, FK `(tenant_id, group_id)`→`tb_process_group`, FK `(tenant_id, process_id)`→`tb_process`. |

이관: 테넌트·이름·`inactive`·9개 플래그가 같은 공정을 한 그룹으로 묶고 최소 `process_id`를 마스터로 삼는다. 모든 기존 `(group_id, process_id)`를 마스터 기준 매핑으로 만들고(같은 작업장 안 중복은 하나로 합침) 마스터 외 행은 삭제한다.

## 트리 API: `/api/v1/pr/processes`

- `GET`: 작업장 행 `g:<group_id>`(`parentId` null)와 연결 행 `m:<map_id>`(`parentId` = `g:<group_id>`)를 반환한다. 연결 행은 마스터의 이름·설명·이미지·플래그를 담고 `processId`(마스터 ID)와 `code`(= 마스터 ID 문자열)를 가진다.
- `POST /save-batch`: 같은 `ProcessChangesVO` 형식.
  - 신규 `g:new-*`, 신규 연결 `m:new-*`(`parentId`는 `g:<id>` 또는 같은 요청의 `g:new-*`, `processId` 필수).
  - 수정은 작업장(`g:`)만 허용한다. 연결 행 수정은 거부한다.
  - 삭제는 작업장·연결 행. 연결이 남은 작업장은 삭제하지 않는다. 같은 요청에서 연결과 작업장을 함께 삭제하면 연결을 먼저 삭제한다.
  - 같은 작업장에 같은 공정을 중복 연결하면 `이미 연결된 공정입니다.`로 거부한다. 존재하지 않거나 다른 테넌트의 공정·작업장은 거부한다.
  - 이름 1~100자, 설명 255자 이하는 기존과 같다.
  - 권한은 기존과 같이 메뉴의 생성·수정·삭제 권한으로 검사한다.

## 공정 마스터 API

- `GET /api/v1/pr/processes/masters`: 테넌트의 공정 마스터를 `p:<process_id>` 행(`parentId` null)으로 반환한다.
- `POST /api/v1/pr/processes/masters/save-batch`: 같은 `ProcessChangesVO` 형식. 신규 `p:new-*`, 수정·삭제 `p:<id>`. 이름 1~100자, 설명 255자 이하, 이미지 PNG/JPEG·512KB·실제 형식 검증은 기존과 같다. `parentId`는 null이어야 한다. 작업장에 연결된 공정 마스터는 삭제할 수 없고 `연결된 작업장이 있는 공정은 삭제할 수 없습니다.`를 반환한다. 응답은 저장 후 마스터 목록이다.
- 권한은 같은 메뉴(`/pr/master/process-management`)의 조회·생성·수정·삭제를 따른다.

## 화면

- 문구: 헤더 버튼 `작업장 추가`, 검색 placeholder `작업장 / 공정 검색`, 트리 컬럼 `작업장 / 공정명`, 컨텍스트 메뉴 `작업장 추가`·`공정 추가`.
- 트리: 작업장 행은 이름·설명·미사용을 편집한다. 연결 행은 모든 셀을 읽기 전용으로 표시하며 수정은 공정 설정에서 한다.
- `공정 추가`(버튼·컨텍스트 메뉴): 대상 작업장을 정한 뒤 `공정 선택` 모달을 연다. 사용 중이고 그 작업장에 아직 없는 마스터를 다중 선택해 연결 행을 추가한다. 선택 가능한 공정이 없으면 안내 문구를 표시한다. 공정이 선택되면 트리에 연결 행이 추가되고 저장 버튼으로 반영한다.
- `공정 설정` 버튼: 생성·수정·삭제 권한 중 하나라도 있으면 표시한다. 미저장 트리 변경이 있거나 로딩·저장 중이면 비활성화한다. 모달에서 마스터 그리드를 편집하고 모달의 저장 버튼으로 저장한다. 저장하면 트리를 다시 조회한다. 미저장 변경이 있으면 닫을 때 확인한다. 삭제는 선택 행 삭제 후 저장하며 서버가 연결 여부를 검사한다.
- 트리의 삭제는 작업장 또는 연결 행을 삭제한다. 연결이 있는 작업장은 삭제할 수 없다는 메시지를 표시한다. 이미지는 마스터 모달에서만 편집한다.
- 헤더 버튼 순서: `공정 설정`, `작업장 추가`, `공정 추가`, `조회`, `저장`, 삭제.
- `조회` 버튼: 조회 권한이 있을 때만 표시하고 작업장 트리를 다시 조회한다. 저장하지 않은 변경이 있으면 공통 확인 모달(`useCommonConfirmDialog`, "저장하지 않은 변경사항")에서 확인한 뒤에만 조회하고, 취소하면 변경을 유지한다. 브라우저 새로고침의 `beforeunload` 안내는 플랫폼 동작이라 그대로 둔다.
- 공정 설정 모달 저장 성공 시 토스트 `공정을 저장했습니다.`를 표시하고, 작업장 트리는 로딩 표시와 오류 메시지 초기화 없이 조용히(silent) 다시 조회한다. 조용한 재조회가 실패하면 페이지 오류 메시지를 표시한다.
- 저장 흐름(진행 표시·성공/실패 메시지·dirty 초기화·저장 후 갱신)은 기존 공정관리와 같다.

## 검증 기준

- 서비스: 연결 행 신규/삭제 검증, 수정 거부, 중복 연결·미존재 거부, 마스터 삭제 차단, 이미지 검증 유지.
- 프론트: 연결 행 읽기 전용, 공정 선택 후 `m:new-*` 행 제출, 공정 설정 저장 후 재조회, 문구 변경.
- 실제 브라우저(375/768/1280px)에서 트리와 두 모달을 확인한다.
