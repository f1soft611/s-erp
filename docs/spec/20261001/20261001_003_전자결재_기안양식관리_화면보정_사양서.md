## 2. 분류 설정 모달

### 레이아웃과 스크롤

- 모달은 제목, 오류 안내, 행 추가 액션, Grid, 하단 저장/취소 액션으로 구성한다.
- Grid 컨테이너는 모달 콘텐츠에서 남는 공간을 채우며 `min-height: 0`을 포함한 flex 제약을 적용한다.
- 세로로 긴 분류 목록은 Grid 내부에서 스크롤한다. 모달 본문이나 페이지 전체가 목록 길이만큼 늘어나지 않는다.
- 모바일의 기존 full-screen 규칙과 제목/하단 액션은 유지한다.

### 편집 및 저장

- 별도 row form modal 또는 하단 상세 입력 폼을 표시하지 않는다.
- 행 추가 액션으로 신규 행을 추가하고 Grid 셀에서 편집한다. 기존 저장 행도 Grid 셀 편집을 허용한다.
- 변경 집합은 신규 행을 `insertedRows`, 실제 변경된 저장 행을 `updatedRows`로 구분한다.
- 편집 값이 원래 값과 동등하면 updated 상태가 없어야 한다. 공백/숫자·문자 형태가 기존 Grid 비교 계약상 동등한지 확인해 일관되게 비교한다.
- 저장은 기존 하단 저장 버튼 한 곳에서 수행한다. 신규 행은 기존 create API, 수정 행은 기존 update API를 사용한다.
- 저장 중에는 Grid 전체를 가리는 로딩 상태를 표시하지 않는다. 저장 버튼을 비활성화하고 버튼 내부 또는 인접한 작은 진행 표시를 보여 중복 제출을 막는다.
- 저장 완료 후 목록 재조회 및 변경 상태 초기화를 수행한다. 실패 시 모달 내 오류 안내를 유지하고 재시도할 수 있어야 한다.
- create/update 요청과 `onReload()`가 모두 성공한 뒤 기존 `NotificationContext`를 통해 `공통코드를 저장했습니다.` 성공 toast를 한 번 표시한다. 저장 또는 재조회 실패 시 성공 toast는 표시하지 않고 기존 오류 흐름을 유지한다.
- 물리 삭제와 새 API는 제공하지 않는다. 기존 삭제 컨텍스트 메뉴 정책을 유지한다.
- 셀 편집 중 Grid의 다른 셀로 포커스를 옮기면 현재 편집값을 commit하고 dirty 변경 집합 및 저장 버튼 상태를 갱신한다. 그리드를 감싸는 부모 Dialog/Modal은 편집기 popup으로 간주하지 않는다.
- 편집기가 별도 portal 기반 Select/Date/Time popup을 열어 포커스가 해당 popup으로 이동하는 경우에는 blur commit을 보류해 popup 선택이 가능해야 한다.
- 변경이 있는 상태에서 하단 취소 또는 제목 X로 닫기를 요청하면 `UnsavedChangesConfirmDialog`를 표시한다.
- 확인창 취소 시 확인창만 닫고 분류 설정 모달, 편집값, dirty 상태를 모두 유지한다.
- 확인창 계속 시 pending 변경을 버리고 dirty/Grid 상태를 초기화한 다음 분류 설정 모달을 닫는다. 변경이 없으면 확인 없이 즉시 닫는다.

## 3. 기안양식 Grid 값 표현 및 변경 추적

### Select 컬럼

- `categoryItemId`, `regTermId`, `reviewerId`, `approverId`, `useAt`의 기존 값 타입/API 계약을 바꾸지 않는다.
- 편집 상태에서 옵션을 선택하면 컬럼 데이터에는 기존 값 타입에 맞는 값(ID 또는 코드)을 저장한다.
- 비편집 상태에서는 select 원시 값 대신 옵션의 표시명(label)을 렌더링한다.
- 저장된 행에서 select 편집기를 열고 값을 변경하지 않은 뒤 종료하면 Grid 변경 집합에 해당 행을 추가하지 않는다.
- 다른 옵션으로 변경하면 행을 dirty로 표시하고 원래 ID/코드가 아닌 선택한 ID/코드를 기존 API payload로 보낸다.
- 신규 행은 기존 필수값 검증과 저장 동작을 유지한다.

### 저장 후 조용한 재조회

- 기안양식 저장 중에는 저장 액션을 비활성화하고 작은 진행 아이콘을 표시해 중복 제출을 막는다.
- 저장 완료 후 목록을 갱신하는 동안에는 기존 행을 유지하고 메인 Grid 전체 로딩 오버레이를 표시하지 않는다.
- 초기 진입과 사용자가 직접 실행한 조회/상세검색의 로딩 표시는 기존 동작을 유지한다.
- 저장 또는 조용한 재조회 실패 시 기존 오류 안내를 표시하고 미저장 변경사항을 임의로 폐기하지 않는다.

### Dirty 상태에서 조회/상세검색

- 기안양식 그리드에 inserted/updated/deleted 변경이 없는 경우 기존 조회 및 상세검색 적용 동작을 그대로 수행한다.
- dirty 상태에서 조회 액션, 검색어 Enter 적용 또는 상세검색 적용으로 현재 목록을 교체하려 하면 `UnsavedChangesConfirmDialog`를 표시한다.
- 확인창 제목은 `저장하지 않은 변경사항`, 설명은 `변경사항을 버리고 기안양식 목록을 다시 불러오시겠습니까?`, 액션은 `취소`와 `계속`을 사용한다.
- 취소 시 보류 중인 검색 조건을 폐기하고 확인창만 닫는다. 현재 Grid 행, 편집값, dirty 상태와 저장 액션 활성 상태를 유지하며 목록 API를 호출하지 않는다.
- 계속 시 dirty Grid 상태를 초기화하고 확인창을 닫은 뒤 사용자가 요청한 검색 조건으로 목록 API를 한 번 호출한다. 검색어/상세 검색 값은 요청을 보류한 시점의 값을 사용한다.
- 완료 후 조회된 행을 표시하고 dirty/저장 액션을 초기 상태로 돌린다. 실패 시 기존 목록 오류 표시 규칙을 따른다.
- 패턴은 `ModuleManagementPage`와 `CommonCodeManagementPage`의 조회 확인 동작을 따른다. 페이지 메뉴 전환이나 브라우저 종료에 대한 전역 이탈 가드는 이번 범위에 추가하지 않는다.

### 검토자와 승인자 미선택

- 옵션 목록에 `선택 안 함`을 포함한다.
- 서버 응답의 null 또는 편집 값의 빈 선택은 표시 label `선택 안 함`으로 나타낸다.
- 저장 payload 값은 기존처럼 `null`로 정규화하며 문자열 `"선택 안 함"`이나 빈 문자열을 사용자 ID로 보내지 않는다.

## 4. 기안양식관리 레이아웃

- `PageHeader`, `PageSearchArea`, 메시지 영역 다음 Grid 컨테이너 바깥의 위·아래·좌·우 여백을 모듈관리 페이지의 `CardContent p: 1`과 맞춰 각 8px로 설정한다.
- 여백 조정 외 반응형 동작, Grid 높이/스크롤, 검색 및 액션 배치는 변경하지 않는다.
- 375px, 768px, 1280px 화면에서 콘텐츠 겹침과 페이지 전체 가로 overflow가 없어야 한다.

## 5. API, DB, 권한 및 오류 처리

- API: 변경 없음. `draftFormManagement.service.ts`의 기존 기안양식 및 common-code item CRUD 호출을 재사용한다.
- 분류 ID 저장: 기존 `category_item_id` 및 `WF_FORM_CATEGORY` common-code item ID 계약을 유지한다. `drafting_work_category_group_id`나 분류 그룹 테이블로 전환하지 않는다.
- DB: 변경 없음. 신규 SQL, migration, rollback은 작성하지 않는다.
- 권한: 기존 tenant admin 및 메뉴 `CREATE`/`UPDATE` 권한 판단을 유지한다.
- 확인 다이얼로그는 기존 `UnsavedChangesConfirmDialog`를 재사용하며 새 권한/API 계약을 추가하지 않는다.
- 오류: 기존 API 예외 메시지는 모달 내 오류 안내에 표시한다. 저장 중 오류가 발생해도 편집 내용은 임의로 버리지 않는다.

## 6. 테스트와 브라우저 완료 기준

- 도움창: 신규 행 추가 후 저장 시 create 호출, 저장된 행 변경 시 update 호출, 변경 없는 기존 행은 update되지 않음, 저장 중 중복 제출 방지 및 오류 표시.
- 저장 피드백: create/update 및 reload 성공 후 `공통코드를 저장했습니다.` 공통 toast가 표시되고, 실패 시 success toast가 표시되지 않는다.
- 셀 이동 dirty: 부모 Dialog 내부에서 셀을 편집한 뒤 다른 셀을 클릭하면 편집값이 commit되고 dirty/저장 상태가 갱신된다. 부모 Dialog 자체는 editor popup guard로 취급하지 않으며, 실제 portal editor popup 보류 동작은 유지한다.
- dirty 확인: 기안양식 조회/상세검색에서 취소하면 편집 행과 dirty 상태가 유지되고 API가 호출되지 않음; 계속하면 보류한 필터로 한 번 조회하고 변경 상태가 초기화됨. 분류 설정 닫기/취소도 같은 취소/계속 결과를 보장함.
- 기안양식: select를 변경하지 않았을 때 dirty 없음, 실제 변경 시 dirty 및 올바른 ID payload, 비편집 label 렌더링, 검토자/승인자 null의 `선택 안 함` 표시.
- 저장 피드백: 저장 API와 저장 후 목록 재조회 중 작은 진행 아이콘은 표시하고 Grid 전체 오버레이는 숨긴다. 초기/직접 조회는 기존 Grid 로딩을 유지한다.
- 시각 확인: 모달 Grid 영역 채움 및 내부 스크롤, 메인 Grid 네 방향 여백, 375/768/1280px 반응형 레이아웃.
- 자동 검증: 해당 페이지/도움창 Vitest, 필요 시 관련 F1-Grid focused tests, `npm run build`.
- F1-Grid core 변경은 `GridCell`의 popup 판별에서 현재 GridCell을 포함하는 상위 container를 제외하는 단일 보정으로 제한한다. 다른 core 기능/API는 변경하지 않는다.
- 실제 브라우저에서 동작과 스크린샷을 확인하고 결과 폴더의 원장/보고서에 명령 및 관찰 결과를 기록한다.
