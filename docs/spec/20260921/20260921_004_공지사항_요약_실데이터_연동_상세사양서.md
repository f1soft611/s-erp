# 20260921_004 공지사항 요약 실데이터 연동 상세 사양서

## 1. 화면 대상

- 경로: `/groupware/community/notice`
- 상위 화면 컴포넌트: `CommunityNoticePage`
- 요약 컴포넌트: `NoticeSummaryPanel`
- 데이터 서비스: `fetchNoticePosts`

## 2. 데이터 흐름

```text
fetchNoticePosts()
  -> NoticeBoardPostApi[]
  -> toNoticeFeedItem()
  -> noticeItems
  -> deriveNoticeSummary(noticeItems)
  -> NoticeSummaryPanel
```

필터 변경으로 `noticeItems`가 다시 로드되면 요약 통계와 최근 이슈도 같은 목록 기준으로 다시 계산한다.

## 3. 요약 통계 계약

```ts
type NoticeSummaryStat = {
  label: string;
  value: string;
};
```

표시 항목은 아래 순서로 고정한다.

| label     | 계산 규칙                                                                    |
| --------- | ---------------------------------------------------------------------------- |
| 전체 공지 | `noticeItems.length`                                                         |
| 이번 주   | 유효한 `createdAt`이 현재 주의 시작일 이상이고 다음 주 시작일 미만인 항목 수 |
| 중요 공지 | `isNotice === 'Y'`인 항목 수                                                 |
| 첨부 문서 | 각 항목의 `attachmentDetails.length` 합계, 없으면 0                          |

표시 값은 정수 문자열이며, 천 단위 구분이 필요한 경우 기존 화면 포맷 규칙을 따른다. 목록이 비어 있으면 모든 값은 `0`이다.

## 4. 최근 이슈 계약

```ts
type NoticeRecentIssue = {
  id: number;
  title: string;
  viewCount: number;
  commentCount: number;
  score: number;
};
```

### 점수와 정렬

- `viewCount`는 `item.meta` 문자열에서 추출하지 않고 별도 데이터 필드로 유지한다.
- API 변환 시 `NoticeFeedItem.viewCount`에 원본 조회수를 연결한다.
- `commentCount`와 `viewCount`는 `Number(...)` 변환 후 유한한 0 이상 정수로 정규화한다.
- `score = viewCount + commentCount`
- 점수 내림차순
- 동점이면 `createdAt` 최신순
- 날짜까지 같으면 `id` 내림차순
- 상위 3개까지만 표시

최근 이슈 항목에는 다음 텍스트를 표시한다.

```text
{title}
조회 {viewCount} · 댓글 {commentCount} · 점수 {score}
```

목록이 비어 있으면 하드코딩된 샘플 대신 `최근 이슈가 없습니다.`를 표시한다.

## 5. 컴포넌트 계약

```ts
type NoticeSummaryPanelProps = {
  stats: NoticeSummaryStat[];
  recentIssues: NoticeRecentIssue[];
  isDark: boolean;
};
```

`NoticeSummaryPanel`은 API를 직접 호출하지 않으며, 전달받은 계산 결과만 렌더링한다. 기존 LIVE 표시와 카드 레이아웃은 유지한다.

## 6. API 계약

- 기존 목록 API 사용: `GET /api/v1/groupware/boards/notice/posts`
- 요청·응답 형식 변경 없음
- 기존 응답 필드 재사용:
  - `postId`
  - `viewCount`
  - `commentCount`
  - `isNotice`
  - `createdAt`
  - `attachments`
- 별도 API, 백엔드 DTO, DB 변경 없음

## 7. 예외 및 권한

- 목록 API 실패 시 기존 페이지 오류·재시도 처리를 유지한다.
- 목록이 비어 있거나 일부 필드가 누락되어도 요약 영역은 예외를 발생시키지 않는다.
- 기존 공지사항 인증·권한 정책을 변경하지 않는다.
- 클라이언트 계산 결과는 화면 표시용이며 서버 데이터 저장이나 권한 판단에 사용하지 않는다.

## 8. 반응형 기준

- 375px: 요약 카드와 최근 이슈의 제목·수치가 잘리지 않고 가로 스크롤이 없어야 한다.
- 768px: 요약 영역과 피드의 배치가 겹치지 않아야 한다.
- 1280px: 기존 2열 레이아웃과 카드 폭을 유지한다.
- 긴 공지 제목은 컨테이너 내부에서 줄바꿈 또는 말줄임으로 처리한다.

## 9. 회귀 검증

1. 목록 3건에서 전체 공지 수가 3으로 표시된다.
2. 이번 주·중요 공지·첨부 문서 수가 입력 데이터와 일치한다.
3. 조회수와 댓글수 합산 점수 순으로 최근 이슈가 정렬된다.
4. 점수 동점 시 최신 작성일과 게시글 ID 규칙이 적용된다.
5. 최근 이슈가 최대 3개를 초과하지 않는다.
6. 빈 목록에서 요약 수치가 0이고 최근 이슈 빈 상태가 표시된다.
7. 누락된 조회수·댓글수·첨부파일이 0으로 처리된다.
8. 필터 변경 후 요약 영역이 새 목록에 맞춰 갱신된다.
9. 기존 목록·상세·댓글·첨부파일 회귀 테스트가 유지된다.
