# 20260921_002 공지사항 작성 모달 제목 강조 및 이미지 노드 리사이즈 상세 사양서

## 1. 대상 화면

- 경로: `/groupware/community/notice`
- 대상 컴포넌트: `NoticeComposerDialog`
- 적용 모드: 신규 작성 및 기존 공지 수정

## 2. 제목 입력 UI

- 제목 `TextField`의 입력 텍스트는 `fontWeight: 700`으로 표시한다.
- 피드의 공지 제목과 동일한 굵기 수준을 사용한다.
- placeholder 텍스트의 색상, 입력값, 저장 payload, 접근성 라벨은 변경하지 않는다.

## 3. 이미지 선택 및 노드 영역

1. 본문 이미지 클릭 시 Tiptap 이미지 노드 선택을 수행한다.
2. 선택된 이미지에는 기존 `ProseMirror-selectednode` 테두리를 표시한다.
3. 선택된 이미지의 경계를 감싸는 리사이즈 오버레이를 표시한다.
4. 오버레이는 다음 8개 방향을 제공한다.

| 방향                   | 조절 축   | 커서            |
| ---------------------- | --------- | --------------- |
| `nw`, `ne`, `sw`, `se` | 너비·높이 | 대각선 리사이즈 |
| `n`, `s`               | 높이      | `ns-resize`     |
| `w`, `e`               | 너비      | `ew-resize`     |

5. 선택이 해제되거나 다른 노드가 선택되면 오버레이를 숨긴다.
6. 오버레이는 에디터 업데이트, 선택 변경, 스크롤, 창 크기 변경 후 선택 이미지 위치에 맞춰 갱신한다.

## 4. 이미지 크기 계산

- 시작값은 포인터 다운 시점의 이미지 렌더링 너비·높이로 측정한다.
- 모서리 드래그는 시작 종횡비를 유지한다.
- 동쪽 계열 방향은 포인터의 X 변화량을 너비 변화량으로 사용한다.
- 서쪽 계열 방향은 포인터의 X 변화량을 반대로 사용한다.
- 남쪽 계열 방향은 포인터의 Y 변화량을 높이 변화량으로 사용한다.
- 북쪽 계열 방향은 포인터의 Y 변화량을 반대로 사용한다.
- 모서리 드래그는 계산된 너비와 종횡비로 높이를 산출한다.
- 너비는 최소 120px, 최대 1200px로 제한한다.
- 높이는 최소 80px로 제한하며 음수 또는 `NaN`은 허용하지 않는다.
- 계산된 값은 정수 픽셀 문자열로 변환한다.

## 5. Tiptap 노드 반영

- 포인터 이동 중 현재 선택 이미지에 다음 속성을 갱신한다.

```ts
editor.commands.updateAttributes('image', {
  width: `${width}px`,
  height: `${height}px`,
});
```

- 기존 이미지 `src`, 업로드 토큰, 파일 ID, object key, MIME 타입은 변경하지 않는다.
- 저장 시 기존 `serializeNoticeEditorJson` 및 body payload 흐름을 사용한다.
- 재조회 시 이미지의 `width`·`height` 속성이 유지되어 같은 크기로 렌더링되어야 한다.

## 6. 제거 대상

- 문서 바깥에 생성하던 `.notice-image-resize-handle` 단일 버튼
- 단일 우측 핸들의 `pointerdown` 및 위치 동기화 로직
- 단일 방향만 지원하는 `ew-resize` 스타일

## 7. API 계약

- 변경 없음
- 이미지 업로드: 기존 `uploadNoticeEmbeddedImage` 유지
- 게시글 저장: 기존 공지 저장 API와 body/bodyJson 계약 유지
- 이미지 조회 및 URL 재작성: 기존 `normalizeNoticeEmbeddedImageSources` 유지

## 8. 예외 및 경계 조건

- 선택된 이미지가 없으면 리사이즈 이벤트를 시작하지 않는다.
- DOM 이미지 위치를 Tiptap 문서 위치로 변환할 수 없으면 이벤트를 무시한다.
- 이미지가 최소 너비·높이에 도달하면 더 작아지지 않는다.
- 에디터 또는 이미지 DOM이 제거되면 오버레이와 전역 포인터 리스너를 정리한다.
- 포인터 업 이벤트가 에디터 외부에서 발생해도 리사이즈 상태를 해제한다.
- 모바일 터치 환경에서는 `touch-action: none`을 사용해 페이지 스크롤과 충돌하지 않도록 한다.

## 9. 권한 및 보안

- 권한, 인증, API 상태 코드 변경 없음
- 클라이언트에서 변경하는 것은 이미지 표시 크기 속성뿐이며 업로드 파일 계약은 변경하지 않는다.

## 10. 회귀 검증 케이스

1. 제목 입력 요소의 입력 슬롯이 `font-weight: 700`을 가진다.
2. 이미지 너비 계산이 120~1200px 범위를 벗어나지 않는다.
3. 동쪽·서쪽·북쪽·남쪽 방향의 축별 계산이 올바르다.
4. 모서리 계산 결과가 시작 종횡비를 유지한다.
5. 선택 이미지에 오버레이 조절 영역 8개가 표시된다.
6. 포인터 이동 시 이미지 노드에 `width`와 `height`가 함께 반영된다.
7. 이미지 업로드와 기존 본문 이미지 렌더링이 유지된다.
8. 375px과 1280px 이상 뷰포트에서 오버레이가 이미지 밖으로 부자연스럽게 잘리지 않는다.
