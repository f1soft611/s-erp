## 대상 및 기대 동작

| 등록 페이지 | 현황 기준 패딩 |
|---|---|
| 수주등록 | `px: { xs: 1, sm: 2 }, pt: 1, pb: 2` |
| 출하등록 | `px: { xs: 1, sm: 2 }, pt: 1, pb: 2` |
| 출하계획등록 | `px: { xs: 1, sm: 2 }, pt: 1, pb: 2` |
| 거래명세서 | `px: { xs: 1, sm: 2 }, pt: 1, pb: 2` |

현황 화면 기준의 좌우 패딩은 375px에서 8px, 768px 이상에서 16px이며, 위 8px·아래 16px이다. 네 등록 화면의 본문 래퍼를 이 값에 맞춘다.

## 메시지와 그리드 폭 정렬

- 영업 현황의 검색결과 메시지와 오류 메시지의 좌우 경계는 해당 화면의 F1Grid 경계에 맞춘다.
- 그리드 콘텐츠 래퍼 바깥에 표시되는 수주·출하·거래명세서 메시지는 그리드의 반응형 좌우 거터(`xs: 8px`, `sm` 이상: `16px`)를 사용한다.
- 메시지가 이미 거터가 적용된 출하계획현황 콘텐츠 래퍼 안에 표시되는 경우 메시지 자체의 추가 좌우 패딩은 0으로 둔다.
- 공통 메시지의 기본 패딩과 영업 현황 이외 화면의 메시지 배치는 변경하지 않는다.
- 메시지 다음에 오는 콘텐츠 래퍼의 기존 상단 간격 보정 및 메시지의 위·아래 간격은 변경하지 않는다.

## 예외와 제한

- 현황 페이지는 기준 화면이며 콘텐츠 래퍼 패딩을 변경하지 않는다.
- 수주등록의 embedded 모드 0px 패딩과 저장 오류 시 대칭 간격을 위한 별도 패딩은 유지한다.
- 거래명세서의 embedded 등록 영역 및 각 페이지의 상세/편집 패널은 대상이 아니다.
- 반응형 동작, 권한, 검색조건, 메시지 수직 간격, 데이터와 API 계약은 유지한다.

## 출하계획현황 테두리

- 출하계획현황 목록을 감싼 `Paper variant="outlined"`의 바깥 테두리를 제거한다.
- 동일한 flex 크기, 최소 높이, 최소 너비, overflow를 가진 테두리 없는 Box로 대체한다.
- F1Grid의 자체 1px `divider` 테두리, radius, 배경 및 그리드 동작은 변경하지 않는다.

## 검증

1. 네 등록 페이지가 해당 현황 페이지의 위·아래 여백과 동일한지 확인한다.
2. 출하계획현황 F1Grid 직계 래퍼가 outlined Paper가 아니며 F1Grid 자체 테두리를 유지하는지 확인한다.
3. 해당 상태 페이지 테스트와 프런트엔드 빌드 및 변경 파일 lint를 실행한다.
4. 375px, 768px, 1280px 브라우저에서 등록/현황의 콘텐츠 좌우 간격과 수직 배치를 비교하고 수평 overflow를 확인한다.
5. 스크린샷과 실제 검증 결과를 날짜별 결과 폴더에 기록한다.
