# 모바일 영업 등록 및 모듈 바 상세사양

근거: [계획서](../../plan/20261110/20261110_001_mobile-sales-grid_계획서.md), [작업지시서](../../directions/20261110/20261110_001_mobile-sales-grid_작업지시서.md).

## F1-Grid

- 모바일 판정은 대시보드와 같은 768px 미만이다.
- `rowFormPlugin` 미지정 시 모바일 편집 가능 Grid는 기존 행 폼을 기본 활성화한다. 데스크톱 미지정은 기존 즉시 추가·인라인 편집이다. 명시적 플러그인과 `enabled: false`는 기존 계약을 우선한다.
- `addRow`는 모바일에서 초안 폼을 열고 적용 시에만 행/변경 집합/합계에 반영한다. 취소·닫기는 초안을 폐기한다. 기존 컬럼의 code picker, 숫자·날짜 입력, `onValueChange`, 필수/범위/고유성 검증을 재사용한다.
- 날짜·일시·시간 행 폼 라벨은 항상 입력란 위에 표시해 빈 native 입력의 날짜·시간 placeholder와 겹치지 않게 한다.
- 모바일 편집 가능 행에는 우측 고정 `상세` 액션을 제공한다. `startEdit`도 모바일에서는 기존 편집 허용 검사 후 행 폼으로 연결한다. 폼은 편집 가능한 컬럼만 포함한다. 읽기 전용 Grid에는 자동 액션을 만들지 않는다.
- 명시적 플러그인 없이 열린 모바일 폼도 화면이 커졌다고 닫지 않으며 적용/취소까지 유지한다.
- 출하계획은 기존 분할 버튼으로 먼저 분할 행을 만들고 자동 편집을 시작한다. 모바일에서는 계획일·수량 폼이 열린다. 취소는 기존 셀 편집 취소와 동일하게 분할 행 자체를 제거하지 않으며, 분할행 삭제로 제거한다. 수주 품목별 합계·식별자·저장 순서는 유지한다.

## 등록 레이아웃

- 수주·출하·출하계획 기본정보 → 상세 도구 → F1-Grid → 기존 합계 순서와 스타일을 유지한다.
- 입력 영역은 세로 스크롤한다. 상세 패널은 도구·최소 260px 그리드·합계의 실제 높이를 수용한다. 자식이 패널의 `overflow: hidden` 밖으로 잘리면 안 된다.
- F1-Grid는 고정 컬럼 폭을 유지하고 본문 안에서 가로·세로 스크롤한다. 페이지 전체에 가로 스크롤을 만들지 않는다.
- 수주 상세 버튼은 필요 시 줄바꿈하며, 합계 세 항목을 모바일에서도 끝까지 스크롤해 볼 수 있어야 한다.
- 하단 합계가 없는 출하계획·거래명세서 상세 패널은 그리드의 좌우·아래 안쪽 여백을 모두 8px로 통일한다. 공유 폼을 쓰는 상세보기·수정에도 동일하게 적용한다. 거래명세서도 그리드 최소 높이를 수용하는 flex 구조로 맞춘다.

## 모듈 바

- 768px 미만: 좌측 92px 레일 대신 화면 상단에 아이콘·모듈명 가로 목록을 표시한다. 로고 영역은 생략하고 버튼은 줄어들지 않게 하며 넘치는 모듈은 목록 내부 가로 스크롤로 접근한다.
- 768px 이상: 기존 좌측 레일과 메뉴 접기/펼치기를 유지한다.
- 업무 메뉴는 기존 햄버거 버튼과 임시 Drawer를 사용한다. 모바일 Drawer 폭은 `min(320px, 100vw - 32px)`이며 모듈 레일용 공백을 남기지 않는다. 메뉴·즐겨찾기·최근 메뉴·권한과 라우팅은 기존 동작을 유지한다.

## 검증

- PageHeader 경로 블록은 모바일에도 가용 폭 전체를 강제 점유하지 않는다. 경로와 버튼의 실제 폭이 가용 폭 안에 들어가면 같은 줄에 표시하고 부족하면 줄바꿈한다. 긴 경로·설명·여러 버튼은 잘라내지 않는다. 487px 거래명세서현황의 설명 접기 상태를 회귀 기준으로 삼는다.

- Vitest: 옵션 없는 모바일 행 추가, 취소 무변경, 필수 검증, 적용 dirty 반영, 수정 적용/취소, 읽기 전용, 명시적 비활성화, 데스크톱 즉시 추가.
- 기존 수주·출하·계획 등록/저장 및 대시보드 테스트를 실행한다.
- 실제 브라우저 375/768/1280px: 세 등록 화면 전체 가로 넘침 없음, 내부 가로 스크롤과 마지막 컬럼 접근, 합계가 패널 안에 있고 세로 스크롤로 접근, 코드 도움창을 포함한 모바일 행 폼 입력·수정·저장, 계획 분할 폼, 상단 모듈 전환과 메뉴 열기.
- 실제 서비스/DB 데이터는 사용하지 않는다. 합성 API 응답으로 UI와 요청 내용을 검증하고 백엔드 저장 자체를 검증했다고 표현하지 않는다.
