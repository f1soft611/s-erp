## 표시 기준

| 상태/구분 | 색상 의미 | 표시 방식 |
|---|---|---|
| 임시저장 | 중립 회청 | 채움 |
| 결재진행중 | 파랑 | 채움 |
| 승인/발송완료 | 초록 | 채움 |
| 반려 | 빨강 | 채움 |
| 보완요청 | 주황 | 채움 |
| 기안 | 파랑 | outlined |
| 업무 | 초록 | outlined |
| 지출 | 주황 | outlined |
| 근태 | 보라 | outlined |
| 공지 구분 | 분류 코드별 색상 | 코드별 색상을 텍스트/테두리에 적용한 outlined |

- 위 상태/구분 의미는 문서 작성, 결재 알림, 문서 현황 리스트/피드/상세 등 표시 위치 간 동일하게 유지한다.
- 검색 결과 안내와 페이지 오류는 공통 메시지 컴포넌트의 대칭 수직 여백을 사용한다. 바로 뒤 콘텐츠 상단의 중복 패딩을 제거해 화면별로 메시지 아래 간격이 달라지지 않게 한다.
- 검색 결과 안내는 페이지 기본 배경과 구별되는 정보 톤 배경을 사용한다. 다크 모드에서는 같은 정보 색상 계열을 더 낮은 대비로 섞어 텍스트 가독성을 보존한다.
- 공지 분류는 임의 색상 재할당 대신 기존 분류 코드 기반 색상 생성과 라벨을 유지한다.
- 공지 구분 칩은 기존 채움형 스타일을 outlined 스타일로 대체한다. 다크 테마에서도 읽을 수 있는 전경색/테두리 대비를 사용한다.
- 배지 모서리와 프런트엔드 직각형 UI 모서리의 공통 기준은 6px다.
- 아바타 등 원형 UI(`50%`)와 의도적 0px 접합 경계는 예외로 둔다.
- 내부 상태 코드, 표시 라벨, 저장/조회/결재 동작, API 및 DB 계약은 변경하지 않는다.
- 라이트/다크 모두 텍스트 대비와 기존 키보드/반응형 동작을 유지한다.

## 검증 기준

1. Vitest에서 모든 상태 라벨·색상 의미·variant 및 문서구분 색상 매핑을 확인한다.
2. 문서/공지 배지의 높이·간격·텍스트·색상 계산과 6px 반경을 확인한다.
3. 원형 및 0px 경계 예외가 유지되고 명시적 직각형 반경은 6px인지 확인한다.
4. 라이트/다크 테마, 기존 공지 분류 코드별 색상 및 업무/공지 표시 회귀가 없다.
5. `npm run build`와 375px/768px/1280px 실제 브라우저 렌더링에서 잘림, 겹침, 페이지 가로 overflow가 없다.
6. 합성 데이터 스크린샷 및 결과 보고서를 날짜별 결과 폴더에 보관한다.

## 오류 처리 및 데이터 계약

- API, DB, 업무 데이터는 변경하지 않는다.
- 배지 표시 값이 없는 기존 경로의 fallback과 기존 오류 처리를 변경하지 않는다.
