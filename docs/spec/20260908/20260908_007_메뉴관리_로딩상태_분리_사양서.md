## 1. 상태 모델

### 1.1 `MenuManagementPage`

- `loading`: 메뉴 조회가 스켈레톤을 표시해야 하는 동안 `true`
- `saving`: 메뉴 저장 작업 중 `true`; 저장 버튼과 편집 관련 동작 제한에 사용
- 두 상태는 독립적으로 관리한다.
- `loadMenus(moduleId, options?)`의 옵션은 다음과 같다.
  - `reloadPermissions?: boolean`: 기존 권한 목록 재조회 여부
  - `clearVisibleMenus?: boolean`: 요청 시작 시 기존 메뉴 제거 여부
  - `roleId?: string`: 조회할 권한 ID
  - `showSkeleton?: boolean`: F1-Tree 스켈레톤 표시 여부, 기본값 `false`
- 요청 시작 시 `showSkeleton`이 `true`일 때만 `setLoading(true)`를 호출한다.
- 요청 완료·실패·취소 시 해당 요청이 최신 요청일 때만 `setLoading(false)`를 호출한다.
- 저장 후 `onRefresh`는 `showSkeleton: false`로 호출한다.

### 1.2 호출별 정책

| 상황                         | `showSkeleton` | 기존 메뉴 행     | 목적                 |
| ---------------------------- | -------------: | ---------------- | -------------------- |
| 페이지 최초 진입의 메뉴 조회 |         `true` | 초기 상태        | 최초 로딩 안내       |
| `조회` 버튼                  |         `true` | 요청 옵션에 따름 | 명시적 재조회 피드백 |
| 검색어 Enter 재조회          |         `true` | 기존 로직 유지   | 조회 동작과 동일     |
| 모듈 변경/권한 변경          |         `true` | 필요 시 비움     | 새 컨텍스트 로딩     |
| 저장 후 재조회               |        `false` | 유지             | 조용한 갱신          |

초기 모듈·권한 선택이 완료되지 않은 경우에는 메뉴 API를 호출하지 않고 안내 문구를 유지한다.

## 2. 컴포넌트 계약

### `MenuManagementPanelProps`

- `menuGridLoading?: boolean` 추가
- 기본값은 `false`
- 내부 `F1Tree`에 `loading={menuGridLoading}` 전달
- `F1Tree`와 F1-Grid 공통 로딩 구현이 `GridLoadingSkeleton`을 렌더링한다.

스켈레톤 표시 중에도 `F1Tree`의 헤더, 컬럼, 높이, 컨테이너 레이아웃은 유지한다.

## 3. API 계약

API 엔드포인트와 요청/응답 구조는 변경하지 않는다.

- 메뉴 조회: 기존 `fetchMenuRows(moduleId, roleId)`
- 모듈 목록: 기존 `fetchModules()`
- 활성 권한 목록: 기존 `fetchActivePermissions()`
- 역할 목록: 기존 `fetchRoleRows()`
- 메뉴 저장: 기존 `saveMenuChanges(...)`
- 역할별 메뉴 권한 저장: 기존 `saveRoleMenuPermissions(...)`

HTTP 오류는 기존 서비스 계층의 `Error` 메시지를 `PageMessageArea`로 표시한다. 조회 실패 시 메뉴 행을 비우는 기존 동작과 저장 실패 시 `saving=false` 복구 동작을 유지한다.

## 4. UI 및 접근성

- `F1Tree`의 기존 `ariaLabel="F1-TREE 메뉴 관리"`를 유지한다.
- 스켈레톤은 기존 `GridLoadingSkeleton`의 `data-testid="grid-loading-row-skeleton"`를 통해 테스트한다.
- 스켈레톤 중 메뉴 관리 헤더와 그리드 컬럼 헤더는 화면에 남아 있어야 한다.
- 모바일 레이아웃의 기존 유동 폭과 내부 스크롤 규칙을 변경하지 않는다.

## 5. 권한 및 예외

- 조회/저장 버튼 노출은 기존 `selectedMenuPermissions` 기반 정책을 유지한다.
- 모듈과 권한이 모두 선택되지 않으면 메뉴 조회와 저장을 실행하지 않는다.
- 저장 중에는 중복 저장 및 컨텍스트 전환을 막는 기존 `saving` 조건을 유지한다.
- 오래된 조회 응답은 `menuLoadRequestIdRef`로 무시한다.

## 6. 테스트 사양

1. 메뉴 목록 요청을 지연한 최초 진입에서 행 스켈레톤과 그리드 헤더가 함께 표시된다.
2. 메뉴 목록이 완료되면 행 스켈레톤이 사라지고 메뉴 데이터가 표시된다.
3. 조회 버튼 클릭 후 지연된 요청 중 행 스켈레톤이 표시된다.
4. 저장 후 재조회 요청을 지연해도 행 스켈레톤이 표시되지 않는다.
5. 저장 실패 시 오류 메시지가 표시되고 저장 상태가 해제된다.
6. 모듈·권한 미선택 시 메뉴 API가 호출되지 않는다.

## 7. DB 영향

없음. 프론트엔드 상태 표시와 컴포넌트 prop 연결만 변경한다.
