## 1. 메뉴관리 검색조건 필수화 + 스켈레톤

### 1.1 상태 정의 (`MenuManagementPage.tsx`)

- 기존 `selectedModuleId: number | undefined`, `selectedRoleId: string`(빈 문자열이 "미선택")을 그대로 사용한다.
- 파생 값: `hasRequiredSelection = Boolean(selectedModuleId) && Boolean(selectedRoleId)`.

### 1.2 조회 동작 변경

- `loadMenus`, `requestModuleChange`, `requestRoleChange`, `requestRefresh` 함수의 시작부에서 `hasRequiredSelection`이 `false`이면:
  - `fetchMenuRows` 등 API 호출을 수행하지 않는다.
  - `menus`를 빈 배열로 설정(또는 유지)하고 `loading`을 `false`로 유지한다.
  - 단, 권한 목록(`fetchActivePermissions`)과 모듈 목록(`fetchModules`), 역할 목록(`fetchRoleRows`)은 최초 진입 시 그대로 로드한다(권한/역할 Select 옵션 채우기 위함).
- 모듈 변경 시 권한 선택은 초기화하지 않는다(기존 선택 권한 유지, 단 목록에 없으면 유지 여부는 기존 로직 따름).

### 1.3 안내 문구 UI

- `hasRequiredSelection`이 `false`인 경우, `MenuManagementPanel`이 렌더링하던 `F1Tree` 대신 안내 영역을 표시한다.
- 안내 문구: `"모듈과 권한을 모두 선택하세요."`
- 표시 위치: 트리 영역(`Box sx={{ flex: 1, minHeight: 0 }}`) 내부, 중앙 정렬 `Typography` (variant="body1", color="text.secondary").
- 구현 방식: `MenuManagementPanel`에 `disabledMessage?: string` prop을 추가하거나, `MenuManagementPage`에서 직접 조건부 렌더링으로 `MenuManagementPanel` 대신 안내 Box를 렌더링한다. (권장: `MenuManagementPage`에서 `hasRequiredSelection`이 false면 `MenuManagementPanel` 대신 안내 Box를 렌더링 — 컴포넌트 책임 분리 유지)

### 1.4 저장 버튼 비활성화

- `pageActionGroups`의 `write` 액션 `disabled` 조건을 다음과 같이 변경한다:
  ```tsx
  disabled: !dirty || saving || !selectedModuleId || !selectedRoleId,
  ```
- 조회 액션(`read`)의 `onClick`도 `hasRequiredSelection`이 `false`이면 아무 동작하지 않도록 가드한다.

### 1.5 스켈레톤 적용

- `MenuManagementPanel`에 `menuGridLoading?: boolean` prop을 추가한다.
- `MenuManagementPage`에서 `<MenuManagementPanel ... menuGridLoading={loading} />`로 전달한다(모듈+권한이 모두 선택된 상태에서만 패널이 렌더링되므로 `loading`을 그대로 사용 가능).
- `MenuManagementPanel` 내부 `<F1Tree ... />`에 `loading={menuGridLoading}` prop을 추가한다. `F1Tree`는 `F1Grid` props를 그대로 전달(spread)하므로 `F1Grid` 내부의 `GridLoadingSkeleton`이 자동으로 적용된다(권한관리 페이지의 `F1Grid loading={roleGridLoading}`과 동일 패턴).
- 최초 진입, 모듈 변경, 권한 변경 시 `loading`이 `true`가 되므로 스켈레톤이 자동 노출된다(기존 `loadMenus`의 `setLoading(true/false)` 로직 재사용, 별도 신규 상태 불필요).

### 1.6 예외 처리

- 모듈/권한 목록 조회 실패 시 기존 `error` state와 `PageMessageArea`를 그대로 사용한다(변경 없음).

## 2. 새로고침 시 메뉴없음 UX 개선

### 2.1 상태 추가 (`DashboardPage.tsx`)

```tsx
const [menusLoading, setMenusLoading] = useState(true);
```

### 2.2 로딩 흐름 변경

```tsx
useEffect(() => {
  let cancelled = false;
  setMenusLoading(true);

  Promise.all([fetchMyMenus(), fetchModuleRows().catch(() => [])])
    .then(([response, moduleRows]) => {
      if (cancelled) return;
      const sourceModules = buildModuleDescriptors(
        response ?? { user: { userId: '', roles: [] }, menus: [] },
      );
      setModuleItems(
        buildModuleItems(hydrateModuleDescriptors(sourceModules, moduleRows)),
      );
    })
    .finally(() => {
      if (!cancelled) setMenusLoading(false);
    });

  return () => {
    cancelled = true;
  };
}, []);
```

- 기존 로직(`buildModuleDescriptors`, `hydrateModuleDescriptors`, `buildModuleItems`)은 변경하지 않고 `.finally()`로 `menusLoading`만 추가한다.
- API 실패 시에도(`fetchMyMenus`가 reject되는 경우) `.finally()`가 실행되어 무한 로딩을 방지한다. 단, 현재 `fetchMyMenus()`에는 `.catch`가 없으므로 실패 시 promise chain이 catch 없이 종료될 수 있다 — `fetchMyMenus()`도 `.catch(() => undefined)` 처리를 추가해 `.finally`가 항상 도달하도록 보강한다.

### 2.3 렌더링 3단 분기

기존:

```tsx
{hasAccessibleMenu ? ( ...대시보드... ) : ( ...메뉴없음... )}
```

변경:

```tsx
{menusLoading ? (
  <Box sx={{ flex: 1, display: 'flex', alignItems: 'center', justifyContent: 'center' }}>
    <CircularProgress size={32} />
  </Box>
) : hasAccessibleMenu ? (
  ...기존 대시보드 렌더링(변경 없음)...
) : (
  <Box sx={{ flex: 1, display: 'flex', alignItems: 'center', justifyContent: 'center', px: 3 }}>
    <Typography variant="h6" sx={{ fontWeight: 700 }}>
      접근 가능한 메뉴가 없습니다.
    </Typography>
  </Box>
)}
```

- `CircularProgress`는 `@mui/material`에서 import 추가.
- 로딩 중에는 `DashboardSidebar` 등 나머지 레이아웃도 표시하지 않고 중앙 스피너만 표시한다(사이드바가 빈 상태로 깜빡이는 것을 방지).
- `hasAccessibleMenu = moduleItems.length > 0` 계산은 변경하지 않는다.

## 3. NotFound 페이지 추가

### 3.1 신규 컴포넌트: `frontend/src/pages/errors/NotFoundPage.tsx`

- 레이아웃(첨부 이미지 기준):
  - 전체 화면 중앙 정렬, 배경색 `#f2f2f2` 계열(theme `background.default` 사용).
  - 제목: `요청하신 페이지를 찾을 수 없습니다` (variant="h6", fontWeight 700).
  - 안내문: `주소가 변경되었거나 페이지가 삭제되었을 수 있습니다.` (variant="body2", color="text.secondary").
  - 버튼: `돌아가기` (variant="contained", color="dark"/기본, MUI `Button`).
  - 하단 카피라이트: `© 2026 FoodLink Cloud · F1soft` (variant="caption", color="text.disabled", 화면 최하단 고정 또는 페이지 하단 배치).
- 버튼 클릭 핸들러:
  ```tsx
  const navigate = useNavigate();
  const handleGoBack = () => {
    navigate(isAuthenticated() ? '/dashboard' : '/login', { replace: true });
  };
  ```
- `isAuthenticated`는 `frontend/src/shared/services/authService.ts`에서 import.

### 3.2 라우터 변경 (`AppRouter.tsx`)

기존:

```tsx
<Route
  path="*"
  element={
    <Navigate to={isAuthenticated() ? '/dashboard' : '/login'} replace />
  }
/>
```

변경:

```tsx
<Route path="*" element={<NotFoundPage />} />
```

- `import { NotFoundPage } from '../pages/errors/NotFoundPage';` 추가.
- 인증 여부와 무관하게 정의되지 않은 모든 경로에서 `NotFoundPage`를 렌더링한다(요구사항 3.1).
- `/dashboard/*` 하위 라우트는 `DashboardPage` 내부에서 자체적으로 세그먼트를 해석하므로 이번 변경의 영향을 받지 않는다(기존 동작 유지).

### 3.3 접근성

- 버튼에 `aria-label="돌아가기"` 지정.
- 페이지 최상위에 `role="main"` 또는 시맨틱 컨테이너 사용.
