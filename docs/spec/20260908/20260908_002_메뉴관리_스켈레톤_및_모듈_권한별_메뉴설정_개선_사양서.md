# 메뉴관리 페이지 스켈레톤 UI 적용 및 모듈/권한별 메뉴 설정 개선 사양서

## 1. 화면 UI 사양

### 1.1 페이지 레이아웃 및 상단 버튼 영역 (`MenuManagementPage.tsx`)

- **PageHeader**:
  - `breadcrumbItems={[selectedModule.name, currentMenuName]}`
  - **버튼 영역 (`actionGroups`)**: [저장] 등 주요 동작 버튼 배치
- **PageSearchArea**:
  - **모듈 선택 Select**: `selectedModuleId` 선택 Dropdown (모듈 목록: `fetchModules()`)
  - **권한 선택 Select**: `selectedRoleId` 선택 Dropdown (역할 목록: `fetchRoleRows()`)
  - **통합 검색 TextField**: 메뉴명, 메뉴코드, 경로, 설명 기준 필터링
- **PageMessageArea**: 조회/저장/삭제 결과 메시지 안내
- **콘텐츠 영역**: `MenuManagementPanel` (F1-Tree/F1-Grid 1개)

### 1.2 F1-Grid / F1-Tree 스켈레톤 UI (`MenuManagementPanel.tsx`)

- `loading` prop 지원: `loading={pageLoading || menuGridLoading}`
- `loading === true` 시 권한 관리 페이지(`RoleManagementPanel`)와 동일하게 Skeleton 행 UI 노출.

### 1.3 모듈별 · 권한별 메뉴 및 버튼 권한 저장 구조 및 DB 테이블 현황

- **기존 DB 테이블 존재 현황**:
  - `tb_role`: 역할/권한 마스터 (`role_id`, `tenant_id`, `role_code`, `role_nm` 등)
  - `tb_module`: 모듈 마스터 (`module_id`, `tenant_id`, `module_code`, `module_nm` 등)
  - `tb_menu`: 메뉴 마스터 (`menu_id`, `tenant_id`, `module_id`, `parent_menu_id` 등)
  - `tb_permission`: 버튼/기능 권한 마스터 (`permission_id`, `permission_code`: READ, CREATE, UPDATE, DELETE, EXCEL 등)
  - `tb_menu_permission`: 메뉴별 허용 가능한 기본 버튼 권한 마스터
  - `tb_role_menu_permission`: 역할(Role)-메뉴(Menu)-버튼권한(Permission) 3자 매핑 테이블 (이미 DB 스키마에 구축됨)

- **권한별 메뉴 및 버튼 권한 저장 메커니즘**:
  1. **조회/동기화**: 상단 검색 조건에서 [모듈]과 [권한(Role)]을 선택하면, 해당 권한(`roleId`)에 매핑된 메뉴 활성화 여부(`enabled`)와 허용된 버튼 권한 체크박스(READ, CREATE, UPDATE, DELETE, EXCEL 등)가 그리드/트리에 로드됨.
  2. **편집**: 사용자가 그리드/트리에서 특정 메뉴의 활성화 여부 체크 및 버튼 권한 체크박스를 토글함.
  3. **저장**: PageHeader 우측 상단의 **[저장]** 버튼 클릭 시, 선택된 권한(`roleId`) 관점의 메뉴-버튼권한 변경 목록이 백엔드로 전송되어 `tb_role_menu_permission` 테이블에 반영(INSERT / DELETE / UPDATE)됨.

### 1.4 다중 권한 지원 및 활성화 정책

- 사용자가 여러 개의 역할/권한(Role)에 속해 있을 때, 속한 권한 중 1개라도 메뉴 및 해당 버튼 권한이 `Y`(또는 허용) 상태인 경우 UI/기능이 활성화되는 정책 유지.

## 2. API 계약 및 데이터 구조

- `GET /api/v1/system/modules` : 모듈 목록 조회
- `GET /api/v1/system/roles` : 역할/권한 목록 조회
- `GET /api/v1/system/menus?moduleId={moduleId}&roleId={roleId}` : 선택된 모듈 및 권한(Role) 기준 메뉴 목록 및 매핑된 버튼 권한 정보 조회
- `GET /api/v1/system/permissions` : 버튼 권한 마스터 목록 (READ, CREATE, UPDATE, DELETE, EXCEL) 조회
- `PUT /api/v1/system/roles/{roleId}/menu-permissions` : 선택된 권한(Role)의 메뉴 및 버튼 권한 매핑 일괄 저장/업데이트

### 2.1 F1-Grid 컬럼 확장 계약

```typescript
type F1GridCellRenderContext<T extends object> = {
  row: T;
  rowId: F1GridRowId;
  column: F1GridColumn<T>;
  value: unknown;
  rowIndex: number;
};

type F1GridCellProps = {
  className?: string;
  style?: React.CSSProperties;
  title?: string;
  'aria-label'?: string;
};
```

`F1GridColumn<T>`은 다음 선택적 확장 함수를 지원한다.

- `renderCell(context): ReactNode`: 표시 모드의 셀 콘텐츠를 직접 구성한다. `span`, `button`, `a`, 배지 등 개발자 정의 태그를 사용할 수 있다.
- `getCellStyle(context): React.CSSProperties`: 행 또는 값 상태에 따른 동적 셀 스타일을 반환한다.
- `getCellProps(context): F1GridCellProps`: `className`, `style`, `title`, `aria-label`을 반환한다.

함수가 없으면 기존 기본 값 표시를 사용한다. 문자열 CSS(`style="color:red;background-color:blue"`)는 지원하지 않으며, 스타일은 `React.CSSProperties` 객체로 지정한다. `renderCell`은 표시 모드에만 적용하고, 편집 모드에서는 기존 `CellEditor`와 editor plugin 생명주기를 우선한다.

### 2.2 편집 가능 컬럼 헤더 표시 계약

- 편집 가능 여부는 활성 editor plugin이 하나 이상이고 해당 컬럼에 대해 하나 이상의 행이 `isCellEditable(column, row) === true`인지로 판정한다.
- `editable`이 함수인 경우 현재 행별 결과를 사용한다.
- 편집 가능 컬럼은 헤더 하단 border에 테마의 강조 색상을 표시한다.
- 해당 표시는 헤더명, 정렬 아이콘, 필터 아이콘, 메뉴 버튼, 리사이즈 핸들, 고정 컬럼 배경을 가리지 않아야 한다.

## 3. 예외 처리 및 하위 호환성

- 모듈 또는 권한 선택 변경 시 unsaved changes(dirty 상태)가 존재할 경우 변경사항 확인 다이얼로그(`UnsavedChangesConfirmDialog`) 노출.
- API 에러 발생 시 PageMessageArea 및 Notification Toast로 명확한 사용자 안내 메시지 출력.
- `renderCell`, `getCellStyle`, `getCellProps`가 없는 기존 컬럼은 현재 표시·편집 동작을 그대로 유지한다.

## 4. 검증 기준

1. 표시 모드에서 `renderCell`이 반환한 사용자 정의 태그가 렌더링된다.
2. `getCellStyle`과 `getCellProps.style`의 동적 스타일이 셀에 적용된다.
3. `getCellProps.className`, `title`, `aria-label`이 셀 루트에 반영된다.
4. 편집 모드 진입 시 커스텀 표시 렌더러가 에디터를 가리지 않는다.
5. 활성 editor plugin이 없으면 편집 가능 헤더 표시가 나타나지 않는다.
6. 행별 `editable` 조건에 따라 편집 가능 헤더 표시가 나타난다.
7. 기존 컬럼 테스트와 정렬·필터·고정·리사이즈·dirty 표시 회귀 동작이 유지된다.
