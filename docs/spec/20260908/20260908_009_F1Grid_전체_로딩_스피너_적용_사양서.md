# 상세 사양서

## 제목

F1-Grid 전체 영역 로딩 스피너 적용

## 1. 컴포넌트 구조

```text
F1Grid root (role="grid", position: relative)
├─ header scroll area
├─ body scroll area
│  └─ loading=true: existing GridLoadingSkeleton
└─ loading=true: full-grid loading overlay
   └─ existing refresh loading spinner pattern
```

- 오버레이는 `F1Grid` root의 직접 자식으로 둔다.
- root가 이미 `position: relative`이므로 별도 좌표 계산 없이 `inset: 0`으로 헤더·본문을 모두 덮는다.
- 오버레이는 스피너를 중앙 정렬하고, 배경은 기존 그리드 내용이 인지될 정도의 반투명 색상으로 처리한다.
- 오버레이는 전체 그리드 영역의 pointer event를 차단한다.
- 로딩이 아니면 오버레이를 렌더링하지 않는다.

## 2. 로딩 상태 계약

### 입력

- 기존 `F1GridProps.loading?: boolean`을 그대로 사용한다.
- `F1TreeProps`는 기존 상속 구조를 통해 동일한 `loading` 계약을 사용한다.
- 각 페이지의 `loading` 값 생성·전달 방식은 변경하지 않는다.

### 로딩 중

- `F1Grid` root에 `aria-busy="true"`를 설정한다.
- `GridLoadingSkeleton`과 `grid-loading-row-skeleton`은 기존 조건에 따라 계속 렌더링한다.
- 헤더와 본문 위에 오버레이·스피너를 표시한다.
- 오버레이의 pointer event 차단으로 셀 편집, 행 선택, 헤더 정렬·필터, 컨텍스트 메뉴 입력을 적용하지 않는다.

### 로딩 종료

- `aria-busy`를 `false` 또는 비표시 상태로 되돌린다.
- 오버레이와 스피너를 제거한다.
- 기존 `GridBody` 또는 기존 로딩 완료 후 렌더링 경로와 상호작용을 그대로 사용한다.

## 3. 스켈레톤 보존 규칙

- `GridLoadingSkeleton` 컴포넌트는 삭제·대체하지 않는다.
- `data-testid="grid-loading-skeleton"`과 `data-testid="grid-loading-row-skeleton"`을 유지한다.
- 스켈레톤의 행 수, 열 구조, 헤더 유지, 그리드 높이·스크롤 스타일을 변경하지 않는다.
- 스피너는 스켈레톤을 대체하는 별도 본문이 아니라 기존 본문 위의 상태 표시다.

## 4. 적용 범위

공통 `F1Grid`를 직접 또는 간접 사용하는 다음 페이지가 대상이다.

- 메뉴관리의 `F1Tree`
- 모듈관리의 `F1Grid`
- 권한관리의 역할·사용자 `F1Grid`
- F1-Grid 테스트 페이지의 `F1Grid`
- 문서 플레이그라운드의 `F1Grid`·`F1Tree`

`F1Tree`는 내부적으로 `F1Grid`에 `loading`을 전달하므로 별도 오버레이 구현을 추가하지 않는다.

## 5. API·권한·예외 처리

- API 엔드포인트, HTTP 메서드, Request/Response 필드는 변경하지 않는다.
- 권한 정책과 화면별 조회·저장 조건은 변경하지 않는다.
- API 오류 시 각 페이지의 기존 오류 메시지와 loading 종료 흐름을 유지한다.
- 요청 경쟁 상태, 저장 상태, 오류 상태는 각 페이지의 기존 구현을 그대로 사용한다.
- 로딩 오버레이는 네트워크 요청을 새로 만들지 않고 전달된 `loading` 값만 표시한다.

## 6. 테스트 사양

1. `F1Grid loading` 렌더링 시 그리드 root에 `aria-busy`가 설정된다.
2. 로딩 중 헤더·본문 구조가 존재하고 전체 오버레이 테스트 식별자와 스피너가 표시된다.
3. 로딩 중 `grid-loading-skeleton`과 5개의 `grid-loading-row-skeleton`이 유지된다.
4. 로딩 중 오버레이가 pointer event를 받아 그리드 조작을 차단한다.
5. `loading`을 `false`로 전환하면 오버레이·스피너가 사라지고 일반 행 본문이 복구된다.
6. `F1Tree` 사용 화면에서도 동일한 공통 로딩 표시가 나타난다.
7. 기존 메뉴관리·권한관리 로딩 회귀 테스트가 새 공통 표시와 함께 통과한다.

## 7. 반응형·브라우저 검증

- 375px, 768px, 1280px에서 오버레이가 그리드 root 안에만 표시되는지 확인한다.
- 스피너와 로딩 상태 문구가 있다면 부모 영역 안에서 잘리지 않는지 확인한다.
- 오버레이 추가로 페이지 전체 가로 스크롤이 생기지 않는지 확인한다.
- 데스크톱·모바일 캡처 경로를 결과 문서에 기록한다.
