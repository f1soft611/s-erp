# 20261014_006 문서작성 피드 공지사항 UI 정합성 상세사양서

## 목적 및 기준

문서작성 `/groupware/doc/write` 화면의 피드형 카드가 공지사항과 같은 공통 UI 레이아웃을 사용하도록 한다. 상세 수정 모달의 열림/닫힘 동안 우측 상세 패널을 유지하고, 변경 후 데이터를 조용히 갱신한다.

## 화면 계약

### 보기 전환과 피드 카드

- 최초 선택 모드는 `list`이다. `PinnedViewToolbar` 피드/리스트 전환, 문서 구분 필터, 상단 고정 패널은 유지한다.
- 피드 모드는 shared `FeedView` 안에서 document `FeedCard`를 공지사항과 동일한 카드 shell, spacing, responsive wrap으로 표시한다.
- 카드 header는 기안자와 날짜를 표시하고, 기존 업무구분 및 결재상태 badge, 제목, 요약/본문을 유지한다.
- 접힌 상태는 목록 응답의 `summary`를 표시한다. `summary`와 본문이 다르거나 본문에 이미지가 있으면 공통 `FeedBodyContent`의 `더보기`를 제공한다.
- 첫 확장 요청은 `getDocumentApprovalDetail(electronicApprovalId)`를 호출하고 그 응답의 `contentsHtml`을 인라인 렌더링한다. 성공 응답은 document ID로 캐시해 피드 모드 전환 후에도 같은 페이지에서 재사용한다.
- 확장된 본문은 기존 전자결재 상세와 같은 embedded image 참조 규칙 및 인증 Blob fetch를 사용한다. 닫힌 component가 만든 Object URL은 폐기한다.
- 본문 지연 조회 중에는 해당 카드 안에서만 progress/status를 표시한다. 조회가 실패하면 해당 카드에서 오류와 재시도 버튼을 제공하고 접힌 요약은 유지한다.
- 피드 카드 본문/더보기 조작은 `openDetail`을 호출하지 않는다.

### 리스트형 상세

- 리스트 항목의 기존 선택 동작으로 `PageAreaOverlay`와 전자결재 상세 패널을 연다.
- 상단 고정 문서 선택 및 요약 알림이 사용하는 기존 범위/문서 선택 상태는 변경하지 않는다.
- 피드/리스트를 전환하거나 피드 본문을 펼쳐도 상세 패널을 새로 열지 않는다.

### 수정 모달 및 갱신

- 상세의 `문서 수정` 또는 `수정 후 재상신` 메뉴 선택 시 `editingDocument`와 Composer를 설정하되 `detailDocumentId`를 초기화하지 않는다.
- Composer dialog는 상세 패널보다 위에 표시된다. 닫기·취소·저장 후에도 같은 상세 패널이 유지된다.
- Composer 종료 시 문서 목록/요약을 갱신하고 상세 refresh signal을 올린다.
- `refresh({ quiet: true })`는 현재 목록/요약 데이터를 그대로 유지한 채 API를 요청한다. scope, kind 등 필터 변경으로 인한 일반 조회는 기존 로딩 skeleton을 표시한다.
- 상세 refresh signal은 열린 상세의 GET을 재요청하되 기존 상세 내용을 지우거나 `isLoading`을 켜지 않는다. 성공하면 상세 응답을 교체한다.
- 목록 또는 상세 갱신 실패는 기존 `loadError`/상세 `loadError` 영역에 노출한다. 실패 시 기존 데이터와 상세 패널을 유지한다.

## 데이터와 오류 처리

- 신규 API/요청 필드/응답 필드, 서버 로직, DB 변경은 없다.
- feed body fetch는 기존 `getDocumentApprovalDetail`를 사용한다.
- feed body 오류에는 현재 `Error.message`를 표시하고 비-Error 예외에는 `문서 본문을 불러오지 못했습니다.`를 표시한다. 재시도 시 같은 document ID 요청을 다시 수행한다.
- 이미지 실패는 기존 전자결재 상세의 `일부 본문 이미지를 불러오지 못했습니다.` 표현을 따른다. 실패한 이미지 때문에 다른 본문 또는 목록 데이터를 성공 형태로 대체하지 않는다.
- quiet refresh는 실패 오류를 감추거나 stale 데이터를 새 데이터인 것처럼 표시하지 않는다.
- 권한 검증, 편집 가능 상태, Composer 저장 오류 흐름은 기존 코드 그대로 유지한다.

## 접근성·반응형

- 본문 펼침은 공통 `FeedBodyContent`의 button과 `aria-expanded` 상태를 사용한다.
- busy 상태는 카드 범위의 accessible status로 표시한다. 오류와 retry 버튼은 키보드 접근이 가능해야 한다.
- 375px, 768px, 1280px에서 메타정보, badge, 본문, 펼침 컨트롤의 겹침/잘림 및 가로 overflow를 확인한다.
