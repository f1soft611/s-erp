# 20260827_006 모듈-메뉴 권한 목업 데이터 사양

근거 문서: [20260827*006*모듈*메뉴*권한*목업*데이터*구성*계획.md](../../plan/20260827/20260827_006_모듈_메뉴_권한_목업_데이터_구성_계획.md)

## 1. 데이터 계약

```ts
export type MenuPermission = {
  read: boolean;
  create: boolean;
  update: boolean;
  delete: boolean;
};

export type MenuNode = {
  menuId: number;
  parentMenuId: number | null;
  name: string;
  icon?: string;
  path?: string;
  permissions?: MenuPermission;
  children?: MenuNode[];
};

export type UserMenuResponse = {
  user: { userId: string; roles: string[] };
  menus: MenuNode[];
};
```

`MenuTreeNode`에 `menuId?: number`, `permissions?: MenuPermission`를 추가한다. 기존 필드는 유지한다.

## 2. 목업 데이터

파일: `frontend/src/pages/dashboard/data/adminUserMenus.json`

| menuId | parentMenuId | 이름        | path                   | 구분      |
| ------ | ------------ | ----------- | ---------------------- | --------- |
| 100    | null         | 그룹웨어    | /groupware             | 모듈 루트 |
| 110    | 100          | 종합현황    | /groupware/overview    | 메뉴      |
| 120    | 100          | 문서관리    | /groupware/documents   | 메뉴      |
| 200    | null         | 환경설정    | /settings              | 모듈 루트 |
| 210    | 200          | 시스템 관리 | /settings/system       | 메뉴 그룹 |
| 211    | 210          | 권한관리    | /settings/system/roles | 메뉴      |
| 212    | 210          | 메뉴관리    | /settings/system/menus | 메뉴      |

- `user`: `{ "userId": "admin", "roles": ["ADMIN"] }`
- 리프 메뉴 4건 모두 `read/create/update/delete` 전부 `true`
- 메뉴 그룹(210)은 권한을 갖지 않는다.
- 루트 메뉴 `icon`: 100 → `Groups`, 200 → `Settings`

## 3. 변환 규칙

파일: `frontend/src/pages/dashboard/services/menuService.ts`

| 항목        | 규칙                                                    |
| ----------- | ------------------------------------------------------- |
| 모듈 ID     | 루트 `path`의 첫 세그먼트                               |
| 모듈 이름   | 루트 `name`                                             |
| 모듈 아이콘 | 루트 `icon` 문자열                                      |
| 트리        | 루트 `children`을 `MenuTreeNode`로 재귀 변환            |
| 노드 ID     | `path` 마지막 세그먼트, `path`가 없으면 `menu-{menuId}` |
| `pageKey`   | 자식이 없는 노드에만 노드 ID와 동일하게 부여            |
| `menus`     | 트리를 평탄화한 리프 목록                               |

제공 함수

- `userMenuResponse`: 목업 응답 원본
- `moduleDescriptors`: 아이콘 문자열을 가진 모듈 목록
- `menuPermissionMap`: `"{moduleId}:{menuId}"` → `MenuPermission`
- `getMenuPermission(moduleId, menuId)`: 권한 조회, 없으면 `undefined`

## 4. 화면 연동

파일: `frontend/src/pages/dashboard/services/dashboardData.tsx`

- `moduleDescriptors`의 `iconName`을 MUI 아이콘 노드로 매핑해 `moduleItems`를 생성한다.
  - `Groups` → `GroupsOutlined`, `Settings` → `SettingsOutlined`, 그 외 → `SettingsOutlined`
- `pageContentMap` 키는 `overview`, `documents`, `roles`, `menus` 4개로 정비한다.
- `defaultPage`는 유지한다.

## 5. 동작 사양

1. 로그인 후 `/dashboard` 진입 시 `/dashboard/groupware/overview`로 이동한다.
2. 모듈 레일에는 그룹웨어, 환경설정 두 개만 표시된다.
3. 그룹웨어 선택 시 트리에 종합현황, 문서관리가 표시된다.
4. 환경설정 선택 시 `/dashboard/settings/roles`로 이동하고 시스템 관리 그룹이 확장된 상태로 권한관리, 메뉴관리가 표시된다.
5. 리프 선택 시 `/dashboard/:moduleId/:menuId`로 이동하고 본문 제목이 메뉴명과 일치한다.
6. 유효하지 않은 메뉴 ID로 진입하면 해당 모듈의 첫 리프로 대체한다. (기존 정책 유지)

## 6. 경계 조건

- 루트 메뉴에 `children`이 없으면 해당 모듈은 트리와 리프가 비며, 기존 fallback 콘텐츠를 표시한다.
- `permissions`가 없는 노드는 `getMenuPermission`에서 `undefined`를 반환한다.
- 권한 값은 이번 범위에서 화면 제어에 사용하지 않는다.

## 7. 검증 기준

- 모듈 레일에 그룹웨어/환경설정만 존재하고 구매관리·생산관리·재무관리·인사관리는 없다.
- 그룹웨어 트리에 종합현황/문서관리, 환경설정 트리에 시스템 관리 그룹과 그 하위 권한관리/메뉴관리가 렌더링된다.
- `/dashboard/groupware/documents` 직접 진입 시 문서관리가 선택 상태로 표시된다.
- `getMenuPermission('settings', 'menus')`가 4개 권한 모두 `true`를 반환한다.
- `npm run build`, `npm run test` 성공
