# 최근 사용 메뉴 PC 유지 상세 사양서

**근거:** [계획서](../../plan/20261103/20261103_003_최근사용메뉴_PC유지_계획서.md)

## 저장 계약

- 위치: 동일 origin 브라우저 `localStorage`, 키: `s-erp:recent-menu-history`.
- 자료: 기존 `RecentMenuEntry[]` (`menuId`, `moduleId`, `label`, `path`, `visitedAt`, 선택 `moduleName`, `breadcrumbPath`).
- 복원 시 배열과 필수 문자열, 유한 숫자 방문 시각, 선택 문자열을 확인한다. 유효 항목만 최대 5건 복원한다. 깨진 JSON/잘못된 구조는 무시하고 현재 메뉴 이동을 정상 처리한다.
- local 기록이 없거나 유효하지 않으면 기존 session 기록을 읽는다. 유효한 local 빈 배열은 session 기록보다 우선한다.
- 쓰기 성공 후 구 session 키만 제거한다. 저장소 접근/용량 오류가 있어도 화면 메모리에서 메뉴 이동은 계속된다.

## 동작

- 앱 최초 마운트 시 복원하며 기존 effect로 현재 메뉴 방문을 최신순에 반영한다.
- 기존 메뉴 중복 제거 및 최신 5건 제한을 유지한다. 통합검색을 최근 메뉴로 기록하지 않는다.
- 만료 시간이나 주기적 삭제를 두지 않는다. 로그아웃에서도 최근 메뉴를 지우지 않는다.
- 공통코드 등 페이지 조회 상태는 기존 세션 삭제 정책을 유지한다.
- 현재 기록은 영구 저장 후 다음 탭/브라우저 세션에서도 복원한다. 사용자가 저장소를 삭제한 경우나 시크릿 모드에서는 보존을 보장하지 않는다.
- 레이아웃, 문구, 최근 방문 상대 시간, 클릭 이동은 변경하지 않는다.

## 검증 기준

1. 메뉴 방문 후 local에 저장되고 로그아웃 후 동일 데이터가 유지된다.
2. 재로그인과 앱 재마운트/sessionStorage 초기화 이후 이전 메뉴가 복원된다.
3. 기존 session 배열이 local로 이관되며 local 기록이 있는 경우 이를 덮어쓰지 않는다.
4. 깨진 JSON, 배열 아닌 값, 잘못된 항목으로 대시보드가 중단되지 않는다.
5. 새 메뉴·재방문에서 5건 제한/중복 제거/최신순 및 최근 항목 클릭 이동을 유지한다.
6. 실제 브라우저에서 새 페이지·로그아웃·재로그인 흐름과 375/768/1280 레이아웃을 확인하고 스크린샷을 남긴다.

이번 사양은 기존 20260923 최근 메뉴 및 페이지 상태 문서의 최근 메뉴 세션 삭제 부분만 대체하며, 페이지 상태 자체의 정책은 변경하지 않는다.
