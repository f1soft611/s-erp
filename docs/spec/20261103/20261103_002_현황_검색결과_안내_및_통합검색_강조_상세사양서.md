## 결과 안내 동작

- 문서현황과 수주현황은 동일한 `SearchResultMessage` 컴포넌트를 사용한다.
- 안내는 검색 조건 영역 바로 다음, 그리드 앞에 배치한다.
- 문서현황 결과 수는 `list.totalRowCount`, 수주현황 결과 수는 `list.rows.length`를 사용한다.
- 0건 문구: `조회 결과가 없습니다. 조회 기간을 넓히거나 검색 조건을 변경해 주세요.`
- 양수 문구: `조회 결과 총 N건입니다.`. N은 천 단위 구분을 적용한다.
- 두 문구 모두 `severity="info"`, `role="status"`의 닫을 수 있는 Alert로 표시한다. 초기화 버튼은 제거한다.
- 결과 안내 외곽의 수평 패딩은 기존 PageMessageArea와 같게 유지한다. 안내 wrapper의 위 패딩은 theme spacing 1, 아래 패딩은 0으로 둔다. 두 현황 화면의 그리드 컨테이너가 안내 다음에 theme spacing 1의 위 패딩을 이미 제공하므로, Alert와 바로 앞/뒤 콘텐츠 간 실제 간격은 각각 8px로 같아진다. 좁은 화면에서는 문구와 X가 겹치거나 가로 넘침을 만들지 않는다.
- 화면별 성공 조회 조건(loaded, loading 아님, 기본값 오류/목록 오류 없음)을 만족할 때만 렌더링한다. 조회 중, 최초 조회 전, 오류에는 숨긴다.
- 사용자가 X로 닫은 메시지는 현재 성공 응답 동안만 숨긴다. 다음 조회 요청 동안 컴포넌트를 언마운트하고, 성공 후 새 결과 안내를 다시 표시한다.
- `PageMessageArea`의 기본 오류 메시지 여백, severity, role 및 닫기/재시도 동작은 변경하지 않는다. 결과 안내만 선택적 밀집 간격을 사용한다.

## 통합검색 강조

- 기존 제목 강조 기능과 대소문자 무시 매칭을 유지한다.
- 같은 `Highlight` 렌더러를 결과 설명 문자열에도 적용한다.
- 텍스트는 React 텍스트 노드로 렌더링하고, 일치 부분에만 `<mark>`를 사용한다. HTML 문자열 삽입은 하지 않는다.
- 검색어가 없거나 현재 문자열에서 일치하지 않으면 원문을 그대로 표시한다.
- 검색 API, 결과 필드, 라우팅 및 검색 범위는 변경하지 않는다.

## 테스트 기준

1. 공통 결과 메시지에서 0건 안내, 양수 건수, X 닫기, wrapper `pt: 1`/`pb: 0`, 초기화 버튼 없음 확인.
2. 두 현황 페이지에서 0건/양수 건수 표시, 조회 중/오류 시 숨김, 새 조회 완료 시 메시지 재노출 확인.
3. 기존 검색 조건 초기화 동작이 결과 안내에 연결되지 않음을 확인한다.
4. 통합검색 결과 제목 및 설명에서 대소문자 무시 일치 강조, 불일치 텍스트 보존, HTML 미삽입 확인.
5. Vitest, production build, lint가 통과하고 375px/768px/1280px 브라우저에서 줄바꿈, 양쪽 8px 간격, 가로 넘침을 확인한다.
