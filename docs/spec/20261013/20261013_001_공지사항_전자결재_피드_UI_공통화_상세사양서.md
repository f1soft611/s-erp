# 20261013_001 공지사항·전자결재 피드 UI 공통화 상세사양서

## 목적

좌측 피드와 우측 상세 화면을 공지사항 기준 공통 UI로 조립 가능하게 한다. 공통 컴포넌트는 데이터 표현만 담당하고 기능별 업무 규칙은 해당 페이지와 service/hook에 남긴다.

## 공통 컴포넌트 계약

### 좌측 피드 카드

- 기존 `FeedView`는 리스트 배치 및 아이템 iteration을 계속 담당한다.
- 공통 `FeedCard`는 카드 chrome, author/avatar/meta, title/summary, optional badge/action slots 및 child content를 제공한다.
- feature consumer가 domain data를 display props로 변환하고 click/action callback을 전달한다.
- component는 API, 로그인 identity, 권한 판정, query state를 소유하지 않는다.
- notice와 approval의 기본 배치, 간격, radius, responsive wrapping은 동일하게 notice 디자인 기준으로 렌더링한다.
- notice는 본문 확장, 이미지 미리보기, 첨부, pin, reaction, 댓글 동작을 기존처럼 유지한다. approval은 기존 문서 제목/요약/작성자/문서유형/상태와 상세 열기를 유지한다.

### 우측 상세 패널

- `PostDetailPanel`이 공통 header, close control, scroll viewport를 유지한다. 각 feature가 title/subtitle 및 children을 공급한다.
- 상세 content는 기능별 상단 정보와 공통 section을 순서대로 조립한다.
- 공통 section:
  1. 첨부 목록: 기존 `AttachmentList` 재사용, 다운로드 callback은 feature에 위임
  2. 반응 영역: 좋아요, 북마크, 댓글 수를 전달받고 callback을 호출
  3. 이전 댓글 컨트롤: 표시 조건/disabled/loading/click callback을 전달받음
  4. 댓글 thread/input: 기존 `CommentThread` 재사용, comment CRUD/reply/attachment callback을 feature에 위임
- 공통 section은 댓글 fetch/API, cursor 계산, 권한, mutation 오류 상태를 소유하지 않는다.
- notice와 approval은 같은 section 배치/typography/spacing을 사용하고 데이터만 다르게 연결한다.

## 전자결재 상세 content 순서

1. 기안자 avatar/name 및 기안일.
2. 읽기 전용 결재선:
   - 실제 결재선 record만 출력하며 빈 placeholder 슬롯을 추가하지 않는다.
   - `APPROVAL` 단계는 stage/participant 순서, 이름, 부서, 처리 상태, 처리 의견을 표시한다.
   - `AGREEMENT`는 합의 그룹으로 표시한다.
   - `REFERENCE`는 참조 그룹의 participant chip으로 표시한다.
   - 모든 표현은 read-only이고 결재 action을 실행하지 않는다.
3. 문서 제목, 본문, 인증 embedded image preview.
4. 공지사항과 동일한 첨부 목록.
5. 공지사항과 동일한 좋아요/북마크/댓글 수 영역.
6. 공지사항과 동일한 이전 댓글 보기 버튼 및 댓글 thread/input.
- 본문은 공지사항과 같이 접기/더보기로 전환할 수 있고, 본문 이미지가 있으면 썸네일 미리보기와 이미지 뷰어를 제공한다.
- 상세 content 전체는 공지사항 피드 카드처럼 경계가 보이는 카드 안에 배치한다.

기존 전자결재 문서 수정/삭제, 결재 승인·반려·보완요청, 첨부 다운로드, 본문 이미지, 댓글 callback은 변경하지 않는다. 반응의 서버 영속화를 새로 추가하지 않는다.

## 댓글 및 시스템 이력

- USER 댓글과 대댓글의 기존 순서, 권한, CRUD, 첨부 및 pagination 동작을 보존한다.
- approval SYSTEM 이벤트는 기존처럼 USER root 댓글과 시간순으로 합친다.
- SYSTEM 행 author 표시 옆에 시스템 표시를 제공한다. 최신 승인 UI 변경은 하단의 상세 패널 UI 통일 사양을 따른다.
- SYSTEM 행은 읽기 전용이다. 답글, 수정, 삭제, 첨부 관리 UI와 관련 callback을 제공하지 않는다.
- 삭제된 USER 댓글은 개인정보 보호로 `writerId`가 `null`일 수 있다. 이 응답도 정상 목록으로 처리해 댓글/페이지네이션을 계속 렌더링한다.
- notice USER 댓글에는 SYSTEM badge를 표시하지 않고 기존 UX를 유지한다.

## 반응형/접근성

- 최소 375px, 768px, 1280px에서 좌측 카드 및 우측 패널 콘텐츠를 검증한다.
- 텍스트 긴 제목/기안자/결재 의견은 줄바꿈 또는 말줄임 규칙으로 다른 controls를 밀어내지 않는다.
- 패널 scroll container만 세로 스크롤하며 의도하지 않은 페이지 가로 넘침은 없어야 한다.
- 클릭 가능한 카드는 키보드로 조작할 수 있어야 하며 카드 내부의 별도 동작 버튼은 부모 클릭을 중복 실행하지 않는다.
- 아이콘 버튼과 이전 댓글 보기 등 기존 접근성 label을 보존한다.

## 오류 처리 및 호환성

- 데이터 로딩, 파일 다운로드, 댓글 조회/저장 오류는 기능별 기존 알림/오류 표현을 유지한다.
- 댓글 등록 성공 후 재조회 응답에 삭제된 댓글이 포함되어도 목록 검증 실패로 새 댓글을 숨기지 않는다.
- shared component는 callback 실패를 삼키거나 임의 성공 상태로 바꾸지 않는다.
- API 및 DB 계약 변경은 없다.
- notice의 현재 표시·interactions를 변경 전 회귀 기준으로 삼는다.

## 승인된 후속 요구사항 — 본문·결재선·댓글

### 공통 본문 표시

- 공지사항과 전자결재 상세는 같은 `FeedBodyContent` 프레젠테이션 컴포넌트를 사용한다.
- 공통 컴포넌트는 본문 표현, 접기/펼치기, 최대 높이 clip, 이미지 미리보기 배치와 이미지 선택 callback만 담당한다.
- HTML sanitization, 인증 이미지 요청 및 Blob URL 수명관리, 각 문서의 펼침 상태와 이미지 뷰어 연결은 기존 notice/approval 소유 컴포넌트에 둔다.
- 접힌 본문은 최대 220px clip/gradient mask와 제목 없는 112×76 embedded image 썸네일을 사용한다. 펼친 본문에는 이미지 placeholder 문자열이 아닌 인증된 실제 `<img>`가 포함된 HTML을 표시한다.
- 본문에 이미지가 없고 요약과 본문이 같으면 불필요한 펼치기/접기 컨트롤을 표시하지 않는다. 이미지가 포함된 본문은 요약 길이만으로 펼치기 기능을 숨기지 않는다.
- `[본문 이미지 ...]` placeholder 문자열 및 별도 `본문 이미지` 미리보기 제목은 렌더링하지 않는다.

### 전자결재 결재선

- 상세 결재 참여자는 작성 모달과 같은 세로 슬롯 구조를 사용한다: 직위/역할 32px, 서명 또는 도장 64px, 순번·이름 32px.
- 실제 결재선 참여자만 표시하고 읽기 전용으로 유지한다. 승인 동작, 편집, 선택 기능은 추가하지 않는다.
- 결재/합의/참조를 포함한 결재선 영역의 마지막 참여자 다음에 구분선을 둔다.

### 전자결재 이전 댓글

- 상세 진입 시 최신 댓글 3개를 요청해 초기 thread에 표시한다.
- `hasPrevious`가 참이면 “이전 댓글 보기”를 표시한다. 누르면 기존 cursor 계약으로 최대 20개 이전 댓글을 요청하고 기존 댓글 앞에 시간순으로 병합한다.
- 이전 댓글 요청 중 중복 요청을 막고 loading/오류 처리는 기존 기능별 표현을 유지한다. 이전 댓글이 없는 경우 버튼은 표시하지 않는다.

## 최신 승인 변경 — 상세 패널 UI 통일

다음 동작은 2026-10-13에 승인된 후속 요구사항이며, 기존 SYSTEM 배지 기준을 대체한다.

### 로딩 및 본문 초기 상태

- 공지사항과 전자결재의 상세 로딩 중 공통 `PostDetailPanel` 본문 viewport 전체를 진행 상태로 교체한다.
- 진행 상태는 accessible `status`와 로딩 이름을 제공하고 스피너는 가용 콘텐츠 영역의 가로·세로 중앙에 둔다.
- 리스트에서 상세를 선택해 진입하면 본문을 펼쳐 표시한다. 피드 카드의 기본 접힘 상태 및 접기/펼치기 조작은 유지한다.
- 공지사항 로딩 여부는 현재 선택된 공지의 상세 fetch 요청에만 연결한다. 선택이 바뀐 뒤 이전 요청이 완료되어도 새 선택의 로딩 상태를 지우지 않는다.

### 시스템 이벤트 및 답글 토글

- SYSTEM 이벤트의 텍스트 `시스템` 배지를 접근 가능한 이름을 가진 비대화형 시스템 아이콘으로 교체한다.
- SYSTEM 이벤트의 작성자, 본문, 순서, 읽기 전용 제약은 유지하며 답글·수정·삭제 조작을 노출하지 않는다.
- 답글 토글은 접힘 상태에서 아래 화살표, 펼침 상태에서 위 화살표를 표시한다. `aria-expanded`는 동일한 실제 확장 상태를 반영한다. 정상 댓글 및 삭제 댓글의 답글 요약 모두에 적용한다.

### 상세 separator

- 공지사항 상세와 좌측 피드 카드에서는 반응 바 이후 이전 댓글 컨트롤 앞의 separator를 제거한다. 첨부가 없을 때 본문 바로 뒤에 오는 반응 바 앞 separator도 제거하며, 첨부가 있을 때 첨부와 반응 바 사이 separator는 유지한다.
- 전자결재 상세에서는 본문 직후 separator와 반응 바 이후 이전 댓글 컨트롤 앞의 separator를 제거한다.
- 전자결재 상세의 첨부·첨부/반응 separator·반응바·댓글은 공통 footer 영역으로 묶어 바깥 Stack이 내부 항목 사이에 추가 수직 간격을 넣지 않게 한다. 첨부/반응 separator의 상·하 여백은 공지사항과 같은 `my: 1.5`로 유지한다.
- 좌측 목록 본문은 접힘 상태로 유지한다. 첨부/반응 사이 separator, 결재선 아래 separator 및 나머지 섹션 구분은 유지한다.
- 전자결재 좌측 목록의 로딩은 현재 feed/list view mode에 맞는 skeleton을 표시하고, notice와 같은 `FeedViewSkeleton` / `ListViewSkeleton`을 사용한다. 공지사항의 기존 로딩 skeleton은 유지한다.

### 변경 비범위 및 검증

- API, 권한, 승인 상태, 댓글 순서/CRUD/cursor/page size, 반응 동작은 변경하지 않는다.
- 공통 패널·공지사항·전자결재·댓글 UI의 회귀 테스트와 production build를 확인한다.
- 실제 브라우저에서 375px, 768px, 1280px를 확인하고 결과 문서에 스크린샷과 검증 결과를 기록한다.
