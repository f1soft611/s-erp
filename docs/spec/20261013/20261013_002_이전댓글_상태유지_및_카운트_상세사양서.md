# 20261013_002 이전 댓글 상태 유지 및 카운트 상세 사양서

## 사용자 동작

1. 상세 피드에서 `이전 댓글 보기 (N)`을 선택하면 이전 페이지가 기존 댓글과 함께 목록에 추가된다.
2. 이전 댓글이 추가된 상태에서 댓글 또는 답글을 등록하면 기존 전체 로드 댓글을 그대로 표시하고 새 항목을 기존 최신 댓글 위치에 반영한다.
3. 댓글 등록으로 현재 목록을 최신 3개로 접거나 페이지 커서를 초기화하지 않는다.
4. 이전 댓글을 더 불러오면 버튼 카운트가 새로 로드된 수만큼 감소한다. 더 불러올 댓글이 없으면 버튼을 숨긴다.

## 버튼 레이블 및 카운트

- 카운트가 알려져 있고 1 이상이면 사용자 표시와 접근 가능한 이름을 `이전 댓글 보기 (N)` 형식으로 제공한다.
- `N`은 `max(전체 사용자 댓글 수 - 현재 로드된 사용자 댓글 수, 0)`이다.
- 댓글/답글을 새로 생성하면 총 댓글 수와 현재 로드 수가 각각 1 증가하므로 남은 이전 댓글 수는 유지된다.
- 카운트가 없거나 유효하지 않으면 숫자 없이 `이전 댓글 보기`를 표시한다.
- 승인 시스템 이벤트는 댓글 개수에 포함하지 않는다.
- 로딩 중에는 기존 `이전 댓글 불러오는 중...` 레이블과 disabled 상태를 유지한다.

## 상태 처리

### 공지사항

- `NoticeFeedList`가 댓글 페이지 병합, 현재 로드 상태, 커서를 보유한다.
- 로드된 이전 댓글은 새 댓글/답글로 서버 item의 `comments`가 바뀌더라도 유지한다.
- 신규 댓글은 현재 목록에 한 번만 반영하며, 전체 댓글 카운트는 기존 mutation 로직이 갱신한다.
- 다음 이전 페이지 커서 및 exhausted 상태는 댓글 추가만으로 초기화하지 않는다.

### 전자결재

- 초기 조회는 기존대로 최신 3개 댓글을 요청한다.
- 이전 댓글 추가 조회는 기존 커서 기반 조회를 사용한다.
- 신규 댓글/답글 등록 성공 시 응답 댓글을 현재 `commentRecords`에 삽입하고 `commentCount`를 1 증가한다. 등록 직후 첫 페이지를 재조회하지 않는다.
- 신규 댓글 첨부는 업로드 응답의 기존 파일 메타데이터를 포함한다.
- `nextBeforeCommentId`, `hasPreviousComments`는 신규 작성만으로 바뀌지 않는다.
- 기존 댓글 편집/삭제는 변경된 항목만 반영하고 이전 페이지 데이터와 커서를 보존한다.

## 실패 처리

- 댓글 생성 전 실패는 댓글 데이터 및 페이지네이션 상태를 바꾸지 않고 기존 오류 알림을 유지한다.
- 댓글 생성 성공 뒤 첨부 업로드 실패 시 서버에 저장된 댓글은 이미 로드된 댓글 목록에서 보이게 하고, 업로드 오류 및 기존 첨부 정리 오류 처리를 유지한다.
- 이전 댓글 조회 실패 시 기존 댓글과 카운트가 유지되고 기존 오류 메시지가 표시된다.

## 회귀 검증

- 공통 댓글 섹션의 카운트 레이블/숫자 생략 및 로딩 상태 테스트
- 공지사항에서 이전 페이지 로드 후 새 댓글·답글 등록 시 전체 로드 댓글·커서·남은 수 유지
- 전자결재에서 이전 페이지 로드 후 새 댓글·답글 등록 시 전체 로드 댓글·커서·남은 수 유지, 첫 페이지 재조회 없음
- 기존 댓글 수정/삭제/답글/첨부/시스템 이벤트 및 페이지네이션 테스트
- 전체 프론트엔드 빌드와 375px/768px/1280px 실제 브라우저 확인
