# 20261013_003 전자결재 상세 결재선 시각화 상세사양서

## 목적과 승인 방향

전자결재 상세 본문 위의 결재선을 사용자가 공유한 참조 이미지에 맞춘 **컴팩트 결재 패널**로 표현한다. 공유 이미지의 옅은 패널, 한 줄 메타 헤더, 원형 상태 도장, 내부 구분선 및 하단 합의/참조 칩 구조를 기준으로 한다.

## 영역 및 순서

- 결재선 패널은 문서 제목/본문 위에 둔다.
- 패널 외곽은 옅은 surface 배경, 얇은 경계선, 둥근 모서리와 내부 여백으로 하나의 영역처럼 보이게 한다.
- 패널 헤더 한 줄 왼쪽에는 `결재선` 제목과 `기안자 {이름} · {작성일}` 메타 정보를 나란히 둔다.
- 기존 pin, 더보기 메뉴 및 문서 상태 표시는 헤더 오른쪽에 유지한다. 기안자 아바타/이름/작성일이 별도 줄에 중복되지 않게 한다.
- 실제 `APPROVAL` 참여자를 `stageOrder`, `participantOrder` 오름차순으로 표시한다.
- 각 승인 카드 사이에 가운데 정렬된 화살표를 표시하고 마지막 카드 뒤에는 표시하지 않는다.
- 결재선 영역이 좁으면 승인 흐름만 내부 가로 스크롤한다. 부모 패널/문서 전체의 가로 overflow는 허용하지 않는다.
- 승인 카드 그룹 뒤에 패널 내부 구분선을 두고, 그 아래 합의/참조 칩을 배치한다. 합의/참조가 모두 비어 있으면 내부 구분선과 하단 영역을 숨긴다.
- 합의/참조 칩은 실제 참여자만 `합의 · {부서} {이름}`, `참조 · {부서} {이름}`으로 표현한다.
- 패널 아래의 기존 결재선 외부 구분선은 유지한다.
- 결재 참여자 슬롯은 작성 화면과 같이 `32px 64px 32px` 구조를 유지한다.

## 카드 표시

- 1행: 참여자 부서명.
- 2행: 상태를 원형 도장처럼 표시하고, 저장된 처리 의견이 있으면 도장 아래에 표시한다.
- 3행: 순번 원형 표시와 참여자 이름.
- 상태 도장은 기존 상태 라벨을 표시하며 상태 색상과 이중 단서(텍스트)를 함께 제공한다.
- `PENDING` 도장은 primary 색상과 카드 강조로 현재 처리 단계임을 구분한다.
- 처리가 끝난 카드에는 다음 단계 강조를 적용하지 않는다.

## 상태 표시와 색상

기존 `approvalLineStatusLabel` 텍스트를 보존하고 아래 의미 색상으로 시각적 차이를 추가한다.

| 상태 | 표시 | 테마 색상 의미 |
|---|---|---|
| `WAITING` | 대기 | 중립 점선 원형 |
| `PENDING` | 처리 중 | Primary 원형/현재 단계 |
| `APPROVED` | 승인 | Success 원형/완료 |
| `REJECTED` | 반려 | Error 원형/반려 |
| `RETURNED` | 보완요청 | Warning 원형/보완 필요 |
| 그 외 상태 | 기존 라벨 함수 결과 | 안전한 중립 표시 |

상태 색상은 아이콘/경계/상태 텍스트의 보조 표현이다. 의미는 텍스트만으로도 식별 가능해야 하며 색상만으로 상태를 전달하지 않는다.

## 보존 요구사항

- API, 타입, 서버 상태 전이, 결재 권한, 첨부/댓글 흐름은 변경하지 않는다.
- 표시 참여자는 서버가 제공한 실제 행에 한정하며 빈 슬롯/가상 결재자를 추가하지 않는다.
- 상세 결재선은 읽기 전용이며 버튼 또는 선택 가능한 제어 요소를 추가하지 않는다.
- 긴 부서명, 상태 의견, 이름이 카드 크기를 밀어내지 않게 기존 `noWrap`/ellipsis 동작을 보존한다.
- 하단 합의/참조 chip은 기존 그룹 의미와 읽기 전용 상태를 유지하고 API/데이터를 변경하지 않는다.
- 본 작업과 무관한 워킹트리 변경을 수정하거나 되돌리지 않는다.

## 검증 기준

- 렌더링 테스트에서 한 줄 패널 헤더, 기안 메타, 원형 상태 도장, 내부 구분선, 합의/참조 chip을 확인한다.
- 실제 결재행이 순서대로 표시되고 카드 간 연결은 마지막을 제외해 존재한다.
- `WAITING`, `PENDING`, `APPROVED`가 서로 구분되고 `PENDING`만 현재 단계 강조를 갖는다.
- 합의/참조 표시와 읽기 전용 검증이 계속 통과한다.
- 관련 Vitest와 프로덕션 빌드가 통과한다.
- 375px, 768px, 1280px에서 카드 간 겹침 및 페이지 가로 넘침이 발생하지 않는지 실제 브라우저에서 확인한다.
