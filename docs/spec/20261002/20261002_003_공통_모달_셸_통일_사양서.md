# 20261002_003 공통 모달 셸 통일 상세 사양서

## 1. 대상 화면과 컴포넌트

- 그룹웨어 공지 작성/수정: `frontend/src/pages/groupware/community/notice/components/NoticeComposerDialog.tsx`
- F1-Grid 행 폼: `frontend/src/shared/components/f1-grid/form/F1GridFormModal.tsx`
- 기안양식관리: `frontend/src/pages/co/workflow/form/components/DraftFormGrid.tsx`의 `rowFormPlugin`을 통해 F1-Grid 행 폼을 사용하므로 별도 모달을 만들지 않고 간접 적용한다.
- 공통 셸 신규 컴포넌트: `frontend/src/shared/components/CommonDialog.tsx`

## 2. 목적과 현재 문제

현재 F1-Grid 행 폼과 공지 작성 모달은 각자 헤더·본문·푸터를 구성한다. 이로 인해 여백, 경계, 배경, 높이와 스크롤 규칙이 다르고, 공지 작성의 하단 왼쪽 툴바를 다른 모달에서 재사용할 공통 계약이 없다.

공통 셸은 영역 배치와 기본 시각 규칙을 책임지고, 업무별 폼·표·에디터 및 데이터 동작은 기존 화면 컴포넌트에 유지한다.

## 3. 공통 컴포넌트 계약

```ts
import type { DialogProps } from '@mui/material/Dialog';
import type { ReactNode } from 'react';

export type CommonDialogSize = 'md' | 'lg';
export type CommonDialogBodyMode = 'content' | 'fill';

export type CommonDialogProps = {
  open: boolean;
  onClose: () => void;
  title: string;
  description?: string;
  children: ReactNode;
  footerStart?: ReactNode;
  actions?: ReactNode;
  size?: CommonDialogSize;
  bodyMode?: CommonDialogBodyMode;
  fullScreenOnMobile?: boolean;
  dialogProps?: Omit<
    DialogProps,
    'open' | 'onClose' | 'children' | 'fullWidth' | 'maxWidth' | 'fullScreen'
  > & { [key: `data-${string}`]: string | number | undefined };
};
```

- `size` 기본값은 `md`; `md` 폭은 820px, `lg` 폭은 960px이다.
- `bodyMode` 기본값은 `content`이다. `content`는 콘텐츠 높이에 맞추고 최대 높이를 85vh로 제한해 기존 F1-Grid 동작을 보존한다. `fill`은 paper 높이를 `min(90vh, 880px)`로 두고 본문이 남은 높이를 채우게 한다.
- `fullScreenOnMobile` 기본값은 `false`이다. `true`이면 MUI `sm` breakpoint 미만에서 전체 화면으로 표시한다.
- `dialogProps`는 기존 grid 이벤트 전파 차단, 화면별 `data-testid`와 `data-theme-mode` 같은 root 속성을 전달한다. 공통 셸이 관리하는 열림 상태, 닫기, 크기, 자식은 호출부가 덮어쓸 수 없다.
- `footerStart`는 보조 툴바·안내 등 푸터 왼쪽의 선택 콘텐츠다. `actions`는 오른쪽 액션 그룹이다. 두 항목이 모두 없으면 푸터 영역을 렌더링하지 않는다.

## 4. 공통 레이아웃과 시각 규칙

1. 다크 모드의 모달 paper·헤더·푸터는 페이지에서 사용하는 슬레이트 표면색 `#1e293b`를 사용하고, 본문은 `background.default`를 유지해 은은한 층을 만든다. 라이트 모드는 paper `background.paper`, 본문 `background.default`의 기존 조합을 유지한다. 구분선은 `divider` 토큰을 사용한다.
2. 헤더는 제목, 선택 설명, 우측 닫기 버튼을 제공하고 하단에 divider를 둔다. 제목과 설명은 각각 고유 ID로 연결하고 설명이 있을 때만 `aria-describedby`를 지정한다.
3. 본문은 `display:flex`, `flex:1`, `min-height:0`, `overflow-y:auto`를 사용한다. 본문이 넘칠 때 헤더와 푸터는 고정되고 본문만 스크롤된다.
4. 푸터는 상단 divider와 공통 여백을 사용한다. 데스크톱에서는 `footerStart`를 왼쪽, `actions`를 오른쪽에 배치한다. 좁은 화면에서는 줄바꿈 또는 두 줄 배치를 허용하되 서로 겹치거나 가로로 잘리지 않게 한다.
5. 공통 안쪽 여백은 테마 spacing 기준으로 헤더/푸터 좌우 24px, 본문 좌우 24px을 기본으로 한다. 작은 뷰포트에서는 좌우 여백을 16px로 줄인다.
6. 폼 모달의 내부 그룹 카드, 공지 에디터·첨부 표면 등 도메인 콘텐츠 안쪽의 표현은 공통 셸이 덮어쓰지 않는다.
7. F1-Grid 폼 섹션처럼 내부 표면을 구분해야 하는 자식 콘텐츠는 기존 `background.paper`를 사용해 모달 셸과 구분한다.

## 5. 적용 화면별 설정

### 5.1 F1-Grid 행 폼 및 기안양식관리

- `size="lg"`, `bodyMode="content"`, `fullScreenOnMobile`을 사용한다.
- 현재 플러그인 기반 제목/설명, 폼 draft, 필수 검증, 첫 오류 입력 포커스, `onBeforeApply`, 적용/취소 동작은 유지한다.
- `onContextMenu`, `onCopy`, `onKeyDown`, `onPaste` 전파 차단을 `dialogProps`로 전달한다.
- 기존 “적용 후 화면의 저장 버튼으로 최종 저장됩니다.” 안내는 `footerStart`에 배치한다. 적용/취소 버튼은 `actions`에 배치한다.
- 기안양식관리의 등록/수정 제목과 권한 동작은 기존 `DraftFormGrid.rowFormPlugin` 흐름으로 유지한다.

### 5.2 그룹웨어 공지 작성/수정

- `size="md"`, `bodyMode="fill"`, `fullScreenOnMobile={false}`를 사용한다.
- 공지 에디터, 제목, 첨부 목록, 이미지 리사이즈, 저장 payload, 편집기 상태는 기존 구현을 유지한다.
- 편집/첨부 툴바를 `footerStart`, 저장/취소 버튼을 `actions`에 배치한다.
- 기존 `notice-composer-dialog-root` 테스트 식별자와 `data-theme-mode`를 root에 유지한다.
- 작은 뷰포트에서도 툴바와 액션이 겹치지 않고, 툴바 팝업은 viewport 안에 표시되어야 한다.

## 6. 상태와 이벤트

- 닫기 버튼, Escape, backdrop 닫기는 각 호출부의 기존 `onClose`/`onCancel` 동작을 사용한다.
- 공통 셸은 데이터 저장, draft 생성, 검증 또는 API 호출을 하지 않는다.
- 셸 전환으로 인해 기존 자식에서 처리하는 키보드·클립보드 이벤트가 바깥 Grid로 전파되지 않도록 기존 F1-Grid 차단 동작을 유지한다.
- 모달이 닫힐 때 Notice 편집기의 기존 이미지 리사이즈 오버레이 및 전역 핸들러 정리 동작을 유지한다.
