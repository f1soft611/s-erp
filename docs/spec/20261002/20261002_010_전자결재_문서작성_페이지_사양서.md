# 20261002_010 전자결재 문서작성 페이지 상세 사양서

## 1. 대상과 라우팅

- 메뉴 경로: `/groupware/doc/write`
- 선택 모듈/페이지 키: `groupware` / `write`
- 구현 위치: `frontend/src/pages/groupware/documents/write/DocumentWritePage.tsx`
- 기존 Dashboard 셸과 메뉴 breadcrumb를 유지한다.

## 2. 화면 구성

- `PageHeader` 우측에 문서작성 액션을 둔다. 액션을 누르면 작성 팝업을 연다.
- 본문은 기존 `ContentSplitLayout`으로 좌측 문서 목록과 우측 요약 패널을 나눈다.
- 좌측은 공지사항 페이지와 같은 `PinnedViewToolbar` → 고정 항목 패널 → 피드 또는 리스트 순서를 사용한다. 첫 보기 mode는 `list`, 선택 가능 mode는 `feed`와 `list`다.
- 툴바의 필터는 공지사항과 동일한 아이콘형 메뉴다. 별도 텍스트 검색 필드는 제공하지 않는다.
- `PinnedItemsPanel`에는 고정 문서만 표시하고, 본문 `FeedView`/`ListView`에는 비고정 문서만 표시한다.
- 리스트 모드는 공통 `ListView`를 사용한다. 제목 오른쪽에 업무구분 라벨과 결재상태를 연이어 배치하고, 작성자/작성일 메타 행은 공지 리스트와 같은 위치를 유지한다.
- 피드 모드는 공통 `FeedView`에 공지 피드와 같은 카드 구조(작성자/날짜 및 상태 행, 제목, 요약 본문)를 사용한다. 업무구분과 결재상태는 작성자/날짜 행의 우측에 표시한다.
- 좌측 항목의 업무구분은 `기안서`, `업무연락`, `지출결의서`, `근태신청`이다.
- 우측 요약은 공지사항 요약 패널과 같은 카드 간격, 테두리 및 콘텐츠 패딩으로 `결재 요약`과 `놓치지 마세요`를 표시한다. 모든 표시값은 로컬 샘플 데이터 기반이다.
- 작성 팝업은 공지 작성 모달과 같은 `CommonDialog` 크기(`md`), `bodyMode="fill"`, 헤더/푸터 구조를 사용한다. 문서 구분 탭은 공지의 구분 입력 위치에 놓고 제목 필드 바로 위에 표시한다. 탭은 네 가지 유형명을 표시하며 `기안서`, `업무연락`만 선택 가능하고 나머지는 disabled다.
- 제목 필드의 크기/타이포그래피/배경과 본문 Tiptap 편집 영역/placeholder는 공지 작성 모달과 같은 스타일을 사용한다.
- 푸터 왼쪽은 공지와 같은 툴바 열기 및 첨부 링크 아이콘 버튼을 제공한다. 툴바는 굵게, 기울임, 취소선, 글머리/번호 목록, 인용, 실행취소/다시실행을 제공한다. 선택 파일은 로컬 목록으로만 표시한다.
- 푸터 오른쪽 버튼 순서는 저장, 취소다. 현재 문서 API 계약이 없어 저장은 비활성 상태이며 실제 저장/상신 동작은 이번 사양에서 정의하지 않는다.

## 3. 샘플 표시 계약

- 업무 구분은 네 종류를 모두 목록/피드 항목의 라벨로 표현한다.
- 결재상태 라벨은 시각 검토용 예시 데이터에만 둔다. 서버 enum, API 요청/응답, 권한 계약을 의미하지 않는다.
- 문서 목록과 요약 수치는 페이지 내부 샘플 데이터에서 제공한다. 네트워크 요청을 추가하지 않는다.
- 별도 문서현황 페이지의 상세검색과 F1-Grid는 범위 밖이며 이 페이지에 그리드를 추가하지 않는다.

## 4. 상태/동작

- 기본 보기: `list`
- 피드/리스트 전환 시 동일한 샘플 목록을 유지한다.
- 문서작성 액션과 빈 상태의 작성 액션은 같은 팝업을 연다.
- 팝업 닫기 및 취소는 팝업을 닫는다.
- 모달을 닫으면 입력 중인 제목, 본문, 첨부 선택과 툴바 상태를 초기화한다.
- 작성 유형 변경은 선택 탭 상태를 바꾸며, 지출결의서/근태신청은 비활성 상태다.

## 5. 검증 기준

1. DashboardContent의 `groupware/write` 분기가 `DocumentWritePage`를 렌더링한다.
2. 첫 표시 mode는 리스트이고 보기 전환 후 피드가 표시된다.
3. 상단고정 문서는 전용 패널에만 표시되고 본문 피드/리스트에는 중복되지 않는다.
4. 작성용 텍스트 검색 필드가 없고, 공지사항과 동일한 아이콘형 필터가 제공된다.
5. 테스트 문서에 결재상태와 네 업무구분 라벨이 공지사항 레이아웃의 해당 위치에 노출된다.
6. 문서작성 액션으로 모달이 열리고 첫 두 유형은 선택 가능, 후속 두 유형은 비활성이다.
7. 우측 요약과 좁은 폭 레이아웃이 표시된다.
8. 테스트와 빌드가 통과하며 375px/768px/1280px 브라우저 캡처를 결과 폴더에 남긴다.
