## 2. 공통 에디터 계약

### 2.1 소유 위치

도메인 중립적인 공통 코드는 `frontend/src/shared/components/rich-text-editor/` 아래 둔다. public component는 `RichTextEditor.tsx`, clipboard API는 `clipboard.ts`, 공통 타입은 `richTextEditor.types.ts`, editor surface 스타일은 `editorStyles.ts`, 읽기/편집 본문 스타일은 `contentStyles.ts`, 이미지 크기 계산은 `imageResize.ts`로 명명한다. 공통 파일·테스트 경로에 `notice` 이름을 사용하지 않는다.

### 2.2 Props 및 이미지 upload adapter

공통 컴포넌트는 다음 책임만 제공한다.

- 편집기 생성 및 destroy lifecycle, toolbar, 공통 schema/extensions, paste 정규화
- 이미지 clipboard 파일의 local placeholder 삽입, upload callback 호출, 성공/실패 상태 반영
- 선택된 이미지의 크기 조절과 공통 content style
- 부모 다이얼로그에서 editor 인스턴스/변경 상태를 사용할 수 있는 callback

타입 계약의 논리 형태는 다음과 같다. 최종 TypeScript 필드 표기는 구현 계획과 현재 Tiptap 타입에 맞추되 의미와 책임은 유지한다.

```ts
type RichTextEditorImage = {
  src?: string;
  alt?: string;
  uploadToken?: string | null;
  fileId?: string | null;
  objectKey?: string | null;
  fileSize?: number | null;
  mimeType?: string | null;
};

type RichTextEditorProps = {
  content?: string | JSONContent;
  uploadImage?: (file: File) => Promise<RichTextEditorImage>;
  onEditorReady?: (editor: Editor | null) => void;
  onContentChange?: (editor: Editor) => void;
  onUploadingChange?: (uploadingCount: number) => void;
  readOnly?: boolean;
  placeholder?: string;
  ariaLabel?: string;
};
```

세부사항:

- `content`는 초기 콘텐츠 용도다. 비동기 조회 뒤 복원하거나 저장 완료 뒤 정리해야 하는 부모는 `onEditorReady`로 받은 editor의 Tiptap command를 사용한다. 매 부모 render마다 동일 콘텐츠로 덮어쓰지 않는다.
- `uploadImage`가 없거나 read-only일 때 image file paste는 편집기에 삽입하지 않고 안전하게 무시하며, 일반 텍스트/표 붙여넣기는 계속 지원한다.
- 업로드 결과에 `src`가 있으면 성공 이미지의 source를 교체한다. `src`가 없으면 기존 local object URL을 유지한다. `alt`는 업로드 결과 값이 있을 때만 교체하고, `uploadToken`, `fileId`, `objectKey`, `fileSize`, `mimeType`만 공통 `data-*` metadata로 저장한다. 임의 attribute map이나 endpoint-specific key는 공통 계약에 넣지 않는다.
- Notice adapter는 기존 notice 응답(`imageUrl`, object/file metadata)을 위 계약으로 변환한다. Draft adapter는 draft 전용 업로드 응답을 동일 계약으로 변환한다. 저장 payload 직렬화 시 기존 도메인 다이얼로그가 원래 계약으로 변환한다.
- 업로드 중에는 local object URL 및 editor-local 식별자로 image node를 특정한다. 업로드 완료 후 해당 node가 편집기 문서에 없으면 optional orphan callback으로 결과를 부모에 전달한다. Draft adapter는 전용 DELETE API로 즉시 제거한다. Notice는 기존 server cleanup 계약을 그대로 사용하며 공통 컴포넌트가 endpoint를 추정하지 않는다.
- 실패 시 실패 placeholder만 제거하고 upload error callback/state를 전달한다. 기존 다른 본문은 변경하지 않는다. 실패·node removal·unmount 시 local object URL을 revoke한다. 성공 응답에 안정 `src`가 있으면 교체 직후 local URL을 revoke하고, `src`가 없는 경우 이미지가 편집기에 남아 있는 동안 유지한 후 제거/unmount 시 revoke한다.
- 업로드 진행 수를 callback으로 보고해 다이얼로그가 기존 저장 비활성/닫기 정책을 유지한다.

### 2.3 공통 편집 기능

- Basic text: bold, italic, strike, bullet list, ordered list, blockquote, undo, redo.
- Inline style: font family, font size, text color; 안전한 값 parsing/rendering은 기존 notice allowlist와 Tiptap 확장을 유지한다.
- Table: 표/행/셀/헤더 및 기존 resize와 `cellMinWidth=16` 동작. 셀 배경, 테두리, 정렬, 크기 등 기존 notice clipboard allowlist만 유지한다.
- Clipboard: 표 HTML 우선, plain text fallback, 직접 row/cell 경계, `rowspan`/`colspan`, 빈 셀/행, `<br>`/문단 경계, 허용된 폰트 스타일을 기존 notice normalizer와 동일하게 처리한다. unsafe HTML/CSS는 제거한다.
- Images: 파일 clipboard 우선(단, 표 HTML 존재 시 현재 notice 동작대로 표를 우선), upload placeholder, upload state, aspect ratio를 유지하는 선택 이미지 크기 조절. 기존 notice의 width clamp 120–1200px, height 최소 80px 및 8개 resize handle 방향을 유지한다.
- Toolbar는 각 호출부가 제공하는 footer 영역에 렌더링하거나 공통 editor API를 통해 동일 명령을 제어한다. 두 호출부의 명령/active state 의미는 동일하며 각 다이얼로그의 모달·필드·첨부 UI는 공통 editor 범위에 포함하지 않는다.

## 3. 도메인 adapter 계약

### 3.1 공지

- `NoticeComposerDialog`는 제목/구분/첨부 선택·삭제/필수 검증/submit을 계속 소유한다.
- `uploadNoticeEmbeddedImage` 호출과 응답 mapping, 저장 body HTML/JSON/text 및 `embeddedImages` payload 구성은 notice 경계에 남긴다.
- 기존 인증 notice 이미지의 blob 복원, 이미지 metadata 및 `collectNoticeEmbeddedImages` 대응 직렬화도 도메인 책임이다.
- API path, 저장 payload key, attachment 동작, modal theme/size는 변경하지 않는다.

### 3.2 기안양식

- `DraftFormTemplateDialog`는 template GET/PUT, image upload/delete/GET, authenticated image 복원, dirty confirmation 및 저장 후 목록 갱신을 계속 소유한다.
- 업로드 반환값을 공통 이미지 계약으로 변환하되 `/api/v1/co/workflow/forms/...` 경로, upload token/fileName, tenant/form 소유권, cleanup 및 JSON/HTML 저장 방식은 변경하지 않는다.
- template JSON/HTML round-trip에 font, color, table, image size와 기존 이미지 식별자가 유지되어야 한다.

## 4. 공지 페이지 모듈 경계

- `CommunityNoticePage.tsx`: route props와 page layout, permission props, hooks 결과의 하위 component 전달만 담당한다.
- `hooks/`: 기능 책임별 조회/목록 상태와 상호작용 흐름을 소유한다. 검색 결과에 근거해 경계를 나누며, 모든 동작을 단일 거대 hook으로 옮기지 않는다. hook은 UI 렌더링이나 JSX를 소유하지 않는다.
- `services/noticeBoardService.ts`: 공지 게시글 endpoint의 단일 소유자. endpoint 경로, method 및 payload 계약은 변경하지 않는다.
- `types/`: 공지 API DTO, 작성/수정 폼 payload, 화면 callback에 필요한 도메인 타입을 둔다. 타입 중복 선언을 남기지 않는다.
- `data/`: API 모델을 feed/comment/summary view model로 바꾸는 순수 변환과 fixture를 유지한다.
- `components/`: 기존 feed/list/summary/filter/composer/panel UI를 유지한다.
- `shared/services/`: 댓글, 공통 파일, 공통 코드 endpoint는 현재 shared API owner를 유지한다. 훅에서 조합 호출하되 endpoint를 복제하지 않는다.
- 로딩/오류/낙관적 갱신, pagination/filter, selected detail, comment paging, like/bookmark/pin, create/update/delete 동작은 이전 페이지 테스트와 동일해야 한다.

## 5. 기존 문서 동기화 범위

### 20261002_011 기안양식 본문 에디터

- 공통 editor component가 shared에 위치하며 dialog 내부 전용 editor 파일을 만들지 않는 것으로 변경한다.
- draft API, 업로드/이미지 ownership, save, cleanup과 권한은 그대로 draft dialog/service에서 관리한다고 명시한다.
- 표준 rich-text 기능은 shared editor에서 제공하며 draft의 이전 기능 수준 제한을 제거한다.

### 20261002_012 공지 Excel 붙여넣기

- clipboard 정규화 코드가 공지 폴더에서 shared clipboard module로 이동하는 것을 명시한다.
- 현재 Excel 표 구조, 스타일 allowlist, 일반 텍스트 fallback 및 이미지 우선순위 요구를 그대로 유지한다.
- Excel 전용 작업의 제외 범위는 당시 편집 범위 설명으로 유지하되, 공통화 후 draft가 같은 구현을 소비한다는 후속 작업 문서를 링크해 “다른 consumer의 편집기 동작은 영구히 별도”라는 의미가 되지 않도록 한다.

## 6. 회귀/접근성/반응형 검증

- Vitest: clipboard unit, shared editor rendering/commands, upload success/failure, image resize, notice composer payload/theme, draft dialog/service, notice page and local update tests.

- Browser: Chromium으로 UI 경로를 통해 공지 작성과 기안양식 메뉴를 열어 plain text, Excel 표 paste, 이미지 upload/resize, save/close를 확인한다. viewports: 375px, 768px, 1280px.
