## 2. 데이터 모델

### 2.1 `tb_id_sequence`

| 컬럼                | 타입           | 제약/의미                                                   |
| ------------------- | -------------- | ----------------------------------------------------------- |
| `generator_key`     | `varchar(100)` | 발번 목적. 상세코드는 `COMMON_CODE_ITEM_CODE`               |
| `scope_key_1`       | `varchar(100)` | 첫 번째 발번 범위. 상세코드는 `common_code_group_id` 문자열 |
| `scope_key_2`       | `varchar(100)` | 두 번째 발번 범위. 상세코드는 빈 문자열                     |
| `last_issued_value` | `bigint`       | 마지막으로 발급/예약한 숫자, 0 이상                         |
| `created_at`        | `timestamp`    | 생성 시각                                                   |
| `updated_at`        | `timestamp`    | 갱신 시각                                                   |

복합 기본키는 `(generator_key, scope_key_1, scope_key_2)`이다. 범위 키는 NOT NULL로 두어 PostgreSQL NULL 복합 유일성 문제를 피한다. 이 테이블에는 `tenant_id`를 두지 않는다. 현재 공통코드 그룹 ID는 전역 고유하므로 그룹 ID가 카운터 범위를 구분한다. 기존 `tb_common_code_group` 및 `tb_common_code_item`의 `tenant_id`는 그대로 둔다.

### 2.2 기존값 초기화

마이그레이션은 각 상세코드 그룹의 숫자 전용 `item_code` 최대값으로 해당 카운터를 초기화한다. 숫자 문자열은 발급 비교 시 정수로 취급한다. 세 자리 초과 값도 유지하며 자르지 않는다. 기존 문자열 코드의 의미나 값은 변경하지 않는다.

## 3. 발급 및 저장 흐름

1. 공통코드 생성 요청의 `itemCode`를 trim한다.
2. 값이 비어 있으면 `COMMON_CODE_ITEM_CODE`, 그룹 ID, 빈 두 번째 범위 키로 `nextValue`를 요청한다.
3. 발급 숫자를 최소 세 자리 0-padding 문자열로 만든다. 예: `1 -> 001`, `999 -> 999`, `1000 -> 1000`.
4. 카운터 발급은 PostgreSQL `INSERT ... ON CONFLICT DO UPDATE ... RETURNING` 단일 문장으로 처리한다.
5. 값이 직접 입력된 경우 기존 중복 검증을 수행하고 문자열을 그대로 저장한다. 값이 숫자 전용이면 저장 트랜잭션 안에서 카운터를 입력값 이상으로 동기화한다.
6. 공통코드 관리 화면의 신규 행과 기안양식 분류 설정 공통 모달의 신규 행은 코드 생략이 가능하고 상세코드명은 계속 필수다. 수정 행은 기존처럼 코드 필수 검증을 유지한다.
7. 동일 그룹의 코드 유일성은 기존 `UNIQUE (group_id, item_code)` 제약이 보장한다.
8. 공통 모달의 상세코드 컬럼은 읽기 전용을 유지하며, 빈값 허용을 위해 컬럼 필수 검증만 끈다. 모달 저장 콜백은 기존 상세코드 생성 API를 호출한다.

## 4. 오류·동시성 기준

- 발급과 상세코드 insert는 같은 DB 트랜잭션에서 수행한다. insert 실패 시 카운터 증가도 롤백된다.
- 같은 발번 키에 대한 병렬 호출은 upsert 행 잠금으로 서로 다른 정수를 받아야 한다.
- 수동 숫자 코드 동기화는 `GREATEST(현재값, 입력값)`으로 처리해 카운터를 후퇴시키지 않는다.
- 기존 직접 입력, 테넌트 검증, 그룹별 중복 검사, 상위 상세코드 검증은 유지한다.

## 5. 검증 기준

- 빈 코드의 첫 발급 결과가 `001`이다.
- 같은 그룹에서 다음 발급은 증가하고 다른 그룹은 별도 카운터를 쓴다.
- 기존 그룹의 최대 숫자 코드가 `999`이면 다음 발급은 `1000`이다.
- 수동 숫자 코드 저장 후 자동 발급값이 수동 숫자보다 크다.
- 수동 비숫자 코드와 기존 API 계약이 유지된다.
- 신규 행의 빈 코드 저장을 UI가 허용하고 기존 행 코드 삭제는 차단한다.
- 공통코드 설정 모달에서 상세코드가 비어 있는 신규 분류 저장이 생성 API에 빈 코드로 전달된다.
- 일괄 저장 API가 신규 행만 빈 코드를 허용하고 수정 행의 빈 코드를 거부한다.
- DB 동시성 테스트/검증과 백엔드·프론트엔드 관련 테스트 및 빌드가 통과한다.
