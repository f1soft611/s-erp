# 20261002_004 메뉴관리 조회조건 세션 보존 상세 사양서

## 1. 목적과 대상

대상 화면은 `frontend/src/pages/settings/system/menus/MenuManagementPage.tsx`다. 화면 재진입 시 로그인 세션 동안 마지막으로 사용한 모듈, 권한, 검색어를 복원한다. 공통코드 관리와 동일한 페이지 세션 훅을 사용한다.

## 2. 저장 계약

- Session key: `s-erp:page:menu-management`
- Version: `1`
- 저장 필드:
  - `selectedModuleId?: number`
  - `selectedRoleId: string`
  - `searchQuery: string`
- 초기 상태: 모듈 ID 미지정, 빈 권한 ID, 빈 검색어.
- 저장 훅: `usePageSessionState` (`sessionStorage` 수명은 현재 탭 세션).
- 검증 실패 또는 버전 불일치는 공통 훅이 key를 제거하고 초기 상태를 사용한다.

## 3. 초기 복원 순서

1. 모듈/권한 정의를 불러오고 역할 목록을 불러온다.
2. 저장 모듈 ID가 현재 모듈 옵션에 있으면 사용한다. 없으면 현재 기존 초기화와 같이 첫 번째 모듈을 사용한다.
3. 저장 권한 ID가 현재 역할 옵션에 있으면 사용하고, 없으면 빈 값으로 둔다.
4. 복원된 모듈과 권한이 모두 유효할 때 해당 조합으로 메뉴 목록을 조회한다. 권한이 없거나 만료되었으면 메뉴 API를 호출하지 않고 기존 필수 선택 안내를 표시한다.
5. 검색어는 세션 값 그대로 입력 컨트롤에 복원하고, 기존 `filteredMenus` 로직으로 현재 메뉴 목록을 필터링한다.
6. 모듈, 권한, 검색어가 바뀌면 최신 페이지 상태를 저장한다.

초기 비동기 옵션 로드가 완료되기 전에는 저장된 ID의 유효성을 추정하지 않는다. 로드 오류는 기존 `메뉴 관리 정보를 불러오지 못했습니다.` 오류 흐름을 유지한다.

## 4. 기존 동작 유지

- 사용자 입력으로 모듈/권한을 바꿀 때 기존 dirty 검사 및 확인 다이얼로그를 유지한다.
- 조회, 저장, 삭제, 오류 처리, 검색 필터와 API 파라미터는 변경하지 않는다.
- 세션은 조회 조건만 복구하며 행 데이터나 미저장 편집 내용을 복구하지 않는다.

## 5. 제외 범위

- 트리 행 선택 및 트리 펼침/접힘 상태
- 신규/수정/삭제된 그리드 행, 편집 셀, 미저장 권한 변경
- localStorage, 서버 영구 저장, 다른 탭/사용자와 상태 공유
- F1Tree/F1Grid 공통 API 변경

## 6. 검증

- 세션 값으로 모듈·권한·검색어가 복원되고 맞는 메뉴 조회가 발생하는지 검증한다.
- 옵션에 없는 ID 및 잘못된 세션 값이 안전한 기본/빈 권한으로 처리되는지 검증한다.
- 메뉴관리 필수 선택/그리드 테스트와 프론트엔드 빌드를 실행한다.
