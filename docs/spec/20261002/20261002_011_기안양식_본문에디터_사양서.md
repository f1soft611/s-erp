# 20261002_011 기안양식 본문 에디터 상세 사양서

> 계획서: [20261002_011 기안양식 본문 에디터 계획서](../../plan/20261002/20261002_011_기안양식_본문에디터_계획서.md)

## 1. 문서 상태 및 결정 근거

- 상태: 계획서·사양서 작성 완료, 구현 승인 대기
- 기능 경로: 기준정보 > 전자결재관리 > 기안양식관리 (`/co/workflow/form`)
- read-only PostgreSQL MCP `list_tables(public)`에서 `tb_drafting_work_category`, `tb_common_file`을 확인했다. `describe_table`에서 template JSONB/HTML 컬럼과 공통 파일 소유권/임베디드 컬럼을 확인했으며 업무 데이터 행은 조회하지 않았다.
- `drafting_work_template_text` 컬럼은 실제 스키마에 없다. 신규 텍스트 컬럼은 만들지 않으며 본문 text는 HTML/에디터 상태에서 파생한다.
- 신규 테이블, 컬럼, FK 변경이 없으므로 migration/rollback SQL은 작성하지 않는다.
- MinIO 운영자는 `tenant/` prefix와 object tag `s-erp-temp-owner=drafting-work-form`가 모두 일치하는 임시 객체를 7일 후 만료하도록 설정한다. 영구 객체에는 tag를 copy하지 않아 이 rule에 포함되지 않게 한다. 애플리케이션은 저장/취소 시 명시된 임시 객체를 즉시 정리한다.

## 2. 화면 구성 및 동작

### 목록 액션

- `DraftFormGrid`의 마지막 컬럼은 `문서 양식`이며 F1-Grid 공개 `renderCell` API를 사용한다.
- `hasDocument=false`이면 액션 `문서 작성`, `hasDocument=true`이면 `문서 수정`을 표시한다. 액션은 현재 행의 `draftingWorkCategoryId`, `cataTypeCode`, `codeName`으로 대상 양식을 고정한다.
- 현재 메뉴의 UPDATE 권한이 있을 때만 실행 가능한 버튼을 표시한다. 권한이 없으면 상태 텍스트만 표시한다. 액션 클릭은 Grid의 행 선택/편집 상태를 바꾸지 않는다.
- 본문 전문은 목록 응답에 넣지 않는다. 기존 조회 응답의 `hasDocument` 계산은 JSONB 또는 공백이 아닌 HTML이 있을 때 true로 유지한다.

### 본문 다이얼로그

- S-ERP `CommonDialog` 공통 셸, 공지사항 작성 모달의 `md` 폭 및 fill body/header/footer 배치를 따른다.
- 제목은 신규 `문서 양식 작성` 또는 기존 `문서 양식 수정`이며, 양식 코드와 양식명을 식별 정보로 표시한다. 양식 메타데이터는 여기서 수정하지 않는다.
- 본문 영역은 Tiptap 기반 단일 rich-text editor다. 툴바/표 편집은 공지사항 본문 에디터의 기존 기능 수준을 따른다. 첨부파일/공지 분류/게시글 제목 입력은 포함하지 않는다.
- 저장 중 중복 저장과 편집을 막고 진행 상태를 표시한다. 성공하면 목록을 quiet reload해 `hasDocument`를 갱신하고 다이얼로그를 닫는다. 실패하면 다이얼로그와 편집 내용을 유지하고 오류를 표시한다.
- 본문이 변경된 상태에서 취소, X, 바깥 닫기를 요청하면 공용 unsaved-changes 확인을 표시한다. 취소 응답은 편집을 유지하고 폐기 응답은 남은 임시 업로드를 삭제한 후 닫는다.

### 붙여넣기

- `text/html`에 표 행이 있으면 공지사항의 clipboard HTML normalizer와 같은 정규화/허용 셀 구조를 사용해 `<table>/<tr>/<td>/<th>`로 삽입한다. 원본 스프레드시트의 script/style/비허용 외부 포맷은 유지하지 않는다.
- 표형 HTML이 아닌 텍스트는 `text/plain`의 줄바꿈/탭 정규화를 거쳐 일반 텍스트로 삽입한다.
- 클립보드에 이미지 파일이 포함되면 이미지 업로드를 우선한다. 한 번에 여러 이미지가 오면 클립보드 순서대로 처리한다.
- 이미지 업로드 동안 원래 커서 위치에 local placeholder와 업로드 상태를 보이고, 각 이미지마다 기안양식 전용 임시 API를 호출한다. 성공 시 반환된 `uploadToken`을 image node metadata에 연결하고 실패한 이미지는 제거하며 오류를 표시한다. 표형 clipboard HTML과 함께 제공되는 이미지는 기존 공지사항 우선순위와 동일하게 표 HTML 붙여넣기를 우선한다.
- 외부 HTML의 이미지 URL은 허용된 `http(s)` 또는 앱 상대 경로만 유지한다. 붙여넣기 이미지의 저장 본문은 임시 URL을 남기지 않고 서버가 반환한 고정 인증 URL로 다시 쓴다.

## 3. API 계약

모든 endpoint는 `/api/v1/co/workflow/forms` 하위에 둔다. `ResultVO` 성공 응답은 기존 패턴의 `result.item`을 사용한다. API는 요청 tenant ID를 받지 않고 인증된 `LoginVO.tenantId`를 기준으로 한다.

### 템플릿 상세 조회

`GET /{draftingWorkCategoryId}/template`

- 인증: tenant에 속한 인증 사용자
- 성공 `200`:

```json
{
  "result": {
    "item": {
      "draftingWorkCategoryId": 123,
      "cataTypeCode": "007",
      "codeName": "정기점검",
      "hasDocument": true,
      "templateJson": { "type": "doc", "content": [] },
      "templateHtml": "<p>점검 내용</p>"
    }
  }
}
```

- 양식이 tenant 내에 없거나 삭제된 경우 `404`. 미인증 `401`.

### 템플릿 저장

`PUT /{draftingWorkCategoryId}/template`

- 인증/권한: 기존 기안양식 변경 API와 같이 tenant admin을 요구한다. UI는 메뉴 UPDATE 권한이 없으면 실행 액션을 노출하지 않는다.
- 요청:

```json
{
  "templateJson": { "type": "doc", "content": [] },
  "templateHtml": "<p>점검 내용</p>",
  "embeddedImages": [
    {
      "uploadToken": "uuid-issued-by-upload-api",
      "fileName": "pasted-image.png"
    }
  ]
}
```

- `templateJson`은 Tiptap 문서 JSON이고 PostgreSQL `drafting_work_template_json JSONB`에 저장한다. `templateHtml`은 제한된 허용 태그/속성으로 정규화해 `drafting_work_template_html TEXT`에 저장한다. `template_text`는 저장하거나 반환하지 않는다.
- `embeddedImages`는 이번 본문에서 사용하는 임시 업로드만 전달한다. 기존 이미지의 `fileId`는 HTML/JSON node metadata와 `tb_common_file` 소유권으로 검증한다. 클라이언트가 보내는 object key, MIME, 파일 크기는 소유권 판정 근거로 신뢰하지 않는다.
- 성공 `200`: 저장된 `item`에 `draftingWorkCategoryId`, `hasDocument`, 안정화된 `templateJson`, `templateHtml`을 반환한다. 서버는 새 임시 이미지의 영구 귀속 후 HTML/JSON 이미지 `src`를 `/api/v1/co/workflow/forms/{id}/template-images/{fileId}`로 바꾼다.
- 권한 없음 `403`, 양식 없음 `404`, malformed JSON/HTML 또는 유효하지 않은 임시 이미지 `400`, 과대 이미지 `413`, 저장소/DB 오류 `500`.

### 기안양식 전용 이미지 임시 업로드

`POST /{draftingWorkCategoryId}/template-images/temp` (`multipart/form-data`, field `file`)

- 인증/권한: tenant admin, 양식은 인증 tenant에 존재해야 한다.
- 최대 크기 10 MiB, MIME/파일 signature 허용값은 `image/png`, `image/jpeg`, `image/gif`, `image/webp`다. 클라이언트 파일명은 경로 성분을 제거해 정규화한다.
- 저장소 object key는 `tenant/{tenantId}/drafting-work-form-temp/{draftingWorkCategoryId}/{uploadToken}/{safeFileName}` 형식이며, 업로드 시 `s-erp-temp-owner=drafting-work-form` object tag를 기록한다. 공지사항 `notice-temp` prefix 및 API를 사용하지 않는다.
- 성공 `201`의 `result.item`: `uploadToken`, `fileName`, `fileSize`, `mimeType`. 브라우저는 업로드 진행 중 local object URL을 사용하므로 임시 이미지 URL은 응답하지 않는다.
- 해당 API는 bucket 존재 확인/자동 생성/수정 권한을 요구하는 동작을 추가하지 않는다. 기존 MinIO upload 서비스 정책을 따른다.

### 미사용 임시 이미지 삭제

`DELETE /{draftingWorkCategoryId}/template-images/temp/{uploadToken}?fileName={safeFileName}`

- 인증/권한: tenant admin. 서버는 인증 tenant 및 path form ID로 임시 object key를 직접 구성하고 token/fileName을 검증한다. 임의 object key 입력은 받지 않는다.
- 현재 편집 세션에서 삭제 또는 취소된 업로드만 제거한다. 성공 `200`; 잘못된 token/file name `400`; 다른 tenant/form 소유 또는 미존재 양식 `404`.
- 본문 저장에서는 실제 본문에 사용되지 않은 이번 요청의 임시 uploadToken을 제거한다.

### 저장된 템플릿 이미지 조회

`GET /{draftingWorkCategoryId}/template-images/{fileId}`

- 인증: 현재 tenant 사용자.
- 서버는 `tb_common_file.tenant_id`, `owner_type='DRAFTING_WORK_TEMPLATE'`, `owner_id=draftingWorkCategoryId`, `file_usage_type='EMBEDDED'`, `deleted_yn='N'` 및 file ID를 모두 확인한다.
- 성공 시 저장소 stream을 `Content-Type`과 안전한 cache 정책으로 응답한다. 타 tenant, 다른 양식 또는 일반 첨부 파일이면 동일하게 `404` 처리한다.

## 4. 저장 및 파일 소유권

- 기존 `tb_drafting_work_category`의 tenant/form 행을 잠금 또는 원자적 조건으로 확인한 후, template JSONB/HTML 갱신과 공통파일 소유 metadata 저장을 같은 DB 트랜잭션으로 처리한다.
- 임시 object prefix는 `tenant/{tenantId}/drafting-work-form-temp/{formId}/{uploadToken}/{safeFileName}`이고 영구 object prefix는 `tenant/{tenantId}/drafting-work-form/{formId}/{uploadToken}/{safeFileName}`다. 임시 object에는 `s-erp-temp-owner=drafting-work-form` tag를 저장한다. 저장 시 server-side copy의 tagging directive를 `REPLACE`로 설정해 이 tag를 제거하면서 영구 prefix로 옮기고, `tb_common_file`에 `owner_type='DRAFTING_WORK_TEMPLATE'`, `owner_id=formId`, `file_usage_type='EMBEDDED'`로 귀속한다.
- 이미지 첨부 행을 기존 template의 `<img>`/Tiptap image nodes와 대조한다. 재사용 중인 file ID만 유지하고 제거된 이미지 metadata는 soft-delete 후 영구 객체를 삭제한다. DB commit 실패 시 새 영구 객체를 보상 삭제하며 원본 template은 유지한다.
- template HTML/JSON sanitizer는 script/style/iframe/object/event-handler 속성을 제거하고 Tiptap이 사용하는 paragraph, heading, list, blockquote, table, image 등 allowlist만 보존한다. 이미지 `src`는 앱의 고정 인증 이미지 URL 또는 검증 완료한 현재 요청의 임시 upload token에서만 허용한다.
- template GET과 저장 응답은 공통파일 owner 검증 후 안정 URL로 rewrite한다. 만료 가능한 presigned URL은 저장 HTML/JSON에 넣지 않는다.
- 업로드 취소/본문에서 제거 시 DELETE API로 임시 객체를 즉시 제거한다. 비정상 종료로 잔류한 객체는 MinIO lifecycle에서 `tenant/` prefix와 전용 tag가 함께 일치할 때 7일 후 정리한다. 영구 prefix에는 해당 tag를 복사하지 않아 lifecycle rule을 적용하지 않는다.
- 기존 `tb_common_file` 스키마는 `owner_type`, `owner_id`, `file_usage_type`을 지원한다. 이 작업에서는 DB DDL을 변경하지 않는다.

## 5. 오류/빈 상태/로딩 처리

- 템플릿 GET 중에는 dialog body loading 상태를 보여 편집을 막는다.
- GET 실패 시 오류와 닫기만 제공한다. 기존 목록 화면은 유지한다.
- 이미지 업로드 실패는 이미지 단위로 제거하고 에러 메시지를 표시한다. 그 외 본문은 보존하며 업로드 중 저장은 비활성화한다.
- PUT 실패 시 다이얼로그를 유지하고 입력 내용을 보존하며 재시도를 허용한다.
- 성공 후 목록은 전체 blocking overlay 없이 재조회하고 `hasDocument` 및 액션 라벨을 갱신한다.

## 6. 테스트 및 완료 검증

- Frontend: action renderer/권한, template GET/PUT payload, 신규·기존 본문 초기화/복원, dirty close, upload success/failure, cancel delete, Excel table/normal text normalization 테스트.
- Backend: template tenant scope, tenant admin write check, list `hasDocument` parity, JSONB/HTML round trip, malicious HTML rejection, tenant/form mismatch, temporary key/token/MIME/signature/size validation, image promotion and `tb_common_file` ownership, stable stream access, unused image cleanup, 7-day prefix configuration evidence.
- Regression: 공지사항 Excel/일반 텍스트/이미지 붙여넣기 및 notice 저장 흐름 focused suite.
- `cd frontend; npm run build`, focused Vitest, `cd backend; mvn test`를 실행하고 결과 원장에 기록한다.
- Playwright Chromium에서 기안양식 메뉴를 UI로 연 뒤 신규/기존 행의 문서 액션, 표/이미지 붙여넣기, 저장·재열기·취소 흐름을 375px, 768px, 1280px에서 확인하고 캡처를 결과 폴더에 저장한다.
- 완료 결과는 `docs/result/20261002/draft-form-template-editor/`에 원장, 결과 설명, 스크린샷을 둔다.
