# 알림 구분 표시 상세사양서

기준: [작업지시서](../../directions/20261030/20261030_007_알림구분표시_작업지시서.md), [계획서](../../plan/20261030/20261030_007_알림구분표시_계획서.md), [설계](../../superpowers/specs/2026-10-30-notification-type-labels-design.md)

## 유형 표시 및 필터

| `eventType` | 표시 |
|---|---|
| `APPROVAL_COMMENT_MENTION` | 문서 멘션 |
| `DIRECT_MESSAGE_RECEIVED` | 새 쪽지 |

- 알림함 리스트형 행의 첫 번째 고정 열에 비상호작용 분류 아이콘을 표시한다. 문서 작성 리스트형처럼 아이콘은 본문 영역과 분리하며, 읽음 점과 제목보다 앞에 둔다. 문서 멘션은 문서 아이콘, 새 쪽지는 봉투 아이콘을 사용하며 tooltip과 accessible label은 각각 `문서 멘션`, `새 쪽지`다. 제목은 줄어들어 말줄임될 수 있으나 아이콘은 유지된다.
- `전체 유형`, `문서 멘션`, `새 쪽지` 유형 필터를 기존 `전체`/`읽지 않음` 상태 필터와 독립적으로 제공한다.
- 두 필터 그룹은 좁은 화면에서 겹치지 않고 줄바꿈한다.
- 유형은 `GET /api/v1/groupware/notifications?eventType=...`로 전달한다. 전체 유형은 parameter를 생략한다.
- 허용 유형은 위 두 eventType뿐이며 미지원 값은 `400 Bad Request`다. 유형 조건은 사용자/tenant, unreadOnly, cursor, limit와 함께 DB query에 적용되어 pagination 결과가 유형별로 정확하다.
- 헤더 팝오버와 쪽지함은 변경하지 않는다.

## 알림 숨김

- 각 알림에 `목록에서 숨기기` 단건 액션을 제공한다. 현재 사용자/tenant 범위의 알림 하나만 숨기며 원본 댓글/쪽지는 변경하지 않는다.
- `읽은 알림 정리`는 확인 다이얼로그를 표시한다. 현재 category filter 범위의 읽은 알림만 숨긴다. 읽지 않음 상태 filter에서는 버튼을 비활성화한다.
- 단건 API `PUT /api/v1/groupware/notifications/{notificationId}/archive`는 현재 사용자의 알림만 대상으로 하고 재호출에도 성공한다.
- 일괄 API `PUT /api/v1/groupware/notifications/archive-read?eventType=...`는 선택한 유형의 읽은 알림만 archive하고 처리 건수를 반환한다. `eventType`은 생략 가능하고 동일 allowlist를 적용한다.
- 숨긴 행은 목록과 unread summary에서 제외한다. 물리 삭제는 하지 않아 이벤트 deduplication 이력을 보존한다.

## 데이터베이스

- `tb_notification.archived_at TIMESTAMP NULL`을 추가한다.
- schema migration, rollback, 변경 이력을 `docs/database/20261030` 및 `backend/DATABASE/20261030`에 동일한 이름으로 작성하고 누적 `docs/database/db-schema.md`를 갱신한다.
- DB MCP 근거: `list_tables`로 `tb_notification` 존재를 확인했다. `describe_table`에서 `event_type`, `read_at`, `created_at`은 존재하고 `archived_at`은 없음을 확인했다. 행 데이터를 조회하지 않았고 DB에 migration을 적용하지 않는다.

## 검증

- 알림 목록 frontend tests: 두 accessible 유형 아이콘이 첫 번째 열에 표시되는지, 유형 filter 전달, read filter와 병행, 오래된 요청 응답이 현재 필터 결과를 덮어쓰지 않는지, 단건 hide, 읽은 알림 bulk hide 확인.
- 알림 service tests: eventType URL encoding 및 archive API request/response 검증.
- Backend `NotificationServiceImplTest`, `NotificationMapperXmlTest`: 허용 유형 전달, 미지원 유형 400, tenant/user 범위, 읽은 알림만 일괄 archive, 숨김 목록/요약 및 cursor/filter mapper 조건 확인.
- 실행: `npm run test -- tests/notification-inbox.test.tsx tests/notification-service.test.ts tests/notification-center.test.tsx`, `npm run build`, `mvn -f backend/pom.xml '-Dtest=NotificationServiceImplTest' test`.
- 실제 브라우저 375px, 768px, 1280px에서 첫 번째 열 분류 아이콘/필터 그룹과 archive controls 가시성, 가로 넘침을 확인한다.
