# 문서현황 참조 확인 상태 호환성 상세사양

## 근거

- [계획서](../../plan/20261030/20261030_001_document-status-confirmed_계획서.md)
- [기존 참조 확인 계약](../20261029/20261029_001_문서_참조자_확인_액션_상세사양서.md): 참조 확인은 `REFERENCE` 참여 행의 `action_status=CONFIRMED`로 기록하며 일반 조회 권한을 유지한다.

## 계약

- 문서현황 `myActionStatus` 응답의 단일 `CONFIRMED` 및 기존 상태와 쉼표+공백으로 결합된 `APPROVED, CONFIRMED`를 정상으로 받아들인다.
- 기존 `ACTION_STATUS_OPTIONS`에 `CONFIRMED / 확인완료`를 추가해 응답 검증, 내 처리상태 표시 및 상세검색 옵션을 일치시킨다.
- 프론트엔드 `DocumentStatusActionStatus`와 서버 문서현황 검색 허용 상태에 `CONFIRMED`를 추가한다. `myActionStatus` 필터는 기존 SQL 조건과 인증 사용자/테넌트 범위를 사용한다.
- 알 수 없는 상태나 잘못된 문서 응답은 종전대로 오류로 처리한다. 임의 상태 허용, 행 누락, 빈 성공 응답으로의 변환은 금지한다.
- 확인 액션, 결재 상태 전이, 승인/합의 처리 허용 상태, 기준일, 권한, 레이아웃은 바꾸지 않는다.

## DB 확인과 변경 범위

- 기본 `s-erp-postgresql-readonly`의 `list_tables`, 관련 문서·참여자·사용자 연결 테이블 `describe_table`을 직접 호출했다.
- 제한된 `COUNT` 집계로 조회 대상 존재와 `CONFIRMED` 참여 문서 존재를 확인했다. 개별 업무 행, 계정/인증 정보는 결과에 기록하지 않는다.
- DB 데이터/스키마/SQL 변경 없음. 날짜별 마이그레이션 및 누적 스키마 갱신 대상이 아니다.

## 검증

- 단일·복합 확인 상태가 섞인 전체/페이징 응답 수용과 알 수 없는 상태 거부.
- 검색값 변환 및 서버 DAO 필터 전달에서 `CONFIRMED` 보존.
- 합성 데이터로 실제 브라우저 375/768/1280px 목록과 확인완료 표시, 페이지 전체 가로 넘침 여부 확인.
- 실제 사용자 인증 재현은 자격 증명 없이 수행했다고 주장하지 않는다.
