# 거래명세표와 회사 직인 상세사양서

## 회사정보

- 기존 페이지 헤더와 저장 권한을 유지한다. 입력 영역을 기본정보, 주소·연락처, 직인으로 나누고 반응형 배치한다.
- 입력 폼은 가운데 정렬하되 세로 스크롤은 전체 콘텐츠 폭을 사용하는 외부 영역에 둔다.
- 각 입력 필드의 중복 기본 여백을 제거하고 행 사이 간격을 12px로 유지한다.
- 회사정보 저장 요청이 성공하면 공통 성공 토스트로 `회사정보를 저장했습니다.`를 표시한다. 저장 실패 시에는 기존 오류 표시를 유지하고 성공 토스트를 표시하지 않는다.
- 직인은 PNG 또는 JPEG 파일을 선택해 미리보기·교체·삭제한다. 최대 파일 크기는 512 KiB, 이미지 면적은 16,777,216픽셀이다. 회사정보 저장을 눌러야 함께 반영된다.
- 회사정보 GET·PUT의 `stampImage`는 이미지 데이터 URL 문자열이다. 빈 문자열은 삭제, 요청에서 필드를 생략하면 기존 이미지를 유지한다. 서버에서 실제 이미지 형식·크기와 디코딩 가능 여부를 검증한다.
- `tb_tenant.stamp_image`에 보관한다. 본래 테넌트의 회사정보 권한을 그대로 적용한다.

## 출력 및 보존

- 사용자 최종 요청과 PDF의 구조처럼 각 A4 페이지에 같은 거래명세서 두 부를 상하 배치한다. 수신처와 공급자 정보, 직인, 금액, 품목별 일자·품명/규격·수량/단위·단가·공급가·VAT 및 수량·금액 합계를 표시한다.
- 합계가 안전한 정수일 때 금액을 한글과 숫자로 함께 표시한다. 소수 금액은 잘못된 한글 금액을 표기하지 않고 숫자로 표시한다.
- 미리보기에서 출력 용지를 가로로 가운데 정렬한다. 좁은 화면은 출력물을 축소하거나 자르지 않고 내부 가로 스크롤을 제공한다.
- 품목이 많거나 품명이 길면 출력에 필요한 줄 수를 고려해 페이지별로 분할하고 각 페이지에 동일한 두 부를 배치한다. 각 행은 한 번씩 각 부에 나타나며 합계는 전체 명세서 기준이다.
- 발행 시 `tb_sales_statement_hd.supplier_stamp_image`에 회사 직인을 복사한다. 스냅샷이 있으면 직인 변경 또는 삭제 후에도 스냅샷을 사용한다. 직인 스냅샷이 없는 기존 명세서는 출력 시 현재 회사 직인을 사용하며, 이 경우 회사 직인 변경이 해당 명세서 출력에도 반영된다.
- 두 컬럼의 날짜별 SQL, 변경 이력과 롤백을 두 스키마 폴더에 동일하게 보관하며 실제 적용은 하지 않는다.

## 검증

- 직인 유효·잘못된 파일·크기 초과·삭제·누락, 테넌트 권한, 발행 시 스냅샷과 과거 출력 보존을 집중 검증한다.
- 375·768·1280px 회사정보와 인쇄 미리보기, A4 다중 페이지의 양쪽 사본을 실제 브라우저로 확인한다.
