# 출하계획 메뉴와 레이아웃 상세사양서

## 메뉴

- `SALES_DELIVERY` 아래에 `SALES_DELIVERY_PLAN_CREATE`와 `SALES_DELIVERY_PLAN_STATUS`를 배치한다.
- 기존 두 자식의 ID, URL과 권한은 보존한다. 독립 부모 `SALES_DELIVERY_PLAN`은 안전하게 제거할 수 있을 때만 제거한다.
- 기존 노드가 없을 때 출하계획등록과 출하계획현황을 추가한다. 신규 권한은 기존 수주 메뉴 권한 복사 규칙을 따른다.
- 충돌 또는 예기치 않은 참조는 중단하고 임의 삭제하지 않는다. SQL과 롤백은 날짜별 이력에 기록하고 DB에는 직접 실행하지 않는다.

## 화면

- 출하계획등록: 출하등록과 동일한 PageHeader, 기본정보, 상세 그리드와 툴바 구조를 사용한다. 계획 일자, 수량 편집과 분할을 보존한다.
- 출하계획현황: 출하현황과 동일한 헤더 조회 버튼, PageSearchArea, F1-Grid 결과 목록 구조를 사용한다. 계획일 기간은 필수이며 상세 조회와 수정은 계속 가능하다.
- 현황 수정은 기존 현황 수정 권한 또는 읽기가 허용된 계획등록 메뉴의 수정 권한을 사용한다. 읽기가 없는 등록 메뉴의 수정 권한은 사용하지 않는다.
- AUTO는 기존 계획을 조회·수정하며 MANUAL 신규 등록을 유지한다. API, ID, 권한, 주문 연계 및 검증은 변경하지 않는다.
- 모바일 375px, 태블릿 768px, 데스크톱 1280px에서 화면 전체 가로 넘침과 겹침을 확인한다.
