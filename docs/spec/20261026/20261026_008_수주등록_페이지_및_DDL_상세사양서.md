## 1. 메뉴 및 페이지

- 메뉴 계층: 영업관리 > 수주관리 > 수주등록
- 경로: `/sales/order/create`
- 대시보드가 반환한 sales 모듈의 leaf 경로 ID/page key `create`에서만
  페이지를 렌더링한다.
- `AppRouter`의 `/sales/*` 인증 경로와 기존 메뉴/권한 데이터는 변경하지
  않는다.
- 페이지는 신규 수주 작성 전용이다. 수주 검색/수정 및 저장 API는 포함하지
  않는다.
- 기존 공통 `PageHeader`, `PageMessageArea`, F1-Grid를 사용한다.
- 저장 버튼은 비활성 상태이며 API 미연결임을 명시한다. 어떤 입력도 저장된
  것처럼 표시하거나 초기화하지 않는다.

## 2. 데이터베이스 계약

### 2.1 `public.tb_sales_order_hd`

| 컬럼 | 타입 | Null/기본값 | 비고 |
| --- | --- | --- | --- |
| `sales_order_id` | BIGSERIAL | NOT NULL | 내부 PK |
| `tenant_id` | BIGINT | NOT NULL | `tb_tenant(tenant_id)` FK |
| `order_no` | VARCHAR(30) | NOT NULL | `tenant_id` 내 유일 업무번호 |
| `order_dt` | DATE | NOT NULL | 수주일 |
| `customer_id` | BIGINT | NOT NULL | 거래처 ID |
| `quot_no` | VARCHAR(30) | NULL | 견적 참조 문자열, FK 없음 |
| `delivery_dt` | DATE | NULL | 헤더 납기 |
| `delivery_place` | VARCHAR(200) | NULL | 납품 장소 |
| `delivery_method` | VARCHAR(50) | NULL | 배송 방법 |
| `status` | VARCHAR(20) | NOT NULL, `수주등록` | 허용: 수주등록/생산대기/생산중/출하완료/취소 |
| `total_amt` | NUMERIC(15,2) | NULL, 기본 0 | 상세 합계 |
| `remark` | VARCHAR(500) | NULL | 비고 |
| `use_at` | CHAR(1) | NOT NULL, 기본 Y | Y/N CHECK |
| `created_by` | VARCHAR(10) | NULL | 생성자 |
| `created_at` | TIMESTAMP | NOT NULL, 기본 CURRENT_TIMESTAMP | 생성 시각 |
| `updated_by` | VARCHAR(10) | NULL | 수정자 |
| `updated_at` | TIMESTAMP | NULL | 수정 시각 |

키 및 관계:

- PK: `sales_order_id`
- UNIQUE: `(tenant_id, order_no)`, `(sales_order_id, tenant_id)`
- FK: `tenant_id → tb_tenant(tenant_id)`
- FK: `(customer_id, tenant_id) → tb_customer_info(customer_id, tenant_id)`
- status CHECK는 원본 SQL의 수주상태 5개 값을 사용한다.
- 현재 견적 테이블이 없어 `quot_no` FK는 만들지 않는다.

### 2.2 `public.tb_sales_order_dt`

| 컬럼 | 타입 | Null/기본값 | 비고 |
| --- | --- | --- | --- |
| `sales_order_detail_id` | BIGSERIAL | NOT NULL | 상세 내부 PK |
| `sales_order_id` | BIGINT | NOT NULL | 헤더 ID |
| `tenant_id` | BIGINT | NOT NULL | 헤더 tenant |
| `line_no` | INT | NOT NULL | 수주 내 순번 |
| `material_id` | BIGINT | NOT NULL | 품목 ID |
| `order_qty` | NUMERIC(15,2) | NOT NULL | 주문 수량 |
| `unit_price` | NUMERIC(15,2) | NOT NULL | 수주 단가 |
| `supply_amt` | NUMERIC(15,2) | NOT NULL | 공급가 |
| `vat_amt` | NUMERIC(15,2) | NULL, 기본 0 | 부가세 |
| `total_amt` | NUMERIC(15,2) | NOT NULL | 공급가+부가세 |
| `delivery_dt` | DATE | NULL | 라인 납기 |
| `shipped_qty` | NUMERIC(15,2) | NULL, 기본 0 | 출하 완료 수량 |
| `line_status` | VARCHAR(20) | NULL, 기본 `대기` | 상세 상태 |

키 및 관계:

- PK: `sales_order_detail_id`
- UNIQUE: `(sales_order_id, line_no)`
- FK: `(sales_order_id, tenant_id) → tb_sales_order_hd(sales_order_id,
  tenant_id) ON DELETE CASCADE`
- FK: `(material_id, tenant_id) → tb_material_info(material_id, tenant_id)`
- material_id 검색 인덱스를 추가한다.
- `tenant_id`가 일치하는 마스터만 참조할 수 있도록 복합 FK를 유지한다.

### 2.3 SQL 이력

- 생성, 빈 테이블 전용 rollback, 변경 이력은
  `docs/database/20261026`와 `backend/DATABASE/20261026`에 같은 이름과
  내용으로 저장한다.
- rollback은 헤더 또는 상세 데이터가 존재하면 예외로 중단하고, 상세를
  먼저 제거한다.
- SQL 정적 검사로 사본 동일성과 계약을 확인한다. MCP는 읽기 전용이며
  실제 DDL 실행은 하지 않는다.
- `docs/database/db-schema.md`에 현행 계약과 변경 파일 링크를 기록한다.

## 3. 공통 마스터 선택기

공통 타입:

```ts
export type MasterPickerOption = {
  id: number;
  code: string;
  name: string;
};

export type MasterPickerSearch = (
  keyword: string,
) => Promise<MasterPickerOption[]>;
```

- `CustomerPicker` 및 `MaterialPicker`는 `value`, `search`, `onChange`,
  `disabled`를 받는다.
- 공통 dialog는 검색어와 명시적 검색 액션/Enter를 지원한다.
- loading, 결과 없음, 검색 오류는 서로 다른 표시 상태다.
- 오류를 빈 결과로 바꾸지 않는다. 더 새로운 검색 요청의 결과가 있으면
  오래된 비동기 응답으로 결과를 덮어쓰지 않는다.
- 선택 결과는 양의 정수 ID, 코드, 이름을 반환한다.
- 공유 UI는 페이지 전용 API/서비스를 import하지 않는다. 수주 기능이 기존
  `fetchCustomers`와 `fetchMaterials`를 호출하여 typed option으로 변환한다.

## 4. 수주 입력 UI

### 4.1 헤더

- 수주번호: read-only 안내 “저장 연동 단계에서 채번 기준 확정”.
- 수주일자: 로컬 날짜 기준 오늘.
- 거래처: `CustomerPicker`에서 선택, 코드/이름 표시 및 customer ID 보존.
- 견적번호: 선택 입력 텍스트. 견적 마스터 검색/전환은 제공하지 않는다.
- 납기일, 납품 장소, 배송 방법, 비고: nullable 입력.
- 상태: `수주등록` 기본값; 신규 입력 단계에서는 상태 전이 기능을 제공하지
  않는다.
- `use_at`은 생성 기본값 Y이며 이번 화면에서 수정하지 않는다.
- 합계 표시: 상세행 공급가, VAT, 총액을 각각 합산한다. 헤더 DB에 저장되는
  금액 필드는 total amount 하나다.

### 4.2 상세 F1-Grid

표시 컬럼: 행 번호, 품목코드, 품목명, 주문수량, 단가, 공급가, 부가세,
라인합계, 납기, 출하수량, 라인상태.

- 내부 `sales_order_detail_id`는 표시하지 않는다. 저장 전 행 식별은 임시
  문자열 키를 쓴다.
- 품목코드 `type: 'code'`와 `onOpenCodePicker`로 `MaterialPicker`를 열고,
  선택한 품목 ID/코드/이름을 `applyPatch`로 해당 행에 적용한다.
- 주문 수량, 단가, VAT는 입력 대상이다. 공급가/라인합계는 계산 값이다.
- 통화 및 수량 표시/입력은 소수점 두 자리로 제한한다.
- 신규 라인의 출하수량은 0, 라인상태는 `대기`이며 초기 등록 화면에서는
  읽기 전용이다. 상세 라인의 납기는 선택 입력이다.
- 미저장 상세행은 추가/삭제할 수 있다.

### 4.3 금액 규칙

- 공급가 = 주문 수량 × 단가, 소수 둘째 자리 반올림.
- VAT = 공급가 × 0.10, 소수 둘째 자리 반올림.
- 수량 또는 단가가 변경되면 공급가와 VAT를 다시 계산한다.
- VAT를 사용자가 직접 수정하면 해당 행 합계만 다시 계산한다. 다음 수량/
  단가 변경 시에는 VAT를 다시 10% 기본값으로 계산한다.
- 라인 합계 = 공급가 + VAT.
- 헤더의 공급가/VAT/총액 표시는 각 라인 값의 합이다.
- DB에는 세율/과세구분 필드를 추가하지 않으며 source의 금액 컬럼만 유지한다.

## 5. 오류·반응형·검증

- API 응답 형식/마스터 ID가 올바르지 않으면 오류 메시지를 보여준다.
- 마스터 검색 실패 또는 저장 API 미연결 상태에서도 사용자 입력을 보존한다.
- 검색·저장 API가 없는 상태에서 성공 토스트, 저장완료 표식, 데이터 초기화를
  수행하지 않는다.
- 375px, 768px, 1280px 실제 브라우저 폭에서 확인한다. 좁은 화면에서 페이지
  자체 수평 오버플로 대신 Grid 내부 스크롤을 사용한다.
- 테스트: 계산/반올림/재계산, 공통 picker 검색·선택·loading·empty·error 및
  stale response, 품목 행 패치, 라우트 분기, DDL 사본/제약 정적 검사.
- 기존 기준선 `dashboard-data.test.tsx`의 모듈 아이콘 테스트는 현재
  `moduleItems[0]` undefined로 실패한다. 이 수주 작업의 회귀로 취급하지 않고,
  신규 라우트 테스트는 테스트명 선택 실행으로 검증하며 기존 실패를 결과에
  별도 기록한다.
