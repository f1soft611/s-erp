## 1. 화면 구조와 필드 배치

기존 `수주 기본정보` 카드, 필드 이름, 입력 값, DOM 순서를 유지한다.

| 화면 폭 기준 | 기본정보 그리드 |
| --- | --- |
| xs, 600px 미만 | 1열 |
| sm, 600px 이상 | 2열 |
| lg, 1200px 이상 | 4열 |

lg 이상에서 첫 행은 수주번호, 수주일자, 거래처, 견적번호 순서로 배치한다.
두 번째 행은 납기일자, 납품장소, 배송방법, 수주상태 순서다. 비고는 전체
그리드 행을 사용한다. sm부터 lg 미만까지는 같은 필드 순서를 2열로 배치하며,
xs에서는 한 열로 표시한다.

## 2. 거래처 선택 버튼

- 거래처 필드 옆의 `선택` 버튼은 기존 `MasterPicker` 동작과 너비를 유지한다.
- 버튼의 높이와 최소 높이는 40px로 설정해 `size="small"` 입력 필드와 맞춘다.
- 버튼은 입력 필드 옆에 유지되며 좁은 화면에서도 페이지 가로 폭을 넘지 않는다.
- 검색 dialog, 선택 상태, 검색 결과 및 오류 표시 로직은 변경하지 않는다.

## 3. 동작 및 범위

- 수주번호, 수주일, 거래처, 견적번호, 납기일, 납품장소, 배송방법, 상태,
  비고의 입력 의미와 값은 변경하지 않는다.
- 페이지 헤더 액션, API 미연결 안내, 저장 비활성 상태, 상세 F1-Grid,
  합계 계산에는 변경이 없다.
- 다른 메뉴, API, 권한, DB, 공통 디자인 토큰은 수정하지 않는다.

## 4. 검증 기준

- `frontend/tests/master-picker.test.tsx`에서 picker 버튼 높이와 최소 높이
  40px을 확인한다.
- 기존 `sales-order-create-page.test.tsx` 및 `sales-order-scroll.test.tsx`를
  함께 실행해 입력 페이지 동작과 스크롤을 회귀 확인한다.
- `npm run build`가 성공해야 한다.
- 실제 브라우저에서 375px, 768px, 1280px을 확인한다. 각 폭에서 페이지
  가로 넘침/입력 겹침/잘림이 없어야 하며, 1280px에서는 지정된 두 행과
  전체 너비 비고 필드, 거래처 버튼의 동일 높이를 확인한다.
- 확인한 세 화면의 스크린샷과 결과 보고서를 날짜별 결과 경로에 저장한다.

## 5. Task 3 검증 실행 상태 (2026-10-26)

위 검증 기준은 유지한다. 실행 결과는 빌드 성공, 지정된 집중 테스트 9개 통과다.
실제 페이지 경로는 인증 페이지로 이동했고, 로그인 화면에서
`로그인 정보가 올바르지 않습니다.`가 표시되어 세 뷰포트 렌더링 확인 및
스크린샷 생성을 완료하지 못했다. 따라서 실제 화면 기준의 overflow, 겹침,
잘림, 1280px 필드 배치 및 버튼 높이는 확인되지 않았다. 자세한 실행 근거는
[결과 문서](../../result/20261026/sales-order-entry-layout/20261026_010_수주등록_레이아웃_개선_결과.md)를
참고한다.
