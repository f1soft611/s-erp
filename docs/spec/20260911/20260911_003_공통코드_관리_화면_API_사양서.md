## 2. 기능 개요

공통코드 관리 화면은 그룹 계층과 상세코드 체계를 기반으로, 테넌트 범위의 공통코드 데이터를 관리하는 관리 페이지이다.

핵심 동작은 다음과 같다.

- 좌측 F1Tree에서 공통코드 그룹 트리 렌더링
- 특정 그룹 선택 시 해당 그룹의 상세코드 목록 조회
- 자식 그룹의 상세코드는 해당 부모 그룹의 상세코드만 상위코드로 선택 가능
- 페이지 상단 액션은 기존 메인 관리 페이지 패턴과 동일하게 처리
- F1Tree/F1Grid의 컨텍스트 메뉴는 활성화하되, 행 추가/삭제 전용 기능은 제외

## 3. 화면 구성

### 3.1 페이지 레이아웃

```text
┌─────────────────────────────────────────────────────────────┐
│ 공통코드 관리                               조회 저장 엑셀 │
├─────────────────────────────────────────────────────────────┤
│ 검색 영역 / 필터 영역                                        │
├───────────────────────┬─────────────────────────────────────┤
│ 공통코드 그룹 트리      │ 선택 그룹 상세코드                   │
│                       │ 그룹코드 / 그룹명 / 부모그룹           │
│ ▾ 첨부문서업무          │                                     │
│   ▾ 첨부문서구분        │ 상세코드 | 상세코드명 | 상위코드명     │
│     - 거래명세서       │ STATEMENT | 거래명세서 | 거래처        │
│     - 사업자등록증     │ LICENSE   | 사업자등록증 | 품목        │
└───────────────────────┴─────────────────────────────────────┘
```

### 3.2 화면 동작

- 그룹 트리의 루트/자식 노드는 `group_code`, `group_nm`, `parent_group_id`를 기준으로 표시한다.
- 트리 노드를 선택하면 해당 그룹의 상세코드 데이터를 F1Grid로 조회한다.
- 현재 선택된 그룹이 자식 그룹이면 `parent_item_id` 선택 영역이 활성화된다.
- 자식 그룹이 아니면 상위코드 선택은 비활성화된다.
- 저장 버튼 클릭 시 그룹 생성/수정/삭제와 상세코드 변경을 일괄 반영한다.

## 4. F1Tree 및 F1Grid 사양

### 4.1 F1Tree

- 그룹 계층은 자기참조 구조인 `parent_group_id`로 표현한다.
- 루트 그룹과 자식 그룹의 관계를 계층 트리로 표시한다.
- 트리 선택 시 상세코드 조회를 수행한다.
- 우클릭 컨텍스트 메뉴는 활성화한다.
- 트리의 전용 행 추가/삭제 기능은 사용하지 않는다.

### 4.2 F1Grid

- 컬럼 구성: `commonCodeItemId`, `itemCode`, `itemNm`, `parentItemNm`, `useAt`, `sortOrder`, `itemDc`
- 기본 데이터는 선택 그룹에 속한 상세코드 기반으로 조회한다.
- F1Grid의 우클릭 컨텍스트 메뉴는 활성화한다.
- 템플릿에서 제공되는 행 추가/삭제 버튼은 구현하지 않는다.
- 행 추가/삭제 전용 컨텍스트 항목은 이 화면에서 비활성화 또는 표시하지 않는다.

### 4.3 컨텍스트 메뉴 정책

공통 코드는 다음 메뉴를 유지한다.

- 엑셀 내보내기
- 필터 초기화
- 정렬 초기화
- 레이아웃 복원

다음 기능은 제외한다.

- 행 추가 버튼
- 행 삭제 버튼
- 전용 행 추가/삭제 컨텍스트 메뉴

즉, F1Tree와 F1Grid 모두 컨텍스트 메뉴 자체는 활성화되지만, 행 추가/삭제 기능은 이 화면에서 사용하지 않는다.

## 5. API 계약

### 5.1 공통코드 그룹 API

#### GET /api/v1/system/common-code-groups

- 설명: 테넌트 기준 그룹 목록 조회
- 응답 예시:

```json
{
  "resultCode": "SUCCESS",
  "resultMessage": "조회 성공",
  "resultList": [
    {
      "commonCodeGroupId": 1,
      "tenantId": 3,
      "groupCode": "ATTACH_DOC",
      "groupNm": "첨부문서업무",
      "groupDc": "첨부문서 업종 공통코드",
      "parentGroupId": null,
      "sortOrder": 1,
      "useAt": "Y",
      "createdAt": "2026-09-11T09:00:00",
      "updatedAt": "2026-09-11T09:00:00"
    }
  ]
}
```

#### POST /api/v1/system/common-code-groups

- 요청 필드:

```json
{
  "groupCode": "ATTACH_DOC",
  "groupNm": "첨부문서업무",
  "groupDc": "첨부문서 업종",
  "parentGroupId": null,
  "sortOrder": 1,
  "useAt": "Y"
}
```

- 성공 상태: `201 Created`
- 실패 상태: `400 Bad Request`

#### PUT /api/v1/system/common-code-groups/{groupId}

- 응답 및 검증 규칙 동일
- 자기 자신을 부모로 지정하는 요청 거부
- 다른 테넌트 그룹을 상위 그룹으로 지정하는 요청 거부

#### DELETE /api/v1/system/common-code-groups/{groupId}

- 실패 조건:
  - 하위 그룹이 존재하는 경우
  - 상세코드가 사용 중인 경우
  - 참조 관계가 남아 있는 경우

### 5.2 공통코드 상세 API

#### GET /api/v1/system/common-code-groups/{groupId}/items

- 설명: 특정 그룹의 상세코드 목록 조회

```json
{
  "resultCode": "SUCCESS",
  "resultList": [
    {
      "commonCodeItemId": 101,
      "groupId": 1,
      "itemCode": "STATEMENT",
      "itemNm": "거래명세서",
      "itemDc": "거래명세서 첨부문서",
      "parentItemId": 11,
      "sortOrder": 1,
      "useAt": "Y"
    }
  ]
}
```

#### GET /api/v1/system/common-code-groups/{groupId}/parent-items

- 설명: 현재 그룹의 부모 그룹 상세코드 목록 조회
- 사용 목적: `parent_item_id` 선택 목록 제한

#### POST /api/v1/system/common-code-groups/{groupId}/items

```json
{
  "itemCode": "STATEMENT",
  "itemNm": "거래명세서",
  "itemDc": "거래명세서 첨부문서",
  "parentItemId": 11,
  "sortOrder": 1,
  "useAt": "Y"
}
```

#### PUT /api/v1/system/common-code-groups/{groupId}/items/{itemId}

- `parentItemId`는 해당 부모 그룹의 상세코드만 허용
- 다른 그룹의 상세코드를 상위코드로 지정할 수 없음

#### DELETE /api/v1/system/common-code-groups/{groupId}/items/{itemId}

- 사용 중인 코드가 다른 곳에서 참조 중이면 삭제 제한

## 6. 권한 및 예외 처리

### 6.1 권한 정책

- 공통코드 관리 화면은 기존 메뉴별 권한 체계에 따라 표시/숨김 처리
- 조회는 `READ` 권한 사용
- 저장은 `CREATE`/`UPDATE` 조합 기획에 따라 표시
- 엑셀 내보내기는 기존 `EXCEL` 권한 기준 사용

### 6.2 검증 예외

- 중복 코드: `400 Bad Request`
- 잘못된 부모 그룹/상위 상세코드 조합: `400 Bad Request`
- 자기참조/허용되지 않은 참조 조합: `400 Bad Request`
- 삭제 참조 존재: `400 Bad Request`
- 인증/권한 미보유: `403 Forbidden`

## 8. 비기능 요구사항

- 테넌트 별 데이터 분리 유지
- 부모/자식 관계는 자기참조 구조로 유지
- 저장 버튼에서 일괄 반영
- 에러 메시지는 사용자에게 이해 가능한 문구로 표시
- UX는 기존 관리 페이지와 동일한 메인 액션 배치 유지

## 9. 검증 기준

- `/co/master/cmncodes` 접속 시 인증 사용자에게 화면이 표시된다.
- 부모그룹과 자식그룹이 F1Tree에서 계층 구조로 표시된다.
- 그룹 선택 시 해당 그룹의 상세코드가 F1Grid에 렌더링된다.
- 자식 그룹 상세코드의 상위코드는 부모 그룹 상세코드만 선택 가능하다.
- 잘못된 조합은 서버에서 저장되지 않는다.
- F1Tree/F1Grid 컨텍스트 메뉴는 활성화되고, 행 추가/삭제 전용 버튼은 없다.
- 프론트엔드 빌드/테스트 및 백엔드 테스트가 통과한다.

## 10. 예외 및 범위 관리

- 그룹 깊이 무제한 그래프 UI는 구현하지 않는다.
- 다국어 코드명은 별도 작업으로 관리한다.
- 트리/그리드 우클릭 메뉴의 신규 행 추가/삭제 기능은 제외한다.
- 기존 `TB_CommonCode`는 사용하지 않는다.
