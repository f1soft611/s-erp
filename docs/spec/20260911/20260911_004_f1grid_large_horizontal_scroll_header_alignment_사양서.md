# F1-Grid 대용량 가로 스크롤 헤더 정렬 오류 상세 사양서

## 1. 목표

F1-Grid의 대용량 가로 스크롤 상태에서 헤더와 데이터 행이 서로 다른 위치를 계산해 정렬이 틀어지는 문제를 해결한다. 가로 스크롤 끝까지 이동해도 헤더와 본문 열의 시작 위치가 동일하게 유지되어야 한다.

## 2. 사용자 요구사항

### 2.1 헤더와 바디 정렬 유지

- 가로 스크롤이 생긴 상태에서 스크롤을 끝까지 이동해도 헤더와 데이터가 같은 열 기준을 따른다.
- 본문 셀 좌표와 헤더 셀 좌표가 동일한 기준으로 계산되어야 한다.

### 2.2 가상화와 pinned 컬럼 경계 보장

- 가상화된 컬럼 범위, pinned columns, protected columns가 함께 있을 때도 정렬이 유지되어야 한다.
- 보이는 영역과 스크롤 위치가 달라도 각 열의 x 좌표가 동일하게 계산되어야 한다.

### 2.3 대용량 데이터에서 안정성

- 대용량 데이터셋에서도 가로 스크롤 보정 로직이 반복 계산을 유발하지 않는다.
- 스크롤 이벤트에서 header/body 좌표 계산이 서로 엇갈리지 않아야 한다.

## 3. 화면/로직 요구사항

### 3.1 스크롤 동기화

- `bodyScrollRef`의 `scrollLeft` 값과 `headerScrollRef`의 `scrollLeft` 값은 동일 기준으로 동기화해야 한다.
- 이벤트가 서로 다른 방향으로 전달되어도 최종 값은 같은 좌표를 유지한다.

### 3.2 컬럼 렌더 기준 통일

- `renderedColumnIndexes`, `columnTracks`, `leftOffsets`, `rightOffsets`는 동일한 가로 스크롤 값과 기준 좌표를 사용해야 한다.
- `GridHeader`와 `GridBody`가 같은 열 위치를 참조하도록 정리한다.

### 3.3 경계 조건 처리

- 스크롤 끝에 도달한 상태에서도 마지막 컬럼이 잘려 보이지 않도록 보정한다.
- 가장 오른쪽 컬럼/마지막 visible 컬럼의 위치 계산을 정확히 유지한다.

## 4. 기능 동작 사양

### 4.1 기본 처리

- `scrollLeft` 값이 변경될 때마다 헤더/바디의 렌더 계산이 같은 기준을 참조한다.
- `pinned`/`hidden`/`virtualized` 상태를 포함한 정확한 시작/끝 인덱스 계산이 유지된다.

### 4.2 회귀 보호

- 기존 세로 스크롤, 셀 선택, 카드/폼 행 이동, pinned column 기능이 예외 없이 유지되어야 한다.
- 컬럼 resize와 reorder 동작에도 헤더와 바디 정렬이 유지되어야 한다.

## 5. 비기능 요구사항

### 5.1 성능

- 스크롤 이벤트 중 중복 계산을 줄이고, 불필요한 레이아웃 업데이트를 방지한다.
- 대용량 시나리오에서 스크롤 후 좌표 정합성이 계속 유지되어야 한다.

### 5.2 유지보수성

- 스크롤 관련 계산을 한 곳으로 정리해 헤더와 바디의 기준을 명확히 한다.
- 가상화/offset 계산 로직이 다른 컴포넌트와 충돌하지 않게 유지한다.

## 6. 예외 사항

- 본 작업은 F1-Grid 공용 레이아웃 버그 수정에만 한정한다.
- 다른 화면 로직이나 백엔드/DB 변경은 포함하지 않는다.
- 대규모 리팩터링을 본 작업 범위에 넣지 않는다.

## 7. 검증 기준

### 7.1 단위/통합 테스트

- `frontend/tests/f1-grid-virtualization.test.ts`가 통과한다.
- `frontend/tests/f1-grid.test.tsx`가 통과한다.

### 7.2 빌드 검증

- `cd frontend && npm run build`가 정상 종료한다.

### 7.3 브라우저 검증

- 대용량 데이터셋에서 가로 스크롤을 끝까지 이동해도 헤더와 본문 열 정렬이 유지된다.
- pinned column/hidden column 상태에서도 동일하게 동작한다.

## 8. 완료 기준

- 가로 스크롤 끝에서 헤더와 본문 컬럼이 틀어지지 않는다.
- 대용량 표에서 좌표 계산이 일관되게 유지된다.
- 회귀 테스트와 빌드 검증이 통과했다.
- 결과 문서와 검증 로그가 기록되었다.

## 9. DB 영향

- DB 스크립트: 해당 없음
- 영향 검토: 프론트엔드 공용 F1-Grid 레이아웃/스크롤 로직만 변경하며, 데이터베이스 및 API 계약은 유지한다.
