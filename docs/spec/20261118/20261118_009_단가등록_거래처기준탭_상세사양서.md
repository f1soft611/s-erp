# 20261118_009 단가등록 거래처 기준 탭 상세 사양서

기준: [작업지시서](../../directions/20261118/20261118_009_단가등록_거래처기준탭_작업지시서.md), [계획서](../../plan/20261118/20261118_009_단가등록_거래처기준탭_계획서.md), [007 사양서](20261118_007_단가등록_이력부가세외화_상세사양서.md), [008 사양서](20261118_008_단가등록_품목기준트리화면_상세사양서.md)

## 1. 화면 구성
- 탭: **품목 기준** · **거래처 기준** · **단가 이력 조회**. 거래처 기준 탭은 좌우 분할(마스터-디테일)이다. 좁은 화면(768px 미만)에서는 위아래로 쌓는다.
- 기준 화면: 같은 메뉴의 품목 기준 탭(헤더·탭·조회조건·그리드 배치)과 기준정보 거래처 관리. 좌측은 거래처 관리 화면의 목록 컬럼 구성을 따른다.

### 1.1 좌측: 거래처 목록
- 컬럼: No, 거래처코드, 거래처명, 사업자번호, 등록 건수. 읽기 전용, 행 클릭으로 선택(단일).
- 조회조건: 거래처 통합검색(코드·명·사업자번호), 단가 등록 여부(전체 / 등록 / 미등록). 세 탭의 조회조건은 통합검색 + 상세검색 "선택" 그룹(단가 상태·단가 등록 여부·거래구분·사용여부·단가 이력)으로 통일하고 적용 기준일은 화면 조건으로 두지 않는다(서버 날짜).
- "등록 건수" = 해당 거래처의 적용 중·예정 단가(사용여부 Y, 종료일 없음 또는 기준일 이후) 중 (품목, 구분) 조합 수. 기준일은 서버 오늘.

### 1.2 우측: 선택 거래처의 단가
- 거래처를 선택하면 그 거래처의 적용 중·예정 단가를 조회한다(조회조건 "이력 포함" 선택 시 과거 포함 — 과거 행은 편집 잠금).
- 한 행 = 품목 + 거래구분. 컬럼: No, 거래구분(매입/매출), 품목 선택(코드·명 선택 창), 규격·단위(읽기 전용), 원화단가*, 부가세구분, 부가세포함, 외화단가, 통화, 적용일*, 종료일(읽기 전용), 최소주문수량, 사용여부. 필수 표시(*)는 008과 같이 표시 전용 `requiredMark`를 쓰고 검증은 저장 시 변환 로직·서버가 한다.
- 맨 오른쪽 "상세" 아이콘의 행 폼에서도 입력한다. 행 추가는 행 폼 창에서 입력한다(품목 선택, 구분 선택).
- 행 잠금: 과거 행은 전부 읽기 전용, 적용 중 행은 거래구분·품목·적용일 변경 불가(적용일을 바꾸는 대신 새 행으로 등록 안내), 예정 행은 자유 편집, 신규 행은 모두 편집.
- 수량·단가 표시 자릿수는 008과 같이 단가·외화단가·최소주문수량을 2자리로 고정한다(기준정보 모듈 소수점 정책 연결 전까지).

## 2. 저장
- 변경 집합 생성 규칙은 008 사양 4절과 같고 단위만 "행(품목+구분)"이다.

| 상태 | 처리 |
| --- | --- |
| 신규 행 | `insertedRows`(거래처는 선택한 거래처 고정). 적용일 비우면 서버 오늘 |
| 적용 중 행, 값만 변경 | `updatedRows`(정정, 종료일·MOQ 유지) |
| 적용 중 행, 적용일을 더 늦게 | 새 기간 `insertedRows`(직전 행은 서버가 자동 종료) |
| 예정 행 | `updatedRows`(적용일 이동 포함) |
| 과거 행 / 적용일 앞당기기 / 단가 지우기 | 변경 불가·오류 |

- 같은 품목+구분이 한 거래처에 이미 있는데 새 행으로 같은 키를 추가하면 서버 규칙(적용일 같음 409/겹침 400)을 따른다.
- 거래처를 바꾸거나 다시 조회할 때 저장하지 않은 변경이 있으면 확인 창을 띄운다(008과 같음).

## 3. API
### 3.1 거래처 목록: `GET /api/v1/co/master/item-partner-prices/customer-overview` (조회 권한)
| 파라미터 | 설명 |
| --- | --- |
| `keyword` | 거래처코드·명·사업자번호 부분검색 |
| `registerFilter` | `ALL`(기본) / `REGISTERED` / `UNREGISTERED` |
| `effectiveOn` | 기준일(기본 서버 오늘) |

- 응답 `resultList`: `customerId`, `customerCode`, `customerName`, `businessNo`, `priceCount`. 대상은 사용 중 거래처(`use_at = 'Y'`)를 코드순으로, 최대 2,000건(초과 시 400 "검색 조건을 좁혀 주세요"). 등록 건수는 거래처별 집계 서브쿼리 1회로 구한다(거래처마다 개별 쿼리 금지). tenant 격리 필수.

### 3.2 단가 목록: `GET /api/v1/co/master/item-partner-prices` 확장
- 조건 `customerId`(양수, 선택)를 추가한다. 지정하면 그 거래처의 단가만, 기본단가(거래처 NULL)는 제외한다. 기존 `includeHistory` 등과 함께 쓴다. 응답 필드는 007과 같고 `materialSpec`을 추가한다(품목 규격 표시용).

## 4. 엑셀
- 헤더·검증·오류 코드는 007 사양의 엑셀 규칙을 그대로 쓴다(거래처코드 필수, 신규 행만, 기존 키는 `EXISTING_PRICE_KEY` 오류).
- 달라지는 점: 검증 통과 후 "그리드에 추가"가 아니라 확인 창을 거쳐 `save-batch`로 바로 저장하고 우측 목록을 다시 조회한다. 오류가 한 행이라도 있으면 전체 반영하지 않는다. 업로드한 행의 거래처가 현재 선택 거래처와 달라도 허용하며(일괄 등록), 저장 후 선택 거래처의 목록을 재조회한다.
- 양식 다운로드·업로드 버튼은 이 탭 헤더에 두고 생성 권한이 있을 때만 보인다.

## 5. 테스트
- 백엔드: 거래처 목록 등록 건수 집계(기준일 적용 중·예정만), `registerFilter` 3종, 2,000건 초과 400, 목록 API `customerId` 조건(기본단가 제외), tenant 격리, Mapper SQL(키워드·필터·limit).
- 프론트: 변경 집합 변환(신규/정정/새 기간/잠금/오류), 거래처 목록 렌더링과 선택→우측 조회 호출, 저장하지 않은 변경 확인, 엑셀 반영 확인 창 후 저장 호출, 탭 구성.
- 실서버·브라우저·스크린샷은 구현이 끝난 뒤 한 번에 수행한다.

## 6. 미결정 사항
- 엑셀 업로드 시 거래처 기준 양식을 "선택 거래처 고정(거래처코드 열 없음)"으로도 제공할지는 사용 후 의견에 따라 후속으로 정한다(이번에는 007 양식 그대로).
