## 계약

- 로그인은 `AppRouter`의 lazy 페이지다. 사용자 입력 전에 `업체코드` 등 실제 컨트롤을 비동기로 기다린다.
- 현재 로그인 브랜드는 `iPlusMES`, 제목은 `통합 MES 시스템 로그인`이다. 테스트 복구를 위해 운영 문구나 테마를 되돌리지 않는다.
- 사이드바에 그룹웨어·환경설정만 보인다는 테스트는 그 두 모듈과 자식 메뉴를 응답으로 준비한다. 기본 전역 fixture는 단일 종합현황뿐이므로 해당 전역 fixture를 확대하지 않는다.
- 프로필 테스트는 합성 사용자 응답의 이름·부서·직급·이메일과 세 가지 액션을 검증한다.
- 메뉴 페이지를 조회하려면 모듈과 역할이 모두 필요하다. 선택하지 않은 역할을 자동 선택한 것으로 가정하지 않는다.
- 최근 메뉴 영속성·5개 제한·잘못된 값 복구·로그아웃 세션 정리와 메뉴 패널의 모바일 열기/닫기 단언을 보존한다.
- 종합현황의 `지금 결재할 업무`와 `내가 확인할 문서` 영역을 구별한다. quiet 상세 액션 중 기존 영역과 상세가 유지되고 성공 후 갱신되는지 확인한다.
- 초기 연결 실패는 데이터 기반 화면 본문만 대체하며 헤더와 탐색은 유지한다. 정적·미구현 화면을 연결 실패 대상으로 포함하지 않는다.
- 로그아웃 결함: 현재 `DashboardPage.handleLogout`이 공통코드 키만 제거하여 메뉴관리 조건이 다음 로그인까지 남는다. 메뉴 세션 사양의 로그인 세션 수명과 다른 사용자 간 공유 제외 조건에 맞게 `s-erp:page:menu-management`도 제거한다.
- 운영 변경은 `DashboardPage.tsx`의 기존 키 상수 옆에 메뉴 키를 선언하고 같은 logout 처리에 제거 호출을 추가하는 범위다. 유효한 version 1 세션을 저장한 기존 통합 테스트가 먼저 실패하는지 확인한다.
- 최근 메뉴 영속성·로그인 저장·다른 페이지 상태·인증 API·권한·DB는 변경하지 않는다. 실제 브라우저 검증은 새 격리 프로필과 합성 응답만 사용한다.
