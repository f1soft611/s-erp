## 페이지 준비 계약

- 초기 필수 요청은 모듈, 활성 권한 정의, 역할 목록이다. 각 통합 테스트는 이 요청을 빠짐없이 mock한다.
- 첫 모듈은 기존 방식대로 선택할 수 있지만 저장 세션에 유효한 권한이 없으면 권한은 빈 값이다. 테스트 편의를 위해 운영 자동 권한 선택을 추가하지 않는다.
- 이미 조회된 페이지를 검증하는 경우 모듈 1·권한 문자열 `1`·빈 검색어의 version 1 세션을 명시적으로 준비하거나 실제 권한 선택을 수행한다.
- 메뉴 요청은 `/api/v1/system/menus?moduleId=1&roleId=1`처럼 선택한 권한을 포함한다.
- 권한 미선택·세션 유효성·권한 변경 테스트는 해당 조건을 유지하며 공통 fixture로 무조건 선택하지 않는다.
- 검색어 초기화 버튼은 화면 검색어와 세션 검색어를 함께 비운다. 모듈·권한 선택은 유지하고 재진입 시 초기화한 검색어가 다시 나타나지 않아야 한다. 이는 기존 세션 사양의 누락된 구현을 복구하는 변경이다.

## 그리드 검증 계약

- 신규 행은 현재 컨텍스트 메뉴 → 신규 등록 다이얼로그 → 필드 입력 → 적용 흐름을 따른다.
- 행·셀·권한의 변경과 원상 복구는 실제 그리드 값, 저장 버튼 상태 또는 저장 요청 payload로 검증한다.
- 과거 툴바 문구·컬럼 고정 인덱스·더 이상 제공하지 않는 스켈레톤 test id에만 의존하지 않는다. 다만 단언을 없애거나 항상 참인 조건으로 대체하지 않는다.
- 비동기 조회는 로딩 중 그리드 상태와 완료 후 복원을 모두 확인한다. 미완료 Promise는 테스트 종료 전에 해소한다.
- 저장 오류·자동 재조회 오류 때 로컬 변경 보존 및 중복 저장 방지 단언을 유지한다.

## 제외와 검증

- API, 권한 정책, 서버·DB, 페이지 세션 저장 형식, 그리드 운영 동작은 변경하지 않는다. 운영 코드는 위 검색어 초기화의 세션 동기화만 수정한다.
- 운영 결함이 확인되면 별도 사양 보완 후 최소 수정한다.
- 두 테스트 파일을 CI와 동일한 threads 풀·최대 워커 2로 실행한다. 기존 실패가 사라지고 기존 성공 단언이 유지되어야 한다.
- 타입 검사와 lint를 실행하고 기존 경고와 신규 오류를 구별한다.
- 테스트만 변경한 단계는 UI 스크린샷 대상이 아니며, 이를 결과에 명시한다.
