- 스크립트·롤백·변경 이력 md를 `docs/database/20261118`, `backend/DATABASE/20261118`에 두고 `db-schema.md`를 갱신한다.

## 2. 단가 조회 API 확장
`GET /api/v1/materials/purchase-request-confirms/unit-price?materialId&supplierId&baseDt` (기존)

| 필드 | 설명 |
| --- | --- |
| `unitPrice` | 원화단가(기존) |
| `currency` | 항상 `KRW`(기존) |
| `taxType` | 단가 행의 부가세구분(없으면 `TAXABLE`) |
| `vatIncludedAt` | 단가 행의 부가세포함 Y/N |
| `foreignUnitPrice`, `foreignCurrency` | 외화단가와 그 통화(없으면 null) |

- 거래처 일치 단가 → 기본단가 순으로 찾는 규칙은 그대로다. 외화단가는 참고 정보로만 내려주고 기본 설정은 원화다.
- **통화·단가 기본 설정**(확정 행·발주 헤더, 서버가 `currency`/`unitPrice`를 아래 규칙으로 내려준다):
  - 원화단가가 있으면 `currency = KRW`, `unitPrice = 원화단가`. 외화단가가 같이 있으면 `foreignUnitPrice`/`foreignCurrency`를 참고로 함께 내려주고, 사용자가 통화를 그 외화통화로 바꾸면 단가를 외화단가로 바꿔 채운다(외화통화가 아닌 다른 통화로 바꾸면 단가를 비우고 직접 입력하게 한다).
  - **원화단가가 없고 외화단가만 있으면** `currency = 외화통화`, `unitPrice = 외화단가`로 내려준다(통화를 KRW로 바꾸면 단가를 비운다).

## 3. 구매요청확정
- 저장 요청의 확정 상세에 `taxType`, `vatIncludedAt`을 추가한다. 비어 있으면 `TAXABLE`/`N`. `taxType`은 공통코드 존재 여부를 검증하고, `vatIncludedAt = Y`는 `TAXABLE`일 때만 허용(아니면 400).
- 확정 행 조회·불러오기(발주용 후보) 응답에 `taxType`, `vatIncludedAt`, `currencyCode`를 포함한다.
- 화면: 확정 그리드에 부가세구분·부가세포함·통화 컬럼을 추가한다(선택, 단가 조회 시 자동 설정, 사용자 수정 가능). 구매처 선택으로 단가를 조회하면 `unitPrice`와 함께 `taxType`, `vatIncludedAt`, `currencyCode`(KRW)를 한 번에 채운다. 과세가 아닌 구분을 고르면 부가세포함은 미포함으로 고정한다.
- 이미 입력한 값이 있는 행은 구매처를 바꿀 때만 다시 조회하고 사용자가 고친 값은 덮어쓰지 않는다(기존 단가 자동 설정 동작과 같게).

## 4. 발주
- **확정 불러오기**: 후보 응답의 `taxType`, `vatIncludedAt`, `currencyCode`로 헤더를 설정한다. 이미 담긴 품목이 있으면 세 값이 모두 같아야 담을 수 있고, 다르면 "부가세구분·부가세포함·통화가 다른 확정 품목은 한 발주서에 담을 수 없습니다"로 막는다(통화는 기존 메시지 유지). 값이 NULL인 기존 확정은 `TAXABLE`/`N`으로 본다.
- **직접등록**: 품목을 추가하고 단가를 조회할 때 담긴 품목이 없으면(첫 품목) 단가의 `taxType`, `vatIncludedAt`, `currency`로 헤더를 설정한다. 담긴 품목이 있으면 헤더 값은 그대로 두고, 새 품목의 단가 정보가 헤더와 다르면 "단가 정보(부가세구분·포함·통화)가 발주서 설정과 다릅니다. 단가를 직접 확인해 주세요."로 경고만 한다(통화가 다를 때의 기존 동작과 같음).
- 서버 저장 검증(헤더 `tax_type`, `vat_included_at`, `currency_code` 규칙)은 변경하지 않는다. 사용자가 헤더를 수정하면 수정한 값이 최종이다.

## 5. 단가등록 보강(007·008·009)
- 서버: 단가 저장·엑셀 검증에서 `vatIncludedAt = Y`는 `taxType = TAXABLE`일 때만 허용한다(아니면 400 / 엑셀 오류 `INVALID_VAT_INCLUDED_AT`).
- **원화·외화 단가 중 하나 이상 필수**: 서버 저장·엑셀 검증에서 둘 다 비어 있으면 400(`원화단가 또는 외화단가를 입력해 주세요`), 외화단가가 있으면 통화 필수(기존). 원화단가가 없으면 `unit_price`는 NULL로 저장하고, 단가 조회·목록·품목 기준·거래처 기준 응답의 `unitPrice`는 null일 수 있다. 화면의 필수 표시(*)는 원화단가·외화단가 모두에 "둘 중 하나" 안내를 두고(필수 `required`가 아닌 표시 전용), 검증은 저장 시 변환 로직과 서버가 한다. 품목 기준 탭의 "단가가 있는 칸" 판단과 단가 지우기 금지 규칙은 원화·외화가 모두 비는 경우에만 적용한다.
- **단가 조회·구매 반영**: 외화단가만 등록된 단가는 위 규칙대로 외화통화 + 외화단가가 기본으로 설정된다. 두 단가가 모두 없는 행은 저장 단계에서 거부되므로 조회 응답에 나오지 않는다.
- 화면: 단가 입력 폼·그리드에서 부가세구분을 과세 외로 바꾸면 부가세포함을 미포함으로 바꾼다(품목 기준 탭, 거래처 기준 탭, 이력 조회 외 입력 화면 공통).

## 6. 테스트
- 백엔드: 단가 조회 응답 필드(기본단가 폴백 포함, 원화단가 null 포함), 확정 저장의 부가세 검증·저장, 후보 응답 필드, 단가 저장의 과세 외 포함 거부, 원화·외화 모두 없을 때 거부와 외화단가만 저장 허용, Mapper SQL.
- 프론트: 외화단가만 있는 단가의 표시·저장(품목 기준 변경 집합, 거래처 기준, 엑셀), 확정 그리드의 단가 조회 자동 설정·통화 변경 시 외화단가 전환과 수정 유지, 발주 확정 불러오기 헤더 설정·혼합 차단, 직접등록 첫 품목 헤더 설정과 불일치 경고, 단가 입력의 과세 외 포함 고정.
- **실제 작동 확인**: 테스트 단가 데이터(매입 기본단가: 과세·포함, 영세·미포함 품목, 외화단가 품목, 특정 구매처 특별단가)를 API로 등록하고 ① 구매요청 → 확정(단가·부가세·통화 자동 설정, 저장 후 재조회) ② 확정 불러오기 → 발주(헤더 설정, 혼합 차단) ③ 직접 발주(첫 품목 헤더 설정, 불일치 경고)를 실서버·브라우저로 확인하고 결과를 기록한다.

## 7. 미결정 사항
- 외화단가 사용 방식은 사용자 확정: 원화 기본 + 통화를 외화통화로 바꾸면 외화단가로 전환한다.
