# 그리드 컨텍스트 회귀 복구 상세사양서

> 후속 정정: 이 문서의 9월 사양 기반 운영 회귀 판단은 최신 10월 공통 Tree 사양을 누락했다. [사양 010](20261118_010_tree-policy-alignment_상세사양서.md)에 따라 정렬·필터 비활성화를 유지하고 구형 테스트를 정정한다. 아래 격리 실험과 당시 보류 결과는 역사적 증거로 보존한다.

## 근거와 원인

- [계획서](../../plan/20261118/20261118_006_grid-context-recovery_계획서.md)
- [트리 필터/정렬 사양](../20260909/20260909_006_메뉴관리_트리_필터정렬_우클릭_정합_사양서.md)은 F1Tree가 두 기능을 강제로 끄지 않도록 명시한다.
- [컨텍스트 구분선 사양](../20261015/20261015_017_F1Grid_컨텍스트메뉴_구분선_상세사양서.md)은 호출자의 비활성화 정책에 따라 해제 항목을 노출한다.
- [행 삽입 사양](../20261008/20261008_004_F1GRID_행삽입_사양서.md)은 가상 신규 행의 viewport 이동·렌더링·포커스를 요구한다.
- 현재 F1Tree는 전달된 `gridProps` 뒤에 `disableSorting`/`disableFiltering`을 강제로 덮어써 승인 계약과 다르다.
- 기존 가상 삽입 테스트는 `rowHeight={32}`를 표시 배율 적용 전후 모두 32px로 가정한다. 현재 실제 기본 표시 높이는 28.8px이므로 설정한 viewport와 선택 행 위치가 다르다.

## 격리 실험과 범위 제한

- 강제 속성 두 줄 제거만으로는 안전하지 않다. 현재 F1Grid는 계층 투영 뒤 일반 query를 적용하므로 부모 Zulu/자식 Alpha를 오름차순 정렬하면 자식이 부모보다 앞선다. 격리 worktree의 임시 회귀에서 순서 역전을 확인했다.
- 따라서 위 후보는 철회하고 원본 F1Tree를 유지한다. 임시 정책 조합/계층 probe 테스트도 제거하며, 기존 정렬/필터 실패 2개는 그대로 보존한다. 이를 통과로 바꾸거나 일괄 skip하지 않는다.
- 가상 삽입 테스트는 렌더링된 행 높이 조절기의 공개 `aria-valuenow`로 실제 표시 높이를 읽어 mock scroll geometry를 일관되게 구성한다. 아래 삽입 시 스크롤 증가·신규 행 렌더링·포커스 기대는 유지한다.
- 트리 계층, 신규 행 생성, 데이터 변경 추적, API/DB와 저장 payload는 변경하지 않는다.
- 이 하위 작업의 확정 변경은 가상 viewport 테스트와 문서뿐이다. 신규 UI 스크린샷은 해당 없음이다. 향후 계층 인지 정렬/필터 구현 시 조상 보존, 펼침/접기, 형제 순서, 필터 결과의 조상 표시 정책과 실제 브라우저 검증을 별도 정의해야 한다.
