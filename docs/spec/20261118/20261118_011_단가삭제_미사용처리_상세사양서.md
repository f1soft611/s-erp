# 20261118_011 단가 삭제·미사용 처리 상세 사양서

기준: [작업지시서](../../directions/20261118/20261118_011_단가삭제_미사용처리_작업지시서.md), [계획서](../../plan/20261118/20261118_011_단가삭제_미사용처리_계획서.md), [007 사양서](20261118_007_단가등록_이력부가세외화_상세사양서.md)

## 1. 서버 삭제 규칙 (`save-batch`의 `deletedRows`)
- 요청의 `prices.deletedRows`는 `{ priceId }`(양의 정수 문자열) 목록이다. 비어 있어도 되고 중복 ID·수정 행과 겹치는 ID는 400.
- 처리 순서: **삭제 → 수정 → 신규**(한 트랜잭션, 하나라도 실패하면 전체 롤백).
- 행별 삭제 규칙(서버 날짜 기준):
  - 대상이 없거나 다른 tenant 행이면 404.
  - 종료일이 오늘 이전인 과거 행은 409 "종료된 과거 단가는 삭제할 수 없습니다."
  - 적용 중·예정 행은 물리 삭제한다.
- **직전 행 재개방**: 삭제 행과 같은 (tenant, 품목, 거래처 또는 기본, 거래구분)에서 `use_at = 'Y'`이고 종료일이 삭제 행 시작일의 전날인 행이 있으면 그 행의 종료일을 삭제 행의 종료일(없으면 NULL)로 바꾼다. 변경자·변경일시를 갱신한다.
- 응답은 기존과 같다(`prices`, `rowIdMappings`). 삭제 행은 `prices`에 포함하지 않는다.
- 기존 규칙 변경: "물리 삭제는 허용되지 않습니다" 오류(007)를 없앤다. 미사용 처리는 기존 수정 경로(`use_at`)를 쓴다.

## 2. 품목 기준 탭
- 헤더 액션 "단가 삭제"(권한: 관리자 + 삭제 권한, 저장하지 않은 변경이 있으면 비활성). 품목 행(부모)이나 특별단가 행(자식)을 선택한 상태에서 누르면 확인 창이 열린다.
- 확인 창: 대상(선택 행의 품목·거래처), **구분 선택**(매입·매출, 그 구분에 적용 중·예정 단가가 있을 때만 체크 가능, 과거만 있으면 비활성), **처리 방식**(삭제 / 미사용 처리) 라디오, 안내문.
  - 삭제: "잘못 등록한 단가를 지웁니다. 되돌릴 수 없습니다. 직전 단가의 종료일은 다시 열립니다." 
  - 미사용: "더 이상 쓰지 않는 단가로 표시합니다. 이력은 남습니다."
- 실행하면 변경 집합을 만들어 저장하고 다시 조회한다. 삭제는 `deletedRows`, 미사용은 같은 값으로 `useAt = 'N'` 수정(`updatedRows`). 화면에 보이는 기준 행(적용 중, 없으면 가장 가까운 예정 행)만 대상이다. 그 뒤의 예정 행이 있으면 다음 조회에 보인다.
- 삭제·미사용 후 부모 행의 매입·매출 칸이 비면 단가 없음으로 표시되고, 특별단가 행은 목록에서 사라진다(자식 행의 두 구분이 모두 사라지면).

## 3. 거래처 기준 탭
- 행 삭제: 그리드 컨텍스트 메뉴 "행 삭제"를 켠다(관리자 + 삭제 권한). 저장하지 않은 신규 행은 화면에서만 제거되고, 저장된 행은 `deletedRows`로 전송된다. 과거 행은 서버가 409로 거절하고 메시지를 상단에 보여 준다(화면에서도 과거 행은 삭제 메뉴를 비활성).
- 미사용 처리: 기존 "사용여부" 컬럼을 N으로 바꾼다(저장 시 수정 경로). 사용여부 N인 행은 다음 조회에서 목록에서 빠진다(조회는 사용 중만).

## 4. 테스트
- 백엔드: 과거 행 삭제 409, 적용 중·예정 삭제, 직전 행 종료일 재개방(삭제 행 종료일 승계), tenant 격리/404, 삭제 → 수정 → 신규 처리 순서와 중복 ID 400, Mapper SQL.
- 프론트: 품목 기준 삭제/미사용 변경 집합(구분 선택, 과거 제외), 거래처 기준 삭제 행 변환, 확인 창 동작.
- 실서버·브라우저: 오등록 단가 삭제 후 직전 단가 재개방, 미사용 처리 후 조회 제외, 과거 단가 삭제 거절.
