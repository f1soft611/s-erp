# 매입마감 재조회 상태 초기화 상세 사양

## 계약

- [기존 화면 사양](../20261117/20261117_007_매입마감처리_화면_상세사양서.md)의 구매처 선택/전체 행 복귀, 미마감 편집과 마감/해제 후 재조회를 유지한다.
- 기존 effect의 `[list.rows, list.suppliers]`와 동일하게 두 배열 참조 중 하나가 바뀌거나 최초 적용일 때만 편집 map·입고 행 선택·구매처 선택을 초기화하고 supplierGridKey/rowsEpoch를 한 번 증가시킨다.
- 마지막 적용 참조는 state로 추적한다. render에서 ref를 읽거나 쓰지 않는다. 같은 참조의 일반 render에는 상태를 초기화하지 않는다.
- 첫 새 결과 commit부터 초기화된 상태와 새 Grid key를 함께 게시한다. 잠깐 이전 구매처 필터나 수정값을 노출하던 타이밍만 수정한다.
- 조회 lifecycle hook·요청·취소·응답 타입·서비스·마감/해제 payload·검증·금액 계산·권한·JSX/CSS·Splitter는 그대로 둔다.

## 검증

- 기존 실제 페이지 테스트의 API 경계 mock을 사용한다. 단가 수정·구매처/입고 행 선택 뒤 검색어 입력만으로는 이를 보존한다. 새 조회 응답에 다른 구매처 이름/입고번호를 사용하고 실제 Profiler commit에서 이전 필터·선택·편집값이 없는지 확인한다.
- 수정 전 첫 새 응답 commit의 stale 상태를 RED로 확인한다. 수정 후 관련 입고 화면/현황과 매입마감 기존 전체 회귀를 확인한다.
- 브라우저는 실제 페이지·Grid·Profiler를 사용한다. GET 응답과 검색 기본값 경계만 합성하고 모든 POST/기타 transport와 영구 저장소를 차단한다. 실제 마감·해제 저장은 수행하지 않는다.
- 최소 375/768/1280px native 선택·조회, 첫 새 결과 commit·가로 넘침과 스크린샷을 확인한다.
- backend/API/DB/의존성 변경 없음. DB MCP·스키마 스크립트 대상이 아니다. 잔여 78개는 검증 전 예상이며 진단 위치 교체도 별도로 확인한다.
