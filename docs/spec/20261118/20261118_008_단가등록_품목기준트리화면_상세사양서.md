# 20261118_008 단가등록 품목 기준 트리 화면 상세 사양서

기준: [작업지시서](../../directions/20261118/20261118_008_단가등록_품목기준트리화면_작업지시서.md), [계획서](../../plan/20261118/20261118_008_단가등록_품목기준트리화면_계획서.md), [007 사양서](20261118_007_단가등록_이력부가세외화_상세사양서.md)

## 1. 화면 구성
- 메뉴(`item-partner-prices`) 안에 탭 2개: **품목 기준**(기본 탭, 입력·정정) · **단가 이력 조회**(조회 전용 평면 그리드, 종료된 과거 단가 포함). 거래처 기준 탭은 009에서 추가한다.
- **단가 이력 조회 탭은 조회 전용**이다: 입력·저장·엑셀 업로드/양식 버튼과 행 폼(상세)이 없고 헤더 필수 표시(*)도 없다. 기본은 이력 포함으로 조회하며 조회조건 "이력"에서 "현재·예정만"을 고를 수 있다. 품목·거래처는 코드·명 컬럼으로만 보여 주고(선택 컬럼 숨김) 거래처가 없는 행은 "기본단가(거래처 공통)"로 표시한다. 엑셀은 그리드 내보내기만 쓴다.
- 품목 기준 탭 조회조건: 품목 검색어(코드·명·규격), 단가 상태(전체 / 매입 미등록 / 매출 미등록 / 특별단가 있는 품목만), 적용 기준일(기본 서버 오늘).

## 2. 트리 행 모델
| 구분 | 부모 행(품목) | 자식 행(특별단가) |
| --- | --- | --- |
| 행 ID | `item-{materialId}` | `cust-{materialId}-{customerId}` |
| 상위 | 없음 | `item-{materialId}` |
| 표시 | 품목코드·명·규격·단위, 특별단가 건수("특별 N건") | 거래처코드·명 (품목 열에는 거래처명이 하위로 표시) |
| 구분별 값(매입/매출 각각) | 단가, 부가세구분, 부가세포함, 외화단가, 통화, 적용일, 단가 행 ID, 적용상태 | 동일 |
| 편집 | 품목 정보 편집 불가, 단가 칸 편집 가능 | 거래처 칸은 추가 시에만 선택, 단가 칸 편집 가능 |
| 추가/삭제 | 품목 행 추가·삭제 불가 | 부모에서 "자식 추가"(품목 고정, 거래처 선택). 삭제는 하지 않음(007 규칙: 사용여부로 비활성화) |

- 자식 행은 기본 접힘. 부모의 "특별 N건"은 해당 품목의 거래처 지정 단가 중 적용 중·예정 행이 있는 거래처 수.
- 한 구분(매입/매출)의 한 칸 묶음에는 표시 기준 행 1개가 대응한다: 기준일에 적용 중인 행, 없으면 가장 가까운 예정 행. 그 외 기간 행은 "단가 목록" 탭의 이력 포함 조회에서 본다.
- 첫 컬럼은 **No**(행 번호), 트리 열 머리글은 **품목**이다.
- 필수 표시(*): 거래처 선택(특별단가 행), 매입·매출 원화단가·적용일. 행·구분마다 조건부로 필수라 검증용 `required`가 아니라 표시 전용 `requiredMark`(공통 그리드에 추가한 옵션)를 쓴다.
- **상세 폼**: 맨 오른쪽 "상세" 아이콘으로 행 폼을 열어 품목 정보(읽기 전용), 매입 단가·매출 단가 그룹(원화단가·부가세구분·부가세포함·외화단가·통화·적용일)을 폼에서 입력한다. 특별단가 추가도 폼 창에서 입력하며, 적용하면 그리드에 반영되고 "저장"으로 최종 저장한다.
- 기본으로 보이는 컬럼: 매입단가, 매입적용일, 매출단가, 매출적용일. 부가세구분·포함·외화단가·통화는 컬럼 설정에서 표시하거나 행 폼에서 입력한다(컬럼 설정 지원 여부는 구현 단계에서 확인하고, 미지원이면 행 폼 입력으로 한정).
- 단가가 없는 칸은 빈 값. 적용일 기본값은 서버 오늘이며 수정할 수 있다.

## 3. 조회 API
`GET /api/v1/co/master/item-partner-prices/overview` (조회 권한, tenant는 인증정보)

| 파라미터 | 설명 |
| --- | --- |
| `keyword` | 품목코드·품목명·규격 부분검색 |
| `priceFilter` | `ALL`(기본) / `NO_PURCHASE` / `NO_SALES` / `HAS_SPECIAL` |
| `effectiveOn` | 기준일(YYYY-MM-DD), 기본 서버 오늘 |

- 응답: `resultList`에 부모·자식 행을 평면 목록으로 내려주고 각 행에 `parentId`를 둔다. 필드: `rowId`, `parentId`, `materialId/Code/Name/Spec/Unit`, `customerId/Code/Name`, `specialCount`, 구분별 `purchase`·`sales` 객체(`priceId`, `unitPrice`, `taxType`, `vatIncludedAt`, `foreignUnitPrice`, `currency`, `startDt`, `endDt`, `priceStatus`).
- 대상 품목: 사용 중인 품목(`delete_status='N'`, `deleted_at IS NULL`)을 코드순으로. 결과 품목이 2,000건을 넘으면 400으로 "검색 조건을 좁혀 주세요"를 반환한다.
- 기본단가 = `customer_id IS NULL` 행, 특별단가 = 거래처가 있는 행. 사용여부 `Y`만 대상. 기준 행 선택 규칙은 2절과 같다.
- 쿼리는 품목 1회 + 단가 일괄 조회 1회로 나누고 서비스에서 피벗한다(품목마다 개별 쿼리 금지).

## 4. 저장 (기존 `save-batch` 재사용)
화면이 변경된 구분·행마다 아래 규칙으로 변경 집합을 만든다. 서버 검증(겹침·자동 종료·과거 잠금·공통코드)은 007 그대로다.

| 상태 | 처리 |
| --- | --- |
| 칸에 단가 행 ID가 없고 단가 입력 | `insertedRows`: 품목, 거래처(부모는 NULL), 구분, 단가, 적용일 |
| 단가 행이 있고 적용일 그대로, 값만 변경 | `updatedRows`(정정) |
| 단가 행이 있고 적용일을 더 늦은 날짜로 변경 | `insertedRows`(새 기간). 직전 행은 서버가 자동 종료 |
| 단가 행이 과거(종료) 상태 | 편집 잠금 |
| 단가를 지움 | 지원하지 않음(비활성화는 "단가 목록" 탭의 사용여부로). 지우려는 입력은 검증 오류 |

- 한 번에 같은 구분의 정정과 신규를 같이 보내지 않는다. 필수: 원화단가 ≥ 0, 적용일, 외화단가가 있으면 통화.
- 저장 후 응답의 `prices`와 `rowIdMappings`로 트리를 다시 조회해 맞춘다.

## 5. 엑셀 (품목 기준)
- 양식 다운로드: 현재 조건의 품목 전체를 행으로, 현재 기본단가를 채워서 내려준다. 헤더: 품목코드, 품목명(참고, 업로드 시 무시), 매입단가, 매입부가세구분, 매입부가세포함, 매입외화단가, 매입통화, 매입적용일, 매출 동일 6열.
- 업로드: 품목코드 키로 읽어 미리보기·검증 후 반영한다. 빈 값은 무시, 현재 값과 같으면 무시, 다르면 4절 규칙(적용일 비우면 오늘, 적용일이 같으면 정정, 더 늦으면 새 기간)으로 변경 집합을 만든다. 오류가 한 행이라도 있으면 전체 반영하지 않는다(007 방식). 최대 1,000행, 10 MiB.
- 특별단가(거래처 지정) 엑셀 등록은 이력 조회 탭이 조회 전용이 되어 이 작업에서는 제공하지 않는다. 거래처 기준 탭(009)에서 다시 제공하는 안을 협의한다.

## 6. 테스트
- 백엔드: 부모·자식 피벗, 기준 행 선택(적용 중 우선, 없으면 예정), `priceFilter` 4종, 2,000건 초과 400, 기본단가가 없는 품목의 특별단가, tenant 격리.
- 프론트: 응답→트리 행 변환, 셀 변경→변경 집합 변환(신규/정정/새 기간/잠금), 자식 추가 시 품목 고정, 엑셀 양식 내용과 업로드 변경 집합.
- 실서버·브라우저·스크린샷은 구현이 끝난 뒤 한 번에 수행한다.

## 7. 미결정 사항
- 컬럼 설정(표시/숨김)으로 부가세·외화 컬럼을 노출하는 방식은 F1Grid 지원 여부 확인 후 확정한다.
- 거래처 기준 탭(009)과 단가 노출 권한 분리는 이번 범위가 아니다.
