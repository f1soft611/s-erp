# 20261118_004 구매자재 등록화면 상단 메시지 정리 상세 사양서

기준: [작업지시서](../../directions/20261118/20261118_004_구매자재_등록화면_메시지정리_작업지시서.md), [계획서](../../plan/20261118/20261118_004_구매자재_등록화면_메시지정리_계획서.md)

## 1. 공통 훅 `usePageMessages` (`shared/hooks/usePageMessages.ts`)
```ts
const {
  validationMessages, setValidationMessages, // 입력 검증 오류 목록(string[])
  notice, setNotice,                         // 성공 안내(string)
  warning, setWarning,                       // 저장 후 경고(string)
  error, setError,                           // 서버·처리 오류(string)
  clearMessages,                             // 위 네 종류를 모두 비운다(참조 안정)
} = usePageMessages();
```

## 2. 적용 화면
구매요청(`PurchaseRequestCreatePage`), 구매요청확정(`PurchaseRequestConfirmPage`), 발주(`PurchaseOrderCreatePage`), 가입고(`MaterialArrivalCreatePage`), 입고(`MaterialReceiptCreatePage`), 수입검사(`MaterialInspectionCreatePage`). 수정 창(발주현황·가입고현황·입고현황·검사현황)은 같은 페이지 컴포넌트를 쓰므로 함께 적용된다.

## 3. 지우는 시점 (`clearMessages()` 호출)
- 그리드 값 수정: 변경된 행이 있을 때. 변경이 없는 콜백(그리드 재구성 직후)은 검증 메시지만 지운다.
- 헤더 입력 변경: 날짜, 비고, 구분·용도·부가세·창고 선택, 구매처 선택.
- 동작 시작: 저장, 취소·삭제, 불러오기(선택기 확정), 행 추가·삭제, 신규.
- 한 동작이 오류를 만들면(예: 구매처 불일치) 먼저 `clearMessages()`로 비운 뒤 `setError(...)`로 새 메시지를 설정한다.
- 비동기 처리(`runBusy`)는 시작할 때 비우고, 결과(성공·오류)는 처리 끝에서 설정한다.

## 4. 유지되는 안내(상태에서 계산)
취소된 문서 안내, 확정과 다른 행(diff) 경고, 출력됨 경고, 가입고·입고 잠금 안내, 입력 안내(`info`)는 메시지 훅과 무관하게 현재 상태로 표시한다.

## 5. 검증 기준
- 훅: 네 종류 설정·전체 지우기, setter 참조 안정.
- 화면: 오류/성공/검증이 보이는 상태에서 값을 고치면 모두 사라지고 상태 안내는 남는다. 저장 성공 직후 성공 메시지가 유지된다. 동작이 만든 새 오류는 보인다.
- 실제 브라우저: 발주 수정 창에서 오류·경고를 만든 뒤 값을 고치면 상단이 비워지는지 확인.
