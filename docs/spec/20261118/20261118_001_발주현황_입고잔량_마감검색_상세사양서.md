# 20261118_001 발주현황 가입고수량·입고잔량 컬럼 및 입고대기마감 검색 상세 사양서

기준: [작업지시서](../../directions/20261118/20261118_001_발주현황_입고잔량_마감검색_작업지시서.md), [계획서](../../plan/20261118/20261118_001_발주현황_입고잔량_마감검색_계획서.md)

## 1. API (`GET /api/v1/materials/purchase-order-status`)
- 요청 파라미터 추가: `receiptCloseType`
  - `OPEN` 입고대기 미마감 행(`od.receipt_close_at = 'N'`), `CLOSED` 마감 행(`'Y'`), 없음 전체.
  - 그 밖의 값은 400 `검색 조건이 올바르지 않습니다.`
- 응답 행(`PurchaseOrderStatusVO`) 추가 필드
  | 필드 | 타입 | 설명 |
  | --- | --- | --- |
  | `arrivedQty` | decimal | 가입고수량. 유효 가입고 합 − 유효 수입검사 불합격 합 (가입고 없으면 0) |
  | `remainQty` | decimal | 입고잔량. `max(orderQty − arrivedQty, 0)` |

## 2. SQL (상태 mapper)
- 가입고 집계 서브쿼리를 `LEFT JOIN`으로 붙인다(발주 상세별 1행). 정의는 가입고 대상 조회의 `arrivedQtySubquery`와 같다.
- `COALESCE(a.arrived_qty, 0) AS arrivedQty`, `GREATEST(od.order_qty - COALESCE(a.arrived_qty, 0), 0) AS remainQty`
- 마감 조건은 `<if test="receiptCloseType == 'OPEN'">`, `'CLOSED'`로 `od.receipt_close_at`을 비교한다.
- 기존 정렬·상태·검색 조건·행 수는 변하지 않는다(서브쿼리는 상세 행당 1행).

## 3. 프론트
- 타입: `PurchaseOrderStatusRow`에 `arrivedQty`, `remainQty`(number), `PurchaseOrderStatusFilters`에 `receiptCloseType?`.
- 컬럼(`purchaseOrderStatusColumns.tsx`): `발주수량` 뒤에 `가입고수량`, `입고잔량`(decimal 2자리, 폭 100, 우측 정렬, 검색 숨김). 기존 `입고대기마감` 표시 컬럼은 그대로.
- 검색 전용 숨김 컬럼 `receiptCloseType`: 라벨 `입고대기마감`, 선택지 `미마감`(OPEN)/`마감`(CLOSED), 비우면 전체. 검색 영역 `span 1`, `group '선택'`, 순서는 출처 다음(7), `납기일`은 8로 이동.
- 필터 변환(`toPurchaseOrderStatusFilters`): `receiptCloseType`을 텍스트로 읽어 전달(없으면 제외).
- 그리드 `storageKey`를 `materialsPurchaseOrderStatusGrid-v2`로 올린다.

## 4. 검증 기준
- 백엔드: mapper SQL에 서브쿼리·`arrivedQty`·`remainQty`·마감 조건이 들어가고, OPEN/CLOSED/없음 각각 올바르며, 서비스가 값을 정규화·거부한다.
- 프론트: 컬럼 순서·헤더, 검색 필드 구성, 필터 변환, 기존 현황 테스트 유지.
- 실제 DB 조회로 한 발주의 가입고 전·후·불합격 후 수량이 맞는지, 마감 후 `CLOSED`로만 조회되는지 확인.
- 브라우저 1920/768/375px에서 컬럼 표시와 상세검색 배치 확인.
