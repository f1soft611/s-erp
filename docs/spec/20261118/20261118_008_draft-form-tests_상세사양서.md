# 기안양식 테스트 복구 상세사양서

- [계획서](../../plan/20261118/20261118_008_draft-form-tests_계획서.md)
- [기안양식관리 사양](../20261001/20261001_001_전자결재_기안양식관리_사양서.md)은 행 추가/복사/삭제와 삭제 행의 `useAt=N` 저장을 정의한다. [후속 사양](../20261001/20261001_003_전자결재_기안양식관리_화면보정_사양서.md)의 수정 권한과 저장 후 조용한 조회를 유지한다.
- 현재 양식명 컬럼은 `codeName`이며 header/form label은 `양식명`이다. 과거 `구분명`을 찾던 테스트만 현행 label로 맞춘다.
- 현재 관리 훅은 deletedRows를 기존 수정 API의 `useAt=N`으로 변환하지만, Grid가 행 삭제를 무조건 숨겨 해당 경로에 진입할 수 없다.
- `allowDeleteRowInContextMenu`는 `canUpdate && !saving`일 때만 활성화한다. 여기서 삭제는 사용 해제를 의미하며 별도 DELETE 권한/API나 물리 삭제를 만들지 않는다.
- 수정 권한 없음, 저장 중, 수정 가능/대기 상태의 세 조합으로 메뉴와 키보드 차단을 확인한다. 저장 중인 역할/행/검색/조용한 갱신 잠금 단언과 실패 시 보존 동작은 유지한다.
- 기존 API 요청/응답, ID·코드 타입, 백엔드·DB는 변경하지 않는다. 기존 PUT 경로를 UI에서 다시 연결할 뿐이므로 DB MCP·SQL 변경 대상이 아니다.
- 합성 데이터만 사용하는 실제 화면에서 삭제 표시 후 저장 요청의 `useAt=N`과 응답 후 상태를 검증하고 좁은 화면의 가로 넘침을 확인한다.
