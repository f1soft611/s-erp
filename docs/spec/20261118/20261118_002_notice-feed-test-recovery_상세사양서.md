## 보존할 표시 계약

- 시스템 이벤트 배지는 6px 모서리를 사용한다. 이전 8px 사양보다 2026-11-10 공통 사양을 우선한다.
- 20px 높이·0.75rem 글자·좌우 6px 라벨 padding과 상태별 색상 의미·variant를 유지한다.
- 색상은 실제 제공된 MUI 테마의 색상 계산과 일치해야 한다. 토큰 기반 표시를 다른 테마의 고정 RGB 값으로 단정하지 않는다.
- 시스템 메시지의 수정·삭제·답글 제한과 미지원 이벤트 fallback 검증을 유지한다.

## 보존할 공지 동작

- 일반 목록은 `isPinned='N'` 조건이며 고정 목록을 별도로 불러온다. mock도 해당 구분을 지킨다.
- 요약 패널·고정 목록·피드에 같은 제목이 있을 수 있다. 특정 공지의 상호작용 테스트는 해당 카드/패널을 식별하여 수행한다.
- 최초 조회 실패는 본문 오류로 표시한다. retry 중에는 오류 안내를 유지하고 재시도 버튼만 비활성화하며 성공 후 정상 화면으로 복원한다.
- 기존 성공 이후 실패는 기존 목록·댓글·입력 내용을 유지하는 경로로 검증한다.
- 댓글 편집은 명시적 소유권을 가진 fixture로 수행하고, 소유권 미확인의 댓글에 편집 권한을 가정하지 않는다.
- 새 댓글·답글의 표시와 서버 총 건수, 첨부 보상 정리, 이전 댓글 커서, 부모 관계, 실패 후 원상 보존 단언을 삭제하지 않는다.
- Promise·IntersectionObserver·시간을 통제하는 테스트는 테스트 종료 시 원복한다.

## 댓글 로컬 변경과 상세 조회 경합

- 댓글 작성·편집·삭제 또는 댓글 첨부 삭제가 시작된 뒤, 그보다 먼저 시작한 상세 조회 응답이 늦게 도착해 현재 댓글 트리나 댓글 총 건수를 이전 서버 응답으로 되돌려서는 안 된다.
- 상세 응답을 병합할 때 요청 시작 시점 이후 로컬 댓글 상태가 바뀌었는지 확인하고, 바뀌었다면 현재 댓글 트리와 댓글 수를 보존한다. 이 보호는 댓글 상태에 한정하고, 제목·본문·첨부 등 상세 조회가 갱신해야 할 다른 공지 필드는 기존 병합 동작을 유지한다.
- 회귀 검증은 삭제 API 성공 후 로컬 댓글/첨부 상태가 갱신된 것을 먼저 확인하고, 그 뒤에 요청 전 상태를 담은 상세 응답을 완료시켜 최신 UI가 유지되는지 확인한다. 서버가 이미 변경된 댓글을 반환하도록 mock을 바꾸어 로컬 상태 갱신을 대신 검증하지 않는다.
- 변경 범위는 프론트엔드 `useNoticeInteractions`의 상세 응답 병합과 해당 테스트 fixture로 한정한다. API·DB·권한 계약은 변경하지 않는다.

## 범위와 완료

- 대상은 계획서에 명시한 네 테스트 파일과, 위에서 재현된 경합을 보호하는 최소한의 `useNoticeInteractions` 변경이다. 권한 정책·API·DB를 변경하지 않는다.
- 기존 테스트를 skip하거나 단언을 없애고 성공 처리하지 않는다. 전역 시간 제한도 변경하지 않는다.
- 추가 회귀 테스트에서 상세 응답 경합이 재현되었다. 테스트 및 구현은 위 댓글 로컬 변경 보존 계약에 따라 진행한다.
- 관련 파일의 집중 검사, 타입·lint, 변경 내역 리뷰로 검증한다. 이번 변경은 상태 경합 보호로 화면 레이아웃·외형을 바꾸지 않지만, 실제 `CommunityNoticePage`를 직접 마운트한 합성 브라우저 시나리오에서 오래된 상세 응답 이후 삭제 상태를 확인하고 375/768/1280px 스크린샷과 가로 넘침 결과를 보관한다.
