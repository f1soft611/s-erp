- 현행 사용 문서의 빠른 날짜: 서버 날짜 기준으로 해당 날짜 필드만 채우며 자동 조회하지 않는다.
- 프론트엔드 내부 응답 적용 시점만 수정한다. API·DB·응답 필드·날짜 계산·권한 계약 변경은 없다.

## 원인

기존 applyQuickDate는 await 전에 생성된 updateValue closure를 호출해 당시 draft 전체를 다시 병합한다. 그 사이 수정한 다른 필드·같은 날짜·초기화 값이 이전 값으로 돌아가며, 닫힌 패널이나 unmount 뒤에도 callback이 실행될 수 있다. 이전 요청 실패도 최신 성공 이후 오류를 띄울 수 있다.

## 적용 계약

- 유효한 요청은 최신 draft와 해당 날짜 필드만 병합한다. 다른 필드의 최신 입력은 보존한다.
- 같은 날짜 필드의 직접 수정 또는 후속 빠른 요청은 앞선 요청을 무효화한다.
- 서로 다른 날짜 필드는 독립적으로 요청을 추적한다.
- 초기화, 두 닫기 경로, 조회 성공 후 닫기, 외부 값의 실질적 복원, unmount는 이전 요청을 무효화한다.
- 동일 값 controlled echo는 요청을 취소하지 않는다.
- 무효 응답은 값·오류·변경 callback에 영향을 주지 않는다. 현재 요청의 실패는 기존 오류 문구를 유지하고 브라우저 날짜로 대체하지 않는다.
- callback은 state updater 외부에서 한 번 호출한다. 공개 props, Portal backdrop과 기존 조회·초기화·닫기 callback 흐름을 보존한다.

## 검증

deferred 성공/실패, 직접 수정, 역순 요청, 초기화/닫기/복원/unmount 회귀를 먼저 실패시키고 수정 후 관련 전체 테스트를 실행한다. 실제 브라우저 375/768/1280px 합성 화면에서 지연 응답과 수동 입력을 확인하며, 인증·테넌트 자료는 사용하지 않는다.
