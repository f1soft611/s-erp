# 출하 상세 발행 제한 상세사양

기준: [계획서](../../plan/20261123/20261123_001_출하상세_발행제한_계획서.md), 사용자 승인 설계.

## 계약

- 일반 거래명세서 생성과 매출마감 요청은 최대 100개 상세 ID를 받는다. 서버는 중복 제거 전 요청 목록 길이를 검사하는 기존 동작을 유지한다.
- 기존 요청에서 상세 ID가 생략되면 서버가 해당 출하의 발행 가능한 상세를 조회한다. 이 결과에도 동일한 100건 제한이 적용된다.
- AUTO 출하 자동 발행도 같은 상한을 유지한다. 자동 발행 실패는 기존과 같이 출하 저장을 포함해 전체 롤백한다. MANUAL 출하를 이 제한만으로 거부하지 않는다.
- 제한 초과 시 서버는 기존 HTTP 400을 유지하되 사용자가 최대 100건임을 알 수 있도록 오류를 제공한다. 빈 목록·잘못된 ID 오류의 기존 의미는 유지한다.
- 일반 발행·매출마감 화면은 중복을 제거한 실제 선택 건수가 101건 이상이면 요청 전에 최대 100건임을 표시한다. 100건은 다른 유효성 검사에 통과하면 요청 가능하다.
- AUTO 출하 저장이 제한으로 실패한 경우 화면에 최대 100건과 저장 실패를 알린다. 정책이 불명확한 상태에서 모든 출하를 일괄 제한하지 않는다.
- 화면에서는 일괄 분할 처리하지 않는다. 기존 단일 트랜잭션과 API 경로·권한은 유지한다.

## 검증

- 일반 발행, 매출마감, 상세 생략 기존 API, AUTO 발행에서 100/101건 경계를 확인한다. AUTO 실패 시 저장이 완료되지 않음을 확인한다.
- 일반 발행·매출마감 화면의 101건 사전 차단 및 100건 요청, AUTO 오류 표시를 검증한다.
- 프론트 관련 테스트와 typecheck/build/lint, 백엔드 관련 테스트 및 Java 8 API 호환 컴파일을 수행한다.
- 브라우저 375/768/1280px에서 오류 표시를 확인하고 스크린샷을 결과에 보관한다. DB 변경이나 실 데이터 변경은 하지 않는다.
