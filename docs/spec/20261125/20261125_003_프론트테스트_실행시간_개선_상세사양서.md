# 프론트 테스트 실행시간 개선 상세사양서

- 계획서: [계획서](../../plan/20261125/20261125_003_프론트테스트_실행시간_개선_계획서.md)

## 파일 구조

```text
frontend/tests/document-write-page/
  documentWritePage.harness.tsx        # 공용: mock, vi.mock, 픽스처, 헬퍼, 전역 훅 (테스트 파일 패턴에 해당하지 않음)
  document-write-page.part1.test.tsx   # 분할 테스트 (원래 순서 유지)
  ...
  document-write-page.partN.test.tsx
```

- `vite.config.ts`의 `include: tests/**/*.{test,spec}.*` 패턴에 하위 폴더가 포함되므로 설정 변경은 필요 없다. harness 파일은 `.test.`가 아니어서 테스트로 수집되지 않는다.

## 공용 모듈 규칙

- 기존 1~703행을 그대로 옮기고, 테스트에서 쓰는 최상위 식별자(mock 객체, 픽스처, 헬퍼, import한 컴포넌트·훅·테스트 라이브러리 함수)를 `export`한다.
- `vi.mock`의 경로는 harness 위치 기준(`../../src/...`)으로 바꾼다. 대상 모듈과 mock 내용은 동일하다.
- 전역 `beforeEach`/`afterEach`는 harness에 두며, 각 테스트 파일이 수집 시 harness를 import할 때 해당 파일 suite에 등록된다(파일마다 모듈이 새로 평가됨).
- 유일하게 테스트 본문에서 재할당하던 `restoreImagePreloader`는 ES 모듈 바인딩을 외부에서 바꿀 수 없으므로 `setRestoreImagePreloader(fn)` 함수로 설정한다. 동작(테스트 후 복원)은 같다.

## 테스트 파일 규칙

- 첫 import는 harness이며, 그 다음에 기존 테스트 본문의 최상위 `it`/`it.each` 블록을 원래 텍스트 그대로 둔다.
- `describe('Document write page', ...)` 이름을 유지해 테스트 전체 이름이 바뀌지 않게 한다.
- 각 테스트의 개별 timeout 인자, 단언, mock 설정은 변경하지 않는다.

## 검증 기준

1. 분할 파일 전체 실행: 156건 통과, 실패·skip 0.
2. 테스트 전체 이름 목록(describe > test)이 분할 전 목록과 정확히 일치.
3. `npx tsc -p tsconfig.app.json` 범위가 tests를 포함하지 않으면 Vitest 실행으로 타입·import 오류를 확인하고, 변경 파일 린트를 실행한다.
4. 로컬 전체 `npm run test`의 벽시계 시간을 변경 전(629초)과 비교해 기록한다. 측정 시 다른 프로세스 부하가 있으면 함께 기록한다.
