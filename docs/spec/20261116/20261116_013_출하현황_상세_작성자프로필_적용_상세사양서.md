# 출하현황 상세 작성자 프로필 적용 상세사양서

## 사용자 동작

- 출하현황 목록의 출하번호를 클릭하면 기존 상세 패널을 연다.
- 상세 작성자 영역에 사용자 이름, 등록 시점의 프로필 이미지, 등록일을 표시한다.
- 프로필 이미지가 없거나 로드에 실패하면 `ProfileAvatar`의 기존 fallback을 사용한다. 사용자 이름이 없으면 기존 작성자 ID를 표시하고, 둘 다 없으면 `-`를 표시한다.
- 상세 조회 중·오류·닫기 및 수정/보기 동작은 변경하지 않는다.

## 데이터 계약

- 상세 조회 `GET /api/v1/sales/deliveries/{salesDeliveryId}` 응답은 기존 필드를 유지하고 `createdByName`, `createdByProfileImage`, `createdAt`을 추가한다.
- 작성자 이름은 `tb_user.user_nm`, 프로필 이미지는 `tb_login_account.profile_image`, 등록일은 출하 헤더의 `created_at`에서 읽는다.
- 사용자와 로그인 계정은 기존 `created_by`의 로그인 코드, `tenant_id` 조인으로 연결한다. 작성자 정보가 없을 때 출하 상세 자체는 정상 반환한다.
- 목록 API, 쓰기 요청 및 데이터베이스 스키마는 변경하지 않는다.

## 구현 및 검증 기준

- 상세 조회 SQL 회귀 테스트에서 작성자명·프로필 이미지·등록일 필드와 테넌트 범위 조인을 확인한다.
- API 테스트에서 상세 응답 필드가 직렬화되는지 확인한다.
- 프론트엔드 테스트에서 작성자 이름과 이미지 URL이 `ProfileAvatar`에 전달되고 등록일이 보이는지 확인한다.
- 관련 테스트와 빌드를 통과시키고, 실제 브라우저에서 375px·768px·1280px 크기의 상세 패널을 확인한다.
