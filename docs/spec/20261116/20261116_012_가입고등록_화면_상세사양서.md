## 2. 계산 규칙

- 잔량 = `발주수량 − SUM(arrival_qty)` (대상: 유효한 가입고 헤더(`use_at='Y'`)의 행). 가입고 행이 빠지거나 가입고가 취소되면 자동 복원된다.
- 부가세는 발주등록 사양(`20261113_001` 2절)과 같은 규칙이다. 행 단위, 반올림은 영업 `roundSalesOrderAmount`와 같은 소수 둘째 자리 HALF_UP이며 서버 `PurchaseOrderAmountCalculator`와 화면 `calculateOrderAmounts`를 재사용한다.

| 구분 | 공급가 | 세액 | 합계 |
| --- | --- | --- | --- |
| 과세 + 미포함 | 수량 × 단가 | 공급가 × 10% | 공급가 + 세액 |
| 과세 + 포함 | 수량×단가 ÷ 1.1 | (수량×단가) − 공급가 | 수량 × 단가 |
| 영세·면세 | 수량 × 단가 | 0 | 공급가 |

- 세액은 직접 수정할 수 있고 수정하면 합계를 다시 계산한다(영세·면세는 0 고정). 헤더 금액은 행 합이며 서버가 같은 규칙으로 다시 계산해 저장하고, 화면 값과 다르면 서버 값을 쓴다.
- 부가세구분·여부는 가입고 헤더에서 정한다. 발주 불러오기로 첫 행을 담을 때 그 발주서의 값을 기본값으로 채우고 수정할 수 있다(과세일 때만 포함 선택, 영세·면세는 미포함 고정).
- 수량은 소수 2자리까지, 0보다 커야 한다. 잔량을 초과해도 입력·저장할 수 있다(2026-11-17 변경).

## 3. API (`/api/v1/materials/material-arrivals`)

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/candidates` | 발주 행 후보. 조건: 발주 유효, `receipt_close_at='N'`, 잔량 > 0. 쿼리: 발주일 기간, 검색어, 구매처명 |
| POST | `/` | 가입고 저장 |
| GET | `/{materialArrivalId}` | 저장된 가입고 조회(헤더 + 행) |

### 3.1 후보 응답 행
`purchaseOrderDetailId`, `orderNo`, `orderDt`, `taxType`, `vatIncludedAt`, `supplierId/Name`, `materialId/Code/Name/Spec/Unit`, `materialTypeName`, `inspectAt`, `orderQty`, `arrivedQty`, `remainQty`, `deliveryDt`, `warehouseId/Name`, `unitPrice`, `currencyCode`, `orderTypeName`, `useTypeName`, `remark`.

### 3.2 저장 요청
```
{
  "arrivalDt", "supplierId", "taxType", "vatIncludedAt", "remark",
  "details": [{
    "purchaseOrderDetailId",
    "arrivalQty", "unitPrice", "warehouseId", "vatAmt",
    "manufactureDt", "expireDt", "remark"
  }]
}
```

### 3.3 저장 규칙
1. 인증·테넌트 확인. 행 1건 이상.
2. 대상 발주 행을 `FOR UPDATE`로 잠그고 모두 존재·발주 유효·`receipt_close_at='N'`인지 확인한다. 모든 행의 발주 구매처가 요청 `supplierId`와 같아야 하며 통화도 같아야 한다. 다르면 400.
3. 같은 발주 행 중복 거부(400).
4. 입력 검증: 수량 > 0(소수 2자리), 단가 필수(null이면 400, 0은 허용), 부가세 조합(영세·면세에서 포함 선택 거부, 영세·면세 세액은 0만 허용), 창고 필수·사용 가능(`disuse_at='N'`, `stock_io_at='Y'`), 소비기한은 제조일 이후.
5. 수량이 잔량을 초과해도 서버는 거부하지 않는다(2026-11-17 변경). 초과 확인은 화면 책임이며 별도 플래그는 없다. 수량 0 이하는 400.
6. 행의 `inspect_at`은 요청 값을 받지 않고 발주 행 값을 복사한다. 금액 재계산 후 저장, 번호 `MP-YYYYMMDD-NNNN` 발급. 하나라도 실패하면 전체 롤백.
7. 응답: 저장된 가입고(헤더 + 행).

### 3.4 발주 연동 검증 (발주 서비스 보강)
`20261113_002` 사양 2.5에서 예약한 검증을 추가한다. "가입고가 있는 행"은 유효한 가입고(`use_at='Y'`)에 연결된 발주 행이다.
- `PUT /purchase-orders/{id}`: 가입고가 있는 행을 빼는 요청은 409(`가입고가 있는 행은 삭제할 수 없습니다.`), 수량을 가입고 합계보다 작게 줄이면 409(`가입고 수량보다 작게 수정할 수 없습니다.`), 가입고가 있는 행의 `inspectAt`을 바꾸면 409(`가입고가 있는 행은 검사대상을 바꿀 수 없습니다.`).
- `POST /purchase-orders/{id}/cancel`: 발주서의 행 중 하나라도 가입고가 있으면 409(`가입고가 있는 발주는 취소할 수 없습니다.`).
- `PUT /purchase-orders/{id}/receipt-close`: 이번에는 검증을 추가하지 않는다.

## 4. 화면 (`frontend/src/pages/materials/arrival/create`)

- 구성: `MaterialArrivalCreatePage`, `components`(헤더 폼, 행 그리드, 발주 불러오기 창), `services`, `types`, `data`(컬럼), `hooks`. 라우팅은 `AppRouter.tsx`에 추가(`/materials/arrival/arrival-create`).
- 등록 화면은 신규 작성용이다. 등록 화면 안에 기존 건 조회·검색은 두지 않는다(현황 화면에서 처리).
- 헤더: 가입고번호(저장 시 MP 번호, 읽기 전용), 가입고일(기본 오늘), 구매처(발주 불러오기로 결정, 읽기 전용), 담당자(로그인 사용자 표시), 부가세구분, 부가세여부(영세·면세는 비활성), 비고, 공급가액·부가세액·합계액(읽기 전용).
- 버튼: [발주 불러오기], [선택 행 빼기], [저장], [초기화].
- 발주 불러오기 창 컬럼: 선택, 발주번호, 발주일, 구매처, 품목계정, 품목코드, 품목명, 규격, 단위, 발주수량, 기가입고, 잔량, 납기일, 입고창고, 검사대상, 비고. 상단 검색(발주일 기간, 검색어, 구매처).
  첫 체크 행의 구매처를 칩으로 고정하고 다른 구매처 행을 체크하면 자동 제외 + 안내 문구(발주등록의 확정 불러오기와 같은 방식). [선택 불러오기]로 누적 반영하며 이미 담은 발주 행은 건너뛴다. 같은 통화만 허용한다.
- 그리드 행: 품목코드, 품목명, 규격, 단위, 발주번호, 발주수량, 잔량(읽기 전용), 수량(편집, 기본값 잔량), 단가(편집, 필수, 0 허용, 기본값 발주단가), 공급가·세액·합계(계산, 세액은 수정 가능·영세/면세 잠금), 입고창고(편집), 제조일, 소비기한, 검사대상(읽기 전용 표시), LOT번호(읽기 전용, 빈값), 비고.
- 수량이 잔량을 넘는 행이 있으면 저장 시 확인창("발주 잔량을 초과한 품목이 N건 있습니다. 그대로 등록하시겠습니까?", 수정은 "수정")을 띄운다. 확인이면 저장, 취소면 화면 그대로 둔다. 단가 비어 있으면 저장 차단 안내.
- 로딩·에러·저장 중 중복 방지를 확인한다. 저장 성공 시 가입고번호 안내 후 화면을 초기화한다.

## 5. 검증 항목
- 같은 구매처 제한과 칩 초기화, 분할 가입고 후 잔량 감소·후보 제외.
- 입고대기마감 행이 후보에 나오지 않는다.
- 단가 누락·소비기한 역전·사용 불가 창고 거부, 실패 시 전체 롤백.
- 가입고가 있는 발주 행의 삭제·수량 축소·검사대상 변경, 발주 취소가 409.
- 행 빼기(저장 전).

## 6. 확정한 사항 (2026-11-16 사용자 확인)
- 부가세는 가입고 단계에서도 발주등록의 규칙을 따라 공급가·세액·합계를 함께 관리한다.
