# 20261116_013 가입고현황 화면 상세 사양서

## 1. 메뉴 (DB)

- `MATERIALS_ARRIVAL_STATUS`(가입고현황, `/materials/arrival/arrival-status`, 정렬: 가입고등록 바로 다음)를 `MATERIALS_RECEIPT`(입고관리) 그룹 아래에 등록한다.
- 메뉴 권한 READ, EXCEL. 역할 권한은 `MATERIALS_ORDER_STATUS`의 READ·EXCEL 역할 권한을 복사한다. 형식은 `20261113_005` 현황 메뉴 스크립트와 같다.
- 수정·취소 권한은 `MATERIALS_ARRIVAL_CREATE`(가입고등록)의 UPDATE 권한을 쓴다. 테이블 변경은 없다.

## 2. API

### 2.1 목록 `GET /api/v1/materials/material-arrival-status`
품목 행 단위로 펼친 가입고 목록(같은 테넌트). 정렬 `가입고일 내림차순, 가입고번호 내림차순, 행번호`.

검색 조건(모두 선택): `keyword`(가입고번호·구매처·품목코드·품목명·담당자), `arrivalNo`, `arrivalDtFrom/To`, `supplierKeyword`, `status`(`ACTIVE`/`CANCELED`, 없으면 전체), `materialKeyword`, `orderNo`.
시작일이 종료일보다 늦거나 날짜 형식이 틀리면 400.

응답 행: `materialArrivalId, materialArrivalDetailId, arrivalNo, arrivalDt, supplierName, receiverName, status, taxType, taxTypeName, vatIncludedAt, headerSupplyAmt, headerVatAmt, headerTotalAmt, headerRemark, lineNo, orderNo, materialCode, materialName, materialSpec, unit, orderQty, arrivalQty, unitPrice, supplyAmt, vatAmt, totalAmt, warehouseName, manufactureDt, expireDt, lotNo, inspectAt, remark`.

### 2.2 단건 `GET /api/v1/materials/material-arrivals/{id}` (보강)
상세 행에 `orderNo, orderQty, remainQty, orderUnitPrice, orderWarehouseId`를 추가한다. `remainQty`는 이 행을 제외한 다른 유효 가입고 수량을 뺀 발주 잔량이다(수정 화면의 수량 상한).

### 2.3 수정 `PUT /api/v1/materials/material-arrivals/{id}`
요청 본문은 등록 저장 요청을 재사용한다. 사용하는 값은 `arrivalDt, taxType, vatIncludedAt, remark`와 `details[]`뿐이며 `details[]` 각 항목은 `materialArrivalDetailId, arrivalQty, unitPrice, warehouseId, vatAmt, manufactureDt, expireDt, remark`다. 구매처·발주 행·품목은 저장된 값을 유지한다.

규칙:
1. 헤더를 `FOR UPDATE`로 잠근다. 없으면 404, 취소된 가입고면 409(`취소된 가입고는 수정할 수 없습니다.`).
2. `details[]`는 1건 이상이고 모두 이 가입고의 기존 행이며 중복이 없어야 한다. 아니면 400. 모든 행을 빼는 요청은 400(`모든 행을 뺄 수 없습니다. 가입고 취소를 사용해 주세요.`).
3. 요청에 없는 기존 행은 삭제하고, 남은 행은 기존 행번호 오름차순으로 1부터 다시 매긴다.
4. 값 검증과 금액 재계산은 등록과 같다(수량 > 0, 단가 필수·0 허용, 부가세 조합과 세액 규칙, 창고 사용 가능, 소비기한). 대상 발주 행을 `FOR UPDATE`로 잠그고 "다른 가입고 합 + 수정 수량 ≤ 발주수량"을 확인한다. 초과하면 400.
5. 헤더 금액은 남은 행 합으로 다시 계산한다. `updated_by/at`을 기록한다.
6. 수정·취소 전 잠금 검증은 하나의 메서드(`validateEditable`)로 분리한다. 후속 작업이 입고·수입검사 잠금을 여기에 추가한다. 지금은 취소 여부만 확인한다.
7. 응답은 저장된 가입고(헤더 + 행)다.

### 2.4 취소 `POST /api/v1/materials/material-arrivals/{id}/cancel`
1. 헤더를 잠근다. 없으면 404, 이미 취소면 409. `validateEditable`을 통과해야 한다.
2. 헤더를 `use_at='N'`으로 바꾼다(행은 이력으로 남긴다). 발주 잔량은 유효 가입고 합으로 계산하므로 자동 복원된다.
3. 응답은 취소된 가입고다.

### 2.5 후속 연동 (지금은 검증하지 않음)
- 무검사 행: 입고가 생기면 수정·취소 409, 수정·삭제는 입고에서만. 입고 삭제 시 가입고를 함께 취소, 입고 수정 시 가입고 수량 동기화.
- 검사 대상 행: 수입검사가 진행되면 수정·취소 409.
위 검증은 입고·수입검사 작업의 사양서에서 정의하고 `validateEditable`에 추가한다.

## 3. 화면

### 3.1 가입고현황 (`frontend/src/pages/materials/arrival/status`)
- 발주현황과 같은 구성: 빠른 검색 + 상세검색(가입고일 기간 필수·기본 최근 1개월~오늘), 같은 가입고는 헤더 열 병합, 가입고번호 링크.
- 컬럼: No, 가입고번호(링크), 가입고일, 구매처, 담당자, 상태(정상/취소), 행, 발주번호, 품목코드, 품목명, 규격, 단위, 발주수량, 가입고수량, 단가, 공급가, 세액, 합계, 입고창고, 제조일, 소비기한, 검사대상, 비고. 상세검색: 가입고번호, 구매처, 상태, 품목, 발주번호.
- 엑셀 내보내기는 EXCEL 권한이 있을 때만 보인다. 취소된 가입고도 조회된다(상태 컬럼으로 구분).

### 3.2 상세 패널
- 가입고번호, 작성자·수정 정보, 상태 칩, 요약(가입고일, 구매처, 담당자, 부가세구분, 통화, 합계액), 비고, 품목 표. 더보기 메뉴에 `자세히보기`, 수정 가능할 때 `수정`.
- 수정 가능 조건: 가입고 상태가 정상이고 가입고등록 메뉴의 UPDATE 권한이 있을 때.

### 3.3 조회/수정 다이얼로그
가입고등록 화면을 `embedded`로 띄운다(`mode='view'|'edit'`, `materialArrivalId`).
- 불러오기: 저장된 가입고를 읽어 헤더와 행(발주 대비 포함)을 채운다.
- `view`: 모든 입력 읽기 전용. `edit`: 가입고일, 부가세구분·여부, 비고, 행의 수량·단가·세액·창고·제조일·소비기한·비고, 행 빼기만 가능하다. 구매처·발주 불러오기는 숨긴다.
- 하단: 수정은 [저장], [취소(닫기)], 왼쪽에 [가입고 취소]. 저장 성공 시 상세·목록을 다시 조회한다. 가입고 취소는 확인창 후 실행하고 성공하면 다이얼로그를 닫는다.
- 변경 사항이 있는 채로 닫으면 확인창을 띄운다.

### 3.4 등록 화면과의 차이 기록
등록 화면(`create`)의 동작은 그대로다. 같은 폼·그리드·컬럼·금액 계산을 공유하며 차이는 위 3.3의 숨김·읽기 전용뿐이다.

## 4. 검증 항목
- 목록 조회와 필터, 날짜 범위 오류, 취소 건 표시.
- 수정: 값 변경 시 금액·헤더 합계 재계산, 행 삭제 후 행번호 재정렬, 모든 행 삭제 거부, 취소된 가입고 거부, 잔량 초과 허용(수정 저장 시에도 같은 확인창).
- 취소: 취소 후 발주 잔량 복원(발주 불러오기 후보에 다시 나옴), 취소 건 재취소 거부.
- 화면: 상세 패널, 조회 모드 읽기 전용, 수정 저장, 가입고 취소.
