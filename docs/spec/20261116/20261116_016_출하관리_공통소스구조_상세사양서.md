## 목표

출하관리의 영문 상위 디렉터리는 `shipment`다. 하위 세 업무는 같은 깊이에 둔다.

```text
frontend/src/pages/sales/shipment/
  delivery/       # 기존 출하 등록·현황, 내부 역할별 폴더 유지
  deliveryplan/   # 기존 출하계획 등록·현황, 내부 역할별 폴더 유지
  statement/      # 기존 거래명세서 등록·현황, 내부 역할별 폴더 유지

backend/src/main/java/egovframework/let/sales/shipment/
  delivery/       # controller, domain, service 유지
  deliveryplan/   # controller, domain, service 유지
  statement/     # controller, domain, service 유지

backend/src/main/resources/egovframework/mapper/let/sales/shipment/
  delivery/EgovSalesDelivery_SQL_postgresql.xml
  deliveryplan/EgovSalesDeliveryPlan_SQL_postgresql.xml
  statement/EgovSalesStatement_SQL_postgresql.xml
```

백엔드 테스트의 패키지 경로도 운영 코드의 `sales.shipment` 분류와 맞춘다.
수주 서비스와 테스트는 기존 위치를 유지하고 출하계획 import만 바꾼다.

## 변환 규칙

| 현재 위치 | 최종 위치 |
|---|---|
| 프론트 `sales/delivery/plan` | `sales/shipment/deliveryplan` |
| 프론트 `sales/delivery/statement` | `sales/shipment/statement` |
| 프론트 `sales/delivery`의 나머지 등록·현황 | `sales/shipment/delivery` |
| 백엔드 `sales/delivery` | `sales/shipment/delivery` |
| 백엔드 `sales/deliveryplan` | `sales/shipment/deliveryplan` |
| 백엔드 `sales/statement` | `sales/shipment/statement` |

Java의 package/import/완전한 클래스 참조와 Mapper `resultType`은 새 패키지로 변경한다.
MyBatis의 `SalesDeliveryDAO`, `SalesDeliveryPlanDAO`, `SalesStatementDAO` namespace 및 Bean 이름은 그대로다.
런타임 Mapper 검색은 기존 재귀 glob을 유지하며 새 하위 폴더도 동일하게 검색되어야 한다.

## 변경하지 않는 계약

- `/api/v1/sales/deliveries`, `/api/v1/sales/delivery-plans`, `/api/v1/sales/statements`와 하위 API.
- 메뉴 URL, page key, 화면 레이블, 권한, JSON 필드, 서비스 메서드 및 트랜잭션.
- 모든 SQL 본문과 DB 스키마·데이터·날짜별 스키마 이력.
- 견적관리 등 기존 미커밋 사용자 작업.

## DB 메타데이터 사전 확인

기본 `s-erp-postgresql-readonly`의 `list_tables` 후 다음 세 테이블에 `describe_table`을 호출했다.

- `tb_sales_delivery_hd`: 출하 식별자, 기준일, 거래처·수주 참조 및 금액 필드 확인.
- `tb_sales_delivery_plan_hd`: 계획 식별자·계획번호와 감사 필드 확인.
- `tb_sales_statement_hd`: 명세 식별자·출하 참조, 기준일, 보관된 공급자/거래처 필드 확인.

데이터 행이나 인증 정보는 조회하지 않았다. 이번 변경은 물리적 소스 위치만 바꾸므로 신규 SQL·롤백은 필요하지 않다.

## 완료 검증

1. 프론트 페이지·API·라우팅·출력 테스트와 TypeScript/Vite 빌드, 변경 영역 lint.
2. 백엔드 출하·출하계획·거래명세서 Controller/Service/Mapper 테스트와 수주 자동계획 연계 서비스 테스트.
3. Java 8 `--release 8` API 호환 컴파일 적용 여부 확인.
4. 이전 package/모듈/Mapper 경로가 활성 소스에 남지 않으며 SQL·API 경로가 보존됨을 확인.
5. 합성 API만 사용하는 실제 브라우저에서 375/768/1280px 흐름과 오류를 확인하고 스크린샷 저장.
6. 사용자 소유 기존 서버를 종료하거나 업무 데이터에 쓰기 요청을 보내지 않음.
7. 루트·프론트·백엔드 `AGENTS.md`에 공통 분류와 영역별 책임 분리 규칙, 고정된 출하 경로 및 참조 동시 갱신 기준이 기록되어 있음.
