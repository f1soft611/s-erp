# 모듈별 공통코드 Seed 상세사양서

근거: [계획서](../../plan/20261116/20261116_018_page-common-codes_계획서.md), [작업지시서](../../directions/20261116/20261116_018_page-common-codes_작업지시서.md)

## 1. 선택한 접근

1. 모든 select를 공통코드화: 검색 전용 값·상태 전이·마스터 ID까지 혼합되므로 채택하지 않는다.
2. 업무 구분값 선별 Seed + 보류 목록: **채택**. 값과 표시명을 유지하고 화면 연결은 별도 작업으로 남긴다.
3. 화면을 API 공통코드 조회로 일괄 변경: 이번 요청의 조사·Seed 범위를 넘어 제외한다.

## 2. 등록 계약

| 적용 | 그룹 코드 / 이름 | 상세코드 = 현재 값 → 표시명 (정렬순서) |
| --- | --- | --- |
| 기본 | `ITEM_PARTNER_TRADE_TYPE` / 품목 거래처 단가 거래구분 | `매입` → 매입 (10), `매출` → 매출 (20) |
| 기본 | `SALES_DELIVERY_TYPE` / 출하구분 | `DIRECT` → 직출하 (10), `ORDER` → 수주출하 (20) |
| 선택 | `WORK_STANDARD_VERSION_STATUS` / 작업표준서 버전 상태 | `양산` → 양산 (10), `샘플` → 샘플 (20), `폐기` → 폐기 (30) |
| 선택 | `WORK_STANDARD_SHELF_LIFE_BASE` / 작업표준서 소비기한 기준 | `반제품 생산완료일` → 반제품 생산완료일 (10), `제품 생산완료일` → 제품 생산완료일 (20) |

- 그룹 순서: 위 순서대로 200, 210, 220, 230. 부모 그룹·상세는 NULL, `use_at=Y`.
- 기본 2그룹 4항목, 선택 2그룹 5항목. 선택 Seed는 기본 Seed를 실행해도 자동으로 실행되지 않는다.
- 거래구분·출하구분은 서버 허용값/분기와 연결된 **고정 도메인 목록**이다. 공통코드 등록은 임의 값 추가를 허용한다는 의미가 아니다.
- 선택 후보는 작업표준서 문서에 정의되어 있으나 저장 API가 없으므로 운영 데이터 계약으로 확정한 것으로 간주하지 않는다.
- 품목계정/생산단위는 `ITEM_TYPE`/`ITEM_UNIT` 재사용 검토, 제품분류/공정은 분류·공정 마스터 사용을 우선한다.
- 창고 `plantId`의 0/1은 numeric ID와 구분값 의미가 혼재되어 보류한다.

## 3. DB 안전성

- 기본 서버 MCP `list_tables` → 그룹/상세 `describe_table` → 문자열 길이 및 후보 그룹 존재 여부만 조회한다.
- 연결된 DB에서 기존 그룹 14종의 존재와 신규 후보 6종의 부재를 확인했다. 이는 특정 대상 테넌트의 항목 충족 여부를 보증하지 않는다. 테넌트 행은 조회/기록하지 않는다.
- 현행 PK 기본 시퀀스 및 `tenant_id`, `group_code`, `group_id`, `item_code`, 설명·정렬·감사 컬럼을 사용한다.
- `psql -v target_tenant_id=<대상ID> -f <스크립트>`로 명시적 한 테넌트만 처리한다. 실 ID를 파일에 하드코딩하지 않는다.
- SQL에서 변수 값을 임시 컨텍스트에 보관하고 DO 블록으로 테넌트 존재를 확인한다. 미지정 변수는 psql 오류, 없는 테넌트는 예외로 실패한다.
- 그룹 `(tenant_id, group_code)`, 상세 `(group_id, item_code)` 충돌 시 **아무것도 덮어쓰지 않는다**.
- 기존 비활성/부모 그룹에 상세를 임의 추가하지 않는다. 같은 코드 그룹의 구조·활성이 부적합하면 전체 트랜잭션을 실패시킨다.
- 그룹 설명 및 항목 설명에 작업 표식을 남긴다. 롤백은 표식뿐 아니라 원본 이름·순서·활성·부모·감사 변경 여부가 동일한 행만 대상으로 한다.
- 롤백 시 다른 상세의 부모로 참조되는 항목, 자식 그룹이 있는 그룹, 남은 항목이 있는 그룹은 보존한다. 다른 FK 참조가 있다면 DB 제약으로 트랜잭션을 실패시켜 안전하게 중단한다.
- 문자열 코드로 사용한 업무 데이터 참조는 FK로 탐지할 수 없다. **화면 연결/업무 사용 전 복구용 롤백**이며, 사용 후에는 영향 분석 없이 실행하지 않는다.
- DDL·계정·테넌트 데이터 변경은 없다. 운영 DB에는 실행하지 않는다.

## 4. 검증

- 전용 `test_page_common_codes` DB만 허용하는 psql 검증 SQL을 제공한다.
- 합성 테넌트로 기본/선택 항목 수와 값·라벨·순서, 재실행, 다른 테넌트 불변, 기존 이름·비활성 보존, 없는 대상 거부, 수정/참조 행 보존 및 삭제 후 재실행을 확인한다.
- 로컬 PostgreSQL 임시 클러스터를 사용한다. 테스트용 테이블은 원본 공통코드 DDL을 사용하고 연결정보는 저장소에서 읽지 않는다.
- 프론트/Java 소스와 UI를 변경하지 않으므로 빌드·브라우저 스크린샷 대신 SQL 검증을 수행한다.
