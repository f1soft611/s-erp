## 2. 기능 개요

공통코드 관리 페이지는 좌측 트리와 우측 상세 그리드가 연결된 관리 화면이다. 점검 대상은 조회, 저장, 루트 추가, 행 추가, 행 삭제의 정상 동작 여부이며, 이들 기능이 비정상일 경우 최소 수정으로 문제를 해결한다.

## 3. 사용자 시나리오

### 3.1 조회

- 페이지 진입 시 그룹 목록을 조회한다.
- 기본 선택 그룹이 있으면 해당 그룹의 상세코드 목록을 조회한다.
- 그룹 선택 변경 시 상세 목록이 재조회되고 화면이 갱신된다.
- 결과는 사용자에게 바로 확인 가능한 상태로 최소 로딩/에러 처리를 제공한다.

### 3.2 저장

- 사용자가 데이터 변경을 수행하면 dirty 상태가 반영된다.
- 저장 버튼 클릭 시 변경사항을 서버에 전송한다.
- 성공 시 데이터 재조회 및 상태 초기화를 수행한다.
- 실패 시 사용자에게 에러 메시지를 보여주고 변경 내용은 유지하거나 적절히 복구한다.

### 3.3 루트 추가

- 사용자가 루트 추가 액션을 선택하면 새 그룹이 생성된다.
- 생성된 그룹은 트리에 표시되고, 적절한 선택 상태로 유지되며 저장 가능한 상태가 된다.
- 생성 후 재조회 여부와 dirty 상태가 정상 동작해야 한다.

### 3.4 행 추가

- 선택된 그룹에 행 추가를 수행하면 새 상세코드 행이 추가된다.
- 추가 행은 그리드에 표시되고 저장 대상으로 포함된다.
- 해당 동작이 실패하거나 선택 그룹과 연결이 깨지지 않아야 한다.

### 3.5 행 삭제

- 선택된 상세코드 행을 삭제하면 해당 항목이 그리드에서 제거된다.
- 삭제된 항목은 저장 대상 목록에서 제외되거나 삭제 플래그로 관리된다.
- 저장 후 실제 서버 호출과 재조회가 정상 진행되어야 한다.

## 4. 검증 기준

- 조회는 기본 로딩 이후 선택 그룹과 상세 목록이 매칭되어야 한다.
- 저장은 변경된 그룹/상세코드 모두 반영되어야 한다.
- 루트 추가와 행 추가는 새 row가 화면에 즉시 반영되어야 한다.
- 행 삭제는 선택된 row가 제거되고 dirty 상태가 갱신되어야 한다.
- UI와 데이터 흐름이 어긋나는 경우, 원인을 확인하고 최소 수정으로 해결해야 한다.

## 5. 수정 원칙

- 수정 범위는 페이지와 서비스 로직 중심으로 제한한다.
- F1Tree/F1Grid 이벤트 흐름을 우선 점검하고, 필요 시 공용 컴포넌트 수준으로 범위를 넓히되 최소화한다.
- 기능 건수별로 재현 조건을 남기고 검증한다.
