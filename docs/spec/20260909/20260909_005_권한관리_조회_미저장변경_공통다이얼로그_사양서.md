# 모듈관리·권한관리 조회 미저장 변경 공통 다이얼로그 사양서

## 적용 대상

- 페이지: `frontend/src/pages/settings/system/modules/ModuleManagementPage.tsx`, `frontend/src/pages/settings/system/roles/RoleManagementPage.tsx`
- 공통 컴포넌트: `frontend/src/shared/components/UnsavedChangesConfirmDialog.tsx`
- 검증: `frontend/tests/role-management-notification.test.tsx`

## 동작 계약

1. 모듈관리 또는 권한관리 그리드가 변경되어 `panelDirty`가 `true`이면, 조회 버튼은 대상 목록 API를 즉시 호출하지 않는다.
2. 페이지는 기존 공통 `UnsavedChangesConfirmDialog`를 열고 아래 값을 전달한다.
   - 제목: `저장하지 않은 변경사항`
   - 설명: 모듈관리는 `변경사항을 버리고 모듈 목록을 다시 불러오시겠습니까?`, 권한관리는 `변경사항을 버리고 권한 목록을 다시 불러오시겠습니까?`
   - 취소 버튼: `취소`
   - 계속 버튼: `계속`
3. 취소하면 다이얼로그만 닫고, 역할 목록·사용자 매핑·그리드 변경 상태를 유지한다.
4. 계속하면 다이얼로그를 닫은 뒤 기존 조회와 동일하게 각 페이지의 목록 조회 함수를 호출한다. 새 목록이 반영되면 기존 패널 입력과 그리드 키 갱신 흐름으로 변경 상태가 초기화된다.
5. `panelDirty`가 `false`이면 조회 버튼은 확인 없이 기존 조회를 즉시 실행한다.

## 상태 및 책임

- `ModuleManagementPanel`과 `RoleManagementPanel`은 기존처럼 편집 결과를 `onDirtyChange`로 상위에 알린다.
- `ModuleManagementPage`와 `RoleManagementPage`는 `panelDirty`를 기준으로 조회를 보류하고, 공통 다이얼로그의 열림 상태를 소유한다.
- `UnsavedChangesConfirmDialog` 구현과 public props는 변경하지 않는다.

## 예외 및 비범위

- 저장 중 동작, 역할 행 전환 시 사용자 매핑 확인, 메뉴관리 조회 확인 흐름은 변경하지 않는다.
- API endpoint, 요청/응답 데이터, 서버 로직, DB 스키마 변경은 없다.

## 검증 기준

1. 두 페이지의 더티 상태 조회 클릭에서 공통 다이얼로그가 렌더링된다.
2. 취소 후 대상 목록 API 재호출이 발생하지 않고 편집 내용이 남는다.
3. 계속 후 대상 목록 API가 재호출되고 최신 목록이 표시된다.
4. 두 페이지에서 더티 상태가 아닌 조회는 즉시 재조회된다.
5. 관련 Vitest와 `npm run build`가 통과한다.
