## 2. API: `GET /api/v1/sales/statements/source-deliveries`

| 파라미터 | 필수 | 규칙 |
| --- | --- | --- |
| `keyword` | 아니오 | 기존 통합검색 |
| `deliveryDtFrom`, `deliveryDtTo` | 아니오(둘 중 하나라도 있으면 둘 다 `YYYY-MM-DD`) | 형식 오류 400 `출하일을 확인해 주세요.`, 시작 > 종료 400 `출하일 기간을 확인해 주세요.` |
| `deliveryType` | 아니오 | `DIRECT`/`ORDER` 외 400 `출하구분을 확인해 주세요.` |
| `customerKeyword` | 아니오 | 거래처 코드·이름 부분 일치(ILIKE) |
| `materialKeyword` | 아니오 | 출하 상세 품목 코드·이름 부분 일치. `EXISTS`로 처리해 결과 행의 `salesDeliveryDetailIds`는 줄지 않음 |
| `deliveryNo` | 아니오 | 출하번호 부분 일치 |

- 프론트는 값이 빈 파라미터를 보내지 않는다. 파라미터가 없으면 기존 동작과 같다.
- 응답: `{ items: StatementSource[] }`(`salesDeliveryId, customerId, deliveryNo, deliveryDt, deliveryType, customerName, totalAmt, salesDeliveryDetailIds`). 변경 없음.
- DB 스키마 변경 없음.

## 3. 화면: 거래명세서현황

- 그리드 맨 앞에 `No`(rownumber) 컬럼(출하현황과 같은 설정).
