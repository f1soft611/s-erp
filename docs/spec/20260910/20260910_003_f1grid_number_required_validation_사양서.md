## 1. 기능 개요

이 기능은 F1-Grid의 공용 그리드 편집기와 폼 모달을 개선해, 숫자 컬럼의 소수점 입력을 명시적으로 제어하고 `required` 컬럼의 누락을 조기에 식별하도록 한다. 저장과 폼 모달 적용 흐름 모두에서 동일한 규칙이 적용되어야 하며, 누락된 필드는 자동으로 선택 포커스와 오류 강조를 통해 수정 가능해야 한다.

## 2. 숫자 컬럼 규칙

### 2.1 소수점 제한 규칙

- `column.type === 'number'` 또는 `column.type === 'decimal'`인 경우, `decimalPlaces` 값이 `0`이면 소수점 입력을 허용하지 않는다.
- `decimalPlaces` 값이 `1` 이상이면 입력값은 해당 자리수까지만 허용한다.
- 사용자가 소수점을 입력하거나 허용 범위를 초과하는 값을 입력하면, 입력값이 자동으로 정규화되거나 차단되어야 한다.
- 셀 편집, 폼 모달 입력, 저장 전 검증 경로는 같은 제한 규칙을 사용한다.

### 2.2 입력값 처리

- 빈 값은 빈 문자열로 유지한다.
- 유효한 숫자 값은 숫자 타입으로 최종 반영한다.
- `decimalPlaces` 제한은 `NumberEditor`와 `GridFormField`의 입력 변환 로직에서 공통으로 처리한다.

## 3. 폼 모달 기본 필드 세팅 규칙

- 폼 모달의 기본 필드 목록은 `editable: true` 인 컬럼만 포함한다.
- `editable: false` 또는 조건부 `editable` 함수가 false를 반환하는 컬럼은 기본 설정에서 제외한다.
- `hidden` 또는 `form.hidden`으로 숨김 처리된 컬럼은 기본 필드에서 제외한다.
- 다만 사용자가 플러그인 또는 화면 코드에서 명시적으로 추가한 필드는 별도 로직으로 유지할 수 있다.

## 4. 필수값 검증 및 UX

### 4.1 저장 시 검증

- `column.required === true`인 컬럼의 값이 비어 있으면 저장이 차단된다.
- 저장 시 누락된 첫 번째 필드가 자동으로 선택되고 포커스가 이동한다.
- 해당 셀 또는 입력 필드는 오류 강조 스타일을 사용해 시각적으로 식별 가능해야 한다.
- `validateGridRow`는 `required` 누락을 기준으로 에러 객체를 생성한다.

### 4.2 폼 모달 적용 시 검증

- 폼 모달에서 `적용` 버튼을 누르면 포함된 필드들을 대상으로 필수 검증을 수행한다.
- 누락값이 발견되면 모달이 닫히지 않고, 해당 입력 필드에 에러 메시지와 포커스를 보인다.
- `required` 상태는 라벨에 표시되어야 하며, 색상만으로 의미를 전달하지 않아야 한다.

## 5. 인터랙션 사양

### 5.1 셀 편집

- `NumberEditor`는 브라우저/DOM 입력 기본 동작과 충돌하지 않도록 충분히 정규화된 입력 값을 전달해야 한다.
- `selectOnFocus` 동작과 숫자 입력 제한 로직은 별도로 깨지지 않아야 한다.
- 사용자가 해당 셀을 다시 편집할 때 기존 값이 올바르게 유지되어야 한다.

### 5.2 폼모달

- `F1GridFormModal`은 `validateGridRow` 결과를 기반으로 `focusRequest`를 설정한다.
- 오류가 있는 필드는 `fieldRefs`를 통해 즉시 포커스되며, 최상위 에러 객체는 생성/수정 모달에서 공유된다.
- `onDraftChange`는 값 수정 시점에만 반영되며, 필수 오류 초기화와 함께 일관되게 처리한다.
