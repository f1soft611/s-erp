## 1. 기능 개요

본 기능은 F1-Grid가 대용량 데이터셋을 처리할 때 기대하는 동작 범위와 문서화 기준을 정의한다. 핵심 목표는 50,000건과 100,000건의 샘플 데이터를 생성하고, 문서 포털에서 해당 데이터에 대한 동작 시나리오, 성능/UX 요구사항, 안정성 기준을 명확히 공유하는 것이다.

대용량 데이터 처리는 단순히 더 많은 행을 무작정 렌더링하는 것이 아니라, 정렬/필터/selection/편집/dirty 상태를 포함한 기존 Grid UX가 큰 데이터셋에서도 유지되는지 검증하는 기준으로 정의한다.

## 2. 대용량 데이터 처리 요구사항

### 2.1 데이터 볼륨 기준

- 기본 샘플은 50,000건 데이터셋으로 정의한다.
- 확장 샘플은 100,000건 데이터셋으로 정의한다.
- 각 행은 고유 식별자, 코드, 이름, 상태, 금액, 담당자, 일자, 그룹 정보 등을 포함한다.
- 샘플 값은 반복 실행 가능하고, 정렬/필터/검색 시나리오를 재현할 수 있어야 한다.

### 2.2 동작 기준

- 데이터가 많아져도 기본 스크롤, 키보드 이동, 체크박스 선택, 행 하이라이트 동작은 유지되어야 한다.
- 정렬/필터/selection 상태는 보이는 행 기준에서 일관되게 동작해야 한다.
- 편집 중 dirty 상태, 행 추가/삭제, 저장 전 체크가 대용량 데이터셋에서도 동일한 로직을 따라야 한다.
- 사용자에게 “대용량”은 별도 화면이 아니라 기존 F1-Grid 사용 방식의 확장으로 인지되어야 한다.

### 2.3 성능/안정성 가이드

- 렌더링 성능은 대용량 데이터셋에서도 버벅임 없이 스크롤 및 포커스 이동이 가능해야 한다.
- 메모리 사용량과 연산량이 비정상적으로 증가하지 않도록, 생성 범위와 샘플 구조를 제한한다.
- 큰 데이터셋은 로컬 예시 문서와 테스트에서 반복 가능한 데이터 생성 전략을 사용해야 한다.

## 3. 샘플 데이터 구조

### 3.1 공통 필드

- `id`: 고유 행 식별자
- `rowNo`: 순번
- `itemCode`: 품목 코드
- `itemName`: 품목명
- `supplierName`: 거래처명
- `departmentName`: 부서명
- `status`: 상태값
- `amount`: 금액
- `managerId`: 담당자 ID
- `managerName`: 담당자명
- `createdAt`: 생성일
- `updatedAt`: 수정일
- `isActive`: 활성 여부
- `category`: 카테고리

### 3.2 생성 규칙

- `id`는 오름차순 정렬이 가능하도록 연속값으로 생성한다.
- 문자열 값은 규칙적이고 반복 가능한 패턴을 사용해 정렬/필터를 검증할 수 있는 형태로 만든다.
- 금액/일자/상태 값은 실제 ERP 업무와 유사하도록 구성한다.
- 중복값을 일부 포함해 필터와 정렬 시나리오를 재현할 수 있게 만든다.

## 4. 문서 포털 요구사항

### 4.1 문서 업데이트 대상

- `frontend/src/pages/f1-grid-docs/F1-GRID.md`
- 필요 시 관련 문서/예시 섹션 또는 결과 문서

### 4.2 문서에 포함해야 할 항목

- 대용량 데이터의 정의와 작업 시나리오
- 50k/100k 샘플 데이터 구조 설명
- 기대 동작: 스크롤, 정렬, 필터, 키보드 이동, 선택, 편집
- 주의사항: 렌더링 비용, 메모리, dirty 상태 유지
- 회귀 검증 방법과 체크리스트

### 4.3 문서 스타일 가이드

- 구현/운영자가 바로 이해할 수 있도록 표준 용어와 예시값을 사용한다.
- 코드 예시는 짧고 재현 가능해야 한다.
- “작동하는 기준”과 “주의해야 할 범위”를 구분해 설명한다.

## 5. 사용자 경험 기대사항

- 사용자는 대용량 데이터셋에서도 기존 F1-Grid와 동일한 인지 모델을 유지해야 한다.
- 체크박스 선택, 정렬, 필터, 스크롤, row focus, dirty 마크는 기존 동작과 동일하게 작동해야 한다.
- 대용량 데이터는 기존 화면을 확장하는 방식으로 동작해야 하며, 별도 학습이 필요하지 않아야 한다.

## 6. 구현 제약

- 백엔드 DB 변경은 없다.
- 외부 Grid 라이브러리 도입은 없다.
- 본 작업은 문서/샘플 데이터/검증 시나리오와 필요한 공용 로직 보완에 한정한다.
- 대용량 처리와 무관한 화면/기능 변경은 포함하지 않는다.

## 7. 검증 기준

### 7.1 문서와 샘플 데이터 검증

- 50k/100k 샘플 데이터가 문서에 명시된 구조와 일치하는지 확인한다.
- 샘플이 정렬/필터/selection 동작을 재현할 수 있는지 검증한다.

### 7.2 전반적 동작 검증

- 기본 데이터셋과 대용량 데이터셋 간 핵심 UX가 동일하게 유지된다.
- dirty 상태, 체크박스, 정렬, 필터, 스크롤 동작이 대용량 케이스에서도 유지된다.
- 문서와 실제 기능 동작이 충돌하지 않는다.

## 8. 완료 기준

- 50,000건/100,000건 샘플 데이터 구조가 정의된다.
- 대용량 데이터 처리 요구사항과 기대 동작이 문서화된다.
- F1-Grid 문서 포털에 대용량 처리 가이드가 반영된다.
- 구현 단계에서 바로 확인할 수 있는 검증 기준이 준비된다.
