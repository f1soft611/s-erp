## 칸반 컬럼이 많을 때

- 넓은 화면: 보드 안에서만 가로 스크롤한다(페이지는 스크롤되지 않음). 컬럼 폭은 250px 고정, 컬럼이 한 칸씩 맞게 멈추는 스크롤 스냅(`x proximity`), 더 볼 내용이 있는 쪽 가장자리를 28px 흐리게 표시한다. 보드 높이는 `100vh - 260px`로 제한해 세로 스크롤은 컬럼 안에서 하므로 컬럼 제목 줄이 항상 보인다.
- 카드를 끌 때 포인터가 보드 좌우 가장자리 56px 안으로 들어오면 가까울수록 빠르게(최대 28px) 보드를 스크롤한다. 브라우저 기본 자동 스크롤에 기대지 않고 직접 처리한다.
- 좁은 화면(600px 미만): 가로 스크롤 대신 `요청 1 | 진행중 2 | 완료 1` 같은 컬럼 탭으로 한 컬럼씩 본다. 숨긴 컬럼은 탭에 나오지 않고, 카드 이동 메뉴는 그대로 쓴다.
- 레이아웃 폭: 좌측은 칸반 4컬럼이 들어가는 폭(250px×4 + 간격 12px×3 = 1036px)까지만 쓰고, 남는 폭은 우측 패널이 가져간다(최소 320px). 공통 `ContentSplitLayout`의 선택 옵션(`leftMaxWidth`, `rightMinWidth`)이며 기본 비율은 그대로다. 1920px 화면에서는 좌 1036px·우 약 436px, 1280px에서는 우측이 최소 폭 320px이다.
- 가로 스크롤바 위치: 보드가 남은 높이를 채워(좌우로 나뉘는 900px 이상에서만) 컬럼이 아래까지 늘어나고, 스크롤바는 보드 하단이자 화면 아래에 놓인다. 컬럼이 4개 이하이면 스크롤바가 생기지 않는다. 한 열로 쌓이는 폭에서는 채우지 않는다.

## 반응 줄·구분선·댓글 (공통 `FeedEngagementSection`)

문서관리·공지사항·협업공간의 피드 카드 아래쪽은 같은 공통 컴포넌트 `FeedEngagementSection`(반응 줄 → 구분선 → 댓글)으로 그린다. 구분선이 번지는 폭은 `bleed`로 컨테이너 안쪽 여백에 맞춘다: 피드 카드(`FeedCard`)는 기본값(xs 1.5 / sm 2.5), 문서 상세 패널의 카드(안쪽 여백 xs 1.5 / sm 2)는 `{ xs: 1.5, sm: 2 }`. 공통 댓글의 기본 위 여백·구분선은 `commentListSx={FEED_COMMENT_LIST_SX}`로 없앤다. 아래는 협업공간 기준 상세 값이다.

- 첨부와 반응 줄(좋아요·북마크·댓글 수) 사이에는 구분선을 두지 않는다.
- 반응 줄 바로 아래에 구분선 하나를 두며, 카드 안쪽 여백만큼 음수 여백을 줘 카드 좌우 끝까지 닿게 한다. 간격은 위아래를 맞춘다: 첨부 → 반응 줄 8px, 반응 줄 → 구분선 8px, 구분선 → 첫 댓글 아바타 12px(반응 줄 글자 기준 위쪽 간격 8+4px와 같게). 브라우저에서 이 값을 측정해 확인한다.
- 공통 댓글(`CommentThread`)의 기본 위 여백·구분선·안쪽 여백은 선택 옵션 `commentListSx`로 덮어써 없앤다(이전 댓글 보기 유무와 관계없다). 기본 모양은 다른 화면에서 그대로다.
- `Stack`의 `spacing`은 자식 margin을 덮어쓰므로 이 영역은 `useFlexGap`(gap)을 쓴다.

## 컬럼 색상

- 방 설정: 컬럼 행마다 색상 버튼. 색은 `#rrggbb` 형식만 허용하며 서비스가 검증한다(`컬럼 색상 형식이 올바르지 않습니다.`). 색이 없으면 기본 모양이다. 관리자만 바꿀 수 있고 방 전체에 적용된다.
- 컬럼 설정(사용자별): 컬럼마다 색상 버튼. 개인 색이 방 색보다 우선하고, `방 기본 색상 사용`으로 되돌린다. 사용자별 설정(`columnColors`)에 저장되며 삭제된 컬럼의 값은 버린다.
- 색 선택: 서식 에디터의 글자색 팔레트와 같은 견본 12색(`TEXT_COLOR_SWATCHES`, 에디터와 공유), 기본 색상 버튼, 최근 색상(6개), 6열 배치.
- 표시: 칸반 컬럼은 옅은 배경과 위쪽 띠, 피드·상세의 상태 배지는 윤곽선·글자·옅은 배경을 그 색으로 칠한다. 리스트형의 상태 배지는 공통 `ListView`가 지정 색 이름만 받아 색을 적용하지 않는다.

## 피드 카드 구성

| 영역 | 공통 컴포넌트 | 협업공간 값 |
|---|---|---|
| 카드 | `FeedCard` | 작성자 이름, 메타 `작성일시`, 배지: 방에 컬럼이 있으면 상태(컬럼 이름) 칩, 제목 |
| 본문 | `FeedBodyContent`(richText) | 서식 HTML. 접힘: 이미지를 뺀 본문 + 이미지 미리보기 줄, 펼침: 이미지 포함. `더보기/접기` |
| 첨부 | `AttachmentList` | 파일 아이콘, 이미지 첨부 미리보기(blob), 내려받기 버튼 |
| 반응 | `FeedReactionBar` | 좋아요·북마크는 화면 상태만(문서작성 피드와 동일), 댓글 수 |
| 댓글 | `FeedCommentsSection` + 공통 `CommentThread` | 서식 댓글, 파일 첨부, 답글, 본인 댓글 수정·삭제, 삭제된 댓글 표시 |
| 이미지 | `ImageViewerDialog` | 본문·첨부·댓글 이미지 클릭 시 열림 |

## 데이터 계약안 변경

| 타입 | 변경 |
|---|---|
| 글 `body` | 서식 HTML. 일반 텍스트로 저장된 옛 값은 화면에서 문단으로 변환해 보여준다 |
| 첨부 | `name`, `size`, `type`, 선택 `dataUrl`(1MB 이하일 때만) |
| 댓글 | `body`(서식 HTML), `attachments`, `deleted`(삭제 표시, 본문 비움), `replies` |

## 서비스 규칙

- 댓글 작성: 저장 권한 필요. 본문에 글자도 이미지도 없고 첨부도 없으면 거부(`댓글 내용을 입력하세요.`).
- 댓글 수정: 작성자 본인만. 그 외 `수정 권한이 없습니다.`
- 댓글 삭제: 작성자 본인 또는 방 설정 권한. 삭제는 `deleted: true`로 표시하고 본문·첨부를 비워 답글 구조를 유지한다.
- 글 작성: 제목 필수(기존). 본문은 비어 있어도 된다.

## 화면 규칙

- 읽기 전용 사용자와 메뉴 쓰기 권한이 없는 사용자는 댓글 입력창이 보이지 않고 수정·삭제도 할 수 없다.
- 1MB 초과 파일을 내려받으려 하면 "백엔드 연동 전에는 이 파일을 내려받을 수 없습니다." 경고를 보여준다.
- 이미지 업로드는 서식 에디터에서 data URL로 삽입하며 2MB 초과는 오류 메시지를 보여준다.
- 칸반 카드 상세 다이얼로그도 같은 본문·첨부·댓글 구성을 쓴다.

## 검증 기준

- 서비스: 댓글 수정·삭제 권한, 빈 본문 판정, 삭제 후 답글 유지
- 화면: 카드 구성 요소가 공통 컴포넌트의 `data-testid`로 확인됨, 더보기, 첨부 이미지 미리보기, 읽기 전용 입력 불가
- 실제 브라우저에서 375/768/1280px
