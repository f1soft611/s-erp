# 거래명세서 헤더 합계 소수점 계약 적용 상세사양서

- 계획서: [20261126_004](../../plan/20261126/20261126_004_명세서_헤더합계_소수점_계약_적용_계획서.md)
- 공통 규칙: [공통 소수점 계약 가드레일 사양](20261126_001_공통_소수점_계약_가드레일_상세사양서.md)

## 동작

- 명세서 발행(`createGrouped`)은 거래처 그룹마다 선택된 출하 상세의 `total_amt`를 합산한 뒤 `SalesDecimalPolicy.amount("deliveryTotal", 합계, "명세서 합계")`로 규칙을 적용해 헤더 `total_amt`에 저장한다. 출하 서비스의 `sumTotals`와 같은 규칙이다.
- 규칙은 `SalesDecimalPolicy.from(systemPolicyService.getGridDecimals(tenantId), DecimalColumnContract.forDocument("sales.delivery"))`로 만든다. 정책 조회나 계약 오류는 예외로 전파되어 트랜잭션이 롤백된다.
- 상세 행(`tb_sales_statement_dt`)은 출하 상세의 수량·단가·금액을 그대로 복사한다. 출하 저장 때 이미 규칙이 적용된 값이다.
- 합계 범위 검증(`validateRange`)은 `SalesDecimalPolicy.amount`가 수행한다.

## SQL

- `lockDeliveryDetails`: `d.total_amt AS "totalAmt"` 추가.
- `insertHeader`: `total_amt`를 서브쿼리 `SUM` 대신 `#{totalAmt, jdbcType=NUMERIC}`로 저장.
- 테이블·컬럼 변경 없음(`total_amt numeric`), 별도 DB 스크립트 없음.

## 검증

- 단위: 합계가 정책 규칙으로 반올림되어 `insertHeader`에 전달되는지, 정책이 없을 때 기본 규칙이 쓰이는지.
- 기존 명세서·출하·매출마감 서비스 테스트 회귀.
