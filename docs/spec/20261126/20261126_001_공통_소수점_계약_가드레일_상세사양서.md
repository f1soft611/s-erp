# 공통 소수점 계약 가드레일 상세사양서

- 계획서: [20261126_001](../../plan/20261126/20261126_001_공통_소수점_계약_가드레일_계획서.md)

## 1. 규칙 (공통 정책)

1. 소수점의 단일 출처는 `frontend/src/shared/config/decimal-column-contract.json`이다. 키는 `<모듈>.<문서>`이고 서버 클래스패스로 복사된다.
2. 우선순위: 계약 컬럼의 `places`·`rounding`·`trailingZeros` > 정책(`type` 기준). 항목별로 적용한다.
3. 계약 대상 문서의 화면 코드는 컬럼에 `decimalPlaces`, `rounding`, `trailingZeros`, `decimal`을 직접 쓰지 않고, `places: <숫자>` 같은 고정 자릿수도 쓰지 않는다.
4. 정책이 로드되기 전에는 고정 대체값으로 값을 표시하지 않고 로딩 상태를 둔다.
5. 서버 계산은 `DecimalColumnContract`와 `SalesDecimalPolicy`(영업) 같은 모듈 정책 진입점을 거친다. 컬럼 규칙을 서버 코드에 직접 쓰지 않는다.
6. 프론트·서버 계약이 다르면 저장은 409로 거부한다. (기존 동작)

## 3. 신규 모듈 적용 절차

1. 계약 JSON에 `<모듈>.<문서>`를 추가하고 컬럼마다 `type`을 쓴다. 예외가 필요한 컬럼만 `places`/`rounding`/`trailingZeros`를 추가한다.
2. `tests/decimal-contract-guard.test.ts`의 `GUARD_SCOPE`에 문서와 화면 폴더를 등록한다.
3. `tests/fixtures/decimal-column-contract.golden.json`을 계약 JSON과 같은 내용으로 갱신한다.
4. 서버는 `DecimalColumnContract.forDocument("<모듈>.<문서>")`로 규칙을 얻어 계산·저장한다.
5. 화면은 `getDecimalColumnContract`/`resolveDecimalColumn`으로 규칙을 얻고, 직접 설정을 쓰지 않는다.
6. 프론트·서버를 함께 배포한다.

## 5. 컬럼 예외 설정 방법 (계약 JSON 예시)

JSON은 주석을 쓸 수 없으므로 설정 방법은 이 절을 기준으로 한다. 현재 영업 계약에는 예외 컬럼이 없고, 모든 컬럼이 정책(`type`)을 그대로 따른다.

### 5.1 기본형: 정책을 그대로 따름 (현재 영업)

```json
"sales.order": {
  "orderQty":  { "type": "number" },
  "unitPrice": { "type": "decimal" },
  "supplyAmount": { "type": "currency" }
}
```

### 5.2 예외형: 해당 컬럼만 자릿수·반올림을 직접 지정

```json
"sales.order": {
  "orderQty":  { "type": "number", "places": 2, "rounding": "HALF_UP" },
  "unitPrice": { "type": "decimal" },
  "orderTotal": { "type": "currency", "places": 1, "rounding": "DOWN", "trailingZeros": "AUTO" }
}
```

| 키 | 필수 | 허용 값 | 생략하면 |
| --- | --- | --- | --- |
| `type` | 필수 | `number`(수량), `decimal`(단가), `currency`(금액) | 오류 |
| `places` | 선택 | 0~6 정수 | 정책의 `type` 자릿수 |
| `rounding` | 선택 | `HALF_UP`(반올림), `UP`(올림), `DOWN`(버림) | 정책의 `type` 반올림 |
| `trailingZeros` | 선택 | `FIXED`(0 채움), `AUTO`(불필요한 0 제거) | 정책의 `type` 값 |

- 항목별로 우선순위를 적용한다. `places`만 쓰면 반올림·0 처리는 정책 값을 쓴다.
- 이 외의 키, 없는 `type`, 범위를 벗어난 값은 저장과 테스트에서 거부된다.

### 5.3 예외를 넣을 때 해야 할 일

1. 계약 JSON의 해당 컬럼을 수정한다.
2. 골든 파일을 같은 변경에 갱신한다. 갱신하지 않으면 테스트가 실패한다.
3. 프론트와 서버를 함께 배포한다. 한쪽만 배포되면 저장이 409로 거부된다.
4. 해당 컬럼을 보여주는 모든 화면(등록·현황·상세·출력)이 계약 규칙을 쓰는지 확인한다.
5. 화면 코드에 `decimalPlaces`, `rounding`, `trailingZeros`, `decimal`을 직접 쓰지 않는다.

### 5.4 계약에 없는 표시 전용 컬럼의 기준

계약에 컬럼으로 등록되지 않은 표시 전용 컬럼(잔량, 기출하 등)은 `decimalColumnOptions(getDecimalColumnContract('<문서>'), '<필드>')`로 의미가 같은 계약 컬럼의 설정을 따른다. 화면에 `type`이나 소수점 옵션을 직접 쓰지 않는다. 대상 필드의 예외를 바꾸면 이 컬럼들이 함께 바뀐다.

| 화면 컬럼 | 따르는 계약 컬럼 |
| --- | --- |
| 출하계획·출하 등록 원천: 수주수량(`orderQty`) | `sales.order.orderQty` |
| 출하계획: 계획잔량(`remainingPlanQty`), 출하 등록 원천: 계획수량(`plannedQty`) | `sales.deliveryPlan.plannedQty` |
| 출하계획: 출하수량(`deliveredQty`)·출하잔량(`remainingQty`), 출하 등록 원천: 기출하·미납수량 | `sales.delivery.deliveryQty` |
| 거래명세서 원천: 합계(`totalAmt`), 명세서 상세 총 합계 | `sales.delivery.deliveryTotal` |

- 매출마감(`revenue/closing`)은 계약 문서가 없어 이번 범위에서 제외한다. 계약에 문서를 추가한 뒤 위 규칙으로 연결한다.
- 정책 규칙이 없으면 고정 자릿수 대신 `-`를 표시하고 계산하지 않는다.
