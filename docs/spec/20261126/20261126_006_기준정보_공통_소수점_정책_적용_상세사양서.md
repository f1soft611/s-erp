## 계약 (예외 없음, 모두 정책을 따름)

| 문서 | 필드 | 화면 컬럼 | 구분 |
| --- | --- | --- | --- |
| `co.itemPartnerPrice` | `unitPrice` | 원화단가 | 단가 `decimal` |
| `co.itemPartnerPrice` | `foreignUnitPrice` | 외화단가 | 단가 `decimal` |
| `co.itemPartnerPrice` | `moq` | 최소주문수량 | 수량 `number` |
| `co.material` | `materialWeight` | 중량 | 수량 `number` |
| `co.material` | `safeInvoice` | 안전재고 | 수량 `number` (기존 `decimal` 표시에서 변경) |
| `co.material` | `expiryedCount` | 소비기한 숫자 | 수량 `number` |
| `co.itemPartnerPriceSummary` | `priceCount`, `customerCount` | 등록 건수, 거래처 수 | 수량 `number` (화면 전용) |
| `co.classification` | `sortSeq` | 정렬순서 | 수량 `number` (화면 전용) |
| `co.commonCode` | `sortOrder` | 정렬순서 | 수량 `number` (화면 전용) |

- `COMMON` 정책의 number는 0자리이므로 최소주문수량·안전재고·중량은 정수로 입력·저장한다. 단가는 3자리다.

## 서버

- `SalesDecimalPolicy.forModule("COMMON", 정책, 계약 문서)`로 규칙을 만든다(기존 `from`은 `SALES`).
- 품목단가 저장·수정(`saveParams`)과 엑셀 검증(`validateImport`)은 `unitPrice`·`foreignUnitPrice`·`moq`를 정책 자릿수로 검증하고, 자릿수 초과나 음수는 오류로 거부한다. 저장값은 정책 자릿수로 맞춘다. 엑셀 오류 메시지에는 정책의 자릿수가 들어간다.
- 품목 저장(`MaterialInfoServiceImpl.saveParams`)은 `safeInvoice`·`materialWeight`·`expiryedCount`를 같은 방식으로 검증한다.
- 서버 정책 스냅샷(409) 비교는 이번 범위가 아니다. 정책이 바뀐 직후에는 서버가 자릿수 초과 값을 오류로 거부한다.
- 서버가 계산하지 않는 화면 전용 문서(`co.itemPartnerPriceSummary`, `co.classification`, `co.commonCode`)는 서버 가드의 허용 목록에 둔다.

## 화면

- 숫자 컬럼은 `decimalColumnOptions(getDecimalColumnContract(문서), 필드)`로 `type`과 예외를 얻는다. 직접 쓰던 `decimalPlaces: 2`를 제거했다.
- 클라이언트 입력 검증(그리드 `validate`, 엑셀 사전 검증)은 0 이상의 숫자 형식만 확인하고 자릿수는 그리드(F1-Grid 정책 적용)와 서버가 검증한다.

## 검증

- 서버: 자릿수 초과·음수 거부, 테넌트 `COMMON` 정책 반영, 엑셀 검증 메시지, 안전재고 정책 검증, 서버 가드(`let/sales`, `let/co` 필드 대조).
- 프론트: 컬럼이 계약 타입을 따르고 직접 옵션이 없음, 계약 예외가 단가 컬럼에 전달됨, 가드 테스트(폴더 등록·직접 설정 차단).
