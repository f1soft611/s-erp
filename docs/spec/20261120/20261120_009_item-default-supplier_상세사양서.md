## 3. 단가 모듈 API 변경

### 3.1 저장 `POST /api/v1/co/master/item-partner-prices/save-batch` (`insertedRows`·`updatedRows`·`deletedRows`)
행 변경 객체에 두 필드를 추가한다.

| 필드 | 설명 |
| --- | --- |
| `orderType` | 문자열 또는 null. 공통코드 `PURCHASE_ORDER_TYPE`의 사용 중 항목이어야 한다(아니면 400 "사용할 수 없는 발주구분입니다."). **매입 행에서만** 허용(매출이면 400 "발주구분은 매입 단가에만 입력할 수 있습니다."). 값이 같으면 단가 행을 갱신하지 않는다. |
| `defaultSupplier` | true / false / 생략. **매입 행 + 거래처가 있는 행 + 사용 중 행**에서만 true 허용(아니면 400 "기본 거래처는 거래처가 있는 매입 단가에만 지정할 수 있습니다."). |

기본 거래처 반영(모든 행 변경을 적용한 뒤, 같은 트랜잭션):

1. 한 품목에 서로 다른 거래처가 `defaultSupplier = true`로 들어오면 400 "품목당 기본 거래처는 하나만 지정할 수 있습니다."
2. `true`: 그 품목의 기본 거래처 행을 그 거래처로 INSERT 또는 UPDATE(`updated_by/at`). 후보 조건은 그 거래처가 사용 중이고, 변경 반영 후 **그 품목의 사용 중 매입 단가 행이 1건 이상**(기간 무관)인 것이다(아니면 400).
3. `false`: 현재 기본 거래처가 그 행의 거래처이고, 같은 요청에서 같은 품목을 `true`로 지정한 행이 없으면 기본 행을 삭제한다. 다른 거래처가 기본이면 아무것도 하지 않는다.
4. 생략: 변경 없음. `defaultSupplier`만 달라진 변경은 단가 행(수정자·수정일시)을 건드리지 않는다.
5. **자동 해제**: 이번 요청으로 단가 행이 비활성화·삭제(`use_at = 'N'`)되어 기본 거래처의 사용 중 매입 단가가 하나도 남지 않으면 기본 행을 삭제한다. 응답 `clearedDefaultMaterialIds`에 품목 ID를 담는다(화면이 안내에 쓴다).
- 응답(저장된 행)에 `orderType`, `defaultSupplier`를 포함한다.

## 4. 구매요청확정 API 변경

### 4.0 공통 단가 조회 서비스 (원칙)
단가를 가져다 쓰는 업무가 계속 늘어날 것이므로, 단가 조회 규칙은 **단가 모듈(`let/co/master/itempartnerprice`)의 서비스 한 곳**(가칭 `ItemPriceLookupService`)에만 둔다.

- **이 서비스만 단가 테이블(`tb_item_partner_price`)과 기본 거래처 테이블(`tb_item_default_supplier`)을 조회한다.** 다른 모듈은 이 서비스를 호출만 하고, 단가 테이블을 직접 읽는 쿼리를 새로 만들지 않는다.
- 제공하는 조회 두 가지:
  1. **거래처 지정 조회**: 품목 + 거래처 + 기준일 → 가격 정보(현재 `unit-price` API가 쓰는 규칙).
  2. **기본 거래처 기준 일괄 조회**: 품목 목록 + 기준일 → 품목별 기본 거래처와 그 거래처의 가격 정보(요청 불러오기가 쓰는 규칙). 한 번의 쿼리로 처리한다.
- 가격 정보 = `unitPrice`, `currency`, `taxType`, `vatIncludedAt`, `foreignUnitPrice`, `foreignCurrency`, `orderType`. 선택 규칙은 거래처 단가 → 공통단가, 기준일 유효, 시작일 최신, 가격 ID 최신이고, 통화·단가 결정은 010 사양을 따른다.
- 거래구분(매입/매출)을 입력으로 받아 다른 업무가 같은 서비스를 쓸 수 있게 한다. 기본 거래처는 매입 전용이므로 매출은 "거래처 지정 조회"만 지원한다(이번 범위는 매입만 구현하고 매출은 영업 담당자 확인 후 적용).
- 현재 확정 모듈의 `selectDefaultUnitPrice` 쿼리와 가격 결정 코드는 이 서비스로 **옮기고** 확정 모듈에서는 삭제한다. 확정 모듈의 `unit-price`·`request-details`는 이 서비스를 호출한다.
- 규칙 검증 테스트는 이 서비스에 모으고, 호출하는 모듈은 서비스를 호출하는지만 확인한다.

### 4.1 `GET /api/v1/materials/purchase-request-confirms/request-details`
- 파라미터 `baseDt`(yyyy-MM-dd, 선택, 기본 서버 오늘)를 추가한다. 화면은 현재 입력된 확정일을 보낸다.
- 응답 행의 확정 입력 필드를 **미확정 행이면 기본값으로** 채운다(확정된 행은 저장값 그대로).

| 필드 | 값 |
| --- | --- |
| `supplierId`, `supplierCode`, `supplierName` | 품목의 기본 거래처(사용 중 거래처일 때). 없으면 모두 null |
| `unitPrice`, `currencyCode`, `taxType`, `vatIncludedAt`, `foreignUnitPrice`, `foreignCurrency` | 기본 거래처가 있을 때, `unit-price` API와 **같은 규칙**(010 사양): 그 거래처의 기준일 유효 단가 → 없으면 공통단가 → 없으면 null. 가격 선택은 시작일 최신순. 통화·단가는 원화 우선, 원화단가가 없고 외화단가만 있으면 외화통화·외화단가 |
| `orderType` | 선택된 단가 행의 `order_type`(비어 있으면 null) |

- 기본 거래처가 없는 품목은 위 필드를 모두 null로 둔다(공통단가가 있어도 구매처 없이 단가만 채우지 않는다).
- 기본 거래처는 있는데 기준일에 유효한 단가가 없으면 구매처만 채우고 가격 필드는 null이다.
- **쿼리**: 4.0의 공통 서비스(기본 거래처 기준 일괄 조회)를 호출한다. 품목 ID 목록 기준 한 번의 쿼리로 기본 거래처와 단가를 함께 구하며, 품목별 개별 쿼리를 쓰지 않는다.

## 5. 화면

### 5.1 단가등록 (품목 기준 · 거래처 기준 · 이력 조회 탭, 행 폼)
- 문구: "기본단가(거래처 공통)" → "**공통단가**"(그리드, 삭제 확인 창, 검색 라벨, 엑셀 안내 문구 모두).
- **품목 기준 트리**
  - 부모 행(품목): 읽기 전용 열 **매입 기본 거래처**(거래처명, 없으면 빈칸)를 추가한다. 부모의 매입 단가 칸은 공통단가이며 발주구분을 입력할 수 있다.
  - 자식 행(거래처 단가): 매입 묶음에 **기본** 체크박스와 **발주구분**(선택)을 추가한다. 체크하면 같은 품목의 다른 자식 행의 체크는 화면에서 해제된다(서버가 최종 보장). 그 거래처 행에 매입 단가가 없으면 체크할 수 없다. 과거 행(편집 잠금)은 체크를 바꿀 수 없다.
  - 저장 후 부모의 "매입 기본 거래처"는 재조회 값으로 갱신한다. 서버가 자동 해제한 품목이 있으면 "기본 거래처가 해제되었습니다: 품목명" 안내를 표시한다.
- **거래처 기준 탭**: 우측 행(품목+구분)에 **기본**(매입 행만)과 **발주구분**을 추가한다. 한 거래처를 여러 품목의 기본으로 지정할 수 있다. 체크한 품목의 기존 기본 거래처는 저장 시 이 거래처로 바뀐다(안내 문구를 열 머리글 툴팁으로 표시).
- **단가 이력 조회 탭**(조회 전용): **발주구분**, **기본 거래처**(Y/빈칸) 열을 추가한다.
- **행 폼(상세)**: 매입 단가 그룹에 발주구분과 기본 거래처 체크를 추가한다.
- **변경 집합**: 기본 체크만 바뀌어도 변경 행이 된다. 이때 값 필드는 그대로 보내고 서버가 단가 행을 갱신하지 않는다(3.1 4번).
- **검색 조건**: "단가 상태"에 "매입 기본 거래처 미지정"을 추가하고, 기존 두 항목은 "매입 공통단가 미등록", "매출 공통단가 미등록"으로 바꾼다.

### 5.2 구매요청확정
- 요청 불러오기로 행이 들어오면 4.1 응답의 구매처·단가·통화·부가세·발주구분이 확정 행에 들어가고 금액(확정수량 × 단가)과 합계가 계산된다. 기준일은 그때 입력된 확정일이다. **확정일을 바꿔도 다시 조회하지 않는다.**
- 기본 거래처가 없는 행은 구매처·단가가 비어 있고 [확정] 시 기존 검증("구매처를 선택해 주세요")이 적용된다.
- 구매처를 직접 고르거나 바꾸면 기존처럼 단가를 다시 조회한다. 응답에 `orderType`이 있을 때만 행의 발주구분을 덮어쓴다(없으면 기존 선택 유지).
- 기본 거래처 단가의 통화가 섞이면 기존 "통화가 다른 품목이 섞여 있습니다" 경고가 그대로 보인다.
- 사용자가 고친 값은 요청을 다시 불러오기 전에는 덮어쓰지 않는다.

## 6. 검증 기준

| 구분 | 확인 항목 |
| --- | --- |
| SQL 정적 | 테이블·제약·`order_type` 컬럼, 한 곳뿐인 품목 이전 쿼리, 롤백 중단 조건, 사본 동일 |
| 백엔드 단가 | 발주구분 검증(코드·매입 한정), 기본 거래처 지정·변경·해제, 품목당 하나(충돌 400), 후보 조건(단가 없는 거래처 400), 자동 해제, 플래그만 변경 시 단가 행 불변, 매출 행 거부, 조회 응답 필드, 필터, 엑셀 오류 코드, tenant 격리 |
| 백엔드 확정 | 기본 거래처·단가 일괄 설정(기본 거래처 없음 / 단가 없음 / 공통단가 대체 / 통화·외화 규칙 / 발주구분), `baseDt` 기본값, `unit-price` 발주구분, 사용 중이 아닌 거래처 제외, tenant 격리 |
| 프론트 | 트리·거래처 기준·이력 탭 컬럼과 체크 규칙, 변경 집합(플래그만 변경 포함), 문구 변경, 검색 조건, 확정 화면 불러오기 후 필드 설정, 구매처 변경 시 발주구분 처리 |
| 실서버(마지막) | 스크립트 적용 후 MCP 확인, 기본 거래처 지정·변경·해제와 자동 해제, 요청 불러오기 시 자동 설정(기본 거래처 있음/없음/단가 없음), 영업 화면 영향 없음 확인 |

## 7. 미결정·가정

- 확정일 변경 시 재조회 없음, 거래처 기준 탭에서 기존 기본 거래처 이름 표시 없음(툴팁 안내만): 기본 버전 가정이다.
- 엑셀 발주구분은 공통코드 이름 또는 코드 모두 허용한다.
- 공통단가 폐지, 기본 거래처 변경 이력, 매출 기본 거래처는 후속 작업이다.
