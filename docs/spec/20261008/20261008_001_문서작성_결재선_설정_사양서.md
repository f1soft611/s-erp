# 20261008_001 문서작성 결재선 설정 사양서

## 1. 목적 및 범위

문서작성 모달에서 현재 작성 중인 결재선 및 참조선을 불러와 편집할 수 있는 별도 설정 창을 제공한다. 결재/합의 단계 재정렬과 참여자 변경을 지원하며, 적용 전까지 원본 작성 상태를 변경하지 않는다.

- 작업지시서: [20261008_001 문서작성 결재선 설정](../../directions/20261008/20261008_001_문서작성_결재선_설정_작업지시서.md)
- 승인 설계: [문서작성 결재선 설정 설계](../../superpowers/specs/2026-10-08-document-approval-line-settings-design.md)
- 기존 결재선 구현/계약: [문서작성 결재선 에디터 사용성 개선 사양서](../20261007/20261007_001_문서작성_결재선_에디터_사용성_개선_사양서.md)

이 사양은 작성 상태의 결재선/참조선을 편집하는 범위에 한정한다. 저장/상신/승인 및 즐겨찾기 영속 저장은 포함하지 않는다.

## 2. UI 동작

- 결재선 사용자 선택 입력 옆의 `결재 추가`, `합의 추가` 뒤에 `결재선 설정`을 제공한다.
- 설정 버튼은 기존 작성 모달 위에 별도의 `CommonDialog`를 연다.
- 설정 창은 현재 `approvalStages`와 참조 사용자 ID를 복사해 편집 상태로 표시한다.
- 푸터에는 `취소`와 `적용`을 제공한다. 헤더 닫기와 `취소`는 설정 창의 변경을 폐기한다. `적용`은 결재선 및 참조자 상태를 한 번에 작성 모달에 반영하고 설정 창을 닫는다.
- 기존 사용자 옵션을 재사용한다. 사용자 후보 로딩이 실패한 경우 기존 오류를 표시하고 사용자 변경 액션을 비활성화한다.

## 3. 단계/참여자 계약

- 데이터 타입은 기존 `DocumentApprovalStage`를 유지한다: `id`, `kind` (`approval` 또는 `agreement`), `users`, 선택적 `isFixed`.
- 고정 기안자 단계는 항상 첫 위치를 유지하고 이동/삭제/교체할 수 없다.
- 각 결재 단계는 사용자 한 명이다. 추가 시 선택한 각 결재자는 독립된 결재 단계가 된다.
- 합의 단계는 여러 사용자를 담는 하나의 단계다. 단계 전체를 이동하며 단계 안의 사용자는 개별 추가/삭제할 수 있다.
- 합의 단계의 마지막 사용자를 삭제하면 그 단계도 제거한다. 사용자가 없는 단계는 작성 상태에 적용하지 않는다.
- 단계 재정렬은 드래그 앤 드롭과 위/아래 버튼 모두 제공한다. 위/아래 버튼은 키보드 접근이 가능하고, 고정 기안자에는 이동 컨트롤을 제공하지 않는다.
- 결재/합의 역할 전환은 제공하지 않는다.
- 참조선은 기존 다중 사용자 선택기로 편집한다. 현재 작성 기능에서 쓰는 결재-참조 중복 제한을 유지한다.
- 새 결재 단계 ID는 기존 ID 및 hook의 다음 ID 생성값과 충돌하지 않아야 한다.

## 4. 즐겨찾기 동작

- `자주 쓰는 결재선 저장`, `자주 쓰는 결재선 불러오기` 버튼을 표시한다.
- 테이블/API 명명 및 저장 계약이 확정되기 전까지 두 버튼을 disabled 처리한다.
- “저장 테이블/API 준비 후 제공”을 버튼 근처에 텍스트로 안내한다.
- 브라우저 저장, 서버 요청, DB/SQL 변경, 성공 토스트 또는 저장된 결재선 샘플을 추가하지 않는다.

## 5. 오류/반응형 처리

- 편집 상태는 원본 상태의 복사본이며, 적용 전의 수정은 부모 작성 상태에 영향을 주지 않는다.
- 설정 창 열기, 편집, 닫기는 네트워크 요청을 추가하지 않는다.
- 사용자 옵션이 로드되지 않은 경우 선택/추가 액션을 허용하지 않는다.
- 375px, 768px, 1280px에서 설정 창과 내부 목록이 화면 안에 배치되어야 한다. 긴 단계 목록과 사용자 입력은 모달 너비를 확장하지 않으며, 필요한 내부 스크롤을 사용한다.
- 다크/라이트 테마는 기존 공통 모달과 F1-Grid 선택기 테마를 따른다.

## 6. 검증

### 자동 테스트

1. 설정 창을 열면 기존 단계와 참조자가 순서/선택 상태를 보존해 표시된다.
2. 기안자는 고정되고, 드래그 및 위/아래 버튼은 나머지 단계를 단계 단위로 재정렬한다.
3. 결재 추가는 선택 사용자별 개별 단계를 추가하고, 합의 추가는 선택 사용자를 하나의 그룹 단계로 추가한다.
4. 결재자/합의자 삭제와 참조 선택 변경이 편집 상태에 반영되고, 빈 합의 단계는 제거된다.
5. 적용 시 결재선과 참조자가 모두 부모 상태로 반영된다. 취소/닫기는 원본을 유지한다.
6. 적용 후 다음 결재 단계 추가에도 ID가 중복되지 않는다.
7. 즐겨찾기 버튼은 비활성화되어 있고 실제 저장/불러오기 요청은 없다.
8. 사용자 옵션 로드 실패 시 기존 오류가 노출되며 사용자 변경이 불가능하다.

### 브라우저 확인

375px, 768px, 1280px에서 설정 창 열기, 목록 재정렬 컨트롤, 참조 선택 영역, 푸터 버튼, 내부 스크롤/가로 넘침 및 테마 표시를 확인한다. 캡처는 `docs/result/20261008/document-approval-line-settings/screenshots/`에 보관한다.

## 7. 범위 제외

- 결재선 즐겨찾기 영속 저장과 테이블/API 계약
- 백엔드/DB/SQL 변경
- 문서 저장, 상신, 결재 실행 및 역할 전환
- 기안자 단계 변경
