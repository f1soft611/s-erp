# 20261008_004 F1-Grid 행 삽입 사양서

## 1. 목적 및 범위

일반 F1Grid에서 컨텍스트 메뉴의 기준 행 바로 위/아래로 신규 행을 삽입하고, 삽입된 행을 바로 편집할 수 있게 한다.

- 작업지시서: [20261008_004 F1-Grid 행 삽입](../../directions/20261008/20261008_004_F1GRID_행삽입_작업지시서.md)
- 계획서: [20261008_004 F1-Grid 행 삽입](../../plan/20261008/20261008_004_F1GRID_행삽입_계획서.md)
- 승인 설계: [F1-Grid Row Insertion Design](../../superpowers/specs/2026-10-08-f1-grid-row-insertion-design.md)

이 사양은 프론트엔드 F1Grid 행 순서 조작에 한정한다. API/DB 계약과 F1Tree의 계층 순서는 변경하지 않는다.

## 2. 메뉴와 삽입 동작

- 우클릭 대상이 데이터 행인 일반 F1Grid 컨텍스트 메뉴에 `위에 행 삽입`, `아래에 행 삽입`을 제공한다.
- 삽입 anchor는 메뉴를 연 시점의 우클릭 대상 row ID다. 빈 영역 우클릭 시 상대 삽입 메뉴는 표시하지 않는다.
- `위에 행 삽입`은 anchor의 데이터 순서 인덱스에, `아래에 행 삽입`은 anchor 인덱스 + 1에 신규 행을 삽입한다.
- 신규 행은 `inserted` 상태 및 기존 `getChanges().insertedRows` 계약을 따른다. 행 배열과 row ID/index lookup이 같은 순서를 나타내야 한다.
- 삽입 행을 선택하고 첫 편집 가능 비체크박스 셀에 포커스한다. 가상화가 활성화된 경우에도 신규 행이 렌더링되도록 스크롤한다.
- 기존 `행 추가`, 컨텍스트 빈 영역의 `행 추가`, `F1GridRef.addRow()`는 계속 목록 끝에 행을 추가한다.
- `rowFormPlugin`으로 신규 행 폼을 여는 화면에서는 기준 row ID와 삽입 방향을 임시 폼 세션에 보존한다. Apply와 기존 검증이 성공해야 그 위치에 행을 삽입하며, 취소/검증 오류 시 데이터는 변경하지 않는다.

## 3. 정렬/필터 제약

- `sortState` 또는 `filterState`가 비어 있지 않으면 두 상대 삽입 메뉴를 비활성화한다.
- 비활성 메뉴에는 정렬/필터를 해제해야 삽입할 수 있다는 안내를 표시한다.
- 삽입 동작은 sort/filter를 자동 해제하지 않는다.
- 필터/정렬이 해제된 뒤에는 기존 원본 데이터 순서의 바로 위/아래에 삽입한다.

## 4. F1Tree 및 메뉴 옵션

- F1Tree의 `루트 추가`, 우클릭 행의 자식 `행 추가`, 계층 정렬 규칙은 변경하지 않는다. F1Tree 메뉴에는 일반 F1Grid 상대 삽입 액션을 노출하지 않는다.
- 기존 `allowAddRowInContextMenu`로 행 추가 메뉴를 숨긴 경우 상대 삽입 메뉴도 함께 숨긴다.
- 기존 `createRow` 및 행 폼 활성 조건에 따른 신규 행 생성 가능 여부를 그대로 따른다.

## 5. 상태 및 오류 처리

- GridState 삽입 함수는 지정 index를 유효한 배열 범위로 clamp하고 duplicate row ID가 있으면 상태를 변경하지 않는다.
- 삽입 시 `rows`, `rowById`, `rowIndexById`, `stateById`, `dirtyFieldsById`, `patchesById`, `changedIds`를 일관되게 갱신한다.
- 컨텍스트 메뉴 액션은 우클릭 대상을 보존한 뒤 메뉴를 닫는다. 생성된 신규 행이 정상적으로 적용되면 선택/포커스/스크롤을 갱신한다.
- 행 폼 오류는 기존 오류 표시 및 재시도 흐름을 유지하며 행 삽입 성공으로 처리하지 않는다.

## 6. 검증

### 자동 테스트

1. GridState 인덱스 0/중간/끝 및 범위 초과 입력에서 행 순서와 두 ID/index map이 일치한다.
2. 중복 ID는 기존 상태를 바꾸지 않으며, 신규 ID는 inserted 상태와 `insertedRows` 변경 목록에 들어간다.
3. 우클릭 행 위/아래 삽입, 신규 행 선택/포커스, 빈 공간 메뉴 노출 여부를 확인한다.
4. sort 또는 filter 활성 시 두 메뉴가 비활성이고 해제 후 활성화되며, sort/filter 값은 삽입 과정에서 유지된다.
5. 기존 끝 추가와 F1GridRef `addRow()`가 계속 끝에 추가한다.
6. 행 폼 Apply는 anchor 위치에 삽입하고, 취소/검증 실패는 원본 데이터를 유지한다.
7. 가상 스크롤 위치에서 신규 행이 viewport로 이동하고 렌더링/포커스된다.
8. F1Tree root/child 행 추가가 기존처럼 동작하며 상대 삽입 메뉴는 없다.

### 브라우저 확인

375px, 768px, 1280px에서 컨텍스트 메뉴의 위치/잘림 여부와 활성/비활성 메뉴 설명을 확인한다. 긴 그리드에서 viewport 밖 기준 행을 삽입해 신규 행으로 스크롤되는지 확인하고, 결과 캡처는 `docs/result/20261008/f1-grid-row-insertion/screenshots/`에 저장한다.
