## 1. 저장 오류 조사 기준

- `SalesOrderServiceImpl.createOrder()`는 수주 헤더/상세 저장 뒤 AUTO 모드이면 `createAutomaticPlan()`을 같은 트랜잭션에서 호출한다.
- 사용자 직접 납품계획 생성은 저장 후 계획 상세를 반환해야 하므로 `(sales_order_id, tenant_id, use_at='Y')` 및 주문·거래처 조인으로 재조회한다.
- 수주 AUTO 저장에서 자동 계획은 내부 연계 데이터이므로 삽입 ID와 성공한 상세 INSERT로 생성 결과가 확인된다. 수주 저장 트랜잭션이 불필요한 조회/표시용 JOIN 결과에 의존하지 않도록 생성과 응답 재조회를 분리한다.
- 제공된 런타임 예외는 자동 계획 생성 후 재조회 결과가 `null`임을 확정한다. 실제 DB에서 어떤 predicate/join이 불일치했는지는 tenant MCP 메타데이터에 주문/계획 테이블이 없어 확정하지 않는다.

## 2. 오류 메시지 레이아웃

- 수주등록 페이지의 `PageMessageArea`만 compact 레이아웃을 사용한다.
- compact 메시지의 바깥 위·아래 패딩은 각각 8px로 동일하게 한다.
- 오류 발생 시 수주 입력 영역의 상단 패딩을 16px로 설정한다. 상위 페이지 영역의 상단 여백 16px, 메시지 상단 패딩 8px의 합은 24px이며, 메시지 하단 패딩 8px와 다음 영역 간격 16px의 합도 24px가 되도록 맞춘다. 정상/embedded 레이아웃의 기존 패딩은 유지한다.
- 공통 컴포넌트의 다른 페이지 사용 및 메시지 내용/닫기 동작은 변경하지 않는다.

## 3. 검증 기준

1. 수주 저장에서 납품계획 생성이 호출되는 조건과 재조회 기준을 코드/Mapper에서 확인한다.
2. AUTO 계획 생성이 계획 상세 INSERT 후 표시용 헤더 재조회 실패에 영향받지 않으며, 수동 계획 생성은 기존 응답 재조회 계약을 유지한다.
3. 저장 오류가 표시될 때 수주등록 오류 메시지의 실제 위·아래 공백이 동일하다.
4. 수주등록 관련 Vitest, 프론트 빌드 및 브라우저 레이아웃 검증이 통과한다.
