# 20260922_001 공지사항 중요 공지 기능 상단 고정 전환 상세 사양서

## 1. 화면 사양

대상 화면은 `/groupware/community/notice`이다.

- 기존 헤더, 필터, 좌우 콘텐츠 셸, 피드/리스트 보기 전환은 유지한다.
- 작성/수정 모달에는 중요 공지 및 상단 고정 체크박스를 표시하지 않는다.
- 각 게시글의 더보기 옆에 고정 상태 아이콘을 표시한다.
  - 미고정: 상단 고정 명령과 고정 아이콘
  - 고정: 상단 고정 해제 명령과 해제 아이콘
- 좌측 상단 고정 영역에는 별도 조회 결과의 고정 게시글만 표시한다.
- 일반 피드에도 동일 게시글이 표시될 수 있다.
- 중요 공지 문구, 중요 공지 전용 필터, 중요 공지 색상, 중요 공지 요약은 표시하지 않는다.

## 2. 상태 모델

```ts
type NoticeBoardPostApi = {
  postId?: number | string | null;
  title?: string | null;
  isPinned?: string | null; // Y/N
  // other existing fields
};

type NoticeListResponse = {
  resultList: NoticeBoardPostApi[];
  resultCnt: number;
};

type NoticeFeedState = {
  items: NoticeFeedItem[];
  page: number;
  pageSize: 20;
  hasMore: boolean;
  isLoading: boolean;
  isLoadingMore: boolean;
  errorMessage?: string;
};
```

백엔드 검색 VO는 `egovframework.com.cmm.ComDefaultVO`를 상속한다. Controller/Service는 `PaginationInfo`에 `pageIndex`, `recordCountPerPage`, `pageSize`를 설정한 뒤 `getFirstRecordIndex()`와 `getLastRecordIndex()`를 검색 VO에 주입한다. 목록 결과는 첨부 프로젝트와 같이 `ListResult<T>`의 `resultList`/`resultCnt` 의미로 묶고, 외부 HTTP 응답은 기존 `ResultVO` 형식을 유지한다.

이 계약은 이번 공지 목록뿐 아니라 공지 도메인의 모든 페이징 목록 API에 공통 적용한다. 신규 공지 목록·검색·댓글 API는 `ComDefaultVO` 상속 검색 VO, `PaginationInfo` 인덱스 계산, 동일 조건 count 조회, `ListResult<T>` 목록/총 건수 응답을 사용한다. 상세·단건 조회 API는 페이징을 적용하지 않는다.

- `isPinned === 'Y'`만 고정 게시글이다.
- 일반 피드와 고정 영역은 서로 다른 상태와 조회 결과를 보유한다.
- 고정 게시글은 두 영역에 중복될 수 있다.
- 새 필터·새로고침·재시도 시 일반 누적 목록은 1페이지로 초기화한다.

## 3. 조회 및 무한 스크롤

### 3.1 일반 피드

- 최초 요청: `page=1&size=20`이며 `isPinned` 조건을 보내지 않는다.
- 목록 끝 감지 시 `page + 1&size=20`으로 요청한다.
- 성공 시 기존 `items` 뒤에 결과를 추가한다.
- `items.length >= totalCount`이면 `hasMore=false`로 전환한다.
- `isLoadingMore=true`인 동안 추가 요청을 막는다.
- 필터 값이 바뀌면 이전 요청 결과를 현재 상태에 적용하지 않고 새 1페이지 결과만 사용한다.

### 3.2 상단 고정 영역

- 동일 목록 API에 `isPinned=Y`를 넣어 별도 요청한다.
- 고정 영역은 별도 `resultList`와 `totalCount`를 사용한다.
- 기본 요청은 고정 게시글 전체를 표시할 수 있도록 `page=1&size=20`으로 시작한다. 고정 게시글이 20건을 초과하면 동일한 20건 단위 추가 조회를 사용한다.
- 상단 고정 카운터는 고정 조회의 `totalCount`를 표시한다.
- 일반 피드 결과에서 고정 게시글을 추출해 고정 영역을 만들지 않는다.

## 4. API 계약

### 4.1 목록 조회

- Method: `GET`
- Path: `/api/v1/groupware/boards/notice/posts`
- Query:
  - `page`: 1 이상 정수
  - `size`: 양의 정수, 화면 조회 단위는 20
  - `keyword`: 선택 문자열
  - `noticeGubunCode`: 선택 문자열
  - `isPinned`: 선택 `Y` 또는 `N`
- Response:

```json
{
  "resultList": [
    {
      "postId": 101,
      "title": "시스템 점검 안내",
      "isPinned": "Y"
    }
  ],
  "resultCnt": 1
}
```

- `isPinned=Y`이면 고정 영역 조회, 미전달이면 일반 피드 조회다.
- `resultCnt`는 현재 query 조건에 대한 전체 건수이며 일반 피드와 고정 영역에서 각각 사용한다.
- 일반 피드에도 `isPinned=Y` 게시글이 포함될 수 있다.
- `page`는 `PaginationInfo.pageIndex`로 전달하고 `size`는 `recordCountPerPage`로 사용한다. 내부 SQL은 검색 VO의 `firstIndex`와 `recordCountPerPage`를 사용한다.

### 4.2 게시글 저장/수정

- 기존 게시글 생성/수정 API를 유지한다.
- 작성/수정 모달 payload에는 `isPinned`를 포함하지 않는다.
- 고정 토글은 기존 수정 API에 최소 payload `{ "isPinned": "Y" | "N" }`를 전달한다.
- 성공 상태: 기존 API의 성공 응답 규칙 유지
- 인증 실패: `401`
- 권한 없음: `403`
- 대상 없음: `404`
- 입력 오류: `400`

### 4.3 상단 고정 상태 변경

- Method: `PUT`
- Path: `/api/v1/groupware/boards/notice/posts/{postId}/pin`
- Request: `{ "isPinned": "Y" | "N" }`
- 전체 게시글 수정 API를 사용하지 않고 `is_pinned`, 수정자, 수정일시만 갱신한다.
- 프론트는 확인창에서 `확인`을 선택한 경우에만 이 API를 호출한다.
- 취소 시 API를 호출하지 않고 현재 상태를 유지한다.

## 5. DB 사양

- 대상 테이블: `tb_board_post`
- 기존 `is_notice CHAR(1) NOT NULL DEFAULT 'N'`를 `is_pinned CHAR(1) NOT NULL DEFAULT 'N'`로 컬럼명 변경한다.
- 기존 `Y/N` 데이터는 컬럼명만 변경해 보존한다.
- Mapper 결과 매핑과 INSERT/UPDATE/WHERE/ORDER BY는 `is_pinned`를 사용한다.
- 중요 공지라는 의미의 주석·문서·쿼리 조건은 제거하고 상단 고정으로 설명한다.

## 6. 권한 및 예외 처리

- 기존 공지 조회·작성·수정·삭제 권한을 유지한다.
- 고정 토글도 게시글 수정 권한을 적용한다.
- 고정 토글 실패 시 현재 화면 상태를 임의로 변경하지 않고 오류 알림을 표시한다.
- 무한 스크롤 실패 시 이미 표시된 목록은 유지하고 하단 재시도 진입점을 제공한다.
- 필터 변경 중 이전 요청이 늦게 완료되어도 최신 필터 결과를 덮어쓰지 않는다.
- 빈 고정 목록은 전용 빈 상태로 표시하고, 일반 목록 빈 상태와 혼동하지 않는다.

## 7. 테스트 기준

- `isPinned` query가 일반 조회와 고정 조회에 각각 올바르게 전달된다.
- 목록 응답의 `resultCnt`로 `hasMore`와 고정 카운터가 계산된다.
- 일반 피드가 20건씩 누적되고 끝에서 추가 요청한다.
- 추가 요청 중 중복 호출이 발생하지 않는다.
- 고정 게시글이 일반 피드와 고정 영역에 동시에 표시될 수 있다.
- 작성/수정 모달에 고정 체크박스가 표시되지 않는다.
- 더보기 옆 고정/해제 아이콘이 상태에 따라 바뀌고 최소 payload를 보낸다.
- 중요 공지 필터·색상·요약·문구가 제거된다.
- 375px·768px·1280px에서 아이콘과 목록이 겹치거나 잘리지 않는다.
