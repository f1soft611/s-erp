# 20260917_001 공지사항 실제 브라우저 테스트 상세 사양서

## 1. 개요

본 사양서는 공지사항 페이지의 실제 브라우저 동작 검증과 필수 오류 수정 범위를 정의한다. 구현이 아니라 검증 중심 업무이며, 사용자 요구사항은 다음과 같다.

- 실제 브라우저에서 공지사항 저장, 수정, 삭제가 정상 동작하는지 확인한다.
- 첨부파일 포함 저장, 수정, 삭제를 실제 UI로 검증한다.
- 댓글과 답글의 저장, 수정, 삭제를 실제 UI로 검증한다.
- 문제 발생 시 즉시 원인 분석 후 코드 수정과 재검증을 수행한다.

## 2. 요구사항 정의

### 2.1 저장

- 사용자가 공지사항을 작성하면 페이지 목록에 정상 반영되어야 한다.
- 첨부 파일이 포함된 공지사항 역시 정상 저장되어야 한다.
- 댓글과 답글도 정상적으로 저장되어야 한다.

### 2.2 수정

- 공지사항 수정 시 기존 내용이 로드되고 변경 사항이 저장되어야 한다.
- 첨부 파일 추가/삭제 수정 역시 정상 반영되어야 한다.
- 댓글과 답글 수정 시 해당 내용이 즉시 갱신되어야 한다.

### 2.3 삭제

- 사용자가 삭제 액션을 수행하면 실제 데이터가 사라지거나 목록에서 제거되어야 한다.
- 첨부 파일이 포함된 공지 삭제 시 연관 첨부도 정합성 있게 처리되어야 한다.
- 댓글과 답글 삭제 시 계층 구조가 유지되어야 한다.

### 2.4 예외 처리

- 저장/수정/삭제 실패 시 사용자에게 오류 메시지가 표시되어야 한다.
- 네트워크 또는 API 실패가 발생하더라도 UI가 정지하지 않아야 한다.
- 재조회가 필요한 경우 목록이 새로고침되어 최근 상태를 반영해야 한다.

## 3. 화면/UI 요소 요구사항

### 3.1 공지사항 작성/수정 모달

- 제목 입력 영역이 정상 동작해야 한다.
- 본문 에디터 값이 실제 저장될 수 있어야 한다.
- 첨부 파일 선택이 정상 동작해야 한다.
- 저장 시 모달이 닫히고 목록이 갱신되어야 한다.

### 3.2 공지사항 목록 및 상세

- 목록이 로드되고 새 공지가 즉시 표시되어야 한다.
- 수정된 공지가 다시 목록에서 보이거나 갱신되어야 한다.
- 삭제된 공지가 목록에서 제거되어야 한다.

### 3.3 댓글/답글 UI

- 댓글 작성 폼이 정상 활성화되어야 한다.
- 답글 작성 폼이 정상 활성화되어야 한다.
- 댓글/답글 목록이 계층 구조로 보이며 수정/삭제 액션이 동작해야 한다.

## 4. API/데이터 계약

본 작업은 기존 프론트엔드 서비스 계약을 기준으로 검증한다.

### 4.1 공지사항 API

- `fetchNoticePosts(page, size, keyword)`
- `fetchNoticePostDetail(postId)`
- `createNoticePost(payload)`
- `updateNoticePost(postId, payload)`
- `deleteNoticePost(postId)`
- `uploadNoticeAttachment(postId, file)`
- `deleteNoticeAttachment(boardFileId)`
- `downloadNoticeAttachment(attachment)`

### 4.2 공통 댓글 API

- `fetchCommonComments(ownerType, ownerId)`
- `createCommonComment(ownerType, ownerId, content, parentCommentId?)`

### 4.3 예상 동작

- 작성 API 성공 시 서버가 결과 item 또는 result 반환한다.
- 수정 API 성공 시 반영된 값이 다시 조회된다.
- 삭제 API 성공 시 목록/상세에서 제거되어야 한다.
- 댓글/답글은 ownerType/ownerId와 parentCommentId가 일관되게 전달된다.

## 5. 예외/에러 기준

### 5.1 필수 에러 대응

- 저장 실패 시 사용자에게 `showError` 메시지가 표시되어야 한다.
- 댓글/답글 저장 실패 시 별도 메시지가 표시되어야 한다.
- 파일 업로드 실패 시 공지 저장 전체가 중단되기 전에 사용자 피드백이 제공되어야 한다.

### 5.2 재검증 기준

- 동일 시나리오를 다시 수행해 에러가 재발하지 않는지 확인한다.
- 수정 코드는 기능 단위에서 안정적으로 동작해야 한다.

## 6. 구현 원칙

- 기능을 임의로 추가하지 않는다.
- 기존 구조와 API 인터페이스를 우선 유지한다.
- 문제는 실제 브라우저 재현을 통해 확인하고 최소 수정 범위로 해결한다.
- 백엔드 DB/스키마 변경은 필요하지 않다.

## 7. 검증 기준

### 7.1 브라우저 검증

- 저장/수정/삭제 작업을 실제 브라우저에서 수행한다.
- 첨부파일과 댓글/답글을 실제 사용자 흐름으로 확인한다.
- 오류 발생 시 즉시 수정하고 재검증한다.

### 7.2 코드 검증

- `cd frontend && npm run build`
- 필요한 관련 테스트 또는 smoke 검증 수행

## 8. 완료 조건

- 공지사항 CRUD 동작이 브라우저에서 정상 동작한다.
- 첨부파일 포함 CRUD 동작이 정상 동작한다.
- 댓글/답글 CRUD 동작이 정상 동작한다.
- 수정 내역과 검증 결과가 결과 문서에 기록된다.
- DB 변경이 없음을 기록한다.
