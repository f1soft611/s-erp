# 20260917_002 공지사항 댓글 피드형 표시·입력 개선 상세 사양서

## 1. 개요

공지사항 댓글 영역의 표시 계층과 입력 동작을 피드형 UX로 조정한다. 서버의 댓글 저장 구조와 API는 유지하고, 공통 댓글 컴포넌트에서 표시 계층과 키보드 동작을 제어한다.

## 2. 댓글 표시 사양

### 2.1 표시 계층

- 표시 단위는 `root comment`와 `reply` 두 단계다.
- `comment.replies` 안에 다시 `replies`가 존재해도 화면에서는 추가 depth 컨테이너를 만들지 않는다.
- 깊은 답글은 최상위 댓글의 답글 목록에 평탄화하여 표시한다.
- 답글 표시 영역은 최상위 댓글과 동일한 피드 폭 안에서 한 단계 들여쓰기만 사용한다.
- 삭제된 부모 댓글은 기존 tombstone 문구를 표시하고, 활성 하위 답글은 같은 최상위 댓글의 답글 목록에 남긴다.

### 2.2 답글 작성

- 최상위 댓글의 `답글` 액션은 해당 댓글 ID를 부모 ID로 전달한다.
- 깊은 답글의 `답글` 액션도 최상위 댓글 ID를 부모 ID로 전달한다.
- 화면상 답글 입력창은 현재 답글 대상의 위치에 열리되, 새로운 표시 depth를 생성하지 않는다.

## 3. 입력창 UI 사양

### 3.1 기본 레이아웃

- 댓글·답글 입력창은 초기 한 줄 높이로 렌더링한다.
- 입력 본문은 좌측, 첨부파일 아이콘은 우측 끝 액션 영역에 둔다.
- 선택 파일이 있으면 기존 파일명 목록을 입력창 하단에 표시한다.
- 본문이 여러 줄이면 입력 영역은 내용에 맞춰 확장한다.
- 기본 에디터 여백은 댓글 피드 항목 간격과 시각적으로 일치하도록 최소화한다.

### 3.2 키보드 동작

| 입력                | 동작                                           |
| ------------------- | ---------------------------------------------- |
| `Enter`             | 현재 댓글 또는 답글을 등록                     |
| `Shift+Enter`       | 등록하지 않고 새 줄 삽입                       |
| IME 조합 중 `Enter` | 등록하지 않고 브라우저/Tiptap 조합 처리를 유지 |

- 등록할 텍스트가 없으면 API를 호출하지 않는다.
- 등록 성공 시 본문과 선택 파일을 초기화한다.
- 등록 실패 시 본문과 선택 파일을 유지하고 상위 오류 처리 흐름을 따른다.

## 4. 컴포넌트 계약

### 4.1 `TiptapCommentThread`

- 기존 `comments`, `onSubmitComment`, `onSubmitReply`, 수정·삭제·첨부 콜백 계약을 유지한다.
- 내부 표시 컴포넌트는 `rootCommentId` 또는 동등한 최상위 식별자를 사용한다.
- 깊은 답글 표시를 위한 재귀 JSX를 제거하거나 표시용 평탄화 함수로 대체한다.
- 댓글 에디터는 Tiptap editor props의 키보드 이벤트에서 Enter/Shift+Enter를 분기한다.

### 4.2 `NoticeFeedList`

- 서버/로컬 댓글 트리 데이터 타입은 유지한다.
- `onAddComment`의 `parentCommentId`는 표시용 최상위 댓글 ID를 전달한다.
- 기존 댓글 수 계산, 이전 댓글 로드, 수정·삭제·첨부 동작은 유지한다.

## 5. API 및 데이터 계약

- API 엔드포인트, HTTP 메서드, payload 필드, 응답 상태는 변경하지 않는다.
- 댓글 생성은 기존 `createCommonComment(ownerType, ownerId, content, parentCommentId?)`를 사용한다.
- 댓글 첨부파일은 기존 `NOTICE_COMMENT` owner 계약을 사용한다.
- 깊은 답글을 화면에서 평탄화하더라도 서버 응답의 `parentCommentId` 원본은 변경하지 않는다.

## 6. 예외 처리

- 댓글/답글 생성 API 실패 시 로컬 목록에 임시 항목을 추가하지 않는다.
- 실패한 에디터의 내용과 선택 파일을 유지하여 재시도할 수 있어야 한다.
- 첨부파일 선택 중 입력창이 재렌더링되어도 선택 파일이 사라지지 않아야 한다.
- 좁은 화면에서 본문, 첨부 아이콘, 액션 버튼이 겹치면 안 된다.

## 7. 검증 기준

### 7.1 자동 테스트

- 3단계 이상 댓글 데이터가 입력되어도 표시 들여쓰기가 1단계까지만 생성되는지 확인한다.
- 깊은 답글에서 답글 등록 시 최상위 댓글 ID가 콜백에 전달되는지 확인한다.
- 일반 Enter가 등록 콜백을 호출하는지 확인한다.
- Shift+Enter가 등록 콜백을 호출하지 않고 줄바꿈을 허용하는지 확인한다.
- 첨부파일 아이콘의 accessible name과 실패 시 입력 상태를 확인한다.

### 7.2 브라우저 검증

- 375px, 768px, 1280px에서 댓글·답글 입력창과 첨부 아이콘의 겹침·잘림을 확인한다.
- 실제 한글 입력에서 Enter 등록과 Shift+Enter 줄바꿈을 확인한다.
- 깊은 답글 데이터를 포함한 피드가 최대 2단계로 보이는지 확인한다.

## 8. 권한 및 DB 영향

- 기존 댓글 권한 정책을 변경하지 않는다.
- 테이블·컬럼·인덱스·마이그레이션 변경 없음.
- DB 스크립트: 해당 없음, 영향 검토 완료.
