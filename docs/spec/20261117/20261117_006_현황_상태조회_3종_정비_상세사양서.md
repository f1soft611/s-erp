# 20261117_006 기존 현황 화면 상태 조회 3종 정비 상세 사양서

기준: [작업지시서](../../directions/20261117/20261117_006_현황_상태조회_3종_정비_작업지시서.md), [계획서](../../plan/20261117/20261117_006_현황_상태조회_3종_정비_계획서.md)
DB 변경 없음(`s-erp-postgresql-readonly` MCP로 `tb_purchase_order_hd.use_at`, `tb_material_arrival_hd.use_at`이 이미 있음을 확인했고 매퍼가 이를 쓴다).

## 1. API 계약

| API | 변경 |
| --- | --- |
| `GET /api/v1/materials/purchase-order-status` | `status` 없음 → `ACTIVE`로 처리. 허용: `ACTIVE`, `CANCELED`, `ALL`. 그 외 400(`검색 조건이 올바르지 않습니다.`) |
| `GET /api/v1/materials/material-arrival-status` | 위와 동일 |

- `ALL`은 취소 포함 전체이며 매퍼가 `use_at` 조건을 붙이지 않는다(기존 매퍼 구조 그대로, 변경 없음).
- 응답 행의 `status`(`ACTIVE`/`CANCELED`)와 나머지 필드는 바뀌지 않는다.
- 서비스가 `params.status`에 항상 `ACTIVE`/`CANCELED`/`ALL` 중 하나를 넣는다(null 없음).

## 2. 화면

대상: `frontend/src/pages/materials/order/status`, `frontend/src/pages/materials/arrival/status`.

- 상태 검색 선택지: 정상(`ACTIVE`), 취소(`CANCELED`), 전체(`ALL`). 상수는 `…STATUS_OPTIONS`(전체 추가)와 `…STATUS_DEFAULT = 'ACTIVE'`로 서비스 파일에 둔다.
- 필터 변환(`toPurchaseOrderStatusFilters`, `toMaterialArrivalStatusFilters`): 상태가 비어 있으면 `ACTIVE`를 명시한다(서버도 같은 값으로 보므로 일관). 저장된 예전 세션도 정상으로 조회된다.
- 검색 훅(`usePurchaseOrderStatusSearch`, `useMaterialArrivalStatusSearch`): `usePageSearchDefaults`가 주는 기본값에 `status: 'ACTIVE'`를 주입해 처음 열 때와 초기화 때 상태 칩이 정상으로 보이게 한다.
- **상태 필드는 필수 + 빈 값 숨김**: `search: { required: true, allowEmpty: false }`. 항상 정상/취소/전체 중 하나가 선택되어 있고 적용 조건 칩 "상태: 정상"이 처음부터 보이며 칩을 제거할 수 없다. 초기화하면 정상으로 돌아간다. 컬럼·정렬·상세 패널·수정·취소·링크 동작은 바꾸지 않는다.
- **공통 검색 영역 변경**: `select` 검색 필드는 지금까지 빈 값 선택지 "전체"를 자동으로 맨 위에 붙였다. 상태 필드에서는 옵션의 `전체`(`ALL`)와 겹쳐 "전체"가 두 개 보이고, 빈 값 "전체"를 고르면 서버가 정상으로 처리해 "전체"를 골랐는데 정상만 나오는 오해가 생긴다. 컬럼 `search.allowEmpty: false`를 `PageSearchField.allowEmpty`로 전달하고 `PageSearchArea`가 이때 빈 값 선택지를 렌더링하지 않는다(기본 동작은 그대로). F1-Grid 문서에 반영한다.
- **검색 세션 버전**: 상태 기본값이 없던 때 저장된 검색 세션이 복원되면 상태가 비어 보이는 문제가 있어 발주현황·가입고현황과 이미 3종으로 만든 입고현황·자재수입검사현황의 검색 세션 버전을 2로 올려 예전 세션을 버리고 기본값(정상)으로 시작한다.
- 상태 열 라벨(`…StatusLabel`)은 `ALL`에 대한 행 표시가 필요 없으므로(행의 상태는 `ACTIVE`/`CANCELED`) 그대로다.

## 3. 검증 항목
- 서비스: 상태 없음 → `ACTIVE`(두 서비스), `ALL`·`CANCELED` 통과, 잘못된 값 400, 날짜 형식·범위 검증은 기존 그대로.
- 매퍼: `ALL`에서 `use_at` 조건 없음, `ACTIVE`·`CANCELED` 조건 유지.
- 화면: 선택지 3종(빈 값 "전체" 없음), 필터 변환 기본값, 처음 조회 요청에 `status=ACTIVE`, 처음 진입과 예전 세션 복원에서 상태가 정상으로 선택되고 칩이 보임, 취소·전체 선택 시 해당 요청, 기존 테스트 회귀 없음. 공통: `allowEmpty:false`이면 빈 값 선택지가 없고 기본값이면 있다.
- 실서버·브라우저: 여러 건의 정상·취소 데이터로 기본/취소/전체 조회를 확인.
