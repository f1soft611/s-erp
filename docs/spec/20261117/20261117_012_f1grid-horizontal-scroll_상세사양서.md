## 설계 선택

1. **채택:** 기존 네이티브 스크롤과 분리된 헤더/본문/합계를 유지하고, 동기화 이벤트 되먹임을 방지하며 가상 열 창에 히스테리시스를 적용한다. 기존 UX와 데이터 계약을 보존하면서 재현된 원인만 수정한다.
2. **제외:** 단일 스크롤 컨테이너 통합은 고정 헤더/합계와 sticky 레이아웃 변경 범위가 커 이번 작업에 사용하지 않는다.
3. **제외:** smooth-scroll 애니메이션이나 debounce로 입력을 늦추는 방식은 실제 렌더 부담과 되돌림을 해결하지 못하므로 사용하지 않는다.

## 동기화

- 본문 scroll 이벤트는 최신 실제 본문 위치를 헤더/하단 합계에 동기적으로 반영한다.
- 헤더/합계별 마지막 프로그램 동기화 위치를 저장한다. 브라우저가 값을 제한할 수 있으므로 대입 후의 실제 `scrollLeft`를 기록한다.
- 후속 scroll 이벤트의 값이 기록과 같으면 프로그램 동기화의 통지로 판단해 무시한다. 특히 그 사이 본문이 더 이동해도 본문을 과거 위치로 쓰지 않는다.
- 기록과 다른 헤더/합계 위치는 직접 이동으로 받아들여 본문에 반영하고, 본문의 실제 위치를 기준으로 다른 영역도 즉시 동기화한다.
- 리스너 해제 및 합계 dock 변경 시 재연결을 유지한다.

## 컬럼 가상화

- 공개 `virtualizeColumns`, `columnOverscan`의 타입과 기본값은 변경하지 않는다.
- 이전 열 집합은 viewport 실제 열 및 고정/보호 열을 모두 포함할 때 재사용한다. overscan 열의 일부가 viewport 안으로 들어와도 즉시 삭제/재생성하지 않는다.
- 하나라도 누락되면 현재 위치에서 기존 overscan 수만큼 양쪽 열을 새로 계산한다. 빠른 점프와 방향 반전도 지연 타이머 없이 처리한다.
- 너비, 컬럼 구성, pinned/protected, viewport 및 checkbox/폼 액션 구성이 바뀌면 이전 창의 유효성을 초기화한다.
- scroll 갱신 판단과 렌더 창 계산은 같은 옵션과 이전 집합을 사용한다. 연속 입력은 기존 RAF 스케줄러가 마지막 위치로 병합한다.
- 기존 행 가상화 계산, 선택/편집/복사 보호, 체크박스/폼 액션 폭 보정, scrollbar gutter, 합계 값은 유지한다.

## 다중 컬럼 표의 행 렌더 비용

- 자동 모드에서 기존 200행 이상 조건 외에, 병합 컬럼이 없고 삭제/필터 적용 후 행 수 × 숨김 제외 컬럼 수가 1,000 이상이어도 기존 행 가상화를 활성화한다.
- `mergeRows` 컬럼이 있는 표는 추가 셀 수 조건에서 제외해 기존 병합 레이아웃을 보존한다. 기존 200행 기준 및 명시적 가상화 설정은 그대로 유지한다.
- `virtualizeRows={false}`는 셀 수와 무관하게 전체 행 렌더를 유지하며 `true`도 기존 의미를 유지한다.
- 데이터, 전체 선택, export, 집계와 변경 추적은 전체 행 기준을 유지한다. 행 높이/overscan/스크롤 이동 계산은 기존 엔진을 사용한다.
- 120행 × 60열 측정에서 남은 한 번의 대량 셀 렌더 지연을 줄이기 위한 범위 보완이며 새로운 props나 별도 엔진은 추가하지 않는다.

## 검증

- 단위/통합: 지연된 헤더 및 합계 이벤트 각각의 rollback 방지, 직접 이동 양방향 동기화, 이전 창 재사용, 범위 이탈/보호 열/리사이즈 무효화.
- 실제 브라우저: 375/768/1280px에서 좌우 고정, 헤더/본문/합계 정렬 오차 1px 이내, 양 끝과 연속/역방향 이동 및 viewport 열 존재 여부, 페이지 외부 가로 overflow 없음.
- 120행 × 60열 비교에서 같은 이동 동안 commit과 DOM 교체 감소를 확인한다. 시간 수치는 환경 영향을 함께 기록한다.
- API/백엔드/DB 변경은 없으므로 DB MCP 및 SQL 스크립트 대상이 아니다.
