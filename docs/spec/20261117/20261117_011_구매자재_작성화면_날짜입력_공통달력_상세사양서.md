## 1. 공통 컴포넌트 `FormDateField`

위치 `frontend/src/shared/components/FormDateField.tsx`.

| prop | 설명 |
| --- | --- |
| `label` | 필드 이름(예: 요청일). 오류 문구와 접근성 이름에 쓴다 |
| `value` | 현재 입력 문자열 |
| `onChange(value)` | 입력·달력 선택·blur 정규화 결과를 전달 |
| `disabled` | 편집 불가. 입력과 달력 버튼이 모두 비활성이고 달력은 열리지 않는다 |
| `required` | 기본 true. 라벨에 `*` 표시 |
| `error` | 저장 직전 검증 등 외부 오류 문구. 있으면 필드가 오류 상태이고 문구를 보인다 |

- 내부는 `DateEditor`(`variant="outlined"`, `autoFocus={false}`, `selectOnFocus={false}`)이다.
- blur: `normalizeDateInput(value)`가 유효하면 값을 정규화(`YYYY-MM-DD`)해 `onChange`로 전달하고 오류를 지운다. 값이 비어 있지 않은데 무효면 `올바른 ${label}을(를) 입력해 주세요.`를 필드 오류로 보인다(입력 값은 보존). 빈 값이면 오류를 보이지 않는다(필수 검증은 저장 시).
- 값이 바뀌면(입력·달력 선택) blur 오류를 지운다.
- 오류 문구 우선순위: 외부 `error` > blur 오류.
- 같은 이름의 export `normalizeFormDate(value): { date: string; invalid: boolean }`: `date`는 정규화 결과(무효면 빈 문자열), `invalid`는 비어 있지 않은데 무효인지 여부. 저장 직전 검증에서 쓴다.

## 2. 화면 변경

모든 화면: 날짜 `TextField type="date"` → `FormDateField`. `disabled`는 각 화면의 기존 편집 가능 여부와 같다. `onChange`는 기존 처리(`setXDt`, `setDirty(true)`, 검증 메시지 초기화)와 서버 날짜 훅의 `markTouched`를 그대로 호출한다.

| 화면 | label | 비활성 조건(기존) |
| --- | --- | --- |
| 구매요청등록 | 요청일 | `!isEditable` |
| 구매요청확정 | 확정일 | `!confirmEditable` |
| 발주등록 | 발주일 | `!editable` |
| 가입고등록 | 가입고일 | `!editable` |
| 입고등록 | 입고일 | `!editable` |
| 자재수입검사등록 | 검사일 | `!editable` |

### 2.1 저장 직전 처리
각 화면의 저장(확정) 핸들러 맨 앞에서 날짜를 정규화한다.
1. `normalizeFormDate(날짜)` 결과 `date`, `invalid`를 구한다.
2. `invalid`이면 기존 검증 메시지 영역에 `올바른 ○○일을 입력해 주세요.`를 표시하고(그리드 검증과 함께) 요청을 보내지 않는다.
3. 유효하면 화면의 날짜 state도 정규화된 값으로 맞춘다(blur 전에 저장 단추를 눌러도 동일).
4. 필수 검증(`validate…Input`)과 payload 생성에는 정규화된 `date`를 쓴다.
5. 구매요청등록은 변경감지(`baseline.requestDt` 비교)에 정규화된 값을 쓴다.
6. 발주등록의 `fetchDefaultUnitPrice(…, orderDt)`와 확정의 `fetchDefaultUnitPrice(…, confirmDt)`처럼 날짜를 API에 쓰는 곳도 정규화된 날짜만 보낸다(무효·빈 값이면 호출하지 않거나 기존 동작 유지).

## 3. 검증 항목
- `FormDateField`: 축약 입력 blur 확정(`20261117`→`2026-11-17`), 무효 입력 오류 표시와 입력 보존, 빈 값은 오류 없음, 외부 `error` 우선, `disabled`에서 달력 불가, 달력 선택 반영.
- 화면별(여섯 곳): blur 없이 축약 날짜로 저장해도 payload 날짜가 ISO, 무효 날짜는 요청을 보내지 않고 오류 표시, 필수 누락 차단, 읽기 전용에서 달력 불가.
- 기존 구매·품질 화면 테스트와 서버 날짜 테스트(`20261117_010`)가 통과한다.
- 실제 브라우저 375/768/1280/1920px: 입력·달력 아이콘 겹침 없음, 달력 선택, 축약 입력.
