## 2. 수량·잔량 규칙

- 검사 대기량(가입고 행) = `arrival_qty − Σ(유효 검사의 pass_qty + fail_qty)`. 유효 = 검사 헤더 `use_at='Y'`.
- 한 행의 입력 상한 = 해당 가입고 행의 검사 대기량. 수정 시에는 그 검사 자신의 기존 수량을 대기량에 되돌려 놓고 계산한다.
- 수량은 소수 2자리, 합격량·불합격량은 0 이상이고 둘의 합은 0보다 커야 한다.
- 발주 잔량(가입고 가능량) = `발주량 − 유효 가입고 합 + 유효 불합격 합`(`fail_qty`는 발주 행 기준으로 합산). 가입고 데이터는 바꾸지 않는다.
- 구현 전 발주 잔량을 계산하는 쿼리를 전수 확인하고(가입고 후보·가입고 저장 검증·발주 행 변경 409 검증·발주현황 등) 불합격 합 반영 여부를 지점별로 테스트로 고정한다. 영향 범위가 사양과 다르면 이 절을 갱신한다.

## 3. API

### 3.1 검사 등록 (`/api/v1/quality/material-inspections`)

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/candidates` | 검사 대기 가입고 행 목록(불러오기 창) |
| GET | `/{materialInspectionId}` | 검사 단건 조회(헤더 + 행) |
| POST | `/` | 검사 등록 |
| PUT | `/{materialInspectionId}` | 검사 수정(행 빼기 포함) |
| POST | `/{materialInspectionId}/cancel` | 검사 취소 |

#### 3.1.1 후보 조회
- 조건: `arrivalDtFrom`, `arrivalDtTo`(가입고일 기간), `supplierKeyword`, `materialKeyword`, `keyword`.
- 대상: 정상 가입고(헤더 `use_at='Y'`)의 행 중 `inspect_at='Y'`이고 검사 대기량 > 0.
- 응답: `materialArrivalDetailId`, `arrivalNo`, `arrivalDt`, `supplierName`, `orderNo`, `materialCode/Name/Spec`, `unit`, `arrivalQty`, `inspectedQty`(유효 검사 합), `passQty`, `failQty`, `waitQty`(검사 대기량). 정렬은 가입고일·가입고번호 내림차순, 행번호 오름차순. 전체 건수(대기 N건 안내)는 `total`로 같이 준다.

#### 3.1.2 등록 요청
```
{
  "inspectionDt", "inspectorId", "remark",
  "details": [{ "materialArrivalDetailId", "passQty", "failQty", "remark" }]
}
```
- `details` 1건 이상. 같은 가입고 행을 한 요청에 두 번 담을 수 없다(400).
- 행 검증: 가입고 행이 정상이며 `inspect_at='Y'`, `0 ≤ passQty`, `0 ≤ failQty`, 합 > 0, 합 ≤ 검사 대기량(초과 시 409 + 품목·가입고번호·대기량 메시지).
- 검사일은 필수(미래 일자 허용 여부는 가입고일 규칙과 같다), 검사자는 필수·사용 가능한 사용자.
- 처리: 가입고 행을 id 순서로 `FOR UPDATE` → 대기량 재계산 → 헤더·행 저장 → 번호 발급 → 응답에 저장된 검사(헤더 + 행) 반환. 하나라도 실패하면 전체 롤백.
- 번호: `MATERIAL_INSPECTION_NO`, `QI-YYYYMMDD-NNNN`(검사일 기준).

#### 3.1.3 단건 조회 응답
헤더: `materialInspectionId`, `inspectionNo`, `inspectionDt`, `inspectorId/Name`, `remark`, `status`(ACTIVE/CANCELED).
행: `materialInspectionDetailId`, `lineNo`, `materialArrivalDetailId`, `arrivalNo`, `arrivalLinked`, `materialArrivalId`, `supplierName`, `orderNo`, `materialCode/Name/Spec`, `unit`, `arrivalQty`, `otherInspectedQty`(이 검사를 제외한 유효 검사 합), `maxQty`(= `arrivalQty − otherInspectedQty`, 입력 상한), `passQty`, `failQty`, `inspectQty`, `remark`.

#### 3.1.4 수정
```
{
  "inspectionDt", "inspectorId", "remark",
  "details": [{ "materialInspectionDetailId", "passQty", "failQty", "remark" }]
}
```
- 요청에 없는 기존 행은 삭제(빼기). 행 1건 이상 필요. 새 행·가입고 행 변경은 받지 않는다.
- 취소된 검사(`use_at='N'`)는 409, 없으면 404.
- 행 검증과 상한은 등록과 같다(상한은 `maxQty`). 행번호를 다시 매긴다.
- 헤더 → 연결된 가입고 행(id 순) 순으로 잠근다.

#### 3.1.5 취소
- 헤더 `use_at='N'`(행은 이력으로 남는다). 재취소 409. 취소하면 가입고 잠금과 검사 대기량이 복구된다.
- 합격분의 입고 연결 확인은 입고 수동 등록 단계에서 추가한다.

### 3.2 검사현황 (`/api/v1/quality/material-inspection-status`)

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/` | 검사 품목 행 단위 목록 |

- 검색: `inspectionDtFrom`, `inspectionDtTo`(검사일 기간, 필수·시작 종료 모두, 기본 최근 1개월~오늘), `inspectionNo`, `supplierKeyword`, `arrivalNo`, `orderNo`, `materialKeyword`, `inspectorKeyword`, `keyword`, `status`(`ACTIVE` 정상/`CANCELED` 취소/`ALL` 전체, 값이 없으면 서버는 `ACTIVE`, 화면 기본도 정상).
- 응답 행: 헤더 `materialInspectionId`, `inspectionNo`, `inspectionDt`, `inspectorName`, `headerRemark`, `status`; 행 `materialInspectionDetailId`, `lineNo`, `arrivalNo`, `arrivalLinked`(연결된 가입고 행이 남아 있고 그 가입고가 정상이면 true), `materialArrivalId`(링크용), `supplierName`, `orderNo`, `materialCode/Name/Spec`, `unit`, `arrivalQty`, `inspectQty`, `passQty`, `failQty`, `passRate`(합격량/검사량, 소수 1자리 %), `remark`, `createdByName`.
- 정렬은 검사일·검사번호 내림차순, 행번호 오름차순. 등록자 이름은 입고현황과 같이 `tb_login_account` → `tb_user`로 조회한다.

### 3.3 가입고 쪽 변경
- 가입고 단건/목록 응답의 행에 `inspectionId`, `inspectionNo`(유효 검사가 있으면 가장 최근 검사 1건, 없으면 null)를 추가한다. 별도의 `inspectionLocked` 필드는 두지 않고 `inspectionNo`가 있으면 잠긴 행으로 본다.
- 잠금(입고와 같은 방식): 유효 검사가 있는 가입고 행을 "잠긴 행"으로 본다.
  - `PUT /material-arrivals/{id}`: 잠긴 행을 요청에서 빼면 409, 값(수량·단가·세액·창고·제조일·소비기한·비고)이 기존과 다르면 409, 잠긴 행이 하나라도 있으면 가입고일·부가세 설정 변경 409(비고는 수정 가능).
  - `POST /material-arrivals/{id}/cancel`: 잠긴 행이 하나라도 있으면 409.
  - 메시지에 검사번호를 포함한다: `수입검사 QI-…에서 처리해 주세요.`
- 발주 쪽: 가입고가 있는 발주 행의 삭제·취소·수량 축소 검증은 기존대로이며, 불합격 합은 위 2절 규칙으로 잔량에 더해진다.

- 취소·행 빼기 확인창: "취소(또는 행 제외)하면 해당 가입고 행의 수정·삭제가 다시 가능해지고 검사 대기량이 복구됩니다."

### 4.3 자재수입검사현황 (`inspect-status`)
- 목록 컬럼(같은 검사는 헤더 셀 병합): 검사번호(링크), 검사일, 검사자, 상태, 행, 가입고번호(링크: 가입고현황 상세 `?arrivalId=`, 연결이 끊긴 취소 이력은 일반 텍스트), 구매처, 발주번호, 품목코드, 품목명, 규격, 단위, 가입고량, 검사량, 합격량, 불합격량, 합격률, 비고, 등록자.
- 상태 검색: 정상(기본)/취소/전체. 기본 조회에서는 취소건이 나오지 않는다. 필수 조건이 아니라 칩에서 바꾸거나 해제할 수 있다. 기준일(검사일 기간)은 필수이며 칩에서 해제할 수 없다.
- 검사번호 클릭 → 상세 패널: 요약(건수·검사량·합격량·불합격량·합격률), 헤더 정보(검사일·검사자·비고), 행별 검사 실적(가입고량, 이 검사를 제외한 기검사량, 이 검사의 합격량·불합격량 — MES의 "선택한 가입고건 검사실적"과 "기등록 내역" 역할). 가입고 행 전체 누적 합격·불합격 합계는 이번 응답에 없어 보여 주지 않는다. [더보기] 메뉴에서 조회/수정한다.
- 수정 다이얼로그는 등록 화면을 `embedded`로 쓴다: 취소된 검사는 조회만, 정상은 수정(수정 권한은 등록 메뉴 UPDATE), 푸터에 [검사 취소].
- 엑셀은 EXCEL 권한이 있을 때만 보인다. 375/768/1280/1920px에서 가로 스크롤·잘림을 확인한다.

### 4.4 가입고 화면 보강 (`materials/arrival`)
- 가입고현황 상세/수정에서 검사가 있는 행은 읽기 전용으로 표시하고 검사번호(링크: 검사현황 상세 `?inspectionId=`)를 보여 준다. 잠긴 행이 있으면 취소 버튼과 헤더 항목을 비활성화하고 "수입검사 QI-…에서 처리해 주세요" 안내를 보인다(입고 잠금 UI와 같은 방식, 입고번호와 검사번호가 모두 있는 행은 두 안내를 함께 보여 준다).
- 가입고 목록·상세의 `inspectionNo` 컬럼을 입고번호 컬럼 옆에 추가한다.

## 5. 검증 항목
- 후보 조회: `inspect_at='Y'`만, 대기량 0 제외, 취소된 가입고 제외.
- 등록: 여러 가입고 행을 한 번호로 저장, 같은 행 중복 거부, 대기량 초과 거부, 번호 형식 `QI-YYYYMMDD-NNNN`, 롤백.
- 수정: 수량·비고·검사자 변경, 행 빼기 후 행번호 재정렬, 모든 행 빼기 거부, 취소된 검사 수정 409.
- 취소: `use_at='N'`, 재취소 409, 취소 후 가입고 행 수정·삭제 가능, 취소 후 대기량 복구와 후보 재등장.
- 가입고 잠금: 검사가 있는 행의 수정·삭제·헤더 수정·취소가 409이고 검사번호 안내, 검사 대상이어도 검사가 없는 행은 수정 가능.
- 발주 잔량에 유효 불합격 합이 반영되고 취소된 검사의 불합격은 반영되지 않음.
- 현황: 기본 조회는 정상만, 취소·전체 선택 시 해당 건 조회, 검사일 기간 필수, 링크·상세·수정 저장·취소가 목록과 합계에 반영.
- 사이드바에 품질관리 > 수입검사 > 자재수입검사등록·현황 메뉴 표시와 라우팅.

## 6. 확정한 사항 (2026-11-17 사용자 확인)
- 검사는 가입고 행을 **불러와서** 처리하고 여러 행을 한 검사번호로 묶는다. MES의 검사 대상 목록은 불러오기 창이 대신한다.
- 수입검사도 취소(`use_at='N'`)를 둔다. 수정은 수량·비고 정정, 취소는 검사 무효화이며 취소하면 가입고 잠금이 풀린다.
- 현황 화면을 같이 만든다(상태 정상 기본/취소/전체). 별도 모듈 `품질관리`(경로 `pages/quality/inspect`)에 둔다.
- 첫 버전은 전수검사, 합격/불합격 수량만. 샘플·특채·부적합 처리·검사항목별 결과·사진은 제외한다.
