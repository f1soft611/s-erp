## 수정 검증

- 신규 계획은 원본 수주 상세의 `remainingPlanQty`를 한도로 한다.
- AUTO 기존 계획 조회 시 같은 원본 수주상세의 현재 계획 상세 수량을 모두 합산하여 조회 잔량에 더한 값을 해당 계획의 수정 한도로 사용한다. 다른 계획이 이미 사용한 수량은 한도에 포함하지 않는다.
- MANUAL 최초 등록 후 수정은 최초 선택 당시 잔량을 해당 계획의 한도로 유지한다. 이후 저장량이 바뀌어도 최초 한도를 중복하여 증가시키지 않는다.
- 수량 합계는 수주 ID와 수주 상세 ID 조합별로 검증한다. 저장 성공 이후 분할 행을 다시 수정해도 한도가 달라지지 않는다.
- 화면 검증 통과 후에도 서버는 다른 계획 수량 및 출하 사용 여부를 다시 검증한다. 출하된 상세의 수정·삭제 제한과 API 및 DB 계약은 변경하지 않는다.
- 반환된 `deliveredQty`가 0보다 큰 상세는 등록·현황 수정 화면에서 분할·삭제 버튼과 계획일·계획수량 셀 편집을 비활성화한다. 출하되지 않은 형제 상세는 편집할 수 있다. 화면에서 파악할 수 없는 참조 이력이나 동시 출하는 서버가 최종 거부한다.

## 오류 메시지

- 오류 발생 시 출하계획등록 본문 위 패딩 16px과 공통 메시지 compact 위아래 패딩 8px을 적용한다. 본문 gap 16px을 포함한 메시지 위아래 간격은 24px이다.
- 오류 유무와 관계없이 본문 좌우 패딩은 모바일 8px, 그 외 16px을 유지한다. 공통 메시지의 추가 좌우 패딩을 제거해 오류 메시지와 기본정보 영역의 양쪽 경계를 맞춘다.
- 저장 검증 실패 시 직전 성공 메시지를 지워 오류 아래에 성공 알림이 끼어들지 않게 한다.
- 오류가 없을 때 기존 반응형 본문 여백과 성공 메시지를 유지한다. 수주 선택 대화상자 및 다른 영업 화면은 변경하지 않는다.

## 검증

- 잔량 0인 기존 계획 100을 50·50으로 나누어 수정 저장하고 재저장한다.
- 다른 계획이 이미 일부 수량을 사용하는 경우 그 수량까지 포함하여 초과를 거부한다.
- 신규 계획 잔량 제한, 기존 현황 수정 및 서버 출하 이력 보호를 보존한다.
- 부분 출하된 행은 분할·삭제·편집할 수 없고 미출하 형제 행은 분할할 수 있다.
- 관련 Vitest, 빌드, lint와 375/768/1280px 브라우저 확인을 수행하고 결과를 기록한다.
- 각 폭에서 오류 메시지와 기본정보의 좌우 경계가 같고, 오류 표시 전후 기본정보 영역의 좌우 위치가 유지되는지 확인한다.
