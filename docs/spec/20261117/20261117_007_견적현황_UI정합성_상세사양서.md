# 견적현황 UI 정합성 상세사양서

## 근거와 범위

- [작업지시서](../../directions/20261117/20261117_007_견적현황_UI정합성_작업지시서.md), [계획서](../../plan/20261117/20261117_007_견적현황_UI정합성_계획서.md).
- 기준: 수주현황의 `SalesOrderActionsMenu`, `SalesOrderStatusSearchArea`, 검색 훅과 공통 theme의 MuiInputBase disabled 배경.
- 이전 견적 공통코드·레이아웃·날짜 입력 사양은 유지하고 아래 누락 사항만 보완한다.

## 상세 더보기

- 텍스트 작업 버튼 대신 수주현황과 동일한 작은 MoreVert IconButton을 사용한다.
- 접근성 이름은 `견적 더보기`, 메뉴는 `자세히보기` 및 작성자/수정 권한이 있는 경우에만 `수정`이다.
- 기존 상세보기/수정 다이얼로그와 닫기·변경확인 동작은 보존한다.

## 통합검색

- PageSearchArea의 searchField에 공통 스타일 TextField를 넣는다. 안내는 `견적번호/거래처/품목 검색`, 접근성 이름은 `견적현황 빠른 검색`이다.
- Enter, 검색 버튼, 상단 조회, 상세검색 적용 모두 현재 검색어와 해당 적용 상세조건을 함께 전달한다. 검색어 타이핑만으로는 API를 호출하지 않는다.
- 검색어 초기화 아이콘은 입력값만 비우고 다음 검색에서 반영한다. 전체 조건 초기화 시 검색어도 비운다.
- 검색어와 날짜/상세조건을 페이지 세션에 저장한다. keyword가 없는 이전 정상 날짜 세션도 유지하고 빈 검색어로 복원한다. keyword가 문자열이 아닌 세션은 거부한다.
- API: 기존 GET `/api/v1/sales/quotation-status`에 선택 문자열 `keyword` 추가. 앞뒤 공백 제거 후 빈 검색어는 전달하지 않는다.
- 서버: 견적번호, 거래처 코드/명, 상세 스냅샷 품목 코드/명 다섯 컬럼을 OR 부분일치로 묶고 기존 날짜·테넌트·사용 중 조건 및 개별 상세조건과 AND 결합한다. 값은 바인딩하며 직접 SQL 문자열 삽입을 하지 않는다.
- 기본 DB MCP `list_tables`, `describe_table`로 견적 헤더·상세·거래처의 검색 컬럼과 tenant_id 계약을 확인했다. 업무 데이터 행 조회는 하지 않았다. 신규 테이블/컬럼/데이터 변경이 없어 마이그레이션은 만들지 않는다.

## 날짜 읽기전용

- 견적작성일·견적제출일의 DateEditor에 `disabled={!isEditable}`을 직접 전달한다.
- 상위 fieldset만 disabled인 기존 상태에서는 MUI disabled 클래스가 없어 테마 배경이 적용되지 않았다.
- 보기 모드·권한 없음·로딩/저장/잠금 상태에서 입력기 및 달력 버튼은 비활성화되고 입력 루트에 Mui-disabled가 붙어 공통 theme의 action.disabledBackground를 사용한다.
- 수정 가능한 작성/수정 폼은 기존 배경·달력·축약 날짜 정규화를 유지한다. 공통 DateEditor나 테마 전체를 수정하지 않는다.

## 검증

- 프론트엔드: 검색어 trim/URL 전달, 이전/신규 세션 복원, 조회 트리거, 초기화, 필수 날짜 보존, 더보기 메뉴/권한, 두 날짜 MUI 클래스 및 달력 차단.
- 백엔드: keyword trim/null, 테넌트·필수 날짜 유지, 다섯 컬럼 OR 괄호와 바인딩, 빈 검색어 무조건 조회 회귀. 운영 Java는 Java 8 호환성을 유지한다.
- 브라우저: 375/768/1280px 페이지 overflow·메뉴·검색·보기/수정 날짜의 실제 배경과 편집 상태를 확인하고 스크린샷을 저장한다.
