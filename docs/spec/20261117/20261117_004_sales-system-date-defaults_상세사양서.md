# 영업관리 작성 기준일 서버날짜 통일 상세사양서

## 목적

영업관리 작성화면에서 오늘 날짜를 기본값으로 사용할 때 브라우저의 로컬 시계가 아니라 `GET /api/v1/common/system-date`의 날짜를 사용한다. 날짜 API는 기존 `shared/services/systemDateService.ts`의 `getSystemDate()`를 재사용한다.

## 적용 범위

| 화면 | 날짜 필드 | 현재 동작 | 변경 |
| --- | --- | --- | --- |
| 견적작성 | 견적작성일 | 서버날짜 | 현 동작 유지 및 회귀 확인 |
| 수주작성 | 수주일자 | 브라우저 날짜 | 서버날짜로 초기화 |
| 출하작성 | 출하일자 | 브라우저 날짜 | 서버날짜로 초기화 |
| 거래명세서 작성 | 명세일 | 브라우저 날짜 | 서버날짜로 초기화 |

신규 작성과 폼 초기화에서 서버날짜를 사용한다. 수정·조회 데이터 적용 시 저장된 날짜를 유지한다. 거래처, 수주, 출하 등 선택한 원천 데이터에서 복사되는 날짜는 변경하지 않는다. 현황 검색조건의 월 단위 기간 기본값은 오늘 날짜 단일 기본값이 아니므로 제외한다.

## 날짜 로딩과 오류

- 서버날짜 응답의 ISO 날짜를 사용하고, 브라우저 시각으로 대체하지 않는다.
- 신규 폼은 서버날짜를 불러오는 동안 기본 날짜를 적용하지 않는다.
- 조회 실패 시 기존 화면 오류 표시를 사용하고 기본값을 로컬 날짜로 채우지 않는다. 화면에 이미 제공되는 재시도 흐름이 있다면 이를 사용한다.
- 기존 자료를 로드하는 경로가 서버날짜 응답보다 늦거나 빠르더라도 저장된 자료 날짜가 최종 폼 값이어야 한다.
- 초기화 동작이 있는 폼은 초기화 시 서버날짜를 다시 조회한다.

## 회귀 기준

- 브라우저 날짜와 서버날짜가 다른 경우 신규 수주·출하·명세 폼에는 서버날짜가 표시된다.
- 서버날짜 요청 실패 시 로컬 날짜를 표시하거나 저장 기본값으로 사용하지 않는다.
- 기존 자료를 불러오면 저장된 날짜가 유지된다.
- 초기화 후 서버날짜가 적용된다.
- 견적작성의 기존 서버날짜 기본값과 날짜 입력·검증·저장 계약은 변하지 않는다.
