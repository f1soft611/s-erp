# 영업관리 폼 공통 날짜 입력 상세사양서

## 근거 및 범위

- [작업지시서](../../directions/20261117/20261117_003_sales-form-datefield_작업지시서.md)
- [계획서](../../plan/20261117/20261117_003_sales-form-datefield_계획서.md)
- 사용자 요청에 따라 기존 공통 DateEditor를 직접 재사용한다. 별도 날짜 입력 컴포넌트나 라이브러리는 추가하지 않는다.
- 기준은 수주등록 기본정보의 기존 1/2/4열 반응형 폼이며 순서·간격·크기를 유지한다.

| 업무 | 폼 필드 | 정책 |
| --- | --- | --- |
| 견적 | 견적작성일, 견적제출일 | 작성일 필수, 제출일 선택. 진행 중인 작업 002 구현 보존 |
| 수주 | 수주일자, 납기일자 | 수주일 필수, 납기일 선택 |
| 출하 | 출하일자 | 필수 |
| 거래명세서 | 명세일, 원천 출하일자 | 명세일 필수, 원천 출하일자 비활성 표시 |

출하계획의 계획일은 F1Grid 셀 입력이므로 기존 공통 날짜 편집을 유지한다. 현황의 검색조건도 이미 공통 DateEditor를 사용하므로 별도 변경하지 않는다.

## 입력 및 저장

- 폼에서는 `variant="outlined"`, `autoFocus={false}`를 사용한다.
- ISO 날짜, 8자리/6자리, 월일·일 축약 입력과 달력 선택은 기존 DateEditor 규칙을 따른다.
- blur에서 유효한 날짜는 `YYYY-MM-DD`로 확정한다. 잘못된 날짜는 입력을 보존하고 해당 필드에 오류를 표시한다.
- 저장은 blur에 의존하지 않고 모든 대상 날짜를 다시 정규화한다. 비어 있지 않은 무효 날짜 또는 필수 날짜 누락 시 요청하지 않는다.
- 선택 날짜는 빈 값을 허용하며 기존 payload의 null 변환을 보존한다.
- 새 날짜 유효성 처리는 프론트엔드 폼 입력 범위에만 적용하고 API/DB 계약과 서비스 로직은 변경하지 않는다.
- 날짜 수정 시 해당 날짜 오류를 해제하고, 신규/조회/저장 후 폼 적용 시 이전 날짜 오류가 남지 않게 한다.

## 비활성화 및 회귀 기준

- 권한 없음, 조회 전용, 로딩, 저장 중 등의 기존 편집 가능 여부를 입력과 달력 버튼 모두에 반영한다.
- 공통 DateEditor의 disabled는 선택적이며 미지정 시 기존 셀·검색 입력의 포커스·키보드·스타일을 유지한다.
- 달력이 열린 상태에서 disabled가 되면 팝오버를 표시하지 않고 날짜 선택을 차단한다.
- 날짜 기본값의 출처, 기존 검증·권한·저장 및 현황의 폼 재사용을 유지한다.
- 회귀 테스트는 축약 입력 blur 확정, blur 없는 저장 ISO payload, 무효 날짜와 필수 누락 차단, 선택 날짜 삭제, 읽기 전용 달력, 셀·검색 날짜 입력을 포함한다.
- 375/768/1280px 실제 브라우저에서 폼과 달력 사용 가능 여부, 입력·아이콘 겹침, 페이지 가로 넘침을 확인하고 스크린샷을 저장한다.
