# 20261117_007 매입마감처리 화면 상세 사양서

기준: [작업지시서](../../directions/20261117/20261117_007_매입마감처리_화면_작업지시서.md), [계획서](../../plan/20261117/20261117_007_매입마감처리_화면_계획서.md)
DB 확인: `s-erp-postgresql-readonly` MCP로 `tb_material_receipt_dt`(마감 컬럼 없음, 단가·공급가·부가세·합계 있음), `tb_material_receipt_hd`(`tax_type`, `vat_included_at`, `use_at`), `tb_item_partner_price`(부가세 컬럼 없음)를 확인했다.

## 1. DB

`tb_material_receipt_dt`에 컬럼 추가(모두 NULL 허용, 미마감이면 NULL):

| 컬럼 | 타입 | 설명 |
| --- | --- | --- |
| `closing_month` | varchar(6) | 마감월 `YYYYMM`. NULL이면 미마감 |
| `closed_at` | timestamp | 마감 일시 |
| `closed_by` | varchar | 마감자(로그인 ID) |
| `closing_unit_price` | numeric | 마감 단가 |
| `closing_tax_type` | varchar | `TAXABLE`/`ZERO_RATED`/`EXEMPT` |
| `closing_vat_included_at` | char(1) | `Y`/`N` |
| `closing_supply_amt` | numeric | 마감 공급가 |
| `closing_vat_amt` | numeric | 마감 부가세 |
| `closing_total_amt` | numeric | 마감 합계 |

- CHECK: `closing_month IS NULL OR closing_month ~ '^[0-9]{6}$'`, 마감월이 있으면 `closed_at`·세금 구분 필수, `closing_vat_included_at IN ('Y','N')`.
- 인덱스: `ix_material_receipt_dt_closing_month (tenant_id, closing_month)`.
- 스크립트: `20261117_007_add_receipt_closing_columns.sql`, 롤백, 변경이력 md, 메뉴 시드 `20261117_008_seed_receipt_closing_menu.sql`(+롤백, md) — `docs/database/20261117`·`backend/DATABASE/20261117` 동일 유지, `db-schema.md` 갱신. 메뉴는 구매자재 모듈의 입고관리 그룹 아래 `RECEIPT_CLOSING`(경로 `/materials/receipt/receipt-closing`, 기존 화면 코드·정렬 규칙과 `tb_menu` 현재값을 MCP로 확인한 뒤 확정).

## 2. API (`/api/v1/materials/purchase-closings`)

모두 테넌트 범위. 응답 구조·오류 형식은 기존 입고 API와 같다.

| API | 설명 |
| --- | --- |
| `GET /suppliers` | 구매처 요약. 파라미터: `receiptFrom`, `receiptTo`(필수, `yyyy-MM-dd`), `closingMonth`(필수, `YYYYMM`), `keyword`(품목명·코드, 선택) |
| `GET /` | 입고 행 목록. 파라미터: 위와 같음 + `supplierId`(선택), `closeType`(`ALL` 기본/`CLOSED`/`OPEN`), `orderNo`(선택) |
| `POST /close` | 마감. 본문 `{closingMonth, rows:[{receiptDetailId, unitPrice, taxType, vatIncludedAt}]}` |
| `POST /release` | 해제. 본문 `{receiptDetailIds:[...]}` |

### 2.1 구매처 요약 행
`supplierId`, `supplierName`, `bizNo`(사업자번호), `receiptCount`·`receiptAmount`(기간 내 정상 입고 행 수와 합계금액), `monthClosedCount`·`monthClosedAmount`(`closing_month`가 선택 마감월인 행, 입고일 무관), `openCount`(기간 내 미마감 행 수). 합계금액은 마감 행은 `closing_total_amt`, 미마감 행은 `total_amt`. 취소된 입고(`hd.use_at='N'`)는 제외. 행이 없는 구매처는 나오지 않는다.

### 2.2 입고 행
`receiptDetailId`, `receiptNo`, `receiptDt`, `supplierId/Name`, 품목(코드·명·규격·단위), `orderNo`(발주번호), `receiptQty`, 금액 5종(단가·공급가·부가세·합계 + `taxType`, `vatIncludedAt`: 마감 행은 마감 값, 미마감은 입고 값), `warehouseName`, `inspectionNo`, `remark`, `closingMonth`, `closedAt`, `closedBy`, `closed`(boolean). 정렬: 마감월, 입고일, 품목명.
- `closeType`: `OPEN`=미마감만, `CLOSED`=`closing_month`가 선택 마감월인 행만, `ALL`=기간 내 전체.
- `CLOSED`는 입고일 기간과 무관하게 마감월 기준으로 조회한다(기간 조건 미적용).

### 2.3 마감 규칙
- 마감월 형식 `YYYYMM`, 월 01~12. 그 외 400.
- 행은 1건 이상, 최대 500건. 대상 행을 `FOR UPDATE`로 잡고 모든 행이 정상 입고의 **미마감** 행이어야 한다. 하나라도 이미 마감됐거나 취소된 입고면 전체 거부(409, 해당 입고번호 안내).
- `unitPrice` ≥ 0, `taxType`는 3종 중 하나, `vatIncludedAt`는 `Y`/`N`이며 `Y`는 `TAXABLE`일 때만(입고등록과 같은 규칙). 금액은 서버가 `PurchaseOrderAmountCalculator`로 `receipt_qty`, 단가, 구분으로 계산해 저장한다(클라이언트 금액은 받지 않는다).
- 저장: 마감 컬럼 9개 + `updated_by/at`. 입고 행의 원래 단가·금액은 바꾸지 않는다.
- 화면의 초기값은 입고 헤더의 `tax_type`·`vat_included_at`(기본 과세/별도)과 행 단가다.

### 2.4 해제 규칙
- 대상 행을 `FOR UPDATE`로 잡고 모두 마감된 행이어야 한다(아니면 409). 마감 컬럼 9개를 NULL로 되돌린다. 이력 테이블은 없다.

## 3. 입고등록 잠금

`MaterialReceiptServiceImpl`의 수정(`updateReceipt`)·행 빼기·취소에서 해당 입고에 마감 행이 있으면 거부한다(409). 메시지: 마감월과 입고번호를 포함한 `마감된 행이 있는 입고입니다(마감월 YYYY-MM). 매입마감을 해제한 뒤 처리하세요.`. 기존 수입검사 잠금과는 별도의 검사이며, 둘 다 해당하면 마감 메시지를 먼저 보여 준다(마감을 해제해야 다른 처리를 할 수 있는 순서). 입고현황 응답에 `closingMonth`(행별)와 헤더 `closedCount`를 추가하고 입고 화면의 수정·취소 버튼을 마감 여부로 막는다.

## 4. 화면

위치: `frontend/src/pages/materials/receipt/closing/` (라우트 `receipt-closing`). `DashboardContent`에 연결.

- **검색 영역**(`PageSearchArea`): 빠른 검색은 품목코드·품목명, 상세검색은 입고일 기간(필수, 기본 최근 1개월~오늘), 마감월(선택 목록, 필수, 기본 이번 달, 지난 12개월~이후 3개월, 빈 값 없음), 조회구분(전체/마감등록/마감미등록, 필수, 기본 전체), 발주번호. 구매처는 검색 조건이 아니라 왼쪽 요약 그리드에서 고른다(구현 중 단순화). 이전 세션에 값이 없으면 이번 달·전체로 조회한다.
- **레이아웃**: 공통코드 등록 화면과 같은 `Splitter` 좌우 2분할. 왼쪽 구매처 요약(구매처, 입고건, 입고금액, 해당월 마감건, 미마감건), 오른쪽 입고 행. 초기 왼쪽 폭은 좁게(약 420px)하고 구분선으로 조절, 폭은 세션에 저장. 좁은 화면(xs)에서는 위아래로 쌓는다. 오른쪽 그리드는 선택·마감여부·마감월·입고번호·입고일·품목을 왼쪽 고정 열로 두고 가로 스크롤한다.
- **F1Grid**: 왼쪽 `purchase-closing-supplier-grid-v1`, 오른쪽 `purchase-closing-row-grid-v1`(storageKey 고유). 왼쪽에서 구매처를 선택하면 오른쪽이 그 구매처 행만, 선택이 없으면 전체 행을 보여 준다.
- **편집**: 미마감 행만 선택 가능, 단가·부가세구분(과세/영세/면세)·부가세포함(Y/N)을 셀에서 고칠 수 있다. 고칠 때마다 화면에서 미리보기 금액을 같은 규칙으로 계산해 보여 주고(저장 값은 서버 계산), 마감 행은 읽기 전용이다.
- **버튼**: `마감`(선택한 미마감 행을 선택한 마감월로 마감, 확인 창에서 건수·합계 안내), `해제`(선택한 마감 행 해제, 확인 창), `조회`, `엑셀`(기존 공용 내보내기). 선택이 없으면 비활성. 마감·해제 후 두 그리드를 다시 조회한다.
- 합계 행: 입고수량·공급가·부가세·합계.
- 입고현황에 `마감월` 열 추가(마감 전은 빈 값), 입고등록은 마감 행이 있는 입고를 열면 수정·취소를 비활성하고 안내한다.
- 로딩·오류 상태, 빈 목록 안내를 기존 화면 패턴대로 처리한다.

## 5. 검증 항목
- DB 스크립트 테스트(컬럼·CHECK·인덱스·롤백).
- 서비스: 마감월 형식, 이미 마감된 행/취소된 입고 거부, 구분·포함 조합 검증, 금액 서버 계산(과세 별도/포함, 영세, 면세, HALF_UP), 해제 대상 검증, 500건 초과.
- 매퍼: 요약 합계(마감 행은 마감 금액), `closeType` 3종, 취소 입고 제외, `FOR UPDATE`.
- 입고 잠금: 마감 행 있는 입고의 수정·행 빼기·취소 거부, 해제 후 가능.
- 프론트: 검색 기본값, 좌우 연동(구매처 선택→행 필터), 마감 후 재조회, 마감 행 읽기 전용, 미리보기 금액 계산, 확인 창, 입고현황 열.
- 실서버·브라우저: 여러 구매처·여러 행으로 마감·해제·잠금, 1280/768/375px.
