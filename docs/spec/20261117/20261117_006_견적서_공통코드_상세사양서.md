# 견적서 공통코드 상세사양서

## 기준 및 현재 확인

- [작업지시서](../../directions/20261117/20261117_006_견적서_공통코드_작업지시서.md), [계획서](../../plan/20261117/20261117_006_견적서_공통코드_계획서.md).
- 2026-11-17 기본 DB MCP `list_tables`, `describe_table`로 공통코드 그룹·항목 계약을 확인했다. 그룹별 집계 조회에서 CURRENCY, ITEM_UNIT은 존재하고 INCOTERMS, PAYMENT_TERM은 없다. 다른 테넌트의 존재 여부를 추정하지 않는다.
- 레이아웃은 기존 견적작성 및 수주등록을 유지한다. 이전 견적 사양의 세 헤더 자유입력 및 단위 편집불가 정책은 본 사양으로 대체한다.

## 데이터 흐름

| 필드 | 그룹 | 저장값 |
|---|---|---|
| incoterms | INCOTERMS | itemCode |
| paymentTerm | PAYMENT_TERM | itemCode |
| currencyCode | CURRENCY | itemCode |
| unit | ITEM_UNIT | itemCode |

- 기존 `fetchCommonCodeGroups`와 `fetchCommonCodeItems`를 사용한다. 활성 그룹 및 활성 항목만 sortOrder 순으로 선택지에 반영하며 표시명은 itemNm이다.
- 네 항목은 기존처럼 선택사항이다. 빈 값은 선택 안 함, 저장 시 기존 null 정규화를 유지한다. 고정 코드 목록을 프론트엔드 fallback으로 넣지 않는다.
- 조회 중 및 조회 실패 시 해당 select를 비활성화한다. 오류는 기존 본문 Alert와 재시도 버튼으로 알린다. 그룹 누락/활성 항목 없음도 안내하며 나머지 입력과 기존 견적 저장은 막지 않는다.
- 기존 견적의 미등록·비활성 값은 원문 표시·보존한다. 헤더의 과거 값은 disabled 메뉴로만 보여 신규 선택지로 제공하지 않는다. 그리드는 기존 원문 표시 fallback을 사용한다.
- 단위 컬럼은 F1Grid `type: 'select'`와 활성 ITEM_UNIT 옵션을 사용한다. 단위 편집은 materialId·품목 스냅샷을 초기화하지 않는다. 보기/권한 없음은 편집 불가이다.
- 작성·현황 보기/수정 공용 폼에 동일 적용한다. 현황 요약 패널의 기존 문자열 표시는 변경하지 않는다.

## Seed 및 안전성

- 신규 기본 그룹: INCOTERMS(Incoterms), PAYMENT_TERM(결제조건).
- Incoterms 기본값: EXW, FCA, FAS, FOB, CFR, CIF, CPT, CIP, DAP, DPU, DDP.
- 결제조건 기본값: CASH(현금), PREPAID(선불), NET30(30일), NET60(60일), NET90(90일). 이는 관리자가 공통코드에서 수정하는 초기 선택지이며 기본 자동선택·결제일 계산은 추가하지 않는다.
- CURRENCY와 ITEM_UNIT은 기존 코드를 재사용하며 이번 seed는 덮어쓰거나 추가하지 않는다.
- 대상 테넌트는 psql `target_tenant_id` 필수 인자로 지정한다. 없는 대상은 오류, 중복은 DO NOTHING, 기존 미사용 그룹은 오류 처리한다.
- 롤백은 업무 사용 전 전용이며 이번 seed 표시가 붙고 수정되지 않은 행만 대상으로 한다. 문자열 참조를 FK로 감지할 수 없으므로 사용 후 실행하지 않는다.
- 테이블/컬럼/FK 변경 없음. 실제 DB 적용은 수행하지 않는다.

## 검증 기준

- 활성 항목 표시명과 저장 코드가 다를 때 payload는 코드를 보낸다.
- 빈 값·미등록 과거 값·비활성 그룹·조회 실패/재시도·읽기 전용을 검증한다.
- 단위 변경 후 마스터 연결 및 계산이 유지된다.
- 견적 작성/현황/API 회귀, 빌드/lint, 375/768/1280px 실제 브라우저와 스크린샷을 확인한다.
