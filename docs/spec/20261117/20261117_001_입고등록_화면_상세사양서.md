## 2. 계산 규칙
- 부가세·금액은 가입고 사양(`20261116_012` 2절)과 같다. 헤더 금액은 행 합이며 서버가 다시 계산한다.
- 수량은 소수 2자리, 0보다 커야 한다. 발주 잔량을 넘어도 서버는 거부하지 않는다(초과 확인은 화면).
- 발주 잔량은 가입고 합으로 계산하므로 입고가 바꾸지 않는다. 무검사 입고 수량 변경은 가입고 수량으로 반영되어 잔량에 영향을 준다.

## 3. 무검사 자동 입고 (가입고 저장 연동)

가입고 저장(`MaterialArrivalServiceImpl.createArrival`) 마지막에, 저장된 가입고 행 중 `inspect_at='N'`인 행으로 입고를 만든다. 같은 트랜잭션이며 실패하면 가입고 저장도 롤백한다.
1. 무검사 행이 없으면 아무것도 만들지 않는다.
2. 헤더: 가입고의 `supplier_id`, `currency_code`, `tax_type`, `vat_included_at`, 담당자·부서를 복사하고 `receipt_dt = arrival_dt`, 번호 `MI-YYYYMMDD-NNNN`.
3. 행: 무검사 가입고 행마다 1행. `material_arrival_detail_id`, `arrival_no`, `purchase_order_detail_id`, `material_id`, 수량·단가·금액·창고·제조일·소비기한·LOT(빈값)·비고를 복사한다.
4. 헤더 금액은 입고 행 합(무검사 행만)으로 계산한다.
5. 가입고 저장 응답에 자동 입고 정보(`receiptNo`, 입고된 행 수)를 포함한다. 가입고 행 응답에는 연결된 `receiptId`, `receiptNo`를 포함한다(없으면 null).

## 4. API (`/api/v1/materials/material-receipts`)

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/{materialReceiptId}` | 저장된 입고 조회(헤더 + 행). 행에 가입고번호와 "이 행을 제외한 발주 잔량(수량 상한 참고값)" 포함 |
| PUT | `/{materialReceiptId}` | 입고 수정(행 빼기 포함) |
| POST | `/{materialReceiptId}/cancel` | 입고 취소 |

수동 등록(POST `/`)과 불러오기 후보 조회(GET `/candidates`)는 수입검사 작업에서 추가한다.

### 4.1 수정 요청
```
{
  "receiptDt", "taxType", "vatIncludedAt", "remark",
  "details": [{
    "materialReceiptDetailId",
    "receiptQty", "unitPrice", "warehouseId", "vatAmt",
    "manufactureDt", "expireDt", "remark"
  }]
}
```
- 요청에 없는 기존 행은 삭제(빼기). 행 1건 이상 필요. 새 행·구매처·가입고 연결 변경은 받지 않는다.
- 취소된 입고(`use_at='N'`)는 409. 없으면 404.

### 4.2 수정 규칙
1. 입고 헤더(`FOR UPDATE`) → 연결된 가입고 행·발주 행 순으로 잠근다.
2. 입력 검증은 가입고와 같다(수량 > 0, 단가 ≥ 0, 부가세 조합, 창고 사용 가능, 소비기한은 제조일 이후). 잔량 초과는 거부하지 않는다.
3. 연결된 가입고 행의 `inspect_at='N'`(무검사)이면 같은 변경을 가입고 행에 반영한다: 수량, 단가, 공급가·세액·합계, 창고, 제조일, 소비기한. 가입고 헤더의 `tax_type`·`vat_included_at`도 같이 바꾸고 가입고 헤더 금액을 가입고 행 합으로 다시 계산한다. (가입고일·가입고 비고는 건드리지 않는다.)
4. 빼는 입고 행이 무검사면 연결된 가입고 행도 물리 삭제한다. 가입고 행번호를 다시 매기고 금액을 다시 계산한다. **가입고 행이 하나도 남지 않게 되면 행은 이력으로 남기고 가입고 헤더만 취소(`use_at='N'`)한다**(취소된 가입고가 가입고현황에서 행과 함께 조회되도록).
5. 입고의 부가세구분·여부가 바뀌면 가입고 헤더도 같은 값으로 바꾸고, 입고와 연결되지 않은 가입고 행(같은 가입고의 검사 대상 행)의 금액도 새 부가세 설정으로 다시 계산한다(세액 직접 수정값은 초기화된다).
6. 입고 행번호를 다시 매기고 헤더 금액을 다시 계산해 저장한다. 실패 시 전체 롤백.

### 4.3 취소 규칙
- 입고 헤더 `use_at='N'`(행은 이력으로 남는다).
- 무검사 행은 연결된 가입고 행을 4.2의 4와 같이 정리한다. 가입고 행이 일부만 빠지면 그 행을 삭제하고(입고 상세의 `material_arrival_detail_id`는 `SET NULL`이 되고 `arrival_no`는 남는다), 가입고의 모든 행이 대상이면 행은 두고 가입고 헤더만 취소한다(연결은 유지되고 입고현황의 가입고번호 링크는 취소된 가입고라 비활성이다).
- 취소된 입고는 재취소 409.

### 4.4 가입고 쪽 잠금 (`validateEditable` 구현)
가입고 서비스의 수정·취소 경로에서 유효한 입고(`use_at='Y'`)와 연결된 가입고 행을 "잠긴 행"으로 본다.
- `PUT /material-arrivals/{id}`: 잠긴 행을 요청에서 빼면 409. 잠긴 행의 값(수량·단가·세액·창고·제조일·소비기한·비고)이 기존과 다르면 409. 잠긴 행이 하나라도 있으면 헤더의 가입고일·부가세구분·부가세여부 변경도 409(비고는 수정 가능). 잠기지 않은 행(검사 대상, 입고 없음)은 기존대로 수정·삭제할 수 있다.
- `POST /material-arrivals/{id}/cancel`: 잠긴 행이 하나라도 있으면 409.
- 메시지에 입고번호를 포함한다: `입고 MI-…에서 처리해 주세요.`

- 취소된 입고 수정·재취소 409.

## 7. 확정한 사항 (2026-11-17 사용자 확인)
- 한 가입고 행에 입고 여러 건 분할 가능(무검사는 1:1). 수입검사 병행 개발 여부는 입고 작업 종료 후 결정한다.
- 입고 수정은 가입고에도 반영한다. 입고 취소는 헤더 `use_at='N'`, 행은 물리 삭제 후 행번호 재정렬.
- 무검사 입고 취소는 연결 가입고 행도 정리한다(혼합 가입고는 행 단위 처리). 사용자 안내와 편의를 시스템이 제공한다.
- 취소건 조회는 모든 현황에서 정상(기본)/취소/전체 3종이다(`20261117_002`).
