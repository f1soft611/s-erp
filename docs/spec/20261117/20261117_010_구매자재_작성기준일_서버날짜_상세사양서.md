# 20261117_010 구매자재 작성 기준일 서버날짜 통일 상세 사양서

기준: [작업지시서](../../directions/20261117/20261117_010_구매자재_작성기준일_서버날짜_작업지시서.md), [계획서](../../plan/20261117/20261117_010_구매자재_작성기준일_서버날짜_계획서.md)
DB·API 변경 없음. 날짜 API는 기존 `shared/services/systemDateService.ts`의 `getSystemDate()`(`GET /api/v1/common/system-date`, 응답 `{ today: 'YYYY-MM-DD' }`)를 재사용한다.

## 1. 공통 훅 `useServerDateDefault`

위치 `frontend/src/shared/hooks/useServerDateDefault.ts`.

```ts
useServerDateDefault({ enabled, onDate, onError }): { markTouched(): void; reload(): Promise<void> }
```

- `enabled`: 신규 작성 화면이면 true. 저장된 자료를 여는 화면(수정·조회)은 false라서 조회하지 않는다.
- 마운트(또는 `enabled`가 true가 될 때) 서버 날짜를 한 번 조회해 `onDate(date)`를 호출한다. 사용자가 이미 날짜를 바꿨다면(`markTouched` 호출됨) 호출하지 않는다. 호출 후에는 touched로 본다.
- 실패하면 `onError('서버 기준일을 불러오지 못했습니다. <사유>')`만 호출하고 `onDate`는 호출하지 않는다. 브라우저 날짜로 대체하지 않는다.
- `markTouched()`: 사용자가 날짜를 직접 입력할 때 호출한다(늦게 도착한 서버 날짜가 입력값을 덮어쓰지 않게 한다).
- `reload()`: 초기화용. touched를 풀고 서버 날짜를 다시 조회해 `onDate`를 호출한다. 실패하면 `onError`.
- `onDate`·`onError`는 최신 값을 ref로 보관해 훅의 효과가 콜백 변경으로 다시 실행되지 않는다. 언마운트 후 도착한 응답은 버린다.

## 2. 화면 동작

| 화면 | 필드 | `enabled` | 서버 날짜를 쓰는 시점 |
| --- | --- | --- | --- |
| 구매요청등록 | 요청일 | 요청 ID 없음 | 최초 진입, `resetToNew`. 서버 날짜는 날짜와 baseline을 함께 갱신해 변경감지에 잡히지 않는다 |
| 구매요청확정 | 확정일 | 항상(신규 모드) | 최초 진입, `resetToNew`, 요청 불러오기 후 새 확정 폼 설정 |
| 발주등록 | 발주일 | 발주 ID 없음 | 최초 진입, `resetToNew` |
| 가입고등록 | 가입고일 | 가입고 ID 없음 | 최초 진입, `resetToNew` |
| 입고등록 | 입고일 | 입고 ID 없음 | 최초 진입, `resetToNew` |
| 자재수입검사등록 | 검사일 | 검사 ID 없음 | 최초 진입, `resetToNew` |

- 초기 날짜 값은 빈 문자열이다(서버 날짜 도착 전에는 채우지 않음).
- `resetToNew`는 날짜를 비우고 `reload()`를 호출한다.
- 날짜 입력의 `onChange`에서 `markTouched()`를 호출한다.
- 서버 날짜 적용은 `setDirty`를 호출하지 않는다.
- 저장된 자료를 열면(`applyLoaded`) 저장된 날짜가 그대로 설정된다. 이때 `enabled`는 false라 서버 날짜가 덮어쓰지 않는다.
- 구매요청확정은 한 페이지에서 신규 확정(요청 불러오기)과 저장된 확정 조회를 모두 다룬다. 최초 진입의 서버 날짜는 신규 모드에서만 쓰고, 저장된 확정을 연 뒤에는 저장된 확정일을 유지한다(`loaded`가 있으면 무시).

## 3. 오류 표시
- 각 화면의 기존 오류 영역(`setError`)에 `서버 기준일을 불러오지 못했습니다. …`를 표시한다. 날짜는 비어 있고 사용자가 직접 입력할 수 있다.

## 4. 검증 항목
- 훅: 도착 시 `onDate` 1회, 실패 시 `onError`만(로컬 날짜 없음), `enabled=false`면 요청 없음, `markTouched` 후 늦은 응답 무시, `reload` 재조회, 언마운트 후 응답 무시.
- 화면별(가입고·입고·검사·요청·확정·발주): 서버 날짜가 브라우저 날짜와 다를 때 서버 날짜가 표시된다. 조회 실패 시 날짜가 비고 오류가 표시된다. 초기화 후 서버 날짜가 다시 적용된다. 저장된 자료를 열면 저장된 날짜가 유지된다. 서버 날짜 적용만으로 저장하지 않은 변경 경고가 뜨지 않는다.
- 기존 구매자재 화면 테스트 전체가 통과한다.
- 실제 브라우저: 서버와 브라우저 시계가 다른 상태에서 여섯 화면의 기본 날짜가 서버 날짜.
