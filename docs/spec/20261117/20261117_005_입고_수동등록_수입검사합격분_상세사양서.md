## 2. 수량 규칙

- 입고 가능량(검사 행) = `pass_qty − Σ(유효 입고의 receipt_qty)`. 유효 입고 = 입고 헤더 `use_at='Y'`, 연결 = 입고 행의 `material_inspection_detail_id`.
- 한 행의 입고수량 상한 = 그 검사 행의 입고 가능량. 수정 시에는 이 입고 자신의 기존 수량을 합에서 뺀다(`excludeReceiptId`).
- 수량은 소수 2자리·0 초과. 단가는 0 이상. 금액·부가세는 입고 헤더의 부가세 설정으로 기존 `PurchaseOrderAmountCalculator`가 계산한다.
- 발주 잔량은 가입고 합과 불합격 합으로만 계산하므로 입고는 발주 잔량을 바꾸지 않는다(검사 대상 행).

## 3. API (`/api/v1/materials/material-receipts`)

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| GET | `/candidates` | 입고 대상 수입검사 합격분 목록(불러오기 창) |
| POST | `/` | 입고 수동 등록 |
| GET | `/{materialReceiptId}` | (기존) 응답 행에 검사 연결 정보 추가 |
| PUT | `/{materialReceiptId}` | (기존) 검사 연결 행 수량 상한 검증 추가 |
| POST | `/{materialReceiptId}/cancel` | (기존) 변경 없음. 검사 연결 행은 가입고·검사를 건드리지 않는다 |

### 3.1 후보 조회
- 조건: `fromDt`, `toDt`(검사일 기간), `keyword`(검사번호·가입고번호·발주번호·구매처·품목).
- 대상: 정상 검사(`ih.use_at='Y'`)의 행 중 연결 가입고 행이 남아 있고 가입고가 정상(`ah.use_at='Y'`)이며 입고 가능량 > 0.
- 응답: `materialInspectionDetailId`, `inspectionNo`, `inspectionDt`, `materialArrivalDetailId`, `arrivalNo`, `supplierId`, `supplierCode`, `supplierName`, `currencyCode`, `taxType`, `vatIncludedAt`(가입고 헤더 기준), `purchaseOrderDetailId`, `orderNo`, `materialId`, `materialCode/Name/Spec`, `unit`, `passQty`, `receivedQty`, `receivableQty`, `unitPrice`, `warehouseId`, `warehouseName`, `manufactureDt`, `expireDt`(가입고 행 값). 정렬은 검사일·검사번호 내림차순, 행번호 오름차순, 최대 500행. `total`은 조회 조건과 무관한 전체 입고 가능 행 수다.

### 3.2 등록 요청
```
{
  "receiptDt", "taxType", "vatIncludedAt", "remark",
  "details": [{
    "materialInspectionDetailId",
    "receiptQty", "unitPrice", "warehouseId", "vatAmt",
    "manufactureDt", "expireDt", "remark"
  }]
}
```
- 검증: 입고일 필수, `details` 1~200건, 검사 행 ID 중복 불가(400), 부가세 구분·포함 조합(영세·면세는 포함 불가), 수량 > 0(소수 2자리), 단가 ≥ 0, 창고 사용 가능, 소비기한은 제조일 이후, 비고 500자 이내.
- 행 상태 검증(검사 행을 ID 순서로 헤더와 함께 `FOR UPDATE` → 같은 행 재조회): 검사가 정상, 연결 가입고 행이 남아 있고 가입고가 정상이어야 한다(아니면 409 `입고할 수입검사 품목이 변경되었습니다`). **구매처가 모두 같고 통화가 모두 같아야 한다**(아니면 400). `receiptQty ≤ 입고 가능량`(초과 409, 메시지에 품목·검사번호·가능량).
- 처리: 번호 `MI-YYYYMMDD-NNNN`(입고일 기준, 키 `MATERIAL_RECEIPT_NO`), 헤더 = 구매처(가입고 헤더 값), 통화, 요청의 부가세 설정, 담당자·부서 = 로그인 사용자(`PurchaseRequestDAO.selectRequester`), 행 = 요청 순서대로 행번호, `material_arrival_detail_id`·`arrival_no`(가입고 행), `material_inspection_detail_id`·`inspection_no`, 발주 행·품목, 입고창고 요청값, `lot_no` NULL. 헤더 금액은 행 합. 같은 트랜잭션, 하나라도 실패하면 롤백. 응답 `item`은 저장된 입고(헤더 + 행).

### 3.3 입고 조회·수정 변경
- 조회 응답 행에 `materialInspectionDetailId`, `inspectionNo`, `receivableQty`(검사 연결 행의 상한 = 입고 가능량 + 이 입고의 기존 수량, 무검사 행은 null)를 추가한다.
- 수정: 검사 연결 행(`material_inspection_detail_id` 있음)은 검사 행을 `FOR UPDATE`한 뒤 재조회해 `receiptQty ≤ 입고 가능량 + 자기 기존 수량`을 검증한다(초과 409). 가입고·검사에는 반영하지 않는다(`inspect_at='Y'`). 행 빼기는 기존 규칙(모든 행을 뺄 수 없음). 무검사 행의 기존 동작(가입고 반영, 발주 잔량 초과는 거부하지 않음)은 그대로다.
- 취소: 헤더만 취소하며 입고 가능량은 합계에서 빠지는 즉시 복구된다. 가입고·검사 행은 그대로다.

### 3.4 수입검사 서비스 변경 (`/api/v1/quality/material-inspections`)
- 조회 응답 행에 `receivedQty`(유효 입고 합), `receiptNo`(가장 최근 유효 입고번호, 없으면 null)를 추가한다.
- 수정(PUT): 기존 행 중 `receivedQty > 0`인 행은 ① 요청에서 빼면 409, ② `passQty < receivedQty`이면 409(`수입검사 QI-…의 합격분이 입고 MI-…에 입고되어 합격량을 줄이거나 행을 뺄 수 없습니다. 입고 MI-…에서 처리해 주세요`). 불합격량·비고·검사일·검사자와 합격량 증가(대기량 범위)는 허용한다.
- 취소(POST cancel): 유효 입고가 연결된 행이 하나라도 있으면 409(입고번호 안내). 입고가 모두 취소되면 다시 가능하다.
- 검사 서비스는 입고 서비스를 호출하지 않고 검사 DAO가 `tb_material_receipt_dt/hd`를 읽는다. 검사 헤더 잠금(`selectInspectionForUpdate`)은 기존 그대로다.

### 3.5 입고현황 변경 (`/api/v1/materials/material-receipt-status`)
응답 행에 `inspectionNo`(없으면 null)를 추가한다. 검색 조건은 바꾸지 않는다.

## 4. 화면

### 4.1 입고등록 (`materials/receipt/create`) — create 모드 활성화
- create 모드는 신규 등록이다(`loaded` 없음). 저장 권한은 기존대로 입고등록 메뉴 UPDATE.
- 위쪽 안내: "입고 가능한 수입검사 합격분 N건이 있습니다. 수입검사 불러오기로 입고할 품목을 담으세요. 무검사 품목은 가입고를 저장하면 입고가 자동으로 등록됩니다."(N = 후보 `total`, 0이면 "입고 가능한 수입검사 합격분이 없습니다.").
- 헤더: 입고번호(저장 후 표시), 입고일(기본 오늘), 구매처(읽기 전용, 첫 불러오기 행에서 정해짐), 담당자(읽기 전용 "로그인 사용자"), 부가세구분·포함(첫 행의 설정이 기본값, 변경 시 행 금액 재계산), 통화(읽기 전용), 비고, 합계.
- **수입검사 불러오기 창**: `수입검사 합격분 선택`(기존 틀 교체). 검색(검사일 기간, 통합 검색어), 다중 선택 그리드(검사번호, 검사일, 가입고번호, 구매처, 발주번호, 품목코드·명, 규격, 단위, 합격량, 기입고, 입고 가능량). 첫 체크 행의 구매처를 칩으로 고정하고 다른 구매처 행은 선택에서 제외하며 안내 문구를 보인다(칩 ✕로 초기화). 통화가 다른 행이 섞이면 담지 않고 안내한다. 이미 그리드에 담긴 검사 행은 목록에서 뺀다.
- 그리드 행(create·edit): 검사번호(읽기 전용, 검사 연결 행만), 가입고번호, 발주번호, 품목코드·명·규격·단위, 가입고수량, 입고 가능량(검사 연결 행의 상한, 읽기 전용), 입고수량(편집, 기본 = 입고 가능량), 입고단가, 공급가·세액·합계, 입고창고, 제조일, 소비기한, LOT번호(빈값), 비고. 기존 `잔량` 열은 무검사 행에만 값이 있다.
- 검증: 검사 연결 행의 입고수량이 입고 가능량을 넘으면 저장 전에 그 행 오류와 메시지로 막는다. **발주 잔량 초과 확인창은 무검사 행에만 적용**하고 검사 연결 행에는 적용하지 않는다. 담은 행이 없으면 저장 불가(create). 저장 성공 시 "입고를 등록했습니다. 입고번호: MI-…"를 알리고 입력을 초기화하며 후보 건수를 다시 조회한다. 수정 모드 동작은 무검사 입고와 같다(취소·행 빼기 확인창의 가입고 안내는 무검사 행이 있을 때만).
- 그리드 `storageKey`: create는 `materials-material-receipt-create-grid-v1`(기존), 수정·조회는 `materials-material-receipt-detail-grid-v1`(기존), 불러오기 창은 `materials-material-receipt-inspection-picker-grid-v1`(기존). 컬럼이 늘어도 키는 유지한다.

### 4.2 입고현황 (`materials/receipt/status`)
목록 컬럼에 `검사번호`(가입고번호 옆, 링크 없음)를 추가하고 상세 패널 품목 표에도 검사번호를 보인다. 상세 패널의 가입고번호 링크는 기존 그대로다.

### 4.3 자재수입검사 (`quality/inspect`) — 제한 표시
- 수정 다이얼로그(등록 화면 embedded)에서 입고된 합격분이 있는 행(`receivedQty > 0`): 행에 `기입고(입고)` 정보를 보이고 합격량 입력의 최소값을 `receivedQty`로 검증한다. [선택 행 빼기]로 뺄 수 없고 시도하면 "입고 MI-…에 입고된 품목은 뺄 수 없습니다. 입고에서 처리해 주세요."를 보인다. [검사 취소]는 비활성화하고 안내 문구에 입고번호를 보인다.
- 그리드에 `입고량`(읽기 전용) 열을 추가한다. 검사현황 목록 컬럼은 바꾸지 않는다.

## 5. 검증 항목
- 후보: 입고 가능량 > 0인 정상 검사 행만, 취소된 검사·취소된 가입고 제외, 취소된 입고는 합계에서 제외, 일부 입고 후 가능량 감소, 전량 입고 후 목록에서 제외.
- 등록: 같은 구매처 여러 검사 행을 한 입고로 저장, 구매처·통화 혼합 400, 중복 행 400, 가능량 초과 409, 번호 형식, 가입고·검사 행 불변, 롤백.
- 수정: 상한 = 가능량 + 자기 수량, 행 빼기, 취소된 입고 수정 409, 무검사 입고 수정 회귀 없음.
- 취소: 헤더만 취소, 취소 후 입고 가능량 복구와 후보 재등장, 재취소 409.
- 수입검사 제한: 입고된 합격분이 있으면 취소·행 빼기·합격량 축소 409(입고번호 안내), 불합격량·비고 수정 허용, 입고 취소 후 다시 가능.
- 화면: 구매처 고정·통화 혼합 안내, 저장 payload, 가능량 초과 검증, 무검사 행 초과 확인창 유지, 현황 검사번호 열, 수입검사 화면의 행 잠금·취소 비활성.

## 6. 확정한 사항 (2026-11-17 사용자 확인)
- 입고수량은 입고 가능량(합격량 − 기입고)을 넘을 수 없다(서버 거부, 초과 확인창 없음).
- 한 입고는 구매처 1곳·통화 1종이며 첫 선택 행으로 고정한다. 부가세 설정은 첫 행 설정이 기본값이고 화면에서 바꿀 수 있다.
- 입고된 합격분이 있는 수입검사는 취소·행 빼기·합격량 축소가 제한되고 입고번호를 안내한다(불합격량·비고 수정은 허용). 입고를 취소하면 제한이 풀린다.
- 입고 취소는 입고 헤더만 취소하고 가입고·검사는 그대로 둔다. 합격분의 입고 가능량이 복구되어 다시 입고할 수 있다.
