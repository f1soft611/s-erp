# F1-Grid 날짜 검색 기본값 상세 사양서

## 1. 검색 metadata 계약

날짜 컬럼의 검색 metadata에서 상세검색 날짜 범위의 시작과 종료 기본값을 각각 설정한다. 이 설정은 상세검색에만 적용하며 F1-Grid 셀 또는 신규 행의 기본값이 아니다.

```ts
type F1GridDateDefault =
  | { type: 'fixed'; year: number; month: number; day: number }
  | {
      type: 'systemDate';
      offset?: { years?: number; months?: number; days?: number };
    };

type F1GridDateRangeDefault = {
  from?: F1GridDateDefault;
  to?: F1GridDateDefault;
};
```

검색 옵션은 다음 선언 형식을 사용한다.

```ts
search: {
  defaultValue: {
    from: { type: 'systemDate', offset: { months: -1 } },
    to: { type: 'systemDate' },
  },
}
```

- `fixed`는 실제 달력 날짜여야 한다. 예: 2026년 10월 20일.
- `systemDate`는 서버 응답 날짜를 기준 날짜로 사용한다.
- offset은 선택적으로 정수 `years`, `months`, `days`를 포함한다.
- 계산은 연도 → 월 → 일 순서다. 월말 날짜가 대상 월에 없으면 대상 월의 말일로 보정한다.
- `from`과 `to`는 독립적으로 설정한다. 생략한 endpoint는 빈 값으로 둔다.
- 잘못된 날짜, 잘못된 offset, 날짜 필드가 아닌 곳의 default metadata는 명시적 설정 오류다. 임의의 빈 날짜로 변환하지 않는다.

## 2. 백엔드 시스템 날짜 API

- Method/path: `GET /api/v1/common/system-date`
- 인증: 로그인 사용자 대상의 기존 `/api/v1` 공통 API 보안 정책을 따른다.
- 날짜 출처: `EgovDateUtil.getToday()`의 `yyyyMMdd` 결과를 `LocalDate.parse(value, DateTimeFormatter.BASIC_ISO_DATE).toString()`으로 ISO 날짜로 정규화한다. 현재 `getCurrentDate(String)`은 `"yyyy-MM-dd"`를 올바른 패턴 인자로 전달하지 못하므로 사용하지 않는다.
- 응답: 기존 `ResultVO` envelope에서 `result.today`가 `yyyy-MM-dd` 형식의 실제 날짜 문자열이다.
- DB 연결, 업무 데이터 조회, 스키마 변경은 수행하지 않는다.

프런트엔드 `apiGet`은 표준 envelope를 해제한 `result` 객체를 전달받으며, `systemDateService`가 실제 날짜 여부를 검증한다. 응답 형식 또는 날짜가 유효하지 않으면 성공값처럼 처리하지 않고 오류를 발생시킨다.

## 3. 프런트엔드 기본값 처리

1. `toPageSearchFields`가 날짜 검색 metadata의 `defaultValue`를 상세검색 field에 보존한다.
2. resolver는 metadata를 검증하고, system date endpoint가 필요한 경우 한 번만 호출한다.
3. resolver는 모든 기본값을 `{ [field]: { from, to } }` 형태의 상세검색 값으로 변환한다. 생략된 endpoint는 빈 문자열이며 기본값 없는 필드는 resolver 결과에 포함하지 않는다.
4. `usePageSearchDefaults`는 `values`, `loading`, `error`, `retry`를 제공한다. 성공 전 `values`는 null이고, 실패 시 error와 retry를 제공한다.
5. `PageSearchArea`는 값이 명시되지 않은 필드에 대해 resolved `defaultValues`를 표시한다. 초기화 시 resolved default map을 적용하고 `onDetailValuesChange`를 호출한다.
6. 공통 검색 영역은 초기화만으로 검색을 실행하지 않는다. page가 `onDetailReset`을 제공한 경우에만 page가 초기화 조건을 적용하고 조회한다.
7. 브라우저 `Date`, `new Date()`, `Date.now()`로 system date 기본값을 계산하거나 API 실패를 대체하지 않는다.

## 4. 문서현황 동작

- `submittedAt` 컬럼 metadata에 `from = server date - 1 calendar month`, `to = server date`를 선언한다.
- 최초 기본 검색은 서버 기본값 해석 완료 후 시작한다. 해석 전 또는 실패 상태에서 빈 날짜 필터 목록 요청을 보내지 않는다.
- 유효한 세션 snapshot이 있으면 세션의 검색어와 상세검색 값을 기본값보다 우선한다.
- 유효 세션이 없으면 기본값 해석 후 해당 검색어/상세검색/적용 필터를 설정하고 session snapshot을 저장한다.
- 기본값 API 요청 중에 임시 null/빈 상태가 저장되어 기존 snapshot을 덮어쓰지 않도록 session persistence를 지연한다.
- 초기화 callback은 검색어를 비우고 기본값이 선언된 필드에는 resolved 값을, 나머지 필드에는 빈 값을 적용한다. 같은 값을 목록 필터와 session snapshot에 저장한다.
- 기본값 API 오류는 명시적으로 보여주며 retry는 system date resolver를 다시 실행한다. 브라우저 날짜로 fallback하지 않는다.

## 5. 달력 계산 및 오류 검증 사례

- 고정 `2026-10-20` → `2026-10-20`
- 기준 `2026-10-20`, 1개월 전 → `2026-09-20`
- 기준 `2026-03-31`, 1개월 전 → `2026-02-28`
- 기준 `2024-03-31`, 1개월 전 → `2024-02-29`
- 기준 `2026-03-01`, 1일 전 → `2026-02-28`
- 누락 endpoint → 빈 값
- 2월 30일, 비정수 offset, 잘못된 API 날짜 → 오류
- system-date API 실패 → retryable error, browser-clock fallback 없음, 기본값 의존 첫 목록 요청 없음

## 6. 비범위

- 날짜별 시간대 또는 시각 검색
- DB 스키마/쿼리/업무 데이터 API 변경
- 검색 metadata가 아닌 행/셀 편집 기본값
- 기본값이 없는 검색 필드의 reset 의미 변경
