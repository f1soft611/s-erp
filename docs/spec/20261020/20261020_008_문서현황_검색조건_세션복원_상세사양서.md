# 20261020_008 문서현황 검색조건 세션 복원 상세사양서

## 1. 저장 형식

- Storage: 브라우저 `sessionStorage`
- Page key: `s-erp:page:document-status`
- 버전: `1`
- 저장값:

```ts
type DocumentStatusSearchSession = {
  keyword: string;
  detailValues: Record<string, PageSearchFieldValue>;
};
```

- 목록 필터는 저장값에서 `toDocumentStatusFilters(keyword, detailValues)`로 다시 생성하며 별도 저장하지 않는다.
- 사용자/인증 토큰, 선택 행, 상세 패널 열림 여부, 그리드 레이아웃은 포함하지 않는다.

## 2. 초기 진입 및 복원

1. 공통 `usePageSessionState`가 key/version으로 저장값을 읽고 타입 validator를 실행한다.
2. 저장값이 없으면 기존 동작대로 결재신청일 최근 1개월을 기본 상세 값 및 초기 API 필터로 사용한다.
3. 유효한 저장값이 있으면 `keyword`와 `detailValues`를 검색 UI에 복원하고 동일 값에서 필터를 계산해 자동 조회한다.
4. 초기화 상태는 `{ keyword: '', detailValues: { submittedAt: { from, to } } }`로 저장한다. 결재신청일은 초기 진입과 같은 최근 1개월 기본 범위이며, 나머지 검색조건은 비어 있다.
5. 잘못된 구조 또는 version은 공통 훅의 정책대로 폐기하고 기본 상태로 시작한다.

## 3. 검색 적용과 미적용 입력

- 빠른 검색 또는 상세검색의 검색 실행 시 현재 화면 입력의 snapshot을 저장하고 그 snapshot에서 API 필터를 계산한다.
- 상세검색 버튼과 빠른 검색 버튼은 같은 적용 경로를 사용한다.
- 사용자가 검색어 또는 상세검색 입력을 변경해도 검색을 실행하기 전에는 저장 snapshot 및 현재 조회 결과를 변경하지 않는다.
- 적용할 상세 입력 객체는 중첩 date-range 객체를 포함해 새 객체로 snapshot하여 UI 입력 변경과 기존 세션 상태가 참조를 공유하지 않도록 한다.

## 4. 초기화

- `검색 조건 초기화` 실행 시 빠른 검색어와 결재신청일 외 상세검색 값을 지운다.
- 결재신청일 입력은 초기 진입과 동일한 최근 1개월 기본 범위로 되돌린다. 기본 범위를 포함한 조건으로 목록을 즉시 다시 조회한다.
- 세션에는 `{ keyword: '', detailValues: { submittedAt: { from, to } } }` 형태의 초기화 snapshot을 기록한다.
- 페이지를 나갔다 돌아와도 빠른 검색어와 기타 상세조건은 비어 있고, 저장된 기본 결재신청일 범위로 조회한다.

## 5. 검증 기준

- 기존 날짜 기본값 및 첫 목록 조회 회귀 없음
- 저장된 빠른 검색어와 복수 상세 필드 및 날짜 범위가 UI와 요청에 일치
- 검색하지 않은 편집 입력은 저장하지 않고, 재진입 시 마지막 적용 조건만 복원
- 초기화 후 결재신청일 기본 범위의 UI, 요청, 세션 저장 및 재진입 복원 일치
- 초기화 후 다른 검색조건은 제거
- 구버전·손상된 세션 데이터가 화면 오류나 잘못된 API 필터를 만들지 않음
- API/DB 계약 변경 없음
