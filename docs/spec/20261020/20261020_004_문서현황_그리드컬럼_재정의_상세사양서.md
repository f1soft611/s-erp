# 20261020_004 문서현황 그리드 컬럼 재정의 상세사양서

## 1. 데이터 의미

| API 필드 | DB 필드 | 의미 | 화면 |
|---|---|---|---|
| `electronicApprovalId` | `electronic_approval_id` | 결재 문서의 tenant 내 ID/PK | 문서번호 |
| `eabusNo` | `eabus_no` | 문서유형별 구분 코드 | 문서번호로 사용하지 않음 |
| `documentType` | `document_type` | 기안서, 업무연락 등 사용자에게 표시할 종류 | 문서종류 |

PK는 `rowKey`와 상세조회의 문서 식별자로도 사용한다. ID는 숫자 정렬과 상세검색 일치 비교를 지원한다.

## 2. 목록 컬럼

| 순서 | 필드 | 표시명 | 검색 |
|---:|---|---|---|
| 1 | `rowNumber` | No | 숨김 |
| 2 | `electronicApprovalId` | 문서번호 | 양의 정수 일치 |
| 3 | `title` | 제목 | 부분 문자열 |
| 4 | `documentType` | 문서종류 | 기존 종류 선택 |
| 5 | `documentStatus` | 결재상태 | 기존 상태 선택 |
| 6 | `submittedAt` | 결재신청일 | 시작/종료일 |
| 7 | `drafterName` | 기안자 | 부분 문자열 |
| 8 | `drafterDepartmentName` | 기안부서 | 부분 문자열 |
| 9 | `myParticipantType` | 내 결재 역할 | 승인/합의/참조 선택 |
| 10 | `myActionStatus` | 내 처리상태 | 대기/진행/승인/반려/보완 선택 |
| 11 | `currentApprovalStep` | 현재 결재단계·담당자 | 담당자명 부분 검색 |
| 12 | `approvalProgress` | 결재 진행 | 표시 전용 |
| 13 | `updatedAt` | 최종 변경일 | 날짜 범위 |

`participantName` 전체 명단 요약 및 `eabusNo` 컬럼은 그리드에서 제거한다. 단, 숨김 `participantName` 컬럼의 검색 metadata로 결재 참여자 이름 상세검색은 유지한다. 현재 결재단계·담당자는 해당 문서에서 현재 `PENDING`이며 결재/합의 유형인 가장 앞선 단계의 단계 순서와 담당자 이름을 요약한다. 활성 단계가 없으면 빈 값이다.

내 역할/처리상태는 현재 인증 사용자 ID와 일치하는 결재선 정보만 이용한다. 복수 역할/상태가 있으면 서로 다른 표시값을 구분자 `, `로 이어서 보여준다. 사용자가 기안자이면서 결재선 참여자는 아닐 때 값은 빈 문자열이다.

## 3. 상세검색/빠른검색

- 상세검색 필드는 컬럼 `search` metadata에서 생성하며 순서는 결재신청일 → 상태/종류 → 문서번호 → 제목 → 기안정보 → 결재 참여자 → 내 결재정보 → 현재 결재담당자 → 최종 변경일이다.
- 빠른검색 키워드는 문서 ID 문자열, 제목, 기안자에 부분 검색으로 적용한다. `eabusNo`는 빠른 문서번호 검색에서 제외한다.
- 상세 문서번호는 양의 정수 값만 허용하고 정확히 일치시킨다. 값이 비어 있으면 필터하지 않는다.
- 역할 허용값은 `APPROVAL`, `AGREEMENT`, `REFERENCE`다.
- 처리상태 허용값은 `WAITING`, `PENDING`, `APPROVED`, `REJECTED`, `RETURNED`다. 허용값 밖의 값은 HTTP 400으로 거부한다.
- 담당자 검색은 현재 활성 단계의 승인/합의 담당자 이름만 대상으로 부분 검색한다.
- 결재 참여자 검색은 숨김 컬럼 metadata에서 기존 `participantName` API 조건으로 생성되며 목록의 이름 나열에는 사용하지 않는다.
- 기존 날짜 범위 및 tenant/사용자 조회조건을 보존한다.

## 4. API 응답 파생값

`DocumentApprovalStatusListItemVO`의 목록 항목에 `myParticipantType`, `myActionStatus`, `currentApprovalStep`을 추가한다. 기존 문서작성 목록/피드 DTO 및 응답 shape는 변경하지 않는다. 신규 응답값은 null 대신 빈 문자열로 반환하여 화면 타입 검증을 단순하고 명시적으로 유지한다.

목록과 전체 건수 쿼리는 동일한 필터 fragment를 공유한다. 정렬 허용목록에 `electronicApprovalId`, `myParticipantType`, `myActionStatus`, `currentApprovalStep`을 추가하며 SQL 컬럼 이름은 서버 측 `<choose>`로 고정한다.

## 5. 권한·DB

- 기존 tenant ID, 기안자 ID, 참여자 ID 기반 접근 조건을 목록 및 건수 query에서 유지한다.
- 사용자별 파생 상태는 `participantUserId`와 결합해 계산한다. 다른 사용자의 결재선 정보가 현재 사용자 참여정보로 노출되지 않도록 한다.
- `tb_electronic_approval_main` 및 `tb_electronic_approval_line_info` 기존 컬럼만 사용한다. 새 스키마는 없다.

## 6. 테스트

- UI: 컬럼/검색 순서와 정확한 헤더, document ID 표시, `eabusNo`/참여자 전체 컬럼 부재, 상세검색에서 새 필터가 API query로 전달됨.
- 서비스: 새 response 필드 타입 검사, ID/참여자 역할/상태/담당자 필터의 query serialization, ID sort.
- 백엔드: 새 파라미터의 검증, 허용 값/거부 값, ID/담당자/내 역할/상태 SQL fragment, 목록과 count에 접근 제한 및 동일 필터 반영.
- 기존 상세 overlay, 신청일 기본 기간, 페이징/정렬/오류 검증은 회귀 없이 유지한다.
