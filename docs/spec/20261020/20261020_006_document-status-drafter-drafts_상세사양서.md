# 20261020_006 문서현황 기안자 역할 및 임시저장 표시 상세사양서

## 1. 내 결재 역할

- 목록 응답의 `myParticipantType`은 현재 인증 사용자가 해당 문서의 기안자이면 `DRAFTER`를 반환한다.
- 기안자 우선 규칙은 같은 사용자 ID가 결재선에 `APPROVAL`, `AGREEMENT`, `REFERENCE`로 존재해도 적용한다.
- 현재 사용자가 기안자가 아니면 기존대로 결재선의 사용자별 참여유형을 distinct 집계한다.
- UI 표시는 `DRAFTER`를 `기안`으로 변환한다. 상세검색 허용값에 `DRAFTER`를 추가한다.
- `DRAFTER` 역할 검색은 `m.drafter_id = 현재 로그인 사용자 ID`로 제한한다. 결재선 참여유형 `DRAFTER` 값은 사용하지 않는다.
- 내 처리상태 집계는 기존 결재선 기반 동작을 유지한다.

## 2. 임시저장 및 날짜 필터

- 문서현황의 결재신청일 시작/종료 필터를 적용할 때:
  - `document_status = 'DRAFT'`인 문서는 `created_at`을 기간과 비교한다.
  - 그 외 문서는 기존대로 `submitted_at`을 기간과 비교한다.
- 시작일은 해당 날짜의 00:00을 포함하고, 종료일은 다음 날짜 00:00 미만으로 처리한다.
- 시작일 또는 종료일만 지정된 경우에도 각각의 경계 조건을 동일한 상태별 날짜 기준에 적용한다.
- 기간 범위가 비어 있으면 날짜 조건을 추가하지 않는다.
- 기존 목록/건수 공통 검색 fragment를 사용하므로 두 query의 결과가 일치해야 한다.

## 3. 접근 제어

- tenant 조건과 기존 `documentReadAccess`를 유지한다.
- 임시저장은 `drafter_id`가 인증 사용자 ID인 경우만 조회 가능하다. 다른 사용자의 결재선 참여만으로 임시저장을 볼 수 없어야 한다.
- DB 테이블/컬럼, API 응답 구조 외부의 접근 정책, 상세 결재 작업은 변경하지 않는다.

## 4. 회귀 검증

- 프런트엔드: 역할 옵션에 `DRAFTER`/`기안`이 노출되고 기존 역할 검색 metadata가 유지되는지 확인한다.
- 백엔드 Mapper: `DRAFTER` 조건이 drafter ID에 결합되고, 임시저장 날짜 조건이 `created_at`, 기타 상태는 `submitted_at`을 사용하며 count에도 동일하게 적용되는지 확인한다.
- 백엔드 서비스: `DRAFTER` 필터를 허용하고 유효하지 않은 역할 값은 계속 거부하는지 확인한다.
- 기존 접근 제한 테스트를 유지해 타인의 임시저장 배제가 보존되는지 확인한다.
