# 댓글 첨부 이미지 분리 미리보기 상세사양서

## 1. 목적

문서작성과 공지작성의 댓글·답글에서 이미지 첨부를 일반 첨부파일 항목과 별도 이미지 미리보기 영역으로 분리한다. 첨부파일 이름과 다운로드 동작은 유지하고, 이미지 썸네일을 눌러 기존 확대 뷰어에서 볼 수 있게 한다.

## 2. 적용 범위

- 문서작성 피드 상세의 댓글과 답글
- 공지작성 피드의 댓글과 답글
- 현재 댓글 UI가 표시하는 기존 댓글·답글과 새로 등록한 댓글·답글
- 댓글 보기 상태의 첨부 목록과 그 아래 이미지 미리보기

댓글 목록 페이지네이션, 답글 표시/접기, 첨부 업로드·수정·삭제·다운로드, 권한, 본문 이미지, 댓글 입력기는 변경하지 않는다. 미리보기를 위해 이전 댓글 페이지를 추가 조회하지 않는다.

## 3. 표시 규칙

1. 이미지 파일을 포함한 모든 첨부파일은 기존 댓글 첨부 목록에 파일명, 파일 아이콘 및 기존 파일 동작으로 표시한다.
2. 댓글 보기 상태의 첨부파일 목록 내부에는 이미지 썸네일을 표시하지 않는다.
3. 첨부파일 목록 바로 아래에 별도 이미지 미리보기 영역을 표시한다.
4. `mimeType`이 `image/`로 시작하고 Blob 미리보기 URL이 준비된 첨부만 썸네일로 표시한다. 이미지가 아닌 파일은 이 영역에서 제외한다.
5. 썸네일은 기존 본문 미리보기 기준과 동일하게 너비 112px, 높이 76px로 표시하고 가로 방향으로 배치한다. 이미지 영역은 컨테이너 밖으로 페이지 가로 스크롤을 만들지 않는다.
6. 각 썸네일은 키보드로 실행 가능한 버튼으로 제공하고 접근 가능한 이름은 `댓글 이미지 미리보기 {순번}: {파일명}`으로 구성한다. 이미지 대체 텍스트는 파일명을 사용한다.
7. 썸네일 클릭 시 선택된 이미지의 URL과 대체 텍스트로 해당 페이지의 기존 `ImageViewerDialog`를 연다. 기존 닫기 동작은 그대로 사용한다.
8. 첨부파일을 편집 중인 목록의 표시, 댓글 작성/수정 입력, 업로드 동작은 변경하지 않는다.

## 4. 이미지 데이터와 로딩

### 4.1 문서 댓글

- 문서 상세 화면이 댓글의 이미지 MIME 유형을 기준으로 기존 인증된 댓글 파일 Blob 조회를 실행한다.
- 응답 Blob에서 object URL을 생성해 공통 댓글 UI 모델의 `previewUrl`로 전달한다.
- 댓글 이미지 Blob을 가져오지 못한 경우 해당 첨부는 파일 목록에서 계속 사용할 수 있게 두고, 미리보기 영역에 `이미지 미리보기를 불러오지 못했습니다.`를 표시한다.

### 4.2 공지 댓글

- `toNoticeCommentTree`는 파일 ID, 파일명, 크기와 함께 응답의 `mimeType`을 댓글 UI 모델에 보존한다. `mimeType`이 없을 때만 `contentType`을 사용한다.
- 새 댓글과 댓글 수정 과정에서 업로드한 파일도 동일하게 MIME 유형을 보존한다.
- 현재 댓글 UI에 로드된 댓글 트리의 이미지 첨부만 요청한다. 이전 댓글 페이지를 추가 요청하거나 본문 삽입 이미지 파일을 댓글 이미지로 취급하지 않는다.
- 인증된 공통 파일 다운로드 경로에서 Blob을 조회한다. 경로는 `/api/v1/common/files/{fileId}/download?ownerType=NOTICE_COMMENT&ownerId={commentId}`이며, 공통 `apiGetBlob` 인증 요청을 사용한다.
- 조회 성공 시 object URL을 `previewUrl`로 전달한다. 실패 시 다운로드 가능한 파일 항목을 유지하고 미리보기 영역에 `이미지 미리보기를 불러오지 못했습니다.`를 표시한다.

### 4.3 URL 생명주기

- 화면 또는 댓글 데이터 변경으로 이전 이미지 목록을 교체할 때 해당 목록에서 생성한 object URL을 모두 revoke한다.
- 비동기 조회가 진행 중인 동안 화면이나 댓글 데이터가 변경되면 만료된 결과가 현재 UI 상태를 갱신하지 못하도록 한다.
- 로그인 정보, access token, 저장소 키 또는 다른 인증 데이터를 URL·테스트 출력·문서에 포함하지 않는다.

## 5. 공통 컴포넌트 경계

- `AttachmentList`는 일반 파일 목록을 표시하는 책임을 유지한다. 기존 다른 호출부의 이미지 썸네일 동작은 기본값으로 유지하고, 댓글 보기 상태에서만 썸네일을 끌 수 있어야 한다.
- `TiptapCommentThread`는 첨부파일 목록 아래에 별도 댓글 이미지 영역을 렌더링하고, 클릭 시 페이지가 전달한 이미지 열기 콜백을 호출한다.
- 공통 댓글 컴포넌트는 인증 방식이나 API 경로를 직접 결정하지 않는다.
- 문서와 공지 페이지는 각자의 인증된 이미지 조회를 유지하고 기존 확대 뷰어 콜백을 공통 댓글 UI에 전달한다.

## 6. 오류와 호환성

- 개별 미리보기 요청 실패는 성공으로 처리하거나 숨기지 않는다. 해당 미리보기 오류를 사용자에게 알리고 첨부 파일 항목 및 다운로드 동작은 유지한다.
- 이미지 MIME 정보가 없으면 확장자를 추측해 미리보기 URL을 생성하지 않는다.
- 댓글 시스템 이벤트, 삭제 댓글, 일반 파일, 댓글 편집/삭제 권한 동작은 기존과 동일하다.
- 기존 본문 이미지 미리보기와 확대 뷰어의 동작은 변경하지 않는다.
- API 저장 계약 및 데이터베이스 스키마 변경은 없다.

## 7. 검증 기준

### 기능 및 회귀 테스트

- 공통 댓글 UI에서 이미지 파일을 포함한 첨부 이름과 아이콘이 계속 표시되고, 댓글 첨부 목록 내부에는 이미지 `<img>`가 렌더링되지 않는다.
- MIME 유형이 이미지이고 미리보기 URL이 준비된 파일만 별도 영역에 표시된다.
- 별도 미리보기에서 파일명 기반 접근 가능한 이름을 확인하고, 클릭 시 정확한 URL·대체 텍스트가 확대 뷰어에 전달된다.
- 로드 실패 시 다운로드 가능한 파일이 남고 미리보기 오류가 표시된다.
- 기본 `AttachmentList` 호출부의 기존 이미지 미리보기 동작이 유지된다.
- 문서 댓글의 기존 인증 Blob 요청, 새 댓글 이미지 표시, 실패 알림, object URL 정리를 확인한다.
- 공지 댓글의 MIME 유형 보존(최초 조회·답글·새 댓글·수정 업로드), 인증 Blob 요청, 실패 알림, object URL 정리를 확인한다.
- 댓글 목록 페이지네이션, 답글, 업로드·다운로드·삭제 및 본문 이미지 회귀 테스트를 확인한다.

### 빌드와 브라우저 검증

- 관련 Vitest 테스트와 `npm run build`를 실행한다.
- 실제 브라우저에서 375px, 768px, 1280px 너비를 확인한다.
- 문서 댓글과 공지 댓글 각각에 대해 첨부 목록 분리, 썸네일 배치, 이미지 확대 및 닫기를 확인한다.
- 결과 문서와 스크린샷은 `docs/result/20261020/comment-attachment-image-preview/`에 ASCII 파일명으로 저장한다. 사용자·tenant 데이터는 포함하지 않는다.
