# 댓글 이미지 미리보기 순서 및 테마별 확대 뷰어 상세 사양서

## 1. 목적

문서작성·공지작성 댓글과 답글에서 이미지 미리보기를 첨부파일 목록보다 먼저 노출한다. 이미지 클릭 시 라이트/다크 테마 모두에서 원본 이미지의 색상과 명암을 보존하고 전체 이미지가 비율대로 보이게 한다.

## 2. 적용 범위

- 공통 댓글·답글 UI: `TiptapCommentThread`
- 공통 확대 뷰어: `ImageViewerDialog`
- 뷰어 호출처: 문서·공지 댓글 이미지와 피드 본문 이미지
- 관련 프론트엔드 컴포넌트/페이지 회귀 테스트, 빌드, 합성 fixture 브라우저 검증

인증된 파일 Blob 조회, object URL 생성/해제, 댓글 저장/편집/삭제, 다운로드, API 계약 및 DB 스키마는 변경하지 않는다.

## 3. 화면 사양

### 3.1 댓글 표시 순서

댓글 또는 답글의 일반 표시 순서는 다음과 같다.

1. 댓글 본문
2. 이미지 MIME 첨부의 미리보기 영역
3. 전체 첨부파일 목록
4. 기존 답글/댓글 동작 영역

미리보기 영역에는 기존과 같이 로드된 미리보기 URL이 있는 이미지만 표시한다. 로드 오류는 영역 안에 기존 오류 텍스트로 유지한다. 파일 목록은 이미지 포함 모든 첨부 파일의 이름/아이콘과 기존 동작을 유지한다. 첨부 입력 배열의 이미지 순서와 일반 첨부 순서는 각각 그대로 보존한다.

### 3.2 확대 이미지 뷰어

- 다이얼로그 제목, 닫기 버튼, 표면 색은 활성 MUI 테마 palette를 따른다.
- 이미지 자체에 `filter`, `mix-blend-mode`, 밝기/대비 조정을 적용하지 않는다.
- 이미지 뒤의 캔버스는 반복 체크무늬로 투명 영역을 구별한다.
- 이미지의 가로/세로 비율은 intrinsic ratio로 유지한다. 최대 표시 크기는 사용 가능한 뷰포트 너비와 높이에 제한하며 이미지가 잘리지 않도록 `contain` 방식으로 표시한다.
- 닫기·접근성 레이블·기존 이미지 src/alt 콜백은 유지한다.

## 4. 테마 및 반응형 기준

- 라이트/다크 모두 모달 UI와 제목/닫기 아이콘 대비가 충분해야 한다.
- 원본 색상은 테마 전환에 의해 변하지 않아야 한다.
- 375px, 768px, 1280px 너비에서 다이얼로그와 이미지가 화면을 넘기지 않아야 한다.
- 실제 확인은 개인정보 및 tenant 정보가 없는 합성 이미지/댓글 데이터로 한다.

## 5. 오류 및 호환성

- Blob 미리보기 요청 실패 시 이미지 파일 행과 다운로드는 유지하고 기존 오류 상태를 보여준다.
- 미리보기 URL 수명과 stale 요청 방지 동작은 보존한다.
- 이미지 목록의 표시/클릭 실패가 다른 첨부 동작을 막지 않는다.
- API 및 DB 변경은 없다.

## 6. 검증 기준

1. `feed-components.test.tsx`: 미리보기 DOM이 첨부파일 목록보다 앞에 있고 첨부 파일명 및 이미지 클릭 콜백이 기존과 동일하다.
2. `image-viewer-dialog.test.tsx`: 라이트/다크 테마의 surface, 체크무늬 캔버스, 원본 src 유지, 이미지 CSS 필터 미적용을 확인한다.
3. 기존 문서/공지 댓글 이미지 테스트: 뷰어 연결, 오류 표시, 다운로드 보존이 통과한다.
4. `npm run build` 성공.
5. 실제 브라우저에서 375/768/1280px 및 라이트/다크 뷰어를 확인하고 결과 스크린샷을 보관한다.
