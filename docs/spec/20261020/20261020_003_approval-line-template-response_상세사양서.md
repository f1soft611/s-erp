## 원인

생성 서비스는 저장 결과 VO에 수정일을 설정하지 않으므로 JSON `item.updatedAt`은 null일 수 있다. 프론트엔드는 날짜가 생략되거나 문자열인 경우만 허용하여 실제 저장 성공 이후 응답 오류를 발생시킨다. 목록·상세·이름 변경도 동일 검증을 사용하므로 날짜 직렬화가 숫자인 응답을 처리하지 못한다.

## 응답 계약

- 템플릿 `updatedAt`은 선택 필드이며 문자열, 유한한 숫자형 epoch milliseconds, null을 허용한다.
- null은 생성 결과에 수정일이 포함되지 않음을 뜻하며 가짜 시각을 만들지 않는다.
- 입력 값을 변환하거나 삭제하지 않고 반환한다.
- 배열, 객체, 불리언, NaN, Infinity는 거부한다.
- ID, 이름, 문서 코드, 참여자 검증과 기존 오류 메시지는 유지한다.
- 저장·목록·상세·이름 변경에서 공통 검증을 사용한다.

예시:

```json
{
  "item": {
    "templateId": 3,
    "name": "기본 결재선",
    "eabusNo": "001",
    "updatedAt": null,
    "approvalLines": []
  }
}
```

## UI 및 검증

저장 성공 시 이름 입력창을 닫고 저장한 결재선을 선택한다. 결재선 설정창은 유지하며 작성 화면에는 기존 `적용`을 눌러야 반영된다. 저장 이후 숫자형 수정일을 포함한 목록 갱신이 성공해야 한다. 실제 API의 오류와 잘못된 응답은 기존처럼 표시한다.

회귀 테스트는 네 CRUD 응답의 null/숫자/문자열/생략 날짜와 잘못된 날짜를 검증한다. 기존 다이얼로그 테스트로 임시 상태 및 적용/취소 동작을 확인하고 브라우저에서는 모의 서버 응답을 사용하는 저장 흐름을 확인한다.

DB MCP로 기본 서버의 테이블/컬럼 메타데이터만 확인했다. 사용자·인증·tenant 데이터 행 조회 및 실제 데이터 변경은 하지 않는다. DB 스키마 변경 및 백엔드 구현 변경은 없다.
