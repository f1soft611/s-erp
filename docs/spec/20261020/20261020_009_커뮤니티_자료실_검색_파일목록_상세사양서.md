## 2. 저장 구조 및 권한

- 폴더는 인증 tenant의 `WF_ARCHIVE_CATEGORY` 공통코드 항목이다. 새 폴더/파일 테이블 및 컬럼을 만들지 않는다.
- 파일 한 건은 `tb_common_file` 한 행이며 `owner_type='ARCHIVE'`, `owner_id=tb_board_post.post_id` 관계를 유지한다. 목록은 파일 한 건당 한 행이다.
- `파일 업로드` 버튼은 tenant 관리자이면서 해당 메뉴 create 권한이 있을 때 표시한다. 파일 선택 직후 다중 파일을 각각 업로드하며 정보 입력 폼은 없다.
- `새 폴더` 버튼은 tenant 관리자이면서 create 권한이 있을 때 표시한다. 기존 `CommonCodeItemHelpDialog`로 `WF_ARCHIVE_CATEGORY` 항목을 추가한다. 분류 관리 권한은 tenant 관리자이면서 create 또는 update 권한일 때 허용하여 비활성 항목 재활성화도 가능하게 한다.
- 이름/폴더 변경은 tenant 관리자 및 update 권한, 삭제는 tenant 관리자 및 delete 권한, 다운로드는 기존 읽기/소유권 검증을 적용한다.
- 비활성 폴더는 목록에서 숨기지 않는다. 그 안의 파일은 열람/다운로드 가능하고 업로드, 이름/폴더 변경, 삭제는 막는다. 관리자는 공통코드 도움창에서 해당 폴더를 재활성화할 수 있다.

## 3. 화면 흐름

### 루트

- 자료실 루트에 `폴더` 섹션 후 `파일` 섹션을 표시한다.
- 모든 활성/비활성 분류를 폴더 행으로 표시한다. 통합검색어가 있을 때 폴더명에 같은 키워드를 적용한다.
- 루트 파일은 `category_code IS NULL` 조건으로 조회한다.

### 폴더 내부

- 폴더 선택 시 해당 분류 코드로 이동하고 `자료실 > 폴더명` 경로 및 루트 복귀 동작을 제공한다.
- 중첩 폴더는 없다. 폴더 안에는 해당 폴더의 파일만 표시한다.
- 비활성 폴더에서도 파일 이름, 작성자, 날짜, 크기 및 다운로드를 확인한다. 변경/삭제 작업과 파일 업로드는 표시하지 않거나 비활성화한다.

### 목록 행

- 컬럼 순서: `이름`, `소유자`, `올린 날짜`, `크기`, `작업`.
- 폴더 행은 폴더 아이콘/폴더명, 소유자와 크기 `—`, 사용중지 상태를 표시하고 선택 시 이동한다.
- 파일 행은 MIME/확장자 기반 파일 아이콘/파일명, 게시글 작성자, 파일 생성일시, 친숙한 바이트 단위 크기를 표시한다.
- 파일 작업은 권한에 따라 `다운로드`, `이름/폴더 변경`, `삭제`를 제공한다. 삭제 전 확인하고 진행 중 중복 요청을 막는다.
- 즐겨찾기, 파일 미리보기, 중첩 폴더는 범위에 포함하지 않는다.

## 4. 검색 동작

- 검색줄은 통합 키워드 입력과 `상세검색` 토글로 구성한다. 키워드는 현재 위치의 파일명/소유자를 검색한다.
- 상세검색은 최초 접힌 상태이며 현재 적용 날짜 조건을 함께 보여준다.
- 기본 날짜 범위는 최초 진입일 기준 최근 1년(시작일 포함, 오늘 종료일 포함)이다.
- 사용자는 날짜 시작/종료 중 하나만 지정할 수 있다. 두 날짜가 모두 비어 있으면 전체 기간으로 조회한다. 두 값 모두 있을 때 시작일이 종료일보다 뒤면 검색하지 않고 오류를 표시한다.
- 유형은 `전체`, `문서`, `스프레드시트`, `프레젠테이션`, `PDF`, `이미지`, `비디오`, `압축`이다. 기본값은 `전체`.
- MIME type이 알려진 경우 MIME을 우선한다. MIME이 없거나 `application/octet-stream`이면 파일 확장자를 소문자로 비교한다.

| 유형 코드 | 검색 UI | 확장자 fallback |
|---|---|---|
| `ALL` | 전체 | 제한 없음(알 수 없는 유형 포함) |
| `DOCUMENT` | 문서 | doc, docx, hwp, hwpx, odt, rtf, txt, md, htm, html, xml, json, sql |
| `SPREADSHEET` | 스프레드시트 | xls, xlsx, xlsm, ods, csv |
| `PRESENTATION` | 프레젠테이션 | ppt, pptx, odp |
| `PDF` | PDF | pdf |
| `IMAGE` | 이미지 | png, jpg, jpeg, gif, webp, svg, bmp, tif, tiff |
| `VIDEO` | 비디오 | mp4, mov, avi, mkv, webm, m4v, wmv |
| `ARCHIVE` | 압축 | zip, rar, 7z, tar, gz, bz2, xz |

- 특정 유형 검색은 해당 MIME 그룹 또는, MIME이 없거나 generic일 때만 해당 확장자를 반환한다. 알 수 없는 형식은 특정 유형에 임의 포함하지 않고 전체에서만 확인한다.
- 키워드/날짜/유형 조건은 현재 위치의 파일에 적용한다. 루트 폴더 목록은 날짜/유형 조건의 영향을 받지 않고 키워드만 적용한다.
- 페이지 번호와 더 불러오기는 제공하지 않는다. 조건에 맞는 모든 파일을 한 응답으로 받으며 최신 업로드순(생성 시각 내림차순, 파일 ID 내림차순)으로 표시한다.

## 5. HTTP API 계약

모든 응답은 기존 `ResultVO` envelope를 유지한다. tenant는 인증 principal에서 가져오며 요청의 tenant 값은 받지 않는다.

| Method/Path | 입력 | 결과 및 규칙 |
|---|---|---|
| `GET /api/v1/groupware/boards/archive/files` | optional `keyword`, `folderCode`, `uploadedFrom`, `uploadedTo`, `fileType` | 전체 매칭 파일을 `resultList`로 반환하고 `resultCnt`는 동일 조건 전체 개수. `offset`/`limit`은 보내지 않거나 사용하지 않는다. |
| `POST /api/v1/groupware/boards/archive/files` | multipart `file`, optional `folderCode` | 현재 폴더/루트에 즉시 파일 생성. 활성 분류만 대상으로 허용한다. |
| `PUT /api/v1/groupware/boards/archive/files/{boardFileId}` | JSON `postId`, `fileName`, nullable `folderCode` | 파일명/목적 폴더 변경. 대상 폴더는 루트 또는 활성 분류만 허용한다. |
| `DELETE /api/v1/groupware/boards/archive/attachments/{boardFileId}?postId=...` | 소유 게시글 ID | 기존 tenant/소유권 검증을 유지하고 마지막 첨부 삭제 시 게시글 정리. |
| `GET /api/v1/groupware/boards/archive/attachments/{boardFileId}/download?postId=...` | 소유 게시글 ID | 기존 인증 다운로드 및 tenant/소유권 검증을 유지한다. |

### 목록 파라미터 검증

- `uploadedFrom`, `uploadedTo`는 optional ISO 날짜(`yyyy-MM-dd`)다. 잘못된 날짜 또는 두 날짜가 역전된 경우 400을 반환한다.
- 하한이 있으면 `uploadedAt >= 시작일 00:00`, 상한이 있으면 `uploadedAt < 종료일 다음날 00:00`으로 비교하여 종료일 전체를 포함한다.
- `fileType`은 위 표의 대문자 코드 중 하나다. 누락/`ALL`은 유형 조건이 없고, 다른 값은 400이다.
- 날짜와 유형 파라미터는 SQL 필터로 적용한다. 페이지 수 제한이나 silent truncation을 두지 않는다.
- 폴더 목록 조회 시 비활성 분류도 읽기 가능해야 한다. 파일 조회 SQL은 tenant, `board_type_code='ARCHIVE'`, owner/usage, soft-delete 범위를 유지한다. 잘못되거나 다른 tenant의 폴더 코드는 결과가 없어야 한다.
- 파일 업로드/수정의 분류 검증은 기존 활성 `WF_ARCHIVE_CATEGORY` 검증을 유지한다.

## 6. 오류/로딩/빈 결과

- 검색 중에는 로딩 상태를 표시하고 중복 검색을 통제한다.
- 조회 실패는 오류 메시지와 재시도 동작으로 표시한다. 실패 시 이전 조건이나 전체 목록으로 성공한 것처럼 대체하지 않는다.
- 결과가 없으면 현재 위치와 조건에 맞는 빈 상태를 표시한다.
- 다중 파일 업로드는 각 파일 성공/실패를 구분해 알리고 일부 실패를 성공으로 표시하지 않는다.
- 이름/폴더 변경 및 삭제 실패는 원인을 표시하고, 작업 중 해당 행의 중복 조작을 방지한다.

## 7. 검증 기준

- 백엔드 서비스/컨트롤러/mapper 테스트: 날짜 형식과 역전, 한쪽 날짜만 입력, 양쪽 공백, 8개 유형, unknown MIME, tenant/file scope, 비활성 폴더 읽기, 전체 결과 및 pagination SQL 부재.
- 프론트 서비스/페이지 테스트: query 직렬화, 기본 최근 1년, 상세검색 조건 제출, 폴더 진입/복귀, 비활성 폴더의 읽기 전용 동작, 공통코드 도움창, 업로드/이름 변경/삭제 권한, 로딩/실패/빈 상태.
- 실행 명령:
