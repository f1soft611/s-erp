## 화면과 공통화

- 기안서/업무연락 공통: 읽기 전용 기안일/기안자, 구분/기안양식, 제목/본문/첨부.
- 양식 필터/본문 적용/수정 본문 교체 확인은 기존 규칙을 유지한다.
- 기안서: 기존 결재/합의/참조/결재선 설정 유지.
- 업무연락: 참조 다중 선택만 표시. 작성자는 선택 대상에서 제외. 저장과 발송 버튼 제공.
- 발송 완료 업무연락은 목록/피드/상세/현황에서 `발송완료`, 상세 참여 영역은 `참조자`로 표시. 기존 COMPLETED 필터로 조회한다.

## 탭 이동

1. 초기 조회/양식 조회/저장/이미지 업로드 중에는 이동 불가.
2. 같은 탭 선택은 아무 동작도 하지 않는다.
3. 다른 탭 선택은 수정 여부와 관계없이 항상 확인창을 표시한다. 신규 작성, 임시저장 직후, 저장 문서 재열기 모두 동일하다.
4. 문구: `결재선과 참조자는 초기화되며, 제목과 본문은 유지됩니다.` 버튼은 `취소`, `이동`.
5. 취소/ESC/바깥 클릭은 현재 상태를 보존한다.
6. 이동은 결재/합의/추가 대기 선택/참조자를 초기화한다. 기안서는 작성자 고정 단계만 복구한다.
7. 제목/본문/구분/양식/첨부/문서 ID를 유지한다. 양식 조회나 본문 교체를 발생시키지 않는다.
8. 이동 후 다시 다른 탭을 선택할 때도 항상 확인한다. 수정 감지 snapshot은 사용하지 않는다.

## API와 서버 검증

기존 임시저장/수정/submit API의 요청/응답 구조를 재사용한다.

- `documentType=BUSINESS_CONTACT`, `approvalLines`는 REFERENCE만 포함한다.
- 참조 목록은 stageOrder=1, participantOrder=1부터 연속. 사용자 중복/작성자 자신/비활성·다른 테넌트 사용자/결재·합의 행은 거부한다.
- 임시저장은 빈 참조 목록을 허용한다. 발송은 최소 1명 필요하다.
- 발송은 작성자 권한/수정 가능한 상태/조건부 갱신/트랜잭션을 기존처럼 유지한다.
- 참조 행의 actionStatus/pendingAt/actionAt/actionComment는 null.
- 발송 성공 시 `COMPLETED`로 바로 전이하고 submittedAt을 설정한다. `COMPLETED` 시스템 이벤트와 `업무연락이 발송되었습니다.` 본문을 기록한다.
- 발송 후 수신자는 기존 참여자 권한으로 문서/첨부/댓글을 조회한다. 승인/반려/보완/결재취소는 제공하지 않는다.
- 본문 이미지/첨부 저장 실패 시 오류를 표시하고 발송 성공으로 처리하지 않는다.
- 참조 행만 있는 업무연락 임시저장 재열기를 지원한다. 기안서의 기안자 행 필수 규칙은 유지한다.
- 기존 결재 진행 중 업무연락 데이터를 임의 이관하거나 변경하지 않는다.

## DB 확인 및 스키마

2026-10-20 기본 read-only MCP로 list_tables, 문서/참여자/댓글 describe_table, pg_constraint의 제한된 메타데이터 SELECT를 직접 호출했다. 데이터 행은 조회하지 않았다.

- BUSINESS_CONTACT, COMPLETED, REFERENCE 및 COMPLETED 시스템 이벤트가 현재 CHECK 제약에 허용된다.
- 참조 행은 모든 처리 필드 null이어야 하며 기존 저장 메서드가 이를 충족한다.
- 스키마/데이터 마이그레이션이 필요 없으므로 신규 SQL/롤백을 만들지 않는다.

상단 재사용, 양식 본문 적용, 참조만 발송, 참조 없이 임시저장/재열기, 참조 누락 발송 차단, 잘못된 참여자 서버 거부, 취소 시 보존, 이동 시 참여자 초기화 및 제목/본문 유지, 같은 탭 무동작, 미수정 이동, 저장 후 이동, 기안서 기본 결재 복구, 발송완료 표시, 기존 기안서 상신을 검증한다. 375/768/1280px 브라우저에서 모달 가로 넘침과 컨트롤 접근성을 확인한다.
