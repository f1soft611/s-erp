## 입력 및 안전 경계

psql 필수 변수: `target_tenant_id`, `drafter_user_id`, `reviewer_user_id`, `approver_user_id`. 모두 양의 BIGINT이며 사용자 3명은 서로 달라야 한다. `base_date`는 선택 DATE이며 기본값은 실행일이다. 생성일은 기준일보다 2~14일 앞이므로 당일 이후의 타임라인을 생성하지 않는다.

대상 테넌트 및 그 안의 활성 사용자/로그인 연결을 검사한다. 실제 이름·부서는 실행 중 내부 참조할 뿐 출력하거나 저장소에 복제하지 않는다. 기안자/댓글 작성자는 login code, 결재선 참여자는 user ID 문자열을 사용한다. 개인정보·연락처·실제 거래 정보는 합성하지 않는다.

시드 키 `S_ERP_GROUPWARE_DEMO_20261029`와 항목 번호를 본문 JSON의 `_demoSeed`에 남기며 제목에는 `[데모]`를 붙인다. 일반 댓글은 HTML 주석으로 같은 키를 식별한다. 시스템 이력은 일반 텍스트이며 문서 JSON의 집계 지문으로 보호한다. 시드/롤백은 동일 테넌트 advisory transaction lock을 사용한다. 타임아웃으로 무한 대기를 피한다.

## 생성 데이터

| 구분 | 수량/규칙 |
| --- | --- |
| 공지사항 | 8건. 생산계획, 안전교육, 재고실사, 구매마감, 품질점검, 출하, 시스템점검, 월간회의 |
| 전자결재 | 12건. 기안 6건으로 모든 문서 상태를 포함하고, 지출 3건, 근태 2건, 업무연락 1건 |
| 일반 댓글 | 공지 8건과 임시저장 외 문서 11건에 각각 루트 2건+대댓글 1건, 총 57건 |
| 결재선 | 일반 문서 11건은 기안자→검토자→최종결재자 3단계 APPROVAL. 업무연락은 검토자/최종결재자 2명 REFERENCE |
| 시스템 이벤트 | 최초 저장, 상신, 실제 처리 상태의 승인/반려/보완, 완료. 업무연락은 발송 완료와 참조확인 |
| 조회수 | 0. 실제 조회 이력 없이 임의 조회수를 부풀리지 않는다 |
| 제외 | 자료실/첨부파일/좋아요/조회/고정 이력, 계정, 업무양식 마스터, ERP 마스터/수주 |

활성 `NOTICE` 게시판과 대상 테넌트의 활성 `NOTICE_GUBUN` 그룹 내 각 시나리오 코드가 모두 있어야 한다. 누락 시 임의 분류를 추가하거나 대체하지 않고 중단한다. 기안분류는 선택 컬럼이므로 NULL을 사용한다.

JSON은 Tiptap `doc`/`paragraph`/`text` 구조로, HTML은 동일 문장들의 `p` 태그로, text는 공백으로 연결한 동일 내용으로 저장한다. `_demoSeed` 메타데이터는 편집 콘텐츠와 분리된 최상위 필드다.

## 문서 상태와 번호

- DRAFT: 상신 시각 없음, 모든 결재선 WAITING, 일반 댓글 없음.
- PENDING: 기안자 자동 승인, 검토자 PENDING, 최종 WAITING.
- IN_PROGRESS: 기안자/검토자 APPROVED, 최종 PENDING.
- COMPLETED: 모두 APPROVED. 업무연락은 결재 없이 REFERENCE 2명 중 1명 CONFIRMED.
- REJECTED / REVISION_REQUESTED: 검토자 REJECTED / RETURNED, 최종 WAITING.
- 생성 → 저장(+5분) → 상신(+1시간) → 댓글(+2시간) → 답글(+3시간) → 검토(+4시간) → 추가댓글(+5시간) → 최종승인(+8시간) 순서다. 결재 완료 문서의 완료 확인 댓글은 승인 이후인 +9시간에 작성한다.
- updated_at은 각 행에 실제 포함된 가장 마지막 이벤트 시각이다. 초기값을 마커에 기록하여 변경 검출에 사용한다.
- `EA-YYYYMMDD-NNNN` 번호를 사용한다. `(ELECTRONIC_APPROVAL_NO, tenant, issue_date)` 생성기 값을 기존 번호 최댓값 이상으로 올리고 원자적으로 한 건 예약한다. 다른 업무 생성기나 다른 테넌트 카운터는 변경하지 않는다.

## 재실행·롤백·업데이트

- 같은 테넌트에 해당 키가 있으면 전체 중단한다. 제목이 바뀌어도 JSON 마커가 있으면 중복을 막는다.
- 단일 트랜잭션으로 데이터/문서번호 카운터를 원자적으로 변경한다. PostgreSQL BIGSERIAL 시퀀스는 롤백되어도 공백이 남을 수 있다.
- 롤백은 대상 키가 있는 부모만 찾는다. 대상 건수/댓글 수가 예상과 다르거나, 삭제·수정되거나, 마커 없는 댓글/타 문서 대댓글/파일/좋아요/조회/팝업 닫기/문서 고정이 있으면 전체 중단한다.
- 결재선 전체 행의 JSONB 집계 지문을 최초 생성 시 문서 마커에 저장한다. 롤백 시 다시 비교하여 부모 수정일이 유지된 결재선 편집도 보호한다.
- APPROVED 결재선에는 합성 승인 의견을 넣지 않는다. 반려/보완 사유는 유지한다. SYSTEM은 HTML/마커 없는 일반 텍스트이며 문서의 `systemFingerprint`로 변경을 검증한다. 기존 HTML 마커 버전의 삭제 롤백도 유지한다.
- 롤백 도중 관계 테이블에 SHARE ROW EXCLUSIVE 잠금을 짧게 획득한다. 잠금은 전체 테넌트의 해당 테이블 쓰기를 일시 대기시키므로 유지보수 시간에 실행한다. 잠금 대기 제한은 5초다.
- 생성 댓글→결재선→부모 순으로 삭제한다. 시퀀스·문서번호 카운터는 되감지 않는다. 롤백 재실행은 대상이 없으면 무변경 성공한다.
- UI 편집으로 JSON 마커가 사라지면 누락 건수 검사로 자동 삭제를 중단한다. 일부 누락이 있어도 강제 정리하지 않는다.
- 신규 환경은 시드를 실행한다. 내용 변경 후 재생성은 사용자 상호작용이 없는 환경에서 롤백 후 새 버전을 실행한다. 배포된 과거 SQL을 고쳐 실DB 기존 값을 덮어쓰지 않는다.

## 확인 근거와 검증

기본 `s-erp-postgresql-readonly`의 list_tables, 대상 describe_table 및 pg_constraint 메타데이터만 확인했다. 테넌트/계정/업무 데이터 행은 조회하지 않았다.

근거: 그룹웨어 기준 DDL(`20261022_009`), 문서번호 마이그레이션(`20261028_010`), 참조확인 제약(`20261029_001`), `DocumentApproval_SQL_postgresql.xml`, `DocumentApprovalDraftSupportServiceImpl`, `DocumentApprovalInteractionServiceImpl`, 공지/자료실 Mapper.

검증은 Node 내장 테스트와 별도 메모리 PGlite PostgreSQL에서 합성 픽스처로 실행한다. 운영 PostgreSQL/MinIO/API/브라우저 적용 검증과 psql CLI 자체 실행은 하지 않으며 이 한계를 결과에 구분한다.
