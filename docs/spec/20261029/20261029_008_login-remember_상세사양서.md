# 로그인 저장 상세사양서

근거: [작업지시서](../../directions/20261029/20261029_008_login-remember_작업지시서.md), [계획서](../../plan/20261029/20261029_008_login-remember_계획서.md)

## 화면 및 상태

- 기존 입력 라벨과 배치를 유지하고 비밀번호 아래, 제출 오류/로그인 버튼 위에 `로그인 저장` 체크박스를 추가한다.
- 저장값이 없거나 유효하지 않으면 업체코드/사용자 ID/비밀번호는 빈 값이며 체크박스는 해제된다.
- 저장값이 유효하면 업체코드와 사용자 ID를 복원하고 체크박스는 선택된다. 비밀번호는 항상 빈 값이다.
- 기존 테마, 키보드 접근성, 제출/오류/라우팅 동작은 유지한다. 체크박스는 제출 중 비활성화한다.

## 브라우저 저장 계약

- 키: `s-erp-remembered-login`. 인증 세션 키와 분리한다.
- JSON 객체의 `tenantCode`, `userId` 두 문자열만 쓴다. 로그인 성공 시 두 입력값을 trim하여 저장한다.
- 비밀번호, 토큰 및 선택 상태 외 다른 인증 정보는 새 저장 항목에 포함하지 않는다. 체크 상태는 유효한 저장값 존재로 복원한다.
- 체크만 해서는 저장하지 않는다. 필수 입력 검증과 기존 로그인 성공 이후에만 저장한다.
- 체크 해제 시 해당 키만 즉시 삭제하고 현재 입력값은 유지한다. 저장하지 않는 로그인 성공 시에도 해당 키만 삭제한다.
- 로그아웃/세션 만료 시 기억한 두 필드는 유지한다. 자동 로그인이나 인증 세션 유지 기간을 변경하지 않는다.
- JSON 파싱 실패, 객체가 아닌 값, 문자열 아닌 필드, 빈 필드는 무시한다. 저장소 접근/쓰기/삭제 예외가 로그인 폼과 성공 흐름을 막지 않아야 한다.
- 저장 실패를 인증 실패로 표시하지 않는다. 저장소를 사용할 수 없으면 이번 로그인만 기존대로 수행한다.

## 검증

- Hook 테스트: 기본값, 복원과 비밀번호 제외, 성공 시 두 필드만 저장, 실패/입력 검증 시 미저장, 해제 즉시 삭제, 미선택 로그인, 잘못된 JSON/필드, 저장소 읽기/쓰기/삭제 실패.
- UI 테스트: 접근 가능한 `로그인 저장` 체크박스가 기본 해제 상태로 표시된다.
- 기존 로그인 필수 검증/성공 이동/실패/세션 및 입력 컴포넌트 테스트를 유지한다.
- Playwright: 합성 입력과 모의 인증 응답만 사용해 저장과 새로고침 후 복원, 비밀번호 빈 값, 해제 후 재진입 시 빈 값을 확인한다.
- 라이트/다크 각각 375/768/1280px에서 실제 렌더링, 가로 넘침 없음, 체크박스와 버튼 표시 및 접근성을 확인한다. 스크린샷에는 계정/인증 정보와 개발 계정 안내를 포함하지 않는다.

## 영향 범위

- 프론트엔드 로그인 폼/훅/페이지 및 관련 테스트와 문서만 변경한다.
- 백엔드, DB, API 데이터 계약 변경이 없으므로 DB MCP/SQL/스키마 이력은 대상이 아니다.
