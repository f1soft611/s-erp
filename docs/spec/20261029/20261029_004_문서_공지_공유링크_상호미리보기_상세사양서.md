# 문서·공지 공유 링크 및 공통 미리보기 상세 사양서

## 목표와 범위

문서와 공지의 내부 공유 링크 및 외부 HTTP(S) URL을 문서관리와 공지사항의 본문, 댓글, 답글에서 구분된 카드로 표시한다. 내부 링크 카드는 대상 문서/공지 상세를 연다. 기존 외부 OG API는 그대로 사용한다.

## 공유 링크와 권한

- 문서 공유는 기존 문서 토큰/URL/API/tenant·문서 조회권한 정책을 그대로 사용한다. legacy `documentId` 링크도 지원한다.
- 공지 작성자 메뉴에 `공지 공유하기`를 추가한다. 기존 문서 메뉴와 같이 인증된 발급 요청 후 URL을 클립보드에 복사하고 성공 알림을 표시한다.
- 공지 발급 endpoint: `POST /api/v1/groupware/boards/notice/posts/{postId}/share-link`.
- 공지 해석 endpoint: `GET /api/v1/groupware/boards/notice/shared-post?token={token}`.
- 공지 토큰은 암호화된 tenant ID와 notice ID만 포함하며 저장하지 않는다. AES-GCM AAD/key derivation에 공지 전용 문맥을 사용해 문서 token으로 해석될 수 없도록 한다.
- 공지 링크는 인증이 필요하다. 요청자 tenant가 토큰 tenant와 일치하고 기존 공지 상세 권한 정책으로 게시글을 읽을 수 있어야 한다. 삭제/미존재/권한 없는 대상은 generic unavailable 결과로 처리한다.
- 공지 URL은 `/groupware/community/notice?share={token}`이다. 문서 URL과 마찬가지로 token을 외부 OG API로 보내지 않는다.

## 공통 링크 분류 및 화면 동작

- 공지 공유 카드 subtitle은 `공지구분 · 작성자` 형식이다. 기존 공유 조회 응답의 `writerName`을 사용하며 공백만 있거나 누락되면 구분명만 표시한다. 작성자 ID를 이름 대신 노출하지 않는다.

- 공지 공유 카드의 subtitle은 기존 `NOTICE_GUBUN` 공통코드 항목 명칭으로 표시한다. 코드값을 하드코딩 번역하지 않으며 미등록/조회 실패 시 `공지`를 표시한다. 공통코드 조회 오류가 공지 미리보기 자체를 막지 않는다.

- 같은 origin의 문서 작성 경로 공유 token 및 지원 중인 legacy `documentId`는 시스템 문서 링크로 분류한다.
- 같은 origin의 공지사항 경로 공유 token은 공지 링크로 분류한다.
- 이 외의 유효한 외부 HTTP(S) 링크만 웹 링크 OG API로 보낸다. 현재 origin의 일반 경로, 상대 URL, malformed URL, `javascript:`, `data:` 및 localhost류 URL은 외부 미리보기 대상에서 제외한다.
- 앵커는 `href`만 추출하고, 앵커 바깥 본문 텍스트의 URL도 검색한다. 같은 본문 내 중복은 제거한다.
- document/notice/web preview는 공통 feed preview 컴포넌트를 사용한다. 내부 카드는 `시스템 문서`, `공지사항` label을 유지하고 외부 카드는 독립된 `웹 링크` label 없이 사이트명, 제목, 설명, 이미지를 표시한다. 로딩/오류 안내와 사용자가 본문에 입력한 링크 텍스트는 유지한다.
- 동일 기능 문서/공지 카드는 기존 상세 패널을 연다. 교차 기능 카드는 현재 경로/화면을 유지하고 토큰으로 확인한 대상 ID를 공통 우측 패널에서 기존 상세 API로 조회한다. 내부 카드는 새 탭이나 대상 기능 화면으로 이동하지 않는다. 패널 안의 링크는 같은 패널의 대상을 교체한다.
- 공통 패널은 모바일 767px 이하 전체 폭, 그 외 `min(975px, 72vw)`이며 닫기 버튼/ESC/배경 클릭으로 닫는다. 로딩과 실패를 표시하고 이전 대상의 비동기 결과를 버린다. 기존 본문/댓글 UI를 재사용하며 관리용 편집/삭제/고정은 원래 기능 화면에 유지한다.
- 외부 카드는 선택 시 원문 URL을 새 탭에서 연다(`target="_blank"`, `rel="noopener noreferrer"`). 미리보기 이미지는 lazy-load 및 `no-referrer`를 사용한다.
- 본문/댓글 HTML 변경 또는 컴포넌트 해제 시 늦게 도착한 요청 결과를 버린다. 실패한 미리보기는 원문 본문 저장/댓글 등록을 막지 않는다.

## 오류 처리 및 개인정보

- 내부 공유 토큰은 클라이언트/서버 로그 또는 오류 메시지에 노출하지 않는다.
- 유효하지 않거나 tenant가 다르거나 삭제/권한이 없는 링크는 동일한 일반 unavailable 상태로 표시한다.
- 공유 링크 발급 또는 클립보드 복사가 실패하면 성공처럼 처리하지 않고 기존 알림 방식으로 오류를 알린다.
- 외부 OG fetch는 기존 URL/IP 검증, DNS pinning, redirect 재검증, 응답 한계, 인증 정책을 그대로 유지한다. 외부 URL을 제3자 provider에 전송하지 않는다.

## DB와 API 데이터 계약

- 공유 token과 OG 결과는 DB에 저장하지 않는다. 테이블, 컬럼, mapper/SQL, migration을 변경하지 않는다.
- 기존 문서 API 응답과 token 호환성을 유지한다.
- 공지 resolver는 기존 공지 상세 response contract를 사용하고 신규 token field만 발급 응답 `item.token`에 반환한다.
- 읽기 전용 DB MCP `list_tables`로 public table 목록을 확인했다. tenant/data rows는 조회하지 않았다.

## 검증 기준

- 공유 API/codec 테스트의 고정 문자열 생성은 Java 8 API와 호환되어야 한다. `v1.`/`v2.` 접두사 및 58/59/60자 경계값을 유지하며 Java 11의 `String.repeat()`에 의존하지 않는다.
- Backend: 문서 token regression/byte compatibility, 문서·공지 domain token 상호 거부, notice token round-trip, tenant isolation, 로그인/권한/삭제 처리 및 controller envelope.
- Frontend: 내부 문서/공지/외부 URL 분류, legacy documentId, URL dedupe, menu owner visibility, clipboard/API failures, 본문·댓글·답글 모든 링크 종류 카드, 동일/교차 기능 우측 패널, expired/unauthorized state 및 external fallback.
- `npm run build`, 집중 Vitest/lint와 backend 집중 Maven tests를 실행한다. 기존 관계없는 전체 backend 테스트 실패는 별도로 식별한다.
- Chromium 375px/768px/1280px에서 혼합 링크, 카드 구분, 내부 상세 열기/교차 화면 이동, 외부 새 탭 및 overflow를 확인하고 스크린샷을 결과 폴더에 보관한다.
