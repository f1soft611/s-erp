## 참여자 상태 및 권한

- 확인 대상은 기안서(`DRAFTING`)와 업무연락(`BUSINESS_CONTACT`)의 참조 결재선 참여자다.
- 임시저장(`DRAFT`)은 확인할 수 없다. 업무연락은 발송 후 `COMPLETED`, 기안서는 상신 후의 모든 문서 상태에서 확인할 수 있다.
- 미확인 참조자는 확인 후 참여 행에 `action_status=CONFIRMED`, `action_at` 확인 시각을 기록한다. `action_comment`는 비워 둔다.
- `CONFIRMED` 상태는 `REFERENCE`에만 허용하며 승인·합의 처리 상태 전이에는 사용하지 않는다.
- 기존 읽기 전용 DB CHECK 제약은 참조 행의 모든 처리 필드를 NULL로 제한하고 `REFERENCE_CONFIRMED` SYSTEM 이벤트를 허용하지 않는다. 이를 변경하는 `20261029_001` migration은 참조 미확인 상태(네 필드 NULL)와 확인 완료 상태(`CONFIRMED`, `action_at` NOT NULL, 나머지 처리 필드 NULL)를 제한하고 새 SYSTEM 이벤트를 허용한다.
- 사용자/tenant 및 참여 행은 서버의 인증 정보에서 결정한다. 요청에서 사용자 ID, 참여자 ID 또는 확인 시각을 받지 않는다.
- 이미 확인한 참조자의 요청은 성공으로 응답하고 새로운 이벤트를 추가하지 않는다.

## API 및 조회 계약

- 확인: `POST /api/v1/groupware/approvals/{electronicApprovalId}/reference-confirmation`
  - 인증 사용자에게 해당 문서의 참조 참여 행이 존재하는지, 문서가 임시저장이 아닌지 서버가 검증한다.
  - 처리 상태 갱신과 SYSTEM 이벤트 추가는 동일 트랜잭션이다.
  - 처리 결과는 기존 `ResultVO` 패턴의 `item`으로 `electronicApprovalId`, `actionStatus=CONFIRMED`, `actionAt`을 반환한다.
- 미확인 목록: 기존 문서작성 문서 조회 API에 `MY_REFERENCE_PENDING` 범위를 추가한다.
  - 로그인 사용자의 `REFERENCE` 참여 행 중 `CONFIRMED`가 아닌 행이 있는 문서만 조회한다.
  - `DRAFT`, 삭제 문서는 제외하며 다른 상태의 문서(완료/반려 포함)는 포함한다.
  - tenant와 사용자 범위는 기존 `actorParams`의 인증 정보만 사용한다.
- 결재요약 API 응답에 `referenceConfirmationRequiredCount`와 `referenceConfirmationItems`를 추가한다. 참조 대기 목록은 결재 `notices`와 별도 배열이다.
- 종합현황 응답의 `approval` 객체에 동일 의미의 `referenceConfirmationRequiredCount` 및 `referenceConfirmationItems`를 제공한다. 항목은 문서 ID와 제목을 포함한다.
- `s-erp-postgresql-readonly` MCP의 테이블/컬럼 및 제한된 CHECK 제약 메타데이터를 조회했다. 행 데이터는 조회하지 않았다. `backend/DATABASE/20261029`와 `docs/database/20261029`에 동일한 SQL/변경 이력/롤백 파일을 두고 `docs/database/db-schema.md`를 갱신한다. migration 파일은 이 작업 중 실제 DB에 적용하지 않는다.

## SYSTEM 이력

- 이벤트 코드: `REFERENCE_CONFIRMED`
- 표시 문구: `문서를 확인했습니다.`
- 작성자 및 기록 시각은 기존 결재 액션 SYSTEM 이력과 같은 공통 이력 기록 경로와 화면 표시 규칙을 사용한다.
- 새 별도 로그 또는 USER 댓글을 만들지 않는다.
- 이력 등록 실패 시 확인 상태 변경도 롤백한다. 기존 문서 참여 권한이 있는 사용자는 해당 이력을 조회할 수 있다.

## 화면 요구사항

### 문서 상세

- 현재 사용자가 미확인 참조자일 때만 `확인` 액션을 표시한다.
- 클릭 중 액션을 비활성화한다. 성공하면 상세 참여 상태 및 시스템 이력을 새로고침하고, 문서작성 요약과 종합현황 대기 목록/건수를 갱신한다.
- 이미 확인했거나 참조자가 아니면 액션을 표시하지 않는다. 오류 시 기존 상세의 오류 안내를 사용하고 성공으로 보이지 않는다.

### 종합현황

- 결재 대기 및 보완요청과 분리된 `내가 확인할 문서` 영역을 표시한다.
- 미확인 건수와 문서 목록을 보여주며 선택 시 기존 전자결재 상세를 연다.
- 확인 성공 시 현황 데이터를 새로고침한다. 참조 확인은 결재 액션 수/목록에 포함하지 않는다.

### 문서작성

- `결재 요약` 패널에 별도 `내가 확인할 문서` 건수를 표시한다.
- 요약 항목을 선택하면 `MY_REFERENCE_PENDING`으로 문서 목록을 조회한다. 결재 대기와 분리하고 기존 표시 모드/문서 상태 패널의 의미는 보존한다.
- 확인 성공 후 관련 문서 목록과 요약을 갱신한다.

## 오류 처리 및 경계

- 다른 tenant, 비참조자, 임시저장, 삭제 또는 접근 불가 문서는 확인할 수 없다.
- 목록과 건수는 현재 인증 사용자 및 tenant만 대상으로 하고 문서별 중복 없이 계산한다.
- 중복 요청에서 이벤트를 중복 저장하지 않는다.
- 확인 API 응답의 `actionAt`은 서버가 저장한 참여자 행의 시각이며 요청 본문은 받지 않는다.
- 상태 저장, 이벤트 등록, 요약 조회 및 목록 조회 오류를 빈 성공 응답으로 변환하지 않는다.
- 기존 결재 액션, 상태전이, 업무연락 발송 상태, 공유 링크 조회 계약은 변경하지 않는다.

## 회귀 및 검증

- 참조자만 확인 가능, 임시저장 제외, 완료/반려 문서 확인 대상 유지, 중복 요청 멱등성, 이력 실패 시 롤백을 검증한다.
- 목록/요약/종합현황 사용자 범위, 정확한 대기 건수, 확인 후 목록 제외를 검증한다.
- 결재 요약 건수와 결재 notice에 참조 확인이 섞이지 않는지 검증한다.
- 확인 시스템 이벤트가 기존 상세 타임라인에 기존 결재 시스템 메시지와 같은 형식으로 노출되는지 검증한다.
- 관련 기존 문서작성/대시보드 테스트와 백엔드 회귀 테스트를 실행한다.
- 프론트엔드 빌드와 실제 브라우저 375px/768px/1280px 확인을 수행하고 결과 문서/스크린샷을 남긴다.

## 제외 범위

- 결재선 조정, 문서 상태 변경, 과거 문서 자동 확인
