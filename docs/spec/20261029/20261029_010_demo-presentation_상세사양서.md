# 데모 표시 보정 사양

## 원인과 정상 계약

`DocumentApprovalDraftSupportServiceImpl.insertSystemEvent`는 일반 텍스트를 저장한다. 기존 시드는 같은 필드에 `<p>…</p><!--S_ERP_GROUPWARE_DEMO_20261029-->`를 저장해 문자 그대로 표시됐다. 결재선 `action_comment`에는 합성 승인 의견을 강제로 넣었다.

- 신규 시드: APPROVED의 action_comment는 NULL, SYSTEM content는 일반 텍스트, 반려/보완은 사유 유지.
- 시스템 이력은 상태 뱃지와 정상 문구를 유지한다. 승인 도장/상태/시각을 삭제하지 않는다.
- HTML을 화면에서 강제 해석하거나 일반 사용자 댓글의 HTML을 변경하지 않는다.

## 기존 데이터 보정

- 필수 psql 변수 `target_tenant_id`; 양의 BIGINT와 테넌트 존재를 확인한다.
- `_demoSeed.key=S_ERP_GROUPWARE_DEMO_20261029` 문서만 선택한다. 문서/결재선/댓글 테이블에 짧은 쓰기 잠금, 기존 시드와 동일 advisory lock을 잡는다.
- 시스템 이력은 원본과 완전히 일치하는 합성 HTML 9종만 변환한다. updated_at=created_at이며 deleted_yn=N인 행만 대상이다. APPROVED 시스템 문구는 실제 서비스와 같은 `문서가 승인되었습니다.`로 정규화한다.
- 승인 의견은 APPROVED이면서 정확히 `검토 내용을 확인하여 승인합니다.`인 행만 NULL로 만든다. 해당 문서의 최초 결재선 지문이 현재와 다르면 전체 중단한다.
- 변경 전후 content/action_comment와 행 ID, 이전 결재선 지문을 문서 JSON의 `_demoSeed.presentationRepair`에 보관한다. DB 내부 백업이며 결과/채팅에 복제하지 않는다.
- 생성/수정/처리 시각과 문서 상태, 조회 이력, 일반 댓글, 다른 테넌트를 변경하지 않는다. 보정 후 결재선/시스템 이력 지문을 갱신한다.
- 재실행은 백업이 있는 문서를 건너뛰고 무변경 성공한다.
- 대응 복원 SQL은 변경 후 값과 지문이 동일할 때만 원래 값으로 복원하고 백업 필드를 제거한다. 수정이 있으면 중단한다.
- 삭제 롤백은 신규 일반 텍스트 SYSTEM의 지문을 검증하고, 기존 HTML 마커 버전도 허용한다. 실제 추가 이력과 의견 수정은 계속 보호한다.

## 확인과 한계

현재 DB MCP 검색 결과 도구 0개로 재확인 불가. 이전 세션 내 확인한 메타데이터, 날짜별 DDL, Mapper/Service를 대체 근거로 사용한다. `.env`나 연결 정보를 확인하지 않았다.

테스트는 메모리 PGlite에서 합성 데이터만 사용한다. 실DB/브라우저 결과를 주장하지 않는다. UI 수정이 없어 스크린샷은 해당 없음이며 사용자 첨부 이미지(계정 표시 포함)를 저장소에 복사하지 않는다.
