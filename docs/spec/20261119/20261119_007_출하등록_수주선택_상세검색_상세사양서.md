# 출하등록 수주 선택 상세검색 상세사양서

## 1. 목적 및 범위

출하등록의 `수주 선택` 모달에 기본 통합검색과 토글형 상세검색을 제공한다. 공통화는 검색 폼의 UI·상호작용에 한정하며, 대상 필드, 조회 API/조건, F1-Grid 목록 및 선택/검증은 출하등록 모달이 소유한다.

## 2. UI 및 사용자 흐름

- CommonDialog의 기존 제목, 크기, 모바일 전체화면, `선택`/`닫기` 액션과 F1-Grid를 유지한다.
- 빠른검색은 수주번호·거래처·품목을 OR로 찾는 기존 통합검색 의미를 유지한다. 현황 화면과 같이 별도 실행 버튼은 표시하지 않고 Enter로 조회하며, 입력한 검색어를 지우는 버튼은 제공한다.
- 검색 영역 끝의 상세검색 토글은 `PageSearchArea`의 공통 상세검색을 열고 닫는다. 모달 모드에서는 페이지 검색 영역의 360px 최대 폭 및 페이지 여백을 제거해 대화상자 폭에 맞춘다.
- 상세검색 패널이 펼쳐진 동안 선택 모달 전체(제목·본문·하단 액션)를 현황 상세검색 backdrop과 같은 `rgba(15, 23, 42, 0.12)`로 딤 처리한다. 상세검색 패널은 선명하게 유지하고 결과 F1-Grid의 포인터·키보드 상호작용을 막는다. 딤은 선택 모달 안에만 적용하고 앱 화면 바깥은 기존 CommonDialog backdrop 상태를 유지하며, 패널을 닫거나 검색을 적용하면 모달을 원래 상태로 복원한다.
- 검색 실행은 미납 계획 상세 결과만 갱신하고 기존처럼 선택 상태를 초기화한다. 결과 선택 방식, 다른 거래처 혼합 방지 및 응답 선택 데이터는 바꾸지 않는다.
- 로딩 중 검색을 중복 실행할 수 없고, 조회 오류는 기존 `PageMessageArea`에 표시한다.

## 3. 상세검색 필드

| 조건 | 타입 | 필수 | 동작 |
|---|---|---:|---|
| 수주일자 | 날짜 기간 | 예 | 기준일. 시작·종료 양쪽 필수. 기본값은 서버 오늘 기준 전월 시작~오늘 |
| 수주번호 | text | 아니오 | 수주번호 부분 일치 |
| 거래처 | text | 아니오 | 거래처 코드 또는 명 부분 일치 |
| 품목 | text | 아니오 | 품목 코드 또는 명 부분 일치 |
| 계획번호 | text | 아니오 | 출하계획 번호 부분 일치 |
| 계획일자 | 날짜 기간 | 아니오 | 계획일 시작/종료를 각각 입력한 경계 조건; `plan_dt`가 nullable이므로 optional |

- 수주일자 필드는 현황의 필수 기준일 패턴을 따른다. 적용조건 칩에서 제거할 수 없다.
- `오늘`, `이번주`, `이번달`, `전월`, `최근 30일` 빠른 날짜 버튼과 서버 기준일 요청 동작은 공통 검색 구현 그대로 사용한다.
- 서버 기본 날짜를 가져오지 못하면 브라우저 날짜로 대체하지 않고 오류와 재시도 동작을 제공한다. 유효한 기본 수주일자가 준비될 때까지 조회를 막는다.
- 날짜 값이 역전되었거나 필수 수주일자의 양 끝점이 없으면 검색 요청을 보내지 않고 오류를 표시한다.

## 4. 조회 API 계약

### Endpoint

`GET /api/v1/sales/deliveries/source-orders`

### Query parameters

| 이름 | 필수 | 설명 |
|---|---:|---|
| `keyword` | 아니오 | 수주번호·거래처 코드/명·품목 코드/명 OR 부분검색 |
| `orderDtFrom`, `orderDtTo` | 예 | 필수 기준 수주일자 기간 |
| `orderNo` | 아니오 | 수주번호 부분검색 |
| `customerKeyword` | 아니오 | 거래처 코드 또는 명 부분검색 |
| `materialKeyword` | 아니오 | 품목 코드 또는 명 부분검색 |
| `planNo` | 아니오 | 계획번호 부분검색 |
| `planDtFrom`, `planDtTo` | 아니오 | 계획일자 경계 조건. from만 있으면 이후, to만 있으면 이전, 둘 다 있으면 기간 |

- 필드 내 여러 컬럼 매칭은 OR이며, keyword/상세 필드/날짜 조건 간에는 AND이다.
- 수주일자는 양쪽 값이 유효한 ISO date여야 하고 시작일이 종료일보다 늦으면 요청을 거부한다.
- 계획일자는 지정된 각 endpoint만 비교하며, 양쪽 입력 시 시작일 <= 종료일이어야 한다.
- tenant ID는 요청 파라미터를 받지 않고 인증 사용자 tenant로 제한한다.
- 기존 `items` envelope, 정렬, 활성 수주·활성 계획·양수 미납 잔량 조건 및 최대 200건 제한을 유지한다. 모든 검색 필터는 LIMIT 전에 적용한다.
- DB schema 변경은 없다.

## 5. 검증 기준

### Frontend

- 상세검색 열기/닫기, 기준일 필수 표시, 기존 5개 빠른 날짜 버튼 노출을 확인한다.
- 기본값 로딩 전/실패 시 검색 차단과 오류/재시도를 확인한다.
- 통합검색 Enter와 상세검색 검색 버튼이 올바른 keyword/필터를 보낸다. 통합검색 영역에는 실행 버튼이 표시되지 않는다.
- 날짜 범위 누락·역전은 API 요청 전에 차단한다.
- 결과 갱신 시 선택 해제, 미납 행 표시, 같은 거래처 선택 제한 및 기존 출하 폼 반영을 회귀 검증한다.

### Backend

- controller parameter binding 및 tenant principal 전달
- 필수 날짜 누락/형식 오류/역전 거부
- 계획 날짜 단일 endpoint 및 기간 조건 처리
- 상세 조건 필드 간 AND, field 내 code/name OR, 통합 keyword OR
- tenant, 상태, 활성 계획, 양수 잔량, 정렬 및 limit 조건 유지

### Browser

- 375px, 768px, 1280px에서 상세검색이 modal 내부에 표시되고 빠른 날짜·필드·버튼이 잘리지 않는다.
- 좁은 화면에서도 외부 가로 overflow 없이 F1-Grid 내부에서만 가로 스크롤한다.
