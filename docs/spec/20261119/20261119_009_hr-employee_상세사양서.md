## 2. 백엔드 `egovframework.let.hr.employee`
- 구조: `controller/EmployeeApiController`, `service/EmployeeService`, `service/impl/EmployeeServiceImpl`, `domain/model/*VO`, `domain/repository/EmployeeDAO`, Mapper `mapper/let/hr/employee/Employee_SQL_postgresql.xml`; 공통 암호화 `egovframework.let.hr.common.ResidentNumberCipher`; 테스트 `src/test/.../hr/employee`.
- 접근: 개인정보라 **모든 API가 테넌트 관리자 전용**(`EgovAccessControlHelper.isTenantAdmin`, 아니면 403). 삭제 API 없음.
- API `/api/v1/hr/employees`:
  - `GET ?keyword=&status=ACTIVE|RETIRED|ALL&departmentId=` 목록(기본 ACTIVE). 통합검색은 이름·영문이름·사번·부서명·직위명·로그인 아이디·전화·이메일 부분 일치.
  - `GET /{userId}` 상세, `POST` 등록, `PUT /{userId}` 수정.
  - `GET /check-employee-no?employeeNo=&userId=` 사번 중복 확인(`available` true/false).
  - `GET /check-login-code?loginCode=` 로그인 아이디 사용 가능 여부(형식 검사 후 중복 확인, 형식이 틀리면 400).
- 응답 필드: `userId, employeeNo, userNm, englishNm, departmentId, departmentNm, positionCode, positionNm, levelId, levelNm, genderCode, genderNm, employmentTypeCode, employmentTypeNm, nativeTypeCode, nativeTypeNm, nationalityCode, nationalityNm, birthCalendarCode, birthDt, joinDt, retireDt, suspendDt, backDt, workEndDt, admissionDt, stayFromDt, stayToDt, contractFromDt, contractToDt, residentNoMasked, mobileNo, homePhoneNo, emailAddr, postalCode, address, addressDetail, realUserAt, loginId, loginCode, loginUseAt, photoImage, employmentStatus(ACTIVE|LEAVE|RETIRED), departmentManagerYn`. 주민등록번호 원문은 어떤 응답에도 없다.
- 재직상태(계산): 퇴직 = `retire_dt <= 오늘`, 휴직 = `suspend_dt <= 오늘` 이고 (`back_dt` 없음 또는 `back_dt > 오늘`)이며 퇴직 아님, 그 외 재직. 필터 ACTIVE = 퇴직 제외(휴직 포함), RETIRED = 퇴직만.
- 사번: 입력이 있으면 `영문·숫자 1~20자`로 검증하고 그대로 사용, 없으면 자동 `YYMM`(입사일 기준)+순번 2자리(99 초과 시 3자리). 순번은 `tb_id_sequence`(generator `HR_EMPLOYEE_NO`, scope `tenantId`, `YYMM`)로 증가시키고 이미 쓰는 번호는 건너뛴다. 중복은 409(`이미 사용 중인 사번입니다.`), DB 유일 인덱스 충돌도 409. 수정 시 사번 값이 바뀌어 있으면 400(`사번은 수정할 수 없습니다.`). 기존 사원(사번 없음)은 수정 때 한 번 지정할 수 있다.
- 필수: 이름, 부서(사용 중 부서), 직위, 근무형태, 입사일. 공통코드 값은 해당 그룹의 사용 중 항목인지 검증. `retire_dt >= join_dt`, `back_dt >= suspend_dt`. 이메일 형식·중복(409), 이름 100자 이하, 상세주소 등 길이 제한.
- 주민등록번호: 입력은 숫자 13자리(하이픈 허용)만 허용. 저장은 `ResidentNumberCipher.encrypt`(AES-256-GCM, 키 버전 AAD)와 `hash`(HMAC-SHA256, hex)로 `resident_no_enc/key_version/hash`에 기록하고 같은 테넌트의 중복 해시는 409. 수정 시 입력이 비어 있으면 기존 값을 유지한다. 마스킹 값(`생년월일6-성별1******`)은 저장 시점에 `resident_no_masked`로 같이 기록해, 목록·상세가 복호화 없이(키가 없거나 바뀌어도) 마스킹 값을 보여 준다. 키 환경변수 `HR_RESIDENT_NO_ENCRYPTION_KEY`(Base64 32바이트), `HR_RESIDENT_NO_ENCRYPTION_KEY_VERSION`이 없으면 주민번호가 포함된 저장은 503(`주민등록번호 암호화 키가 설정되지 않았습니다.`)로 막고 다른 항목은 그대로 동작한다.
- 실사용자·계정: `realUserAt='Y'`이고 연결된 계정이 없으면 `initialPassword`(8자 이상)가 필수이고, `loginCode`(영문·숫자·`._-` 4~30자, 테넌트 내 유일, 중복 409)는 **비우면 사번을 로그인 아이디로 쓴다**(사용자 결정). 사번이 아이디 규칙(4~30자)에 맞지 않거나 이미 쓰는 아이디면 직접 입력하도록 안내한다(400/409). 로그인 아이디는 발급 후 사원등록에서 수정할 수 없다(관리자 변경은 2-2 계정 관리에서 다룬다). 한 트랜잭션에서 `tb_login_account`(`password_hash=EgovFileScrty.encryptPassword`, `password_changed_at` NULL = 변경 필요, `profile_image`=사진, `use_at`='Y')와 `DEFAULT_USER` 역할을 만들고 `tb_user.login_id`에 연결한다. 이미 계정이 있는 사원은 계정 입력을 받지 않는다. 계정이 연결된 사원을 실사용자 'N'으로 바꾸는 것은 400(`로그인 계정이 있는 사원은 실사용자를 해제할 수 없습니다. 계정 관리에서 로그인을 미허용 처리해 주세요.`). 실사용자 'N'은 계정을 만들지 않는다.
- 사진: 데이터 URL(`data:image/(png|jpeg|webp);base64,`)만, 700KB 이하. `tb_user.photo_image`에 저장하고 연결된 계정이 있으면 `tb_login_account.profile_image`에도 같이 쓴다. 이미지를 보내지 않으면 변경하지 않고, 빈 문자열이면 지운다.
- 등록·수정 응답은 상세 응답과 같다. 모든 검증 실패는 400, 중복·상태 충돌은 409.

- 부서관리 화면의 소속 사원 목록에 사번·직위 컬럼과 재직/퇴직/전체 필터를 추가한다(기본 재직).
- **주소 검색**: 카카오(구 다음) 우편번호 서비스를 `shared/services/postcode.ts`로 연동한다. 스크립트는 처음 검색할 때 한 번만 불러오고(`https://t1.kakaocdn.net/mapjsapi/bundle/postcode/prod/postcode.v2.js`), 실패하면 팝업 상단에 오류를 보여 주며 다시 시도할 수 있다. 주소를 고르면 `zonecode`→우편번호, 도로명 주소(+법정동 `동/로/가`로 끝날 때, 공동주택 건물명을 괄호로)→주소가 채워지고 커서가 상세주소로 이동한다(MES `WHR101_CT.js`와 같은 조합 규칙, 도로명이 없으면 지번 주소). 기존 `t1.daumcdn.net`은 2026-11-30에 종료되므로 쓰지 않는다. 백엔드 CSP `script-src`에 `https://t1.kakaocdn.net`을 추가한다(`SecurityConfig`). 검색 창은 클릭 한 번에 한 번만 열고(칸 클릭은 입력창에만 연결), 스크립트를 이미 불러왔으면 클릭과 같은 동작 안에서 바로 연다. 팝업을 열 때 스크립트를 미리 불러 두어 브라우저 팝업 차단을 피한다.
- 라우트·메뉴: `DashboardContent`에 `selectedModule.id === 'hr' && currentPageKey === 'employee-manage'` 분기(`/hr/*` 라우트는 이미 있음).

## 5. 구현 중 확정한 사항
- 헤더 "조회" 버튼은 입력한 통합검색어와 적용된 상세조건(재직 구분)으로 다시 조회한다(같은 조건 재조회가 아니다).
- 내/외국인이 '외국인'이 아니면 외국인 전용 항목(국적, 취업기간만료일, 입국일, 체류기간, 근로계약기간)은 화면에서 숨기고 저장할 때 비워서 보낸다.
- 이름(파란 링크)과 맨 오른쪽 고정 "상세"(연필) 열의 버튼이 모두 등록·수정 팝업을 연다(품목관리 등 다른 목록과 같은 방식이며, 행 선택 이벤트에 의존하지 않아 같은 행을 다시 열 수 있다). 재직상태 열은 퇴사일 뒤쪽에 둔다(입사일·퇴사일로도 알 수 있는 파생 정보라 중요도가 낮다). 수정 권한이 없으면 팝업은 입력이 잠긴 조회 전용이다.
- 팝업 입력칸 정렬: 테마의 `TextField` 기본 여백(`normal`, 위 16px/아래 8px)이 날짜 입력(여백 없음)과 달라 같은 줄의 칸이 16px씩 어긋났다. 팝업 그리드에서 `TextField` 여백을 모두 0으로 하고 `align-items: start`로 맞춘다.
- 사번 칸 안내: 등록 시 "직접 입력하거나 비우면 자동 부여합니다. 부여한 사번은 변경할 수 없습니다.", 수정 시 "사번은 한 번 부여하면 변경할 수 없습니다."를 항상 보여 준다(변경 요청 문의 대응).
- 부서 선택 도움창은 **선택을 한 번만 전달**한다. 부모가 선택에 반응해 다시 그려질 때 선택 이벤트가 반복 호출되어 화면이 멈추던 문제를 사원 팝업 연동 테스트에서 발견해 고쳤고 회귀 테스트를 추가했다.
- 기존 로그인 계정이 있는 사원은 `20261119_004`가 `real_user_at`을 'Y'로 맞춘다(계정 있는 사원의 실사용자 해제를 막는 규칙과 일치시키기 위한 데이터 보정 1건).
- 신규 계정 발급 시 비밀번호 변경 시각(`password_changed_at`)을 비워 "초기 비밀번호" 상태로 둔다. 최초 로그인 시 변경을 강제하는 동작과 비밀번호 초기화·로그인 허용/미허용은 2-2(계정 관리)에서 구현한다.
- 암호화 키 환경변수는 URL-safe Base64(패딩 없음) 32바이트이며 키와 버전을 함께 설정해야 한다. 생성 예: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`. 키는 운영에서 별도 보관하고 분실하면 저장된 주민등록번호를 복호화할 수 없다.
