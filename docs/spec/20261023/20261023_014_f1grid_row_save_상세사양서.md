# F1-Grid 행별 저장 확정 상세사양서

## 승인 동작
거래처·품목은 배치 저장 성공 응답의 최종 행을 현재 행 위치에 반영한다. 전체 목록/품목 옵션 GET과 gridKey 증가는 하지 않는다. 저장 행은 검색 조건에서 벗어나도 유지하고 다음 조회에 조건을 적용한다. 최초 및 사용자 조회는 기존 로딩을 유지한다.

여기서 검색 조건은 페이지가 서버에 보내는 조회 조건이다. Grid의 기존 로컬 정렬/필터는 변경하지 않으며 그 규칙에 따른 표시 이동/숨김은 유지한다. 확정 API 반환값은 전체 현재 행 스냅샷이므로 부분 저장 소비자는 남은 dirty 행을 서버 기준 목록으로 오인하지 않는다. 두 적용 화면은 저장 중 편집을 차단하고 변경 집합 전체를 저장한다.

## API 호환
기존 `item.customers`/`item.materials` 배열은 그대로 유지한다. `item.rowIdMappings`는 요청 행의 customerId/materialId 문자열을 키로, 저장 결과의 실제 양수 ID를 값으로 하는 객체다. 임시 ID는 DB에 기록하지 않는다. 기존 ID 없는 신규 요청은 여전히 허용하되 매핑에 포함하지 않는다. 같은 요청 ID의 중복은 저장 전에 거부한다.

## 공용 확정
`F1GridSavedRow<T> = { previousRowId: F1GridRowId; row: T }`.
`acceptSavedRows(savedRows): T[]`는 모든 원본 ID 존재, 중복 원본/대상 ID 및 다른 행과의 충돌을 먼저 검증한다. 삭제 상태는 지원하지 않는다. 오류 시 아무 상태도 바꾸지 않고 예외를 발생시킨다.

성공 시 해당 행 객체를 교체하고 ID 인덱스를 갱신한다. 해당 행의 state는 normal, dirty/original/patch/previousState는 제거한다. 나머지 행 참조와 수정 상태는 보존한다. 체크 선택, 마지막 선택, 포커스, 셀 범위, 복사 범위의 ID를 전환한다. 편집 중 호출은 거부한다. 부모가 반환 배열을 rows로 동기화해도 선택을 초기화하지 않는다.

공용 응답 검증은 요청 변경 행 모두가 응답 매핑과 최종 행에 정확히 한 번 존재해야 통과한다. 배열 순서나 이름으로 연결하지 않는다.

## 오류
저장 요청 실패는 dirty와 입력을 유지한다. 서버 성공 이후 응답/화면 확정 실패는 “저장은 완료했지만 화면 반영에 실패했습니다. 조회를 다시 실행해 주세요.”를 표시하고 재저장을 막는다. 조회 성공 후 해제한다. 성공으로 위장하거나 자동으로 저장을 재시도하지 않는다.

## 검증
- 기존 수정/여러 신규 행의 서버 정규화값, 실제 ID·자동 코드 반영.
- 다른 수정 행 보존, ID 충돌/누락/중복/역순 응답, 실패의 원자성.
- 체크/포커스/범위 유지, 저장 후 후속 수정 및 변경 취소의 새 기준값.
- 양 화면 저장 후 목록/옵션 GET 추가 호출 없음 및 DOM 재생성 없음.
- 기존 성능 테스트/타입 빌드와 합성 브라우저 375/768/1280 확인.

## DB 근거
2026-10-23 기본 readonly MCP list_tables 후 tb_customer_info와 tb_material_info describe_table 직접 확인. 실제 PK는 bigint이다. 업무 데이터 행은 조회하지 않았다. DB/Mapper/SQL 변경은 없다.
