## 셀 렌더 계약

- 고정 위치 객체가 새로 생성되어도 side, offset, shadow가 같으면 표시를 다시 렌더링하지 않는다. 실제 위치/그림자 변경은 즉시 반영한다.
- draftValue는 현재 편집 셀에만 전달한다. 다른 셀은 편집 문자열 변경으로 다시 렌더링되지 않는다.
- 열 가상화가 활성화되어도 계산된 표시 인덱스 집합이 같으면 Set 참조를 유지한다.
- 일반 행의 포커스/편집/범위 상태는 해당 행의 시각적 영향으로 비교한다. 병합 열은 전역 포커스/편집 비교를 유지해 병합 그룹 갱신을 보존한다.
- 드래그 중 리사이즈 비활성화는 부모의 `data-f1-grid-selecting`과 CSS로 전달하고, pointerdown 핸들러도 최신 드래그 상태를 검사한다.
- 헤더는 편집 문자열 변경만으로 재생성하지 않으며, 비체크박스 열에서는 전체 행 체크 상태를 계산하지 않는다.
- memo로 표시를 생략한 셀도 최신 이벤트 콜백을 실행한다. 과거 편집값, 권한, 선택 상태를 캡처한 이벤트로 되돌아가면 안 된다.
- 100행 고정열 테스트에서 단일 셀 선택 후 다른 행의 표시 renderer 호출은 0회, 편집 문자열 변경 후 비편집 표시 renderer 호출은 0회여야 한다.
- 선택, 드래그, 복사, 병합, 이동, Enter/Tab 확정, Escape 취소, 고정 위치 이동, 오류 표시, 폼 기능을 보존한다.

## 저장 완료 흐름

1. 기존 배치 저장 요청과 조회 요청을 그대로 사용한다.
2. 저장 응답 후 조용한 재조회를 기다리는 동안 현재 그리드를 유지한다.
3. 재조회가 끝나면 변경 상태를 초기화하고 그리드를 새 목록으로 재생성한다.
4. 저장 실패 시 수정값을 보존한다. 저장 성공 후 재조회 실패는 기존 오류 메시지를 표시하고 이미 저장된 변경을 중복 전송하지 않도록 초기화한다.

## 검증/한계

- 합성 데이터만 사용한다. 업무 데이터나 인증 정보를 로그·결과·스크린샷에 담지 않는다.
- 실제 브라우저에서 선택·편집의 React commit 시간과 renderer 호출을 전후 비교한다.
- 375/768/1280px에서 내부 스크롤과 편집 입력을 확인한다.
- 저장 API와 DB 소요시간은 별도 원인이다. 프론트엔드 재생성 비용 개선만으로 서버 응답 속도를 보장하지 않는다.
- DB/백엔드 변경 없음.
