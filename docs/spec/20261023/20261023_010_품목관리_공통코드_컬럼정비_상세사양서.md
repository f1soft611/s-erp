## 컬럼 및 데이터 흐름

기본 순서는 `No → 품목계정코드 → 품목코드 → 품목명 → 기존 나머지 컬럼`이다. No와 세 업무 컬럼은 왼쪽 고정한다. 품목코드는 읽기 전용·서버 자동채번을 유지한다.

| 화면 | API 필드 | 공통코드 그룹 | 정렬 |
| --- | --- | --- | --- |
| 품목계정코드 | materialTypeCode | ITEM_TYPE | 기존 왼쪽 |
| 품목코드 | materialCode | 해당 없음 | 가운데 |
| 품목명 | materialName | 해당 없음 | 기존 왼쪽 |
| 단위 | unit | ITEM_UNIT | 기존 왼쪽 |
| 품목유형 | materialKind | MATERIAL_TYPE | 가운데 |
| 보관방법 | storeMethod | STORE_METHOD | 가운데 |
| 소비기한기준 | expiryedStatus | EXPIRY_STATUS | 가운데 |
| 안전재고 | safeInvoice | 해당 없음 | 오른쪽 |

공통코드 select는 목록 편집, 행 폼, 해당 필드가 이미 포함된 상세검색에 동일한 컬럼 metadata를 전달한다. 단위를 상세검색에 새로 추가하지 않는다. 저장값은 코드, 표시값은 코드명이다. 선택형 일반 필드의 빈값 옵션과 기존 행의 미등록/비활성 코드 보존 동작은 유지한다. 품목계정코드의 필수 검증은 유지한다.

`matCataType` 컬럼은 생성하지 않아 사용자 컬럼 표시 메뉴에서도 복구되지 않는다. 폼·상세검색 metadata에도 노출하지 않는다. 타입, 목록 정규화와 저장 payload에는 남겨 기존 값을 보존한다.

## 소비기한

새 선택지는 `EXPIRY_STATUS` 공통코드 중 `NONE/DAY/MONTH/YEAR`만 제공한다. 임의 status는 API/DB 계약상 허용하지 않는다. 현재 조회 행이 사용하는 허용 status가 옵션에 없으면 코드 자체를 label로 보존한다. 코드 조회 결과에 없는 다른 status를 하드코딩하여 새 선택지로 제공하지 않는다.

신규 기본값 `NONE`, 기준별 숫자 단위, `NONE` 전환 시 숫자 비움, 활성 기준 숫자 필수·양의 정수 검증은 유지한다.

## 백엔드 및 오류

기존 `GET /api/v1/co/master/materials/options`의 결과 shape(`groupCode`, `itemCode`, `itemName`)는 유지하고 조회 그룹만 다섯 개로 확장한다. 인증 tenant 조건과 그룹/상세 활성 조건 및 sort_order 정렬을 유지한다.

공통코드 조회 실패는 기존 hook의 오류 영역을 사용하며 하드코딩 값으로 성공 처리하지 않는다. DB 스키마/데이터 변경이나 신규 API는 없다. 기본 MCP에서 공통코드 두 테이블의 메타데이터 및 다섯 그룹 존재를 직접 확인했다.

## 검증 기준

- 컬럼 순서, 왼쪽 고정, 정렬, 공통코드 매핑, 폼/검색의 품목분류 제외를 Vitest로 확인한다.
- 기존 품목분류 저장값·미등록 코드 보존과 소비기한 검증을 회귀 테스트한다.
- MyBatis BoundSql로 다섯 그룹 및 tenant/활성 조건을 확인한다.
- TypeScript/Vite 빌드와 375/768/1280px 실제 브라우저 렌더링을 확인한다.
- 좁은 화면의 넓은 그리드는 기존 내부 스크롤을 사용하고 페이지 전체 가로 스크롤은 발생하지 않아야 한다.
- 기존 사용자 컬럼 설정이 이전 순서/고정을 강제하면 품목관리 전용 저장 키를 버전 변경하고 결과 문서에 안내한다.
