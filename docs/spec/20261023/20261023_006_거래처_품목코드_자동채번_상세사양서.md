## 2. 화면 계약

- `customerCode`와 `materialCode`는 각각 거래처·품목 목록 컬럼으로 계속 표시한다.
- 두 코드 컬럼은 F1-Grid 행 폼에서 숨기고, 셀 편집 및 TSV/클립보드 붙여넣기 대상에서 제외한다.
- 신규 행의 코드는 폼에서 입력하지 않는다. 저장 후 서버 응답 또는 성공 후 목록 재조회 데이터에 담긴 자동 채번 값을 표시한다.
- 기존 행의 코드는 목록에 그대로 보이며 수정 폼에서는 다루지 않는다.
- 코드 외 다른 폼 필드, 권한, 검색, 저장 오류/성공 피드백은 기존 동작을 유지한다.

## 3. API 및 서비스 계약

| 작업 | 요청 코드 값 | 저장 동작 |
| --- | --- | --- |
| 거래처 생성 | 누락, 빈 값, 임의 값 모두 가능 | 요청 값은 무시하고 기존 `customerCodeIdGnrService`로 생성한 값을 저장 |
| 거래처 수정 | 누락, 빈 값, 기존 값 또는 다른 값 | 요청 값은 무시하고 저장된 `customer_code`를 보존 |
| 품목 생성 | 누락, 빈 값, 임의 값 모두 가능 | 요청 값은 무시하고 기존 `materialCodeIdGnrService`로 생성한 값을 저장 |
| 품목 수정 | 누락, 빈 값, 기존 값 또는 다른 값 | 요청 값은 무시하고 저장된 `material_code`를 보존 |

- 기존 코드 생성기, 6자리 형식, 초기화/범위 오류, 테넌트 범위 중복 검사, 재시도, DB unique 오류 처리를 유지한다.
- 생성 코드를 검증하거나 저장하는 흐름은 기존 DAO/Mapper를 계속 사용한다. 생성 시 사용자 값이 전달되더라도 우선권을 갖지 않는다.
- 수정 Mapper SQL은 각각 `customer_code` 및 `material_code`를 `SET` 절에 포함하지 않는다.
- API 경로, 요청/응답 필드 이름, 인증 tenant 처리, 나머지 business validation은 변경하지 않는다.
- 요청 VO의 API 문서 설명은 서버 생성 및 요청값 무시 정책에 맞춘다.

## 4. 데이터베이스 및 운영 범위

- DB 스키마, 테이블, 컬럼, 제약, 인덱스와 ID Generator 설정은 변경하지 않는다.
- 기존 코드 행을 재채번하거나 정리하지 않는다.
- 운영/읽기 전용 MCP DB에 쓰기 작업을 하지 않는다.
- 백엔드 계약 변경을 시작하기 전에 기본 `s-erp-postgresql-readonly` MCP로 `list_tables`를 호출하고 `tb_customer_info`, `tb_material_info`, `ids`의 메타데이터를 `describe_table`로 확인한다. 테이블 행은 조회하지 않는다.

## 5. 회귀 검증

- 프론트엔드:
  - 코드 열이 표시되고 `editable`이 꺼져 있는지 확인한다.
  - 코드 열이 신규/수정 행 폼에서 제외되는지 확인한다.
  - 코드 셀 더블클릭과 붙여넣기로 편집할 수 없는지 확인한다.
  - 프론트엔드 집중 테스트와 TypeScript/Vite 빌드를 실행한다.
- 백엔드:
  - create 요청의 빈 코드와 임의 코드 모두 기존 generator 값을 저장하는지 확인한다.
  - update 요청에서 코드 값 누락, 빈 값, 위조 값이 기존 코드 보존을 방해하지 않는지 확인한다.
  - update Mapper SQL에서 코드 컬럼 대입이 없는지 확인한다.
  - 기존 생성 범위/충돌 처리, 인증 tenant 범위, 다른 필드 validation 테스트를 유지한다.
- 브라우저에서 거래처관리와 품목관리를 375px, 768px, 1280px로 확인하고 코드 표시, 폼 제외, 저장 후 코드 표시 및 다른 필드 저장을 점검한다.
- 결과 문서에는 테스트 명령, 브라우저 확인과 스크린샷, MCP 확인 내용, DB를 변경하지 않았다는 사실을 기록한다.

## 6. 완료 조건

- 사용자가 거래처코드와 품목코드를 직접 지정하거나 수정할 수 없다.
- 신규 생성 코드는 기존 서버 채번기로만 저장된다.
- 수정 코드 값의 변경 시도가 저장 코드에 영향을 주지 않는다.
- 기존 API 이름, 코드 형식, 테넌트/중복/오류 처리와 기타 저장 동작이 보존된다.
- 필요한 테스트, 빌드, 브라우저 확인, F1-Grid 문서 및 결과물이 완료된다.
