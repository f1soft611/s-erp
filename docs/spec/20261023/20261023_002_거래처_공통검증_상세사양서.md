# 거래처 공통검증 상세 사양

## 근거 및 범위

- [계획서](../../plan/20261023/20261023_002_거래처_공통검증_계획서.md)
- 2026-10-23 사용자 승인: 필수·자리수 공통 검증, 폼 적용·저장 모두 실제 오류 상단 표시.
- 프론트엔드만 변경한다. 백엔드/API/DB 계약은 변경하지 않는다.

## 컬럼 및 검증

- 거래처명과 사업자번호는 `F1GridColumn.required: true`로 선언한다.
- 필수 표시는 그리드 헤더와 폼 라벨에서 기존 공통 렌더러를 사용한다.
- 빈 문자열·공백은 필수 오류다. 사업자번호는 하이픈을 제외한 숫자 10자리여야 한다.
- `inputFormat.validDigitCounts` 및 국내 전화 규칙은 기존 `validateGridRow`에서 검사한다. 선택 필드의 빈 값은 허용한다.
- 폼은 포함된 컬럼을, `validate()`는 기존 동작대로 전체 visible rows와 전체 컬럼을 검사한다. 숨긴 폼 필드의 자리수도 최종 저장 시 검증한다.
- 저장 훅은 거래처명 필수 검사를 반복하지 않는다. 수정 코드 필수, Y/N, 식별자, 삭제 방지 등 업무 규칙은 유지한다.

## 공통 오류 전달

- `F1GridValidationError`: `{ rowId: F1GridRowId; field: string; message: string }`.
- `F1GridProps.onValidationErrors?: (errors: F1GridValidationError[]) => void`.
- `validate()`와 폼 적용 검증 때 같은 형식으로 알린다. 성공하면 빈 배열을 전달한다.
- 기존 `validate(): boolean` 반환값과 오류 셀 상태는 유지한다. 콜백 미설정 화면의 동작은 바꾸지 않는다.
- 폼은 외부 오류도 포함해 전달하고 실패 시 적용하지 않으며 첫 오류 입력에 포커스한다.
- 거래처 페이지는 메시지를 중복 제거해 줄바꿈으로 연결한 뒤 기존 `PageMessageArea`에 전달한다. 검증 성공은 이전 메시지를 비운다.
- 모달이 열린 동안 페이지 메시지는 모달 배경에 있으며, 현재 폼의 오류 설명·포커스·빨간 테두리로 오류를 즉시 확인한다. 취소 후에도 페이지 상단 메시지는 남는다.
- 폼 오류 입력의 빨간 테두리·오류 설명, 그리드 오류 셀의 빨간 강조·툴팁은 유지한다. 잘못된 입력으로 API가 호출되지 않는다.
- 오류 셀에 포커스가 남아 있어도 선택 테두리는 파란색보다 오류 빨간색을 우선한다.

## 회귀 검증

- 신규 폼에서 거래처명·사업자번호 미입력/공백: 필수 표시, 적용 차단, 첫 필드 포커스, 상단 실제 오류.
- 사업자번호 9자리: 폼 적용 차단, 10자리 오류 표시. 10자리로 수정 후 적용 가능.
- 기존 행의 사업자번호 누락/자리수 오류: 다른 값을 변경한 뒤 최종 저장 차단, 오류 셀 표시, API 미호출.
- 공통 콜백은 폼/그리드 양쪽에서 같은 행 ID·필드·메시지를 전달하며 정상 검증은 빈 배열을 전달한다.
- 전화·법인번호·우편번호 기존 공통 자리수 검사 및 선택값 비움 동작을 유지한다.
- 375px/768px/1280px 실제 렌더링과 스크린샷을 확인한다.
