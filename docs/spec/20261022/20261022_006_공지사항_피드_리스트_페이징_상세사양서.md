# 20261022_006 공지사항 피드·리스트 페이징 상세 사양서

## 목적

공지사항 `/groupware/community/notice`의 피드형·리스트형 일반 목록을 문서작성 페이지처럼 20건 단위로 이어 불러오고, 상단 고정 공지를 별도로 조회하여 전체 표시한다.

## 데이터 조회 계약

### 일반 공지

- 첫 조회는 `fetchNoticePosts(1, 20, '', selectedNoticeFilter || undefined, 'N')`로 수행한다.
- 다음 조회는 현재 필터와 `isPinned='N'`을 유지하고 page를 1씩 증가시켜 20건씩 요청한다.
- 응답의 `resultCnt`는 현재 필터 조건에 맞는 비고정 공지 총 건수다.
- `hasNext`는 누적된 고유 일반 공지 수가 `resultCnt`보다 작은지로 계산한다.
- 성공한 페이지의 고유 공지만 현재 결과 뒤에 추가한다. 같은 post ID가 이미 있으면 다시 추가하지 않는다.

### 상단 고정 공지

- 일반 공지와 별도로 `fetchPinnedNoticePosts(1, 20, '', selectedNoticeFilter || undefined)`부터 요청한다.
- 응답의 `resultCnt`를 기준으로 모든 고정 공지가 수집될 때까지 동일 조건으로 페이지를 순차 요청한다.
- 누적 결과가 `resultCnt`에 도달한 경우에만 고정 패널에 새 배열을 반영한다.
- 총 건수에 도달하기 전에 빈 페이지가 반환되거나 누적 고유 ID가 늘지 않으면 완료로 간주하지 않고 명시적 조회 오류를 표시한다.
- 일반 피드와 리스트는 `isPinned='N'`으로 조회하므로 고정 공지 패널과 항목이 겹치지 않는다.

## 페이징 동작

- 피드형과 리스트형 모두 공유 `ViewModePagination` 센티널을 사용한다.
- 센티널 관찰 root는 공지 페이지의 실제 스크롤 컨테이너이며 root margin 등 공통 페이징 동작은 공유 컴포넌트 설정을 따른다.
- 페이지당 크기는 20건이다.
- 다음 페이지를 요청할 때 이전에 표시된 항목은 유지하고 `isLoadingMore` 상태를 접근 가능한 로딩 표시로 제공한다.
- 공지 화면 로딩 상태의 접근성 이름은 `다음 공지 불러오는 중`이다. 문서작성 등 기존 호출부의 기본 이름 `다음 문서 불러오는 중`은 유지한다.
- 일반 페이지 요청 실패 시 해당 페이지를 자동으로 다시 요청하지 않는다. 오류와 `다시 시도` 동작을 제공하고 성공한 데이터는 보존한다.
- 재시도는 실패한 page를 요청한다. 성공 이후 다음 page는 정상 증가한다.
- 요청이 진행 중인 동일 page는 중복 요청하지 않는다.

## 상태 초기화와 동시성

- 선택 카테고리 변경, 보기 방식 전환으로 인한 재조회, 명시적 refresh는 새 목록 generation을 시작한다.
- 새 generation 시작 시 일반 page cursor, `hasNext`, 실패 페이지, 중복 방지 상태를 초기화한다.
- 현재와 다른 generation 또는 현재와 다른 page를 위한 늦은 응답은 일반/고정 상태를 수정하지 않는다.
- pin/unpin 성공 후 일반 목록과 고정 목록을 함께 조용히 재조회해 공지가 섹션 간 이동하도록 한다.
- 고정 목록 재조회 중에는 페이지 응답을 임시 배열에 모으고 마지막 페이지까지 완료되기 전에 부분 배열을 성공 상태로 노출하지 않는다.

## 보존할 기존 동작

- 공지 작성/수정/삭제, 상단 고정 전환, 상세 오버레이, 댓글/답글/첨부, 좋아요/북마크, 이미지 인증 조회 및 카테고리 필터 동작은 유지한다.
- 요약 패널, 목록/피드 보기 전환, 초기 skeleton, 오류 retry, 빈 상태 표현을 유지한다.
- 현재 적용된 프로필 이미지와 로그인 팝업 배지 변경은 보존한다.
- 백엔드 API 계약, DB 및 문서작성 화면은 수정하지 않는다.

## 오류 처리

- 초기 일반/고정 조회 실패는 성공한 빈 목록처럼 처리하지 않고 페이지 오류 및 기존 재시도 UI로 표시한다.
- 다음 일반 페이지 실패는 현재까지 화면에 있는 항목을 제거하지 않는다.
- 고정 조회 일부 페이지가 실패한 경우 부분 고정 배열을 새 완성 결과로 표시하지 않는다.
- 새 필터/재조회 이후 이전 응답은 폐기하며, 최신 요청의 오류/데이터만 화면 상태에 반영한다.

## 검증 기준

- 첫 일반 요청의 page/size/category/`isPinned='N'` 인자와 고정 별도 요청의 필터를 확인한다.
- 일반 2페이지 로딩 시 기존 목록 뒤에 고유 항목만 추가하고 총 건수에 따라 종료 상태가 계산되는지 확인한다.
- 고정 `resultCnt > 20`일 때 모든 페이지를 요청하며, 마지막 응답 전 부분 pinned 데이터가 교체되지 않는지 확인한다.
- 피드와 리스트 모두 pagination을 전달하고 지정한 scroll root 및 접근성 레이블을 사용하는지 확인한다.
- 중복 요청 차단, 같은 페이지 retry, 필터 전환 시 stale 응답 무시, pin/unpin 후 분리 갱신을 확인한다.
- 관련 Vitest 집중 실행, `npm run build`, 375px/768px/1280px 실브라우저 확인 및 결과 스크린샷을 완료한다.
