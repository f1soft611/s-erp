# 로그인 공지 팝업 상세 사양

## 승인된 UI

구분(전체 폭), 로그인 시 팝업 체크·팝업 종료일(2열), 제목(전체 폭), 기존 본문 에디터 순서. 600px 미만에서는 1열. 구분/제목/날짜는 업무작성 메타데이터와 같은 outlined 입력, 작은 라벨, 명확한 테두리. 팝업 비활성 상태에서 날짜 입력 비활성; 활성화하면 필수. 날짜 없이 저장 시 필드 오류 표시.

## 설정 저장

- `loginPopupYn`: `Y|N`, 누락 시 기존 클라이언트 호환을 위해 `N`.
- `popupEndDate`: `YYYY-MM-DD|null`. 활성화한 공지는 필수. 연도 0001~9999의 실제 달력 날짜여야 한다.
- 종료일 경과는 일반 공지 조회를 막지 않고 로그인 팝업만 종료한다. 과거 종료일을 가진 기존 공지의 편집도 허용한다.
- 새 컬럼: `tb_board_post.login_popup_yn char(1) NOT NULL DEFAULT 'N'`, `popup_end_date date`.
- 숨김: `tb_notice_popup_dismissal(tenant_id, post_id, login_id, dismissed_on date)`, 복합 PK. 서버 인증 컨텍스트에서만 사용자/tenant 파생.
- 날짜 판정은 서버 한국 시간 `Asia/Seoul`. `popup_end_date >= today`, `dismissed_on != today`.
- 기존 조회수 이력은 별도 유지. 하루 숨김은 읽음/조회수와 관계없다.

## API (인증 필수)

공통 prefix: `/api/v1/groupware/boards/notice/login-popups`

| Method | 경로 | 응답/효과 |
|---|---|---|
| GET | prefix | `resultList`: postId/title 등 큐 메타데이터. 최신 등록일/ID 내림차순. 조회수 미증가 |
| GET | `/{postId}` | `item`: 기존 상세 형식. 현재도 유효하고 오늘 미숨김인 공지인지 확인 후 기존 최초 조회수 등록 재사용 |
| PUT | `/{postId}/dismiss-today` | 해당 사용자의 한국 날짜를 upsert. 응답 성공 전에는 다음 공지로 넘기지 않음 |

기간 종료/삭제/팝업 해제/오늘 숨김 공지는 상세 404. 잘못된 저장 필드는 400. 인증 없음 401. 서버 오류는 기존 예외 처리 규칙 적용.

## 로그인 큐와 표시

- 브라우저 새 창이 아닌 앱 내부 CommonDialog. 제목 '로그인 공지' 오른쪽에 연한 파란 진행 배지 `1 / N`(한 건이면 `1 / 1`)를 표시한다. 제목 아래에는 작은 사용자/시계 아이콘 및 라벨로 작성자·작성일시를 구분한다. 작성자 값은 약간 강조하고 날짜/시각은 회색으로 표시한다. 모바일에서는 작성일시를 다음 줄로 내려 날짜·시간을 각각 묶어 표시한다. 상세 로딩 중에는 진행 배지만 보여준다. 본문에는 진행/작성 정보를 중복하지 않고 공지 제목/본문/첨부 다운로드를 표시한다.
- 기존 HTML 정제와 인증 이미지 뷰를 재사용. 댓글, 수정/고정/삭제 버튼은 표시하지 않음.
- 인증 이미지 요청은 현재 공지의 API origin/경로에만 전송한다. 이미지 실패는 본문 내 재시도를 제공하고 팝업 종료 시 blob URL을 해제한다.
- 한 번에 한 건만 상세 요청하여 표시한다. 대기열에 있다는 이유로 모든 공지 조회수를 증가시키지 않는다.
- '확인' 또는 X/ESC/배경 닫기로 현재 공지를 처리하고 다음 공지로 이동. 마지막은 닫힘.
- '오늘 하루 이 공지 보지 않기' 체크 시 현재 공지 숨김 요청 성공 후 진행. 체크 상태는 다음 공지에서 초기화.
- 로그인 성공 시 임의 ID를 생성하여 인증 세션에 저장. 토큰 갱신에는 변경하지 않으며 로그아웃/재로그인 시 새 ID.
- sessionStorage의 세션/tenant/사용자 키별 대기열과 현재 위치로 메뉴 이동 및 새로고침 재노출 방지. 일일 숨김의 근거는 서버이며 브라우저 저장소가 아님.
- 기존 로그인 세션(새 필드 없음)도 최초 앱 진입 한 번을 로그인 진입으로 취급.
- 목록/상세 실패는 모달 오류와 재시도/현재 로그인에서 닫기 제공. 이미 없어진 공지는 제외 안내 후 다음으로 이동 가능. 계정 변경 시 진행 중 요청 결과 폐기.
- 팝업을 조회/표시하는 동안 앱 렌더링과 로그인 성공은 차단하지 않는다. 실제 독해 여부를 측정하는 기능은 아니다.

## 피드·리스트의 팝업 설정 표시

- 기존 `loginPopupYn === 'Y'`인 공지만 아이콘을 표시한다. 일반 공지는 팝업 아이콘 없음.
- 한국 날짜 기준 종료일 당일까지 알림 아이콘(파란색), 다음 날부터 알림 해제 아이콘(회색). 접근성 이름은 각각 '로그인 팝업', '팝업 종료'. 개인별 하루 숨김과 무관한 공지 설정 상태이다.
- 피드는 핀 버튼 바로 옆에 표시한다. 상단 고정 패널은 최종 지시에 따라 팝업 표시 없이 기존 핀만 유지한다. 리스트는 후속 승인에 따라 `문서 아이콘 · 제목 … 팝업 아이콘 · 핀 아이콘 · 분류 배지` 순서로 표시한다. 제목 앞 아이콘은 문서작성 리스트의 기본 `DescriptionOutlinedIcon`과 동일하다. 텍스트 배지는 사용하지 않는다. 구분/상단고정과 독립적이며 아이콘은 편집/노출 실행 버튼이 아니다. 리스트 핀은 상태만 나타내며 별도 변경 액션을 추가하지 않는다.
- 분류 배지는 피드/리스트 모두 동일 공통 컴포넌트에서 `getNoticeCategoryPresentation`의 코드·테마별 배경색과 같은 글자색을 사용한다. 크기는 기존 피드 28px, 리스트 22px를 유지한다.
- 툴팁: 활성은 '로그인 시 표시 · 종료일 YYYY-MM-DD (당일까지)', 종료는 '로그인 팝업 종료 · 종료일 YYYY-MM-DD'. 종료일 누락은 '로그인 팝업 종료일 정보가 없습니다.'로 명시하며 활성 노출 여부를 보장하지 않는다.
- 화면을 계속 열어 두어도 한국 자정과 탭 복귀 시 상태를 갱신한다. 리스트 제목의 기존 말줄임 및 피드 제목 스타일은 유지한다.
- 기존 응답/어댑터 설정을 재사용하며 추가 상세 요청, 조회수 집계, API/DB 계약 변경은 없다.

## 검증

최초 사용자 조회 +1/동일 사용자 재노출 미증가/목록 미집계, tenant 분리, 만료 및 오늘 숨김 제외, 한국 자정 경계, 숨김 멱등, 저장/편집 값 왕복, 오류 재시도, 다중 큐, 세션 새로고침, 좁은 화면 가로 넘침 및 테이블 내부 스크롤을 확인한다.

## DB 확인/배포

2026-10-22 기본 readonly MCP로 관련 세 테이블 및 제약을 확인했다. 현재 팝업 컬럼·테이블은 없다. 개인/tenant 행 데이터는 조회하지 않았다. SQL은 배포 전 적용해야 하며 읽기 전용 MCP로 실행하지 않는다. 서버와 프론트는 SQL 적용 후 함께 배포한다.
