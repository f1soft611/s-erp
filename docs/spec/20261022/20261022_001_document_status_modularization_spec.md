변경 대상은 문서현황 기능 폴더, 관련 테스트, 이 작업의 문서/결과뿐이다. 문서작성은 참고 및 기존 UI 재사용 대상이며 수정하지 않는다. API/백엔드/DB 계약 변경은 없으므로 DB MCP 확인이 필요한 구현은 없다.

## 책임과 데이터 흐름

| 단위 | 책임 | 입력 및 출력 |
| --- | --- | --- |
| 페이지 | 훅 연결과 화면 조립 | 기존 모듈/메뉴/콘텐츠 props 유지 |
| 검색 훅 | 기본값, UI 입력, 적용 필터, 세션 | 컬럼 기반 검색필드 → 준비 상태/입력/실행/초기화 |
| 목록 훅 | 비동기 조회 수명주기 | 적용 필터/준비 여부 → rows/건수/로딩/오류/재시도 |
| 상세 훅 | 선택, 상세 및 편집 상태 | 목록 갱신 콜백 → 선택/편집 핸들러 및 상세 refresh token |
| 검색 UI | 빠른 검색과 상세검색 조립 | 검색 훅의 필드/값/콜백 |
| 빈 결과 UI | 안내와 조건 초기화 버튼 | 초기화 콜백 |
| 상세 UI | 기존 상세 피드/작성 다이얼로그 연결 | 상세 훅의 상태/콜백 |
| 그리드 | 읽기 전용 F1Grid 연결 | 전체 rows/로딩/선택 콜백 |
| 정의 | 옵션/라벨/색상 및 컬럼 메타데이터 | 그리드/검색/검증에서 공유 |
| 서비스 | 검색 값 변환, 응답 검증, HTTP 전송 분리 | 기존 필터 및 응답 shape 유지 |
| 타입 | 도메인/검색 세션/페이지/API 계약 | 중복 정의와 불필요한 cast 없이 import |

검색 훅의 적용 필터와 초기화 완료 여부를 목록 훅에 전달한다. 목록 새 조회 시작 시 상세 훅의 안정적인 닫기 콜백으로 선택을 해제한다. 상세 훅은 목록 훅에 의존하지 않으며 페이지가 두 훅의 갱신 콜백을 연결한다. 상세 작업 완료 또는 편집 다이얼로그 종료 시 목록과 상세 refresh token을 갱신한다.

## 보존 동작

- 기본 날짜는 서버 날짜 기준 최근 1개월이며 로드 전 목록을 요청하지 않는다.
- 세션 key `s-erp:page:document-status`, version `1`, snapshot 형식과 검증 정책을 유지한다.
- 검색 실행 전 편집한 값은 조회나 세션에 적용하지 않는다. 날짜 범위를 복제하여 참조 공유를 방지한다.
- 초기화는 빈 빠른 검색과 기본 날짜로 즉시 조회/저장한다. 날짜를 지우고 실행한 세션은 날짜 없이 복원한다.
- `currentApprovalStep` 상세 입력은 기존처럼 `currentApproverName` 필터로 변환한다.
- 전체조회 및 기존 페이징 서비스 함수, 경로, 파라미터 직렬화, AbortSignal 전달, 오류 문구와 날짜 정규화를 유지한다.
- 그리드 정렬·필터·엑셀은 로컬 전체 행으로 처리하고 목록 API를 재호출하지 않는다.
- 이전 조회는 취소되며 취소된 응답/오류/완료가 최신 상태를 덮어쓰지 않는다.
- 기존 기본값 오류와 목록 오류의 표시/재시도, 빈 결과, 오른쪽 클릭/선택, 상세 및 편집 종료 동작을 유지한다.
- 문서번호 텍스트 입력과 최종 변경일 상세검색 숨김은 현재 소스 그대로 유지한다. 숫자 입력과 최종 변경일 노출을 기대하는 기존 테스트만 현재 동작에 맞춘다.
- 기존 컬럼 팩터리 및 응답 타입 import 경로는 재export하여 소비자 호환성을 보존한다.

## 검증 및 완료 기준

1. 기존 페이지/서비스 테스트에 회귀가 없다. 기준선 2개 실패는 UI 변경 없이 테스트 기대만 정합화한다.
2. 검색 helper 단위 테스트가 enum/문자열/날짜/세션/복제를 검증한다.
3. 훅 테스트가 취소, 늦은 응답, 오류/재시도 및 상세 편집 갱신을 검증한다.
4. TypeScript + Vite 빌드가 성공한다.
5. 375/768/1280px 실제 브라우저에서 동일 검색/그리드/상세 UI와 페이지 가로 오버플로를 확인하고 합성 데이터 스크린샷을 결과 폴더에 보관한다.
6. 리팩터링은 유지보수 책임 분리를 위한 것이며 성능 개선 수치를 주장하지 않는다. 신규 네트워크 요청, 기능, 의존성을 추가하지 않는다.
