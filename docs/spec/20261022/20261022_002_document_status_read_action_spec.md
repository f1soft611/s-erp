# 문서현황 조회 버튼 상세사양서

## 근거

- [작업지시서](../../directions/20261022/20261022_002_document_status_read_action_work_instruction.md)
- [계획서](../../plan/20261022/20261022_002_document_status_read_action_plan.md)
- 사용자가 승인한 기존 페이지 방식: 현재 입력조건으로 조회한다.

## UI 및 권한

- 다른 관리 페이지처럼 PageHeader의 공통 액션 그룹으로 검색 아이콘과 `조회` 버튼을 상단 우측에 표시한다.
- DashboardContent의 현재 메뉴 `selectedMenuPermissions`를 전달하며 `read === true`일 때만 표시한다. 권한 미전달/false이면 숨긴다.
- 기본 검색값이 준비되지 않았거나 불러오는 동안 비활성화한다. 기본값 실패 시 기존 다시 조회 버튼으로 복구한다.
- 좁은 화면에서 공통 헤더의 줄바꿈 배치를 유지한다.

## 동작 및 보존

- 클릭 시 `search.applySearch()`로 현재 빠른검색과 상세검색 입력을 적용하고 기존 세션 저장/목록 요청 경로를 사용한다.
- 동일 조건으로 다시 클릭해도 새 조회가 발생한다.
- 조회 실패는 기존 메시지와 재시도 흐름으로 표시한다.
- 자동조회, 검색바/상세검색 버튼, 기존 상세/편집/그리드 동작은 유지한다. 기존 미커밋 분리 작업을 보존한다.
- API 및 DB 계약 변경이 없으며 백엔드/SQL 변경이나 DB MCP 확인 대상 구현은 없다.

## 검증

권한 true/false/미전달, 초기 기본값 로딩, 현재 입력조건 요청과 세션 저장, 동일 조건 재조회에 대한 테스트를 작성한다. 기존 문서현황 회귀 테스트와 타입/프로덕션 빌드를 실행하고, 합성 데이터로 375/768/1280px 브라우저 렌더링 및 스크린샷을 확인한다.
