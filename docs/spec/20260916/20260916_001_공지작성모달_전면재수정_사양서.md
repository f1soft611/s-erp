## 2. 기능 개요

공지 작성 모달은 기존의 커스텀 `f1-editor` 기반 문서 편집 구조를 제거하고, Tiptap 에디터를 사용한 표준 편집형 입력 영역으로 변경한다. 사용자는 제목을 먼저 입력하고 본문을 작성한 뒤, 첨부 파일이 하단에 카드 리스트처럼 이어지는 경험을 받는다. 요구사항상 “제목 본문 첨부 영역이 한몸처럼 보이는 것”을 핵심으로 한다.

핵심 기능은 다음과 같다.

- 제목, 본문, 첨부가 하나의 연속된 입력 흐름으로 보이는 레이아웃
- 첨부 파일 목록이 공지사항 페이지의 첨부 리스트와 유사한 카드형 UI로 노출
- Tiptap 에디터 적용
- 불필요한 하단 툴바 제거
- 기본 Tiptap 툴바 유지
- `f1-editor` 의존성 제거

## 3. 사용자 시나리오

### 3.1 모달 열기

- 사용자가 공지 작성 버튼을 누르면 모달이 열린다.
- 모달 내부에는 제목 입력 영역이 최상단에 보이고, 본문 에디터가 이어서 표시된다.
- 본문 아래에는 첨부 파일 카드 목록이 자연스럽게 표시된다.

### 3.2 본문 편집

- 사용자는 Tiptap 기본 툴바를 통해 굵게, 기울임, 목록, 인용 등 기본 서식을 적용할 수 있다.
- 하단에 별도 커스텀 툴바는 표시되지 않는다.
- 에디터는 기존 그룹웨어 톤에 맞춰 높이와 간격을 유지한다.

### 3.3 첨부 파일 추가

- 첨부 아이콘을 누르면 파일 선택 창이 열리거나 연결된 첨부 액션이 실행된다.
- 첨부된 파일은 이름, 확장 아이콘, 삭제 버튼을 포함한 카드형 묶음으로 표시된다.
- 첨부 리스트는 공지사항 페이지의 첨부 목록 스타일과 유사해야 한다.

### 3.4 에디터 제거 및 정리

- `NoticeComposerDialog`의 `f1-editor` import와 관련 구현이 제거된다.
- `frontend/src/shared/components/f1-editor` 파일은 더 이상 사용되지 않는 구조로 정리된다.

## 4. 화면 구성

### 4.1 레이아웃 구조

- 상단 헤더: 제목(“새 공지 작성”), 닫기 버튼
- 본문 영역: 제목 입력 + Tiptap 에디터를 하나의 연속 영역으로 구성
- 첨부 영역: 에디터 하단에 파일 카드 리스트 배치
- 하단 액션: 저장 / 취소 버튼

### 4.2 첨부 리스트 규칙

- 파일명은 텍스트 생략 처리
- 확장자별 배경색과 텍스트 색상 유지
- 삭제 버튼은 우측에 위치
- 목록 간격과 카드 굵기는 공지사항 페이지 첨부 리스트와 서로 맞춘다.

### 4.3 툴바 규칙

- 기본 Tiptap 툴바를 사용한다.
- 하단 툴바 버튼 그룹을 노출하지 않는다.
- 링크 버튼은 하단 영역이 아니라 Tiptap 기본 툴바 구조에 맞게 처리한다.

## 5. 컴포넌트 명세

### 5.1 `NoticeComposerDialog`

```tsx
type NoticeComposerDialogProps = {
  open: boolean;
  isDark: boolean;
  onClose: () => void;
};
```

- `open`이 `true`일 때 모달 표시
- `isDark`에 따라 다이얼로그 테마와 배경 패널을 조정
- `onClose`로 닫기 동작 수행
- 내부 에디터는 Tiptap 기반으로 교체

### 5.2 첨부 카드 목록

- 각 카드에는 파일 이름, 확장 아이콘, 삭제 버튼 포함
- 카드 배열은 본문 영역 아래에 표시
- 파일 카드 사이 간격은 보기에 편한 수준으로 유지

## 6. 동작 규칙

### 6.1 레이아웃 동작

- 제목과 본문이 하나의 입력 흐름으로 보여야 한다.
- 첨부 리스트는 본문 아래에 자연스럽게 이어져야 하며, 독립된 섹션처럼 느껴지지 않아야 한다.
- 저장/취소는 하단 액션 영역에 유지된다.

### 6.2 에디터 동작

- 기본 Tiptap 서식 버튼이 정상 동작해야 한다.
- 불필요한 하단 툴바는 표시되지 않아야 한다.
- 첨부 아이콘은 본문 흐름에 자연스럽게 연결되어야 한다.

## 7. 제거 범위

### 7.1 제거 대상

- `frontend/src/shared/components/f1-editor/**`
- `NoticeComposerDialog` 내부의 `f1-editor` 관련 코드와 타입 참조
- 하단 툴바 배열 및 별도 링크 버튼 로직

### 7.2 유지 대상

- 공지 작성 모달 전체 톤과 사용자 흐름
- 저장/취소 UX
- 다이얼로그 테마/배경/빈 여백
- 공지 페이지 첨부 리스트와 유사한 사용자 경험

## 8. 예외 처리 기준

- 제목/본문/첨부 영역의 구분이 부족하면 레이아웃 간격과 패딩을 조정한다.
- 첨부 리스트가 너무 덩어리져 보이면 카드 높이와 간격을 줄여 자연스러운 흐름을 유지한다.
- `f1-editor` import가 남아 있으면 구현 불가 기준으로 판단한다.

## 9. 검증 기준

- 모달을 열면 제목 입력 영역과 본문 영역이 연속적으로 보인다.
- 첨부파일 카드 리스트가 본문 아래에 표시된다.
- 하단 별도 툴바가 보이지 않는다.
- 기본 Tiptap 툴바와 첨부 기능이 함께 동작한다.
- `f1-editor` import와 구현이 제거된다.
- 관련 빌드와 테스트가 통과한다.
