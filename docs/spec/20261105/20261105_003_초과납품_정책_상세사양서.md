# 초과납품 정책 상세사양서

## 정책 및 데이터

- `tb_tenant.over_delivery_policy VARCHAR(10) NOT NULL DEFAULT 'BLOCK' CHECK IN ('BLOCK','WARN')`. 기존 테넌트는 차단 유지, AUTO/MANUAL과 독립.
- 계획·수주 기준수량은 원본 유지. 실제 계획납품량·수주출하량은 기준 초과 가능하되 비음수·유한수·숫자 정밀도를 유지한다.
- 초과수량 `max(누적실납품 - 기준수량, 0)`, 미납수량 `max(기준수량 - 누적실납품, 0)`. 잔량만으로 초과수량을 숨기지 않는다.
- WARN에서는 잔량이 0 이하인 계획도 납품 선택 가능하다. 신규 선택행의 초기 수량은 `max(잔량, 0)`이며 사용자가 실제 양수를 입력해야 한다.
- 실제 DB는 적용하지 않는다. 기본 MCP `list_tables`, `describe_table(tb_tenant/tb_sales_order_dt)`에서 정책 컬럼·계획 테이블 미반영을 확인했다. 업무 데이터는 조회하지 않았다. 제약은 저장소 날짜별 DDL/Mapper를 기준으로 변경한다.

## 저장 계약

- 기존 납품 POST/PUT 요청에 선택적 `overDeliveryConfirmed: boolean`(기본 false)을 추가한다. DIRECT는 확인 불필요.
- 서버가 수주 잠금 후 계획상세별 누적량과 수주상세별 요청 합산량을 검증한다. 수정은 해당 납품의 기존수량을 빼고 신규 요청을 더한다.
- BLOCK은 초과 시 기존처럼 409로 거부한다. 확인 플래그가 있어도 우회할 수 없다.
- WARN에서 실제 초과가 있고 미확인 시 409, reason 접두어 `[OVER_DELIVERY_CONFIRM_REQUIRED]`와 계획/수주 기준·저장후누적·초과수량을 반환한다. 이 거부 전 업무 변경은 없어야 한다.
- 프론트 서비스는 HTTP 409와 정확한 접두어를 함께 확인해 전용 오류로 변환한다. 다른 오류는 일반 실패로 유지한다.
- 화면은 서버의 경고 내용을 표시하고 `취소 / 초과납품 저장`을 제공한다. 취소는 입력 보존, 저장은 경고를 받은 입력 스냅샷에만 확인 플래그를 붙여 재시도한다. 대화상자 중 입력 변경과 중복 저장을 막고 일반 저장 시 확인 상태를 재사용하지 않는다.
- 서버는 재시도에서도 최신 정책·수량을 검증하며, 수량 동기화·삭제 역보정은 한 트랜잭션이다. 경고 확인은 승인 워크플로우가 아니며 기존 메뉴 권한을 대체하지 않는다.
- 수주/계획 초과 여부를 각각 안내한다. 추가 승인권한, 초과율 상한, 초과사유 입력은 이번 범위에서 제외한다.

## 영향 및 검증

- 초과 실적이 있는 계획을 수정할 때 원래 계획수량을 강제로 실적 이상으로 늘리지 않는다. 초과 실적이 있는 AUTO 수주의 무관한 수정도 허용하되 기존 연결과 수량을 보존한다.
- 기존 BLOCK, WARN 확인/취소, 분할 계획 합산, 이미 소진된 계획, 수정 자기수량 복원·삭제, DIRECT, 타 테넌트 참조 차단을 검증한다.
- 경고/보고 화면은 실제 브라우저 375/768/1280px로 확인한다. 기존 흐름도에 초과납품 정책 분기를 반영한다.
