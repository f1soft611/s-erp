# 수주 선택 모달 레이아웃 상세사양서

## 증상과 원인

첨부 화면의 `수주 선택` 모달에서 검색 입력이 돋보기 옆 약 320px만 차지하고 나머지 공간이 비어 있다. `PageSearchArea`는 일반 페이지 검색용으로 검색 필드 wrapper에 `maxWidth: 360` 및 버튼 별도 flex 배치를 강제하므로, `CommonDialog` 안에 재사용할 때 모달 가로폭을 활용하지 못한다.

현재 수주 선택 그리드 열 너비는 190+120+160+120+160+110+110+110=1080px이다. CommonDialog lg의 내부 폭보다 넓어 데스크톱에서도 잔량 열이 일부 잘리고 가로 스크롤이 상시 표시된다.

## 기대 동작

- 검색 입력과 검색 버튼은 한 행의 `<form>` 안에 둔다. 검색 입력은 `flex: 1`, `min-width: 0`로 가용 폭을 사용하고 버튼은 축소하지 않는다. Enter와 버튼 모두 동일한 현재 키워드로 검색한다.
- 검색 입력 outlined root와 버튼의 바깥 높이는 동일한 40px 기준값을 공유한다.
- 데스크톱 1030px 이상에서 모달 안 8개 열(수주번호, 수주일자, 거래처, 품목코드, 품목명, 주문수량, 출하수량, 잔량)이 수평 스크롤 없이 표시된다. 너비는 합계 920px 이하로 계획한다.
- 768px 및 모바일에서는 외부 페이지/모달의 수평 overflow를 만들지 않고, 넓은 데이터는 F1-Grid 내부에서 수평 스크롤한다.
- 주문번호 선택 버튼의 텍스트는 줄바꿈/잘림 없이 읽히며, 클릭 시 기존대로 동일 수주의 모든 행을 `onSelect`에 전달한다.
- Dialog 크기, 닫기, 검색 오류 처리, API 계약은 변경하지 않는다.

## 검증

- 렌더 테스트: 검색 form에 입력과 버튼이 함께 있고 Enter/버튼이 같은 검색 흐름을 호출한다.
- 기존 수주납품 생성 테스트에서 선택한 수주의 모든 잔량 라인이 유지된다.
- 실제 브라우저에서 375/768/1030x668/1280px 화면의 검색 input 폭, visible column count, grid `scrollWidth/clientWidth`, document overflow를 확인한다.
