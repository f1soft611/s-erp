## 화면

생산관리 > 기준정보 > 공정관리. 공정그룹이 루트, 공정이 자식인 F1Tree에서 등록·수정·삭제한다. 공정그룹명과 공정명은 필수이며 공정그룹 설명과 사용 여부, 공정 설명·사용 여부 및 레거시 공정 속성을 관리한다. 자식 공정이 남은 그룹은 삭제하지 않는다. 검색과 저장·오류·권한 동작은 기존 관리 화면을 따른다.

`/pr/master/process-management`는 기존 업무 화면처럼 인증된 사용자의 대시보드 경로로 처리한다. 인증되지 않은 요청은 로그인으로 이동하고, 유효하지 않거나 권한이 없는 메뉴는 기존 대시보드 검증을 따른다.

통합 검색 입력은 창고관리와 작업표준서 화면처럼 기본 텍스트 필드 여백을 제거하고 높이 40px을 사용해 검색 아이콘과 일렬로 표시한다. 검색 동작과 편집 중 검색 제한은 유지한다.

우클릭의 기존 루트 추가·행 추가를 이 화면에서 각각 공정그룹 추가·공정 추가로 표시한다. 그룹을 우클릭하면 그 그룹에 공정을 추가하고 공정을 우클릭하면 같은 그룹에 공정을 추가한다. 대상이 없으면 공정 추가를 비활성화하고, 생성 권한이 없거나 검색 중·저장 중에는 추가하지 않는다. 공정 속성 체크박스는 중앙에 표시한다.

코드는 조회·검색 데이터에 유지하되 공정관리 그리드에 표시하지 않는다. 확장자와 실제 이미지 형식이 다른 경우 PNG/JPEG 파일 서명을 기준으로 데이터 URL의 MIME을 정규화한다. 실제 이미지 형식·크기 검사와 저장 제한은 유지한다.

F1Tree의 루트가 아닌 행에는 ㄴ 모양 연결선을 표시한다. 최하위 행의 연결선은 이름에 가깝게 배치하고 중간 부모의 연결선은 펼침 버튼 앞에 배치한다. 루트에는 표시하지 않으며 접기·펼치기 및 행 선택·편집은 기존과 같다. 공정그룹의 이미지 셀은 빈칸으로 유지한다.

공정관리 화면은 창고관리의 기능 폴더 구조를 따른다. 페이지는 화면과 동작을 조립하고 트리 컴포넌트는 컬럼과 트리 렌더링을 맡는다. 관리 훅은 조회·검색·선택·변경·저장을 관리하며 서비스는 기존 API 계약을 유지한다. 행 초기값과 행 타입은 기능 폴더의 데이터·타입 파일에 둔다. 구조 분리 과정에서 검색, 권한, 저장, 메뉴와 미저장 변경 동작을 변경하지 않는다.

백엔드는 창고관리와 같이 `controller`, `service` 인터페이스, `service/impl` 구현, `domain/model`과 `domain/repository`를 사용한다. 기존 공정 배치 요청·응답 필드, SQL과 권한 확인 및 트랜잭션은 유지한다. 기존 공정 테이블을 사용하며 스키마 변경은 없다.

## 이미지

F1Grid `image` 셀은 약 60×60 미리보기 또는 빈 이미지 아이콘을 표시한다. 편집 가능한 셀의 이미지를 클릭해 파일을 선택하고 셀에 포커스한 상태에서 Delete 키로 이미지를 제거한다. 셀 안에 선택·삭제 버튼은 표시하지 않으며, 터치용 행 상세 폼에서는 파일 선택·삭제를 제공한다. PNG/JPEG, 최대 512 KiB로 제한하고 서버에서 실제 이미지 형식과 크기를 재검증한다. 편집 취소와 행 삭제에 따른 변경 사항은 그리드의 기존 변경 추적을 따른다.

## 데이터 및 검증

그룹과 공정은 각각 테넌트별로 저장하고 공정의 그룹 참조는 동일 테넌트로 제한한다. API는 세션의 테넌트와 메뉴 권한을 사용한다. 날짜별 생성·메뉴·롤백 SQL과 변경 이력을 관리한다. 테스트는 이미지 선택·제거, 트리 관계, 저장 검증·테넌트 격리 및 오류를 확인한다. 브라우저는 375/768/1280px을 확인한다. 기본 DB MCP에서 확인한 기존 테이블·메뉴와 적용 대상별 미확인 사항은 결과 문서에 기록한다.
