## 1. 메뉴

| 항목 | 값 |
| --- | --- |
| 메뉴 | `MATERIALS_REQUEST_STATUS` / 구매요청현황 / `/materials/request/request-status` / 정렬 20 |
| 상위 메뉴 | `MATERIALS_PURCHASE` (구매관리) |
| 메뉴 권한 | READ, EXCEL |
| 역할 권한 | `ORDER_STATUS`(수주현황) 역할 권한 중 READ, EXCEL 복사 |
| 대상 테넌트 | 1 |

`DashboardContent`에서 `selectedModule.id === 'materials'` 이고
`currentPageKey === 'request-status'`일 때 `PurchaseRequestStatusPage`를 렌더링한다.

## 2. 목록 API

`GET /api/v1/materials/purchase-request-status` (READ 권한)

### 2.1 검색 파라미터

| 파라미터 | 조건 |
| --- | --- |
| `keyword` | 구매요청번호·품목코드·품목명·요청자명 부분일치 |
| `requestNo` | 구매요청번호 부분일치 |
| `requestDtFrom` / `requestDtTo` | 요청일 범위 |
| `requesterKeyword` | 요청자명 부분일치 |
| `status` | `REQUESTED` / `CONFIRMED` |
| `materialKeyword` | 품목코드·품목명 부분일치 |
| `requestDeliveryDtFrom` / `requestDeliveryDtTo` | 요청납기일 범위 |
| `useType` | 사용용도 코드 |

- 항상 로그인 테넌트, `hd.use_at = 'Y'` 조건을 붙인다.
- 정렬: 요청일 내림차순, 구매요청번호 내림차순, 행 번호 오름차순.

### 2.2 응답 행

```json
{
  "resultList": [
    {
      "purchaseRequestId": 1,

      "requestNo": "MR-20261112-0001",

      "requestDeptName": "생산지원팀",
      "status": "REQUESTED",
      "remark": null,
      "lineNo": 1,
      "materialCode": "3001587",
      "materialName": "OPP 테이프(블랙)",
      "materialSpec": null,
      "unit": "BOX",
```

`useTypeName`은 같은 테넌트의 `PURCHASE_USE_TYPE` 공통코드 이름으로 조인한다.

## 3. 화면

### 3.1 구조 (수주현황과 동일)

```text
┌ PageHeader: 구매자재 > 구매관리 > 구매요청현황                         ┐
├ 검색: [빠른 검색 ______] [상세검색 ▾] [조회] [초기화]                 ┤
├ F1-Grid (품목 행 단위, 헤더 컬럼 병합)                                ┤
│ 구매요청번호 │ 요청일 │ 요청자 │ 요청부서 │ 상태 │ 행 │ 품목코드 │ …   │
└──────────────────────────────────────────── 상세 패널(오른쪽) ────────┘
```

### 3.2 그리드 컬럼

| 컬럼 | 필드 | 병합 | 상세검색 |
| --- | --- | --- | --- |
| 구매요청번호 | `requestNo` | 예 (링크, 클릭 시 상세 패널) | 구매요청번호 |
| 요청일 | `requestDt` | 예 | 요청일 (기간) |
| 요청자 | `requesterName` | 예 | 요청자 |
| 요청부서 | `requestDeptName` | 예 | - |
| 상태 | `status` | 예 | 상태 (요청/확정 select) |
| 행 | `lineNo` | 아니오 | - |
| 품목코드 | `materialCode` | 아니오 | 품목 |
| 품목명 | `materialName` | 아니오 | (품목에 포함) |
| 규격 | `materialSpec` | 아니오 | - |
| 단위 | `unit` | 아니오 | - |
| 요청수량 | `requestQty` | 아니오 | - |
| 요청납기일 | `requestDeliveryDt` | 아니오 | 요청납기일 (기간) |
| 사용용도 | `useTypeName` | 아니오 | 사용용도 (공통코드 select) |
| 확정수량 | `confirmQty` | 아니오 | - |
| 비고 | `requestRemark` | 아니오 | - |

- 상태는 `select` 컬럼 옵션으로 `REQUESTED`→요청, `CONFIRMED`→확정 라벨을 표시한다.
- 검색 기본값은 수주현황과 같은 `usePageSearchDefaults` 방식을 쓴다.
- 엑셀 내보내기는 EXCEL 권한이 있을 때만 보인다.
- 하단 합계는 두지 않는다. F1-Grid에 합계 행 기능이 없고 수주현황도 같은 방식이다.

### 3.3 상세 패널

- 제목 "구매요청 상세", 부제 "구매요청번호: MR-…".
- 상태 칩(요청/확정), 요약(요청일, 요청자, 요청부서, 품목 수).
- 품목 목록: 품목코드, 품목명, 요청수량, 요청납기일, 사용용도.
- 비고, 작성자/작성일시, 수정자/수정일시.
- 더보기 메뉴: **자세히보기**(항상), **수정**(`REQUESTED`이고 구매요청등록 메뉴의 UPDATE 권한이 있을 때만). 수주현황과 달리 작성자 본인 여부는 따지지 않는다.
- 데이터는 `GET /api/v1/materials/purchase-requests/{id}`로 가져온다.

### 3.4 조회/수정 다이얼로그

- 수주현황의 `SalesOrderEditorDialog`와 같은 방식으로 `PurchaseRequestCreatePage`를
  `embedded` + `mode`(`view`/`edit`)로 띄운다.
- 수정 저장 또는 삭제가 끝나면 다이얼로그를 닫고 목록과 상세 패널을 다시 조회한다.
- 저장하지 않은 변경이 있으면 닫기 전에 기존 미저장 확인 대화상자를 띄운다.

## 4. 20261112_002 등록 화면에 필요한 조건

- `PurchaseRequestCreatePage`는 `embedded`, `mode`(`create`/`view`/`edit`),
  `purchaseRequestId`, `onSaved`, `onDeleted`, `onEmbeddedActionsChange` props를
  수주등록 화면과 같은 의미로 지원한다.
