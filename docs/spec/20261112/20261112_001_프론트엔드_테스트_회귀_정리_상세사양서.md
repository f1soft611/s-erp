# 프론트엔드 테스트 회귀 정리 상세사양서 (배치 1)

## 원칙

- 운영 코드는 변경하지 않는다. 테스트를 현재 계약에 맞춘다.
- 기존 테스트가 보호하려던 의도(검증, 계약)는 유지한다.

## 변경 사양

1. `tests/sales-delivery-api.test.ts`
   - 초과 소진된 계획 행의 검증 메시지 기대값을 `출하수량`으로 변경.
2. `tests/document-status-search.test.ts`
   - `electronicApprovalId` 입력/기대값을 `documentNo` 로 교체.
3. `tests/common-content-api.test.ts`
   - owner 쿼리 다운로드/레거시 다운로드: `apiDownload` 가 `(url, undefined)` 로 호출됨을 기대.
   - 댓글 조회 결과에 `resultCnt: 0` 포함을 기대.
4. `tests/menu-permissions.test.ts`
   - 제거된 `userMenuResponse` 목 데이터 의존 테스트를 인라인 픽스처 + `buildModuleDescriptors` / `buildMenuPermissionMap` 로 변경.
   - 빈 기본값(`moduleDescriptors`, 미등록 메뉴 권한 `undefined`)은 유지 검증.

## 완료 기준

- 4개 테스트 파일 모두 통과, `tsc --noEmit` 통과.
