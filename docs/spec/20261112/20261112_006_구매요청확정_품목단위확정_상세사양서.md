## 1. 데이터베이스

| 테이블 | 변경 |
| --- | --- |
| `tb_purchase_request_dt` | `purchase_confirm_id BIGINT NULL` 추가, FK `fk_purchase_request_dt_confirm (purchase_confirm_id, tenant_id)` → `tb_purchase_confirm_hd`, 인덱스 `ix_purchase_request_dt_confirm`, CHECK `ck_purchase_request_dt_confirm_link`: `(purchase_confirm_id IS NULL) = (confirm_qty IS NULL)` |
| `tb_purchase_request_hd` | `purchase_confirm_id`, `fk_purchase_request_hd_confirm`, `ck_purchase_request_hd_confirm_link`, `ix_purchase_request_hd_confirm` 삭제. `ck_purchase_request_hd_status`를 `REQUESTED`, `PARTIALLY_CONFIRMED`, `CONFIRMED`로 교체 |

- 이전: 확정 상태 요청의 헤더 `purchase_confirm_id`를 그 요청 상세 행 전체에 복사한 뒤 헤더 컬럼을 삭제한다.
- 롤백: 한 요청에 확정 ID가 2개 이상이거나 부분확정 요청이 있으면 중단한다. 아니면 헤더에 확정 ID를 되돌리고 005 제약을 복원한다.

## 2. 요청 상태 계산

확정·확정 취소 후 영향받은 요청마다 상세 기준으로 다시 계산한다.

| 조건 | 상태 |
| --- | --- |
| 확정된 행 없음 | `REQUESTED` |
| 일부 행만 확정 | `PARTIALLY_CONFIRMED` |
| 모든 행 확정 | `CONFIRMED` |

헤더 `total_amt`는 확정된 행 `amount` 합계. 화면 라벨: 요청 / 부분확정 / 확정.

## 3. API 변경 (005 대비)

| 메서드·경로 | 변경 |
| --- | --- |
| `GET /candidates?keyword=` | **품목 행 목록**. 사용 중 요청(`REQUESTED`, `PARTIALLY_CONFIRMED`)의 확정 안 된 행. 검색어: 구매요청번호·요청자·품목코드·품목명. 정렬: 요청일 내림차순, 구매요청번호 내림차순, 행 번호. 최대 500행 |
| `GET /request-details?purchaseRequestDetailIds=` | 상세 행 ID 기준. 확정됐거나 삭제된 요청의 행이 있으면 409. 최대 200행 |
| `POST /` | body에서 `purchaseRequestIds` 제거. `details`의 상세 ID 1~200건·중복 없음 |
| `GET /`(목록) | `requestCount` = 확정에 묶인 상세 행들의 요청 수 |

후보 행 필드: `purchaseRequestId`, `purchaseRequestDetailId`, `requestNo`, `requestDt`, `requesterName`, `requestStatus`,
`lineNo`, `materialCode`, `materialName`, `materialSpec`, `unit`, `requestQty`, `requestDeliveryDt`, `useTypeName`, `requestRemark`.

### 3.1 확정 처리 순서

1. 상세 ID 정렬 → 상세 행 `FOR UPDATE`(요청 헤더 사용 중). 개수가 다르거나 이미 확정 ID가 있으면 409
   "이미 확정되었거나 삭제된 구매요청 품목이 있습니다. 다시 불러와 주세요."
2. 행별 검증·통화 동일 검증(005와 같음) → 확정번호 채번 → 확정 메인 INSERT.
3. 상세 UPDATE: 확정값 + `purchase_confirm_id`, 조건에 `purchase_confirm_id IS NULL`(0건이면 409).
4. 영향받은 요청 상태·합계 재계산.

### 3.2 확정 취소

그 확정의 행 요청 ID 목록 조회 → 상세 확정값·`purchase_confirm_id` 초기화 → 요청 상태·합계 재계산 → 확정 메인 `use_at = 'N'`.

## 4. 화면 변경

- 요청 선택 창: 품목 행 그리드(다중 체크). 컬럼: 구매요청번호·요청일·요청자(같은 요청 병합), 상태, 행, 품목코드, 품목명,
  규격, 단위, 요청수량, 요청납기일, 사용용도, 비고. [선택 불러오기 (N)]은 고른 행 수.
- 확정 화면: [선택 요청 빼기] → [선택 행 빼기](체크한 행만 제거). 기본정보에 "품목 수" 추가.
- 구매요청 상태 라벨에 `PARTIALLY_CONFIRMED` → 부분확정. 현황 상세 패널 칩 색은 부분확정 `warning`.
