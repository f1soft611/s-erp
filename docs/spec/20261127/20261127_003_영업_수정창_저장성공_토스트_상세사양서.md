# 영업 저장 성공 토스트 상세사양서

- 작성일: 2026-11-27
- 계획서: [영업 저장 성공 토스트](../../plan/20261127/20261127_003_영업_수정창_저장성공_토스트_계획서.md)

## 1. 규칙

| 구분 | 표시 위치 | 비고 |
| --- | --- | --- |
| 성공(저장·수정·삭제·마감) | 공통 토스트 `useNotification().showSuccess` — 우측 하단, `severity="success"`, 4초 자동 닫힘, 닫기 버튼 | 화면 안 성공 `Alert` 없음 |
| 실패(서버 오류·입력 검증·권한) | 해당 화면 또는 수정 창 안 메시지 영역 | 토스트 없음, 수정 창 유지 |

## 2. 화면별 성공 문구(기존 그대로)

| 화면 | 문구 |
| --- | --- |
| 견적등록 / 견적 수정 창 | 견적이 저장되었습니다·수정되었습니다. 견적번호: {번호} · 견적이 삭제되었습니다. 견적번호: {번호} |
| 수주등록 / 수주 수정 창 | 수주가 저장되었습니다·수정되었습니다. 수주번호: {번호} · 수주가 삭제되었습니다. 수주번호: {번호} |
| 출하등록 / 출하 수정 창 | 출하가 저장되었습니다. 출하번호: {번호} · 출하가 삭제되었습니다. |
| 거래명세서등록 / 거래명세서 수정 창 | 거래명세서가 저장되었습니다. 명세번호: {번호} (삭제 문구 없음 — 기존과 동일) |
| 출하계획등록 | 출하계획이 등록되었습니다·수정되었습니다. 계획번호: {번호} |
| 출하계획현황(수정 창) | 출하계획 {번호}이 수정되었습니다. |
| 매출마감 | {n}개 상세의 매출마감이 완료되었습니다. |

## 3. 검증 기준

| 번호 | 기준 | 검증 |
| --- | --- | --- |
| T1 | 견적 수정 창 저장 성공 → 창 닫힘, 토스트에 수정 문구 | `quotation-create-page.test.tsx` |
| T2 | 견적 수정 창 삭제 성공 → 창 닫힘, 토스트에 삭제 문구 | 같음 |
| T3 | 견적 수정 창 저장 실패 → 창 유지, 창 안 오류, 성공 문구 없음 | 같음 |
| T4 | 수주 수정 창 저장·삭제 성공 → 창 닫힘, 토스트 | `sales-order-create-page.test.tsx` |
| T5 | 메뉴에서 연 견적·수주 등록 저장·삭제 성공 → 토스트(기존 테스트 갱신) | 같은 두 파일 |
| T6 | 출하계획 등록·수정, 매출마감 성공 → `showSuccess` 호출(기존 테스트 갱신) | `sales-delivery-plan-page`, `sales-revenue-closing-page` |
| T7 | 영업 관련 테스트 전체 회귀 없음 | `npm run test:ci` |
| T8 | 실제 화면에서 수정 창 저장 후 창이 닫히고 토스트 표시 | 로컬 브라우저 스크린샷 |
| T9 | 5개 수정 창(견적·수주·출하·거래명세서·출하계획) 저장 실패 시 창 안에 오류 표시, 창 유지, 토스트 없음 | 로컬 브라우저(저장 요청만 500으로 대체) |
| T10 | 출하계획 수정 창 실패가 현황 화면 메시지 영역에 함께 나오지 않고, 창을 닫으면 사라짐 | `sales-delivery-plan-page.test.tsx` |
| T11 | 출하계획 수정 창 오류 영역이 등록 화면처럼 본문 레이아웃에 바로 놓여 기본정보 패널과 좌우 경계가 같음 | 같은 테스트 + 스크린샷 |

## 4. 후속 피드백 반영(2026-11-27)

- "모달창에서 실패했는데 메인쪽에 표시되면 안 보이니 모달창에 표시되어야" → 5개 수정 창 확인. 출하계획 수정 창만 현황 화면과 `error` 상태를 공유해 뒤쪽에도 표시되어, 창 전용 `dialogError`로 분리했다.
- "수정창 오류 메시지 영역을 등록페이지처럼 여백·넓이를 맞춰" → 출하계획 수정 창만 `PageMessageArea` 기본 여백(좌우 24px·상하 16px) 때문에 좁았다. 등록 화면과 같이 `Alert`을 본문에 바로 두었다.
