# skill-orm — MyBatis 매퍼 XML 생성

정본: `backend/src/main/resources/egovframework/mapper/let/system/modules/EgovSystemModule_SQL_postgresql.xml`

## 0. 시작 전

1. 정본 매퍼와 `EgovSystemMenu_SQL_postgresql.xml`(동적 SQL·nullable FK 참고)을 Read.
2. skill-impl 이 만든 `<Prefix>DAO.java` 를 Read — statement id / 파라미터 키 / 반환 타입의 **근거**.
3. 대상 테이블 실제 컬럼 확인 (`docs/database/db-schema.md` 또는 MCP `postgres`).

## 1. 배치와 명명

| 항목 | 규칙 | `warehouses` 예시 |
|---|---|---|
| 파일명 | `EgovSystem<Entity>_SQL_postgresql.xml` | `EgovSystemWarehouse_SQL_postgresql.xml` |
| 디렉터리 | `backend/src/main/resources/egovframework/mapper/let/<area>/<plural>/` | `.../let/system/warehouses/` |
| glob 매칭 | `classpath:/egovframework/mapper/let/**/*_postgresql.xml` (필수) | ✓ |
| `namespace` | DAO 단순 클래스명 = `System<Entity>DAO` | `SystemWarehouseDAO` |
| `resultMap id` | `<singular>` | `warehouse` |
| `resultMap type` | `<Prefix>VO` FQN | `egovframework.let.system.warehouses.domain.model.SystemWarehouseVO` |

- **접미사 `_postgresql.xml` 은 필수.** dev/prod 프로파일이 `Globals.DbType=postgresql` 이라 `EgovConfigAppMapper` 가 이 glob 로만 매퍼를 로드한다 (`application.properties` 의 `mssql` 은 무시됨).
- 외부 설정 수정 불필요 — glob 이 자동 탐지. namespace 는 반드시 DAO **단순 클래스명**(FQN 아님).

> 사용자가 매퍼를 레퍼런스와 같은 `.../mapper/let/system/modules/` 폴더에 두라고 명시하면 그 지시를 따르되, 파일명은 도메인별로 유일해야 한다. 기본값은 위 표대로 도메인 전용 폴더.

## 2. 골격

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE mapper PUBLIC "-//mybatis.org//DTD Mapper 3.0//EN" "http://mybatis.org/dtd/mybatis-3-mapper.dtd">
<mapper namespace="<Prefix>DAO">

    <resultMap id="<singular>" type="<Prefix>VO FQN">
        <result property="<pkCamel>" column="<pk>"/>
        <result property="tenantId" column="tenant_id"/>
        <!-- 업무 컬럼: <camelProp> ← <snake_column> 1:1 -->
        <result property="useAt" column="use_at"/>
        <result property="createdAt" column="created_at"/>
        <result property="updatedAt" column="updated_at"/>
    </resultMap>

    <select id="select<Entity>List" resultMap="<singular>">
        SELECT x.<pk>, x.tenant_id, <업무 컬럼...>, x.use_at, x.created_at, x.updated_at
               <!-- 자식 카운트가 필요하면: , (SELECT COUNT(*) FROM tb_<child> c WHERE c.<fk> = x.<pk>) AS <child>_count -->
        FROM <table> x
        WHERE x.tenant_id = #{tenantId}
        <if test="useAt != null and useAt != ''">
            AND x.use_at = #{useAt}
        </if>
        <!-- FK 필터가 있으면 <if test="fooId != null"> AND x.foo_id = #{fooId} </if> -->
        ORDER BY x.sort_order ASC, x.<pk> ASC
    </select>

    <select id="select<Entity>ById" parameterType="map" resultMap="<singular>">
        SELECT x.<pk>, x.tenant_id, <업무 컬럼...>, x.use_at, x.created_at, x.updated_at
        FROM <table> x
        WHERE x.<pk> = #{<pkCamel>} AND x.tenant_id = #{tenantId}
    </select>

    <!-- 코드 유니크가 있을 때만 -->
    <select id="select<Entity>IdByCode" parameterType="map" resultType="long">
        SELECT <pk> FROM <table>
        WHERE tenant_id = #{tenantId} AND <code> = #{<codeCamel>}
    </select>

    <!-- INSERT 는 <select> + RETURNING. <insert> 아님 -->
    <select id="insert<Entity>" parameterType="map" resultType="long">
        INSERT INTO <table> (tenant_id, <편집 컬럼...>, use_at)
        VALUES (#{tenantId}, #{...}, #{useAt})
        RETURNING <pk>
    </select>

    <update id="update<Entity>" parameterType="map">
        UPDATE <table>
        SET <컬럼> = #{...}, ...,
            use_at = #{useAt},
            updated_at = now()
        WHERE <pk> = #{<pkCamel>} AND tenant_id = #{tenantId}
    </update>

    <delete id="delete<Entity>" parameterType="map">
        DELETE FROM <table>
        WHERE <pk> = #{<pkCamel>} AND tenant_id = #{tenantId}
    </delete>

    <!-- 삭제 가드가 필요할 때만 -->
    <select id="countChildrenBy<Entity>Id" parameterType="map" resultType="int">
        SELECT COUNT(*) FROM tb_<child>
        WHERE <fk> = #{<pkCamel>} AND tenant_id = #{tenantId}
    </select>

</mapper>
```

## 3. 규칙

- `resultMap` 은 `mapUnderscoreToCamelCase=true` 라도 **명시적으로** 필드마다 `<result>` 를 적는다(레퍼런스 관례).
- `select<Entity>List` 는 `parameterType` 생략(DAO 가 `SearchConditionVO` 전달, 추론). 나머지 조회/변경은 `parameterType="map"`.
- 동적 SQL 은 `<if test="필드 != null and 필드 != ''">` 한 줄씩. `<where>` 태그 안 씀(테넌트 조건이 항상 존재). `IN` 목록이 필요하면 `<foreach collection="..." item="..." open="(" separator="," close=")">`.
- **ID 전략**: DB identity (`<pk> bigint GENERATED BY DEFAULT AS IDENTITY`). Postgres `RETURNING <pk>` 로 반환, DAO `selectOne` 이 읽음. `<selectKey>` / egov id-gnr 금지.
- INSERT 에서 `created_at`/`updated_at` 은 제외(컬럼 DEFAULT). UPDATE 는 항상 `updated_at = now()` 명시.
- **nullable `bigint` FK 바인딩은 `#{<fk>Id, jdbcType=BIGINT}`** (전역 `jdbcTypeForNull=VARCHAR` 때문에 미지정 시 varchar NULL → bigint 캐스팅 오류). INSERT·UPDATE 양쪽.
- 감사 컬럼(`created_by`/`updated_by`)은 대상 테이블에 있고 스펙에 요구될 때만 INSERT/UPDATE 에 추가.
- 모든 statement 는 `tenant_id = #{tenantId}` 로 스코프.
- `#{...}` 키는 skill-impl 의 ServiceImpl param `HashMap` 키와 **정확히 일치**해야 한다. `<if test>` 이름은 `SearchConditionVO` 필드명과 일치.
- 사용 가능한 PG 관용구: `RETURNING`, `now()`, `COALESCE(col, 'Y')`, `EXISTS (SELECT 1 ...)`, `ON CONFLICT (a,b) DO NOTHING`, `CAST(#{x} AS BIGINT)`, `LIMIT #{n}`. **LIMIT/OFFSET 페이지네이션은 이 API 계열에 없음.**
- `resultType="map"` 을 쓰는 경우 컬럼을 `AS "camelKey"` 로 별칭.

## 4. DAO ↔ XML 바인딩 확인표

| DAO 메서드 | statement id | param | 반환 |
|---|---|---|---|
| `select<Entity>List(SearchConditionVO)` | `<Prefix>DAO.select<Entity>List` | SearchConditionVO | `resultMap="<singular>"` → `List<<Prefix>VO>` |
| `select<Entity>ById(Map)` | `<Prefix>DAO.select<Entity>ById` | `map(<pkCamel>, tenantId)` | `resultMap` → `<Prefix>VO` / null |
| `select<Entity>IdByCode(Map)` | `<Prefix>DAO.select<Entity>IdByCode` | `map(tenantId, <codeCamel>)` | `resultType="long"` → `Long` |
| `insert<Entity>(Map)` | `<Prefix>DAO.insert<Entity>` | `map(tenantId, 편집컬럼..., useAt)` | `resultType="long"` → `Long` (RETURNING) |
| `update<Entity>(Map)` | `<Prefix>DAO.update<Entity>` | `map(<pkCamel>, tenantId, 편집컬럼...)` | `<update>` (무시) |
| `delete<Entity>(Map)` | `<Prefix>DAO.delete<Entity>` | `map(<pkCamel>, tenantId)` | `<delete>` (무시) |
| `countChildrenBy<Entity>Id(Map)` | `<Prefix>DAO.countChildrenBy<Entity>Id` | `map(<pkCamel>, tenantId)` | `resultType="int"` → `Integer` |
