# 초과납품 정책 스키마 변경

- 날짜/작업: 2026-11-05 / 003.
- 선행: 20261104_001 납품 스키마, 20261105_002 납품계획 스키마.
- 대상: `tb_tenant`, `tb_sales_order_dt`, `tb_sales_delivery_plan_dt`.
- 변경: `over_delivery_policy` BLOCK/WARN(기본 BLOCK), 계획 납품량 상한 CHECK 제거, 비음수/NaN 거부 유지 및 수주 출하량 비음수 CHECK 추가.
- 영향: 기준수량은 보존하고 실제량 초과 허용 여부를 서버가 테넌트 정책 및 명시적 확인으로 검증한다. 기존 CHECK는 다른 테이블의 정책을 참조할 수 없으므로 상한은 서비스·Mapper에서 처리한다. SQL 직접 쓰기는 해당 업무 API의 검증을 대신하지 않는다.
- 적용: 실제 DB 미적용. 읽기 전용 MCP list_tables와 describe_table로 tenant/order 상세 메타데이터만 확인했다. 기본 DB에는 계획/납품 테이블 및 정책 컬럼이 아직 없다. 수주 상세의 출하 상한 CHECK는 기존 저장소 DDL에 없으며 계획 상세의 제약명은 002 DDL을 따른다.
- 롤백: 첨부 rollback 사용. 쓰기 중지 및 테이블 잠금 후 초과 실적이 남거나 WARN 테넌트가 있으면 중단한다. 실적을 삭제하거나 기준수량을 변경하지 않는다. 승인된 운영절차로 정합성 확인 후 수행한다.
- 설정: 테넌트별 승인된 SQL 운영절차로 BLOCK/WARN을 지정한다. 테넌트 설정 UI는 이번 범위가 아니다. 기본값을 일괄 WARN으로 변경하지 않는다.
- 사본: `docs/database/20261105`와 `backend/DATABASE/20261105`의 같은 003 파일을 동일하게 유지한다.
