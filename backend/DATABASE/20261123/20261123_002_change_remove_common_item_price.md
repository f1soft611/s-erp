# 20261123_002 단가 공통단가 폐지 이력

- 날짜: 2026-11-23
- 작업: 거래처 없는 공통단가를 폐지하고 단가를 항상 거래처에 붙인다 ([사양서](../../spec/20261123/20261123_002_item-price-redesign_상세사양서.md))
- 스크립트: `20261123_002_remove_common_item_price.sql` / 롤백 `20261123_002_rollback_remove_common_item_price.sql`
- 선행 확인(읽기 전용 DB, 2026-11-23): 공통단가 행은 매입 8행(품목 1·2·3·30·32·33·36, 품목 1은 2행), 매출 0행. 거래처 단가 행은 매입 9, 매출 2. 거래처 2곳 이상인데 기본 거래처가 없는 매입 품목은 품목 ID 8 하나(거래처 4는 유효, 거래처 8은 2026-11-26 시작 예정).

| 대상 | 변경 |

## 영향 범위
- 공통단가가 있던 품목(1·2·3·30·32·33·36)은 그 단가가 사라진다. 품목 2·30은 거래처 단가가 따로 있어 단가가 남고, 1·3·32·33·36은 단가가 없는 품목이 된다(테스트 데이터, 사용자 확인).
- 이 SQL은 **새 백엔드 코드가 배포된 뒤에** 실행한다. 이전 코드는 `customer_id` NULL 저장을 시도할 수 있어 NOT NULL 제약에 걸린다.
- 백업 테이블은 롤백용이며 운영 확인 후 삭제할 수 있다.
- 재실행해도 안전하다(백업은 중복 없이 복사, 기본 거래처는 이미 있으면 건너뜀).

## 롤백
롤백 스크립트가 이 작업이 추가한 기본 거래처(수정 이력 없는 행만)를 삭제하고, `customer_id` NOT NULL을 해제하고, 백업 행을 원래 `price_id`로 복원하고, 부분 유니크 인덱스를 되살린 뒤 백업 테이블을 삭제한다. 백업 `price_id`가 이미 사용 중이면 중단한다.

## 적용 결과 (읽기 전용 DB 조회, 2026-11-23 실행 후)
- 공통단가 행 0건(전체 19→11건), `customer_id` NOT NULL, 백업 8건, 공통단가 전용 인덱스 삭제, 품목 8 기본 거래처=거래처 4(`migration-20261123`).

## 검증
- 격리된 PGlite(PostgreSQL 호환 임시 DB)에서 실행·재실행·NULL 거래처 입력 거부·롤백을 확인했다(품목 8 상당 사례는 거래처 4, 모두 만료된 사례는 시작일이 늦은 쪽이 기본으로 지정됨).
- 실제 DB에는 적용하지 않았다.
