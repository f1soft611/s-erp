# 2026-10-22 품목코드 자동채번 변경 이력

- 작업 번호: 010
- 대상: 기존 `public.ids`의 `table_name = 'tb_material_info'` 카운터.
- 변경: 기존 숫자 1~6자리 품목코드 최댓값 다음 값으로 초기화한다. 기존 높은 카운터는 유지한다.
- 영향: 품목코드 미입력 신규 등록에 eGov IDS 6자리 코드 사용. 직접 입력 및 tenant 내 unique 유지. 품목 테이블 DDL 변경 없음.
- 확인: 지정 tenant 읽기 전용 MCP의 테이블/컬럼/제약 메타데이터를 확인했다. 업무 행과 카운터 값은 조회하지 않았다.
- 적용: 읽기 전용 MCP로 실행하지 않았다. 운영 적용 전 해당 DB 관리 절차에 따라 초기화 SQL을 실행해야 한다.
- 롤백: 애플리케이션 변경만 되돌린다. 이미 발급된 코드 재사용 방지를 위해 카운터를 낮추거나 삭제하지 않는 no-op 롤백이다.
- 사본: `docs/database/20261022` 및 `backend/DATABASE/20261022`의 같은 번호 파일을 동일하게 유지한다.

## 2026-10-22 생성 스크립트 누락 보완

- 원인: 최초 작업은 기존 테이블 사용만 고려하여 채번 초기화만 작성했고, 테이블이 없는 환경용 DDL을 누락했다.
- 대상/영향: 신규 환경의 `public.tb_material_info`와 종속 BIGSERIAL 시퀀스. 기존 테이블은 수정하지 않는다.
- MCP 재확인: 지정 tenant 서버의 list/describe 및 카탈로그 제한 조회로 전체 37개 컬럼, 길이/null/default/주석, PK/FK/unique/CHECK, 인덱스 2개를 확인했다. 업무 행은 조회하지 않았다.
- 생성: [20261022_010_create_material_schema.sql](20261022_010_create_material_schema.sql). `public.tb_tenant`가 먼저 있어야 한다. 이미 품목 테이블이 있으면 실행하지 않는다. 스키마 불일치를 감추지 않도록 기존 테이블이 있으면 생성은 오류로 중단한다.
- 적용 순서: 테이블이 없으면 **생성 SQL → 기존 채번 초기화 SQL**. 테이블이 있으면 채번 초기화만 적용한다. 채번 초기화에는 기존 `public.ids`가 필요하다.
- 신규 생성 롤백: [20261022_010_rollback_material_schema.sql](20261022_010_rollback_material_schema.sql). 이 스크립트로 생성한 빈 테이블에만 적용한다. 배타 잠금 후 데이터가 있으면 예외로 중단한다. 의존 객체는 강제로 삭제하지 않으며 BIGSERIAL 소유 시퀀스는 테이블과 함께 제거된다. IDS 카운터는 보존한다.
- 기존 `20261022_010_rollback.sql`은 채번 적용에 대한 no-op 롤백으로 유지한다. 생성 롤백과 목적이 다르므로 임의로 대체하지 않는다.
- 검증: `node --test tools\tests\test_material_schema.cjs`로 컬럼/제약/인덱스/주석/파일 사본 일치/롤백 정적 계약을 확인한다. 실제 PostgreSQL 실행·DB 반영 검증과 구분한다.
- DB 반영: 생성/롤백 SQL을 실제 DB에 실행하지 않았다.
