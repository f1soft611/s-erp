# 입고 테이블 생성 변경 이력

- 변경일: 2026-11-17
- 대상 테이블: `tb_material_receipt_hd`(신규), `tb_material_receipt_dt`(신규)
- 변경 항목:
  - 헤더: 입고번호 `MI-yyyyMMdd-NNNN`, 구매처·통화 1종, 담당자·부서, 부가세구분·포함여부, 공급가·세액·합계, 사용여부(취소)
  - 상세: 가입고 행 연결(`material_arrival_detail_id`, `ON DELETE SET NULL`, 분할 입고 시 중복 가능), 가입고번호 복사본(`arrival_no`), 발주 행 연결, 수량·단가(0 허용), 공급가·세액·합계, 입고창고, 제조일·소비기한, LOT번호(빈값)
  - CHECK: 영세·면세는 포함 불가, 수량 > 0, 단가 ≥ 0, 소비기한 ≥ 제조일, Y/N 컬럼 값
- 선행: 가입고 스키마(`20261116_002`), 발주 스키마(`20261113_002`), 부가세구분 공통코드(`20261113_001`)
- 영향: 신규 테이블만 추가한다. 기존 테이블은 변경하지 않는다. 검사 여부는 연결된 가입고 행의 `inspect_at`으로 판단하며 입고 상세에 복사하지 않는다.
- 제외한 MES 컬럼: LOCATION, 실입고량, 입고유형·임의입고·참조, 사용용도, 수주·생산 연계(`T_ORDER_*`), 도면번호, 플랜트, 선행품, 입고단위수량, 원가확정월, 저장시재고, 마감 플래그, 불량수량, 매입마감(`VC_*`), 시스템 LOT 생성
- MCP 확인: `s-erp-postgresql-readonly`의 `list_tables`로 입고·수입검사·재고 테이블이 아직 없음을 확인했다. 가입고·발주·품목·거래처·창고 구조는 기존 스크립트 기준이며 적용 후 `describe_table`로 재확인한다.
- 적용 상태: SQL 스크립트만 작성했으며 실제 DB에는 적용하지 않았다.
- 롤백 여부: 제공함. 입고 상세와 헤더 테이블을 삭제한다(데이터가 있으면 함께 삭제).

적용 SQL: `20261117_001_create_material_receipt_schema.sql`

롤백 SQL: `20261117_001_rollback_material_receipt_schema.sql`
